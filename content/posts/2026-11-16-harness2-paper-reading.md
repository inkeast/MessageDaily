## 一、论文背景

### 1.1 Harness 是什么

一个 LLM Agent 的能力不只取决于底座模型，还取决于**执行 harness**——包裹在冻结模型外层的运行时脚手架，包括系统提示词、护栏规则、记忆、技能（skill）、工具使用指南、脚本、子代理与编排插件。业界有一个流行的公式：**Agent = Model + Harness**。同一个模型装进不同的 harness，表现可能天差地别；就好比同一个新员工，给他一套草台班子流程和给他一套成熟的企业 SOP 体系，产出完全不同。

Lilian Weng 在 2026 年 7 月的综述性博文《Harness Engineering for Self-Improvement》中把这一层正式命名为值得独立研究的工程对象：早期 Agent 框架关注的是记忆、工具、规划、行动的组合，而 harness 工程进一步把**工作流编排、上下文构造、工具接口、中间件控制**整体纳入可优化的代码面。生产级编码 Agent（Claude Code、Codex CLI、OpenCode、CodeBuddy）本质上都是各自 harness 的产物。

### 1.2 为什么手工设计 harness 走不通

随着 Agent 从编码扩展到办公流程、法律等高风险专业领域，任务形态越来越开放多样，手工设计并持续精修 harness 需要反复的工程投入，且**部署前静态选定的 harness 在开放世界往往无法泛化**——开放世界的核心特征是任务在设计阶段不可预知、测试时全新出现。

### 1.3 递归自我改进（RSI）与其两大拦路虎

递归自我改进（Recursive Self-Improvement, RSI）指 AI 系统把执行结果和内部反思转化为对自身的持久修改，且这些修改会进一步影响后续改进如何被生成、评估与保留——即 AI 改进 AI。改进对象可以是模型权重（self-rewarding LM）、改进程序（STOP）、Agent 代码（Darwin Gödel Machine），harness 也可以是这样一个对象。

把 RSI 部署到开放世界，论文指出两个关键挑战：

1. **没有真值验证器**：开放世界任务在测试时才首次出现，没有标准答案、没有单元测试、没有可靠的自动判分器。现有方法依赖代理信号、假设的 ground truth 或成对输出判断，但如何**安全地使用不完美的执行证据来指导 harness 在线修改**仍是难题。
2. **改一个任务不等于会改下一个任务**：为单个任务做的特化编辑在需求变化时常常失效；直接继承高度定制的 harness 又会随任务分布漂移引入噪声。但改进过程本身产生了高度可复用的经验——弱点如何被诊断、哪些修改被测试、执行揭示了什么。**改进过程本身必须成为学习对象**。

这就引出论文的中心问题：递归自我改进能否同时改进当前 harness 与未来改进 harness 的机制？

## 二、论文定位和关联工作

### 2.1 研究谱系一：离线 harness 优化（部署前搜出好 harness）

- **DSPy / GEPA / ADAS / AFlow**（2024–2026）：从提示词到 Agent 工作流的自动优化，但都在固定训练任务上以评估反馈为信号做离线搜索。
- **Meta-Harness**（[arXiv:2603.28052](https://arxiv.org/abs/2603.28052)，COLM 2026，Stanford+KRAFTON+MIT）：把 harness 视为代码，用 agentic proposer 在训练任务上离线搜索最优 harness 再部署，是被本文重点对比的最强基线。局限：依赖标注训练集，部署后不再适应。
- **AHE**（[arXiv:2604.25850](https://arxiv.org/abs/2604.25850)）：可观测性驱动的编码 Agent harness 自动进化，提出了本文沿用的 harness 文件级分解（本文在其基础上扩展到 8 个组件）。

### 2.2 研究谱系二：在线/测试时 harness 进化

- **RHI**（Recursive Harness Self-Improvement，[arXiv:2607.15524](https://arxiv.org/abs/2607.15524)）：迭代改进 agentic loop，用成对输出判断做信号。
- **Harness Scaling**（Wang et al., COLM 2026 Workshop）：每个测试任务孤立地花额外推理预算重写 harness，**跨任务不携带状态**——这正是本文的对照基线之一，其缺陷（无经验传承）被本文实验放大。
- **TTHE**（[arXiv:2607.08124](https://arxiv.org/abs/2607.08124)）：在无标注批次上进化 harness 并携带到下一批次，但依赖执行派生的代理信号（含可用时的公共测试）。

### 2.3 研究谱系三：记忆/经验路线

- **ReasoningBank**（[arXiv:2509.25140](https://arxiv.org/abs/2509.25140)，ICLR 2026，Google Research）：harness 完全不变，把自判成功/失败轨迹蒸馏为文本策略记忆，检索回填上下文。它是本文最重要的在线基线——代表了改上下文而不改可执行 harness 的路线。

### 2.4 研究谱系四：RSI 经典

- **Self-Refine**（NeurIPS 2023）：迭代自反馈精修单次输出，改进不持久。
- **STOP**（COLM 2024）：递归重写代码改进程序，靠单元测试引导。
- **Darwin Gödel Machine**（[arXiv:2505.22954](https://arxiv.org/abs/2505.22954)，ICLR 2026）：靠 benchmark 评估驱动 Agent 代码进化。这些系统的共同点是依赖效用/基准/验证信号。

### 2.5 本文定位

| 维度 | 离线优化（Meta-Harness 等） | 记忆路线（ReasoningBank） | 每任务改写（Harness Scaling） | **Harness^2** |
|---|---|---|---|---|
| 改进对象 | harness | 上下文文本（harness 不变） | harness（任务孤立） | harness + 改进机制本身 |
| 阶段 | 离线 | 在线 | 在线 | 在线（流式单遍） |
| 外部标签 | 需要 | 不需要 | 不需要 | **不需要** |
| 跨任务状态 | 无 | 有（文本记忆） | 无 | 有（可执行库+经验） |
| 测试时扩展研究 | 无 | 有 | 有 | 有（k=1→5 单调上升） |
| 改进器自身更新 | 部分 | 无 | 无 | **有** |

论文 Table 4 对 20+ 相关方法做了六维系统对比：Harness^2 是唯一同时满足 Online / 无标签 / 流式 / 有 Scaling 研究 / 有 Improver Update 的工作。其核心增量在于：把任务级精修的**过程经验**也变成改进对象（双层递归），且全程不使用任何正确性标签。

## 三、问题定义

### 3.1 从具体场景到抽象结构

具体场景：一个 Agent 依次处理 N 个开放世界任务 q1…qN，每个任务无真值答案、完成后不可重放，只允许在当前任务预算内反复执行。要在每个任务上自动改出更好的 harness，还要越改越会改。

抽象后，这是一个**双层耦合优化问题**：

- **内层（任务级）**：给定冻结模型 M、当前执行 harness H、任务局部执行历史 E 和改进 harness R，求后继 harness H' 使当前任务执行更好——且**唯一的可用信号是执行行为对比**，没有分数、没有答案。
- **外层（harnessing 级）**：给定整个改进过程记录 D（参考执行、候选、探针、组合决策），更新改进 harness R，使**未来任务的改进更有效**。

### 3.2 形式化

- 内层：(H', e', ξ) = Φ(qt, H, E; Rt)，其中 e'=(轨迹, 交付物)，ξ 是步骤记录。
- 外层：R(t+1) = Update(Rt, H★t, Dt)，H★t 是被采纳的 harness，库在任务间演化、模型权重与阶段指令冻结。

### 3.3 这个抽象的精妙之处

它把无验证器在线改进难题**降维成证据比较问题**：不问对错，只问在相同模型与环境条件下，改动前后行为是否不同、差异是否指向目标缺陷。这与控制变量实验的同构性是全文可靠性的基石；外层则与元学习（learn-to-learn）同构——但优化对象不是梯度可达的参数，而是文件级的可执行组件与经验文本。约束最狠的一点：**基准分数只用于事后评估，绝不进入改进管线**（实现上有一个 guard 拒绝把任何含评分、rubric、判分 verdict 的工作目录交给编辑器），保证了设定的纯粹性。

## 四、问题解法

### 4.1 可编辑面：8 个 harness 组件

沿用 AHE 的文件级分解并扩展为 K=8，每个组件是一个文件，编辑即 diff：

| 分组 | 组件 | 载体文件 | 激活时机 | 作用 |
|---|---|---|---|---|
| 上下文构造 | C1 系统提示 | systemprompt.md | 每次调用 | 人设与顶层流程 |
| 上下文构造 | C2 护栏 | guardrails.md | 每次调用 | 跨任务硬约束 |
| 上下文构造 | C3 记忆 | LongTermMEMORY.md | 每次调用 | 跨任务领域事实 |
| 上下文构造 | C6 技能 | skills/n/SKILL.md | 按需加载 | 专家流程手册（类比岗位操作手册） |
| 工具接口 | C4 工具指南 | tool_guidance.md | 每次调用 | 何时用哪个工具、怎么用 |
| 工具接口 | C7 脚本 | scripts/name.py | 经 bash 执行 | 确定性能力，替代逐 token 推理 |
| 编排 | C5 子代理 | sub_agents/n/AGENT.md | task 工具 | 独立上下文的委派工人 |
| 中间件 | C8 插件 | plugin/name.ts | 工具环内 | 模型无法跳过的行为强制（hook） |

关键设计：**常驻文本（C1–C4）每个字都在占用每次调用的上下文预算，是昂贵选项；技能按需加载、脚本确定执行、插件在工具环内强制行为**，三者的边际成本结构完全不同。编辑提示词中明确要求优先用按需组件而非加常驻文本。

### 4.2 任务级递归：对比式 Propose–Probe–Compose

**Propose（提出）**：先获得当前 harness 的参考执行 e0（暴露行为方式，而非判断对错）。然后提出两个互补作用域的候选 harness：

- **invariant 候选**：针对跨域复发的 agentic 过程缺陷——规划、工具使用、上下文管理、委派（改的是 Agent 怎么工作）；
- **domain 候选**：针对当前领域的知识、流程、约束（改的是从业者知道什么）。

候选可直接复用/改编库中组件，但任务特定事实必须对照当前任务证据核查。

**Probe（探针）**：每个候选在**相同模型与环境配置**下于同一任务执行，与参考执行对比得到**行为对比**（behavioral contrast）——证据只说明编辑是否缓解目标缺陷、无变化还是引入回归，不验证任务正确性。这里刻意控制变量：同模型、同环境、同任务，唯一差异是编辑本身。

**Compose（组合）**：读取参考执行、候选、diff 与全部执行证据，形成后继 harness——可合并受支持的修改、修订冲突编辑、整体采纳一个候选，或保持现状（KEEP_BASE 是合法答案）。**每个决策必须绑定一个具体的轨迹时刻，而非臆测的分数增益**；任何关联执行产出为空的编辑被显式视为不安全。

### 4.3 两种递归扩展 + 终选

- **并行递归**：k 个参考执行 + k×2 个候选（每个作用域 k 个）独立探针，再由 k 个独立组合会话各自组合（借鉴 RSA 的聚合思想，但聚合对象是可执行 harness 及其行为后果，而非推理文本）。k 控制宽度。
- **串行递归**：链式 k 步，每步以前一步的 harness 与累积证据为条件（Self-Refine 思想施加于 harness）。后步可保留、修订或纠正早先改动。k 控制深度。
- **终选**：k>1 时，一个匿名化盲选器只看交付物对比任务要求做选择，不得合成新内容；k=1 时退化为单步无终选。

### 4.4 harnessing 级递归：把改进过程变成学习对象

每个任务交付后，Reflector 复盘完整改进记录 D：哪些改动解决了观察到的缺陷、在什么条件下、后果如何。只有被**执行对比**支持的教训才写入改进库；仅被选中不构成可迁移性证明。库条目 = 完整被采纳 harness + EXPERIENCE.md（适用情境 cue + 可执行教训 lesson + 证据），带索引按需检索。下一个任务仍从公共初始 harness H0 出发，但 Propose/Compose 由更新后的 Rt 指导——组件被选择性复用而非自动继承。证据不足时宁可不写新条目（NO_ENTRY 是合法输出）。

### 4.5 工程安全机制（值得单独学习）

- **信息隔离 guard**：任何包含判分 verdict、rubric、分数的工作目录被拒绝交给编辑会话；所有提示词明确声明上下文中不存在评分器，禁止揣测评判者想要什么。
- **结构验证器**：技能必须在常驻文本中有触发行否则整案报废；常驻文本禁止 Jinja 模板双花括号；被引用的脚本必须随案交付。验证失败重试一次，再失败则回退继承原 harness。
- **提示注入防御**：context/ 下文件一律视为数据而非指令，禁止执行候选 harness 中的脚本，只作文本分析。

## 五、评估指标与实验证据

### 5.1 基准与指标体系

| 基准 | 领域 | 测试规模 | 判分方式 | 衡量的能力 |
|---|---|---|---|---|
| WorkBuddy-Bench | Code/Web/Office 三域 | 40/35/25 个测试任务（80/70/50 对半分） | 复合验证器（隐藏测试+文件结构检查+LLM/VLM 判官），任务分=通过检查占比 | 办公型交付物的工程完备性 |
| JobBench | 7 个职业域端到端任务 | 34 个测试任务（65 任务冻结 31/34 分） | Claude Opus 4.8 加权评分量表（rubric 对管线不可见） | 长程专业任务对人类意图的对齐 |
| LAB（Harvey 法律基准） | 24 个法律执业领域 | 100 个留出测试任务（自 1251 任务分层抽样） | Claude Sonnet 4.6 判官，Partial=逐项标准通过率 | 高风险专业法律工作 |

主表为 3 次打乱任务顺序的独立流均值±标准差；同时报告 #Steps（每任务执行步数）以对照分数与代价。**设计关键点：训练半区只给 Meta-Harness 离线搜索用，Harness^2 与其他在线基线一律空库起步处理测试流；基准分数只用于评估。**

### 5.2 主结果：单步与递归增益

配置：冻结执行器 Gemini 3.5 Flash 与 GLM-5 × 初始 harness OpenCode 与 Codex，默认编辑器 Claude Opus 4.8，k=1 单步 / k=5 并行递归。

- **WorkBuddy-Bench**：GLM-5+OpenCode 单步 64.2→75.7（**+11.5，全基准最大单步提升**）；Gemini+OpenCode 72.4→77.5，+k=5 并行递归再 +3.3；GLM-5+Codex 64.4→75.3，+递归再 +3.0。四配置 Avg 全部超过所有基线（如 GLM-5+OpenCode 75.7 vs 最强基线 Meta-Harness 69.7，领先 +6.0）。
- **JobBench**：Gemini+OpenCode 单步 31.5→36.0（**+4.5**）；GLM-5+OpenCode 20.6→24.2（+3.6），+递归再 +4.2。四配置全部领先（Gemini+OpenCode 36.0 vs Meta-Harness 35.8）。
- **LAB**：GLM-5+OpenCode 单步 59.6→71.4（**+11.8 个百分点**），+k=5 再 +6.7；GLM-5+Codex 65.9→70.7（+4.8）。四配置中 3 个领先，仅 Gemini+Codex 上 Meta-Harness（76.5）高于 Harness^2（75.6）——这是全文对基线的唯一让步，且该基线用了 24 任务 dev 集做离线搜索。
- **弱执行器获益更大**：GLM-5 在 WB 和 LAB 的绝对增益全面超过 Gemini（WB 单步 +11.5 vs +5.1）；GLM-5 配改进 harness（75.7）反超 Gemini 配初始 harness（72.4）。

### 5.4 主结果速览（单步 k=1 → 并行递归 k=5）

| 配置 | WorkBuddy-Bench Avg | JobBench | LAB Partial |
|---|---|---|---|
| Gemini 3.5 Flash + OpenCode | 72.4 → 77.5（+5.1）→ 80.8 | 31.5 → 36.0（+4.5）→ 39.0 | 79.9 → 81.9 → 84.5 |
| Gemini 3.5 Flash + Codex | 74.5 → 77.5（+3.0）→ 80.4 | 33.9 → 35.3（+1.4）→ 39.5 | 71.6 → 75.6 → 78.5 |
| GLM-5 + OpenCode | 64.2 → 75.7（**+11.5**）→ 79.6 | 20.6 → 24.2（+3.6）→ 28.4 | 59.6 → 71.4（**+11.8**）→ 78.1 |
| GLM-5 + Codex | 64.4 → 75.3（+10.9）→ 78.3 | 23.6 → 24.8（+1.2）→ 27.9 | 58.1 → 65.9（+7.8）→ 70.7 |

注：单步数字为论文主表均值；k=5 列按主表分数加上 Recursion 行增量合成，便于一图总览（LAB Gemini+Codex 行为唯一基线反超项，Meta-Harness 76.5）。

### 5.5 为什么这些实验能证明论点

1. **规模曲线证明递归有效性**：WB-code 并行递归 k=1→5 从 76.5 单调升至 80.8，WB-office 79.5→83.4；**两种递归形式在 k=2 就超过所有基线在 k=5 的表现**——增益来自递归结构本身而非单纯堆算力（对照：Harness Scaling 在 k=2→3 出现回退，ReasoningBank 波动；Best-of-k base 也不及）。k=5 时并行略优于串行，但并行会话可并发执行，实际延迟取决于并发资源。
2. **Pareto 前沿证明计算-性能权衡合理**：统计提交交付物前的全部 token，Gemini+OpenCode 下 k 1→5 对基线增益 JobBench 4.5→7.5 分、WB 5.1→8.4 分，两种配置均位于经验 Pareto 前沿；Meta-Harness 用比 k=5 更多的算力得到更低分数。
3. **消融定位每个组件的贡献**（Gemini+OpenCode，k=1）：去改进库 WB 77.5→74.4（-3.1）、JB 36.0→34.2（-1.8）；去双作用域编辑 WB -2.9、JB **-3.7**；去组合阶段 WB -1.6、JB -1.9。组件级消融：从改进后 harness 去掉 skills 损失最大（Avg -5.3，Web -6.9），scripts -3.7（Office -7.4），prompt 组仅 -1.5——**按需加载的技能/脚本比常驻提示更值钱**。
4. **反事实检验无证据编辑的危险**：直接在没有参考执行、探针与库的条件下盲改 harness，WB-code 从 73.4 **跌至 63.2**、Web 69.9→65.0——对比证据不是锦上添花，而是防止在线编辑自毁的必要条件。
5. **基线弱点被实验放大而非回避**：ReasoningBank 在编码任务上最低落后 base 6.6 分（文本策略无法修复过程缺陷）；Harness Scaling 在 12 个基准-配置对中有 7 个低于 base（无状态传承的孤立改写得不偿失）。
6. **库的可迁移性证明外层递归真实有效**：k=5 库相对 base 支持 Code/Web/Office +0.9/+4.4/+5.1 的**免探针一步增益**；JobBench 学到的库迁到 WB 仍 +0.6/+0.5/+2.9；留一法（去掉每个任务自己的条目）重跑仍高于原始在线运行（WB 77.5→79.4，JB 36.0→37.7），证明库条目对后来任务有净贡献。
7. **同模型自改排除强编辑器依赖**：执行器=编辑器（k=2），GLM-5 到 Claude Opus 5 五个模型在三基准全部提升（Opus 5：WB/JB/LAB +3.3/+5.5/+3.0；GLM-5 在 LAB +13.7）。
8. **跨模型迁移证明 harness 中沉淀的是可迁移能力**：为 Gemini 精修的 harness 原样给 GLM-5 用，Code 58.5→75.8（**+17.3**）；对 Gemini 3.7 Flash（Office +6.4）与 Opus 4.8 也为正增益。
9. **对生产级固定 harness 的碾压性对照**：从 OpenCode 起步 k=5，在 Code/Web/Office 各域超过最强固定生产 harness（CodeBuddy/Codex/Claude Code 中该域最强者）4.6/5.8/4.9 分。
10. **工具可靠性侧证机制**：单步改进后三基准工具错误率全部下降（JobBench 14.4%→9.1%，-36.8%），且 WB 上调用数更少、JB/LAB 上调用数更多——改进是更好用工具而非少用工具。

论文同样诚实呈现了 9 个回退案例的三类失败：盲选器选中更弱候选（95 分在场却选了 55 分）、错误前提跨候选传播（编辑器自写的检查器查不出编辑器自己的假设）、判官崩溃与双峰判分抽样噪声。#Steps 方面，多数配置在提分的同时减少了执行步数（如 Gemini+OpenCode WB 25.4→21.9）。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**因果链一：对比证据替代分数信号，解决无验证器在线编辑的可靠性问题。**

- 方法差异：Probe 在同模型/同环境/同任务条件下执行候选与参考 → 机制变化：变量被控制，行为差异可归因于编辑本身；Compose 只采纳有具体执行证据的编辑并显式拒绝产出为空的危险编辑 → 指标体现：消融中去 scoping 贡献 2.9–3.7 分、去 composition 贡献 1.6–1.9 分；盲改（无证据）使 Code 掉 10.2 分。（论文实验已支持）
- 深层原因：无标签 setting 下，唯一的可靠信号源是**控制变量下的行为差分**——它把不可判定的对错问题转换为可观察的机制问题。这是实验科学方法对奖励信号缺失的替代。

**因果链二：经验以可执行组件+适用情境形式沉淀，使外层递归产生复利。**

- 方法差异：库存放完整可执行 harness 与 EXPERIENCE.md（cue/lesson/evidence），而非文本摘要 → 机制变化：后续任务的 Propose 可直接复用/改编组件，且教训声明了触发情境，避免过期事实污染（论文的编辑提示词要求复用组件时必须对照当前证据重验事实）→ 指标体现：去库 -3.1 分；k=5 库免探针增益最高 +5.1；JB→WB 跨基准迁移为正。（论文实验已支持）
- 这解释了对 ReasoningBank 的持续优势：后者只检索文本策略、可执行面不变，遇到过程性缺陷（如工具调用写成纯文本、聚合粒度错误）无能为力；也解释了对 Harness Scaling 的优势：后者每任务孤立改写、无状态传承，k 增大时收益小且不稳定，而 Harness^2 的增益随 k 单调上升并位于 Pareto 前沿。

**因果链三：弱执行器获益更大，因为 harness 补足的恰是弱模型缺失的过程规范与领域检查。**

- GLM-5 单步 +11.5 vs Gemini +5.1；跨模型迁移中 GLM-5 拿到 +17.3。harness 承载的检查清单、验证脚本、触发式技能对缺乏内生过程纪律的模型是净增量，对已具备者增量较小。（论文实验已支持；机理归因部分为阅读者推测，论文未做逐机制拆解）

### 6.3 综合判断与未决问题

- **多研究共同支持**：harness 是有效优化对象（Meta-Harness、AHE、TTHE 等）；harness 能力可跨模型迁移（AI4AI 与本文独立一致）；纯文本经验不足以修复过程缺陷（ReasoningBank 在本文与原论文各自设定下均显现局限）。
- **仍属推测**：弱模型获益更大的具体机理（过程规范替代说）是合理解释但未被逐项拆解验证。
- **适用边界**：行为对比仍受执行随机性与共享模型偏见影响（论文 Limitations 自认），错误前提可跨候选传播（论文失败案例：编辑器写的缓存检查器三次 PASS 却错失内容键控需求）；无验证器方法的根本不可靠性有理论证据（Setlur），本文是工程级缓解而非消除；收益需付出测试时算力，k 的最优分配未解。

## 七、必要知识反推

假设一个零背景的人要做这个工作，最少必须掌握：

### 7.1 领域知识层

- **现代 coding agent 的运行时解剖**：系统提示/技能/工具环/子代理/插件各是什么、何时进入上下文、成本结构如何——不知道这些就无法定义 8 组件可编辑面，更谈不上按成本选形（技能优先于常驻文本）。
- **生产 harness 生态**：OpenCode、Codex CLI 等真实 Agent 的文件面构成，使方法 plug-and-play 而非论文玩具。
- **专业领域任务形态**：办公交付物、长程职业任务、法律工作的验收标准差异，才能选对三个互补基准。

### 7.2 方法论知识层

- **RSI 研究脉络**：Self-Refine→STOP→DGM→Meta-Harness 的改进对象演化谱系，才能定位双层递归的空白。
- **实验科学方法论**：控制变量对比、证据分级（helped/hurt/confounded 的归因纪律）、反事实检验——Probe 与 Reflector 的设计直接由此驱动。
- **元学习结构**：内外两层优化、固定外环更新内环的时序分离，与 MAML 的 task/meta 两层同构。
- **测试时扩展研究**：Best-of-k、Pareto 前沿分析范式，用于证明增益非算力堆砌。

### 7.3 工程知识层

- **提示工程与信息隔离的边界设计**：guard 拦截判分信息、证据作数据不作指令的注入防御、结构验证器三规则——这些是把无标签承诺落到工程可信的关键。
- **评测管线设计**：复合验证器、rubric 不可见、三流均值、#Steps 计量、留一法迁移检验。

### 7.4 知识融合的关键节点

- **节点一**：把控制变量实验方法嫁接到无验证器在线编辑上——Probe 的同条件执行设计是全文可靠性支点，源于实验方法论与 Agent 工程的交叉。
- **节点二**：把元学习双层结构映射到文件级 harness——执行 harness 与改进 harness 的分离使 RSI 从改代码升级为改改进机制。
- **节点三**：把软件工程的配置管理思想（diff、验证、回退、复用需重验）注入 LLM 自改进，使编辑过程本身可审计（每条决策绑定轨迹时刻）。

## 八、论文中可以提取的通用性灵感

1. **无真值信号时，用控制变量对比替代分数判断。** 核心思想：当无法评估对错时，制造唯一差异可控的 A/B 执行并比较行为，是唯一可靠的改进信号。论文证据：去 composition -1.9~-3.7 分、盲改掉 10.2 分。推广场景：无标注数据的在线系统调参（如推荐策略灰度）、无法复现的生产事故根因定位、机器人新环境技能验证、教育中无标准答案的开放式作业改进。

2. **改进过程本身是最被浪费的学习材料。** 核心思想：做完一个任务的诊断-尝试-验证过程比任务产出更可复用，应作为一等资产沉淀（含适用情境与证据，而非只存结论）。论文证据：去库 -3.1 分，k=5 库免探针 +5.1 分，跨基准迁移为正。推广场景：运维事后复盘自动沉淀为 runbook+触发条件、销售丢单分析沉淀为话术库、医生误诊讨论沉淀为检查清单、代码评审意见沉淀为 lint 规则。

3. **能力应沉淀为按需加载的可执行物，而非常驻描述。** 核心思想：知识的最优形态是带触发条件的技能/脚本（用时才进上下文、执行确定性强），而非每句话都付费的常驻文本。论文证据：组件消融 skills -5.3 / scripts -3.7 远大于 prompt 组 -1.5。推广场景：企业 SOP 从全员工手册改为触发式流程卡、RAG 系统把高频问答编译为函数、个人知识管理从笔记流改为情境触发卡片。

4. **弱主体配强脚手架可反超强主体裸奔，且脚手架可跨主体迁移。** 核心思想：过程规范与检查清单对缺乏内生纪律的一方边际价值更高，且其中沉淀的是可迁移能力而非模型私有物。论文证据：GLM-5 单步 +11.5、跨模型 +17.3、75.7 反超 Gemini 基线 72.4；AI4AI 独立得出 0.49→0.91 的一致结论。推广场景：新手程序员配资深工程规范、小团队套用大厂流程模板、小模型部署用为大模型定制的推理脚手架。

5. **对自我改进系统，必须把评判权与被评判物隔离，并给保守回退以合法地位。** 核心思想：任何自改进回路都要防作弊信号泄漏（guard 拦截评分）与防危险变更（空产出编辑视为不安全、KEEP_BASE/NO_ENTRY 是合法输出、验证失败自动回退）。论文证据：guard 与验证器三规则、Reflector 的 confounded 归因纪律。推广场景：自动化交易系统的熔断回退、A/B 测试平台防指标泄漏、AI 自编写代码的沙箱执行约束、组织变革中的试点回滚机制。

6. **堆算力不等于改进：递归结构化探索才产生单调增益。** 核心思想：同等算力下，宽度/深度的递归组织方式（并行候选+证据组合、串行链式精修）决定增益是否单调可积累；孤立重复改写则收益不稳甚至回退。论文证据：k=2 即超所有基线 k=5；Harness Scaling 7/12 低于 base 且 k=2→3 回退。推广场景：并行架构搜索 vs 单模型放大、多方案比稿+择优合并的创意流程、迭代式产品优化与一次性大改版的对照。
