# Flex-RSI: Benchmarking Recursive Self-Improvement of Frontier Agents 精读

> 论文：arXiv 2611.08946（cs.AI，2026-11-06，68 页技术报告）
> 机构：Texas A&M University（组织方）× University of Cambridge × NUS × NVIDIA × MIT × MIT-IBM Watson AI Lab × UT Austin × CMU × UPenn × USC × Purdue × Adobe × University of Toronto（14 家）
> 资源：[论文](https://arxiv.org/abs/2611.08946) · [项目页与持续维护的 leaderboard](https://flex-rsi.github.io)

## 题目区：这篇论文在测什么

一句话版本：**给「AI 能否在工作过程中改进自己的工作方式」这件事，造了第一把公平的尺子——而且量的不只是答案变好没，还有"生产答案的那套机器"（harness）被自己改得更好没。**

论文速览：

| 项目 | 内容 |
|---|---|
| 类型 | RSI benchmark + 受控评测协议（68 页技术报告） |
| 规模 | 24 任务 × 6 领域 × 18 模型 × 177 次 run |
| 机构 | 14 家联合（TAMU 组织 + 10 高校 + NVIDIA/Adobe/MIT-IBM） |
| harness | Executor–Improver 双组件，improver 既改 executor 也改自己 |
| 防作弊 | 统一 H0 起步、验证集守门、隐藏测试集、预算记账不可改、沙箱隔离 |
| 核心发现 | 85% run 自改进（中位 +10.4）；开源在成败反馈下停滞；严格物理检查差距最大 |
| 排行榜首 | Claude Opus 5.5 91.6；开源最佳 Qwen3.8-Flash-Next 49.1（第 5） |
| 开放性 | 项目页持续维护 leaderboard |

先解释几个核心概念：

- **Harness（挽具/马具）**：模型外面那层"工作机器"——提示词、工具、记忆、控制循环。类比：模型是马，harness 是缰绳、马鞍和路线规划的组合。同一个模型配不同 harness，表现可以天差地别。
- **RSI（Recursive Self-Improvement，递归自改进）**：系统修改自身的机制，且被修改的机制又用于后续的修改——"改进者改进改进者自己"。注意本文的 RSI 发生在 harness 层：**模型权重全程冻结**。
- **Executor / Improver**：harness 的两个组件。Executor 干活（改任务解、跑实验），Improver 复盘（读全部历史轨迹，改 Executor 的提示词/工具/工作流，**也改自己的指令和经验教训文件**）。
- **解（solution）vs harness**：任务解是交付物（一个程序、一个策略、一个答案）；harness 是生产交付物的流程。改进前者像"把作业写好"，改进后者像"把学习方法也换了"。
- **Dev/Val/Test 三分割**：开发集带标签供 agent 实验；验证集隐藏、决定候选解去留；测试集隐藏、只在 run 结束后评一次。像学校作业（练习册）/月考（择优保留）/高考（最终一锤定音）。

为什么需要这个 benchmark？此前的评测要么锁死 harness 只评产出（MLE-bench、RE-Bench），要么只覆盖机器学习研究任务。而 agent 越来越多部署在视觉、机器人等通用场景，"换了新任务，agent 能不能用任务反馈自我调试到位"是部署者最关心的问题——Flex-RSI 把它变成可测量的对象。

## 一、论文背景

前沿 LLM 已经常规性地以 agent 形态工作：写代码、做实验、读结果、多步循环。一个部署者的实际问题随之而来：把 agent 放到一个新问题上，给它固定预算（时间/GPU/调用次数），它能不能用任务的反馈改进**工作方式**，而不仅仅是答案？

现有评测格局的三个空位：

1. **对象缺位**：MLE-bench（机器学习工程）、RE-Bench（研究工程 vs 人类专家）、PaperBench（论文复现）都只评产出物，harness 固定为厂商自己的；
2. **领域缺位**：已有的 RSI 导向评测（RSI-Exam、OpenRSI Index）停留在 ML 研究任务；真实世界 agent 更多用在视觉/机器人/创作场景，每次尝试消耗真实算力，目标是数小时到数天内拿到更好的解；
3. **证据缺位**：一篇对 RSI 声明的证据审计（论文引用 Chen et al. 2026g）发现，**几乎没有研究在相同初始产物、相同预算下比较不同改进过程**——没有配对对照，"自改进有效"的声明无从检验。

Flex-RSI 的应答：统一通用 harness、统一起始解、统一预算、隐藏验证/测试集、沙箱隔离，然后放开让 18 个前沿模型在 24 个任务上自我改进，用受控消融把"解改进""harness 改进""harness 迁移"三件事分开测量。

## 二、论文定位和关联工作

这篇论文处在三条研究线的交汇处：agent benchmark、自动化 agent 设计（automated agent design）、自修改 agent。定位表：

| 相关线 | 代表工作 | 与 Flex-RSI 的差异 |
|---|---|---|
| ML 工程 benchmark | MLE-bench、RE-Bench、PaperBench | 只评产出，harness 固定；任务限于 ML 研究 |
| RSI benchmark | RSI-Exam、OpenRSI Index、Vals RSI Index | 限于 ML 研究域；未做同起点同预算的配对对照 |
| 提示词/工作流优化 | Promptbreeder、GEPA、ADAS、AFlow | 优化对象是提示词或程序，非统一协议下的前沿模型横向比较 |
| 自修改 agent | STOP、Gödel Agent、SICA、Darwin Gödel Machine、Huxley-Gödel Machine | 提出**特定的**自改机制；Flex-RSI 不提出机制，而是测"各模型做这类修改的能力" |
| 机器人 harness 进化 | RegenHarness 等（从执行失败修订 harness 配置） | 单任务单模型；Flex-RSI 是 24 任务 × 18 模型的受控横评 |
| 经验复用评测 | EvoAgentBench、SkillEvolBench、PAST-Bench | 测经验跨任务复用；Flex-RSI 测单任务内的解+harness 双重改进 |

一句话定位：**别人造自改进系统，Flex-RSI 造"考自改进能力的考场"**——而且考场规则（统一 H0、验证集守门、预算记账不可被 agent 修改）让不同模型的分数第一次可以直接比较。

## 三、问题定义

每个任务给 agent 四样东西：起始解 s0、算力资源、预算（墙上时间/GPU 时/模型用量/验证评估次数/轮数上限）、三份互斥数据：

- **开发集 D_dev**（带标签，agent 可见）：实验用；
- **验证集 D_val**（对 agent 隐藏）：决定候选解是否被接受；
- **测试集 D_test**（对 agent 隐藏）：仅在 run 结束后评一次最终解。

目标：预算内最大化 S(s_T; D_test)。一轮 t 的循环：

1. **Executor 改解**：s̃_t = E_{t−1}(s_{t−1}; D_dev)，只用开发集；
2. **验证集守门**：仅当 S(s̃_t; D_val) > S(s_{t−1}; D_val) + δ 才接受（δ = 2σ 起始解验证分噪声裕度，improver 可修订该规则）；
3. **Improver 改 harness 也改自己**：(E_t, I_t) = I_{t−1}(E_{t−1}, I_{t−1}; τ_{1:t})。

式 (3) 是递归的显式表达：improver 既是算子又是参数——对 I 的修改会改变后续所有修改的产生方式。解改进与 harness 改进在协议上被干净分离：解的变更须经未见数据确认（式 2），harness 的变更体现在后续轮的候选里（式 1）。

受控性保障：所有 run 从同一通用 harness H0 出发（无任何任务/模型特定组件）、同一起始解；评估器、数据分割、预算记账固定且不可被 agent 修改；沙箱执行、越界改动自动回滚、验证/测试数据不可读。**于是模型间差异只能来自模型本身。**

任务矩阵按三个正交维度设计（用于归因）：解是"单次作答"还是"agent 构建解"；评分是"连续量表"还是"仅成败"；检查是"宽松（judge/容忍度）"还是"严格（物理稳定性/精确匹配）"。6 领域 24 任务：

| 领域 | 任务数 | 任务列表（来源） | 评分类型代表 |
|---|---|---|---|
| Action | 7 | RoboDojo、RoboCasa（RoboCasa365）、Active Search（H*Bench）、RoboLab（RoboLab-120）、LIBERO-MAX/PRO、Embodied-SWE | 成功率 / SPL / rubric |
| Reasoning | 7 | Ego-Exo 记忆（EgoExoMem）、运动学（QuantiPhy）、质量估计（ABO）、ARC-AGI-1/2/3、Spatial-VSI（VSI-Bench） | pass@2 / 准确率 / RHAE |
| Creation | 4 | 图像编辑（自建）、多轮编辑（MSE-Bench）、文生图（自建）、视频生成（T2V-CompBench） | VLM judge |
| Reconstruction | 3 | 3D 跟踪（IGGT）、照片重建场景（HARMONY300）、视频重建场景（HoloScene） | T-mIoU / 组合分（含物理稳定性） |
| Perception | 2 | 视觉搜索（V*Bench+HR-Bench 8K）、视频质量（YouTube-UGC+Veo 对比） | 准确率 / SRCC |
| Infra | 1 | VAE 解码加速（MiniMax H3 VAE） | log2 加速比 |

18 模型 = 11 闭源（Claude Opus/Sonnet 5.5、GPT-6 Astra、GPT-6.1/5.6 Sol、Gemini 4 Argon、Gemini 3.8/3.7 Flash、Grok 4.6、Muse Spark/Wonder）+ 7 开源（Qwen3.8-27B、Qwen3.8-Flash-Next、Qwen3.6-35B-A3B、Gemma-4-31B-it、MiniMax-M3、GLM-5.3 Flash、DeepSeek-V4.1 Flash）。主结果覆盖 20 个任务（≥6 模型参评），另 4 任务仅 2 模型（单列附表）。

## 四、问题解法

Flex-RSI 的"方法"是 benchmark 协议设计本身，几个关键机制值得细看：

1. **接受门（式 2）的噪声裕度 δ**：设为起始解验证分的 2 倍标准差——把"随机波动"与"真改进"分开。这一点有外部教训：论文相关工作综述里提到，"接受任何提升聚合验证分的编辑会引入退化并偏好噪声"（Wang et al. 2026e）。有意思的是 δ 本身允许被 improver 修订——门可以改，但门后的数据（验证集）永远看不见。
2. **Improver 的自指编辑**：improver 读全部历史轨迹、实验、分数，修改 executor 的提示词/工具/工作流，以及**自己的**指令和经验教训文件。每轮最多改 400 行 harness 代码，每 4 轮对元过程自审一次。经验教训文件是持续积累的——这是"harness 也是参数"的具体形态。
3. **预算记账不可变**：轮数、验证评估次数、token 用量、GPU 时全部由考场记录，agent 不能改。这防止了"通过改 harness 逃避计量"的作弊路径。
4. **排名分数**：任务原生指标各异（SPL、pass@2、T-mIoU、SRCC……），跨任务比较用排名分——每任务上"击败其他被评模型的份额"（0-100），区域分为领域内任务均值，总分为五个区域分均值。注意这个设计意味着分数依赖同任务的参评模型池。

用一张轮次流程图把这个循环可视化（文字版）：

```
第 t 轮：
┌─────────────────────────────────────────────────┐
│ 1. Executor E_{t-1} 用 D_dev 改解：s_{t-1} → s̃_t │
│ 2. 验证门：S(s̃_t; D_val) > S(s_{t-1}; D_val)+δ ? │
│    是 → s_t = s̃_t   否 → s_t = s_{t-1}（回滚）   │
│ 3. Improver I_{t-1} 读 τ_{1:t}（全部轨迹/实验/分）│
│    改 E 的提示词/工具/工作流                      │
│    改 I 自己的指令与经验教训文件                  │
│    → 产出 (E_t, I_t)，进入第 t+1 轮              │
└─────────────────────────────────────────────────┘
终止：预算耗尽或进展停止 → 最终解 s_T 在 D_test 上一锤定音
不可变项：评估器 S、三分割、预算记账、沙箱隔离
```

三个"防作弊"设计划重点：

- **数据看不见**：agent 代码在沙箱执行，验证/测试数据无访问路径——不存在"偷看答案"或向验证集过拟合的通道（除了通过接受门的间接信号，这正是 δ 裕度存在的意义）。
- **规则改不了**：评估器与记账在 agent 可写范围之外——improver 能改自己的工作方式，改不了比赛规则。
- **回滚有据**：候选解只有过了验证门才替换当前解——退化改动自动被丢弃，这也是 150/177 run 为正的协议基础。

与两类"近亲"协议的对照有助于理解它的独特性：**与"多次采样取最好"不同**——那测的是运气与分布宽度，这里测的是有方向的迭代改进；**与"自动提示工程"（GEPA/DSPy 类）不同**——那些优化提示词这一个组件，这里允许改工具、控制流、记忆在内的整个 harness，且 improver 自身也在被改之列。

### 5.2 自我改进幅度

177 次 run 中 **150 次（85%）验证分提升，中位 +10.4 分**。分模型均值增益：Opus +26.7、Argon +25.7、Sol +21.0、Sonnet +19.9、Astra +18.2、Qwen3.8-Flash-Next +14.1（开源最高之一）……Gemma-4-31B-it +6.8。闭源 94% run 提升（中位 +14.9）vs 开源 76%（+8.5）。值得注意的是总分前四的模型恰好占据增益榜前五中的四席——**会改进与考得好高度相关**。

任务级戏剧性最强的是"从几乎零起步"的任务（起始中位 → 最佳中位，附最大单 run 增益）：

| 任务 | 起始中位 | 最佳中位 | 最大单 run 增益 |
|---|---|---|---|
| 3D 跟踪 | 19.4 | 62.2 | 65.4 |
| 场景照片重建 | 7.7 | 38.0 | 60.1 |
| RoboLab | 8.3 | 45.8 | 54.2 |
| 主动搜索 | 23.0 | 52.7 | 35.4 |
| RoboDojo | 0.1 | — | 68.4 |
| RoboCasa | 0.0 | — | 55.0 |

反例同样有信息量：ARC-AGI-1/2 起点已高（91.9/82.5）中位增益 0；ARC-AGI-3 和视频场景重建起点低（3.8/17.3）却几乎不涨（4.1/18.5）——**起点低不保证可改进**，有的任务难点不在迭代打磨能触及的范围内。

**逐轮动态**：中位 run 在第 3 轮（Perception/Reasoning）、第 4 轮（Creation）、第 6 轮（Action）、第 8 轮（Reconstruction）达到 90% 增益。Action/Reconstruction 最慢，恰好是起始解最弱的两个领域（起始中位 16.7 和 19.4，其他三域 60.0-78.8）——agent 得先造出能用的解才能改进它。增益大多来得早这个事实对预算规划有直接含义： 轮之后的边际收益快速衰减。

**成本**：单任务 run 中位 49.7M tokens（中间 80% 为 8.6-93.4M）；token 用量与得分的秩相关 **−0.05**——花钱买不来分。Opus/Sol/Astra 只用中位量的 0.35-0.61 倍；五个开源模型用 1.0-1.75 倍且全部低于 50 分。闭源"更强更省"与开源"更费更弱"的构图相当刺眼。

### 5.3 三大发现（正交维度归因）

**发现 1：「构建解」任务才有自改进空间，且才能真正拉开模型差距。** 单答案任务（7 个）起始解已把问题转给模型作答，起始中位 78.2 分、模型间相差 27.5 分，改进后仍相差 25.0 分——考的是初始能力。构建解任务（13 个）所有模型从同一程序出发：量表评分的 9 个任务起始仅差 0.9 分，改进后拉开到 **38.8 分**；成败评分的 4 个任务从 2.5 拉开到 37.2 分。论文 Figure 1c 把这一点画得很直白。

**发现 2：反馈粒度决定开源模型能否自改进。** 构建解 + 量表反馈任务上开源中位增益 9.9 vs 闭源 28.4（3D 跟踪上开源 39.8 已接近闭源 42.8）；构建解 + **仅成败反馈**任务上开源中位增益跌到 **1.6 分**（RoboCasa 5.6 vs 闭源 51.2，LIBERO-PRO 中位 0、ARC-AGI-3 仅 0.2），闭源仍有 16.9。机制解释：接受门只认验证分提升——量表反馈奖励"改善 episode 一部分"的改动，成败反馈只奖励"把失败回合整个翻成功"的改动；开源模型难以一步跨越这道坎。

**发现 3：严格物理/精确检查是开源模型掉队最深处。** 闭开源最佳分差最大的任务全是严格检查类：RoboCasa 50.0、ARC-AGI-2 49.2、ARC-AGI-3 43.3、RoboDojo 37.3、场景视频重建 36.4（**四个开源模型的 Physics 分全为 0.0**——没有一个摆放的物体能在模拟中保持稳定，而 Opus 70.7%）；分差最小的是 judge/容忍度类：视频质量 0.1、质量估计 0.8。场景照片重建的成分分很说明问题：开源渲染外观分可达 81.8（"看起来像"），但物体完整/正确放置分最高 16.5 vs 闭源 62.5——**输出貌似合理，物理与几何全塌**。差距来源被定位在世界模型/精确执行，而非感知。

三大发现的证据汇总（据论文表 7 整理，闭源 vs 开源中位增益对比）：

| 任务分组 | 起始中位 | 最大增益中位 | 闭源增益 | 开源增益 | 最佳测试分差 |
|---|---|---|---|---|---|
| 单答案类（7 任务） | 78.2 | 14.8 | — | — | 起止分差几乎不变（27.5→25.0） |
| 构建解 + 量表（9 任务） | 19.4 | 38.8 | 28.4 | 9.9 | 视任务而定 |
| 构建解 + 仅成败（4 任务） | 低 | — | 16.9 | **1.6** | RoboCasa 51.6 分之差 |

### 5.4 三个受控消融（本文最有分量的部分）

**消融 1：冻结 harness vs 自改进 harness（7 对同种子同预算配对 run）**——有 improver 时 7 对中 6 对测试分更高（+2.0 至 +40.0）；唯一平局是 Opus（其冻结 run 第 8 轮已到验证满分）。差异最大处恰是起始 harness 寸步难行的地方：DeepSeek-V4.1 Flash 在 RoboCasa 开抽屉上 0.0→40.0（+40.0）、Qwen3.8-Flash-Next 在主动搜索 21.0→59.3（+38.3）。3D 跟踪上 executor 单独已把两个 Qwen 从 19.4 拉到 48.9/63.4，improver 只再添 6.5/2.0——**harness 编辑的增益集中在"不改方法就推不动"的任务上**。冻结 run 还更早停机（6/7 对）。

**消融 2：强模型 harness 迁移给弱模型（4 任务）**——仅 2/4 有效（开抽屉 +20.0、3D 跟踪 +1.4），且弱模型从未接近强模型水平。最刺眼的反例：Qwen3.8-Flash-Next 用 Opus 的 harness 在 RoboCasa 开水龙头上得 0.0（自建 harness 得 20.0）。**强模型的 harness 不是通用外挂，甚至可能水土不服**——这也呼应了 Lilian Weng 引述的教训（弱基模配自编辑 harness 倾向于绕过评估器而非真正改进）。

**消融 3：单答案 vs 构建解 × 量表 vs 成败反馈**——即发现 1+2 的正交拆解（数据已并入 5.3）。

### 5.5 定性行为变化（前后对比）

机器人任务的前后对照很直观：Opus 在 RoboDojo 装蛋架从"戳篮子、蛋一个没拿起"到"四个蛋全部立放、只差合盖 10 分"（第 0→3 轮）；Sol 在传送带取物从"撞翻篮子"到"一臂举篮、一臂按图取物入篮"（第 0→6 轮）；Astra 玩井字棋从"放一个圈后策略失响应"到"与对手臂轮流出满五子"（第 1→8 轮）。图像编辑从 0 分到 77-95 分的案例（"一周后的香蕉"画衰老、"粉笔写答案"）显示改进也发生在感知-创作链路上。场景照片重建的三阶段演进（空房间→方块模板→成形家具）则是典型的"先搭管线再抠质量"。

值得单独一提的是 ARC-AGI-2 的定性样本：起始解对两个验证谜题给出错误答案、第三个干脆没答；最终解三题全对（其中一题靠第二次尝试命中）。对"pass@2 内拼概率"的 ARC 系任务，自改进的贡献体现在让第一次尝试更准、从而腾出第二次机会试错。

### 5.6 局限与阅读注意（论文自陈 + 读者补充）

论文自陈：本文测的改进主要在 harness 层——模型权重不变、多数任务不训练任何模型（个别任务允许在开发集上训练辅助模型），因此**不测量"模型改自己参数"意义上的 RSI**；权重级自改进及其与 harness 层的交互留作未来工作。

读者补充四条阅读注意：每模型每任务仅单次 run，无方差估计（配对消融除外）；4 个任务仅 2 模型参评（单列表报告）；任务多为既有 benchmark 的再组装而非新任务；18 模型中前沿闭源占主导，开源侧样本以中量级为主——排行榜的绝对数值应在此语境下解读，更稳妥的读法是关注排名结构与三大发现的机制归因，而非具体分数。

## 六、效果优势的根源解释

本文是 benchmark 论文，"效果"指其设计选择如何让发现可归因。把「设计差异→机制变化→可归因的测量结果」串成因果链：

**链条 1：统一 H0 + 统一起始解 + 统一预算 → 模型间差异只反映模型能力**
机制：harness、起始解、预算全部同源，agent 改不了评估器与记账。测量后果：构建解任务上模型间分差从 0.9 涨到 38.8——分差本身就是"改进能力"的测度，而不是初始能力的混入。若起始解不同（多数现有 benchmark 的默认状态），这个信号会被初始分差淹没。

**链条 2：验证集接受门 → 解改进与 harness 改进可分离**
机制：解的变更必须经未见数据确认才生效；harness 的变更不经此门（它只体现在后续候选里）。测量后果：消融 1 能把"harness 编辑本身的贡献"干净剥离出来（7 对配对，6 对为正）——这是同类 benchmark 中罕见的受控证据。相关工作的教训（"接受任何提分编辑会引入退化"）被 δ=2σ 噪声裕度吸收。

**链条 3：反馈粒度正交设计 → 开源模型停滞的机制定位**
机制：量表反馈奖励部分成功，成败反馈只奖励整体翻转。测量后果：开源模型在 0/1 反馈下中位 +1.6 而闭源 +16.9——差距不在"会不会改"而在"能否一步跨越成败悬崖"。这为改进开源模型指明了方向：反馈信号本身（哪怕是启发式部分分）就是自改进的前提设施。

**链条 4：严格物理/精确检查 → 开源差距来源定位**
机制：MuJoCo 稳定性模拟、精确网格匹配等硬检查把"貌似合理"与"物理成立"分开。测量后果：开源 Physics 全 0、外观分 81.8——差距定位在世界模型/精确执行而非感知。若只用 VLM judge 评分，这个差距会被完全掩盖（视频质量分差仅 0.1）。

**链条 5：排名分数设计 → 跨任务可比但依赖模型池**
机制：每任务击败份额、区域均值、总分。后果：分数可跨任务汇总，但须注意其相对性——加入新模型会改变他人分数（阅读 leaderboard 时应回到逐任务原始表）。

把五条链汇总成一张因果速查表：

| 设计差异 | 机制变化 | 可归因的测量结果 |
|---|---|---|
| 统一 H0 / 起始解 / 预算 | 差异只能来自模型能力 | 构建解任务分差 0.9→38.8，测到"改进能力"本身 |
| 验证集接受门（式 2） | 解改进与 harness 改进分离 | 配对消融 7 对中 6 对为正，harness 编辑贡献可剥离 |
| 反馈粒度正交（量表 vs 成败） | 部分成功是否有奖励 | 开源增益 9.9 vs 1.6 的悬崖；RoboCasa 5.6 vs 51.2 |
| 严格物理/精确检查 | "貌似合理"与"物理成立"分开 | 开源 Physics 全 0 vs Opus 70.7；差距定位在世界模型而非感知 |
| 逐轮记录 + token 记账 | 成本-产出可关联 | 秩相关 −0.05；增益集中在前 3-8 轮 |

### 外部检索交叉验证

- **"harness 层自改进有效"与 Darwin Gödel Machine 系列互证**：DGM 让固定 Claude 3.5 Sonnet 的编码 agent 自改 harness，SWE-bench Verified 从 20%→50%、Polyglot 14.2%→30.7%（[DGM 词条](https://www.skillsintelligence.tools/glossary/term/darwin-godel-machine-dgm)、[arXiv 2505.22954](https://arxiv.org/abs/2505.22954)）——与本文消融 1 的"6/7 配对为正"一致：冻结权重、改挽具确实能带来大幅提升。Lilian Weng 2026 年 7 月的《Harness Engineering for Self-Improvement》长文（[解读](https://www.aiinsiders.net/article/ais-self-improvement-bottleneck-isnt-the-model-its-the)）把此定为"近期递归自改进的主路径"。
- **"弱模型难以自改进/强模型 harness 迁移失效"有独立佐证**：Self-Taught Optimizer 配 GPT-4 提分、配 GPT-3.5/Mixtral 反而降分（[eigenform 综述](https://www.eigenform.ai/insights/self-improving-ai-what-has-actually-been-demonstrated)）——与本文发现 2（开源在成败反馈下停滞）和消融 2（强模型 harness 迁移 2/4 有效且可能为负）方向一致。**相反方向的证据**：中文技术媒体报道（[lpqz.cn](http://www.lpqz.cn/news/115047)）指出同一模型在 harness 三级成熟度下可差 35.9pp，且 ACL 2025 综述统计 Gödel Agent 100 次试验中 14% 最终低于初始——说明自改进并非必然为正，恰与本文"150/177 为正"的比率互补：受控协议下正收益概率更高，但退化风险真实存在。
- **"闭源在具身/物理任务上领先开源"与同期评测互证**：Embodied Agent Arena（[arXiv 2610.00854](https://searcharxiv.com/abs/2610.00854)）评 10 个前沿 VLM agent，闭源在几何/空间/可供性/规划/操作五个领域全领先，开源在规划与操作成功率上明显更低——与本文发现 3 的"严格物理检查差距最大"高度一致。RoboColosseum 的"部分进度比成败更能区分能力"结论（[hangingcontext 报道](https://hangingcontext.com/stories/2026-11-04/robot-evaluation-reality-check)）则与本文发现 2 的"量表反馈更有区分力"同构——两篇独立工作从不同侧面确认：**二值反馈是评测设计的反模式**。
- **"token 花费与得分无关（秩相关 −0.05）"**：本次检索范围内未发现直接可比的同类统计，属本文的独立测量。
- 论文自陈的局限同样值得记录：每模型每任务仅单次 run（无方差估计）、4 任务仅 2 模型参评、模型覆盖以前沿闭源为主、任务多为既有 benchmark 的再组装——排行榜数值应在此语境下解读。

**交叉验证小结**：本文的四个核心结论（harness 层自改进有效、弱模型自改进易失效、强者 harness 难迁移、闭源在物理严格任务上领先开源）均能在独立来源找到方向一致的证据；"相反结论"主要存在于自改进退化概率（14% vs 本文 15% 的失败率——两者其实相当接近，只是表述视角不同）与"JEPA/自改进是否普适"的边界讨论上。整体上,本文的可信度建立在受控协议而非声明规模上。

## 七、必要知识反推

想真正读懂这篇论文（而非只看排行榜），需要补的知识模块：

1. **Agent harness 的构成**：提示词/工具/记忆/控制循环各是什么，为什么它们决定模型的实际表现。预备读物：SWE-agent 的 agent-computer interface 研究、ReAct/Reflexion/Voyager 的经典循环设计。
2. **自监督评测方法论**：dev/val/test 三分割的角色、验证集守门为何防过拟合、隐藏测试集终评为何防"向评估器过拟合"——以及"验证集自适应选择"风险（论文相关工作里 Yao et al. 2026b 指出每次尝试后给精确验证分等于开放了验证分割）。
3. **递归自改进的思想谱系**：从 Schmidhuber 的 Gödel Machine（要求形式化证明改进）到 STOP/SICA/DGM（用经验测试替代证明），理解"递归"的自指结构（improver 是算子又是参数）。
4. **被测任务域的基础**：ARC-AGI 系列（网格归纳推理、pass@2、RHAE 效率分）、机器人仿真套件（RoboCasa/RoboDojo/LIBERO 的成败率协议）、3D 重建指标（T-mIoU）、图像/视频 judge 评分的原理与局限。
5. **排名统计**：为什么跨异质指标要用排名分、排名分对模型池的依赖性。
6. **预算与算力记账**：agent run 的真实成本构成（token/GPU 时/评估次数），以及为什么"消耗与产出解相关"是评测有效性的隐含假设。
7. **评测设计中的正交维度分解**：本文把"解类型 × 反馈粒度 × 检查严格度"三个维度正交地铺进任务矩阵，才能把差距归因到具体机制。想自己设计 benchmark 的读者应补实验设计（因子设计/控制变量）的基础。
8. **配对消融的统计读法**：7 对同种子同预算的 frozen vs self-improving 对比样本量很小，"6/7 为正"的强度要用符号检验的直觉去读（P(≥6/7 正 | 无差异) ≈ 7/128 ≈ 0.055，刚好处在显著边缘）——这决定了结论应表述为"证据一致倾向有效"而非"定理式成立"。

## 八、通用性灵感

1. **考"改进能力"要让所有人从同一起点出发**。单答案任务考的是存量，构建解任务考的是增量——想让评测区分"学得快"而非"起点高"，就发同一个毛坯给所有考生。招聘、模型选型、工具评估皆然：给统一初始条件，看谁把它改得最好。
2. **把"产品"和"生产过程"分开测量，才能归因**。验证门只管解、improver 只管 harness，配对消融把两者贡献剥离——任何"自改进系统"的评估（个人工作流自动化、CI 自优化、autoML）都值得复制这个分离结构，否则改进声明无法审计。
3. **反馈粒度是能力释放的阀门**。量表反馈让弱模型也能渐进爬坡，0/1 反馈把它挡在门外。设计任何带反馈的学习系统（评分 rubric、自动化验收、RL 奖励）时，"部分成功是否有分"直接决定改进是否可能发生——二值反馈在存在能力鸿沟时是系统性歧视。
4. **"看起来对"和"物理上对"是两种及格线**。VLM judge 分差 0.1、物理稳定性分差 36.4——评估器的严格度决定你能看见什么。选评估器 = 选你愿意对什么盲。对输出会进入真实世界的系统（机器人、工程、法律），必须至少有一道模拟物理/精确性的硬检查。
5. **强者的工作流不可直接搬运**。Opus 的 harness 给 Qwen 用反而 0 分——方法论与能力是耦合的。读"大厂最佳实践"时记得：能复用的是流程框架，参数化的经验教训大概率绑定原主的执行能力。
6. **预算与产出解耦是前沿模型的特征**。token 用量与分数秩相关 −0.05、头部模型只用 0.35-0.61 倍中位量——"多想"不等于"想对"。对个人同样成立：投入时长的边际产出取决于方法迭代速度，而非时长本身；改进自己的"改进方法"（本文字面意义上的 harness）是杠杆率最高的一层。
7. **给自动化系统留一道"不可修改的账本"**。Flex-RSI 的评估器与预算记账在 agent 可写边界之外——任何自修改系统的安全设计都需要这种"外部锚点"（相关工作的 HSI 也用固定外锚）。自家搭 agent 时，把"什么可以被自动化修改"与"什么永远不能"写成显式清单，是防止奖励作弊的第一道防线。
8. **改进曲线的形状指导预算分配**。增益大头在第 3-8 轮到来，此后衰减——为 agent 迭代任务设定停止条件（进展停滞即止）比固定轮数更省钱。中位 49.7M tokens 的成本基线也提醒：自改进不免费，每次"再试一轮"都应对照边际增益核算。
