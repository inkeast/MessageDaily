## 先说结论

这是 Latent Space 在 AI Engineer New York 2026 大会现场的短访谈（采访者 Richard MacManus，嘉宾 Aman Singh，Arca 的 AI 平台团队负责人；节目官方页面核实身份，发布于 10 月 31 日）。Arca 是一家「AI 原生」财富管理公司——注意不是给理财公司卖软件的 SaaS：「我们自己就是这家公司（We are the firm ourselves）」。访谈最值得记住的一句是 Singh 的「**Agent 提示人，多于人提示 Agent**」：客户从不直接接触 AI，顾问也不再给 AI 派活，而是 7×24 小时运行的后台代理主动分析每个客户的处境、在正确的时间把正确的人拉进流程。支撑这个模式的是四件工程实事：跨十天的长周期记忆系统、把资金动作锁死在人手里的确定性护栏、「能力边缘收口」的多层验证，以及把员工每一次修改都变成 eval 的反馈闭环。对做 Agent 系统的读者，这是一份罕见的「AI 原生服务公司」参考架构；对观察行业的人，它演示了当 Anthropic 们开始卖金融行业方案时，应用层公司的差异化护城河还剩什么。

## 不是 SaaS，是公司本身：「AI 原生」的准确含义

Arca 的业务是全方位财富管理：财务建议与规划、税务规划、保险、遗产规划；客户从刚卖掉公司的企业主、筹划提前退休的大型科技公司高管，到攒钱买首套住房的小家庭（0–120s）。Singh 反复强调一个区分：**「拥有 AI 工具的服务公司」要求用户去提示 Agent 干活，而「为 AI 原生而建的公司」里 Agent 主动运行整个业务**（840–960s）——客户体验到的只是「这个行业从未有过的服务响应速度」，由人类顾问的共情来交付，AI 替换掉的是顾问周围的所有后台工作。因为自己就是业务方，Arca 能把工作流程本身标准化，让 Agent 以标准化方式参与工作；也能强制内部员工在每次修改或取消 Agent 结果时填写「为什么」——这两个前提对 SaaS 公司都不成立。融资方面，节目口播称「recently raised 64 million dollars」，而 Latent Space 官方文案写的是 **4850 万美元、General Catalyst 领投**（Index Ventures、Venrock 跟投）——两处口径不一致，如实并列。

## 长周期而非长运行：十天任务的记忆与信号系统

Singh 在大会演讲里给出的关键区分是 **long-horizon ≠ long-running**：Arca 的任务不是 Agent 连续磨几天 token，而是一个客户目标横跨十天、走走停停、多角色多决策点多交接。访谈里用「客户邮件来了一张税单、需要在组合里筹出十万美元」举例（240–480s）：分析环节——客户的钱现在都在哪、怎样清算最优化——完全由 Agent 自动完成；但**任何资金划转、资产清算、以及直接联系客户的动作都被严格的人类在环护栏挡住**。与托管方（custodian）有很深的 API 集成，技术上能自动执行，但策略上不允许。Agent 的产出是一份给专家审阅、可调整的执行计划。跨天恢复靠两套机制：**信号系统**把新邮件回复路由给已在跟进的既有 Agent，而中途插入的一通电话是全新信号、会唤醒一个新 Agent；**持久记忆**为每个客户维护「现在在办什么、谁负责什么、到目前为止发生了什么、未来几天与长期各在追什么」，新 Agent 靠它秒速进入状态。还有一个 Singh 称为「**做梦过程**」（dreaming process）的反思机制，定期回顾与客户相关的世界状态、把长周期任务的进展写回记忆——这与本博客此前介绍过的若干「反思式记忆」实践互为印证。「Agent 提示人」也由此落地：通过记忆+每日反思，Agent 判断世界状态到了哪一步、该把哪位专家在什么时机拉进来——就像人类团队里第七步的执行者不必知道第一至六步的细节。

## 安全与合规：确定性护栏加「能力边缘收口」

金融业务的验证体系是本期信息密度最高的部分（480–720s、960–1200s）。原则一：**所有安全限制全部是确定性的，把决策权从 Agent 手里拿走**——简单记账类工具 Agent 可自己执行，涉及风险的一律不行。原则二：**在能力边缘收口，而不是更早**——不过度约束 Agent 内部行为，但在每个出界点设卡。具体四层：每次写数据库的工具调用都伴随快速 LLM 验证；外来的邮件、文档、电话都是提示注入目标，在入口处做注入特征检测；数据离开系统时（Web 搜索、给客户 Richard 发日历邀请）先过确定性 PII 检查，再由多个小模型**共识**判断是否有数据外泄企图；沙箱方面 Agent 本体不在沙箱里，而是把计算卸载到沙箱——Agent 用代码查询公司数据做聚合加工，产出物（如给客户的财务规划 PDF）被翻译成严格格式、代码本身被丢弃，产出物再过确定性检查（如裸账号号码）与小模型合规审查（如是否在承诺收益）。Singh 的一个反直觉论断：这比人做合规**更好**，因为「AI 不知疲倦地找出最小的不合规表述」。合规侧，审计是默认能力：Agent 的每个动作产生「改了什么、谁改的、从系统哪个部分、何时」的变更日志，人类在 UI 上的动作同样入账——同一份日志反哺 Agent 循环。模型选型同样服从内部证据：Claude 是当前主力（此前历经 Gemini→OpenAI→Anthropic），按任务复杂度分层（税务分析用最重的 Opus/GPT 级，后台杂务用轻模型），顾问对此完全无感；外部基准再风光的模型（他点名 Luna「又慢又贵」）过不了内部基准就不用——**模型无关、harness 自有**是两条红线。也因此他对 Anthropic 新推的托管 Agent 基础设施态度明确：模型可以买，「记忆与运营知识那一层外包出去，等于把智能的所有权交出去」。对 Anthropic 进军金融服务，他的评价是「对行业是验证」，但「带 AI 工具的服务公司」与「AI 原生公司」是两个物种。

## 反馈闭环与知识库：把员工纠错变成 eval

改进机制同样成体系（1200–1440s）：员工的每次修改/取消带着强制的「为什么」，反馈与产生它的 Agent 轨迹配对入库；**每晚一个元 Agent 跑真实轨迹**，提出 harness 改进建议（误导性的工具、报错、知识库缺漏），但 prompt 变更出货前仍有人类工程师把关——因为「放任 Agent 自己改 prompt 会改得很脏：每个小修复都会膨胀成整个 prompt 重写，它们无法保持元层面、把修复泛化」。知识库是产品的一等公民：左侧 Knowledge 标签里是 Agent 正在使用的全部运营上下文，由内部专家维护，Agent 工作时会引用知识，引用出错会在轨迹分析中暴露、专家直接编辑修正。效果案例（1440–1560s）：一位尚未签约的准客户带来全套材料，Agent 读完后发现其现有顾问（收费 1500 美元还不回消息）**在收他不知情的费用、且根本不是受托责任（fiduciary）身份**——这种细节注意力是规模化人类团队做不到的；日常还包括主动提醒截止日、防止错过 RMD（法定最低分配额）等「对人类难以规模化、对 Agent 是默认行为」的服务。

## 机制与启发

三条可迁移链条：**其一是「长周期」的设计范式**：把多天、多角色、停停走走的业务建模为「信号→持久记忆→反思→在正确时机拉人」，而不是追求单个 Agent 连续运行——对一切有交接环节的专业服务（法律、税务、医疗随访）直接可搬。**其二是护栏的位置学**：确定性规则管死高危动作、LLM 验证管写操作、共识小模型管出边界、人类在环管资金与客户触点——「在能力边缘收口，而不是更早」避免了把 Agent 管死又保住了风险面；审计日志与 Agent 循环共用一份事实，是合规成本变能力成本的样本。**其三是应用层护城河的重构**：当模型厂开始卖行业方案（Anthropic 金融服务、托管 Agent），Arca 的回答是「拥有 harness 与记忆层=拥有智能」，外部基准不可信、行业知识库与 eval 数据才是资产——这预示 AI 应用的竞争正从「谁的模型好」转向「谁的业务能被标准化并被 Agent 参与」。观察指标：Arca 何时（是否）放开自主交易；托管 Agent 产品与自建 harness 的边界会不会被 Anthropic 的平台化挤压；以及「Agent 提示人」的交互范式能否走出财富管理这个高客单价场景。
