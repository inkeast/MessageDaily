## 一、论文背景

### 1.1 推理模型的成本悖论：什么题都想一遍

Kahneman 在《思考，快与慢》里把认知分成两个系统：System 1"自动快速运转，几乎不费力，没有主动控制的感觉"；System 2"把注意力分配给那些需要它的费脑活动"。这个划分塑造了大模型推理的设计哲学——但受它影响的工作要么造一个好的 System 2，要么造一个好的 System 1，**一个模型同时是两者**这件事长期没人做。

现状是两个极端各自繁荣：

1. **System 2 阵营（推理模型）**：GPT-6、Claude Fable 5、开源的 Qwen3.8，都在答案前写一长串思维链（chain of thought）。代价是每一道题都要付 token 和延迟——哪怕是"1+1=?"。一篇 2026 年的工程分析估计，对分类这类思考毫无帮助的任务，思维链让 token 开销膨胀 2 到 5 倍、每次调用多等 5 到 15 秒。
2. **System 1 阵营（零生成决策模型）**：Jev、AnyJev 等模型走极端路线，推理时不生成任何 token，单次非自回归前向直接出答案。它们大多是从推理模型 backbone 改造而来，快是快了，难题就不行了。

中间派的工作都在"把思维链变短"：限制长度、压缩轨迹、按 token 分配深度。这些方法让思维链**更便宜**，但没有让它**可选**——它们问的是"推理应该跑多久"，而不是"这道题到底需不需要推理"。

### 1.2 zero-or-T thinking：把"想多久"换成"要不要想"

论文提出的范式叫 **zero-or-T thinking**：一道题的成本要么是 0（一次前向传播内部的隐式思考直接出答案，零 token 生成），要么是 T（完整自回归推理的 token 数），**没有中间档位**。

这个二值化设计比看起来激进。现有自适应推理方法缩短思维链、或跳过部分推理，答案最终仍是一个 token 一个 token 写出来的；zero-or-T 直接取消了"便宜地写答案"这个选项——要么不写，要么完整地想。论文的一句核心表述值得记住：**与其决定想多少，不如决定自回归思考是否根本需要发生**（rather than deciding how much to think, the model decides whether autoregressive thinking is needed at all）。

### 1.3 关键分歧：uplift 路由 vs 置信度路由

实现这个范式需要一个路由器：每道题来的时候，判断走快模式还是慢模式。主流做法是**置信度路由**——快模式答完看看自己多确定，不确定就升级去想。

论文指出置信度答错了问题。置信度回答的是"我对快答案多确定"，而路由器需要回答的是"慢模式会不会给出不一样的答案"。这两个问题在两个方向上都会分离：

- **快对慢也对**：模型很确定，也想不出更好的——思考纯属浪费，但置信度路由发现不了这一点，只要置信度不够高就会触发一次无谓的升级；
- **快对、慢反而错**：思考有时会把快模式本来对的答案想歪（overthinking 文献里的"convergence problem"：模型沿正确方向出发，想着想着被自己引入的备选方案带偏）——这时升级是有害的；
- **快错、慢对**：这才是升级真正赚钱的地方。

换句话说，正确的路由信号是**思考这一干预的因果增益**（uplift / treatment effect），而不是**当前答案的可信度**。这是全文方法论上的胜负手，后文详述。

## 二、论文定位和关联工作

论文把相关工作的谱系梳理成四支，HDM 的独特位置在于"零 token 模式 + 增益信号 + 免费路由"三件事同时成立：

| 方法（年份） | 切换对象 | 路由信号 | 慢模式形态 | 额外前向 | 与 HDM 的关键差异 |
|---|---|---|---|---|---|
| FrugalGPT / RouteLLM（2023/2024） | 模型之间 | 偏好数据 / 二分类器 | 更强的另一个模型 | 是 | 选的是"贵的答案 vs 便宜的答案"，两边的答案都要生成 |
| ThinkSwitcher（2025） | 长/短思维链 | 两模式通过率之差的阈值 | 同一 backbone 两种提示 | 是 | 两种模式都自回归解码，选的是"写多少推理"；复现显示其选题质量低于随机升级（352 vs 213 token） |
| AdaptThink / AdaCoT / Thinkless / LHRM（2025） | think / no_think 模式 token | RL 奖励（长度惩罚） | 同一模型的完整推理 | 混入生成 | 训练 backbone 本身，模式靠生成特殊 token 决定 |
| Self-Route / 置信度路由（2025） | 思考模式 | 隐状态能力估计 / 输出置信度 | 完整推理 | 预推断探测 | 信号预测"答案对不对"，不是"思考能不能救回" |
| LEV（2026） | 循环深度 | 答案随深度是否收敛 | 重跑自身层（无生成） | 否 | 旋钮仍是"想多深"，不是"要不要想" |
| AnyJev（2026） | 零 token 决策是否升级 | 固定 top-2 边际（规则） | 完整推理 | 是 | 最接近的工作，但路由规则是手工边际阈值而非学习的增益预测器 |
| **HDM（本文 2026）** | **零 token vs T token** | **思考的增益 vi（uplift）** | **同一冻结 backbone 的自回归推理** | **否** | — |

三个定位要点：

1. **对"缩短思维链"一支**（s1、L1、TokenSqueeze 等）：它们让思考更便宜，HDM 让思考可选——量纲从"多少"变成"是否"。
2. **对"模式切换"一支**（ThinkSwitcher、AdaptThink 等）：它们切换的两种模式都自回归解码答案，且路由信号大多在答案之外单独计算（模式 token、外部分类器）；HDM 的快模式零生成、路由信号从快模式已算出的隐状态免费读取。
3. **概念溯源**：论文预测的那个量在三个领域里早有名字——元推理里的"计算价值"（value of computation，Horvitz 1987、Russell & Wefald 1991）、uplift 建模里的"处理效应"（treatment effect）、learning to defer 里的"延迟决策"。**新的不是概念，而是为同一个网络的两种模式、从该网络自己已产出的状态里估计它**。

## 三、问题定义

### 3.1 抽象化：一个二值决策，而不是一个预算

给定一个请求（提示 + 可选的显式问题 + 候选答案集），模型要在**任何 token 生成之前**做一个二值决策：这道题用隐式思考（零 token）直接回答，还是升级到自回归推理（最多 B 个 token）。决策必须满足两个约束：决策时两种模式的对错都尚未可知；决策只能读取模型已经算出的量——不增加前向、不增加 token。

### 3.2 形式化：思考的价值与思考的价格

把模式 m 在题 i 上的效用定义为对错 u_i(m) = a_i^m ∈ {0,1}。快慢两模式都跑一遍的话，一道题必然落入四类之一：**都对 / 只有快对 / 只有慢对 / 都错**——这个四分类是全文的骨架。

正确的答案是值得等的，但等本身有代价。论文用**指数折扣**给"答案迟到"定价：每个生成的 token 让效用乘以 e^(-ρ)，即

```
r_i(m, ρ) = u_i(m) · e^(−ρ·T_i^m)
```

慢模式只在"思考的价值超过价格"时运行。思考的价值定义为两模式成功率的**对数比**：

```
vi = log [ P(slow✓) / P(fast✓) ]
```

当且仅当 vi > λ 时升级。λ 是**按请求设定的思考价格**（price of thinking）——一个可解释的业务旋钮，不是按 benchmark 调出来的超参。λ=0 意味着"只要思考有正增益就升级"；λ 调大，模型就越来越抠门。

两个设计细节值得玩味：

1. **为什么是对数比而不是差值**：线性价格在增益最大的地方反而收缩（log 让量纲对称），且 vi > λ 精确等价于"思考把答对的概率提升至少 e^λ 倍"——一个干净的概率语义。
2. **为什么按题统一计价 λ 而非精确的 ρ·T_i^slow**：每题慢模式的真实长度 T_i^slow 只有跑完才知道，所以按平均长度 ¯T 定价 λ = ρ·¯T^slow。代价是对会想很久的题升级得太大方、对想得快的题太保守——论文对这个近似是坦诚的。

## 四、问题解法

### 4.1 HDM 架构：一个冻结 backbone + 几百 KB 的路由块

HDM（Hybrid Decision Model）= 冻结的 backbone LLM（实验用 Qwen3.5-4B 和 Qwen3.8-27B）+ 一个轻量 **self-routing block**（唯一可训练部件，仅几百 KB）。三步流水：

1. **快模式读出**：一次前向编码请求，在读出位置取隐状态 h_i，用 LM 头在候选码 logits 上做 softmax 得到答案分布 p_i（零 token 生成）。decoder-only 模型在生成任何 token 之前就已经编码了请求——各层对输入逐层抽象，这是"不写下来的思考"（latent/implicit reasoning），h_i 是模型已经加工过的信息，不是输入的另一种存放形式。
2. **路由块预测联合结果**：block 读取 h_i（某中间层的标准化隐状态）+ p_i 的 8 个分布统计量（最大概率、归一化熵、top-2 边际、集中度、log K、类型 one-hot 等），经过一个小 MLP，输出**四类联合结果的分布** o_i = (P(慢对快对), P(慢错快对), P(慢对快错), P(慢错快错))。两个边际随即可得：置信度 c_i = P(fast✓)，以及思考的价值 vi = log[(o_{i,1}+o_{i,3}) / (o_{i,1}+o_{i,2})]。
3. **一次路由**：vi > λ 则升级。升级后慢模式**从快模式已编码的前缀继续自回归解码**（复用同一上下文与 KV cache），最多 B=4096 token，路由块不再被咨询——每题只决策一次，不是每 token 决策一次。

一个训练好的 block 覆盖整条成本-精度曲线：换 λ 只是沿曲线移动工作点，不用重训、不用第二个 block。

### 4.2 有标签场景：四分类自标注监督

单轮问答有金标准答案时，监督信号可以**自标注**（self-labelling）：对每道题把两种模式都跑一遍，和金标准比对，得到四分类标签 y_i ∈ {都对, 只有快对, 只有慢对, 都错}，然后对 block 做普通交叉熵训练。妙处在于：损失里不含价格 λ，**一次拟合服务所有价格**。唯一的标注成本是金答案本身，不需要任何人工路由标注。

### 4.3 无标签场景：CDPO

多轮 agent 任务（episodic agentic）里，单个决策的对错不决定任务成败，也没有每题标签。论文为此提出 **CDPO（Calibrated Decision Policy Optimisation）**，一个 PPO 变体，从 episode 级回报训练路由块：

- **回报**：episode 的终局奖励 R，按本次决策价格指数折扣掉全 episode 的升级次数——G_t = R·e^(−λ_t·Σe_s)。升级越多，同一回报打越大的折；
- **按决策重要性比裁剪**：轨迹级重要性比在几十步上连乘会塌缩，所以比值按单个决策计算、在 PPO 的 clipped surrogate 内使用（论文坦承这使 CDPO 成为目标的代理而非无偏梯度估计器）；
- **软路由温度 τ**：block 以 π_θ(e_t|x_t,λ_t) = σ((v_t−λ_t)/τ) 的可微形式训练，τ→0 时恢复硬阈值规则；
- **无 critic**：优势 A_t = G_t − Ḡ，基线是同批同价回报的均值，不需要价值网络。

论文诚实列出三个缺口：不做信用分配（episode 里每个决策都被后续决策的表现连带评分，这是配方里最弱的假设）；价格每轮重抽而轨迹不重采。这部分的自我批评质量很高。

## 五、评估指标与实验证据

### 5.1 指标体系

准确率（accuracy/utility）、升级率（escalation，送往慢模式的题占比）、token/题、秒/题、路由 AUROC（vi 能否把"思考能救回的题"排到前面）。核心度量是**准确率与成本的权衡曲线**：λ 扫过 111 个价格点（步长 0.01），一条曲线看全部。

### 5.2 通用问答：MMLU-Pro / AGIEval / GPQA-Diamond

训练集用 MMLU-Pro 14 类中的 11 类（1,154 题），**整类留出**化学、经济、心理 3 类（346 题）做测试——所有数字都是对未见学科的迁移。AGIEval 取英文多选每第 7 题（335/2,340），GPQA-Diamond 全部 198 题，一块 block 三个 benchmark 通吃、零重训。

Qwen3.8-27B 关键数字（λ=0.5 时）：

| Benchmark | HDM 准确率 | always-thinking | token/题 | 节省 |
|---|---|---|---|---|
| MMLU-Pro（留出 3 类） | 0.873 | 0.902 | 486 vs 778 | **−38%** |
| AGIEval | 0.890 | 0.925 | 439 vs 824 | **−47%** |
| GPQA-Diamond | 0.788 | 0.848 | 1463 vs 2571 | **−43%** |

AGIEval 用 1.5 个准确率点换 47% 的思考 token。换一个视角：HDM 以 62% 的 token 拿到 always-thinking 相对快模式增益的 88%（MMLU-Pro），以 53% 拿到 84%（AGIEval）——**增益的绝大部分在前一半 token 里**。

一个精彩的归因观察：λ=0.5 时 block 只在 38% 的 MMLU-Pro 题上思考、省了 38% 的 token；如果升级是随机的（等长题），38% 的升级率本可省 62%。**省得少说明它在专挑长题升级**——路由器学会了"哪类题值得想"，而不是均匀撒网。

### 5.3 JevBench 与 BANKING77：对打 System One 模型

**JevBench**（231 道公开题，含 139 choice、74 noul 判断、18 score 评分三类题型——也是唯一同时考察跨题型迁移的场合）：

| 系统 | 升级率 | 准确率 | 中位延迟 |
|---|---|---|---|
| Jev 1.13.0 | — | 0.851 | 0.652 s |
| AnyJev Tacit-9B adaptive | — | 0.887 | — |
| HDM-4B fast only | 0% | 0.762 | 0.226 s |
| HDM-4B always thinking | 100% | 0.931 | 3.86 s |
| **HDM-4B routed λ=0** | **30%** | **0.857** | **0.179 s** |
| **HDM-27B routed λ=0** | **54%** | **0.987** | **2.49 s** |

HDM-4B 以 0.857 对 Jev 的 0.851（+0.7%），中位延迟 0.179s 对 0.652s（**−72.5%**）；27B 达 0.987，距 always-thinking 上限 0.991 仅 0.4 个点。跨题型迁移也成立：没训练过的 noul 题型升级率 0.784，远高于训练过的 choice 的 0.417——判断题更需要想，路由器自己看出来了。

**BANKING77**（300 题、20 类意图分类）是成本侧最清晰的展示：这个任务上思考根本不划算——always thinking 0.913 分要花 135.3 token/题，快模式单独就有 0.923 分、零 token。路由器直接跟了便宜的一边：**λ=0.05 时 0.920 分、1.1 token/题**。对照最接近的已发表 System One 系统 Tacit-9B+AnyJev：0.913 分、140.2 token/题——**token 成本相差约两个数量级**。论文作者专门用对方公开的 checkpoint 和官方代码在同一批 300 题上复测得出此数，对比是干净的。

### 5.4 Agent 任务：CDPO 的考场

| 场景 | 快模式 | 慢模式 | HDM（CDPO 训练） | 节省 |
|---|---|---|---|---|
| ALFWorld（134 局） | 0.463 | 0.642 | **0.560**（升级 46%） | 以 48% 思考 token 拿到 54% 可得增益；token/ep −52% |
| MiniWoB（27 任务） | 0.407 | 0.519 | **0.469**（升级 26%） | **token −80.1%、wall-clock −67.4%** |

MiniWoB 上用 0.05 的 reward 换 80% 的思考 token——在"每一步都想一遍"的 agent 场景里，这个交换率非常有说服力。

### 5.5 消融与路由基线对比

**特征来源**（MMLU-Pro 选集上的路由 AUROC，"rescue"=识别"思考能把错的想对"的能力）：最优配置 layer-24 raw 达 0.778（交叉验证）/ 0.762（留出），显著高于只用输出统计量的 0.671/0.701——**隐状态才是信号的载体**。有意思的是最后一层并非最优（layer 24 领先它 0.013/0.046），但论文仍用最后一层跑全部主实验，理由是"每个 transformer 都有最后一层"，通用性优先。

**固定精度比成本**（JevBench 上达到 always-thinking 90% 精度所需 token/题，27B）：

| 规则 | token/题 |
|---|---|
| always thinking | 591 |
| ThinkSwitcher（复现） | 352 |
| 随机升级 | 213 |
| 置信度阈值 | 138 |
| RouteLLM（复现） | 112 |
| **HDM** | **103** |

HDM 以 103 对 RouteLLM 的 112、置信度的 138；4B 上 792 对 822。最刺眼的是 ThinkSwitcher（352）**比随机升级（213）还贵**——它挑的题还不如随机抽的值钱，这对"通过率阈值"路线是一个响亮的否定。

### 5.6 案例研究：路由器在真实题目上的判断

论文附录 G 逐题展示了 λ=0 一次运行中的七个案例（该次共升级 124/231 题），前四个是"快错慢对、块花钱救回"：最便宜的一题花 326 token（从事故统计表里做贝叶斯条件化推断根因），最贵的一题花 3,415 token（判断一段自相矛盾的任务描述是否满足要求）。后三个是"两模式都对、块拒绝了免费之外的思考"：一道贝叶斯供应商归因题慢模式本会花 1,523 token，一道 SRE 告警分类题本会花 499 token，块都判断 vi ≤ λ、零 token 直出正确答案。两个方向的判断都对，正好对应四分类里"只有慢对"和"都对"这两类的正确处置——联合分布预测不是纸面设计，案例里看得见它工作。

## 六、效果优势的根源解释

### 6.1 uplift 与置信度的信息差

置信度 c_i = P(fast✓) 只有一个边际；HDM 的 o_i 预测的是**联合分布**。"快对慢也对"和"只有快对"这两类在置信度眼里一模一样（快答案都对、都挺确定），但前者升级是浪费、后者升级是赔本。反过来，"只有慢对"（快错慢对）才是升级唯一赚钱的类别，而置信度低既可能意味着这道题能被救回，也可能意味着思考也救不回（"都错"类）。**置信度在 2×2 的联合结果空间上只投了一条对角线阴影，uplift 看到整个棋盘**——这就是信息差。表 6 里置信度规则 138 vs HDM 103 的差距、以及"ThinkSwitcher 挑题不如随机"，都是这个信息差的实证。

### 6.2 四分类联合预测：把反事实变成监督

uplift 建模的经典困难是**反事实不可观测**——同一道题你只能观察到一个模式的结果。HDM 的解法朴素而有效：训练时把两种模式都跑一遍，和金标准各比一次，四分类标签就造出来了（快慢两模式都是冻结 backbone 的确定性映射，温度 0 下可复现）。监督学习的目标直接就是联合分布，两个边际（置信度、增益）从一个 o_i 里同时读出。这相当于用"自己给自己做 A/B 测试"绕开了因果推断的难题——同一道题上成对观察两个"处理组"，不存在个体异质性混杂。

### 6.3 prefill 复用：让升级不付第二次编码成本

级联/路由方法的经典隐藏开销是"升级 = 从头再算一遍"。HDM 的两个模式由同一 backbone、同一提示渲染，快模式的前向就是慢模式的第一步——升级时慢模式直接从快模式已算好的前缀继续解码，**KV cache 全量复用**。附录 A 给了实测而非断言：一次运行中所有升级的慢读出全部命中缓存，中位命中接近整个提示，几乎只需重算边界处几个 token。这让"先快速试一下、不行再想"的代价结构从"1+1 次编码"降到"1 次编码 + 条件解码"，是 zero-or-T 范式在系统层面成立的前提。

### 6.4 外部交叉验证（证据等级标注）

我用 WebSearch 检索了自适应推理方向的独立资料交叉验证上述论断：

1. **"模式切换系工作仍在'写多少推理'层面"**——arXiv 2508.12265《Fast, Slow, and Tool-augmented Thinking for LLMs: A Survey》确认：ThinkSwitcher 预测两模式通过率并按阈值切换长短 CoT，Self-Route 用隐状态分类器选模式，AdaptThink/AdaCoT 用 RL 决定 think/no_think；其快慢两模式的答案均为自回归生成。与论文 related work 的叙述一致。**证据等级：强（同行可审综述）**。
2. **三策略分类学**——arXiv 2605.28398（HRBench）把思考模式切换分成 prompt-tuning / routing / speculative 三类，HDM 属于 routing 家族，但其切换目标是"零 token vs T token"而非"预算档位"，在该分类学中无先例（其模式空间定义 think/no_think/低中高/连续预算，全部以生成为载体）。**证据等级：强（arXiv 论文）**。
3. **"思考可能把对的想错"**——多篇工程文献记载 overthinking 的 convergence problem：模型沿正确轨迹出发后被延伸思考引入的伪备选带偏；一项跨 10 个推理 benchmark 的研究测得最优思考预算按任务类别相差 8 倍。这印证论文"置信度与思考价值双向分离"的前提。**证据等级：中（工程实践文献，非同行评审）**。
4. **生产系统正在走向"默认不思考"**——2026 年的多篇推理架构实践文章给出一致结论："default to no thinking, route only when signals warrant"、置信度升级模式最好与静态基线叠加使用、按任务类别分预算可省 40-60% 思考 token。方向与本文一致，但这些系统的信号仍是置信度/启发式，未做到 per-request 可解释定价 λ。**证据等级：中（工程博客，一手生产数据但非同行评审）**。

结论：论文的两个核心主张——(a) 路由信号应是增益而非置信度，(b) 现有"模式切换"仍停留在自回归档位选择——在外部独立来源中均获得方向性支持，未发现反证。

## 七、必要知识反推

要读懂这篇论文，需要三层知识，以及一个把它们缝起来的针脚：

### 7.1 第一层：深度学习基础

- **Transformer 前向传播与隐状态**：理解 h_i 是读出位置上最后一层（或中间层）的 d 维向量，是全网络加工后的表示；
- **logits / softmax / 候选码读出**：快模式把答案当 K 分类——在候选码的词表 logits 上取 softmax（zero-shot 多选的标准协议，可追溯到 BERT 时代）；
- **AUROC**：消融表用它衡量 vi 对"rescue 题"的排序能力；
- **PPO**：CDPO 的底座——clipped surrogate、重要性比、优势基线。

### 7.2 第二层：领域方法层

- **测试时扩展与思维链**：为什么生成 token 能增加推理步数（每个 token 重入上下文，下一次前向从更远处出发）；
- **隐式/潜推理**（latent reasoning）：Grokked transformer、 Coconut 一系——不写下来的推理是真实存在的；
- **置信度估计**：从隐状态读"答案对不对"已有大量先例（Hendrycks & Gimpel、Kadavath 等），HDM 读的是不同目标；
- **uplift 建模 / treatment effect / learning to defer / 元推理的 value of computation**：四个名字一个量——干预的增益；
- **级联与模型路由**：FrugalGPT、RouteLLM 一系的价格-精度权衡传统。

### 7.3 第三层：系统工程层

- **KV cache 与 prefill**：为什么"升级复用前缀"能省下整段编码成本，这决定了 HDM 的部署形态；
- **SGLang 服务栈**：全部 B=4096 实验经 SGLang 服务，缓存命中率可实测；
- **typed decision API（Jev 协议）**：choice/score/noul 三类题型 + 候选集的结构化请求模式，HDM 直接沿用并扩展了 {λ, B} 字段。

### 7.4 融合节点

三层知识的缝合点是 **"自标注四分类"** 这个构造：用第一层的确定性前向（冻结 backbone + 温度 0）制造可复现的成对观察，用第二层的 uplift 概念定义预测目标（联合分布的两个边际之一是增益），用第三层的共享 prefill 保证"两个模式"在同一次编码内可切换。抽掉任何一层——没有隐状态就没有免费信号，没有 uplift 概念就退回置信度路由，没有 prefill 复用升级就付双倍编码成本——整个方法就不成立。看懂这个三角依赖，比记住任何一个数字都重要。

## 八、通用性灵感

### 灵感一：把"要不要做 X"从"X 做多久"中剥离出来

- **核心思想**：连续预算问题（想多久/查多深/迭代几轮）往往内嵌着一个更本质的二值问题（要不要做），先答二值问题，预算问题可能整个消失。
- **论文证据**：zero-or-T 把思考成本压到 {0, T} 两点，JevBench 上 30% 升级率就拿到 0.857（接近 always-thinking 0.931 的 92%），比"把思维链压短"一类方法的上限更彻底。
- **推广场景**：(1) agent 决定是否调用某工具，而非决定工具调用几次；(2) RAG 决定是否检索，而非检索几轮；(3) 编码补全决定是否加载跨文件上下文，而非加载多少；(4) 视频会议决定是否上高码率，而非动态调码率；(5) 数据库决定是否启用向量索引，而非调召回深度。

### 灵感二：升级决策看增益（uplift），不看置信度

- **核心思想**：当"升级"是一个可选干预时，决策依据应是干预的期望增益，而不是当前状态的可靠度。置信度是 P(现在对)，决策需要的是 P(升级后会更好)。
- **论文证据**：表 6 中置信度阈值要 138 token 才够到 90% 精度，HDM 只要 103；ThinkSwitcher（通过率阈值）352 反而不如随机 213；BANKING77 上快模式 0.923 > 慢模式 0.913，增益为负，路由器正确地学会了几乎从不升级（λ=0.05 时 0.3% 升级率）。
- **推广场景**：(1) 客服系统何时升级人工——不是机器人答不上来就转，而是判断"人工能救回"的概率；(2) 医疗二诊决策——低置信度不等于需要重复检查；(3) 风控复审——只复审"复审会改变结论"的案件；(4) 模型级联的每一跳触发条件；(5) 教育系统给学生提示的层级——先判断提示能否改变答案，而非学生答错的概率。

### 灵感三：从已计算的中间状态免费读取决策信号

- **核心思想**：昂贵的推断之前，系统往往已经算过一遍"便宜版本"——其副产品（隐状态、中间层表示、统计量）里藏着决策所需的信号，不必为决策单独再算一次。
- **论文证据**：路由块只读快模式已产出的 h_i 和 8 个分布统计量，"选择本身不花一次前向、不花一个 token"；AUROC 消融显示隐状态携带的 rescue 信号（0.778）远高于仅统计量（0.671）。
- **推广场景**：(1) 搜索引擎用首轮打分的中间表示决定是否触发重排；(2) 自动驾驶规划器用低精度轨迹的隐层特征决定是否启动高保真规划；(3) 芯片 EDA 用快速时序分析的中间信号决定是否跑全量签核；(4) 推荐系统用轻量召回的特征决定是否调用重模型；(5) 投机解码用草稿模型的隐状态决定接受/重算。

### 灵感四：一个可解释阈值覆盖整条成本-精度曲线

- **核心思想**：把"多贵的操作值得做"表达成一个业务方可直接设定的价格参数（λ），训练与定价解耦——一次训练，运行时任调。
- **论文证据**：block 的监督损失不含 λ（训练时从 [−0.2, 0.5] 抽样价格），一块权重支撑 111 个价格点的完整权衡曲线；λ 是 per-request 参数，同一模型对高优先级请求想得多、对批量请求想得少。
- **推广场景**：(1) 多租户 API 按客户等级设不同思考价格；(2) 移动设备按电量档位动态设 λ；(3) 交易系统按单笔金额设风控核查深度；(4) 云函数按 deadline 紧迫度设优化强度；(5) 翻译系统按用途（草稿 vs 出版）设润色深度。

### 灵感五：episode 级回报 + 按干预次数指数折扣，训练每步门控

- **核心思想**：当每步决策只有延迟的、聚合的回报（episode 结束才知道成败）时，可以把"这一路用了多少次昂贵操作"直接乘进回报里做指数折扣，用 PPO 按步裁剪训练轻量门控——不需要 critic、不需要逐步标签。
- **论文证据**：CDPO 在 ALFWorld 以 48% 思考 token 拿到 54% 可得增益，MiniWoB 上 token −80.1%、wall-clock −67.4%；论文同时坦承三个理论缺口（代理目标、无信用分配、价格重抽），自我批评可作后续工作地图。
- **推广场景**：(1) 机器人分层控制——低层快反射、何时唤醒高层规划；(2) 游戏 AI 的难度/搜索深度按局势动态调节；(3) 多轮对话的记忆压缩——每轮决定是否触发昂贵的长期记忆读写；(4) 自动驾驶的规划频率按路况复杂度自适应；(5) 多代理系统里决定哪一步值得 spawn 一个子代理。

## 结语

这篇论文最值得带走的不是 JevBench 上的 0.857，也不是 −72.5% 的延迟，而是一个提问方式的转换：**在问"如何让思考更便宜"之前，先问"这道题配不配被思考"**。把路由信号从置信度换成增益、把信号源从额外计算换成免费副产品、把定价从训练期烧死换成请求期可调——三步合起来，"一个模型同时是 System 1 和 System 2"第一次有了工程上站得住的实现。当然要记住论文自己的边界声明：主张的是更低 token 成本下的竞争力而非全面碾压（BANKING77 上就有两个配置比它分数高），引用的他人延迟测自不同后端。方法论的生命力，最终要看 uplift 路由这个思想能否在更多"要不要做 X"的决策场景里复现。
