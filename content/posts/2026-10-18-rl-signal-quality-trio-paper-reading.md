# 题目区：为什么把这三篇放在一起读

用大模型做智能体并施以强化学习（agentic RL）已成本流。但无论任务是修仓库 issue、在网页里购物，还是生成一条 SQL，GRPO 这类组相对算法都有一个共同的软肋：**奖励信号又稀疏又粗**。一个任务只在结束时给一次 0/1；一次生成里格式、可执行、正确性三个奖励被压成一个优势值均匀摊到每个 token 上。三篇论文恰好从三个互补的切面攻击同一堵墙：

- **ANTE（Anticipate, Then Execute）**：让策略在每步动作前显式写出预测，由真实执行来验证，再用被验证的预测做逐步信用分配——**信号变准的来源是执行验证**。
- **SERO（State-Rooted Executable Rollout Optimization）**：当整组 rollout 都没采到有用行为时，任何 credit assignment 都无米下锅；SERO 让训练期 oracle 在策略真实到达的状态上真实续跑，把缺失的正目标补进训练——**信号变多的来源是 oracle 可执行未来**。
- **MRTPO（Multi-Reward-to-Token Policy Optimization）**：多个验证器各自只检查响应的一小部分 token，却把优势平均摊给全部 token；MRTPO 用自重放测出每个奖励与哪些 token 相关，把每个奖励的优势发还给它们自己的 token——**信号变细的来源是奖励特定归因**。

一句话主线：**RL 的奖励信号正从轨迹级的稀疏粗粒度，走向步级、token 级的细粒度可信。**

# 一、论文背景：三个共同的痛点

## 1.1 终端奖励下的信用分配困境

先从最基础的讲起。GRPO / RLOO 这类免 critic 的组相对方法，做法是：对同一任务采样 N 条轨迹，用组内均值做基线，整条轨迹共享一个优势值。这个设计在数学推理这类短程任务上很好用，但在智能体场景暴露两个问题：

1. **粒度问题**：一条轨迹几十步、几万 token，最后只有一个 0/1。哪一步救了任务、哪一步埋了雷，算法无从分辨。ANTE 论文里有个精确的例子：一条 resolved 轨迹在第 30 步加了打印机覆盖、第 41 步又删掉它——单一任务奖励对破坏构建的步骤和修复它的步骤给了一模一样的奖励。
2. **覆盖问题**：组相对方法只能给采样到的行为排序。如果整组 rollout 全都没摸到有用的行为分支，再精细的信用分配也造不出缺失的正目标。SERO 论文把这称为结构性限制：监督信号被当前策略访问到的未来所封顶。

## 1.2 多奖励场景的污染问题

第三个痛点来自多奖励。实践中一个任务往往有多个验证器：SQL 要查格式、可执行、执行结果对；指令遵循里每条约束是一个奖励。GRPO 把奖励加总再归一化，不同奖励组合会被压成同一优势（reward collapse）；GDPO 改为每个奖励分别归一再加权，但优势仍然均匀摊给全响应的每个 token——格式奖励明明只检查标签，惩罚却落在正确生成的参数上。

## 1.3 已有的缓解路线与不足

- **世界模型路线**：CWM、SWE-World、PatchWorld 学一个环境模拟器，但要么在 RL 前冻结、要么把模拟器放在策略外部，学到的预测不参与信用分配。
- **辅助观察损失路线**：ECHO、PaW 给环境输出加辅助损失，但策略行动前仍不写预测，预测也不被显式验证。
- **judge 路线**：用 LLM judge 给中间步骤打分，但 judge 只能近似正确，且容易被 reward hacking。
- **教师引导路线**：OPD 在策略到达的状态上查询单步纠正，但交互环境里执行一个纠正会改变后续所有观测，只学根处单步纠正浪费了纠正的长程后果。
- **重加权路线**：GDPO / SAW / DVAO / GD2PO 决定每个奖励在响应级贡献多少权重，但每个 token 收到的仍是所有奖励之和——奖励越多，无关 credit 污染越大。

三篇论文各自站在这四条路线的延长线上，又各自换掉了关键零件。

## 1.4 一个统一的视角：信号的质量维度

如果把 RL 学习信号当作一个工程对象，它有四个可度量的质量维度：

1. **粒度**（granularity）：信号能定位到多小的行为单元——轨迹级、步级还是 token 级；
2. **正确性**（correctness）：信号与真实因果关系的一致程度——摊匀的信号里有多少比例发错了地方；
3. **覆盖**（coverage）：信号能触达的行为空间比例——采样不到的行为永远得不到正信号；
4. **可信度**（trustworthiness）：信号本身能否被博弈——LLM judge 可被 hack，确定性执行器不能。

在这个坐标系里，GRPO 是「粒度=轨迹、覆盖=受限于采样、可信=中等」；三篇论文各自把一两个维度推向极限而保持其余不倒退：ANTE 主攻粒度与可信度（执行验证）、SERO 主攻覆盖（oracle 续跑补正目标）、MRTPO 主攻粒度与正确性（逐奖励定位）。这个坐标系也是后文评估与根源分析的骨架。

# 二、论文定位和关联工作

## 2.1 按谱系定位

| 谱系 | 代表工作 | 核心思想 | 本文的突破 |
|------|---------|---------|-----------|
| 代码世界模型 | CWM、SWE-World、PatchWorld、ECHO | 预测环境输出 | ANTE：策略显式预测 + 真实执行验证 + 预测参与信用分配，三合一闭环 |
| 步级信用分配 | GiGPO（按重复状态分组）、ReBel（按谓词分组）、PRIME（隐式过程奖励） | 找可比步骤做基线 | ANTE/BAPO：按预测结果分组，不要求状态重访；MRTPO：按 token 相关性分配，无需任何分组 |
| 教师/oracle 引导 | DAgger、OPD、OraRL、多轮 OPD 变体 | 在学习者状态上给纠正 | SERO：把 oracle 控制的可执行未来本身作为训练轨迹 + 前缀可达性加权 |
| 多奖励优化 | GRPO、GDPO、SAW、DVAO、GD2PO | 响应级奖励重加权 | MRTPO：首个奖励特定 token 级分配，与重加权族正交可叠加 |
| token 级信号 | 过程奖励模型、VinePPO、熵调制（80/20 高熵 token）、CoRT | 细化到 token | MRTPO：无需辅助模型、无需 token 标注，且每个奖励单独定位 |

## 2.2 三篇互为镜像的关系

有趣的是，三篇论文的方法可以直接互相当对照系：

- ANTE 的 BAPO 与 GiGPO 的差别只在分组键：GiGPO 要求同一环境状态在不同轨迹中重复出现（仓库级任务里状态几乎不复现），ReBel 要求人工预定义谓词，BAPO 用策略自己输出的预测——预测相同即同组，天然可比较。
- SERO 与 ANTE 的对照：两者都引入策略外信号（执行验证 / oracle），但 ANTE 的信号是奖励内部的自洽验证，SERO 的信号是奖励之外的新轨迹源；ANTE 不改变奖励定义，SERO 也不动基础 RL 的奖励、优势与比率。
- MRTPO 与 SERO 的对照：MRTPO 的自重放是纯前向传播（不执行、不采样新响应），SERO 的 oracle 续跑是真实执行（要恢复环境快照）；一个解决信号该给谁，一个解决信号从哪来。

# 三、问题定义：抽象出共同的本质问题

把三篇论文的具体场景剥掉，它们面对的是同一个抽象问题：

> **给定一个只返回终端奖励（或多个粗粒度奖励）的环境，如何在不引入不可靠的外部评判者、不破坏基础 RL 算法结构的前提下，为策略的每一步（甚至每个 token）提供既正确又可信任的学习信号？**

三篇论文分别把它拆成三个子问题：

| 论文 | 子问题 | 形式化 |
|------|--------|--------|
| ANTE | 步级信号从哪来 | POMDP 中隐状态是整个容器/仓库；策略在动作 t 前写信念 β_t=(摘要 z，预测 ŷ，决策 d∈{trust,abstain})，预测取值于确定性验证器 ψ 的结果空间，执行后 ŷ 与真实 y 对质 |
| SERO | 正目标缺失怎么办 | 在策略真实到达的状态 s_t 恢复快照，oracle 与环境多步交互产生轨迹 τ^O，求一个辅助监督目标使期望回报提升，约束是不改基础 RL 估计量、推理时无 oracle |
| MRTPO | 每个奖励发给谁 | 响应 y 有 T 个 token、K 个奖励，GDPO 给每个 token 相同优势 A_t=A；求与奖励 k 相关的 token 子集，把 A_k 按相关性分配且不引入辅助模型或标注 |

三个定义的精妙之处在于**信任来源的设定**：ANTE 只信任确定性执行验证器（读出 check/exit 两个字段），不信 LLM judge；MRTPO 只信任策略自身前向传播的分布差异，不需要任何额外模型；SERO 只在训练期用 oracle，推理时策略独立。三者都刻意绕开了「学一个奖励模型来评判」这条容易被 hack 的路。

# 四、问题解法

## 4.1 ANTE：预测、验证、然后执行

ANTE 的流水线分三个阶段。

**信念状态（写预测）**。策略每个动作前输出三元组 β=(z, ŷ, d)：一句话摘要 z（已确认什么、坏什么）、预测 ŷ（下一动作跑的检查会得到 pass/fail/na + 是否干净退出）、决策 d（trust = 承诺该预测；abstain = 仍写预测仍执行但不承诺）。预测取值于验证器可读的结果空间，所以它是环境可以证实或证伪的陈述，而非自由发挥的感想。

**Stage I（ANTE-SFT）**。在 BeliefTraj 语料（仓库任务 12,500 条成功轨迹覆盖 6,729 个任务；终端任务 30,161 条覆盖 10,823 个任务）上做带信念的 SFT。预测标签由 hindsight 从真实执行结果回写。论文给出模仿学习的上界（命题 1）：SFT 损失越小，策略越接近示范成功率，只差一个不可因果化的余项 Λ——这正是 Stage II 要修的。

**Stage II（ANTE-RL，核心是 BAPO）**。RL 阶段三路信号汇成一个目标：

1. **预测损失 L_pred**：每个可验证步的预测 token 对真实结果做交叉熵（执行接地的监督）；
2. **决策奖励**：conclusive 步上，信任且预测对得 +α，信任但错付 −γ，弃权付固定成本 −κ；γ=αq*/(1−q*) 的设定使只有预测准确率超过目标 q* 时信任才有正期望；
3. **BAPO 步级优势**：把同任务不同 rollout 中**预测同一结果**的步聚成信念组 G(ỹ)，再按决策细分为 G(ỹ,d)，组内决策回报均值当价值基线 V̂(ỹ)、Q̂(ỹ,d)，步优势 = 任务级优势 A_i + ω·(信念相对优势 + 决策相对优势)，ω=1/2。

直觉版：两个 rollout 里都有一步预测「目标测试会过」，一个 trust 一个 abstain，事后回报一高一低——BAPO 让它们互为对照，credit 精确落在「预测相同前提下的决策差异」上。这与按状态分组（GiGPO，要求状态重访）和按谓词分组（ReBel，要求人工定义）都不同：预测是策略自己的输出，天然存在于每一步。

**ANTE-TTO（测试时）**。策略弃权或预测 fail 时，采 K=3 个候选动作，按候选自己写的信念排序（PASS≻NA≻FAIL，再看干净退出），只执行最高分的那个。不需要外部打分器、不重复执行候选。理论侧（命题 2）给出：选择遗憾被候选的预测散度上界控制——把预测练准，按预测选择就有保证。

**训练目标的细节**。RL 目标把三路信号焊进一个损失：策略项用非对称裁剪的重要性比率乘 A_{i,t}，KL 锚定在冻结的 warm start；预测损失只作用于预测 token 位置，summary token 不给梯度（没有任何东西检查摘要），推理与动作 token 同时被策略项与预测项（经由共享上下文）塑造。这种「同一消息内按因子分职责给梯度」的设计，是信念不干扰动作生成又能反哺动作表征的关键工程手。

**一个完整案例**。SWE-bench 的 psf__requests-1724（Unicode HTTP 方法导致上传崩溃）：Reactive 只看眼前报错把方法 encode 成 bytes，Python 3 下 43 个测试被带崩，还嘴硬「与本题无关」提交；Retrospective 的记忆只记录了发生过什么，对 bytes 编辑将要做什么只字未提；ANTE 在编辑前预测「改 parse() 输出→目标过但三个调用方崩」（Forecast A，弃权）与「加默认值→全部 242 个测试过」（Forecast B，trust），执行验证 B 后才提交——27 步解决，而 Reactive 花了 50 步以失败告终。

## 4.2 SERO：把 oracle 的可执行未来当作训练轨迹

SERO 的每个训练迭代三步走。

**第一步，照常跑基础 RL**。收集 on-policy rollout 组，照原样计算 GraphGPO / HGPO / GRPO 等基础算法的目标。oracle 数据不进入奖励统计、优势、重要性比率——SERO 是纯附加项。

**第二步，可执行 oracle 续跑**。从某个策略真实到达的前动作状态 s_t 恢复环境快照（单独的环境副本、同样的剩余视界），让训练期 oracle（ALFWorld 专家规划器 / WebShop 目标元数据 oracle）从那里继续多步交互直到任务完成或预算耗尽。关键差异：下游每个目标都以**前序 oracle 动作产生的真实观测**为条件——这是单步纠正（OPD 类）拿不到的信息。每步按「oracle 回报是否超过同根同视界的策略回报」做改进门 g_r=clip((G^O−G^π)/c_R,0,1)，不改进的分支不计入。

**第三步，策略可达性加权**。深部状态越来越 off-policy（要跟着前缀 oracle 动作才到得了）。冻结行为策略给每个 oracle 命令打长度归一化似然 z_k，第 k 步的权重 w_k=∏_{j<k} z_j，根处 w_0=1。直觉：某个早期 oracle 动作策略学不像，它后面所有监督都降权；随着策略变兼容，有效监督深度自动延长（论文 Fig.4 显示早期 w_k 快衰减、后期保持）。最终 L_total = L_base + λ_O·L_SERO，λ_O=0.1，推理时无 oracle。

一句话类比：OPD 是「在学生做错的题旁边写一个正确答案」，SERO 是「让老师从学生卡住的地方把整场棋下完，学生再按自己跟得上的程度逐段学习」。

## 4.3 MRTPO：每个奖励发给它自己的 token

MRTPO 只改一处：每个 token 的优势 A_t 怎么来。三步机制：

**第一步，构造 verifier 信息块 Z_k**。每个验证器检查什么，就把对应信息写成文本块：SQL 场景里 Z1 是格式要求、Z2 是 SQLite 报错、Z3 是参考查询；指令遵循里每条约束本身就是信息块。

**第二步，leave-one-out 自重放**。把全部信息块拼进 prompt 得 P_all，去掉第 k 块得 P_{\k}；用采样时的参数 θ_old 对同一条已生成响应各做一次前向传播（无新采样），逐位置算两组下一 token 分布的 Jensen–Shannon 距离 q_{k,t}∈[0,1]。直觉：去掉 Z_k 后预测变化最大的位置，就是依赖 Z_k 的位置——SQL 报错信息一撤，预测抖动最大的是写错的表名。

**第三步，按相关性重排优势**。w_{k,t}=(1−β)+β·q_{k,t}/q̄_k（β=0.5，带 warm-up 和重分配上限），平均相关性的 token 权重不变为 1，每个 token 保底 1−β，响应总信用量守恒、只改放置位置。逐 token 求和 S_t=Σ_k A_k w_{k,t} 再批级归一。

与近邻的关键区别：OPSD 用特权信息蒸馏一个教师分布（奖励被替换）；MRTPO 奖励照旧是目标，重放只决定优势去哪。GDPO+SAW 决定每个奖励贡献多少（响应级），MRTPO 决定发给谁（token 级），两者正交、可直接叠加。

# 五、评估指标与实验证据

## 5.1 ANTE：三规模、双 harness、11 个 OOD 基准

主指标是 SWE-bench Verified pass@1 与 Terminal-Bench 2.0 resolved 率。实验设计最值得称道的是**配对对照**：Reactive（思维+工具调用）与 Retrospective（加显式记忆）两个基线与 ANTE 共享轨迹来源与工具调用，RL 阶段各用自己 SFT 检查点、同任务池，唯一差异是信念——这样任何提升都可归因到信念机制。

| 方法（SWE-bench Verified pass@1, %） | 7B | 14B | 32B |
|---|---|---|---|
| Reactive-RL | 24.4 | 41.8 | 51.0 |
| Retrospective-RL | 25.2 | 43.4 | 52.4 |

成本侧：ANTE-TTO 在 7B 只花 1.31× token（TTS-4 要 4.42×），四设定平均 1.6× vs 4.1×。

## 5.2 SERO：五重对照逐一排除替代解释

SERO 的主表是 ALFWorld（seen/unseen 成功率）与 WebShop（task score/success），双底座（GraphGPO/HGPO）双规模（1.5B/7B）全对照，3 种子均值±标准差报告：

| 1.5B ALFWorld seen/unseen | 数值 | WebShop score/success | 数值 |
|---|---|---|---|
| GraphGPO | 90.63/88.02 | GraphGPO | 87.27/77.93 |
| **GraphGPO+SERO** | **95.83/91.67** | **+SERO** | **88.90/79.27** |
| HGPO | 92.19/87.24 | HGPO score/success | 87.80/73.70 |
| **HGPO+SERO** | **94.53/90.10** | **+SERO** | **88.43/77.47** |

7B 侧同样全面：GraphGPO+SERO 把 ALFWorld 从 91.67/76.30 提到 95.57/87.50，WebShop 从 89.77/80.47 提到 91.93/83.67；HGPO+SERO 把 WebShop success 从 74.47 提到 79.63。最大单项增益在 7B GraphGPO 的 unseen：76.30→87.50（+11.20）。对照 prompting 与经典 RL 差距悬殊（1.5B ReAct 12.8、GRPO 72.8/70.1、GiGPO 88.27/86.47、GPT-4o 48.0/46.0、Gemini-2.5-Pro 60.3/50.5）——SERO 的增益是在已经很强的状态级 RL 底座之上的净提升。

真正让 SERO 论证有说服力的是五重消融（1.5B GraphGPO）：

1. **只学根处单步纠正反而降分**：Root-only 87.76/83.85（比 base 降 2.87/4.17）——单步纠正不是弱化版而是有害版；
2. **完整续跑是关键**：Full-Flat（完整续跑+平铺权重）94.79/88.28，比 Root-only 高 7.03/4.43；
3. **可达性加权是第二关键**：SERO 再比 Full-Flat 高 1.04/3.39；
4. **权重必须与前缀对齐**：冻结库对照里把 SERO 权重打乱位置即崩——Shuffled 85.16/80.73（比 SERO 88.02/85.94 低 2.86/5.21），固定深度衰减也不如（87.24/82.55）；
5. **不是多交互的功劳**：预算匹配对照（GraphGPO 多训 15 步抵掉 SERO 的额外环境交互）93.49/90.36，仍低于 SERO 2.34/1.31。

另有两组机制检验。其一是 w_k 的实证：把 2,869 个根-深度对（271 个根、每根 8 次前缀试验）按 w_k 分桶，[0.50,1] 桶前缀复现率 40.97%、[0.25,0.50) 桶 6.66%、[0,0.05) 桶 0%——权重确实单调编码了策略复现前缀的能力；单步兼容度 z_k 与采样动作匹配频率的 Spearman 相关达 0.763。其二是任务类型分解：ALFWorld 六个任务族上 SERO 的提升分散在多族（7B unseen 的 Clean/Cool/Heat/Pick2 最明显），不是被单一天类别拉动。λ_O 敏感性在 [0.1,0.5] 稳定，1.0 过强反而掉分。

## 5.3 MRTPO：增益随奖励数增长的机制学证据

三个任务、六个模型全对照。核心设计与 GDPO 严格可比：两者算出完全相同的逐奖励优势，唯一差别是分配方式——增益只能来自 token 级分配。

Text-to-SQL 侧（Spider dev/test/Syn/Realistic/DK + BIRD dev，六基准执行准确率）：

| 模型 | Base | GRPO | GDPO | OPSD | MRTPO | MRTPO+SAW |
|---|---|---|---|---|---|---|
| Coder-3B 平均 | 53.88 | 65.37 | 67.32 | 59.02 | **68.60** | **68.96** |
| Coder-7B 平均 | 69.28 | 70.93 | 71.55 | 71.49 | **73.15** | **73.41** |

一个反直觉的对照：OPSD 的教师能看到带推理过程的完整参考解答（比特权信息多于 MRTPO），却全面低于 MRTPO——说明策略需要的不是更完整的教师，而是「验证器已用信息」的正确用法。指令遵循（HIR-16K 训练、每 prompt 5–13 个约束各为一个二元奖励）：

| 模型 | GRPO | CoRT | GDPO | MRTPO |
|---|---|---|---|---|
| Qwen3-4B 四基准平均 | 61.12 | 60.84 | 61.37 | **62.54**（IFBench 38.76 vs 36.39，+2.4） |
| Qwen2.5-7B 四基准平均 | 56.54 | 56.36 | 56.67 | **57.36**（IFBench 38.87 vs 35.70，+3.2） |

工具调用（BFCL-v4 single-turn AST）：1.5B Non-Live 80.05 vs GDPO 79.30、Live 68.66 vs 67.05；3B Non-Live 82.55 vs 82.42。

最有证明力的是**增益随奖励数增长的梯度**：指令遵循每 prompt 有 5–13 个约束奖励，增益最大（IFBench +2.4 / +3.2，且这些约束训练中没见过）；SQL 3 个奖励次之（+1.3/+1.6）；工具调用只有 2 个奖励，终点接近 GDPO、增益主要体现在速度（格式奖励达到 0.8 的中位步数 13 vs 19 vs 34——MRTPO/GDPO/GRPO；10 步后 BFCL 格式率 97% vs GDPO 的 2%）。这恰好是污染机制（无关奖励越多、摊匀后污染越重）的定量预言。

定位分析给出机制可视化。集中度：SQL 三个奖励 80% 的重放距离分别落在 26.2%（execution）、26.5%（executability）、28.8%（format）的 token 上；工具调用更集中（13.2%/15.0%）。分区域：format 奖励给标签两倍于其 token 占比的距离（工具调用场景 think 标签达三倍），execution 奖励把 10% 的距离放在选定列（两倍占比）、几乎不给标签；end-phrase 约束 40% 的距离落在 4% 的 token 上（集中比 9–10 倍）；被违反的约束会把距离移到缺失内容应在的位置（如缺引号时的起始 token）。

两个消融是关键一击：其一，把权重在响应内 shuffle 位置（保留数值、破坏对位），增益消失（71.03 < GDPO 71.55）——增益确来自每个奖励发给自己的 token；其二，联合重放（所有奖励一个共享轮廓）72.56 也低于逐奖励的 73.15——逐奖励分配本身必要。附带收益：响应长度缩短 40%（不影响查询的推理拿不到执行优势，自然萎缩）；β 敏感性上 0.5 在指令遵循最优、SQL 上 0.25 略高，作者为省算力全任务统一 0.5。开销 10–20%（只有组内有方差的奖励才重放，12–21% 的响应-奖励对被重放，工具调用组内正确性有方差的比例从首十步 61% 降到约 10%）。

# 六、效果优势的根源解释

## 6.1 根源机制与证据链

**ANTE 的因果链**：结果 RL 的奖励只在轨迹末端到达，错误编辑可在信号到来前不可逆破坏仓库状态 → ANTE 把对下一动作结果的事前预测变成可被确定性执行验证的监督（L_pred 直接压低预测分布与真实结果的 KL）→ 命题 2 保证选择遗憾被预测散度上界控制 → 策略内部长出世界模型（命中率 44→69%【论文实验已支持】）→ BAPO 以预测为分组键，让同任务跨 rollout 的可比步骤获得条件化基线，稀疏终端奖励下逐步 credit 成为可能【论文实验已支持：w/o BAPO 与 BAPO 的差 +1.8～3.0】→ OOD 迁移与 TTO 增益表明预测能力可跨域、可用于推理时选择【论文实验已支持】。一个阅读者推测：32B 增益（+6.2）大于 7B（+2.8）可能部分来自更大模型的预测因子更容易被 SFT 学准，论文未直接检验这一点。

**SERO 的因果链**：交互环境中执行一个纠正动作会改变后续所有观测，只学根处单步纠正浪费纠正的长程后果 → SERO 恢复策略到过的状态让 oracle 真实续跑，每个下游目标以前序 oracle 动作的真实观测为条件【Root-only 反而降分 + Full-Flat 大涨支持】→ 但深部状态对当前策略日益 off-policy → w_k=∏z_j 编码策略复现前缀的程度【w_k 分桶复现率 0%→40.97% 支持】→ 压低支持差的前缀、随训练自动加深有效监督【Fig.4 支持】→ 增益集中于 OOD（unseen +11.20 最大），因为分布外策略更缺正目标【论文解释，与数据一致但属合理推断】。

**MRTPO 的因果链**：GDPO 类方法每个 token 收到所有奖励优势之和，多数 credit 来自无关奖励且奖励数越多污染越大 → 自重放 JS 距离无监督定位验证器实际检查的位置【Table 4 集中比 9–10 倍支持】→ 由少数 token 决定的奖励不再被稀释 → 学习加速（格式 13 步 vs 19 步达 0.8；10 步 97% vs 2%）【论文实验已支持】→ 增益排序 IF（5–13 奖励）> SQL（3）> 工具调用（2）与污染机制定量吻合【论文实验已支持】。

## 6.3 三条因果链的交叉印证

把三条链并排看，有两处漂亮的交叉印证。其一，**「分组/定位键的选择决定信用分配上限」**在三篇中反复出现：BAPO 换掉 GiGPO 的状态键换来仓库级任务可用性；MRTPO shuffle 消融证明同一组权重换个位置增益即消失；SERO 的 Shuffled 对照（−5.21）证明同一组权重不跟前缀对齐即失效——三个实验从不同角度说明信用分配的收益不在「给了多少信号」而在「信号落在哪」。其二，**「辅助信号不侵入主目标」**是三篇共同的保守设计：ANTE 的预测损失走独立 token 位置、SERO 的 oracle 损失走独立辅助项（λ_O=0.1）、MRTPO 只改 A_t 不动目标函数——这使三者都能与既有算法栈叠加而非替代，也解释了为什么 SERO 能同时给 GraphGPO 和 HGPO 两个底座带来一致增益。

## 6.4 综合判断与未决问题

多项研究共同支持的机制：（1）步级/token 级条件化基线优于轨迹级均摊——GiGPO、BAPO、MRTPO 从三个分组/定位维度独立证实；（2）少数关键 token/步骤承载多数学习信号——熵视角与重放视角互证。仍属推测的部分：ANTE 增益的规模效应机制；SERO 增益向 OOD 集中的解释。适用条件与失效边界：BAPO 需要验证器可读的结果空间（pass/fail/na）；MRTPO 要求奖励的验证信息可写成文本且增删会改变预测（作者明示长度类奖励无法定位，只能保持均匀分配，且实验只到 7B、β 全任务固定 0.5）；SERO 依赖可恢复的环境快照与训练期 oracle，推理时不可用——在不可逆真实环境（论文也承认）与无 oracle 的场景需另行验证。

# 七、必要知识反推

假设一个零背景的人要复现这三篇工作，最少必须掌握什么？

**领域知识层**。LLM 智能体的工具调用循环（观察-思考-动作）与容器化执行环境（R2E-Gym、Tmax/Harbor 这些 harness 的协议）；POMDP 建模——ANTE 必须理解为什么仓库状态是隐状态、为什么预测取值于验证器结果空间才能被证实；交互环境的快照/重放机制——SERO 的全部前提是「状态可恢复」，不懂模拟器序列化就无从设计可执行续跑；各任务的验证器结构——MRTPO 的 Z_k 直接来自验证器检查什么。

**方法论知识层**。组相对 RL（GRPO/RLOO）的优势构造及其坍缩条件；分层/分组信用分配谱系（GiGPO 状态分组、ReBel 谓词分组）——BAPO 的分组键创新只有放在这条谱系里才可评价；模仿学习上界与 regret 界分析（ANTE 命题 1/2 的证明工具）；on-policy/off-policy 失配的理论（SERO 的可达性加权本质是 off-policy 修正的软形式）；信息论距离（JS 距离、KL）与 leave-one-out 因果归因思想（MRTPO 的 q_{k,t} 就是一次单因素消融实验的模型内版本）；自蒸馏/OPD 谱系（两篇都以此为最近邻对照）。

**工程知识层**。BELIEF 语料的 hindsight 标注与泄漏过滤（ANTE 附录专门处理决策标签与泄漏）；belief 消息的自回归因子分解——预测 token 与动作 token 分开训练（预测损失只进 value 位置、summary 不给梯度）这种细粒度 loss masking 是实现层面的成败手；冻结行为策略打分的实现（SERO 的 z_k 要 stop-gradient）；重放的前向传播批处理与「组内有方差才重放」的稀疏化调度（MRTPO 开销控制在 10–20% 的关键）。

**知识融合的关键节点**。三篇论文各自的化学反应点：ANTE 把「选择性预测（selective prediction）的 trust/abstain」从推理时技巧变成 RL 可训练的决策变量，与信用分配融合；SERO 把 DAgger 的「专家在学习者状态上示范」从单步扩到整段未来，又用 off-policy 加权驯服了随之而来的分布失配；MRTPO 把「消融实验」这个科研动作内化为训练信号——去掉一块信息看预测变不变，变化即相关性。三个融合点共同的前提洞察：**策略自己产生的中间量（预测、前缀、重放分布）本身就是免费且不可 hack 的监督载体。**

# 八、论文中可以提取的通用性灵感

**灵感一：把事前预测交给事后验证，是最便宜的监督。**
核心思想：任何系统在行动前被迫写出可证伪的预测，行动结果就自动成为该预测的监督信号，无需人工标注。论文证据：ANTE 的预测命中率在 RL 中从 44% 升到 69%，且预测能力迁移到 11 个 OOD 基准（+6.2 平均）。推广场景：运维系统在执行变更前写「预期影响面」由监控验证；推荐系统在展示前预测点击率由真实反馈校准；自动驾驶规划器在变道前预测周围车辆反应；科研 agent 在实验前写预期结论。

**灵感二：分组键可以从环境借，也可以让策略自己造。**
核心思想：做对比基线（谁跟谁比）时，重复状态、人工谓词都不如策略自己输出的中间表征可靠且无处不在。论文证据：BAPO 用预测做键在 GiGPO（要求状态重访）失效的仓库级任务上工作，贡献 +1.8～3.0 点。推广场景：A/B 测试中以用户自述意图而非人口属性分层；代码评审按变更意图而非文件路径聚类；教育测评按学生自报解题策略分组诊断。

**灵感三：教人做事，示范完整过程远强于纠正单步。**
核心思想：在动态系统里，一个纠正的价值大部分藏在它引发的后续观测里；只教第一步会丢掉长程后果。论文证据：SERO 中 Root-only 反而比不教更差（−2.87/−4.17），完整续跑 +7.03/+4.43，Short-bridge 仍落后完整版 4.16/4.95。推广场景：新手培养用完整项目带教而非逐题纠错；机器人示教给整条轨迹而非单点修正；LLM 工具教学的案例应展示工具链完整调用链路。

**灵感四：监督要与学习者当前可达性对齐，且随能力自动加深。**
核心思想：超出当前能力的示范应降权而非硬灌，随学习者进步逐步放开——课程学习不必手工设计，可用「学习者复现前缀的概率」做自动调度器。论文证据：SERO 的 w_k 与前缀复现率单调对应（[0.50,1] 桶 40.97% vs [0,0.05) 桶 0%），打乱权重即崩（−5.21）。推广场景：蒸馏课程按学生困惑度加权样本；康复训练按患者完成度递进；自适应教育推送按学生可达知识边界选材料。

**灵感五：想知道谁该负责，就做一次单因素消融。**
核心思想：判断某因素与某结果的因果相关性，最干净的办法是固定其余、只动这一个，观察输出变化——这个动作可以在模型内部批量、廉价地执行。论文证据：MRTPO 的 leave-one-out 重放定位出 end-phrase 40% 距离在 4% token 上，shuffle 后增益消失。推广场景：归因分析用遮罩/重放定位关键输入段；Bug 定位用增删代码块看测试分布变化；组织诊断通过单变量试点定位因果关系。

**灵感六：信号的可信度等级设计——确定性验证 > 自我一致性 > 学习型裁判。**
核心思想：为训练信号选择信任来源时，优先确定性程序验证，其次策略自身统计量，最后才是学出来的裁判模型——越靠后越容易被博弈。论文证据：ANTE 弃 LLM judge 用执行验证器，其信念判决（73.2/0.482）反超专用 32B 奖励模型（58.4/0.359）；MRTPO 用策略自身前向分布而非外部模型；SERO 推理期完全不带 oracle。推广场景：数据质量管道用可执行校验规则优先于模型打分；自动化评估用单元测试而非 LLM 评审做主信号。

# 加评（结语）

把三篇并置，能看到 agentic RL 正在发生的信号工程转向：第一代方法问「奖励怎么给」，这一批工作问「信号怎么变细、变准、变得不可 hack」。ANTE 证明了策略内部的预测可以成为免费且可验证的监督源；SERO 证明了正目标缺失时可以从受控的执行里借未来；MRTPO 证明了多奖励污染可以用模型自省式的重放来解毒。三者叠加的想象空间是显然的：BAPO 的分组键与 MRTPO 的 token 归因同属信用分配的两级粒度，SERO 的 oracle 轨迹同样可以被 ANTE 式的预测验证所过滤。留白也诚实：ANTE 依赖 harness 提供可读的检查结果；SERO 依赖可快照的环境与 oracle 存在；MRTPO 的验证信息必须可文本化且模型对其敏感（长度类奖励即失效）。信号质量的下一站，大概率是把这三条路线焊进同一条训练管线——谁先做到，谁就能在同样的算力下榨出更干净的学习信号。
