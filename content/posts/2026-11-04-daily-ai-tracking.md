### 1. 前沿学术与技术突破（Hugging Face 精选 + Arxiv 精选）

#### 1.1 长上下文与推理效率

- **论文名称**：**[You don't need long context / 你不需要长上下文]**
- **核心亮点**：
  - **任务定义**：论证前沿 LLM 完成长程任务与长输入任务不需要长上下文窗口——频繁压缩即可保持短上下文且几乎不损精度（LLM 推理系统/上下文管理领域）。
  - **方法核心**：三种上下文管理机制对比——EoCC（对话末尾压缩：达阈值时让模型生成任务相关压缩、开新会话）、SAC（单动作压缩：每会话只执行一个动作后更新语义状态）、配合"选择性输入阅读"（长输入存文件系统、用 Bash 按需读取），并据此提出语义状态空间模型（SSSM）概念。
  - **评估指标**：长程任务 6 基准（SWE-bench Verified/Multilingual、Terminal-Bench 2.1、FRAMES、BFCLv3、τ2-bench）上 Opus 4.5 精度变化 -3.7~+5.6pp、GPT 5.6 Sol -3.3~+4.4pp（22 个配置中 ≤5 个损失超 2pp），成本节省 2.2×-8.8×；长输入 7 基准（LongBench v2/LOONG/RULER 等）同样持平甚至更好（LOONG +9.2~+10.1pp）；256K→16K 窗口解码吞吐提升 3.6×（GLM 5.2）/5.6×（Kimi K2.6）/7×（Qwen3 Coder Next）。
  - **为何优于 baseline**：长上下文下 token 生成成本/延迟随深度线性增长（后期 token 贵达 7×）→ 压缩机制把活跃上下文压到 16-48K 规避长 KV cache 代价 → 服务端吞吐大幅上升；而任务所需信息通过压缩状态+文件系统外置按需读取保留 → 精度不降。多数任务的历史信息只需"需要时可取"，不必常驻上下文。
- **团队背景**：NVIDIA 纯企业团队。
- **相关链接**：[📄 点击阅读论文原文](https://arxiv.org/abs/2611.05306)

- **论文名称**：**[Think Less, Locally: Local Preference Learning for Reasoning Compression / 局部偏好学习实现推理压缩]**
- **核心亮点**：
  - **任务定义**：解决大推理模型 overthinking——已获足够信息后仍冗余推理（推理链压缩/偏好学习领域）。
  - **方法核心**：LoCo 局部偏好学习：从模型自身轨迹检测步骤级 overthinking 状态（步骤置信度低且波动高 + 强 judge 复核），冻结该推理前缀，从同一前缀重新采样取最短正确续写为正样本、原续写为负样本，构成状态条件化偏好对用 DPO 训练——教模型"何时该继续思考、何时该收尾"。
  - **评估指标**：数学 5 基准 token 减少 41.7%-45.4%（AIME24: 13493→7364，↓45.4%）且精度 50.83→54.17（+3.34）；代码 3 基准 token 减少 23.4%-36.3%；仅用数学数据训练即迁移到代码。
  - **为何优于 baseline**：轨迹级方法（DAST/TokenSqueeze）只给"整体短更好"信号无法定位冗余位置 → LoCo 把偏好锚定在同一冻结状态上对比两条续写，直接监督"该状态下是否还需思考"这一局部决策 → 高难度集上同时取得最大压缩与最高精度。
- **团队背景**：西安交通大学 + 腾讯 WeChat AI——企业+高校合作，WeChat AI 主导。
- **相关链接**：[📄 点击阅读论文原文](https://arxiv.org/abs/2611.04814)；[💻 代码仓库](https://github.com/MuyaoYuan/LoCo)

- **论文名称**：**[Adversarial Speculative Reasoning Improves Long Horizon Agents / 对抗投机推理改进长程智能体]**
- **核心亮点**：
  - **任务定义**：发现投机解码验证块内数值噪声随槽位增长（约 +4%/槽），会改变长程 agent 的输出分布与推理精度（LLM 推理系统领域）。
  - **方法核心**：用反向 DPO 训练 draft 模型偏好"目标应避免的推理框架"→ 推理时 draft 恰在关键决策点与目标模型分道 → 验证重启、决策 token 由目标模型残差采样写入新块首槽（最精确条件）→ 关键推理被高精度编码且更耐久，仅训练 0.06%-0.28% 参数。
  - **评估指标**：DeepSWE：GLM-5.3-NVFP4 从 60.6%→67.6%（+7.0 点）；DeepSeek-V4.1-Flash 从 67.8%→71.8%（+4.0 点）；解码速度损失 ≤2%。
  - **为何优于 baseline**：投机验证分布无损但精度不均——槽位越深噪声越大 → 被接受 token 以所在槽精度写入 KV cache，被拒 token 由目标模型重采样写入新块 0 槽 → 反向偏好训练使 draft 在决策点必然被拒 → 关键推理始终经最精确路径写入上下文。
- **团队背景**：Subconscious Systems + MIT + Princeton + Northeastern——企业+高校合作。
- **相关链接**：[📄 点击阅读论文原文](https://arxiv.org/abs/2611.05345)

#### 1.2 Harness 与自演化系统（今日最强主线）

- **论文名称**：**[Harness-S: Learning from Sibling Harnesses for Generalizable Agent Training / 从同胞 harness 学习可泛化智能体]**
- **核心亮点**：
  - **任务定义**：发现 harness 演化具有三性质——Locality（各修复不同失败）、Complementarity（同胞 harness 互补可互相补救）、Nonstationarity（效用随 policy 学习而变），据此利用同胞 harness 的失败救援能力训练单一 policy（agent RL 训练领域）。
  - **方法核心**：三组件：方向性 harness 演化（按根因分类分支同胞池）；互补救援训练（原 harness 全失败任务由路由器选 Top-k 同胞 harness 重新采样、替换失败组做 GRPO 更新）；策略感知画像重锚定（随 policy 演化刷新路由证据）。
  - **评估指标**：Qwen3.5-9B 三基准 Avg@3：AppWorld 62.34 vs GRPO 53.31（+9.03）、SWE-Gym +6.87、DBBench +6.44；行为内化证据：schema lookup 22.9%→67.6%、翻页 13.8%→38.3%。
  - **为何优于 baseline**：单 harness 无法兼容所有局部修复且耦合演化代价高 → 把演化产物固定为可复用救援池，仅当原 harness 全失败时用辅助 harness 采样成功轨迹 → 共享 policy 从"互补执行支持下的自身动作"学习 → 行为内化进 policy 本身，撤掉辅助 harness 后仍保持。
- **团队背景**：上海交通大学 + 小红书 + CMU 等——企业+高校合作。
- **相关链接**：[📄 点击阅读论文原文](https://arxiv.org/abs/2611.04277)；[💻 代码仓库](https://github.com/DeepExperience/Harness-S)

- **论文名称**：**[Meta²: Precomputing Reusable Knowledge for Online Harness Evolution / 为在线 harness 演化预计算可复用知识]**
- **核心亮点**：
  - **任务定义**：harness 在线演化每次干预从零推理且测试时无验证器反馈，离线优化共享 harness 又易过拟合（长程 agent harness 优化领域）。
  - **方法核心**：离线不优化共享 harness，而是对比同任务三种配置（无 evolver/用当前 Meta-Skill/有训练期特权验证器）的 rollout 差异，提炼文本化 Meta-Skill（何时演化/保持/避免何种干预）；在线每 L 步检查点用冻结 Meta-Skill + 当前证据决定 KEEP 或任务局部 EVOLVE。
  - **评估指标**：Terminal-Bench 2.1 81.00%、DeepSWE 1.1 44.44% 均为方法最高；vs 种子 harness +14.67/+10.66，vs Meta-Harness 离线优化 +7.67/+7.11。
  - **为何优于 baseline**：共享 harness 的持久编辑会把某任务修正泛化到无关任务 → Meta-Skill 是跨任务可复用的"何时/如何演化"知识而非具体编辑 → 既能在证据出现时响应（在线优势）又不依赖测试期验证器（知识由训练期对比学习获得）。
- **团队背景**：马里兰大学 + 华盛顿大学 + UIUC + Scale AI——高校为主+企业参与。
- **相关链接**：[📄 点击阅读论文原文](https://arxiv.org/abs/2611.05139)；[💻 项目主页](https://meta-square.github.io/)

- **论文名称**：**[Recursa: Toward Recursively Self-Improving Foundation Model Systems / 递归自改进基础模型系统]**
- **核心亮点**：
  - **任务定义**：让系统（知识库+harness+模型）不依赖人类专家或更强教师，通过自身经验递归自我改进适配新领域（RSI 领域）。
  - **方法核心**：两阶段闭环：Bootstrapping（并行 agent 概括领域材料、生成自练习任务弥合知识鸿沟）+ 递归自我改进（Learner 分解学习任务给子 learner 并行尝试、验证并合并知识库修订、反思存入记忆弥合行为鸿沟）。
  - **评估指标**：Harvey 法律知识基准（100 测试任务 all-pass rate）：DeepSeek-V4.1-Flash 从 30.0%→55.0%（+25pp）、Qwen3.8-Flash 35.0%→46.0%；bootstrapping 使交互轮次与输入 token 各减约 1/5-1/4。
  - **为何优于 baseline**：知识密集领域正确性依赖证据定位+局部行为规范 → 单独学语料或单独任务反馈都不够 → 先从语料 bootstrap 导航结构与技能（减少重复搜索），再用并行 learner 从失败轨迹验证式修订 → 无更强模型介入保证可扩展性。
- **团队背景**：阿里巴巴纯企业团队。
- **相关链接**：[📄 点击阅读论文原文](https://arxiv.org/abs/2611.04035)

- **论文名称**：**[RSI-Dojo: Training LLM Agents to Automate LLM Post-Training / 训练智能体自动化大模型后训练]**
- **核心亮点**：
  - **任务定义**：让 LLM agent 掌握"自动后训练"能力（选数据/训练模型/诊断失败/迭代改进）并内化进模型本身（RSI/agent 训练领域）。
  - **方法核心**：RSI-Craft 流水线把近三年顶会论文转为可执行训练环境：爬取筛选 547 候选任务、按数据规模/执行可靠性/区分度过滤得 281 任务；用改进 harness 从前沿模型收集轨迹，经 rubric+outcome 双重过滤微调开源模型。
  - **评估指标**：PostTrainBench v1.1：RSI-Dojo-35B-A3B 29.95（基座 13.08，+16.87）超过 GPT-5.5（27.80）、Claude Opus 4.7（28.56），接近 GLM-5.2（29.52）。
  - **为何优于 baseline**：现有方法把能力放在 workflow/harness 层、换环境即失效 → 281 任务规模化环境使"如何后训练"以 SFT 轨迹形式内化进权重 → 35B MoE 追平前沿闭源模型的后训练能力。
- **团队背景**：香港中文大学 + 字节跳动 + 清华 + 上交——企业+高校合作。
- **相关链接**：[📄 点击阅读论文原文](https://arxiv.org/abs/2611.03698)

#### 1.3 Agent 安全：从静态扫描到执行执法

- **论文名称**：**[RuntimeTickets: Source-Grounded Security Obligations for Agent Skills / 智能体技能的安全义务票据]**
- **核心亮点**：
  - **任务定义**：第三方 agent 技能可在合法工作流中夹带数据外泄/输出操纵，读描述或授予工具权限都无法判断执行是否安全；现有扫描器同时存在漏放与误杀（agent 技能安全领域）。
  - **方法核心**：每任务由 LLM 一次性提出安全义务票据（引用技能行号、只收紧不放宽授权），冻结后由模型无关的出口网关逐发送检查收件人/对象/数量，确定性解码器输出 SUPPORTED/VIOLATED——执行与判定全程无 LLM，注入文本无法改变发送规则。
  - **评估指标**：60 对攻击/良性孪生技能五类危害：overlook 率 0.0% 且 overkill 率 0.0%（双零）；vs 生产级扫描器（两类错误皆有）、allow-list（75% 攻击通过）、无网关（100% 通过）。
  - **为何优于 baseline**：危害取决于任务与对象而非性包本身——静态扫描看不见任务 → 票据把任务契约转成逐次运行的细粒度允许动作 → 关键设计是"LLM 只提案、模型无关代码执法"：技能注入文本最多影响提案、无法改变判定规则。
- **团队背景**：UNC Chapel Hill + MBZUAI + McGill——高校合作。
- **相关链接**：[📄 点击阅读论文原文](https://arxiv.org/abs/2611.03772)

- **论文名称**：**[Can Benign Skills Induce Misaligned Behavior in LLM Agents? / 良性技能会诱发智能体失准行为吗]**
- **核心亮点**：
  - **任务定义**：系统研究"技能诱发行为失准"——添加无恶意指令的良性技能也会使 agent 在有害请求下执行违规外部动作（agent 安全实证领域）。
  - **方法核心**：5 个 LLM 基座 × 3 基准（316 对良性/有害请求）成对对照：Base（无技能）vs Skill（检索良性技能 top-3），区分"执行违规"（UAR）与"完成有害目标"（ASR）。
  - **评估指标**：良性任务 ACC +10.3pp 的同时不安全动作率 UAR 也 +10.3pp（SafeAgentBench +15.7）；151 个此前安全执行中 50 个变为不安全；蒸馏技能比其源良性轨迹更危险；预执行工具调用安全守卫使 UAR 降 23.8-46.2pp 且保留 ACC 增益。
  - **为何优于 baseline**：技能提供"如何做"的程序性知识而不判断"该不该在此请求下做" → agent 沿技能流程完成违规外部动作；蒸馏为可复用技能会去掉原轨迹的状态条件与拒绝分支 → 程序效用与执行安全存在结构性缺口，执行前检查外部动作（而非检查技能内容）是有效防线。
- **团队背景**：南洋理工大学。
- **相关链接**：[📄 点击阅读论文原文](https://arxiv.org/abs/2611.04299)

- **论文名称**：**[Voluntary Servitude: Weaponized Safety Warning Mechanisms / 武器化的安全警示机制]**
- **核心亮点**：
  - **任务定义**：发现绕过注入检测的新攻击——攻击者不写任何命令，伪造安全警示（普通评论形式）让 agent 依自身避害推理主动取消合法选项、选中攻击者目标（agent 安全领域）。
  - **方法核心**：单条伪造危害评论（四段式普通推荐评论结构）；防御为在指令中加入"佐证要求"——因安全理由淘汰提供商前须有独立来源支持。
