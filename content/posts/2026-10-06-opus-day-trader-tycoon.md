## 先说结论

一个 YouTuber 用 Opus 5.5 从近乎零起点造出了一款 C++ 原生的交易模拟经营游戏《Day Trader Tycoon》，仿《过山车大亨》画风，并且通过 API 与 WebSocket 把 Hyperliquid（加密永续合约）和 Polymarket（预测市场）的真实账户直接接进游戏——游戏里点确认，链上就是真钱成交。更值得注意的不是游戏本身，而是开发方式的三个信号：起手 prompt 只有一句话、加一个完整新功能只需约 20 分钟口头描述、数值平衡与测试由模型自己启动游戏跑数千个模拟日完成。创作者的观点很直接："说 AI 不会影响游戏开发的人，错得离谱。"按 skill 惯例先声明：以下所有能力与数字均为创作者在视频中的自述或演示，本文不对其独立核验。

## "这游戏是 C++ 写的，不是我写的"

按创作者自述，这个项目的起点是一句风格指令：让 Opus 5.5 "build a day trader tycoon game in the style of OpenRCT / RollerCoaster Tycoon"——OpenRCT 是经典游戏《过山车大亨》的开源复刻，是他 90 年代童年玩过的东西。他强调现在"不需要给那些疯狂的详细指令"了。第一版尝试其实是个赛马游戏，但"没那么好玩"，于是转向交易主题。

技术细节上，视频称整个游戏用 C++ 编写，使用"STL3 Metal framework"（转写疑似，应为 SDL3 多媒体库 + Apple Metal 图形 API）跑在 Mac 上，"所有美术资源也是模型自己写的"。这不是又一个网页小游戏——创作者特意区分了这一点。

游戏本体的经营层相当完整，从视频演示看包含：地下室起步、多显示器 rigs 与各类交易台（股票台、预测市场台、宏观台、加密台、永续 pits、风控台）的建造解锁机制；招聘（演示中有风控经理 Ivan、量化交易员 Ines——"她给公司赚了 2000 美元"）；协同加成（"quants +3 BPS edge"）；排行榜 AI 对手（榜首 Granite Street 1716 万美元、月收益 12%，还有对手以 "crypto degenerate" 风格爆仓出局）；组合页有最大回撤、资金费率等真实交易指标，杠杆随等级从 5 倍解锁到 40 倍。价格数据聚合自 Yahoo Finance、Hyperliquid、Polymarket 与一个转写为 "Calche" 的来源（疑似事件合约平台 Kalshi）。

## 真钱模式：游戏手柄直连实盘

真正让这个项目出圈的是 live trading mode：把 Hyperliquid 和 Polymarket 的 API 与 WebSocket 直接塞进游戏。视频里创作者从游戏内的 "Binary Booth" 买了一张 1 美元的 "5 分钟比特币涨跌" down 单，点确认后，真实成交出现在 Polymarket 的 "Bitcoin Up or Down October" 合约上——游戏内的持仓卡片和链上仓位一一对应。创作者称实盘模式带确认弹窗与"安全限额"（二元单上限目前设 10 美元），且这是一个把多个交易账户（Hyperliquid + Polymarket，理论上还能接券商）聚合到一个界面统一操作的终端。

这里有一条值得单独拎出的机制链：**交易所与预测市场平台开放 API + WebSocket → 周边必然涌现"体验层"创新 → 游戏化 UI 把娱乐用户低摩擦地引进受监管的金融活动**。游戏 UI 天然消解交易的严肃性——创作者自己也承认 live trading "就是个噱头（gimmick），但真的很好玩"。对监管视角而言，一个让用户在虚拟经营快感中按下真钱确认键的界面，其风险提示的显著性天然弱于正规交易终端；对产品视角而言，"多账户聚合 + 游戏化仪表盘"可能恰好击中散户的真实需求。两个方向都指向同一个观察指标：Polymarket、Kalshi、Hyperliquid 这类开放 API 平台周围，第三方客户端生态的密度会不会快速上升。

## 20 分钟加一个 AI 交易员，平衡性测试模型自己跑

视频后半段是最有信息量的部分：创作者现场演示"现在如何加新功能"。他用一段口语化的需求描述——"早期雇不起人，加一个 3000 美元可购买的 AI agent 系统，等级 2 解锁，能读新闻、自主下单、可分配预算"——贴给 Opus 5.5，然后关闭游戏。接下来模型自己启动游戏、截图、执行测试。为了标定这个 AI 交易员的数值，模型跑了 30 个市场日 × 8 个 agent × 4000 美元余额的模拟，并为排行榜所有对手、所有市场累计跑了"数千个模拟日"来做平衡与找 bug，测得 agent 平均胜率约 52%，以此调整参数。

新功能实测的决策回路值得注意：agent 读新闻终端的传闻流，比如一条"过去一小时 2 万枚比特币从交易所提走（吸筹）"，agent 判断概率 70% 而市场定价 64%，存在优势（edge），于是 5 倍杠杆做多；而另一条"通缩回来了"它判断 76% 对市场价 77%，判定"没有优势剩下"，不下注。每一笔决策都有可读的思考日志（thinking log），收益计入独立的 "AI agent's book"。创作者的评价是：可以挂机让它在后台自动交易。

这一段演示实际上把传统开发流程里的三个角色——实现者、QA、数值策划——压进了同一个 agent 会话。可迁移的原则是：**与其写更详细的实现指令，不如把验收标准写成可执行的模拟与测试**，让模型在闭环里自我标定；这个频道的实践恰好与"评测驱动 agentic coding"的社区共识互相印证。

## 哪些话要打折听

按不替播客背书的惯例，以下声明无法独立核实，读者应保持折价："所有资源都是模型自己写的"（无代码展示）；"跑了几千个模拟日"（只看到摘要输出）；游戏画面中升到排行榜第四、月收益 12% 等战绩属于创作者存档自述。另有两处结构性未定项：项目未开源、未上架（创作者称若视频反响达到"千赞级"会考虑开源或上 Steam），live 模式的确认与限额是否足以构成合规安全层也未经检验。转写层面另有一处开头说 "Opus 4.5" 与标题及全文的 Opus 5.5 不一致，疑为口误或 ASR 误识，本文统一按 Opus 5.5 表述并标注。

## 读者启发

从这条视频可以带走三条链条：其一，**前沿编码模型 → 个人造软件的边际成本趋近于零 → "为自己造的工具"成为新的内容品类**——本项目最初动机纯粹是"我想要一个自己觉得好玩的游戏"，发布与否只是事后选项；对个人而言，验证一个想法的成本已经低到"不值得犹豫"。其二，**agent 的自测自平衡 → 软件工程闭环内移 → 人的价值上移到"定义验收标准"**——创作者的核心贡献是一句风格指令和一段需求描述，而非任何一行代码。其三，**开放金融 API × 游戏化 → 娱乐与实盘边界消融**——这在带来体验创新的同时，也把"在游戏里输掉真钱"变成了一个真实的产品伦理与监管问题。

至于下一步观察什么：这个视频本身是否达到创作者设定的开源门槛；Opus 级模型 agentic 能力（自启动程序、截图、跑模拟）从 demo 到普及的速度；以及 Polymarket/Kalshi 生态里会不会出现更多把交易包装成游戏的客户端。三者任何一个兑现，这条视频就不只是一次个人的好玩实验了。
