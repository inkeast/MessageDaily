## 先说结论

这期视频记录的是「AI 投资建议」向「AI 投资执行」跨出的产品化一步：券商 Public.com 把 agent 能力直接做进了交易平台——桌面端一句自然语言就能生成一个挂在真实账户上的交易 agent（演示为 20 日 EMA 上穿 50 日 EMA 触发、每笔 300 美元的新云趋势反转策略），同时开放 API 与 MCP，让 Claude Code 这类编码代理直接读余额、读持仓、下单、挂止盈止损。真正的矛盾在于易用性与风险的错位：建策略的门槛降到一句英语，执行端却是真金白银的实盘自动交易——追问式参数确认、可暂停可编辑这些交互机制，就是券商对这对矛盾给出的第一版答案。节目引用的数据称 62% 的美国投资者已用 AI 做投资决策、约 41% 散户每周用 AI 做研究（均为节目称，未独立核实），若趋势为真，券商侧的 agent 产品化只会加速。需要再次强调：这是赞助视频，演示效果不构成对产品的背书。

## 从「问 AI 买什么」到「让 AI 替你下单」

视频冷开场就是成品预告：主播坐在一间第一人称视角的虚拟办公室里，俯瞰楼下工位上的 agent 们和一块旋转行情板——这是他视频后半段用 Public API 自建的「交易大厅」，先给结局再讲过程。

正文从两个数据切入（节目引用「最新数据」，未注明来源）：62% 的美国投资者已经用 AI 做过投资决策，几乎已有 41% 的散户每周都用 AI 做研究。主播的判断是：过去你只能「问 AI」，现在你可以「描述你要什么」，券商和公司正在跟进把这类能力做成服务。Public 的桌面端在组合管理界面里新增了 Agents 入口，左侧菜单：my agents（我已有的 agent）、marketplace（预建策略市集）、new conversations（新对话），以及两个功能分支——research（研究）与 build an agent（创建 agent）。

research 演示的问题是：「2026 年 10 月 CoreWeave、Nebius 这类新云（neo cloud，指 GPU 云/AI 基础设施公司）股票大变化的根本原因可能是什么」。后台可见它在调用 Public 自带的网页搜索等工具、可能有子 agent 参与，很快返回研究报告。报告结论（节目引用报告大意）：10 月的波动反映的是一场根本性辩论——纯粹的 AI 基础设施公司能否维持以债务为核心的资本开支模式；这不是单一事件，而是信用风险担忧、马斯克的高调看空警告、市场对 GPU 即服务生意盈利路径的广泛怀疑的叠加。主播对照行情验证：CoreWeave 一度跌了约 60%（主播称），认为报告「说得基本都在点上」，并特别称赞了速度。这段演示的信息量在于：研究 agent 的产出已经能直接挂在行情验证上，而不只是聊天窗口里的一段文字。

## 一句英语造一个趋势反转 agent：真正值得看的是追问式确认

接着是全片最核心的桌面端演示。主播用一句平实的英语描述需求：「我想设一个策略，跟踪这些新云股的趋势是否反转，反转了我们就跟进」。系统（主播称用的是 Public 的 AI agent）把它落实为一个针对 CoreWeave 和 Nebius 的趋势反转（trend reversal）策略，并先确认使用他的券商账户。

关键的交互机制在下一步：系统没有直接建完策略，而是连问四个后续问题——用什么信号、方向、动作、节奏（cadence）。主播逐项作答：信号采纳 agent 的推荐；方向向上；每笔交易 300 美元；节奏为每交易日开盘。最终生成的策略是：**每个交易日开盘时检查 20 日 EMA（指数移动平均线，对近期价格赋予更高权重的趋势指标）是否上穿 50 日 EMA**——即经典的均线金叉信号；上穿则买入 300 美元（Nebius 同样处理），两只都未穿越就不下任何单。点击 Create Agent 创建并激活，agent 上线，页面上可见触发器（开盘）、已设动作、交易历史与活动通知，工作流随时可编辑、可暂停、可删除，多个 agent 集中在一处管理。主播还展示了一个 11 月 2 日创建的「托管型」agent 与两个将在开盘运行的交易策略并存的界面。

这段演示的两面性都值得记住。好的一面：追问式确认把「一句模糊的英语」逼成了带参数的明确策略，可暂停、可编辑、全程留痕，这是负责任的交互设计；对不会写代码的人，这是从零到一的门槛拆除。风险的一面：EMA 金叉是入门教科书的经典信号，当生成一个执行它的实盘 agent 只需要一句话加四次确认，「人人可用」同时也意味着「人人同质」——这类信号的拥挤本身会侵蚀其有效性（主播未展开此点，属写作者推断）。产品还提供 prompt 指南与预建策略市集，进一步提高了策略的「模板化」程度，这既是卖点也是上述风险的放大器。

## API 与 MCP：把券商账户接进编码代理

桌面端之外，Public 开放了 API，主播称桌面端能做的一切都能用 API 做。上手流程被刻意讲得很轻：创建 API key（他顺手撤销了几个不用的旧 key），或者走 MCP 集成——MCP（Model Context Protocol，模型上下文协议）是眼下把外部工具与数据源挂进 Claude Code、Codex 等编码 agent harness 的流行方式，主播称「现在这个圈子里特别流行」，用 MCP 可以把账户全部数据接进你的编码代理。本期他重点演示 API：把 Public 的完整文档喂给 Claude Code，「一两分钟它就理解了如何用这个 API 完成一切」。

随后的演示全部用自然语言驱动：读出当日余额（含高收益现金等）；拉取完整持仓清单——股票与 ETF 合计约 7000 美元、债券约 4400 美元、现金若干，并按资产类别（asset class）汇总成总览；然后是真实下单——「我准备好从现金余额里投 50 美元进 ETF SPY」。Claude Code 先跑了一轮下单前检查（pre-flight check，正式提交前的逐项核对），随后提交买入，订单成交并返回订单号。更进阶的一组演示是 bracket 单与 OCO 单：bracket（括号单）为入场单附带自动止盈与止损——演示动画中价格上涨到目标位自动止盈成交，跌破则触发止损离场；OCO（one-cancels-the-other，二选一单）则对已持有股票同时挂限价卖出与止损单，一张成交另一张自动撤销。最后他让 Claude Code 现场生成了一个 HTML 监控面板（深色主题、Courier New 字体），实时跟踪两个在挂订单的价位变动。

这半段视频的信息量不在任何单个功能，而在「组合的自由度」：账户数据、下单、条件单这些券商核心能力全部接口化之后，一个会用编码代理的个人用户就能在几分钟内组装出读账—执行—监控的私有闭环。门槛从「会写量化框架」降到「会描述需求」。

## Floor 84：把账户变成《办公室》主题的第一人称交易大厅

视频最后回到冷开场的成品。主播用 Claude Code（模型为 GPT-6 Astra，他特意更正口误说这回用的不是 Opus，末尾又补充「大概也掺了点 Opus」）加 Public API，从一句 prompt 搭出了一个第一人称风格的「交易大厅模拟」：纽约摩天大楼顶层的开放式办公区，agent 们坐在工位上走动、互相搭话；他自己的办公室在更高一层，可以俯瞰全场、走近任何一个 agent 问在做什么、在电脑桌前新开出 agent。他给 agent 们起的全是美剧《办公室》（The Office）的角色名：Michael Scott 负责宏观策略、Kevin Malone 在股票研究、Dwight Schrute 做期权研究、Angela 管风控。

这个模拟不是空壳：大厅里的旋转行情板显示的是他真实券商账户的数据（账户价值 2700 美元、苹果持仓浮盈 500 美元，主播称）；向 Michael 提问，回答经由 Public API 取真实数据——英伟达 10 月 27 日成交价 217 美元（据 Public 数据，主播称）。最有意思的是会议室功能：设议程、点名参会 agent，他们分头研究后在会议室向他做幻灯片汇报——Michael Scott 的两页写着「宏观 hurdle、昂贵的资本」（slide 原文转写存疑）与「需求必须变成现金」，Dwight 的那页写着「波动本身不是边际（volatility is not an edge）」。会议结束，agent 们回到工位。

把这个成品放进他一个月的创作线里看是必要的：同一位创作者[10 月初用 Opus 造过交易主题游戏](https://inkeast.github.io/MessageDaily/posts/2026-10-06-opus-day-trader-tycoon/)，[11 月初用 Kimi K3.1 Pro 造过 AI 实验室模拟经营游戏 AI Labs Sim](https://inkeast.github.io/MessageDaily/posts/2026-11-08-all-about-ai-labs-sim-kimi-k31-opencode/)，三连作形态几乎同构——都是「编码 agent + 一个外部系统 + 为自己造一个空间」，只是这次外部系统第一次从纯虚构换成了接真实资金账户的券商 API，「游戏」的 HUD 变成了实盘 PnL。而他此前在 [Kalshi 公平价格一期](https://inkeast.github.io/MessageDaily/posts/2026-10-09-kalshi-ai-fair-price/)里花大力气论证的「先问价格错没错、没有边际就不出手」，在 Floor 84 里被 Dwight 浓缩成了一页 slide——同一创作者的两条线索（研究纪律与执行自动化）正在合流。这也提示了游戏化的一体两面：把账户变成可感知的空间确实提升了对资金的直觉掌控，但 PnL 变成游戏 HUD，也可能钝化对真实风险的感知（写作者推断，节目未讨论）。

## 三条值得带走的观察

**其一：券商 agent 化——自然语言建策略的易用性，对着实盘自动化的风险。** 变化：一句英语加四次追问确认即可上线一个实盘交易 agent。直接原因：AI 使用率数据（节目称 62%/41%）给了券商产品化的市场依据，获客竞争推动功能前置。谁获益/受损：不会写代码的散户获得了量化式的执行工具，券商获得粘性；受损的是把「易用」当「安全」的用户——模板化的经典信号（EMA 金叉）在实盘上的拥挤本身可能侵蚀信号有效性。二阶影响：若多家券商跟进，散户行为可能进一步同质化，「开盘触发」这类统一时点的集中可能改变市场微观结构。观察指标：券商 agent 功能的渗透率披露、策略市集热门模板的集中度、开盘时段成交量与波动形态的变化。读者启发：越容易生成的策略越不稀缺——在让 agent 执行策略之前，先回答「这个策略的边际来自哪里」（Dwight 那页 slide 是最好的注脚）。

**其二：API/MCP 开放——个人金融自动化的门槛从写框架降到说需求。** 变化：账户数据、下单、条件单全部接口化，且官方文档可被编码代理一两分钟学会。直接原因：MCP 生态兴起，券商争夺开发者型用户。谁获益：会用 Claude Code/Codex 的个人能把读账—执行—监控组装成私有闭环（本期演示的 HTML 监控面板就是最小样本）；第三方工具生态（面板、告警、模拟）获得生长基座。二阶影响：自动化链路越长，单点失控的代价越大——一个 API key 就是整个账户的操作权，主播随手撤销多余 key 的动作正是这套自由度的必要配套。观察指标：其他券商是否跟进开放 API 或官方 MCP server、key 权限粒度（只读/交易分离）的产品化进度。读者启发：接口化是双刃剑，key 管理即风控，给编码代理的金融权限应该默认最小化。

**其三：仿真层——「为自己造软件」正从游戏蔓延到金融界面。** 变化：一个月内同一创作者从模拟经营游戏（AI Labs Sim）走到第一人称交易大厅（Floor 84），外部系统从纯虚构换成了真实账户 API。直接原因：编码 agent 让「为自己造一个空间」的成本趋零，一句话 prompt 即可起步。谁获益：创作者与教育者获得把抽象账目变成可感知空间的手段；行业观察者获得前瞻样本——券商的下一代交互形态（空间化、agent 化）可能先从玩家实验里长出来。二阶影响：游戏化界面在提升掌控感的同时可能弱化风险感知，产品与监管都需要新的「冷静机制」对应物。观察指标：券商是否原生引入空间化/agent 化可视化、此类第三方模拟的扩散速度。读者启发：为自己的资金流亲手造一个界面，是建立市场直觉的高效练习——但记住你俯瞰的是真钱。

这期视频本身是一次赞助推广，文中数字（62%、41%、持仓金额、成交价）均为主播演示口播或节目引用，未经独立核实，演示效果不构成对产品的背书，本文亦不构成投资建议。但它作为样本的价值独立于推广性质：券商侧的 agent 产品化、API/MCP 开放与个人自动化生态，是「AI 参与市场」这条主线（可对照本博 [Kalshi 公平价格](https://inkeast.github.io/MessageDaily/posts/2026-10-09-kalshi-ai-fair-price/)与 [Sift 系列复盘](https://inkeast.github.io/MessageDaily/posts/2026-11-10-all-about-ai-sift-nov5-postmortem/)）从研究端向执行端的延伸——下一步值得盯的不是「AI 能不能预测」，而是「AI 执行的交互与风控机制长什么样」。
