# Decoupled Predictive Decision Making: A Shared Conditional Predictor for Agents —— 精读

> **论文链接**：[Decoupled Predictive Decision Making: A Shared Conditional Predictor for Agents](https://arxiv.org/abs/2611.02075)
> **发表时间**：2026年11月（arXiv 2611.02075v1）
> **机构**：Stable AI（Lang Mo、Xingxuan Zhang 等）、Tsinghua University（Peng Cui）
> **领域标签**：cs.AI / Agent 决策架构 / 条件预测基础模型

---

## 一、论文背景

### 1.1 Agent 的两种能力："看懂题"与"做对题"

一个通用 Agent 必须同时会两件事：理解它被要求做什么（语义能力），以及在具体部署环境里做出合适选择（从经验中学习的关系）。LLM 通过预训练获得了强大的语义能力——few-shot 适配、多步推理、工具调用都不在话下；但**一个选择的价值取决于做出它时的条件**：自适应检索研究表明不同查询适合不同检索策略，测试时算力分配研究表明分配方案应随难度变化——这些"什么条件下选什么"的**经验性关系**，任务描述本身往往给不出，只有部署后的观察才能揭示。

### 1.2 现有架构的耦合问题

把经验喂给 LLM 的已有路径各有形态：ExpeL 从经验中提取洞见并召回案例；Rememberer 用 RL 反馈更新外部记忆；Reflexion/Synapse 用反思文字或轨迹示例引导后续行为；Algorithm Distillation、DPT、Pre-DeToR 从交互历史中学习；SayCan 把语言规划与习得的技能价值结合。但论文指出：在以 LLM 为中心的系统里，**推理与动作生成紧密集成，检索到的经验由同一个语言模型解释**——语义解读、经验推断、答案生成三个职能挤在一个预训练机制里。后果是："从部署数据中学习特定关系"的机制**没有被暴露为可独立替换的组件**——你想提升经验学习能力，只能动整个语言策略。

### 1.3 一个关键的概念区分：信息 vs 推断

论文把决策误差拆成两个来源：(1) **信息缺口**——可得历史根本没揭示的关系；(2) **推断缺口**——学习机制没能用好的关系。前者靠积累更多经验解决，后者靠改进学习机制解决——**这是两个不同的研究目标**。增大历史测试前者（§3.3），同历史对比不同学习器测试后者（§3.2）。这个区分是全文实验设计的骨架（附录 H 还给出了风险分解的形式化）。

## 二、论文定位和关联工作

### 2.1 经验学习路线图

| 方法 | 机制 | 经验形式 | 学习器是否独立于 LLM |
|---|---|---|---|
| ExpeL | 提取洞见+召回案例 | 语言化 insights | ✗（LLM 解释） |
| Rememberer | RL 反馈更新外部记忆 | 记忆条目 | 部分 |
| Reflexion / Synapse | 语言反思 / 轨迹示例 | 文本 | ✗ |
| Algorithm Distillation / DPT / Pre-DeToR | 从 RL/交互历史学 in-context 策略 | 轨迹 | ✗（专用训练） |
| SayCan | 语言规划 × 习得技能价值 | 价值函数 | 部分 |
| Voyager | 经验固化为可复用技能库 | 技能代码 | ✗ |
| **DPDM** | **共享条件预测器 + 语义表示接口** | **表示化的 (记录, 目标) 对** | **✓（LimiX-2 可整体替换）** |

### 2.2 技术源头：条件预测基础模型

DPDM 的预测器不是本文训的，而是站在两条线肩膀上：**PFN（Prior-Data Fitted Networks）**证明跨预测任务预训练的 Transformer 能做贝叶斯推断；**LimiX-2（Contextual Mechanism Network）**把这一思想做成结构化数据基础模型。DPDM 的贡献是**接口**：通过 LLM 表示把语义丰富的 Agent 决策接到这个预训练推断机器上——"每个任务保留自己的语义与目标，学习机制只在表示化的记录与标签上运作"。

### 2.3 与 few-shot prompting 的本质区别（最重要的对偶）

few-shot：LLM **既**表示问题**又**从示例中推断**又**生成答案——一个模型三职。DPDM：LLM 只做表示（每条记录独立编码，历史标签**不进**语义编码的提示），推断交给专门的 LimiX-2，答案由决策规则（argmax）给出。这不是实现细节而是架构主张：**让"从经验学习"成为有自己的训练目标与评测标准的独立基础模型能力**。

## 三、问题定义

### 3.1 决策即条件预测

任务规范 𝒯 定义：可观测输入字段、预测目标的含义、候选答案集 𝒴_𝒯(r)。记录 r 包含目标揭晓前的信息（任务上下文、可见交互轨迹、有序候选描述）。历史 S = {(r_i, y_i)}，M 条记录及其**已观察到的目标**（历史反馈就记录为目标标签）；查询记录 r 的目标 y 未知。问题：估计 q_S(y | r, 𝒯)。

不同决策角色（工具适用性判断、候选偏好、推理步骤评估……）定义不同的记录与目标，但**输入接口相同**：表示化的历史示例 + 其目标 + 一个查询。这就是"共享"的含义。

### 3.2 两个冻结模型的分工

- 语义编码器 J_φ（如 Qwen3.5）：在目标问题与候选描述的上下文里表示每条记录；
- 共享条件预测器 F_θ（LimiX-2）：接收表示化历史与查询，返回候选答案上的概率分布；
- 决策规则：ŷ = arg max_y q_S(y | r, 𝒯)。

### 3.3 部署适配：只换历史，不换参数

新标签到来时 S⁺ = S ∪ ΔS，而 **φ⁺ = φ、θ⁺ = θ**——两个神经网络纹丝不动。可变的只有从历史输入拟合的特征变换 ψ（如 PCA/SVD 重新拟合）与由此产生的预测。这条"无参数更新适配"路线与微调派形成鲜明对照。

### 3.4 误差分解形式化（附录 H）

固定任务分布与损失，信息集 I（表示化的支持集与查询、历史目标、任务规范）下最优风险为 R*_I，学习者实际风险 R_m，oracle 拥有更富信息集 I_or。则超额风险 = **信息缺口**（R*_I − R*_{I_or}）+ **推断缺口**（R_m − R*_I）。两者非负。这给了"更多数据 vs 更好学习器"一个干净的数学表达。

## 四、问题解法

### 4.0 全景

```
任务规范 𝒯 + 记录 r ──→ [冻结语义编码器 J_φ (LLM)] ──→ 表示 z_S(r)
                              │  （每条记录独立编码；历史标签不进编码提示）
                              ▼
历史 S = {(r_i, y_i)} ──→ 表示化历史 {(z_S(r_i), y_i)} ─┐
查询 r 的表示 z_S(r) ────────────────────────────────┤
                                                      ▼
                                    [冻结条件预测器 F_θ = LimiX-2]
                                    （结构化数据预训练，32-pipeline 聚合）
                                                      ▼
                                    候选答案概率 q_S(·|r, 𝒯) ──→ argmax → 决策
```

### 4.1 记录表示：三路特征拼接

每条记录编码为一条"特征行"，三部分拼接：

1. **语义特征**：读取冻结 LLM 在**最后一个非填充提示 token**处的最终归一化后隐藏态（答案生成之前）；多个目标提示的状态拼接、L2 归一化、PCA 压到至多 32 维；
2. **词法特征**：可见文本字段的 TF-IDF，配历史上拟合的截断 SVD 降维；
3. **原生字段**：任务自带的数值/类别字段；类别映射与数值缩放只在历史输入上拟合，查询中的未见类别按缺失值处理。

关键纪律：**所有特征变换只在历史输入上拟合、原封不动应用到查询**；查询目标在表示拟合与预测全程不可见。

### 4.2 共享预测器 LimiX-2 的使用细节

所有任务共用同一个冻结 LimiX-2 检查点、32-pipeline 聚合、关闭检索、使用全部历史行。超过 10 个类别时用确定性标签层级 combine 父类与叶类概率；历史中未出现的类别初始概率为零；查询不可用的候选被剔除后重归一化，无概率质量则均分；并列时按候选顺序。带数值"情境-动作"输入的受控实验直接把数值喂给 LimiX-2 并选预测成功概率最高的动作。

### 4.3 与 few-shot 的成本结构差异

few-shot 把历史塞进 prompt：每条查询都要处理整个示例序列，历史长度受上下文窗口与运行时间预算钳制。DPDM 逐条独立编码历史：**历史编码一次、跨查询复用**，历史可以远超单条 prompt（FaithDial 上用到 8,192 条记录 vs few-shot 的 512 条）。这是后面 80.3% GPU 时间节省的结构性来源。

## 五、评估指标与实验证据

### 5.1 设置：50 基准 × 82 任务配置 × 5 类别

五个决策类别：Agent 任务（意图识别、工具适用性、响应模式判断、中间步骤评估、响应偏好：Banking77、BFCL Callability、ToolACE、ToolPRMBench、CodeCritic、HH-RLHF 等）、知识 QA（ARC、CommonsenseQA、HellaSwag、PRM800K、BIG-Bench Mistake 等）、证据一致性（FaithBench、RAGTruth、NLI 系）、安全可靠（BeaverTails、ToxicChat、仇恨言论、ADE Corpus、FaithDial 幻觉判断）、语言理解（AG News、情感、语法接受度）。

编码器四主（Qwen3.5-4B/9B/27B、Llama-3.1-8B）+ 四补充（StartLux 0.8B–27B）+ 外部参照 Jev API。每模型既做直接 prompting 又做 DPDM 语义编码器——同模型自对照。DPDM 结果为 3 个历史采样的均值±样本标准差。主指标：决策准确率（与任务参考目标的一致率）；不平衡场景用**平衡准确率 BA = (Acc_correct + Acc_incorrect)/2**（常数答案恒 50%）。

### 5.2 结果一：50 基准总表（各自历史预算端点）

| 编码器 | Zero-shot | Few-shot | DPDM |
|---|---|---|---|
| Qwen3.5-4B | 64.56 | 60.51 | **80.78 ± 0.11** |
| Qwen3.5-9B | 69.92 | 65.03 | **82.27 ± 0.15** |
| Qwen3.5-27B | 74.02 | 78.80 | **84.92 ± 0.14** |
| Llama-3.1-8B | 53.49 | 41.87 | **77.57 ± 0.13** |
| Jev API（参照） | 75.94 | 79.30 | —— |

四个编码器、五个类别全部超过 few-shot。27B 下 50 个数据集中 **46 个**胜出（两个小 Qwen 全部 50 个、Llama 49/50）。值得注意的细节：**三个较小编码器上 few-shot 反而低于 zero-shot**（示例引入多数标签偏置等干扰），而 DPDM 同时超过两者。Llama-3.1-8B 提升最戏剧：41.87→77.57（+35.7pp）。

**相同历史对照**（同记录、同顺序、同标签、同查询，覆盖全部 50 基准 82 配置）：27B 82.33 vs 78.80；4B 78.37 vs 60.51；9B 80.08 vs 65.03；Llama 73.83 vs 41.87——**证据完全相同时 DPDM 仍胜**，排除了"赢在历史更多"的解释。

### 5.3 结果二：Agent 任务细分与历史增长

五类里最关心 Agent 任务：Qwen3.5-9B 64.30→**83.16**、27B 76.41→**85.18**、Llama 40.77→**79.73**。单项：ToolPRMBench BFCL 42.59→**76.85**（**+34.26pp**）、ToolSandbox 68.04→**96.91**（**+28.87pp**）、CodeCritic Code 76.82→**90.85**、CodeCritic QA 65.85→76.62。

**历史增长实验**（21 基准 29 配置，M=32→8,192，两模型冻结、查询不变）：4B 69.78→80.98、9B 72.65→82.33、27B 75.48→84.87、Llama 63.81→78.74——**每个历史规模、每个编码器都单调上升**，证明"积累经验"这条轴在无参数更新下真实有效。FaithDial 极端例：DPDM 用 8,192 条历史达 83.53%，few-shot 用 512 条只有 54.70%。

### 5.4 结果三：不平衡历史（BIG-Bench Mistake）

历史里 66.41%–95.31% 的步骤是正确的 → few-shot 模型被带偏向"正确"答案，查错能力差。5 任务（Dyck、逻辑推演、多步算术、物体追踪、词排序）× 4 编码器，同历史同查询：平均 BA 从 **59.86% → 74.37%（+14.51pp）**，5 个任务全部改善、20 个编码器-任务对中 18 个获益。物体追踪细账：Qwen3.5-27B few-shot 拒绝 104 个错误步骤中的 42 个，DPDM 拒绝 **93 个**、同时正确接受 95.81% 的正确步骤——BA 69.07→**92.62**。

### 5.5 结果四：三组受控干预（机制归因）

| 对照 | 设置 | 结果 |
|---|---|---|
| **标签置换**（6 任务、128 历史记录、737 查询） | 打乱历史输入-目标配对、保持类频不变 | 原标签 **80.71±0.41** → 置换 **50.13±0.80**；多数标签规则 50.52±1.50——**增益几乎全部依赖正确的输入-目标配对**，不是类先验 |
| **新样本 vs 重复样本**（同 6 任务） | 16 条去重 / 16 条重复 8 次 / 128 条去重 | 60.31 / 64.79 / **80.71**——同为 128 行，去重比重复高 **15.92pp**：**新的独立观察**携带重复不具备的信息 |
| **语义特征消融**（8 任务、18,759 查询、历史上限 16/32/128/512） | 去掉 LLM 语义列、保留词法+原生 | 512 上限处 **80.42 → 63.95**（−16.47pp）；标签置换跌至 48.78——**语义表示与历史配对各贡献一臂** |

### 5.6 结果五：计算成本

五任务（AG News、BeaverTails、FaithDial、CommonsenseQA、CodeCritic Code），同历史、每任务 256 查询，与**带前缀缓存的** few-shot 比：DPDM 全流程 GPU 时间（含历史准备）为基线的 **19.7%**（等权平均，即降 **80.3%**）。逐任务：CodeCritic Code 仅 11.60%、FaithDial 12.65%、CommonsenseQA 最高也只 35.18%。

### 5.7 补充：决策专用后训练模型还能再涨（附录 D）

StartLux 系列是经过大规模决策样本全参后训练的模型。StartLux-27B few-shot 已达 83.85%，**冻结后做 DPDM 语义编码器仍升至 86.57%**（同历史下 84.20%）——即使模型为决策而生，"从部署历史学习"仍是尚待接通的第二能力源。

### 5.8 受控环境示例（附录 I）

4 上下文 × 2 动作 × 2 部署（部署一翻转部署零的成功率矩阵），oracle 知部署、Bayes 规则从历史推断部署。256 条历史时匹配部署的-history 给 **85.00%** 期望成功率（错误部署的历史 50.00%、固定动作 67.50%）；64 条时信息缺口仅 0.00115 而推断缺口 2.624 次失败/百次决策；**256 条时 LimiX-2 与 Bayes 在全部 20 个条件下选择完全一致（推断缺口为零）**——条件预测器在充足历史下能逼近理论最优。

## 六、效果优势的根源解释

### 解释 1：为什么同历史下 DPDM 仍胜 few-shot？（推断缺口的压缩）

因果链：few-shot 让 LLM 在生成答案时"顺便"从上下文示例中隐式推断条件关系 → 这个推断能力从未针对"从标注对中估计条件分布"优化过，且受多数标签偏置、示例顺序敏感等已知偏差干扰（三个小编码器上 few-shot < zero-shot 即为症状）→ DPDM 把推断职能量交给跨海量结构化预测任务预训练的 LimiX-2，其预训练目标正是"给定标注支持集估计条件分布" → 相同证据下决策更准（27B：82.33 vs 78.80；4B：78.37 vs 60.51）。【证据：§3.2 相同历史对照；附录 I 中推断缺口随历史增长收敛到零。】

### 解释 2：为什么 Agent 任务（工具步骤评估类）提升最大（+28~34pp）？

因果链：BFCL/ToolSandbox 这类任务的本质是"在带标注的相似情境库里做模式匹配式判断"（这个工具调用步骤好不好？）→ 正是条件预测器的本行：历史里每条 (步骤, 对错) 对都是直接监督 → 预训练的表格推断能力直接兑现；而 few-shot LLM 面对几十条带标签示例时既受偏置影响又不擅长系统性利用标签 → 差距被放大到 34pp。相对地，纯语义任务（语言理解类）few-shot 本来就强，提升幅度温和。【证据：§3.3 四个 Agent 判断任务的历史扩展曲线；BFCL 42.59→76.85。】

### 解释 3：为什么不平衡历史下 DPDM 的优势以 BA 计更大？

因果链：LLM 的 in-context 预测对示例标签频率与顺序敏感（Zhao et al. 2021、Fei et al. 2023 的已知结论，本文引用）→ 95% 正确示例的历史把 few-shot 拉向"永远答对"（Llama 在多任务上 A_incorrect=0.00~0.83%）→ BA 被压到 50 附近；LimiX-2 的条件预测把支持集当作分布估计问题而非生成延续，类频率影响被显式建模 → 物体追踪上错误步骤拒绝数 42→93、BA +23.6pp。**这不是 DPDM 学到了新知识，而是它对"示例分布"的响应方式不同**。【证据：§3.4 + 附录 E 全表（如 Llama 词排序 few-shot A_correct=100/A_incorrect=0 → DPDM 99.82/0.97 之外多数对双双均衡）。】

### 解释 4：80.3% 的 GPU 节省从哪来？

因果链：few-shot 每条查询都要（即使有前缀缓存也要）在长前缀上做注意力计算，且缓存构建本身要完整过一遍长 prompt → 成本随查询数×历史长度增长；DPDM 历史记录**独立编码一次**、之后所有查询复用这些表示行，LimiX-2 的预测在低维特征行上运行（查询侧只需编码单条记录）→ 256 查询下五任务平均只剩基线 19.7% 的 GPU 时间。【证据：§3.6 计时协议（含历史准备、排除加载与预热）；表 11 逐任务 GPU 小时。】

### 解释 5：为什么"冻结一切只加历史"的路线成立？

因果链：条件预测预训练（PFN/CMN 谱系）提供了"推断机制"这个可复用先验 → 部署历史的作用不是更新参数而是**实例化**问题特定的预测（提供支持集）→ 于是"适配"退化为"追加记录+重拟合特征变换"，无梯度、无灾难性遗忘、可随时回滚 → 历史增长实验中 32→8,192 单调上升、附录 I 中推断缺口收敛到零，说明瓶颈确实能沿"信息"轴移动。附注边界：该结论在"目标可由支持集推断"的评测形态下成立；若部署中目标语义漂移（历史上从未出现的判断维度），冻结表示可能不够。【证据：§3.3；附录 I；§4.1 的架构含义讨论。】

### 6.2 对照相关工作定位（依论文 Related Work/Discussion）

| 研究 | 关系 | DPDM 的差异 |
|---|---|---|
| ExpeL / Reflexion / Synapse | 经验以语言形式回流 LLM | DPDM 经验以 (表示, 标签) 对进专用预测器，LLM 不解释历史 |
| DPT / Algorithm Distillation | in-context RL，交互历史学策略 | 需为决策族专用训练；DPDM 用现成结构化数据基础模型，任务侧零训练 |
| PFN / LimiX-2 / CMN | 条件预测预训练基础 | DPDM 是其与语义决策任务的接口层 |
| ICR-RL / BC-ICL | 预测基础模型用于控制/上下文赌博机 | DPDM 覆盖语义异质的 50 基准并给出信息/推断分解 |
| SayCan | 语言规划 × 习得价值 | DPDM 的"经验学习"是可整体替换的共享组件而非配套价值函数 |

## 七、必要知识反推

### 7.1 领域知识层

- **条件预测 / in-context 学习的统计视角**：把"给支持集预测查询目标"看作分布估计问题（PFN 的贝叶斯推断视角）——理解"为什么结构化数据基础模型能当学习器"的前提；
- **in-context 偏置文献**：标签频率/顺序对 LLM 预测的影响（calibrate before use、标签偏置缓解）——理解 few-shot 为何在小模型上倒退、BA 实验的设计动机；
- **表格/结构化数据基础模型**：LimiX 谱系与 TabPFN（Nature 2025）的"跨数据集预训练推断机器"范式；
- **Agent 判断类任务的形态**：工具适用性、PRM 式步骤评估、偏好选择——为什么它们天然是"带标注历史库的条件预测"。

### 7.2 方法论知识层

- **信息缺口/推断缺口分解**：风险可加分解（附录 H），把"加数据"与"换学习器"变成可分别度量的研究轴——任何"系统靠经验提升"的评测都可用这个框架先问"提升来自哪一侧"；
- **同证据对照（matched-history）**：与 PACT-Check（潜空间通信审计）同理，控制"证据量"单独归因"机制"——增益归因纪律的又一范例；
- **置换/重复/去列三类干预**：标签置换保类频断"配对依赖"；重复样本同行数断"独立信息依赖"；去语义列断"表示贡献"——归因实验设计的模板；
- **平衡准确率与常数基线**：不平衡评测中 50% 基线的读法。

### 7.3 工程知识层

- **表示提取细节**：末 token 隐藏态、L2 归一化、PCA≤32 维、TF-IDF+SVD、原生字段——把 LLM 当特征提取器的标准流水线；
- **泄漏防控**：特征变换只在历史上拟合、查询目标全程隔离、历史与查询按源组分离、查询选取与标签无关；
- **概率到决策的工程**：层级标签合成、零概率类别处理、不可用候选剔除与重归一化、并列裁决——把通用预测器接到具体任务的"最后一公里"；
- **成本核算协议**：全流程（含历史准备）计时、前缀缓存基线、排除加载/预热——公平计时研究的做法。

### 7.4 知识融合的关键节点

1. **"表示与推断分家"**：把 NLP 的"LLM 表示一切"惯性与表格 ML 的"推断机器"传统焊接——两个预训练先验各司其职；
2. **"历史即支持集"**：把 Agent 经验流重看为条件预测的支持集——于是部署适配=追加支持集，零参数更新；
3. **"误差二分法"**：信息论式的风险分解（附录 H）落到实验设计（增长历史 vs 同历史换学习器）——理论区分直接变成实验轴。

## 八、论文中可以提取的通用性灵感

### 灵感 1：把"从经验学习"做成可独立替换的组件

- **核心思想**：复杂系统里"解释语义"与"从数据学关系"是两种能力，应各自暴露为有独立训练目标与评测标准的组件，而不是耦合在一个模型里——任一侧进步都能独立升级整个系统。
- **论文证据**：同一 LimiX-2 检查点跨 8 个编码器、50 基准复用；StartLux-27B（决策后训练模型）接上后仍 +2.72pp。
- **推广场景**：(1) 检索系统：语义索引器与排序学习器解耦升级；(2) 推荐系统的特征服务与排序模型分层；(3) 数据库优化器：基数估计器独立于查询计划器演进；(4) 医疗诊断：影像表示模型与风险预测模型分开认证更新；(5) 组织中的"前线感知"与"决策分析"职能分离。

### 灵感 2：用"冻结主干 + 追加证据"适配新环境

- **核心思想**：当推断机制本身足够通用时，部署适配可以完全绕开参数更新——新证据只是实例化一个新的决策函数，安全、可回滚、无遗忘。
- **论文证据**：S⁺=S∪ΔS、φ⁺=φ、θ⁺=θ；历史 32→8,192 准确率单调升。
- **推广场景**：(1) 边缘设备上的模型通过增加本地示例库适配而不重刷固件；(2) 合规敏感场景"模型权重只读"；(3) A/B 环境快速回滚（撤掉记录即回滚）；(4) 冷启动新客户：注入其历史数据立即生效；(5) 个人化助手以用户历史实例化行为而非微调。

### 灵感 3：区分"信息不够"与"没用好信息"再投资

- **核心思想**：性能不达标时先做分解——是证据根本没揭示规律（去采更多数据），还是机制没用上已有规律（去改进学习器）？两者的投资方向完全不同。
- **论文证据**：附录 H 风险分解；增长历史测信息轴（§3.3）、同历史对照测推断轴（§3.2）、附录 I 中两 gap 分别量化。
- **推广场景**：(1) ML 项目先查数据覆盖还是模型容量；(2) 客服质量：先补知识库还是改检索/排序；(3) 医疗误诊：检查手段不足 vs 判读能力不足；(4) 销售失单归因：市场情报缺失还是转化策略不当；(5) 教育诊断：教材信息量 vs 学生利用效率。

### 灵感 4：警惕示例的"多数偏置"——分布之外还有判别力

- **核心思想**：给系统看的历史若高度不平衡，它会把"常见"误当"正确"；评测须用对类不平衡鲁棒的指标（如 BA），机制上要显式建模支持集分布而非被其裹挟。
- **论文证据**：三编码器 few-shot < zero-shot；BIG-Bench Mistake 平均 BA +14.51pp；Llama 在两任务上 few-shot A_incorrect=0.00。
- **推广场景**:(1) 审核系统对"大多数正常"流水的异常召回评估；(2) few-shot 提示工程的类平衡示例设计；(3) 风控中正负样本失衡的指标选择；(4) 医疗罕见病诊断辅助的训练集构造；(5) 司法/招聘等高风险决策的公平性审计。

### 灵感 5：独立编码历史，跨查询复用——接口决定成本曲线

- **核心思想**：把"每查询处理全历史"改为"每记录编码一次、全查询共享"，成本从 O(查询×历史) 降为 O(查询+历史)——适用的前提是历史与查询可以解耦表示。
- **论文证据**：全流程 GPU 时间平均降至缓存 few-shot 的 19.7%；FaithDial 历史 8,192 条 vs prompt 512 条。
- **推广场景**：(1) RAG 的文档表示缓存与查询表示分离；(2) 数据仓库物化视图；(3) 编译器的增量编译缓存；(4) 多租户 SaaS 的租户上下文预计算；(5) 会议知识库：一次摘要、多次引用。

### 灵感 6：用置换/重复/去列三连对照审计"经验学习"的真伪

- **核心思想**：声称"从历史学习"的系统应做三问——打乱配对还灵吗（还是只在学类先验）？重复样本能替代新样本吗（还是只在数行数）？去掉表示还灵吗（还是全靠词面统计）？
- **论文证据**：置换标签 80.71→50.13（≈随机水平）；重复 8×只涨 4.5pp 而去重 128 条涨 20.4pp；去语义列 −16.47pp。
- **推广场景**:(1) RAG 系统的检索增益归因（打乱文档配对/重复文档/去检索特征）；(2) 推荐系统消融"历史行为 vs 流行度先验"；(3) A/B 实验的安慰剂组设计；(4) 员工"经验丰富"的归因审计（真因果知识 vs 幸存者偏差）；(5) 教育测评中区分理解与题海记忆。

### B. 术语备忘

- **DPDM**：Decoupled Predictive Decision Making，语义表示（LLM）与经验推断（条件预测器）解耦的决策架构。
- **记录 r / 目标 y / 历史S**：当前决策的可见输入 / 任务定义的答案或判断 / M 条 (记录, 已观察目标) 对——历史反馈以目标标签形式记录。
- **LimiX-2**：Contextual Mechanism Network，结构化数据预训练的条件预测基础模型，本文共享预测器实例（全程冻结）。
- **信息缺口 / 推断缺口**：最优规则因信息不足承受的风险 / 学习者超出最优可用信息规则的风险（附录 H 风险分解）。
- **多数标签偏置**：LLM 倾向复制上下文示例中的高频标签的现象，BA 实验的针对对象。
- **匹配历史对照（matched-history）**：两方法同记录、同顺序、同标签、同查询的比较，用于单独度量机制差异。
