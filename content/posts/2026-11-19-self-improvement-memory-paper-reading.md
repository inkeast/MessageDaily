## 一、论文背景

### 1.1 LLM Agent 的两半：策略模型与 Harness

一个 LLM Agent 的能力由两部分共同决定：一是**策略模型**（policy model），即冻结权重的大模型本身；二是 **harness**——围绕模型搭建的执行框架，负责管理上下文、工具、记忆与执行流程。可以做一个类比：策略模型像一位能力很强但不了解你公司流程的新员工，harness 则是员工手册、工具箱、审批流程与工作台的集合。同一个模型装进不同的 harness，表现可能天差地别——一个编码 Agent 的 harness 决定了它能否看到命令执行的真实报错、长命令是否会被截断、它声称任务完成时是否真的有执行证据。

改 harness 不动权重就能涨分，这让 harness 工程成为一条绕开昂贵的模型训练的性能提升路径。但手工调 harness 需要反复的工程迭代与评测，费时费力。于是出现了 **递归自改进（Recursive Self-Improvement, RSI）**：让 LLM 驱动的优化器利用执行反馈，循环地提出 harness 修改（propose）、执行评测（evaluate）、筛选保留（select），自动演化 harness。

### 1.2 RSI 的隐含假设：设定不变

现有 harness RSI 工作（Meta-Harness、AHE、RRSI 等）几乎都在一个**固定设定**内做优化：策略模型固定、基准固定。优化循环收敛后产出一个"演化 harness"，它在该设定上显著超过种子 harness。

但现实中的 Agent 系统是活的：模型会升级换代（Gemini 2.5 → 3.5 → 3.8 → 4），Agent 会遇到新任务分布（换基准、换数据集），多模型服务场景下一个 harness 要服务不同厂商的模型。每一次变动都意味着：**优化需要在新设定下继续**。这就引出两个根本挑战：

1. **适应新模型**。为一个策略模型调好的修改，换个模型可能表现完全不同。论文实测：Opus 演化出的 workspace harness 第一次跑在 Gemini 上只得 68.41 分，**低于** Gemini 种子 harness 的 73.89——精心优化十轮的成果，换模型后成了负资产。
2. **适应新数据**。策略固定但任务分布变化时，源优化没覆盖的失败模式会暴露。例如一个检查命令是否成功执行的完成门（completion gate），在新的任务分布下还需要检查可行解是否足够优化。

### 1.3 被丢弃的"为什么"

面对这两种过渡，只带着演化 harness 走进新设定是不够的。harness 代码只记录了**改了什么**，不记录**为什么改、当时预期修什么、实测结果如何**。目标设定的优化器看到一个来历不明的完成门，无从判断它针对的失败在新设定下是否还存在、实现方式是否还适用，只能盲改——可能把有用的守卫拆掉，可能重复已经失败过的方向。

这个问题的本质是：**源优化过程产生的证据（诊断、预测、实测）是有价值的经验资产，但它通常不随 harness 一起迁移**。论文要回答的核心问题就是：源优化期间积累的经验，能否帮助 harness 适应新模型或新数据？这正好与持续学习（continual learning）的经典关切——旧能力的保留与新变化的适应之间的张力——在 harness 层面汇合。

## 二、论文定位和关联工作

### 2.1 谱系一：Harness 递归自改进（RSI）

RSI 的思想源头可追溯到 I.J. Good 1965 年的智能爆炸构想与 Yudkowsky 的递归自改进论述。落到 LLM Agent 的工程实现上，近两年形成了一条清晰的谱系：

- **GEPA**（ICLR 2026）：用轨迹反思与重组优化提示词，是"用反馈迭代改写 Agent 配置"的早期形态，但只动 prompt。
- **Meta-Harness**（CoLLM 2026, Lee et al.）：端到端优化模型 harness，把历史实现、执行轨迹与分数经共享文件系统暴露给优化器，论文的文本分类实验直接沿用其在线分类环境。
- **AHE**（Agentic Harness Engineering, Lin et al. 2026）：把 harness 组件与修改结果做成可观测的，**将编辑级预测与后续任务实测对照**——论文的 SIM 在记录"预测任务 vs 实测修复"上直接继承了这个思想。
- **RRSI**（Xia et al. 2026）：正则化递归自改进，约束打包修改、停滞时重定向搜索；论文的 workspace/engineering 两域直接采用 RRSI 的环境、种子 harness 与评测接口。
- 更远的分支：DGM / Hyperagents 探索 Agent 程序的自修改与开放式演化；SIA 同时改 harness 与模型权重（本文明确定位在权重冻结一侧）；AlphaEvolve / FunSearch 把"生成-评估-保留"循环用于算法与基础设施代码发现，验证了自动评估器驱动的进化搜索在可验证域的可行性。

**与本论文的关系**：这些工作证明了 propose-evaluate-select 循环在固定设定内有效，且部分工作（AHE、Meta-Harness）已报告演化 harness 能迁移到其他基准或模型。但它们的**优化过程本身不延续**——换设定后要么直接用旧 harness（transfer），要么从头再优化。SIM 论文把问题推进为：优化过程本身如何跨设定持续。

### 2.2 谱系二：演化 harness 的迁移

- **ModularRSI**（Wu et al. 2026）：基准不相交的演化数据 + 模块化编辑，提升迁移泛化。
- **Harmony Harness**（Yu et al. 2026a）：把通用机制与基准特定适配分离。
- **PluginRSI**（Shi et al. 2026）：把演化出的插件库在后续优化中复用——这是"复用优化产物"的近期尝试。
- **Harness2 / Xu 2026**：用自由文本笔记与源任务回放做多任务演化的延续，或跨基准复用改进库。

**与本论文的关系**：这些方法努力让 harness 本身更可迁移，但论文指出其有效性仍依赖模型-harness 交互（Yang et al. 2026; Yu et al. 2026d），且它们没有把"优化的历史证据"作为一等公民随 harness 迁移。SIM 与它们正交：不管 harness 怎么改，历史证据都能指导续优化时的保留/修订决策。

### 2.3 谱系三：Agent 记忆

- **任务解决侧记忆**：Reflexion（NeurIPS 2023）把失败复盘写成语言反思存入情景记忆，下次尝试前读取——"语言强化学习"；Voyager（TMLR 2024）在 Minecraft 中把成功操作序列固化为可执行技能库，实现终身学习；ExpeL（AAAI 2024）从成功/失败轨迹蒸馏跨任务洞见；ReasoningBank 与 ACE（均 ICLR 2026）分别维护可检索的推理策略库与增量演化的上下文 playbook。
- **优化器侧记忆**：HarnessBank 按"被修改组件 × 被诊断失败"分组存候选 harness 供重组；Causal Improvement Graph 用图结构连接证据-假设-干预-结果；SkillHone 保存诊断、修订与评测证据；Turbo Harness 把完成的优化总结成 playbook。
- **持续适应性研究**：Chen et al.（2610.25858）与 Zhao et al.（2611.03219）记录了自进化 Agent 与编码 Agent 在任务流变化时的干扰与遗忘问题。

**与本论文的关系**：论文的关键区分正在于此——上述任务侧记忆服务的是**执行任务的策略**，优化器侧已有记忆则多存产物（候选 harness、编辑历史、改进图）。SIM 的独特位置是：**给优化器（proposer/selector）的记忆，按可复现的 harness 问题分组，绑定修改-预测-实测-出处四元组，并随 harness 一起跨越基准/模型边界**。检索侧还发现同期 Google 另一团队（Google+Purdue）的 EfficientSkill（arXiv:2611.19823）同样聚焦优化器侧（先学后压缩的技能文件演化），与本论文同属"harness 优化器自身如何记忆与管理经验"这一新方向，但二者团队与切入点不同（EfficientSkill 治技能膨胀，SIM 治迁移断裂），阅读时注意区分。

### 2.4 定位总结

| 维度 | 之前的路线 | 本论文的突破 |
|------|-----------|-------------|
| 优化设定 | 固定模型+固定基准内一次性优化 | 定义 CRSI：基准或模型更换后优化继续 |
| 迁移对象 | 只迁演化 harness（代码即产物） | harness + 完整优化经验（SIM）同时迁移 |
| 记忆主体 | 任务执行策略的经验记忆 | 优化器自身的结构化经验记忆 |
| 记录粒度 | 候选产物/自由文本笔记/编辑图 | 根因分组的（修改, 预测, 实测, 出处）证据链 |
| 评估方式 | 单次运行、终点分数 | 同起点同预算四条件对照 + 十次独立配对统计检验 |

**定位结论**：SIM 论文站在 Meta-Harness/AHE/RRSI 的肩膀上，把"RSI 的经验记忆"补进迁移方程，是 harness 进化与持续学习两条线的交汇点上的第一篇系统性受控研究。

## 三、问题定义

### 3.1 从具体困境到抽象问题

具体场景：换模型或换基准后，续优化器面对一份继承的演化 harness，要决定每个继承组件的去留。困难在于：harness 代码不含意图。

核心洞察：**harness 优化过程的副产品——诊断、预测与实测——恰好是判断继承组件适用性所需的证据**。这些证据在源优化中本来就会产生（AHE 甚至要求对照预测与实测），只是没有被结构化保存与复用。于是问题可以抽象为：

> 源优化得到的经验 E（关于"什么问题、试过什么、结果如何"的记录），能否作为目标优化的先验，使目标终分高于仅携带优化产物（演化 harness）的续优化？

### 3.2 形式化

- 设定 σ = (M, X)：策略模型 M 与任务集 X（划分为 evolve 集 X_evo 与 held-out 集 X_eval，只有 evolve 集反馈可用于提改、选择、更新记忆与停止）。
- Harness RSI：每轮 t，评测器执行 H_t 得反馈 F_t；proposer 生成 k 个候选：C_t = P(H_t, F_t, D_t)；selector 筛选并选择：H_{t+1} = S(H_t, F_t, C_t, F_C_t)；无候选被接受则 H_{t+1} = H_t。
- CRSI：源设定 σ_S 中优化得 (H_S, M_S 经验)；目标设定 σ_T = (M_T, X_T) 中从 H_S 续优化。**跨数据集 CRSI**：X_S ≠ X_T 且 M_S = M_T；**跨模型 CRSI**：M_S ≠ M_T 且基准与划分不变。两者要求 harness 可执行接口兼容。
- 度量：目标改进 = held-out 集上终分减起点分，J(·; M_T, X_eval_T)。

### 3.3 抽象的类比：经验迁移 ≈ 参数迁移 + 训练日志迁移

| 深度学习概念 | CRSI 对应物 |
|---|---|
| 预训练权重 | 演化 harness H_S |
| 训练日志（loss 曲线、消融记录） | SIM（根因/修改/预测/实测/出处） |
| 新任务微调 | 目标设定续 RSI |
| 只拿权重不拿日志微调 | Harness Transfer（业界常规） |
| 数据/目标分布漂移 | 基准更换（跨数据集） |
| 架构更换后旧权重部分失效 | 模型更换（跨模型） |

这个抽象的精妙之处：它把"harness 迁移"从一个二进制问题（迁/不迁）变成一个**证据条件的续优化问题**——续优化器不是盲人，而是带着一份带出处的实验档案做决策。同时它保持了最小侵入性：任何 propose-evaluate-select 型 RSI 方法都能套用 CRSI 设定，无需改动其提案、评测与选择程序。

## 四、问题解法

### 4.1 SIM 的数据结构：按根因分组的证据链

类比：医院病历。Harness 的问题像症状反复出现的病人，每次就诊（一次修改尝试）记录"诊断假设、开的药（修改内容及理由）、预后的预判（评测前预测哪些任务会被修复）、实际疗效（评测后哪些任务真被修复）以及就诊医院与日期（域/基准/策略/轮次出处）"。病历按病人（根因假设 c_i）归档，而不是按药品归档。

形式化地，一个 SIM 条目为：

```
m_i = (c_i, [(a_ij, o_ij, p_ij)]_j)
```

- **c_i**：根因假设，如"未经执行验证的提前完成"（premature completion）；
- **a_ij**：第 j 次尝试的修改及理由（what + files + rationale）；
- **o_ij**：预测与实测任务结果——**预测在评测前写下**（predicted：预计修复哪些任务），评测后对照记录 fixed / missed；即使修改被回退或没修好，实测结果照样追加；
- **p_ij**：出处（domain、benchmark、policy、round）。

关键设计点：

1. **预测前置**。评测前写下的预测让"预期修复"与"实测修复"可对照，这是识别"想修没修好"与"意外修复"的证据基础。
2. **失败也记录**。被选中但回退的编辑、没修复预测任务的编辑，全部留在条目里——已试方向不再重复，未解决问题保持可见。
3. **根因分组 + 确定性合并**。新提案必须引用既有根因或开新条目；根因文本相同则合并（保历史），存储用 JSON 带 aliases 字段记录合并映射（如 P6→P5）。匹配由 proposer 自身判断，无需单独的相似度模型。

### 4.2 SIM 接入优化循环：proposer 与 selector 都读全量记忆

类比：给深度学习训练加上"实验追踪系统对研究员完全透明"——不是检索式地只看相似实验，而是全量可见。

修改后的循环（对应论文式 3）：

```
C_t = P(H_t, F_t, D_t; M_t)          # proposer 读 SIM 提候选
H_{t+1} = S(H_t, F_t, C_t, F_C_t; M_t)  # selector 读 SIM 做筛选
M_{t+1} = U(M_t, e_t)                # 仅选中编辑（含实测）被追加
```

- **proposer**：每轮收到完整 SIM（无检索、无截断），新提案引用既有根因或开新条目；
- **selector**：读同一份记录评估候选——某方向历史上试过没成、某根因在新设定下的证据权重如何；
- **更新**：每轮只有被选中的候选连同实测结果写入（e_t），无编辑被接受则记忆不变。

Prompt 指引（附录 D.2）体现八条原则，核心有四：条目是先验经验但保留改写自由；基准或模型变化后重新评估旧修改的适用性；只有新证据才能重开已试方向；任务专属证据在相似设定权重高、基准与模型都变时权重低。

### 4.3 CRSI 流程：把 (H_S, M_S) 一起带入目标设定

1. **源 RSI**：从空 SIM 起步，产出 (H_S, M_S)；
2. **迁移**：Full SIM 把两者一起带入目标优化；proposer/selector 利用每条编辑的理由、结果与评测上下文判断其对当前失败是否仍适用，据此**保留、修订、替换或删除**继承修改，同时保留记忆中的历史记录；
3. **目标 RSI 期间**：新的尝试按同样格式追加到 SIM。

### 4.4 四种对照条件（受控实验的关键）

| 条件 | 起点 harness | 记忆 | 模拟的现实场景 |
|---|---|---|---|
| Cold Start | 种子 H_0 | 无 | 推倒重来、全新优化 |
| Harness Transfer | 演化 H_S | 无 | 业界常规：只迁 harness |
| Problem-Only | 演化 H_S | 仅根因 | 只带走诊断名目 |
| Full SIM | 演化 H_S | 完整记录 | 论文主张 |

后三个条件共享同一 H_S、同预算（N=10 轮 × k=5 候选、每任务 5 rollouts），记忆条件贯穿目标 RSI 全程——因此 Full SIM 对 Harness Transfer 的差距**纯粹归因于记忆**，对 Problem-Only 的差距则归因于"完整证据链 vs 仅诊断名"。

### 4.5 方法全景表

| 组件 | 输入 | 输出 | 作用 |
|---|---|---|---|
| 条目结构 m_i | 根因假设 c_i | (修改, 预测, 实测, 出处) 序列 | 按问题沉淀可追溯证据 |
| proposer（读 SIM） | H_t, F_t, D_t, M_t | k 个候选（引用/新开根因） | 避免重复已试方向、站在历史诊断上提改 |
| selector（读 SIM） | 候选 + F_C_t + M_t | 采纳/拒绝 | 据历史证据判候选风险与适用性 |
| 更新 U | 选中编辑 + 实测 | 追加或新开条目 | 失败也留痕，未解预测保持可见 |
| 跨设定迁移 | (H_S, M_S) | 目标续优化先验 | 支撑保留/修订/替换/删除决策 |

## 五、评估指标与实验证据

### 5.1 实验设计的四个问题

论文实验围绕四问：SIM 能否改善基准/模型更换后的续 RSI；完整记录是否优于仅根因；SIM 如何指导继承编辑的复用与修订；收益是否跨独立源 harness 复现。

### 5.2 四域基准与指标体系

| 域 | 源 → 目标 | 任务数（S/T） | 指标（0–100） |
|---|---|---|---|
| 编码 | Terminal-Bench 2.1 → TB4 | 89 / 66 | pass@1（每任务 5 rollouts 平均） |
| 文本分类 | 3 数据集套件（LawBench、Symptom2Disease、USPTO-50k）→ 8 数据集套件（AG News、GoEmotions、Banking77、FinancialPhraseBank、SciCite、TweetEval-Hate、Amazon5、SciTail） | 412 / 1000 | 样本池化准确率 |

### 5.3 指标如何证明论点：三层证据

**第一层：跨数据集 CRSI（策略固定为 Gemini 3.8 Flash，6 设定）**

| 设定（起点分） | Cold Start | Harness Transfer | Problem-Only | **Full SIM** |
|---|---|---|---|---|
| 编码 / AHE（18.18） | 19.39 | 20.61 | 18.79 | **24.85** |
| 编码 / Terminus-2（19.39） | 19.39 | 19.39 | 20.61 | **21.82** |
| 文本分类 / NoMemory（71.40） | 72.00 | 71.00 | 73.40 | **73.60** |
| 文本分类 / FewShotAll（72.92） | 75.92 | 74.12 | 75.52 | **77.92** |

| 工程 / ReAct（39.13） | 40.87 | 42.61 | 42.61 | **46.96** |

Full SIM 在全部 6 设定终分最高：超 Harness Transfer **2.43–4.35 分**，超 Problem-Only **0.20–6.06 分**。Problem-Only 效果不稳定（相对 Harness Transfer 从 −1.82 到 +2.40），说明仅有诊断名而无证据链不足以支撑判断。

两个值得注意的细节：(a) **源优化提升不保证目标起点更好**——源 RSI 在全部 6 设定把 held-out 源分提升 2.75–6.41 分，但 FewShotAll 演化 harness 在目标套件起点 72.92 反低于种子 75.72，且 Harness Transfer 终点 74.12 仍低于 Cold Start 的 75.92——直接迁移甚至可能是负资产，而 Full SIM 到 77.92 完成翻盘；(b) NoMemory 上 Cold Start 提升幅度（+3.40）大于 Full SIM（+2.20），但终分仍输（72.00 vs 73.60）——论文因此同时报两点与增益，并以共享起点的 Harness Transfer 作为记忆机制的直接对照。

**第二层：跨模型 CRSI（Opus 5.5 演化 → Gemini 3.8 Flash 续优化，4 域）**

| 设定（起点分） | Cold Start | Harness Transfer | Problem-Only | **Full SIM** |
|---|---|---|---|---|
| 编码 / AHE（13.94） | 19.39 | 18.18 | 20.61 | **21.82** |
| 文本分类 / FewShotAll（77.72） | 82.72 | 80.20 | 81.32 | **83.80** |
| Workspace（68.41） | 82.98 | 73.42 | 79.22 | **84.75** |
| 工程（34.78） | 40.87 | 42.61 | 46.96 | **50.43** |

Opus 演化 harness 在 Gemini 上起点全部低于 Gemini 种子（差距 0.60–5.48 分）；Harness Transfer 终点在 3 个域仍低于 Cold Start，而 Full SIM 四域全部最高，超 harness-only **3.60–11.33 分**。workspace 最戏剧化：同起 68.41，Full SIM 到 84.75，harness-only 只到 73.42（差 11.33 分）——还低于 Gemini 种子直接冷启的 82.98。跨模型差距（最高 11.33）系统性大于跨数据集差距（最高 4.35），因为模型更换时 harness-策略交互改变最剧烈。

**第三层：十次独立配对研究（编码，统计效力保障）**

从 Terminus-2 种子在 TB2.1 上独立跑 10 次源 RSI，每个演化 harness 初始化一对 TB4 续优化（一个带 SIM 一个不带，其余全同）。结果：SIM 在 **10 对中赢 9 对**（唯一输的一对 −0.61），共同起点均值 18.36，SIM 终点均值 21.70 vs 无 SIM 19.33，**配对优势均值 +2.36 分（95% CI [1.05, 3.68]，双侧配对 t(9)=4.06，p=0.003；符号秩检验 p=0.006；标准化效应量 dz=1.28）**。以独立源 RSI 运行为分析单元，排除了"碰巧一次好源 run"的解释。

### 5.4 三个补充设定

- **模型代际链**（TB2.1 上 Gemini 2.5 Flash → 3.5 → 3.8 → 4 Argon，harness+SIM 逐代相传 vs 每代从种子重优化）：CRSI 在 3.5/3.8 两代超 Fresh RSI +3.5/+1.6 分（4 Argon 低 0.8）。第一代两法同种子，差值即 SIM 对首轮 RSI 本身的增益（22.4 vs 21.4）。
- **一 harness 服务三模型**（Grok 4.20/Opus/Gemini，文本分类）：统一合成（S2，每轮汇总三模型反馈）held-out 75.24 ≈ 分别演化 harness 的 75.20（B1），高于共享种子的 73.28 与顺序 CRSI 的 74.20；单模型演化 harness 交给别的模型只有 66.84–72.24。共享 harness 可行，且多模型反馈合成是构建它的较好方式。
- **proposer/selector 换模型**：源 RSI 的优化器换成 Opus，held-out 源分更高（AHE 91.28 vs 90.22；Terminus-2 91.61 vs 91.56），说明 SIM 机制不绑定特定优化器模型。

### 5.5 证据链小结

同起点、同预算、四条件对照（6+4=10 设定 Full SIM 全胜）→ 十对配对统计检验（p=0.003）→ 案例级证据（P5/P8/P3 条目）→ 源保留追踪（TB2.1→TB4 迁移中 Full SIM 仅丢 3/225 个成功 rollout vs harness-only 丢 6，同时目标增益 +6.67 vs Problem-Only 的 +0.61）。预算方面：每 run 10 轮 × 5 候选，编码每轮约 4 小时（含 1.7 小时评测、34 分钟候选采样），所有条件轮数与候选数严格匹配。指标体系直指核心主张：**记忆本身（而非额外算力或更好起点）带来了续优化优势**。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**对比对象**：Harness Transfer（业界常规）曾有效，因为演化 harness 确实把源设定的通用机制（命令分块传输、JSON 修复、完成门）编码进了代码。

**baseline 的根本局限**：演化 harness 是优化过程的**最终产物快照**，它压缩掉了过程信息——为什么改（诊断）、当时预期什么（预测）、实际如何（实测）。代码只有"是什么"没有"为什么"。这不是"缺个注释"的表面问题，而是导致了不可逾越的推断障碍：**继承组件的适用性判断在逻辑上需要反事实信息（当时不加会怎样、加了实际修了什么），而这些信息物理上不存在于产物中**。无 SIM 续优化只能把继承代码当作自己第一轮的产物来对待，论文的案例精确记录了这个失败模式：无 SIM 的 run 把继承的完成门误归因于自己第 1 轮、4 次改门其中 2 次在修"完成死锁"——它在不了解门存在理由的情况下收紧了门，制造了死锁再修死锁，空耗轮次。

**SIM 的根本性改变**（因果链，标注证据等级）：

1. SIM 把根因-修改-预测-实测-出处五元组绑定 → 续优化器获得了判断继承组件适用性所需的反事实证据【论文案例已支持：F.3 中 SIM run 保留 P5 理由并按目标需求扩展检查】；
2. 根因分组让"要求可迁移、实现需重写"的区分成为可能 → P5（完成需要证据）的要求跨基准成立，但"何为足够证据"从"命令是否执行"变为"解是否最优"，SIM run 据此扩展门而非推倒重来【论文案例已支持：P5→P8 案例】；
3. 失败留痕避免重复搜索 → 已试方向（如 P8 第 4 轮的硬阻塞后来被改）在记忆中保持可见，后续轮次不会盲撞【论文实验已支持】；
4. 出处字段支持证据加权 → prompt 指引明确"基准与模型都变时任务专属证据降权"，跨模型场景（证据适用性最不确定）恰是 SIM 收益最大处（11.33 分）【前半为论文设计、后半为论文数据；二者组合的解释为阅读者推测，与论文叙述一致】；
5. Problem-Only 的不稳定表现（−1.82~+2.40）反向证明：仅诊断名而无修改-预测-实测证据链，判断所需的反事实信息仍然缺失【论文实验已支持】。

**反事实推理**：若去掉"实测记录"只留"预测"，proposer 将无法区分"预期修复且真修复"与"预期修复但失败"两类方向，重复失败方向的代价回归——这正是 Problem-Only 与 Full SIM 差距（0.20–6.06 分）所量化的部分。若去掉"失败也记录"，已试未成的方向（P8 前两次尝试 fixed 均为空）将被重试，轮次预算被空耗。

### 6.3 综合判断与未决问题

- **多项研究共同支持的机制**：(a) 结构化外部记忆优于隐式产物（Voyager、ACE、ReasoningBank 与 SIM 一致）；(b) 失败/实测信息是记忆的关键成分（Reflexion、ExpeL、ReasoningBank 与 SIM 的失败留痕一致）。
- **仍属合理推测的部分**：出处加权规则（"双变降权"）与 11.33 分最大差距之间的因果解释得到数据形态支持（跨模型差距 > 跨数据集差距），但论文未做该规则的消融。
- **适用条件**：harness 可执行接口兼容（论文明确边界）；记忆条目量小到可以全量读入（无检索无截断的设定在条目规模大时可能失效）；收益在 10 轮 × 5 候选预算内测得，更长链路上的表现未验证。
- **可能失效的条件**：模型代际链中 4 Argon 一代 CRSI 反低 0.8 分，提示当新模型自身强到接近基准饱和（95.6 vs 89.7）时，继承经验的边际价值可能转负；跨域太远时根因假设可能整体失效，此时 Problem-Only 与 Full SIM 的差距应缩小——论文未测此边界。

## 七、必要知识反推

假设让一个完全没有背景的人重做这项工作，他最少必须掌握什么？

### 7.1 领域知识层

- **Harness 与策略模型的分离**：不理解"harness 决定上下文/工具/执行流、权重冻结也能涨分"，就无法定位这个问题值得做。来源可以是 AHE/Meta-Harness 的阅读与实践。
- **RSI 循环的形态**：propose-evaluate-select 的外环、evolve/held-out 划分防泄漏、滚动评测反馈——这是 CRSI 的直接基座。
- **迁移的失败模式**：必须知道 harness-策略交互的存在（Opus 的修复对 Gemini 可能有害），否则不会想到"起点可能低于种子"这一反直觉现象并围绕它设计对照。

### 7.2 方法论知识层

- **持续学习的问题框架**：保留旧能力 vs 适应新分布的张力、干扰与遗忘的度量——CRSI 的设定构造（源保留追踪 TB2.1 + 目标增益 TB4 双指标）直接套用了这套框架。
- **受控实验与配对设计**：四条件同起点同预算对照、以独立源 run 为分析单元的十对配对 t 检验——没有这层知识，结论就会被"你只是多花了算力"或"碰巧好源 run"击穿。
- **病历式知识组织**：按问题（根因）而非按产物组织经验的直觉，与循证决策中"干预-预期-实测"对照的思想同构；AHE 的编辑级预测对照是最直接的先行示范。

### 7.3 工程知识层

- **基准与评测接口工程**：四域基准（TB、分类套件、workspace 评审、冻结验证器）的选择、对半切分、重叠题记零分防泄漏、失败 rollout 留在分母——评审接口的可靠性直接决定结论可信度。
- **优化循环的预算与成本核算**：10 轮 × 5 候选、每轮 4 小时的成本结构、候选与 rollout 预算分离——不知道成本量级就无法设计可比对照。
- **prompt 工程**：八条记忆使用指引（先验非硬约束、双变降权、新证据才能重开方向）是把记忆变成行为的接口。

### 7.4 知识融合的关键节点

1. **融合节点一：RSI × 持续学习**。把"任务分布变化下的学习"视角从模型权重搬到 harness 优化过程——两个领域的文献都存在，但交汇点此前无人系统研究。
2. **融合节点二：证据记录 × 迁移决策**。AHE 的编辑级预测对照（为可观测性而生）被重新定位为"迁移决策所需的反事实证据"——记录的目的从 debug 变成跨设定复用。
3. **融合节点三：病历组织 × LLM 上下文**。根因分组 + 全量读入（无检索）的组合，恰好在"结构化可追溯"与"LLM 可直接消费"之间取了平衡点——这是对 LLM proposer 消费记忆方式的工程判断。

## 八、论文中可以提取的通用性灵感

### 灵感一：产物之外，过程经验是独立的一等资产

- **核心思想**：优化过程的副产品（诊断、预测、实测、出处）与最终产物（优化后的工件）是两种可分离的资产，迁移时应打包携带。
- **论文证据**：同一起点同预算下，harness+SIM 比 harness-only 终点高 2.43–11.33 分（10/10 设定）；十对配对 +2.36 分（p=0.003）。
- **推广场景**：(1) 编译器调优——flag 组合的试验记录随配置文件迁移到新硬件；(2) 数据库查询优化——计划调优的假设-实测记录跨数据集版本复用；(3) 个人知识管理——决策日志（为什么选、预期什么、结果如何）随项目档案交接；(4) 自动化机器学习——超参搜索轨迹随数据漂移继续；(5) 运维故障处理——根因条目库随基础设施演进持续追加。

### 灵感二：按问题组织经验，而非按方案组织

- **核心思想**：以"反复出现的问题/根因假设"为主键组织记忆，让同一问题的多次尝试（含失败）自然聚合，比按产物/工具/时间组织更能支撑"要不要再试"的判断。
- **论文证据**：根因分组使 P5 的三次源尝试聚合、P8 两次目标尝试与未解预测可见；对比 Problem-Only（仅问题名）效果不稳（−1.82~+2.40），完整条目才是有效粒度。
- **推广场景**：(1) 客服知识库按客户问题类型而非答案模板归档；(2) 医院 MDT 病例库按病理假设组织治疗史；(3) 软件缺陷库按根因而非表面症状聚类；(4) 销售 playbook 按客户异议类型沉淀应对话术试验史；(5) 科研实验室 notebook 按假设分组记录实验。

### 灵感三：预测前置 + 实测后置的对照是知识的质检器

- **核心思想**：在验证之前强制写下"预期修复什么"，验证后强制对照实测，能把"自以为有效"与"真有效"区分开，形成可积累的证据。
- **论文证据**：SIM 每次尝试记录 predicted/fixed/missed；P8 两次被选中的修改 predicted 4 个任务 fixed 0 个，预测保持未解状态——防止后续轮次高估该方向；P5 三次尝试实现 4/6 预测。
- **推广场景**:(1) A/B 实验文化——上线前登记预期指标与量级；(2) 医疗——治疗前后预期症状对照记录；(3) 投资——交易前写投资逻辑与预期，事后复盘偏差；(4) 教育——预习预测 vs 测验结果的元认知训练；(5) 法务——诉前风险评估 vs 判决结果归档。

### 灵感四：要求的可迁移性高于实现，迁移时保留要求、重写实现

- **核心思想**：一条经验的"要求"层（完成需要证据）与"实现"层（什么算足够证据）可迁移性不同；跨设定时应识别要求并为其重写实现，而非整体照搬或整体丢弃。
- **论文证据**：P5→P8 案例——完成门的要求跨 TB2.1→TB4 成立，但证据标准从"命令是否执行"变为"可行解是否最优"，SIM run 扩展门（275→437 行）而保留其状态机骨架。
- **推广场景**：(1) 安全合规——内控目标跨司法辖区不变、控制措施本地化重写；(2) API 设计——接口契约稳定、各平台 adapter 重写；(3) 组织管理——质量目标不变、流程按团队规模重定制；(4) 教育——培养目标不变、教学法按学生重选；(5) 翻译本地化——品牌诉求保留、表达重写。

### 灵感五：失败与被替换的尝试也要留痕，防止搜索历史随产物更迭而丢失

- **核心思想**：只保留当前最优工件的组织，会在每次替换时丢失"为什么放弃旧方案"的知识；被替换方案的历史应与其诊断、未解预测一起保留。
- **论文证据**：P8 第 4 轮的硬阻塞编辑后来被改掉，但记录留在 SIM；无 SIM 的 run 误把继承门当自己第 1 轮产物、两次修自己制造的死锁——正是"搜索历史丢失"的行为画像。
- **推广场景**：(1) 代码库——被 revert 的 PR 附决策记录（ADR）防重提；(2) 药物研发——失败化合物与假设留档防重复立项；(3) 产品——下线功能的实验数据保留，环境变化后可复活；(4) 政策评估——废止政策的原始依据归档；(5) 机器学习——剪枝掉的模型分支与其验证记录保留供后续搜索。

### 灵感六：换引擎（模型）比换路况（数据）更需要经验记忆

- **核心思想**：当交互双方（模型×harness、员工×流程）中一方整体替换时，历史证据的边际价值最大，因为此时"什么还适用"最不可知。
- **论文证据**：跨模型 SIM 优势 3.60–11.33 分 > 跨数据集 2.43–4.35 分；workspace 跨模型案例中 harness-only 终点（73.42）甚至低于种子冷启（82.98），而 Full SIM 达 84.75。
- **推广场景**:(1) 团队换负责人——交接文档中的决策史比流程文档更关键；(2) 生产系统换底层框架——迁移经验记录决定适配速度；(3) 车队换电动平台——维修经验库按"问题是否仍存在"重审；(4) 多语言产品换翻译引擎——术语库与失败案例跨引擎迁移；(5) 换供应链——历史谈判记录随供应商切换复用。

以论文中被完整追踪的 P5 条目为例（存储为 JSON，字段含 id、name（根因名）、opened_round、attempts[]；每次尝试含 round、sample、accepted、what、files、predicted、fixed、missed、passed/total、domain）：

- **P5 = "未经执行验证的提前完成"**（源 TB2.1 第 6 轮开立）
  - 第 6 轮：新建 execution_gating_interlock.py（137 行）跨轮状态机，拒绝"上轮解析错误/无命令执行"时的完成请求（上限 3 次）→ 预测 [circuit-fibsqrt, configure-git-webserver]，实测全修复（两任务各从 1/5 → 5/5），通过 49/60；
  - 第 8 轮：拦截模拟多轮文本/截断丢弃命令块/仅 1 条真实命令即完成 → 预测 [constraints-scheduling]，实测修复，通过 45/60；
  - 第 10 轮：完成请求时检测终端崩溃/断言失败/HTTP 404/测试错误 → 预测 3 个任务，实测修复 1 个（configure-git-webserver），missed 2 个，通过 47/60——**未解预测保持可见**。
- 目标 TB4 阶段新开 **P8 = "优化任务中可行但次优解的提前终止"**（domain: tb4，出处即知其为目标原生）：第 2、4 轮两次被选中的修改（最优性提示 + 可行性分数阻塞）predicted 共 4 个任务、fixed 0 个；第 4 轮的硬阻塞后来被回退，最终 harness 保留源状态机四条拒绝路径 + "可行≠最优"提示，而 P8 的两次尝试与未解预测完整留档。
