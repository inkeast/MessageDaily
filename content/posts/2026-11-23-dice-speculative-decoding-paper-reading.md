## 一、论文背景

### 1.1 自回归解码的瓶颈与投机解码

大语言模型逐 token 生成文本，每生成一个 token 都要把完整模型权重从显存读一遍。在 batch size 为 1 的交互式场景下，这个步骤受限于显存带宽而非算力——大模型验证 5 个 token 与验证 1 个 token 的耗时几乎相同。**投机解码（Speculative Decoding, SD）**正是利用这一空隙：让一个轻量起草器（drafter，小模型或附加模块）先猜出 K 个候选 token，再让大目标模型（target）一次前向并行验证，接受最长合法前缀。通过精心设计的接受规则（modified rejection sampling），输出分布与目标模型单独采样完全一致，即所谓"无损"。

标准投机采样中，起草器提出的 token x 以概率 min(1, p(x)/q(x)) 被接受，其中 p、q 分别是目标与起草分布。两条奠基性工作 Leviathan et al.（ICML 2023）与 DeepMind 的 Chen et al.（2023）各自独立证明了该规则的分布保持性。

### 1.2 两类不确定性：一个被忽视的不对称

预测"目标模型会走哪条路"涉及两类不确定性：

- **目标预测的不确定性**：起草器无法完全预知目标模型的输出分布 p。要消除它必须跑一次目标前向，代价高昂。
- **采样随机性**：即使 p 和 q 都固定，采样结果仍随随机数变化——验证时用的均匀数 u 决定接受阈值 p(x) ≥ u·q(x)，Gumbel 扰动 g 决定 Gumbel-max 采样的选择。

过去几年几乎所有进展（EAGLE 系列、Medusa、DistillSpec 等）都在攻击第一类不确定性——训练更强的起草器让 q 逼近 p。但作者指出一个关键不对称：**第二类随机性可以在起草前就采样固定，并同步给起草方**——它根本不需要目标前向。

### 1.3 核心洞察：阈值已知，"投机"变"半确定"

以 q(x)=0.5 的固定提议为例：若验证数 u=0.1，则只要 p(x)≥0.05 就接受——x 几乎稳过，应沿 x 深挖；若 u=0.9，则需 p(x)≥0.45——x 很可能被拒，应提前准备替代分支。**p 仍然未知，但接受阈值已经已知**。同一份起草预测，配合不同的 draws，最优的算力分配完全不同。这就是标题的含义：投机解码其实没有你想象的那么"投机"——它有一半的随机性可以提前揭示。

## 二、论文定位和关联工作

### 2.1 起草质量路线：让 q 逼近 p

- **Medusa**（Cai et al., ICML 2024，arXiv:2401.10774）：在目标模型顶层加多个轻量解码头并行预测未来多个 token，配合树注意力一次验证，Medusa-2 达 2.3-3.6× 加速。无需独立草稿模型。
- **EAGLE / EAGLE-2 / EAGLE-3**（Li et al., ICML 2024 / EMNLP 2024 / NeurIPS 2025，arXiv:2503.01840）：在特征层而非 token 层起草，利用目标倒数第二层特征；EAGLE-2 用草稿置信度动态建树；EAGLE-3 放弃特征预测、改用多层特征融合与 training-time test，将加速比推到 6.5×，并使草稿模型随训练数据规模持续受益。
- **EAGLE-4**（2026 preprint）：高效起草器 + 成本感知的动态树尺寸调节，面向不同 batch size 与硬件。
- **MTP**（Gloeckle et al. ICML 2024；DeepSeek-V3）：多 token 预测模块，推理时作为内置草稿头。

### 2.2 候选组织路线：树结构优化

- **SpecInfer**（Miao et al., 2024）：开创树结构候选的并行验证。
- **Sequoia**（Chen et al., NeurIPS 2024）：考虑硬件相关成本，鲁棒地优化树拓扑。
- **OPT-Tree**（Wang et al., TACL 2025，arXiv:2406.17276）：显式最大化期望接受长度 E(A) = Σ 节点路径概率之和，贪心构建自适应草树，加速比达 3.2×，强草稿器 + 充足预算下单步可产出十多个 token。

### 2.3 异步路线：重叠起草与验证

- **SSD（Speculative Speculative Decoding）**（Kumar et al., 2026，arXiv:2603.03251）：在目标验证当前提议的同时，为可能的下一轮前缀预取草稿，缓存 B 个条目；命中则省去一次起草等待。
- **SwiftSpec**（Zhang et al., ASPLOS 2026）：分离式投机解码与融合内核，降低延迟。

### 2.4 共享随机性路线：本文的精神近亲

- **Coupling without Communication / 起草器不变投机解码**（Daliri et al., ISIT 2025）：用共享随机数（Gumbel 采样）替代最优耦合，使输出只依赖种子与目标模型、与起草器无关——目的是**可复现性**，接受率反而可能受损。
- **Rowan et al.**（NeurIPS 2025）：把耦合扩展到多份草稿，建立条件起草器不变性。
- **Kobus & Gündüz**（ACL 2025 Findings）：指数竞赛投机采样，用边际节点接受概率分析树构建。
- **PTP（Parallel Token Prediction)**（Draxler et al., ICLR 2026，arXiv:2512.21323）：最接近的同期工作——把采样随机数作为模型**输入**，训练一个模型在单次前向中联合预测多个未来 token，2.4× 加速。但它需要训练新模型。

### 2.5 定位总结

| 维度 | 之前的路线 | DICE 的突破 |
|------|-----------|-------------|
| 信息源 | 只用草稿分布 q | q + **已揭示的验证随机数**（u、g） |
| 手段 | 训练更强起草器 / 优化树结构 | 训练自由地改打分与选点，不改起草器 |
| 无损性 | 接受规则保证 | 命题 1/2 证明输出与目标采样逐 token 一致 |
| 适用面 | 各自方法绑定 | 叠加在 OPT-Tree、EAGLE-2/3/4、MTP、SSD 之上均有效 |

DICE 的定位：**不替换以上任何一条路线，而是为它们全部提供一个此前被丢弃的免费信号**。与共享随机性路线相比，DICE 首次把随机数从"耦合样本的工具"升级为"指导投机计算分配的先验信息"。

## 三、问题定义

### 3.1 从具体场景到抽象问题

**具体场景**：给定预算 N 个树节点（或 B 个预取缓存槽），草树应包含哪些候选 token？

**深层结构**：现有方法（如 OPT-Tree）把这个选择抽象为最大化期望接受长度 E(A)——每个节点乘以其**边际**被访问概率。但"被访问"取决于目标采样将走向哪里，而这由两部分决定：目标 logits z（未知）与随机数（可先验固定）。现有方法把两部分都当作不确定，只用 q 近似；DICE 发现第二部分的不确定性是**人为保留的**——随机数完全可以在起草前揭示。

**形式化**：给定前缀 h、起草器 D、预算 N、温度 T 与 draws {gᵢ}（起草前采样并同步），构造草树 S 使条件期望接受长度 E[A | {gᵢ}] 最大化——即在"这一次采样运行"的条件化概率空间里优化，而非在边际期望意义下优化。

**抽象类比**：

| 概念 | 类比 |
|------|------|
| 验证 draws | 提前翻开的一部分底牌 |
| 目标 logits | 对手仍未亮出的手牌 |
| 草树构建 | 在已知部分底牌下决定如何下注 |
| 接受长度 τ | 本轮下注的实际回报 |

### 3.2 这个抽象的精妙之处

约束条件的松绑是不平凡的：命题 1 证明，只要 draws 按绝对位置索引、树以任何方式依赖 draws 构造，输出序列都与自回归 Gumbel-max 采样逐 token 完全一致——**条件化只改变"每轮发出多少 token"，不改变"发出哪些 token"**。这意味着揭示随机数是纯粹免费的自由度，无损性不被破坏。

## 四、问题解法

DICE 由两个实例化组件和一个工程实现构成。

### 4.1 组件一：种子感知草树构建

**类比**：随机效用模型（multinomial logit，McFadden 1974）——把"目标会选哪个 token"建模为"已知效用 + Gumbel 噪声"的选择问题。

**做法**：在每个节点 x 处，目标是 argmax(zₓ + T·g)，其中 zₓ 未知、g 已知。用草稿 logits dₓ 近似 zₓ，得局部分：

```
r̂ₓ(v) = softmax_v( (α·dₓ(v) + T·g(v)) / σ )
```

- α 校正草稿 logits 相对目标过尖或过平的尺度；σ 度量目标偏离缩放后草稿的程度。α→∞ 时退化为 argmax(αd + Tg)，σ→∞ 时趋于均匀。
- **校准**：对每对目标-起草器，用解码中观察到的前 2000 个节点（约 1-3 个 prompt）做一次最大似然拟合。对数似然在参数化 (a=α/σ, b=1/σ) 下是凹的，几步梯度下降收敛，也可在线进行。附录 A 显示 1600 节点即可恢复全量拟合 98-100% 的似然增益。

**路径分**：ŵ(xv) = ŵ(x)·r̂ₓ(v)，估计节点被验证访问的概率。三个用途：局部分决定**提议哪些子节点**；累计分决定**扩展哪些节点**；最终路径分选 **Top-N 进入验证**。动态树尺寸开启时还指导起草深度与验证宽度。

**正确性**（命题 1，附录 B）：按绝对输出位置索引 draws，参考序列 y* 由目标自回归 Gumbel-max 采样定义。归纳法可证：每轮从 y* 的前缀出发，验证到达的节点要么被接受前进、要么在缺失处发出 bonus token 结束——无论树如何依赖 draws 构造，每轮发出的都是 y* 的下一段。**树只决定每轮发多少，不决定发什么**。

### 4.2 组件二：种子感知异步预取

**类比**：在知道部分抽奖结果的前提下，对"验证会在哪里停下、停下后接什么 token"做贝叶斯估计，把有限的 B 个缓存槽押在概率最大的结果上。

**做法**：验证结果 (k, v) 决定下一轮前缀。两类已知 draws 各管一半：

1. **接受数 uᵢ 预测停在哪**：把接受条件改写为 ρᵢ = pᵢ(xᵢ)/qᵢ(xᵢ) ≥ uᵢ。目标概率不可得，但对校准过的草稿有 E[ρᵢ|qᵢ]=1 且 0≤ρᵢ≤1/qᵢ——在 [0,b] 上均值为 1 的分布中熵最大的截断指数分布 fq 完全由 q 决定（速率 λ 由均值约束唯一确定，查表可得，无拟合参数）。接受概率 η̂ᵢ = Pr(ρ≥uᵢ) 有闭式，连乘得接受恰 k 个的概率 P̂(k)。
2. **Gumbel 向量 g_{k+1} 预测接什么**：对每个 k，从 fq 采样比率构造修正/奖励 token 权重 m̂ₖ(v)（拒绝时为残差 [p−q]₊ 形式、全接受时为 p 形式），固定 g_{k+1} 重复 argmax(log m̂ₖ + g_{k+1}) 得频率估计 r̂ₖ(v)。

合并为 π̂(k,v) = P̂(k)·r̂ₖ(v)，选 B 个最高分结果异步预取（实现上 M=16 候选、S=128 分层样本）。

**正确性**（命题 2）：投机采样的分布保持只需 (i) 提议抽自 q、(ii) 验证随机数独立于提议。DICE 只选择"为哪些前缀预先起草"，不改变提议的分布来源，预取与 miss 后补起草在分布上等价。

### 4.3 工程实现

draws 用确定性 counter-based 哈希按"请求种子 + 绝对 token 位置 +（Gumbel 的）词表索引"按需生成；接受、目标采样、草稿提议使用独立随机流。起草与验证 worker **即使在不同 GPU 上也能本地重放同一 draws，无需存储或传输随机数缓冲区**。打分融合进现有 GPU 候选选择内核（词表过滤时施加已知扰动），可被 CUDA graph 捕获，零额外前向。

## 五、评估指标与实验证据

### 5.1 指标体系

- **主指标**：解码吞吐（tok/s）与相对自回归（AR）的加速倍数——直接度量"算力是否花在了被使用的续写上"。
- **辅助指标**：平均接受长度 τ（每次目标前向产生的 token 数）；预取场景的缓存命中率（Hit）。
- **消融指标**：打乱 draws、仅子节点用 draws、不同停止模型对 τ/命中率的影响——分离"信息"与"扰动"。

### 5.2 实验设置

16 对目标-起草器（5 个独立小起草器 + OPT-Tree、8 个 EAGLE-2/3/4、3 个 MTP），其中两对 EAGLE-4 同时在 SGLang 与 vLLM 上评（共 18 个模型-后端配置）；基准为 Spec-Bench（对话/翻译/摘要/数学/QA/RAG）与 SPEED-Bench；预取用 SSD 原版四件套（Alpaca/GSM8K/HumanEval/UltraFeedback）。默认 T=1、并发 1、H200 GPU。baseline 为各起草器原生方法的最快配置。

### 5.3 树解码主结果（表 1 摘选）

| 配置 | AR | Baseline | DICE | 增益 |
|------|-----|----------|------|------|
| Llama-3.1-8B/EAGLE-3，Spec-Bench | 34.7 | 81.1 (2.33×) | 98.6 (2.84×) | +21.5% |
| Llama-3.1-8B/EAGLE-3，SPEED-Bench | 32.4 | 53.1 (1.64×) | 66.2 (2.05×) | +24.6% |
| Llama-3.1-70B/8B，SPEED-Bench | 13.0 | 17.2 (1.32×) | 21.2 (1.63×) | +23.6% |
| Qwen3.8-27B/EAGLE-4，vLLM SPEED | 169.6 | 377.6 (2.23×) | 456.4 (2.69×) | +20.9% |
| Qwen3.8-27B/MTP，SGLang Spec | 136.3 | 299.8 (2.20×) | 320.3 (2.35×) | +6.9% |

全部 16 对均提升：Spec-Bench +4.3-21.5%，SPEED-Bench +5.6-24.6%，接受长度 τ 同步上升（如 Llama-70B/8B 从 4.37 到 7.31）。这个设计之所以能证明论点：**草稿权重与推理后端完全不动，唯一变量是"是否使用已知 draws 分配算力"**，吞吐差异只能归因于分配本身。

### 5.4 预取结果（表 2）

四对配置命中率从 45.6-67.6% 提升至 69.8-80.7%，吞吐 +4.0-13.7%（最高 Llama-70B base 对 +13.65%）。τ 几乎不变——因为 DICE 只改变"准备哪些草稿"而不改草稿本身，这精确对应方法设计的意图。与 Saguaro 重塑分布的参数 C 正交：每个 C 下 DICE 都稳定加 13-18 个百分点命中率，二者组合达 177 tok/s（vs SSD 最优 C 的 168）。

### 5.5 温度与并发扫描

- **温度**：T=0 时 DICE 与 EAGLE-4 同速（贪婪验证下 draws 无信息）；温度升高，EAGLE-4 吞吐明显下滑而 DICE 降幅小得多——树是"为真正会用的 draws 而建"。SSD 命中率在 T=1 跌到 57-60%，DICE 保持约 80%。
- **并发 1-64**（Qwen3.8-27B，SPEED-Bench）：DICE 在 SGLang/vLLM 每个并发点都是最快，领先最强 baseline 2-18%/8-20%；并发 64 时并行起草器 DFlash2/DSpark 跌破 AR 而 DICE 仍保有 1.19×/1.28×。引擎在高并发收缩为单链起草时 DICE 原样适用（链即每节点单子的树）。

### 5.6 消融：增益来自信息还是扰动？

- 打乱 draws（与目标 draws 独立但保留扰动）：τ 反而**下降 11-14%**；同步 draws 提升 11-24%——增益来自"知道目标将用哪些随机数"，不是加噪声。
- 仅子节点选择用 draws、预算仍按草稿概率分配：大部分增益消失——信息必须作用于**分配**才有效。
- 覆盖率 C_d（树覆盖目标实际续写的概率）随深度拉开差距且逐层扩大，其深度方向的求和恰为 τ，直接解释吞吐提升的来源。
- 预算越大优势越大：EAGLE-4 需 64 节点才达到 DICE 16 节点的 τ；DICE 用 8 个缓存结果匹配 SSD 用 24 个的命中率——同一预算下信息换算成 4 倍效率。
- 两类 draws 分工明确：仅 u 或仅 g 各把命中率从 59.8% 提到 66.9-67.9%，合并达 76.2%。

### 5.7 需要多精确的建模？

plug-in 默认参数（α=σ=1）已带来 9-22% 的 τ 提升；校准再加 1-2 个点；神经预测器只再加至多 1.5 个点（held-out 似然 0.94 vs 0.95 nats）。预取侧换用任意"随观测 draws 递增"的停止模型，命中率都在最大熵模型 3 个点以内；忽略或反向使用 draws 则损失 10-17 个点。**结论：收益主要取决于是否使用真实 draws，而非目标分布估计的精确形式**——排序够好即可，不必完整建模目标。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**因果链一（树解码）**：

1. 验证规则 p(x)≥u·q(x) 的右端 u·q(x) 在 u 已知时变为已知阈值【论文式(1)，论文实验已支持】
2. 小 u ⇒ 阈值低 ⇒ 当前路径大概率延续 ⇒ 算力向深度倾斜；大 u ⇒ 阈值高 ⇒ 需要备胎 ⇒ 算力向广度倾斜【机制推理，由覆盖率曲线 C_d 逐层扩大直接证实】
3. 同预算下树覆盖实际采样路径的概率 C_d 在深度 >1 后逐层领先【论文图 5b，实验已支持】
4. C_d 的深度求和 = 期望接受长度 τ ⇒ τ 提升 ⇒ 每次目标前向摊薄更多权重读取 ⇒ 吞吐上升【定义级推理 + 表 1 数据支持】

**因果链二（预取）**：

1. uᵢ 序列已知 ⇒ 拒绝位置的分布被条件化 ⇒ P̂(k) 集中在真实停点附近【机制推理，命中率提升证实】
2. g_{k+1} 已知 ⇒ 修正/奖励 token 的 Gumbel-max 结果可部分预判【机制推理】
3. B 个缓存槽押在 π̂(k,v) 最高分上 ⇒ 命中率 +13-18pp ⇒ 省去 miss 后的起草等待 ⇒ 吞吐 +4.0-13.7%【表 2 + 图 6，实验已支持】

**反事实验证**（论文最有力的一组证据）：打乱 draws 不仅无效而且**有害**（τ −11-14%）——排除"任何扰动都帮忙"的替代解释，把增益唯一归因于"揭示真随机数"这一信息源；仅用 draws 选子节点而预算仍按 q 分配则增益消失——说明信息必须流经**分配决策**而非仅仅改变局部选择。

**无损性的根源**：命题 1/2 的证明结构表明，条件化作用于"每轮产出多少 token"这一维度，而"产出哪些 token"由目标 logits 与 draws 联合锁定——随机数从"验证时的偶然"变成"起草时的已知"没有改变任何边缘分布。这是该信息源"免费"的根本保证。

| 研究（可核验链接） | 相似尝试 | 相关结论 | 与本文的差异与适用边界 | 对根源解释的影响 |
|---|---|---|---|---|
| OPT-Tree（[TACL 2025](https://aclanthology.org/2025.tacl-1.8/)） | 同样最大化期望接受长度 E(A)=Σ路径概率 | 证明"预算分配质量"直接决定接受长度——与 DICE 的 C_d 机制同构 | OPT-Tree 的路径概率用草稿 q 的边际概率；DICE 换成条件于 draws 的 ŵ。E(A) 最优性是边际意义下的，条件化后仍有建模误差 | **支持**：确认"树覆盖采样路径概率→τ→吞吐"这条因果链在无 draws 时同样成立，DICE 是在更好的条件化空间里做同一优化 |

| PTP（[ICLR 2026, arXiv:2512.21323](https://arxiv.org/abs/2512.21323)） | 同样把采样随机数作为**模型输入**，让未来 token 成为随机数的确定函数 | 独立得出"揭示随机性使并行预测可行"的结论，2.4× 加速 | PTP 需蒸馏/逆自回归训练专用模型；DICE 训练自由、即插即用，且作用于任意现有起草器 | **强支持（结论相近）**：两条完全不同的技术路径（训练式 vs 打分式）都证实"已揭示随机性是可利用的信息源"，这是对论文核心命题最有力的外部验证 |

| SCD（Speculative Coupled Decoding，ICML 2026） | 视觉自回归生成中让相邻轮草稿共享 Gumbel 噪声提高碰撞概率 | 共享随机性把"概率空间近、样本空间远"的错位拉回 | 视觉生成场景，耦合对象是相邻轮 draft 而非 draft-target；Gumbel 噪声按 token 全局索引哈希在线生成与 DICE 实现同源 | **补充**：跨模态证据——共享随机数思想在视觉 AR 加速中同样有效，且"哈希生成随机数零开销"的工程手法被独立重复 |

### 6.3 综合判断与未决问题

**多研究共同支持的机制**：(1) 树覆盖采样路径概率决定接受长度（OPT-Tree 无条件版 + DICE 条件版 + EAGLE 系列的置信度建树实践）；(2) 并行验证边际成本近零（Medusa/SpecInfer/Sequoia 的系统研究共识）；(3) 已揭示随机性是可利用信息源（PTP 从训练角度独立证实）。

**仍属推测的部分**：α/σ 校准的跨域稳定性（论文只验证了 7 对模型、1600 节点；域外分布漂移时校准是否需要重做未讨论）——标注为阅读者推测。

**优势成立条件**：T>0（采样模式）；草稿大致校准（最大熵模型的 E[ρ|q]=1 假设）；单请求或并发不饱和（高并发下引擎收缩树时增益收窄但仍为正）。

**可能失效条件**：T=0 贪婪解码（draws 无信息，论文实测同速）；草稿严重未校准时截断指数模型的均值假设失真；若未来采样策略不再暴露可先验固定的随机数流，机制前提消失。

## 七、必要知识反推

假设一个零知识的人要完成这项工作，最少需要掌握：

### 7.1 领域知识层

- **投机解码全流程**：draft-verify 循环、接受规则 min(1,p/q)、残差分布修正、bonus token——不理解"验证一次前向就能检查所有候选"就无法意识到分配问题是核心瓶颈。
- **Gumbel-max 技巧**（Maddison et al., 2014）：采样 = argmax(logits + Gumbel 噪声)。这是整个方法的语言——没有它就无法把"验证随机性"统一表达为可预生成的扰动向量。
- **LLM 服务引擎内幕**：SGLang/vLLM 的树验证、CUDA graph 捕获、GPU 候选选择内核——决定方法能否零开销落地。

### 7.2 方法论知识层

- **随机效用模型与 multinomial logit**（McFadden 1974）：已知效用 + 独立 Gumbel 噪声 ⇒ softmax 选择概率。局部分公式直接由此导出，α/σ 的凹似然与校准方法也依赖这一理论。
- **最大熵原理**：在"均值约束 + 支撑集约束"下选截断指数分布——预取的比率模型无需拟合参数的根源。
- **投机采样的分布保持证明技术**（Leviathan/Chen 的构造）：命题 1/2 的归纳证明是这套技术在"条件于 draws"情形的延伸。

### 7.3 工程知识层

- **确定性 counter-based 哈希随机流**：按种子+位置+词表索引按需复现随机数，跨 GPU 无需通信——分布式起草/验证共享 draws 的前提。
- **实验设计**：同草稿同后端只换分配策略的对照、打乱 draws 的负对照、预算扫描——增益归因的严谨性来自这些控制变量设计。

### 7.4 知识融合的关键节点

三个化学反应节点：(1) **"验证随机数可预生成" × "随机效用模型"** → 用草稿 logits 替代未知目标 logits、把已知扰动当作效用的一部分，得到可校准的打分规则；(2) **"Gumbel 扰动可预生成" × "逐位置索引"** → 树只影响每轮长度不影响内容的正确性证明；(3) **"接受均匀数已知" × "最大熵建模"** → 零参数的停止位置分布估计。三条融合链的共同入口都是先问"这个不确定性到底能不能提前消除"——这是比任何单项知识更根本的问题意识。

## 八、论文中可以提取的通用性灵感

### 灵感一：把不确定性分类为"昂贵未知"与"免费已知"，并利用后者

- **核心思想**：系统中的不确定性并非同质——有的消除它需要昂贵计算（目标前向），有的只需改变生成顺序就能提前揭示（随机数）。优化前先做这道"不确定性成本审计"。
- **论文证据**：同一套 baseline 上仅引入已知 draws 即 +4.3-24.6%；消融显示增益完全来自信息而非扰动。
- **推广场景**：(1) 强化学习 rollout 中提前固定环境种子，指导树搜索的展开方向；(2) 蒙特卡洛模拟中预生成随机流以做条件化的方差缩减；(3) 数据库查询优化中利用提前可知的绑定参数重排执行计划；(4) 分布式系统里用确定性哈希替代随机数广播，省去同步开销。

### 灵感二：条件化优化空间优于边际优化空间

- **核心思想**：在边际期望意义下最优的分配，在每次具体实例的条件分布下往往次优；一旦能对实例做哪怕部分条件化，就应把整个优化搬进条件空间。
- **论文证据**：OPT-Tree 在边际空间已近最优，DICE 仅把路径概率换成条件于 draws 的版本，EAGLE-4 需 4 倍节点数才能追平。
- **推广场景**：(1) 缓存预取：用会话内已见 key 的哈希条件化预测下一个 key；(2) 编译器寄存器分配：条件于已揭示的分支预测结果；(3) 推荐 systems：条件于本次会话已曝光的物品重排候选；(4) 网络调度：条件于已确认的 ACK 序列调整冗余发包。

### 灵感三："改变做多少，不改变做什么"是无损改造的安全模式

- **核心思想**：当一个系统的输出正确性由某不变量保证时，把优化限制在不触碰该不变量的自由度上（如只改数量、不改内容），可以安全地获得性能收益。
- **论文证据**：命题 1/2 的证明恰好表明 draws 条件化只作用于"每轮发出多少 token"，输出序列的不变量完好——这是全部增益免费的原因。
- **推广场景**：(1) 数据库：只改查询计划不改结果语义的优化器重写；(2) 通信协议：只改分包策略不改字节流的重传机制；(3) 训练系统：只改算子调度不改数学等价性的图优化；(4) 量化推理：只在数值等价范围内的核融合。

### 灵感四：免费信号要流经"分配决策"才能变现

- **核心思想**：新信息只有作用于资源分配环节才产生价值；仅改善局部选择而保留旧分配规则，信息会被浪费。
- **论文证据**：仅用 draws 选子节点、预算仍按草稿概率分配时大部分增益消失（children-only 消融）。
- **推广场景**：(1) 推荐：新特征只用于精排而粗排不变，增益有限——应贯穿召回；(2) 供应链：需求预测只用于定价而库存分配照旧；(3) 自动驾驶：感知置信度只用于刹车而不影响路径规划。

### 灵感五：粗糙估计 + 正确信号 > 精确模型 + 缺失信号

- **核心思想**：当关键信号缺失时，把估计器做精的边际收益迅速衰减；先引入正确信号，粗糙估计就够用。
- **论文证据**：plug-in 参数已得 9-22% 增益，校准 +1-2 点，神经预测器仅再 +1.5 点；停止模型换个函数形式影响不超过 3 点，而忽略/反向 draws 损失 10-17 点。
- **推广场景**：(1) 搜索排序：点击信号的有无比排序模型的精化更重要；(2) 医疗诊断：拿到关键检验指标比精细化先验分布更改变决策；(3) 量化交易：知情方向比定价模型精度更决定盈亏。
