# 一、论文背景：Agent 演化的"分数幻觉"从哪里来

## 1.1 什么是 Agent harness 演化

先拆三个概念。

**LLM Agent（智能体）**：一个大语言模型加上一套"手脚"——它能读环境、调工具、执行动作。今天你可能已经见过能自动写代码、自动订机票的 Agent。

**Harness（运行时护架）**：包在模型外面的整套系统——系统提示词、技能文件（Skill，可以理解为"岗位操作手册"）、工具接口、编排逻辑，甚至源代码。模型本身冻结不动，但护架的每一个部件都可以改。打个比方：模型是发动机，护架是整辆车——变速箱、导航、轮胎。发动机不换，换胎、调变速箱照样能让车开得更快更稳。

**Agent harness 演化**：让 Agent 根据自己的执行经验，**自动、持续地修改自己的护架**——这就是一条实现"递归自我改进（Recursive Self-Improvement，RSI）"的具体路线。RSI 的愿景是系统能反复修正自身设计、越变越强；改权重（训练）成本高、门槛高，而改护架（提示词、技能、代码）便宜、可逆、人人可做。

近一两年涌现了一批把"执行 → 诊断 → 变异 → 评估"闭环自动化的框架，并报告在标准基准上拿到了分数上涨。于是社区开始默认：harness 演化 = 一条通往 RSI 的可行道路。

## 1.2 核心疑点：总分上涨 ≠ 更好用的 Agent

但一个更高的总分（比如基准从 60% 涨到 65%）真的意味着更好的 Agent 吗？本文作者指出三个被普遍忽视的问题：

1. **总分是平均值**：新做出的任务可以掩盖丢掉的旧任务。100 道题从"会 60 道"变成"会 65 道"，其中可能有 10 道是新学会的、5 道是原本会现在不会的——总分完全看不出这种"翻车"。
2. **部署成本被忽略**：演化后的 Agent 可能每题花费的 token 钱更多。
3. **训练集外的表现未知**：分数是在引导演化的那批任务上测的，换个环境还灵吗？

评估方法学领域早有类似警示（论文引用了 Kapoor 等人的 *AI Agents That Matter*，以及 Gao 等人的自进化基准研究）。而针对 harness 演化，Wang 等人 2026 年的研究更发现：在匹配反馈与推理预算下，harness 演化并不稳定地胜过简单的测试时搜索基线。本文就是把这层"分数下面"的系统审计做透的工作。

## 1.3 为什么现在需要这项研究

harness 演化正在从学术演示走向工程实践（演化框架开源、基准公开），如果社区继续只看总分选方法，就可能选中"脆弱又昂贵"的版本，把"对演化用任务的过拟合"误当"通用进步"。在规模化之前搞清楚**哪些持续修改真正产生有用增益、增益如何产生又如何流失**，是这篇论文的出发点。

# 二、论文定位和关联工作

论文把这片研究版图组织为四条谱系，本文 Auditing 研究站在它们交汇处：

**谱系一：推理时改进 vs 持久改进**。Reflexion 把语言反馈存进情景记忆、Self-Refine 迭代改写当前输出——都是"当下这一次任务"内的改进；Voyager 的技能库、ACE 的上下文手册开始把改进**持久化**为文件。harness 演化继承后者：改的是会留下来的系统部件。

**谱系二：程序/结构优化**。DSPy 优化 LM 程序、TextGrad 用文本反馈做"反向传播"、Promptbreeder 演化提示词、GPTSwarm 优化可编排图、ADAS 用元 Agent 生成 Agent 程序。它们证明"提示词与程序空间可以被搜索"，但大多优化单一构件，且评估以总分为主。

**谱系三：开放式自我修改（本文的四位主角所在）**。STOP 递归改写优化器脚手架；Darwin Gödel Machine（DGM）演化自己的编码 Agent 代码；AlphaEvolve 用可执行评估反馈演化目标算法。本文直接审计的四种方法是：
- **AHE**（实现中心：以可观测性驱动的调试报告指导修改）；
- **HyperAgents**（实现中心：连"修改程序本身"也可编辑）；
- **A-Evolve**（反思中心：把部署经验蒸馏为对持久系统状态的修改）；
- **GEPA**（反思中心：轨迹反思 + Pareto 选择互补候选，ICLR 2026 上报告过胜过 RL 的提示优化器）。

**谱系四：评估批评**。*AI Agents That Matter* 强调成本控制与可复现性；Wang 等人（arXiv:2607.12227）质疑 harness 演化相对测试时搜索的优势与泛化。本文与谱系四同方向，但更进一步：不只批评，还做了机制归因（增/损从哪来）与建设性修复（AGE）。

**定位对比表**：

| 维度 | 之前的工作（四方法/四谱系） | 谱系四评估批评 | 本文（审计 + 修复） |
|---|---|---|---|
| 关心什么 | 让基准分数上涨 | 质疑分数可信度 | 分数下面的增益结构：可靠性/覆盖/成本/留存 |
| 评估粒度 | 聚合总分 | 总分 + 成本 + 留出集 | 任务级增损配对、split 归因、机制干预实验 |
| 结论形态 | 报告提升 | 报告"不一定真提升" | 增损并存规律 + 选择/变异/准入机制缺陷 + AGE 修复 |
| 是否给出修复 | —（各推各的方法） | 呼吁更好协议 | EvoAudit 工作流 → AGE 算法，四设置全胜参考方法 |

一句话定位：**这是第一篇把 harness 演化当作"被审计对象"做系统解剖的研究，并用审计发现反向设计出更强演化算法的工作。**

# 三、问题定义：把"演化改进"从总分中抽象出来

## 3.1 从具体场景到抽象结构

具体场景：某个演化框架跑 20 代，产出冠军 Agent，基准分数 +5。这算成功吗？

抽象洞察：**演化改进不是一个数，而是任务成功在任务集合上的重新分布**。作者把 Agent 形式化为 A = (M, H)——冻结模型 M + 护架 H；演化算法 E 从种子 A₀ 出发跑 G 代，每代从历史护架版本与评估证据中选出亲本（Parent）、生成候选（Candidate），最后按规则 Q 从全部存档版本中选出冠军 H★。这个形式化把"演化"拆成了一串**决策算子**：select（选谁改）、rollout（收证据）、analyze（诊断）、mutate（变异）、gate（准入）、record（记录）。

核心抽象问题：**给定冻结模型与有限搜索预算，演化循环产生的持久护架修改，是否带来（a）可靠（跨任务跨轮次稳定）、（b）高效（部署成本可负担）、（c）可迁移（超出引导任务仍有效）的改进？每个决策算子如何影响这三条？**

这相当于把"Agent 进化效果"变成一个类似软件工程的"变更审计"问题——不问"版本 2.0 分数多高"，而问"每次提交改了什么行为、保住了什么行为、删掉了什么行为"。

## 3.2 为什么这个抽象合理

- **Avg@k 与 Pass@k 必须分开**：Avg@k 衡量 k 次执行的平均成功率（可靠性），Pass@k 衡量 k 次里至少一次成功的任务比例（经验覆盖）。一个"碰运气型"Agent Pass 高 Avg 低；一个"稳定型"Agent 相反。总分合并了两种截然不同的能力。
- **增/损分开记账**：相对种子的覆盖增益数（Gained）与丢失数（Lost）分开统计，净增不代表"保住了已会的"。
- **成本进入同一坐标系**：Cdep@k（k 次通过的任务级部署成本）与覆盖曲线联合解读，区分"每试更贵"与"达标需要更少次尝试"。

# 四、问题解法：EvoAudit 系统审计 + AGE 修复工作流

论文的解法分两层：**先做系统审计（EvoAudit 的诊断部分），再把诊断结论转译成算子修复（AGE）**。

## 4.1 审计设计：4 方法 × 2 harness × 2 域 = 16 条谱系

- **方法**：AHE、HyperAgents（实现中心）；A-Evolve、GEPA（反思中心）。
- **harness**：MiniSWE 2.4.5（源码可编辑：允许改内部源代码）；Codex 0.143.0（仅外层：只能改提示词/技能/配置/外部编排，源代码不可动）。全部用 GPT-5.4 作目标模型。
- **基准**：τ3-Banking（97 个通用工具交互任务：模拟银行客服，双控环境，要跟用户对话、调 API、遵守政策）；Terminal-Bench 2（89 个编码任务：在终端里完成长程真实工程任务）。
- **迁移目标**：τ3-Banking → 全量 τ2-bench（278 任务，零售/航空/电信三域）；Terminal-Bench 2 → DeepSWE v1.1（113 个长程仓库级实现任务）。
- **评估协议**：每配置 8 轮完整重复评估（τ3 共 7,760 次、TB2 共 7,120 次选定执行），配对比较冠军 vs 种子。

四大类诊断实验分别对应三个研究问题：

| 诊断 | 问题 | 做法 | 关键发现 |
|---|---|---|---|
| 重复评估 | RQ1 现象学：分数上涨是可靠的吗 | 8 轮重复 + 任务级 9×9 转移矩阵 + 成本曲线 | 16 个冠军**全部**增损并存；11 个可靠性提升中 8 个部署更贵 |
| split/跨基准 | RQ2 泛化：增益出圈后还在吗 | Train/Val/Test 分解 + 外部迁移 | Test 可靠性 10/16 提升；通用迁移覆盖 7/8 下降，编码迁移覆盖 7/8 上升 |
| 亲本扩展实验 | RQ3 机制：select 会选"潜力股"吗 | 每个 4-亲本池统一用 A-Evolve 流程各产 3 个候选 | 原始选择规则在通用任务上命中"最佳亲本"的概率（17.5%、8.8%）**低于随机 25%**；编码任务上（59.5%、55.7%）高于随机 |
| 组件干预 + 准入重放 | RQ3 机制：变异组合与准入好吗 | 冠军改动拆成组件 A/B 单独装回种子；冻结池上重放不同 gate 规则 | 15/16 组件胜过"通用提醒"对照；HyperAgents 两案例组合增益比单件之和低 6.3/6.6 分（负交互）；更严的准入规则把 15 个池的最佳候选留存砍到 6 个 |

行为审计还给出增/损的具体机理（22 个任务-谱系案例）：成功轨迹保护恢复文件、尊重动作依赖、交付自包含产物；失败轨迹参数错误、过早终止、"本地能跑但评测环境跑不了"。

## 4.2 从审计到修复：EvoAudit 工作流与 AGE 算法

EvoAudit 是一个 Agent 辅助工作流：对存档的演化产物跑诊断实验 → 把发现接地为证据报告 → 提出算子修订假设（含支持证据、预期效果、适用条件）→ 修订代码 → 接口与回归验证 → 准入。把四项修订装进 A-Evolve（其他一切不变），就得到 **AGE（Audit-Guided Evolution，审计引导演化）**：

| 算子 | 原设计的问题 | AGE 的修复 |
|---|---|---|
| select | 分数高 ≠ 潜力大（通用任务上选"最佳亲本"命中率低于随机） | **回归感知选种**：仍以最高分为主目标，仅在并列时，在并列者中选相对种子回归最少的（回归计数 R(C) 最小化），证据可比性有严格校验条件 |
| analyze | 诊断容易飘在"分数/指标"上，不落地到行为 | **行为接地分析**：评判器只看工具调用轨迹（禁看基准奖励/隐藏测试），输出 0–10 行为分 + "观察 vs 推断"分离的裁决；轨迹渲染有 12k/30k/60k 字符预算与首尾保留截断 |
| mutate | 改动组合可能负交互、破坏有用行为 | **依赖闭包变异**：变异前必须写明"观察到的行为→推断机制→替换行为→激活条件→预期权衡"；检查受影响接口的生产者/消费者；做一次连贯干预、可跨文件多层、检查冲突或重复指导 |
| gate | 只看分数，或过于保守丢掉有用替代 | **成本感知门控**：保留对亲本的严格分数提升，并列时且成本可验证更低才准入（accept = 分数更高 ∨ (并列 ∧ 可比 ∧ 成本更低)） |

另有 8 位人类专家对四项修订做了盲审（先独立选方向再看提案），方向一致 6/8、证据支持 6.25/8、背书验证 6.75/8。

# 五、评估指标与实验证据

## 5.1 指标体系

- **主指标**：Avg@8（8 轮平均成功率 = 可靠性）、Pass@8（8 轮至少一次成功的任务比 = 经验覆盖）。
- **结构指标**：任务流转（Gained/Lost 相对种子）、Std@k（轮间标准差）、split 贡献分解（Train/Val/Test 之和 = 总增益）。
- **成本指标**：每任务部署成本 Cdep@k（k 轮成本合计，美元）、演化成本 Cevo。
- **机制指标**：最佳亲本命中率（对照 25% 随机基线）、组件 vs 通用提醒、交互非可加性 I =（组合增益）−（单件增益之和）、尺寸归一化最佳候选留存率。

这个设计证明论点的方式值得注意：**"16/16 全部增损并存"不是某个方法不行，而是全部方法、全部 harness、全部域的共有结构性现象**——16 条谱系覆盖 2 种范式 × 2 种 harness × 2 个域，任何单点解释（比如"GEPA 的反思不行"）都推不出这么齐的模式，只有"总分掩盖重分布"这一结构性解释成立。

## 5.2 主实验结果

**Table 1（现象学）**：16 条谱系中 11 条可靠性提升、10 条覆盖提升，但 4 条两指标反向。典型：Codex+HyperAgents 在 τ3 上可靠性 +6.6、覆盖 +9.3，看起来很美——但 Figure 2 显示它 gain 11 / loss 2；而 MiniSWE+A-Evolve 在 τ3 上可靠性 −1.2，仍是 gain 7 / loss 6。摘要中的案例：某通用任务冠军可靠性 +5.2，同时丢了 10 个种子已覆盖任务。

**任务流转（Figure 2 汇总）**：τ3-Banking 上 16 个冠军 gain 1–15、loss 2–10；Terminal-Bench 2 上同样无一例外。

**成本（Table 13/B.4）**：11 个可靠性提升的冠军中 8 个单试成本高于种子；但 MiniSWE+AHE 在 τ3 上 4 轮达 56.7% 覆盖，超过种子 8 轮的 54.6%，部署总成本反而更低——"单试更贵"与"达标更省"可以并存。

**泛化（Table 3）**：Test 可靠性 10/16 提升（实现中心 7/8）；通用迁移（τ2-bench）覆盖 7/8 下降、编码迁移（DeepSWE）覆盖 7/8 上升（Codex 上 DeepSWE 覆盖绝对值 77.0 → 85.0）。

**AGE 对比（Table 10，核心修复证据）**：

| 设置 | A-Evolve ∆Avg@8 | AGE ∆Avg@8 | AGE ∆Pass@8 | AGE 丢失任务数 |
|---|---|---|---|---|
| τ3 × MiniSWE | −1.2 | **+6.6** | +11.3 | 2（A-Evolve 为 6） |
| τ3 × Codex | −2.2 | **+7.9** | +10.3 | 5（8） |
| TB2 × MiniSWE | +2.1 | **+5.9** | +3.4 | 2（2） |
| TB2 × Codex | −2.0 | **+3.5** | +2.2 | 1（3） |

AGE 在全部四设置上可靠性与覆盖双双超过 A-Evolve，四设置中三个丢失任务更少、一个持平；且在 τ3×Codex 上以 +7.9 分超过所有四种现有方法的最大增益（HyperAgents +6.6）。演化成本（20 代约 983–1481 美元）与 GEPA（1629–2373 美元）相比也更省。

## 5.3 指标真的证明了主张吗

- **"增损并存"**：8 轮重复 + 任务级配对使得每个 gain/loss 有统计支撑（如 Codex+GEPA 在 τ3 净 −3 但 gain 6/loss 9——如果只跑 1 轮，这类结论会被噪声淹没）。
- **"选择信号失准"**：48 个候选共享同一生成流程，排除了"变异质量差异"的混淆，把差异归因到亲本本身；命中率以均匀随机为基线，结论可核验。
- **"准入有反作用"**：冻结池重放保证两种规则看到完全相同的候选与证据，纯规则对比。
- 需要注意的边界：AGE 只与 A-Evolve 对照（它是"装四项修订"的宿主），四设置各一条 20 代谱系、单一随机种子（seed 0），作者也如实报告了这一点；人类评估样本仅 8 位专家。

# 六、效果优势的根源解释

## 6.1 根源机制与证据链

为什么 AGE 能在四个设置上稳定超过 A-Evolve（而 A-Evolve 自己四设置两负两平）？因果链逐级展开（标注证据等级）：

**链条一：总分把"生成"与"保持"混为一谈 → 回归感知的选择与准入直接保住覆盖。**
- 机制：Avg@k 只奖励均值，不惩罚单任务回归；于是演化搜索愿意接受"加三分新能力、丢两分旧能力"的候选。AGE 在 select 并列时最小化种子相对回归 R(C)、在 gate 中要求严格分数提升，等于给搜索加了"保持约束"。
- 证据：论文实验支持——AGE 四设置丢失任务数 1–5，A-Evolve 为 2–8；τ3×Codex 的 ∆Pass 达 +10.3（对照 −2.2 前的 +1.0）。软件工程中"回归测试守行为"是数十年共识（行为保持式重构），AGE 是把这套纪律移植到演化搜索。

**链条二：反馈带宽 < 变更影响面 → 行为接地 + 依赖闭包让每次修改"改得准、带全依赖"。**
- 机制：一个 prompt/skill/代码变更影响许多行为，但评估只采样有限执行并把代价压缩成一个分——这是论文对"为何增损并存"的第一性解释（Discussion: Feedback Can Be Narrower Than a Change's Effects）。AGE 的 analyze 强制诊断落在可观察行为（工具调用、错误、完成信号）上，mutate 强制写明机制与激活条件、检查接口生产者/消费者，等于把"盲改"变成"定向改"。
- 证据：论文实验支持（机制层）——15/16 组件胜过通用提醒证明"具体修改"优于"泛泛建议"；HyperAgents 两案例 −6.3/−6.6 的负交互证明"组合会打架"，而依赖闭包检查正是针对这一点。τ3×MiniSWE AGE 的 ∆Avg 从 A-Evolve 的 −1.2 翻到 +6.6，与其减少了 4 个丢失任务一致。
- 阅读者推测：单一 seed 下 +7.8 分的翻转幅度可能还包含变异提示词工程质量等因素，论文未做四项修订的独立消融（每项单独装回），这是归因上诚实的缺口。

**链条三：搜索决策需要"决策特定证据" → 各算子各用各的信号。**
- 机制：论文发现"当前分高"与"后代增益大"在通用任务上甚至负相关（命中率 17.5%/8.8% < 25% 随机）——这与"高分亲本已接近局部最优、中低分亲本改进空间大"的直觉一致，也与 RSIBench-Data 的发现同构（78.26% 的搜索在峰值后继续搜索反而收得更差）。AGE 不再用同一总分服务所有决策：select 看后续增益潜力与回归、analyze 看行为轨迹、gate 看分数 + 成本。
- 证据：跨工作相互印证（见下表）。

## 6.3 综合判断与未决问题

**多研究共同支持的机制**：(1) 总分驱动的演化搜索会系统性掩盖回归——本文 16/16、DGM 的早期候选现象、RSIBench-Data 的峰值后衰退三方一致；(2) 保持性约束（回归感知/归档报告最优）能有效守住覆盖——AGE 与 DGM 的报告策略殊途同归；(3) 成本必须与准确率联合评估——Kapoor 线一脉相承。

**仍属推测或证据不足的**：行为接地分析 vs 依赖闭包变异 vs 回归选择 vs 成本门控四项修订的**独立贡献**未消融；AGE 相对 A-Evolve 的增益中有多少来自更好的变异提示词工程（论文未分离）；"选择信号失准"在通用 vs 编码任务上的反转（<25% vs >55%）只有四个池的样本，可能是域特性也可能是噪声。

**适用条件与失效风险**：AGE 的修订是保守的（分数优先、并列才看回归/成本），在"分数信号本身稀疏/高方差"的小验证集上（每代 1 轮 × 19–20 任务），并列裁决可能很少触发——此时 AGE 近似于 A-Evolve + 更好的变异提示，这或许能部分解释 TB2×Codex 上 +3.5 的温和优势。若换到"准入门控收得极严"的场景，论文自己的 gate 重放已经警告：过严准入会把最佳候选从 15 个池砍到 6 个。

# 七、必要知识反推

如果让一个零基础的人复现这项研究，最少需要知道什么？

**领域知识层**：
- LLM Agent 与 harness 的工程分解（提示词/技能/工具接口/编排/源码的边界）——不知道就无法定义"什么在演化"。
- τ-bench 系列的双控交互协议（用户侧与 Agent 侧都能改变环境状态）与 Terminal-Bench 的终端评测合约——不知道就无法复现评估或做迁移协议（含"冻结适配器翻译消息协议"这种关键工程细节）。
- RSI 概念谱系（改权重 vs 改护架 vs 改改进过程）——不知道就无法定位四方法与 STOP/DGM 的差异。

**方法论知识层**：
- 演化搜索的算子化视角（select/rollout/analyze/mutate/gate/record）——这是全文审计的单位；也是"把方法差异翻译成可对比实现"的通用手法。
- 评估统计：重复评估、Avg@k vs Pass@k 的语义差、任务级配对转移矩阵、尺寸归一化留存率、基于引导区间的非可加性估计——不会这些就无法把"增损并存"做成可检验命题。
- 混淆控制设计：共享生成流程的亲本扩展实验、冻结池重放、组件拆解 + 通用提醒对照——这是"机制归因可信"的关键。

**工程知识层**：
- 两个 harness 的具体可编辑面（MiniSWE 的 src/、Codex 的 prompt/skills/外层 adapter）与版本锁定；成本台账（每次调用计价、演化/部署成本分离）。
- 大规模执行编排：7760+7120 次基准执行 + 22240 次迁移评估 + 9040 次编码迁移，含中断恢复政策。

**知识融合的关键节点**：
1. **"软件回归审计" × "演化搜索"**：把进化过程的每次准入类比为一次代码提交，需要回归测试——这是 AGE 设计的灵魂融合点。
2. **"评估方法学" × "机制实验"**：不是笼统呼吁"评估要更好"，而是把每个评估缺陷对应到一个可重放的机制实验（命中率/交互量/重放留存），再对应到一条算子修订——证据→假设→修复的完整闭环是这篇论文区别于纯批评文章的地方。
3. **"多维度分解" × "保守工程"**：所有修复都设计为对参考方法的最小侵入（并列才触发、分数优先），这需要同时理解统计诊断与生产系统工程的谨慎。

# 八、论文中可以提取的通用性灵感

**灵感一：平均值是危险的决策信号——任何"改进"都应做增/损分开记账。**
- 证据：16/16 演化冠军增损并存；HyperAgents 在 τ3×Codex 可靠性 +6.6 的同时丢掉 2 个已覆盖任务、AHE 案例可靠性 +5.2 丢 10 个任务。
- 推广：模型迭代（新版本 vs 旧版本的任务级配对）、推荐系统改版（新增点击 vs 流失点击）、供应链换供应商（新增收益 vs 隐性中断）、个人知识管理改工具链——都应问"我丢了什么原来有的"。

**灵感二：证据带宽必须匹配决策粒度——不同决策需要不同证据。**
- 证据：论文 Discussion 明确提出"Evidence Must Match the Decision"；select 用后续增益衡量（而非当前分）、analyze 用行为轨迹（而非基准分）、gate 用分数 + 成本。
- 推广：招聘（过往绩效 ≠ 未来潜力信号）、投资（历史收益 ≠ 前瞻风险）、医学（诊断证据与疗效证据分离）。任何系统里"用一个总分喂所有决策"都是反模式。

**灵感三：保守修复优于激进重设计——在既有目标上加"并列裁决"约束。**
- 证据：AGE 的 select/gate 修订都保留原主目标，仅在并列时启用回归/成本次级准则；四设置全胜而非部分翻车。
- 推广：制度设计（加触发条件有限的复审而非推翻原规则）、代码优化（先保语义不变再谈性能）、组织变革（增量试点 + 回滚线）。

**灵感四："可编辑的改进过程"本身需要回归约束。**
- 证据：HyperAgents 允许编辑自身演化算子，却仍有 gain 13/loss 10 的重分布；更严准入重放中最佳候选留存从 15 池跌到 6 池。
- 推广：任何元学习/自指系统（自动调参的 ML pipeline、自动改写自身提示的优化器）都要警惕"改进机制的改进"引入新的失败模式。

**灵感五：能力越强的起点未必是最大的改进来源。**
- 证据：四个亲本池中最高分亲本与最大改进亲本全部不重合；原始选择规则在通用任务上最佳亲本命中率 17.5%/8.8%，低于随机 25%。
- 推广：教育（优等生提升空间小）、组织改进（标杆部门挖潜难）、资源分配（边际改进最大的常是中游单元）。

**灵感六：审计可以产品化为"诊断 → 修复"闭环。**
- 证据：EvoAudit 把七类诊断实验固化为对存档产物的标准流程，产出带证据与适用条件的算子修订，经 8 专家盲审后落地为 AGE。
- 推广：代码库健康审计、数据质量审计、安全审计都可以从"出报告"升级为"出经过验证的修复补丁"。

---

**一句话总结**：这篇论文用 16 条演化谱系的系统审计证明，harness 演化的"分数进步"之下是任务成功的重新分布——有得必有失、有覆盖就有成本、有能力就有漂移；而把审计发现翻译成四个保守的算子修复（AGE），就能在全部设置上把"进化"变成真正的净进步。它给整个 Agent 自进化领域立了一个新规矩：**报告增益时，请同时报告你丢了什么。**
