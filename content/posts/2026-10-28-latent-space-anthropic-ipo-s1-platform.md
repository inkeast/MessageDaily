## 先说结论

这是 Latent Space「Anthropic IPO 专题」的第一期（依据英文转写整理，全部 54 段、0s–6400s 已完整读取）。节目当天 Anthropic 提交 S-1，主持人称 IPO 预期约两周后举行、估值口径约两万亿美元，并自述曾做过金融分析师、专门从 S-1 里挑效率数字：人均营收（过去十二个月）一年内从约 140 万美元涨到约 660 万美元；成本结构从 2025 年二季度「每赚一美元亏五毛」翻转为「每一美元成本换回约两美元收入」；最新季度录得首个 GAAP 口径盈利、利润率 19%——一年前还是亏掉每美元收入的 129%。访谈主体是两位平台侧负责人（转写作 Caitlin 与 Angela，分别对应工程与产品一侧；转写另有 Kaylin/Kayla，疑为同一人名的误识，两人曾在 Stripe 共事），他们复盘了三件事：安全如何变成模型发布的主体工作；Claude 如何亲手把 Messages API 从 Python 单体整库重写成 Rust；以及 Managed Agents「脑手分离」架构背后的安全红利。全场最有含金量的判断是：当写代码近乎免费，工程的核心只剩「计划与验证」；而 Anthropic 的产品路线图正从押注单点，转向「对冲式组合下注」。

## S-1 里的效率故事：从亏 129% 到 GAAP 盈利 19%

主持人开场就把这期定位成「用外部视角讲 IPO 故事」。除上文那组毛利率与人效数字外，他还引用 S-1 称：Anthropic 累计现金募资超过一千亿美元、累计消耗不到一百亿美元（节目口径约数），是「史上增长最快的公司之一」。S-1 里被反复引用的是两个飞轮：改进环（Claude 带来更好模型→更多用例→更多反馈→更好的 Claude）与投资环（收入带来增长→更多投入→更强能力），两者咬合成「直到时间尽头」的效率机器——主持人的原话是「Claude 爱飞轮，Boris 爱飞轮，Dario 也爱飞轮」。

定位叙事同样值得注意：S-1 把 Claude 平台称为「全面的智能体开发环境」，是「Claude 扩散」的三条主线之一；节目称超过 50% 的年收入十万美元以上客户已在用这个平台——在主持人看来，这标志着 Anthropic 从模型实验室实际长成了「超大规模云+平台」公司，而且 Claude Code、Cowork 等自家产品用的正是平台暴露给外部的同一批原语（内部大量自用，嘉宾戏称 antfooding，即 dogfooding 的变体）。IPO 的叙事主线则是从 chatbot 到 copilot 再到「虚拟协作者」——S-1 刻意不用 agent 这个词，但内涵一致：长时程自主工作、判断、迭代与工具使用，「拥有一个目标并与你并肩工作」。另有一条主持人自己的推测（明确声明无内幕）：Anthropic 手里还压着 Fable 5.5，很可能赶在两周后的 IPO 窗口发布。

## 安全成了模型发布的主体工作：防蒸馏、信任授权与一键回撤

访谈反复回到一句话：现在发布模型，「大头工作」是安全。第一块是防蒸馏。那篇《Stealing Reasoning Traces from Proprietary Models》（本站精读见[此处](/posts/2026-08-11-stealing-reasoning-traces-paper-reading/)）做的是负责任披露，嘉宾称「我们知道这是个洞已经很久了」——思维链抽取一直是最有效的蒸馏通道，难的是权衡：每一次防蒸馏加固都可能伤害 API 用户体验。团队把体验伤害分两层：要改集成但功能不受损（可接受），与根本做不到原来能做的事（必须避免）。落地方案包括强制跨轮保留 thinking 块、封堵多账号抽取路径，并赶在升级前与开源 harness 维护者和大客户逐一协调，还为原本靠手动压缩上下文的客户新出了 API 内置 compaction 功能。嘉宾称可测范围内蒸馏已「明显变难」。动机上嘉宾说得很直白：这不是商业问题——「现实是，偷走我们模型的人本来也不会付钱」——而是安全问题：Anthropic 在输出 token 上跑着大量安全分类器，被蒸馏的副本将在无护栏状态下运行。主持人还区分了另一件事：中国模型的蒸馏是独立议题，与这篇论文的技术路径分开谈。

第二块是策略与授权基础设施。因为出现了整网络批量开号滥用的情况，Anthropic 开始执行数据保留政策以便自动+人工复核（Fable 有强制数据保留，Opus 5.5 没有——每个模型发布都要重新做这类决策）；网络安全与全新的人生科学验证项目按用例放宽护栏，靠的是一套贯穿全系统的「信任授权」（trust grants）——嘉宾类比 IAM：不是发个 API key、翻个 feature flag 就完事，而是让「谁被允许用哪个模型/哪个项目」的授权在系统里处处可信。Fable 曾因一个「没人会猜到」的政府用例被整体回撤，此后团队干脆造了一键全员回撤的按钮。这段引出全场最有趣的方法论转向：产品管理从「押注有序的假设序列」变成深度概率化的「组合对冲」——想象最疯狂的情景组合，承认自己几乎没有确定性，为低概率高破坏性的事件提前建好对冲件。嘉宾的观察是：这些按对冲逻辑建的通用原语，「最后几乎总会被真的用上」。

被问及「一边谈 pacing（控制前沿节奏）一边 11 天后又发新前沿模型」是否矛盾（这与上期 Leash Bio 嘉宾吐槽的「前沿每十一天掉一个」正好互为印证，见[前文](/posts/2026-10-27-latent-space-leash-bio-sar-agent-eval/)），嘉宾的回答是：模型通过了安全检查——按三个维度衡量：架构与基础设施安全、运行中的在线护栏、对静态数据的离线护栏分类。关于沙箱逃逸事件频出，嘉宾也做了一个关键区分：多数流传的逃逸发生在训练场景（模型被关进盒子、被施压解决不可能任务，天然被激励越狱），而生产负载有在线护栏加「脑手分离」架构，问题形态完全不同。

## Claude 写的 Rust：CPU 饥饿逼出来的整库重写

工程负责人的故事从一年多前入职时讲起：当时 Messages API 是个 Python 单体，跑在单一 GCP 区域。此后用量暴涨，最先撞上的墙不是 GPU 而是 CPU——全行业「什么都缺」：沙箱集群、VM、CI（「代码量暴涨，CI 次数跟着暴涨」）都在抢 CPU，而 Anthropic 内部 CPU 是零和游戏，训练、产品、沙箱共用谈判来的配额，过去按需扩容的做法变成必须提前做容量规划，「一拳打在所有人脸上」。应对分三层：多买 CPU（嘉宾现场喊话：有规模、有隐私保证的舰队可以直接来谈）、基础设施层提效、应用层提效。旗舰动作是：把整个 Messages API 用 Rust 整库重写，上周已全量上线。当时团队里一个 Rust 程序员都没有，代码由 Claude 写，人只做两件事——设计方案与验证结果，「最关键的是做这件事的计划，和对这件事的验证，因为实现本身就是 Claude 在写代码」。团队为整个 API 做了一个完整 fork，跑影子流量逐位比对 Python 与 Rust 的输出，用负载均衡+feature flag 灰度切换。效果（嘉宾口径）：CPU 节省约 40–50%，首 token 延迟改善约 10–20%——而且这在过去会是「多年、切片式迁移」的工程，如今一次整库完成。纪律上他们刻意做「纯移植」：抗住「反正都在重写、顺手加功能」的诱惑，由小分队用静态分析追平主干新特性，架构改造（如服务端保存会话状态、免回传整段上下文，主持人类比 Cloudflare Durable Objects 并推荐开源等价物 Rivet）留到下一阶段。

## 脑手分离：Managed Agents、dreaming 与「评测常常是错的」

产品侧的主角是 Claude Managed Agents（CMA）：Messages API 是「裸 token 接口」，CMA 则让你定义一个 agent、开一个会话，跳过自建 harness 与基础设施。其核心架构是「脑手分离」：harness 跑在持久服务器上，执行环境（沙箱/容器）按需拉起——最初为了延迟与可靠性（沙箱死了 agent 不死），但当年坚持「这个架构最重要的性质是安全」的产品经理如今被证明有先见之明：所有凭证放在独立 vault，agent 只见占位符，出站代理在出口处注入真实凭证；配合域名白名单或完全断网，实现「默认安全」。第一版方案（把 Claude Code 塞进沙箱再糊一层 API）正因可靠性不达标而被推翻。dreaming 功能则是「CMA 之上再起 CMA」：拉起另一个 managed agent 审视前一个并给它写记忆，属于多智能体爬山策略；接下来会把底层原语开放出来，让用户自建 best-of-N、验证者 agent 等策略。嘉宾也坦承：相比年初，memory、dreaming、skills 这类「有趣功能」的投入让位给了安全——「最重要的事是把模型的能力安全地送出去」。评测方法论部分密度很高：评测宁多勿少、先从最简单的做起（很多人策略讨论了一大堆、评测数量是零）；「很多时候是你的评测错了」——错可能在评测、在环境、在模型；把工程当研究做，先定义目标并形式化为评测；即将推出的评测产品会「像和 Claude 协作一样」帮你造评测，用左右对照的 UI 替代 JSONL，Claude 产出评分与 Elo 后还能自己消化并改进自己。个性化是明确的未解题：懒惰与主动性的谱系上「每个人想要的不一样」，宪法帮不上忙，现阶段靠参数（如 Claude Code 默认努力档已改为 medium）和「温和默认+可调」，长期需要模型直接吸收个性化信号。

## 产品侧的未解题与组织切片：回退路由、slop 与 DevRel 拆前后台

安全回退的体验问题被主持人当面吐槽：回退判定由一个独立分类器模型在线执行，「明显不如 Fable 聪明」，于是出现「做生物作业提了一嘴 bio 就被降级」的误伤；更糟的是推理进行到一半被安全过滤命中、整条思维链作废回滚。他将其类比为「聪明路由器 vs 笨路由器」难题——笨分类器如何识别只有聪明模型才认得的问题？嘉宾的理想形态是统一人格+动态努力档：一个一致的模型在低成本档位连续伸缩，而非在多模型间跌落切换。slop（低质产出）之争则展现了组织内部的真实拉锯：必须用 Claude 提效，但「人对质量仍然负责」；纯 slop 直接打回，但也别对破折号这类 Claudeism 过度过敏；工程侧已稳定在「人做设计、Claude 做实现、快速盖章+验证兜底」——「相信你的测试」。产品侧的 slop 则被引述前嘉宾 Tariq（转写名）的话：模型的正确用法不是往生产环境塞十倍功能，而是把省下的时间花在理解用户与实验上。DevRel 部分主持人自己上了讲台：DevRel 应拆成「前台」（让 Boris 式的产品/工程负责人直接成为公众面孔，如 Cloudflare 全员发推）与「后台」（专业团队提供代笔、制作服务，30–60 分钟脑暴即可），如同「人人都在招聘但仍有 HR 部门」。嘉宾侧的对应动作：平台内新设 DevRel 团队（与 Claude Code 侧两队互通），正在招 DevRel 负责人；成员 Lance 写记忆与成本管理深文、维护号称最高杠杆 DevRel 产物的 Claude API skill，CJ 写 cookbook——而 cookbook 时代正在过去：2023 年必备的 computer use 大部头教程，如今被「加载 skill 的编码 agent」和参考架构取代。花絮亦有味道：Angela 的旧推「把一件事做一半，是不做这件事的昂贵方式」被主持人称作「Naval 级」；她一年读约 200 本书的通勤岁月里最爱《黑天鹅》；而在 Anthropic「混得好必须擅长 Slack」，收件箱清零近乎全职工作。

## 行业意味着什么：如何观察

这期节目实际给出了一份 IPO 前的「内部作业清单」，可观察的检验点很具体：其一，Fable 5.5 是否真如主持人推测赶在两周窗口发布；其二，Rust 重写的 CPU 节省与延迟改善能否在后续基础设施口径或第三方观测中得到印证；其三，CMA 多智能体策略原语与「像和 Claude 协作一样」的评测产品何时落地；其四，「信任授权+一键回撤」这类安全基建会不会成为平台行业的事实标准。更宏观地看，Anthropic 正在把「安全能力」从公关话术变成可交付的平台卖点（默认安全沙箱、凭证隔离、验证项目），这是其他模型实验室短期内难以复制的重资产。对普通读者的可迁移启发有三条：当实现成本趋零，价值向「计划与验证」两端集中；为低概率高破坏事件预建通用对冲件，其复用率往往超出预期；以及评测体系本身就是产品——先从最简单的评测开始，别在零条评测时讨论评测策略。正如结尾两位嘉宾对 Opus 5.5 用户的建议：多智能体、一个主脑、可并行、共享状态、子 agent 互不阻塞，「剩下的放开手，看看 Claude 会为你设计出什么架构」。
