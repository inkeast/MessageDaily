## 一、论文背景：临床场景把 AI agent 逼进了死胡同

要理解这篇论文，先从三个概念说起。

**什么是 Agentic AI（智能体）？** 它指能自主规划并执行多步分析的 AI 系统：接收一个请求（比如『把这些 CT 图像做全脑分割』），自己决定调用哪些软件工具、按什么顺序调用、每个工具的参数填什么，然后真正执行。在生物医学研究里，这类 agent 可以帮研究者准备影像数据集、训练模型、查询蛋白质组学数据库——每一步都是一次**工具调用（tool call）**。

**什么是 MCP（Model Context Protocol）？** 这是 Anthropic 于 2024 年 11 月发布的开放协议，为工具调用定义了统一接口：每个工具发布一个名字、一段描述和一份 JSON Schema（声明它接受哪些参数、参数是什么类型、可选值有哪些）。支持 MCP 的服务器可以被任何 MCP 兼容的客户端发现和调用，集成从『每个工具 × 每个应用』的一次次开发，变成『一次实现、处处可用』。本论文的 157 个工具全部封装成 18 个 MCP 服务器。

**什么是决策模型（decision model）？** 这是 2026 年 9 月以来爆发式兴起的新模型品类。TypeSafe 的 Jev 开了先河，Cloudflare（Clef）、Perplexity（pplx-decider）、OpenAI、Liquid AI、AWS 等陆续跟进。它与 LLM 的本质区别：**不生成任何文本**。输入一个状态（state）、一个问题、一份有限选项列表，一次前向传播（single forward pass）返回每个选项的概率——就像把 LLM 的『写一篇作文回答』换成『涂答题卡』。没有采样、没有解码、没有 JSON 要修复，速度快一个数量级、成本低几十倍。

### 两条死胡同

临床场景对 agent 有两条硬性要求，而现状是两条都过不去：

**第一是隐私。** 最有能力的 LLM 都是云端服务，每次请求和它引用的数据都会离开机构。对患者数据而言，这与 GDPR/HIPAA 等数据保护规则以及医院自身的数据治理政策直接冲突——大量医院因此把 AI 项目卡死在试点阶段。本地部署的 LLM 能让数据不出院，这条似乎有解（如波恩大学医院的隔离式本地部署实践），于是引出第二关。

**第二是可靠性，这一关更隐蔽也更致命。** 任何基于 LLM 的 agent 都是**逐 token 生成**工具调用的：每生成一个 token 都是一次概率采样。这意味着它可能调用不存在的工具、使用 schema 里没有的参数名，或者——最危险的——**给参数填一个用户从未给出的值**。论文里的量化触目惊心：本地 LLM agent 有 5.5%–19.7% 的调用至少含一个编造值，编的多是用户没说的超参数、文件路径、选项；对那些缺了必需参数的请求，LLM agent 高达 62.1% 的情况下直接编一个值填上。

为什么这在临床是致命的？因为**幻觉值不会让程序报错**。一个被编造的阈值参数会静默地改变那一步的分析结果，而流水线后面的每一步都建立在这个被污染的结果之上。论文里举的推理模式（reasoning mode）也救不了场：开启推理能减少部分错误，但生成的 token 数变成 3–5 倍，时间和能耗同步膨胀，且幻觉值依旧存在。

### 洞察的种子

作者的洞察从一个观察出发：**工具调用几乎没有什么是真正开放的**。工具清单就摆在那里（目录），参数名和合法值写在 schema 里，值几乎全在用户的请求文本里——剩下能由规则推导（如单位换算）。所以一次工具调用的本质不是『写一段文字』，而是**一连串选择**：选哪个工具？请求里的哪个值填进哪个参数？这个参数要不要设？该不该调用？

而『读状态、回答有限选项的问题、返回概率』恰恰是决策模型的本职。认知科学里的双过程理论（Kahneman《思考，快与慢》）把这种快速、单步、直觉式的判断称为 **System 1**——论文标题由此而来：**System 1 agents，就是每个决策都是一道多选题、由决策模型作答、全程不生成一个字儿的本地 agent**。

## 二、论文定位和关联工作

这篇论文站在三条研究脉络的交汇点上。

### 脉络一：临床/隐私场景的本地 LLM

Wiest 等（npj Digit. Med. 2024）证明了本地 LLM 做结构化医疗信息检索的可行性；波恩大学医院的隔离式部署实践展示了通过容器化、网络分区和出口过滤把开源 LLM 留在院内的工程路径。本论文引用了这条线（参考文献 7），并同样坚持全程本地推理（llama.cpp + 单卡 GPU，评估器和归一化器也全部本地运行）。**关键区别**：这条线解决的是『数据不出门』，没有解决『本地模型更小、幻觉更多』——论文实测本地 LLM agent 的编造率恰好落在此区间。

### 脉络二：工具调用幻觉的测量与防御

工具调用幻觉已有成熟的测量基准：ToolBeHonest（EMNLP 2024）做多级幻觉诊断，Berkeley Function Calling Leaderboard（BFCL, ICML 2025）专设幻觉测量类别。防御方面，业界的标准答案是**约束解码（constrained decoding）**——把 schema 编译成语法，在每个解码步屏蔽掉会让输出违反语法的 token（llama.cpp 的 GBNF、Outlines、XGrammar 等）。行业报告称结构化输出能消除 95% 以上的 schema 违规。

**但约束解码有一条被反复指出的天花板：它管形状，不管内容。** 语法能保证输出的 JSON 里枚举字段只取合法值，却无法阻止模型在自由文本字段里编一个不存在的文件路径——因为那个字段对任意字符串都合法。2026 年的 Closed-World Resolution 研究进一步指出：对『调用了不存在的工具』这类幻觉，任何门控都无法拦截，因为它根本不是门控做过的决策。本论文的方案可以视为对这条线的**极端化**：不只是约束解码路径，而是把整个输出空间预先封闭成『请求/schema/目录/策略』四个来源的选项集合——值不是从合法 token 序列里生成出来的，是从有限候选里**选**出来的。

### 脉络三：决策模型与 System One 模型品类

2026 年 9–11 月，决策模型从单品爆发为品类：Jev（TypeSafe，9 月 15 日）、Clef/Clef-flash（Cloudflare，10 月 1 日开源 Apache 2.0）、pplx-decider（Perplexity，开源）、OpenAI Decisions API、Liquid d1、AWS Strands Decider 等。第三方 DecideBench v2 评测显示 pplx-decider 27B 是可本地运行的最强决策模型（450 项决策准确率 92.2%）。本论文直接消费了这波红利：六个已发布的决策模型（decider-4b、decider-35b-a3b、pplx-decider-flash、pplx-decider-27b、OpenJev、Clef，4B–35B）**零微调**直接用。

### 脉络四：作者自己的前序系统

两位作者此前已发表 ReclAIm（Radiology AI 2026，多 agent 监控医学影像 AI 性能衰减）和 mAIstro（Eur. J. Radiol. AI 2025，端到端放射组学/深度学习多 agent 系统）——本论文的 123 条评估提示逐字取自这两个系统的真实 notebook，评估集里的 18 个 MCP 服务器（含 11 个影像服务器）也来自其 ReCo 框架（medRxiv 2026）。可以说 System 1 agents 是他们在临床 agent 实战中撞到可靠性墙之后的『反思之作』。

### 定位对比表

| 维度 | 云端 LLM agent | 本地 LLM agent + 约束解码 | **System 1 agent（本文）** |
|------|---------------|--------------------------|---------------------------|
| 数据出境 | 是 | 否 | **否（单卡本地）** |
| 工具/参数名幻觉 | 可能 | 语法上可消除 | **结构上不可能（选项来自目录与 schema）** |
| 参数值幻觉 | 常见（5.5–19.7% 调用） | 语法无法阻止自由字段编值 | **结构上不可能（值来自封闭候选集）** |
| 缺失必需参数 | 常被编造填充 | 常被编造填充 | **留空并模板化追问用户** |
| 每次调用成本 | 123–952 生成 token | 同左（推理模式更多） | **约 12 道单遍前向、0 生成 token** |
| 可复现性 | 采样随机 | 采样随机 | **同输入同输出，可逐题审计重放** |

## 三、问题定义

剥掉临床场景的具体外壳，论文面对的问题可以抽象为：

**给定**：(1) 一个工具目录 T = {t₁…tₙ}，每个工具附带 JSON Schema 声明的参数集；(2) 一条自然语言请求 r；(3) 一个本地可运行、不生成文本的决策模型 M（输入状态+问题+选项，输出选项概率分布，单次前向）。

**求**：一个映射 f(r) → 调用决策，即：选哪个工具（或不调用）、请求中的哪些值填入哪些参数、可选参数是否设置。

**约束**（这是问题的灵魂）：
1. **封闭性**——输出中出现的每个工具名 ∈ T，每个参数名 ∈ 该工具的 schema，每个参数值 ∈ {请求文本、schema、固定规则推导、策略} 四个来源的并集；
2. **不编造**——必需参数在请求中无值时，不得填充，必须交还用户；
3. **每个决策带概率**——低置信要转化为拒绝或追问，而不是硬着头皮猜；
4. **可重放**——同一输入在同一硬件/软件上输出完全一致，运行可被逐题审计。

这个抽象的精妙之处在于一次**问题形态的改写**：把『生成一段符合 schema 的调用文本』（开放的、逐 token 的、无界的）改写为『在有限选项集上做一系列选择』（封闭的、一次前向的、有界的）。一旦改写成功，幻觉就不再是一个需要努力减少的统计性质，而是一个**定义域之外的事件**——模型连『编造』这个动作在数学上都不可能做出，因为它的输出只能是选项的凸组合（概率分布）。

类比：LLM agent 让模型参加的是作文考试，再怎么强调格式也会写错字；System 1 agent 让模型参加的是选择题考试——答卷上根本没格子让你写字，只能涂选项。

## 四、问题解法

System 1 agent 的架构原则是一句话：**模型只做判断，代码逐字执行**（the model judges, and code executes verbatim）。整个系统三个组件，各管一件事。

### 4.1 组件一：Agent——工作流的控制器

Agent 负责把一个请求路由成对决策模型的一串提问：

1. **工具选择题**：对目录里全部 157 个工具 + 一个『以上都不是』选项出一道选择题，每个选项是『服务器名.工具名 + 描述前 220 字符』。决策模型对每个选项给一个概率。
2. **歧义消解**：如果前两名工具的概率差距小于 0.3，追加一道二选一——把两个工具的参数名列出来，问哪个工具的参数与请求中给出的值对应。
3. **能力核验**：对选中的工具出一道是非题——展示完整描述和参数名，问它能否完成这个请求；正面概率低于 0.5 就拒绝。
4. **缺失值处理**：必需参数缺值时，agent 不填，而是向用户展示固定模板（参数名 + schema 描述前 120 字符），等待用户提供。模板由 schema 填充，**没有任何随机生成**。
5. 多步请求中，每次调用及其结果的前 1,200 字符会加入状态，再问一道『是否需要下一步』。

### 4.2 组件二：Compiler——确定性的问题编译器

编译器是纯代码（无模型参与），把选中工具的 JSON Schema 和请求文本转成一道道有限选项的问题：

| 参数类型 | 问题形式 | 选项来源 |
|---------|---------|---------|
| 枚举（enum） | 『参数 x 应取哪个值？』 | 枚举值 + 『未指定（保默认）』 |
| 布尔（boolean） | 『请求要把选项 x 开还是关？』 | on / off / 未提及 |
| 数字、路径、列名、自由文本 | 值问题 | 编译器从请求中抽取的候选 + 『未指定』 |
| 列表（list） | 逐项选择 | 剩余候选 + 『没有更多项了』（候选互相竞争，一个值最多被用请求中出现的次数） |
| 对象（object） | 是非题 + 每键一个值问题 | —— |

候选值来自四个来源：**(1) 请求本身**——路径、数字（含文字写法如『三』）、范围、引号串、标识符、紧凑代码、≤3 词的短语、写在标签后的文本等；**(2) 固定规则推导**——单位换算、分数与百分比、类别计数、数据集标识符、染色体/等位基因记法、由片段组合出的路径；**(3) schema**——描述中列出的值、文档化的列表项；**(4) 环境与前序步骤**——比如另一个参数指向的 CSV 文件的表头。命名工具或服务器的词不会被列为候选（防止拿工具名当值）。

**沉降与接受规则**（防止过度填充）：独立问题并行发送、按固定顺序沉降，自由值按概率从高到低落位；可选参数只有当其概率 ≥ 0.7 才设置；等于文档默认值的参数不传；两个参数争同一个值时，问一道『这个值属于哪个参数』，答案概率 ≥ 0.7 才生效；必需参数无值则上报 agent 为缺失，低于 0.5 的回答标记为不确定。

### 4.3 组件三：决策模型——答题者

决策模型回答每道题：输入（状态、问题文本、选项列表、题目类型），一次前向输出每个选项的概率，无采样。**任何满足此接口的决策模型都可以原样替换**。论文用了三个协议族的六个已发布模型（均不微调，llama.cpp b11929 本地服务，每题一个独立请求）：

- **decider 族**（decider-4b / decider-35b-a3b）：状态优先布局的提示，答案读选项标签 token 的 log 概率，除以拟合温度后归一化；最多 10 个选项用字母 A–J，更大的题每选项一个单 token 标签，最多 255 个。
- **pplx-decider 族**（flash / 27b）：chat 模板 + 非因果（全注意力）层，llama-server 以 embeddings 模式返回标记 token 处的最终隐状态，agent 应用模型自带的读出矩阵（255 × 隐维）与温度归一化。
- **原生 SystemOne 模型**（OpenJev / Clef）：llama.cpp 直接实现其提示、读出头和温度，`/v1/systemone` 端点直接返回每选项概率。OpenJev 每题至多 52 个选项，更大的题拆成均衡分组、组内先答再组间决赛，选项概率 = 组冠军概率 × 组内概率。

OpenJev 每题上限 52 个选项而目录有 158 个选项——这就是分组锦标赛机制的用武之地。**确定性保证**：同一模型、硬件、llama.cpp 构建下，同样的（状态、问题、选项、类型）给出同一分布；每个答案以 (model, kind, state, question, options) 的 SHA-256 哈希为键存档，可完整重放。

### 4.4 编译器的开发回路：oracle 方法

编译器的规则（候选怎么抽、问题怎么出）是唯一被开发的部分，论文设计了一套把**模型失败与编译器失败分开**的回路，避免『为了某道题打补丁导致过拟合』：

1. **编译器 oracle**：把决策模型换成一个『知道标准答案、总选标注值』的组件。oracle 跑不通的请求，暴露的是『没有任何一道题提供这个值』——这是编译器的失败，需要修。
2. 每个失败被分类为编译器失败（值没被提供或形式不对）/ 模型失败（提供了但模型没选对）/ 标注错误。**只修编译器失败**。
3. 每次修改必须是一条**关于请求如何表达值的一般规则**，而非针对特定工具的特例；接受标准在任何模型评估之前成文。
4. 一组修改被接受，当且仅当：跨模型的总正确调用数上升、此前的参考请求不超过预设容差地退化、且删掉任何单条修改都无法简化（留一法验证）。

这套方法学与软件工程里的『先写回归测试再改代码』同构：oracle 就是永不失败的黄金测试，参考请求就是回归测试集。

### 4.5 全景：一个请求的完整旅程

用户请求进入 → agent 出工具选择题（157+1 选 1）→ 必要时歧义消解 → 能力核验（<0.5 拒绝）→ 编译器把 schema+请求编译成约 12 道有限选项题 → 决策模型逐题（并行批）单次前向给概率 → 沉降规则拼装参数 → 必需值缺失则模板化追问用户 → 否则发出 MCP 调用。全程零 token 生成，每个决策带概率存档。

## 五、评估指标与实验证据

### 5.1 实验设置

- **工具面**：157 个工具、18 个 MCP 服务器，分两个目录——影像目录 42 工具/11 服务器（nnU-Net、Merlin CT 基础模型、PyCaret AutoML、PyRadiomics、TotalSegmentator 等），生物医学目录 115 工具/7 服务器（proteomics-mcp 53 个、AlphaGenome 22 个、ClinicalTrials.gov、ChEMBL、Scanpy、TISSUE 等）。
- **评估集**：2,126 条请求 = 2,003 条自拟（覆盖改述、干扰值、数字格式、引号、否定、文本噪声等 16 类语言现象）+ 123 条逐字取自已发表论文的提示（ReclAIm 73 条、mAIstro 50 条）。拆分为：**主基准 1,952 条**（1,645 条完整请求，声明 6,056 个参数值；307 条越界请求）+ 174 条欠定规请求（缺必需参数，单独评估）。
- **对照组**：9 个开源权重 LLM（Nemotron 3.5 Bolt E4B/74B-A9B、Qwen3.8-27B、Muse Glimmer 30B、Gemma 4 E4B/26B-A4B、Qwen3.5-4B/27B/35B-A3B）× 推理开/关 = 18 个设置；每个请求一次补全（固定种子），llama.cpp 原生解析工具调用，首个调用计分，无调用视为拒绝。其中三个 LLM 恰好是五个决策模型的基座模型——**同骨干对照**由此而来。
- **硬件**：单张 NVIDIA RTX PRO 5000 Blackwell（48 GB），全程本地，能耗用 NVML 整卡计数器计量。
- **统计**：每个 System 1 agent 与每个 LLM 设置配对，108 对/指标，McNemar 精确检验 + Holm 校正。

### 5.3 实验设计如何支撑论点

这套设计有三个值得称道的地方：

1. **幻觉的判定标准对 System 1 略偏严**：一个值只要匹配标注值、请求里任何地方写过的文本/数字、编译器提供的选项、或 schema 内容之一就算有据（grounded）——这实际上**低估计**了幻觉（请求里写过的任何字都算有据）。在这个偏严标准下 LLM 仍有 5.5–19.7% 调用含编造值，且经 200 个被标记值的独立人工复核校准过精度上下界。对比是公平的。
2. **拒绝与漏调的权衡被正面处理**：LLM 可以靠『多拒绝』刷高越界拒绝率，但论文同时报告完整请求不调用率——拒绝最多的两个 LLM 设置分别丢了 24.3% 和 36.5% 的完整请求。System 1 两边都稳（拒绝 87.0–94.5%，漏调仅 1.0–3.3%）。
3. **稳健性检查**：换两处评分规则（搜索文本不去停用词、AutoML 模型名走 PyCaret 名表）重打全部对比——324 组中只有 1 组从 System 1 优势变为无显著差异；给每个 LLM 事后选其更好的推理模式（偏向 LLM 的选择），System 1 仍 33:8 领先。123 条真实论文提示上 System 1 也 ≥ LLM。**可复现性**：重放存档答案可重建全部 12,756 条 System 1 记录，脚本可再生成所有图表。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**因果链一：输出空间的封闭 → 幻觉的结构性不可能。**

LLM agent 逐 token 采样生成调用文本 → 词表是开放的，任何 token 序列都可能出现 → 因此会写出目录外的工具名、schema 外的参数名、请求中不存在的值（观测：5.5–19.7% 调用含编造值，推理模式不消除；三个 LLM 在 19–53 次调用里用了 schema 外参数名）。System 1 的输出是**选项集上的概率分布** → 一个分布的支撑集只能是选项本身 → 编造在数学上不在输出空间里（观测：10,888 次调用、33,945 个参数值，零无据值）。这不是『更少的幻觉』，是『幻觉的定义域外』。【论文实验已支持】

注意这条链与约束解码的区别：约束解码在 token 层面封闭输出（语法合法），但自由文本字段的『合法 token 序列』仍然是无穷的，值级编造依然可能；System 1 在**值层面**封闭——候选列表里没有的值，概率恒为零。这就是 0% 与『语法上已消除 95% schema 违规但语义编造仍在 3–7% 平台期』的区别。【对比属阅读者分析，基于公开的约束解码文献】

**因果链二：缺参时的策略差异 → 欠定规请求的 86.2–93.7% vs ≤5.7%。**

LLM 被训练成『给出完整回答』，面对缺失必需参数会倾向于补全（观测：最高 62.1% 的欠定规请求被编值填充，最准的 LLM 设置也有 27.6%）；System 1 的 agent 策略是『缺了就留空、模板化追问』——这是**代码策略而非模型行为**，不依赖模型的『诚实度』。【论文实验已支持】

**因果链三：显式候选竞争 → 工具选择 76:5 的优势。**

LLM 自由生成函数名时，选择信号分散在生成概率里，相近工具名容易混淆；System 1 把 157 个工具的『名+描述』作为显式候选一次性摆上答题卡，决策模型做的是对比判别而非回忆生成——辨析题比默写题容易。前两名差距 <0.3 时还追加参数匹配的 tiebreaker。【机制为阅读者推测；76:5 的配对结果为论文实验支持】

**因果链四：零 token 生成 → 时间与能耗优势。**

每请求约 12 道单遍前向、无自回归解码，对比 LLM 无推理 123–340 token、有推理 417–952 token → OpenJev agent 92.9% 全对下 2.6 s、0.228 Wh/全对请求，优于最佳 LLM 设置的 91.3%、4.5 s、0.413 Wh。高准确端 System 1 同时更快更省电；但注意 Qwen3.5-35B-A3B（推理开）能耗低于 OpenJev agent——能耗优势不是无条件的。【论文实验已支持】

**反事实验证**：同骨干对照就是天然的反事实——同样的基座模型，走生成路径（Qwen3.5-27B agent）还是走判别路径（pplx-decider-27b），全对差 2.6–5.0 个百分点、编造值 7.4% vs 0%；而 decider-35b-a3b 落后基座 3.0 个百分点证明**当决策模型本身不够强时，接口优势会被模型劣势吃掉**。优势的边界清晰可见。

### 6.3 综合判断

**多项研究共同支持的机制**：(a) 封闭输出空间消除对应类别错误（本文 0/10,888 + 约束解码文献的形状合规 + Closed-World 的拦截主张）；(b) 判别式概率输出在对比型任务（选工具、路由、检索）上优于生成式自由输出（本文 + Jetriever + Beyond Plain MCP）。

**仍属推测的机制**：因果链三（候选竞争导致工具选择优势）的具体心理物理学解释；OpenJev 的分组锦标赛机制是否优于直接截断。

**失效条件**：决策模型本身弱（decider-35b-a3b）；候选生成规则覆盖不到的值形制（22 次形制错误暴露编译器规则的盲区）；标识符需要世界知识推理而非请求内抽取时（数据库查询类工具）；开放域任务（需要写代码、写分析报告）System 1 完全不适用——它只解决 tool calling 这一段。

## 七、必要知识反推

假设找一个什么都不知道的人重做这项工作，他至少需要：

### 领域知识层
- **临床数据治理**：明白 GDPR/HIPAA 下患者数据为什么不能出境、医院为什么卡审批——这是『必须本地』这条硬约束的来源，决定了整个方案的天花板设计。
- **生物医学工具生态**：熟悉 nnU-Net、PyRadiomics、AlphaGenome、Scanpy 等工具的参数习惯（什么参数常被写、什么值常出现），否则编译器的候选抽取规则无从设计——论文的 16 类语言现象覆盖（数字格式、路径、标识符、染色体记法……）全部来自对真实请求的观察。

### 方法论知识层
- **双过程认知理论**：知道 Kahneman 的 System 1/System 2 划分，才能把『快而单步的判断』这一认知形态映射到『单次前向的决策模型』上，给方法命名并定位。
- **决策模型品类**：知道 2026 年 9 月后 Jev/Clef/pplx-decider/OpenJev 的存在、各自的协议细节（读出矩阵、温度、选项上限），才能『拿来即用、零微调’地组装六个 agent。
- **幻觉文献**：了解 ToolBeHonest/BFCL 的测量方法和约束解码的天花板，才能准确定位自己的贡献在『值级封闭』而非『形状级约束』。
- **实验方法学**：McNemar 精确检验、Holm 校正、Wilson 区间、bootstrap——以及更重要的：如何设计同骨干对照、oracle 回路、留一验证来隔离混杂因素。

### 工程知识层
- **MCP 协议与 JSON Schema**：catalogue 是服务器返回的工具清单快照，编译器的输入就是 schema——不懂 schema 的 anyOf/oneOf、pattern、default 语义写不出参数类型判定。
- **llama.cpp**：GGUF 量化模型的本地服务、logits/embeddings 模式、原生 tool-call 解析——六个决策模型和九个 LLM 全部经它跑在同一张 48 GB 卡上。
- **NVML 能耗计量**：整卡能耗计数器、空闲基线测量——效率对比才站得住。

### 知识融合的关键节点

1. **洞察节点**：『工具调用 ≈ 一系列选择』——这一改写需要同时见过 MCP schema（知道值的来源封闭）和决策模型（知道它天生答选择题），两者缺一，这个等号画不出来。
2. **工程节点**：oracle 回路——把软件工程的黄金测试思想移植到编译器开发，使『修规则』不退化为『背题』。这需要对评测方法学 + 软件工程的双重熟悉。
3. **验证节点**：同骨干对照——只有同时了解决策模型的家谱（谁的基座是谁）才能设计出这组最锋利的对比。

## 八、论文中可以提取的通用性灵感

### 灵感一：把生成问题改写为选择问题，错误的类别就从统计性质变成结构不可能

**核心思想**：当一个系统的输出被要求来自封闭集合时，不要让模型『自由地写对』，而是把输出空间本身封闭起来——错误从『概率上有多少』变成『定义上不存在』。
**论文证据**：10,888 次调用零编造值 vs LLM 5.5–19.7%；缺参处理 86.2–93.7% vs ≤5.7%（缺参不填是代码策略，不依赖模型诚实）。
**推广场景**：(1) 金融交易指令生成——指令字段全部来自白名单；(2) 法律文书起草中的条款引用——引用条目来自法条库而非自由生成；(3) 工业控制系统的人机指令翻译——动作集封闭；(4) API 自动化测试的用例参数——从录制流量中抽候选。

### 灵感二：『模型判断、代码执行』的责任切分

**核心思想**：把系统中所有**需要语义理解**的环节交给模型，把所有**需要确定性**的环节交给代码，两者之间用『概率 + 阈值』的窄接口连接——模型永远不直接产出被执行的内容。
**论文证据**：编译器是纯代码；agent 的追问模板从 schema 填充；每个决策带概率，0.5/0.7 的阈值把低置信转化为拒绝/追问/留空。
**推广场景**：(1) 数据清洗管道——模型判断字段映射，代码执行变换；(2) 客服路由——模型判断意图归属，代码执行 SLA 策略；(3) 自动化运维——模型判断告警相关性，代码执行预案。

### 灵感三：用 oracle 分离『表达失败』与『判断失败』，只修前者

**核心思想**：开发任何『模型+规则』混合系统时，先造一个知道标准答案的 oracle 替身，跑出『规则表达不了正确答案』的上界；只修规则层失败、只修一般规则、用回归集守底线——这能防止为个案打补丁导致的过拟合。
**论文证据**：编译器开发回路七步法（oracle → 失败分类 → 只修编译器失败 → 一般规则 → 聚合提升+容差+留一 → 存档重放 → 代码哈希）。
**推广场景**：(1) prompt 工程团队的天花板分析——先测『最优 prompt 能到多少』再优化；(2) 编译器/DSL 设计——语义等价性 oracle；(3) 任何 data pipeline 的 schema 演进管理。

### 灵感四：可审计性来自『每步存概率 + 确定性重放』，而非事后解释

**核心思想**：要讓高风险系统的每个决定可追责，不靠事后用另一个模型解释，而靠事前让每个决定以带概率的原子形式留档、且系统整体确定性可重放。
**论文证据**：答案按 SHA-256(模型, 类型, 状态, 问题, 选项) 存档；重放存档答案重建全部 12,756 条记录；同输入同输出。
**推广场景**：(1) 医疗 AI 的监管审查——逐判断回放；(2) 自动驾驶决策日志；(3) 交易算法的合规留痕；(4) 科学计算 pipeline 的可复现性认证。

### 灵感五：准确率并非免费的代价，但接口红利有条件

**核心思想**：判别式接口的可靠性红利真实存在，但它以上游模型自身的判别力为前提——接口是放大器不是点金术；选型时必须做同骨干对照。
**论文证据**：pplx-decider-27b > 基座 +5.0 点，pplx-decider-flash > 基座 +6.4/+9.6 点，但 decider-35b-a3b < 基座 3.0 点；参数填充上大 LLM 逼近（46:19:43），标识符密集数据库上 LLM 反超。
**推广场景**：任何『新接口/新范式 vs 旧范式』的迁移决策——都应先跑受控的同骨干（或同容量）对照，再谈架构升级。

### 灵感六：隐私约束可以是架构创新的催化剂

**核心思想**：『数据不能出门』这类硬约束，与其当作待绕开的障碍，不如当作逼问系统本质需求的筛子——论文正是被『必须本地』逼到了『本地模型弱 → 不能靠模型能力 → 只能靠结构设计』的路线上，最终反而得到了比云端更强的可靠性。
**论文证据**：全流程单卡本地（含评分器归一化），却取得 97.0% 工具调用准确率与零幻觉。
**推广场景**：(1) 边缘设备的 on-device AI——算力约束倒逼蒸馏+结构化输出；(2) 涉密单位的内网知识问答；(3) 小微企业的低成本自动化。

## 结语

这篇论文的格局比标题看起来更大。表面上它是一个临床 AI 工具调用系统，内核则是一次干净利落的范式示范：当一类任务的输出空间本质上是封闭的（选工具、选值、选开关），生成式模型就是被错用的工具——不是模型不够好，是考试题型出错了。把题型从作文改成选择题之后，『幻觉』这个困扰了 LLM agent 社区数年的问题，在工具调用这个场景里被证明可以不是被减少，而是被消灭。它同时诚实地标注了边界：决策模型本身的强弱仍然决定成败，标识符密集的场景生成式依然占优，开放域任务它无从置喙。对于任何在高风险领域构建 agent 的团队，这套『模型判断、代码执行、概率留痕、oracle 开发』的四件套，都值得抄走。
