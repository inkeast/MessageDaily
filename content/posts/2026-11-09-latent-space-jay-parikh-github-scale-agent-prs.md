# 40% 的 PR 已由 agent 创建：Jay Parikh 谈 GitHub 的全栈演化——模型路由、Token 财务治理与开源安全的「围墙花园」反命题

> 信源说明：本文基于 Latent Space 频道 2026-11-08 发布的《GitHub's Growth: 225M Developers, 34.3B Commits — Jay Parikh, EVP of CoreAI, Microsoft》（视频 ID `rSWiNE92xqM`，全长 1395 秒≈23 分 15 秒，英文转写 12 段、0s–1395s 已完整读取）。采访在 GitHub Universe 大会现场进行（紧接嘉宾主题演讲之后；节目自述）。受访者为 Jay Parikh（转写作 Jay Parick），微软 Core AI 的 EVP——按主持人说法「实际上统管包括 GitHub 在内的多数核心 AI 服务」；其履历（Facebook 工程负责人、Lacework CEO、Ning/Akamai 工程副总裁）为节目自述。主持人依节目自述与结尾称呼「Sean」推断为 Shawn Wang（swyx，Latent Space 主理人、AI Engineer 大会主办方）——推断级标注；节目另提及曾采访 GitHub COO Kyle Daigle（转写作 Kyle Dagel）与 Satya Nadella。全部数字与判断均为受访者/主持人陈述，归属按「Parikh 称/主持人认为/节目引用」分层，本文未做独立核实；ASR 疑似错词以文末校正表标注，附录含完整修正版转写与逐段中文翻译。本站此前无 Jay Parikh 或 GitHub 专题文章（已检索确认），无重复风险。

## 先说结论

这场 23 分钟的走廊采访信息密度很高，核心是一个正在进行的换轴：**GitHub 的主要用户构成正从「人类工程师」滑向「agent」——节目口径约 40% 的 pull request 已由 agent 创建、agent 总量六个月增长 6 倍——而平台的应对不是做一个更聪明的补全工具，而是在技术栈每一层同时演化**：底下是 Azure 迁移（Parikh 称计划「明年年初」完成），中间是 Git/Actions/AI 网关等平台服务，往上是把 Copilot harness 与 Fusion（模型路由）打包成可组装的原语，再往上才是手机/桌面/IDE 的各个表面。主持人的开场玩笑——GitHub 是「今年第一个达到零个 9 可靠性的服务」——恰好解释了为什么是「每一层都要动」：规模（2.25 亿开发者、每秒新增一人）与负载构成（agent PR）同时在涨。对读者的两个直接抓手：其一，Parikh 把「Token 花销治理（FinOps）」列为明年的头等事项之一，并点破「实验室不会做这个，因为它们希望你花得越多越好」——中立平台的成本治理正在变成产品能力；其二，对「代码变便宜了、不如 vendor 一切依赖」的安全论调，他给出的是维护成本的反驳而非价值辩护。

## 规模：每秒一个开发者，与六个月 6 倍的 agent

顶层数字（均为节目口径，Octoverse 报告数据的转述）：平台开发者 2.25 亿、覆盖所有国家，连续第二年「每秒新增一个」（主持人换算：约 3150 万/年）；179 亿次代码推送、343 亿次提交、13 亿次 PR；开源贡献 25 亿次、同比 2.5 倍。主持人特别为工程师听众做了一步翻译：这些不是虚荣指标，每一次都是数据库写入、文件写入、元数据更新与索引负载。变化更快的是构成：约 40% 的 PR 由 agent 创建（主持人开场口径），agent 总量六个月 6 倍；与此同时人类开发者还在净增长——两条曲线同时上扬，这就是「每层都要演化」的压力来源。

## 「代码社交网络」的边界扩张：从 PR 的终结到「repo 里只有 markdown」

主持人的第一个结构性观察：GitHub 本质是开发者社交网络，而 Parikh 的履历（Ning→Facebook→Lacework）恰好是「社交网络+基础设施+安全」的合集。Parikh 的判断是 AI 把「社区」的准入门槛拆掉了——不再是「我是软件工程师所以我能用 GitHub」：一位记者试验出一个想法，就直接开 repo 分享求反馈。两个具体交锋值得记录：其一是重度用户 Pete Steinberger 的「pull request 终结论」，Parikh 的回应不是捍卫 PR，而是「概念应当可配置」——平台提供概念、用户按自己的工作方式组装；他自曝有从不走 PR 的实验 repo。其二是主持人注意到主题演讲里被重点展示的一个 repo 只是纯 markdown 文件夹（来自大会演讲者 Matt Pollock），顺势发问：语言占比统计（「76% Rust」）还有意义吗？什么是 repo、什么是代码、我们在存储什么？Parikh 的回答兼顾两端：一边是「什么都能存」的开放性，另一边是别忘了还有几十年历史、支撑商业关键系统的 Java/.NET 存量在被打补丁、做现代化——「有些代码在我们说话这会儿正在被氛围编程（vibe code）直接进生产」。

## Harness 与 Fusion：模型路由成为平台能力

主持人给了一个相当准确的定位：Fusion 是「harness 之上的元抽象」，而 Copilot 是「第一个 harness」（约四年）。Parikh 的展开有三层：①Copilot harness 已开放 SDK，可以拿去构建别的应用（他自己试过）；其设计原则之一是**多模型**，并随 MCP、工具生态、新模型的涌现持续调整。②harness 之上需要一层智能，把任务/提示拆解为「最终完成的软件工作单元」，把「该用哪个模型」的认知负担从工程师身上拿走——「最好的质量、更快、还更便宜」。③这与 Fusion 互相流动：harness 解决工具与工作方式的编排，Fusion 解决模型选择。主持人补充了他此前采访 Satya 的口径：模型选择正越来越成为微软的一个衡量指标——换言之，路由权本身就是平台权力。

## 同一 harness 贯穿全部表面：「智能复利」作为护城河

被问到「UI 层是否只需贴牌」时，Parikh 的回答是「两者都要」：基础设施、平台、工作流、表面四层同时演化，这条「铺好的路」才是产品。更有信息量的是跨表面设计：Copilot 应用、VS Code、github.com 现在共用同一个 harness——手机上发起、桌面续做、随手丢新想法进去；关键在于上下文、记忆、偏好与安全发现「在同一个地方为你复利累积」，且与用哪个模型无关。他的对照很直白：用 A 家工具再切到 B 家，「它们的智能不会相互复利」——换句话说，切换成本正在从「模型忠诚度」转移到「上下文积累」，这是把平台价值锚定在数据与历史而非模型能力上的经典打法。

## 安全：PHP 事件之后，与「围墙花园」的反命题

安全段落的背景是最近的 PHP 供应链事件（主持人提及）。Parikh 列了三层动作（均为 Parikh 称）：产品层的 code review（可找更严重、更冷僻的 bug，守住「生成代码量暴涨但质量线不下滑」）；GitHub Advanced Security 引入 AI 扫描——主题演讲演示了误推密钥被系统直接拦截、未能进入仓库；平台与生态层的微软×GitHub 安全团队协作——与维护者合作、限制 npm 等包管理器的暴露面、引入发布时间延迟、下架被入侵的 repo。

主持人随后抛出一个更根本的挑衅：开源供应链的底层预设是「代码昂贵」；如果代码与安全审查都变便宜了，最安全的做法也许是 vendor 一切依赖、或干脆全部重写，「别依赖开源」——把 2000 个核心依赖砍到 20 个。Parikh 的反驳是维护成本视角：「你砍掉 1980 个，那 1980 个的维护现在归你了」——这只是换了个主人，不是消除了风险；真正的解法是「把开源变安全」，而不是「所有人躲进围墙花园」——他判断开源对商业与构建者的价值「从这里起只会上升」。这段对话是本期最值得留存的交锋：它把「安全经济学」从情绪（依赖恐惧）拉回到账本（维护责任转移）。

## 2027 预测：Azure 迁移收尾、上千 agent 与 Token 财务治理

对「明年此时 GitHub 会是什么样」，Parikh 给了四条：①Azure 迁移「计划明年年初」完成，主题是每一层的阶跃式改进；②工作方式继续剧变——「我们是在管理成千上万个 agent，而不是几十几百个？我不知道」——所以平台要提供可组装的正确原语；③安全持续为头等事项；④**FinOps**：token 花销的可见性、优化建议（「这些用例你在用这个模型，也许该换那个」）、以及面向财富 500 强的治理与限额。他顺带点破一个激励结构：「实验室不会做成本控制，因为它们希望你花得越多越好」——中立平台恰好可以把「帮你少花钱」做成功能。主持人接的那段对话则给了工程团队一个可直接抄的表述框架：他不在乎团队花他的钱买 token，「只要让我看到花得值」——本周 1000 美元 token 换来什么？Parikh 修正了他的「2.5 万美元收入」版本：写代码的人不背营收，但应该绑在可度量的结果指标上——发布的特性、成本节约、参与度、留存、CSAT。

最后一个小而妙的注脚：主持人专门点名 GitHub Universe 的会议徽章——一个可编程的 Game Boy（带 A/B 键，可接 Copilot，且「就是用 Copilot 做的」），在「电子垃圾徽章」的传统里反着来；他把这视为硬件取用的门槛正在被模型抹平的证据——开发者想玩硬件时，「软硬件接口这种事，现在模型能替你搞定」。

## 机制 → 影响 → 启发

- **agent 化链条**：agent 创建 PR 占比升至约 40%、agent 总量六个月 6 倍 → 平台负载与构成剧变 → 概念层走向「可配置、可组装」（PR 从必需品变选项；repo 可只存 markdown）→ 观察指标：agent PR 占比曲线、无 PR 工作流的原语化程度、Azure 迁移完成节点（Parikh 称明年年初）。启发：当 agent 成为平台的多数「用户」，平台设计的默认值会翻转——企业现在就应开始区分与计量「人类贡献 vs agent 贡献」，否则一年后连成本与质量归因都做不了。
- **路由权力链条**：多模型 harness + Fusion 模型路由 → 「选模型」从用户技能变成平台能力 → 中立平台把成本治理（FinOps/限额/优化建议）产品化，而模型厂因激励结构不会做 → 观察指标：Copilot 的模型替换建议被采纳率、F500 治理功能采用。启发：买编码 agent 时把「花销可见性与限额」当硬指标；harness 时代的议价点从「用哪家模型」移到「谁替我管模型」。
- **上下文复利链条**：同一 harness 贯穿手机/桌面/IDE → 上下文、记忆、偏好、安全发现在一处复利累积 → 切换成本从模型忠诚度转向上下文积累 → 观察指标：跨表面会话接续的实际使用率。启发：选 agent 平台的第一标准是「我的上下文住在哪里」，其次才是模型清单。
- **安全经济学链条**：代码与安全审查成本下降 → 「vendor 一切/重写一切」的诱惑 → Parikh 的反驳：依赖收敛只是维护责任转移（1980 个依赖的维护归你）→ 行业解落在自动化（AI 扫描、密钥拦截、npm 暴露面限制、发布延迟）而非围墙花园 → 观察指标：供应链事件的响应时延、AI 扫描的采用率。启发：给依赖瘦身前先算「维护承接成本」，安全姿态势必从「审查人力」转向「平台自动化」。
