## 一、论文背景

### 1.1 LLM 引导的进化搜索：强，但慢

数学与科学计算中的许多问题都可以表述为「搜索一个好程序」：符号回归、不等式常数优化、为微分方程构建稳健求解器。进化计算提供了迭代改进的框架（变异、交叉、选择），而 LLM 正在成为其中的变异与交叉算子——FunSearch 找到了 cap set 新构造，AlphaEvolve 发现了更高效的 4×4 复矩阵乘法算法。后续工作在探索策略上不断加码：FunSearch 用隔离岛、AlphaEvolve 及开源变体加 MAP-Elites 存档保多样性；有的拒绝近重复提案、自适应分配预算、甚至进化搜索策略本身；有的用更好的上下文引导（历史改动如何影响分数、相关文献、模拟同行评审）；还有的扩展规模——并行轨迹、按题强化学习、多角色 agent（前沿 LLM 集成、多 agent 辩论、共享记忆协作）。

### 1.2 瓶颈在哪

论文对现状的诊断非常直接：**这些框架里搜索又慢又贵**。每个 agent 每轮都要写一段**长文本思维链**；不断增长的解法存档、评估反馈、agent 间文本消息把 LLM 上下文撑得很长；扩展到更多 agent、更大模型或测试时训练，成本成倍放大——搜索跑不到很多开放问题所需要的规模。于是核心问题被提炼为一句：**低成本 agent 蜂群能否让进化搜索更快且更好？**

### 1.3 技术前提：潜推理与潜通信

答案建立在两条近期研究线的交汇处：

- **潜推理（latent reasoning）**：LLM 不采样 token，把最后隐藏态 h_t 直接反馈为下一个输入嵌入 e_{t+1}，在连续向量空间中推理（Coconut、Soft Thinking、CODI 等）。
- **潜通信（latent communication）**：agent 之间不传文本，而是交换 token 嵌入、激活、隐藏态或 KV cache（Let's Speak Ciphers、激活通信、KVComm 等）。

关键的前驱是 **LatentMAS**（ICML 2026）：免训练地把两者结合——agent 在潜空间推理，把 KV cache 传给一个 summarizer 由它写出答案。SwarmEvolve 把这个机制放大成**大规模、低成本的进化搜索引擎**：每轮数百个 agent 并行潜推理，多样性直接在隐藏态空间里度量与过滤，交叉（crossover）在潜空间里自然发生。

## 二、论文定位和关联工作

### 2.1 LLM 进化框架谱系

| 框架 | 探索机制 | 与 SwarmEvolve 的关系 |
|---|---|---|
| FunSearch | 隔离岛进化 | 首批 LLM 变异算子；每轮单样本 |
| AlphaEvolve | MAP-Elites 存档 + 前沿 LLM 集成 | 本文 16 个数学题取自其附录 B；超越其 3 个构造 |
| OpenEvolve | AlphaEvolve 开源复现 | 主要基线之一（提供题目/初始程序/评估器） |
| ShinkaEvolve | 样本高效进化 + 嵌入模型查重 + LLM 判断 | 基线；其查重要外部嵌入模型与 LLM 调用 |
| CodeEvolve | 开源进化编码 agent，8 岛 | 基线 |
| ThetaEvolve / EvoX / AdaEvolve 等 | 测试时 RL / 元进化 / 自适应预算 | 扩展规模的不同路线：训练模型 vs 本文的推理侧规模化 |

### 2.2 潜推理与潜通信谱系

- **潜推理**：Coconut（训练 LLM 在连续空间推理）、Soft Thinking、CODI（把 CoT 自蒸馏压缩进连续空间）、Superposition 论文给理论基础。
- **潜通信**：Ciphers（嵌入辩论）、激活通信、Thought Communication（隐藏态）、KVComm（选择性 KV 共享）、Recursive Multi-Agent Systems、Latent Collaboration。
- **LatentMAS** 是直接的机制基础：SwarmEvolve 明确复用其「潜推理 + KV cache 传递给 summarizer」的设计并首次用于进化搜索的规模化。

### 2.3 定位总结

SwarmEvolve 的差异化主张：**不是更强的单次提议，而是每轮更多、更多样、更便宜的提议**。现有框架一次生成一个响应或跑一个小团队；SwarmEvolve 每轮 450 个潜 agent，各有不同的专长、父程序与思维方式——多样性、交叉、吞吐三个优势同时来自「潜空间」这一层。

## 三、问题定义

形式化地，LLM 引导的程序进化在每轮要解决一个**条件生成问题**：给定问题陈述、存档中的父程序及其分数与评估反馈，产生新的候选程序。传统实现把它做成「LLM 逐 token 解码长 CoT 再写程序」，单轮成本高，导致**时间预算下可评估的程序数**成为搜索的硬瓶颈。

论文要回答的核心问题：**若把每轮的「生成」搬进潜空间（不解码、以 KV cache 为通信介质），蜂群式并行能带来多大的吞吐增益与质量增益？** 具体拆为三个子问题：

1. **吞吐**：潜 agent 蜂群能否在不损失（甚至提升）提议质量的前提下，把每小时评估的程序数提高一个量级？
2. **多样性**：新颖性能否直接在隐藏态空间度量与过滤，替代外部嵌入模型 + LLM 判断的查重流水线？
3. **交叉**：把多个 agent 各自读不同父程序的推理 KV cache 拼接给一个 summarizer，能否实现真正的思想重组？

约束条件（潜在挑战）：同一轮所有 agent 与 summarizer 必须共享同一个 LLM（KV cache 可读的前提）；要求标准注意力架构（RoPE 旋转可平移 KV 块）；KV cache 内存随 agent 数×步数×层数线性增长。

## 四、问题解法

### 4.0 全景：每轮的流水线

```
存档(程序+分数+反馈) ──选父──> 10 个蜂群 × 45 个潜 agent
   │  4 个精炼群(2 最佳程序×2) / 3 个杂交群(前10随机5程序) / 2 个探索群(全存档随机4+裸题) / 1 个重启群(初始程序)
   ▼ 每个agent读: 题目 + 焦点提示(5种措辞×9种思维方式) + 1个父程序及评估
450 agent 同批 40 步潜推理(共享父程序 KV, paged attention)     [约4秒]
   ▼ 新颖性过滤: 按平均隐藏态余弦距离贪心最远点选择, 每群留30/45  [0.05分钟/轮]
   ▼ KV 拼接: 题目‖30×(焦点+40步潜推理)‖Q个父程序‖指令, key 旋转 Rδ
summarizer 解码写 1 个新程序/群 ──> 查重/语法/补 import ──> CPU 评估 ──> 入档
（旁路：参数调优 agent 每轮读最佳程序，单参数单值微调，至多 8 次）
```

### 4.1 组件一：蜂群组织——结构化的多样性供给

每轮 **10 群 × 45 agent = 450 个潜 agent**，四类蜂群对应进化搜索的四种压力：

- **4 个精炼群**：存档最佳的两个程序各配两群，焦点选该程序迄今用得最少的角度（数学表述、时间预算利用等）——纯 exploitation。
- **3 个杂交群**：从前十名随机抽 5 个程序，每程序 9 个 agent 读——crossover 的入口。
- **2 个探索群**：从整个存档随机抽 4 程序（各 9 agent），另有 9 个 agent 只读题目不带父程序——exploration。
- **1 个重启群**：只拿初始程序，目标是找与现有路线都不同的新思路。

每个 agent 的提示 = 焦点（14 种「侧面」或 14 种「视角」之一）× 5 种措辞 × 9 种思维方式（如「从第一性原理推理」「质疑程序的一个假设」）——提示级的多样性正交于蜂群级的多样性。

### 4.2 组件二：潜推理——LatentMAS 式免训练回投

agent 读完输入后做 **40 步潜推理**：每步把最后隐藏态 h_t 经对齐矩阵 W_a 映射回输入嵌入空间，再重标度为词表平均嵌入范数 γ：

e_{t+1} = γ·W_a h_t / ‖W_a h_t‖，其中 W_a = W_in^T W_out (W_out^T W_out + ρI)^{-1}（岭回归闭式解，把每个 token 的输出嵌入映射到其输入嵌入）。

全程不解码任何文本；每步在 KV cache 增加一个位置。**450 个 agent 跑一个 batch**，读同一父程序的 agent 通过 paged attention 共享该程序 KV cache 的同一副本——这是吞吐的工程支点之一。

### 4.3 组件三：新颖性过滤——多样性直接可测

每群按 agent 的 **40 步平均隐藏态** h̄_j 表示，对群均值 μ 中心化并归一化后，做**贪心最远点选择**（cosine 距离，从最接近 μ 的 agent 开始）保留 30/45 个「彼此最不同」的 agent。因为隐藏态本来就在 GPU 显存里，整个过滤几乎零成本（每轮 **0.05 分钟**）；对照 ShinkaEvolve 需要外部嵌入模型 + LLM 判断的查重共花 **4.5 分钟/轮量级**。

### 4.4 组件四：KV 拼接通信与 summarizer 写程序

每个 summarizer 读一个拼接的大 KV cache：题目 ‖ 30 个保留 agent 各自的（焦点提示 + 40 步潜推理）‖ Q 个父程序 ‖ summarizer 指令。因为并行 agent 的 cache 都从位置 0 开始，拼接前把每个块的 key 乘 RoPE 旋转矩阵 Rδ 平移到其偏移位置（value 不带位置信息，直接拼接）。summarizer 一次性「看见」30 条读着不同父程序的推理轨迹后，解码输出方向简述 + 一个完整程序——**交叉在潜空间自然发生**。采样温度按蜂群类型分级：精炼 0.3（稳）、杂交 0.5、探索/重启 0.8（散）。

### 4.5 评估与迭代

新程序去重、语法检查、自动补标准库 import 后，由确定性评估器在 CPU 核上打分（8 核并行评 8 个程序）入档；另有参数调优 agent 每轮读最佳程序，一次只提议**改一个数值参数**，至多 8 个单数编辑/轮——把「暴力调参」与「结构创新」解耦。超参全篇固定：45/30 agent、40 潜步、精炼链至多 20 步、summarizer 至多 4096 新 token。

## 五、评估指标与实验证据

### 5.1 实验设置

- **21 题**：16 题取自 AlphaEvolve 附录 B（装填、几何、分析、组合），沿用 OpenEvolve 的题目/初始程序/评估器；分数 = 目标值 ÷ AlphaEvolve 已发表构造值（**>1 即超越 AlphaEvolve**）。另设计 **5 个科学计算题**：稀疏线性方程组（5 个 PDE 离散矩阵，最大 262,144 未知số）、非正规矩阵特征值（6 个矩阵）、Burgers / 对流扩散 / Helmholtz 方程（各 5 个参数情形），分数 = 相对高保真参考解的正确位数（上限 dcap=6/8/10 位）对情形取平均。
- **预算**：60 分钟、1 GPU + 8 CPU 核、3 个种子；模型 Qwen3 8B（L40S）/ 14B（RTX PRO 6000）/ 32B-FP8（H100）；基线 OpenEvolve、ShinkaEvolve、CodeEvolve 用默认配置 + vLLM 服务。

### 5.2 主结果（Table 1，60 分钟最佳分三种子平均）

| 模型 | SwarmEvolve | OpenEvolve | ShinkaEvolve | CodeEvolve |
|---|---|---|---|---|
| Qwen3 8B | **0.804** | 0.693 | 0.642 | 0.700 |
| Qwen3 14B | **0.837** | 0.771 | 0.686 | 0.739 |
| Qwen3 32B-FP8 | **0.869** | 0.774 | 0.733 | 0.731 |

三个层面的结论：

1. **8B 反超 32B**：SwarmEvolve + 8B 的 0.804 超过所有基线 + 32B-FP8 的成绩（0.774/0.733/0.731）——吞吐优势兑换成了质量优势。
2. **单题统治力**：以 60 分钟终点计，SwarmEvolve 在 8B 下 21 题中 **18 题**最高（14B 16 题、32B 17 题）；32B-FP8 下把 5 个稀疏线性系统**全部解到满分 1.000**（无任何基线运行做到过）。
3. **15 分钟定律**：仅 15 分钟时，SwarmEvolve 在所有模型下都已超过全部基线的 60 分钟平均分。

### 5.3 吞吐与到达时间

- 60 分钟评估程序数：SwarmEvolve **734** vs OpenEvolve 158 / ShinkaEvolve 99 / CodeEvolve 81——**每小时多评 5–13 倍**的程序。
- 追平基线 60 分钟最佳分所需中位时间：8B 下 4–8 分钟（对 OpenEvolve/ShinkaEvolve/CodeEvolve 分别为 7/8/4 分钟），大模型下 3–6 分钟——摘要口径「中位 3–8 分钟」。

### 5.4 超越 AlphaEvolve（Supp. Table 5）

用冻结的 **Qwen3 8B**，SwarmEvolve 在 **3 题**上超越 AlphaEvolve（基线各只有 1 题）：

- **方中 26 圆装填**：达到最佳已知解 **2.635983**（与 Packomania 记录持平；AlphaEvolve 构造 2.635863）；32B-FP8 同样达到。
- **第二自相关不等式**（下界 C2↑）：8B 找到 **0.9213998**、14B **0.9314238**、32B-FP8 **0.9289826**，全部超过 AlphaEvolve 的 0.8962799（最佳已知 0.9635881）。
- **第三自相关不等式**（上界 C3↓）：8B **1.460021**、14B 1.460180、32B-FP8 **1.459198**，超过 AlphaEvolve 的 1.468762（最佳已知 1.453675）。

32B-FP8 还在另外 4 题逼近 AlphaEvolve：矩形装圆差 1 ppm 内、两个距离比与 Erdős overlap 差 0.02% 内。所有框架最大的差距集中在六边形装填、Heilbronn 问题、11 维 kissing number。公平性说明：第三自相关不等式按 OpenEvolve 评估器口径 AlphaEvolve 值取 1.4688；不确定性不等式限 Hermite 多项式族内比较（AlphaEvolve 族内 0.3521，其最好界 0.3216 用的是族外 Laguerre）。最佳程序在 AlphaEvolve 精确约束下重跑复核，分数至多降 3.3×10⁻⁴。

### 5.5 时间去哪儿了（Supp. Table 2）

| 阶段（60 分钟占比） | SwarmEvolve | OpenEvolve | ShinkaEvolve | CodeEvolve |
|---|---|---|---|---|
| 读提示 | 7.1 min (12%) | 1.0 (2%) | 0.5 (0.9%) | 0.1 (0.2%) |
| **文本推理** | – | **52.5 (87%)** | **34.4 (57%)** | **46.8 (78%)** |
| 潜推理 + 潜通信 | 4.1 (7%) + 2.6 (4%) | – | – | – |
| **写程序** | **39.4 (66%)** | 6.4 (11%) | 5.7 (9%) | 4.7 (8%) |
| 查重 | 0.05 (0.1%) | – | 4.5 (7%) | – |
| 其他（总结旧程序/改系统提示/调参等） | 1.9+4.7 | 0.1 | 14.7 (24%) | 7.7 (13%) |
| 程序数 | **734** | 158 | 99 | 81 |

基线 87%/57%/78% 的 GPU 时间花在文本推理上（每程序 20–35 秒、数千 token）；SwarmEvolve 把时间翻转过来：**66% 的时间在写程序**——搜索引擎的产出环节。

### 5.6 消融一：潜推理 vs 文本推理（A.1）

把 40 步潜推理换成至多 40 或 256 token 的文本推理（summarizer 读文本）：平均分 **0.804（潜） vs 0.796（40 tok） vs 0.767（256 tok）**；60 分钟评估程序数 734 / 663 / 402。潜 agent 一轮约 **4 秒**，256-token 文本要 **32 秒**，且 summarizer 还要多花 8–15 秒重新编码这些文本。有趣的反转：**40 token 文本反而优于 256 token**——长消息会撑爆 summarizer 的 32,768 token 上下文。结论：agent 间短消息即可有效通信，而潜通信在效率与质量上双优。

### 5.7 消融二：蜂群规模（A.2）

每群 agent 数 0/15/45/75（过滤器各留 0/10/30/50）：**前 150 个程序内大群显著占优**——从第 55 个程序起 75-agent 设置的平均最佳分超过所有其他设置与基线；三个基线 60 分钟只评 80–160 个程序、终分低于所有蜂群规模。约 150 个程序后各规模收益落入 bootstrap 区间内，小时终点分数趋同；小群单轮更快、能评更多程序。机制解读：大群让每个程序被更多视角审视（早期多样性红利）；后期收敛反映 **LLM 自身的知识上限**——所有 agent 共享同一模型的知识，加 agent 加不出模型没有的盲区，此时**换更大的模型才持续涨分**。

### 5.8 潜空间结构（Fig. 5）

对一轮 450 个 agent 的平均隐藏态做 PCA：全局视角下**不同蜂群占据潜空间的不同区域**（PC1/PC2 解释 24%/10%），第一主成分大致按角色排序（精炼→探索→重启）；单群内部 agent **按所读父程序聚类**（39%/20%），新颖性过滤从每个聚类都有保留、覆盖全群。焦点提示与过滤器共同保证了「群间多样 + 群内多样」。

### 5.9 找到的程序长什么样（附录 F）

SwarmEvolve 的最佳程序普遍体现「多点重启 + 数值优化器」的组合：方中 26 圆用 **10 次重启的 SLSQP**（扰动格点 + 随机起点）对全部圆心半径联合优化，而基线多为手工布局的单次 SLSQP；Heilbronn 三角用对称格点出发的 **10 次重启模拟退火**；Burgers 方程按粘度自适应选 **8192/2048 网格点**的两段 Runge–Kutta；对流扩散与 Helmholtz 则把网格加密到 **768×768 / 818×818**（基线 128–601）——更快地把标准数值方法部件组装到位，正是高吞吐的直接体现。

## 六、效果优势的根源解释

建立「方法差异 → 机制变化 → 指标提升」的因果链：

### 解释 1：为什么每轮 734 个程序而基线只有 81–158 个？

因果链：基线把 57–87% GPU 时间花在逐 token 解码文本 CoT（每程序 20–35 秒）→ SwarmEvolve 用 40 步潜推理替代（450 agent 同批约 4 秒），把文本编码 summarizer 输入的开销也一并消去（KV 拼接即通信）→ 查重从「嵌入模型 + LLM 判断」变为显存内隐藏态余弦距离（0.05 vs 4.5 分钟量级）→ GPU 时间从「推理」转移到「写程序」（66%）→ 同预算评估程序数提高 5–13 倍。
【论文证据：Table 1 程序计数、Supp. Table 2 时间分解、A.1 的 4s vs 32s 对比。】【边界条件：该优势以标准注意力 + 单一共享模型为前提，见限制三条。】

### 解释 2：为什么吞吐优势能兑换成分数优势（8B 反超 32B 基线）？

因果链：进化搜索在固定预算下的收益近似随评估数增长（搜索空间大、好程序稀疏）→ 每轮 10 个蜂群同时覆盖精炼/杂交/探索/重启四种压力且首轮即并行多父程序 → 曲线在最初几分钟爬升最陡（Fig. 21–23：多数题 SwarmEvolve 的包络带整个高于基线）→ 15 分钟即超过基线 60 分钟均分 → 终点分数与程序数同向增长。
【论文证据：Fig. 1 中图「15 分钟平均最佳分」、Fig. 4 到达时间、A.2 中三个基线（80–160 程序）终分低于任何蜂群规模设置。】【推测标注：「评估数→分数」的边际关系论文以经验曲线呈现，未拟合解析模型。】

### 解释 3：为什么 40 步潜推理不输给数百 token 文本推理？

因果链：LatentMAS 的岭回归对齐把隐藏态投影回「模型自己的输入嵌入流形」→ 潜步复用模型的连续计算而无采样噪声 → summarizer 通过注意力按需读取 30 条潜轨迹中相关的部分（KV 拼接保留全部信息），而不是被迫读进被压缩成文本的摘要 → 每步信息密度高于 token；且 40 步潜推理 + 30 agent 拼接的上下文规模可控，不触发「256-token 文本压爆 32,768 上下文」的问题。
【论文证据：A.1 平均分 0.804 vs 0.796/0.767；40-token 文本 > 256-token 文本的反转现象。】【推测标注：潜步与 token 的「信息当量」论文未直接测量，此链是从消融方向反推的机制解释。】

### 解释 4：为什么早期大群占优、后期收敛到模型上限？

因果链：每群读同一父程序的多个 agent 从不同焦点/思维方式推理 → 平均隐藏态按父程序聚类、过滤器跨聚类保留（Fig. 5 右）→ summarizer 的交叉素材更多样 → 前几百个程序内发现好方向更快（第 55 个程序起 75-agent 全面领先）→ 但所有 agent 共享同一 LLM 的参数化知识 → 多样性供给存在与模型知识无关的上限 → 后期增益饱和；此时增大模型（8B→14B→32B 终点分 0.804→0.837→0.869）才是解除上限的杠杆。
【论文证据：A.2 的配对增益曲线与 bootstrap 区间；Table 1 模型规模的单调提升。】

### 解释 5：为什么能在 3 题上超越 AlphaEvolve（前沿模型）？

因果链：这 3 题的结构共同点是「程序化构造 + 数值精修」（步函数不等式界、装填坐标优化）→ 解的质量主要由「重启次数 × 数值优化调用次数」与起点多样性决定，而非单次推理的智力 → SwarmEvolve 的高吞吐天然多发地撞上「多次重启 + SLSQP/退火」模板（附录 F 的最佳程序形态）→ 冻结 8B 模型以数量换质量；反之在需要深层构造洞察的题（六边形装填、Heilbronn、kissing number）上与 AlphaEvolve 差距最大——各框架共同的短板。
【论文证据：Supp. Table 5 的三题数值与「最大差距」清单；附录 F 程序形态对比。】【推测标注：「题目结构 × 框架能力」的匹配解释是基于结果的归纳，论文未做按题失败归因。】

### 解释 6：三个局限的机制根源

(1) **必须同模型**：KV cache 只有同一模型的嵌入空间/层结构才可直接拼接——跨模型需学习式翻译（Cache-to-Cache 一类）。(2) **必须标准注意力**：RoPE 的平移不变性使 KV 块可旋转平移；线性注意力/SSM 把过去压成定长状态，拼接通信退化为「状态合并」问题。(3) **内存线性增长**：一轮的 KV 随 agent 数×潜步数×层数线性增长——32B 模型需要大 GPU；压缩潜消息（CondenseFlow）与多卡分轮是论文给出的扩展路径。

## 七、必要知识反推

### 7.1 领域知识层

- **进化计算的骨架**：变异/交叉/选择、exploitation–exploration 权衡、MAP-Elites 式存档——读懂四类蜂群分工（精炼=变异、杂交=交叉、探索/重启=多样性注入）的前提。
- **Transformer 与 KV cache**：K/V 只依赖前缀、共享前缀只算一次、每新 token 单步前向——「潜 agent 为什么便宜」的全部算术基础。
- **RoPE 的旋转结构**：注意力分数只依赖相对偏移 → KV 块平移只需给 key 乘 Rδ、value 无位置信息——KV 拼接通信的可行性来自这一条性质。
- **数值方法工具箱**：SLSQP、模拟退火、Runge–Kutta、有限差分、Chebyshev 配点、Sylvester 方程——最佳程序实际上是这些标准件的组装，评估题本身就是数值分析课程的延伸。

### 7.2 方法论知识层

- **潜推理文献坐标**：Coconut/Soft Thinking/CODI/Superposition——「把 CoT 压进连续空间」的不同路线（训练式 vs 免训练闭式对齐）。
- **潜通信介质光谱**：token 嵌入 → 激活 → 隐藏态 → KV cache，带宽与兼容性依次变化；LatentMAS 的「潜推理 + KV 传给 summarizer」是本文直接借用的设计模式。
- **多样性度量**：隐藏态余弦距离 + 贪心最远点选择（Gonzalez 1985 的 k-center 经典算法）——用表示空间距离替代「生成再判重」的通用技巧。
- **评测协议设计**：以 AlphaEvolve 构造为分母的归一化分数（>1 即超越）、正确位数打分与 dcap 封顶、多种子 + 包络带、精确约束复核（3.3×10⁻⁴ 容差）与未播种随机程序 33 次重跑取最优——把「进化搜索的分数」做成可比、可复核的工程。

### 7.3 工程知识层

- **吞吐工程**：450 agent 单批潜推理、共享父程序 KV 的 paged attention、summarizer 批量解码 + prompt-lookup 投机采样（从上下文复制 token 起草、按投机采样规则验证，分布无偏）、CUDA graph 捕获、FlashAttention-3——把「每轮几秒」变成现实的完整栈。
- **预算分配**：温度按蜂群角色分级（0.3 精炼 / 0.8 探索）、参数调优 agent 与结构生成分离（单参数单值、每轮 ≤8 次）、精炼链上限 20 步——搜索预算的微观管理。
- **评估流水线**：去重、语法检查、自动补 import、CPU 核并行确定性评估、与 GPU 推理完全重叠——评估永远不拖 GPU 后腿。

### 7.4 知识融合的关键节点

1. **「通信即拼接」**：把多 agent 协作从「协议设计」问题变成「张量操作」问题——KV cache 沿序列维拼接 + RoPE 旋转平移，两行系统级操作承载了 crossover 的全部语义。
2. **「多样性可测量」」**：新颖性不再需要生成后判断（嵌入模型+LLM），推理过程中的隐藏态本身就可度量——测量点前移带来 0.1% 的成本占比。
3. **「数量×质量」的兑换率**：8B×734 程序 > 32B×158 程序——在搜索式任务上，推理吞吐可以替代（部分）模型能力，这是本文最实用的经验公式。
4. **「饱和点诊断」**：蜂群规模的早期收益与后期饱和把「多样性瓶颈」与「知识瓶颈」分开——前者用并行解决，后者只能靠换更大的模型，为后续工作（跨模型蜂群）指明动机。

## 八、论文中可以提取的通用性灵感

### 灵感 1：把中间产物留在潜空间——省掉编码/解码的往返税

- **核心思想**：流程中每一步若把内部表示序列化成文本再解析回来，都要付两次变换的税（编码+解码）与上下文长度的税；当消费者是同一模型时，直接传连续表示（KV/隐藏态/嵌入）几乎零成本。
- **论文证据**：潜通信 4 秒 vs 256-token 文本 32+15 秒；平均分 0.804 vs 0.767；40-token 短文本优于 256-token 长文本（上下文溢出）。
- **推广场景**：(1) 微服务间传中间特征而非 JSON 化数据；(2) 团队交接传结构化工作文件而非重写成报告；(3) 编译器 IR 直传优化 pass 而非反复 pretty-print；(4) 数据库内部列式/向量化执行避免物化文本；(5) 个人笔记用「可直接续作的草稿态」而非成文态积累。

### 灵感 2：多样性前置到「思考过程」层，用表示距离做门控

- **核心思想**：与其在产出后查重（生成→嵌入→判断→丢弃），不如在思考过程中就度量轨迹间的距离，只保留彼此最远的若干条——把去重变成「采样时的覆盖率最大化」。
- **论文证据**：隐藏态贪心最远点选择每群 30/45；成本 0.05 分钟/轮 vs ShinkaEvolve 嵌入+LLM 查重 4.5 分钟；PCA 显示保留集覆盖每个父程序聚类。
- **推广场景**：(1) 头脑风暴会先收集匿名想法再按观点聚类选代表，而非先到先得；(2) 集成学习的基模型按预测多样性而非仅精度挑选；(3) 推荐系统探索用 embedding 空间的远点采样；(4) 实验设计选最大化参数空间覆盖的配置（主动学习）；(5) 投资组合按观点差异性配置研究员信号。

### 灵感 3：交叉 = 让一个读者同时看见多条推理轨迹

- **核心思想**：重组思想的充分条件不是显式的交换算子，而是让一个具备综合能力的「读者」同时接触多条独立加工的上下文——注意力机制会自动完成取舍与合并。
- **论文证据**：summarizer 拼接 30 个各读不同父程序的 agent 的 KV 后写出的程序稳定优于单亲变异（杂交群是 10 群之一，整体分数提升中有其贡献；附录 F 最佳程序呈现多起点/多模板组合形态）。
- **推广场景**：(1) 需求评审会让架构师同时读三份独立方案草案；(2) 医疗多学科会诊共享同一份病程上下文；(3) 情报分析把多个来源的原始摘录并列给同一分析员；(4) 代码评审聚合多位评审人的批注后由 owner 统一裁决；(5) 教育：让学生先看多个同伴的解题路径再重构自己的解法。

### 灵感 4：吞吐与单体能力可兑换——先问「更多尝试」还是「更强单次」

- **核心思想**：在评估便宜、解空间稀疏的搜索型任务里，单位时间的尝试次数与单次成功率之间存在替代关系；先用工程手段把尝试次数提一个量级，常常比升级模型更划算。
- **论文证据**：Qwen3 8B + 734 程序/小时（均分 0.804）> 基线 32B-FP8 + ~100–160 程序/小时（0.731–0.774）。
- **推广场景**：(1) A/B 测试平台先提流量切分效率再谈模型预估精度；(2) 招聘中结构化多轮筛选 vs 单次深度面；(3) 创业 MVP 快速迭代 vs 完美首发；(4) 药物筛选的高通量湿实验 vs 单分子精细设计；(5) 个人决策：快速多方案试错（可逆决策）vs 深思单一方案（不可逆决策）。

### 灵感 5：识别「多样性瓶颈」与「知识瓶颈」的饱和信号

- **核心思想**：并行/多样性的投入存在饱和点——当所有副本共享同一知识源时，再加副本不再产生新信息；饱和后的正确动作是升级知识源本身，而非继续加副本。
- **论文证据**：蜂群 0→15→45→75 早期增益显著、约 150 个程序后落入 bootstrap 区间；模型 8B→14B→32B 终点分单调上升（0.804→0.837→0.869）。
- **推广场景**：(1) 团队扩张：同质背景员工的边际创意递减，此时换「知识源」（跨领域人才/外部顾问）；(2) 集成模型：同构 learner 加到饱和后引入异构；(3) 问卷调查样本量设计与人口覆盖的区分；(4) 自动化测试的同种子重跑 vs 变异测试；(5) 服务器冗余：同构副本解决可用性、解决不了正确性。

### 灵感 6：把搜索压力组织成角色化的「群」——精炼/杂交/探索/重启的普适四分法

- **核心思想**：任何迭代改进系统都需要四种正交压力——深挖当前最优（精炼）、重组已有优势（杂交）、边缘试探（探索）、推倒重来（重启）；显式地把并行资源按比例分配给四者，比让单一策略自适应切换更稳。
- **论文证据**：10 群的固定配比 4:3:2:1；焦点提示按群类型分流（14 侧面 vs 14 视角）；温度 0.3/0.5/0.8/0.8 与角色对齐。
- **推广场景**：(1) 研究经费配置：主流路线深化/交叉融合/高风险探索/全新范式；(2) 产品路线图：核心体验打磨/功能组合/边缘创新/second-system 重构；(3) 个人学习的刻意练习/跨领域联系/新领域试探/推翻重学；(4) 城市规划：旧城改造/新区组合开发/边缘试验区/新城计划；(5) 投资组合：核心持仓/策略混合/小仓探索/彻底换仓。

### B. 术语备忘

- **潜推理（latent reasoning）**：把最后隐藏态经对齐矩阵 W_a（输出→输入嵌入的岭回归闭式解）重标度后回投为下一步输入嵌入，全程不采样 token。
- **潜通信 / KV 拼接**：把多个 agent 的 KV cache 沿序列维拼接（key 乘 Rδ 平移到偏移位置）供 summarizer 注意力读取——本文的 crossover 载体。
- **新颖性过滤（novelty filter）**：以 agent 的 40 步平均隐藏态（群内中心化+归一化）为表示，贪心最远点选择保留 2/3 最异质 agent。
- **LatentMAS**：前驱工作（ICML 2026），免训练的潜推理+潜通信多 agent 机制，SwarmEvolve 将其首次规模化用于进化搜索。
- **四类蜂群**：refinement（精炼最佳程序）/ hybridization（杂交前 10）/ exploration（全档随机+裸题）/ fresh-start（仅初始程序），配比 4:3:2:1。
- **分数定义**：AlphaEvolve 16 题为「目标值 ÷ AlphaEvolve 构造值」（>1 即超越）；科学计算 5 题为「相对高保真参考的正确位数（封顶 dcap）按情形平均」。
