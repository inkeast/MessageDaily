## 一、论文背景

### 1.1 从一个日常场景说起：AI 是怎么"动手"的

假设一位医学研究者对 AI 说：『把这些 CT 图像跑一遍全器官分割，分辨率用 1.5 毫米。』AI 要完成这件事，不能只是"回答"——它得真正去调用一个分割软件（比如 TotalSegmentator），把参数填对，然后执行。这类"自主规划并执行多步分析"的 AI 系统就是 **agentic AI（智能体）**，而它每一次"动手"都是一次**工具调用（tool call）**：选一个工具、填一串参数、发出去执行。

**MCP（Model Context Protocol）** 是 Anthropic 2024 年 11 月发布的开放协议，为工具调用定义了统一接口——官方的类比是"AI 应用的 USB-C 接口"。每个 MCP 服务器把自己的工具发布成三件套：名字、描述、一份 JSON Schema（声明接受哪些参数、什么类型、有哪些合法取值）。任何 MCP 兼容的客户端都能发现并调用这些工具，集成从『每个工具 × 每个应用』的一次次开发，变成『一次实现、处处可用』。到 2026 年，MCP 已被 OpenAI、Google、Microsoft 及数千个社区服务器采纳，成为事实标准——本论文的 157 个工具全部封装为 18 个 MCP 服务器。

### 1.2 临床场景的两堵墙

对临床研究来说，agent 有两条硬性要求，而现状两条都过不去：

**第一堵墙是隐私。** 最强的 LLM 都是云端服务，每次请求连同它引用的患者数据都会离开医院。这与 GDPR/HIPAA 及机构数据政策直接冲突。本地部署 LLM 可以让数据不出院——但这引出第二堵墙。

**第二堵墙是可靠性，而且更隐蔽。** 任何基于 LLM 的 agent 都要**逐 token 生成**工具调用的文本：每生成一个 token 都是一次概率采样，理论上任何 token 序列都可能出现。于是它可能调用不存在的工具、使用 schema 里没有的参数名，或者——最危险的——**给参数填一个用户从未说过的值**。论文的量化触目惊心：本地 LLM agent 有 **5.5%–19.7% 的调用至少含一个编造值**，编的多是用户没提的超参数、文件路径和选项；开推理模式也消不掉。

为什么这在临床是致命的？因为**编造的值不会让程序报错**。一个被虚构的阈值会静默改变那一步的分析结果，而流水线后面的每一步都建立在这个被污染的结果上——错误是级联放大的。而对那些缺了必需参数的请求，LLM agent 在高达 **62.1%** 的情况下会直接编一个值填上，而不是回头问用户。

### 1.3 决策模型：不写作文、只涂答题卡的新物种

传统上这类判断都交给 LLM"写一段话"来解决。但 2026 年下半年兴起了一个新物种——**决策模型（decision model）**：TypeSafe 的 Jev 开了先河，Cloudflare（Clef）、Perplexity（pplx-decider）、OpenJev 等陆续跟进（本博客此前已对 AnyS1、Jeveration、Piccolo、Decision-10、Jetriever、DREX、Decision Gates 等这一脉络做过系列精读）。它与 LLM 的本质区别是：**不生成任何文本**。输入一个状态（state）、一个问题、一份有限选项列表，一次前向传播（single forward pass）返回每个选项的概率——没有采样、没有解码、没有 JSON 要修。

认知科学家卡尼曼在《思考，快与慢》里把人的认知分成两个系统：System 2 缓慢、审慎、逐字推敲；System 1 快速、单步、直觉判断。决策模型就是机器版的 System 1——论文标题由此而来。

### 1.4 洞察的种子：工具调用其实是选择题

作者的洞察从一个观察出发：**工具调用几乎没有什么是真正"开放"的**。工具清单就摆在目录里，参数名和合法值写在 schema 里，参数值几乎全在用户的请求文本里，剩下的能靠固定规则推导（比如单位换算）。所以一次工具调用的本质不是"写一段文字"，而是**一连串选择**：选哪个工具？请求里的哪个值填进哪个参数？这个开关设不设？该不该调用？

既然是选择题，就该用做选择题的模型——而不是让一个擅长写作文的模型硬着头皮默写。这是全文的种子。

## 二、论文定位和关联工作

### 2.1 谱系一：临床/隐私场景的本地 LLM

Wiest 等（npj Digit. Med. 2024，论文参考文献 7）证明了本地 LLM 做结构化医疗信息检索的可行性。这条线解决了"数据不出门"，但没解决"本地模型更小、幻觉更多"——本论文实测的编造率恰好落在这个缺口上。**关键区别**：论文同样坚持全程本地（llama.cpp + 单卡 GPU，连评分器都本地跑），但用架构而非模型规模来解决可靠性。

### 2.2 谱系二：工具调用幻觉的测量与防御

测量侧有 ToolBeHonest（EMNLP 2024，论文参考文献 10）与 Berkeley Function Calling Leaderboard（ICML 2025，参考文献 11）。ToolBeHonest 的核心发现是"可解性幻觉"：面对工具做不了的任务，模型倾向于硬编一个解法——Gemini-1.5-Pro 与 GPT-4o 在不可解任务上的得分只有可解任务的零头。

防御侧的业界标准答案是**约束解码（constrained decoding）**：把 schema 编译成语法，在每个解码步屏蔽掉会让输出违反语法的 token（llama.cpp 的 GBNF、Outlines、XGrammar 等；OpenAI Structured Outputs、各家 function calling 底层同此）。行业报告称它能消除 95% 以上的 schema 违规。但这条路线有一条被反复指出的天花板：**它管形状，不管内容**。语法能保证枚举字段只取合法值，却无法阻止模型在自由文本字段里编一个不存在的文件路径——因为任意字符串对该字段都"合法"。语义编造停在 3–7% 的平台期。

**本论文的位置**：把约束推到极端——不只约束 token 序列，而是**整个输出空间预先封闭**成"请求/schema/目录/策略"四个来源的选项集合。值不是从合法 token 序列里"生成"出来的，是从有限候选里"选"出来的。

### 2.3 谱系三：决策模型品类与 System 1 应用浪潮

2026 年 9–11 月，决策模型从单品爆发为品类：Jev（TypeSafe）、Clef（Cloudflare，开源 Apache 2.0）、pplx-decider v1.2（Perplexity，开源，基于 Qwen3.5 骨干改造：剪枝词表输出层为 255 行读出矩阵、全注意力层非因果化）、OpenJev、Mapika 的 decider 系列等。Perplexity 官方博客明确了这一设计哲学：路由、审核、过滤、重排这些任务"此前由生成式模型处理，但它们并不需要自由文本生成"。应用侧，本系列此前精读的 AnyS1（从技能库挖掘决策点训单个通用 System-1）、Jetriever（决策模型做记忆检索效用打分）、Decision Gates、DREX 等都在把决策模型嵌入 agent 工作流的不同环节。**本论文的独特位置**：它是第一个把"整个工具调用环节"完整交给决策模型、并给出系统性构造方法（编译器）与大规模对照实验的工作。

### 2.4 谱系四：作者自己的前序系统

两位作者此前发表了 ReclAIm（Radiology AI 2026，多 agent 监控医学影像 AI 性能衰减）与 mAIstro（Eur. J. Radiol. AI 2025，端到端放射组学多 agent 系统）——本论文 123 条评估提示逐字取自这两个系统的真实 notebook，18 个 MCP 服务器中 11 个影像服务器来自其 ReCo 框架。可以说这是他们在临床 agent 实战中撞到可靠性墙之后的反思之作。

### 2.5 定位对比表

| 维度 | 云端 LLM agent | 本地 LLM agent + 约束解码 | **System 1 agent（本文）** |
|------|---------------|--------------------------|---------------------------|
| 数据出境 | 是 | 否 | **否（单卡本地）** |
| 工具/参数名幻觉 | 可能 | 语法上可消除 | **结构上不可能（选项来自目录与 schema）** |
| 参数值幻觉 | 常见（5.5–19.7% 调用） | 语法无法阻止自由字段编值 | **结构上不可能（值来自封闭候选集）** |
| 缺失必需参数 | 常被编造填充（最高 62.1%） | 常被编造填充 | **留空并模板化追问用户** |
| 每次调用生成 token | 123–952 | 同左 | **0（约 12 道单遍前向）** |
| 可复现性 | 采样随机 | 采样随机 | **同输入同输出，逐题可审计重放** |

## 三、问题定义

### 3.1 一个类比：把作文题改成选择题

理解这篇论文只需要一个类比。LLM agent 参加的是**作文考试**：题目说"调用分割工具"，它要自己一个字一个字写出整份调用代码——再怎么强调格式规范，也保不齐写出几个错别字（编造的工具名、参数名、参数值），而且错别字藏在合法句子里，语法检查抓不住。System 1 agent 参加的是**选择题考试**：答题卡上根本没有格子让你写字，只有选项可以涂——工具名只能是目录里的 157+1 个选项之一，参数值只能是从请求、schema 和规则推导里抽出的候选之一。**答案只能从选项里来，编造无从谈起。**这不是"更少写错字"，是"想写错字都没有地方写"。

### 3.2 形式化

剥掉临床外壳，论文解决的问题可以写成：

**给定**：(1) 工具目录 T = {t₁…t₁₅₇}，每个工具附带 JSON Schema 声明的参数集；(2) 一条自然语言请求 r；(3) 一个本地可运行、不生成文本的决策模型 M（输入状态+问题+选项，一次前向输出选项概率分布）。

**求**：映射 f(r) → 调用决策——选哪个工具（或不调用）、请求中的哪些值填入哪些参数、可选参数设不设。

**约束**（问题的灵魂）：
1. **封闭性**：输出中每个工具名 ∈ T，每个参数名 ∈ 该工具 schema，每个参数值 ∈ {请求文本、固定规则推导、schema、agent 策略} 四个来源的并集；
2. **不编造**：必需参数在请求中无值时不得填充，必须交还用户；
3. **每个决策带概率**：低置信转化为拒绝或追问，而不是硬猜；
4. **可重放**：同输入同输出，运行可逐题审计。

### 3.3 这个抽象的精妙之处

精妙在于一次**问题形态的改写**：把"生成一段符合 schema 的调用文本"（开放的、逐 token 的、无界的）改写为"在有限选项集上做一系列选择"（封闭的、一次前向的、有界的）。改写一旦成立，幻觉就不再是一个需要努力减少的统计性质，而是**定义域之外的事件**——决策模型的输出是选项上的概率分布，一个分布的支撑集只能是选项本身，目录里没有的工具概率恒为零。约束解码在 token 层封闭（形状合法），System 1 在**值层面**封闭（内容有据）——这是 0% 与"95% 形状合规但语义编造仍在 3–7% 平台期"的本质区别。

## 四、问题解法

架构原则一句话：**模型只做判断，代码逐字执行**（the model judges, and code executes verbatim）。整个系统三个组件，各管一件事。

### 4.1 组件一：Agent——出题的控制器

Agent 把一个请求路由成对决策模型的一串提问：

1. **工具选择题**：对目录全部 157 个工具 + 一个『以上都不是』选项出一道选择题，每个选项是"服务器名.工具名 + 描述前 220 字符"；
2. **歧义消解**：前两名工具概率差距 < 0.3 时，追加一道二选一——列出两个工具的参数名，问哪个的参数与请求给出的值对应；
3. **能力核验**：对选中工具出一道是非题——展示完整描述与参数名，问它能否完成该请求；正面概率 < 0.5 就拒绝（部署时另有全程置信度 < 0.3 拒绝的策略）；
4. **缺失值处理**：必需参数缺值时**不填**，而是向用户展示固定模板（参数名 + schema 描述前 120 字符），等用户提供——模板由 schema 填充，无任何随机生成；
5. 多步请求中，每次调用及其结果的前 1,200 字符加入状态，再问一道"是否需要下一步"。

### 4.2 组件二：Compiler——确定性的问题编译器

编译器是纯代码（无模型参与），把选中工具的 JSON Schema 和请求文本编译成一道道有限选项题：

| 参数类型 | 问题形式 | 选项来源 |
|---------|---------|---------|
| 枚举（enum） | 『参数 x 应取哪个值？』 | 枚举值 + 『未指定（保默认）』 |
| 布尔（boolean） | 『请求要把选项 x 开还是关？』 | on / off / 未提及 |
| 数字、路径、列名、自由文本 | 值问题 | 编译器从请求抽取的候选 + 『未指定』 |
| 列表（list） | 逐项选择 | 剩余候选 + 『没有更多项了』（候选互相竞争，一个值最多被用请求中出现的次数） |
| 对象（object） | 是非题 + 每键一个值问题 | —— |

候选值来自四个来源：**(1) 请求本身**——路径、数字（含"三"这类文字写法）、范围、引号串、标识符、≤3 词短语、标签后的文本等；**(2) 固定规则推导**——单位换算、分数与百分比、染色体/等位基因记法、由片段组合的路径；**(3) schema**——描述中列出的值与文档化列表项；**(4) 环境与前序步骤**——如另一参数指向的 CSV 文件表头。命名工具或服务器的词不会被列为候选。

**沉降与接受规则**（防止过度填充）：独立问题并行发送、按固定顺序沉降，自由值按概率从高到低落位；可选参数只有概率 ≥ 0.7 才设置；等于文档默认值的参数不传；两个参数争同一个值时加问一道归属题（概率 ≥ 0.7 才生效）；必需参数无值上报为缺失，回答 < 0.5 标记为不确定。

### 4.3 组件三：决策模型——答题者

决策模型回答每道题：输入（状态、问题、选项、题型），一次前向输出每选项概率，无采样。**任何满足此接口的模型都可原样替换**。论文用了三个协议族的六个已发布模型（4B–35B，全部零微调，llama.cpp b11929 本地服务，每题独立请求）：

| 模型 | 协议族 | 基座 | 读出机制 |
|------|--------|------|---------|
| decider-4b / decider-35b-a3b | decider（Mapika） | Qwen3.5-4B / 35B-A3B | 选项标签 token 的 log 概率除以拟合温度归一化；≤10 选项用字母 A–J，最多 255 个单 token 标签 |
| pplx-decider-flash / pplx-decider-27b | pplx-decider（Perplexity v1.2） | Qwen3.5-4B / 27B | chat 模板 + 非因果全注意力层，embeddings 模式取标记 token 处隐状态，过 255×隐维读出矩阵归一化 |
| OpenJev / Clef | 原生 SystemOne | 27B Qwen3.5 架构 / Qwen3.5-27B+联合 schema 头 | llama.cpp 原生 /v1/systemone 端点直接返回每选项概率 |

OpenJev 每题至多 52 个选项，而工具选择题有 158 个选项——大题拆成均衡分组、组内先答再组间决赛，选项概率 = 组冠军概率 × 组内概率。**确定性保证**：同一模型、硬件、构建下，同样的（状态、问题、选项、题型）给出同一分布；每个答案按其 SHA-256 哈希存档，可完整重放。

### 4.4 编译器的开发回路：oracle 方法

编译器的候选抽取规则是唯一被开发的部分，论文设计了一套把**模型失败与编译器失败分开**的回路：

1. **编译器 oracle**：把决策模型换成"知道标准答案、总选标注值"的替身。oracle 跑不通的请求，暴露的是"没有任何一道题提供这个值"——编译器的失败，需要修；
2. 每个失败分类为编译器失败 / 模型失败 / 标注错误，**只修编译器失败**；
3. 每次修改必须是一条关于"请求如何表达值"的**一般规则**，而非特定工具的特例；接受标准在任何模型评估前成文；
4. 一组修改被接受，当且仅当：跨模型总正确调用数上升、此前参考请求不超过容差地退化、且删掉任何单条修改都无法简化（留一验证）。

这套方法与软件工程的"先写回归测试再改代码"同构：oracle 是永不失败的黄金测试，参考请求是回归测试集。

### 4.5 全景：一个请求的完整旅程

请求进入 → agent 出工具选择题（157+1 选 1）→ 必要时歧义消解 → 能力核验（<0.5 拒绝）→ 编译器把 schema+请求编译成约 12 道有限选项题 → 决策模型逐题一次前向给概率 → 沉降规则拼装参数 → 必需值缺失则模板化追问用户 → 否则发出 MCP 调用。全程零 token 生成，每个决策带概率存档。

## 五、评估指标与实验证据

### 5.1 实验设置

- **工具面**：157 个工具、18 个 MCP 服务器。影像目录 42 工具/11 服务器（nnU-Net、Merlin CT 基础模型、PyCaret AutoML、PyRadiomics、TotalSegmentator、2D/3D 分类等）；生物医学目录 115 工具/7 服务器（proteomics-mcp 53 个、AlphaGenome 22 个、MSMCP 13 个、ClinicalTrials.gov 7 个、ChEMBL 7 个、Scanpy 7 个、TISSUE 6 个）。
- **评估集**：2,126 条请求 = 2,003 条自拟（覆盖改述、干扰值、数字格式、引号、否定、噪声等 16 类语言现象）+ 123 条逐字取自已发表论文的提示（ReclAIm 73 条、mAIstro 50 条）。拆分为：**主基准 1,952 条**（1,645 条完整请求、声明 6,056 个参数值；307 条越界请求，即没有任何工具能服务的请求）+ **174 条欠指定请求**（缺必需参数，单独评估）。
- **对照组**：9 个开源权重 LLM × 推理开/关 = 18 个设置，每个请求一次补全（固定种子 20261102），llama.cpp 原生解析，首个调用计分，无调用视为拒绝。其中三个 LLM（Qwen3.5-4B/27B/35B-A3B）恰是五个决策模型的基座——**同骨干对照**由此而来。
- **硬件**：单张 NVIDIA RTX PRO 5000 Blackwell（48 GB），全程本地，NVML 整卡能耗计数器计量。
- **统计**：每个 System 1 agent × 每个 LLM 设置配对，108 对/指标，McNemar 精确检验 + Holm 校正；比例报告 Wilson 95% 区间。

### 5.5 可靠性：论文最锋利的结果

- **零虚构**：10,888 次 System 1 调用、33,945 个参数值，无一"无据值"（判定标准：值既不匹配标注值、也不是请求里写过的文本/数字、也不是编译器提供的选项、也不在 schema 里——这个标准把请求中任何地方写过的值都算有据，实际上**偏严地低估**幻觉，且经 200 个被标记值的独立人工复核校准）。LLM 侧：5.5–19.7% 的调用含至少一个编造值，三个 LLM 在 19–53 次调用里用了 schema 外参数名。
- **缺参不猜**：174 条欠指定请求上，System 1 正确处理（选对工具 + 填对已给值 + 报告缺失参数）86.2–93.7%；LLM 最多 5.7%。LLM 在最高 62.1% 的欠指定请求上直接编值填充，最准的 LLM 设置也有 27.6%。
- **拒绝与漏调的平衡**：System 1 拒绝了 87.0–94.5% 的越界请求、只漏调 1.0–3.3% 的完整请求；LLM 拒绝率 41.4–97.4% 但拒绝最多的两个设置分别丢了 24.3% 和 36.5% 的完整请求——**靠多拒绝刷分在这个评测里无处遁形**。
- **诚实的边界数据**：22/10,888 次调用把请求里写过的值放错了形制（如标识符格式）；每个 agent 有 2–6 次把请求里别处的值错填进缺失参数——这是**选错**，不是**编造**。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**因果链：从"开放式生成"到"封闭式选择"的结构改写。**

1. **工具调用大部分非开放式**【论文观察，已支持】：几乎每个参数值要么写在请求里、要么能由固定规则从请求推导（如单位换算）、要么列在 schema 里，工具本身列在目录中——值的来源天然封闭；
2. **所以工具调用本质是一系列选择**【论文洞察】：选哪个工具、哪个值进哪个参数、开关设不设、要不要调用——每一步都是"从有限候选中挑一个"；
3. **LLM 却用开放式方式做封闭式的事**【论文实验支持】：LLM 逐 token 生成调用文本，词表开放、任何 token 序列都可能被采样出来 → 虚构的工具名/参数名/参数值有非零概率出现（实测 5.5–19.7% 调用含编造值，推理模式不消除）→ 且编造值不报错，在流水线中**静默传播**到后续每一步；
4. **本文把每步选择编译成有限选项单选题**【方法设计】：确定性编译器从请求/schema/规则抽取候选，决策模型一次前向在候选上给分布；
5. **输出空间封闭 → 虚构在结构上不可能**【论文实验支持】：分布的支撑集只能是选项本身，目录外的工具、schema 外的参数名、候选外的值概率恒为零——10,888 次调用 0 虚构不是"幻觉率低"，是**幻觉的定义域外事件**；
6. **缺值问用户而非猜**【论文实验支持】：这是代码策略而非模型行为——不依赖模型的"诚实度"，故欠指定请求正确处理 86.2–93.7% vs LLM ≤5.7%。

**代价与互补性**【论文实验支持】：封闭候选集对**长标识符抽取**不利——ClinicalTrials.gov 工具调用 System 1 组均值 89.8% vs LLM 推理开 98.6%，ChEMBL 上 LLM 填值也更好；标识符常需世界知识推理而非请求内抽取，自由生成在那里反而是优势。故作者定位为**互补**：判别式管"值有据"的场景，生成式管"值需推理"的场景。modality 类越界请求（工具能做该任务但不支持给定输入类型）所有 agent 都难（System 1 组均值 57.3%）——能力核验的判断本身仍会错。

**与约束解码的机制对比**【阅读者分析，基于公开文献】：约束解码在 token 层封闭输出（语法合法），但自由字段的"合法 token 序列"仍无穷多，值级编造无法根除；System 1 在值层面封闭。这是"形状约束"与"内容约束"的层次差异，解释了 0% 与 3–7% 平台期的差距。

### 6.3 综合判断与未决问题

**多研究共同支持的机制**：(a) 封闭输出空间使对应类别的错误从统计性质变为结构不可能（本文 0/10,888 + 约束解码文献的形状合规 + 生产实践中 strict 模式不编键）；(b) 判别式概率输出在对比型任务（选工具、路由、重排）上匹配或超过生成式（本文 + Jetriever + AnyS1）。

**仍属推测或单源支持的机制**：工具选择 76:5 优势的"显式候选竞争"心理物理解释（辨析题比默写题容易）为阅读者推测；OpenJev 分组锦标赛是否优于直接截断未消融。

**适用条件**：值的来源封闭（请求/schema/规则可覆盖）；候选抽取规则覆盖值形制（22 次形制错误暴露盲区）；决策模型自身判别力够强（decider-35b-a3b 反例）。**可能的失效条件**：标识符需世界知识推理的场景（LLM 反超）、开放域生成任务（完全不适用）、候选列表质量决定上界（编译器 Bug 会系统性漏值）。

## 七、必要知识反推

假设找一个零知识的人重做这项工作，他至少需要掌握：

### 7.1 领域知识层

- **临床数据治理**：理解 GDPR/HIPAA 下患者数据为什么不能出境、医院为什么卡审批——这是"必须本地"硬约束的来源，决定了整个方案的天花板设计；
- **生物医学工具生态**：熟悉 nnU-Net、PyRadiomics、AlphaGenome、Scanpy 等工具的参数习惯，否则编译器的候选抽取规则无从设计——16 类语言现象覆盖（数字格式、路径、标识符、染色体记法……）全部来自对真实请求的观察；
- **MCP 协议与 JSON Schema**：catalogue 是服务器返回的工具清单快照，编译器的输入就是 schema——不懂 anyOf/oneOf、pattern、default 语义写不出参数类型判定。

### 7.2 方法论知识层

- **双过程认知理论**（Kahneman）：把"快而单步的判断"映射到"单次前向的决策模型"，方法的命名与定位都系于此；
- **决策模型品类地图**：知道 Jev/Clef/pplx-decider/OpenJev/decider 各自的协议细节（读出矩阵、温度、选项上限），才能"零微调"组装六个 agent 并正确调用；
- **幻觉文献与约束解码天花板**：了解 ToolBeHonest/BFCL 的测量方法和约束解码"管形状不管内容"的局限，才能把自己的贡献准确定位在"值级封闭"；
- **实验方法学**：McNemar 精确检验、Holm 校正、Wilson 区间、bootstrap，以及更重要的——同骨干对照、oracle 回路、留一验证的混杂因素隔离设计。

### 7.3 工程知识层

- **llama.cpp**：GGUF 量化模型本地服务、logits/embeddings 模式、原生 tool-call 解析——六个决策模型和九个 LLM 全部经它跑在同一张 48 GB 卡上；
- **NVML 能耗计量**：整卡能耗计数器、20 秒空闲基线——效率对比才站得住；
- **可复现工程**：SHA-256 哈希存档每个答案、代码哈希、存档重放重建全部记录——审计友好不是口号而是工程交付物。

### 7.4 知识融合的关键节点

1. **洞察节点**："工具调用 ≈ 一系列选择"——需要同时见过 MCP schema（知道值来源封闭）和决策模型（知道它天生答选择题），缺一个这个等号画不出来；
2. **工程节点**：oracle 回路——把软件工程黄金测试思想移植到编译器开发，使"修规则"不退化为"背题"；
3. **验证节点**：同骨干对照——只有了解决策模型家谱（谁的基座是谁）才能设计出这组最锋利的对比。

## 八、论文中可以提取的通用性灵感

### 灵感一：把生成问题改写为选择问题，错误类别从统计性质变成结构不可能

- **核心思想**：当一个系统的输出本应来自封闭集合时，不要让模型"自由地写对"，而是把输出空间本身封闭起来——错误从"概率上有多少"变成"定义上不存在"。
- **论文证据**：10,888 次调用零编造 vs LLM 5.5–19.7%；缺参处理 86.2–93.7% vs ≤5.7%。
- **推广场景**：金融交易指令生成（字段全来自白名单）；法律文书条款引用（引用条目来自法条库）；工业控制指令翻译（动作集封闭）；API 自动化测试参数（从录制流量抽候选）。

### 灵感二：『模型判断、代码执行』的责任切分

- **核心思想**：语义理解交给模型，确定性交给代码，两者之间用"概率 + 阈值"的窄接口连接——模型永远不直接产出被执行的内容。
- **论文证据**：编译器纯代码；追问模板从 schema 填充；0.5/0.7 阈值把低置信转化为拒绝/追问/留空。
- **推广场景**：数据清洗管道（模型判字段映射、代码执行变换）；客服路由（模型判意图、代码执行 SLA）；自动化运维（模型判告警相关性、代码执行预案）。

### 灵感三：用 oracle 分离『表达失败』与『判断失败』，只修前者

- **核心思想**：开发"模型+规则"混合系统时，先造一个知道标准答案的 oracle 替身测出规则表达力的上界；只修规则层失败、只修一般规则、用回归集守底线——防止为个案打补丁导致过拟合。
- **论文证据**：编译器开发七步法（oracle → 失败分类 → 只修编译器失败 → 一般规则 → 聚合提升+容差+留一 → 存档重放 → 代码哈希）。
- **推广场景**：prompt 工程的天花板分析（先测最优 prompt 能到多少再优化）；DSL/编译器设计的语义等价 oracle；数据管道 schema 演进管理。

### 灵感四：可审计性来自『每步存概率 + 确定性重放』，而非事后解释

- **核心思想**：高风险系统的可追责不靠事后用另一个模型解释，而靠事前让每个决定以带概率的原子形式留档、系统整体确定性可重放。
- **论文证据**：答案按 SHA-256(模型, 类型, 状态, 问题, 选项) 存档；重放存档答案重建全部 12,756 条记录；同输入同输出。
- **推广场景**：医疗 AI 监管审查的逐判断回放；自动驾驶决策日志；交易算法合规留痕；科学计算 pipeline 的可复现性认证。

### 灵感五：接口红利是放大器不是点金术，选型必须做同骨干对照

- **核心思想**：判别式接口的可靠性红利真实存在，但以上游模型自身判别力为前提；评估任何"新范式 vs 旧范式"都应先跑同骨干（或同容量）受控对照。
- **论文证据**：pplx-decider 系两个模型比基座 agent 高 2.6–9.6 个百分点，但 decider-35b-a3b 反而低 3.0 个百分点；参数填充上大 LLM 逼近（46:19:43），标识符密集数据库上 LLM 反超。
- **推广场景**：任何架构升级迁移决策；新推理引擎/新量化方案的性能归因；多供应商 LLM 应用的中间件选型。

### 灵感六：隐私硬约束可以是架构创新的催化剂

- **核心思想**："数据不能出门"这类约束与其当作待绕开的障碍，不如当作逼问系统本质需求的筛子——论文正是被"必须本地"逼到"本地模型弱 → 不能靠模型能力 → 只能靠结构设计"的路线上，反而得到比云端更强的可靠性。
- **论文证据**：全流程单卡本地（含评分器），却取得 97.0% 工具调用准确率与零幻觉。
- **推广场景**：边缘设备 on-device AI；涉密单位内网知识问答；小微企业低成本自动化。

## 结语

这篇论文表面上是临床 AI 的工具调用系统，内核是一次干净的题型改革：当任务的输出空间本质封闭（选工具、选值、选开关）时，生成式模型是被错用的工具——不是模型不够好，是考试题型出错了。把作文题改成选择题之后，"幻觉"在工具调用场景里被证明可以不是被减少，而是被消灭。它同时诚实标注了边界：决策模型强弱仍决定成败（decider-35b-a3b 反例）、标识符密集场景生成式占优（互补而非替代）、开放域任务它无从置喙。对本系列持续追踪的决策模型浪潮而言，这项工作补上了关键一环：**不训练、不微调，只用确定性编译器 + 现成决策模型，就能让整个工具调用环节在结构上免于幻觉**——这为决策模型从"嵌入环节"走向"接管环节"提供了迄今最完整的实证。
