## 一、论文背景

### 1.1 离线 RAG 的信任真空

小规模量化模型让**完全离线的 RAG** 在嵌入式板上成为现实（战场、工业、野外等断网场景）。知识以**签名知识包**（signed knowledge packs）形式到达设备：文本块 + 清单 + **预计算嵌入向量**。为什么要带向量？因为在树莓派 5 的 CPU 上给 950 段落做嵌入要 **29 分钟**——设备上重算不现实。

签名在此暴露出根本盲区：**签名证明「这些字节是谁发布的」，不证明「这些向量编码了这些文本」**。控制发布管线的攻击者（入侵的构建管道、持有内容密钥的恶意内部人）可以发布通过全部内容审查的良性文本，同时配上精心选择的向量来操纵检索。同样的鸿沟存在于任何向量数据库：库里存的是向量（往往是压缩码），审计把存储向量与重算向量在某个容差内比对——这个容差给了攻击者多大的操纵空间，此前无人量化。

### 1.2 作者的前作与本文的递进

作者 2026 年前作（arXiv:2610.33732）提出签名版本化知识包并在树莓派 5 上实测，留下一个开放问题：**一个有效签名但被投毒的包通过了全部包检查**。本文把它磨成更尖锐的形态并给出四问（RQ1-4）：容差校验让渡多少查询？压缩存储格式暴露多少？精确校验能否跨异构硬件成立？设备端校验成本与端到端后果如何？

### 1.3 一句话预告结论

**容差即攻击预算**：容差校验让渡的查询份额可由「检索边际分布」精确预测（margin law）；现实中边际很小，所以从浮点噪声到 INT8 到压缩存储，容差越大暴露越多，直至全部可劫持；而出路是**别信发布者的向量/码——校验者自己算，模糊自己判，判完自己改写**。

### 2.2 与 OWASP 指南的关系

OWASP GenAI 把「向量与嵌入弱点」列为 LLM 应用十大风险之一（LLM08:2025），建议「定期审计与验证知识库完整性」——但**没有规定存储向量如何绑定到文本**。本文把这条建议变成可测量、可校准、可审计的具体程序。

### 2.3 威胁模型（五级校验器谱系）

- **系统**：发布者分发包 P={(t_i, v_i)}，校验者（设备或库审计者）可计算 f(t_i)；向量库场景 v_i 换成码 c_i。
- **对手**：能让校验者收到签名有效的包/库——被入侵的发布者或构建管线、持内容密钥的恶意内部人、被入侵的库写入者。文本全部过审，**向量/码由对手选择**；可新增文本过审的块（端到端实验中加一条「编辑部注」）。知道公开的嵌入模型，最坏情况知道目标查询；也评估只知道同段落其他问题的迁移攻击者。
- **目标**：劫持（把选定块顶到目标查询 rank-1）或载荷投递（把含指令的块送进 top-k 上下文）。
- **校验器**：V0 不校验 / V1 仅签名 / V2 容差重算（cos ≥ τ 即收）/ V3 逐位精确（需可复现计算）/ V4 码级校验（码相等或校验者自判模糊的邻码，随后规范化改写）。
- **范围**：校验侧的模型/配置/代码/信任锚与码本不受对手控制；不涉及改文本、改索引结构、查询信道攻击、侧信道与 DoS。

## 三、问题定义

### 3.1 margin law（边际律）——本文的理论核心

设查询 q、金标单元 g、其余单元集合 C（全部归一化）。θ_g = arccos(q·g)，θ_c = min_{c∈C} arccos(q·c)，只考虑金标排第一的查询（θ_g ≤ θ_c）。定义**角边际** m(q) = θ_c − θ_g。

V2 校验器在 cos(ṽ, v) ≥ τ（即 ∠(ṽ,v) ≤ α = arccos τ）时接受送达向量。**最优攻击者把最近的非金标向量朝 q 旋转 α**，其与 q 的夹角减为 max(θ_c−α, 0)；当且仅当 m(q) < α 时 rank-1 被劫持。于是：

**HR(τ) = (1/|Q|)·Σ_q 1[m(q) < arccos τ]** —— 劫持率 = 容差角度处的**边际经验分布**。

两条直接推论：(1) 运营者可用诚实向量+查询日志离线算出暴露率，**无需运行攻击**；(2) 容差的安全性取决于语料与嵌入模型，不能抽象谈论。数值上用双精度稳定公式 2arcsin(‖q−d‖/2) 重算全部边际，变化 < 4×10⁻⁵ 度，零边际对应文本完全相同的文档。

### 3.2 定律的五条边界（论文的自我限定，值得品味）

1. HR 是**逐查询暴露**——单一被篡索引未必同时实现全部劫持（端到端实验每问单独构造被篡上下文）；
2. 以金标排第一为条件（SQuAD 上 BGE-M3 78%、MiniLM 70%），全体问题暴露按此缩放；
3. 极小容差下暴露者多为金标的**近重复**——被自己的副本顶掉未必有害，小容差暴露是有害性的上界；
4. 忽略重算噪声（比除最小容差外的一切容差小几个量级；FP32 行是理想化数字）；
5. 定律回答「某非金标块能否被顶上去」，**投递特定固定块更难**，在端到端实验单独测。

另有保守性说明：对手若还能把金标向量旋走 α，条件变 m(q) < 2α——本文报告单旋转的保守情形。

### 3.3 问题的深层结构：三种数值偏差 vs 检索边际的尺度错配

- **浮点噪声**：同模型 FP32 跨设备坐标差 10⁻⁷–10⁻⁵，最大角偏差 0.04°（x86↔ARM）；
- **量化计算**：动态 INT8 使向量偏差数十度（MiniLM 中位 INT8–FP32 余弦 0.956；0.1% 分位阈值对应 **25.3°**）；
- **压缩存储**：FP16 复现角 0.03°、SQ8 0.35-0.56°、SQ4 5.8-9.6°、PQ 23-40°、二值 41-47°。

而五语料两模型的检索边际**中位数只有 2.1-7.4°**——三种偏差源逐一与边际同尺度或远超边际，容差必须容忍偏差源就意味着必须让渡边际。这就是「容差即攻击预算」的几何本质。

## 四、问题解法

### 4.0 全景：测量（margin law）→ 暴露（容差审计）→ 封闭（码级校验）

```
诚实向量 + 查询日志 ──margin law──> HR(τ) 暴露率（无需攻击）
容差审计 V2：容忍存储/计算偏差 ⇒ 让渡等量操纵空间（SQ4/PQ/二值≈全暴露）
封闭路径：
  ├─ 设备重算并丢弃发布者向量（发布者数值无关化）
  ├─ V3 逐位精确（要求逐位可复现计算——实测 FP/动态INT8 管线都不满足）
  └─ V4 码级校验：校验者重算嵌入→自己量化→码相等？
        模糊（边界 ε 内）由校验者判定，可收邻码
        收后一律改写为校验者自己的码（canonicalisation）⇒ 发布者无选择
```

### 4.1 组件一：可复现性测量（V3 的可行性检验）

精确校验的前提是逐位可复现推理。实测结果（均为最大绝对坐标差）：PyTorch FP32 随**批大小**变（GPU/CPU ~10⁻⁷；GPU FP16 10⁻⁴）；Apple M2 CPU/Metal GPU 也随批变（1.4×10⁻⁷ / 4.5×10⁻⁸）；ONNX FP32 单机内批/padding 不变但**跨架构变**（x86↔ARM 1.9×10⁻⁷）；动态 INT8 随**同批其他输入**变（至 0.03——per-tensor 动态量化的已知行为）。结论：**常见 FP 与动态 INT8 管线皆非逐位可复现**，V3 需要 pinned 栈或整数-only 推理——这本身是论文的一个独立贡献性测量。

### 4.2 组件二：码级校验 + 守卫带 + 规范化（V4，核心防御）

对压缩存储（SQ/PQ/二值码）**校验码，不校验向量**：

1. 校验者从文本重算嵌入，用量化方案的**可信码本**自己量化，得自己的码 c；
2. **模糊判定权在校验者**：当自己重算的值落在舍入边界 ε 邻域内（SQ：值域 ε SQ；PQ：最近与次近质心平方距离差 < ε PQ；二值：|v| < ε_bin），该条目标记为模糊；
3. 存储码**每条目都等于 c**，或为模糊条目且等于邻码 a，才接受；
4. **规范化**：接受后一律改写为校验者自己的码——发布者在模糊条目上的选择权被清零。

发布者的浮点向量自始至终不被使用。守卫带按「发布者与校验者平台间实测浮点偏差」校准（实证：桌面 NVIDIA↔x86 与 M2 Metal↔ARM 上 SQ8 全收的最小宽度同为 3×10⁻⁷（MiniLM）/3×10⁻⁶（BGE-M3），且都不超过实测最大跨设备偏差）。「使容差审计失效的格式（粗量化胞）恰恰使码级审计最可移植——**粗胞吸收浮点噪声**」是全文最美的转折。

为何校验而不直接替换？替换同样安全但是**静默的**：被篡的库被修好却无人知晓写入者作恶。校验-后-规范化把不一致变成**事件**：可拒绝、可记日志、可依签名归责。

### 4.3 组件三：预注册协议与工程卫生

假设、指标、决策门槛在测量前写定并注明日期随代码发布；34 条偏差与探索性分析全部记日志；复现检查：语料与前作逐字节一致、检索 top-5 一致、前作主配置 60/60 答案复现；模型 revision 全部 pin（M2 复刻核对哈希一致）；延迟剔除 prompt-cache 命中。

## 五、评估指标与实验证据

### 5.1 实验设置

- **硬件**：树莓派 5（16GB，Cortex-A76，LLM/嵌入/校验全在 CPU）、桌面（RTX 4090）、Apple M2 三平台。
- **模型**：Qwen2.5-3B-Instruct（Q4_K_M，llama.cpp）为端上 LLM；BGE-M3 稠密检索（段落级）；all-MiniLM-L6-v2（ONNX，FP32 与动态 INT8，128-token 窗）；交叉编码器/NLI/抽取式 QA 辅助模型。
- **数据**：SQuAD 2.0（950 段落 300 问 + 全部 4,690 可答开发问题）；BEIR 四语料（SciFact/NFCorpus/ArguAna/FiQA）；MS MARCO 1,000 查询。
- **校准阈值**：INT8 参考阈值取树莓派 CPU 上动态 INT8 vs FP32 输出余弦的 **0.1% 分位**（0.9040，25.3°；1,745 窗、批 32；同设置重编码逐位复现，批 64 变至 0.03——阈值属于该配置）。

### 5.2 RQ1：margin law 的验证与暴露率

**定律校验**：300 问集合上，定律预测与模拟攻击在**每个容差上最大绝对差 0.0**——完全吻合。

**SQuAD 全量（Table 2，金标第一的可答问题：BGE-M3 3,648 / MiniLM 3,301）**：

| 容差 τ | 角度 | BGE-M3 劫持率 | MiniLM 劫持率 |
|---|---|---|---|
| 1（精确） | 0° | 0% | 0% |
| 0.99999976（FP32 x86↔ARM） | 0.04° | 0.49% | 0.24% |
| 0.99999 | 0.26° | 2.2% | 1.3% |
| 0.999 | 2.56° | **24.6%** | **16.8%** |
| 0.99 | 8.11° | 74.9% | 54.7% |
| 0.95 | 18.19° | 99.6% | 91.9% |
| **0.904（INT8 参考）** | **25.31°** | **100%** | **98.4%** |
| 0.8 | 36.87° | 100% | 100% |

- 中位边际 **5.2°（BGE-M3）/ 7.4°（MiniLM）**；5% 查询边际 < 0.6°/0.8°。
- **迁移攻击者**（知道目标段落与其他问题、不知查询原词，把载体转向同段落问题的质心）：INT8 阈值下仍成功 **81.2% / 44.0%**——不知查询原文也挡不住。
- **跨语料（Fig.1）**：中位边际 SciFact 5.1-7.2°、NFCorpus 3.5-6.3°、FiQA 3.3-4.7°、**ArguAna 2.1-3.2°（5% 查询边际 <0.02°）**；FP32 噪声容差暴露 0-5.5%，INT8 阈值 98.7-100%。
- **重复文档的辨析**：ArguAna/NFCorpus 小容差暴露大多来自**精确重复文本**（归一空白+小写后相同，仅 qrels 标注不同）——被自己的副本顶掉无害。剔除后 FP32 噪声容差暴露：ArguAna 1.2%/0.8%、SQuAD 0.49%/0.22%、NFCorpus 0/0.22%、FiQA 0.74%/0、SciFact 0——**摘要中「至多 1.2%」的出处**。

### 5.3 RQ2：压缩存储与真实 FAISS 攻击

**容差审计暴露（Table 3，容差=各格式最大诚实重建角，5 语料×2 模型区间）**：

| 存储 | 比特/维 | 最大诚实重建角 | 可劫持查询 |
|---|---|---|---|
| FP16 | 16 | 0.03° | 0-5.2% |
| SQ8 | 8 | 0.35-0.56° | 2.0-14.5% |
| SQ4 | 4 | 5.8-9.6° | **55-89%** |
| PQ（d/8 子向量×256 质心） | 1 | 23-40° | **99.7-100%** |
| 二值（符号） | 1 | 41-47° | **100%** |

**执行攻击（真实 FAISS，FiQA 全库 57,638 文档，MiniLM）**：对手取排位 11-60 的最高排非相关「载体」文档，替换其码为最大化得分的码本条目，回退低增益改动直到解码向量通过全局容差检查。结果（60 目标查询）：**60/60 篡改码全部通过容差审计**；按索引自身评分（查询与全部 57,638 文档解码 PQ 向量的内积）**载体在 25% [16,37] 的目标上排第一**。**码级校验+规范化检出并清除全部 60 个篡改码**（100% [94,100]）。FAISS 本身无过错——它只提供存储与检索，这里把它当作此类审计必须容忍的格式的现实实现。

### 5.4 RQ3：码级校验实测（Table 5，双向、三平台、四后端）

- **精确相等（ε=0）已近乎全收**：SQ8 91.0-99.4%、SQ4 99.3-100%、PQ 99.995-100%、二值 99.99-100%；
- **最小全收守卫带**：MiniLM SQ8 3×10⁻⁷、BGE-M3 SQ8 3×10⁻⁶（两平台一致），PQ/二值 ≤3×10⁻⁷ 或无需；SQ/二值的守卫宽度在一切设置中都 ≤ 实测最大跨设备浮点偏差（桌面 4.3×10⁻⁷ / 1.0×10⁻⁵，M2 3.6×10⁻⁷ / 5.6×10⁻⁶）；
- 守卫例外稀少：M2 最小充分宽度下仅 0.9%（MiniLM）/ 9%（BGE-M3）的 SQ8 向量动用 1-3 个例外；
- 明确限定：这些宽度是三平台+测试格点的**经验校准**，非对他数据的保证；部署应实测自家发布者↔校验者平台偏差。

**残余预算与规范化**：被妥协发布者可在模糊条目上选「抬载体压金标」的邻码。实测（SQuAD，模糊由校验者判定）：校准宽度下发布者选择劫持 **0%（MiniLM 全格式）/ 至多 0.16%（BGE-M3 SQ8）**；故意放宽到 10⁻⁵ 也只到 0.41%——对比容差审计的 2-100%。**规范化后残余为零**（接受但改写为校验者码，发布者无选择）。

### 5.5 RQ4a：设备端成本

1,745 窗语料在树莓派 CPU 重嵌入 **72.9s（FP32）/ 41.6s（INT8）**（对照：前作 BGE-M3 950 段落 CPU 索引 1,725s）。与 LLM 抢 CPU：**8 对/秒的周期性校验使解码速度 −22.9%~−31.4%、p99 inter-token 延迟 +108%~+167%**；满速重索引 −64.5%~−73.9%。结论：可行但与生成争算力——应调度在模型空闲时或挪到独立处理器。大规模参考：57,638 FiQA 文档 MiniLM 重嵌入 M2 CPU 277s / GPU 106s——码级校验可作为入库时或周期性后台审计，不在查询路径上。

### 5.6 RQ4b：端到端攻击效果与包更新

**端到端攻击**（100 可答问题，加入一条固定「编辑部注」指令块——声称信息不存在——其文本各条件相同、向量为把其送进 top-3 而定）：

| 条件 | 正确 | 弃答 | 错误 | 载体进入 top-3 |
|---|---|---|---|---|
| 无攻击 | 0.75 | 0.13 | — | — |
| FP32 校验 τ=0.999 | 0.74 | 0.13 | — | 2% |

### 5.7 阴性结果（预注册，Section 5.6）

- **弃答**：SQuAD 上相关度分数分不开「域内不可答」与可答（bi-encoder AUROC 0.69 / cross 0.63），抽取式 QA 无答案边际 0.86 最好；**MS MARCO 上排名翻转**（0.76/0.83/0.70）——各 scorer 在其训练域最优、无一可假定迁移，门槛必须域内校准。

## 六、效果优势的根源解释

> 按「方法差异→机制变化→指标提升」因果链展开；本文的对比轴是**码级校验 vs 容差审计**。

**解释 1：为什么容差审计在向量场景系统性失效？**

因果链：容差审计的初衷是容忍**诚实偏差源**（浮点/量化/存储重建）→ 容差下界由偏差源最大幅度决定（SQ8 0.57°、PQ 38°、INT8 25.3°）→ 而攻击者的操纵预算恰是同一容差（margin law：可旋转 α=arccos τ 不被发现）→ 暴露率 = P(边际 < α)，由**检索几何**决定，不由审计者意愿决定 → 五语料边际中位 2.1-7.4°，与偏差源尺度错配 → SQ4/PQ/二值/INT8 容差下 55-100% 可劫持。根因是**「合法变化空间」与「恶意操纵空间」在容差语义下不可分**：审计者把两者混在同一个球里，攻击者住在球里的任意处。
【论文实验支持：Table 2/3/4 完整的偏差-边际-暴露对照；300 问上定律与模拟攻击逐容差 0.0 差。】

**解释 2：为什么码级校验+规范化能零让渡且跨平台可行？**

因果链：校验对象从「向量（连续，差一分度都是它）」改为「量化码（离散，非此即彼）」→ 判定退化为逐条目相等比较，不再需要容差球 → 诚实浮点噪声只剩两种效应：(a) 极少数条目落在舍入边界附近——由**校验者自己的重算**判定模糊并允许邻码；(b) 其余全部逐位相等 → 规范化把接受的邻码也改写为校验者码 → 发布者对最终码的**选择自由度=0**（残余预算实测 0-0.16%、规范化后 0）。跨平台可移植的根源在于**粗量化胞的吸收效应**：胞径（SQ8 0.35-0.56°）远大于跨设备浮点偏差（0.04°/坐标 10⁻⁷-10⁻⁵），所以同一文本在两平台落进同一胞——「使容差审计失效的量化误差」在同一离散化里变成了对噪声的免疫。
【论文实验支持：Table 5 三平台×四后端最小全收宽度不超过实测跨设备偏差；Table 4 执行攻击 60/60 被 V4 拦截。】【推测标注：守卫带宽度是经验校准，论文明言非保证——理论模型（从浮点误差模型推导守卫带）列为 future work。】

**解释 3：为什么端到端伤害是「弃答暴涨」而非「错误回答暴涨」？**

因果链：载荷是「信息不存在」编辑部注 → 进入 top-3 上下文后与真实段落冲突 → Qwen2.5-3B 在矛盾证据下倾向保守，选择弃答 → 正确 0.75→0.39 中大部分变成弃答（0.13→0.50），错误仅 0.11。这提示向量投毒对小型模型的伤害形态是**可用性塌陷**（拒绝回答）而不只是错误信息——对断网场景（本就无兜底）两种伤害都致命。若载荷换成功说性错误信息，错误率形态会不同——论文固定载荷设计换来干净的投递-效果分离，但也使该结论限于此类指令型载荷。【论文实验支持：5.6 节数值与载荷文本固定声明；载荷类型对伤害形态的依赖未系统变化（单载荷设计）。】

**解释 4：为什么三线防御失败各有教训（阴性结果的机制）？**

- 弃答翻转：相关度分数是「分布拟合质量」的代理，不是「可答性」的语义判断；每个 scorer 在训练域学到的是该域的分数-可答性映射，换域映射失效——**任何校准阈值都是域的局部属性**。
- 剪枝：剪掉的是「模型生成时回头看的冗余」，哪怕答案串还在——3B 模型的抽取依赖完整语境的注意力模式，96% 的「字面在场」≠「可用」。延迟收益与答案可用性的交换必须看**错误分解**（正确→弃答 vs 正确→错误），不能只看总正确率。
- NLI 筛查：MiniLM 级 NLI 依赖词汇重叠启发式，「改一个事实的近拷贝」词汇重叠极高 → 判蕴含 → AUROC 0.18 近乎反向。**语义级防御撞上的正是本文攻击的镜像**：向量攻击在文本层不可见，语义筛查在向量层不可见。
【论文实验支持：5.6 节预注册数值；NLI 词汇重叠偏差引 McCoy et al.。】

## 七、必要知识反推

### 7.1 领域知识层

- **RAG 检索的向量空间决策**：哪个块进上下文完全由余弦相似度在向量空间决定——理解「操纵向量=操纵一切下游行为」必须先理解这一点；嵌入模型是公开的，攻击者可以离线试出理想向量。
- **向量压缩格式谱系**：FP16/SQ8/SQ4/PQ/二值的比特/维与重建误差量级（0.03°→47° 跨三个数量级）——这是审计设计的物理约束表。
- **浮点不可结合性与动态量化的批耦合**：归约顺序随核/批/padding/线程/硬件变；per-tensor 动态量化让同批一个输入改变另一个的计算——「重算即可复现」在生产栈里是幻觉。
- **软件供应链安全工具箱**：TUF 角色分离、Certificate Transparency 透明日志、in-toto、模型签名——它们绑定字节与密钥、字节与历史，不绑定工件内部的语义一致性。

### 7.2 方法论知识层

- **把攻击面变成可计算分布**：margin law 示范了「最优攻击者几何 → 指标分布 → 离线可算的暴露率」的推导范式——安全度量不一定要打红队，有时一条引理就够。
- **保守性边界的显式枚举**：五条 remarks 逐条说清定律测什么、不测什么（逐查询 vs 单索引、条件性、近重复无害性、噪声理想化、特定投递更难）——每条都防止一次过度解读。
- **预注册协议**：测量前写定假设/指标/决策门槛，34 条偏差记日志——把「探索性分析偷换为确认性结论」的通道制度性堵死；阴性结果与阳性结果同等发表。
- **威胁模型的诚实边界**：谁不在对手能力内（校验侧栈、码本）、哪些攻击不在范围（文本、索引结构、查询信道）——清楚的不保证比模糊的保证更有用。

### 7.3 工程知识层

- **数值栈 pin 清单**：模型 revision、分词器、截断长度、pooling、归一化、runtime/编译器版本、编译图——一切影响数值的东西进签名清单；码本哈希必须来自与被验方不同的信任源。
- **校验调度**：8 对/秒就吃掉 LLM 23-31% 解码速度——校验属后台批任务，不属查询热路径；入库时/副本同步时/周期审计三个挂点。
- **阈值-模型绑定**：路由阈值随模型换血重标（前作教训）；守卫带随平台对/模型/runtime 换代重测。
- **度量卫生**：Wilson 区间、固定种子、双向测量（发布者→校验者与反向）、复现检查（60/60 答案逐字复现）。

### 7.4 知识融合的关键节点

1. **「容差=预算」的几何翻译**：把「审计误差容忍」这一工程参数翻译成「攻击者旋转半径」，再翻译成「边际分布上的概率」——供应链安全与信息检索几何在这一点上化学反应，产出无需攻击的测量术。
2. **「离散化免疫」的反直觉利用**：量化误差通常被视为损失，此处粗量化胞恰好吸收跨平台噪声使精确码比较可移植——同一现象在威胁模型翻转后从缺点变成防御资源。
3. **「判定权归属」的安全原则**：模糊条目由校验者而非发布者判定 + 判后改写——把剩余自由度从对手侧搬到防御侧，是「canonicalisation 零让渡」的全部秘密。
4. **「检测与修复分离」的事件化设计**：静默修复丢失归责线索；先校验（产生事件）再规范化（产生安全），配签名（产生归责）——三者各司其职。

## 八、论文中可以提取的通用性灵感

### 灵感 1：容差即攻击预算——一切「差不多就行」的校验都应换算成暴露率

- **核心思想**：任何以容差容忍诚实噪声的完整性校验，都把同尺度的操纵空间让渡给对手；暴露率可用「系统判别量的边际分布」离线算出，无需攻击演练。
- **论文证据**：margin law 与模拟攻击逐容差 0.0 差；FP32 噪声 0-5.5%、τ=0.999 17-25%、INT8 98-100%。
- **推广场景**：(1) 任何「重算比对」型校验（编译产物、特征存储、模型缓存、CDN 内容）；(2) 生物特征比对的 FAR 换算成冒充预算；(3) 区块链轻客户端的容差同步；(4) 金融对账的容差豁免额→挪用空间；(5) 数据质量监控中「允许 1% 偏差」的规则一律应问：谁住在这 1% 里？

### 灵感 2：校验离散码而非连续值——把噪声吸收进判定粒度

- **核心思想**：当合法变异（跨平台噪声）与非法操纵在连续空间不可分时，把校验对象离散化到「胞径 > 噪声、胞界模糊由校验者判定」的粒度，比较即退化为精确匹配。
- **论文证据**：粗胞吸收浮点噪声：三平台最小全收守卫带 ≤ 实测跨设备偏差；PQ/二值几乎无需守卫。
- **推广场景**：(1) 分布式系统的幂等判定（把浮点指标离散成档位）；(2) 竞技体育的电子判罚粒度；(3) 版本指纹/模糊哈希的档位设计；(4) 传感器网络的异常检测阈值离散化；(5) 合同条款的「实质相似」判定改为枚举差异类型。

### 灵感 3：判定权与改写权留在校验侧——消除对手的剩余选择自由度

- **核心思想**：只要流程中存在「两种都合法、由对方选」的自由度，就存在被利用的缝隙；把模糊判定权收归校验者、接受后一律按校验者版本改写，缝隙归零。
- **论文证据**：无规范化残余 0-0.16%（发布者选邻码），规范化后 0；执行攻击 60/60 被拦。
- **推广场景**：(1) 数据入库的默认值填充权（不给提交者留默认值选择）；(2) API 的响应规范化层（服务端改写而非信任客户端格式）；(3) 法律文本的「以备案版本为准」；(4) 编译器的 canonical form 输出（比较 AST 而非源码排版）；(5) 供应链的「验收即重封」（收货后按自己的标准重新封装标识）。

### 灵感 4：签名绑定的是身份不是语义——工件内部一致性需要独立机制

- **核心思想**：签名/溯源体系回答「谁」，不回答「内容各部分是否如声明的那样互相对应」；任何多部分工件（文本+向量、模型+卡片、代码+文档）都需要显式的内部绑定校验。
- **论文证据**：有效签名的投毒包通过全部签名/哈希/日志检查；OWASP 建议审计但未规定绑定方法。
- **推广场景**：(1) ML 模型+README 声明指标的复现校验；(2) 数据集+数据字典的模式校验；(3) 固件+ changelog 的一致性；(4) 药品包装+批记录；(5) 学术论文+数据/代码可用性声明（repo 与结论一致性）。

### 灵感 5：确定性是安全属性——不可复现的计算无法被精确校验

- **核心思想**：「同样输入同样输出」从工程便利升级为安全前提：凡校验依赖重算，重算的逐位可复现性就是信任链的一环；跨平台部署要选择或构造可复现栈（整数-only、pinned 核）。
- **论文证据**：FP32/FP16/动态 INT8 全部随批或架构变化（10⁻⁷ 到 0.03）；V3 因此对常见栈不可用。
- **推广场景**：(1) 可验证计算与审计日志的复现要求；(2) 监管报送的数值可复现性（巴塞尔/风控模型验证）；(3) 科学的计算可复现危机；(4) 电子证据的取证哈希链；(5) 多人协作系统的冲突消解（确定性合并算法）。

### 灵感 6：暴露度测量应成为部署前的常规步骤——像压测一样测攻击面

- **核心思想**：论文示范的流程——取生产语料与真实查询日志 → 算边际分布 → 读出任意候选容差的暴露率 → 决定接受/换方案——可标准化为任何系统的上线检查项。
- **论文证据**：五语料边际中位 2.1-7.4°、ArguAna 5% <0.02°——不同语料暴露差一个数量级，「安全性取决于语料而非容差本身」。
- **推广场景**:(1) 风控规则上线前的边际分布分析；(2) 推荐系统对操纵排名的暴露测量；(3) 搜索引擎 SEO 攻击面的量化；(4) 搜索广告位的竞价边际；(5) 密码策略的熵分布审计（而非仅平均强度）。

### B. 术语备忘

- **margin law**：容差 τ 下的最优攻击者劫持率 = 角边际分布 P(m(q) < arccos τ)；可从诚实向量+查询日志离线计算。
- **文本-向量完整性鸿沟**：签名证明发布者身份、不证明向量编码其文本的空白。
- **V0-V4**：不校验 / 仅签名 / 容差重算 / 逐位精确（需可复现计算）/ 码级校验（校验者判模糊+守卫带+规范化）。
- **规范化（canonicalisation）**：接受模糊条目后改写为校验者自己的码，清零发布者选择权。
- **守卫带 ε**：舍入边界邻域宽度，按发布者↔校验者平台实测浮点偏差校准。
- **动态 INT8 参考阈值**：0.9040（25.3°）——本文「现实容差」的代表性上界，用于展示量级而非推荐配置。
