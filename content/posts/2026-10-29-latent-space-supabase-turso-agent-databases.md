## 先说结论

这是 Latent Space 对 Supabase 两位联合创始人 Paul Copplestone（CEO）与 Ant Wilson 的专访（依据英文转写整理，全部 39 段、0s–4598s 已完整读取；主持人 swyx 开场即声明利益相关——他是六年前 Supabase 种子轮的天使投资人，Supabase 也是该播客的第一个赞助商）。两位创始人此前从未同台接受过采访。整场对话围绕 Supabase Select 2026 客户大会的「Build / Operate / Scale」三大主题展开，但真正的线索只有一条：**数据库的下一个用户不是人，是 agent**——平台当前每月新建约 500 万个数据库，嘉宾判断这个数字将走向「每月数十亿」，为此他们发布了无超时的长时计算、重写的 Postgres 存储引擎与高可用层，并买下 Turso 来做「一个想法一个数据库」的小实例。与之配套的是一组反直觉的增长数据：模型变强后注册量暴涨，而通常会被稀释的激活率与付费转化率反而同步上升——因为从注册到激活这一步现在由 agent 一步完成。矛盾也在这条线上：PLG 收入天花板原本被两位创始人估算在 1–2 亿美元，AI 直接把天花板掀到了未知处；而 OLTP 数据库迁移「几乎从不发生」，所以 Supabase 的企业策略不是赢得迁移，而是赢得 day one。这与本站 9 月 24 日云栖大会「为 Agent 重构数据库」专场复盘中阿里云给出的判断互为印证：数据库的设计前提，正在因为用户从人变成 Agent 而整体改写。

## 一、Select 2026 发布了什么：给 Agent 造的三层楼

第一层是计算。Supabase 现有的 Edge Functions 基于 Deno 运行时、有两秒的执行上限，社区长期想跑分块（chunking）、嵌入（embedding）这类长任务跑不了。新发布的 Supabase Compute 是无超时、serverless 的完整容器计算，与数据库跑在同一私有网络、物理同位，可以直接建立 Postgres 连接，Rust、Python、乃至 agent 本身都能塞进去——Paul 类比它是「容器版的 Lambda」[360–480s]。

第二层是纵向扩展，两个数据库内核级项目同日发布公开测试版。OrioleDB 是 Postgres 传统 heap 存储引擎的 drop-in 替换，嘉宾称快 1.5–2 倍、彻底消除 vacuum 与表膨胀，过去一年被拿去跑了 PGRegress 全量兼容、Antithesis、TPC-C 每夜基准与 Jepsen 一致性测试，并转为附带专利授权的 Apache 2 许可——Supabase 收购了这项技术、买下专利后免费开放[480–600s]。Multigres 则是对标 Vitess 的「Postgres 版分片方案」，请来了 Vitess 原作者 Sugu 主导。他们的出发点是一个扎眼的发现：**Postgres 生态里所有 operator 在特定条件下都可能丢数据**，于是干脆从零重写整个集群管理层；嘉宾称已通过上千次顺序故障切换测试且零丢数据，完全开源，平台上先以邀请制提供。与 Vitess 时代最大的不同是「先做兼容、后做分片」——分片能力预计明年初落地，届时用户不需要改任何查询[480–720s]。

第三层最重：收购 Turso，横向扩展。嘉宾给出的算术很直白——每月新建 500 万个数据库已是常态，而如果 ChatGPT（节目称月活 12 亿）这类入口让每个用户、每个 agent、每个想法都配一个数据库，就必须做到每月数十亿个，「给每人一个专用 Postgres 集群，全世界的物理计算机很快不够用」[720–960s, 3360–3480s]。Turso 用 Rust 从头重写了 SQLite（因许可证问题 fork 为 libSQL），为单写者的 SQLite 补上了 MVCC 多写能力，用无盘、WAL 写 S3 的架构在一台服务器上跑数百万个库。Paul 特别指出，这条路之所以现在走得通，是因为对象存储的新特性——S3 的强一致性、S3 Express 一到两毫秒的写入——正在让对象存储变成「数据库底下的那个集群」；Turso 创始人 Glauber Costa 的重写博客则给出了通往 Postgres 兼容的路径[840–960s]。收购后 Turso 品牌保留、专注 SQLite，Supabase 将推出兼容全部自家库的小型实例 **Supabase Spark**：任何想法先开一个 Spark，跑起来后零停机升级到完整 Postgres，再一路升到 Multigres[960–1080s]。算力层面，Supabase 同时宣布引入新投资方 CapitalG，嘉宾坦言需要 GCP 与多云——算力短缺之下「我们和 AWS 谈了很多次，付更多钱、做更多承诺」[1560–1680s]。（本站查证补充：官方新闻稿称此轮融资 1.5 亿美元、GIC 领投，Turso 收购同日宣布，Glauber Costa 加入后任 Head of Agentic Services；播客内只提到 CapitalG 一家。）

## 二、增长机器：从 8 个用户到「被所有前沿模型推荐」

Supabase 的冷启动如今已成创业教材：他们本来准备了 Hacker News 上线，却被一个随机用户抢先发帖，帖子冲上 HN 史上最高赞之一。关键转折是把标语从没人理睬的「realtime Postgres」改成「open source Firebase alternative」——12 小时后爆帖，用户从 8 个涨到 800 个。当时每个数据库要吃掉 DigitalOcean 两台 5 美元 droplet，1 万美元信用点 48 小时烧光；进了 YC 后 AWS 给了 15 万美元信用点，他们在 YC 第一周手工迁移了 800 个库。DigitalOcean 因为「已用过小额信用点计划」拒绝批给他们 30 万美元额度的大计划——嘉宾笑称这可能是 DO「因过于严格而损失的最大客户」，而 DO 如今市值 160 亿美元[1320–1560s]。

增长手段则几乎是反营销的：meme。Ant 团队每周开 meme workshop、雇了一小组青少年帮忙，因为「要既懂技术又懂开发者觉得什么好笑，这种人很难招」；曾有人写了四万字的 Supabase 推特策略拆解发上 HN，被社区骂，Ant 把骂声截图发回自家推特——「你的恨意滋养我」[1080–1320s]。

真正的爆发来自 Ant 总结的「AI 三部曲」：第一部是 embedding 时代，靠 Andrew Kane 独立开发的 pgvector 扩展教育市场「存向量不需要再买一个数据库」；第二部是 2024 年底的 vibe coding 浪潮（Lovable、Bolt），团队曾激烈辩论要不要服务这些「玩具项目」，最终被「存储世界的数据」这个使命说服——「在你起步时在场，确保你永远不想离开」；第三部就是今年：模型变强后注册量陡增，而反常识的是，**通常消费级流量涌入会拉低激活与付费转化，这次两者却同步上升**——因为注册到激活由 agent 一步完成、摩擦消失，且这批用户的付费转化率高于传统开发者，而公司几乎没有营销预算[1800–2040s]。变现也在加速：过去是做完产品再接计费，现在 Stripe 在 agentic 层直接可用，嘉宾看到有客户同周内产生可观现金流、上线几天赚一万美元——正是那个案例让他们确认 vibe coding 不是 NFT 式的一阵风[1680–1800s]。客户画像随之改变：教师出身的 Magic School 创始人、没有技术联创也没有 CTO 的公司越来越多，「人人都是 builder」[960–1080s]。

swyx 用自己的 AEO 追踪器补上了最关键的一环：**每一个前沿模型都把 Supabase 推荐为 integrated backend 的首选**。嘉宾把这归因于运气加卡位——在 LLM 起飞前三四年就以「Firebase 的头号开源替代」存在，社区六年积累的博客、YouTube、Discord 问答、开源代码全部被模型吸收，「我们只是需要维持这个领先」[2040–2160s]。社区资产也被正式资本化：为了让社区参与融资，律师说没有合格投资者机制不行，他们反问「如果不投资、直接送股票呢」——最终划出 100 万美元股票赠予社区成员，第一位是 Discord 里六年回答了两万个问题（其中 1.3 万个在一小时内回答）的退休传奇用户 Gary Abbott[2160–2280s]。开源版本则刻意不埋任何追踪——他们不知道开源市占率，但有大药企主动找上门说「我们跑着你们开源项目的 100 个实例，能卖我们个产品吗」，于是把面向 AI 平台公司的 Supabase for Platforms（2025 年 12 月上线）重新打包成企业舰队管理产品 Control Tower[2400–2520s]。

## 三、销售与迁移：被掀翻的 PLG 天花板，与从不发生的迁移

Supabase 以 PLG 著称——嘉宾称每届 YC 批次 60% 的公司在用，榜样是 Stripe（「唯一顶住十年上移市场还保住开发者爱的开发者工具」）。但他们的销售层值得所有 SaaS 公司抄作业：每周约 1000 个产品触发（扩容、报错、消费阈值、重点 logo）触发外联，约 500 人回应；**不回应的那 500 人天然构成对照组，月环比增长 25%；被销售「上电话帮忙」过的账户月增 125%——多出来的 100 个百分点就是销售提成的唯一依据**。销售的任务不是推销，而是拿着 AI 根据用户流量模式生成的脚本去帮人解决问题[2520–2640s]。

迁移则是整场访谈里最冷酷的判断：OLTP 生产数据库的迁移「几乎从不发生」，因为每一分钟停机都是直接收入损失、双库并行又带来 split-brain（脑裂）风险；历史上所有以迁移为主业的数据库公司都失败了。所以策略是「day one 落地、day 一万留住」，企业市场的 greenfield（企业内部产品团队人手起一套新栈）反而是最肥的新场景。Multigres 留给未来想搬 Oracle 的巨兽——节目引用称一年前 Oracle 按收入只有 5% 的负载在云上；一位董事会成员（转写名不清晰）的论点是 Supabase 不只替代 Firebase，更是「新 RDS」、终局去掀 Oracle 的桌。嘉宾的回应很克制：当然会试，但先聚焦进入企业[2640–3000s]。被问到 Databricks 两位联创（本播客此前专访的 Matei 与 Reynold）宣称解决 HTAP 时，Paul 表示更看好 DuckDB/Duck Lake 路线（「分析界的 Postgres」；嘉宾并称 DuckDB Labs 近期被 AWS 收购——此说法本文未核实），但立场是 OLTP 到一定规模必须分片、分析用对的工具分开做，「把两者硬捏在一起未必有意义」[3000–3240s]。

战略层面最坦率的一句话是关于天花板的：创业时他们以为 PLG 能做到 1 亿美元、最多 2 亿美元就要换打法，「因为 AI，天花板被掀掉了，我们不知道掀到了哪里——是 10 亿还是 20 亿」。年初 offsite 定下的「疯狂野心」收入目标，有人担心团队会因达不到而失望，结果四个月就完成了[3360–3480s]。当前 P0 是赢得各家前沿实验室与模型伙伴（已合作 Gemini、支持 Sign in with ChatGPT，希望成为 ChatGPT 应用分发的默认后端之一）、继续 PLG、以及拿下企业新负载；Temporal 式持久工作流也因 2 秒超时的解除而解锁——此前社区想在 Supabase Functions 上建工作流引擎全部失败[3240–3360s]。

## 四、代码优先，与两个焦虑

给 agent 的最后一块拼图是开发体验的范式转移：Supabase 从 dashboard 公司走到 headless，今年的重心是 code-first、Git 原生。传统 Postgres 工作流是 migrations 文件夹——每次变更追加一个文件的「历史日志」，agent 面对上千个迁移文件只能重编译或起库内省才能猜出当前表结构，太慢。新发布的 PG Delta 库让 schemas 文件夹成为数据库的**完全声明式状态**（表、策略、注释全在文件里），「agent 主要在代码上操作，它们不想外呼任何东西」[3480–3720s]。Paul 的愿景推到极致：对手机上的个人 agent 说「我要做 X」，一秒后应用上线——不再需要是工程师。

两个焦虑也都值得记录。Ant 担心 **mode collapse**：软件行业的进步靠 flame war 维持多样性、让最优解胜出，如果 agent 让所有人变懒、全部收敛到一种「正确的」构建方式（「他们全都会用 Supabase，太棒了，但是……」），行业可能锁死在局部最优。Paul 认为恐惧有效但不可控：低门槛的 casual builders 会收敛到均值（也就是模型推荐的那一家），高技术的人会继续抠细节并向下渗透；他顺带下了个暴论——「平均水平的大学可能完了」，顶尖自学者永远有出路[3720–3840s]。第二个焦虑关于开源本身：嘉宾认为 Rust 重写浪潮是真实机制，大多数开源工具会塌缩成少数 Rust 赢家，连 Postgres 若被重写也只会剩一个 Rust fork 胜出；Vercel 的 Malte Ubl 提议留一笔钱把所有依赖的 C/C++ 层重写成 Rust、相当于「开源世界的一次性升级」——Paul 说 100% 支持，但预测不会发生，因为人们爱自己动手[4080–4320s]。

AI 内政数据也少见地透明：公司去中心化到各团队自定 AI 编码政策，最近才开始围绕成本收拢。swyx 给出的市场锚点是普通人每月 20 美元、平均员工 200 美元、OpenAI 五十分位员工 3000–5000 美元、顶尖者数十万美元；Paul 给出的度量是 **token 花费与人力成本之比——多数公司 0.1，可以安全升到 1，超过 1.5 大概率有麻烦**。Supabase 自身是每月 30 万美元、450 人，分布极度偏斜（两三个重度用户贡献大头）；公司内部有使用排行榜，上榜者会有点羞愧——swyx 立刻反驳说焦点错了，该看的是端到端解决了多少流程、把多少长周期人工问题压短，而不是花了多少钱。作为全异步公司，Supabase 把一切决策都记录在案，如今正拿这些语料构建「公司 harness」，让 AI 把整段公司史沉淀成决策原则[4200–4440s]。招聘上约 50 个开放岗位、全球远程同薪，最缺 SRE——swyx 断言 AI SRE 至今是 agent 创业最难攻克的类别，Paul 认同：「造软件勉强算解决了，让东西一直跑着完全是另一头怪兽」[4440–4598s]。

## 行业机制与读者启发

把账本串起来，至少四条链值得带走：

1. **「每 agent 一库」的经济学重写数据库行业**。变化：模型变强→注册即激活（agent 代劳）→非技术 builder 涌入→建库量从 500 万/月冲向数十亿/月。机制：专用 Postgres 集群的物理成本不可扩展，文件型数据库（SQLite 重写 + WAL-on-S3）+ 小实例（Spark）+ 零停机升级路径成为唯一解。二阶影响：数据库的计价单位从「公司」塌缩到「想法」，对象存储的新特性变成数据库内核的地基。观察指标：ChatGPT 等入口是否默认给每个 artifact 配库、Spark 与 Multigres 分片（嘉宾称明年初）的落地、Supabase 月建库数与 attach rate。启发：基础设施的胜负手正在从功能清单变成「入口的默认选项」——被模型推荐就是新的分发渠道。
2. **AEO 是提前三四年埋下的复利**。机制：开源+社区内容（博客/视频/问答/GitHub as CMS）全部可被抓取→被前沿模型固化为「标准答案」→agent 生成的代码自动选择你→增长自我强化，营销预算近乎归零。启发：agent 时代的内容策略是「让模型读得到」，封闭社区与私有文档等于放弃分发；后来者（如节目提到的 Resend）只能靠 AEO 实践追赶。
3. **不可迁移性是数据库最深的护城河**。OLTP 迁移的停机成本与脑裂风险让「赢得迁移」近乎伪命题，可行战略是「赢得 day one」并陪伴到 day 一万；企业 greenfield（内部人人开发）取代迁移成为新单来源。启发：评估任何数据库/基础软件公司时，与其看迁移工具，不如看它在「新建项目第一分钟」的占有率——Supabase 用 60% YC 批次渗透率与产品触发式销售（对照组增量 100 个百分点作提成基准）把这件事做成了可复制的机器。
4. **AI 编码开销有了可用的预算锚**。token 花费:人力成本比 0.1→1 为安全区、>1.5 预警；且分布极偏，管理少数重度用户优于全员限额。配合「看端到端流程解决量而非支出」的视角，这套口径可直接搬进任何团队的 AI 政策讨论。
