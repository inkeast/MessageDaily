> **嘉宾**：张阔（阿里国际站总裁） · **主持**：硅谷101主持人
> **转写说明**：文中 Accio（转写多误作 Excel Work / Xu Work / Axure）、Claude Cowork（误作 Cloud Co Work）、CoCreate Pitch（误作 Peach）、长程（误作长城）、帕累托（误作帕洛特/帕累特）、OpenRouter/Fireworks（连读）等均已按上下文校正。

## 先说结论

这期节目回答了一个很多AI用户的共同困惑：每次新模型发布榜单都在刷新，为什么工作体感没跟上？张阔的答案很直接——**通用智能分数与垂直业务完成率之间"其实没有那么大相关性"**，而弥合这个落差的方法不是等更强的模型，是换一把尺子再加一套工程。他的团队把阿里国际站上百万量级的真实经营数据提炼成107个端到端电商任务，开源为 CommerceAgentBench；目前最强的前沿模型在完全无人干预下通过率只有61.7%（张阔在《财富》中文网署名文章中披露）。与之配套的是"Agent = 模型 × 执行框架（Harness）× 上下文（Context）"的乘法公式——任何一项为零则整体为零——通过任务分层路由和小模型后训练，Accio 跑完全量107个任务的预估成本为3.69美元，约为同期 OpenAI Codex（9.27美元）和 Anthropic Claude Code（9.51美元）的四成（亿邦动力，2026年9月）。一句话：**当模型成为大宗商品，竞争轴心从"谁的分高"转向"谁用最低成本把事做完"，而"用得起的AI才是有价值的AI"**。

## 一、107个任务：给"模型变强"装上水位计

节目最有信息量的部分，是张阔对"榜单通胀"的过程性描述。他说模型发布频次快到"在硅谷待一个礼拜，光个人助理就发了好几个"，每个新模型都宣称全方位变好、榜单冲到99分之后还在小数点后进步，但团队"日常使用时又没有感觉到像说的这么好"。coding、数学这些通用 agentic 能力的得分，与"电商领域里能完成更多工作"之间相关性有限——通用智能变好确实能提高一些任务的通过率，"但大家没有把本质的水位每一个发布的模型时拉得那么大"。

于是他们自建了尺子。据环球网、亿邦动力对 CoCreate 峰会的报道，CommerceAgentBench 的数据底座来自 Accio 上1000万活跃中小企业用户、160万条真实对话与20万条执行轨迹，提炼为107项端到端任务、七大类商业场景。张阔在节目里举了三个例子，能看出这套测试的"毒辣"之处：

- **供应商比价**：从大量商家回复的报价单（quotation）中选出最合适的一家，报价里除了产品、工艺、价格，还要算清含税到手价、物流方案，而且测试会**故意掺入几封钓鱼邮件**——识别不出有害信息、算错任何一环，任务即失败；
- **订舱**：给定交期和起讫点，在船公司网站上真实订到一条船，订不上就是 fail；
- **纠纷裁决**：基于买家对卖家的投诉判断赔还是不赔、现有信息够不够下结论。

这套测试按**最终状态**评分，用张阔在《财富》中文网署名文章里的话说，"如果仅凭输出的文字来评判AI智能体，无异于只靠笔试成绩考核飞行员，却不检验他们能否驾驶飞机平稳着陆"。任务还按L1到L4划分自主等级——越长程、越开放，能通过的模型越少。张阔还提到一个工程细节：bench 是"此时此刻的快照"，团队持续把更复杂的问题加进去，因为模型和 Agent 迭代一段时间后要"避免腐化"——原来能跑通的 case 变差是不可接受的结果，所以每个版本都要重新跑 evals。这其实是把软件回归测试的思路搬进了 Agent 时代。

对"刚发布的模型到底行不行"这类问题，张阔的回答是"过两天直接去我们 bench 上看评分"——单一能力突破（他泛指某些模型在单项能力上的进展）不等于通用商业 agentic 能力强，"你说他是AGI，我现在给你打保票的，肯定不是AGI"。

## 二、乘法公式：成本压到四成的秘密

如果说 bench 是尺子，那降本就是打法。张阔自述的公式是 Agent = Model × Harness × Context，并特意解释为什么是乘法：**"哪一项是零，整个公式结果就是零"**。三块的投入节奏并不平均：起步阶段 harness 花精力最多——连接工具、管理记忆、做好用户授权，因为电商天生是连续数月不停执行的长程任务；context 则是平台型玩家的祖传优势，二十多年沉淀的供应商对话、行业属性、平台趋势都是上下文；而现在是三者齐头并进，尤其模型侧"不是用一个通用 frontier 模型简单做做 FT（微调）就行"，要基于一定尺寸的模型做后训练，且"模型和 harness 要在一起优化"。

一个关键实证：**用千问最新版小尺寸模型做后训练，效果已经非常接近 frontier 顶级模型**。这意味着大量简单任务可以路由给小模型快速出结果，复杂任务才调用昂贵模型，由产品层基于帕累托最优曲线统一路由。三重省钱机制叠加——任务分层路由、集约采购比个人用模型便宜、同模型下更优的 harness 工程与 context 管理提高效率——最终得到那个成本数字：107个任务全量跑完，Accio 3.69美元 vs Codex 9.27美元、Claude Code 9.51美元（亿邦动力报道的峰会数据；张阔在节目中粗略表述为"三分之一"，精确计算约为四成）。

这个数字的商业含义比技术含义更大。张阔反复强调，商家侧产品是日常经营天天用的，"必须是一个用得起的AI，才是一个有价值的AI"——不是解一道数学难题用一次就扔。他还观察到商家抱怨"贵"的两种典型：对特定任务觉得贵，或者固定用最贵的模型解决所有问题，所以 Accio 的建议是直接选 Auto 模式，让系统按帕累托最优分配。对照美国市场，他点出一类正在变得受欢迎的生意——类似 OpenRouter、Fireworks 这样托管大量模型、按任务优化路由的公司——因为"每一段时间都有一个更好的开源模型出现"，模型商品化让路由层在相当长时间内都有优化空间。这与 Codex、Claude Code 这类 Agent 与自家模型绑定的产品形成了结构性差异：后者很难做跨模型路由。

## 三、为什么 Coding 先渗透、生意后跑通

节目前半段回答了另一个结构性问题：为什么 Agent 先吃掉写代码，商务场景却"刚刚开始"。张阔估计 coding 渗透率高达99%——"很难看到身边有一个研发人员不用任何AI写代码"——而第二个垂直赛道的渗透远小于此。原因有二：**代码百分之百数字化**，全部躺在 GitHub 和代码库里供模型广泛学习；**代码天然可验证**，编译过没过、结果对不对一目了然。商业场景则相反：数据多元、没有通用流程、不同企业对"经营结果好坏"的判断标准各异，且验证闭环不以单次计，而以天、周、月甚至年计。

这个框架还能解释 SaaS 与 AI 的关系。去年美国 SaaS 恐慌性抛售时，张阔的判断是"用得好AI的SaaS反而是利好"，这次他给出了机制解释：SaaS 与工作流集成紧密，掌握企业上下文——他借用了流行词 **ontology（本体论）**——"你就算请一个大学生来，搞不清楚这个企业各数据到底意味着什么，让这个人做事也很困难"。反过来，通用 AI 进企业也绕不开同样的问题：老板到底要优化毛利还是市场份额，预算、库存、广告的花法完全不同。所以现在是"两边互相集成"的过程。至于 Harvey、OpenEvidence 这类跑得快的垂直 AI native 产品，他的解释很朴素："每一个时代都有这个时代的公司"，技术转折点上新公司对技术理解更好、对领域理解更深，速度就更快，就像移动互联网时代有移动互联网时代的产品。

中美差异也被这个框架消化了：美国 SaaS 垂直成熟（CRM、法律、医疗各有体系），中国则是平台侧大量垂直整合功能，AI 进来时带着不同的惯性。但有一个反常识的观察——**AI 产品第一天就是全球化的**。语言问题天生不存在，交互门槛因 LUI（语言界面）大幅降低，Accio 从最早服务海外买家到现在中国企业用得更多（供给侧 Enterprise 版本中国公司多），一个产品同时服务全球，这在过去 1688 与 Alibaba.com 分平台运营二十几年的格局下是不可想象的。张阔称之为"AI Agent 时代一个新的产品设计范式"，前提是需求本身的最大公约数接近——电商符合，流程环境差异巨大的领域仍需分区域重做。

对"云端 Agent"的热话题，他的拆解同样去魅：上云是 basic 需求，"今天你说你没上云，那就是你功能还没做完"，PC 版发布几天后就有云端了。真正值得定义的是**长程任务的三种形态**——每天出报告的定时任务、跟单这类事件驱动任务、以季度为周期的整盘生意复盘。至于追求模型7×24跑一个礼拜不挂？"它不挂 means nothing，如果没有解决你的问题的话。"

## 四、人守住的三个按钮

聊到人机分工，张阔拒绝按"环节"切分，主张按**频次**和**决策权重**切分。必须留给人的按钮至少有三个：**支付采购**（terms 都生成好了，但按下采购键的人要对经营结果负责）、**产品品味**（idea 靠不靠谱、解的是不是真问题、目标客群基数够不够大愿不愿付溢价）、**经营节奏**（同样一笔预算，更多广告还是更多库存、铺渠道还是保毛利——这是经营者对当下市场的直觉判断）。AI 可以做全部的市场分析和调研进对，但"最终这个商业判断还是人去做"。

有意思的是用户行为的演化数据。Accio 内部把任务按七大类×L1-L4难度管理，从发布第一天到今天的截图显示：**任务难度在持续从简单推向复杂**——开始是"我问你答"的L1，慢慢变成"教给你任务帮我做完"，再到"教给你与经营最终判断相关的任务"。商家每隔一段时间就会 push 产品解决更复杂的问题、交付更多任务、交出更多经营数据。

具体到日常场景，张阔（他2011-2016年在淘系做商家平台，自称当时觉得商家后台"已经做得比较极致"，如今站在AI视角发现经营方法灵活得多）举了三个高频用例：**多平台经营利润表**——抖音、淘系、京东、多多同时开店，"流水进来不代表有利润"，要跨平台拉投入、收益、退换货数据形成完整报表，以前人工多平台切换整理Excel"最终还不一定算对"，现在任何时间节点都能给出实时结论；**多平台商品发布**——每个平台规则、受众、内容形式都有差别，稍具规模的商家"发布一个商品光 update 一遍就是很大的事情"，AI 做完可以放草稿箱人工确认或授权直发；**客服质检与预警**——以前开经营会一条条复盘谁答对谁答错，现在 AI 能全量分析什么回答更好、哪个 To B 客户的交易"中间出了什么问题这个单子可能要黄了"，提前预警。

面对"多个 Agent 建议冲突怎么办"的追问，他的回答坦率：不同 Agent 给不同建议"非常正常"，不存在一个统一 Agent 调和所有意见的产品初衷——老板要回到自己的经营目标（以毛利为结果还是以规模、速度为结果）去判断哪条建议合理。"这次交易就算成功了，它可能最终导致你商业失败，那它也不是一个好的交易。"

## 五、中小企业放大器：一场一万五千人的大会

节目结尾落在洛杉矶 CoCreate 大会上。张阔说最惊讶的是"来的人太多了"：注册到场约一万五千人（环球网、新浪财经报道均为15000名美国中小企业主），登记摊位排到中午还没消化完。他觉得美国用户群体对 AI 与 Agent 的教育领先，"或多或少对产品理念本身是接受和理解的"。

两个 CoCreate Pitch（类似《赢在美国》的创业赛）冠军案例被用来收束整期主题：英国冠军是个15岁的初中生，用 Accio 找供应商做自动降温毛巾、宠物降温产品，已形成系列，年销售额约一百万英镑；美国冠军 Christian Reed——出场穿着很"工地化"，后来发现是 MIT 毕业——做数字测量设备，从 idea 到供应链全程基于 Alibaba.com 和 Accio，客户包括施耐德电气和 SpaceX，今年生意做到几千万美金以上（Reed 获 CoCreate Pitch 美国区总冠军、奖金20万美元已获 Retail TouchPoints 等外部报道证实；具体客户与营收为嘉宾陈述）。张阔的落点：中小企业的核心问题从来不是"AI 取不取代工作"，而是**没有那么多资源和经验，又想把生意做大、用上全球供应链**——AI 恰好是这个缺口的放大器。

这也回到了他对商业 AGI 的定义，也许是整期节目最值得抄录的一段话：**"给定一定的边界——你的 budget、你的供应链是一样的情况下——这个 Agent 的产品经营，一定比一个人去做日常的这些操作和判断能赚到更多的钱，那就是这个商业领域里边的 AGI。"** 不谈通用智能的哲学定义，只谈同一约束下的经营结果对比。

## 观察指标与读者启发

把整期内容压缩成可跟踪、可迁移的几条：

- **判断AI进步，看端到端完成率而非榜单分**：通用 benchmark 与垂直任务完成率相关性弱，61.7%这个数字意味着近四成任务仍会出错——规模化落地时"哪些场景可以自动化、哪些环节需要人工同步监督"要用 evals 持续回答（证据层级：张阔《财富》署名文章+峰会多来源报道）。
- **成本公式正在改写竞争格局**：模型商品化（尤其高性价比开源模型）让价值向 harness（工程、路由、缓存）和 context（私有数据、行业知识）转移——张阔自述为推断+峰会数据佐证；个人选型上的对应动作是别"用最贵的模型解决所有问题"，Auto/路由模式是趋势。
- **可验证性决定渗透速度**：99%渗透的 coding（全数字化+天然可验证）与刚起步的商务 Agent（多元数据+长反馈闭环）之间，隔着的是验证结构，不是模型智力——这是分析任何"AI 能不能吃下某个行业"的通用透镜（嘉宾框架，逻辑自洽）。
- **产品全球化的门槛被 LUI 拉平**：AI 产品第一天即可全球分发，前提是需求最大公约数接近；这一条同时解释了为什么 Accio 能合并过去 1688 与 Alibaba.com 二十几年分治的用户群。
- **接下来盯三个信号**：GPT-6 Astra 等新模型在 CommerceAgentBench 上的开源评分（张阔明言"过两天直接去 bench 上看"）、107个任务数量的增长（bench 是活的标准）、以及小模型后训练逼近 frontier 效果的幅度——三者共同决定"用得起的AI"什么时候在更多垂直领域成立。
