# 一、论文背景

## 1.1 什么是 OPD（On-Policy Distillation，在策略蒸馏）

想象学下棋有两种方式：一种是**实战演戏**——自己下完整盘棋，最后只知道赢没赢（强化学习）；另一种是**请家教**——看高手棋谱模仿（监督微调）。OPD 相当于请了一位**天才教练坐在你旁边**：你自己落子（学生生成 rollout），教练对你走的**每一步**都打分（冻结教师模型对每个 token 给出概率分布），你据此修正。

形式化地说：学生模型 πθ 对每个 prompt 自己生成回答，冻结的教师 πT 在学生的每条轨迹上给出逐 token 的分布监督，训练目标是最小化两者间的**反向 KL 散度**（reverse KL）。它由 GKD（Agarwal et al., ICLR 2024, [arXiv:2306.13649](https://arxiv.org/abs/2306.13649)）与 MiniLLM（Gu et al., ICLR 2024, [arXiv:2306.08543](https://arxiv.org/abs/2306.08543)）奠基——反向 KL 是 mode-seeking 的：学生集中学好教师分布的高概率模式，而不是勉强覆盖长尾。

## 1.2 什么是 GRPO

GRPO（Group Relative Policy Optimization，DeepSeekMath 提出，[arXiv:2402.03300](https://arxiv.org/abs/2402.03300)）是当前推理模型后训练的主流 RL 方法：对一个 prompt 采样一组（如 8 条）回答，按结果奖励（数学答案对/错、代码通过/不通过）做组内归一化得到优势值，再用策略梯度更新。它的信号是**稀疏的**——每条轨迹只有一个 0/1 标量奖励，不告诉你错在哪一步。

## 1.3 争端：密集信号是否真的更"省"

OPD 的直觉卖点非常硬：GRPO 只有一个 bit 的结果反馈，OPD 每个 token 都有教师的完整分布反馈（O(N) bits/episode vs O(1)）。Thinking Machines Lab 2025 年 10 月的博客（[On-Policy Distillation](https://thinkingmachines.ai/blog/on-policy-distillation/)）声称 OPD 比 RL 少 7-10 倍梯度步数、换算为 50-100 倍计算效率，轰动一时。

**但问题在于**：教师对每个训练 token 都要做一次前向传播，回答越长开销越大。"更少的 rollout 数或优化器步数"不等于"更少的 FLOPs"。而且 GPU-hours、wall-clock 这类指标纠缠了框架实现与硬件差异，**FLOPs 才是实现无关的计算度量**。本文 Appendix A 做了一次 406 篇 OPD 论文的 LLM 辅助审计（每篇由 Claude Opus 4.8 全文阅读并要求逐字段附 PDF 原文引用）：406 篇 → 170 篇强到弱设置（教师不小于学生且是独立模型）→ 70 篇真正跑了 GRPO baseline → 3 篇声称 OPD 更省算力 → **0 篇用 FLOPs 度量**。这三篇幸存者（REOPOLD、Near-Policy、f-OPD）全部只报 GPU-hours 或 wall-clock。这就是本文要填的坑。

一句话：**第一个以 FLOPs 为统一度量、对 strong-to-weak OPD vs GRPO 做系统性受控对比的工作**，并进一步回答"什么条件下蒸馏真正省算力"——答案是教师来源（provenance）决定一切，以及蒸馏的正确角色是"多专家合并器"而非"RL 替代品"。

# 三、问题定义

## 3.1 从具体到抽象

具体问题：给同一个学生基座（如 Qwen3-4B-Base）和同一批训练数据，用 OPD 还是 GRPO 能以更少的训练 FLOPs 达到相同的 held-out 精度？

抽象问题：**在统一计算记账下，逐 token 密集监督（O(N) bits/episode）与轨迹级稀疏奖励（O(1) bit/episode）相比，每 FLOP 的学习效率是否更高？** 这剥离了框架、硬件、数据格式的干扰，只剩"监督密度 × 每信号单价"两个本质变量。

## 3.2 两个目标的精确定义

**GRPO 目标**（沿 Liu et al. 2025 公式化）：对 prompt q 采样一组 G 条 rollout {o_i}，二值结果奖励 {r_i} ∈ {0,1}，组内减均值得优势值，最大化优势加权的对数似然：

```
L_GRPO(θ) = -E_q,{o_i}[ (1/G) Σ_i Â_i/|o_i| · Σ_t log πθ(o_{i,t} | q, o_{i,<t}) ]
其中 Â_i = r_i - mean({r_j})
```

**OPD 目标**（vanilla reverse-KL，闭式 top-k 估计）：在每个位置 (i,t) 取学生 top-k token 集 S_k（k=16），学生与教师概率都重归一化到该集合上，再精确计算反向 KL。结果奖励 r_i **完全不进入** OPD 损失——这是与 GRPO 的本质对照点。

```
L_OPD(θ) = E_q,{o_i}[ (1/G) Σ_i Σ_t Σ_{v∈S_k} π̃θ(v) · (log π̃θ(v) - log π̃T(v)) ]
```

## 3.3 FLOPs 记账（问题的公平性基石）

设 Ns、Nt 为学生/教师参与矩阵乘的参数量。前向 2 FLOPs/参数/token，前向+反向 6 FLOPs/参数/token。学生每个生成 token 被用三次：

| 方法 | 每生成 token 成本 | 构成 |
|------|-----------------|------|
| GRPO | f = **10·Ns** | 生成 2Ns + log-prob 重算 2Ns + 策略更新 6Ns |
| OPD | f = **10·Ns + 2·Nt** | 同上 + 冻结教师前向 2Nt |

只计生成 token，不含共享的 prompt 前缀。这个记账让"OPD 步数少但每步贵"与"GRPO 步数多但每步便宜"第一次可以公平比较。

## 3.4 问题空间的关键变量

- **教师 provenance**：外部开箱即用 thinking 模型 / 再 GRPO 训练过的 thinking 模型 / GRPO 训练过的 base 模型 / **学生自己的 GRPO checkpoint（self-GRPO）**
- **任务域**：数学（DAPO-Math-17K、DeepMath-103k）、代码（LiveCodeBench v1–v5、CodeForces 精选）、指令遵循（IFBench-RLVR）、知识（MMLU-Pro 5-shot）
- **难度分层**：按学生/教师的 mean@32 解出率对数据集做二维分层
- **九个优化轴**：学习率、batch size、KL 估计器、思考模式、学生初始化（Base/SFT 冷启动）、学生尺寸（1.7B/4B/8B）、训练域、RL 框架（verl 两个版本 + tinker）、rollout 组大小 G

# 四、问题解法

## 4.1 实验框架

**共享超参**（GRPO 与 OPD 完全一致，保证公平）：

| 设置 | 值 |
|------|-----|
| 框架 | verl 0.7.0.dev（自研 fork）+ SGLang 0.5.2 rollout |
| rollout 组大小 G | 8 rollouts/prompt |
| batch size | 64 prompts |
| 响应上限 | 7168 tokens（除另有标注） |
| rollout 采样 | temperature=1.0, top-p=1.0, top-k 关闭 |
| 优化器 | Adam（β1=0.9, β2=0.95, ε=1e-8），lr 2e-6 恒定无 warmup，200 步 |
| 精度/硬件 | bf16 rollout + fp32 优化器，FSDP，单节点 8×H200 |
| KL-to-reference | 双方均关闭（谁也不用为参考策略前向买单） |

- **GRPO 侧**：二值结果奖励（数学精确匹配/代码沙箱通过）、DAPO 式非对称 clip [0.8, 1.28]、token-mean 聚合、单 epoch 更新
- **OPD 侧**：教师 temperature 1.0、学生 top-16 支撑集上的闭式反向 KL（重归一化后精确计算，不采样）、结果奖励不进入损失
- **学生**：Qwen3-1.7B/4B/8B-Base 为主，外加 Olmo-3-7B-Instruct-SFT（跨家族）与 Qwen3.5-9B（tinker 复现）
- **评估**：mean@16；数学 OOD macro = AIME24(30题) + AIME25(30题) + AMC23(83题) 非加权平均；代码 LCBv6(175题)；每 20 步评一次，画"held-out 精度 vs 累计训练 FLOPs"曲线

## 4.2 发现一：外部教师 OPD 全面落败

**基线对比**：Qwen3-1.7B-Base 学生 + 外部 Qwen3-4B/8B/32B thinking 教师，DAPO-Math-17K。GRPO 在每个评估 FLOP 点上都高于每条 OPD 曲线，而 OPD 花了 **1.4-4.7 倍**算力。更大的教师只把 OPD 曲线右移（更贵），不抬高学生性能。

**难度分层手术**（最有说服力的实验设计）：把 DAPO-Math-17K 按学生（=0 / >0）×教师（=0, (0,0.3], (0.3,0.6], >0.6）的 mean@32 解出率切成 8 个 cell，每个 cell 重训。理论上最有利于 OPD 的 cell 是"学生 mean@32=0 且教师>0.6"——此时 GRPO 的结果奖励几乎没有正信号，密集监督应该价值最大。**结果：GRPO 在全部 8 个 cell 的 in-domain 都赢**，且教师越强 GRPO 领先越大。

**意外的 OOD 侧写**：OOD 上 OPD 反而在教师最弱的 3 个 cell（教师=0 列 + 学生=0且教师∈(0,0.3]）峰值超过 GRPO；OPD 的 OOD 几乎恒定在 15%-18%（与训练子集无关），GRPO 则随数据从 11.9% 波动到 20.5%——OPD 从外部教师学到的东西部分**与训练 prompt 无关**，更像学到了教师的"通用行为"。附录 F 给出第二个证据：只用代码训练的 OPD 学生数学 OOD 达 33.3%（LCBv1-v5）/33.9%（CodeForces），比代码训练的 GRPO（20.7%/24.8%）高约 10 个点——跨域迁移是外部教师 OPD 的隐藏福利，但代价是 in-domain 崩溃。

**九轴消融全部不改排序**：
- 学习率五档扫描：最优 GRPO 18.9% OOD @7.8 EFLOP vs 最优 OPD-4B 18.4% @14.3 EFLOP（1.8 倍算力换更低分）；GRPO 对 lr 更敏感但最佳配置仍胜
- batch size {64/128/256}：小 batch 对两者都好，阶梯平行
- KL 估计器（闭式 top-k vs 采样单 token）：曲线几乎重合，不是估计器的锅
- 思考模式：think 对 GRPO 只伤 2.1 点，对 OPD-4B/32B 伤 8.2/7.7 点（长思维链放大分布失配）
- SFT 冷启动（OpenThoughts-3，扫过 SFT lr）：不改变排序；4B-SFT 起点已 51.0% OOD，GRPO 继续升到 57.7%，两个 OPD 教师（含生成 OpenThoughts 的 QwQ-32B）反而**跌到 36%**，低于起点
- 学生尺寸 4B/8B：外部教师在所有尺寸都不达教师精度
- 训练域：代码上差距更夸张——GRPO 46.4% LCBv6 @0.6 EFLOP，OPD-32B 峰值仅 28.7% @68.7 EFLOP（114 倍算力差）
- 框架：verl 新旧版本、tinker（Qwen3.5-9B，40 步：GRPO AIME24 mean@8 = 0.542 vs OPD 崩到 0.013，98.75% 的 OPD rollout 打满 16384 上限）全部复现同一排序
- **唯一例外**：G=1（每 prompt 单 rollout，8 倍优化器步数）让外部教师 OPD 在**单域数学**上反超 GRPO（4B 学生 47.7%、8B 学生 50.6%）——但在代码上无效（停在 32%-36%），在 4 域混合上直接崩溃（数学 18.9%→7.2%→37.7%→**0.3%**）

## 4.3 发现二：self-GRPO 教师，50 倍效率的来源

固定学生 Qwen3-4B-Base，扫三类教师（各 4B/8B/14B）：

| 教师类型 | 结果 |
|---------|------|
| GRPO 训练的 base 模型 | 学生 ≤2.5 EFLOP 即收敛到窄带（35.8%/34.5%/33.0%）；**同尺寸 4B 教师 1.62 EFLOP 完整恢复其 33.9%（GRPO 自己要 10.1 EFLOP，约 6 倍）；G=1 时仅 0.2 EFLOP（50 倍）**；更大的 8B/14B 教师学生反而停在略低处——教师的多余能力不迁移 |
| 外部 thinking 模型 | 爬升慢：8B 教师峰值 34.2% @27.2 EFLOP，全部远低于教师自身 |
| 再 GRPO 训练的 thinking 模型 | 最不稳定：4B 教师学生第 80 步冲到 38.7%（贴着最优 GRPO 的 38.8%）后**崩到 26.0%**；8B 教师学生跌回 6.6%（低于初始化） |

**可预测性诊断**：沿用 Li et al. (2026) 的初始 top-16 overlap（首个训练 batch 上，学生 top-16 token 出现在教师 top-16 的比例）。14 个 OPD run 的回归显示 overlap 与"归一化最小师生差距"负相关（斜率 -4.68，R²=0.85）——overlap 越高，学生越能逼近教师。但作者诚实标注：4B 与 8B 的 GRPO 教师点之间存在数据空洞，这只是固定学生下的侧面分析，不是普适规律。

**长度膨胀病理**（Appendix E，机制分析的关键证据）：
- 外部 thinking 教师（哪怕与学生同为 4B）：学生响应长度第 9 步就冲过 7000 token，第 19 步起 100% 打满 7168 上限；OOD 评估中学生均值 28-30K token，**教师自己只有 12-13K**——学生比要模仿的教师长 2.3-2.6 倍，这是分布发散而非长度匹配
- self-GRPO 教师：学生终长 3741 vs GRPO 的 3813——**完全无膨胀**，停止行为几乎完美迁移
- 终态病理表（step 200，500 rollouts）：外部教师学生的中位响应 = 30720（评估上限），97.8% 打满上限，63.6% 检出短周期重复环，49.0% 丢失 \boxed{} 格式；GRPO 与 self-GRPO-OPD 在所有指标相差 <2 个点
- 多域混合下外部教师还出现**语言崩塌**：英文 prompt 下 100% 的 rollout 前 2K 字符含中文（GRPO 与 MOPD 均为 0%）

**跨设置复制**（Appendix G）：8B 学生（约 3 EFLOP @G=8 / 1 EFLOP @G=1 恢复教师 40.1%，GRPO 需 27.9 EFLOP）；代码域（self-GRPO 教师 47.3% LCBv6 @0.25 EFLOP，反超 GRPO 的 46.4%）；跨家族 Olmo-3-7B-Instruct-SFT（**56 倍**更少 FLOPs 恢复教师 40.0%，且学生继续涨到 **51.2%，反超教师 11 个绝对点**——作者承认原因未知，留作开放问题）。

**诚实的悖论**：单域上 GRPO checkpoint 本身就是你想要的模型，再蒸馏回 base 学生纯属额外开销——50 倍只算蒸馏阶段，没算训练 checkpoint 的钱。这就引出发现三。

## 4.4 发现三：多教师 OPD——蒸馏的真正用武之地

数学和代码各自 GRPO 训出的专家，任何一个 checkpoint 都不能同时服务两个域。**多教师 OPD（MOPD）**：fresh 的 Qwen3-4B-Base 学生，每条训练实例路由到其所属域的 self-GRPO 专家教师计算反向 KL。

| 设置 | 专家训练成本 | 蒸馏追加 | 占比 | 对比联合 GRPO |
|------|------------|---------|------|--------------|
| 2 域（math+code） | 10.7 EFLOP | +0.55 EFLOP | **5.2%** | 两阶段总账省 **42.0%** FLOPs 达到同等性能 |
| 4 域（+IFBench+MMLU-Pro） | 14.4 EFLOP | +1.15 EFLOP | **8.0%** | 省 31.6%；且联合 GRPO 在测试预算内**根本达不到**合并学生的水平 |

- 联合 GRPO 两种变体（instance-mix 每批跨域采样 / batch-mix 每批单域）都输给 MOPD
- 单一外部 8B 教师在 2 域还能撑（26.7%），4 域直接崩盘：0% 数学、0% 代码、7% MMLU-Pro、18% IFBench——尽管它是全场最强模型
- MOPD 学生的响应长度保持在各专家基准的 0.93-1.19 倍（IFBench 除外，1.65-2.25 倍）；外部教师学生膨胀 3.98-37.05 倍；联合 GRPO 的长度被批内其他域拖拽（2 域 mix 中代码被数学拖到 3.64 倍）
- G=1 比 G=8 省得多（数学：0.2 vs 1.6 EFLOP 到顶；GRPO 专家要 10 EFLOP）

这正好解释了前沿实践：DeepSeek-V4 先训 10+ 个领域专家再用 MOPD 收拢；Kimi K3 更进一步训了 **9 个教师**（3 域 × low/high/max 三档推理努力），每 token 从对应教师收 clipped log-ratio 奖励。这些报告都把 MOPD 当工程选择，本文首次给出 matched-FLOPs 的理性依据。

## 4.5 机制根源：为什么外部教师"不可达"

Appendix H 借用谱继承分析（Zhu et al. 2026, [arXiv:2607.19331](https://arxiv.org/abs/2607.19331) 的 ISO 工作）：对每个权重矩阵做 SVD，在 base 模型的奇异框架下度量位移 ΔW = W1 - WB 的三个谱标量。

| 对（base ↔ W1） | κspec（谱位移） | ρΣ | 结论 |
|----------------|---------------|-----|------|
| 4B-Base ↔ 外部 Qwen3-4B | **3571** | 15.5% | 教师离 base 三个数量级远 |
| 4B-Base ↔ GRPO 训练的 4B-Base | **2.81** | 6.3% | RLVR 更新几乎等谱 |
| 4B-Base ↔ OPD 学生（外部教师，中期/末期） | 3.16 / 3.42 | — | **OPD 学生的谱停在 RLVR 范围** |
| 8B-Base ↔ 外部 Qwen3-8B | 2077 | 15.5% | 同样三个数量级 |

**因果链**（论文实验支持的部分）：GRPO/OPD 都在学生自己的 rollout 上做策略梯度类更新 → 这类 RLVR 幅度的更新每单位算力只能小幅移动权重谱（κspec≈1-3）→ 外部 thinking 教师的谱离 base 约 2000-3600 → 要匹配它需要 SFT 量级的谱移动，OPD 的梯度方向产生不了 → **外部教师在任何现实算力预算下权重空间不可达**；而 self-GRPO 教师就坐在同一个 RLVR 范围里，少量步数即可到达。这与 top-16 overlap 诊断（4.3 节）、长度膨胀病理（外部教师信号把学生拉向一个它结构上到不了的方向，途中丢失停止行为）形成三重互证。作者对谱解释的措辞是"a plausible mechanism"——标注为合理假设而非定论。

## 4.6 评估指标体系与数据集明细

### 指标体系

| 层级 | 指标 | 定义 | 衡量什么 |
|------|------|------|---------|
| 主指标 | **精度 vs 累计训练 FLOPs 曲线** | 每 20 步评估 mean@16，横轴为该时刻累计 FLOPs | 每 FLOP 的学习效率——论文全部核心主张都落在这条曲线上 |
| 主指标精度定义 | mean@16 | 每 prompt 独立采样 16 次、取平均精度 | 生成式方法的方差鲁棒度量，比单次贪心解码更公平 |
| 辅助指标 | 初始 top-16 overlap | 首个训练 batch 上学生 top-16 token 出现在教师 top-16 的比例 | 蒸馏前预测"教师可达性"的廉价诊断 |
| 辅助指标 | 归一化最小师生差距 | (T - s*) / (T - s0)，s* 为训练中任一点的最佳学生精度 | 量化"OPD 到底把学生带多接近教师" |
| 消融指标 | 响应长度分布 | 训练/评估逐 step 的均值长度、打满上限比例 | 捕捉长度膨胀这一隐性 FLOPs 开销与病态行为 |
| 消融指标 | 谱标量 κspec/ρΣ/δΣ | base 模型 SVD 框架下分解权重位移 | 教师在权重空间是否"可达"的机制度量 |
| 病理度量 | 重复环/CJK 崩塌/\boxed{} 缺失率 | 朴素窗口检测 + 前 2K 字符中文占比 + 格式抽取失败率 | 外部教师 OPD 的定性失败模式 |

### 数据集与基准

| 用途 | 数据集 | 规模 | 说明 |
|------|--------|------|------|
| 数学训练 | DAPO-Math-17K | 17K 题 | 主训练集；可按 mean@32 切 8 个难度 cell |
| 数学训练 | DeepMath-103k | 103K 题 | Thinking Machines Lab 博客同款，换数据不改排序（GRPO 领先反而从 7.7 扩到 11.5 点） |
| 数学 OOD 评估 | AIME24 + AIME25 + AMC23 | 30+30+83 题 | 非加权 macro，与训练数据隔离 |
| 代码训练 | LiveCodeBench v1-v5 / CodeForces 精选 | / 1207 题 | CodeForces 从 6594 题库严格筛 1213 题全测试集完备的，再删 6 道泄露例题 |
| 代码评估 | LCBv6 | 175 题 | 版本隔离防污染 |
| 指令遵循 | IFBench-RLVR | 94,873 prompts | 可编程验证约束，奖励 = 全约束满足则 1 否则 0 |
| 知识 | MMLU-Pro 5-shot | 11,904 题（留 512 评估） | 二值字母匹配奖励 |

### 为什么这套设计能证明论点

三个设计选择决定了证明力：(1) **matched-FLOPs 曲线**而非终点精度比——它把"更快"定义为曲线上每一点的优势，杜绝"跑更久追上"的辩护；(2) **难度分层手术**直接命中 OPD 最强的理论卖点（学生解不出时密集信号最有价值），在该 cell 依然输掉意味着卖点被证伪而非未测；(3) **九轴单变量消融 + 三框架复现**排除了"配置不好/实现不好"的辩护路径——每条 OPD 失败曲线都对应一组翻了某个轴的对照。加上审计文献的 406→0 漏斗，论文同时证明了"没人做过这件事"和"这件事做完是这样的"。

# 五、必要知识反推

假设让一个零基础的人重做这项研究，最少需要哪些知识？

**领域知识层**
- LLM 后训练全景：预训练/SFT/RLVR 的分工；thinking 模式 vs no-think 的解码差异
- GRPO 的组相对优势机制与 verl/SGLang 训练栈（含 DAPO 式非对称 clip、token-mean 损失聚合）
- 反向 KL vs 前向 KL 的 mode-seeking/mode-covering 数学（MiniLLM 一系）；闭式 top-k 估计器 vs k1 采样估计器的取舍

**方法论知识层**
- **FLOPs 记账方法学**——本文最大的方法论武器：前向 2、前+反向 6 FLOPs/参数/token 的单位成本模型，把所有方法折算到同一货币。没有它，一切"效率"声称都是各说各话
- 对照实验设计：难度分层（mean@32 双轴分层控制任务难度混淆）、单变量消融（九轴逐一翻转）、matched-FLOPs 曲线比较（而非终点精度比）
- 谱分析工具：SVD 框架下分解权重位移的 κspec/ρΣ/δΣ 三标量（借自 ISO 工作）；top-k overlap 诊断（借自 Li et al.）
- LLM 辅助文献审计：用 schema 强制的结构化抽取 + 双盲复读 + 逐字段 PDF 原文引用，把 406 篇文献的筛选变成可审计流程

**工程知识层**
- 8×H200 单节点的 FSDP 分片、bf16 rollout + fp32 优化器
- 评估协议细节：mean@16、因果截断 re-grade（截断到 token 前缀后用同一 verifier 重判，因为生成是因果的所以精确）、每域不同的响应上限（OPD 会打满上限，预算不同结论会翻转）
- 病理度量：短周期重复的朴素检测（响应[-200:-100] 的 100 字符窗口在别处出现 ≥3 次）、CJK 崩塌检测、长度分布统计

**知识融合的关键节点**
1. **"步数 ≠ FLOPs"的记账转换** + **"教师 per-token 前向要花钱"** → 发现所有前人效率声称的度量缺陷 → 设计统一 FLOPs 轴
2. **RLVR 谱继承现象** + **"外部教师是 SFT 后的产物"** → 三个数量级 κspec 落差 → OPD 不可达性的权重空间解释
3. **单域悖论**（"已有 checkpoint 为何还蒸馏"）+ **"多域专家互不兼容"** → 把 OPD 重新定位为合并器 → 与 DeepSeek-V4/Kimi K3 的工程实践闭环

# 六、论文中可以提取的通用性灵感

**灵感 1：效率声称必须绑定实现无关的度量单位**
核心思想：任何"A 比 B 省资源"的结论，若度量单位（GPU-hours/wall-clock/步数）与实现耦合，就不可跨论文比较；先统一记账再比。
论文证据：406 篇审计中 3 篇声称 OPD 更快，0 篇用 FLOPs；本文用 10Ns vs 10Ns+2Nt 的记账推翻/修正了全部三篇的语境。
推广场景：推理框架对比（tokens/s 要折算到同精度同硬件）、Agent 框架对比（把工具调用、上下文长度折算成统一成本）、模型压缩方法对比（蒸馏/剪枝/量化的"每比特精度成本"）。

**灵感 2：监督信号的价值 = 信号密度 × 接收方可达性**
核心思想：密集监督不是免费午餐——若监督源（教师）落在接收方（学生）结构上不可达的区域，再密的信号也只是噪声，甚至有害（长度爆炸、语言崩塌）。
论文证据：外部 32B 教师的逐 token 监督让学生在 68.7 EFLOP 只有 28.7%（code），谱距离三个数量级；self-GRPO 教师监督密度相同，0.2 EFLOP 即恢复。
推广场景：教育中"远超学生水平的名师"未必优于"略强于学生的助教"；代码评审中资深架构师的详尽意见对新人的边际价值；课程设计中的最近发展区（ZPD）理论。

**灵感 3：正确的角色分工——专才训练 + 通才合并**
核心思想：与其让一个模型联合学所有域（互相拖拽、超参互斥），不如每域独立训到顶，再用蒸馏做廉价合并层。
论文证据：2 域合并追加 5.2% FLOPs 即达专家上限，总账省 42%；联合 GRPO 在预算内达不到合并模型；各域最优超参本就不同（响应上限 3072-16384 不等）。
推广场景：多技能 Agent 的模块化训练（工具专家 + 规划专家 + 合并蒸馏）；多语言模型的分语种专家 + 合并；联邦学习中本地特化 + 中央聚合。

**灵感 4：诊断指标先行——花小钱预测大实验的成败**
核心思想：跑昂贵实验前，先用便宜的相关量（如首个 batch 的 top-16 overlap、权重谱距离）预判成功率。
论文证据：overlap 与归一化最小师生差距的 R²=0.85；κspec 三个数量级落差先验预测了所有外部教师的失败。
推广场景：微调前用表征相似性预测迁移学习收益；合并模型前用权重谱兼容性筛选候选；招聘中用工作样本测试替代简历筛选。

**灵感 5：警惕"单点结论的条件依赖"——同一方法换个舞台就反转**
核心思想：G=1 的外部教师 OPD 在单域数学反超 GRPO，换到代码即失效，换到多域直接崩溃——结论必须标注适用边界。
论文证据：Appendix I 的三段式检验（math 赢 → code 输 → 4 域崩到 0.3%）。
推广场景：推荐系统的离线指标上线反转；bench 过拟合的模型换评测集崩塌；任何消融实验都应报告"结论在哪些轴上翻转"。

**灵感 6：负面结果 + 文献审计 = 高价值研究选题**
核心思想：系统性地证明"某流行声称从未被正确度量过"，本身就是一等贡献，且天然引出填补空白的实验设计。
论文证据：Appendix A 的 406→0 漏斗既证明了动机的正当性，又精确定位了本文的文献坐标。
推广场景：审计某领域声称的可复现性缺口；用结构化 LLM 抽取做系统综述的新范式。

## 结语

这篇论文最值得尊敬的地方是它的**记账纪律**：不厌其烦地把教师来源、rollout 组大小、响应上限、每 FLOP 成本全部对齐，让"蒸馏 vs RL"这场吵了一年的架第一次有了同一张记分牌。答案分三层：外部教师的 OPD 是个昂贵的陷阱；self-GRPO 教师的 OPD 是廉价的重放；多教师 OPD 是把"专才训练"与"通才部署"焊接在一起的正确工具——DeepSeek 和 Kimi 已经用万亿参数模型投了票，Salesforce 补上了收据。
