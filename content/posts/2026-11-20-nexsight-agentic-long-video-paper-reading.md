## 一、论文背景

### 1.1 长视频理解难在哪：证据稀疏且散落

一段几小时的视频，真正与问题相关的证据往往只有几秒钟。比如"主角一共倒了几次咖啡""离开前有没有拿走桌上的手机""字幕里的网址是什么"——这类细粒度问题的答案散落在时间轴的角落里。传统做法是均匀采样：把固定帧预算（比如 64 帧）摊在几小时上，相当于每几分钟才看一眼，关键瞬间极易被跳过。

围绕这个瓶颈，过去两年长视频理解基准密集出现：[Video-MME](https://arxiv.org/abs/2405.21075)（900 视频/2700 题，覆盖短到长全时长）、LVBench（小时级极端长视频，约 1,549 题量级）、LongVideoBench、MLVU、EgoSchema、HourVideo 等。它们共同揭示了一个规律：视频越长，模型与人类的差距越大；而且不少模型在静态物体识别上接近满分，在动作计数、事件顺序等时序任务上接近随机。检索类的 V-NIAH（视觉大海捞针）测试进一步把"在小时级视频里找特定画面"变成了标准压力测试。

### 1.2 应运而生的主动观察范式

均匀采样是"被动感知"：不管问题是什么，都给模型同一套帧。而人类看视频是任务驱动的：先粗扫全局建立时间地图，再对可疑片段反复细看，必要时凑近看细节（比如读小字），最后整合证据作答。

把这种行为搬给模型，就是"主动观察 / agentic 视频理解"：模型自己决定**何时看时间轴的哪个窗口、看帧内哪个区域、何时停止搜索并作答**。VideoAgent、VideoTree、Active Video Perception（AVP）、T*、LongVT 等工作都属于这条线。其中 AVP 的迭代"计划-观察-反思"循环和 LongVT 的原生视频裁剪工具是代表性设计，DeepEyes 则在图像侧用强化学习激发了"边看边想"（thinking with images）的缩放检查能力。

### 1.3 论文指出的两个未解问题

这篇论文的切入点不是再造一个 agent 框架，而是指出该方向缺两块地基：

**第一，测不准。**评测 agentic 模型需要"答案正确且证据足以让任何人重构答案"的任务。但细粒度任务很多是全局主张：要证明"恰好发生了 3 次"，光有 3 段支持证据不够，还需要反例证据证明没有漏数、没有重复计数。现有 grounding 基准（NExT-GQA、CG-Bench）只关联稀疏支持帧，不足以验证全局主张；而看到草稿答案的验证者倾向于确认而非重构（确认偏差）。任务本身不可信，误差就无法归因：是没找到证据、用错了证据，还是题出错了？

**第二，教不会。**最终答案监督不指定"下一步看哪里"这类观察决策。论文给了一个刺眼的数字：指令微调后的 Qwen3.5-35B 允许它搜索时只有 28.06%，反而低于直接给 64 均匀帧的 33.23%——**工具在手，模型不会用**。要教会观察决策，需要真正逼着模型找证据的任务、可信到可以直接监督的答案，以及搜索过程本身的记录。

## 二、论文定位和关联工作

### 2.1 研究谱系一：固定输入的长视频评测

Video-MME、LongVideoBench、LVBench 评测多样化内容、长上下文指代推理与极端长视频；EgoSchema、HourVideo、MLVU 强调扩展时序推理与多任务；MVBench、Perception Test 提供技能级评测；TemporalBench、TempCompass 补充时序细节诊断。这条线的共同局限：模型被动接收固定帧输入，评测的是"给定这些帧你能答多好"，无法测量"你能不能自己找到该看的帧"。NexSight 的 SightLine 直接从 Video-MME Long 的 108 条视频出发构造全新任务（原题只用于去重防泄漏），算是站在最广泛使用的长视频基准肩上。

### 2.2 研究谱系二：主动 / agentic 视频理解

- **VideoAgent（Wang et al.）/ VideoTree / AVP**：迭代或查询自适应的视频观察，证明主动搜索在效率与精度上的潜力；但都是推理时框架，不训练模型，也没有验证任务本身的证据链。
- **T***：面向高效关键帧搜索；**LongVT**：全局预览+原生视频裁剪，配套 VideoSIAH 数据套件（247.9K SFT 样本）做三阶段训练，是最接近"既评测又训练"的同期工作，但其任务构造没有答案隐藏验证与反例检查这道关。
- **图像侧启发**：V* 引导视觉搜索、Visual CoT 区域监督、VLM-R3 交错区域选择与推理、DeepEyes 用 RL 激发缩放工具使用——SightLoop 的"局部 think-with-image"子代理直接沿用 DeepEyes 范式（裁剪/缩放/高亮/对比，且子代理用同一个被评测 VLM，资源计入账本）。

### 2.3 研究谱系三：证据接地评测与视频推理训练

- **NExT-GQA / CG-Bench**：把答案与支持帧/区间关联，回答"答案有没有视觉依据"；但如前所述，稀疏支持不等于全局主张可验证。
- **MINERVA** 诊断中间推理错误；**LongVidSearch** 评测多跳检索规划；**VideoGAIA** 研究工具增强的视频助手；**AgentVidBench** 用工具无关的证据里程碑评多跳推理；**TRACE / VES-Bench** 联合审计解码帧覆盖与答案正确性（覆盖排序与计数）——这是与 NexSight 观察级评测最相近的一支，区别在于 NexSight 把"任务构造验证、原始视频交互、观察级评测、后训练"四件事闭环在同一证据标准下。
- **训练侧**：ReXTime、VideoEspresso 构造视频推理监督；Video-R1、VideoRFT 结合监督数据与强化学习。论文 Table 1 的对照显示：此前几乎没有工作在"自己构造的数据上做训练实验"并全程记录实际解码帧。

### 2.4 定位总结

| 维度 | 之前的路线 | NexSight 的突破 |
|------|-----------|----------------|
| 任务可靠性 | 稀疏支持帧标注，不验证全局主张 | 答案隐藏验证 + 反例检查 + 独立评审，83.8% 人类保留率 |
| 评测粒度 | 只看答案或里程碑 | 实际解码帧 vs 标注证据的命中率（Rhit）联合答案准确率 |
| 评测接口 | 各自为政的私有工具链 | 共享 SightLoop harness，跨模型可复用，资源全记账 |
| 训练闭环 | 少数工作在自己数据上训练 | QA 监督 + 求解器轨迹步级监督，<6K 样本交互准确率翻倍 |

一句话定位：**NexSight 不是又一个 agent 框架，而是给整个方向补上"可验证的任务 + 观察级的尺子 + 对应的教材"这三件基础设施。**

## 三、问题定义

### 3.1 从具体场景到抽象问题

具体场景：模型面对一条小时级视频和一个细粒度问题，需要在预算内决定看哪、看多细、何时停。抽象后，论文把 agentic 长视频理解形式化为**任务条件化的观察选择**：

给定视频 V = {(x_t, t)}_{t∈[0,L]} 和问题 q，模型基于历史 h_k 选择观察动作 u_k，接收观察 o_k = O(V, u_k)（O 是冻结的视频访问协议），或在 judged 证据充分时输出答案并停止。目标：在预算 B 内获取并整合足够证据答对问题。

这里的精妙之处有二：

1. **搜索范围 ≠ 证据数量**：一个局部窗口可能足以验证已找到的答案，但定位它可能需要大范围时间探索——"找"和"验"是两种成本，任务设计必须区分。
2. **信息边界**：标准评测只暴露问题、视频元数据和访问接口；答案、标注证据位置、构造摘要全部隐藏。答案必须锚定在视频帧（含画面内文字）上，禁止依赖网页、标题、外部字幕或语音转写——否则测的就不是视觉取证。

### 3.2 核心洞察：验证本身是主动观察问题

这是全文的题眼。证明"某动作恰好发生 3 次"这类全局主张，需要：回到原视频、在主张所在处密集取证、在反例可能藏身之处搜索——这恰恰就是我们希望 agent 学会的那些观察决策。**从固定视角出发的标注流水线做不到这件事，agentic 流水线可以。**于是验证过的任务一鱼两吃：证据既证明参考答案可信（评测的尺子），又构成训练的靶场（在留出视频上逼出真正的找证据行为）。

类比：这就像考试命题——好考题不仅要答案正确，还要"反向可解"：一个没见过标准答案的阅卷人，只凭题目和参考材料应该能独立做出同样的答案。NexSight 把这个朴素原则工程化成了流水线。

## 四、问题解法

NexSight 由三个子系统加一个训练配方组成，形成"构造 → 评测 → 训练"闭环。

### 4.1 SightForge：验证式任务构造

类比：一条带"盲审 + 反例听证"的学术出版流程。五个阶段：

1. **全视频索引**：分层随机观察覆盖整条时间轴（72 段各取 1 帧随机抖动帧，组成 6 张 12 帧带时间戳的故事板），观察模型记录可见人物/动作/道具/场景变化/画面文字，确定性程序（不做自由改写）压缩成时间线摘要——保证候选生成不依赖固定均匀采样位置。
2. **候选生成**：基于时间线摘要提出"问题 + 草稿答案 + 结构化答案规范 + 证据/检索计划"，计划明确潜在反例位置。
3. **密集证据回采**：验证必须回到**原始视频**按任务类型密集取证：边界任务保留转变前后画面；计数任务覆盖完整计数范围并明确计数单位；身份任务保留跨窗身份锚点；文字任务检查相邻帧可读性。多帧"证据面板"（Evidence Panel）按时间序组装，保留局部变化与先后顺序。
4. **答案隐藏验证**：验证者在独立上下文中只看问题 + 回采证据作答，**看不到草稿答案与生成推理**，答案再与草稿比对。三维度检查：答案正确性（对照视频事实）、证据充分性（足以支持答案）、问题有效性（清晰、无歧义、可作答）。
5. **独立评审与反例检查**：人类盲审或独立实例化的 Codex 评审重构答案并提交证据；反例检查巡视相邻窗口与任务要求的更大范围——全局主张（计数、首末次出现）必须记录搜索范围。三道关全过才入池。

产出：370 个候选中 188 个直接通过、122 个微调措辞后保留、60 个被拒，最终 310 个任务，人类评审保留率 83.8%。

### 4.2 SightLine：六能力基准

310 个任务来自 108 条 Video-MME Long 视频（与原题严格去重防泄漏），总时长 74.12 小时，5 个内容域（艺术表演/影视/知识/生活/体育各约 60 题），1,080 个标注证据工件。六项细粒度能力：

| 能力 | 任务数 | 考什么 |
|------|--------|--------|
| 未定位事实检索 | 69 | 无时间戳提示找到特定事实 |
| 事件顺序 | 60 | 相隔遥远的事件谁先谁后 |
| 跨窗计数 | 32 | 跨时间窗计数且不重复不遗漏 |
| 身份追踪 | 45 | 遮挡与镜头切换下保持身份 |
| 状态/属性变化 | 54 | 识别状态何时、如何改变 |
| 时序边界定位 | 50 | 精确定位转变发生的时间点 |

### 4.3 SightLoop：多尺度主动观察 harness

灵感来自认知科学的任务驱动视觉（Hayhoe & Ballard）：人的眼动由当前任务决定看什么。SightLoop 把两类决策耦合进一个可回访的观察循环：

- **全局概览**：稀疏全片一瞥建立粗粒度场景与事件地图；
- **时间探索**：选择时间窗口细看，可请求更早/更晚/重叠区间；
- **局部 think-with-image**：图像推理子代理对抽出的帧做裁剪、缩放、高亮、区域对比（沿用 DeepEyes 范式），检查身份线索、手-物交互、小字等答案关键细节。视频 agent 选帧与检查问题，图像 agent 选局部操作，**子代理用同一个被评测 VLM，其调用、视觉输入、token 全部计入被评系统的资源账**——防止"把活外包给更强模型"的作弊空间；
- **回访与证据整合**：用累积观察更新解释、发现缺失证据、再选窗口或区域；可选结构化记忆（Ledger）跨轮保留观察摘要。

预算 B = (T_max, F_max, P_max, K_max) 显式约束交互轮数、实际观察帧数、像素分辨率与输入 token 上限；每轮记录动作参数、实际返回观察、时间戳与资源用量，形成**可重放轨迹**。这使"观察级评测"成为可能：不问你说你看了什么，而是核对实际解码帧。

### 4.4 评分：答案与证据命中率双轨

- 答案：冻结的 gpt-6-luna/high 语义评分器 + 每题答案规范（类型/单位/容差/别名），无效、缺失、未决输出一律 0 分，分母固定 310。
- 时间证据覆盖：帧命中率 R_hit——每题标注证据区间被实际解码帧命中的比例（点证据按 ±2 秒窗口计），再做基准宏平均。**答案准确率与 R_hit 联合诊断"取证失败"还是"用证失败"**——这是全篇分析的支点。

### 4.5 训练数据构造与 Sight-35B

评测/训练按原始视频源 ID 严格隔离（V_train ∩ V_test = ∅）。训练配方两条腿：

1. **静态 QA 监督**：2,623 条直接 QA 样本（433 个源组）。
2. **求解器轨迹步级监督**：deepseek-v4-flash-vision-exp/xhigh 作为求解器在训练任务上**从零解题**（不给参考答案与标注证据），收集 837 条轨迹；每次保留的主 agent 模型调用变成一条步级样本——交互历史为上下文、当前 assistant 输出为训练目标，**loss 只算当前目标轮**，历史轮/视觉输入/工具返回只作上下文；工具调用目标保留录制的文本、推理与动作参数。关键设计：**只过滤格式错误与执行失败的调用，不按最终答案对错过滤轨迹**——保留多样探索与纠错行为。共 3,315 条步级样本（2,499 工具步 + 816 作答步，356 个源组）。

合计 5,938 样本，对 Qwen3.5-35B-A3B-Base 微调 186 步（2 epoch，lr 2e-5 余弦退火，序列长 262,144，全局批 64，视觉编码器与投影器冻结），得到 Sight-35B。构造与被评测 VLM 的解题过程严格分离。

## 五、评估指标与实验证据

### 5.1 指标体系

| 层级 | 指标 | 定义 | 衡量什么 |
|------|------|------|----------|
| 主指标 | 总体准确率 | 正确数/310（无效计 0） | 端到端解题能力 |
| 诊断指标 | R_hit 帧命中率 | 解码帧时间戳与标注证据区间相交比例 | 时间定位/取证能力 |
| 诊断设置 | Evidence Oracle | 直接喂标注证据作答 | 剥离取证后的用证上限 |
| 对照设置 | Matched-budget | 等帧预算下固定/随机/agentic 选窗 | 孤立出时间选窗的贡献 |
| 资源指标 | 调用数/观察帧/token | 全程记账 | 效率与"多看是否多对" |

### 5.2 主结果一：SightLine 远未解决，取证是瓶颈

| 模型/配置 | 正确/310 | 准确率 |
|-----------|----------|--------|
| **GPT-5.6 Sol（Ledger Off）** | **169** | **54.52%** |
| GPT-5.6 Sol（Ledger On） | 165 | 53.23% |
| DeepSeek V4 Flash Vision（On） | 154 | 49.68% |
| Nex-N2.5-Mini（Off） | 133 | 42.90% |
| **Sight-35B（On）** | **131** | **42.26%** |
| GPT-5.6 Sol（Direct-128） | 135 | 43.55% |
| Qwen3.5-397B（Direct-128，其最佳） | 111 | 35.81% |
| Qwen3.5-35B-Inst（Direct-64） | 103 | 33.23% |
| Qwen3.5-35B-Inst（Agentic On） | 87 | 28.06% |
| Qwen3.5-35B-Base（Agentic On） | 66 | 21.29% |
| GPT-5.6 Sol（Evidence Oracle） | 246 | 79.35% |

三个关键读数：

1. **最强模型也只有 54.52%**，而同一模型拿到标注证据可达 79.35%（配对差 +26.13，CI [+19.68, +32.41]）——约 25 分的差距证明瓶颈主要在**取证**而非用证。象限分析：101 题只有 Oracle 做对（取证失败主导），44 题两者皆错，20 题反而只有主动探索做对。
2. **被动缩放仍有效但天花板低**：帧数 64→128 一致提升（GPT-5.6 +5.81、DeepSeek +5.16），说明固定输入远未饱和；但 397B 模型最佳成绩反而出现在 Direct-128 而非交互设置——大模型不会自动从工具中受益。
3. **Ledger 结构化记忆对 GPT-5.6 略有反效果**（53.23 vs 54.52），对多数模型则小幅正贡献——记忆结构并非万能。

### 5.3 主结果二：等预算对照——选窗使取证翻倍，答案提升有限

固定 128 帧槽位（32 概览帧 + 6 个 30 秒×16 帧窗口），禁用空间工具，只让窗口坐标变化（GPT-5.6 Sol，全部 310 题）：

| 条件 | 准确率 | R_hit 帧命中率 |
|------|--------|----------------|
| 固定窗口 | 36.13% | 19.84% |
| 随机窗口（3 种子均值） | 32.69% | 19.09% |
| Agentic 选窗 | 40.97% | 40.63% |

Agentic 对固定的命中率差 **+20.79 分（95% CI [+16.04, +25.60]，显著）**，但准确率差只有 **+4.84 分（CI [−0.96, +10.51]，不显著）**；对随机准确率差 +8.28（显著）。能力分解进一步显示：边界定位（6.0%→36.0%）与事实检索（34.78%→44.93%）显著受益，而跨窗计数、事件顺序、身份追踪与固定窗口持平甚至更低——**找到对的时刻还不够，跨窗整合是独立短板**。

### 5.4 主结果三：训练教会模型找证据

| 模型 | Direct-64 | Agentic（Ledger On） |
|------|-----------|----------------------|
| Qwen3.5-35B-Base | 25.81% | 21.29% |
| Qwen3.5-35B-Inst | 33.23% | 28.06% |
| **Sight-35B** | 28.39% | **42.26%** |

- **排名反转**：Inst 在被动 Direct-64 领先（33.23 vs 28.39），Sight-35B 在交互设置反超 14.19 分——被动 QA 与交互解题必须分开评测的铁证。
- 不到 6K 样本把交互准确率近乎翻倍（21.29%→42.26%），并超过同族 397B 模型的全部配置。
- **增益恰好落在选窗无能为力的能力上**：跨窗计数 15.62%→53.12%（+37.50）、状态变化 18.52%→53.70%（+35.19）、身份追踪 +26.67、事件顺序 +20.00，而事实检索仅 +1.45——步级轨迹监督补的正是跨窗整合课。
- **行为质变**：Sight-35B 训练后开始使用显式空间检查（0.72 次/轨迹），Base 模型从未使用（0.00）；帧提取调用 0.39→3.25 次。

### 5.5 主结果四：能力迁移到外部基准（Direct-64）

| 基准 | 题数 | 35B Base | Sight-35B | Δ |
|------|------|----------|-----------|---|
| Video-MME Long | 900 | 53.00% | 61.22% | +8.22 |
| — 训练不相交视频 | 600 | — | — | +9.33 |
| LVBench 子集 | 123 | 44.72% | 52.85% | +8.13 |

增益主要来自训练未见的视频（600 题中 +56 对 300 题中 +18），说明学到的是可泛化的取证行为而非记忆；Video-MME 上生成稳定性也大幅改善（有效输出 729→849/900），动作识别 +25.40、时序推理 +12.09。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**因果链 A：答案隐藏验证为什么能造出可信任务。**

- 对比对象：让验证者看着草稿答案打分（CoVe 论文已证明的确认偏差：看到草稿的验证者倾向于捍卫草稿而非重构事实）。
- 机制改变：NexSight 的验证者在独立上下文中只拿问题与回采证据独立作答——条件概率从 P(认可|草稿) 变成 P(重构=草稿|证据)，把"打分"变成了"盲审重做"。
- 证据：人类评审保留率 83.8%（60/370 被拒），反例检查专门针对漏数/重复计数/身份混淆/边界漂移四类错误设计；Oracle 实验得以把 25 分差距干净地归因于取证——**前提是参考答案与证据本身可信，归因才有意义**。【论文实验已支持】
- 推论（阅读者推测）：83.8% 的保留率也说明纯模型验证不足以独立把关，独立人审/Codex 评审这道关实质承担了相当比例的否决。

**因果链 B：为什么 agentic 选窗取证翻倍、答案不涨。**

- 机制：R_hit 只度量"解码帧时间戳与证据区间相交"，它不保证帧内细粒度信息被解析（论文自己在局限里承认），更不保证跨窗信息的整合（计数需去重、顺序需跨窗比较、身份需跨窗锚定）。
- 证据：命中率 +20.79 显著而准确率 +4.84 不显著；能力分解中整合型任务不升反平。【论文实验已支持】
- 这条链解释了为什么"更好的检索"（AVP 等推理时框架的强项）不能单独解决细粒度任务——整合是独立的失效模式，需要训练而非仅靠更好的选窗策略。【论文实验支持的机制 + 与 AVP 结论互补】

**因果链 C：为什么步级轨迹监督有效、且增益集中在整合型能力。**

- 对比对象：指令微调模型（Inst）——有工具反而降分（28.06 vs 33.23），说明"会用工具搜索"不是指令微调的副产品，需要显式监督。
- 机制改变：求解器轨迹把"下一步看哪、看什么、何时答"的决策序列变成 step 级模仿目标（loss 只在当前轮，历史/工具返回只作上下文）——相当于把观察决策从"隐性能力"变成"显式监督信号"。同时**不按最终对错过滤**，保留探索、回头、纠错等多样行为。
- 证据：交互 +20.97 分；增益最大恰是链 B 中选窗帮不上的跨窗计数/状态变化；空间检查从 0 次涌现为 0.72 次/轨迹；外部基准 +8 分且主要来自未见视频。【论文实验已支持】

**因果链 D：为什么 <6K 样本就够翻倍。**

- 机制（推测成分较高）：验证过的任务答案可信（错误答案会把模型教坏——监督信号噪声上界由构造质量控制）；步级样本天然是稠密的过程监督（一条轨迹产出 ~4 条样本）；上下文-目标分离使多轮历史成为免费的课程。对照同期 LongVT 用 247.9K SFT 样本做冷启动，NexSight 的数据效率暗示"质量×密度"可能比数量更关键，但论文未做数据规模消融，此解释属于合理猜测而非已证结论。【标注为推测】

### 6.3 综合判断与未决问题

**多项研究共同支持的机制**：(1) 隔离/答案隐藏验证优于可见草稿验证（CoVe 的文本结论 + 本文 83.8% 保留率的工程验证）；(2) 主动观察提升取证效率（AVP、本文等预算对照一致）；(3) 过程/步级监督优于纯结果监督（FACT、P2T、本文训练增益与能力分布三处独立证据）。

**仍属推测的机制**：小样本高效的原因（数据质量×过程密度 vs 未做规模消融）；"不按终局对错过滤轨迹"的净收益（P2T 的对照结论提示需要更细的步级质量筛选）；RL 能否替代/超越轨迹模仿（DeepEyes 同向但域不同，论文自认未做）。

**优势成立条件**：任务答案可由视觉证据重构（不依赖音频——论文明确排除跨模态验证）；预算与接口被诚实记账（子代理同模型否则失效）；评测与训练源严格隔离。

**可能失效条件**：证据面板存在系统性盲区时反例检查会漏（Rhit 只审时间维度，空间细节未度量）；被评测模型与构造模型同源时的自我确认风险（本文用 gpt-5.6 构造、也用其评测，虽有人审兜底但值得警惕）；交互预算极低时步级行为可能退化为死板的程序性模仿。

## 七、必要知识反推

假设一个完全没有背景的人要复现这项工作，他至少需要掌握：

**领域知识层**

- 长视频理解的失效模式：均匀采样为何漏证据、细粒度全局主张（计数/顺序）为何需要反例证据——不理解"证明恰好 N 次"与"证明发生过"的区别，就无法设计反例检查。
- 认知科学的任务驱动视觉（Hayhoe & Ballard 的眼动研究）：SightLoop 的设计直接以此为动机。
- 确认偏差与验证心理学：知道"看到草稿的验证者会顺从"，才会想到答案隐藏。

**方法论知识层**

- 评测构造方法论：grounding 基准（NExT-GQA/CG-Bench）的局限谱系，agentic 评测（AgentVidBench/TRACE）的记账原则——Table 1 的五维对照就是这层知识的浓缩。
- 多模态 agent 训练谱系：DeepEyes 的 think-with-image、LongVT 的三阶段、Video-R1 的 RL 路线——用于选择 SFT 轨迹模仿而非 RL 作为第一步。
- 步级损失设计：上下文-目标分离、多轮历史免费课程——与 FACT/Guava 等蒸馏工作同构的工程知识。

**工程知识层**

- 大规模 agentic 流水线编排：skill 协议、独立上下文验证器、人机混合评审队列、可重放轨迹记录、SHA-256 清单与复现性数据。
- 视频基础设施：故事板索引、密集证据面板组装、帧提取与 PTS 去重。
- 分布式微调工程：262K 序列长、冻结视觉塔的 35B MoE 微调配置。

**知识融合的关键节点**

1. **"验证 = 主动观察"的等式**（领域×方法论）：把认知科学的任务驱动视觉、CoVe 的隔离验证、agentic 工作流三个不相邻领域的知识在一点上融合——这是全文的创造性核心。
2. **双轨诊断**（方法论×工程）：把"答案准确率"与"帧命中率"两条独立测量管道焊在一起，才有了"取证 vs 用证"的归因语言。
3. **不过滤的轨迹蒸馏**（方法论）：意识到探索/纠错行为本身是教材而非噪声，与结果过滤的默认做法反着来——增益恰好落在整合型能力上验证了这个选择。

## 八、论文中可以提取的通用性灵感

**灵感 1：验证即生产——把验收环节变成产能。**

- 核心思想：一个系统最难的质量关（验证全局主张）如果本身需要稀缺能力（主动取证），那就让质量关顺便产出稀缺资源（可信任务与轨迹）——验证不是成本中心，而是数据飞轮。
- 论文证据：SightForge 验证流水线同时产出 310 个可信评测任务与 5,938 条训练样本；<6K 样本实现交互准确率翻倍。
- 推广场景：①代码智能体——用"测试通过+盲审重构"验证过的 bug 修复任务反哺训练；②内容审核——验证违规主张的取证过程本身成为审核员培训教材；③医疗报告质检——复核诊断的检查单生成结构化训练集；④科学发现——可复现性验证过程产出方法学课程数据。

**灵感 2：答案隐藏是所有验证器的默认姿势。**

- 核心思想：任何"让模型检查模型"的环节，只要被检对象可见，验证就退化为顺从；先重构、后比对，而非先看、后打分。
- 论文证据：验证者独立作答再与草稿比对 + 独立人审/Codex 评审，83.8% 保留率；CoVe 的 factored 变体一致性优势作为外部佐证。
- 推广场景：①AI 代码审查——评审模型不看作者注释独立重构需求再比对；②数据标注质检——盲审重构标注而非确认标注；③Agent 评估——裁判不见模型身份与彼此评分（本文评分器已践行）；④文档事实核查——按句重构事实而非按句打分。

**灵感 3：找得到 ≠ 用得好——能力诊断必须双轨。**

- 核心思想：复杂任务的"获取信息"与"整合信息"是两种可分离的能力，单指标会把两种失败混为一谈；给"资源命中率"与"最终正确率"各配一把尺，才能定位真正的短板。
- 论文证据：R_hit 翻倍（+20.79 显著）而准确率不动（+4.84 不显著）；训练增益恰好集中在此前不动的整合型能力上。
- 推广场景：①RAG 系统——检索命中率与答案质量分开报表；②推荐系统——曝光覆盖与转化分离诊断；③运维告警——信号捕获与根因分析双轨考核；④教育测评——资料查找与综合论述分项计分。

**灵感 4：过程教材不必按结果筛——探索与纠错本身就是课程。**

- 核心思想：轨迹数据的默认清洗方式（只保留成功轨迹）会删掉最有教学价值的片段：走错、回头、补证；把每一步决策变成独立监督目标，失败的轨迹里也有好步骤。
- 论文证据：步级转换只滤格式错误不滤终局对错，保留多样探索行为；837 条轨迹产出 3,315 条样本，交互准确率 +20.97。
- 推广场景：①客服 agent 训练——保留安抚失败但话术正确的片段；②游戏 AI——败局中的合理操作单独打分；③自动驾驶数据——未接管但值得学习的决策片段挖掘；④代码补全——编译失败提交中的正确局部编辑。

**灵感 5：把外包计入账本——评测的公平性靠资源记账维持。**

- 核心思想：开放工具接口的评测，作弊空间来自"未记账的外包"（更强的子模型、免费的外部知识）；让所有子代理、工具调用、像素、token 都进同一本账，分数才可比。
- 论文证据：图像子代理强制使用同一被评测 VLM，其调用/输入/token 全部计入预算 B=(T,F,P,K)；每轮记录形成可重放轨迹。
- 推广场景：①编程基准——限制并记账网络搜索与外部 API；②数学评测——计算器/搜索工具调用统一计量；3 多智能体系统评测——子 agent 成本合并归因；④云服务 SLA——跨组件资源账本统一核算。
