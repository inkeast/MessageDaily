## 一、论文背景

### 1.1 真实软件开发是"连续任务"，而主流评测是"孤立任务"

真实世界的编码 agent 面对的不是一个个孤立的 issue，而是同一个演化中仓库上**依次到来**的任务流：任务 T1 改了代码、留下仓库状态 S1；任务 T2 在 S1 之上继续，留下 S2……ChainSWE 基准（Jin et al., 2026）模拟的正是这种设定——每个任务继承前序任务的全部编辑，且**下一个任务是什么事先未知**。这与主流的 SWE-bench（每个 issue 独立、从干净 checkout 开始）形成鲜明对比。

在连续任务设定下，一个自然的想法是：任务 k 结束时写一份记忆 m = π_write(τ_k)，让任务 k+1 不必重新探索仓库。但"该记什么"在下一个任务未知时是个非常微妙的问题——你不知道下一个任务是修同一个 bug 的延续、还是完全无关的模块。

一个具体例子（论文 Figure 1）：任务 1 在 flake8-simplify 仓库修了一个 SIM102 规则的 bug，结束时写下 889 字符、18 个锚点的记忆；任务 2 是同一仓库更晚的一个 SIM102 修复——无记忆时要 13 步（ls、grep SIM102、cat 一路探索），有记忆时 9 步（第 1 步直接 `sed -n 34,58p rules/ast_if.py` 定位、第 6 步直接跑 `pytest -k sim102` 验证）。省下的正是"定位"和"找验证命令"这两段探索。

ChainSWE 的具体构造也值得一提：100 条任务链，每条链是一个真实仓库的 issue 序列，按链在共享工作区中依次解决；论文按仓库把链对半切成训练/测试两半（52/48 条链、97/96 个边界），保证没有任何仓库跨训练测试出现。测试边界还按"gold patch 与前序 patch 是否触碰相同文件"分成 linked（54 个，下一任务与记忆高度相关）与 unlinked（42 个，基本无关）两类——这个切分后面会反复用到：**一份好记忆必须在 linked 上赚回成本，在 unlinked 上不拖后腿**。

### 1.2 既有记忆方法在这个设定下集体失灵

论文做了一个非常扎心的动机实验（Figure 3）：在 ChainSWE 测试集上跑四种现有跨任务记忆形式，统计步数与 token（含记忆模块自身的开销）相对无记忆的变化：

- **Full history**（把此前任务轨迹整段注入）：27B 上步数 +7%、token +21%；
- **Mem0**（抽取事实记忆）：27B 上 token +113%（记忆模块本身比省下的还贵），resolve/token −52%；
- **MemOp**（同库 guidebook）：27B 上 token +57%，resolve/token −29%；
- **ReasoningBank**（跨库策略蒸馏）：27B 上 token +110%，resolve/token −43%。

**没有任何一种现有记忆形式能落进"步数与总 token 双降"的象限**。有的只是"买解决率"（resolve 涨了但更贵），每一种都在记忆模块上花的 token 比省下的还多。

### 1.3 为什么会失灵：设定错位 + 目标错位

论文指出两类根本错位（Figure 2 的四象限图非常清晰）：

1. **任务内压缩方法**（SWE-MeM、CompactionRL）：为当前任务压缩上下文，目标已知，任务结束什么都带不走；
2. **跨库经验方法**（ReasoningBank、SWE-Exp）：在独立任务间蒸馏泛化"洞察"，只有见解能带走，仓库状态带不走；
3. **MemOp 最接近**——同库跨任务 guidebook——但它的评测设定里**每个任务仓库重置**（reset 到 base commit + gold patch），所以它只能按"来源任务上的回放增益"来优化记忆设计。而重置恰恰把答案（gold patch）递给了下一个任务，且"对上一个任务有用"≠"对未知的下一个任务有用"。

这就引出 Challenge 1：**在下一任务未知时，什么信息值得跨任务边界携带？** 还有 Challenge 2：记忆的价值只有 actor 执行中真正用上才兑现——现有方法基本不动读记忆的模型本身，而 agent 的信息需求随任务展开而演化，任务开头检索一次远远不够。

## 二、论文定位和关联工作：agent 记忆的三条路线

把这篇论文放进 agent 记忆的版图（结合论文 §2 与附录 N 的相关工作梳理）：

| 路线 | 代表工作 | 记忆形式 | 记忆在哪被估值 | 与 CoReMem 的差异 |
|---|---|---|---|---|
| 任务内压缩 | SWE-MeM、CompactionRL | 上下文摘要 | 当前任务内部 | 任务结束即消亡，不跨边界 |
| 跨任务泛化经验 | ReasoningBank、SWE-Exp、Agent KB | 蒸馏的策略/教训 | 独立任务间 | 只有洞察跨库迁移，仓库状态不携带 |
| 同库 guidebook | MemOp（每任务重置仓库） | 每库指南 | **来源任务回放增益** | 重置把 gold patch 递了过去；按回放优化≠按下一任务价值优化 |
| 本文 | **CoReMem** | 锚点式记忆 | **未知下一任务的实测节省** | 仓库状态与记忆同时携带，成本内化到记忆设计与 actor 训练 |

其他相关支线：仓库上下文文件评测（AGENTS.md 研究发现加指令未必涨分还更贵）、部署侧的 Claude Code auto memory 与 Codex 跨会话记忆、记忆 RL 训练（Mem-α、Memory-R1 训 writer；ECHO、MemCalib 做信用定位）、记忆评测基准（LoCoMo、LongMemEval、VibeMemBench、MemDelta 强调写路径成本核算）。CoReMem 的独特站位是：**在"下一任务未知、仓库状态继承"这个部署中真实存在的边界上，用配对实验实测记忆的前瞻价值，并把测量结果同时喂给记忆设计和 actor 后训练**。

值得注意的一点诚实：CoReMem 的锚点设计（定位 + 验证）与 Agentless 的 validation/localization 两阶段遥相呼应——论文自己也点明了这层关系，等于说"便宜地解决 issue"这件事在记忆形态上找到了对应物。

## 三、问题定义："下一任务未知时记忆的前瞻价值"

### 3.1 形式化设定

单个持久工作区中，仓库被任务链 T1,…,TK 依次处理。任务 k 结束时留下：仓库状态 Sk（编辑过的代码树）与轨迹 τk（动作与观测记录）。在边界 bk = (Sk, τk, Tk+1) 处：**状态持久**（下一任务打开这一任务关上的树），**轨迹丢失**，记忆 m = π_write(τk)——任务 k 结束、Tk+1 下发之前写一次——是唯一跨边界的文本。

关键约束：因为仓库状态是继承的（不重置），**记忆无法在它自己的来源任务上检验**——来源任务的答案仓库里就装着。这就是与 MemOp 回放式估值最本质的区别。

### 3.2 学习目标

论文把问题拆成两层：

- **记忆形式**（记什么）：由 §3.1 的前瞻估值诱导；
- **actor 适配**：把 actor 参数从 θ0 调到 θ = θ0 + Δθ，使得在训练边界集合 B 上（式 1）：

min E_θ[n(τ)]  s.t. E_θ[res(τ)] ≥ E_θ0[res(τ)]

即**在解决率不低于基线 actor 的约束下，最小化下一任务的期望步数**。"成本内化"（cost-internalizing）的意思是：记忆在下一任务上引起的努力变化被**测量**，且测量值同时进入记忆保留什么（M1）与 actor 怎么被训练（M2/M3）两处。

### 3.3 前瞻价值的定义

记忆 m 在边界 b 的前瞻价值（式 2）：

**Δy(m|b) = E[y(m)] − E[y(∅)]**

其中 y 是下一任务 session 的某个结果量（是否解决、步数、actor token），期望对 actor 的采样取。估计用配对运行均值差 Δ̂y = ȳ(m) − ȳ(∅)；n 个候选记忆共享一个无记忆臂，2n 变 n+1 个臂，省算力。这个定义看似简单，却是全文的脊梁——**所有后续设计（片段估值、锚点、门控信用）都是这个量的不同用法**。

## 四、问题解法：三个模块

CoReMem = M1 前瞻片段估值（决定记什么）+ M2 成本内化 on-policy 估值 + M3 溯源门控价值信用（共同决定怎么用）。

### 4.1 M1：前瞻片段估值 → 锚点式记忆设计

三步走的系统流程：

**(a) 切片段**。把轨迹按角色切成七类片段：命令（commands）、读到的仓库内容（repo content）、测试输出（test output）、最终 diff（change）、推理文本（reasoning）、结果（outcome）、临时文件（scratch files）。切分完全机械——任何编码 agent 的记录天然就是这些部分（assistant 消息、命令、观测、diff、结局），不需要任何"什么重要"的先验。

**(b) 逐片估值**（式 3）。把整条轨迹 M = τk 整体作为记忆注入，然后逐片移除，测下一任务的中位步数变化 νc 与中位 token 变化 κc：

- 移除**命令**：+2 步（56/27 个边界变差/变好，BH 校正 p*=.0070）
- 移除**仓库内容**：+1 步（52/34，p*=.0302）
- 移除**推理文本**：0 步，还省 1.14K token
- 移除**diff 正文**：0 步，省 0.94K token
- 测试命令带退出码比完整测试输出多省 1 步（p*=.045）；diff 的文件清单≈完整 diff

**(c) 从价值到设计**。保留"移除会加步数"的片段、丢弃"只费 token"的片段。结论浓缩为一句话：**能省下一任务努力的是"去哪看"和"跑什么"，不是叙事**。论文把这些可执行的引用定义为**锚点（Definition 1）**：

- **位置 WHERE**：文件路径带行号/符号名，如 `rules/ast_if.py:34-58`；
- **检查 VERIFY**：可直接运行的命令或测试 id，如 `python -m pytest tests/ -k sim102`。

最终记忆模板分两块（任务块 TASK：FILES/STATUS+TESTS/VERIFY/DID+WHERE；仓库块 REPO：CONTEXT+WHERE），**至多 10 行 1200 字符**。一个真实例子（flake8-simplify 任务写的记忆）只有 889 字符、18 个锚点：

```text
FILES: flake8_simplify/rules/ast_if.py
STATUS: submitted | TESTS: python -m pytest tests/ -q [exit 0]
VERIFY: python -m pytest tests/ -k sim102 -q [exit 0] | COVERS: .../ast_if.py
DID: added is_main_check() to skip SIM102 when outer if is `__main__`
     | WHERE: flake8_simplify/rules/ast_if.py:34-58
CONTEXT: rules live in flake8_simplify/rules/*.py, one file per AST node type
         | WHERE: flake8_simplify/rules/ast_if.py
CONTEXT: tests run via `python -m pytest tests/ -q`; full suite 90 passed
         | WHERE: tests/
```

每一行都有出处：FILES 与 WHERE 来自最终 diff，TESTS 来自最后一次全量测试，VERIFY 是实跑过的命令带真实退出码，CONTEXT 来自任务中真正读到过的文件内容——写记忆的指令明文禁止发明、凑数和贴 diff 正文。数字验证：这份记忆以 **6% 的字节**（1,056 vs 17,320 字符）保住 M 在 linked 边界上的全部中位步数节省（2/2 步）。写记忆的开销也极低：writer 只花 1.9–5K token，而 Mem0/MemOp/ReasoningBank 的记忆模块要 13–64K。

### 4.2 M2：成本内化 on-policy 成组估值

记忆的价值只有 actor 用上才兑现，所以直接训 actor（LoRA 适配器，冻结底座）。在训练边界 b 上，当前策略 πθ 滚出 G=8 个 session 的组：

- 4 个**无记忆** session（∅）
- 3 个**自有记忆** session（m，来自冻结基座 actor 写的记忆池：27B 每边界 3 条，9B 12 条）
- 1 个**错置记忆** session（m̃，来自**另一个仓库**的真实记忆——形式对、内容错）

奖励函数（式 4）是成本内化的核心：session 解决任务时 R = W − n（W=250 的解决报酬**减去步数 n**——步数在成功内部被"收费"）；未解决时 R = α·f（α·部分测试通过率，27B 上 α=50）。W > n_max + α 保证**任何解决过的 session 排名必高于任何未解决的**——想靠早退省步数？没门，因为早退直接丢掉 W。

记忆价值直接在策略上测出：**V̂b = R̄m − R̄∅**（自有记忆组均值减无记忆组均值）。这恰是式 2 的前瞻价值以 R 为 y 的实现——**每次访问边界都免费测一次**，不需要额外跑数。错置记忆 m̃ 则教会 actor：盲从记忆会在 m̃ 上翻车，全忽略记忆则错过 m 的价值。

### 4.3 M3：溯源门控价值信用 + Proposition 1

组内信用分配分两层（式 5/7）：

- **结果信用**（每个步骤都有）：A_i = (R_i − R̄_∅)/s（∅ 和 m̃ session）或 (R_i − R̄_m)/s（m session），即普通的组相对优势，训练"又快又对地解决任务"；
- **价值信用**（只给记忆驱动的步骤）：m session 的第 t 步若满足 ωt=1，额外拿 ωt·V̂b/s。

**溯源门（provenance gate，式 6）**是三个条件的与：该步消息中出现锚点 a ∈ A(m)（来自记忆）**且** a ∉ A(h_t)（本 session 此前没见过）**且** a ∉ U_b（同组无记忆 session 的前 K=8 步也发现不了它）。三个条件合起来筛掉"碰巧撞上"和"反正自己也会找到"的假命中——校准实验显示无 veto 时 5.5% 的步被标为记忆驱动，加前 8 步 veto 后降到 1.9%，全长度 veto 会砍到 0.65%（太狠）。实际部署中被记入价值信用的步骤占 **3.46%**（泄漏零假设 1.61%），且集中在轨迹后段（7–9 十分位是 4–6 十分位的约 2.02 倍）——正是 actor 跑测试、用记忆 TESTS/VERIFY 行的地方。

训练细节上有几个值得注意的工程选择：边界抽样按 (u_b + ε)·g_b 加权，u_b 是"无记忆 session 解决率方差"的滑动平均，让梯度集中在"可解与不可解对半"的边界上（永远能解/永远不能解的边界没有对比信号）；优势用固定尺度 s=100 而非组内标准差（Dr. GRPO 的建议），保证 V̂b/s 跨边界可比；每组 G=8（4 无记忆 + 3 自有记忆 + 1 错置）；LoRA rank/alpha=16，27B 学习率 2e-4，共 20 个 update，每 update token 预算 350K（27B）/600K（9B）。

**Proposition 1（价值信用 = 对"用记忆"的定向推动）**：在式 7 的总体形式下，带记忆 session 的期望策略梯度为

g_m = (1/s)∇θJ_b^mem + (V_b/s)·Σ_t E[∇θ p_t]

其中 p_t = P_θ(ωt=1|h_t, m) 是第 t 步被门标记的概率。第一项是普通的结果学习；第二项按记忆价值的**符号与幅度**推动"actor 多久用一次记忆"——记忆有用就多用、没用就少用。关键推论：**若把价值付给每一步（ωt≡1），第二项期望为零**——因为 Σ_x ∇θπ = ∇θ·1 = 0，价值乘在整条轨迹的零均值 score 上什么也教不了，等价于只加了一个基线，还凭空添方差。附录 F 还给出更细的观察：整轨迹支付时，对记忆驱动步的推动会被等大反向的"推动其他所有步"精确抵消——门控付第一个、撤掉第二个。

## 五、评估指标与实验证据

### 5.1 实验设置

- **基准**：ChainSWE，100 条任务链按仓库对半切：52 训练链（97 边界）/ 48 测试链（96 边界），仓库不重叠；测试边界按 gold patch 文件是否重叠分 linked（54）/unlinked（42）；
- **harness**：mini-swe-agent，98K token 窗口；actor：Qwen3.5-9B、Qwen3.8-27B-FP8、Gemma-4-31B（三个开源、可后训练）+ Claude Opus 5.5、GPT-5.6 Luna、DeepSeek-V4-Flash（API 侧只测冻结记忆层）；
- **指标**：resolve rate（%）、steps/task、cache-aware tokens/session（分 actor/writer/total）、resolve per K tokens；统计用链聚类配对 bootstrap 95% 区间。

### 5.2 主结果（Table 1，27B Qwen3.8-27B-FP8）

| 记忆层 | Res.(%) | Steps | Total tokens | Res./K total tokens |
|---|---|---|---|---|
| 无记忆 | 21.0 | 35.1 | 32.2K | 0.653 |
| Full history | 22.4 (+7%) | 32.6 (−7%) | 39.0K (+21%) | 0.574 (−12%) |
| Mem0 | 21.5 (+2%) | 35.9 (+2%) | 68.7K (**+113%**) | 0.314 (−52%) |
| MemOp | 23.4 (+12%) | 33.5 (−4%) | 50.4K (+57%) | 0.465 (−29%) |
| ReasoningBank | 25.2 (+20%) | 34.3 (−2%) | 67.5K (+110%) | 0.375 (−43%) |
| CoReMem w/o training | 23.4 (+11%) | 31.8 (−10%) | 32.4K (**0%**) | 0.724 (+11%) |
| **CoReMem（后训练）** | **25.7 (+22%)** | **29.2 (−17%)** | **28.5K (−11%)** | **0.902 (+38%)** |

三个放大结论：

1. **冻结 actor 只换记忆层**（CoReMem w/o training）：步数 −10% 且总 token 与无记忆持平（0%），是唯一接近"双降象限"的形式——同设定下 Mem0 的记忆模块让总 token 暴涨 +113%（MemOp +57%、ReasoningBank +110%）。API 模型上同样成立：Opus 5.5 / GPT-5.6 Luna / DeepSeek-V4-Flash 上 CoReMem w/o training 的 resolve/token 分别 +7%/+7%/+10%，步数 −6%/−9%/−13%，是三个模型上唯一全进双降象限的记忆层。
2. **后训练内化成本**：三模型全面兑现——27B：21.0→25.7%（+22% 相对）、步数 −17%、token −11%、resolve/token +38%；9B：14.0→17.7%（+27%）、98.2→72.4 步（−26%）、token −19%、resolve/token +46%；Gemma-4-31B：11.5→14.2%（+24%）。**三模型平均 resolve/token +41%**。相对未后训练的同一记忆，27B 步数再降 8%、9B 再降 24%。
3. **锚点真的被用了**（Table 2，冻结 27B）：每千字符被下一任务使用的锚点数——CoReMem 1.32 vs MemOp 0.92、ReasoningBank 0.19、Mem0 0.14。CoReMem 每千字符装 15.8 个锚点（MemOp 14.4、Mem0 9.7），且使用率最高。

### 5.3 消融：M2 与 M3 各自的贡献（Figure 7）

- **M2（成功内部收步费）**：resolve-only RL 已把 27B 步数从 32.6 降到 30.4、9B 从 91.9 到 75.5；加步数收费（M1+M2）进一步降到 29.7 与 63.8；完整方法稳定在 29.2 与 72.4。训练动态（Figure 8）显示从 update 12 起完整方法持续降努力（−0.25 步/update），resolve-only RL 停在 30 步附近且 actor token 回升；update 20 时完整方法比 resolve-only 少 2.0 步 [−4.1, +0.4]、少 6.9K actor token [−11.2, −3.1]、resolve 还多 1.0 点。
- **M3（门控价值信用）教"何时用记忆"**：无价值信用时错置记忆让 27B 多花 +2.1 步 [+0.4, +3.9]；有门控后代价缩到 **+0.3 步** [−1.2, +2.1]，同时记忆收益从 +1.7 升到 **+2.3 点**。也就是说，门控教会了 actor 分辨"这条记忆值不值得跟"。

### 5.4 训练分布之外（附录 E）

- **SWE-bench Verified（无记忆、单任务）**：后训练 27B 69.2→73.7%（**+4.5 点** [+2.4, +6.5]，步数 −7%、actor token −9%）；9B 49.1→55.5%（**+6.4 点**，步数 −22%、token −22%、撞步数上限率 7.1%→0.1%）。这证明 LoRA 适配不仅没伤通用编码能力，反而白赚——学到的"少绕路"本事泛化到了无记忆场景。这里有个严谨的对照设计：untrained 行不是原生底座，而是同一 LoRA 服务路径上的零 update 适配器，排除 serving 差异混入。
- **外部任务链（冻结 27B + 同一套写记忆指令）**：SWEContextBench 步数 **−29%**、总 token −38%、resolve +8 点；SWE-Bench-CL（仓库重置、只有记忆跨界）步数 **−14%**、resolve +5 点。前者证明"换一套挖掘出来的任务链"结论仍成立，后者证明即使仓库状态不继承（只剩记忆这一个通道），锚点记忆仍有净收益。
- **换 harness（OpenHands，只换 harness 其他不动）**：CoReMem w/o training 16.5% vs 无记忆 10.6%（+6 点）且是唯一提升 resolve/token（+11%）的记忆层；后训练再 +5 点到 21.3%。注意 ReasoningBank 在 OpenHands 下 resolve 最高（21.8%）但代价是 token 1943K（无记忆的 2.2 倍）——"买解决率"与"降成本"的分野在换 harness 后依然清晰。

### 5.5 局限

论文自陈的边界：主实验是 Python 仓库 + mini-swe-agent harness；后训练只覆盖三个开源 actor；努力只按步数与 cache-aware token 度量，未报告 wall-clock 延迟与能耗；记忆如何在更长的仓库历史中累积、刷新（记忆膨胀问题）留作未来工作。另外锚点匹配器是字符串级的（4 类 token + 过滤规则），跨语言/跨框架的可迁移性未经检验。

## 六、效果优势的根源解释

### 6.1 前瞻估值 vs 来源任务回放增益：估值对象错了，设计就错了

MemOp 类方法的根本问题是**用错误的因变量优化记忆**：在重置的仓库上回放来源任务，记忆里"叙事完整、能复述这次修复"的部分得分高——但下一任务需要的是"去哪看、跑什么"这类可执行引用。CoReMem 的估值直接瞄准部署时真正发生的事：下一任务从继承树上带/不带记忆各跑一遍，差值就是记忆的全部真相。证据等级：**强**——七片段的逐片移除实验（Table 8）显示推理文本删除 0 步损失（34 helped/45 hurt，反而略好）、命令删除 +2 步（p*=.0070），"省步数的全是锚点类信息"有置换检验 + BH 校正支持；且 6% 字节保住全部中位步数节省（保留裕度 0.50 达标）是直接复现的数字。一句话：**不是"记多点总会用到"，而是价值密度在锚点上高度集中，叙事是纯开销**。

### 6.2 锚点这个数据结构：便宜、可执行、可追溯

锚点设计的妙处在于一石三鸟：

1. **便宜**：889 字符 + 18 锚点 vs 17K 字符原始轨迹，writer 只花 1.9–5K token——记忆模块不再吃掉自己的收益（对比 Mem0 +113% 的 token 膨胀）。证据等级：**强**（Table 1/3 直接可查）。
2. **可执行**：WHERE 直接省定位步数、VERIFY 直接省"找哪个测试跑"的步数——对应 Agentless 的定位/验证两阶段，是省探索的已知机制。linked 边界（文件重叠）上收益最大（27B linked 25.1% vs unlinked 26.5% 涨幅相当，但步数节省集中 linked）。
3. **可追溯**：锚点是字符串匹配器（4 类 token：文件路径/符号/测试 node id/命令 token，配三重过滤），能机械地标记"哪一步用了记忆"——这直接成为 M3 门控的实现基础。证据等级：**中强**——使用率 1.32/千字符 vs MemOp 0.92 是观测相关，"可追溯"到门控 3.46% 步的校准（泄漏零假设 1.61%）有 held-out 数据支撑。

一个反事实佐证：论文试过"似然比门"（有无记忆时消息似然之比）作为替代信号，AUC 只有 0.506——**记忆改变的是少数几个动作，不是整个分布**，所以尖锐的锚点匹配是对的信号，平坦的似然比没信号。

### 6.3 门控信用的数学保证：为什么"付给每一步"等于没付

Proposition 1 的证明链值得展开：策略梯度中价值项 V_b·ωt 乘以 score 函数 ∇θ log πθ(x_t|h_t)。当 ωt≡1（整轨迹支付）时，该项对 x 求和得 Σ_x ∇θπθ(x|h_t) = ∇θ·1 = **0**——价值乘在零均值 score 上，期望贡献为零，只剩方差膨胀（附录 F：付给每步 = 对记忆驱动步的正推动 + 对其余所有步的等大反推动，期望抵消）。而当 ωt 是与 θ 无关的确定性函数（门控由消息内容决定）时，E[ω(x_t,h_t)·∇θ log πθ] = Σ_x ω(x,h_t)·∇θπθ(x|h_t) = **∇θ P_θ(ωt=1)**——价值项变成对"该步被标记为记忆驱动"这一事件概率的**定向梯度**，符号由 V_b 决定。这解释了消融里 M3 的两个数字：错置记忆代价 2.1→0.3 步（负价值把"跟记忆"的概率往下推）、记忆收益 1.7→2.3 点（正价值往上推且更会用）。证据等级：**强**——数学证明（附录 F）+ 配对消融双重支撑。

### 6.4 外部交叉验证：这不是 ChainSWE 上的过拟合

WebSearch 检索"agent memory coding successive tasks"方向的相关工作可交叉印证三个点：（i）SWE-Milestone（ICML 2026）报告状态携带时 resolve 从 80%+ 跌到 38%——连续任务是公认难场景，CoReMem 在其上同时改善 resolve 与成本，方向稀缺；（ii）AGENTS.md 评测（Gloaguen et al., 2026）发现仓库级上下文文件未必涨分还更贵——与 Figure 3 中现有记忆层全亏的观察一致，锚点式紧凑设计是对"堆上下文无用"的回应；（iii）MemDelta（2026）强调写路径成本核算——CoReMem 把 writer token 计入 Total 的记账方式正合此意，且 writer 只花 1.9–5K。证据等级：**中**——方向一致但均为间接印证；CoReMem 自己的外部迁移（SWE-bench Verified +4.5/+6.4 点、SWEContextBench −29% 步、OpenHands +6 点）是最强的泛化证据。

## 八、通用性灵感

**1. 用"对下一用户的实测节省"给缓存/记忆定价，而不是对来源场景的回放**

核心思想：任何"留给未来的产物"（记忆、缓存、文档、交接笔记）的价值应在**未知未来的消费端**配对实测（有 vs 无），而非在来源端回放。论文证据：MemOp 按来源任务回放优化，在继承设定下 resolve/token −29%；CoReMem 按下一任务估值，6% 字节保住全部步数节省。推广场景：（a）客服知识库——按"新人接手时省多少处理时长"决定 FAQ 条目去留；（b）代码交接文档——按下一个开发者 clone 后定位 bug 的耗时筛选必写项；（c）多轮对话系统的跨会话用户画像——按下一会话的轮次数节省评估画像字段；（d）RAG 索引——按下游答案质量增益（而非检索指标）做索引裁剪。

**2. 锚点式数据结构：把"叙事记忆"换成"可执行引用"**

核心思想：LLM 记忆普遍存叙述（总结、教训、洞察），但可执行引用（路径+命令+校验）价值密度更高、可机器验证、可追溯使用。论文证据：删推理文本 0 步损失省 1.14K token；删命令 +2 步；使用率 1.32/千字符碾压叙事型记忆（Mem0 0.14）。推广场景：（a）运维 runbook——把"事故复盘叙事"改成"检查命令 + 指标路径"清单；（b）数据分析 agent——记忆"表结构 + 验证 SQL"而非分析心得；（c）法律/合规 agent——记忆"条款编号 + 检索命令"而非案情综述；（d）个人知识管理——Zettelkasten 的"原子化引用卡片"其实是同构思想。

**3. 成本内化奖励：只在"成功内部"对努力收费**

核心思想：奖励设计 R = W − n（解决时才扣步数）杜绝"为省钱早退"，同时让省努力成为硬目标——约束式目标（resolve 不降前提下 min 步数）变成可微的可优化目标。论文证据：resolve-only RL 停在 30.4 步，加步数收费降到 29.7，完整方法 29.2 且 resolve 还涨 1 点；早退激励被 W > n_max + α 的构造消除。推广场景：（a）工具调用 agent——解决前提下按调用次数收费，防"多调保险"与"少调躺平"；（b）推理模型——答对前提下按思考 token 收费（与 L1/高效推理 RL 同思路）；（c）机器人任务规划——完成任务前提下按能耗/时间收费；（d）人效管理——OKR 达成前提下考核资源消耗而非工时。

**4. 溯源门控信用：给"用了某个输入"的步骤发专项奖励**

核心思想：当一个标量奖励要教模型"何时使用某资源"时，把资源的测得价值只付给**可追溯使用了它**的少数步骤（三重过滤：来自资源 + 本会话新见 + 无资源也找不到），数学上保证产生定向梯度；付给全部步骤则期望抵消为零。论文证据：Proposition 1 证明 + 错置记忆代价 2.1→0.3 步、记忆收益 1.7→2.3 点；被标记步骤仅 3.46% 且集中在跑测试的后段。推广场景：（a）RAG 训练——按"引文确实被采用"给检索步骤发信用，教会模型何时检索（现有很多方法把检索奖励整段广播）；（b）工具学习——只有真正调用了工具且工具输出被引用的回合拿工具价值信用；（c）多 agent 协作——把某个子 agent 的贡献测出来只付给转发其结果的编排步骤；（d）推荐系统——把"某特征的价值"付给使用该特征的模型分支。

**5. 对抗性对照 arm：每组混一个"看起来对的假输入"**

核心思想：训练时混入错置记忆 m̃（形式完美、内容错误），让模型在真实部署遇到不相关记忆时有免疫力——比数据清洗或规则过滤更根本，因为免疫力是在策略分布上学出来的。论文证据：每组 8 个 session 固定含 1 个 m̃；有门控后错置代价仅 +0.3 步。推广场景：（a）RAG 抗污染——训练时混入看似相关的错误文档；（b）代码 agent 防过时记忆——混入旧版本仓库的记忆；（c）邮件/指令 agent——混入精心伪装的钓鱼式输入练习忽略；（d）团队交接——新人培训中故意给一份"格式正确但项目不符"的交接文档练辨别力。

**6. 继承状态是比"重置"更真实的评测设定**

核心思想：把评测从"每任务干净起点"搬到"继承前序所有副作用的起点"，才能测出记忆/习惯的真实价值——重置会偷偷把答案递过去（MemOp 的 gold patch）或把困难藏起来（SWE-Milestone 的 80%→38% 崩塌）。论文证据：CoReMem 在继承设定下解决率与成本双改善，且能力迁移到无记忆的 SWE-bench Verified（+4.5/+6.4 点）。推广场景：（a）长程具身任务——机器人在连续弄乱的环境中作业而非每次复位；（b）持续学习基准——模型在线服务时数据分布漂移下的表现；（c）人机协作系统——接手同事半成品而非从空白开始；（d）数据库/基础设施运维——在"前人遗留配置"上排障而非理想环境。

## 附：论文的一个细节美学

这篇论文在"诚实记账"上做得罕见地好：所有 token 数字都是 cache-aware 的（对预填缓存友好度不同的情况如实反映）；记忆模块自身的 writer token 一律计入 Total（Mem0/MemOp/ReasoningBank 的 token 膨胀就是这么暴露出来的）；SWE-bench Verified 的 untrained 对照用同一 LoRA 服务路径的零 update 适配器，排除 serving 差异；unlinked 边界单列，让"记忆在无关任务上不拖后腿"可被直接检验；消融的每个 arm 各自带无记忆/错置记忆对照。这种"把测量口径本身当作设计对象"的风格，与论文"成本内化"的主题互为表里——**在测量成本这件事上省成本，就是在结果里埋雷**。

**一句话总结**：CoReMem 把"给下一个未知任务留什么"从一个玄学问题变成了一个可测量、可优化、可证明定向性的工程问题——测出来的答案是锚点（去哪看 + 跑什么），优化路径是成本内化的 on-policy 训练，而这一切的入口只是一个朴素的定义：**记忆的价值 = 下一任务有无记忆的差值**。
