## 先说结论

一位在 Claude Code 团队做了一年多的工程师，在宣布加入 OpenAI 的当天发布的这期节目里，几乎没谈「模型有多强」，而是用闭幕演讲的篇幅讲自己过去一年错在哪。Thariq Shihipar 的核心判断是：2026 年「软件工厂」解决了软件变便宜、变可靠、可规模化的问题，但工厂只管一半——引擎、平衡、规模化可以交给自动化，手感、趣味、个人软件「到底要不要用」必须由人在环里试出来；他把这两半分别叫作「工业革命」和「文艺复兴」，并认为它们可以在同一个项目里分层共存（[0s–120s]、[600s–720s]）。他真正感到的瓶颈不是 token、也不是智能，而是「和模型一起工作的方式」（[840s–960s]）。围绕决策模型（系统一模型），主持人与嘉宾打了一场没结论的拉锯：主持人认为「又便宜又快就是笨模型」，嘉宾认为智能的取舍正在变化、harness 们普遍低估了这类新原语（[1080s–1680s]）。对递归自改进（RSI），嘉宾的态度是：要不要让模型「无头」地自我改进是一种选择而非定局，他更希望 RSI 把 AI 研究变成「知识工作」，把数十亿美元级实验的决策权留给人（[2520s–3000s]）。对从业者，这意味着把工程精力投向人机接口与新原语的 harness 化；对观察者，这意味着用「一次前向传播的智能」和「几千局模拟」这类评测去看模型，而不是只看发布会的分数。

## 换了东家的 Claude Code 老兵：革命与文艺复兴可以是同一个项目

这期节目是 Latent Space 在 AI Engineer Code Summit 现场录制的一组访谈之一。主持人 swyx 在开场介绍，嘉宾「此前在 Anthropic，但就在今天宣布加入 OpenAI」，并在大会上做了闭幕演讲，反响很好（[0s–120s]）。站内 10 月 24 日的日报记过「Claude Code 核心成员 Thariq 宣布离开 Anthropic」（https://inkeast.github.io/MessageDaily/posts/2026-10-24-daily-ai-tracking/ ），这次是去向落定：公开报道显示，他于 2026-11-25（美国时间）在 X 宣布加入 OpenAI，帖中点名 Thibault Sottiaux、Andrew Ambrosino 等为未来同事；具体职务未在节目和官宣中披露。

swyx 转述了闭幕演讲的框架，并特意声明「我代表自己，不代表他」。所谓「革命」，是过去一年让软件更便宜、更可靠、更易规模化，附带产出大量 slop 的工业化进程——「软件工厂」是全年最热的词之一；所谓「文艺复兴」，是当造软件变得可负担之后，人们有能力做「个人的」东西、提升自己的手艺、把时间花在人在环里的打磨上。swyx 的观察是，大会上的不少信息都在说「我们也许太快冲向工厂了」，但即便有了工厂，它也只是把生产力解放出来，让人去做另一侧的事；两者可以在同一个项目里发生（[0s–120s]）。

演讲的核心信息，按 swyx 的概括，是「把反馈回路拿回来」：过去大家花了很多力气把人移出回路，让 agent 自治、做「黑灯工厂」；但要有品味，就得把人的反馈回路放回去——做临时工具快速试，人真正试过才知道好坏。他认为大量 slop 之所以产生，是因为人没有在构建过程中真正 dogfood 和测试（[0s–120s]、[120s–240s]）。

这个判断来自嘉宾自己的教训。swyx 提到，嘉宾有一个 /human skill，它源自一种直觉：模型会认为自己交出了完美的作品——一个完美平衡的游戏、一个好的 macOS Dock 应用——但你不会去用，原因很简单，你在构建它的过程中从来没有用过它。swyx 认为这也多少透露了嘉宾下一步计划的想法（[120s–240s]）。至于这个「下一步」，节目里只有一条线索：嘉宾宣布去 OpenAI 时，Thibault 和 Andrew 都说「是时候重新发明 Codex 了」；swyx 说这话具体什么意思是开放的，演讲的几页幻灯片里或许透露了一点思路（[120s–240s]）。公开报道里，Andrew Ambrosino 在欢迎帖中写的正是「time to reinvent Codex」。

访谈本身以「过去一年我错在哪」为题。嘉宾先承认自己也有答对的部分：一年前他是最早发现 Claude 能用代码做视频的人之一，也是最早谈「HTML 的不合理有效性」的人；swyx 补充说，当时他以为这不过是「token 堆砌」，后来才意识到那是丰富的输出。嘉宾据此总结了自己的方法：看到模型聪明地做成一件事，就推断它一年后能真正做成（[120s–240s]）。接下来，他用了三个「我错了」来说明，这种方法在哪些地方把他带偏了。

## 三个「我错了」：模型不是只会 Bash 的外星异类

嘉宾的第一个错判是「Bash 就是全部」（bash is all you need）。他曾深信 CLI 浪潮会席卷一切：不再需要 MCP，只需要 CLI，甚至不需要工具——有 CLI 就够了。第二个错判是「React 就是全部」：他曾以为 React 会成为终极语言，因为模型只会写 React。主持人插话说「我没见你写过这个」，嘉宾承认「没写，但想过」（[240s–360s]）。

两个错判背后是同一个观察：模型在变强的同时也在变「宽」。当某项能力处在模型能力的边缘时，它只会用一种方式去做；能力提上去之后，可以让它用 computer use 操作 Figma、直接在 Figma 里把前端画出来，效果一样好。让嘉宾意外的是，模型开始按照「我们工作的方式」做事，而不是按照「模型需要的方式」（[240s–360s]）。

第三个错判他称之为「外星异类」论：他曾以为模型只会用一种方式工作，像一个奇怪的异类，所有东西都用 Bash 或者 XML 写出来。实际发生的是，模型越通用，就越能按你想要的任意格式工作，包括在 Figma 里画图。他认为这带来一个下游效应：你能理解模型在做什么，也能和它协作；未来不一定是模型在那里自我循环、产出一堆没人能维护的烂摊子（[360s–480s]）。

由此引出演讲的主要要点：你可以更多地「设计构建软件的体验」。嘉宾正在做一款游戏，主持人猜是「Avatar」风格，嘉宾赶紧澄清已经「去版权化」、做了泛化处理。他说提示词的一个难处在于：你描述一样东西，模型会做出几个合理的假设；等到你真正去玩的时候才发现「我根本不知道这个角色在这种情况下会这样」——他觉得这种失控感令人迷失，这也是他不喜欢 vibe coding 的地方（[360s–480s]）。

他的解法是把人的可读性写进工具链。他写了一门脚本语言，放在一个「human 文件夹」里——这就是 /human 这个名字的由来。这个文件夹的 lint 规则和别处不同：注释密度要高，禁止单字符变量名，限制行长。目标是让每个文件读起来像规格说明（spec），但它们是真实的代码：可以玩、可以调、能看懂发生了什么，而不是文档的副产品（[360s–600s]）。工作方式也随之改变：让模型做出底层原语，然后自己上手玩——「如果这个角色同时发出三个火球会怎样？」（[480s–600s]）。

主持人补了一个观察：模型非常擅长「默认值」。大多数生成的网站长得一样；让它做一个游戏，默认就会加上「按住 Shift 加速」。默认值很好，但这也是让人意识到「可以做得比默认更多」的起点（[480s–600s]）。嘉宾顺势把话题引向演讲的框架：AI 既是工业革命，也是文艺复兴——下一节展开。

## 工厂管引擎，人管手感：从「完美平衡很无聊」到几千局模拟

嘉宾的定义很直接。工业革命让人想到效率、可靠性、标准化的质量水准；文艺复兴则是「每一档边际质量提升都有用、都有价值」。他说大会上很多人在谈软件工厂和工业化，也有人谈文艺复兴，「Jason 的演讲」就在谈这个；他自己的判断是，2026 年是软件工厂与工业化之年，接下来更多会是软件的文艺复兴之年（[480s–600s]）。主持人当场质疑：你说文艺复兴，我想到的是意大利文艺复兴、艺术那种，你描述的却是渐进的质量改进，「不太像文艺复兴」（[480s–600s]）。

嘉宾的回答是把文艺复兴拆成两面。一面是「软件作为艺术或内容」：一款游戏的操控方案，你可以接受 Claude 给的默认值，也可以反复迭代让它更好，用户会感知并欣赏这种质量提升。另一面是用它去造全新的语言、全新的写软件的体验、全新的原语——这些同样有价值（[600s–720s]）。主持人归纳为：一边你可以用 Rust 重写一切，另一边可以把一个小功能做到任意小众的边际效用；嘉宾补了一句，「人们就是会想要很高质量的软件」（[600s–720s]）。

两者能否在同一个项目里并存？嘉宾认为可以，并给出了他的分层计划：等游戏引擎做好之后，用 WebAssembly 来实现，脚本语言作为带钩子的轻层搭在上面；数值平衡则尽量自动化——通过自动化测试和真实对局拿到「不平衡报告」，Claude 给出建议，但他自己保留意见（[600s–720s]）。换句话说，引擎和测试交给工厂，手感和取舍留给人。

为什么不干脆让模型把游戏调到「完美平衡」？嘉宾的说法是「完美平衡的游戏很无聊」，石头剪刀布就是完美平衡的。主持人追问，他举英雄联盟为例：它不平衡，有一些公认偏弱的角色，但「没有角色永远弱」——这些角色「弱但高方差」，玩家要去摸索版本的 meta；新角色出来之后，原先的弱角色反而适合某个场景（[600s–840s]）。方差造就了可探索的空间。

主持人问他：这些只是下一步的想法，还没试过？嘉宾说「我没告诉过你」——他一直在做一款桌游/卡牌游戏，叫 Frontier Lab：玩家扮演一家前沿实验室，有资源和科技树；设计上像《文明》，开局一个文明与其他文明竞争，胜利条件包括经济胜利（赚最多钱）、科学胜利（实现 AGI）、文化胜利（让普通人喜欢 AI，他说是最难的一种），第四种他忘了（[720s–840s]）。

他让 Claude 在这套规则上跑模拟，跑了几千局，结果永远是「走经济胜利」最优。他再让 Claude 修平衡，Claude 试了，但「非常不擅长」。嘉宾把这个过程当作一种评测：模型是否理解一个跨越数千回合的整体系统，能否调整平衡，让通常失败的策略至少在某些局面下获胜（[720s–840s]）。

主持人从游戏设计角度补了一刀：这类问题通常靠「加方差」解决，比如 roguelike 里每一局规则略有不同——军队刷新速度翻倍之类；嘉宾纠正说这不是难度等级。他自己设想的机制是：每次升级从牌堆里给三个随机选项，你的选择改变文明的偏好走向——方差更大，可能出现「选对组合就很强」的破绽，但每局都做不到，这正是有趣的地方（[720s–960s]）。

从这些信息可以推断两层启发：架构上，把可自动化的部分（引擎、测试、报告）和需要人判断的部分（手感、平衡取舍）分成两层；评测上，「几千局模拟后能否修平衡」是一种比基准分数更接近系统理解能力的测试。

## 不缺智能、不缺 token，缺的是「和模型一起工作的方式」

进入正题前，主持人先问了一个宽泛的问题：决策模型层出不穷，权重空间编程（weight space programming）也来了，现在到底是什么让嘉宾忙起来？嘉宾的回答分了几层。第一，他「不是永久底层论者」——他不认为人类会就此沦为相对 AI 的永久底层；第二，公共模型已经很好，他两家 200 美元套餐都在用（其中点了 Claude），还没碰到上限，两家的模型各有所长；第三，他既不被 token 瓶颈卡住，也不觉得被智能瓶颈卡住，「可能是被野心瓶颈」，如果他有更大的事要做的话。真正卡住他的，是「和模型一起工作的方式」——这正是他做那门脚本语言的原因：「我讨厌现在构建这个游戏的体验，虽然它很酷，但我完全不知道发生了什么。」他认为与 AI 工作的体验还有很多可以改变的空间（[840s–960s]）。

主持人接着抛出「聪明的通才」这个说法：有了模型，你不再需要领域细节。嘉宾以自己为例：他概念上懂可解释性和强化学习（RL），但不会 PyTorch、不懂 CUDA、对神经网络架构知道得不多，却能动手做 RL 和可解释性实验。他说 Astra 挺擅长这类事——比如「拿 Qwen 改一改，让它以为埃菲尔铁塔在罗马，看看下游会怎么变」（[960s–1080s]）。他认为现在是一个好时期：可以在自己不是最专长的领域做新尝试。他手上有一个 RL 想法，「可能完全天真」，但「我不觉得有人这样做 RL」；它可能是错的，但让更多有一定能力的天真的人去尝试，是好事（[960s–1080s]）。

主持人把 RL 的话题引向目标函数：探索的关键是用什么目标函数、什么数据集。对话中梳理了几个坐标：除了 RLCD（有人打趣「天知道那是什么」），最后一次大跃进大概是直接偏好优化 DPO；「组偏好」也不错；除此之外很难说目标是什么。有人提出一个建议：还没人真正做「图灵测试式 RL」——「听起来像人」和「你更偏好哪个输出」是两回事；RLVR 更偏可验证的数学题。结论是「一切都取决于选对目标函数」；至于 RLCD，节目里的说法是「没有论文，随便猜」（[960s–1200s]）。需要补充口径：TypeSafe AI 的官方博客已把 RLCD 展开为 Reinforcement Learning for Calibrated Decisions，用来训练 Jev 返回决策和校准过的概率。

回到「酷东西」，嘉宾认为决策模型很酷，而且「harness 们在低估决策模型」。他的做法是：开一个新项目时，先让模型去研究什么是决策模型、写文档（比如关于 Jev），再把 Jev 的 API key 或者 Luna 决策模型给它——目的不是从大模型蒸馏，而是让它「知道可以用」。原因是这东西太新，模型自己不会主动用；即便你明说，它也可能自己去训练一个小分类器（[1080s–1200s]）。

决策模型在系统里的位置，嘉宾用游戏 AI 来说明：一端是全部硬编码，另一端是每一回合都跑一个工具调用循环（需要非常快的推理）；决策模型在中间——行为可以预先写好，但又能根据任意时刻的游戏状态做选择。当用户的表达方式很多、难以预测、动作空间很大时，它特别有用。他说现在会试的例子是一个以决策模型为主的客服机器人：客服本质上是一棵决策树，必要时才「升级」到推理（[1200s–1320s]）。

问题在于「到底需要多少智能」。嘉宾承认决策模型没有思考、没有推理，但要把请求路由正确，需要一定的理解力；主持人说这正是他愿意采用 TypeSafe 叫法的理由——不叫「决策模型」，叫「系统一模型」，差别很小，「但有时你需要一个聪明的模型来做决定」（[1200s–1320s]）。嘉宾补了一句：这也是概率分布和置信度的用途——但模型也会「自信地错」，他很想看看 Jev 自信出错的例子，「我觉得没人探索过这个」（[1320s–1440s]）。

他进一步引用可解释性研究的常识：一次前向传播之后，模型就已经知道很多信息。Ilya 有个经典例子：一部长篇推理小说的最后一句是「凶手是 X」，这几个词的熵是零——模型早就知道凶手是谁，再解码一堆词纯属浪费；如果答案是「从这个数组里选一个」，那直接告诉我是哪个就好。所以他认为决策模型「不一定更笨」——除非 token 之间确实在做事（推理、工具调用）。他以客服为例：「我误了航班」需要知道是哪趟航班，得调工具；但连这一步也可以用决策模型来判断——用户是在要更多信息，还是引用了需要拉取的信息，还是要编一个？主持人补了一句「尽量别编」（[1320s–1560s]）。

## 「又便宜又快就是笨模型」吗：一场没打完的拉锯

主持人显然不接受「决策模型不一定更笨」。他的反驳是：通常就是更笨——OpenAI 那个是 GPT Luna，不是 Terra；你当然可以用 Sol、降低批次换更快的速度，但成本就上去了。「重力定律在这里仍然适用：又便宜又快，那就是笨模型」（[1440s–1560s]）。

嘉宾的回击是：智能的取舍并不一样，一代模型之内可以同时更便宜、更快、更聪明。他举的例子是「5.5 对 5」——5.5 每 token 更便宜、更省 token、而且更聪明（ASR 转写作 OpenAI 5.5 对 OpenAI 5，节目官网转写作 Opus 5.5 对 Opus 5，具体型号存疑）。主持人指出这里面有 RL 的混杂因素，嘉宾表示「愿意让步」（[1440s–1560s]）。

接着他把矛头转向透明度：大家没足够吐槽 Jev 不公开模型规模。「如果告诉你它是个 1B 模型，你用 1B 模型做决策的感受会完全不同」（[1440s–1560s]）。主持人同意这一批评，并说自己曾在推特上说过「Jev 可能定价偏低」，他更希望他们有一个更大的模型。他区分了 Luna 和 Sol：Sol 明显更聪明，但聪明在长程任务上；真正的问题是，一次前向传播之后的智能在两者之间真的有差别吗？他还给了几个数字：开源的决策模型规模不是 1T；Jev 自己不跑基准，但别人测过，大约 20B；decision evals 之类的榜单上有规模与质量的粗略对应（[1440s–1680s]）。

嘉宾退了一步：「决策模型还很早」，他更关注的是「预训练评测」这类东西。他举 Karpathy 展示过的一个例子：对每个经纬度点问模型「是陆地还是水」，把答案画出来就是地球。Opus 5.5 基本知道整个地球的形状，Opus 4 或 4.6 则很模糊——他认为这就是「一次前向传播的智能」的度量（[1560s–1680s]）。公开报道显示，这个实验由一位 X 用户完成，对 Opus 5.5 以每 2 度一次的密度问了 16,200 次，Karpathy 对此的评论是「模型知道，因为它们压缩了互联网」。

主持人还有两点回击。第一，Jev 的定价不算贱卖：Diogo 公开说过他们至少在单位经济上是盈利的，毛利没问题。第二，一次前向传播能做多少功，取决于层数——Z.ai 的一位教授（转写疑似 Jiatang）谈过消融层数和智能的关系，「更深更好」；大模型在一次前向里显然能做更多，区别只在于计算在哪里发生（[1560s–1680s]）。嘉宾的结论收得很克制：决策模型太早了，但很酷。

主持人顺势扩展了「系统一模型」的外延：Diogo 前一天也在会上讲了，除了决策模型还有别的系统一模型——比如记忆模型；再比如「做我想做的，不是我做说的」，也就是不按字面、按精神执行指令。主持人自己则一直想把「优先队列模型」也算作系统一模型（[1680s–1800s]）。

嘉宾对后一个例子反应热烈，称之为「很 based 的模型」——这正是他想到客服机器人的点：多数公司要的其实是 DPO 式的偏好。你对 Walgreens 的客服投诉，和对 Costco、对奢侈品牌的客服投诉，得到的回应都会很道歉、带着倾向性，而不是客观地回答是或否（[1680s–1800s]）。

主持人则把历史拉回来：GPT-2 式的下一 token 预测模型之前，初代 Transformer（BERT）做的是命名实体识别、抽取式摘要、句子位置判断这类任务——这些都可以「决策化」。「把每个旧模型重造一遍、起个性感名字」，你就能有一个书籍摘要公司——节目里说的金额，ASR 转写作「十亿美元」，官网转写作「百万美元」，这里取后者但存疑。嘉宾附和道：旧任务实在太多了（[1680s–1800s]）。主持人给听众的建议是：用更多决策模型做 harness 工程，「这是很酷的东西，值得动手实验」。

嘉宾最后补了他正在关注的两件事。一是权重空间编辑：模型现在勉强能做，「12 个月后会非常强」，可能出现新的 AI 开发与研究方式；行业还在摸索「协调者」（coordinators）这类角色，每家都有了自己的 projects 版本。二是多智能体通信——这部分留到下一节（[1800s–1920s]）。关于 Jev 与「系统一模型」的来龙去脉，站内有一篇 Jev 创始人的访谈整理可以对照：https://inkeast.github.io/MessageDaily/posts/2026-10-08-twiml-jev-machine-native-intelligence/ 。

## 做了才知道不要：多智能体、个人软件与「挠不到的大脑」

嘉宾说，他最感兴趣的是多智能体通信：「我想让我的 Dot、Duet 和 Grokbot 互相说话。」他不喜欢的是各家互相抄袭的趋势——软件变得太便宜，于是「我们也做一个」；他承认每家都有自己的视角，但作为消费者仍然很难判断该用哪个（[1800s–1920s]）。

主持人接话说自己做了「最蠢的小东西」：把所有助手接到同一个 txt 文件里，让它们「自我介绍一下」。他本来就在用不同的助手做不同的事，这个文件就是它们的共享草稿本；整个过程花了 30 秒——让其中一个先起头，现在它们都有了一些共享上下文。说到底就是一个简单的 markdown 文件（[1800s–1920s]）。

嘉宾则把精力放在「个人软件」上。他在演讲里展示过一个 macOS 上的替代 Dock，把 Dock 和专注状态结合起来；但他坦言个人软件很难——你有一个想法，但它是不是好想法、你最后会不会真的用，「很难判断」。他已经关掉了最初那个想法，现在想做的是一个待办清单、屏幕时间管理和催睡 App 的结合体，可能会用到决策模型：它知道你的日历和待办，于是会问「你现在在 AIE 期间，刷 Twitter 合理吗？」——他把 AIE 形容为「Twitter 大会」；但如果是和朋友出去玩，也许就不该刷（[1800s–2040s]）。

让他兴奋的是平台原生提供的钩子：Mac 和手机上的实时小组件、主屏的小组件预览、iMessage activities——这些以前做起来非常烦人，现在可以深度定制，「重建你的手机」，尤其是配合 Shortcuts 手动配置一下（[1920s–2040s]）。他搭快捷指令的办法是让 computer use 操作 iPhone 镜像，因为他「懒得学那些规则」。主持人问他拿 Shortcuts 做什么，他说自己有一批只支持 Hey Google、不支持 Siri 的旧智能灯具和开关；嘉宾的回应是「我给你做个快捷指令」——主持人有十个这样的旧开关，十分钟后它们都能用 Siri 控制了（[1920s–2160s]）。

主持人追问了一个关键问题：你做了 Dock，后来却不用了，为什么？嘉宾的回答是「我甚至知道自己要什么吗？」他最初的假设是：写作、编码、刷手机是不同的活动，各需要一个不同的空间；但用下来发现，真正要紧的只是「我在不在刷」——发消息、刷 Twitter 是一类活动，其他一切差不多都算工作。同时他又想要灵活性：在这件事上干了 30 分钟，想看看 YouTube，不希望被禁止。他想同时做到「不被无谓打扰」和「设计自己想要的数字生活」，但「很难知道那到底长什么样」（[2040s–2160s]）。

主持人认为，「理解自己想要什么」有一部分正是靠「免费的 token」——零成本做原型。他举例说自己有五个同步 Whoop 和 Apple Health 的健康工具，一个都不用。嘉宾也类似：他做过一个 Rewind 式的监控工具，非常省电，但不喜欢它输出的方式，所以不用，「总有一天会重做」。而做它只花了一晚上：聊 10 分钟、发一段长长的启动提示；虽然用了大量 token、被重置了限额，但试过之后他更清楚自己喜欢什么、不喜欢什么（[2040s–2280s]）。

游戏也是同样的流程。他有一个「游戏设计」创意文件夹，本质上是酝酿想法的地方；给 Claude 的指令是：我谈一个想法时，去研究其他游戏怎么处理、落到游戏设计原则上、帮我搭原型。但他经常只是发一个想法过去，看看自己喜不喜欢——那款「bending game」就是留下来、他想要继续迭代的一个（[2160s–2280s]）。

最后谈到个人软件的扩散难题。主持人说，这东西难在「挠到你大脑的东西不挠别人的大脑」，对你显而易见的事对别人不然。嘉宾更狠：「我自己大脑都难挠。」他做得极其个人化——有人问「能试试吗」，他的回答是「大概不行」；但他的态度是：「这是代码，告诉它你想要什么，它就能重做。」多数个人软件不需要很久就能做完，而且随时可以改（[2160s–2280s]）。从这些信息可以推断，他所设想的个人软件，价值不在「可安装」，而在「可按需重写」。

## 2026：agent 跑通了，但「什么都没发生」

收尾前，主持人抛出一个总结性的话题：对 coding 来说是奇妙的一年，如果回顾 2026 年的亮点——是模型发布，是趋势，又如何把这些转成对下一年的洞见？

嘉宾的回答是，这一年「agent 跑通了」；但与此同时，「一切都很不同，又没什么不同」。他一度口误说「大家都在手写代码」，随即改正：是「大家都在用 agent 写代码」——软件还是要写，前面谈到的那些问题一个都还在：什么是正确的决策？你到底想要什么？他形容模型的采用率「insane」（疯狂），是「有史以来采用最快的东西」，节目里还提到 Anthropic 公开文件里的数字；但另一方面，变化没那么大——软件依然难做，没人看到 10% 的 GDP 增长，也没有看到对劳动力市场的重大影响（[2280s–2400s]）。

于是有了「慢起飞」之争。嘉宾说，他的总体希望是：RSI 会发生，而且发生时也像「什么都没真的发生」——这就是慢起飞。主持人不同意「慢起飞」的说法：也许五年后家里就有一个机器人做家务，就像十五年前不是人人有手机、现在人人都有——世界在某些方面截然不同，在另一些方面又没那么不同。嘉宾干脆说：与其叫慢起飞，不如叫「没起飞」——不是渐进的线性变化，而是「人们会调整」。他补充说，人的问题还是人的问题：地位、幸福、「保姆迟到了而你要开会，孩子没人带」；RSI 和人类问题可以并存，还有企业采用这一层（[2280s–2520s]）。

嘉宾随后给出了他个人对 RSI 经济图景的预期，并声明「仍在打磨」。他认为会有一批前沿能力——机器人、生物、计算——在某个时刻成为明确的赢家。计算是当下的明确项：造芯片、建数据中心，「做了就赚钱」。生物和机器人则仍是在证明可行性的基础研究，一旦证明可行，就会变成「能投多少投多少」；前沿工作（能源、机器人、生物）会越来越多，那是「最该花算力和智能、最有野心的人会去的地方」。另一侧是企业：AI 被用来做粘合剂、提高效率、确保交付。他的判断是，企业不可能「真正 AI 原生」，因为它们没有那样的机会，「要找到机会，你必须做前沿的事」。他希望经济就这样分化成两侧，而不是一次性的大颠覆：企业在提效创收，每一项前沿能力解锁新的营收和可能（[2400s–2640s]）。

主持人补了 RSI 的另一个要素：模型改进自己的研究。他说自己做过几期 RSI 主题的节目，其中一环经历了「自动研究」阶段，现在是在优化自己的推理；他还在等它如何改进预训练和后训练。他猜测「可能有一些我们不知道的进展，因为我们不在那些团队里」，而这「可能是 RSI 最重要的形式」（[2520s–2640s]）。

嘉宾把 RSI 定义为「模型改进模型」，然后提出一个选择问题：「要不要让模型完全无头地自我改进？我不清楚这是不是最好的选项。」他坦承这些还在打磨，只是把想写进文章里的要点先说出来。他的核心想法是：RSI 会把 AI 研究变成「知识工作」——做决策、分配资源、争取支持、出点子，而不是硬核的技术工作；效率、安全、正确性这些交给 AI 处理。他认为这是一个「好的平衡」（[2520s–2640s]）。

这个逻辑可以推广到其他行业。以生物为例：今天它是一个「脏乱的湿实验室领域」，RSI 会把困难的部分自动化，剩下的变成知识工作——「我们在做什么实验？要解决什么？我怎么说服 CEO 做这个？」如果所有行业都这样，理想的结果是创造更多白领岗位——「经营餐厅也成了白领工作」：机器人干活，你决定菜单和毛利。他觉得知识工作本身就很有趣——「Slack 为什么让人上瘾？全是讨论和通知」；模型负责难的技术工作、正确性工作、实验工作，「对我们来说是个好结局」（[2640s–2760s]）。

主持人指出，其中很多已经在发生：做预训练、后训练、架构的人已经不自己写 PyTorch、不自己调那些 bug；嘉宾说「确实不」。主持人追问：你描绘的是某种「突破式」的 RSI——比如一个 3B 模型跑赢，理论上现在就可能？嘉宾的回答是：实验室的目标本来就是把一整座数据中心交给下一代模型（他点了 Fable 和 Astra），「去打败现有的」（[2640s–2760s]）。

## 谁来决定哪条路值得几十亿美元：RSI 里人的位置

主持人先承认「在座没人属于某家实验室」，然后给出判断：这类实验肯定在做——所有实验室都在给研究员大量算力去尝试，因为谁都想要第一个突破；「但目前模型还不够聪明」（[2760s–2880s]）。

他给了一个三十秒的思想实验：假如世上没有「推测解码」这个概念，也没有任何前置论文，你让一个模型「把推理做快」——它不会想到去训练一个小的草稿模型、按下一 token 的概率来加速；它会给出 kernel 优化、自定义推理引擎这类「暴力」做法。「它们不够有创造性。」他补了一句：也许今天的模型可以，但三到六个月前他会说不。他进一步设想：Opus 4.5、5.5、6.5 能不能只凭「做快点」就想出推测解码？（[2760s–2880s]）

嘉宾认为这是个好类比，但推测解码本身也未必是快速推理的全局最优解——他声明「我对各家怎么做推理一无所知，也没有披露任何东西」。可能存在人类想到的方案，也可能存在一种更「苦涩教训」式的方案。他的落点是一个预算问题：每个人的算力预算都是固定的，你会怎么花？他猜是让人和模型一起头脑风暴、出点子、批准哪些实验该跑；到了这个规模，一次训练是「数十亿又数十亿美元」，「这个算力分配问题，你终究希望由人来决定」（[2760s–3000s]）。

主持人顺势说：那你需要一个桌游来帮你训练——「没人发明这种桌游不奇怪吗？」对话中提到，Simon Sarris 把电子游戏称为「成就的假肢」：一个孩子有野心，但没人会给他高风险的事；他可以去当 WoW 公会会长，于是就有了组织人、赶 deadline、解谜、分派任务这些高风险的练习。据说很多 RL 和预训练领域的成功人士曾是 WoW 公会会长（节目提到「Luca 很有名」，具体是谁无法核实）。随着模型越来越能干，人的劳动变得非常高杠杆——「谁在决定那个万亿美元集群跑什么？」这种工作从来没人做过（[2880s–3000s]）。

嘉宾说，算力方面显然是做过上一次训练的人做这一次；但对初级的人，最好能有一些「假肢式的成就」——它们在物质意义上不真实，但能显示你有能力承担真实的任务。主持人提到 IOI、IMO 这类「最能赢的游戏」，但它们现在被「解决」了。嘉宾认为这是一个开放问题：年轻人应该有清晰的社会性成就假肢；学校曾经扮演这个角色——GPA、学生会主席；主持人加了一句：「现在有 token 花费。」嘉宾问：招人的时候，我要的是「哈佛毕业」这种成就假肢，还是 WoW 公会会长？（[3000s–3120s]）

主持人的观察是：让你在成人生活中成功的东西，往往和学校训练你的东西相反——学校的信息是完全的，成人生活是不完全信息、有「战争迷雾」；学校给你接下来 12 年的教学大纲，而有了 AI，你更是什么都不知道。他把这比作开放世界游戏和线性游戏的区别：自选路径，在别人看来很怪，直到走通——「然后你发明了深度学习」（[3000s–3120s]）。

嘉宾认为这是必须解决的问题，因为「人们正在失去对学校的信心」。主持人提到嘉宾曾做过教育科技。嘉宾说，他支持「假肢游戏」「假肢成就」，但「不确定这是否真的为生活做了准备」；他给年轻人的建议是：多用最新的工具、多构建、多在学校之外做事（[3120s–3240s]）。

swyx 最后把话题收回自己的大会：「我把 AIE 设计得有点像一个游戏」——激励 YouTube 播放量、庆祝有播放量的人，让人们在工作之外也有成就。他认为表达想法的能力天花板很高、可迁移、有需求；嘉宾大概不想永远在 AIE 讲 AI——「Jensen 不在 AIE 演讲，但未来的 Jensen 也许正在 AIE 演讲」。嘉宾回了一句「我正看着一个」。两人把这叫作「工作之外的工作证明」：过去是 GitHub star 和提交图，现在是演讲，以及——「token 花费」（[3120s–3240s]）。同一主办方把大会带到上海的思路，站内有一篇 swyx 的访谈可以对照：https://inkeast.github.io/MessageDaily/posts/2026-11-05-latent-space-aie-shanghai-swyx/ 。

## 机制链与读者启发

**链条一：模型变「宽」→ 表达方式的选择权回到人手里 → 工具链假设重写**
- 变化/信号：嘉宾承认自己「Bash 就是全部」「React 就是全部」「模型是只会一种格式的外星异类」三个判断全错；模型越过能力边缘后能按人的工作方式做事（computer use Figma 画前端、在 human 文件夹里写高注释密度的脚本语言）（[240s–480s]）。
- 直接原因：通用能力上升带来「宽度」，模型不再被自己的短板限定在一种表达格式里。
- 谁获得/失去：围绕「模型只会 X」设计工具链的框架和产品失去前提；把可读性写进 lint 规则的人获得了「能理解、能协作」的模型产出；围绕模型短板做流程的团队需要重做假设。
- 二阶影响：slop 的成因从「模型不行」转向「人没在构建过程中试用」；差异化转向手感、个人化与边际质量——也就是嘉宾所说的「文艺复兴」一侧。
- 未来观察指标：可读性约束（注释密度、变量命名、行长）是否成为 agent 生成代码的标配；harness 产品是否吸收「human folder」这类人在环层；围绕 CLI-only / 单一格式的设计是否退潮。
- 对读者的启发：不要把模型当下的局限固化成架构；自己先当用户，在构建过程中就试用，而不是交付后才发现「技术完美但没人用」。

**链条二：引擎与手感分层 → 自动化拿走可测的部分，人保留取舍权 → 「模拟 + 修平衡」成为新评测**
- 变化/信号：嘉宾计划把游戏引擎用 WebAssembly 实现、脚本语言作为人的轻层；让 Claude 跑几千局 Frontier Lab 模拟，发现永远走经济胜利，Claude 修平衡「非常不擅长」（[600s–840s]）。
- 直接原因：单一优势策略容易被复现和报告，但「让通常失败的策略偶尔赢」需要跨数千回合的系统理解与取舍；完美平衡反而无趣，方差才是可探索性的来源。
- 谁获得/失去：独立开发者获得过去只有大团队才有的测试规模；以「完美平衡」为卖点的内容失去吸引力；靠手工调数值的岗位被「报告 + 人工意见」替代。
- 二阶影响：「几千局模拟后能否修平衡」成为一种系统理解评测；游戏设计里的「加方差」（roguelike、随机三选一）成为对抗优势策略的通用手法。
- 未来观察指标：模型在多回合、多主体系统任务上的表现是否被纳入主流评测；独立开发者是否普遍用模拟做平衡；自动平衡报告是否成为游戏工具链的常规输出。
- 对读者的启发：把可自动化的部分（引擎、测试、报告）与需要人判断的部分（手感、取舍）在架构上分层；把「平衡」当作设计目标而不是默认终点。

**链条三：决策模型出现而 harness 不用 → 新原语的知识滞后 → 显式注入成为竞争力**
- 变化/信号：Jev、GPT Luna 等系统一模型出现，嘉宾认为「harness 们在低估决策模型」；他的做法是先让模型研究并写文档，再把 Jev API key 给它（[1080s–1200s]）。
- 直接原因：新原语太新，模型的训练数据里没有；即便明确指示，它也可能自己去训练一个小分类器而不是调用现成模型。
- 谁获得/失去：把决策模型文档和密钥显式写进 harness 的团队获得延迟和成本优势；客服、路由这类「决策树」场景最先受益；坚持「所有事都走全推理」的团队承担更高成本。
- 二阶影响：「一次前向传播的智能」成为评测维度（Karpathy 的水陆评测）；BERT 时代的旧任务被重新命名包装成新公司；「又便宜又快就是笨模型」的重力定律与「一代之内更便宜更快更聪明」的说法正面冲突，规模透明度（1B？20B？）成为信任问题。
- 未来观察指标：决策模型的「自信地错」是否被系统记录；模型规模是否公开；客服/路由类产品是否普遍采用「便宜决策 + 昂贵推理兜底」的分层；decision evals 类榜单是否成熟。
- 对读者的启发：新工具要主动写进 harness，而不是指望模型自己发现；不要只用价格判断能力，用「一次前向」类任务去测；给决策模型留出升级到推理的出口。

**链条四：零成本原型 → 做了才知道不要 → 个人软件从「可安装」变成「可重写」**
- 变化/信号：嘉宾的 Dock、Rewind 式监控，主持人的五个健康工具，都是几乎零成本做出来却不用（[2040s–2280s]）。
- 直接原因：构建前不知道自己要什么（「我甚至知道自己要什么吗？」），试过之后才清楚喜欢/不喜欢；构建只需一晚、10 分钟聊天加一段长提示。
- 谁获得/失去：个人开发者获得认识自己需求的便宜方式；以「安装量」衡量个人软件的价值失去意义；做通用工具的团队面对一群「自己做给自己」的用户。
- 二阶影响：个人软件的价值从可安装变成可重写（「这是代码，告诉它你要什么，它能重做」）；token 用量成为新的工作量证明（「现在有 token 花费」）；多智能体互通（Dot、Duet、Grokbot 互相说话）成为下一个需求。
- 未来观察指标：token 花费/用量是否成为公开的成就信号；个人软件分享是否从「发安装包」变成「发代码 + 提示」；助手间共享上下文的最简做法（一个 txt 文件）是否被产品化。
- 对读者的启发：先做原型、允许废弃，把「我不用了」当作有效信息；想清楚你是要解决「刷不刷」这类一个问题，还是设计整套数字生活。

**链条五：实验室用算力试 RSI → 模型不够有创造性 → 研究变成知识工作、算力分配由人决定**
- 变化/信号：主持人称所有实验室都在给研究员大量算力做 RSI 实验，但模型「还不够聪明」；推测解码思想实验说明模型倾向暴力解而非创造（[2760s–2880s]）。
- 直接原因：模型能做 kernel、自定义推理引擎这类暴力优化，但很难凭「做快点」想出训练草稿模型这种跳跃。
- 谁获得/失去：擅长做决策、分配资源、争取支持的人在研究中的权重上升；硬核实现工作被 AI 承担；只以硬核技术为资本的研究者失去稀缺性；初级人员缺少「假肢式成就」来证明自己能承担高风险任务。
- 二阶影响：各行业变成知识工作（湿实验室自动化、「经营餐厅也成了白领工作」）、创造更多白领岗位；人的劳动变得高杠杆，谁来决定万亿美元集群跑什么成为新问题；学校外的成就阶梯（WoW 公会会长、YouTube 播放量、token 花费）成为地位信号。
- 未来观察指标：模型能否独立提出推测解码级别的创意；「无头」自改进是否被实验室选择；企业是否真的无法「AI 原生」；招聘是否把 token 花费、演讲等纳入评价。
- 对读者的启发：把精力放在判断与取舍上，而不是和模型比实现速度；年轻人去找高风险的练习场，而不是只刷被「解决」了的游戏。

**行业意味着什么**

这期节目把 2026 年的两条叙事接在了一起。一条是「工厂」：模型足够便宜、可靠、可规模化，agent 跑通了，采用率史上最快；另一条是「文艺复兴」：当工厂把生产力解放出来，价值转向手感、个人化和边际质量。嘉宾的判断是两者并不对立，而是在同一个项目里分层——引擎、测试、报告交给自动化，取舍留给人。对工具链而言，这意味着围绕「模型只会 X」设计的假设正在失效，可读性和人在环的约束会成为新的设计对象；对决策模型这类新原语，意味着 harness 需要主动吸收，而不是等模型自己学会。对 RSI，嘉宾给出的不是「会不会」，而是「选哪种」：无头自改进是一种选择，他更倾向于让 AI 研究变成知识工作、把数十亿美元级实验的决策权留给人——这个判断成立的前提是模型在创造性上仍然有限，而主持人自己也说「也许今天的模型可以」。

**我该如何观察**

第一，看 agent 项目的工具链是否开始出现可读性约束（注释密度、命名、行长）和「human folder」一类的人在环层，这是「反馈回路拿回来」是否落地的直接信号。第二，看决策模型的采用方式：客服、路由类产品是否普遍采用「便宜决策 + 昂贵推理兜底」；规模是否公开；「自信地错」的错误模式是否被记录——这决定了「重力定律」和「一代之内更聪明」哪种说法更接近现实。第三，看评测：多回合模拟（几千局后修平衡）和「一次前向传播」类任务是否进入主流评测，这比发布会分数更能反映系统理解与知识密度。第四，看 RSI 的组织形态：实验室是否公开模型参与研究的方式，企业是否真的无法「AI 原生」，以及 token 花费、演讲这类「工作之外的工作证明」是否被招聘和社区认真对待。
