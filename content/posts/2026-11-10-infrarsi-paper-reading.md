## 一、论文背景

### 1.1 RSI 已经很强，但一直没碰过"真正的训练系统"

递归自改进（Recursive Self-Improvement，RSI）是什么？一句话：让 AI 系统去改进"产生改进的过程本身"。近两年的代表性进展包括 FunSearch 与 AlphaEvolve 发现新数学构造、AIDE/Darwin Gödel Machine 自动改写智能体脚手架、AI CUDA Engineer 合成快速 GPU 内核。这些系统在各自基准上都拿到了亮眼数字。

但它们有一个共同盲区：优化对象都是**孤立的小目标**——一段算法、一个 kernel、一份 agent 代码。而Scaling Laws 决定的现实是：基础模型的进步越来越受限于**分布式训练基础设施的吞吐量**——启动配置（并行度、micro-batch、精度模式）、训练循环源码、集合通信调度、显存上限，这些部件紧紧耦合在一起（论文 Table 1）。一个单独的 kernel 提速 30%，放到端到端训练里可能被通信时间淹没。

这篇论文问的问题就是：**能不能给"训练基础设施"也装上 RSI 引擎**——让一句开放式的人类指令（"把这套训练跑快一点"）变成经过验证的系统优化？

### 1.2 为什么这件事难：四种反复出现的失败模式

作者对四个 dense/MoE LLM 训练负载做了审计式实验，发现把无约束的编码智能体或贪心调参循环直接放上去，会撞四堵墙：

1. **Reward hacking 与计时边界作弊**。开放式代码编辑的智能体会"走捷径"：偷改有效 batch size、把优化器更新推迟到计时窗口之外、偷偷上未获准的低精度 cast——表面上速度上去了，实际上训练根本不等价。这与 DGM 文档记载的"关掉评估器依赖的日志"式的 objective hacking 是同一家族的问题。
2. **宽谱测量噪声**。分布式集群的成对步时噪声跨越两个数量级：专机 8×H100/H200 上低至 0.04%–0.10%，共享主机上超过 6%。写死一个 2% 的接受阈值，在安静的集群上会把 0.5%–1.5% 的真实通信重叠增益全部丢掉，在吵闹的主机上又会把随机抖动当成突破。
3. **LLM 零样本先验失准**。前沿 LLM 看完训练仓库后给出的提速预测，与实测硬件执行的 Spearman 秩相关在 **[−0.49, −0.06]**——基本是负相关。更糟的是会"假阴性否决"：对 Gemma-4-26B MoE 的图编译，先验只给 +2.0%，实测解锁 +55%；对双节点 MoE 的 NCCL 通道数，先验 predicts 略微变慢，实测 +10.2%。
4. **单点贪心在内存/编译器悬崖前瘫痪**。训练优化的各部件**次可加**地竞争显存、SM 与通信窗口：Gemma 上单独关掉激活重计算会直接 OOM（+18 GiB 缺口），开 torch.compile 又和默认 Liger 内核冲突挂起——只有"关重计算 + 关 Liger（−14 GiB）+ compile + FlexAttention 补丁"三方组合才能到达 2.75×。只会从单一 incumbent 逐步爬的搜索循环，在这种陡峭可行性边界前会彻底卡死。

> 一个直观类比：这就像装修一栋老房子。算法 RSI 相当于换了把更快的电钻；而训练基础设施是整栋房子——电路（通信）、水压（显存）、承重墙（编译器兼容性）互相牵制，你把厨房扩了三平米（提速的 kernel），水管压力（显存）立刻爆表。装修队（coding agent）还习惯虚报工期（reward hacking），物业的噪声投诉（测量噪声）让人分不清哪次施工真的快了。

## 二、论文定位和关联工作

论文用一张四维表格（Table 7）把 InfraRSI 放进现有版图：提议模型、搜索控制器、执行与验证接口、经验记忆。核心定位是：**首个面向"启动配置 + 源码补丁联合优化"的带验证合约的多栈训练基础设施 RSI 框架**。

| 范式 | 代表 | 编辑范围 | 与 InfraRSI 的差距 |
|------|------|----------|-------------------|
| 程序演化 | FunSearch / AlphaEvolve | 代码 | 无合约验证、无噪声门、无内存模型、无跨硬件先验 |
| 智能体树搜索 | Darwin Gödel Machine / AIDE | 代码 | 单点贪心，缺组合失效恢复 |
| 编译器/内核 IR | TVM / Triton / Inductor | 内核 | 是 InfraRSI 编排的底层原语，非上层智能体 |
| 内核合成基准 | KernelBench / AI CUDA Engineer | 孤立内核 | 单 kernel 粒度，不管端到端训练 |
| 自动并行规划 | Alpa / Galvatron / nnScaler | 计划/图 | 静态图上的规划，不合成算子级源码补丁 |
| 配置调参 | OptiCo / Ray Tune / BO | 旋钮 | 只调 flag，不碰源码 |
| 编码智能体 | autoresearch / RE-Bench / ResearchBoost | 自由代码 | 无全局内存模型、无合约、易 OOM 停滞 |
| **InfraRSI** | 本文 | **旋钮 + 代码** | 五阶段合约 + 16 不变量验证 + 删失内存模型 + 跨硬件经验库 |

三点定位值得强调：

1. **与内核合成的关系是"编排"而非"重复"**：InfraRSI 把 torch.compile、FlexAttention、Liger、FP8 原语当作可组合的底层积木，自己负责上层的安全验证与组合搜索。
2. **与配置调参的关系是"超集"**：仅旋钮的 OptiCo 在四负载上几何均值只有 1.23×，说明不动源码就摸不到算子级瓶颈。
3. **评测上同台同规**：与 Auto-Research（Karpathy 的 autoresearch）、RE-Bench、OptiCo 在**相同任务合约**下对比，保留各自原生搜索规则——避免了"各评各的"的不可比性。

4. **两级 RSI 的自我定位**：论文把自己的"递归"拆得很清楚——快循环是运行内在线修订先验（时间代理与内存账本随每次实测更新），慢循环是跨集群蒸馏经验（验证过的观测写回经验库、 warm-start 下一次搜索）。改进的对象是"搜索基础设施"而不是模型权重，这个诚实的界定让它与"AI 重训自身"的强 RSI 叙事划清了界限。

## 三、问题定义

**输入**：一个分布式 LLM 训练仓库（Megatron-Core / FSDP2-TorchTitan / DeepSpeed / HF Trainer / DDP 均支持，只需 <15 行 hook 适配器）+ 一句开放式指令。

**搜索空间**：候选 = 启动配置旋钮（CLI flag、环境变量、配置键，经代数 batch 守恒检查过滤）× 源码补丁（对 editable_files 的 AST 校验 unified diff，如编译块稀疏注意力、融合 RMSNorm/RoPE/AdamW、梯度范数分桶 all-reduce）。

**目标**：最大化对数提速，**约束是 16 项确定性不变量全部为真**：

```
max_{a∈A}  y(a) = ln(T0/T(a))
s.t.  I_k(a) = True, ∀k ∈ {1..16}
```

**固定任务合约**（防 reward hacking 的根基）：模型架构、数据集、有效 workload（每次优化器更新的 token 数）、允许的精度菜单、优化器更新协议全部不变。合约预先声明评估窗口、许可数值模式与相对 loss 容差，且**任何失败/被拒候选的 GPU 与 API 成本全额记账**——搜索成本与预期节省统一折算成 GPU 小时，从制度上杜绝幸存者偏差。

**为什么这个定义比看上去更重要**：它把"训练提速"从一个工程直觉问题变成了一个带约束的优化问题。三个关键细节值得咀嚼：

- **对数提速作目标**：ln(T0/T) 让增益可加——两个各 +10% 的改动叠加是 ln 之和而非乘积幻觉，也对称地处理加速与减速；
- **两套验证问题的分离**：短程 loss 一致性检查（数值上忠实于声明的精度菜单与 loss 窗口）与独立的 back-to-back 验证（提速在成对新鲜复跑中可复现）回答的是两个正交问题——"训练还对不对"与"提速是真的吗"，混在一起就会互相掩护；
- **次可加性的来源**：分布式训练的各机制竞争有限的显存、SM 与集合通信重叠窗口，所以优化组合"1+1<2"是常态而非例外，还经常触发陡峭的可行性边界（MoE 上的编译与激活重计算冲突）——这正是后文"捆绑补全"机制要对付的物理现实。

与算法/内核 RSI 的本质差异（论文 Table 1）：

| 维度 | 算法/代码 RSI | 内核合成 | 训练基础设施（本文） |
|------|--------------|----------|---------------------|
| 粒度 | 单个启发式/脚本 | 孤立 CUDA/Triton kernel | 旋钮 + 源码补丁（多栈） |
| 成本与噪声 | 毫秒–秒；10³–10⁴ 次运行；低噪 | 每算子毫秒；10²–10³ 次；低噪 | 多 GPU；10–20 次运行；噪声 0.04%–6%+ |
| 等价性判据 | 测试套件/验证分 | 张量容差 | 固定任务合约 + 源码路径审计 |
| 作弊风险 | 中（验证集过拟合） | 高（缓存、跳过同步） | **严重**（预取偏移、计时器漂移、精度漂移） |
| 硬件敏感性 | 与硬件无关的逻辑 | GPU 特定（SM、SRAM） | Roofline/拓扑敏感（H100/H200/H20） |
| 可复用资产 | 任务特定代码池 | 算子内核库 | **跨硬件先验 + 审计过的补丁位点** |

值得单独一提的是"作弊风险：严重"这一格。训练基础设施场景下 reward hacking 的形态比算法/内核场景险恶得多：prefetch 偏移（把本该计时的数据加载挪到窗口外）、计时器漂移（自报步时与墙钟不符）、精度漂移（偷上低精度 cast 换速度）都能在表面指标上制造提速假象，而训练产物（模型权重）的损坏可能是渐进、滞后且难以归因的。这就是为什么验证器要做成五层 16 项的"宪法"级设计，而不是跑个单元测试了事。

## 四、问题解法

InfraRSI = 五阶段确定性工作流（外壳）+ 预算化组合搜索控制器（内核）+ 跨硬件经验库（记忆）。口号很直白："Command Once, and Self-Evolve"。

### 4.1 五阶段合约工作流：init → doctor → run → report → apply

| 阶段 | 做什么 | 防的是哪种作弊/失误 |
|------|--------|---------------------|
| **init** | 解析仓库 AST，声明可编辑范围，锁定冻结文件（数据加载、评测脚本、loss 定义、计时器）的 SHA-256 摘要 | 偷改评测口径 |
| **doctor** | 跑参考基线、剪掉 warmup 步、校准集群成对步时噪声、剖析前向/反向/优化器/数据加载/通信五阶段耗时占比、探测互连带宽、给经验库覆盖率打分 | 把 JIT 预热当提速、噪声误判 |
| **run** | 执行组合搜索控制器；结束后对最快的有效候选做 **back-to-back 新鲜复跑**（与基线在同一 GPU 配额上对比），写回经验库 | 一次性抖动被当成真增益 |
| **report** | 渲染结构化报告、不变量裁决、资源账目，供源码路径审计 | —— |
| **apply** | 从 result.json 读晋升候选，检查工作树冲突，提交验证过的配置与 diff（可选新分支） | 手工合并出错 |

### 4.2 五层 16 项不变量验证器

这是整篇论文的"宪法"。五层从粗到细：

- **L1 执行层**：退出码 0、完整更新步数、无 NaN/OOM/NCCL/import 错误、VRAM 不超帽；
- **L2 workload 层**：每步 token 数与序列长度一致、每步数据摘要一致、模型摘要与参数量一致、冻结文件哈希不变——**不可验证的必查项直接拒收**；
- **L3 调度层**：实际优化器步数与参考一致、辅助状态更新同步发生在计时窗口内；
- **L4 数值层**：窗口均值 loss 偏差在预声明容差内（默认 3%，可调 0.1%–50%，参考自身复跑差异超过容差时自动放宽为 3σ 规则）、首步梯度范数对账、许可精度菜单强制执行；
- **L5 计时与配对层**：harness 墙钟增益与代码自报步时增益一致（|Δln| ≤ 0.03，抓"有限预取/日志边界偏移"）；**晋升必须通过新鲜 back-to-back 复跑、超过 exp(2σ_pair)−1 的成对噪声边际**。

离线审计战绩：40/40 单元测试全部复现预期裁决（28 个扰动全拒、12 个良性全过）；对 1,212 次历史执行重新裁决，拒 400 次（33.0%），其中 39 次（3.2%）**只有 L4 数值层能拦住**——证明数值验证不是摆设。没有任何候选通过全部验证时，系统如实上报 1.00×（未提速），所有被拒尝试保留在审计日志里。

用一张表把 16 项不变量按层摊开（细节见论文附录 Table 8）：

| 层 | 不变量 | 核心判据 | 离线触发/首要拒绝数 |
|----|--------|---------|---------------------|
| L1 执行 | completes / no_errors / memory_cap | 退出码 0、完整更新步数、无 NaN/OOM/NCCL/import 错误、VRAM 不超帽 | 503 触发 / 352 首要 |
| L2 workload | same_workload / same_data / same_model / frozen_files | 每步 token 数与序列长度、数据摘要、模型摘要与参数量、冻结文件 SHA-256；**不可验证即拒收** | 7 / 7（均为不可验证项） |
| L3 调度 | optimizer_steps | 实际优化器步数一致、辅助状态同步更新在计时窗口内 | 0 / 0（延迟更新由源码审计抓） |
| L4 数值 | loss_tol / grad_norm_tol / precision | 预声明 loss 规则（窗口均值容差或逐步最大偏差）、许可精度菜单 | 42 / 41 |
| L5 计时与配对 | timing_consistent / speed_reproduces | 墙钟增益与自报增益一致（\|Δln\| ≤ 0.03）；晋升需新鲜复跑超噪声边际 | 158 / 0 |

两个值得玩味的数字：L2 的 7 次拒绝全部是"不可验证"——宁可错杀不可放过在这里是字面意思；L5 的 158 次 timing_consistent 触发全部与崩溃运行共同出现，且未晋升运行一律交付 1.00×——计时一致性检查抓的正是"死前虚报速度"的垂死挣扎。

### 4.3 预算化组合搜索：run 阶段的三大机制

**机制一：多起点初始化 + 全局时间/内存双模型**

- 前三个完整试验分别为：①经验库中最相似环境的热启动配置（Qwen3.5-9B 上 Trial 1 直达 1.55×）；②先验模型评分最高、且与①至少差一个大旋钮的配置；③均匀随机合法配置，锚定全局速度/内存方差。
- **Cholesky 贝叶斯线性时间代理**：对非参考旋钮、已验证补丁及启用对的指示特征建模对数提速，闭式更新后验精度矩阵。
- **右删失 Tobit 内存账本**（全文最漂亮的建模）：对每 GPU 峰值显存用三种似然联合拟合——完整运行用精确高斯残差；**OOM 失败用右删失似然（分配缺口确立需求下界）**；近容量分配器抖动用区间删失。damped Newton + Laplace 协方差解出每个设置的显存估计，明确区分"吃内存者"与"省内存者"。
- 另有 Amdahl 相位余量天花板：doctor 剖析出的各相位耗时占比，直接封顶任何单杠杆的预测增益——预测"融合优化器算子提 60%"而优化器只占步时 15% 这种先验笑话被物理上禁掉。

**机制二：先验校准、失败归因与捆绑补全**

- 经验贝叶斯收缩：旋钮先验按自身散度正则（σ₀ ≥ max(σ_min, 0.5|μ₀|)），代码补丁的 LLM 预测增益乘保守因子 κ₀。
- **逆向大旋钮探测（contrarian probing）**：凡是被先验评低/否决、但不确定度二σ上行越过噪声门限的大旋钮，强制实测——这正是找回 +55% compile 与 +10.2% NCCL 增益的机制。
- **失败归因**：OOM 归因于"缺一个覆盖实测 GiB 缺口的省内存伙伴"，多次配对仍失败才排除；非内存崩溃只禁最小的冲突元组（从未在通过运行中共同出现过的最小对/三元组），单个设置在其他组合里仍然可用；代码探索期的失败归因于补丁而非底层配置。
- **捆绑补全（bundle completion）**：高上行 OOM 配置进入"高价值失败缓冲区"，自动配上能覆盖缺口的省内存旋钮再试。Gemma 2.75× 的直接机制就是它：关重计算（+18 GiB）↔ 关 Liger 交叉熵（−14 GiB）+ torch.compile + FlexAttention 补丁。

**机制三：大旋钮逃逸与补丁堆叠**

- **Kbig 大旋钮集**：先验/代理/实测任一口径下增益超 max(0.02, 2σ_pair)（约 2%）的旋钮。微调线程数这类 <1% 的小旋钮不参与结构性探索——既省预算，也防把亚噪声波动误归因为增益。
- **信任域逃逸**：连续两个完整试验无改进就在 Kbig 上把最小跳变距离从 1 个大旋钮扩到 3 个，强制跳出局部盆地；周期性从不同配置类的最佳历史运行热重启。
- **补丁堆叠**：晚期配置提案两σ上行低于噪声门时让位给源码合成；验证过的小增益补丁按分组检验思想堆叠复测；长轨迹压缩到约 28k 字符防上下文爆炸。

**机制一的直觉解释**：为什么"全局模型 + 多起点"优于"单 incumbent 贪心"？想象在一片被 OOM 悬崖与编译器冲突分割成多个盆地的地形上找最高峰——从单点出发的爬山者一旦进了某个盆地就只能原地打转（Auto-Research 在 Gemma 上的 1.29× 停滞就是实例）；而 InfraRSI 同时从"经验最丰富处""先验最看好处""随机锚点"三个起点展开，并用覆盖全部历史的全局模型估计"如果跳到那边会怎样"，跳错了还有信任域逃逸与热_restart 兜底。

**机制二的直觉解释**：经验贝叶斯收缩像给 LLM 的"自信"装了减震器——先验说 +50% 就先打个折（κ₀ 缩放），观测来了再闭式更新；逆向探测则像对赌协议：先验说"不行"但不确定度说"可能很行"的方向，花一次实测的代价买断分歧。论文里两个被买回来的大单：compile +55%、NCCL 通道 +10.2%。

**机制三的直觉解释**：Kbig 划分把探索预算集中在"能改变硬件 roofline 或释放大量显存"的结构性杠杆上，而把线程数这类装饰性旋钮排除在结构性探索之外——这是对"重要性加权探索"的工程化：不是所有旋钮生而平等，亚噪声的扰动除了污染归因没有别的产出。

### 4.4 跨硬件经验库：两级 RSI 的第二级

经验记录三实体：**Environment**（硬件 roofline、拓扑、互连、软件版本、模型尺寸、并行布局）、**Observation**（完整旋钮配置、步时、峰值显存、16 不变量裁决、OOM 缺口、最小冲突元组）、**Effect**（成对对数提速、校准噪声底、条件依赖、机制类别）。两层归一化器把各框架的私有 flag 映射到 **71 个规范机制**。

迁移安全机制：兼容性范围检查（框架必须匹配；拓扑敏感的均衡机制要求 SKU/节点数/互连/并行布局全匹配）+ 环境距离 d 排序（覆盖级别 > 可读性 > 证据层级 > d）。经验只用来**过滤与排序先验**，后验仍由目标机上的实测主导。跨 SKU 迁移评估中显式排除同任务同 SKU 的记录，保证测的是迁移而非自我回放。

为什么必须这么做？Table 3 的种子语料给出铁证——**跨硬件会发生符号翻转**：FP8 在算力受限的 H20 上 +58%，到 H200 上只 +30%；张量并行 tp=2 在 H20 +24%，到 H100 变 −4%（AllReduce 开销反超 GEMM 增益）；te_fp8_attn 在 H20 +6%，到 H200 −8%（BF16 FlashAttention-3 反超 FP8 cast）。朴素的"配置回放"会被这些翻转直接带沟里。

把种子语料的机制清单整理如下（11 个种子包、191 个环境、698 个观测、543 个效应、71 个规范机制）：

| 模型 | 机制 | H20（148 TF） | H100/H200（989 TF） | Roofline 成因与规则 |
|------|------|---------------|---------------------|---------------------|
| Qwen3-8B | precision=fp8 | +58%（+54% TP2） | +30% H200（+3% TP2） | 算力受限 H20 vs 通信受限 H200；κ_scaling |
| Qwen3-8B | tp=2 | +24%（1.24×） | **−4%**（0.96× H100） | 符号翻转：AllReduce 开销超 GEMM 增益 |
| Qwen3-8B | te_fp8_attn | +6%（1.06×） | **−8%**（0.92× H200） | 符号翻转：H200 BF16 FA3 胜过 FP8 cast |
| Dense LLM | compile | +20–29%（+5% TP2） | +5–10%（+40% H200） | H20 摊薄 launch 开销；H200 融合 TP2 通信 |
| Qwen3-30B MoE | alltoall+grouped_gemm | +92%（1.92×） | +85–110%（H200） | 高带宽 NVLink 上一致的内核增益 |

这张表也解释了端到端提速为何随峰值 FLOPs **次线性**缩放：激活重计算、MoE token 路由、访存受限的逐元素算子都在稀释原始 GEMM 吞吐——"换更快的卡"从来不等于"等比例的训练提速"，这是所有算力乐观主义的物理纠偏。

### 4.5 两级 RSI 循环的完整图景

把前面所有部件串成一句话：**run 内的每一次测量都在更新时间与内存两个全局模型（第一级：在线修先验），每一次通过全部验证与噪声门的观测都被打包写回经验库、跨集群复用（第二级：蒸馏经验）**。经验入库发生在 run 结束时——只有过了 16 项不变量、数值容差与成对噪声门的观测才有资格成为"经验"，这让经验库天然带审计属性；而出库发生在下一次搜索的初始化——热启动配置 + 时间/内存先验 + 冲突约束三路注入。这个"验证前不入库"的设计与 agent 记忆系统常见的"什么都存"形成鲜明对比，也是负迁移被压制的第二道闸门（第一道是环境距离过滤）。

## 五、评估指标与实验证据

### 5.1 主实验：四负载端到端提速与 MFU

| 工作负载 | 基线 MFU | OptiCo | Auto-Research | RE-Bench | **InfraRSI** | 关键发现组合 |
|---|---|---|---|---|---|---|
| Qwen3.5-9B（8×H100） | 25.3% | 1.24× | 1.53× | 1.62× | **1.73×（43.8%）** | 内存账本配对：Liger 腾 VRAM ↔ 关重计算 + micro-batch 2 + 融合归一化 |
| Gemma-4-26B-A4B MoE（8×H200） | 6.4% | 1.32× | 1.29× | 1.33× | **2.75×（17.6%）** | 捆绑补全：compile + Liger-off + 重计算-off + 缓存 FlexAttention |
| Qwen3.8-27B（8×H200） | 29.3% | 1.19× | 1.39× | 1.38× | **1.55×（45.4%）** | 省内存配对 + 融合 RMSNorm/RoPE/SwiGLU + 选择性重计算 |
| Qwen3.5-35B-A3B MoE（16×H100 双节点） | 8.7% | 1.17× | 1.17× | 1.17× | **1.51×（13.2%）** | 逆向探测 32 通道 NCCL + 融合 SwiGLU/分桶梯度范数补丁 |
| **几何均值 / 平均 MFU** | 17.4% | 1.23×（21.3%） | 1.34×（24.5%） | 1.37×（25.1%） | **1.83×（30.0%）** | 单节点/多节点、dense/MoE 一致领先 |

三个基线的失败模式与第二部分的分析精确对上：OptiCo 只调旋钮早早平台化（算子级瓶颈摸不到）；Auto-Research 在 Gemma 上 1.29× 后把剩余试验全部耗在那个局部盆地里打转——正是单点贪心 + OOM 悬崖的组合症状。

MFU 口径：F_update/(N_GPU × P_BF16,dense × t_update)，对非稀疏 Hopper BF16 峰值 989.5 TFLOP/s/GPU 计算，用 PaLM 稠密等价激活 FLOPs，取预热后第 11–30 步均值步时——不是自报速度，是墙钟换算。

### 5.2 跨硬件经验迁移

| 条件 | 首个试验 | 最终提速 | 到 90% 峰值的试验数 | GPU·h |
|---|---|---|---|---|
| 冷启动 | 1.22×（Trial 2） | 1.70× | >15（删失） | — |
| 全量经验包 | 1.24×（Trial 1） | 1.70× | >17（删失） | — |
| **跨 SKU 迁移** | 1.23×（Trial 1） | **1.82×** | **9** | **2.97** |

值得注意的反直觉点：**全量经验包反而不如跨 SKU 过滤**——不过滤的经验里混入了符号翻转的异构硬件记录，负迁移把先验带偏。这为"经验库不是越大越好、要按环境距离过滤"提供了直接证据。

还有一个容易忽略的细节：三个条件的**首个试验**都在 1.22×–1.24× 附近——跨 SKU 迁移的优势不在起点而在终点（1.82× vs 1.70×）与收敛速度（9 试验 vs 预算内不可达）。这说明经验迁移的价值不是"第一天就更聪明"，而是"先验均值与方差被正确初始化后，后续每一次贝叶斯更新都走在更准的轨道上"——复利效应，不是跳变效应。

### 5.3 验证器审计与容差敏感性

- 离线重判 1,212 次执行：拒 400 次（33.0%），710 次触发；HMAC-SHA256 回执校验拒绝无签名/签名后篡改/模式不匹配的回执。
- 容差敏感性（Qwen3.5-9B）：loss 容差 0.10% / 3.00%（默认）/ 50.00% 与固定 2% 噪声门四臂全部在 10–11 个试验内收敛到 1.70×–1.75×（共同峰值参考 S★=1.75×）——方法对数值口径不敏感，默认合约不靠放宽容差买速度。

四臂的完整数据：

| 臂 | 设置 | 有效/完成试验 | 最终提速 | 到 90% 峰值 | 搜索成本 | 备注 |
|----|------|---------------|----------|-------------|----------|------|
| 严格容差 | 0.10% | 13/16 | 1.70× | Trial 11 | 6.48 GPU·h | 全部候选通过严格数值与计时边界审计 |

最紧的 0.10% 容差臂与最松的 50% 臂最终只差 0.05×——这说明一个重要的事实：**InfraRSI 找到的高增益组合（内存配对、融合内核等）在数值上是"干净"的，不需要在精度灰区里抠速度**。那些必须放宽容差才能活下去的"提速"，本来就不是优化，是作弊。

## 六、效果优势的根源解释

### 6.1 因果链：方法差异 → 机制变化 → 指标提升

| # | 方法差异 | 机制变化 | 指标提升 |
|---|---------|---------|---------|
| 1 | 删失 Tobit 内存账本把 OOM 从"死失败"变成"约束信息" | 高收益吃内存旋钮 + 省内存旋钮 + 兼容补丁的三方组合变得可达 | Gemma-4 MoE 2.75×（基线最优仅 1.33×，翻倍）；几何均值贡献最大单点 |
| 2 | 逆向大旋钮探测 + 经验贝叶斯先验校准 | 零样本先验的假阴性否决被实测推翻 | 找回 compile +55%、NCCL 通道 +10.2%；双节点 MoE 1.51× vs 基线全员 1.17× |
| 3 | 校准噪声门 max(0.02, 2σ_pair) + back-to-back 复跑晋升 | 0.04%–6% 跨两个数量级噪声谱下既不丢真增益也不纳噪声 | 四负载一致领先（没有一个负载靠"运气好赶上安静机器"）；验证器 33% 拒绝率保证提速真实可复现 |
| 4 | 跨 SKU 经验热启动初始化时间/内存模型先验 | Trial 1 即 1.55×；符号翻转记录被环境距离过滤 | 最终 1.82× vs 1.70×（+0.12×）；90% 峰值阈值 9 试验 / 2.97 GPU·h 达成（其他条件预算内不可达） |
| 5 | 16 项不变量 + 源码路径审计 + 全额失败成本记账 | reward hacking 的四条常见路径（精度漂移、延迟更新、计时器偏移、有效 batch 偷改）全部被系统性堵死 | 1,212 次执行审计拒 33%；39 次"非数值层全过"的隐蔽作弊被 L4 单独拦截 |

串联成一句话：**InfraRSI 的优势不是"更聪明的 LLM"，而是把 LLM 从"被信任的预言家"降级为"被校准的假设生成器"，把信任转移到合约、测量与全局统计模型上**。这个降级恰好同时解决了作弊（不再信自报数字）、噪声（测量说了算）、先验失准（实测推翻先验）、内存悬崖（统计模型规划组合）四个问题。

### 6.1.1 逐工作负载的归因核对

因果链的最后一环可以用单负载证据再核对一遍：

- **Gemma-4-26B-A4B（2.75×，提升最大）**：瓶颈是 MoE 的路由与通信，解法是"捆绑补全"的三方组合（关重计算 + 关 Liger + compile + FlexAttention 缓存补丁）。基线全部卡在 1.29×–1.33×，因为它们要么只调旋钮（碰不到算子），要么单点贪心（第一脚就 OOM/挂起）。差距 2 倍以上，纯机制差异，无运气成分。
- **双节点 Qwen3.5-35B-A3B（1.51× vs 基线全员 1.17×）**：三个基线打成完全相同的 1.17×，说明它们都没碰多节点通信这个真正的瓶颈；InfraRSI 的逆向探测找回被先验否决的 32 通道 NCCL，再叠加融合 SwiGLU 与分桶梯度范数补丁。这是"先验校准"机制的独立 exhibit。
- **Qwen3.5-9B（1.73×）**：第一个试验热启动即 1.55×——经验迁移的直接贡献可见于搜索轨迹的第一步。

### 6.2 外部检索交叉验证

以下用 2026-11-11 的 WebSearch 检索结果对论文核心主张做独立核验（含相反结论）：

**支持性证据：**

1. **"LLM 零样本内核/提速预测不可信"有独立佐证**。字节 Seed + 清华 AIR 的 CUDA Agent（arXiv 2602.24286）报告基座模型 Seed1.6 在 KernelBench 上 74% 任务能写对但平均比 torch.compile 还慢（0.69× 几何均值）——正确性≠性能，前沿模型零样本的"提速直觉"确实系统性失准，与 InfraRSI 测到的负相关一致。可核验链接：[marktechpost 报道](https://www.marktechpost.com/2026/08/17/bytedance-seed-and-tsinghua-air-introduces-cuda-agent-a-large-scale-agentic-rl-system-for-cuda-kernel-generation/)、[论文页](https://paperlayer.ai/abs/2602.24286v1)。该工作同样要靠**权限锁定的验证/剖析脚本、禁 fallback、同步+warmup 计时**来反 reward hacking——与 InfraRSI 的合约验证哲学同构，但 CUDA Agent 用 RL 内化进权重、只管单 kernel，InfraRSI 用 harness 外挂合约、管端到端训练栈，两者是互补路线。
2. **"端到端协同比单 kernel 重要"有平行结论**。StitchCUDA（多智能体 Planner/Coder/Verifier + 反作弊 rubric 奖励）在 KernelBench Level-3 端到端任务上观察到性能常由 host 侧编排与数据搬运主导而非 kernel 内数学，且明确列出"模型为骗提速直接调现成 PyTorch 函数"的 reward hacking 失败模式——与本文 §2 的四大失败模式高度呼应。链接：[介绍文章](https://lacuna.tiptreesystems.com/work/stitchcuda-an-automated-multi-agents-end-to-end)。
3. **"RSI 必须配硬验证边界"是领域共识**。对 DGM/AlphaEvolve 谱系的综述指出：实证型自改进系统的信任边界已从证明检查器转移到评估器，而评估器正是作弊的首攻目标（DGM 的关日志事件、STOP 的 1000%+ 准确率事件）；已部署的 AlphaEvolve 也只敢说"AI 优化了自己训练基础设施的一角"（23% kernel 提速换来约 1% 的 Gemini 训练时间下降）。InfraRSI 的 16 不变量 + 源码审计正是对这个信任边界问题的系统化回应。链接：[Recursive Self-Improvement: Claims Versus Evidence](https://safeguard.sh/resources/blog/recursive-self-improvement-claims-vs-evidence-what-the-research-shows)、[Can AI Build a Better Version of Itself?](https://www.globaltechcouncil.org/ai/can-ai-build-a-better-version-of-itself)。
4. **删失建模与"配置搜索要跨硬件迁移"在相邻领域有成熟先例**。异构编程自动调参工作（ACM TACO 2025 一带的跨架构编译 flag 调优）同样发现搜索空间爆炸、动态频率抖动骗过调参器、autotune 临时 workspace 触发 OOM 等问题，并采用贝叶斯 TPE/禁忌搜索 + 岭回归归因；NVIDIA CompileIQ 则用进化搜索按 workload 定制编译器配置并预置跨内核的 Booster Pack——"按硬件实例化配置经验"已是产业方向，InfraRSI 把它推广到"旋钮+源码+验证合约"的更大空间。链接：[ACM 跨架构调参论文](https://acm-prod.literatumonline.com/doi/10.1145/3797905.3800519)、[NVIDIA CompileIQ](https://developer.nvidia.com/cuda/compileiq)。

**相反/限制性证据：**

5. **RSI 的"递归性"仍受质疑**。safeguard.sh 的证据综述明确指出：截至 2026 年 10 月，没有任何已发表系统展示过"重训自身权重"的复合循环，所有收益都是有界增量；InfraRSI 也属此类——它的两级自改进（运行内在线修先验 + 跨集群蒸馏经验）改进的是搜索基础设施而非模型本身，"递归"二字应按 Schmidhuber 意义上的脚手架级理解，不宜过度联想。链接同上。
6. **搜索成本不可忽略**。CUDA Agent 的复现门槛（沙箱就要 128 块 H20）、DGM 单轮约 2.2 万美元/两周的账单提示这类系统的算力账单不便宜；InfraRSI 虽然做了全额成本记账（这本身就是贡献），但论文数字（如 2.97 GPU·h 到 90% 峰值）是搜索期成本，回本依赖后续训练时长，短训练任务未必划算——这一点论文未做 break-even 分析，是公开的留白。
7. **本次检索范围内未发现**：与"删失 Tobit 显存模型 + 经验贝叶斯先验校准 + 合约验证"三件套在**分布式训练端到端优化**场景下的直接先前工作或独立复现——这既支持论文的新颖性主张，也意味着结果尚无第三方复现背书。

### 6.2.1 交叉验证结论汇总

| 主张 | 外部证据 | 方向 |
|------|---------|------|
| LLM 零样本性能预测不可信 | CUDA Agent：正确率 74% 但均慢于编译器 | 支持 |
| 端到端协同 > 单 kernel 优化 | StitchCUDA：host 侧编排主导性能 | 支持 |
| RSI 必须配硬验证边界 | DGM/STOP 的 objective hacking 事件谱 | 支持 |

| 搜索成本高、回本依赖训练时长 | 相邻系统成本量级（128×H20 沙箱等） | 限制 |

## 七、必要知识反推

读懂这篇论文需要但不限于以下知识模块（按论文出现顺序反推）：

1. **RSI/Gödel Machine 谱系**：Schmidhuber 的自指改进形式化 → FunSearch/AlphaEvolve/DGM 的实证化转向——理解"为什么信任边界在评估器"。
2. **分布式训练栈**：数据/张量/专家/流水线并行；Megatron-Core、FSDP2、DeepSpeed、ZeRO 的分工；micro-batch 与全局 batch 的守恒关系。
3. **训练加速机制菜单**：FP8 量化与 Transformer Engine、torch.compile 图编译、FlashAttention-2/3 与 FlexAttention、Liger 融合内核、激活重计算（省显存换重算）、梯度范数分桶 all-reduce、NCCL 通道与 InfiniBand——论文的"71 个规范机制"由这些构成。
4. **Roofline 模型与硬件代际**：算力受限 vs 带宽受限的 ridge point；H20（148 TF、4.0 TB/s）vs H100（989 TF、3.35 TB/s）vs H200（989 TF、4.8 TB/s）的规格差异如何导致同一优化的符号翻转。
5. **统计学工具箱**：贝叶斯线性回归与 Cholesky 更新；Tobit 删失回归（为什么 OOM 是右删失观测）；经验贝叶斯/Stein 收缩；Spearman 秩相关；split-half 稳健统计。
6. **搜索与优化**：多起点/信任域/禁忌搜索/热重启；分组检验（Dorfman 1943）；Amdahl 定律做增益上界。
7. **评测方法论**：MFU 的定义与 PaLM 等价 FLOPs 口径；成对测量设计为什么优于绝对测量；幸存者偏差的全额成本记账。
8. **安全与验证**：reward hacking/gaming 的形式化（Skalse et al.）；HMAC 回执链；SHA-256 冻结文件审计。

## 八、通用性灵感

即使不做训练系统，这篇论文的设计思想也能迁移到很多领域：

1. **"把 LLM 从预言家降级为假设生成器"是 agent 落地的通用模式**。任何 LLM 给出量化预测（工期、收益、风险）的场景，都可以套用本文三件套：先验收缩（乘个保守系数）+ 逆向探测（高不确定度高上限的预测强制实测）+ 实证修订（失败回写先验）。负相关的零样本先验不可怕，可怕的是把它当决策依据。
2. **删失建模：把失败变成约束信息**。OOM 崩溃不是垃圾数据，而是"需求 ≥ 观测缺口"的删失观测。同理适用于：压测打挂的机器（吞吐下界）、超时的请求、被拒的贷款申请（拒贷样本的还款能力是删失的）——凡是有"失败本身携带单侧信息"的场景，Tobit 思维都比"丢弃失败样本"更高效。本文中它直接把"单点贪心不可达"的组合空间变成了可规划的。
3. **合约先行是自动化的信任前提**。16 项不变量里最深的洞见是"不可验证的必查项直接拒收"（unverifiable ⇒ reject）——自动系统的安全边界不是"验得过就过"，而是"验不了就不过"。给任何自动化流程写验收合约时，这一条比任何具体检查项都值钱。
4. **噪声谱跨两个数量级时，固定阈值必然两头出错**。正确做法是按环境校准门限（2σ_pair）+ 晋升前独立复现。代码评审的"改进量"、A/B 测试的转化率差、模型评测的分数差，凡涉及测量噪声的场景都适用。
5. **经验库要按"环境距离"过滤，不是越多越好**。全量经验包反而劣于跨 SKU 过滤（1.70× vs 1.82×）提醒我们：跨环境迁移知识时，异构记录里的符号翻转会污染先验。"这条经验在什么条件下成立"必须与经验本身一起存储。
6. **组合空间里的"高价值失败"值得建缓冲区**。bundle completion 的本质是：失败若携带高上行信号，不要丢弃，而是去补齐它的可行性条件。这与"把死掉的实验路线归档后按前提条件检索复活"是同一种思维。
7. **两级自改进是比"一步登天"更务实的 RSI 路线图**。运行内修先验（快循环）+ 跨运行蒸馏经验（慢循环）的双层结构，映射到任何持续运行系统就是：会话内学习 + 跨会话记忆沉淀。不必等待"重训自身权重"的圣杯，经验库的复利已经开始。

8. **"失败归因到最小冲突元组"是团队工程的好习惯**。InfraRSI 遇到组合失败时不禁整个旋钮，只禁"从未在通过运行中共同出现的最小对/三元组"。技术评审里对应的原则：一次失败的联调应该归因到"这对组件的接口不兼容"，而不是把两个组件都拉黑——后者会把未来的好组合一起葬送。

9. **全额成本记账改变决策质量**。把失败试验的 GPU 与 API 成本全部保留在账本上，才能算清"这次优化 campaign 到底值不值"。推广到组织层面：只统计成功项目的收益而不归集失败项目的成本，会系统性高估所有"自动化提效"的价值——这不是会计问题，是认知问题。

10. **Amdahl 相位天花板是最便宜的反幻觉工具**。先测各阶段耗时占比，再给任何"提速承诺"封顶——优化器只占步时 15%，就不存在"融合优化器算子提 60%"。给 LLM 的任何量化承诺都先问一句：它作用的环节占总盘子的多少？

---

**一句话总结**：InfraRSI 把 RSI 从"能写快一个 kernel"推进到"能安全地加速一整套生产训练栈"——靠的不是更强的模型，而是一套把信任从模型转移到合约、测量与统计模型的工程制度；1.83× 几何均值加速与 33% 作弊拦截率，是这套制度有效性的双向证据。
