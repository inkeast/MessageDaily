## 一、论文背景

### 1.1 Agent 的"上下文消化不良"

在 ReAct 范式下，LLM Agent 每调用一次工具（典型如网页搜索），就把工具返回的原始观察直接拼进上下文，再决定下一步。论文图 1 给出了一个扎心的统计：随着步数推进，**工具返回占上下文的比例在第 4 步高达 96.7%**——Agent 的"思考"被海量"资料"淹没。单条观察也很长：长度分布的 p50=1352、p95=1861 个 token。

这带来两重代价：

1. **计算开销**：上下文长度 K_t ≈ |q| + Σ(|r_i| + |a_i| + |o_i|)，工具观察项随步数线性累积，且每一步生成都要重新处理整个上下文；
2. **性能退化**：论文举了个例子——问"2016 马拉喀什 ePrix 冠军是哪年出生的"，搜索结果里真正有用的只有"冠军是 Sébastien Buemi"一句，其余赛道长度、观众人数、最快圈速全是与下一步决策无关的噪声。已有研究表明长而杂的上下文会稀释注意力、干扰推理（Lost in the Middle、无关上下文干扰等）。

### 1.2 现有方案的"文本天花板"

自然的解法是压缩上下文，现有工作分两派：**token 剪枝**（LLMLingua 系列用语言模型评估 token 重要性再删）和**文本摘要**（用辅助 LLM 把工具输出改写成短摘要，如 RECOMP、Search-o1、ACON）。但论文指出它们有一个共同的"根本缺陷"：**压缩结果仍是离散文本 token 序列**，必须保持语义连贯（人话得通顺），因此可达到的压缩比天然受限——把 2000 token 的搜索结果压成 50 token 还要"是句人话"，信息保真和语法连贯两头不讨好。

### 1.3 核心拷问：工具必须"说人话"吗？

论文的破局点是一句反问：**工具输出为什么要以文本 token 的形式给 Agent？** 工具观察的唯一消费者是 Agent 的后续推理与动作，而 Agent 是一个神经网络——它真正"读"的是输入 embedding 空间里的连续向量。既然如此，工具完全可以"说向量话"：把长而杂的观察编码成少量**连续潜 token**（高维向量），既紧凑、又可微（能对下游目标直接优化）。近年 Coconut（潜空间推理）、KVComm/LatentMAS（潜空间通信）、MemGen/NextMem（潜空间记忆）等工作已证明模型能直接处理和交换潜 token，本文把这条路线推进到"工具→Agent"这一接口上。

## 二、论文定位和关联工作

### 2.1 压缩方法谱系：按"表示形式"与"保留目标"分类

| 方法 | 表示形式 | 保留目标 | 代表 | 与 Coca-Cola 的关系 |
|---|---|---|---|---|
| token 剪枝 | 离散文本 | 保"重要 token" | LLMLingua / LLMLingua-2 / LongLLMLingua | 主要文本基线之一 |
| 文本摘要 | 离散文本 | 语义连贯的短文 | RECOMP、Search-o1、ACON | 主要文本基线之一 |
| 通用潜压缩 | 连续向量 | **重建/保真原文** | Gist Tokens、AutoCompressor、500xCompressor、ICAE、xRAG | 同为潜 token，但目标不同 |
| **Coca-Cola** | 连续向量 | **对齐下一步动作分布（决策充分性）** | —— | 首个面向 Agent 工具观察的潜压缩 |

### 2.2 与 ICAE 的关键差别：这是本文最重要的对照

ICAE（Ge et al. 2023）与 Coca-Cola 最接近：都用自编码器式架构把长文本压成少量连续向量、都训练目标 LLM 使用这些向量。差别在**训练目标**：ICAE 以**重建原文**为目标；Coca-Cola 论文一针见血——"已有潜压缩方法主要关注保留或重建原始文本信息，而 Coca-Cola 直接为 Agent 的后续决策优化，保留决策关键信息、丢弃冗余内容"。为了让这个对照干净，实验中的 ICAE 基线**复用了 Coca-Cola 的全部架构，仅把训练目标换成重建**——同架构、异目标，归因清晰。

### 2.3 潜 token 的三条既有脉络（论文 Related Work 综述）

- **潜推理**：Coconut、CCoT、SoftCoT——在连续潜空间里做思维链，减少对自然语言推理的依赖；
- **Agent 间潜通信**：KVComm（KV cache 交换）、LatentMAS（隐藏态迁移）——多智能体间不走文本协议；
- **潜记忆**：MemGen、NextMem——用连续潜 token 存取历史信息。

Coca-Cola 填补的是"**工具→Agent**"这最后一环：三者合起来，Agent 生态的推理、通信、记忆、工具接口就都能脱离文本了。

## 三、问题定义

### 3.1 形式化设定

给定任务指令 q，参数为 ψ 的 Agent 在第 t 步产生推理 r_t、发出工具调用 a_t、收到观察 o_t。记 h_t = (r_1, a_1, o_1, …, r_t, a_t) 为收到 o_t 前的轨迹前缀。不压缩时 Agent 这样选下一步动作：

a_{t+1} ~ p_ψ(· | q, h_t, o_t)

文本压缩法用 g_η(q, h_t, o_t) 产生更短的 token 序列 ô_t 替换 o_t；Coca-Cola 则要学一个压缩器产生潜 token：

z_t = A_φ(C_θ(q, r_t, o_t)) ∈ R^{m×d}

其中 d 是目标 Agent 的输入 embedding 维度、m 是潜 token 数，Agent 改为 conditioning 在 z_t 上。

### 3.2 两个核心子问题（论文自述的挑战）

1. **可用性**：潜 token 处在压缩器的表示空间里，怎么让目标 Agent "读得懂"？——需要跨表示空间的接口设计；
2. **信息保真**：在 m 个 token 的有限预算下，保什么、丢什么？——重建原文既不必要也不可行（预算装不下），正确目标应是**保留"决策关键"信息**。

### 3.3 理论动机：码本容量分析

论文用有限精度码本容量论证潜 token 的潜力（固定编码器与 Agent 共享的上下文）：

- n 个文本 token 的码本容量：C_text(n) = n·log₂|V|（每个位置只能从 |V| 个词表符号中选一个）；
- m 个潜 token（每个 d 维、有效坐标数 d_eff ≤ d、每坐标 B 个可分辨取值）：C_latent(m) = m·d_eff·log₂B。

当 **d_eff·log₂B > log₂|V|** 时，同样占 m=n 个输入位置，潜 token 的理论容量更大——因为向量可以在多个坐标上**联合编码**，而文本位置只能选一个符号。打个比方：文本 token 像每个格子只能填一个汉字的表格，潜 token 像每个格子里可以连续调节多个旋钮的组合锁，单格能携带的信息量完全不同量级。作者也诚实声明：这只是"潜力上限"，实际能用多少仍取决于压缩器的编码能力与 Agent 的利用能力。

## 四、问题解法

### 4.0 全景

```
任务指令 q ─┐
当前步推理 r_t ─┼→ [上下文感知编码器 Cθ（小LM）] → [潜适配器 Aφ] → m 个潜 token z_t
工具观察 o_t ─┘                                                    │
                                                    用 ⟨latent_obs⟩ … ⟨/latent_obs⟩ 边界符
                                                    直接插入冻结 Agent 的输入 embedding 序列
训练：对齐"全观察 Agent"与"潜观察 Agent"的下一步动作分布，只更新 Cθ 的 LoRA + Aφ
推理：每次工具调用后用 z_t 替换原始观察，循环多步
```

### 4.1 组件一：上下文感知编码器

一个关键观察：**"哪部分观察重要"不取决于观察本身，而取决于任务指令和 Agent 当前的推理状态**（查"冠军出生年份"时，冠军名字是关键；查"最快圈速"时，同一份结果里关键内容完全不同）。因此编码器 C_θ 是一个小型语言模型，把 (q, r_t, o_t) 三者**联合编码**为上下文条件化的隐藏态 H_t = C_θ(q, r_t, o_t)——压缩器知道"你是谁、你正想干嘛"，才能对症下药地保留信息。

### 4.2 组件二：潜适配器与连续接口

编码器与目标 Agent 的表示空间不同，隐藏态不能直接用。潜适配器 A_φ 把 H_t 变换成固定数量 m 个潜 token 并映射到 Agent 的输入 embedding 空间。生成的 z_t 用特殊边界符包裹后**直接拼进 Agent 的输入 embedding 序列**：

X_t = [E_ψ(q, h_t); E_ψ(⟨latent_obs⟩); z_t; E_ψ(⟨/latent_obs⟩)]

这就在工具与 Agent 之间建立了一个**连续接口**——Agent 像读普通 token 一样"读"向量，无需修改 Agent 本身（E_ψ 是 Agent 原生的 embedding 函数）。

### 4.3 组件三：Action-Preserving Training（本文灵魂）

训练目标是让压缩后的 Agent **行为上**与压缩前一致。把同一冻结 Agent 喂两种输入：

- 教师侧：p_full = p_ψ(· | q, h_t, o_t)（全观察）
- 学生侧：p_latent = p_ψ(· | q, h_t, z_t)（潜观察）

损失函数 L = λ_KL·D_KL(p_full ‖ p_latent) + λ_CE·CE(y_{t+1}, p_latent)：KL 项对齐两侧的**下一步动作分布**（"看全本的 Agent 会怎么选，看压缩笔记的也要这么选"）；CE 项用采到的真实下一动作 y_{t+1} 做动作级监督。两个权重 λ_KL=0.3（前 20% 步 warmup）、λ_CE=1.0。

由于潜 token 连续可微，梯度可以**穿过冻结的目标 Agent** 反传到压缩器；训练中 Agent 全程冻结，只更新编码器的 LoRA 参数（rank 16、scaling 32、dropout 0.05）与潜适配器。注意这里完全**不需要重建原文**——压缩器学的是"动作充分"的表示，不是"原文忠实"的表示。

### 4.4 推理流程与工程细节

- 每次工具调用后，训练好的压缩器把观察压成 **128 个潜 token**（默认值，见消融）替换原文，多步循环；
- 训练数据仅 **4,363** 个"观察-动作"对（来自 4,188 个任务，3,927 训练 / 436 验证）——数据需求非常小；
- 优化器 paged 8-bit AdamW，lr 1.5e-4 线性衰减至 5e-5；
- 硬件 4×A100-80GB：训练时冻结 Agent 分布在 3 卡、压缩器占 1 卡；推理时 Agent 单卡运行（若用第二张卡只放压缩器）；
- 网页搜索设置：每次调用最多取 5 条结果，每任务最多 5 次工具调用。值得强调：Coca-Cola **没有任何搜索专属设计**，压缩器只条件于 (q, r_t, o_t)，换工具无需改架构。

## 五、评估指标与实验证据

### 5.1 设置与指标

- **模型对**：Qwen3.5-35B-A3B + Qwen3.5-4B、GLM-4.7-Flash + GLM-Z1-9B 两组配置（由附录"目标 Agent 分布 3 卡、编码器占 1 卡"的部署可推断：较大的模型作冻结目标 Agent，同族小模型作上下文感知编码器）；
- **基准**：NQ、TriviaQA（单跳 QA）+ 2WikiMultiHopQA、HotpotQA（多跳 QA）；
- **基线**：Vanilla（不压缩直接拼原文）、LongLLMLingua（token 剪枝）、LLMSummary（辅助 LLM 摘要）、ICAE（**同 Coca-Cola 架构、仅换重建目标**——最干净的对照）；
- **指标**：EM / F1（答案正确性）；I_token（输入 token）、O_token（输出 token）、Comp_rate = 1 − (潜设置 token) / (原始设置 token)、端到端耗时 Time。

### 5.2 RQ1 效率：token 降 70%–89%，时间降 24%–56%

**总 token 消耗相对 Vanilla 下降 70.01%–89.24%**，两端代表值：

| 配置·数据集 | Vanilla I_token | Coca-Cola I_token | 输入降幅 | Comp_rate（Coca-Cola） | 同设置最高基线 Comp_rate | Vanilla Time | Coca-Cola Time |
|---|---|---|---|---|---|---|---|
| Qwen·NQ | 14362.12 | 1766.53 | **↓87.7%** | 85.78% | 57.07%（ICAE） | 96.19s | 64.64s（**↓32.8%**） |
| GLM·2Wiki | 31693.47 | 3003.38 | **↓90.5%** | **89.24%** | 81.61%（LLMSummary） | 106.37s | 46.83s（**↓56.0%**） |

- 对比共享架构的 ICAE：Coca-Cola 在**全部 8 个设置**中压缩率更高（如 GLM·2Wiki 89.24% vs 74.12%）——重建目标浪费容量在"把噪声也存回来"上；
- LLMSummary 在 3 个设置压缩率略高，但代价是性能崩（GLM·NQ 的 EM 仅 **16.00%** vs Coca-Cola **23.50%**）；
- 运行时间上 Coca-Cola 在全部 8 个设置最低：Qwen 组降 24.45%–32.80%，GLM 组降 41.61%–55.97%（如 GLM·TriviaQA 91.36s→41.97s，↓54.1%）；
- 连输出 token 也系统性下降（如 Qwen·NQ 的 O_token 992.69→417.69，↓57.9%）——更干净的上下文让 Agent 的推理与追问都更省。

### 5.3 RQ2 性能：激进压缩反而全面涨分

相对 Vanilla，Coca-Cola 在**全部 8 个模型-数据集组合**上 EM、F1 双升：

| 配置·数据集 | Vanilla EM/F1 | Coca-Cola EM/F1 | EM 变化 | 备注 |
|---|---|---|---|---|
| Qwen·HotpotQA | 11.00 / 16.41 | 25.70 / 33.75 | **+133.64%** | 多跳收益最大 |
| Qwen·NQ | 23.67 / 33.17 | 24.78 / 37.33 | +4.69% | |
| Qwen·TriviaQA | 56.10 / 62.87 | 59.20 / 67.07 | +5.53% | F1 低于 ICAE（69.27），但压缩率高得多（83.68% vs 66.92%） |
| Qwen·2Wiki | 17.30 / 26.94 | 24.00 / 32.34 | +38.73% | F1 低于 LongLLMLingua（34.25），压缩率 70.01% vs 41.96% |
| GLM·TriviaQA | 41.50 / 44.57 | 51.50 / 59.41 | **+24.10%** | 超最强基线 LLMSummary 的 49.29 F1 |
| GLM·NQ | 21.50 / 26.08 | 23.50 / 31.45 | +9.30% | |

全局看：**16 个数据集-指标对中 13 个拿到最高分；8 个模型-数据集组合中 6 个 EM 与 F1 同时最高（GLM 组全胜）**。两处未夺冠的例外（Qwen·TriviaQA 输 ICAE、Qwen·2Wiki F1 输 LongLLMLingua）都发生在压缩率远低于对手的背景下——对手用更低的压缩换更高的分。

### 5.4 RQ3 消融：潜 token 数与条件输入

**潜 token 数 m**（NQ·GLM，每个 m 单独训压缩器）：m 从 8→128，F1 从 26.34% 稳步升至 **31.45%**；压缩率在 m≤64 时保持 78.83%–82.56%，m=128 时降至 73.73%。默认取 m=128（性能-效率权衡最优）。

**条件输入**（NQ·GLM，m=128）：

| 变体 | EM | 相对 Full 掉分 | 压缩率 |
|---|---|---|---|
| Full (q, r_t, o_t) | 23.50 | —— | 73.73% |
| w/o Reasoning State (q, o_t) | 21.45 | **−2.05** | 80.43% |
| w/o Task Goal (r_t, o_t) | 20.02 | **−3.48** | 78.38% |
| Observation-only (o_t) | 18.34 | **−5.16** | 79.94% |

两个条件都有贡献，任务指令比推理状态更重要（单跳 NQ 上当前子目标与原问题高度重合，故推理状态贡献偏小）。最有说服力的细节：**Observation-only 变体（18.34% EM、79.94% 压缩率）仍同时优于全部压缩基线（EM 至多 17.00%、压缩率至多 74.62%）**——包括同架构的 ICAE。也就是说，哪怕砍掉条件输入，只要训练目标是"保动作"而非"保原文"，就 Already 赢了：架构不是关键，**目标才是**。

### 5.5 RQ4 案例：HotpotQA #377

问题："Jens Risom 引入了哪种以极简与功能性为特征的设计？"搜索结果同时包含"Mid-Century Modern 家具设计的重要塑造者"与"最早把 Scandinavian design 引入美国的设计师之一"两条线索。Vanilla 被两条线索拉扯，多搜一轮后仍答错（Mid-Century Modern）；Coca-Cola 的潜表示直接锁定与问题匹配的证据，**更少的搜索次数、更低的上下文开销下答对**（Scandinavian design，与参考答案一致）。

## 六、效果优势的根源解释

以下按"方法差异→机制变化→指标提升"建立因果链，证据均来自论文实验。

### 解释 1：为什么潜 token 能把压缩做到 70%–89%，而文本方法结构性做不到？

因果链：文本 token 每个位置只能取词表中 1 个符号（容量 n·log₂|V|），且压缩结果必须语义连贯 → 高压缩比下要么语法破碎、要么丢信息 → 文本基线压缩率被"人话连贯性"锁死；潜 token 在 d_eff 个坐标上联合编码（容量 m·d_eff·log₂B），向量值连续可分 → 单位置信息密度高一个量级 → 同样 8 个设置里 Coca-Cola 压缩率全部高于同架构的 ICAE（89.24% vs 74.12% 极值），也几乎全部高于文本基线。【证据：Table 1/2 压缩率列；§3.2 容量分析。】

### 解释 2：为什么压掉 70%–89% 的信息，性能反而全面超过不压缩的 Vanilla？

因果链：原始观察 96.7% 是与当前决策无关的噪声 → 噪声稀释注意力（论文引用的 Lost in the Middle / 无关上下文干扰文献）→ Vanilla 在多跳任务上尤其容易答非所问（案例 #377 被两条线索拉扯）；Coca-Cola 的压缩器以 (q, r_t) 为条件，显式执行"任务相关过滤" → 决策关键证据在潜 token 中被相对放大、噪声被挤出 → EM/F1 上升，且**多跳任务收益最大**（Qwen·HotpotQA EM +133.64%、GLM·TriviaQA +24.10%，均远高于单跳 NQ 的个位数涨幅——多跳任务里"从多条长观察中甄别证据"的需求最强，过滤的红利也最大）。【证据：Table 3 全部 8 组双升 + 涨幅的多跳>单跳模式 + Figure 4 案例。】

### 解释 3：为什么"保动作"目标胜过"保原文"目标？（对 ICAE 的同架构对照）

因果链：重建目标要求潜 token 携带恢复**全部**原文（含 96.7% 的噪声）所需的信息 → 有限 m 预算被浪费在与决策无关的内容上；动作对齐目标只要求潜 token 支撑起**与全观察一致的下一步动作分布** → 容量全部投给决策关键信息 → 同一架构下，Coca-Cola 8/8 压缩率更高、13/16 指标最高；更极端的证据是 Observation-only 变体（条件最弱）仍胜过 ICAE（18.34 vs 17.00 EM）。这构成"目标函数差异（而非架构差异）导致性能差异"的受控实验级证据。【证据：Table 3 + Table 4 的 ICAE 行。】

### 解释 4：为什么条件输入 (q, r_t) 不可省？

因果链：观察中"何为关键"无法从观察自身判定（同一份搜索结果对不同子目标的关键内容不同）→ 去掉任务指令后压缩器失去"相关性判据"（−3.48 EM），再去掉推理状态连"当前子目标"也不知道（合计 −5.16）→ 压缩变成无条件的有损编码。反向佐证：消融变体压缩率反而更高（78%–80% vs 73.73%）——它们不是压得更多，是**省掉了为相关性付出的表示预算**。【证据：Table 4。】

### 解释 5：输入 token 的节省如何转化为 24%–56% 的端到端时间节省与输出 token 下降？

因果链：Agent 每步生成都重读全上下文，输入 token 是计算量的主导项 → 输入降 70%–89% 直接砍掉每步 prefill/attention 开销；同时更干净的上下文让 Agent 更快收敛到答案——案例显示 Coca-Cola 用更少搜索次数答对 → 输出 token 同步下降（↓26.9%–57.9%）→ 两项叠加成端到端时间收益。GLM 组时间降幅（41.6%–56.0%）大于 Qwen 组（24.4%–32.8%），论文未深究原因（可能与两组任务步数分布与压缩率分布不同有关），此处不做断言。【证据：Table 1/2 的 I/O token 与 Time 列；Figure 4。】

### 边界与未决问题（诚实清单）

- 两处未夺冠设置提示**压缩率-性能存在权衡前沿**：让文本基线少压一点，单点分数可以更高；
- m 的收益仍在单调上升（8→128 F1 稳升），论文未探索更大 m 或变长 m；
- 潜 token **不可人类审计**（不能直接"看"压缩器保留了什么）——这是相较摘要/剪枝的真实代价，论文未讨论；
- 评测限于网页搜索 QA 一类工具，其他工具类型（代码、数据库、API）未验证；
- 训练用的 4,363 个观察-动作对规模很小，泛化到分布外工具/领域的行为未知。

## 七、必要知识反推

读懂本文需要哪些前置知识？按层反推如下：

### 7.1 领域知识层

- **ReAct 循环与上下文累积公式**：K_t ≈ |q| + Σ(|r_i|+|a_i|+|o_i|)，以及"每步生成都重读全部历史"的自回归机制——不理解这个就理解不了工具观察为何是开销大头；
- **长上下文退化现象**：Lost in the Middle、无关上下文干扰——"压缩反而涨分"的直觉来源；
- **embedding 空间与输入接口**：LLM 的输入是 embedding 序列而非 token id 序列本身——潜 token 能"冒充"输入的物理基础；边界标记符的用法；
- **信息论基础**：码本容量 = 可分辨码字数的对数——看懂 §3.2 的量化对比所需的最小概念。

### 7.2 方法论知识层

- **行为蒸馏 / 分布对齐**：KL 教师分布、CE 硬监督的组合是标准蒸馏配方，本文的巧思在于"教师=同一个 Agent 看全本"——**免标注、免额外大模型**；
- **冻结主干 + LoRA 微调**：梯度穿过冻结模型训练前置小模块，是参数高效训练的典型布局；LoRA 的 rank/scaling/dropout 超参含义；
- **受控对照设计**：ICAE 基线"同架构只换目标"是归因干净性的教科书做法；消融中"逐项去除条件输入"的正交设计；
- **压缩率与性能的联合报告**：单看 EM 或单看压缩率都会误导，本文所有主表同时报告两者。

### 7.3 工程知识层

- **显存与并行布局**：冻结大模型 3 卡分布 + 压缩器 1 卡（4×A100-80GB 训练布局）、paged 8-bit AdamW、LoRA 用 8bit 优化器的省显存组合；
- **搜索 Agent 的协议设计**：`<|begin_search_query|>` 等特殊标记、最大搜索次数约束、`\boxed{}` 答案格式；
- **评测协议**：EM/F1 的定义、单跳 vs 多跳基准的分工（NQ/TriviaQA 查事实检索，2Wiki/HotpotQA 考多跳推理链）。

### 7.4 知识融合的关键节点

1. **"消费者决定表示形式"**：把"工具输出的消费者是神经网络"这一事实与 embedding 接口知识相连接，得到"工具可以说向量话"的破局点——全文的 第零块多米诺；
2. **"保行为而非保内容"**：把蒸馏（对齐输出分布）与压缩（信息瓶颈）两个不相干领域的概念焊接在一起——压缩的保真度目标从"重建输入"改写为"不变输出"；
3. **"相关性是条件的函数"**：把检索领域的 query-conditioning 思想移植进压缩器输入设计，得到 (q, r_t, o_t) 联合编码。

## 八、论文中可以提取的通用性灵感

### 灵感 1：接口的表示形式应由消费者决定，而非由生产者惯性决定

- **核心思想**：工具输出给谁用，就按谁的"母语"编码。消费者是模型，就不必迁就人类可读的文本。
- **论文证据**：潜 token 接口使 8/8 设置压缩率超过同架构重建式压缩，极值 89.24%。
- **推广场景**：(1) 传感器→边缘芯片的通信可直接传特征张量而非文本日志；(2) 微服务间 API 增加"机器专用"二进制通道，人读通道仅用于调试；(3) 数据库给分析引擎的列存格式无需可读性；(4) 监控系统对自动化处置管道输出结构化信号、对人输出仪表盘；(5) 翻译流水线中间表示无需在任何自然语言中成立。

### 灵感 2：压缩的保真目标应定义在下游行为上，而非输入重建上

- **核心思想**：有损压缩该保的是"消费者会怎么做"，不是"原料长什么样"。行为一致性是比重建一致性更宽松也更正确的约束。
- **论文证据**：同架构下 ICAE（重建）8/8 压缩率更低且 13/16 指标输给动作对齐版；Observation-only 变体仍胜 ICAE。
- **推广场景**：(1) 日志系统按"告警会触发什么动作"分层保真，而非全文归档；(2) 面向 CV 模型的视频编码保留决策特征而非视觉保真；(3) 会议纪要按"待办与决策"组织而非按发言顺序；(4) 自动驾驶感知中间结果的传输保控制相关性；(5) 知识库蒸馏只保"能答对题"的参数方向。

### 灵感 3：相关性无法从数据自身判定——过滤必须携带任务与状态上下文

- **核心思想**："什么重要"是 (任务, 当前状态, 数据) 三元的函数；无条件压缩等于盲压。
- **论文证据**：去任务指令 −3.48 EM、去推理状态 −2.05、全去 −5.16（NQ·GLM）。
- **推广场景**：(1) RAG 的压缩/筛选应 query-aware（已是业界共识，本文给出量化佐证）；(2) 个人笔记检索按当前项目上下文排序；(3) 新闻推送的"个性化"本质是给压缩器喂状态；(4) 缓存淘汰策略结合当前工作负载而非仅访问频率；(5) 医疗信息系统按当前诊疗阶段过滤病历展示。

### 灵感 4：用"全信息版的自己"当免费教师——自蒸馏式降级

- **核心思想**：要在资源受限下保持行为，先让全资源版跑一遍，再把行为分布蒸馏给低资源版。教师不需要更强，只需要信息更全。
- **论文证据**：p_full（同一个冻结 Agent 看全观察）作为 KL 教师，4,363 对数据即可训出压缩器，Agent 零改动。
- **推广场景**：(1) 硬件降级部署：大显存版行为蒸馏给小显存版；(2) 网页端高保真渲染行为离线蒸馏给低功耗端；(3) 员工手册"完整版决策"培训"速查版"决策；(4) 数据库全量查询计划引导物化视图设计；(5) 教学中先学完整推导再练速解。

### 灵感 5：冻结主干、只训接口，是扩展大模型生态的低风险路径

- **核心思想**：不动大模型参数、只训外围小模块（这里连"模块"都只是输入侧向量），部署风险与计算成本都最小化。
- **论文证据**：目标 Agent 全程冻结，仅训编码器 LoRA + 适配器（1 张 A100 即可放下训练侧新增参数）。
- **推广场景**：(1) 企业按业务线定制外围压缩/路由模块而共享同一个底座模型；(2) 插件化生态：第三方提供"编码器"接入标准大模型；(3) 合规敏感场景模型权重不动、只动外挂；(4) 嵌入式设备只更新传感器适配层不更新推理引擎。

### 灵感 6：上下文预算是 Agent 工程的第一公民资源，值得专门"记账"

- **核心思想**：Agent 的成本与性能都随上下文增长恶化，把每个信息源的 token 占比记账（如"工具观察占 96.7%"）是优化的起点。
- **论文证据**：Figure 1 的上下文构成分析直接定位了"工具观察"这一占比最高的可压缩项。
- **推广场景**：(1) Agent 平台内置 per-source token 仪表盘；(2) 长会话产品的记忆分层（热/温/冷）；(3) 多 Agent 系统的消息预算分配；(4) IDE 插件对代码库上下文的配额管理；(5) 个人信息工具的"注意力资产负债表"。

### B. 术语备忘

- **Coca-Cola**：Context Compression via Continuous Latent Tokens，本文的潜上下文压缩模型。
- **潜 token（latent token）**：位于模型输入 embedding 空间的连续高维向量，占一个输入位置、可在多坐标联合编码信息。
- **Action-Preserving Training**：对齐全观察与压缩观察下 Agent 下一步动作分布的训练方法（KL + CE）。
- **码本容量**：可分辨码字数的对数；文本 token 为 n·log₂|V|，潜 token 为 m·d_eff·log₂B。
- **Comp_rate**：1 − (压缩设置输入+输出 token) / (原始设置输入+输出 token)。
- **ICAE**：In-context Autoencoder，以重建原文为目标的潜压缩方法，本文的同架构对照组。
