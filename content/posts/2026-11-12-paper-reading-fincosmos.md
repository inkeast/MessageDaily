## 一、论文背景

### 1.1 从"能答题"到"能办事"：agent 评测的断层

过去两年，LLM agent 的角色发生了根本变化：它们不再只是回答问题，而是替用户在开放 Web 上工作——搜索来源、调用数据 API、写代码、跑回测，然后交回一份用户"照着做但很少检查"的结果。评测却还停留在"给足条件考答题"的时代：**几乎所有既有金融基准都在某处把现实世界"关闭"了**——要么喂给模型精心整理的数据，要么把任务意图写得明明白白，要么在自家环境里替模型管住了时间线。论文的核心观察是：**每一次"关闭"都恰好删掉了一类真实世界中最危险的静默失败（silent failure），而不是测量它**。

### 1.2 金融是 agent 信任问题最尖锐的战场

论文指出金融场景的三个特殊性，每一个都会产生一种"不崩溃、报告照样漂亮"的静默失败：

| 现实约束 | 具体含义 | 对应的静默失败 |
|---------|---------|---------------|
| **数据在 Web 上，不在模型里** | 价格、财报、新闻海量、数值化、每日更新，靠记忆必幻觉数字，即使有检索模型也算错 | **未验证数据**：报告里的数字无法溯源，也无从核对 |
| **意图在用户脑子里** | 几乎没有两个投资者要一模一样的策略，细节只有在 agent 主动问时才浮出水面 | **未经请求的策略**：agent 交付了一份用户从未要求的策略 |
| **正确性住在 point-in-time 里** | 一个决策只能使用它当天公开的信息，而 Web 会不断自我修订，今天的数据把未来带进过去 | **偷看未来（look-ahead）的回测**：回测用了截止日之后的数据，收益虚高 |

类比理解：传统金融基准像**闭卷考试**（题干、材料、时间都规定好），而真实的金融工作是**开放卷宗 + 口述需求 + 时间锁**——客户说不清楚想要什么，资料要自己去档案室翻，而且只许看某一天之前的卷宗。FinCosmos 要测的正是后一种能力。

### 1.3 既有基准为何测不出这些问题

- **FinQA / FinanceBench / FinBen / MultiFinBen** 类问答基准：在给定报告上做数值推理，任务和数据都封闭，幻觉数据、意图偏差无从发生；
- **FinDeepResearch** 等研究基准：开放了数据，但问题完全指定，按准确性或专家标准答案打分；
- **AlphaForgeBench / BacktestBench** 策略基准：把策略规格和精选数据直接交给 agent；
- **InvestorBench / AMA / DeepFund** 交易基准：在自家环境里回放历史或只评实盘，agent 从不自己搭回测，且按已实现收益打分——收益有偏，也说不清 agent 是否建了用户想要的东西；
- **τ-bench / τ²-bench / τ-banking** 模拟用户基准：需要意图引导（elicitation），但世界是封闭数据库，按目标状态打分，交付物也不是可执行的研究结果。

一句话：**没有一个基准同时保持"意图、数据、时间"三者全开放**（论文 Table 1 的系统对比），因此也就没有一个基准能回答"agent 是否已准备好为真实用户工作"。

### 1.4 补充背景：point-in-time 与回测可信性

Point-in-time（时点数据）是量化金融的老原则：任何历史决策只能用决策日当时公开的数据（财报要用公告日而非报告期戳记，指标不能用全样本窗口计算）。回测过拟合问题至少可追溯至 Bailey 等人 2017 年的经典工作。LLM 时代又叠加了新泄漏路径：模型记住了训练截止日前的行情（Glasserman & Lin 2023；Lopez-Lira 等 2025 的记忆问题研究）、LLM 交易 agent 能从泄漏的未来结果中获利（Profit Mirage, 2025）、厂商报告的有效截止日可能滞后数月（HindsightBench, 2026）。这些工作审计模型或固定管线，FinCosmos 则把目光转向 **agent 自己搭的数据管线和回测本身**。

## 二、论文定位和关联工作

### 2.1 谱系一：金融 agent 与金融基准

LLM 金融 agent 从三个方向演进：交易 agent（FinMem 的分层记忆、FinCon 的多 agent 言语强化、TradingAgents 的多角色辩论、FLAG-Trader 的 RL 融合）、研究 agent（Alpha-GPT 人机交互因子挖掘、R&D-Agent-Quant、FinSight、AutoScientist-Quant——后者的自进化编码 agent 甚至在自家设定里也出现了 look-ahead 错误）、审计 agent（XBRL Agent、FinAuditing）。基准侧从 FinQA/PIXIU/FinanceBench 的"答题"走向 FinBen/MultiFinBen/Herculean 的"工作流"，但**任务在会话开始时即完全指定**。FinTrace（2026，同团队前作）评工具调用轨迹但仍为预定义任务。FinCosmos 是这条线的直接延伸：从"考固定任务"到"考隐藏需求 + 自取数据 + 自建回测"。

### 2.2 谱系二：开放世界 agent 评测

- **模拟用户线**：τ-bench 开创"工具 agent + LLM 模拟用户"范式并引入 pass^k 可靠性指标；τ²-bench 加双控制环境；τ-Voice 加全双工语音；τ-Knowledge（τ-banking）加非结构化知识库与可发现工具。共同局限：封闭数据库 + 目标状态打分。UserBench、Ambig-SWE 关注用户中心交互与欠规范任务，但仍非开放世界交付。UserBench 团队的"LLMs Get Lost in Multi-Turn Conversation"（ICLR 2026）揭示了多轮对话中模型表现崩塌的现象，与本文发现的 elicitation 短板互相印证。金融内的对话评测（ShijianBench、ConvFinRe）评决策而非可验证交付物。
- **Web 开放线**：WebArena 沙箱站点、Mind2Web 真实网站、GAIA/BrowseComp 开放 Web 可验证答案——但任务在开始时说尽。AgenticShop 个性化亦然。
- **评分可信性线**：LLM-as-judge 有已知偏差且可被博弈（MT-Bench / Zheng 等；Cheating Automatic LLM Benchmarks 的空模型高分；rubric RL 的 reward hacking）；PaperBench、DeepResearch Bench 用 LLM 评委；Zhu 等"建立严谨 agent 基准的最佳实践"（NeurIPS 2025）指出任务与评分缺陷会大幅移动 agent 分数——本文 5.2 节的"换评分员就换排名"是又一实证。固定任务集会腐烂：LiveBench 刷新题目、GDPevo 再生成任务；FinCosmos 用**文法采样**生成新任务，约 380 万种策略组合，发布集饱和或泄漏后可再抽。

### 2.3 谱系三：look-ahead 偏差治理

两条既有路线：改模型（Time Machine GPT、时序一致 LLM 只用截止日前数据训练；Summoning the Oracle 在推理时抑制记忆结果）或审计固定回测（When Alpha Disappears 逐 convention 刡换测量膨胀；Can LLMs Catch a Rigged Backtest 发现 LLM 审计员反而把干净回测标为作弊；短窗口高估 LLM 策略）。FinCosmos 的区别：**不藏未来数据、也不信任何审计员，而是把 point-in-time 变成 agent 交付物上可程序检查的不变量**。

### 2.4 定位总结

| 维度 | 之前的路线 | FinCosmos 的突破 |
|------|-----------|-----------------|
| 任务意图 | 开场全量给定（问答/策略/研究基准）或封闭库内引导（τ 系列） | 隐藏文法策略 + "问了才说"的披露策略，elicitation 本身是被测能力 |
| 数据 | 精选文档/价格序列，或自家环境回放 | 不给数据，agent 自行从 Web/247 个金融 API 获取并标注溯源 |
| 时间线 | 基准环境内部强制 point-in-time，或不检查 | agent 自建回测自守截止日，程序逐行验证每个日期 |
| 任务供给 | 固定题库（易饱和/泄漏） | 组合文法 ~3.8M 策略，按需抽新，种子可复现 |
| 评分 | 参考答案/目标状态/已实现收益/LLM 评委 | **Ref.-free**：程序重算 + 隐藏规格保真度检查，45 维 15 否决 |
| 学习闭环 | 一次性评测 | 泄漏无关（leak-free）诊断反馈 + 版本化评分 + 排行榜全记录 |

**定位结论**：FinCosmos 是 τ-bench 式模拟用户评测、GAIA 式开放 Web 评测与量化金融 point-in-time 纪律三者的首次系统合流，把"金融 agent 可信性"从口号变成可测量、可复现、可迭代的对象。

## 三、问题定义

### 3.1 从具体场景到抽象问题

具体问题：如何判断一个金融 agent 的交付物值得用户押上真金白银？直接定义"正确交付"很难——没有标准答案（每个用户策略不同）、无法穷举错误类型、报告的说服力与正确性可以完全脱钩。

核心洞察：**金融工作的正确性可以分解为一组可程序验证的不变量，而"用户想要什么"可以密封为一个隐藏规格**。于是评测问题被抽象为一个"密封规格下的交付物验证"问题：

- **任务** τ = (p, b, c)：人设 p（用户是谁、怎么说话）、信念 b（用户真正想要的隐藏策略）、测试条件 c = (t_cut, A, T, Δ)（数据截止日、可用通道、最大轮数、每轮时限），随任务冻结以保证分数可比；
- **会话** h = (u₀, a₁, ..., aₙ)：用户以模糊请求开场，agent 每轮交出消息 mₜ 与交付文件 Fₜ（数据表、代码、回测结果、报告）；记录恰好一个结束原因 e；
- **交付物** D：只有用户收到的东西参与评分；执行日志 L 与工作区仅用于**检测违规**（如取了截止日后的数据）——只能让检查失败，不能让其通过；
- **判定**：接受 = 用户满意 ∧ 15 项否决全过 ∧ 评分完整；得分 = 预否决质量 Q × 否决通过指示。

### 3.2 这个抽象的精妙之处

1. **"密封规格"替代"参考答案"**：传统基准需要标准答案，任务因此必须固定且会腐烂；FinCosmos 只需一个规格，可从文法无限采样——评分不依赖参照物，任务供给不再稀缺；
2. **"不变量验证"替代"结果匹配"**：正确性不再是比较输出，而是检查"每个日期 ≤ t_cut""每个成交晚于信号""每个报告指标可从交付交易日志独立重算"这类数学事实——程序可判、无幻觉、抗博弈；
3. **"日志只减不加"**：执行痕迹只能提供反证，这堵住了"过程分"与"结果分"混淆的漏洞，也与"用户只看交付物"的现实对齐；
4. **"用户满意"被降格为必要条件而非充分条件**：满意度只是 AND 链上的一项，程序否决保留最终否决权——这是对"用户被说服 ≠ 交付正确"这一金融特有风险的直接形式化。

## 四、问题解法

FinCosmos 由三大组件构成：策略生成器（出题）、用户模拟器（密封与守题）、评估器（判卷与反馈）。隐藏策略对 agent 完全密封：只有模拟器和评估器可见，任何反馈不得泄露。

### 4.1 策略生成器：组合文法出题

- **六组件策略空间**：选股（四族因子：基本面/技术/信息/生物科技事件，加等权、IC 加权、双重排序、梯度提升四种组合法）、择时、组合构建、风险控制、执行、交易成本。每个组件取一个选项及参数，形如 b = ((o_k, θ_k))，一致性规则 C 剔除不合理组合（如风险平价必须指定协方差估计器），得 |B| ≈ 3.8×10⁶ 种策略（参数值之前）；
- **难度标注**：每个选项带难度 δ(o)∈{0..3}，策略难度为各组件之和，用于任务分层；
- **种子化采样**：每次采样可复现，发布基准冻结种子 0–9 的前十个任务供排行榜使用，饱和或泄漏后可再抽新。

类比：这不是题库，而是一台**出题机**——像自动出题系统按语法生成数学卷，而不是反复用同一份卷。

### 4.2 用户模拟器：考官式的"问才说"

模拟器把"用户是谁"（人设）与"用户想要什么"（信念）分离。人设池三类：散户投资者（术语用得自信但常不精确）、全科分析师（中性专业，追问回撤/换手/夏普）、生物科技专家（重行业行话，以催化剂、FDA 决策事件思考）。人设提示词**禁用评测词汇**（如 point-in-time、cutoff）——用户用大白话说"数据只能用到 2026 年 9 月 4 日"，但绝不说"这会被检查"。

**披露策略**是灵魂设计。设信念陈述项全集 H（每个选项与参数值一项），开场请求只含 O ⊂ H 且 |O| ≪ |H|；此后用户只说 agent 问到或提议到的项：Sₜ\Sₜ₋₁ ⊆ Q(aₜ)。配套五条规则：(1) 开场只给一个模糊想法；(2) 只答所问，没问的"想不起来也不主动说"；(3) 问具体值就直接给；(4) 提议冲突时反对并说想要什么；(5) 交付偏差时只点名错的那块（如"仓位那部分不对"）而不复述策略。因此 **agent 只能靠问对问题学到策略**。信念中未陈述的参数（如波动率估计窗口）不计入 H，agent 不对此负责。

**可信性护栏**：每轮模拟器输出结构化决策（动作 + 每个目标的观察 + 下一句消息），程序先验证再发出——目标未观察、达标无引用、核心目标未满足就关闭、无证据挑战、使用内部词汇、复读等都会被拒绝重生成（至多六次，仍失败则会话作废不计）。用户只有当每个核心目标都有引用证据支撑（回测报告的收益/夏普/最大回撤/交易数可追溯到交易日期与价格，报告覆盖摘要/方法/结果/局限）才能满意关闭。

**与既有工作的关键区别**：鉴于 LLM 模拟用户保真度有限（成功率随模拟器模型漂移；更强的助手反成更弱的模拟器；没有 LLM 能忠实复现个体投资者决策——Lost in Simulation、Flipping the Dialogue、MILA 的发现），FinCosmos **不把模拟器当"真人替身"，而当"按固定规则披露隐藏策略的考官"**，并用人类专家双盲验证其行为（见 4.4 与第五部分）。

### 4.3 评估器：程序为主、LLM 为辅、无参考判卷

- **45 维度、七类打分**：数据（6 维 1 否决）、策略（12 维 7）、回测（8 维 4）、评估（5 维 1）、用户体验（6 维 2）共 37 个计分维度，每维 0–4 锚定量表；成本（3 维）与过程透明（5 维）只报告不计分。程序判 17 维，LLM 判 19 维，混合 6 维，成本 3 维直接测量；
- **程序约束 LLM**：凡有程序对应项的 LLM 分数取下界 s = min(s_LLM, s_P)——例如"专业度"不得超过"声明依据的指标占比"程序分，华丽话术封顶；
- **预否决质量 Q ∈ [0,100]**：五类各占 20 分等权（类内按适用维度平均），交付不可检查的维度计 0 分保留在分母；
- **15 个否决维度 V**：point-in-time 严格性（1.1）、六个策略组件保真（2.1–2.6，阈值 <2 否决）、策略歧义（2.7）、回测 point-in-time 正确性（3.1）、独立重算（3.2）、验证器审计（3.7）、过程完整性（3.8）、有据结论（4.1）、对话体验（5.1）、内部泄漏（5.6）。得分 Score = Q·pass，接受 AC = pass·1[e=satisfied]·1[评分完整]——精装报告藏不住漏数据的回测，而 Q 保留了否决抹掉的部分分；
- **四组关键检查**直指三类静默失败：
  - *数据溯源*：每条序列须可追溯到 URL 或带查询参数的 API 调用，不可溯源不计分；程序还测缺失值、缺口、重复、陈旧价格、异常值；
  - *Point-in-time*：不藏未来数据，守时是 agent 的责任——交付数据中任何一行日期 > t_cut 即整场否决；每笔成交须晚于其信号日，入场用基本面须在入场日前公告；
  - *独立重算*：不信任报告的净值曲线，程序从交付交易日志（或权重日志+价格）重建收益并逐指标比对（容差：收益/回撤 0.02、夏普 0.5）；缺交易日志或价格序列直接否决；
  - *策略保真与引导*：逐组件比对 H_k 中每项与 D，主张须有交付物内引文支撑、后撤回可抵消前主张；未问出的缺失项（M_k ⊆ H\S）只把分数封顶在 2，**用户说过却缺失的项封顶 1 并直接否决**——不问不给满分，但不因"没聊到"而判死；
- **泄漏无关反馈**：会话结束后 agent 收到每维的分数、来源与证据；但数据与策略两类的**理由会泄露 b**，故只给分不给理由（唯一例外：point-in-time 严格性，只依赖 t_cut）。程序判分逐轮进行形成轨迹分；每分带评估器版本与评分代码哈希，评估器升级后结果仍可比较。

### 4.4 实验设置与人类专家研究

- **被测对象**：四个通用编码 agent——Claude Code（Claude Opus 5.5）、Codex（GPT-6.1 Sol）、Gemini CLI（Gemini 3.8 Flash）、Kimi Code（Kimi K3，开源权重），各携自带 harness 与工具，记忆关闭；外加裸模型基线（Claude Opus 5.5 无工具）。每个 agent 对十个冻结任务各做三次独立会话，共 150 会话；
- **环境**：沙箱统一运行时与提示；配 Financial Modeling Prep MCP 服务器（247 个常用金融 API）；搜索与抓取由各厂商提供；每会话至多六轮、每轮 300 秒。十个任务均为美股交易（从小篮子到板块或全市场）；
- **模拟器与评委**：模拟器为 Claude Opus 4.8（低推理努力），评委 Claude Opus 5.5；为限制评委模型偏差，数值与时点性质全部由程序重算，并以人类专家研究校准；
- **专家研究**：两位未参与建设的金融专家独立标注后讨论消歧：(1) 模拟器保真——逐条用户消息标为无错/任务良性/任务致命；(2) 评委一致性——在校准集上按评委锚定量表给四个 LLM 否决维度打分；(3) 失败归因——对每个失败会话判定首个关键错误来自 agent、模拟器还是评估器。

### 5.2 主结果：零接受

**150 个会话，接受率 0%，所有 agent 的所有 pass^k 均为 0。** 预否决质量（0–100，95% bootstrap 区间按任务计算）：

| Agent | 满意率 | 接受 | 质量 Q | 数据 | 策略 | 回测 | 评估 | 体验 | 均失败否决 | 会话成本 |
|-------|-------|------|--------|------|------|------|------|------|-----------|---------|
| Claude Code | 30% | 0 | **37.1** [27.8, 45.0] | 44.7 | 38.2 | 26.9 | 23.2 | 52.2 | 7.4 | 1.13M tok / $2.24 |
| Codex | 33% | 0 | **37.2** [30.6, 43.3] | 45.8 | 33.4 | **31.9** | 17.2 | **57.6** | 7.2 | 3.20M tok / $0.80 |
| Gemini CLI | 33% | 0 | 22.2 [16.9, 27.4] | 25.3 | 30.8 | 15.6 | 7.0 | 32.4 | 9.3 | 3.51M tok / $0.80 |
| Kimi Code | 20% | 0 | 22.3 [14.3, 31.6] | 26.8 | 23.4 | 16.5 | 6.5 | 38.2 | 10.1 | 0.89M tok / $0.83 |
| 裸模型 | 0% | 0 | 20.2 [18.8, 21.5] | 0.0 | **49.8** | 4.6 | 1.8 | 44.6 | 9.1 | 0.01M tok / $0.24 |

要点：Codex 与 Claude Code 质量不可区分（配对置换检验 p=0.99）；Codex 显著高于 Gemini CLI 与裸模型（Holm 校正后 p=0.02）；Gemini CLI、Kimi Code 与**毫无工具的裸模型无显著差异**（p≥0.44）。裸模型的分数全部来自策略描述（49.8）与用户体验（44.6）——"会聊天 ≠ 会交付"，数据类 0 分、回测类 4.6 分戳破了流畅对话的假象。120 个 agent 会话中 77 个用户不满离场、8 个到轮数上限；70% 的轮次撞上 300 秒时限——时间是硬约束。成本与质量脱钩：Codex 每会话读 320 万输入 token（约为同等质量 Claude Code 的三倍）；Claude Code 按 API 价最贵（$2.24 vs 约 $0.80）。

### 5.3 静默失败：用户满意的会话全军覆没

模拟用户在 **35/150（23%）的会话中表示满意，而这 35 个会话无一通过程序检查**——满意度与正确性彻底脱钩。具体死因：29 个未交付交易日志或价格序列（收益无从重建）；15 个用了截止日后数据或先于信号成交；15 个交付的策略不是用户的；33/35 至少踩中这三类之一（两项严格完整性检查 3.7/3.8 在几乎全部会话失败，剔除后 150 中仅 2 个会被接受，均为 Codex，但其收益仍与报告不符）。这些会话**格外有迷惑性**：预否决质量 50.8 vs 其余 21.0（p<0.001），用户体验分 69.6 vs 35.0。若只用 LLM 评委裁量的四个否决（2.7/4.1/5.1/5.6），17/35 会被接受，总接受率将从 0% 变 11%——**换评分员不仅改数字，还改排名**：按用户签字 Gemini CLI 以 10/30 并列第一，但其满意会话一个都过不了 LLM 否决（Fisher 精确检验 p<0.001）；Codex 保住 8 个（p=0.005）。报告数字亦不可查：对 agent 自己的净值曲线，35 个满意会话中 10 个指标吻合、11 个自相矛盾、12 个连曲线都不交。论文图 1 的 Kimi Code 实例：用户要短期反转（押注近期输家），模型却按 21 日动量反向下注、把催化剂临近换成财报意外；报告称最大回撤 −18.96% 且"已从交付净值曲线重算"，而该曲线上实际回撤 −21.91%——已击穿用户要求的 20% 止损线；该会话质量分 47.9，用户满意。**用户若据此下单，是在为不存在的业绩押注本金。**

### 5.4 断裂点：工作流两端 + 引导短板

四步工作流漏斗（120 个 agent 会话）：交付用户策略 **25** → 且守截止日 **15** → 且无前视 **14** → 收益可复现 **0**。两端最脆：只有 25/120 交付了用户的策略，而没有任何一个会话的成交记录能复现其报告收益（Codex 有 5 个可部分重建，得分仅 1/4）。裸模型靠"能描述计划"在第一步拿下 9 个，与 agent 持平，但后续全部为零。引导数据：平均每个信念陈述 6.7 项，开场只给 2.6–3.7 项，会话结束时用户说出 4.5–5.4 项——**agent 仅问出未告知细节的 54–64%，未被告知的细节 66–83% 被做错**。多问有用：澄清覆盖率与质量相关（Spearman ρ=0.25, p=0.007）。组件保真否决失败率：选股最高 52%，歧义否决（每条规则须有唯一定义）68%，而交易成本（只有"无/固定费率"两选项）仅 9%。逐轮轨迹：失败否决从第一轮后的 5.3 缓降至第六轮后的 3.8；仅 58/120 会话撑到第四轮，提前结束的 62 个中 51 个是用户离场。难度有效：质量随任务难度下降（ρ=−0.24, p=0.007），难度 ≤10 的任务均分 41.6，≥15 的任务 26.6。

### 5.5 基准可信性：专家双盲验证

150 会话全部有效（2 次评分故障按原条件重跑）。60 个抽样会话（四 agent 各 13 + 裸模型 8）双盲标注：两位专家在同样 3/60 的会话中发现任务致命级模拟器错误（多为 agent 还在干活用户就收摊——抽样 41 个用户离场中至多 3 个属提前离场，5.3 节的大量离场主要反映 agent 停滞而非用户暴躁）；失败归因 **53/60（88.33%）于 agent**、3（5%）于模拟器、4（7%）于评估器——零接受反映的是 agent 而非基准。评委可靠性：LLM 评委与专家 κ=0.87，逼近两位专家之间的一致性 κ=0.93——**评委在其所判维度上是可靠的，静默失败之所以漏过，是因为它们根本不显露在评委能读到的对话与报告里**，只有对交付物的程序检查能抓住。

### 5.6 可解性：从反馈中学完十题

"Claude + Memory"配置（Claude Code + 跨会话持久记忆，每次评分后一个复盘步骤读泄漏无关报告与逐轮程序分、编辑记忆）练习十任务：**首试零通过（首会话中位失败 8 个否决），最终十任务全部达到接受，中位 34.5 个会话/任务（范围 12–132，共 506 个），每个接受会话通过全部 15 项否决**；中位任务前五个会话场均失败 6.3 个否决、临接受前五场降到 2.6 个。整个练习期模拟用户中位满意率 34%——远早于交付物通过否决，再次坐实满意度-正确性鸿沟。155 个学习步骤中 115 个（74%）实际编辑了记忆（平均 4.5 处/步），agent 由此学会评估器要求的交付形态：带成交价的交易日志、六组件规格表、带数字的诊断。最后清掉的否决最常见是策略歧义（2.7，占 6/10 任务；其在接受前 496 会话中失败 77%，在恰好只挂一个否决的 42 个会话中占 28 个）——其失败理由按泄漏无关规则不予反馈，agent 必须从用户的措辞中自行推断。**泄漏无关约束下从反馈学习是可行的，FinCosmos 同时提供了这个闭环及其度量。**

## 六、效果优势的根源解释

本文的"效果"是基准的判别力与可信性（而非某方法的 SOTA 分数），因此根源解释围绕三个问题：为什么关闭世界会系统性漏掉静默失败？为什么程序否决比满意度和 LLM 评委更可信？为什么 agent 恰好断在工作流两端？

### 6.1 根源机制与证据链

**因果链 1：关闭世界 → 删除失败模式 → 分数虚高且不可迁移。**
机制：意图/数据/时间线每关闭一处，对应失败的发生条件即被移除——喂了精选数据就不会有幻觉数字，说明全部任务就不会做错方向，环境管住时间就不会偷看未来（论文实验已支持：Table 1 十个基准逐一对应；本文裸模型对照组亦旁证——去掉工具即令数据分归零）。推理：这不是评测疏忽而是结构性盲区，故 FinCosmos 的贡献是**把失败的发生条件保留下来**（阅读者归纳，论文引言与 Table 1 已隐含此论证）。

**因果链 2：交付物不变量 + 程序重算 → 评分不可博弈且跨评分员稳定。**
机制：满意度与 LLM 评委只读对话与报告——恰恰是 agent 生成质量最高的表层；程序检查读交易日志与价格序列——agent 最不在行的底层数据结构。两者读的信息集不相交，故 35 个满意会话中 29 个因"无交易日志可重算"被程序一票否决，而 LLM 评委本会放行其中 49%（论文实验已支持，5.2 节反事实重算）。评分设计上 min(s_LLM, s_P) 的下界结构保证任何话术性维度不得超越其程序对应物（设计论证，实验由维度分矩阵图 4 佐证）。

**因果链 3：agent 断在两端，源于两端的能力缺口而非难度累积。**
机制：起点（elicitation）要求 agent 主动补全信息缺口——而当前 agent 训练目标偏向"给定请求尽快交付"，54–64% 的澄清覆盖率与 66–83% 的假设率正是不主动提问的直接后果（论文实验已支持：澄清覆盖与质量相关 ρ=0.25；中间步骤单独过半说明并非单纯难度累积）；终点（可复现交付）要求把叙述性结论降维为可重算数据结构（带成交价的交易日志）——这是报告写作训练分布之外的格式纪律（论文实验已支持：零会话通过第四步，学习实验中记忆编辑内容恰为交付形态知识）。"30 秒说不完的需求 ≠ 30 秒写得完的报告"，两端断点的对称性提示这不是算力问题而是行为惯性问题（阅读者推测）。

**反事实推理**：若去掉程序否决只看满意度，接受率 0%→23% 且排名重排（Gemini CLI 登顶）——程序否决的必要性得证；若去掉泄漏无关约束，agent 可从反馈直接读出隐藏策略而"学会"任务，评测退化为记忆任务（论文以设计保留该约束，学习实验证明约束下仍可学习，反证该约束在评测有效性与学习信号之间取得了可行平衡）。

| When Alpha Disappears (arXiv:2605.23959)、Can LLMs Catch a Rigged Backtest (arXiv:2609.28090) | 回测泄漏测量与 LLM 审计 | 逐项 convention 切换量化膨胀；LLM 审计员误标干净回测 | 审计固定管线 | 支持"审计员不可全信、不变量程序检查更稳"，与 FinCosmos 的 3.1/3.2 检查互证 |

### 6.3 综合判断与未决问题

**多项研究共同支持的机制**：(1) LLM 评委单独用于 agent 评分有系统性风险（MT-Bench 线 + 本文反事实 + 严谨基准方法论）；(2) 已实现收益/回报型指标系统性高估 LLM 金融 agent（Profit Mirage + KDD 2026 长周期研究 + 本文不采收益评分的设计）；(3) 隐藏意图 + 模拟用户技术上可行（τ 系列）。**仍属合理猜测的机制**：agent 两端断裂的"行为惯性"解释（训练分布偏向尽快交付 vs 主动提问）——论文数据（澄清覆盖与质量相关、中间步骤过半）与其一致但未做干预实验；程序否决的跨任务集稳健性（十个任务的宽置信区间是明示的局限）。**适用条件**：结论成立于 long-only 美股、固定成本模型、300 秒/轮时限内——更长时限可能改善终点断裂（论文自述 70% 轮次超时）；模拟器/评委/一个被测 agent 同属 Claude 家族，程序检查与专家标注缓解但不能根除同源偏差。**可能的失效条件**：若未来 agent 学会"为评测而交付交易日志"的形式合规而无实质正确（Goodhart 风险），程序不变量的判别力将衰减——这正需要文法源源不断地抽新任务与不变量组扩展来对抗。

## 七、必要知识反推

假设让一个没有背景的人重做这项工作，最少需要掌握什么？

### 7.1 领域知识层（金融运作机制）

- **量化策略的组件化分解**：不知道策略可拆为选股/择时/组合/风控/执行/成本六件套，就无法构造既丰富又可判定的策略文法——这是"出题机"的领域根基；
- **Point-in-time 纪律**：不理解"决策只能用当日公开信息"、财报公告日与报告期之别、Web 数据的事后修订，就设计不出逐行日期检查与"成交晚于信号"这类不变量；
- **回测报告的行业标准交付物**：不知道收益/夏普/最大回撤/交易数应可追溯到交易日期与价格，就定不出"独立重算"的目标形态；
- **回测过拟合与泄漏谱系**：不了解 Bailey 以来的偏差研究，就无法论证"为什么已实现收益不能当评分"。

### 7.2 方法论知识层（评测科学与 agent 研究）

- **模拟用户评测范式**：不熟悉 τ-bench 的 pass^k、目标状态打分及其封闭世界局限，就找不到"考官式模拟器"这一差异化定位；
- **LLM-as-judge 的偏差文献**：不知道位置/自我偏好偏差与博弈风险，就不会把程序分设为 LLM 分的下界，也不会做"换评分员"反事实；
- **任务集饱和/污染问题**：不了解 LiveBench 的应对，就不会想到用种子化组合文法按需出题；
- **统计检验**：配对置换检验、Holm–Bonferroni 校正、bootstrap 区间、Cohen's κ、Spearman 相关——150 会话的小样本结论全靠这些工具守住显著性。

### 7.3 工程知识层（系统实现）

- **MCP/工具服务集成**：247 个金融 API 的接入与统一沙箱运行时，是"开放数据"从口号变为可复现环境的前提；
- **多智能体编排与护栏**：模拟器的结构化决策 + 程序验证再生成（六次重试、失败作废）是把"不可靠的 LLM 用户"驯化为"守规则考官"的关键工程；
- **可复现性工程**：种子化采样、评分代码哈希、评估器版本随分存档——评测基础设施自身的版本治理；
- **泄漏控制**：leak-free 反馈的按类别屏蔽策略（哪些理由会暴露 b、哪些不会），是学习闭环能成立又不毁掉评测有效性的精细权衡。

### 7.4 知识融合的关键节点

1. **"密封规格"洞察**：把"用户脑子里没说出口的策略"（金融常识）与"文法生成任务"（NL 方法论）融合——评测不再需要参考答案，任务从稀缺品变消耗品；
2. **"考官式模拟器"洞察**：把模拟用户保真度文献的负面结论（模拟器不可靠）转化为设计约束（不做真人替身，做规则披露者，程序验证每一步）——缺陷文献变成护栏说明书；
3. **"不变量优先评分"洞察**：把量化金融的 point-in-time 纪律翻译成 agent 交付物上的程序检查——领域风控知识成为评测的评分函数；
4. **"满意度降格"洞察**：把 35/35 满意会话全灭的实证与"用户被说服 ≠ 交付正确"的金融直觉融合成 AC 的 AND 结构——这是全文最反直觉也最重要的评分设计。

## 八、论文中可以提取的通用性灵感

### 灵感 1：评交付物上的不变量，不评叙述质量（信号利用类）

- **核心思想**：让"正确"成为可程序重算的数学事实（每行日期、每笔成交、每个指标），把评分从语言层下沉到数据结构层。
- **论文证据**：35 个满意会话中 29 个因无交易日志/价格被否决；LLM 评委本会接受其中 49%；min(程序, LLM) 的下界结构。
- **推广场景**：(1) 法律科技——合同 agent 交付的条款集可被规则引擎逐条验证而非看文书流畅度；(2) 数据分析——BI agent 的结论必须附带可重跑的查询与中间表；(3) DevOps——变更报告须与实际 diff/日志逐项对账；(4) 医疗文书——结构化字段与原始检查值可交叉复算；(5) 学术复现——论文附代码的"可复现性审计"。

### 灵感 2：密封规格 + 问才披露，把"需求澄清"变成一等被测能力（范式迁移类）

- **核心思想**：把需求藏在模拟干系人手里、按固定披露策略只答所问，让"会不会问"与"会不会做"同权重进入评测。
- **论文证据**：澄清覆盖率 54–64%、假设率 66–83%、覆盖率与质量相关 ρ=0.25；歧义否决失败 68% 且是学习中最难清掉的最后一关（6/10 任务）。
- **推广场景**：(1) 产品经理 agent——从模糊商业想法引导出 PRD；(2) 心理咨询辅助——逐层澄清而非默认假设；(3) 定制旅行规划——隐藏偏好（预算/恐惧症/饮食）问完再排程；(4) 法律咨询 intake；(5) 企业内部 IT 工单——从"系统坏了"问出复现步骤。

### 灵感 3：换评分员做反事实——基准要自带"评分方式敏感性"报告（机制类）

- **核心思想**：任何评测都应回答"如果用另一种评分方式，结论和排名会怎么变"；敏感性本身就是基准质量的诊断指标。
- **论文证据**：满意度 → 23% 接受、LLM 否决 → 11%、全否决 → 0%，且 Gemini CLI 与 Codex 的名次随评分员互换。
- **推广场景**：(1) 推荐系统离线评测——点击率 vs 留存 vs 人工评分的多评分员对比；(2) 代码生成——测试通过率 vs LLM 评委 vs 人工审查的三方敏感性；(3) 招聘测评——结构化面试 vs 情境判断的评分员方差披露；(4) 医疗诊断 AI——按灵敏度 vs 按患者结局的评分分歧报告。

### 灵感 4：任务供给从题库改为生成器（紧凑性类）

- **核心思想**：用组合文法 + 一致性约束 + 难度标注生成任务，按需采样、种子复现，评测集从"资产"变"水流"。
- **论文证据**：六组件空间约 3.8×10⁶ 种策略（参数之前），种子 0–9 冻结十个任务，难度与分数显著相关（ρ=−0.24, p=0.007）验证了难度标注有效。
- **推广场景**:(1) 安全渗透测试——攻击面文法生成测试用例；(2) 教育测评——知识点组合自动出卷与等值化；(3) UI 回归测试——组件组合文法生成页面流；(4) 合规检查——监管规则文法生成交易场景。

### 灵感 5：泄漏无关反馈让"考题密封"与"学习闭环"共存（机制类）

- **核心思想**：反馈可以给分数不给理由（或按信息泄露风险分类屏蔽理由），学习者被迫从可观测行为推断缺失知识——评测有效性与可学习性不必二选一。
- **论文证据**：数据/策略类只回分数不回理由（唯一例外 point-in-time 严格性）；Claude+Memory 在此约束下学完十任务（中位 34.5 会话），最难清掉恰是理由被屏蔽的歧义否决（2.7）。
- **推广场景**：(1) 编程训练平台——只给测试结果不给用例，逼学习者归因；(2) 安防红队演练——只报攻击成功不报路径；(3) 医学模拟问诊——只给诊断对错不给病灶提示；(4) 战术推演——只报战果不报对方部署。

### 灵感 6：用户满意只是必要条件，不是充分条件（关注点分离类）

- **核心思想**：把"体验质量"（UX 分、满意度）与"实质正确"（否决项）解耦为 AND 关系而非加权混合——好体验不得为错误买单。
- **论文证据**：AC = pass·1[satisfied]·1[完整]；满意会话 UX 分 69.6 vs 35.0 却全灭；裸模型策略分 49.8、体验分 44.6 而数据分 0。
- **推广场景**：(1) 客服自动化——满意度与工单实际解决率双门槛考核；(2) 自动驾驶 HMI——驾乘舒适度与安全边界分列；(3) 搜索引擎——用户点击与事实准确性分离计分；(4) 保险理赔自动化——客户好评不得掩盖赔付规则违规。

### 灵感 7：让执行日志只能"减分"不能"加分"（信号利用类）

- **核心思想**：过程痕迹仅作违规反证、不计入功劳，杜绝"表演性过程分"，使评分对齐真实用户的视角（只看拿到什么）。
- **论文证据**：交付物 D 是唯一评分对象；日志 L 与工作区"只能让检查失败，不能让其通过"；cutoff 后痕迹（7.3）属只报告维度。
- **推广场景**：(1) 远程办公产出评估——看交付不看在线时长；(2) 机器人流程审计——日志仅用于违规检测；(3) 学生项目评分——只评作品，过程记录仅查抄袭；(4) 供应商验收——只验货，产线视频仅用于质检追溯。

### 灵感 8：专家归因把"零分"从坏消息变成基准可信性证据（机制类）

- **核心思想**：当所有被测者得零分，评测方必须用外部证据（专家双盲归因、评委-专家 κ、模拟器错误率）证明零分来自被测者而非基准——基准的失效模式分析应内置于发布。
- **论文证据**：88.33% 失败归因于 agent（53/60）、评委-专家 κ=0.87（专家间 0.93）、模拟器致命错误仅同样 3/60 个会话。
- **推广场景**：(1) 新面试题启用前的区分度与效度验证；(2) 竞赛评测器发布前的 gold-set 校准；(3) 自动评分系统附带人工审计报告；(4) 医疗 AI 零召回事件的第三方归因流程。

## 附录：一句话总结

FinCosmos 用"密封的文法策略、问才说的模拟考官、程序不变量判卷"三件套，把金融 agent 最危险的失败——**用户满意地收下了一份错的东西**——第一次变成了可测量、可复现、可学习的对象：150 会话零接受不是 agent 的终点，而是可信性评测的起点；中位 34.5 个会话学完十任务则证明，只要反馈设计得当，这个缺口是可以闭合的。
