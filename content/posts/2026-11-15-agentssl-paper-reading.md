## 一、论文背景

### 1.1 半监督学习是什么

机器学习模型靠两类昂贵投入运转：**标注数据**（给样本打标签，医学影像要医生看图，野生动物视频要生态学家逐帧画框）和**人力工程**（设计网络结构、数据增强、训练策略等"归纳偏置"）。现实中两者的稀缺形态常常不对称——**标签很贵，但原始数据不要钱**：医院有海量未诊断的影像，野外相机陷阱拍了几十万段视频。**半监督学习（Semi-Supervised Learning, SSL）** 研究的就是如何用一小撮标注样本（记作 L）加一大堆无标注样本（记作 U）训练出好模型。

SSL 几十年的研究积累了两大主流套路，理解它们是读懂本文的前提：

- **伪标签（pseudo-labeling）**：先用标注数据训一个初步模型，让它对无标注数据打分，把预测置信度高的样本当作"伪标注样本"加入训练——相当于模型自批作业再自学；自训练（self-training）是它的迭代加强版。
- **一致性正则（consistency regularization）**：假设"同一张图做轻微扰动后，模型预测不该变"——翻转、裁剪后的猫还是猫，据此约束模型在无标注数据上保持稳定输出。

FixMatch（[arXiv:2001.07685](https://arxiv.org/abs/2001.07685)，NeurIPS 2020）把两者组合成名震一时的配方：弱增强产伪标签、置信度阈值过滤、强增强上做一致性训练。后续 SoftMatch（[arXiv:2301.10921](https://arxiv.org/abs/2301.10921)，ICLR 2023）把硬阈值改成截断高斯的软权重，缓解"阈值高了丢弃正确标签、低了放进错误标签"的数量-质量权衡。

### 1.2 SSL 的老毛病：脆、难部署

SSL 方法在 CIFAR 等经典基准上很漂亮，但**对"数据分布是否符合算法假设"极其敏感**——聚类结构是否存在、增强一致性是否成立，换个领域就可能全盘失效，因此每个新数据集都需要大量针对性调参。学界对此早有清算：Oliver 等人的经典论文指出，深度 SSL 的漂亮结果依赖充足的标注验证集来调超参，验证集一缩水优势就缩水（详见第六部分交叉验证）。于是"**在一个新领域部署 SSL**"本质上成了一场在设计空间里的搜索：图传播、伪标签、一致性正则……选哪个、怎么组合、超参多少，都是难题。

### 1.3 另一边：MLE Agent 崛起，但只会"全监督"

与此同时，**MLE Agent（机器学习工程智能体）** 兴起：让 LLM 自动画出并迭代改写完整的训练代码，靠执行反馈驱动。OpenAI 的 MLE-Bench（[arXiv:2410.07095](https://arxiv.org/abs/2410.07095)）用 75 个 Kaggle 竞赛测这类 agent，一年内头部 agent 的百分位排名从 45.2% 飙到 83.1%（AIRA_2，arXiv:2603.26499）。Meta FAIR 的 AIRA 系列工作（[arXiv:2507.02554](https://arxiv.org/abs/2507.02554)）进一步把 agent 形式化为"搜索策略 + 程序变换算子"，在 MLE-bench lite 上把奖牌率从 39.6% 推到 47.7%。

但这些基准几乎全部假设**标注数据充足**——Kaggle 竞赛动辄数千到数百万带标注的训练样本。于是出现一个刺眼的空白：**agent 在"标签稀缺、无标注数据过剩"这个更真实的场景下还能干活吗？** 这正是本文标题的疑问：MLE Agents 能不能用好无标注数据？

两条线合起来看：SSL 需要大量人工调参 → 调参本身就是程序搜索 → 搜索正是 agent 的强项。AgentSSL 由此而生。

## 二、论文定位和关联工作

### 2.1 谱系一：自动机器学习（AutoML → LLM Agent）

| 阶段 | 代表工作 | 核心思想 | 局限 |
|---|---|---|---|
| 传统 AutoML | 超参优化（Optuna）、流水线搜索（TPOT）、神经架构搜索 | 在**人工预设的搜索空间**里做优化 | 空间与目标函数都需大量人工指定 |
| LLM 程序搜索 | AlphaEvolve、AIDE、ML-Master、MLE-Star、AIRA | 在**可执行程序空间**里提议-执行-调试-改写 | 评测几乎全在标注充足的全监督设定 |
| **本文（AgentSSL）** | AIRA-Dojo 之上的 SSL 任务接口 | 程序空间 = 全部 SSL 学习流程，反馈只有弱信号 | 首次系统研究标注稀缺下的 agentic 搜索 |

### 2.2 谱系二：SSL 方法与无监督模型选择

- **经典/深度 SSL**：图传播、低密度分离（转导 SVM）等经典范式；Π-Model、Mean Teacher、FixMatch、SoftMatch 等深度方法——它们构成 agent 搜索的"原料库"，也是本文的对比基线。
- **基础模型时代 SSL**：FineSSL、PET、V-PET（[arXiv:2503.09707](https://arxiv.org/abs/2503.09707)，NeurIPS 2025）。V-PET 是本文实验协议的直接来源：它发现"仅用标注数据做参数高效微调（PEFT）常能打平传统 SSL"，进而提出集成多个 VFM-PEFT 伪标签的自训练方案，并设计了用无监督指标集成做无标签超参选择的协议。**本文的 agent 就在被要求打败这套最新人类工程。**
- **无监督模型选择**：用无标签统计量替代标注验证集——聚类指标（AMI/ARI/Silhouette 等）、表征有效秩 RankMe（[arXiv:2210.02885](https://arxiv.org/abs/2210.02885)，ICML 2023）、批核范数 BNM 等，在无监督域适应与 SSL 中被用作验证准则，但可靠性依赖假设成立。
- **主动模型选择**：花少量标注预算主动询问"哪个模型最好"。CODA（[arXiv:2507.23771](https://arxiv.org/abs/2507.23771)，ICCV 2025）用贝叶斯共识建模把发现最佳模型的标注成本砍掉 70%。此前这类方法的候选池多为"同一流程不同超参"，**本文首次检验它们在架构、训练流程迥异的异质程序池上的表现。**

### 2.3 定位结论

AgentSSL 站在两条谱系的交点上：**用 MLE agent 的程序搜索去解决 SSL 的部署难题，并把"发现好程序"与"选对好程序"拆成两个独立研究对象**。之前的 SSL 工作只研究人类写好算法后的选择问题，之前的 agent 工作只研究标注充足下的发现问题——没有人同时研究过两者在标签稀缺下的耦合。

## 三、问题定义

### 3.1 核心抽象：SSL 部署 = 程序空间中的搜索

本文的第一个洞察是抽象层面的：不把 SSL 限制为"某个固定目标函数下的参数训练"，而是定义为**程序** $A:(L,U)\mapsto h$——一段吃进标注集 L 与无标注集 U、吐出预测器 h 的完整代码。这个定义涵盖了传统深度 SSL（训练 $f_\theta$），也涵盖图传播、最近邻、类原型等非训练式方案——后文会看到，正是这种开放性让 agent 发现了人类想不到的解。

### 3.2 关键分解：发现与选择是两个瓶颈

把"AgentSSL"形式化为程序空间上的 agentic 搜索后，作者做出本文最重要的切分：

| 阶段 | 输入 | 目标 | 评测指标 |
|---|---|---|---|
| **程序发现**（discovery） | L、U、弱反馈信号 | agent 迭代生成候选程序池 P | **Oracle 性能**：池中最优程序 $Q(A^*)$ 的测试精度 |
| **程序选择**（selection） | 候选池 P（无充足标注验证集） | 从中挑出要部署的那一个 | **选择遗憾**：$R_{sel}=Q(A^*)-Q(A_s)$，越低越好 |

这个分解的精妙之处在于：**Oracle 性能只衡量"好程序是否存在于池中"，与能不能挑出来无关**。于是"agent 搜索能力强不强"和"部署时选不选得对"可以分开测量、分开归因——论文后面所有结论（发现已超越人类、选择成为新瓶颈）都建立在这个可分离性上。

### 3.3 搜索过程的形式化

AgentSSL 搜索被定义为五元组 $(F,\pi_{sel},O,\pi_{op},M)$：适应度函数 $F$（反馈信号）、节点选择策略 $\pi_{sel}$（greedy / MCTS / 演化）、程序变换算子集 $O$（Draft、Debug、Improve、Analyze 四种）、算子选择策略 $\pi_{op}$、以及底座语言模型 $M$。搜索维护一个不断生长的有向无环图，节点是程序、边是变换。论文聚焦三个设计轴：**反馈信号**（无监督指标 vs 噪声验证）、**搜索策略**、**底座模型**——它们分别对应"评价、探索、生成"三类自由度。

## 四、问题解法

### 4.1 实验底座：AIRA-Dojo 上的 SSL 任务接口

AgentSSL 构建在 Meta 的 AIRA-Dojo 程序搜索框架上，新增 SSL 任务接口：agent 收到任务描述、小标注集 L、无标注集 U，产出可执行 Python 程序（实现 `fit(img_dir, train_ann, unlabel_ann)` 与 `predict()` 接口的 `ClassificationAgent` 类）。程序在隔离的 Apptainer 容器中执行，执行日志、报错与适应度分数回传给 agent 作为下一轮反馈。为保证与人类基线可比，搜索空间做了约束：只用 CLIP ViT-B/16 与 DINOv2-B 两种骨干、同一套 PEFT 库（LoRA / AdaptFormer / 冻结），并从一个简单的监督微调"热启动"程序开始，让 agent 专注探索 SSL 策略而非重建基础设施。

### 4.2 反馈信号：两种"弱裁判"

标注验证集稀缺是整个问题的前提，所以搜索期间的适应度只有两个便宜选项：

| 反馈 | 构造方式 | 优点 | 缺点 |
|---|---|---|---|
| **无监督指标（U）** | 8 个无标签统计量的集成：聚类指标 AMI/ARI/V-measure/FMI/Silhouette + 表征指标 RankMe + 判别指标 BNM/SND，各自归一化到 [0,1] 后取均值 | 完全不耗标签 | 与测试精度可能弱相关甚至负相关（KITTI 上 r=0.03、RETINO 上 r=0.08） |
| **噪声验证（N）** | 把小标注集切成 k 折做交叉验证（k 按数据集手调，如 DTD 3 折、CLEVR 5 折） | 与精度相关性通常更高 | 低标注下方差大；同样的负相关问题照样出现（KITTI r=0.12、RETINO r=0.09） |

关键设定：**agent 搜索期间看到的只是这个弱裁判的分数**，测试精度只在事后评估时才揭晓。这使得"发现"这一步本身就充满噪声——后文证据显示 agent 竟然扛住了。

### 4.3 搜索算子与策略

四种 LLM 算子驱动搜索图生长：**Draft**（按简单/常规/复杂三档生成新想法与实现）、**Debug**（只修 bug 不改思路）、**Improve**（在既有方案上做最小/中等/大幅改进）、**Analyze**（总结执行结果）。主实验用 greedy 策略（5 个初始草案、5 轮改进）；消融对比 MCTS 与演化搜索（100 代、每代 5 个体、交叉概率 0.5）。搜索预算按数据集规模分配：小数据集 8 GPU 小时、大数据集 15 GPU 小时，刻意与对应人类基线的调优成本挂钩。

### 4.4 选择阶段的两条出路

- **无监督选择**：用无标签指标（如 V-PET 的 rank 集成协议）给候选池排序取最优。
- **主动选择**：预算限定 `min(25, 类别数×每类训练图数)` 个标签查询，评测 IID 随机基线、ActiveTesting、VMA、CODA、ModelSelector 五种方法。为此作者把全部实验产物（agent 程序 + 人类基线，共 16,977 个已评估程序实例、35 个选择任务、逾一万 GPU 小时）打包成 **ProgramSelectBench** 公开 benchmark——把"选择"从昂贵的附带品变成一个可独立复现的研究问题。

### 4.5 生态学真实场景

最后在两个真实生态学检测流水线上检验迁移：WildFin（鱼类行为识别，专家画了 21,116 个框、耗 320+ 小时）与 BuckTales（无人机黑羚羊检测，约 24,000 框）。agent 只拿 10%/20% 的训练数据，与领域专家在同等数据和全量数据上的 YOLOv8 流水线对比；同时跑一个不给学生数据的 **AgentSL**（agentic 监督学习）作为"无标注数据到底值不值"的对照。

## 五、评估指标与实验证据

### 5.1 实验设置一览

| 要素 | 设置 |
|---|---|
| 数据集 | VTAB 协议 6 个：自然（DTD 纹理、SUN397 场景）、专业（RESISC45 遥感、RETINO 糖尿病视网膜病变）、结构化（CLEVR-Count 计数、KITTI 驾驶） |
| 标注规模 | 每数据集 2 档 shot（如 DTD 3/6-shot、RETINO 40/80-shot），共 12 个设定 |
| 随机性控制 | 每设定 3 个随机标注划分，agent 与全部基线在**相同划分**上配对评估 |
| 人类基线 | Supervised / FixMatch / SoftMatch / FineSSL / PET / V-PET 六种，按 V-PET 原协议调优（CLIP+DINOv2+LoRA） |
| 总算力 | 人类基线 7,628.7 GPU 时 vs agent 2,484 GPU 时（约为前者三分之一） |

### 5.2 主结果一：Oracle 下发现能力超越人类（Table 1 精选）

| 设定 | 最优人类基线 | 最优 agent 程序 | 差值 |
|---|---|---|---|
| RETINO 40-shot | 50.66 | 72.47（SSL_N） | **+21.81** |
| RETINO 80-shot | 54.37 | 73.47（SSL_N） | **+19.10** |
| KITTI 5-shot | 41.54 | 49.74（SSL_U） | **+8.20** |
| KITTI 10-shot | 45.66 | 53.45（SSL_U） | **+7.78** |
| DTD 3-shot | 65.83 | 68.94（SSL_U） | +2.91 |
| RESISC45 2-shot | 86.04 | 80.98（SSL_U） | −5.95 |
| CLEVR 20-shot | 66.83 | 52.81（SSL_U） | −13.92 |

12 个设定中 agent 在 8 个胜出、最高 +21.8 个百分点；且这是在 agent 总算力只有人类基线三分之一、反馈信号与测试精度相关性低至 0.03 的情况下取得的。分析章节进一步验证"确实用上了无标注数据"：固定最优程序、只增减无标注语料量，DTD/KITTI/RESISC45 的精度都随无标注数据增多而上升。

### 5.3 主结果二：选择是灾难性瓶颈（Table 2 精选，数值为跨种子平均遗憾）

| 选择方式 | DTD 3 | RESISC45 2 | RETINO 40 | RETINO 80 | CLEVR 10 | KITTI 5 |
|---|---|---|---|---|---|---|
| 人类基线池 + rank 无监督指标 | −3.39 | −1.93 | −23.92 | −42.66 | −15.59 | −9.10 |
| AgentSSL_N 按噪声验证选 | −0.67 | −10.38 | −38.12 | **−47.29** | 0.00 | −8.20 |
| AgentSSL_U 按无监督指标选 | −3.81 | −2.25 | −24.12 | −18.62 | −13.56 | −10.50 |

两个要点：其一，反馈指标与测试精度相关性好的地方（如 CLEVR 10-shot 噪声验证）遗憾几乎为零，相关性崩坏的地方（RETINO、KITTI）遗憾可达 47 个百分点——**摘要里那个刺眼的 47% 就是这么来的**；其二，人类基线池同样选不好（RETINO 80-shot 上 −42.66），说明这是 SSL 领域的老大难，不是 agent 特有的毛病。机制分析点出无监督选择的一个结构性盲区：很多 agent 程序复用同一套冻结表征、只改下游流程，此时**表征类指标对它们完全失明**。

### 5.4 主结果三：标签花在选择上比花在训练上值（Table 3）

固定总标注预算 B，对比"全部用于训练 + 无监督选择"vs"对半分：训练与主动选择"：

| 方法 | DTD | SUN397 | RESISC45 | RETINO | CLEVR | KITTI |
|---|---|---|---|---|---|---|
| IID（随机问询） | −4.71 | −0.83 | −3.47 | **+26.07** | −5.75 | **+10.01** |
| ActiveTesting | −2.35 | −1.17 | −2.61 | **+25.59** | −5.41 | **+10.46** |
| VMA | −1.86 | −1.47 | −7.68 | **+26.07** | −4.49 | **+14.43** |
| CODA | −2.50 | −2.09 | −0.87 | +21.22 | −29.09 | +14.63 |

（数值 = 对半分配 − 全量训练，正为赚）在无监督指标失效的 RETINO / KITTI 上，分一半标签给主动选择净赚 10~26 个百分点；在指标本来就好的数据集上则小亏 1~5 个百分点——**选择的价值取决于无监督指标是否失灵**。ProgramSelectBench 上的更大规模评测还发现：随机 IID 基线意外地强且方差低；CODA 确定性收敛快，但标签一多反而可能"翻车"（RETINO 某任务 40 个标签后突然选了差 30% 的程序）。

### 5.5 机制证据：agent 怎么用无标注数据的

- **策略谱系覆盖广且混搭**：LLM-as-judge 分类（经人工核验）显示 DTD 演化搜索的程序中伪标签占 70.5%、一致性正则 48.9%、自训练 39.5%，还有分布对齐、图方法、对比学习等十余类——agent 把几十年 SSL 文献当成了可自由组合的零件库。
- **程序间互补**：不同策略的高分程序给无标注子集打高置信伪标签的覆盖范围互不相同——候选池不只用于择优，还可以当互补伪标签生成器（呼应 V-PET 的集成思想）。
- **领域定制而非通用配方**：RETINO 最优程序根本不训练分类器——冻结 DINOv2 特征 + 最近邻证据 + 类原型 + 显式序数偏置（糖尿病视网膜病变等级本来就是有序的）+ 图传播式标签扩散，比次优基线高 19%；而跨数据集迁移实验显示最优程序换个数据集普遍掉分——agent 学到的是**为该领域量身定制的归纳偏置**。
- **消融**：GPT-5.4 与 Gemini-3.1 精度相当（前者略高），后者多样性更高；演化搜索多样性最高（DTD 0.66 vs greedy 0.37）、greedy 收敛窄但精度不掉——**设计选择主要改变搜索空间的走法，而非峰值**。

### 5.6 生态学案例：希望与泼冷水并存

| 任务 | 专家全量 | 专家 10%/20% | AgentSL | AgentSSL |
|---|---|---|---|---|
| WildFin mAP@0.5:0.95 | 47.9 | 35.4 | 43.3 | 42.0 |
| BuckTales | 36.2 | 28.1 | 27.7 | 29.8 |

WildFin 上两种 agent 用 10% 数据接近专家全量流水线（标注省 90%）；BuckTales 上高方差、不敌专家 YOLOv8。且 AgentSL 与 AgentSSL 两边都几乎打平——**无标注数据并非总是最值得榨取的资源**，有时把监督设计做好就够了。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**对比对象**：最强人类基线（V-PET 等）为何曾经有效？因为它们由专家把 SSL 文献中经过验证的组件按领域经验组装并全面调参——本质上是**一次高质量的人工搜索**。其根本局限在于：搜索被人类先验固化成单一配方，无法为每个新领域重新定制；且其调优依赖的无监督指标协议在假设不成立时同样失灵。

**因果链一：为什么 oracle 发现能赢（论文实验已支持）**

1. 程序空间开放（$A:(L,U)\mapsto h$ 含非训练式方案）→ agent 可以跳出"微调+伪标签"的常规套路，构造冻结特征+图传播+序数偏置这类领域定制方案（RETINO +19% 的直接证据）；
2. LLM 预训练吸收了数十年 SSL 文献 → 单次搜索就能触达十余个方法族并混搭（LLM-as-judge 统计：70.5% 伪标签 + 48.9% 一致性正则……）；
3. 搜索多样性独立于反馈质量 → 即便 fitness 与测试精度相关性只有 0.03，"广撒网"仍保证池中出现强程序——消融显示演化搜索多样性最高、精度不降，佐证**多样性是发现质量的主要来源，fitness 排序只是次要**；
4. 结果：oracle 性能 8/12 胜出，且算力仅三分之一。

其中第 3 步的"多样性保底"是阅读者根据消融与相关性数据推出的机制解释（论文未直接量化"多样性与 oracle 性能"的因果强度），标注为推测。

**因果链二：为什么选择成为新瓶颈（论文实验已支持）**

无监督指标各自编码假设（聚类结构、表征秩、判别多样性）→ 候选池异质化后假设失配面扩大（共享冻结表征的程序让表征类指标失明）→ regret 在指标-精度相关性差的数据集上爆表（47.29）→ 反之相关性好时遗憾趋零（CLEVR 0.00）。更深刻的一步是算力再分配实验：当选择是瓶颈时，标签的边际价值在"用于选择"高于"用于训练"（RETINO +25.59）——**瓶颈识别直接改写了资源最优配置**。

**反事实**：若去掉"程序空间开放"（只允许标准微调流程），RETINO 式非训练方案不可能出现；若去掉无监督指标集成只用单一指标，反馈失配会更普遍——两者均由论文的机制分析间接支撑。

### 6.3 综合判断与未决问题

- **多项研究共同支持的机制**：(1) LLM 程序搜索能产出竞争力方案（MLE-Bench/AIRA/AIRA_2 独立复现）；(2) 多样性驱动发现质量（AIRA 消融与 ideation 多样性研究同向）；(3) 少量标签用于主动选择回报高（CODA 与本文一致）。
- **仍属推测的部分**：多样性对 oracle 性能的因果强度未单独量化；"领域定制归纳偏置"目前主要靠 RETINO 单案例支撑。
- **适用条件**：优势在标注极稀缺（few-shot 级）且搜索预算与人类调优相当或更少时成立；当无监督指标与精度高度相关时，主动选择的标签再分配反而小亏；检测等非分类任务上迁移不稳定（BuckTales）。
- **失效条件**：候选池高度异质且共享表征时无监督指标失明；agent 越强、生成程序越多，选择缺口可能越大——论文明确警告"更强的 agent 不会自动关上这道门，反而可能把它撕得更大"。

## 七、必要知识反推

假设一个零背景的人要复现这项工作，最少需要哪些知识？

**领域知识层**

- SSL 全景：至少两大范式的原理与失效条件（不知道"序数标签"就不可能理解 RETINO 最优程序为何妙）；
- 基础模型与 PEFT：CLIP/DINOv2 特征的性质、LoRA/AdaptFormer 的含义——候选空间的技术底座；
- 无监督指标家族：八个指标各自度量什么、假设什么——选择阶段的弹药库。

**方法论知识层**

- 程序搜索框架：AIRA 的"搜索图 + 算子"抽象，以及 greedy/MCTS/演化的探索-利用权衡；
- 模型选择理论：无监督选择与主动选择的算法谱系（ActiveTesting/VMA/CODA/ModelSelector）；
- 实验设计：配对划分评估、oracle 与 regret 的可分离评测——本文结论可信的统计根基。

**工程知识层**

- 隔离容器执行不可信代码（Apptainer）、GPU 预算按基线成本缩放、k 折噪声验证的方差-算力权衡；
- LLM-as-judge 分类流水线及其人工核验——定性结论不注水的保障。

**知识融合的关键节点**

1. "SSL 部署 = 搜索"（领域知识 × 方法论）——把调参难题翻译成 agent 可解的问题；
2. "发现/选择可分离评测"（方法论 × 工程）——两个指标拆开，结论才归因得清；
3. "标签可再分配"（选择理论 × 实验设计）——把瓶颈诊断变成资源配比实验。三个节点都不是知识叠加，而是视角切换。

## 八、论文中可以提取的通用性灵感

**灵感一：生成变便宜后，瓶颈从"造"移向"选"**

- 核心思想：当候选生成成本坍缩（agent 写程序、生成式模型出方案），系统瓶颈转移到没有可靠验证信号的挑选环节，且生成端越强缺口越大。
- 论文证据：oracle 8/12 胜 vs 选择 regret 最高 47.29；结论一节明言更强 agent 会拉大缺口。
- 推广场景：代码生成（哪个 PR 能合并）、多模型路由（哪个模型答得对）、AI 科研假说筛选、自动化广告/文案投放选版、软件漏洞修复候选验证。

**灵感二：把"验证预算"当作可优化的稀缺资源**

- 核心思想：标注/评审预算不必全砸进训练（生产），分一块给验证（选择）在验证失灵时回报更高。
- 论文证据：Table 3 中 RETINO +25.59、KITTI +14.43，而指标健康处小亏——条件化配置而非一边倒。
- 推广场景：AI4Science 实验排程（合成 vs 表征验证）、招聘（培训投入 vs 面试成本）、内容平台（创作投入 vs 审核/AB 测试）、自动驾驶（训练数据 vs 路测验证）。

**灵感三：多样性是弱信号搜索的保险**

- 核心思想：反馈与目标弱相关时，别把宝押在精排（exploitation）上，保证候选多样性本身就能兜住解的质量下限。
- 论文证据：fitness 与精度 r 低至 0.03 仍 8/12 胜；演化搜索多样性最高、精度不降。
- 推广场景：推荐系统冷启动探索、科研选题组合、药物筛选（活性弱读数下的骨架多样性）、供应链多源采购对冲。

**灵感四：开放解空间让"领域结构"可被自动发现**

- 核心思想：把解定义从"固定模型的参数"升维到"任意程序"，领域特有的结构（如标签有序性）才可能被非人类方案利用。
- 论文证据：RETINO 最优程序用序数偏置 + 图传播、不训练任何参数，领先次优 19%。
- 推广场景：AutoML for 科学工作流（序数/层级/图结构普遍存在）、机器人技能合成、数据分析 pipeline 生成。

**灵感五：诚实对待"更简单的解可能就够了"**

- 核心思想：探索高级技巧前，把"不用它"也纳入搜索空间——监督方案是 SSL 空间的子集，不该被先验排除。
- 论文证据：AgentSL 在两个生态学任务上与 AgentSSL 打平；作者据此把"是否使用无标注数据"列为未来搜索的一部分。
- 推广场景：Agent 工具选型（先问要不要工具）、模型复杂度选型（线性基线 vs 深度模型）、流程自动化 ROI 评估。

## 附录：一点个人观察

这篇论文最值得学的不是某个数字，而是它**把一个含混的大问题（agent 能否做 SSL）切成两个可测量的小问题（发现与选择）**，再用一个公开基准把后一个钉死成可持续研究的问题。社区里"agent 打败人类工程师"的故事已经很多，但"生成的东西谁来验"一直藏在故事的背面——AgentSSL 把背面翻到了正面。ProgramSelectBench 的 16,977 个预计算程序意味着后续研究者不需要 GPU 集群就能入场研究选择问题，这种"把瓶颈做成公共品"的姿态，可能比 8/12 那个数字对领域的长期影响更大。
