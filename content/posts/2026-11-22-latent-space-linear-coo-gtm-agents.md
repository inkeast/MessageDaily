## 先说结论

2026 年 3 月 24 日，Linear 联合创始人兼 CEO Karri Saarinen 在官网发文宣布「issue tracking is dead」（议题跟踪已死），同时上线 Linear Agent、Skills、Automations，把这家靠议题跟踪起家的公司重新定义为「把上下文变成执行的共享产品系统」（公开资料核实：linear.app/next）。Latent Space 本期请来 COO Cristina Cordova 复盘这场自我颠覆的完整过程：她在 2023 年加入时公司约 40 人、只有一名销售，如今约 170 人、4 万付费客户、业务「至少 10 倍」增长；2025 年 Linear 放弃原定的企业级功能路线图，抢先上线 MCP server 与 Agent 平台，一年半后 Linear 上超过 50% 的 issue 已由 Agent 创建。这篇访谈的真正价值不在结论而在机制：一家 pre-AI 时代的工具公司如何在 Agent 冲击下活下来——什么时候自断品类、什么钱不赚、什么环节坚决不让 AI 碰。

## 一、40 人公司的 COO：入职第一件事是砍掉「进军企业级」

Cristina Cordova 的履历横跨运营与产品：在 Stripe 待了七年半（据其 LinkedIn，28 人时加入、增长到近 3000 人，从早期合作与 go-to-market 一路做到带一条业务线），后任 Notion 平台与合作伙伴负责人（主导 API 上线），再短暂转任 First Round 合伙人做早期投资，2023 年加入 Linear 任 COO。她在节目里自述加入时 Linear「大约 40 人」（主持人问法），当时最大客户不超过约 500 席位、没有上市公司客户，本质上还是一家以初创公司著称的 PLG 公司——Vercel、Ramp 这类客户从未和 Linear 的任何人说过话，自助注册后随公司成长付费。

她入职的桥段本身就是 Linear 文化的展示。 founders 对高管有一套「工作试用」惯例，她的试用项目就是真实的六到十二个月 go-to-market 计划——「这就是这份工作本身，不是虚构课题；如果他们不喜欢我产出的结果，就不该雇我」。入职三周后她在全员 offsite（当时全公司 35–40 人）当众把三个公司级目标之一「进军企业级」划掉，理由是「我们只有一个人做销售，一个人是做不了企业级的」，把目标改成了先打赢成长期公司市场：如果 Linear 能说服已经有同类工具的成长期公司把旧工具连根拔掉换成 Linear，一两年后再谈企业级。结果是直到 2025 年她才重新站出来宣布「今年进军企业」，并组建企业销售团队。

这套「不跳级」逻辑来自她在 Stripe 的直接经验：Stripe 早期赢的是「每一个新成立的公司」（第一次接支付就选 Stripe），后来才逐渐赢下从竞争对手切换过来的公司。她对主持人解释了替换式销售的本质难点：一个产品如果只比对手好 20%–30%，客户不会切换，因为切换成本摆在那里；Linear 早期靠的是 founders 的用户直觉——Karri Saarinen 等三位创始人在 Coinbase、Airbnb、Uber 都被迫用过那些老牌工具，「没人喜欢它们」，所以 Linear 从第一天就把差异押在设计与 UX 上，再用免费额度让人先上手试。

## 二、「Issue tracking is dead」：小公司才有资格自杀

主持人把最尖锐的问题放在了开头和中间：CEO 写文章宣布自己赖以起家的品类死了，你怎么跟客户解释？Cristina 的回答分三层。

第一层是「规模小反而是自由」：「我们还没大到会杀死自己的程度。如果是 Google，你很难亲手杀死搜索业务——在每条搜索结果顶上放一个 AI 框，可能就没人看广告了。」她把这归为 pre-AI 工具普遍的创新者困境：与其守着一个几年后大概率不存在的时代，不如主动去建新时代最好的产品。所谓「死了」的不是 issue 这个工作单元——「issue 仍然存在，死的是让人手动跟踪工作这件事」。

第二层是数据。Linear 2025 年上线 MCP server，Cristina 称他们是这个品类里第一家，此后「一年半的时间里，Linear 上超过 50% 的 issue 由 Agent 创建」。（公开资料可以交叉印证：Karri 的 3 月博文称当时 Agent 创作的新 issue 约占 25%、编程类 Agent 已装进 75% 的 Linear 企业工作区；到 8 月他再发文时，付费工作区 Agent 装载率已达 95%、Agent 创建的工作占比从一年前的 3% 涨到 50%。）更关键的是她主动给出的双指标：「App 内使用量也在同步上升」——很多人以为自己只用 MCP 就够了，但团队工作的可视化、协作，聊天界面都做不好，所以她的判断标准是「MCP 使用曲线和 App 使用曲线一起向右上方走」，证明产品对人和 Agent 都好用。她由此反驳了当下流行的一种工具战略：「很多公司觉得当个数据库、挂个 MCP server、把数据全交给 Agent 互操作就是好商业模式——我不认为那是好商业模式。你必须把 agentic workflow 做进自己的工具里，而且要比别人从外部互操作你的系统更好用，否则用户没有理由进你的产品。」

第三层是客户推力。她说「绝大多数前沿 AI 实验室都在用 Linear」，这批 Linear 之后成立的新公司直接施压「你们不往这个方向走，就不再适合我们」；另一类是 Ramp、Coinbase 这类 pre-AI 但内部自建 Agent 的公司，要求 Linear 开放「在自己系统里创建 Agent」的 API 并保留专有数据——当时竞品没有任何一套这样的 API。而真正有意思的错位是：当初推着她往 Agent 方向走的不是她正要攻克的企业级客户，如今恰恰是这些传统企业在主动找上门，说「我们构建产品的方式变了，底层工具也该跟着编程 Agent 的进化速度一起变」。CEO 发文前全公司早有共识，「没有被吓一跳」。

新定位的直接后果是 2025 年的路线图重写：原计划的企业功能（sub-teams、跨团队多层 roadmap 等）没做完，团队临时插入了 MPC server、Agent 平台、以及与 Codex/Cursor/GitHub Copilot 的合作接入——「这些没有一件是 2025 年初计划过的」。她的原话是选择题：要做落后于变化的公司，还是「racing ahead」？她赌的是：把 Agent 体验做好，同样能赢下企业客户，只是不是以原来想象的方式。事后她认为竞品迟迟不动让 Linear 抢到了本来得不到的位置，「很多企业把 Linear 放进了考虑清单」。

## 三、销售与支持的逆常识：无 SDR、不外包、AI 只起草不拍板

这场访谈几乎是一份「反默认设置」的组织清单。

**没有 SDR（销售发展代表）。** 常规 SDR 做外呼或做首轮资格审查，而 Cristina 认为那通电话对客户毫无价值——「你的销售在问我『你们多大规模、可能付多少钱』，我为什么要浪费 30 分钟才能见到能给我演示的人」。Linear 的立场是销售自己应该会写定制化的外联邮件，再用系统与自动化把 AE 武装起来。销售招聘也反常：专招「卖过技术产品给设计师/工程师」的 AE，因为这类客户挑剔、不想看花哨幻灯片只想直接进产品演示；销售上岗前必须通过内部课程认证才被允许独立见客户。Solution engineer（方案工程师）是后来才加的，与当下流行的 forward-deployed engineer 刻意区分——Linear 的哲学是「产品应该简单到客户自己就能集成」，不做驻场实施；方案工程师的杀手锏是演示速度：「你想看我们怎么和 ServiceNow 集成？我昨晚已经把这个集成做出来了。」

**客服坚决不外包。** 这是 founders 定的规矩，Cristina 说她此前从未见过不外包客服的公司——连 Stripe 也外包。理由是：很长时间里 Linear 没有销售团队，客户想找人说话时唯一的触点就是支持，「所以支持必须好」。团队至今是全球自建、零外包，她引以为傲的证据是「三年半里，我从未因为支持体验差而收到一次客户升级投诉」。

**AI 的边界划在「起草」与「拍板」之间。** Linear 内部用 LLM 自动起草客服回复，但由人审核后发出；她明确反对「100% 工单先由 LLM 回复、客户怒了再转人工」的行业做法。客户的真实反馈常常是「你们回复这么快，是不是 AI」——其实是人快——以及「这是我很久以来第一次跟支持团队的好互动」。市场营销同理：让 AI 转写两小时的客户访谈、挑出最动人的片段，但客户故事必须由人执笔，因为「我们不喜欢 AI 写作的手感」，而 Linear 品牌要的是「定制、手作」（主持人此时插话说自己注意到 Astro——疑指 GPT-6 Astra——最近写作已经相当好；嘉宾未接话展开）。团队结构上她强调不是裁员而是「不再随业务线性加人」：支持团队没按旧比例扩张，销售的网页文案改动现在销售自己就能提交、工程师只需审核。

「不是所有东西都得是 Agent」是这一节的点题案例：有客户许愿「要是有个 Agent 帮我做分诊就好了——没人想维护 backlog」，Linear 的回应不是做一个 Agent，而是把能力做成了产品功能 triage intelligence：bug 报告、功能请求一进系统就自动打标签、自动指派、自动进正确团队的队列，人什么都不用做。从 AI 实验室客户那里学到的用法（销售电话全录音、客户屏幕共享工作流），被打包成给普通客户的最佳实践——「当你的客户是 builder 时，永远先想怎么向他们学习，而不是只想着教育他们」。

## 四、AI 预算的魔法与局限：一年期试验潮

主持人抛出当下的流行观察：「AI 公司三个月做到一亿美元收入」是不是同一件事？Cristina 给出了两个冷静的修正。

其一，采购提速的真正机制是「凭空找到的预算」：传统企业买新工具要挤既有预算、排年度周期（「这得等到 2028 年再决定」），但 AI 预算是一笔新增的、额度很高的池子——「如果工程团队相信这个工具能让他们更好，而且能塞进 AI 预算，决策就快得多」。她的判断是这波试验潮有保质期：「一年后、两年后，公司会搞清楚什么真的有用，这股劲会停下来。」当下的形态是一年期合同和付费试点，而不是三年长约——「两年后世界什么样谁也不知道」。（她也补充：受信任的供应商照样能签到很长的大单，代价是锁价与分步涨价条款。）

其二，三个月一亿美元的收入结构值得怀疑：那些公司往往客户高度集中——卖给国防工业或巨型律所，「签两三单 3000–4000 万美元 ARR 的合同就到一亿了」。对照 Linear：4 万付费客户、直到 2026 年 6 月之前纯按席位收费，「这种结构从零到一亿美元不可能一夜之间发生」。

对「决策是否整体变快」她的回答很坦率：没有。「那些更传统的公司并没有变快，至少这类决策没有。」帮到他们的只是 AI 预算的存在。她还给出两条时间谱系的真实案例：有千人大厂的 CEO 自上而下拍板「这个周末全公司切到 Linear，适应不了的自己看着办」，一个月内成交；也有公司拖了两年半——CTO 不点头、九个月后再来一个人、又九个月后再换一个人来试，最后才批。

## 五、定价：从纯席位到 usage-based 的小心翼翼

2026 年 6 月起 Linear 部分功能转向按用量计费，这是访谈里方法论密度最高的部分。

Cristina 先承认行业没有解出「按结果计价」：Intercom Fin 那种「AI 解决一张工单一美元」的模式令人羡慕，但放到议题跟踪就失灵——「自动把一个 bug 分诊到正确团队，值多少钱？每家公司答案都不一样：有的公司觉得这本来就是 PM 的活，有的公司巴不得 PM 把时间省下来陪客户」。在结果不可定价之前，Linear 的过渡方案是成本加成透明定价：coding session 由用户自选 OpenAI 或 Anthropic 的模型与 harness，计价就是「API 公开牌价 + 一点加成」；Loops 功能用 AI 积分；Linear Agent 聊天免费（用的是前沿模型，赌成本会持续下降）；其余绝大多数 AI 能力直接内置进席位价。

原则有三条。第一，不动存量：「席位收费不取消、原本免费的不收费，新收费只针对新功能」——这是说服客户的关键。第二，beta 免费试用换数据：「我们还不知道这功能值多少钱、怎么收，但我们知道它服务成本很高；先用着，收费前会通知你。」她也如实承认这个模式的挫败面：六个月 beta 之后第五个月客户早忘了免费是暂时的，「只好在产品里加横幅提醒」。第三，定价从紧到松：「宁可先贵后降价，也不要先便宜再道歉。」(她原话是 bias towards making things more expensive at the start and then decreasing costs。)

## 六、护城河塌了之后：团队、速度与六个月路线图

主持人问「Linear 的护城河是什么」，Cristina 的回答经历了两次修正：过去是设计与 UX，现在「大概是团队」；硬要再说一个，是速度——但立刻自我限定：Linear 经常为质量推迟发布，「不是最快的，但也不是最糙的」，只是在和遗留竞品比时足够快。她的判断比答案本身更重：「商业世界里大多数护城河其实已经塌了。昨天这个模型最好，明天另一个最好；两个月前没听说过的公司现在按一百亿美元估值融资。所以我们都该有点偏执。」（主持人顺势吐槽：问初创公司护城河本来就是蠢问题——初创公司的存在意义就是去攻破在位者的护城河。）

这种世界观落在计划周期上：Linear 的产品路线图最长只排六个月，「营销故事也只按六个月的有效期来讲」，过期就换，包括可能已经过时的广告牌。她用 2025 年夏天做例子：往年 SaaS 的夏天必然放缓（客户度假、不做采购），2025 年却「全程油门」——公司开始提前一周通知就在直播里发产品，「周六发布也无所谓」，旧世界「周五不发版、周一不发版」的规矩全部作废。她认为这种状态会持续到「AI 出现整合时刻」为止，不是暂时现象。

回望 2023 年入职时，她赶上的正是初创寒冬——2021–22 年巨额融资的公司在 2023 年（ChatGPT 刚出来）集体砍成本、融资冻结，「初创大清洗」（the great startup culling）。她对当年自己的建议是「放轻松，一切都会没事」：不必试图精确预测未来，而是「信任工程、产品、设计去造他们想在世界里看到的东西，然后围绕它构建商业模式」。公司层面同样的哲学：约 170 人仍保持扁平、没有 C-suite 层层加码（高管只有 founders 和她），「在还小的时候不要加那么多层」；同等阶段与收入的公司团队规模几乎是 Linear 的两倍，「do more with less」同时意味着转向时不用掉头一艘巨轮。为什么当初不直接雇一百个销售去攻企业级？「那不是 Linear 的做事方式」——销售在科技圈曾背着「二手车贩子」的刻板印象，Linear 选择小步慢走换取了工程对销售的深度信任（销售搞不定某个细分市场时会直接和 PM 开电话会），而不是「快雇快裁」。

## 七、从 Stripe 带来什么、拒绝带走什么

结尾的复盘部分是给创始人与管理者的干货密度最高的一段。

带来的是结构性纪律：Stripe 曾出现业务侧招聘速度超过工程师招聘，founders 于是划下硬线——工程/产品/设计/数据合计不得低于全公司的 40%（「这是个拍脑袋的数字，但重要的是想清楚你想让公司长成什么结构」）；销售想再多招人，就得先帮着把工程师招够。Linear 没有照抄 40% 这条线，但 Cristina 入职后做的第一批事之一就是建全员职能台账电子表格，盯着这个比例，「招工程师永远比招销售难，所以得提前想办法」。对照系是 Uber 那种天然运营密集型（要调度人和物）——「先理解你的生意是什么，再决定结构」。

拒绝带走的是「永远能雇到更好的人」的幻觉。Stripe 太成功了（她提到 Stripe 处在 1400–1600 亿美元估值区间的上升期），成功到让人相信在位者的成绩来自平台而非个人——「我在 Google 把营收做了两百亿美元增量——你到底做了什么？」——于是不断用高吸引力去挖「比在位者高两级」的人。Stripe 后来才学会珍惜在位者，出现了大量「回旋镖」员工（离开又回归并干得很好）。Cristina 给自己定的复盘标准是：回头看 Linear 时，希望能说「该晋升的人晋升了，我们没有仅仅因为能雇到更贵的人就从他们头上越过」——创始人几乎没人「精确做过」自己在做的事，早期团队的领导者同样没把支持团队扩到过 200 人，但这不意味着他们做不到，「人可以成长和扩展，应该奖励这种成长」。

至于她那段风险投资经历，她自己的总结相当祛魅：「做 VC 就是销售——你卖的是钱，而别的投资人也在卖一样的钱，你卖的是你自己。」早期投资的核心是投对的人然后让路，「我在公司找到 PMF 之后加入、更能帮上忙」；她带回来的是董事会视角——知道投资人想看什么数据、融资时该对他们的帮助抱什么预期，以及一句朴素的「闭上嘴的人喂不饱」（closed mouths don't get fed）：不主动向投资人要资源，没人会主动给。

## 机制、影响与启发

把这场访谈压缩成四条可迁移的因果链：

1. **Agent 改变了「工作被创建」的方式，工具必须在同一个产品里同时服务人与 Agent。** 证据：Linear 超 50% issue 由 Agent 创建、MCP 与 App 使用量同涨；反面是 Cristina 明确不看好的「数据库 + MCP server」路线——把数据全交给外部 Agent 互操作，用户就再没有理由进入你的产品。二阶影响：pre-AI 工具公司面临「被降级为管道」或「自我升级为 Agent 原生系统」的二选一。观察指标：Agent 创建工作的占比、人类 App 会话量是否同向。启发：评估任何生产力工具时先问它对 Agent 的原生支持程度，而不是只看 UI。

2. **AI 预算是一笔「凭空出现」的新预算池，它暂时绕过了传统采购节奏，但有保质期。** 证据：企业因「AI 预算」加速工具决策、试验潮以一年期合同为主；Cristina 判断一两年后潮水退去。二阶影响：靠 AI 预算起量的收入（尤其客户高度集中的）质量存疑，SaaS 传统结构（4 万客户、按席位）增长慢但稳。启发：如果你的产品能塞进客户的 AI 预算，现在是销售窗口；同时要在窗口关闭前证明留存。

3. **小规模是自我颠覆的资格。** Google 难以亲手杀死搜索广告，Linear 可以宣布自己起家的品类已死；规模小、零上市客户包袱、founders 有「没人喜欢旧工具」的一手体感，使品类自杀的执行成本可控。二阶影响：抢先建 Agent 平台反而把 Linear 送进了原本够不着的企业考虑清单。启发：颠覆自己的最佳时机是在被迫之前、且组织还小的时候。

4. **人机分工的边界比「用不用 AI」更重要。** Linear 的划分：AI 起草（客服回复、访谈转写、初稿检索）+ 人拍板（质量、品牌手感、客户故事执笔）；客服不外包、支持零升级投诉是品牌资产。二阶影响：团队不随收入线性扩张（销售自己改网页文案、工程师只做审核）。启发：先列出你的品牌「手感」清单，把这些环节划为 AI 禁区，其余环节全部用 AI 提效——而不是反过来。
