# Recursive Code World Models 精读：递归构造可执行 3D 世界

> **题目**：Recursive Code World Models: Building Complex Worlds through Recursive Scene Programs
> **链接**：https://arxiv.org/abs/2609.11499
> **团队**：Georgia Institute of Technology（Zhiqi Li, Yuxuan Liao, Bo Zhu）
> **数据日**：2026-09-12（HF 日榜第 12 名，18 赞）

## 一、题目与背景

**代码世界模型**（code world models）把世界表示为可执行程序：几何、材质、空间关系都是显式程序元素，可检视、可编辑、可接入物理仿真。近期的视觉-语言编码 agent（img2threejs 系）已能从图像生成场景代码并靠渲染反馈迭代修正。但一个未被解决的问题浮出水面：**代码表示只定义了"世界长什么样"，没有定义"构造计算该如何组织"**。

想象从一张图重建整个城镇：街道地形定布局，建筑里有立面，立面里有窗户招牌装饰。一次生成整场景代码，局部细节分辨率受 token 预算挤压；给局部独立任务则局部编辑不独立——精修过的桥可能与河岸脱开，招牌可能与邻窗重叠。冲突在局部精炼后才显现，需要在"整体语境"中裁决。这个张力在每个尺度都存在。

## 二、研究定位

与 Chen et al. 2026（code world models 概念化）、Yin et al. 2026（渲染反馈的编码 agent）一脉相承，但前序工作是"单趟生成+整体复查"，RCWM 首次把**递归**作为构造组织原则。与 3D 重建界的分层方法（ LOD、块状重建）精神相通，但那些方法的层级是预定义的网格剖分，RCWM 的递归由**视觉反馈驱动**——哪里没解决就往哪里下降。

## 三、问题定义

抽象问题：当构造目标包含"比单次重建轨迹能分辨的更多结构"时，构造计算应如何分解组织，使得（1）每个子结构获得足够分辨率，（2）子结构间的组合关系（边界、遮挡、共享误差）仍被全局约束？

形式化：给定参考图 I* 与编码 agent A，求递归过程：每个节点"建立整体→对未解子问题调用同一求解器→回访整体精炼组合"，共享相机投影跨层级传播，父级回访裁决局部冲突。

## 四、解法

**表示层——递归场景程序（RSP）**：场景代码组织为嵌套子世界的组合结构：每个子世界是自包含的可执行场景程序，可独立渲染。

**过程层——自递归求解器**：每次调用执行完整三段循环：
1. **建立整体**（establish the whole）：在父级语境下构造当前层级的完整场景框架（继承父级相机投影与空间约定）；
2. **递归构造部分**（prepare and recursively construct the parts）：识别未解决的视觉子问题（渲染与参考图差异大的区域），传递聚焦的参考裁剪（matched reference crops）给递归子调用——子调用获得自己的感知-编辑循环；
3. **回访整体**（revisit the whole）：子结构完成后回到整体，检查并精炼组合——边界、空间关系、局部孤立审查发现不了的共享误差在整体层裁决。

**参考对齐视图**：所有层级共享同一相机投影——子问题在"与父级相同的视角"下求解，避免坐标系漂移。**视觉-语言编码 agent** 对比参考图与场景渲染，引导精炼、下降与返回三个决策。

关键概念区分：**递归决定哪些子问题得到完整求解，并行只改变调度**——兼容的分支可并行执行，但每个分支的求解深度由视觉反馈决定。

## 五、实验结果

| 项 | 结果 |
|----|------|
| 三级递归（33 节点）vs 固定二级 | whole-frame PSNR **16.8→19.0**，local SSIM **0.52→0.60** |
| vs 其他三种工作流 | 两项指标均领先 |
| 消融：构造顺序/递归深度/父级回访 | 三者各有贡献，更深的递归改善更细尺度重建 |
| 参考图设置 | 5 张全场景 + 5 张局部裁剪（含城市全景与街区特写） |

实验设计的证明力：PSNR/SSIM 的 whole-frame 与 local 双口径同时提升回答了核心质疑——"局部细化会不会伤全局"（不会，父级回访兜住）；递归深度消融（二级→三级双指标提升）直接验证"深度换细节"的核心主张。

## 六、知识反推

作者必须掌握：（1）程序化场景表示（Three.js 类场景图的组合结构）；（2）渲染反馈闭环（渲染-比对-编辑的 agent 循环设计）；（3）递归算法设计（下降条件、返回条件、共享状态的传播）；（4）相机几何（跨层级共享投影避免坐标漂移是隐性关键工程）。

融合节点：把编译器的递归下降解析思想移植到视觉构造——"语法分析中遇到未解决的非终结符就递归下降"与"渲染对比中发现未解决的区域就递归构造"同构。

## 七、通用灵感

1. **递归是"分辨率不足"的通用解**（论文证据：递归深度消融的双指标单调改善）：任何"单趟生成分辨率被预算挤压"的场景——代码生成的文件级→函数级→行级、文档写作的章→节→段、Agent 规划的里程碑→步骤→动作——都可以问"该递归了吗"。
2. **局部优化必须配全局回访**（论文证据：父级回访专治局部精炼后才浮现的共享误差）：分层系统的经典陷阱是局部正确全局破碎；显式的"回访整体"阶段是解药。推广：多 Agent 协作的整合阶段、微服务重构后的端到端测试、编辑系统的全局一致性检查。
3. **共享坐标系是分层协作的隐形基础设施**（论文证据：参考对齐视图跨层传播同一相机投影）：子任务分发时最易丢失的是坐标系/接口约定，显式传播能消除一类系统性错误。
