# 一、论文背景：当通用 Agent 范式撞上垂直领域

过去两年，"Agent"这个词承载了太多想象：一个通用大模型，配上工具调用、记忆和规划，似乎就能横扫一切任务。但 2026 年的今天，研究者的目光正在转向一个更具体的问题——**当 Agent 进入垂直领域，通用范式还剩多少直接可用？哪些东西必须为领域重造？**

本文合并精读的三篇论文，正好是这个问题在三个领域的回答，而且三种回答的姿态截然不同：

**第一种姿态：领域要求全新的问题定义（StreamVibe，视频主动交互）。** 想象一个戴着相机或看着你屏幕的 AI 助手：用户说"帮我盯着这道菜"，然后就不说话了。助手必须自己判断——什么时候该提醒、什么时候该闭嘴、用户中途改了主意怎么办？这和传统的"用户提问-模型回答"范式完全不同。现有视频理解模型大多是"被动"的：离线看完整段视频再回答。而真实场景是"流式"的：画面一帧帧到来，用户的意图可能从没说出口（隐式意图），也可能中途改变（动态意图）。StreamVibe 的判断是：这不仅是换个数据集的问题，而是需要基准、模型、运行框架三件套同时重造。

**第二种姿态：领域提供了现成的真实环境（PatEx-Gym，专利审查）。** 专利审查是一个知识密度极高的真实任务：审查员要从一个超过百万篇文档的语料中找出"现有技术"（prior art），对照权利要求判断新专利是否新颖，最后写出正式的审查意见书（Office Action，OA）。这个任务天然是一个"搜索-推理-评估"的闭环，且有一个别处没有的优势——USPTO 的公开审查记录本身就是权威标注。PatEx-Gym 的思路是：与其造环境模拟领域，不如直接把领域本身做成 Agent 的训练场（Gym 这个词正是此意）。

**第三种姿态：领域里堆满了手工 Agent，需要有人泼冷水（RCAtlas，运维根因分析）。** 微服务故障的根因分析（Root Cause Analysis，RCA）领域已经发表了大量 LLM Agent：有的内置标准操作流程（SOP），有的分固定阶段，有的用多个角色子 Agent 投票。但每篇论文都在自己收集的数据上、跟少数 baseline 比。北大的作者提出了一个泼冷水的问题：**如果只是把数据给一个能力强的模型、让它自己决定看什么怎么想，会不会反而更好？** 答案是肯定的——这构成对整个子领域的一次范式修正。

三个领域、三种姿态，合起来就是一幅"垂直领域 Agent"的路线图：哪里需要建基础设施，哪里可以直接复用环境，哪里需要警惕过度工程。这也是把三篇论文放在一起精读的价值。

# 二、论文定位和关联工作

三篇论文各自站在不同的研究谱系中，分别梳理如下。

## 2.1 StreamVibe：主动交互基准与流式视频模型

**谱系一：视频理解基准的演进。** 早期视频基准（如 Video-MME、MVBench）评估离线理解；在线基准（OVO-Bench、OVBench）要求在视频播完前回答；而主动基准（ProactiveVideoQA、EgoProactive、EgoPro-Bench、IPIBench、EgoServe、GuideMe、GUIDE）进一步要求模型自己决定**何时**响应。但论文的对比表显示，这些基准各有缺口：大多只覆盖单一意图类型或单一环境（物理或数字），且基本只做逐点（pointwise）评估。StreamVibe-Bench 是第一个同时覆盖显式/隐式/动态三类意图、物理+数字两类环境、逐点+轨迹双评估的基准（4.1K 评测样本，平均时长 8.3 分钟，是同类中最长的）。

**谱系二：主动交互模型。** 流式视频-语言模型（VideoLLM-Online、ViSpeak、LiveStar、MMDuet2、Mage-VL）支持连续感知与低延迟响应，但大多围绕显式指定的请求设计，缺乏对交互状态和演化意图的跟踪。StreamVibe-VL 的差异点在于联合学习"何时协助"和"如何协助"，且显式面向隐式与演化意图。

**谱系三：记忆与 Agent 框架。** 记忆系统研究（Mem0、A-MEM、Agentic Memory 等）关注如何组织和检索历史信息，但不显式跟踪用户意图与任务进度。StreamVibe-Harness 的定位是把意图做成带生命周期的持久状态——这更像"状态机式的外置记忆"而非通用记忆库。

## 2.2 PatEx-Gym：从检索基准到 Agentic 搜索环境

**谱系一：专利审查基准。** 论文给出了清晰的对比表：PAR4PC 只有 8 个候选文档；IPBench 无现有技术可搜；FiNE-Patents 给定 1 篇文档做细粒度推理；PatRe 给 10 篇参考文献做多轮交互。它们的共同问题是**静态、小候选集**——而真实审查要从海量语料中自主发现证据。PatEx-Bench 用 1M 专利 + 52K 论文的语料直接把搜索空间扩大了五个数量级以上。

**谱系二：Agentic 搜索与深度研究。** ReAct/IRCoT 奠定了"推理-行动"交错范式；Search-R1、TIPS、FORT-Searcher、SearchArt 训练搜索 agent；深度研究（Deep Research）方向评估多步检索与引用支撑的报告生成。PatEx-Gym 的独特定位是：搜索必须支撑一个**有法律效力的、claim 级别的正式决策**，证据约束比开放域报告严格得多。

**谱系三：专利检索经典线。** NTCIR、CLEF-IP 等奠定了现有技术检索的评测传统，但都是"给定查询排序列列"的判别式范式。PatEx-Gym 把它升级为查询本身由 agent 迭代构造的生成式范式。

## 2.3 RCAtlas：从各自为战到同台横评

**谱系一：非 LLM 的 RCA 方法。** 统计排序（NSigma、BARO、ε-Diagnosis）、因果发现（CIRCA、RCD、DyCause）、依赖图传播（MicroRCA、MicroRank）、多源融合（TORAI）——这条线 2018-2024 年很活跃，但天花板明显。

**谱系二：LLM RCA agent。** FoA 用 SOP 固定流程；RCA-Agent 用不接触数据的控制器+写代码的执行器；RCAgent 用专家子 Agent 管理观察；mABC 用角色 Agent 投票；DecompRCA 程序端检索+一次 LLM 重排。这些工作"大多在其作者自采数据上与少数 baseline 比较"——这正是 RCAtlas 要打破的评估格局。

**谱系三：通用 harness 与"简单胜复杂"的证据。** 论文引用的相邻证据链很关键：软件工程领域有固定流水线以极低成本比肩 SWE agent 的先例；Laban 等发现多轮对话会降低 LLM 可靠性；Sutton 的《The Bitter Lesson》主张可随算力扩展的通用方法终将超越手工知识。RCAtlas 是把这个问题在 RCA 领域直接做了对照实验。文中还提到 OpsHarness 已发现 Codex 类 harness 无 RCA 设计也能打赢专用 agent，RCAtlas 取互补视角：不加自进化层，纯对比简单 harness、发表 agent 与非 LLM 方法。

**三篇论文的定位对比**：

| 维度 | StreamVibe | PatEx-Gym | RCAtlas |
|---|---|---|---|
| 论文类型 | 系统+基准+模型 | 环境+轨迹合成+轻量模型 | 横评+基准+机制分析 |
| 领域 | 视频主动交互 | 专利审查 | 微服务根因分析 |
| 核心主张 | 意图感知需要三位一体重建 | 真实环境+隐式信号可训练小模型 | 简单 harness 胜手工 agent |
| 对通用范式的态度 | 扩展（加状态跟踪层） | 移植（把搜索 agent 搬进法律域） | 修正（去掉手工流程） |

# 三、问题定义

三篇论文面对三个具体场景，但抽象之后都指向同一个深层问题：**在垂直领域中，Agent 的"自主性边界"应该画在哪里——哪些决策该交给模型，哪些该由系统固定？**

## 3.1 StreamVibe：把主动协助形式化为因果流式决策过程

StreamVibe 的形式化值得细读。Agent 观测视频流 V = {v_t}，用户随时间表达若干意图 i_j（显式或隐式），每个意图在时刻 τ_j 对 agent 可见。在每个时间步，agent 只能访问 c_t = ⟨V_≤t, I_≤t, H_<t⟩（当前及过去的视频、意图、交互历史），预测 a_t ∈ {沉默, 响应}。关键约束有三个：

1. **因果性**：不能看未来帧或未来用户输入——这与回溯式 VideoQA 的本质区别。
2. **证据窗口**：每个意图对应一个或多个证据点 ξ_jk，每个证据点有有效响应窗口 [s_jk, e_jk] 和参考回答。证据可能在意图表达**之后**才出现——所以不能一听到请求就回答。
3. **意图活性**：意图在所有证据点被覆盖前保持活跃，用户可以修订（Revision）、组合（Composition）、打断（Interruption）。

抽象地说，这是把"主动交互"从"何时说话"的时机问题升级为"**意图推断 × 状态跟踪 × 时机决策**"的联合决策问题。类比深度学习：如果说传统 VideoQA 是分类任务（给定完整输入输出一个标签），StreamVibe 定义的是策略学习问题（在部分可观测环境中逐拍决策）。

## 3.2 PatEx-Gym：把新颖性审查形式化为受限语料上的轨迹生成

PatEx-Gym 的形式化：给定专利申请集 Q 和先验语料 C = P ∪ N（专利+论文），对每个申请 q_i，时间合法性约束把可搜索语料限制为 C_i = {e ∈ C | d_e < d_i}（只许看申请日之前公开的文档——这是专利法的新颖性时间窗）。Agent 以 ReAct 模式在 harness 中交替推理与工具调用，产生轨迹 τ_i，最终输出 OA o_i 与参考文献集 R_i ⊆ C_i。

这个定义的精妙之处在于**把法律约束编码进了环境**：agent 不是在一个通用搜索引擎里漫游，而是在一个带时间闸门的语料上工作，输出必须是可追溯的正式文书。抽象后的问题与深度研究的"检索增强报告生成"同构，但约束从"引用正确"升级为"法定证据链完整"。

## 3.3 RCAtlas：把"手工化程度"变成可测量

RCAtlas 的核心抽象是提出了 **prescribed-call ratio（规定调用比）ρ**：一个方法的模型调用中，由程序在固定节点发出（而非模型自主决定）的比例。计算方式是对每个案例 i 的模型调用数 c_i 中被规定的 f_i 求比值，再对案例与模型取平均。

配合三分类法——main（任务主控的下一轮）、delegated（主控模型自己决定委托的调用）、prescribed（程序固定发出的调用）——这个指标把原本含糊的"这个 agent 有多手工"变成了精确数字：简单 harness 全部为 0.00，DecompRCA 为 1.00，FoA 为 0.51。这个抽象的价值在于：它把"agent 设计谱系"从连续的风格差异压缩成一个可计算的标量，使"手工化程度 vs 性能"的相关性分析成为可能。

**三篇的问题定义对照**：

| 论文 | 具体问题 | 抽象问题 | 形式化核心 |
|---|---|---|---|
| StreamVibe | 视频流中何时/如何主动协助 | 部分可观测下的联合决策 | 因果流式决策过程 + 证据窗口 |
| PatEx-Gym | 专利是否新颖 | 受限语料上的证据发现与决策 | 时间合法语料 C_i 上的轨迹生成 |
| RCAtlas | 手工 agent 值不值 | 自主性边界在哪 | prescribed-call ratio ρ |

# 四、问题解法

## 4.1 StreamVibe：基准、模型、框架三位一体

StreamVibe 的解法是一个三层系统，每层解决一个前一层的遗留问题。

**第一层：StreamVibe-Bench（基准）。** 数据构造流程：收集物理（自我中心日常活动、任务执行）与数字（GUI、计算机使用）两类任务视频 → 用 Gemini-3.8-Flash 清洗数据并生成候选帮助点（含响应窗口、偏好时机、参考回答）→ 四位审核者独立验证，**只有四票全通过才保留** → 对齐为 1 FPS 因果流。规模：4,100 评测样本、20,546 个帮助点、183.4 小时视频；意图分三级——显式（600 样本：单事件 I/状态转移 P/重复事件 R）、隐式（2,000 样本：引导 G/学习 L/监控 M/工具 T）、动态（1,500 样本：修订 RV/组合 CP/打断 IT）。另有 85K 训练样本（70K SFT + 15K RL 种子）。标注质量经过审计：人工间 Fleiss' κ 为 0.82–0.87（"几乎完全一致"区间）。

评估协议分两种，这是设计的亮点：**Pointwise**（在标注帮助点附近采样正负时间戳、独立预测该不该响应，可用 gold 历史隔离局部决策能力）与 **Trajectory**（连续跑完整条流，依赖自生成历史——暴露误差传播与遗忘）。指标覆盖时机（Precision/Recall/F1/FPR）与内容（Answer Score、Content F1）。

**第二层：StreamVibe-VL（流式策略模型）。** 两阶段训练：

- *阶段一：自适应流式 SFT。* 类比：标准 SFT 对沉默/响应 token 一视同仁，就像对类别极度不平衡的数据不做重加权——模型会学到"永远沉默"的偏置（训练流中绝大多数时间步是沉默）。解法是给决策 token 加自适应权重 ω_j = γ^γ_{c(j)}（跟随当前训练分布平衡沉默/响应），同时用 λ_text 保住回答生成本身的学习。冻结视觉编码器，训练 LLM+连接器。
- *阶段二：局部轨迹 RL。* 类比：全轨迹优化就像对一整局游戏给一个总分——正确和错误行为混在一起，信用分配弥散。解法是只在标注帮助点邻域构造短因果 rollout，用 GRPO 优化，奖励分两级：点级 R_align（时机分 τ 与 LLM 评判的内容分 ρ 之积，经一对一匹配聚合，α 平衡漏检与过度响应）+ 轨迹级 R_glob（整段响应序列的一致性与冗余），λ=0.7 偏向时机与内容。

**第三层：StreamVibe-Harness（状态跟踪框架）。** 前两层的遗留问题是：策略模型本身难以在长交互中维护最新状态。Harness 维护显式交互状态 S_t = ⟨A_t, P_t, R_t⟩（活跃意图/任务进度/已交付响应），核心机制三件：

- *意图生命周期*：每个意图是独立的有状态实例，可并发存活与演化；持续型意图跨事件保持活跃，一次性意图满足即关闭。生命周期只决定哪些意图有效，何时响应仍由策略 π 决定——职责分离。
- *分层记忆*：近期信息细粒度保留，旧内容逐步压缩为中期摘要（M=5 个合一块长期块，L=8 块上限，FIFO 淘汰）；按当前意图与任务状态检索（词汇重叠+新近度排序，不用嵌入模型）。检索到的记忆作为附加证据，不直接改状态。
- *状态整合*：每次决策前把持久状态+检索记忆整合进上下文 c̃_t = φ(c_t, S_t, m_t) 交给策略；响应交付后写回状态与记忆。状态变更只在有充分交互或感知证据支持时应用，避免不确定观察导致的过早更新。

辅助记忆模型用现成 Qwen3-VL-4B-Instruct（不训练），另有 10 个只读 Skill 记录（行为规范而非神经模型，每次上下文构造至多选 1 个）。

## 4.2 PatEx-Gym：环境、轨迹合成、轻量 Agent 三组件

**第一组件：PatEx-Bench + harness 运行时。** 任务来自 USPTO 公开审查记录（取首次 OA 与原始申请版），1,000 个任务覆盖全部 8 个 IPC 部类（各占约 12.5%），含 2,946 篇审查员引证专利与 178 篇论文作为金标准参考。语料：Patent-1M（1,011,901 篇专利）+ Paper-52K（52,105 篇论文），并验证每条金标准参考都可从语料中检索到。执行环境基于 harbor 沙箱 + Codex harness，工具集含布尔检索、BM25（稀疏）、BGE-M3（稠密）三种搜索 + Read/Write 工作区工具 + **visit 工具**（渐进披露：搜索只返回题录/标题/摘要，要点开文档才能看 claims 等全文）。运行时分准备/执行/评估三阶段严格隔离，agent 执行时看不到评估规则，全轨迹可审计。

**第二组件：PASS 轨迹合成框架（无标注）。** 这是最有方法论创新的部分。问题：训练 agent 需要高质量轨迹，但不可能雇审查员标注。PASS 的洞察是：**teacher 模型在 rollout 中的 visit（访问文档）动作本身就是隐式相关性信号与证据获取锚点**——类似网页搜索中点击行为之于相关性的意义。具体三步：

- *Step 1：visit 引导的轮次切分。* 把原始轨迹按"搜索→访问"模式切成语义轮次 T_k = (S_k, V_k)：agent 消费完上一轮访问的证据后发起新搜索，即开新轮。
- *Step 2：层级质量建模。* 四个维度：轮内 s_intra（搜索结果转访问检查的效率，NDCG 计算）、轮间 s_inter（相邻轮查询是否实质演进而非同义改写）、轨迹级 s_evi（所选参考文献是否真的被访问过的内容支撑）、s_out（LLM 判最终 OA 的 claim 是否逐条有依据解决、驳回的法条引用是否落地）。
- *Step 3：锦标赛排序 + 拒绝采样。* 先严格拒绝门（缺 OA 或参考文献、超轮次预算即弃），再对存活的轨迹做两两锦标赛——四维分数上赢下严格多数维度者胜，按总胜场排序。这个聚合保留了分数向量结构、不塌缩成标量，使不同失败模式可分离。10K teacher（GLM-5.3）rollout → 6,321 过拒绝门 → 精选约 3K 得 PatEx-SynData。

**第三组件：PatEx-Agent（4B SFT）。** 以 Qwen3.5-4B 为底座，在 PatEx-SynData 上做带环境掩码的 SFT（损失只算模型输出 token，系统/用户/harness 消息全部掩码），slime 框架、8 张 H20、3 个 epoch、lr=1e-5。定位是轻量级基线——验证"训练搜索行为"这条路本身可行。

## 4.3 RCAtlas：一个基准 + 一场对照实验

**RCAtlas 基准构建。** 8 个公开数据源（10 个套件）共 2,359 个案例，统一格式（实体清单+关系表+metrics/traces/logs/events 四类遥测，UTC 时间，清除注入工具痕迹防止答案泄漏）→ 542 个逐一筛查，八条排除规则（标签矛盾/多故障/元凶缺数据/遥测无证据/数据不全/故障前时段不干净等）后剩 348 → 按场景与故障类多样性采样 90 个核心案例（23 场景、10 故障类；根因 59 服务级/20 pod 级/11 节点级；案例遥测 37k–5.6M 行；随机猜测命中率中位数 3.45%）。评分规则处理了各数据集标注粒度不一致的问题：把答案实体沿清单向上映射（pod→service 等），取前五个去重实体按名匹配，报告 PR@1 与 RR。

**三方方法对照。**

- *简单 harness 三种*（共同点：不规定任何模型调用）：One-shot——规则选好的证据包（变动的指标原始序列、每分钟 trace 统计、日志模板、事件）一次调用进模型；SQL agent——单 ReAct 循环 + DuckDB（列文件/读 schema/跑 SQL/提交，至多 100 次调用），仿 OpenRCA 2.0 参考agent；Codex——在案例文件夹跑 Codex CLI，六条规则（只读本文件夹/不联网不装包/不改数据/不猜来源数据集/必须写最终报告/至多一小时），模型自写 shell 与 Python。
- *发表 agent 五个*：RCA-Agent 与 mABC 用原码（只做必要修复）；FoA、RCAgent、DecompRCA 无公开代码、按论文忠实复现（DecompRCA 在 RCAEval RE1 上复现了原文数字）。公平原则：只修阻碍运行或实现错误之处，不加能力。
- *非 LLM 方法七个*：NSigma、BARO、CIRCA、RCD、TORAI、FaultInsight、SimpleRCA，加随机排序做底线。

**实验设置**：Setting 1 全部 LLM 方法跑三个中档模型（GPT-6 Luna / DeepSeek V4.1 Flash / Claude Haiku 5.5）；Setting 2 简单 harness 加跑 GPT-6.1 Sol、GPT-6 Astra、MiMo-V2.6-Pro；Setting 3 把 Luna/Sol 推理档升到 xhigh/max。Luna 上的简单 harness 与 Sol 上的 SQL agent/Codex 各跑三遍取均值。

# 五、评估指标与实验证据

## 5.1 StreamVibe：时机与内容双维度

**指标体系**：主指标为 Timing F1（响应时机：±2s 容差内一对一匹配算 TP）与 Content F1（时机匹配的回答按 Claude Sonnet 4.6 打 0–4 分归一后按 F1 式聚合——漏掉的意图与多余干预都被惩罚）；辅助指标 FPR（假触发率，越低越好）与 Answer Score。

**主表证据（Pointwise，gold 历史，±2s）**：开源模型中 StreamVibe-VL (RL) 在三类意图上均第一或第二——Implicit Content F1 61.28（JoyAI-VL 54.87、Qwen3.5-9B 46.45）；Dynamic Timing F1 66.34、Content F1 39.31；与专有模型相比，Gemini-3.8-Flash 的 Implicit Timing F1 81.00 最高、但 StreamVibe 在开源侧紧追（72.01）。摘要级结论：响应时机与答案质量较其他基线提升 10.7%。

**Trajectory 证据（自生成历史）**：这才是最严酷的测试。开源离线模型全面崩溃（Qwen3.5-9B 三类意图 Timing F1 仅 6.54/7.17/5.44——几乎不做有效时机决策）；流式基线也弱（MMDuet2 Implicit 22.23、ViSpeak 15.10）；StreamVibe-VL (RL) Implicit Timing F1 26.26、Dynamic 19.96，同时 FPR 大幅更低（Implicit 1.49 vs Qwen3-VL-8B 的 26.46）。全模型诊断显示：从 Pointwise 到 Trajectory，Content F1 平均退化 45–61%——**单点判断正确不等于持续交互稳定**，这正是基准要暴露的。

**Harness 消融**：策略固定后加 Harness，Dynamic 意图收益最大（Timing F1 +6.4、部分子项 Content +12.8），FPR 显著下降（RL+harness 的 Explicit FPR 低至 1.49）；摘要级 Harness 再带来 12.3% 主动交互增益。泛化性：EgoProactive Macro 59.5（vs Qwen3.5 46.2、JoyAI 41.0）、IPIBench Timing 39.1（vs 34.3/33.8）；通用视频能力不降反升（MVBench 69.30 vs 基座 68.70 系列）。

## 5.2 PatEx-Gym：漏斗式召回 + 决策质量

**指标体系**：（1）OA 质量分（格式分 1/6 + 三 LLM judge 五维度 1–10 分归一 5/6，×10 满分 10）；（2）决策准确率 Dec. 与法条 F1 Stat.；（3）**Search-R / Visit-R / Select-R 三段漏斗召回**——金标准参考分别在"搜索返回/点开访问/最终写入 OA"三个阶段的召回率。第三组是本文最有领域方法论价值的评测设计：它把"找到"和"用上"区分开了。

**主表证据（13 模型横评）**：Claude-Opus-5-max 全场最强（Score 7.34、Search-R 48.7、Select-R 32.4）；但**Select-R 全场峰值仅 32.4**——即便最强模型，三篇金标准参考也只能用上一篇，天花板极低。PatEx-Agent-4B：Score 5.41（基座 Qwen3.5-4B 3.79，**+42.7%**）、Search-R 38.7（**+66.8%**）、Visit-R 23.2（**+91.7%**）、Select-R 18.2（**+51.7%**）。4B 的 Search-R 38.7 超过 Qwen3.5-397A17B（30.4）与 Qwen3.7-Max（36.1），论文称与 ~30B 级模型相当、Search-R 追平 Qwen3.7-Max。NPL 侧：Paper Search-R 69.4 几乎追平 Qwen3.8-Max 的 69.6。

**关键发现（指标之间的张力）**：Qwen3.6-27B 决策准确率最高（87.6%）但 Score 仅 5.96、Select-R 仅 19.5——**决策对≠审得好**（Dec. 与 Score 的 Kendall τ 仅 0.550）；DeepSeek-V4-Flash Search-R 44.1 很强但 Select-R 停在 24.7——**搜得广≠用得上**。

**消融证据**：（1）轨迹采样：同预算下随机采样 3K 训练，R@10 反从 14.9 降到 11.6（−22.1%）、Select-R 仅 11.96；PASS 精选则 Select-R 18.24（**+51.6%**）——增益来自轨迹筛选而非微调本身；（2）工具消融：Boolean-only 下 agent 的 Search-R 从基座 10.08 升至 25.12（**+149.2%**）——学到的查询构造能力不依赖强工具；只用 BGE-M3 时 agent 几乎恢复全工具性能（Search-R 37.24 vs 38.70）；（3）检索器替换：给基座换更强的 PatEmbed-Large，Search-R 23.20→24.60 但 Select-R 反降 12.00→11.60——更强检索器带来更多相似候选，反而加大了甄选难度。

## 5.3 RCAtlas：一场干净的三方对照

**指标体系**：主指标 PR@1（首答即命中的案例占比）；辅助 RR（对多标签与排名鲁棒的召回式指标）；底线为随机排序（5.5%）。可靠性分析用 aptitude A（三遍中至少一遍解出）与 unreliability U（只在部分遍解出）。

**主表证据（90 案例，三中档模型均值）**：简单 harness 65–77%——Codex **77.2**、SQL agent 72.8、one-shot 65.3；发表 agent 16–53%——FoA 53.3、RCAgent 49.3、RCA-Agent 43.3、DecompRCA 28.5、mABC 15.6；非 LLM 6–39%——NSigma 38.9 最好、RCD 5.9 几乎失效。三个刺眼的交叉点：最弱简单 harness（one-shot 65.3）仍超最强发表 agent（FoA 53.3）**12 个点**；NSigma（38.9）反超 DecompRCA 与 mABC 两个"LLM agent"；**在每个跑了双方的模型上，每个简单 harness 都领先每个发表 agent**（显著性经配对 bootstrap 确认，Codex/SQL agent 领先最佳发表 agent 14–24 点）。更强模型上差距继续拉大：Sol+Codex 87.0、Astra+Codex 86.7、Flash+Codex 85.6。

**分层证据**：根因级别越细，发表 agent 掉得越狠——从 service 到 pod 级，Codex 只掉 9 点，FoA/RCAgent 掉 31–38 点；NSigma 是唯一 pod 比 service 准的方法（55.0% vs 33.9%，资源类故障体现在元凶自身指标上）。数据种类上悖论式发现：四类数据齐全的 17 个案例对所有方法都最难（简单 harness 也只有 52–71%），仅有 metrics 的 10 个案例 SQL agent 反而 95.6% 最易。

**prescribed-call ratio 证据**：Codex 0.00、SQL agent 0.00、one-shot 0.00；FoA 0.51、RCAgent 0.35、RCA-Agent 0.29、mABC ≥0.10、DecompRCA 1.00。注意论文诚实指出：**在发表 agent 内部，ρ 不与准确率排序一致**（RCA-Agent ρ 比 FoA 低却更差）——清晰的分界在"规定零调用"与"规定非零调用"两族之间。

**成本-时间 Pareto**：以 NSigma 的 38.9% 为可用阈值，全部越过阈值的 run 中，**每一条成本与时间 Pareto 前沿上的点都是简单 harness**（7 个发表 agent run 过线但全部被支配）。三个实用档位：Luna+Codex 68.9% 每案例不到 1 美分；Flash+Codex 85.6% 约 5 美分；Sol+SQL agent 45 秒出答案 85.6%。最贵的 Sol xhigh+Codex（88.9%）比最便宜的强配置贵约 5 倍。

# 六、效果优势的根源解释

## 6.1 StreamVibe：策略与状态的职责分离

**对比对象**：基线是离线多模态模型（直接接流式输入）与现有流式模型（学了低延迟响应但没学意图跟踪）。它们为何曾经有效？离线模型有强视觉理解，流式模型有实时性。

**根本局限**：两者的训练信号都没有把"决策"当作一等公民。离线模型的轨迹崩溃（Timing F1 个位数）揭示的是**训练-部署分布错位**：训练时看完整视频，部署时只有历史——内容生成能力无法弥补时机决策缺失。流式基线的高 FPR（ViSpeak Implicit FPR 12.67 且 Recall 74 伴随大量假触发）揭示**选择性缺失**：会说话但不知道何时不该说。

**因果链**（每步标注证据来源）：
1. 自适应 SFT 平衡决策 token → 消除"永远沉默"偏置，Recall 上来（论文实验已支持：SFT 相对基座 Recall +10~+16）；
2. 点级 RL 奖励时机×内容匹配 → 抑制多余触发、集中到合适时机（论文已支持：RL 相对 SFT 的 FPR −6~−13.9、Timing F1 +4~+5.8，Monitoring 子类 FPR 降 15.3）；
3. Harness 意图生命周期显式管理活跃意图集合 → 修复"陈旧估计→重复建议"失效模式（论文已支持：Dynamic 意图 Content +6.4~+12.8 为三类最大；案例中基线重复过时建议而 StreamVibe 跟随任务状态更新）。

**结构必然性**：这不是"加了模块所以好"，而是问题本身被分解为两个正交子问题——证据定位（模型擅长，靠训练解决）与状态跟踪（长程簿记，靠显式状态解决）。把簿记塞进策略模型的隐式上下文，正是基线"陈旧响应"失败的根源。

## 6.2 PatEx-Gym：隐式信号 + 漏斗监督教会"转化"

**对比对象**：基线是零样本通用 agent（直接在 harness 里跑大模型）。它们有效因为大模型自带查询直觉，但 Select-R 天花板 32.4 说明"搜到"与"转化为法定证据"之间有巨大鸿沟。

**根本局限**：零样本 agent 的搜索行为没有受过"证据转化为 OA 论据"的监督——DeepSeek 的 Search-R 44.1 / Select-R 24.7 落差就是量化画像。

**因果链**：
1. visit 是隐式相关性信号 → 用它切分语义轮次，使质量评估有了"轮"的天然单位（设计层面成立；类比网页搜索点击反馈的经典结论，论文自引 Zhou et al. 2026 与 Joachims 2005 支持这一信号的有效性）；
2. 四维质量（尤其 s_evi 证据接地 + s_out 结果质量）筛选轨迹 → SFT 学到的不仅是查询技巧，而是"访问—取证—写入 OA"的完整转化行为（论文实验已支持：随机采样对照 Select-R 11.96 vs PASS 18.24，+51.6%——排除了"微调本身"的解释）；
3. 锦标赛保留向量结构 → 不同失败模式（会搜不会选/会选无接地）可分离（方法设计推理，属合理推断而非直接实验证据）。

**反事实检验**：Boolean-only 消融是漂亮的反证——剥离强检索工具后 agent 仍 +149.2%，说明学的是查询构造与迭代策略本身；换更强检索器反而 Select-R 下降，进一步坐实"瓶颈在转化而非检索"。

## 6.3 RCAtlas：规定性调用跳过决定性证据

**对比对象**：发表 agent 的设计哲学是把专家知识固化进控制流（SOP、固定阶段、角色分工）。它们曾在各自论文中有效——但那是在自采数据、弱 baseline、无对照的条件下。

**根本局限（机制层面）**：当程序决定读什么，它可能系统性跳过决定性证据。案例 rca100-main-0104（inventory 服务停止接收调用导致 cart 报错）的解剖入木三分：FoA 匹配到通用 SOP，其固定步骤**没有日志环节**，永远看不到 cart 日志里那条从 43 次涨到 609 次的 "Connection refused"——判定 cart 为根因（错）；mABC 沿调用链从告警下行，只检查"谁还在收调用"，**一个停止接收调用的服务在它的探照灯外**——停在 cart（错）；NSigma 按带符号 z-score 排序，inventory 请求量暴跌是负向偏离，在 373 列指标中排倒数第二（错）。而 SQL agent 用 31 条自己写的查询从症状反推"谁连不上谁"（对，107 秒），Codex 用 7 条命令对比全部实体前后状态（对，57 秒）。

**因果链**：程序规定调用 → 读取内容被流程先验固定 → 当决定性证据在流程之外（日志/调用缺失/负向信号）时不可达 → 诊断失败。prescribed-call ratio 把这个机制量化到了全部 90 案例：规定比为 0 的族全面胜过规定比 ≥0.10 的族。

**诚实边界（论文自陈）**：ρ 度量"固定了多少"而非"固定导致了失败"——严格因果需要把某个 agent 的规定 lifts 掉做消融（作者列为 future work）；发表 agent 内部 ρ 与准确率不单调。结论的准确表述是：**把领域知识焊死在控制流里，在程序与案例不匹配时有害；领域知识作为可选指导提供给模型可能更好**。

## 6.4 三篇合观的根源共性

| 论文 | 优势根源一句话 | 核心证据 |
|---|---|---|
| StreamVibe | 决策（模型）与簿记（显式状态）分离 | Dynamic 意图 Harness 增益最大；基线轨迹崩溃 |
| PatEx-Gym | 隐式信号筛选的轨迹教会证据转化 | 随机采样对照 +51.6%；Boolean-only +149.2% |
| RCAtlas | 规定性调用造成证据盲区 | prescribed ratio 0 vs ≥0.10 两族分界；案例解剖 |

外部检索说明：按任务约束，本节未做联网检索交叉验证，以上"根源解释"的每条因果链均以论文自身实验为证据并逐一标注；跨论文的互证（如 StreamVibe 的 Harness 与 RCAtlas 的简单 harness 都主张"显式状态好于隐式上下文"）只在三篇内部进行，属阅读者层面的一致性观察，非独立外部证据。

# 七、必要知识反推

假设让一个零基础的人分别重现这三篇工作，最少需要哪些知识？

## 7.1 领域知识层

- **StreamVibe**：必须理解"主动交互"与"被动问答"的范式差异（何为证据窗口、为何因果性约束重要）；需要视频基准构建的领域常识（数据源生态：Ego-Exo4D、HoloAssist、GUI-World 等）、标注质量控制方法（Fleiss' κ 审计、四审核者全票规则）。不懂"沉默也是决策"，就无法设计决策 token 加权。
- **PatEx-Gym**：必须懂专利法基础——新颖性时间窗（为什么 d_e < d_i 是硬约束）、OA 的法定结构（decision × statutory grounds，如 §101/§102/§103/§112 各自含义）、现有技术在审查中的证据角色。不懂"渐进披露"的审查实践，想不到 visit 工具这一设计。
- **RCAtlas**：必须懂微服务可观测性四件套（metrics/traces/logs/events 各自记录什么、什么故障在什么数据里留痕）；Kubernetes 实体层级（service/pod/node 的部署与调用关系）；RCA 领域的方法谱系与各基准的历史问题（不然无法设计八条排除规则——如"注入工具痕迹清除"直接对应反捷径审计发现）。

## 7.2 方法论知识层

- **训练方法**：SFT 的损失设计与 token 掩码（StreamVibe 的自适应权重、PatEx-Gym 的环境掩码）；GRPO/RL 信用分配问题（为何要局部 rollout 而非全轨迹）；拒绝采样与锦标赛选择（PASS 的排序设计）。
- **评测方法论**：这是三篇共同的隐藏主线。StreamVibe 需要 pointwise/trajectory 双协议设计直觉（隔离局部能力 vs 暴露误差传播）；PatEx-Gym 需要漏斗式召回分解（Search→Visit→Select）；RCAtlas 需要"同案例同评分器跨方法横评"的对照实验设计、aptitude/unreliability 分解、Pareto 前沿分析。不理解"指标要能区分能力假说"，就会退化成刷单一分数。
- **信息检索**：BM25/稠密检索/布尔检索的特性与互补性（PatEx-Gym 工具消融直接验证）；NDCG 等排序指标（PASS 轮内质量计算）。

## 7.3 工程知识层

- **Harness/沙箱工程**：三个工作都重度依赖执行环境——harbor 容器沙箱、Codex harness 的运行时（PatEx-Gym）；Codex CLI 的受控使用（RCAtlas 的六条规则）；流式 1 FPS 推理管线（StreamVibe）。这是"垂直 Agent"研究区别于纯模型研究的工程门槛。
- **数据工程**：百万级专利语料的统一 schema 去重（PatEx-Gym）；八源异构遥测数据统一格式与时间对齐（RCAtlas）；视频-意图-证据三元组的序列化（StreamVibe）。
- **LLM judge 工程**：多 judge 一致性（PatEx-Gym 三 judge Kendall W=0.849；StreamVibe 用 Claude Sonnet 4.6 做 0–4 评分）——judge 可靠性本身需要被审计。

## 7.4 知识融合的关键节点

三篇论文各自有一个"化学反应"节点，单科知识叠加不出来：

1. **StreamVibe 的融合点**：把"意图"从 NLP 概念转译为"带生命周期的状态机对象"——需要对话系统知识（意图）与系统设计知识（生命周期/状态机）在流式视频语境下碰撞。
2. **PatEx-Gym 的融合点**：把 IR 的"点击隐式反馈"传统迁移到 agentic 搜索的"visit 动作"——需要同时看到两个领域的形式同构性，这是本文最聪明的一步。
3. **RCAtlas 的融合点**：把 Sutton《The Bitter Lesson》的抽象论断压缩成一个可测标量（prescribed-call ratio）并配上 90 案例对照——需要哲学层面的怀疑（简单会不会更好）与度量设计能力的结合。

# 八、论文中可以提取的通用性灵感

**灵感一：把领域知识做成状态机，而不是做成流程。**
核心思想：领域约束（哪些意图还活跃、哪些证据已交付）适合显式状态管理；调查行为（看什么、怎么推理）留给模型。
论文证据：StreamVibe-Harness 只管意图生命周期不替模型做响应决策，Dynamic 意图 Content +6.4~+12.8；RCAtlas 反面印证——FoA 把调查流程焊死（ρ=0.51），日志证据在流程外不可达。
推广场景：①法律尽调 agent（哪些待核事实还活跃交给状态机，查证路径留给模型）；②医疗问诊（已排除的诊断维护成显式集合，追问策略留给模型）；③科研实验管理（假设生命周期状态化，实验设计自主）；④客户支持工单（SLA 状态显式跟踪，沟通策略自主）。

**灵感二：用户的隐式行为本身就是训练信号。**
核心思想：agent 与环境交互中的低意图动作（visit/点击/停留）是免费的相关性标注，可无监督地用于轨迹切分与质量评估。
论文证据：PASS 用 visit 锚点切轮次 + 四维质量筛选，使同预算训练数据价值提升（Select-R +51.6% vs 随机采样）；StreamVibe 的自历史退化分析（45–61%）同样是从行为轨迹中反推能力缺口。
推广场景：①代码 agent 用"文件打开顺序"做任务分解信号；②浏览器 agent 用滚动/回退行为识别无效搜索；③教育 agent 用答题停顿与回看切分知识盲区；④任何 deep research 系统用"引用了哪些访问过的段落"做证据接地自检。

**灵感三：评测要做成漏斗，不要做成终点线。**
核心思想：复杂任务的最终指标（决策对/回答好）会掩盖中间能力差异，把过程分解成多阶段召回/转化率才能定位瓶颈。
论文证据：PatEx-Gym 的 Search-R 48.7 → Select-R 32.4 落差揭示"转化"瓶颈，Dec. 与 Score 相关仅 τ=0.550；RCAtlas 用 PR@1×可靠性×成本三维定位每个方法的真实档位。
推广场景：①代码生成（编译通过率→测试通过率→评审通过率漏斗）；②客服（检索召回→引用准确→解决率）；③招聘筛选（简历匹配→面试通过→入职绩效）；④ RAG 系统（检索/引用/忠实三层漏斗已是同构实践）。

**灵感四：先跑裸模型基线，再造 agent。**
核心思想：任何手工 agent 设计前，必须先测"零设计的强模型 + 最小工具"这条底线，否则无法归因增益来源。
论文证据：RCAtlas 中每个发表 agent 都被不设计的 harness 以 14–24 点支配；PatEx-Gym 的 13 模型零样本横评同样是 PatEx-Agent 的对照底座。
推广场景：①任何垂直 agent 立项前的 baseline 仪式；②agent 论文审稿要求附 harness-only 对照；③内部工具评估先测裸 API 再谈编排；④数据标注质量审计（LLM 直答作为上限参照）。

**灵感五：规定的知识是负债，可选的知识是资产。**
核心思想：同样一份领域知识，强制执行在控制流里会在分布外案例上变成盲区，以提示/技能库形式提供给模型则保持灵活。
论文证据：FoA 的 12 个 SOP 中 4 个读日志但没匹配到该案例即全盲；RCAtlas 结论明确建议"把流程作为可选指导而非处方"；StreamVibe 的 10 个 Skill 设计恰好是"可选技能"形态（每次至多选 1，选了也不强制触发）。
推广场景：①运维 runbook 从硬编码流水线改为注入模型上下文；②合规审查规则以 checklist 提示而非代码分支实现；③临床指南作为 LLM 检索参考而非决策树；④游戏 NPC 行为树换成"目标+技能库"的自主规划。
