## 一、论文背景

在讲这篇论文之前，先补三个背景概念。

**形式定理证明（Formal Theorem Proving）**。普通的数学证明写在纸上，对错靠人审；形式化证明则把定义、定理、证明全部写成机器可检查的计算对象，由证明助手（如 Lean 4）逐行验证——要么编译通过、证明成立，要么报错、证明无效，没有中间态。对大语言模型来说，Lean 这类环境提供了一个近乎完美的反馈接口：模型生成的每一步证明都会立刻得到机器判定，不存在"看起来对其实错"的模糊地带。近几年 LLM 形式证明能力进步飞快，从高中奥数题一路打到了研究级数学。

**Mid-training（中期训练）**。主流 LLM 训练流水线分为预训练（pre-training，海量通用语料学语言和世界知识）和后训练（post-training，SFT/RL 对齐任务行为）两大阶段。Mid-training 是插在两者之间的一座桥：在预训练之后、后训练之前，用更干净、更贴近目标任务的数据继续训练，往往伴随学习率退火，让模型带着"任务先验"进入后训练，而不是从通用状态硬切换。OctoThinker 等工作已证明面向推理的中期训练能同时提升 RL 效率和最终性能。这篇论文把 mid-training 的对象从"推理"进一步推进到"agent 交互"。

**Agent 交互式证明 vs 完整证明对**。现有证明模型的主流训练数据是"完整定理-证明对"：模型看到一道题和一个写好的完整证明，学习一次性输出全证（whole-proof generation）。但另一条路线是 agent 式证明（agentic proving）：把模型放进一个可执行环境里，让它像人一样查看工作区、检索数学库、运行 Lean、读报错信息、反复修改草稿，在"编辑-检查-修订"循环中把证明磨出来。问题是：静态的完整证明对，和推理时模型真正经历的交互式轨迹，两者分布差异很大——模型在训练里从没见过"工具返回值长什么样""报错后该怎么改"，全靠后训练甚至推理时临时适应。

这篇论文的核心主张就落在这里：**把数学技能先验和与推理时同分布的 agent 轨迹，前移到 mid-training 阶段注入模型**，让后训练的起点更高。

## 二、论文定位和关联工作

论文将 LLM 定理证明系统分为三种范式：

1. **完整证明生成与修订**：从定理陈述直接生成完整 Lean 证明，代表工作 DeepSeek-Prover、Goedel-Prover、Kimina-Prover；后续版本引入迭代修复，如 Goedel-Prover-V2 的验证器引导自纠正，OProver 把检索、编译器反馈与多轮修复轨迹结合并直接训练。
2. **Agent 式证明器**：单个 LLM agent 与外部工具交互、根据输出调整策略，如 AxProverBase、Numina-Lean Agent（基于 Claude Code 通过 MCP 暴露 Lean 验证与定理检索）。
3. **编排式系统**：多个组件按预定工作流协作，如 Seed-Prover 1.5、Hilbert、LongCat-Flash-Prover、Goedel-Architect。

论文的定位是：编排系统的核心构件恰恰是强力的 agent 式证明器，所以本文专注提升 agent 证明器本身的能力——而且是**从训练阶段（而非推理脚手架）提升**。

与本文最相关的谱系对比如下：

| 系统/工作 | 路线 | 与 daVinci-Prover 的关系 |
|---|---|---|
| DeepSeek-Prover-V2（7B/671B） | 完整证明 + 子目标分解 RL | MiniF2F 73.9/82.4（pass@32†），本文大幅超越 |
| Goedel-Prover-V2（8B/32B） | 完整证明 + 脚手架合成 + 自纠正 | MiniF2F 79.4/85.8（pass@32†）；本文 SFT 数据取自其数据集 |
| LongCat-Flash-Prover | agent 工具集成 RL（编排式） | 最强变体 sketch-proof w/ TIR MiniF2F 93.9（pass@32†），本文 pass@8 即达 95.9 |
| OProver（8B/32B） | agent 式修复轨迹训练，65B token 中期训练 | 最直接的对照：MiniF2F 91.8/93.3（pass@32†）；本文用 33B token 配方在 FATE-M 上反超 +12.2 点 |
| Kimi-Dev / daVinci-Dev | 软件工程领域的 agent 原生 mid-training | 同一思想在 SWE 领域的先例，本文把范式迁移到形式证明 |
| OctoThinker | 推理向 mid-training | 论文引用其支持"mid-training 激励 RL 扩展"的论据 |

（† 表示分数直接引用自原论文，未在本文统一协议下重测。）

一句话概括定位：这是第一个（至少是最早一批）把"agent 原生中期训练"系统应用于 Lean 4 形式证明、并给出透明数据配方（data recipe）的工作，恰好回应了摘要开篇指出的痛点——该领域缺一套可复用的系统性提分配方。

## 三、问题定义

把论文的动机抽象一下，它要解决的核心问题可以这样表述：

**给定一个预训练基座模型和一个交互式证明环境（Lean 4 + 工具集），如何在 SFT 之前构造一份训练语料，使得模型既掌握证明所需的数学技能先验，又提前适应 agent 推理时的轨迹分布，从而让后续 SFT 更快收敛、最终证明能力更强？**

形式化地看，论文把这个问题拆成两个子问题：

1. **技能先验注入**：有效证明所需的行为——把目标分解为子定理（decomposition）、探索候选证明步骤（search）、验证中间推理（self-verification）、定位并修复错误（revision）——在既有语料里大多只在后训练或推理阶段才被暴露。能否把它们做成可复用的中期训练数据（skill priors），让模型"先学会怎么想"？
2. **分布对齐（distribution alignment）**：agent 推理时模型看到的是工具调用、执行结果、Lean 证明状态、验证器报错组成的交互序列；而静态训练里模型看到的是完整定理-证明对。能否在 mid-training 阶段就喂入与推理时同分布的环境原生轨迹（agent trajectories），弥合"静态下一词预测训练"与"交互式证明推理"之间的分布鸿沟？

这个定义里有个值得注意的设计判断：论文不认为两种数据可以互相替代，而是假设它们**互补**——"既知道如何思考一个证明（knowing how to reason about a proof），也知道如何通过环境交互实现这个思考（knowing how to realize that reasoning through environment interaction）"。后文的消融实验会正面验证这个假设。

## 四、问题解法

论文的解法是一条三段式流水线：构造 33.7B token 中期训练语料 → 搭建 daVinci-Prover harness → 采集 36K 轨迹做 SFT。

### 4.1 中期训练语料：daVinci-Prover 33.7B Collection

语料总规模 33.7B token（Qwen3.5 分词器计数），分两大成分。技能先验四类数据的构造方式各不相同：

- **定理分解与组装（8.43B token，466 万样本）**：教师模型（DeepSeek-V4-Flash 系列）拿到 Lean 定理及其验证过的参考证明，生成自然语言证明计划、带依赖信息的辅助引理、以及最终组装的完整 Lean 证明，训练模型"先拆再装"的规划能力。
- **验证过的子目标搜索（3.45B token，196 万样本）**：回放已验证的 Lean 证明提取中间状态和可执行快照；对每个状态，让提议模型生成多样 tactic，与参考 tactic 一起匿名、打乱、从同一快照独立执行，保留成功闭合、被接受的开放状态和 Lean 报错（剔除超时）。每条数据把候选 tactic 与执行结果配对，教模型比较不同走法、读懂形式反馈。
- **错误诊断与修订（3.84B token，103 万样本）**：给定失败尝试、诊断反馈和参考修正，教师模型合成结构化诊断——location（错在哪）、symptom（表现是什么）、cause（根因）、fix（怎么改），随后接显式修订计划与修正后的证明。
- **非形式推理与自我验证（5.70B token，8.3 万样本）**：取自 Nemotron-Math-Proofs-v2，用 DeepSeekMath-V2 风格提示构造，覆盖证明生成附带自评、证明验证（找漏洞、评质量）、元验证（审查自评或独立验证者的批评是否成立）。

第二大成分是**环境原生 agent 轨迹（7.17B token，39.7 万样本）**：模型在真实工具调用、执行结果、中间证明状态和 Lean 反馈中留下的交互记录——这正是与推理时同分布的数据。

此外还有 5.11B token 的**回放（replay）数据**：按目标配比给各来源分配回放预算，用来源专属评分挑选高质量父样本，覆盖不同问题以保多样性。原始数据源包括 NuminaMath-LEAN、AoPS、Lean Workbook、Goedel-LM/SFT dataset v2、OProofs。去污染环节剔除了 29 个与评测基准重叠的问题（占 2137 道评测题的 1.36%），涉及至多 11.55M token，仅占语料的 0.03427%。每条样本重构为统一训练文档，在自然边界处语义分块至最多 32K token。

### 4.2 daVinci-Prover harness：7 个工具的隔离工作区

harness 把定理证明组织成一个与 Lean 4 的迭代"编辑-检查-修订"循环。输入定理被原样拷入 `scratch/solution.lean`；agent 每轮从 **7 个工具**中选择：

| 工具 | 类别 | 功能 |
|---|---|---|
| file_read | 文件 | 读工作区文件或行区间 |
| file_write | 编辑 | 写完整工作区文件 |
| file_edit | 编辑 | 替换文本片段或行区间 |
| file_search | 搜索 | 按 glob 模式找文件 |
| content_search | 搜索 | 按文本/正则搜文件内容 |
| lean_retrieve | 检索 | 检索相关 Mathlib 声明 |
| lean_verify | 验证 | 检查 Lean 代码或 scratch 文件 |

设计上有几个要点：可写 `scratch/` 目录存证明候选，`sketch/` 存可选的引理分解草稿，只读 `target/` 提供用于验证的 Lean/Mathlib 工程；**每次编辑 Lean 文件自动触发验证**，草稿检查暴露局部目标与诊断，无占位符的候选进入严格验证；只有候选通过严格 Lean 验证、且声明与详化类型均与原定理匹配，episode 才算成功终止。刻意不暴露 bash 和 Python（只有这 7 个工具），为将来扩展 RL 留出干净的动作空间。

### 4.3 SFT：36K 高质量轨迹

用 DeepSeek-V4-Flash-0731 作为教师模型在 harness 里跑rollout：从 Goedel-LM/RL dataset V2 的约 99K 道未验证题中采样，限制最多 30 轮交互、200 次工具调用。从成功证明运行中筛出约 **36K 条高质量轨迹**，覆盖代数、数论、几何、分析、组合、拓扑、概率统计、线性代数、抽象代数、逻辑与集合论等领域。过滤规则包括：剔除过度重复或不必要工具调用的低质轨迹、少于 5 轮的轨迹，只保留能装进 144K token 上下文窗口的轨迹。实际 SFT 训练样本数 35,861，平均序列长度 36,445 token，P95 长度 84,446 token，5 个 epoch。

### 4.4 记忆压缩：规则式上下文回收

为支撑长程困难证明，推理时用了极简的、无需模型的轨迹压缩：上下文达到 200K token 即触发，把较早的交互替换为确定性抽取的工具证据，同时保留原定理、当前 Lean 证明和近期交互；最多允许 8 次压缩。所有压缩均基于规则抽取，不产生额外 LLM 总结调用（评测期间共 502 次压缩，前后快照的 token 计数与服务器记录完全对账）。

### 4.5 训练配置速览

两处训练的配置值得记录，方便复现者对照。**中期训练**：对 Qwen3.5-9B-Base 与 Qwen3.5-35B-A3B-Base 做全参数训练，自回归下一词预测目标，保留一层 MTP（multi-token prediction）辅助目标、损失权重 0.1；有效训练 token 33,699,997,413，物理 token 34,133,245,952（打包效率 98.73%），固定打包行 1,041,664 条、序列长 32,768；1 个 epoch 共 8,138 步，全局批 128 行（约 419 万 token/步），峰值学习率 5e-5，warmup 244 步（3%）+ cosine 退火至 0，权重衰减 0.1，梯度裁剪 1.0；MoE 模型保留预训练路由并施加系数 1e-3 的全局辅助负载均衡损失；样本级隔离通过逐样本累积序列边界实现块状对角因果注意力、重置位置索引与 Gated DeltaNet 状态。硬件为 4×8 张 H200。**SFT**：35,861 样本、最长 147,456 token（144K），5 个 epoch，全局批 128 样本（约 466.5 万 token/步），峰值学习率 3e-5（9B）/4e-5（35B），最低 4e-6，Adam betas (0.9, 0.98)。

## 五、评估指标与实验证据

### 5.1 评测协议

五个 Lean 4 基准覆盖从高中到大学竞赛的难度谱系：MiniF2F（244 道高中奥数题）、MathOlympiadBench（360 道近期竞赛题）、ProofNet（186 道大学水平定理）、ProverBench（325 道奥数+大学混合）、PutnamBench（672 道普特南竞赛题，最难）；另在 FATE-M/FATE-H（抽象代数与交换代数的教材习题/难题）上分析。统一条件：Lean v4.26 + Mathlib 固定 commit（2df2f015），温度 1.0，200K 上下文，最多 30 轮交互；能三次重复的报 pass@1 三次平均，否则报 pass@8。**任何引入公理或局部实例的证明一律拒绝**（包括 native decide），堵死绕过形式验证的捷径。

### 5.2 主结果：五个基准全部刷新已报告最高分

| Kimi-K2.5（pass@32†） | 1T-A32B | 7.5 | 76.6 | 19.9 | 44.3 | 1.2 |
| DeepSeek-Prover-V2-7B（pass@32†） | 7B | 7.9 | 73.9 | 18.1 | 45.7 | 1.5 |
| DeepSeek-Prover-V2（pass@32†） | 671B-A37B | 13.9 | 82.4 | 30.5 | 52.9 | 3.3 |
| Goedel-Prover-V2-8B（pass@32†） | 8B | 9.9 | 79.4 | 17.3 | 48.6 | 0.7 |
| Goedel-Prover-V2-32B（pass@32†） | 32B | 16.0 | 85.8 | 22.0 | 51.0 | 5.0 |

三个关键读数：其一，教师模型配 harness 的交互式 pass@8 全面超过所有完整证明方法的 pass@32——预算只有对手 1/4 仍最高（如 MiniF2F 95.9 vs sketch-proof w/TIR 93.9）；其二，蒸馏出的 9B 模型（MiniF2F 93.9）已超过 OProver-32B（93.3）；其三，mid-training 在两个尺度、全部五个基准上一致优于对应 Base+SFT，越难的基准（MathOlympiad、Putnam）提升越明显。

### 5.3 跨三个模型家族的一致提升

除了 Qwen3.5-9B/35B，消融用 Qwen3-8B 做严格对照：mid-training 相对匹配的 Base+SFT 在 MiniF2F/FATE-M/ProofNet 三基准平均提升 **+13.7 点**。训练动力学上，SFT 跑 1 个 epoch 后 mid-trained 模型的 miniF2F avg@5 已分别领先 9B +5.33、35B +5.08 点，且第 1 个 epoch 的 pass@5 即追平 Base 模型第 5 个 epoch 的水平。

### 5.4 数据组分消融：小体量 agent 数据为何更猛

Table 4（Qwen3.5-9B，MiniF2F / Fate-M / ProofNet）：

| 组分 | token | MiniF2F | Fate-M | ProofNet |
|---|---|---|---|---|
| Base | – | 87.4 | 88.4 | 42.9 |
| Dskill（四类技能先验） | 25.3B | 87.8 | 89.8 | 43.6 |
| Dagent（仅 agent 轨迹） | 8.4B | 88.8 | 92.2 | 43.5 |
| Dskill + Dagent | 33.7B | **90.1** | **93.3** | **44.5** |

最反直觉的一行：**只用 8.4B token 的 Dagent 在 MiniF2F 和 Fate-M 上超过了 25.3B 的 Dskill**。论文给出的解释正是分布对齐——Dagent 让模型提前见过推理时会遇到的同一套交互原语。两者合并再抬一层，证明互补而非可替代。

### 5.5 33B token 胜过 OProver 65B token

Table 5（Qwen3-8B，统一加 agentic SFT 5 epoch、YaRN 扩展 32K→256K）：

| 数据组分 | MiniF2F | Fate-M | ProofNet |
|---|---|---|---|
| Qwen3-8B-Base + SFT | 73.4 | 68.0 | 28.4 |
| Oprover-8B-Base + SFT（65B token mid-train） | 80.3 | 73.1 | 30.3 |
| Qwen3-Base + Midtrain（本文 33B token）+ SFT | **85.3** | **85.3** | **40.4** |

一半的数据量，Fate-M 反超 +12.2 点、ProofNet +10.1 点——中期训练的效果取决于**成分**而不仅是规模。

### 5.6 记忆压缩：释放长程证明能力

Table 6（pass@1 三次平均）：

| 模型 | MiniF2F | FATE-M | FATE-H |
|---|---|---|---|
| 9B midtrain（无压缩） | 90.1 | 93.3 | 16.7 |
| 9B midtrain（压缩后） | **97.1** | **96.7** | **28.0** |
| 35B midtrain（无压缩） | 90.1 | 93.7 | 16.3 |
| 35B midtrain（压缩后） | **97.1** | **97.3** | **42.0** |

MiniF2F 从 90.1 冲到 97.1 接近饱和；最难的 FATE-H 上 35B 模型从 16.3 跃至 42.0（+25.7 点）。压缩开销极低：26,708 轮记录中仅 502 次压缩事件、累计输入 22 亿 token、输出 9380 万 token，规则式抽取零额外 LLM 调用；Lean 验证调用累计约 11.02 小时、中位单次 0.734 秒、91.4% 的调用不超过 10 秒。

### 5.7 其他证据链

- **数据规模律**：在 7.5B/15B/22.5B/30B/33.7B token 检查点上，性能随规模近似 log-linear 增长；仅前 15B token 就带来 miniF2F +3.96、FATE-M +11.11 点，之后增益收窄。
- **harness 本身的价值**（Table 3，pass@1 三次平均）：给 harness 加上 mathlib 检索工具后，DeepSeek-V4-Flash 的 FATE-H 19.0→29.0、FATE-M 94.7→99.3、Putnam 18.9→22.8；Qwen3.6-35B-A3B 的 MiniF2F 68.0→73.0。收益跨模型背板成立。
- **行为层变化**：Putnam 高难度问题上，mid-trained 模型首个目标证明候选的平均局部分解步数（have/suffices）从 5.13→9.57（9B）、5.73→9.63（35B），步密度从 6.22→9.33、6.28→8.15（每 1000 词法 token），排除"只是代码更长"的解释；显式辅助检查通过率 11.8%→12.7%（9B）、12.6%→13.4%（35B）。工具使用模式上，前 5 轮 lean_retrieve 占全部调用一半以上，第 21–30 轮 lean_verify+file_edit 合计约 55–57%，呈现"先收集信息、后检查修订"的通用工作流。MiniF2F 上 midtrained 模型总调用更少（9B −8.75%、35B −2.65%）但成功任务略多；Putnam 上则维持更长交互、更多调用。

### 5.8 成本透明度

教师模型部署在 48 块 H200 上约 20 天，合计约 23,040 GPU 小时（含失败尝试与空闲）；按公有云 H200 每小时 5.29–6.35 美元折算约 12.2 万–14.6 万美元。Lean 验证另用约 8 个 worker × 20 核 CPU × 80GB 内存，合计约 160 核、76,800 CPU 核时。这种把数据合成成本完整摊开的做法在论文里相当少见，值得肯定。

## 六、效果优势的根源解释

### 6.1 mid-training 与 SFT 的分布对齐让收敛更快、起点更低

训练动力学证据（Figure 5）显示：mid-trained 检查点在 SFT 第 0 步的损失就显著低于 Base 模型，且整个训练过程始终与 SFT 分布更好对齐。这解释了"1 个 epoch 追平 Base 5 个 epoch"的现象——SFT 不是从零教起，而是把 mid-training 已建立的先验"格式化"到交互格式上。更细的证据是 9B midtrain 模型在 MiniF2F 上超过 35B Base 模型、尽管其最终 SFT 损失更高，说明增益确实来自 mid-training 而非拟合更好。

### 6.2 agent 轨迹体量小但同分布，单位 token 增益更高

Dagent 只有 8.4B token（消融口径；语料原始构成中环境原生轨迹为 7.17B token），却在 MiniF2F/Fate-M 上压过 25.3B 的 Dskill。机理在于：静态下一词预测训练与交互式证明推理之间存在分布鸿沟，Dagent 恰好让模型提前暴露于推理时会遇到的同一套交互原语（工具调用格式、执行结果、Lean 反馈），等于把"推理时的分布"搬进了训练期。Dskill 的作用则是另一维：强化分解、搜索、诊断、自验证这些可复用的推理先验。两者合并 (90.1/93.3/44.5) 超过任一单独使用，且跨三模型家族（Qwen3-8B +13.7 平均、Qwen3.5-9B/35B 全基准 +1~+3）方向一致，排除了单一家族偶然性。

### 6.3 规则式记忆压缩释放模型的长程能力（尤其大模型）

FATE-H 35B +25.7 点、9B +11.3 点的跃升说明：200K 上下文被旧交互塞满时，模型并非不会做题，而是有效上下文被稀释。规则式压缩把陈旧交互替换为确定性抽取的工具证据，等于把"工作记忆"腾给当前证明状态。收益随模型规模放大（35B > 9B），提示上下文管理是长程证明中与大模型容量正交但同样关键的瓶颈。另外 harness 的 lean_retrieve 检索工具独立贡献可观收益（FATE-M 94.7→99.3），与 mid-training 是两条并行机制。

### 6.4 交叉验证（WebSearch 外部证据）

- **【证据等级：高】** OProver（arXiv:2605.17283）的第三方论文数据库页面（MLSanity）确认其 MiniF2F pass@32 = 93.3%、ProverBench 58.2%、PutnamBench 11.3%，与本文 Table 2 引用数字一致——本文"pass@8 超对手 pass@32"的对比基础可信。
- **【证据等级：中】** 行业动态侧证：Mistral 于 2026 年 7 月发布 Leanstral 1.5，同样采用"mid-training + SFT + RL"三阶段训练 Lean 4 证明模型，并在 miniF2F 上报 100% 饱和、PutnamBench 解决 587/672（媒体报道口径，未读原文）。这说明"用 mid-training 做形式证明模型"已是行业收敛方向；同时 Leanstral 的更高分数也表明该赛道竞争激烈、本文价值在于透明配方而非绝对榜首。
- **【证据等级：中】** 方法论侧证：Emergent Mind 的 "Agent-Native Mid-Training Paradigm" 专题页把 Kimi-Dev、daVinci-Dev（论文引用的软件工程同族工作）等归入正在成型的"agent 原生中期训练"范式——即用真实动作-观察-反馈序列在中期训练阶段内化 agent 行为。daVinci-Prover 是该范式在形式数学领域的代表实例，范式本身有多领域并行证据。

结论：论文的核心论断（技能先验 + 同分布 agent 轨迹前移到 mid-training 有效）既有论文内部三家族、多基准、多消融的强证据，也有外部工作的方向性印证。

## 七、必要知识反推

要读懂并复现这篇论文，需要三层知识，融合节点在于"把分布式训练配方落到一个具体的可验证环境"。

**第一层：形式证明与 Lean 基础**

- Lean 4 语法与证明结构：tactic、have/suffices 局部引理、证明状态（goals）；
- Mathlib 库的组织方式与声明检索；
- 各基准的定位：MiniF2F（高中奥数 244 题）、ProofNet（大学 186 题）、PutnamBench（672 题）等；
- 证明有效性的严格标准：公理/局部实例/native decide 的排除规则。

**第二层：LLM 训练流水线**

- 预训练→mid-training→SFT/RL 的阶段划分与学习率调度（warmup 3% + cosine 退火、AdamW、MTP 辅助目标损失权重 0.1）；
- 数据工程：语义分块（≤32K）、样本打包（packing 效率 98.73%）、按来源配比回放、去污染（签名匿名化 + 精确匹配，20 token/80 字符阈值）；
- 长上下文扩展：YaRN 从 32K 到 256K；
- MoE 训练细节：路由保持、全局辅助负载均衡损失（系数 1e-3）、专家并行。

**第三层：Agent 系统与数据合成**

- 工具型 agent 的循环结构：观察→工具调用→结果→修订；
- harness 设计：隔离工作区（scratch/sketch/target 三目录）、编辑自动触发验证、7 工具的克制设计（不暴露 bash/Python 以便未来 RL）；
- 教师蒸馏：用强模型（DeepSeek-V4-Flash-0731）在 harness 里 rollout、按行为质量过滤（<5 轮剔除、144K 上限）；
- 轨迹分析：工具调用分布随轮次演化、分解步数/步密度、检索采用率（28.45%/27.01%/27.53%）等行为度量。

**融合节点**：这篇论文真正的门槛不在任何单层，而在于把三层拧在一起——用第二层的训练技术承载第一层的领域数据，数据本身又必须从第三层的 agent 环境中合成出来。理解了"语料里的每一条轨迹都要能真实发生在推理时"，就理解了 agent-native 的含义。

## 八、通用性灵感

**灵感一：把推理时的挣扎过程做成训练数据，而不是只喂完美结果**

- 核心思想：既有语料几乎只有"定理-完整证明"的成功样本，而分解、搜索、失败、诊断、修订这些真实证明过程被丢弃。把它们结构化后前移进训练，模型学到的是"怎么做"而不只是"做成什么样"。
- 论文证据：四类技能先验（分解 8.43B、搜索 3.45B、诊断修订 3.84B、自验证 5.70B）+ 修订诊断四字段结构（location/symptom/cause/fix）；合并后 MiniF2F 87.4→90.1（相对 Base）。
- 推广场景：(1) 代码生成模型训练中加入"报错-定位-修复"配对数据；(2) 科学发现 agent 学习"假设-被驳-修正"轨迹而非只学成功路径；(3) 数学文字题模型注入自我检查与元验证数据；(4) 法律文书起草模型学习条款冲突的诊断修订记录。

**灵感二：分布对齐的数据比规模更重要（Dagent 启示）**

- 核心思想：与推理时同分布的小量数据，单位 token 价值可能数倍于不同分布的海量数据。造数据前先问"模型推理时实际看到什么"，把那个分布搬进训练。
- 论文证据：8.4B token 的 Dagent 在 MiniF2F/Fate-M 上超过 25.3B 的 Dskill；33B token 配方胜过 OProver 65B token（Fate-M 85.3 vs 73.1）；前 15B token 即贡献大头增益。
- 推广场景：(1) SWE agent 的 mid-training 用真实 IDE 交互而非纯代码文件；(2) 搜索助理训练纳入真实搜索结果页的噪声结构；(3) 多模态 agent 提前接触传感器延迟/坏帧的观测分布；(4) 对话系统把真实用户的不完整、口语化输入纳入中期训练；(5) RL 前置的"环境原生 warm-up 语料"成为标准配方组件。

**灵感三：环境（harness）本身就是能力放大器，且应是训练数据的采集器**

- 核心思想：给模型一个干净、克制、可验证的交互环境，收益同时来自推理时（工具放大）和训练时（同一环境采集 SFT 轨迹，天然分布一致）。7 个工具的极简设计还预留了 RL 扩展空间。
- 论文证据：仅加 mathlib 检索工具，DeepSeek-V4-Flash 的 FATE-H 19.0→29.0、Qwen3.6-35B MiniF2F 68.0→73.0；同一 harness 蒸馏出 36K 轨迹，9B 学生 MiniF2F 93.9 超过 OProver-32B 的 93.3。
- 推广场景：(1) 数据分析 agent 配"沙箱 SQL + 采样预览"最小工具集；(2) 硬件设计 agent 配形式化验证器即时反馈；(3) 写作 agent 配事实核查器自动触发验证；(4) 任何领域先用 harness 收集教师轨迹再蒸馏小模型的两段式造数。

**灵感四：规则式记忆压缩是释放长程能力的免费午餐**

- 核心思想：不需要训练额外的记忆模块，用确定性规则把陈旧交互替换为抽取后的工具证据，就能把被稀释的上下文还给当前任务；模型越大收益越大。
- 论文证据：200K 触发、最多 8 次、502 次压缩零额外 LLM 调用；MiniF2F 90.1→97.1、FATE-H 16.3→42.0（35B，+25.7 点）；压缩开销仅占总输入 token 的零头。
- 推广场景：(1) 长程代码 agent 的会话历史压缩（保留测试结果、丢弃中间探查）；(2) 多轮研究的文献综述 agent 只保留结论性证据；(3) 游戏策略 agent 的战报压缩；(4) 任何 200K+ 上下文的成本敏感部署。

**灵感五：跨家族验证是好训练配方的试金石**

- 核心思想：一个数据配方如果在多个基座家族（Qwen3-8B、Qwen3.5-9B、Qwen3.5-35B-A3B）上都稳定提分，才配称为"配方"而非过拟合某一模型的巧合。
- 论文证据：三家族一致 +1~+13.7 点；两个尺度的 midtrain 模型在全部五个基准上一致超越各自 Base+SFT；行为层变化（分解步数、自检率）方向一致。
- 推广场景：(1) 数据配方论文的标准评审要求——至少 3 个基座；(2) 企业内部微调管线上线前的跨模型回归测试；(3) RL 奖励设计的前置多家族消融；(4) 用"行为指标"（如分解步数 5.13→9.57）而非只有分数来确认训练真正改变了策略。

最后提一句论文自己承认的局限：mid-training 阶段没有回放任何通用性数据，作者认为为保持/提升通用能力，加入通用回放既必要又重要。这提示读者：专用 mid-training 与通用能力的平衡仍是开放问题——这也是这套配方走向通用时必须补上的一块。

## 延伸阅读与个人评价

**顺着这篇论文往下读的路线图**：

- 想理解 mid-training 本身的理论定位，可读 Tu et al. 的 LLM mid-training 综述（arXiv:2510.23081）与 Zhang et al. 的《On the Interplay between Pre-training, Mid-training, and RL》（arXiv:2512.07783）；
- 想看同一范式在其他领域的实例，可读 Kimi-Dev（agentless 训练作为 SWE 技能先验，ICLR 2026）与同团队的 daVinci-Dev（arXiv:2601.18418，软件工程版 agent 原生中期训练），本文在相关工作里明确把二者列为方法论近亲；
- 想追最强对手，可读 OProver（arXiv:2605.17283）与 LongCat-Flash-Prover（arXiv:2603.21065）；
- 想了解自我验证数据的源头设计，可读 DeepSeekMath-V2（arXiv:2511.22570）。

**一句话个人评价**：这篇论文的单项技术（中期训练、工具 harness、轨迹蒸馏、上下文压缩）都不算首创，但它把四者拼成了一个证据链完整、成本透明、可复用的配方，并用"8.4B 同分布数据胜过 25.3B 异分布数据"这样干净利落的消融，把"分布对齐"这个抽象主张钉死在实验上。对于任何要做垂直领域 agent 的团队，这份论文值得当作数据配方设计的模板来读。
