# Read Less, Solve More：让 Agent 少读多成的稀疏读取控制层 精读

## 一、论文背景

### 1.1 Agent 的"阅读账单"问题

LLM 智能体（Agent）已经从单轮问答走向长程任务执行：写代码要翻代码仓库，做分析要读 PDF 报表，上网查资料要浏览网页。每一次工具调用返回的观察（observation）都会进入模型上下文，并且在后续每一次模型调用中被重复携带——这就是 Agent 推理成本的结构性特征：**成本随轨迹长度滚雪球式增长**。此前有研究统计，外部观察占 Agent 轨迹 token 处理量的 60-80%（论文引 SWE-Pruner 的观测）。

用一个直观的类比：Agent 读一个网页，就像一个实习生把整本 500 页的操作手册复印一份塞进文件夹，而他这次决策只需要其中第 137 页的两段话。更糟的是，这份复印材料会在他后续每一次翻阅文件夹时都被重新搬运一遍。

论文把这种现象命名为**过度读取（over-reading）**：外部工件以"整个对象"的粒度被访问，而每次决策实际需要的只是一小片有界证据。过度读取不只是浪费钱——多余内容会稀释相关证据，诱发错误的工具调用、来源混淆和"该停不停"。论文的配对实验显示，未修改的 Agent 最多消耗 17.3 倍的 token 却没有换来更高的任务质量。

### 1.2 现有手段为什么不够

围绕 Agent 上下文成本，业界已有一批优化手段，但它们都只治了一部分：

- **提示压缩**（LLMLingua 系列、Selective Context、Gist Tokens 等）：在内容进入上下文之后做词级/摘要级压缩，压缩本身需要额外模型调用，且不知道 Agent 当前的证据需求是什么。
- **KV 缓存压缩**（SnapKV、H2O、PyramidKV 等）：降低已进入上下文内容的计算与显存开销，但不决定"模型该看到什么"。
- **观察压缩与历史裁剪**（ACON、observation masking、AgentFold 等）：对工具观察或交互历史做事后压缩/遮蔽，同样发生在内容进入上下文之后。
- **RAG 检索**（含迭代式、agentic RAG）：能按需取段落，但缺少跨异构工件的统一读取契约——没有演化的读取意图记录、没有显式的来源覆盖跟踪、没有有界的暴露预算与全览回退。

一个 2026 年的行业共识是"上下文工程"（context engineering）取代提示工程成为 Agent 生产的核心学科——工具输出裁剪、历史压缩、按需检索被公认为最高杠杆的降本手段（Sourcegraph、Anthropic 的工程实践都印证了这一点）。SparseRead 的作者把这件事推到了更上游：**与其在内容进入上下文之后压缩，不如在准入（admission）环节就控制住**。

### 1.3 人类阅读的启示

作者从人类阅读行为中提炼抽象：人读材料时先明确目的，必要时扫一眼结构，聚焦相关段落，遇到未解决的细节再回看。论文称之为**稀疏读取（Sparse Reading）**：Agent 只读当前推理所需的内容，需要更多证据时再扩大读取。把它变成机制要解决两个挑战：一是信息需求随任务推进不断演化，每次部分读取必须记录"查过什么、还缺什么"，否则 Agent 会反复重访同一来源；二是稀疏访问并不总是划算——小对象或需要完整视图的请求，反复局部读反而更贵。这要求显式的证据状态、灵活的证据获取方式，以及对"继续稀疏读还是回退全览"的在线控制。

## 二、论文定位和关联工作

### 2.1 研究谱系

**谱系一：提示与 KV 压缩**。Selective Context、LLMLingua/LongLLMLingua/LLMLingua-2、Gist Tokens、AutoCompressors、ICAE 属于提示侧压缩；SnapKV、H2O、KIVI、CacheGen 等属于 KV 侧。它们处理的是"已经在上下文里的内容"。SparseRead 与之正交互补——它管的是内容进入上下文之前的准入，普通稀疏读取还会保留前缀不变以兼容前缀缓存。

**谱系二：Agent 观察与历史管理**。SWE-Pruner/SWE-Pruner Pro、Squeez 按任务需求修剪工具输出；CoACT、AgentDiet、TACO、ACON、AgentFold、observation masking（Complexity Trap）削减观察或历史。论文的定位是"在个体压缩器之上提供读取控制层"：其可插拔 Reader 接口允许 SWE-Pruner、Squeez 作为压缩后端接入，Read Intent Protocol 负责跨精化与验证协调这些后端。

**谱系三：主动阅读与检索**。ReadAgent（Google DeepMind，ICML 2024）是最近的精神先驱——受人类阅读启发，用 gist 记忆 + 选择性回查把有效上下文扩展 3.5-20 倍；IRCoT、Self-RAG 交错检索与推理；Adaptive-RAG 按问题复杂度路由检索。在 SparseRead 里，检索只是统一证据契约下的一种获取方法，与结构化投影、精确源操作并列。

### 2.2 与相近工作的关键区别

| 维度 | RAG（静态/迭代） | ACON/观察遮蔽 | ReadAgent | **SparseRead** |
|------|------|------|------|------|
| 控制时机 | 进入前（检索） | 进入后（压缩/遮蔽） | 进入前（摘要+回查） | **进入前（准入控制）** |
| 意图建模 | 查询词 | 无显式意图 | 隐式（gist 记忆） | **会话+访问双意图、五动作协议** |
| 覆盖跟踪 | 无 | 无 | 页级关联 | **按槽覆盖记录 + SHA-256 版本指纹** |
| 异构工件 | 文本为主 | 工具观察 | 长文档 | **文本/PDF/表格/JSON/代码库统一契约** |
| 暴露上界 | 无 | 无 | 无 | **每 episode 累计暴露 ≤ 2L** |
| 全览回退 | 无 | 无 | 无 | **预算耗尽前忠实回退** |

**定位结论**：SparseRead 是第一个把"工件读取"整体作为控制对象的工作——它不发明新的压缩算法或检索算法，而是定义了读取意图、证据状态与暴露预算的契约，让现有检索/压缩方法成为可替换后端。这类似于操作系统里"内存管理单元"相对于"具体页面置换算法"的位置。

## 三、问题定义

### 3.1 从具体到抽象

具体场景：Agent 下一步决策前，该从网页/文档/仓库/工具响应里读什么？直接定义"什么内容是有效的"很困难。论文的洞察是把它抽象为一个**准入控制问题**：在时刻 t，给定当前外部工件 o 和当前读取意图 h_t，选择暴露给模型的内容 x_t，约束是（1）保留任务相关证据，（2）跟踪 h_t 的覆盖状态，（3）控制后续读取的成本。

一个关键的概念切分支撑了整个抽象——论文区分了三个不必同步缩放的量：

| 概念 | 含义 | 类比 |
|------|------|------|
| 处理范围（processing scope） | Reader 扫描/计算的源内容量 | 厨师看遍全部食材 |
| 模型暴露（model exposure） | 实际进入模型上下文的内容量 | 端上桌的菜 |
| 证据覆盖（evidence coverage） | 当前意图下哪些槽位已有证据、哪些未解决 | 采购清单打勾情况 |

这个切分的精妙之处：**降低模型暴露不要求降低处理范围**。Reader 可以扫描整张表格算出列总和，却只暴露"结果 + 行数 + 来源"三行。这使稀疏读取同时兼容"局部化检索"和"全对象精确操作"两类需求，避免了"要么全读要么摘要"的二元对立。

### 3.2 形式化

给定工件 o、意图 h，求暴露内容 x_t 与读取策略，最小化累计暴露成本，约束为证据保真与覆盖可跟踪。Budgeted Read Gate 给出在线解法：以最便宜忠实全览 f(o) 的长度 L 为预算锚，稀疏证据累计暴露 E ≤ L，超限前回退 f(o)，从而每个读取 episode 的总暴露上界为 2L（命题 4.1，证明在附录 A，论证是紧的：常数 2 不可再改进）。注意这个上界度量的是无权重累计暴露，不约束回放加权上下文、计费 token 或延迟——作者对保证范围的诚实限定本身就是好品味。

## 四、问题解法

SparseRead 的架构分成**控制平面**（面向 Agent：解释意图、选择 Reader、维护证据记录、门控准入）与**证据平面**（可替换的 Reader 集合），两平面共享一个契约：**Read Intent → EvidencePack**。Agent 每次访问提交结构化读取意图，读取层返回带来源锚点、有界、附显式覆盖信息的 EvidencePack；证据是否充分、何时停止由 Agent 自己决定——协议不越权。

### 4.1 Read Intent Protocol：把读取变成有状态的过程

类比：这相当于给 Agent 配了一本"借阅登记簿"。每次访问要登记目的，登记簿记录哪些部分查过、哪些槽位还缺证据。

- **双层意图**：会话意图 h_s（来自用户初始请求）+ 访问意图 h_a（当前决策的具体需要）。访问意图优先级更高，会话意图只填充未指定的细节——避免旧目标覆盖新子目标。
- **五个稳定动作**：scout（看结构预览）、focus（聚焦定位）、collect（收集证据）、refine（精化）、verify（验证）。Reader 把动作映射到具体工件操作，新增 Reader 不扩大 Agent 动作集。
- **意图校验**：可操作的意图直接进入证据获取；欠规范的意图返回有界的对象预览（Object Preview）帮助精化——用结构信号而非任务特定规则判断。
- **版本指纹与覆盖记录**：SHA-256 指纹标识工件版本，版本变化即失效旧证据与覆盖记录；未变的版本上旧 span 仍有效，但可能不覆盖新意图。EvidencePack 中的覆盖是"哪些需求槽有支持证据、哪些未解决"，不是"证据足够了"——充分性判断留给 Agent。
- **episode 概念**：对同一工件版本、同一读取目标的一串访问构成一个 episode，内部共享证据记录与暴露预算。

### 4.2 Adaptive Reader Backends：定位与暴露解耦

类比：Reader 像不同类型的"检索员"，各自主攻一类工件；选择器像调度台，按"可靠且便宜"派单。

每个 Reader 注册其支持的工件类型、动作与成本画像，内部两个独立选择：**怎么定位/处理证据**（文本用词法匹配/BM25 窗口/混合检索；表格用列查询；JSON/日志用键路径查找；集合 Reader 先建清单再选文件），以及**暴露什么形式**（锚定片段/无损紧凑视图/精确操作的结果与出处）。Reader 配置 r = Reader × 定位方法 × 暴露形式的合法组合，所有配置产出同一 EvidencePack 契约。

选择规则是在可靠性约束下最小化估计成本：

```
r* = argmin Ĉ(r|g)  s.t.  p̂_valid(r|g) ≥ τ
```

其中请求组 g 由工件类型 × 尺寸段 × 意图类型构成；p̂_valid 是在人工标注开发请求上校准的可靠率——取 95% Wilson 区间下界（τ=0.6，评测前固定；校准请求与评测任务分离）。作者强调"平均证据召回率不是有效证据的概率"，这个统计上的讲究避免了选择器被偶然高分误导。无配置达标时回退全览而不是悄悄放水阈值。

### 4.3 Budgeted Read Gate：稀疏读取的"经济护栏"

类比：经典在线算法里的 ski rental 问题——不知道该"租"（稀疏读）还是"买"（全览）时，用累计租金逼近买价来决策。Gate 把这个思想迁移到累计暴露控制。

三条规则：（1）模型必须看完整内容或无合适 Reader 时直接全览；（2）小工件跳过稀疏路径；（3）否则从稀疏证据开始，强制 E ≤ L。交付每批证据前先估算规模与剩余预算比较，序列化后再实测校验；装不下就扣下这批、改交 f(o)，证据绝不截断到破坏语义或来源锚。全览交付后再次回退会复用已暴露视图。回退时此前的稀疏观察会从后续 prompt 中退役（retire）以避免继续回放——已付的成本不可退，但未来的重放被切断。

### 4.4 实现与集成

核心是一个共享运行时（协议 + Gate + 证据记录 + Readers + 桥接服务）。三个 Agent 框架（NanoBot、OpenCode、OpenClaw）只用薄适配器接入——OpenCode/OpenClaw 暴露 sro_preview/sro_read 工具并把本地读取/打开事件翻译为同一核心调用。面向模型的 SKILL.md 指引是建议性的；意图校验与预算在核心中强制，**不依赖模型遵守指引**——保证与合规解耦。实现的 Reader 覆盖：文本/PDF（页码/标题锚点 + 有界局部段落）、表格（schema/样本/行列投影，或全表精确计算只回结果与行数，或回可计算的 TSV 片段）、多文件集合（先清单后选文件）、脚本库。全程不需要改模型参数、不需要独立的生成式压缩模型。

## 五、评估指标与实验证据

### 5.1 实验设计总览

四个研究问题：RQ1 跨模型跨场景的效率与质量（六模型 × 五场景 = 30 设置）；RQ2 对比检索与压缩 baseline（三场景 × 五模型 = 15 设置）；RQ3 三组件消融；RQ4 框架可移植性（三框架 × 六模型 = 18 设置）。

**五场景与数据源**（全部 100% 纳入场景相关任务，不做挑选）：长上下文阅读（LooGLE、PinchBench、Workspace-Bench-Lite 年报事实抽取）；多文件审计诊断（QwenClawBench：数据完整性检查、配置与定时任务故障、命令前缀安全分析、服务审计）；结构化分析（QwenClawBench 统计/金融任务 + SpreadsheetBench Verified 表格操作）；Web 深度搜索（FRAMES 多跳 + BrowseComp-Plus 深研，固定语料）；AI for Science（MDGYM 的 LAMMPS 分子模拟脚本生成）。

**六模型**：Qwen3.6-Plus、DeepSeek-V4-Flash（中等）；DeepSeek-V4-Pro、GLM-5.1、Kimi-K2.5（领先开源）；Claude Opus 5（领先闭源）。

**Baseline**：Naive（未修改框架）；RAG Static（BGE-M3 检索 50 候选 + BGE-Reranker-v2-M3 重排，8 块/4096 token 一次性附加，之后不能再读源文件）；RAG Agent（同检索服务，可迭代调用 retrieve(query, scope)，保留原生工具，共享 SparseRead 的迭代与超时限制——对比公平性做得扎实）；ACON（观察+历史压缩，压缩调用计入成本）；Obs. masking（Complexity Trap 的固定策略：保留最近 10 条观察，遮蔽更早的）。

**指标**：端到端总 token 缩减、任务分数变化、墙钟时间节省（均相对 Naive；所有成本含检索/重排/辅助模型调用）。

### 5.2 核心结果

**主矩阵（图 6，30 设置）**：token 缩减 15.7-92.9%（中位 61.4%），时间缩减 23.0-89.0%（中位 53.7%），29/30 设置分数保持或提升（唯一回退：GLM-5.1 在 AI for Science -10 个百分点）。分场景看：长上下文任务省 token 76.5-92.9%、时间 67.1-89.0%；Web 深搜六模型分数全部 +5 到 +14 个百分点，同时省 31.0-43.0% token、23.0-37.0% 时间；Opus 5 在全部五场景省 41.0-89.0% token——**强模型依然受益于少读**。

**对比实验（图 7，15 设置）**：SparseRead 全部设置分数保持或提升，省 27.0-92.9% token、23.0-88.9% 时间；六设置 token 最少、九设置时间最短，在多文件诊断上五个模型同时做到双最低且分数 +17.8-34.5 个百分点。反观 baseline：RAG Static 在 Web 上更快但 15 设置中 9 个低于 Naive 分数；RAG Agent 8 个设置掉分、8 个设置比 Naive 更慢；ACON 5 个设置掉分、6 个设置双升成本；obs. masking 5 个设置掉分。

**可移植性（表 1，18 设置）**：NanoBot/OpenCode/OpenClaw 中位 token 缩减 65.0%/65.2%/30.6%，时间节省 59.3%/63.9%/28.8%，仅 3 个设置分数微降（0.013-0.031）。无需重训模型。

**消融（图 8）**：
- 意图协议：双意图组合把每任务重复读取从 4.8 降到 1.5（-68.8%），不可追溯证据从 28% 降到 8%，解决证据缺口的有效验证占比从 37% 升到 89%，因缺证据而失败的回答从 25% 降到 5%。
- Reader 定位方法（47 篇 LooGLE 文档 741 问，命中 = 覆盖 ≥80% 标注证据）：词法 39.5% 命中/780 字符，BM25 60.1%/1497，混合 65.3%/1490（比 BM25 多 5.2 个百分点几乎不加暴露）；BM25 扩窗反而掉到 56.7% 且暴露涨到 2106 字符——证实"单一后端不通行"。
- Gate 预算检查：交付前检查把全部暴露比压在 1.62-1.93（对照交付后检查可超至 2.10-2.33），验证 2L 上界在工程上成立。

**边界实验（附录 C，图 9，8 任务）**：对不适合稀疏读取的任务（全表统计、SPARQL 生成、折扣计算器），强制稀疏读取 token 反增 49.0%/309.0%/210.5%，而 Gate 反向节省 45.0%/22.5%/54.0% 且分数更高——**门控的识别能力是稀疏读取安全部署的前提**。

### 5.3 指标如何证明论点

这套实验的证明力来自三层：主矩阵证明"少读多成"跨模型跨场景成立（含最强闭源模型）；对比实验证明问题出在准入而非获取方式——同样能迭代检索的 RAG Agent 仍掉分变慢，说明缺的是意图/覆盖/预算契约；消融与边界实验建立因果——三组件各自的贡献可分离，且 Gate 在低稀疏任务上的回退行为被单独验证。评测方法学上，全量纳入场景相关任务（拒绝挑选）、校准请求与评测任务分离、成本端到端计入（不给自家方法藏辅助开销）都提高了可信度。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**因果链 1：证据稀疏性 → 控制准入是第一杠杆**
前提事实（论文实验支持）：标注支持证据中位仅占源 token 的 3.17-5.8%（LooGLE/Qasper），五类工作负载中有效证据占暴露预算 6-69% 不等。既然所需证据天然稀疏，整对象读取意味着 30 倍量级的无效传输；在准入环节裁掉它，收益直接作用于后续每一次携带该内容的模型调用。这是"结构上必然省"而非"调参凑巧省"。

**因果链 2：意图+覆盖记录 → 消除重复读取与无效验证**
机制：没有"查过什么"的记录，Agent 会反复重开同一工件、反复发起不解决证据缺口的验证。双意图协议把重复读取从 4.8 压到 1.5、无效验证从 63% 压到 11%（论文消融支持）。这回答了"为什么 RAG Agent 不够"——迭代检索也有查询更新，但缺跨工件跨工具的一致意图与证据记录。

**因果链 3：定位/暴露解耦 + 按工件选后端 → 跨工件类型的稳定证据质量**
机制：最优定位方法随工件类型变化（长文混合检索最好、表格列查询最好、JSON 键路径最好），单一检索管线必然在某些类型上失手。分离暴露形式后，全表计算也只需暴露结果+行数+出处——处理范围与暴露解耦让"精确操作"与"稀疏证据"共用一套契约（论文图 4(b) 与消融支持）。Wilson 区间校准把"可靠性"从平均召回的误导中解放出来（统计设计支持）。

**因果链 4：门控 → 适用边界自动化**
机制：稀疏读取并非普适最优（强制稀疏 +309% token 的反例）。Gate 用 ski-rental 式在线预算把"何时该全览"的判断变成机制而非猜测：E ≤ L 累计检查 + 2L 上界保证最坏情况劣化不超过原生读取的 2 倍，实践中 1.62-1.93（论文实验支持）。上界证明的诚实限定（不计回放/计费/延迟）避免了过度声称。

**因果链 5（阅读者推测，标注为推测）**：分数提升（如 Kimi-K2.5 长文 +0.598、Web 深搜全模型 +5-14pp）可能部分来自"少即是多"的注意力效应——冗余内容稀释证据、诱发来源混淆，这在论文的失败模式分析与外部文献（lost in the middle、ReadAgent 发现摘要优于原文噪声）中有间接支持，但论文未直接做注意力层面的归因实验。

### 6.2 相关工作检索与对照

| 研究 | 相似尝试 | 相关结论 | 与本文差异与适用边界 | 对根源解释的影响 |
|------|------|------|------|------|
| [ReadAgent（DeepMind, ICML 2024）](https://arxiv.org/abs/2402.09727) | 人类式阅读：gist 记忆+选择性回查，有效上下文扩 3.5-20 倍 | 证实"策略性少读优于被动全读"（QuALITY 上超全文基线） | 单模型提示工程，无工件契约/预算上界/多框架移植 | **支持**因果链 1、间接支持链 5 |
| [ACON（ICML 2026）](https://arxiv.org/abs/2510.00615) | 自然语言空间压缩观察+历史，峰值 token 降 26-54% | 小模型因去噪反而 +46%——压缩即增益 | 进入后压缩，无意图记录；作为 baseline 被本文实测 6 设置双升成本 | **支持**链 5（去噪增益），**对照**出"准入 vs 压缩"的位置差异 |
| [Complexity Trap（obs. masking）](https://arxiv.org/abs/2508.21433) | 保留最近 10 条观察、遮蔽更早内容，52% 降本 | 简单遮蔽 ≈ LLM 摘要的成本效果 | 固定位置策略，不看内容语义；本文实验中 5 设置掉分 | **限定**：无差别裁剪会丢关键早期证据——反衬意图驱动裁剪的必要 |
| [LLMLingua 系列（Microsoft）](https://llmlingua.com/) | 词级困惑度压缩提示，最高 20 倍 | 压缩比超 4-10 倍后多跳推理掉分 | 压缩工具调用提示会掉 5-10 点（业界实测）——不知任务需求的压缩有盲区 | **补充**：压缩适合冗余自然语言，不适合高密度结构化内容；SparseRead 按意图选暴露绕开此限制 |
| [SWE-Pruner / Squeez（2026）](https://arxiv.org/abs/2601.16746) | 按任务修剪工具输出 | 印证观察修剪是 coding agent 降本主战场 | 单一工件类型、无跨工件协议；SparseRead 可将其作为后端接入 | **支持**架构层"控制层+可替换后端"的定位 |
| [RAG 生产实践复盘（Logicbric 等 2026）](http://logicbric.com/insights/rag-not-enough) | top-3 比 top-10 更准（73% 查询）；多跳/分块边界是主要失败模式 | 证实"多读不等于多对"，检索质量是无人审计的失败点 | 经验性生产观察，非受控实验 | **支持**因果链 1 与链 3：证据选择质量比数量重要 |

### 6.3 综合判断与未决问题

**多研究共同支持的机制**：证据稀疏性（因果链 1）与意图记录消除重复访问（因果链 2）有本文消融+外部文献双向支持，最扎实。"去噪提升质量"（链 5）在 ReadAgent、ACON、RAG 复盘中反复出现一致性证据，但 SparseRead 内部未做归因实验，增益混有可能的"更好终止行为"等其他因素。

**仍属推测/未决的部分**：（1）Wilson 校准的 τ=0.6 阈值与请求组划分对分布外工件的泛化未验证；（2）2L 上界不覆盖回放加权上下文与计费 token——长 episode 下退役机制的实际收益未量化；（3）五场景中 Web 深搜基于固定语料（BrowseComp-Plus），开放实时网页的行为未测；（4）读取意图本身消耗的协议开销在小任务上是已知成本，Gate 的绕行规则是补丁式缓解，其判断错误的代价未系统评估。

## 七、必要知识反推

假设一个零知识的人要完成这项工作，最少需要掌握什么？

### 7.1 领域知识层

- **Agent 轨迹成本结构**：观察累积 + 每步重发导致成本随步数超线性增长；前缀缓存能降边际成本但不删内容——不理解这点就无法把"读取"识别为独立的一等控制对象。
- **LLM 长上下文的注意力退化**（lost in the middle 等）：知道"更多上下文"不等于"更好决策"，才能论证 over-reading 不仅费钱还伤质量。
- **异构工件的操作形态**：网页/PDF/表格/JSON/代码库各自的结构与可定位单元（锚点、行列、键路径、清单）——这是设计统一 Reader 契约的原材料。

### 7.2 方法论知识层

- **在线算法与竞争分析**：ski rental 框架直接启发了 2L 预算门控；需要懂得"不知道未来时如何设计有保证的切换策略"。
- **统计校准**：为什么平均召回不是有效概率、为什么要用 Wilson 区间下界——没有这层功力，Reader 选择器会做出自欺的选择。
- **压缩/检索研究脉络**：知道 LLMLingua/ACON/RAG 各自管哪段，才能找到"准入控制"这个空位，并把自己的方法定位为可组合层而非竞品。

### 7.3 工程知识层

- **Agent 框架的插件机制**：三个框架（NanoBot/OpenCode/OpenClaw）的工具注册与事件桥接方式，决定"薄适配器"路线能否成立。
- **端到端评测方法学**：成本须含辅助调用、任务须全量纳入、校准须与评测分离——这些是结论可信的前提。
- **形式化证明的边界意识**：能证明什么（无权重累计暴露 ≤ 2L）、不能证明什么（回放/计费/延迟），写清楚本身就是工程成熟度。

### 7.4 知识融合的关键节点

最有化学反应的三个节点：（1）**人类阅读行为 × Agent 成本结构** → 诞生"读取意图"这一抽象，而不是又做一个压缩器；（2）**ski rental × 累计暴露** → 把"何时回退全览"从启发式变成带上界的机制；（3）**处理范围/暴露/覆盖三分离 × 统一 EvidencePack 契约** → 让检索器、表格引擎、代码扫描器在同一接口下可插拔互换。单独任何一门知识都造不出 SparseRead；融合点在于把"操作系统式资源管理"的思维迁移到"上下文准入"这个新资源上。

## 八、论文中可以提取的通用性灵感

**灵感 1：控制准入优于事后压缩（关注点分离类）**
核心思想：在资源进入昂贵环节之前控制准入，比进入之后再清理便宜且安全。
论文证据：SparseRead（准入）对比 ACON/obs. masking（事后压缩）在 15 设置中后者普遍掉分或双升成本。
推广场景：数据库查询准入（查询预算门控）、API 网关限流、消息队列的背压设计、个人信息流的输入管理、代码 review 的 diff 裁剪。

**灵感 2：双时序意图 + 覆盖记录驱动的有状态访问（机制类）**
核心思想：任何"反复查询外部信息源"的系统都该维护显式的目标层级（会话目标 vs 本次访问目标）与已查/未查清单，而不是依赖隐式记忆。
论文证据：双意图把重复读取 4.8→1.5、证据失败 25%→5%。
推广场景：人机协作工具的记忆管理、爬虫的去重与增量调度、多轮对话系统的槽位跟踪、科研文献综述的证据台账、自动化测试的覆盖清单。

**灵感 3：定位方法与暴露形式解耦，按工件类型自适应（架构类）**
核心思想：没有全能的信息获取方法；把"怎么找"与"给多少"拆成正交维度，按上下文选择组合，并用量化可靠性门槛把关。
论文证据：最优后端随工件类型变化（长文 hybrid、表格 column、JSON keypath）；Wilson 下界校准防选择性偏差。
推广场景：多源数据集成的连接器选择、RAG 系统的检索器路由、监控系统的告警降噪通道选择、人才市场按岗位置信度筛选。

**灵感 4：带忠实回退的预算门控（机制类）**
核心思想：任何可能不适用的新策略，都要配上"最坏情况不超过基准 2 倍"的在线预算与无损回退，让新策略可以安全默认开启。
论文证据：2L 上界 + 交付前检查实测 1.62-1.93；强制稀疏在低稀疏任务 +309% 而 Gate 自动绕行反省 22.5-54%。
推广场景：A/B 实验的预算熔断、渐进式迁移的 shadow 模式、缓存策略的 bypass 规则、自动驾驶的最小风险策略切换。

**灵感 5：处理范围 ≠ 暴露量（范式迁移类）**
核心思想：计算可以看全集，但交付/展示最小充分结果——重计算轻传输在信息消费场景普遍成立。
论文证据：表格 Reader 全表扫描只暴露"结果+行数+出处"。
推广场景：BI 工具的服务端聚合、API 的字段裁剪（GraphQL 按需取数）、隐私计算的最小充分统计量披露、可视化的大规模数据抽样渲染。

**灵感 6：诚实限定保证范围，保证才可信（研究方法类）**
核心思想：明说理论保证不覆盖什么（计费/回放/延迟），比含糊的强声明更有工程价值。
论文证据：命题 4.1 的范围限定与"常数 2 是紧的"论证；附录 C 单独验证边界行为。
推广场景：任何分布式系统的 SLA 定义、安全声明的适用域标注、统计结论的置信区间报告文化。
