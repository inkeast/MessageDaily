> **机构**：Johns Hopkins University（Bowen Sun、Chaowei Xiao，单一高校，无企业合著；两位作者亦是攻击性前作 arXiv 2611.20291 的作者）
> **领域标签**：cs.DC / 系统安全 / LLM 服务

## 一、论文背景：前缀缓存是效率利器，也是泄露窗口

要读懂这篇论文，先要理解四个层层递进的概念。

**LLM 推理的 prefill 与 KV cache 是什么。**

大模型每次响应都要先处理完整个输入提示（prompt）才能吐出第一个词元，这个阶段叫 prefill（预填充）。处理过程中，注意力机制会为每个词元算出一对 Key/Value 张量，统称 KV cache。因果注意力决定了 KV 值只依赖左侧上文、与后文无关，所以同一段开头文本算出的 KV 完全一样——这是前缀复用在数学上合法的原因，也是本文全部故事的地基。

**前缀缓存（prefix caching）是什么。**

很多请求的开头是相同的：agent 的系统指令与工具定义、应用系统提示、RAG 检索到的文档、多轮对话的历史。既然 KV 只依赖前文，服务引擎就把已算好的前缀 KV 存起来，后续请求若以相同前缀开头就直接复用、跳过这部分计算。vLLM 的官方评价是『几乎免费的午餐』。

在 prefill 集群（预填充与解码分离部署的算力池，预填充实例算完首词元并把 KV 传给解码实例）上，配合缓存感知路由（cache-aware routing，把相同前缀的请求送往持有该前缀缓存的实例；vLLM、SGLang、llm-d、NVIDIA Dynamo 等生产级路由器都内置该能力），这项优化的收益尤其大——论文的会话型负载下，无保护共享能从缓存服务 61.8% 的提示词元。

**时序侧信道（timing side channel）是什么。**

缓存命中会让第一个词元提前到达，而这个时间差是稳定、可重复测量的。攻击者发一个以猜测前缀开头的请求：命中则首词元快，未命中则慢——系统等于悄悄回答了『这段前缀最近有没有人用过』。一个比特一个比特地问，就能逐词元拼出别人的完整 prompt。

- Gu et al.（ICML 2025）的审计发现 17 家商用 API 中有 7 家存在跨用户全局缓存共享；
- InputSnatch、EarlyBird 等工作展示了完整的 prompt 重建攻击；
- NDSS 2025 的 PromptPeek 在 SGLang 上报告 95%–99% 的重建成功率。

此后 Anthropic、OpenAI、Google 都把缓存共享范围收缩到账户（组织/工作区/项目）内，vLLM 和 SGLang 提供了给缓存键加盐（cache salt）的隔离机制，Fireworks 提供隔离键（isolation keys）——这些都是对时序攻击的直接回应。

**为什么账户边界不够。**

这篇论文的关键洞见是：账户隔离隐含『同账户内所有请求互相信任』的假设，而这个假设在三种现实场景下失效。

1. **agent 时代**：agent 未经人工审查就发送携带私有数据的请求，且可能被不可信内容注入指令，去探测同账户下的其他请求，并通过网络或文件系统外泄所获；
2. **中转站与经销商**（relay/reseller）：把大量最终用户 pooling 在一个账户后面共享一份缓存，已有测量工作观察到中转商在生产环境合并客户身份；
3. **凭证被盗**：既暴露 prompt 又产生账单。

作者因此提出**最小权限原则**（least privilege，Saltzer & Schroeder 1975）的严格版本：持有一个 API key 只应授权发送请求和付费，不应授予窥探同账户下其他请求的能力——默认每个请求自成一个隔离域，确实需要共享的请求显式加入命名共享组。论文标题 Isonomy（源自希腊语『人人平等之法』）即指这种『每个请求一律平等隔离』的默认。

最朴素的解法是给每个请求的缓存键加独立的盐（fresh salt per request），让任何请求之间都不能复用缓存。但论文实测这个方案只能保留无保护共享吞吐的 0.381——等于放弃了前缀缓存的绝大部分收益。账户级加盐稍好（会话负载 0.945），但在跨账户复用多的负载上掉到 0.802。

于是核心问题变成：**能否既全集群共享一份缓存，又让任何请求都察觉不到别人的命中？**同时还有一层更隐蔽的困难：多实例集群上命中会改变请求的路由去向，这让问题比单实例复杂得多。

## 二、论文定位和关联工作

这项工作处在『LLM 前缀缓存时序侧信道』这条快速形成的研究线上，可以按攻击、防御、理论前作三条谱系梳理。

**攻击谱系。**

Gu et al. 的审计（ICML 2025）首次系统测得商用 API 的跨用户缓存共享；EarlyBird（arXiv 2409.20002，TIFS 2025）与 InputSnatch（arXiv 2411.18191，APPT 2026）用首词元时延逐词元重建他人输入；PromptPeek（NDSS 2025，即『I know what you asked』）在 SGLang 上重建系统提示；OptiLeak 利用最长前缀匹配调度下的响应顺序；后续工作还挖掘了共享批次的数值输出（量化、MoE 路由）、聚合 KV 用量等间接信道。网络侧观察者还能从流的大小与计时中推断推理优化。这些攻击共同确立了：**任何数据依赖的性能差异都是潜在信道**。

**防御谱系——此前全部是单实例方案。**

- **限制共享**：CacheSolidarity（Middleware 26，前称 PrefixWall）只允许复用到首次跨账户复用点为止，保住最多 70% 复用；SafeKV 按内容敏感度异步分类选择共享；KVGov（arXiv 2608.09225）用 HMAC 按主体加盐隔离命名空间、以边界加盐保住约 93% 收益；PrivKV-Sched 限定跨租户命中预算。
- **延迟对齐**：把命中填充到未命中延迟（如延迟均衡方案、Mirage 的拓扑感知填充与隐私里程表）。
- **加盐分区**：vLLM/SGLang 的 cache_salt（2025 年 4 月合并，官方理由就是时序攻击）、Pang et al. 的缓存分区。

这些方案的共同盲区是：**它们都只在单个实例上评估**。一旦实例组成集群并启用缓存感知路由，命中会把请求送往持有前缀的实例 R，而未命中送往最空闲实例 S——两个世界走的是不同队列、面对不同负载，单实例视角的隐藏形同虚设（论文表 4 中『per-instance hiding』在实例加入场景下被单探针以 0.433 的优势检出，而同一场景下 Isonomy 预测模式仅 0.074）。

**理论前作——作者自己的攻击论文。**

这是理解本文动机的钥匙。同一作者五天前发布的 arXiv 2611.20291《Where the Savings Go: The Limits of Hiding Cross-Tenant Cache Hits in LLM Serving》证明：step 型调度器在还有工作等待时从不空转，命中省下的时间会**完整传递给排在后面的每个请求**；攻击者用自己的『监听者』请求夹住探针、数它们几个 step 跑完，即可从他人时序中检测命中。

- 生产 trace 回放下，单探针检测 256 token 以上的缓存文本优势至少 0.98；
- 仅隐藏探针自身时序的防御在 vLLM 与 SGLang 上全部失效；
- 随机延迟要把优势压到 0.1 需达到约十倍偏移量；
- 速率受限租户从共享获得的任何可观测收益本身就是信号（零泄露时只有服务商保有节省）。

Isonomy 正是对这篇『不可能性』论文的建设性回应：先证明商用 API 上这种间接信道（负载可见性）实测不可见（定理 1 的经验前提），再针对直接探针给出完整集群防御。

**经典防御思想的血统。**

预测模式继承 Askarov、Zhang、Myers（CCS 2010）的 predictive black-box mitigation（用预测调度释放事件、约束单位时间泄露量）及其交互系统版（CCS 2011）；执行模式继承 Obladi、Camouflage、StopWatch、SME 等固定共享工作形状的 dummy/replica 设计；最优传输部分用到 Santambrogio 的单调映射理论；负载可见性的经验测试思路呼应 Pacer 的『只控客户端可见物』与共居攻击的实证传统。记忆去重（KSM）被时序攻破后各管理程序停止跨 VM 合并页面的历史，则是『共享优化向安全妥协』的先例——Isonomy 想证明 LLM 缓存不必走到那一步。

| 维度 | 之前的路线 | Isonomy 的突破 |
|------|-----------|---------------|
| 防御范围 | 单实例 | 缓存感知路由的多实例集群（首个） |
| 隔离粒度 | 账户级（信任假设强） | 请求级（最小权限，可显式建组） |
| 缓存共享 | 隔离方案放弃跨域复用 | 全集群一份缓存，只隐藏组外命中 |
| 隐藏对象 | 命中-未命中延迟差本身 | 释放时间对齐 miss twin 的分布 |
| 安全论证 | 多为启发式 | TV 距离界 + 可运行的负载可见性测试 |
| 吞吐代价 | 逐请求加盐仅保留 0.381 | 预测模式保留 0.984 |

定位结论：Isonomy 是首个把『路由信道』纳入威胁模型并给出集群级时序侧信道防御的系统，且以同作者的攻击论文为边界，明确划定了适用部署条件（客户端互相观察不到负载），并与 CacheSolidarity/Mirage 等策略互补——无论策略允许哪些命中，Isonomy 负责在集群上隐藏其时序。

## 三、问题定义：把『隐藏一次命中』抽象为两个世界的分布等价

论文的抽象非常干净：**反事实世界对**（counterfactual worlds）。对探针请求 x，定义两个仅在 x 的组外命中上不同的世界：

- **命中世界 h**：x 的前缀已在组外缓存，x 复用它；
- **未命中世界 m**：x 未命中，其余所有请求的到达与命中完全不变。

x 在世界 m 中的形态就是它的 **miss twin（未命中孪生）**——同一个请求，只是把组外命中改成未命中。防御知道自己在哪个世界，攻击者不得而知。

防御目标是让攻击者无法区分两个世界，形式化为：给定两世界公共信息 I，首词元释放时间 Zh 与 Zm 的**总变差距离** TV(Zh, Zm) ≤ ε（ε-安全）。这个距离恰是单探针优势的上确界，定义与测量直接挂钩。使用与计费也跟随 twin——缓存的词元按未命中计数入账，防止 usage 字段与账单本身成为信道。

**信道分解。**

命中影响可观测时序的路径有三条：

1. **直接信道**：自己的首词元提前；
2. **路由信道**：被送往持有前缀的实例 R 而非本应去的 S，面对不同队列与负载；
3. **间接信道**：省下的算力让排在自己后面的其他请求提前。

对间接信道，论文定义**负载可见性**（load visibility）：一组监听者分辨『某请求存在与否』的优势 Λ = TV(观察值, 无 x 时的观察值)，并证明定理 1：任何监听者区分命中与未命中的优势 ≤ Λh + Λm；更强地，联合观察（探针 + 监听者）的泄露 ≤ ε + Pr[监听观察被 x 改变] 之和。

负载不可见时只需防御直接探针——这是全设计的适用前提，且**无需命中即可测试**：发一个 98K–131K token 的全新长 prompt 或 64-token 短 prompt（等概率），监听者尝试从自己首词元时间中分辨两者，读到的是『追加了工作』的可见性上界。商用 API 无法区分即通过。

**这个抽象的精妙之处有三。**

其一，把『隐藏一次缓存命中』归约为『一次反事实模拟的分布对齐』。miss twin 成为唯一需要的锚点——未命中请求本身就是自己的 twin，无需任何延迟；命中请求则有了自己的、随负载自适应的释放目标，而非全局填充常量。

其二，把集群复杂性化归到单实例。命题 1 说：只要网关关于 x 的所有决策只用两世界公共输入，且逐条件 ε-安全，则全局 ε-安全——『多实例』这个维度被条件化消掉了。

其三，释放时间的可行性由定理 2 完整刻画：存在满足 φ(y) ≥ y（不能提前释放尚不存在的词元）的（可随机化）映射，把两个就绪时间分布都送到同一目标分布 Q，当且仅当 Q 在每个分位数上同时压过两者（Q 的分位数 ≥ max(Fh⁻¹, Fm⁻¹)）。分位数逐点最大值定义的 Q* 是被一切可行目标支配的最优目标，且当未命中分布 Fm 随机占优 Fh 时 Q* = Fm——**未命中无需任何延迟，防御只需处理命中**。这一条直接决定了系统的吞吐底线。

## 四、问题解法：网关路由 + 双模式释放控制器

Isonomy 基于 vLLM 0.26 实现（不修改引擎）：网关约 4000 行 Python 单异步进程，另有约 2200 行以自定义调度器类加载进 vLLM。网关精确追踪每个实例的缓存（总体与按共享组），为每个请求标注所属组（默认仅自身）。解法由三件套组成，分别封掉路由信道与直接信道。

**第一件：twin 路由（解决路由信道）。**

网关在请求到达时，把部署的缓存感知路由规则**只应用于负载与该请求共享组可见的缓存条目**——这些输入在两个世界中相同，故 twin 的实例 S 在两个世界中分布一致，命中不再能把请求挪进另一个队列（命题 1 的条件由此满足）。全请求隔离下，S 就是『无任何缓存匹配』时规则选出的实例。

请求本身仍可被送往持有者 R 去用命中（跨实例命中占命中 token 的 0.34–0.78，随实例数增多而上升），只是其释放时间仍由 S 上的 twin 决定；若预测到在 R 上反而赶不上 twin 的释放时刻，网关就放弃这次命中、让请求在 S 上按未命中执行。命中与否从此不再改变『你在哪个队列』，只改变『你何时被放行』。

**第二件：预测模式（predicting the twin）。**

思路是『重构 twin 的执行、只预测它的时长』，分三步：

- **步重构**：vLLM 调度器是先来先服务 + 每 step 固定 token 预算，twin 的等待步/执行步及其形状（步内各请求的块长与起始深度）完全由到达时刻的队列决定，网关从自己的路由日志可确定性重构——那些『从未运行过的步』的形状是可知的，只是时长不可观测。对真正跑在 S 上的未命中请求验证：98.5–98.9% 的情况预测的第一步正确，其余仅差一步。
- **时长模型**：离线拟合线性公式 d(σ) = a0 + a1N + a2·Σᵢ nᵢ(sᵢ + nᵢ/2)，其中 N 为步内 token 总数、nᵢ/sᵢ 为第 i 块的长度与起始深度，二次项显式建模『更深开始的块更贵』与 128-token 阶梯；在两块 L40S 的 65,876 个 step 上残差标准差 3.34ms，逐实例在线校正因子后降到 2.2–2.4ms。对 twin 各步求和得预测就绪时间 B，再用近期未命中的实际-预测残差估计 miss 就绪时间围绕 B 的分布 F。
- **随机化门**：直接做一对一最优传输映射对预测偏差极敏感——残差散布 10–30ms 时，把优势压到 0.05 只容得 1–4ms 的偏差，离线回放中该映射确实泄漏（上界 0.071）。故改用门 V = B + γ，释放时刻为 max(就绪时刻, V)。γ 从 miss 残差分布 F 的中位数到 1−ε 分位数之间按分布函数 G(r) = ε/(1−F(r)) 抽取（在中位数处放置 2ε 的质量，在 c 处取 1）。命题 2 证明：只要每个命中都在 B + 中位数前就绪，该门即 ε-secure——两释放分布仅在门区间内差常数 ε 的质量、在端点各差 ε。相对固定门 B + c，随机化门平均少扣押请求 12–17%。

工程细节上，网关按预测时长与提示长度分类维护残差分布（每类保留最新 400 样本，不足 50 时用池化分布）；短于 1024 token 的命中省不了多少时间、不值得移动使用；跨实例命中要在『R 上预测就绪 + 命中残差 0.75 分位 ≤ S 上 twin 预测 + 未命中残差 0.25 分位』时才接纳。

**第三件：执行模式（executing the twin）。**

当 Fm 占优 Fh 时，miss 分布本身就是最便宜目标、未命中可即算即走（如无保护共享）；执行模式干脆**把 twin 真的跑出来**当计时器：在 x 的队列位置插入一个虚拟请求（virtual request），占住命中跳过的 n 个 token 槽位（从深度 s 到 s+n，s 是自己组内已缓存的部分）。调度器把槽位当普通请求对待，使每个 step 的形状与未命中世界完全一致——x 的块就是 twin 的收尾块，首词元在两个世界由同一个 step 产出（Yh = Ỹ 按设计成立）。

槽位不能空转浪费算力，**替代者（substitute）规则**：从等待队列选一个其共享组已缓存至少前 s 个 token 的请求 x'，让它从深度 s 起在槽位里算自己的真工作。

- 从不同深度起算的块成本不同，故要求它读齐前 s 个 token、重算槽内遇到的已缓存部分；
- x' 比槽长则剩余部分照常后排；比槽短则末尾用 dummy token 补形；无合格者则整槽全 dummy（含 dummy 的块永不进前缀缓存）；
- 替代者还须未启动且在 x 后面至少排着一个整预算的工作量，保证未命中世界里本会填进 twin 收尾步的请求留在原位；
- 跨实例时 R 上的 x 提前算完、S 上跑覆盖 twin 全程的虚拟请求定钟，预测加 500ms 裕量决定是否接纳（22,513 个接纳命中中仅 14 个晚于 twin）。

命题 3 给出 ε ≤ Pr[Yh > Ỹ] + TV(Ỹ, Ym)：槽位按设计运行时第一项为零。递归替代（最多 4 层）让替代者自带命中并把整槽继续下传，减少整 twin 执行浪费；网关侧的候选池让实例能取用全集群的等待请求（32 实例时每实例候选从 0.8 涨到 13 个）。

| 组件 | 输入 | 输出 | 作用 |
|------|------|------|------|
| twin 路由 | 负载 + 可见缓存条目 | 实例 S | 两世界路由分布相同，消除路由信道 |
| 预测模式 | 队列重构 + 步时模型 + 残差分布 | 释放门 V = B + γ | 命中释放时间对齐 twin 分布（ε-secure） |
| 执行模式 | 虚拟请求槽位 + 替代者 | 真实执行的就绪时刻 | 用真计算保形计时，免步时标定 |
| 负载可见性测试 | 自有请求 + 监听者 | 优势上界读数 | 部署前提的可运行检验 |

**扩展到更难的设置。**

- **MoE 模型**：专家激活使步长依赖内容，未修正时执行模式泄漏优势 0.68–0.80；修正方案为按内容类取最慢步时、用 dummy 重算命中前缀以激活相同专家、或按内容类取最晚 twin 时刻——27 个上界全落噪声内、无一超过 0.094；
- **张量并行多卡**：Qwen3-32B × 双 A100 NVLink，步长仍循 128-token 阶梯且同形状散布更小；执行模式沿用 L40S 定时参数上界仍 0.030——体现『真执行免重标定』优势；
- **分离解码**：解码实例在首词元释放时才收到请求、按仅依赖提示长度的延迟接纳、不缓存前缀；命题 4 证明观察全部词元时刻的优势 ≤ 首词元优势 + 负载差异，实测 ≤ 0.092。

## 五、评估指标与实验证据

**指标体系。**

主指标是**单探针优势 ε 的 95% 自助法上界**：hit/miss 各半概率下，分类器仅凭一个首词元时间猜对的概率至多 (1+ε)/2；用一半探针选阈值、另一半 held-out 估计。估计量只用秩，故无效应时上界分布只依赖每世界探针数。

关键设计是**噪声界**：无效应时上界的模拟 95 分位（1,000 探针/世界为 0.088，7,400 时为 0.029）——上界 ≤ 噪声界才称『不可读』（unreadable），这把『指标好看』与『真的证明了不可区分』在统计上分开。

辅助指标：饱和吞吐保留比（相对无保护共享）、给定 TTFT SLO 下 90% 请求达标的最高到达率（goodput，按无保护饱和吞吐归一）、TTFT p90 增量、端到端 8 选 1 识别率（猜中受害者 prompt 的比例，随机 0.125，其噪声界由 Wilson 区间模拟给出）。

**测试床与负载。**

每实例 Llama-3.1-8B-Instruct + 单块 L40S，16-token 缓存块、2048-token 步预算、147,200-token KV 池；2/4/8 真实实例端到端，模拟与校准外推最高 4,096 实例。三种负载刻画不同复用结构：

- **会话型**：40,000 请求、平均 3,680 token；59% 延续对话、20% 查询跨账户共享文档、10% 开新对话、10% 全新；无保护缓存服务 0.618 的提示词元、账户隔离仍有 0.597——复用主要在账户内；
- **构造型**：把复用从对话搬到跨账户共享文档；无保护 0.568、账户隔离只剩 0.461——专门放大账户隔离的代价；
- **Mooncake 公开 trace**：真实生产会话，仅 0.288 缓存命中且无账户标签，两个加盐基线在此合一。

五个对照臂用同一路由规则发同样的请求：无保护共享、按账户加盐、逐请求加盐、预测模式（ε=0.01 门）、执行模式。安全实验里每 4 个常规请求夹 1 个探针试验：受害者用全新账户发 2048 或 7168 token 前缀 + 新尾部，0.2 秒后探针发 P（命中世界）或不同前缀（未命中世界）。

**安全结果。**

（1）主表：2/4/8 实例 × 2048/7168 token 命中，双模式共 **12 个上界全部落入噪声界**（0.019–0.051 vs 噪声 0.029–0.059）；无保护共享下 7168-token 命中优势高达 0.186–0.249。2048-token 命中在无保护下本就难测（节省相对队列抖动小），7168 才是强测试。

（2）攻击者用 30 秒窗内非重叠探针的中位数做负载中心化再攻击：预测模式 0.022、执行模式 0.018，仍落噪声（无保护 0.446）。

（3）**同账号攻击者**（账户隔离的天敌）：账户隔离上界 0.263 vs 无保护 0.285，差值的 90% 区间 [−0.059, 0.016] 在噪声内——即在测量精度内**账户隔离泄漏与无保护相同**；端到端 8 选 1 识别率 0.277（账户隔离）vs 0.283（无保护），而 Isonomy 两模式仅 0.115/0.106。

（4）**加入实例场景**（路由信道的试金石）：每 5 秒把第二实例移出放置 3 秒、在其回归瞬间发探针——per-instance hiding 上界飙到 0.433（被明确检出），预测模式 0.074（噪声内）；更细的时间分层显示 per-instance hiding 的探针优势从回归前 0.2 秒的 0.061 跳到回归瞬间的 0.393（差 0.33，95% 区间 0.26–0.42）。

（5）先前防御对比：CacheSolidarity 在稳定负载下未被单探针检出（0.052），端到端识别率 0.121–0.128（接近随机）；Mirage 回放未被检出，但每个账户对每个前缀仍有一次未填充探针（0.241），全填充均价 +1.60s/请求 vs 预测模式 hold 0.17s；固定/量化/负载块填充要全格 ≤0.10 需加 0.83–2s/请求。

（6）商用 API 负载可见性：Anthropic（claude-haiku-5-5，131K）/OpenAI（gpt-5.6-luna，98K）/Gemini（gemini-3.5-flash-lite，98K）上，控制组 A 自身优势 0.76–0.99+（测试有效），单监听者上界 0.019–0.037，burst、间隔、共享前缀三族监听全部落噪声（含重复运行；总成本约 $141，全部用自有账户与新随机文本）。

**性能结果。**

- **饱和吞吐**：会话负载预测模式保留 **0.984** > 账户隔离 0.945；构造负载 **0.977 vs 0.802**——多回收 21.8% 相对吞吐、填补到无保护差距的 88%（会话为 71%）；逐请求加盐仅 0.381；
- **GPU 节省实现率**：按完成的提示词元计，预测模式实现无保护相对逐请求加盐 GPU 时间节省的 99%；
- **goodput**：SLO ≥1.25s 起预测模式交付无保护同 SLO goodput 的 0.93–0.98；Mooncake trace 从 0.75s 起至少 0.94；
- **TTFT p90**：相对无保护，会话 +0.04 到 +0.25s、构造 +0.05 到 +0.21s、Mooncake −0.05 到 +0.10s；平均扣押命中 340ms、未命中仅 19ms；
- **执行模式的双刃性**：全隔离下会话负载仅保留 0.477（两实例下近半槽位 token 找不到合适形状的替代者，dummy 占 18%），但把**每个对话设为共享组**后（89% 复用发生在对话内），吞吐达无保护的 **1.015 倍**、浪费仅 3.2%——替代者供给取决于队列形状而非集群大小；
- **规模扩展**：带探针时预测模式在 2–8 实例保留 0.95–0.97；32 模拟实例 0.962，网关单线程仅用 0.47 核（3.8ms/请求）；事件级模拟器在 2 实例上把缓存份额与加盐吞吐复现到 0.01 内、8/32 实例执行吞吐到 0.02 内，模型高估 ≤5%；
- **外推到 4,096 实例**：满覆盖 H=0.76 时预测模式达逐请求加盐的 1.77–1.87 倍（执行模式 1.32–1.34），保留无保护的 0.85–0.86——距理想 4.13 的差距主要在路由本身（无保护也只有 2.08–2.17），且受限容缓存下可复用份额降至 0.55。

这套实验之所以有证明力，在于三重设计：噪声界让『未检出』有了统计学含义而非样本不足；hit/miss 世界对照实验直接对应定义 1 的反事实对，而非 surrogate 指标；商用 API 测试把定理 1 的适用前提从假设变成测量。同时作者对自身证据的边界保持诚实：单实例内的『未检出』只说明测试探针没找到，多实例下的检出才说明设计没藏住。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**为何加盐/隔离类方案注定丢吞吐（方法差异 → 机制变化）。**

加盐把缓存按键切开，跨域相同前缀必须各算一份——这是**结构上放弃复用**：丢掉的吞吐随负载的跨域复用率上升而放大（会话 0.945、构造 0.802、逐请求加盐 0.381，三个点连成一条『复用率 × 隔离粒度』的代价曲线）。

Isonomy 的机制变化是：**缓存仍然全集群一份，组外命中仍然发生、其计算节省仍然被集群保有**（GPU 时间节省实现率 99%），只是不允许这次节省体现在该请求自己的首词元时刻上——要么扣押到 twin 的时刻（预测模式，hold 278–340ms 接近理论下界 255–321ms），要么让其他请求把省下的算力用掉（执行模式，21% 槽位算真替代工作）。

因果链：保留共享 → 命中的 GPU 节省不消失 → 饱和吞吐逼近无保护（0.984/0.977）→ 在跨账户复用多的负载上反超账户隔离 21.8%。

注意 2611.20291 证明了这件事的另一面：租户可观测的节省就是泄漏，零泄露时只有服务商保有节省。Isonomy 把『保有』落实为『扣押后按时释放』或『转售给同集群其他请求』——节省没有消失，只是不再按命中模式分配。这条证据链标注为论文实验已支持。

**为何时序不可区分（安全性根源）。**

可观测差异有两个来源：路由去向不同（面对不同队列）与执行步数不同。

twin 路由消除前者——网关决策只依赖两世界公共输入，命题 1 条件化后两世界路由分布恒同。这是**单实例防御在结构上做不到的一步**：它们假设请求落点固定，而缓存感知路由恰恰让落点依赖命中；表 4 加入实例场景的 0.433 vs 0.074 是这一机制差异的直接实验证据。

释放对齐消除后者：随机化门以 G = ε/(1−F) 构造，使两释放分布在门区间内逐点仅差 ε 的质量（命题 2 精确刻画泄漏形状而非仅给界）；执行模式则让两世界的首词元由同一形状的 step 产出，Yh = Ỹ 按设计成立、无需分布假设（这正是它换硬件不用重标定的原因）。

12/12 上界落噪声界的实验结果与该理论链条逐环对应。更深一层，同作者的攻击论文曾证明『只顾自己时序的防御会被监听者攻破』——本文用定理 1 + 商用 API 实测（监听者优势 0.019–0.037 全落噪声内）先把这条退路封住，这是整个设计因果链的隐含地基，也是它区别于所有前作的关键前提。

**双模式的分野本身也是根源解释的一部分。**

理论框架显式区分两类成本：GPU 成本（拒绝命中、算无用 token）决定吞吐天花板；延迟成本（就绪到释放的等待）决定 SLO 松紧。预测模式几乎零 GPU 成本、纯付延迟（hold 命中 340ms、未命中 19ms）；执行模式反过来，dummy 与整 twin 执行吃吞吐（全隔离 0.477）但不需要步时模型。两模式是同一目标分布 Q* 下的两个帕累托点：步长可预测时（稠密模型、形状主导时长）预测模式占优；队列长、替代者充足或硬件时长难标定时执行模式占优（会话组实验 1.015 倍即是其主场）。

反事实推理支撑各设计的必要性：去掉随机化改一对一传输映射，回放泄漏上界从 0.023 升到 0.071；改固定门，扣押时间增 12–17%；不做跨实例接纳校验，9–38% 的跨实例命中会晚于 twin（压到 1% 需 0.37–1.01s 裕量，双分位校验是更便宜的解）。

### 6.3 综合判断与未决问题

**多项证据共同支持的机制**：路由只用公共输入 ⇒ 路由信道关闭（命题 1 + 加入实例实验 0.433 vs 0.074）；释放分布对齐 ⇒ 直接信道关闭（命题 2/3 + 12/12 落噪声）；缓存不分区 ⇒ 节省保留（0.984/0.977 vs 0.381/0.802）。三者各有独立的理论与实验支撑，因果链完整。

**仍属条件性的机制**：负载不可见前提依赖被测的监听者布放与统计量——论文诚实列出边界：测试不覆盖比采样更精细定时的攻击者；闭环负载下引理前提可破、监听者甚至可能变快；FaaS 共居攻击的成本证据使他们不敢假设监听者不能共享实例。MoE 的内容依赖步长是新暴露面（修正后受控但依赖内容分类）；执行模式在全隔离短队列下替代者匮乏（0.477）说明其优势条件是『负载重或组内有复用』而非普适。

**可能失效的条件**：攻击者可互相观察负载的部署；输出数值因批共享而异的信道（论文明确范围外）；流水线并行与跨节点张量并行未测试；缓存容量有限时 4,096 实例的可复用份额从 0.76 降至 0.55。

综合判断：『安全与近乎全量共享可兼得』在低负载可见性部署内是结构必然而非巧合，但『低负载可见性』本身是需要持续复测的环境属性，不是一次性结论。

## 七、必要知识反推

**领域知识层。**

1. **Transformer 推理栈**：KV cache、prefill/decode 分离、TTFT 作为用户唯一可精确观测的时点——不知道这些就无法定位『泄露发生在哪一毫秒』；
2. **vLLM 调度器细节**：token 预算、先来先服务、块哈希链、128-token 阶梯、块调度时机——步形状的确定性与时长的阶梯结构是预测模式可标定、执行模式可保形的物理基础；
3. **商用 API 的缓存计费与 usage 字段语义**——否则会漏掉『计费与用量本身也是信道』这半边威胁模型。

**方法论知识层。**

1. **时序侧信道的攻击文献图景**（审计、prompt 重建、监听者攻击）——没有它就意识不到单实例防御的盲区恰在路由，也想不到要先测负载可见性；
2. **概率论工具**：TV 距离、耦合构造、随机占优、一维最优传输的单调映射与凸成本最优性——定理 1/2、随机化门的形状与『随机占优 ⇒ 未命中零延迟』都由此而来；
3. **predictive mitigation 与固定形状 dummy/replica 的经典防御谱系**——两模式分别是这两条思路在集群场景的再发明，知道血统才能避免重走『加噪不够』的弯路。

**工程知识层。**

1. **网关/路由器工程**：缓存感知评分函数、负载追踪、把命中的待处理工作按 twin 计重使路由所见负载不依赖命中的技巧；
2. **系统测量方法学**：秩统计上界的噪声界构造、bootstrap 区间、Wilson 区间模拟、开放/闭环双客户端、SLO-goodput 曲线读法——『不可读』判定可复现是安全声明可信的前提；
3. **调度器内部改造能力**（2200 行自定义调度器）与**模拟器校准方法**（覆盖律 M/4096、事件级仿真、≤5% 模型误差界）。作者还提到用 AI 编码 agent 辅助实现——这类系统工作正越来越多地成为人机协作产物。

**知识融合的关键节点。**

最关键的化学反应是**把安全定义写成反事实对，再把反事实的执行外包给现有系统组件**：调度器的确定性使 twin 的步形状无需执行即可重构（预测模式），队列本身的填充需求使 twin 的槽位可以承载真工作（执行模式）——防御成本从『重算一切』降为『扣押或转售』。

第二个节点是**攻击者与防御者视角的闭环**：先用攻击论文证明 naive 隐藏必败的机理（节省会传递给队列），再把该机理转化为可测前提（负载可见性测试），理论攻击直接塑造了防御的适用域声明。

第三个节点是**最优传输理论与工程门的折中**：明知单调映射是凸成本最优，却因 1–4ms 的偏差容忍度选择随机化门——理论告诉你最优在哪，也告诉你在哪里可以安全地让步。

## 八、论文中可以提取的通用性灵感

**1. 反事实孪生作为安全目标：不要抹平差异，而是对齐『如果没有它』的分布。**

核心思想：防御一个优化带来的泄露，不需要放弃优化，而是让每个受影响请求的可观测行为与『该优化未发生』的反事实版本同分布。

论文证据：miss twin 使未命中请求零延迟成本、命中平均仅扣押 278–340ms，同时保住 0.984 吞吐；目标分布由定理 2 完全刻画。

推广场景：数据库查询缓存的结果混淆（对齐无缓存延迟）、CDN 命中的时序伪装、联邦学习中『某客户端是否参与』的时序混淆、加密操作的 constant-time 实现（其特例）、差分隐私机制输出的分布对齐审计。

**2. 决策信道先于数值信道：任何依赖秘密的决策都是侧信道，先堵决策再堵数值。**

核心思想：路由这类『去向选择』本身携带信息；只对齐最终数值而不对齐决策输入的防御，在多节点环境必然漏气。

论文证据：per-instance hiding 单实例 0.043、双实例加入场景 0.433——机制未变，暴露面因决策差异打开；Isonomy 的解法是让决策只吃公共输入（命题 1）。

推广场景：负载均衡器的后端选择、分片数据库的副本选择、搜索集群的缓存路由、多云故障切换的落点选择、匿名通信系统的下一跳选择。

**3. 节省的流向决定泄露的边界：追踪资源节省去了哪，而不是差异有多大。**

核心思想：任何可被租户观测的性能收益本身就是信息；要隐藏一个优化，必须让节省流向不可观测方（服务商内部或其他不相关请求）。

论文证据：定理 1 与前作『零泄露 ⇒ 服务商独占节省』；执行模式把节省转售给替代者（21% 槽位算真工作、会话组下吞吐 1.015 倍）。

推广场景：去重存储的访问延迟混淆、增量编译的命中伪装、多租户批处理吞吐公平性中的信息泄露分析、推荐系统去重候选对曝光信号的影响。

**4. 把不可证伪的前提做成可运行的测试。**

核心思想：理论防御的适用前提（负载不可见）若只能假设就是软肋；若能变成部署前一键测试、且测试本身不需要触发被防行为（无需命中即可测），前提就成了可维护的工程事实。

论文证据：负载可见性测试在三家商用 API 上通过（0.019–0.037），失败即宣告该部署不适用本防御。

推广场景：侧信道加固后的持续回归测试、隐私系统 k-匿名的持续审计、云共居风险巡检、协议常量时间性的 CI 检查。

**5. 一份资源、N 个信任域：隔离键控的是『谁受益』而非『谁存储』。**

核心思想：物理共享与逻辑隔离不矛盾——共享存储以获得效率，把隔离施加在受益路径（计时、计费、路由决策、用量上报）上而非存储分片上。

论文证据：全集群一份缓存 + 每请求独立共享组，账户隔离在跨账户复用多的负载上只剩 0.802 时 Isonomy 仍有 0.977；使用与计费字段也按 twin 上报。

推广场景：多租户 GPU 上的中间计算复用、企业知识库的嵌入共享检索、密码管理器去重存储、跨机构的模型 KV 复用市场。

**6. 双帕累托点设计：同一目标分布下提供『付延迟』与『付算力』两种货币。**

核心思想：当防御成本天然分成互斥的两类（时间与算力），提供两种实现让部署按自身瓶颈选择，比单一方案更普适。

论文证据：预测模式适合步长可预测场景（0.984 吞吐）、执行模式适合难标定或多复用场景（换硬件免重标、组内复用 1.015 倍），两模式在 H≈0.4 前差异 ≤0.02。

推广场景：隐私计算的算法/可信硬件选择、一致性协议的读写权衡、缓存失效策略的延迟/带宽权衡。

## 附录：术语速查

- **TTFT**：time to first token，从发请求到收到首个词元的时间，本文核心可观测量。
- **miss twin**：把请求 x 的组外命中改为未命中后的同一请求；防御让 x 的释放时间与之同分布。
- **负载可见性**：其他请求从自身时序分辨『某请求是否存在』的优势；定理 1 用它界定间接信道上界。
- **预测/执行模式**：分别以『预测 twin 就绪时间 + 随机化门』与『真执行 twin 的步形』设定释放时刻。
- **噪声界**：无效应时检验统计量上界的模拟 95 分位；优势上界落入其中即称『不可读』。
- **替代者（substitute）**：在执行模式槽位内做真工作的等待请求；不足处用 dummy token 补形。
- **步形状（step shape）**：一步内参与请求数、各块 token 数与起始深度；形状（近似）决定时长。
