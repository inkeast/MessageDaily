> **一句话**：让同一个模型既学会"做事"，也学会"写好未来尝试将继承的经验"，并且用可验证的下游执行效果来给这些经验打分训练

## 先说结论

这篇论文处理的是当前 Agent 训练里一个非常扎眼的断层：**强化学习（RL）会更新权重，但交接给未来尝试的只有一个标量奖励；推理时自改进框架（harness）能交接丰富的经验文本，但从不学习怎么写这些文本**。ACE-RL 把两边缝合起来：固定 ACE 框架（Agentic Context Engineering），让一个模型同时扮演 actor（干活）、reflector（从轨迹提炼洞见）、curator（编辑任务局部 playbook）三个角色，然后用两个关键设计训练它——(1) **可验证交接奖励**：把候选 playbook 交给一个全新的 actor rollout 去执行，用任务验证器的得分作为这份 playbook（及其编辑、其反思）的奖励，完全不需要学习型奖励模型；(2) **每角色同输入对比组**：同一轨迹的多个反思互比、同一洞见的多个编辑互比，GRPO 式组内归一化优势后三角色做一次联合更新。结果是等训练算力下，四个基准（Mastermind、MBPP、AppWorld、MiniSWEBench）全部第一，MBPP 上 RSI@3 达到 0.987（次优 GRPO pass@3 为 0.867），且优势外推到训练没见过的 K=8 尝试次数仍然保持。

## 一、论文背景

### 1.1 两条经验交接路线的由来

一个从自己试验中学习的 agent，需要"经验交接"（experience handoff）：这一次尝试探明的环境信息，必须能传给后续的尝试。论文指出存在两条本质不同的交接通道：

- **第一条通道：标量奖励 → 权重**。这是标准 RL。每次 rollout 被打一个分，分数变成优势，梯度步把策略往受奖励的行为推。对语言模型来说，可验证奖励强化学习（RLVR）已经在各种模型家族和规模上稳定地提升 actor 能力（DeepSeekMath、DeepSeek-R1、DAPO 这条线）。但 outcome-only RL 把整个试验压缩成一个数字，**丢掉了错误日志、工具输出、发现的约束条件**——agent 在行动时看得到这些环境反馈，却除了一个抽象标量之外无法把它们交接给未来的 rollout。RL 也没有任何机制教会模型"反思"和"记笔记"这些能承载经验前传的行为。
- **第二条通道：经验工件 → 上下文**。这是各类 harness（脚手架）的路线。harness 决定模型何时行动、看到什么、以及从一次尝试到下一次尝试携带什么。经验以文本形式保存：语言反思（Reflexion）、技能库和可复用工作流（Voyager、Agent Workflow Memory）、cheatsheet 和 playbook（Dynamic Cheatsheet、ACE）、进化出的提示词（GEPA）、测试时发现循环中被评估程序的档案（AlphaEvolve）。在里面放进一个足够强的前沿模型，这类脚手架能展现**推理时递归自我改进（RSI）**：一次 rollout 失败 → 模型反思轨迹 → 重写自己的笔记或上下文 → 下一次以这些笔记为条件的 rollout 表现更好。

### 1.2 本文采用的 RSI 定义

论文明确收窄了 RSI 的含义：**权重固定、harness 固定，模型只通过重写未来 rollout 将继承的上下文来改进自己的后续尝试**。更广义的 RSI 还包括重写自身代码或脚手架的 agent（Gödel machine、STOP、Gödel Agent、Darwin Gödel Machine）、对程序或研究代码做迭代优化的系统（AlphaEvolve、Karpathy 的 autoresearch）、以及用自生成数据更新自身权重的模型（Self-Rewarding LM、Self-Adapting LM 等）。作者选窄定义的原因很干脆：这个循环是尝试之间纯粹的经验交接，是研究"第二类交接"最干净的设置——**从一个尝试传给下一个尝试的唯一东西，就是模型自己写的一件工件**。

关键的问题在于：harness 只是保存经验，它交接的东西的质量被写它的那个冻结模型的能力上限卡死了。反思和编辑的调用从未针对"这些文本对未来 rollout 的影响"被训练过；而优化 harness 本身的方法（GEPA、Meta-harness 等）改的是模型周围的提示词和代码，不是模型书写有用经验的能力。小模型尤其撑不起这条路——论文 Figure 2 显示，未训练的基座模型放进 ACE harness 里，几乎无法从自己的 playbook 编辑中获益。

### 1.3 ACE harness 与三角色

本文的试验台是 ACE（Agentic Context Engineering）框架的任务局部变体。一个模型 πθ 在固定的角色指令下担任三个角色，围绕一个任务局部 playbook P（一段前置到 actor 输入的自然语言提示列表）运转。一次交接迭代为：

1. **act（行动）**：τ ∼ πθ(·|ι_act(q, P))——actor 读任务 q 和当前 playbook，执行轨迹 τ，环境验证器给出奖励 R_q(τ) ∈ [0,1]；
2. **reflect（反思）**：z ∼ πθ(·|ι_ref(τ))——reflector 读完整轨迹（包括奖励和环境揭示的信息：测试失败、工具错误、终止原因），写一条洞见 z；
3. **curate（策展）**：u ∼ πθ(·|ι_cur(P, z))，P′ = Apply(P, u)——curator 读现有 playbook 和洞见，发出结构化编辑操作（对某条 tip 的 ADD/UPDATE/REMOVE），Apply 执行合法操作产出候选 playbook P′。

playbook 是任务局部的：每次 actor 调用都开启全新环境 episode，同一任务跨尝试携带的唯一状态就是 P。测试时权重冻结，harness 对每个任务跑 K 次交接迭代，每次迭代的 curator 编辑直接应用于下一次尝试读的 playbook，**没有额外的 rollout 来给编辑打分**——这个协议叫 RSI@K：K 次迭代中任意一次解决任务即算解决。

### 1.4 核心问题的提出

于是两条路线各缺对方有的东西：RL 从可验证信号更新权重，但只交接一个标量；harness 交接丰富经验，但从不学习书写它。论文的问题陈述非常漂亮：

> **一个模型能否仅从任务结果出发，既学会行动，也学会书写它的未来自我将继承的经验？**

作者把这类训练称为**经验交接强化学习（Experience-Handoff RL，EHRL）**。

## 二、论文定位和关联工作

### 2.1 在研究版图上的位置

ACE-RL 站在四条研究线的交汇点上：

- **推理时自改进 / 记忆反思类**（Reflexion、Voyager、ExpeL、Dynamic Cheatsheet、Agent Workflow Memory、ACE）：冻结模型靠写反思/技能/playbook 改进后续尝试。这些系统假设模型已经会写有用的经验；本文证明小开源模型不会，且可以直接训练出来。
- **harness 优化类**（DSPy、GEPA、Meta-harness、Agentic Harness Engineering）：围绕固定模型编译/进化提示词或搜索 harness 程序。ACE-RL 反其道而行：**固定 harness，训练模型**。工业界的自进化 agent 系统（如阿里的 AgentEvolver）和深度工程化 SWE agent（如 Deep SWE-Agent）同样依赖"模型读写经验工件"这一能力，但它们的经验管理逻辑是设计出来的而非学出来的——ACE-RL 恰好补上了"让模型学会写"的这一环。
- **RL 后训练谱系**（PPO → GRPO → DAPO → 多轮 agentic RL：ArCHer、RAGEN、OpenClaw-RL、RLAnything，以及 GLM-4.5/Kimi 的大规模 RL 管线）：GRPO 及其改进用组相对优势 + 可验证结果训练 actor。ACE-RL 保留可验证奖励这个成分，但**把"分组"从 actor 扩展到 harness 里的每一次模型调用**，用下游执行而非学习型奖励模型给中间文本打分。
- **穿 harness 训练类**（Composer 2、SUPO、CompactionRL、MEM1、MemAgent）：训练一个策略，它自己写的摘要/压缩会成为它的未来上下文，通过链的最终奖励 + 序列级优势或 critic 来回传信用。本文的 Delayed-joint PPO 基线就沿用这个信用结构（CompactionRL 式），结果显示它容易训练崩溃。

最接近的先行工作是用下游结果训练反思/记忆的一批：Reflect-Retry-Reward 用重试的成功给反思发奖；ERL（Experiential RL）把改进内化进权重；Memory-R1 用答案正确性训练记忆管理操作（ADD/UPDATE/DELETE/NOOP）但冻结答题 agent、分开训练；JERP 用冻结编辑器联合学经验规则；Training-Free GRPO 把多次 rollout 的洞见聚合成共享指南但不更新权重。ACE-RL 的差异点：**一个策略训练两阶段交接（先反思、后策展）、交接工件持久且可编辑、且为每个阶段构造对比组**。细粒度分组方面，GiGPO 在重复环境状态处分组、AT-GRPO 构造 agent 级/轮级组，ACE-RL 把同一原则应用到 harness 的依赖树上。

### 2.2 对比表

| 方法 | 训练的角色 | 优势估计 | 交接文本的信用 | 评测协议 |
|---|---|---|---|---|
| PPO | actor | critic（GAE） | — | pass@3 |
| GRPO | actor | 组归一 | — | pass@3、RSI@3 |
| ERL（反思内化） | actor、提示改写器 | 组归一 | 重试奖励；内化进权重 | pass@3 |
| Delayed-joint PPO（CompactionRL 式） | actor、reflector、curator | critic（GAE） | 同链下次尝试的奖励 | RSI@3 |
| **ACE-RL（本文）** | actor、reflector、curator | **每角色一个组** | **被执行的 playbook（Eq.7）** | RSI@3 |

注意所有方法都用同一个任务验证器奖励、每任务同样 8 条 actor rollout 训练——对比在严格等算力下进行。

## 三、问题定义

### 3.1 从"训练 actor"到"训练模型所在的 harness"

Outcome-only 的 agentic RL 最大化 J_act(θ) = E_q E_τ∼πθ(·|ι_act(q,P0))[R_q(τ)]，其中 P0 是空 playbook。这样训出的模型再被塞进 harness，期望"更好的 actor 在 harness 里也更好"。harness 不帮忙时，通常做法是改 harness 而非改模型。两种情况下，模型都没有为"它的反思和编辑对后续尝试做了什么"被训练。

ACE-RL 转而训练模型适配它运行的 harness。令 ω ∼ H[πθ](q) 为 harness H 在任务 q 上的一次完整执行迹，EHRL 目标为：

**max_θ J_H(θ) := E_q E_ω∼H[πθ](q)[R_q(ω)]**

harness 固定提示词、工具和控制流；模型为它们组合执行的结果而被训练，所以它发出的**每一次调用**（不只是 actor）都是训练对象。对 ACE 交接，这个目标可以具体化到 playbook 更新之后的 actor 结果：

**J_ACE(θ) = E_(q,P)∼μ E_τ,z,u,τ̃∼πθ[R_q(τ̃)]**

其中 τ̃ ∼ πθ(·|ι_act(q, P′)) 是在候选 playbook P′ 下的一次全新尝试，μ 是训练访问到的 (q, P) 分布（P 是该任务从前次遭遇继承的 playbook，P0 为初始和每次重置后的状态）。

### 3.2 信用分配难题的抽象

Eq.(5) 的奖励只付给 τ̃，但它依赖于链上的**全部四个样本**：种子轨迹 τ 提供证据、z 决定从证据中提取什么、u 决定 playbook 怎么改、τ̃ 检验 actor 是否用得上这个改动。一个单独的 R_q(τ̃) 无法说明四个环节中谁出了错——这就是交接工件的信用分配问题。更麻烦的是两条天真的路都已被证明有问题：

- **学习型 critic 路线**：让 critic 学出各环节的价值。CompactionRL 式的端到端训练在本文实验中崩溃（详见第五节）。
- **链式摊派路线**：把链的最终奖励经组归一摊给链上所有 token。附录 B 的方差分解显示，链式比较下反思的优势 Y_i − b^−i 可分解为"评估噪声 + 反思质量 + **种子项**"三部分，其中种子项（轨迹本身质量的差异）与反思无关却进入每条反思的优势，随任务内轨迹质量离散度增长——比较不同轨迹的反思时，这个噪声项无法消除。

第三节的目标因此需要一个能同时解决"奖励从哪来"和"跟谁比"两个问题的方案。

## 四、问题解法

ACE-RL 用 GRPO 式更新联合训练三角色，由两个部件构成。

### 4.1 部件一：交接工件的可验证奖励

关键性质：**最终 playbook 是可验证的**。把候选 playbook 交给一个全新的 actor rollout 执行、读任务验证器的分，就能在没有学习型奖励模型的情况下给它打分（沿用 RLVR 的成功逻辑）：

τ̃ ∼ πθold(·|ι_act(q, P′))，V̂(P′) = R_q(τ̃)

这是 Eq.(5) 中条件下游价值的单 rollout 估计。三个角色各自拿到：

- **curator 的奖励**：r_cur(u) = V̂(Apply(P, u))——你编辑出的 playbook 值多少分，就由它执行出来的效果决定；
- **reflector 的奖励**：r_ref(z) = (1/|C(z)|) Σ_{u∈C(z)} V̂(Apply(P, u))——你的洞见派生出的所有合法编辑的平均价值（C(z) 为从 z 派生的合法采样编辑集合，空集时为 0）；
- **actor 的奖励**：r_act(τ) = R_q(τ)——每条 actor rollout 无论在现任 playbook 还是候选 playbook 下采样，都拿自己的任务奖励。

不可采纳的编辑（包括不改 playbook 的编辑）拿 0 分。因为 actor rollout 在现任 playbook 和候选 playbook 下都有采样，actor 同时学会读"保留的交接"和"全新的交接"。

### 4.2 部件二：每角色一个对比组

组相对优势需要从**同一输入**采样的多个输出。算法对带 playbook P 的任务 q 构造一棵采样树：

1. 采 N=4 条种子 rollout τ₁…τ₄ ∼ πθold(·|ι_act(q, P))；
2. 均匀随机选一条种子 τ_j⋆，对它采 M=2 条反思 z₁, z₂；
3. 若有可用反思，均匀选一条 z_h 对它采 C=3 条编辑，其余每条可用反思各采 1 条编辑；
4. 把合法编辑应用到 P 的副本上，每个候选 playbook 用一条新 rollout 打分（Eq.6），这些 rollout 加入该任务的 actor 组。

每个输出 i 拿到优势 A_i = (r_i − μ_G)/(σ_G + ε)，其中 μ_G、σ_G 是**它自己角色组**内的奖励均值和标准差：行动与其他 actor rollout 比、反思与同一种子的其他反思比、编辑与同一洞见的其他编辑比。**一条失败的种子因此仍能产出正奖励的反思**——只要它的反思比另一条同种子的反思派生出更有价值的 playbook。奖励恒定的组被丢弃，三角色的全部输出在共享模型上做一次裁剪更新。

这个设计的算力账算得很精：完整对比树（N,M,C,L)=(4,2,3,1) 每任务要 60 个输出，稀疏化后降到 14 个、其中 8 个是 actor rollout——**与 GRPO 每任务 8 rollout 的预算严格对齐**（链式设计要 32 个）。附录 D 证明：均匀选组保持原始分数均值；单评估保留候选的条件期望 verifier 奖励（只是方差升高）；有限组归一化带来 (G−1)/G 因子等近似——实现是"带条件交接信用和当前 actor 学习的稀疏逐组件 GRPO 代理"，近似都是显式的。

### 4.3 playbook 的选择与重置

训练信用和记忆选择是两个分离的决定。奖励用于排序学习；harness 另行决定任务 q 带进下一次遭遇的 playbook（Eq.8）：在值不低于种子奖励 s 的合法候选中取最高者，否则保留 P。每 F=3 次遭遇重置为 P0——这既限制 retained experience 的年龄（弱参数下早接受的编辑可能误导后期 actor），又让训练反复暴露于"空 playbook"这一评测起点条件。

### 4.4 三角色联合更新

所有被保留的输出（actor/反思/编辑）拼接成一批，最大化 DAPO 式非对称裁剪代理（clip (δ−,δ+)=(0.2,0.28)、对负优势双裁剪 c=3），token 均值聚合、无 KL 惩罚、无熵 bonus、无 critic。候选价值和优势对 θ 是常数。角色权重按 token 数自然加权，不施加显式角色权重。

## 五、评估指标与实验证据

### 5.1 实验设置

- **模型与基准**：Qwen3-0.6B（non-thinking）训 Mastermind（密码破解游戏，奖励为最优猜测得分 (e+v/2)/L）和 MBPP（374 训/100 测，奖励为 3 个单元测试通过比例的最优值）；Qwen3-4B-Instruct-2507 训 AppWorld（90 训/57 dev，二值状态检查奖励）和 MiniSWEBench（100 个 SWE-Gym 实例训/100 个 SWE-bench Verified 测，训练用 0/0.05/0.2/1 整形奖励、测试用二值）。
- **等算力对比**：所有方法每任务 G=8 条 actor rollout、每步 8 个任务，更新 FLOPs（含 PPO 系的 critic）作为训练算力轴；ACE-RL 每步更新 FLOPs 为 GRPO 的 0.91–1.21×（四基准分别 1.14×、1.01×、1.17×、1.21×）。
- **评测协议**：harness 内 RSI@3（3 次顺序访问，每次 1 个 actor episode + 1 次反思 + 1 次编辑，无额外打分 rollout）对比 harness 外 pass@3（3 条独立 episode）——两者消耗相同的 3 个 actor episode。

| GRPO | pass@3 | 0.686±0.010 | 0.867±0.027 | 0.624±0.060 | 0.245±0.040 |
| ERL | pass@3 | 0.615±0.010 | 0.509±0.043 | 0.418±0.059 | 0.234±0.038 |
| 基座模型 | RSI@3 | 0.527±0.015 | 0.387±0.045 | 0.246±0.058 | 0.180±0.039 |
| GRPO | RSI@3 | 0.739±0.012 | 0.820±0.033 | 0.597±0.066 | 0.260±0.044 |
| Delayed-joint PPO | RSI@3 | 0.659±0.011 | 0.500±0.047 | **0.000** | **0.010** |
| **ACE-RL** | RSI@3 | **0.775±0.014** | **0.987±0.011** | **0.667±0.063** | **0.340±0.048** |

按任务配对差（±1 SEM）：ACE-RL 的 RSI@3 高于 GRPO 的 pass@3 达 **+0.089±0.015（Mastermind）、+0.120±0.026（MBPP）、+0.042±0.041（AppWorld）、+0.095±0.034（MiniSWEBench）**。几个关键读数：

- **PPO 在 Mastermind 和 MiniSWEBench 上直接崩到 0.000**，四基准全部低于 GRPO——纯 critic 路线在这个尺度上不稳；
- **ERL 全线低于 GRPO**：只通过权重交接改写后提示的收益，赶不上直接训 actor；
- **Delayed-joint PPO 的崩溃模式最具信息量**：它在 Mastermind 上 0.54 EFLOPs 时达到 0.66（同期 ACE-RL 在 0.46 EFLOPs 已到 0.74），随后训练奖励在 0.73 EFLOPs 前跌到 0.05 以下；MBPP 峰值 0.53 对 ACE-RL 的 0.99；AppWorld/MiniSWEBench 从 0.21/0.08 起步直接跌到接近 0。**其 critic 的解释方差在每次运行后期都保持在 0.95 以上**——拟合良好的 critic 也挡不住崩溃，问题出在信用结构而非 critic 质量。作者的措辞很谨慎：不能断言 critic 信用无法训练交接，但它确实更易崩溃。

### 5.3 "把 actor-only 模型装进 harness"这个常见做法

工业界常见流程是 outcome-only RL 后训练 actor，再放进手工 harness 里跑。实验模拟了这个做法：GRPO 检查点装进 ACE harness（用 ACE-RL 的角色提示词）后确实缩小了部分差距——预算内每个 Mastermind/MBPP 检查点都至少拿到自己 harness 外 pass@1 的分数，AppWorld 47 个检查点中 39 个如此。但等算力下仍然全面落后：Mastermind 0.74 vs 0.78（配对 +0.037±0.018）、MBPP 0.82 vs 0.99（+0.167±0.032）、AppWorld 0.60 vs 0.67（+0.070±0.055）、MiniSWEBench 0.26 vs 0.34（+0.080±0.039）。Figure 2 的 Venmo 任务案例很直观：GRPO 检查点的 curator 反复编辑空 playbook 中不存在的 tip（被拒），playbook 始终为空、三次全败；ACE-RL 的 curator 逐次写入"用 supervisor 或 phone app 数据核实室友身份"、"用 created_at 和核实的当前日期计算 pending 天数"两条 tip，第三次尝试找到全部室友并向 6 笔旧请求发出提醒。

### 5.4 外推到训练地平线之外：K=8

训练时每 F=3 次遭遇重置 playbook，所以从第 4 次访问起 actor 读到的 playbook 编辑轮数超过训练所见。对比 RSI@K（K 次顺序访问的最优）与 GRPO 的 pass@K（K 次独立采样的最优，同样花 K 个 actor episode）：**ACE-RL 的 RSI@K 在全部四个基准的每个 K 上都高于 pass@K**，K=8 时收于 0.81/0.99/0.81/0.40 对 0.78/0.91/0.68/0.30。从 K=3 到 K=8，ACE-RL 各基准再涨 0.03/0.00（MBPP 已到天花板）/0.14/0.06，GRPO 涨 0.09/0.04/0.06/0.06——**差距在 Mastermind 收窄、MiniSWEBench 持平、AppWorld 反而扩大**。playbook 适应的有用性外推超过了训练截断点。

### 5.5 增益来源：edits-discarded 对照

最关键的归因实验：把 ACE-RL 的 harness 内评测重跑一遍，但**丢弃每次编辑**（每次访问都读空 playbook），访问退化为同一 actor 的独立尝试。两种运行之差即 playbook 自身的贡献（actor 固定）。结果：训练地平线内，应用编辑在全部四基准的 K=2、K=3 都提升 RSI@K，最明显的是 **AppWorld K=2 时 +0.105±0.041** 和 **MiniSWEBench K=3 时 +0.090±0.040**；MBPP 上增益小是因为两边都接近天花板（0.987 对 0.977）。地平线外（K=4~8），MiniSWEBench 每个点多 +0.04~+0.07；Mastermind 在 K=3 后收益消退，K=5 起丢弃版反超 0.016±0.016。这个对照直接证明：**训练目标真的造出了有用的 playbook，而不只是把 actor 练得更会适应**。

### 5.6 变体对照与定性证据

- **Delayed-joint ACE-RL**（保留可验证 playbook 奖励但按链分组）：0.743/0.760/0.526/0.250，全面低于 ACE-RL；MBPP 上 ACE-RL 在全部 26 个检查点领先，AppWorld 40 个中 37 个领先；且 K=1（任何交接发生之前）ACE-RL 就已在 MBPP 0.95 对 0.61、AppWorld 0.56 对 0.37——两个运行还混有 actor 采样与提示词差异，作者诚实声明这组对照没有隔离分组本身的效果。
- **学到的 playbook 内容**：第 4 次访问读到的 playbook 中，100 个 Mastermind playbook 含 300 条 tip、203 条去重文本；100 个 MBPP playbook 含 301 条 tip、237 条去重（但 94/100 任务首次访问已解，tip 很少影响奖励）；57 个 AppWorld playbook 中 56 个非空、159 条 tip 里 154 条去重，内容点名任务所需的 API、实体与检查。AppWorld 案例（任务 df61dc5_1，四次访问奖励 0,1,1,1）的 playbook 写着"必须识别并点赞与室友双向的全年度交易"、"提交前检查点赞数大于零且与识别数一致"等可执行检查项。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

ACE-RL 的优势可以从三层机制解释，每层都有论文内直接证据：

**机制一：可验证的下游执行奖励消除了学习型信用错配。** r_cur(u)=V̂(Apply(P,u)) 直接度量"你写的经验导致了什么"，不需要任何中间价值函数去猜。证据链：(a) Delayed-joint PPO（同一信用但经 critic）在两个基准崩到 0.000/0.010，且 critic 解释方差 >0.95 仍崩——说明崩溃源于信用结构；(b) 保留可验证奖励、只改分组的 Delayed-joint ACE-RL 就能正常学习（0.526/0.250）——奖励来源是存活的必要条件。

**机制二：同输入分组消除了信用中的种子方差项。** 附录 B 的分解表明链式比较下反思优势含一个与反思质量无关的种子项，其大小随任务内轨迹质量离散度增长；同种子比较反思、同洞见比较编辑，把这两项直接从基线中减掉。证据链：(a) 同奖励下按组分组的 ACE-RL 对链式的 Delayed-joint ACE-RL 在 MBPP 全部 26 个检查点领先（终值 0.987 对 0.760）；(b) 失败种子也能产出正奖励反思——这保证了困难任务上反思角色仍有梯度，而不是被种子质量淹没。

**机制三：训练目标与部署形态一致。** GRPO 优化的 J_act 与它被塞进 harness 后的实际执行 J_H 不一致，等于"为一个考试训练、却参加另一个考试"。证据链：(a) GRPO 装入 harness 后 RSI@3 仍差 +0.037~+0.167；(b) Figure 2 的 Venmo 案例里 GRPO 的 curator 从不改写 playbook；(c) edits-discarded 对照中 playbook 的独立贡献（AppWorld +0.105±0.041）只有"为 harness 训练"才能产生。

### 6.2 相关工作检索与对照（交叉验证）

为了检验上述机制解释是否与更广的文献一致，我检索了几条相关研究线：

- **GRPO 组信号理论（B 级，外部理论佐证）**：Bay & Yearick（2026）证明二元可验证奖励下每提示的 GRPO 更新量等于组经验标准差 σ=√(k(G−k))/G——全对/全错的"沉默组"教不了任何东西，Big-Math 上 G=8 时 44% 提示沉默。这从外部印证了机制二：ACE-RL 的组构造（同种子反思互比、同洞见编辑互比）本质是在最大化"组内有分歧"的概率，把沉默组问题在中间文本层面也处理掉了。
- **Memory-R1（B 级，同向先例）**：用下游答案正确性 RL 训练记忆管理器的 ADD/UPDATE/DELETE/NOOP 操作，在 LoCoMo 上相对 Mem0 提升 28% F1/34% BLEU-1/30% LLM-J，但记忆管理器与答题 agent 分开训练。它验证了"下游结果可以训练记忆写入行为"（与机制一同向），而 ACE-RL 的增量是三角色联合训练 + 两阶段交接 + 对比组。
- **ACE 原文（A 级，直接上游）**：Stanford/SambaNova/UC Berkeley 的 ACE 论文（ICLR 2026，已获 107 引用）报告 agent 基准 +10.6%、金融基准 +8.6%，AppWorld 榜单上以更小的开源模型追平顶级生产级 agent——证明 playbook 这个交接介质本身有效，但也正如 ACE-RL Figure 2 所示，其收益依赖会写 playbook 的模型。
- **Memento 2 / SRDP 理论（C 级，理论呼应）**：Jun Wang 的 Stateful Reflective Decision Process 把记忆读写形式化为策略评估/策略改进，证明冻结参数下记忆驱动策略可收敛到最优。它从理论上支持"记忆即学习"，但没有回答"记忆书写行为如何被梯度训练"——ACE-RL 恰好补上这块。
- **MemAgent/MEM1/Mem-α 谱系（B 级）**：用 RL 训练上下文内的记忆重写/压缩（MemAgent 用 Multi-Conv DAPO 从 32K 训练外推到 3.5M QA、损失 <5%），证明"RL 训练文本管理行为"可行；它们的记忆是每步覆盖式重写、信用沿链回传，而 ACE-RL 的工件跨尝试持久、可结构化编辑、且信用来自隔离执行。

**证据等级标注**：A 级 = 论文内受控直接实验（配对差、edits-discarded、critic 诊断）；B 级 = 论文内附录推导 + 外部同向实证；C 级 = 外部理论呼应（方向一致但机制不同）。

### 6.3 综合判断

三个机制不是并列的"加分项"，而是一个因果链：**可验证奖励（机制一）让交接信用有真实信号 → 同输入分组（机制二）让这个信号低方差地落到正确的角色头上 → 两者合起来使训练目标对齐部署形态（机制三）**。Support 证据里最有说服力的两个数字是 MBPP 的 0.987 对 0.867（+0.120，机制一+三的共同效果）和 AppWorld edits-discarded 的 +0.105±0.041（纯机制三的效果）。需要保留的谨慎：论文每方法只跑一次训练、模型只到 4B、MBPP 环境显示被评分的断言（作者自己披露）、Delayed-joint 对照未隔离分组变量——这些都在附录 H 里被作者如实列出。综合判断：**机制解释成立且证据链完整，但"在更大规模上是否仍然必要且充分"是开放问题**。

## 七、必要知识反推

要彻底读懂这篇论文，需要的知识可以分成三层，从地基到顶点：

### 7.1 第一层：基础构件（不掌握则寸步难行）

- **策略梯度与 REINFORCE**：∇θJ = E[∇θ log πθ(y|x) · r]——为什么"得分乘以对数概率梯度"就能提高高分行为的概率；基线减除不影响期望只降方差。
- **PPO/GRPO/DAPO 谱系**：裁剪代理为什么防止策略突变；GRPO 用组均值/组标准差替代 critic 的原理（A_i = (r_i − μ_G)/(σ_G + ε)）；DAPO 的非对称裁剪与动态采样。本文训练循环的每一格都建立在这些之上。
- **RLVR（可验证奖励强化学习）**：数学/代码任务用验证器而非奖励模型打分的范式，DeepSeekMath/R1 验证了其跨规模有效性——ACE-RL 的核心直觉"把 RLVR 从 action 输出推广到交接工件"直接由此继承。
- **LLM agent 基础**：多轮工具调用、轨迹（生成动作与环境观测交织）、轨迹奖励、20 turn 预算这类 agentic 评测惯例。

### 7.2 第二层：领域地图（不掌握则读不懂定位）

- **推理时自改进谱系**：Reflexion（语言反思）→ Voyager（技能库）→ ExpeL（经验蒸馏）→ Dynamic Cheatsheet（自适应记忆）→ Agent Workflow Memory（工作流记忆）→ ACE（playbook 演化）。要知道每个系统交接什么工件、以及它们全部假设冻结模型。
- **harness 与模型的分工**：DSPy/GEPA 优化 harness 包裹的提示词 vs. 本文优化模型本身——一字之差决定了训练信号落在哪。
- **穿 harness 训练的信用难题**：Composer 2/SUPO/CompactionRL/MEM1/MemAgent 这条线的共同结构（自写摘要成为未来上下文）和共同软肋（信用经 critic 或链级优势摊派）。
- **细粒度分组谱系**：GiGPO（重复状态分组）、AT-GRPO（agent/轮级组）——ACE-RL 的采样树是这一原则在 harness 依赖树上的实例化。

### 7.3 第三层：本文的融合节点（真正的创新发生处）

- **融合节点 1：交接工件的可执行验证**。把"playbook 是给 actor 看的"翻转为"playbook 的价值由 actor 执行出来"——Eq.(6) 一行，但它是整篇论文借 RLVR 之威的支点。需要同时懂 RLVR（知道可验证奖励为什么可靠）和 ACE（知道 playbook 是什么）才能在这一行上看出分量。
- **融合节点 2：采样树的稀疏化**。完整对比树 60 输出 → 14 输出且 actor rollout 数与 GRPO 严格对齐——这是"理论上想要什么"（每环节多分支对比）与"工程上付得起什么"（每任务 8 rollout）之间的桥。附录 D 的均匀选择保持均值、单评估保期望、(G−1)/G 因子等推导是理解"近似都显式声明"这股学术审慎的关键。
- **融合节点 3：奖励的三路分配**。同一个 V̂ 沿依赖树回溯：编辑拿全额、反思拿其合法编辑的均值、actor 各拿各的——加上"失败种子也能产出正奖励反思"，这个分配方案同时解决了稀疏奖励下中间角色的可学性。

## 八、通用性灵感

### 8.1 用下游执行效果为中间产物定价

**核心思想**：任何"给别人用的中间产物"（经验、记忆、摘要、计划）都不要凭其表面质量打分，让它被真实消费者执行一次，用最终验证器给消费者打的分给它定价。**论文证据**：r_cur(u)=V̂(Apply(P,u)) 是全部收益的支点；edits-discarded 对照显示 playbook 独立贡献 AppWorld +0.105±0.041。**推广场景**：(1) RAG 系统里用"检索文档进入答案后的答题正确率"训练 chunk 切分与索引策略；(2) 编译器/工具链中用最终程序性能给中间表示的优化 pass 打分；(3) 多 agent 系统里用下游 agent 的任务完成度训练上游的"需求文档写作"；(4) 数据工程里用模型在数据上的下游损失训练数据清洗规则。

### 8.2 同输入对比组：把方差从信用里挤出去

**核心思想**：给需要评分的每个生成环节构造"同条件下的兄弟样本"，用组内相对排名而非绝对分数作为学习信号——兄弟共享的噪声（输入难度、轨迹质量）在相减时自动消除。**论文证据**：附录 B 分解出链式信用的种子项；同奖励下按角色分组使 MBPP 全部 26 检查点领先（0.987 对 0.760）；外部佐证是 GRPO 沉默组理论（组内无分歧=无信号）。**推广场景**：(1) 代码评审 agent：同一 PR 的多条评审意见互比，消除 PR 本身难度差异；(2) 推荐系统：同一用户会话内的多个候选排序互比而非跨用户绝对分；(3) 科学假设生成：同一实验数据的多条假设按下游实验验证率互比；(4) 教育 AI：同一学生的多条讲解按后续答题表现互比。

### 8.3 训练目标必须对齐部署形态（train where you deploy）

**核心思想**：如果模型将要在某个脚手架/流程里工作，就把整个脚手架放进训练循环，让每一次调用（不只最终执行）都接受梯度——"为一个考试训练，就去参加那个考试"。**论文证据**：GRPO 装进 harness 后仍差 +0.037~+0.167，其 curator 在案例中从不修改 playbook；ACE-RL 训练的 curator 学会写可执行检查项。**推广场景**：(1) 检索增强系统：训练时就让模型走完整检索-阅读-回答流程而非只训阅读；(2) 工具使用模型：把真实工具调用闭环（含报错与重试）放进 RL 环境；(3) 长上下文模型：训练时就用部署时的上下文压缩管线；(4) 企业工作流 agent：把审批流、人工检查点作为训练环境的一部分。

### 8.4 让"失败"也能产生正梯度的角色分工

**核心思想**：把"做事"与"总结事"拆成不同角色分别评分，失败尝试的总结仍可与同源总结比较而获得正奖励——失败不再是纯负样本，而是反思角色的训练素材。**论文证据**：论文原文明确"A failed seed can therefore still yield a positively rewarded reflection"；这保证了困难任务上系统的每一环都有学习信号。**推广场景**:(1) 复盘文化系统：失败项目的复盘文档按"下次同类项目的改进幅度"评分而非按项目成败；(2) 自动化科研：失败实验的假设修正按后续实验验证率评分；(3) 客服系统：未解决的工单按其记录对后续同类工单的帮助评分；(4) 机器人：失败轨迹中学到的约束知识单独积累与评分。

### 8.5 可重置的任务局部记忆是安全与学习的平衡点

**核心思想**：经验工件限制在任务局部、由验证器定价、周期性重置——既能学到"写有用经验"的能力，又避免错误经验的跨任务扩散与无限累积。**论文证据**：F=3 重置同时服务两个目的（限制早接受错误编辑的误导 + 反复暴露空 playbook 起点条件）；伦理声明明确边界在沙盒内。**推广场景**：(1) 长期运行的运维 agent：每个 incident 的 runbook 局部累积、验证、定期归零重建；(2) 个人助理：每个长期项目的偏好记忆隔离存放、按用户确认更新；(3) 开源社区：每个 issue 的修复攻略局部演化而非全局污染；(4) 自动化交易：每个市场状态的策略笔记按回测效果淘汰。

### 8.6 小模型 + 训练过的 harness ≈ 大模型 + 手工 harness

**核心思想**：能力不足的模型可以通过"为自己所在的系统被训练"来补偿——与其造更大的模型或更精的手工框架，不如让框架固定、让模型学会在框架里把每个角色都做好。**论文证据**：0.6B/4B 的小模型经 ACE-RL 训练后在四基准全胜，AppWorld 案例里 4B 模型的三角色配合完成了 GRPO 版完全无法推进的任务。**推广场景**：(1) 端侧小模型：为固定的本地工具链整体训练而非单任务微调；(2) 垂直行业：小模型 + 全流程 RL 于固定合规管线；(3) 游戏 NPC：为固定行为树的多角色（感知/决策/记忆）联合训练一个小模型；(4) 嵌入式设备：为固定传感器-执行器回路的多个推理角色联合训练。

## 结语

这篇论文的漂亮之处在于它没有发明任何复杂的新优化器，而是做了一个干净的概念缝合：承认"权重更新"和"经验交接"是两条互补的学习通道，然后用 RLVR 的旧智慧（可验证奖励）+ GRPO 的旧机制（同输入组比较）解决了新问题（中间文本的信用分配）。四基准全胜、K=8 外推、edits-discarded 归因这一整套实验设计值得所有做 agent 训练的人学习——尤其是"critic 拟合得再好也可能崩溃"和"训练目标对齐部署形态"这两条教训。局限也同样清晰：4B 以下模型、单次训练运行、任务局部 playbook 不研究跨任务迁移。下一个自然的问题是：当经验交接从任务局部走向跨任务、从 playbook 走向更丰富的工件类型时，可验证奖励和分组比较这两件工具还够不够用。
