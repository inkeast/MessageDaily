# 规划三重奏：能力层级分解、扩散计划修复与跨回合推理节流

## 一、论文背景

### 1.1 长程任务的规划困境：三个瓶颈

要理解这三篇论文，先要理解 Agent 是什么、长程任务难在哪。LLM Agent（基于大语言模型的智能体）不是只回答问题的聊天机器人，而是能"动手做事"的系统：它把语言推理与可执行工具（API、搜索、代码执行器等）结合起来，与外部环境多轮交互，一步步改变环境状态直到完成目标。你让 Agent"把这封邮件里的截止日期加到 Todoist 待办里"，它需要读邮件、提取日期、调用待办应用的接口——这就是一个典型的多步任务。

当任务从三步变成三十步（长程任务，long-horizon task），规划问题开始暴露出三个环环相扣的瓶颈，恰好对应本文的三篇论文：

**瓶颈一：任务分解与系统能力脱节（TaReD 针对）**。复杂任务通常拆成子任务序列来执行，但拆分往往只看任务语义（目标、实体、流程结构），拆出来的子任务可能系统根本没有对应工具可执行，或者漏掉了必要的阶段。更麻烦的是，真实系统的工具库可能大到无法全量塞进模型的上下文窗口——AppWorld 环境有 457 个工具，全部描述注入上下文会消耗大量 token，还会让模型在无关工具中分心、选错工具。类比：让你照菜谱做菜，但菜谱是按法餐流程写的，而你家里只有中餐灶具——菜谱再合理也执行不了；反过来，把整个超市的货架清单塞给你让你自己找食材，你也会被淹没。

**瓶颈二：计划出错后只能整体重写（Plan-and-Patch 针对）**。Plan-and-act（先规划后执行）类 Agent 生成的计划假设执行时成立，但环境会打脸：工具返回意外结果、动作失败、前提条件变化。现有方法修计划时往往全局重写（整个计划重新生成），而实际上失败通常只影响计划的一小段——前后的结构本来是好的，全部重来既浪费计算又可能把本来正确的部分改坏。类比：一篇十段的文章第三段有个事实错误，正确做法是只改第三段并保证上下文衔接，而不是从第一段重写全文。

**瓶颈三：推理的过度供给（RACE 针对）**。大推理模型（LRM，如 DeepSeek-R1、QwQ 一类"先长篇思考再回答"的模型）把 ReAct 式"每回合都先生成推理再出动作"推向默认：每个交互回合都先想一段再动。但早回合生成的推理（计划、约束、中间判断）往往能继续支撑后续多个回合的动作——第二回合想清楚的事，第三、四、五回合未必需要重新想。每回合都推理，推理 token 的成本随轨迹长度线性堆积。类比：开车去机场，出发前规划好路线后，途中每个路口都要重新把全程推理一遍——大部分路口只需要跟着既定路线走。

### 1.2 三篇论文各自的入场时机

这三个瓶颈并非新问题，各自都有前人工作，但都卡在某个关键机制上：

- 工具领域的主流缓解方案是"预测/检索一个任务相关的工具子集"再规划，但子集选漏了必需工具任务就直接不可能完成（论文一实测这个失败模式占任务的 12%），而且平坦列表不提供任何关于能力关系的结构信息，帮不上任务拆分。
- 计划修复领域有"保留已验证前缀、重写后缀"的方案（如 PIVOT、ContextFlow），但"定位中间一段坏掉、只补那一段"的修复一直缺一个天然支持双向条件生成的模型载体。
- 自适应推理领域已有 Thinkless、AdaptThink 等工作让模型选择何时思考，但它们逐回合独立判定，且获取"该回合推理是否可省"的信号需要重复生成验证——轨迹越长、策略越进化，验证成本越爆炸，尤其在 on-policy RL 里每个回合、每条新采样轨迹都要验证一遍。

### 1.3 为什么合读

三篇论文表面分散（工具组织 / 生成模型范式 / 推理效率），内核却是同一个母题的三次变奏：**Agent 规划系统的增益，越来越不来自"更聪明的单次规划"，而来自对规划过程中信息与计算的结构性调度**。TaReD 调度的是"能力信息何时进入上下文"（按需导航 + 延迟绑定契约）；Plan-and-Patch 调度的是"计算预算花在计划的哪一段"（局部 infill 而非全局重写）；RACE 调度的是"推理计算花在哪几个回合"（跨回合覆盖而非逐回合满供）。读完三篇，你会看到同一个设计哲学（按需、局部、延迟）在三个不同层面的复用——这比任何单篇的技巧更值得带走。

## 二、论文定位和关联工作

### 2.1 TaReD 的研究谱系

**谱系一：任务分解与分层规划**。ReAct（Yao et al. 2023）是链式执行的起点——推理与动作交替的单链；分解式方法（Decomposed Prompting、Least-to-Most、HuggingGPT 等）把任务拆成带依赖的子问题再按序求解；ADaPT（Prasad et al. 2024）进一步做到"执行不了再递归分解"。**关键区别**：这些方法的分解边界来自任务语义，不保证每个子任务对得上环境的可执行操作；TaReD 用能力层级反向约束分解——先看系统有什么能力区域，再按能力边界切阶段。

**谱系二：大工具库使用**。早期工具研究（Toolformer、Gorilla、ToolLLM 等）默认工具全量放在上下文里；工具规模一大，出现了两条路：子集预测/检索（ToolGen 等检索后调用）和层级重排（ToolRerank 等）。**关键区别**：子集方法会漏工具（论文实测 12% 任务因此被阻塞）且是平坦列表；TaReD 保留全库可达性（层级导航不遗漏）同时只把访问过的节点放进上下文，且层级的功能关系本身就是分解的结构引导。

**谱系三：检索系统类比**。能力层级树的结构（内部节点是能力摘要卡、叶是工具契约、根到叶逐层具体化）与图书馆分类法/文件系统目录树同构——这不是巧合，作者在附录 A 中详述了由 AI agent（Codex）先策划版本化分类法、再由确定性构建器生成目录的两阶段流程，137 个类别节点 + 457 个原生工具叶。

**定位结论**：TaReD 是首个把"工具发现的按需导航"与"递归任务分解"紧耦合的框架，其独特贡献是消融实验把"递归架构"与"工具感知"两个因子干净分离——同为递归架构，换成平坦子集（ADAPT 式）TGC 从 69.3% 掉到 51.3%，证明增益主要来自工具感知而非递归本身。

### 2.2 Plan-and-Patch 的研究谱系

**谱系一：扩散语言模型（dLLM）与 Agent**。掩码扩散语言模型（LLaDA、Dream 7B 系列等）通过"从周围上下文重建被掩码的 token"训练，天然支持并行生成与双向 infilling；近期工作把它们用于代码生成、代码补全、ReAct 式 Agent。**关键区别**：已有 Agent 应用聚焦"交错生成动作与观察"，Plan-and-Patch 首次把 dLLM 的 infilling 形式化为 plan-and-act 框架中的计划修复算子，并联合训练生成与修复两种能力。

**谱系二：计划修复与程序修复**。PIVOT/ContextFlow 保留已验证前缀重写后缀；Atomic Task Graph 保留已验证图区域修复受影响子图；L-ICL 定位首个约束违反处。程序修复（APR）领域用测试失败引导故障定位与补丁验证。**关键区别**：这些方法要么修的是后缀（不是任意中间区域），要么依赖特殊训练的 FIM；dLLM 的去噪目标天然就是"保留前后缀、重建中间"——修复即 infill，无需额外机制。

**谱系三：FIM（fill-in-the-middle）**。AR 模型可通过 FIM 序列化/训练适配中间填充（Bavarian et al. 2022），但需要专门训练；dLLM 原生支持且前缀后缀作为双向条件同时可见。论文的对照设计（同 tokenizer/数据/表示的 DreamReasoner-8B vs Qwen3-8B）正是为了分离"范式差异"与"训练数据差异"。

**定位结论**：这是一篇实证+框架型工作——它不宣称 dLLM 全面优于 AR（生成上 AR 略优它照实报），而是严格论证了两种解码范式的互补性：AR 擅长从零到一的顺序生成，扩散擅长双向条件下的局部重建与并行解码。贡献在于第一个把这种互补性做成可训练、可评估的 Agent 计划框架。

### 2.3 RACE 的研究谱系

**谱系一：自适应推理 / 推理高效**。Thinkless、AdaptThink（EMNLP 2025）让模型在思考与非思考模式间选择；ThinkSwitcher、AdaCoT 等调节思考深度；DART 用多个无思考草稿的一致性路由思考模式。**关键区别**：这些方法逐回合独立判定"本回合是否需要思考"，不建模推理的跨回合持续性；且判定信号依赖重复生成，成本随轨迹长度增长。RACE 的"推理覆盖"显式建模一段推理能支撑多远的动作，信号用一次 teacher-forced 似然计算获得。

**谱系二：Agent RL**。AgentGym-RL、RAGEN、GRPO 系工作优化任务回报，聚焦性能而非推理行为本身。**关键区别**：RACE 在 GRPO 中加入两个针对推理的机制——屏蔽 LoGiC 判定可省略的推理 token 的策略梯度（防冗余被强化）、推理闭合监督（在 SKIP 回合监督输出 </think>，教模型主动终止推理）。

**谱系三：似然作为信号**。用参考动作的似然变化度量上下文对它的支撑度，与知识编辑、归因分析中"logit/似然变化定位 influential token"的思路同源。**关键区别**：RACE 把它用作"跨回合推理可移除性"的代理信号并系统验证了其与生成恢复率的对应关系（论文 Figure 1(b)）。

**定位结论**：RACE 的增量在于两点——概念上首次显式刻画 agent 推理的跨回合持续性并给出"推理覆盖"形式；方法上用 O(1) 次似然计算替代 O(生成) 次重复验证，使自适应推理信号在 SFT 数据合成与 on-policy RL 两个场景都可扩展。

## 三、问题定义

### 3.1 TaReD：能力对齐的分解问题

具体问题：大工具库环境下，如何分解长程任务使每个子任务可被现有工具执行？

TaReD 的核心洞察是把"工具"与"任务"的匹配问题转化为"能力区域"与"功能阶段"的匹配问题。形式化：给定任务指令 x、初始环境状态 s₀、工具库 T = {T₁,...,Tₙ}（每个工具契约 Tᵢ = (Inᵢ, Outᵢ, Preᵢ, Effᵢ)，即输入输出模式、前置条件、状态改变效果），工具库按功能组织为能力层级树 G = (V, E)（内部节点带能力描述 cap(v)，叶节点对应工具契约）。求一棵根有序任务树 H，其节点 h = (qₕ, cₕ, rₕ) 为阶段目标、相关上下文、期望能力区域，使得对齐条件 Align(H, T) 成立——**每个叶子在环境中有对应工具、每次调用满足其前置条件**——且执行轨迹满足 Done(x, s_L)。规划目标即 max Pr[Done(x, s_L)] s.t. Align(H, T)。

精妙之处在于把"可执行性"从前置校验变成了结构约束：不是分解完再检查"这个子任务有没有工具"，而是分解的每一步都以能力区域为坐标——子任务天然落在某个能力区域内，对齐由构造保证。

### 3.2 Plan-and-Patch：计划修复作为 infilling 问题

具体问题：计划执行失败后，如何只重建受影响区域而保留前后结构？

论文的抽象跳跃在于把"修计划"重新表述为"文本中间填充"：结构化计划序列化为 token 序列 τ ∈ V^L，其每个子目标与步骤有唯一标识符定位其连续 token 跨度（可寻址，addressable）。修复区域 R ⊆ [L]，把 τ 写成 τ_pre ∥ τ_R ∥ τ_post，则在保留前缀、后缀与修复反馈 f_R 的条件下生成替换 ρ，形成 τ' = τ_pre ∥ ρ ∥ τ_post。生成与修复统一为条件文本生成的两个实例：生成以任务目标为条件生成完整 τ；修复以 (τ_pre, τ_post, f_R) 为条件生成 ρ。

这个抽象的精妙处：一旦修复被形式化为 infilling，"哪个模型范式更适合修复"就变成了一个可以严格对照实验的问题——AR 的似然是单向链式分解（前缀条件），扩散的似然天然双向（前缀后缀同时条件）。论文的问题定义本身就是其结论（范式互补）的前提。

### 3.3 RACE：跨回合推理覆盖问题

具体问题：T 回合交互中，哪些回合的推理可以省略而不损害后续动作？

RACE 的洞察分两层。第一层是现象刻画：推理的支撑有**跨回合持续性（cross-turn reasoning persistence）**——第 s 回合的推理支撑的动作可能延续到 s+1, s+2, ...，支撑范围 L 因推理内容而异。直接度量需要生成验证：截断上下文后采样 K 个动作，计算参考动作恢复率 Rec_j。第二层是轻量代理：若某动作在仅保留早期推理的上下文下仍可恢复，其参考动作似然应保持稳定，否则下降——定义似然下降 d_j = ℓ(a*ⱼ|(xⱼ, rⱼ)) − ℓ(a*ⱼ|x̃ⱼ)，发现 d_j 与 Rec_j 紧密对应（Figure 1）。

形式化目标：优化策略 π_θ 使其在每个决策回合选择"先生成推理再出动作"或"直接出动作"两种模式之一，同时保持任务性能。约束是信号获取必须轻量（不能逐回合重复生成验证），于是问题转化为：**用似然下降构造"推理覆盖"（reasoning cover）——保留一个最小 sufficient 的推理集合，使全部参考动作的似然下降都不超阈值 ε**。

精妙之处：这本质上是个集合覆盖问题的贪心近似——LoGiC 从第 2 回合起逐回合测试移除，接受条件是所有受影响动作的似然下降 ≤ ε，被保留的推理构成覆盖。覆盖的"最小性"没有被严格优化（贪心顺序固定），但 sufficiency 有了可操作的判定标准。

### 3.4 三个问题的共同结构

| | TaReD | Plan-and-Patch | RACE |
|---|---|---|---|
| 具体问题 | 任务分解对不上工具 | 计划修复只能全局重写 | 每回合都推理太贵 |
| 抽象问题 | 结构对齐（能力↔阶段） | 双向条件重建（前缀后缀间 infill） | 覆盖选择（最小 sufficient 集合） |
| 关键类比 | 图书馆分类导航 | 文章局部改写 | 出发前规划一次，路口不重想 |
| 数学骨架 | 树上按需导航 + 约束式分解 | 条件生成 p(ρ丨τ_pre, τ_post, f_R) | 贪心覆盖 + 似然阈值判定 |

## 四、问题解法

### 4.1 TaReD：三层机制咬合的执行协议

TaReD 的解法由三个组件构成，类比分层组织的公司：能力层级是"部门章程"，按需导航是"查组织架构图"，递归分解是"项目经理拆任务"。

**组件一：能力层级（静态组织）**。把平坦工具库按功能分类组织成树：根是全库入口，内部节点是能力区域摘要卡 v = (name, summary, children, scope)——总结该区域支持什么操作、消费产出什么信息、能力边界在哪；叶节点保留完整工具契约。构建分两阶段（附录 A）：AI agent（Codex）从公开 API 文档策划版本化分类法（任务无关，不使用任务指令/参考解/验证器反馈），确定性构建器把分类法与完整文档集转换为序列化目录并校验（每工具恰一主父节点、跨支关系用非树链接表示而非复制工具）。AppWorld 的成品是 137 个类别节点 + 457 个工具叶。类比：给 457 本手册建了一套三级目录——查"发邮件"先到"通信"区再到"邮件"再到具体接口，而不是每次翻全部 457 本。

**组件二：按需能力导航（动态发现）**。对任务节点 h，控制器从其期望能力区域 rₕ 出发逐层查询层级：Cₕ = Navigate(qₕ, cₕ, rₕ; G)。查询持续到检索信息足以规划当前节点为止；若期望区域不够，控制器搜索层级其他区域补缺。**只有访问过的节点进入上下文**。实测：能力信息平均只暴露库的 7.41%、详细契约只查 2.48%。关键性质：因为可搜索完整层级，必要工具不会被初始子集遗漏——消融显示平坦 Predictor 子集有 12% 任务出现阻塞性遗漏（占失败案例的 24.3%）。

**组件三：能力对齐递归分解 + 延迟契约绑定**。拿到能力信息后判断当前目标能否作为一个紧凑执行阶段（Direct(h)）：能则直接规划工具调用序列 Pₕ，**此时才**检索精确契约、绑定参数、执行；不能则用能力信息把当前任务拆成有序子任务序列 h → (h₁,...,h_k)，子任务深度优先处理。子任务间依赖 Dₕ 显式记录，输入绑定 B_ij 只传递必需的输出值（不合并前驱完整上下文）；每个工具调用的结果存入引用式值存储 M（键值 + 出处），后续调用与依赖子任务按引用取值。执行终止于无待处理节点或能力不足。

三个机制的咬合点：分解阶段只见能力卡不见参数细节（延迟绑定让分解免于 schema 噪声），能力边界天然提供子任务划分粒度（按区域切阶段而非按语义猜测），引用式交接避免上下文膨胀（k_mail 一个引用替代整封邮件全文）。论文附录 B 给出直观例子：读邮件取截止日期加 Todoist——先导航到邮件能力区，拆出"定位读邮件"与"创建待办"两个阶段，前者执行完存引用，后者绑定参数时才查 todoist.create_task 的契约。

### 4.2 Plan-and-Patch：一个 dLLM 的双重身份

框架结构：单一扩散规划器（DreamReasoner-8B，由 Qwen3-8B-Base 改造）同时承担计划生成与计划修复；独立执行器（Qwen3-8B）把计划翻译成环境动作，失败时兼任失败检测器。类比：一位既能从零起草方案、也能按批注局部修改的文书——起草用发散思维一次成型，修改用聚焦思维只动批注段落。

**生成：并行 unmasking**。输入任务目标、初始观察、动作语法，模型以置信度引导的并行解码生成完整结构化计划：以固定阈值提交足够自信的 token（块大小 b=4 从左到右逐块去噪），一次前向可提交多个 token。这带来速度优势——实测平均生成延迟 14.3s（ALFWorld）vs AR 的 23.3s，降 39%；TextCraft 21.7 vs 40.2s，降 46%。

**失败检测与区域选择**。执行失败（终止未达目标）时，单独提示执行器根据执行历史 h 选出待修步骤（或弃权），构成修复区域 R 与修复反馈 f_R（环境反馈 + 为何需修改的解释）。这一步无需参考计划（history-based 模式）；训练与参考辅助评估中由 LLM 裁判用参考计划选区域。失败可能出现在与需修复不同的步骤上——检测器要做的归因不只是定位报错点。

**修复：mask 后 infill**。规划器收到失败计划、区域、反馈，把选中 span 替换为填充了 mask token 的画布段（总位置预算 K = 2|R|，允许替换变长——遇到 [delete] token 即截断），在保留前后缀条件下用 RelaxedConfidence 过程联合 infill。AR 对照则用 FIM 序列化一次性左到右生成所有替换。

**联合训练与数据管线**。关键发现：先训生成再补训修复会严重损伤生成（格式失效），因此从原始 checkpoint 起联合训练。训练数据三类：回放成功动作序列构建的参考计划（域规则分叶成子目标，LLM 只改写推理与意图字段，动作参数固定；executor 检查终止奖励）+ 真实执行失败 + 对验证计划做结构扰动（改对象/容器/意图/前提）合成的修复例。ALFWorld 修复语料 699 真实 + 763 合成，TextCraft 267 真实 + 1,661 合成。分目标块大小课程：生成偏小块（61.2% 权重 ≤16 token），修复偏大块（49.0% 权重在 4096 token）——短块利搭建、大块利在固定上下文中填充。

### 4.3 RACE：一个信号，两处使用

RACE 的解法是"发现一个廉价信号，然后把它喂进训练的两个阶段"。

**LoGiC 算法（信号生产）**。输入成功轨迹 τ = (q, (rₜ, a*ₜ, oₜ)ᵀ)，三步：初始化动作似然向量（每个参考动作在其原完整推理上下文下的 teacher-forced 平均 token 对数似然）；从第 2 回合起逐回合构造候选轨迹（移除 rₜ，保留之前已接受的移除与后续全部内容），重算当前及后续参考动作的似然；验证——当且仅当**所有** j ∈ {t,...,T} 的似然下降 dⱼ ≤ ε（论文取 0.001）才接受移除，并更新压缩上下文；否则保留 rₜ 入覆盖。终了保留的推理构成推理覆盖，输出压缩轨迹。类比：逐段检查 GPS 导航的每句提示，删掉后你仍能凭之前听过的路线走对每个后续路口（且不会因为删这句导致后面某路口走错），就删；任何路口受影响就留。

**SFT 使用：轨迹改写**。把全推理轨迹经 LoGiC 改写为自适应轨迹（被移除回合变成空推理直接动作），直接监督训练模型"何时可跳过"。SFT 数据来自 DeepSeek-V4-Pro-0813 标注的成功轨迹。

**RL 使用：cover-aware GRPO**。两个机制：(1) 推理屏蔽——对成功 on-policy 轨迹中 LoGiC 判定的 SKIP 回合，把其推理 token 从 GRPO 策略梯度中屏蔽（保留动作 token 参与任务优化，被屏蔽位置仍在归一化分母中），防止冗余推理被回报强化；(2) 推理闭合监督——在 SKIP 回合监督模型输出推理终止符 </think>（损失 L_close，权重 λ=0.02/0.01），直接教模型在该停的地方停。总目标 L_actor = L_GRPO + λL_close。失败轨迹走标准 GRPO。类比：健身教练既不奖励多余动作（屏蔽），又专门纠正结束姿势（闭合）。

### 4.4 三套解法的机制对照

| | TaReD | Plan-and-Patch | RACE |
|---|---|---|---|
| 核心机制 | 能力层级 + 按需导航 + 延迟绑定 | mask-infill 修复 + 联合训练 + 块课程 | LoGiC 似然信号 + SFT 改写 + 双 RL 机制 |
| 类比 | 公司部门制拆任务 | 文书起草+局部修改 | GPS 提示去冗余 |
| 输入→输出 | (任务, 环境, 层级) → 子任务树+轨迹 | (目标, 观察) → 计划；(失败计划, 区域) → 修复计划 | 全推理轨迹 → 自适应推理策略 |
| 训练需求 | 无训练（推理时方法） | 联合微调 8B 规划器 | SFT + GRPO（Qwen3.5-9B） |

## 五、评估指标与实验证据

### 5.1 TaReD：在 457 工具的硬核环境上分离两个因子

**环境与指标**。AppWorld（Trivedi et al. 2024）：9 个日常应用、457 个 API 的交互环境，任务有官方程序化验证器。评估用最具挑战的 Challenge 集（Test-C），骨干统一 GPT-5.6 Luna，600 秒/回合时限、100 步上限、温度 0、种子 42。三个指标：TGC（Task Goal Completion，所有官方验证检查通过的任务比例，越高越好）、SGC（Scenario Goal Completion，场景内全部变体任务通过的比例，衡量跨相关任务表述的一致性）、ATVS（Average Task Verification Score，归一化验证器进度部分分，上限 100）。

**主结果（Table 1）**：TaReD 69.3% / 48% / 80.28 全面领先；对比 ADAPT（递归基线）46.7% / 22% / 66.01、ReAct（线性基线）51.3% / 26% / 66.81、Plan-and-Solve（先规划后执行）29.3% / 16% / 60.60。相对基线最高提升 40 个百分点（TGC 对 P&S）。所有基线用相同的 one-shot Predictor 选工具子集——这保证了对比公平性：差异来自方法而非工具暴露口径。

**关键消融（Table 2，把"递归"与"工具感知"分离）**：同为 TaReD 递归框架，工具感知方式四选——层级感知 69.3% vs Predictor 固定子集 51.3% vs 全库注入 52.0% vs 可扩展子集 58.7%。两组对照各有深意：层级 vs Predictor 分离出"结构化按需发现"的贡献（+18pp）；全库注入仅比子集略好（+0.7pp），说明**暴露全部信息不解决问题——冗余本身就是干扰**；可扩展子集（允许执行中补工具）明显好于固定子集（+7.4pp），说明按需发现有效但平坦结构仍然吃亏。

**机制分析**：12% 任务存在平坦 Predictor 选择的阻塞性工具遗漏（占总失败案例 24.3%）——这是"选漏即不可能完成"失败模式的直接量化；TaReD 平均仅暴露 7.41% 库的能力信息、2.48% 的详细契约——按需性的直接量化。

**这套实验为何能证明论点**：论文的论点是"工具感知的递归分解优于语义分解"。主表证明优于各类基线；消融表进一步证明在递归架构固定时，工具感知方式仍是决定性变量——增益不是来自递归（ADAPT 也是递归只有 46.7%），而是来自能力层级的导航与引导。若无消融，"递归+工具感知"的复合贡献无法归因。

### 5.2 Plan-and-Patch：为"范式互补"设计的对照实验

**环境与指标**。ALFWorld（家庭任务，134 测试任务）、TextCraft（依赖约束合成，100 任务），任务内训练；Natural Plan（旅行/日程规划，程序化约束验证器，无执行器）提供无任务训练评估。生成指标：终端任务成功率（executor 执行计划达目标）；修复指标：修复后从初始状态重启执行的成功率；延迟：单张 A100 同步无批 bf16 解码平均秒数（排除提示构建/解析/环境执行）。主表（Table 1）：

| 环境 | 模型 | 生成 | 参考辅助修复 | 历史式修复 | 端到端 |
|---|---|---|---|---|---|
| ALFWorld | Diff-Plan | 44.0% | 28.4% | 14.3% | 59.9% |
| ALFWorld | AR-Plan | 45.5% | 27.7% | 17.5% | 60.6% |
| TextCraft | Diff-Plan | 63.0% | 15.5% | 24.5% | 68.7% |
| TextCraft | AR-Plan | 66.0% | 18.3% | 30.6% | 72.2% |
| （对照）ALFWorld | ReAct | 38.1% | − | − | − |
| （对照）TextCraft | ReAct | 48.0% | − | − | − |

**无任务训练的 Natural Plan（Table 2）是范式对照的关键**：修复（填参考计划空白区域，2,661 例）扩散 53.7% vs AR 27.0%（验证器口径，近 2 倍；GPT-5/Sonnet 5 裁判同向：72.9 vs 42.1、81.6 vs 53.4）；生成（1,000 任务）AR 反超 48.6% vs 33.0%。精确替换恢复率 22.7% vs 5.0%。域分解显示修复优势集中于旅行规划（93.3% vs 35.7%），其航班图结构利于灵活解码。bootstrap 95% CI [23.8, 29.6]pp。

**区域选择消融（Table A.9）**：同一 175 个失败、反馈固定，历史式选区比参考辅助选区在扩散上低 12pp（17.1% vs 29.1%）——**选对修复区域是当前主要瓶颈**，而非 infill 能力本身。

**表示消融（Table A.7/A.8）**：散文式计划（阶段标题+编号步骤）生成更高（Qwen3-8B 执行器下 ALFWorld +17.9-22.4pp）但修复更差（扩散参考辅助修复 21.3% vs 28.4%）——显式定界利于修复定位，表示的选择是生成与修复的权衡。

**长程失败分析（ScienceWorld，附录 A.3.4）**：参考计划平均 27.1 叶步时扩散解析接受率骤降（34.3% vs AR 73.8%，28+ 步仅 7-9%）——扩散在长计划上有系统性序列完整性问题（754/758 拒绝是未闭合层级+重复动作，中位重复率 93.3%）。这是论文对自己方法边界最诚实的量化。

**这套实验为何能证明论点**：论文论点是"范式互补而非替代"。同 tokenizer/数据/表示/执行器的对照排除了混杂；Natural Plan 的无训练设置隔离了预训练偏好（infilling 是 dLLM 原生目标 vs AR 需 FIM 特训）；生成与修复两个方向都报（包括 AR 占优的）避免单向叙事。诚实的边界报告（ScienceWorld）进一步限定了结论适用范围。

### 5.3 RACE：四域基准上的双重指标

**环境与指标**。四个基准覆盖四类能力：ScienceWorld（30 任务类型 1,819 测试实例，科学推理，要求环境分数达 100）、WebShop（500 测试指令，网购，奖励达 1）、AppWorld（Test-N+Test-C 共 585 任务，应用调用，严格状态单元测试）、DeepSearch（400 题 EM，知识密集检索）。指标双轨：成功率（越高越好）+ 每轨迹平均推理 token 数（越低越好）。骨干 Qwen3.5-9B。主结果（Table 1，RACE-SFT-RL）：

| 基准 | RACE 成功率 | RACE token | 基座 Qwen3.5-9B | vs 基座提升 | vs 基座 token 降幅 |
|---|---|---|---|---|---|
| ScienceWorld | 73.28 | 1,403 | 18.52 / 2,210 | +54.76 | −36.5% |
| WebShop | 53.40 | 535 | 15.60 / 2,713 | +37.80 | −80.3% |
| AppWorld | 65.13 | 1,900 | 46.15 / 3,134 | +18.98 | −39.4% |
| DeepSearch | 35.00 | 822 | 29.25 / 1,281 | +5.75 | −35.8% |

同骨干推理高效基线对比：ThinkTool 19.63/14.00/43.59/25.75、ADaPT 14.24/31.80/21.20/25.75、SparseReAct 19.85/16.40/45.47/26.00、DART 17.92/18.20/49.06/29.00、最强基线 AdaptThink 64.49/44.60/68.72/33.50——RACE 在 ScienceWorld/WebShop/DeepSearch 三域最佳，ScienceWorld 73.28 甚至超过 GPT-5.5 (Medium) 的 69.88（9B 模型超前沿闭源模型）。对 AdaptThink 的 WebShop 细看：token 535 vs 748 且成功率 53.40 vs 44.60——同时更省更强。

**消融矩阵（Table 2）是最有信息量的证据**：完整 RACE-SFT-RL 73.28/1,403（SW）；去掉 RL 中的推理屏蔽 → 72.95/609（成功率几乎不变但 token 大降，但其他域成功率受损——WebShop 掉到 46.00）；去掉 RL 中的 LoGiC（退化为标准 GRPO）→ token 从 1,403 涨到 2,573（SW）、535→2,670（WS）、1,900→8,574（AW）、822→3,507（DS）——**没有 LoGiC 信号，RL 会让推理重新冗长化**（推测机制：任务回报不惩罚冗余推理，策略梯度随机漂移甚至鼓励"多想保险"）；只 SFT 不 RL → 43.05/1,966（SW），成功率大缺口；标准 SFT+GRPO（无任何 LoGiC）→ 74.55/2,073——性能相当但 token 溢出 48%。

**行为分析（Table 3）揭示"节流不等于缩短"**：RL 后 skip 比例 ScienceWorld 37.22%→69.65%、WebShop 7.15%→55.72%；但保留回合的单回合推理量在状态密集任务（SW 132→273、AW 273→302）反而增加、在检索型任务（WS 144→101、DS 259→117）减少——**RACE 学到的是按任务特性重分配推理，不是均匀压缩**。规模实验（2B/4B/9B）显示有效性随规模增长。

**这套实验为何能证明论点**：论文论点是"似然信号足以教会出现代价敏感的自适应推理"。双重指标防止"省 token 掉性能"的退化解读；消融矩阵把 SFT/RL/屏蔽/闭合四个组件的贡献分离；对 AdaptThink 的对比（更强更省）排除了"只是奖励塑形"的解释；行为分析证明学到的是结构性行为（重分配）而非简单截断。

### 5.4 三篇实验设计的共同亮点

三篇论文的实验都有一个难得的品质：**设置了能杀死自己核心主张的对照**。TaReD 的消融杀死"递归本身就行"的替代解释；Plan-and-Patch 的双向报告杀死"dLLM 全面更好"的营销叙事；RACE 的标准 SFT+GRPO 对照杀死"训练本身就会让推理变省"的平凡解释。这种"自我证伪式设计"是判断一篇方法论文可信度的可靠信号。

## 六、效果优势的根源解释

### 6.1 TaReD：为什么层级导航比子集选择与全量注入都好

**对比对象**：两条主流 baseline——全量注入（把 457 个工具描述都给模型）与 Predictor 子集（one-shot 预测任务相关子集）。它们各自为何曾经有效：全量注入在工具少时信息完备、无遗漏；子集选择在工具多时显著减噪、聚焦。

**baseline 的根本局限**（机制层面）：
- 全量注入的瓶颈不是上下文长度而是**选择注意力**：457 条描述同屏时，任务无关工具构成分布层面的干扰，模型选择工具的准确率下降——消融中全量注入 TGC 52.0% 仅比子集 51.3% 高 0.7pp，说明"看到全部"几乎不带来选择收益（论文正文：冗长的工具描述会分散 agent 注意力、使选择与执行复杂化）。
- 子集选择的瓶颈是**不可恢复的信息删除**：选择发生在执行前，此时模型对任务需要哪些能力的判断是不完整的；一旦漏掉必需工具，后续任何规划都无法补救——12% 任务的阻塞性遗漏是结构性的（论文：从未暴露的能力无法在之后被选择）。

**TaReD 的根本性改变**：层级导航改变了信息流的时间结构——能力信息从"执行前一次性给定"变为"执行中按需增量暴露"。这带来三个机制变化：(1) **可达性保持**：完整层级始终可搜索，必要工具不可能被永久遗漏（对比子集的不可恢复删除）；(2) **注意力聚焦**：任意时刻上下文只含已访问路径的能力卡（7.41%），选择问题在每一步都是小规模问题；(3) **结构引导**：能力边界为分解提供了任务语义之外的切分坐标——子任务粒度由能力区域天然界定（对比平坦列表不提供任何结构信息）。

**因果链**（每步标注证据状态）：
1. 平坦子集在执行前遗漏必需工具 → 12% 任务结构性不可能完成 [论文实验已支持：遗漏分析]
2. 层级导航保证全库可达且只暴露访问路径 → 遗漏消除 + 上下文聚焦 [论文实验已支持：7.41%/2.48% 暴露率 + Table 2 层级 69.3 vs 子集 51.3]
3. 能力边界提供子任务划分粒度 + 延迟契约绑定隔离参数细节 → 分解质量提升 [部分支持：论文正文推理性论证，无直接分解质量指标]
4. 同为递归架构，层级感知比子集感知 TGC 高 18pp → 增益主要来自工具感知而非递归 [论文实验已支持：Table 2]

**反事实推理**：若去掉层级保留按需发现（可扩展子集消融），TGC 从 69.3% 降到 58.7%——按需发现解释了相对 Predictor 的大部分增益（+7.4pp），层级结构额外贡献 10.6pp。若去掉延迟绑定（消融未单独报告），论文正文论证其作用但无独立量化——这一环属于"设计合理但证据间接"。

**外部证据交叉验证**：层级化信息组织改善检索与选择，与信息检索领域的成熟结论一致——图书馆科学/文件系统/生物分类学都演化出层级组织，因为层级把 O(n) 的线性扫描变成 O(depth) 的导航；TaReD 附录 A 引用的两阶段构建（AI 策划 + 确定性构建）与软件工程中 schema 演化管理的实践同构。工具检索领域，ToolRerank（Zheng et al. 2024，论文引用）已证明层级感知的重排优于平坦重排——方法相似的外部佐证。Shi et al. 2025（论文引用的"检索模型不擅长工具"基准）从反面支持：平坦检索在工具选择上系统性失误。**在本次检索范围内未发现**直接把"能力层级引导任务分解"作为对照的工作——TaReD 在这个具体交叉点上没有外部对照，其结论目前主要依赖论文自身的消融。

### 6.2 Plan-and-Patch：为什么扩散擅长修复、AR 擅长生成

**对比对象**：AR 规划器（Qwen3-8B，FIM 序列化做修复）。AR 为何曾经有效：左到右生成与自然语言的时序性契合，KV cache 使推理高效，预训练分布大量是前缀条件生成。

**baseline 的根本局限**（对修复任务而言）：
- AR 的似然分解是 p(A|Q) = ∏ p(Aᵢ|A<ᵢ, Q)——**后缀条件必须通过 FIM 特殊序列化/训练才能进入**，且 FIM 训练目标与预训练的左到右目标存在分布偏移。修复需要"替换段与前文和后文都衔接"，AR 只原生看见一半。
- 顺序解码在生成完整计划时 token 间无并行性——延迟与计划长度线性相关。

**Plan-and-Patch 的根本性改变**：dLLM 的训练目标（masked-token objective）**就是**"在保留上下文中重建被掩码区域"——修复与预训练目标同构，无需适配。这带来两个机制变化：(1) **双向条件原生可用**：infill 时前缀后缀同时作为条件，替换段天然与两侧衔接（论文 Natural Plan 案例图 A.5：空白在前缀末尾，扩散正确续出衔接后缀的航班句，AR 重复了下一行）；(2) **并行解码**：置信度引导的一次前向提交多 token（实测每次前向 7.7-18.3 token vs AR 的 1 token），延迟从线性降为近亚线性。

**因果链**：
1. dLLM 去噪目标 ≡ 双向条件重建 → 修复=原生操作，AR 需 FIM 特训且有目标偏移 [机制论证已支持：论文 §3 数学表述 + FIM 文献（Bavarian et al. 2022）]
2. 原生双向条件 → 无任务训练时修复近 2 倍优势（53.7 vs 27.0）[论文实验已支持：Natural Plan，验证器+双裁判三口径一致，CI (23.8,29.6)pp]
3. 置信度并行解码 → 前向提交 token 数 7.7-18.3 vs 1 → 延迟 −39~46% [论文实验已支持：延迟测量 + 前向统计]
4. 顺序生成的全局一致性优势 → AR 生成略优（48.6 vs 33.0）且长计划完整性更强（SW 解析率 73.8% vs 34.3%）[论文实验已支持——注意这条是反方向，诚实划定边界]

**边界与反事实**：区域选择消融显示历史式选区使修复降 12pp——**瓶颈已从填充能力转移到归因能力**（选哪段修）。表示消融显示显式定界对修复定位的价值（散文表示修复更差）。ScienceWorld 长计划上扩散的序列完整性崩塌（重复率中位 93.3%）说明并行解码的代价是全局结构约束变弱——扩散修复优势成立的条件是"计划有显式结构定界 + 修复区域局部"。

**外部证据交叉验证**：扩散模型代码填充优于 AR-FIM 有外部佐证——DreamOn（Wu et al. 2026b，论文引用）专攻超越固定画布的代码 infilling；Diffusion is a code repair operator（Singh et al. 2025，论文引用）直接在代码修复上得出相近结论（方法相似 + 结论相近，强支撑）。Trainin et al. 2026（论文引用）证明扩散模型能利用后缀 token 引导前缀决策（lookahead）——与旅行规划航班图上扩散修复优势集中的发现互相印证（结论相近，不同场景）。反方向的证据论文自己也引了：Lu et al. 2026（"bitter lesson of dLLM for agentic workflows"）发现 dLLM Agent 有重试循环/工具调用格式不精确两类系统失败——与 ScienceWorld 长计划完整性问题一致（限定条件：dLLM 的优势依赖结构化接口与局部操作）。Kim et al. 2025 的性能刻画指出 dLLM 实际效率依赖上下文长度/批处理/采样步数——解释了修复延迟在两环境间的不一致表现。

### 6.3 RACE：为什么似然信号 + 覆盖建模能教会节流

**对比对象**：两类 baseline——无训练的推理高效方法（ThinkTool、DART 等提示/路由）与 AdaptThink（GRPO + 无思考回合比例奖励 r(τ) = R(τ) + δ·NoThink 比例）。AdaptThink 为何有效：奖励显式鼓励跳过思考，GRPO 能优化该偏好。

**baseline 的根本局限**：
- 逐回合独立判定忽略推理的跨回合持续性——第 t 回合"是否需要新推理"的答案取决于第 t-1、t-2...回合的推理还剩多少支撑力，独立判定要么过省（断供）要么过保（冗余）。
- 生成验证的成本结构：每回合采样 K 次候选动作对比，成本 O(K·T·生成长度)；on-policy RL 中策略每步都在变，验证必须随 rollout 重复——成本随训练时长二次增长，实际不可扩展。
- AdaptThink 的比例奖励是**轨迹级**的——它奖励"总体少思考"但不区分哪一回合的思考真的冗余，学与不学的粒度错位。

**RACE 的根本性改变**：把"推理是否可省"的判定从**生成空间**搬到**似然空间**。机制变化：(1) **O(1) 代价信号**：teacher-forced 打分只需一次前向（对比 K 次完整生成），且可在 rollout 批内批处理——信号生产成本从平方降为线性，SFT 合成与 on-policy RL 都用得起；(2) **跨回合判定单位**：LoGiC 的接受条件是"移除 rₜ 后**所有**后续受影响动作似然不降超阈"——天然以覆盖范围而非单回合为单位评估推理价值；(3) **RL 双锁**：屏蔽防止冗余被强化（机制：被屏蔽 token 无梯度，等效于对其"存在与否"不奖不惩）+ 闭合监督给出正向终止信号（机制：直接规定 SKIP 回合的输出是 </think>，把"跳过"变成可学习的显式动作而非默认行为）。

**因果链**：
1. 似然下降与生成恢复率强对应（Figure 1(b)）→ 似然是可移除性的有效代理 [论文实验已支持：Qwen3.5-9B 在 SW/WS 上的对应关系分析]
2. LoGiC 产出覆盖信号 → SFT 直接监督跳过时机 [机制已支持：SFT 消融，RACE-SFT 比标准 SFT token 降 4.3-20.0% 且性能差 ≤1.88 点]
3. RL 中去掉 LoGiC → 推理重新冗长化（token 涨 83%-351%）→ 无信号时 GRPO 默认纵容冗余 [论文实验已支持：Table 2]
4. 双锁下 RACE-SFT-RL vs 标准 SFT+GRPO：性能差 ≤1.40 点但 token −32.3%~−80.2% → 信号带来的节省是"免费"的 [论文实验已支持]
5. 行为分析：skip 比例升 + 状态密集任务保留回合的单回合推理变长 → 学到的是重分配 [论文实验已支持：Table 3——推测性解读：这是 RACE 对表 3 的解释，属于合理推断]

**边界与反事实**：ε=0.001 的阈值敏感性论文未做系统消融（证据缺口）；似然代理假设"参考动作是好动作"——成功轨迹上成立，失败轨迹上未定义（RACE 的 RL 确实只对成功轨迹用 LoGiC，自洽）；跨域最优但 AppWorld 上 AdaptThink 的 68.72 高于 RACE 的 65.13——在应用调用这种"每回合都要细致规划"的域，覆盖式节流的天花板可能低于通用奖励。

**外部证据交叉验证**：AdaptThink（Zhang et al. 2025）本身证明"学会何时思考"可行（结论相近，单回合粒度）；Agent-Omit（Ning et al. 2026，论文引用）同方向做推理与观察省略（方法相似）；Lewis-Lim et al. 2025 用置信度估计判定 CoT 必要性——与似然信号同族的轻量代理（方法相似，不同信号）。反方向/限定性证据：论文自己引用的分析（Chen et al. 2026a "Search more, think less"）显示长程搜索任务中"多搜少想"的效率结构——与 RACE 在 DeepSearch 上 skip 比例仅 5.77%（最低）的行为一致：知识密集检索确实需要每回合推理，RACE 没有强行省掉，这反过来印证信号的自适应性。**在本次检索范围内未发现**对"跨回合覆盖"这一具体概念的独立外部验证——推理覆盖的概念目前是 RACE 一家提出的，其作为心智模型的价值有待后续工作检验。

### 6.4 综合判断与未决问题

**多项证据共同支持的机制**：(1) 结构化信息组织优于平坦注入（TaReD 消融 + 信息检索领域先例 + ToolRerank 外证）；(2) 双向条件生成是扩散范式的真优势（PnP 三口径一致 + DreamOn/Singh 外证 + Trainin 的 lookahead 解释）；(3) 似然类轻量信号足以驱动训练时的行为塑形（RACE 消融矩阵 + 同族工作佐证）。

**仍属推测或单点证据的机制**：延迟契约绑定对分解质量的贡献（TaReD 无独立消融）；旅行规划修复优势的"图结构"解释（PnP 的推测性归因）；ε 阈值的稳健性（RACE 未报敏感性分析）。

**优势的适用条件与失效条件**：TaReD 需要**可离线构建且稳定的能力层级**——工具库频繁变动时两阶段构建的维护成本上升（论文自认：导航的额外模型调用增加执行时间，缓存又增大上下文，权衡开放）；Plan-and-Patch 需要**计划有显式结构定界且失败局部化**——长计划/全局耦合任务上扩散完整性崩塌（ScienceWorld 证据）；RACE 需要**成功轨迹可获取**（SFT 数据源）且**冗余主要来自逐回合重复推理**——若任务本身每回合都需要新颖推理（DeepSearch 的 5.77% skip），节省空间有限。

## 七、必要知识反推

假设一个完全没有背景的人要复现这三篇论文的工作，他最少需要知道什么？

### 7.1 领域知识层

- **Agent 交互模型**：ReAct 式推理-行动-观察循环是什么、plan-and-act 与链式执行的区别——不知道这些就无法定位三篇论文各自改造的环节。
- **工具/API 契约语义**：输入输出模式、前置条件、效果（In/Out/Pre/Eff 四元组）——TaReD 的对齐约束与延迟绑定全部建立在这套语义上；不懂契约就无法理解"绑定"到底延迟了什么。
- **AppWorld/ALFWorld 等环境的结构**：任务如何验证（程序化验证器 vs 终端奖励 vs EM）、Test-C 为什么难——评估协议的选择直接影响结论的可信范围。
- **扩散语言模型 vs AR 的机制差异**：masked-token 目标、置信度并行解码、FIM 是什么——不懂这些，Plan-and-Patch 的对照设计动机完全不可见。
- **推理 token 成本的度量**：每轨迹平均推理 token 为什么是合理效率指标、与延迟的区别——RACE 的核心卖点建立在这个度量上。

### 7.2 方法论知识层

- **任务分解的形式化**：根有序任务树、依赖关系、深度优先处理——TaReD 的问题定义直接使用这套语言。
- **消融设计的因子分离逻辑**：如何用"固定架构换组件"分离两个混在一起的贡献（TaReD 的 Table 2 是范本）——没有这个方法论素养，写不出能说服审稿人的实验。
- **掩码扩散的训练与解码细节**：mask 率采样、块大小课程、RelaxedConfidence、[delete] token 的变长机制——Plan-and-Patch 的工程实现层。
- **GRPO 的机制**：组相对优势、裁剪、token 级策略梯度——RACE 的"屏蔽"操作作用于哪些量，不懂 GRPO 就无法理解屏蔽的确切含义。
- **teacher-forced 似然计算**：与自由生成的区别、为什么它可以批处理——RACE 信号低成本的关键。

### 7.3 工程知识层

- **两阶段目录构建流水线**：AI 策划分类法 + 确定性构建器 + 完整性校验（单父节点、可达性、契约一致性）——TaReD 的层级不是拍脑袋来的，是工程化的产物。
- **参考计划数据管线**：回放成功序列、域规则分组、LLM 改写仅限推理字段、执行验证过滤——Plan-and-Patch 训练数据的质量保障链条。
- **联合训练与课程设计**：为什么顺序微调会灾难性遗忘（PnP 实测生成崩坏）、分目标块大小如何设置——训练配方是可复现性的核心。
- **评估隔离协议**：统一骨干/预算/验证器/种子（TaReD）、同 tokenizer/数据/表示/执行器（PnP）、温度与上下文上限统一（RACE）——公平对照的技术细节。

### 7.4 知识融合的关键节点

三篇论文各自的融合节点有个共同模式：**把一个领域的机制原生地映射到另一个领域的需求上**。TaReD 融合了"信息检索的层级导航"与"任务分解的对齐需求"——发现目录树的导航机制恰好同时解决遗漏与聚焦，这在两个领域各自内部都推不出来。Plan-and-Patch 融合了"扩散模型的去噪目标"与"计划修复的双向条件需求"——意识到 infill 就是修复，是把模型范式知识翻译成任务需求的洞察。RACE 融合了"语言模型的似然语义"与"推理冗余的判定需求"——把生成空间的验证问题搬到似然空间，是计算等价性与成本敏感性的化学反应。三者的深层共同知识是：**理解"模型内部量"（似然、掩码目标、注意力聚焦）与"系统需求"（对齐、修复、节流）之间的翻译表**——这张表比任何单篇的具体技巧都更可迁移。

## 八、论文中可以提取的通用性灵感

**灵感一：按需导航优于全量暴露，也优于预先选择**。

核心思想：面对超大信息空间，"层级化 + 执行中按需下钻"同时优于"全部给你"与"提前替你选好"——前者保可达性，后者保聚焦，层级导航兼得。

论文证据：TaReD 消融——层级 69.3% vs 全库注入 52.0% vs Predictor 子集 51.3%；平均只暴露 7.41% 能力信息；全量注入几乎不比子集好（+0.7pp），证明冗余即干扰。

推广场景：(1) 员工 onboarding——给新人"部门-团队-职责"的导航式目录优于甩全部文档或直接指定导师；(2) API 网关设计——按服务分类树渐进发现优于全量 SDK 文档注入或固定白名单；(3) 个人知识管理——笔记本的层级目录 + 渐进展开优于全库搜索或预制摘要；(4) 医疗分诊——症状-科室-专病的层级导航优于让患者自查全部疾病库。

**灵感二：修复应该形式化为 infilling，而不是重写**。

核心思想：任何"局部损坏的的结构物"（计划/代码/文档/流程），修复的正确抽象是"在保留前后文条件下重建中间段"——这个抽象一旦建立，修复能力就从需要专门机制变成可以继承已有系统能力。

论文证据：dLLM 的去噪目标与修复同构 → 无任务训练修复近 2 倍（53.7 vs 27.0）；历史式选区比参考选区低 12pp，说明瓶颈已转移到"定位损坏段"而非"重建"。

推广场景：(1) 代码修复——diff 定位 + 局部重生成优于全文件重写（APR 领域已验证同逻辑）；(2) 组织流程改进——定位失效环节局部再造，而非组织重构；(3) 文本编辑——编辑指令作用于定位后的 span（显式定界使修复定位成为可能，PnP 表示消融的反面教训）；(4) 供应链恢复——受冲击环节的本地替代方案设计优于全链重排。

**灵感三：昂贵验证的轻量代理信号藏在似然/置信度等内部量里**。

核心思想：当你需要频繁验证"某操作是否可省/可行"而验证本身需要昂贵执行时，先寻找与执行结果强相关的模型内部可计算量——一次前向的似然往往携带与一次生成同量级的信息。

论文证据：似然下降与生成恢复率紧密对应（RACE Figure 1）；O(1) 似然计算替代 K 次生成验证，使 on-policy RL 中的逐回合信号获取从不可扩展变为可行。

推广场景：(1) 数据管道——用 schema 似然/校验分预筛数据质量，仅对可疑记录跑完整处理；(2) 推荐系统——小模型打分预筛 + 大模型精排的级联，本质是同一权衡；(3) 软件测试——变异测试中用覆盖率变化代理缺陷检测；(4) 教育——用答题过程的每步置信度诊断知识断点，替代整卷重考。

**灵感四：持续供给的资源要按覆盖范围调度，而非按消耗周期调度**。

核心思想：当一次投入（推理/规划/学习）能支撑多个后续周期时，调度单位应该是"覆盖范围"而非"每个周期各供一份"——先识别单次投入的有效半径，再以覆盖视角做最小充分配置。

论文证据：RACE 的"推理覆盖"显式建模推理的跨回合支撑范围；学到的行为是 skip 比例大升同时状态密集任务保留回合的推理反而更长（重分配而非均匀压缩）；对 AdaptThink 在 WebShop 上更省更强（535 vs 748 token，53.40 vs 44.60）。

推广场景：(1) 编译与缓存——按依赖图的失效半径决定重编译范围（增量编译的本义）；(2) 库存管理——按需求覆盖周期订货（EOQ 模型的深层逻辑）而非每旬等量补货；(3) 团队知识管理——专家讲解一次录制覆盖多次重复答疑，而非每次答疑都在线；(4) 云资源——按负载覆盖窗口预留实例而非按小时粒度伸缩。

**灵感五：诚实的负结果边界报告是方法可信度的放大器**。

核心思想：主动报告自己方法失效的条件与量化的失败模式，不削弱反而强化主张——因为它把结论从"我们的方法好"升级为"我们的方法在这些条件下好、那些条件下不好"，后者才是可行动的知识。

论文证据：PnP 报告 AR 生成略优与 ScienceWorld 长计划扩散崩塌（解析率 34.3% vs 73.8%）；TaReD 自认层级导航的执行时间开销与缓存权衡开放；RACE 承认 AppWorld 上不及 AdaptThink。

推广场景：(1) 技术选型报告——给每个候选方案列"何时不适用"；(2) 临床指南——适应症与禁忌症并列；(3) 投研报告——做多与做空论据同时呈现；(4) 个人决策——列"什么证据会让我改变主意"。

**三篇论文的共同元灵感**：Agent 规划的下一段红利来自**计算与信息的调度学**——不是让单次规划更聪明，而是精确回答"什么信息在什么时刻进入上下文（TaReD）、什么计算花在计划的哪一段（Plan-and-Patch)、什么推理花在哪几个回合（RACE）"。这与操作系统从裸机程序演化到进程调度的历史阶段同构：当单进程已经足够快，系统级的下一步是调度器。三篇论文各自造了一个小调度器——它们合起来暗示，Agent 系统正在长出自己的操作系统层。
