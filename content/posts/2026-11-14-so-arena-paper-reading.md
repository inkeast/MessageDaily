## 一、论文背景

### 1.1 快思考与慢思考：大模型的"双系统"

心理学里有个著名的双系统理论（Kahneman 的《思考，快与慢》）：人脑有两套运作方式——System 1 快而省力，靠直觉瞬间给出答案；System 2 慢而费力，靠逐步推理解决复杂问题。这个框架近两年被大模型领域直接借用：

- **System Two 模型**（推理模型）：回答前先生成成百上千个推理 token（思维链），在数学、代码、科学推理上大幅提升，但推理 token 意味着真金白银的延迟和算力成本。
- **System One 模型**（决策模型）：不发长篇大论，一次前向传播就直接输出对预定义结果（选项）的概率分布。

为什么需要后者？因为软件工作流里大量日常决策根本不需要"长篇思考"：路由一个请求到哪个服务、从工具菜单里选哪个动作、判断一条任务是否已完成——这些决策高频、重复、实时性要求高。以 Jev 为代表的决策模型把这类决策压缩到单次前向，延迟从秒级降到毫秒级，而且输出是结构化的概率分布，下游软件可以直接消费。

### 1.2 "决策模型"是个什么新品类

传统 LLM 是"文本进、文本出"；决策模型是"状态 + 决策规范进、选项分布出"。形式化地，一个决策请求是三元组 x = (s, q, C)：s 是供给信息（文本、结构化记录、检索段落、交互历史），q 是决策目标，C = {c1, …, cK} 是允许的结果集合。模型返回一个合法的概率分布 pθ(·|x)。这不是"选择题版的 ChatGPT"那么简单——它是一个新的模型品类，有自己的 API 生态（TypeSafe 的 Jev API、OpenAI 的 Decisions API）、自己的开源权重家族（GLiDE、KnowLine、JevAny、Kev、Decider……从 0.4B 到 31B）、自己的调用接口（choice 多选 / noul 是非 / score 评分三种类型化输出）。

### 1.3 为何需要新评测

品类爆发了，评测却没跟上。论文开篇即指出：**现有评测大多只给一个聚合准确率**，看不清两件事——

1. **能力光谱**（capability spectrum）：模型在哪些领域行、哪些领域不行？难度爬升时性能怎么衰减？在真实交互环境（而不是静态选择题）里还能不能行？
2. **决策可靠性**（decision reliability）：把选项换个顺序，答案还稳不稳？选项里根本没有正确答案时，模型能不能发现"无解"而不是硬选一个？

这两件事聚合精度都回答不了。SO-Arena 就是围绕这两个维度构建的基准——用一个二维坐标（能力 C × 可靠性 R）代替一根一维的准确率标尺。

## 二、论文定位和关联工作

### 2.1 决策基准谱系：一条快速拥挤的赛道

2026 年下半年，决策模型评测已经是一条小而拥挤的赛道。论文 Related Work 与引用列表里至少有六个直接同行：

| 基准 | 规模 | 测什么 | 相对 SO-Arena 缺什么 |
|---|---|---|---|
| **JevBench**（Benchmark Heaven） | 数百题 | 能力、校准、延迟、成本 | 无难度分层、无可靠性维度、无 agent 任务 |
| **JEval**（Duan et al., 2610.03935） | 十个应用领域 | 局部决策如何组合成 agent 工作流与社会模拟 | 无域内难度分层、无选项干预测试 |
| **OpenDecisions**（"Releasing the Inner Jev"，2610.17205） | — | 有难度分层与受控扰动 | 分层非域内相对化、无历史依赖验证、无独立可靠性分 |
| **System1-Arena**（2610.21244） | 92,125 题 + 138 闭环环境，30 模型 | 静态决策精度 + Brier 校准 + 闭环 agent | 无受控选项干预（重排/缺失）、可靠性未独立成维 |
| **ReflexBench v1**（Brida） | 数百题 | System One 模型基础能力 | 覆盖窄、排名对任务选择敏感 |
| **S1MB**（HuggingFace 社区） | 100+ 基准聚合 | 横向聚合 | 聚合为主，缺细粒度诊断 |

SO-Arena 的差异化定位是三件事的组合：(1) **域内难度分层**（难度只在领域内部定义，不跨域校准——Math 的 easy 和 Web 的 easy 不可比，但域内可比）；(2) **受控的历史依赖验证**（同一个最终状态、不同执行历史的轨迹对，考"验证者"而不只是"执行者"）；(3) **独立的可靠性分** R，由选项重排一致性与缺失识别力两个受控实验合成。

### 2.2 与通用能力评测、评测器评测的关系

再往外一圈是三条更大的文献线：

- **通用能力评测**：MMLU、BIG-Bench Hard、Humanity's Last Exam 测广度与难度，HELM 强调多维度（校准、效率）标准化评测。SO-Arena 的"能力光谱"概念承接这一传统，但把任务统一到"给定证据与候选选项的决策"框架下。
- **评测器可靠性**：LLM-as-a-judge 的位置偏差/冗长偏差（MT-Bench & Chatbot Arena）、RewardBench / JudgeBench / VerifyBench 对奖励模型与验证器的评测。这条线提出了"审查评测者本身"的视角，SO-Arena 把它推广到通用决策模型：选项顺序不就是决策模型版的"位置偏差"吗？
- **Agent 环境评测**：Mind2Web（动作预测）、WebArena（可复现网页环境）、τ-bench（策略约束的工具交互）、VerifierBench（可执行检查器生成）。SO-Arena 把决策模型放进两种角色：**策略**（从动作菜单里选每一步）与**验证者**（判断录制的执行轨迹是否达成目标）。

一句话定位：**SO-Arena 不是又一个"更大的决策题库"，而是第一个把"能力光谱"与"决策可靠性"作为互补双维度系统化落地的基准。**

## 三、问题定义：能力 + 可靠性的形式化

### 3.1 能力分 C：域等权、聚焦最难层

能力打分有两个设计决定。第一，**以原始任务为计分单位、11 个领域等权**——防止大领域（如 500 题的 Safety）淹没小领域（如 200 题的 Math）。第二，**每个领域只取最难层计入榜单**：有分层的 9 个领域取其 hardest 层（Math 特殊，取 hard + very hard 两层），2 个无分层领域取全部任务。公式为：

C(m) = 100 × (1/D) Σ_{d=1}^{D} (1/|T_d|) Σ_{i∈T_d} c_i(m)

其中 D 是领域数，T_d 是领域 d 的最难任务集，c_i(m) ∈ [0,1] 是模型 m 在任务 i 上的得分（相邻等级部分给分等规则见附录）。聚焦上层的理由很直接：难题上才拉得开模型差距，easy 题大家都是 90+，没有区分度。

### 3.2 可靠性分 R：两个受控实验的几何平均

可靠性被拆成两个可独立测量的性质：

**（1）选项重排序稳定性 S**。把每道题按原始顺序跑一遍，再按 12 种重排各跑一遍，共 13 次；按选项**内容**（而非位置）对齐答案，统计保持原答案的比例 A(m)。关键在校准：随机乱选也会有一定的"假装一致"率 p_e = 1/K_i（K_i 选项数），所以做机会校正：

S(m) = (A(m) − p_e) / (1 − p_e)

随机水平 → 0，完全一致 → 1。注意 **S 测的是一致性，不是正确性**——错也错得稳定，S 照样高。

**（2）缺失正确选项识别力 N**。把每道题出现两次：一次原样，一次抽掉正确选项。模型对"选项集合里不含正确答案"这件事给出概率 p_null（由 1 − p_inc 推出，p_inc 是"至少有一个正确选项被包含"的估计概率）。用 p_null 做 ROC 分类器预测"哪一份拷贝缺了正确答案"，然后：

N(m) = 2·AUC(m) − 1

随机水平 0.5 AUC → N = 0，完美识别 → N = 1。直觉：这是在测模型"知道自己不知道"的能力——当四个选项全错时，是硬着头皮选一个，还是察觉异样？

**（3）合成 R**。可靠 = 重排下稳定 + 缺失时敏感，缺一不可。所以取几何平均，且任何一项不高于机会水平就一票否决归零：

R(m) = √(S(m)·N(m))，当 S > 0 且 N > 0；否则 R = 0。

几何平均（而非算术平均）的含义是惩罚短板：S = 0.95、N = 0.1 的模型 R ≈ 0.31，而不是算术平均的 0.52——一个只会硬选、从不察觉无解的模型，不能靠"选得稳"混进可靠行列。

### 3.3 为什么这构成"问题定义"的抽象化

论文把"评测一个决策模型"抽象为：给定模型 m，输出二维坐标 (C(m), R(m)) ∈ [0,100] × [0,1]，其中 C 刻画"会多少（尤其在难处）"，R 刻画"信不信得过"。这个抽象的锋利之处在于：**R 不是从 C 推导出来的**——后面会看到，实证结果证明二者排名确实解耦，这个独立维度设立得有道理。

## 四、问题解法：SO-Arena 怎么建

### 4.1 任务构建：2919 个任务从哪来

**来源**：40 个公开数据集/基准/环境。代表性来源：GoEmotions（情绪理解）、MATH500（数学）、GPQA Diamond（科学推理）、Mind2Web（网页交互）、BFCL 与 ToolSandbox（工具使用）、BrowseComp-Plus（搜索完成检查）、VirtualHome（家庭活动轨迹）。

**质检**：保留源标签为参考答案 → 人工 + LLM 双重审查 → 剔除参考存疑项。每个任务记录来源、版本、原始标识；参考标签与模型可见输入严格分离（防泄漏）；模型衍生的参考在元数据里显式标记（Safety 域 500 条参考中 100 条为模型衍生，均被标记）。

**结构**：11 个领域归入 5 大能力族——语义理解（500）、知识与推理（800）、安全与策略合规（500）、证据评估（500）、Agent 任务完成（619）。总计 **2,300 个静态任务 + 619 个环境任务 = 2,919**。

### 4.2 难度分层：域内相对、标准各异

9 个领域有分层（easy/medium/hard，Math 额外有 very hard）。分层标准**因域制宜**：

- **Math**（200 题，50/50/70 + 30 very hard）：按计算步数（GSM8K-Platinum）或源难度级（MATH500）；very hard 层是 13 道 AIME 2025 + 17 道 AIME 2026。
- **Intent & Routing**（300 题，100/100/100）：easy 判单句意图，medium 要跨完整对话追踪恰好两个客户目标，hard 要判断领域本体的哪些组件适用。
- **Task Completion Verification**（200 题，91/89/20）：easy 查当前状态，medium 整合有界证据集，hard 必须检查执行历史。
- **Code Understanding**（200 题）：用代码长度/分支数的标准化分位分层，参考标签由沙盒重执行 + 暴力对拍（数千随机输入对比独立暴力实现）确立。
- 情感理解和知识常识两个域因"难度缺少系统性变化空间"而不分层。

开放数学题没有选项怎么办？**用模型自己的错误造干扰项**：600 个干扰项中 350 个来自 Qwen3.5-4B-Base 无思考采样 16 次（每题）的错误答案，22 个来自解题中间结果，228 个是规则构造的近似值（如差一位数字）。这保证了干扰项"像真的错"而不是显然的陪跑。

### 4.3 沙盒交互任务：决策模型当 Actor

619 个环境任务分两类：

- **网页交互（337）**：100 个 Mind2Web 单步（判断给定动作是否推进目标 / 从同页四个控件中选最优）+ 237 个 BreakingWeb 多步任务（medium 137 / hard 100）。多步任务里模型对"操作哪个实体、填什么精确值、何时停止"逐一决策；参考路线由外部 LLM 或人工给出并经重放验证可达成功，替代动作顺序与无害绕路也接受。hard 层门槛：至少 5 个计分决策、或至少 3 个目标未在指令中点名的实体选择，且必须包含"从更早页面回忆取值 / 从 60+ 选项菜单中选择 / 推断多个实体"之一。
- **工具使用（282）**：204 个 BFCL 请求 + 78 个 ToolSandbox 场景。BFCL/ToolSandbox 模拟器执行每个被选动作并返回观测，episode 按各自原生检查器计分（ToolSandbox 做了两处适配：去掉措辞检查、达成全部目标状态且无 minefield 违规即记满分）。每个 episode 有独立预算（hard BFCL：96 次决策、12 次工具调用），超限照常计分（通常失败）。

**最精巧的设计藏在 Task Completion Verification 的 hard 层**：VirtualHome 任务先成功执行一个基础任务，再追加一段可执行的"审计后缀"（audit suffix）——改变电器状态、移走两个目标物体、再恢复零个/一个/两个。于是轨迹可以在"操作电器时物体放错位置、但最终全部归位"——最终目标状态相同、历史却不同。模型要判断三个条件（C1：每次开关电器前摆放是否合规；C2：第一次关门动作前是否合规；C3：最终状态是否达标），从四个三比特剖面中选一个，每个干扰项恰好翻转一个比特。**每条被评测轨迹都配有经验证的反事实轨迹：最终目标状态相同、C1/C2 值不同**——确保只看终态必然答错，必须读历史。

### 4.4 可靠性测量：两种受控干预

对应第三章的形式化：选项顺序测试（原始 + 12 种重排，按内容对齐，939 题）；缺失感知测试（原样 + 抽掉正确选项各一份，用 p_null 做 ROC，597 题）。两个测试都是**受控实验**——只改选项集合这一件事，输入其他部分与能力评测完全相同，因此测到的差异只能归因于选项集合操纵。这与从正确率"间接推断"可靠性有方法论上的根本区别。

| Jeva-4B | 0.46 | 51.6 | 12 |
| SII-4B | 0.36 | 48.0 | 16 |
| Laya | 0.07 | 30.9 | 18 |

读表三个要点：

1. **能力第一 ≠ 可靠性第一**：并列能力冠军的 GLiDE，可靠性 0.78 只排第 7；可靠性冠军 JevAny-27B（0.84），能力只排第 8（58.4 分）。摘要里那句"the best-performing System One model ranks only seventh in reliability"说的就是 GLiDE。
2. **S 与 N 的分布截然不同**：14/18 模型 S > 0.8（0.83–0.94 区间，其余四个 Laya 0.35、SII-4B/Kev-4B/OpenAI Decisions 0.68–0.72）——重排稳定性是"普遍做得还行"的；而 N 从接近随机（Laya 0.01）到约 0.8，**方差巨大**。规模有帮助但非充分：同家族大版本 N 更高，但一些 4B 的 N 超过部分 9B/27B。
3. **错答处不稳**：把重排翻转率按原始答案对错分开统计——答错的题选项翻转率中位数 **25.7%**，答对的只有 **4.3%**。不稳集中在模型本来就心虚的地方。

进一步的成分分析（图 8）：S 随能力上升、多数模型贴趋势线（90% 带半宽仅 0.07）；N 与能力只是松散相关（半宽 0.18）——Kev-27B、Jev API 1.14、JevAny-27B 三者的 N **每一个都超过**四个能力最强的 System One 模型（GLiDE、KnowLine-31B、Sieve-31B-v3、Decider-27B），bootstrap 95% 区间在全部 12 个配对上大于零。结论：**能力分能告诉你 S 大概如何，但几乎不告诉你 N 如何——缺失识别必须直接测**。

### 5.5 哪里追得上 System Two，什么能缩小差距

把 11 个领域按"与 GPT-6 Luna 的差距"（medium+hard 层，2,061 任务）分三类：

**第一类：直接语义判断——已经打平甚至反超**。Knowledge & Commonsense（GLiDE +5.0）、Sentiment & Emotion（+4.8）、Retrieval & Reranking（−5.8，置信区间跨零）。升级骨干（+3.4~+4.4）和思考（−2.2~+3.0）都没什么增益——这类任务单次直觉就够。

**第二类：细粒度落地决策——大骨干能追到 4 分内**。Intent & Routing（GLiDE +0.1）、Safety（+4.0）、Task Completion Verification（+0.9）、Tool & API Use（−3.6）、Web Interaction（+3.1）。但 4B 的 StartLux Instant 落后 Luna 至多 28.8 分（Web）。**骨干升级是主要驱动力**：同家族从 Qwen3.5 小模型换到 Qwen3.8-27B 骨干，Tool & API Use **+25.6**、Web **+23.9**、Task Completion Verif. **+17.4**、Safety **+16.2**——远超思考带来的 +1.8~+7.3。

**第三类：多步推导——还是打不过**。Math（GLiDE −26.7）、Scientific Reasoning（−21.3）、Code Understanding（−25.7）。这里**思考是主要驱动力**：StartLux Auto 从不思考到永远思考，Math 从 **50.8 → 92.5**（+41.7，直逼 Luna 的 100），Scientific Reasoning +12.0、Code +5.7。这与"To CoT or not to CoT?"的发现（思维链主要帮数学与符号推理）一致。

### 5.6 其他值得记录的实证细节

- **拒答与零分**：OpenAI Decisions 拒答了 4 个静态任务、12 个工具 episode、6 个网页精确取值步（如患者门户页面含诊断与免疫记录时拒选就诊原因），拒答计零分、路线进度停在首个错误决策处（例：3/17 = 17.65% 进度）。
- **上下文窗口**：30 个网页任务超出 Laya 的 8,192 token 窗口，不截断、按窗口规则记零分。
- **run 间一致性**：能力跑分与延迟/可靠性跑分是独立 run，939 题原始顺序上每模型 907–938 题给分一致（StartLux Auto 因思考采样只一致 875 题）。
- **难度衰减**：性能随难度层下降，agent 类领域衰减最陡（如 Jev API 的 Tools 从 easy 88 掉到 hard 20）。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链：为什么这套设计能"看见"别人看不见的东西

SO-Arena 的贡献不是"把分数提高了"，而是**把被聚合精度掩盖的现象变成了可测量的对象**。拆开这条机制链：

**方法差异**：验证参考标签（模型可见证据支撑）+ 域内难度分层 + 沙盒交互 + 两类受控选项干预（重排/抽答）。

**机制变化**：传统准确率把"会做"与"做得稳"压进一个数字。SO-Arena 用受控干预把决策一致性与缺失识别力**分离出来直接测量**——重排测试只改顺序，缺失测试只删正确选项，其他一切不变，因果干净。同时难度分层 + 域内相对标准让"能力光谱"有了分辨率；audit-suffix 反事实轨迹让"读历史"从口号变成硬约束（不读历史必然答错三比特剖面题）。

**证据链**（论文内证据）：能力与可靠性排名解耦（GLiDE 能力第 1 / 可靠性第 7；JevAny-27B 可靠性第 1 / 能力第 8）；N 与能力仅弱相关（12 个配对全部显著，见 5.3）；错答处翻转率 25.7% vs 正答 4.3%（不稳有心虚的结构性根源）；三域类别 × 两增益源（骨干 vs 思考）的 2×3 交叉验证了"增益是域依赖的"。

### 6.2 相关工作检索与对照：外部证据是否支持这些发现

我用 WebSearch 检索了决策模型评测与一致性评测的交叉证据，按证据强度排列：

**【强·直接交叉验证】Jeva 论文（2610.18773，NUS 同组）**：从第一性原理构建的决策架构 Jeva 在 BANKING77 空值检测上 AUROC 98.66%（对照 KEV-BF16 93.61%），选项重排决策翻转为零、平均总变差 3.17×10⁻⁸——而 Jev-1.13.0 在 17% 的示例上翻转。这条外部证据**证实了 SO-Arena 可靠性维度的"可改善性"**：N 和 S 低不是品类的宿命，架构级设计（共享编码器 + 轻量决策模块 + 显式覆盖率估计）可以把两者都做上去。注意 SO-Arena 评测的是 Jeva-4B（NUS 同组作品，能力 51.6、R=0.46），并未评测新架构 Jeva——侧面说明评测与被测生态保持了一定独立性。

**【强·独立基准】System1-Arena（2610.21244）**：92k 题、138 闭环环境、30 模型的独立评测，发现大决策模型（Decision-2.0-Vega-27B 73.0%、Jev 72.6%）在非 agent 任务上已追平快 LLM（GPT-6 Luna 71.2%），但在长程任务上小 System One 模型成功率至多 3.1%。这与 SO-Arena 的域谱系发现（语义判断打平、多步推导落后）**方向一致、相互印证**；System1-Arena 用 Brier 分数测校准，SO-Arena 用受控干预测一致性与缺失识别——两者互补而非重复。

**【强·方法论文献】选项顺序敏感性是 LLM 的广泛现象**：MT-Bench/Chatbot Arena（位置偏差与 swap 缓解）、MMBench 的 CircularEval（全排列下都答对才记分）、"Large Language Models Are Not Robust Multiple Choice Selectors"的 token 偏差、PriDe 推理时去偏。SO-Arena 的增量在于**把这种偏差从"评测污染源"翻转成"被测属性"**——不再想办法消除它来保护准确率，而是给它一个独立的分数让生态正视它。

**【中·行业榜单】** systemonemodels.org 汇总的第三方榜单（AA v2.1）里 Jev 1.14 排 9/19（66.2）、pplx-decider 6/19——与 SO-Arena 中"闭源决策 API 不占优"（Jev API 60.4、OpenAI Decisions 53.6，均低于最强开源）的观察大体相容，但各家榜单任务构成差异大，仅作弱对照。

**【弱·媒体转述】** AI Weekly 等媒体报道照转了论文数字（GLiDE/KnowLine 70.2、可靠性第 7 等），无独立复现——不构成额外证据。

### 6.3 综合判断

把内外证据合起来：**SO-Arena 之所以能做出"能力-可靠性解耦"这个核心发现，根源在于它把评测从"单变量观察"升级成了"受控实验设计"**。选项集合是一个可以精确操纵的干预变量，重排和抽答就是两个 A/B 实验；域内难度分层是另一个受控变量（同域内只变难度）；audit suffix 是第三个（同终态、异历史）。三个受控操纵各自隔离出一种被聚合分数掩埋的能力面。而外部证据（Jeva 架构可达高 N/S、System1-Arena 独立复现域谱系）说明这些测量不是噪声，也不是本基准的 artifact——它们测的是真实且可改善的性质。保留的怀疑：域内难度不跨域校准， leaderboard 各域"最难层"任务量不均（Task Completion Verification 的 hardest 层只有 20 题，bootstrap 区间会很宽），跨域等权平均仍有解释上的自由度；可靠性测试集（939/597 题）相对小，且 8 处修正参考属于可靠性集——作者已披露并重跑，但使用者在引用单模型 R 值时应记住这个精度界限。

## 七、必要知识反推：读懂这篇论文需要什么

### 7.1 第一层：基础概念（本科水平）

- **快慢双系统**：Kahneman 框架及其在 LLM 中的映射（推理模型 vs 单次前向决策模型）。
- **概率分布与 softmax 读出**：为什么"输出选项分布"可以是 LLM logit 的一种读出方式，也可以是外接决策头。
- **ROC 与 AUC**：N = 2·AUC − 1 的全部数学前提——分类器排序能力的一个标量度量，0.5 为随机。
- **机会校正**：S 公式中 (A − p_e)/(1 − p_e) 是经典的一致性校正（与 Cohen's kappa 同族思想）。
- **几何平均 vs 算术平均**：为什么几何平均惩罚短板。

### 7.2 第二层：领域方法（研究生水平）

- **决策接口三类型**：choice / noul（是非）/ score（有序等级），以及有序等级"相邻部分给分"的计分细节。
- **选项顺序偏差文献链**：位置偏差 → swap 缓解 → CircularEval → PriDe；决策模型语境下的 permutation invariance。
- **选择性预测与校准**：p_null/覆盖率、selective classification（误差-覆盖权衡）、校准与精度的区分——N 的概念祖先。
- **基准构建方法论**：来源可溯、标签人工验证、参考与输入分离、模型衍生参考标记、难度域内相对化。
- **Agent 评测工具箱**：Mind2Web/WebArena/τ-bench/BFCL/ToolSandbox 各测什么，replay 验证参考路线的做法。

### 7.3 第三层：前沿认知（研究员水平）

- **决策模型生态地图**：Jev API / OpenAI Decisions / GLiDE / KnowLine / JevAny / Kev / Decider / Clef / StartLux / Sieve / Laya……谁开源谁闭源、什么骨干（Qwen3.5 vs Qwen3.8-27B 的世代差）。
- **能力-可靠性解耦**：本文核心实证发现，及其对采购/上线决策模型的直接含义。
- **System1/2 边界的域谱系**：直接语义判断（1 够用）→ 细粒度落地决策（骨干决定）→ 多步推导（思考决定）——"哪些决策可以交给 System 1"第一次有了分层答案。
- **评测即受控实验**：从观察式榜单到干预式测量的方法论跃迁。

### 7.4 融合节点

三层知识的融合点在**"把评测问题翻译成受控实验设计"**这一动作上：第一层给你分布与度量工具（AUC、机会校正、几何平均），第二层给你干预手段（重排、抽答、分层、反事实轨迹），第三层给你生态地图与已知发现。三者在"R = √(S·N)"这个公式里汇合——它要求你同时懂：AUC 怎么算（一层）、为什么缺失识别是决策模型的关键性质（二层）、以及当前生态在这上面差到什么程度（N 从随机到 0.8，三层）。

## 八、通用性灵感

### 8.1 灵感一：给"可靠"独立打分，别让它住在"准确"的屋檐下

**核心思想**：任何系统的"输出质量"至少有两个正交轴——做得对（能力）与做得稳/知道自己不知道（可靠性）——聚合指标会掩埋第二个轴，应拆成独立分数。
**论文证据**：能力第 1 的 GLiDE 可靠性第 7；N 与能力仅弱相关（12 配对全显著）；R = √(S·N) 几何平均惩罚短板。
**推广场景**：(1) RAG 系统评测把"检索准确率"与"无依据时的拒答率"分列；(2) 自动驾驶规划器评测把"到达率"与"同类场景决策方差"分列；(3) 医疗辅助诊断把"诊断符合率"与"不确定病例转诊敏感度"分列；(4) 代码补全把"采纳率"与"同上下文多次生成的稳定性"分列；(5) 内容审核把"判定准确率"与"文案重写后判定一致性"分列。

### 8.2 灵感二：受控干预是测量一致性的黄金手段

**核心思想**：想测"输出是否依赖无关表面形式"，就只改表面形式、冻结其他一切——差异即归因。
**论文证据**：12 种重排、按选项内容对齐、随机校准为 0 的 S；只删正确选项、用 p_null 做 ROC 的 N；错答处翻转率 25.7% vs 正答 4.3%。
**推广场景**：(1) LLM 裁判评测中系统性 swap 候选顺序测位置偏差；(2) 简历筛选系统改名字/性别字段测歧视性不一致；(3) 搜索排序系统改文档 URL 与排版测排序稳定性；(4) 数据管道对同一条记录换字段顺序测解析一致性；(5) 风控模型改申请表格式（不改变实质信息）测评分稳定性。

### 8.3 灵感三：用模型自己的错误造干扰项

**核心思想**：好的测试项需要"像真错"的干扰项，而模型自身的系统性错误是最逼真的干扰项来源。
**论文证据**：Math 600 个干扰项中 350 个来自 Qwen3.5-4B-Base 无思考采样 16 次的真实错误、22 个来自解题中间结果、228 个规则近似；并排除"仅凭选项即可识别正确答案"的题。
**推广场景**：(1) 编程测验用学生历史错误答案构造选择题干扰项；(2) 医学考试的鉴别诊断干扰项取自辅助诊断模型的高频误诊；(3) 面试题库用初筛候选人的真实错误答案升级题目难度梯度；(4) 对抗训练中用被测模型自己的错误模式生成负样本；(5) 翻译质量评估用 MT 系统典型错误类型构造评分锚点。

### 8.4 灵感四：同终态、异历史——验证者必须读历史

**核心思想**：判断"过程是否合规"时，最终状态相同不等于过程相同；构造"最终状态一致、中间历史不同"的配对轨迹（配反事实见证），逼出真正的过程审查能力。
**论文证据**：VirtualHome audit suffix 追加序列使轨迹"终态合规但中途违规"，三条件 C1/C2/C3 四剖面选择题，每条评测轨迹配经验证的反事实（同终态、不同 C1/C2）。
**推广场景**：(1) 合规审计测试集构造"报表最终平衡但科目路径违规"的账目对；(2) 机器人安全评测生成"到达目标但途中碰撞"的轨迹对；(3) agent 评测中"任务完成但用了未授权工具"的轨迹对；(4) 学生实验报告评分——结果正确但数据造假的历史痕迹；(5) API 编排系统验证"响应正确但绕过了缓存/鉴权步骤"。

### 8.5 灵感五：难度域内相对化，别跨域校准

**核心思想**："难"没有全局标尺——分层只在领域内部定义并使用，跨域只比"各自最难层的相对表现"，避免伪可比性。
**论文证据**：9 域各有分层标准（步数/源等级/本体复杂度/状态检查深度），论文明言"Tiers are not calibrated across domains"；榜单取各域最难层等权平均。
**推广场景**：(1) 多学科考试报告"每科年级内百分位"而非跨科总分；(2) 多游戏 agent 评测按"各游戏最难关卡"取成绩；(3) 医院科室质控指标按科室基线分层；(4) 公司多产品线 KPI 按业务线定义难度档；(5) 安全评测按攻击面类型内部分层（钓鱼/注入/提权各自分 easy–hard）。

### 8.6 灵感六：能力谱系思维——"能不能"取决于"哪一域 + 什么在驱动"

**核心思想**：不要问"System One 能不能取代 System Two"，要问在哪个域类别差距多大、以及骨干规模与推理思考哪个才是该域的有效增益杠杆。
**论文证据**：三域类别（语义判断打平 / 落地决策骨干驱动 +25.6 / 多步推导思考驱动 Math +41.7）——同一批模型，增益源完全不同。
**推广场景**：(1) 企业模型选型按任务域谱系决定"小模型直出 / 大骨干 / 加思考"三档路由；(2) 模型训练路线图按域谱系分配算力（骨干升级 vs 推理数据）；(3) 边缘设备部署白名单（只部署语义判断域）；(4) 混合推理系统的自动切换阈值按域设定；(5) 采购谈判时要求供应商提供分域能力矩阵而非单一聚合分。

**一句话收束**：SO-Arena 给"决策模型"这个新品类立了第一块双维标尺——能力上，开源 System One 在语义判断域已与 GPT-6 平起平坐、快数十倍，但在多步推导域仍差 20+ 分；可靠性上，它证明了"准确率榜单会撒谎"：最准的模型可靠性只排第 7，而"发现选项里没有正确答案"这件事，能力分几乎预测不了。以后看决策模型的 leaderboard，记得问一句：R 是多少？
