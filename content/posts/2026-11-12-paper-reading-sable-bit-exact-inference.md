## 一、论文背景

### 1.1 你调用的 API 背后发生了什么

想象一个场景：你通过第三方平台付费调用某顶级大模型。平台承诺用的是完整精度的模型，但你怎么知道？它可能悄悄换成了量化更狠的便宜模型，可能在回答被截断时假装回答完了，也可能在采样时使用了对你不利的随机数。**现有 API 交互中，客户端收到的只有文字，没有任何可验证的证据**。

这就是"可验证推理"（verifiable inference）要解决的问题：让服务器附带密码学证明，证明输出 y 确实等于 F(W, x, r)——其中 x 是 prompt、r 是客户端指定的采样种子、W 是由公开承诺 CW 绑定的模型权重。在所有方案中（可信硬件、多方重执行、统计指纹、密码学证明），只有密码学证明**仅依赖密码学假设、任何人任何时候都能验证、且不需要持有权重**。

### 1.2 为什么"证明推理"比想象中难得多

论文开门见山地指出三大障碍，每一个都值得展开：

**障碍一：被证明的必须是精确函数。** 密码学证明建立的是整数或域元素之间的关系。但浮点推理根本不是"输入的函数"——换一个 GPU kernel、换一个 batch 形状、换一个归约顺序，结果都会变（论文引用了 Thinking Machines Lab 2025 年关于 LLM 推理非确定性的研究）。更致命的是，一个 argmax 或采样决策的改变会让后续所有 token 全变。所以必须先定义一个精确的整数函数 F，并让服务器真的运行这个函数。对浮点计算做"近似检查"（如 TOPLOC）回答的是另一个问题。

**障碍二：小素域与溢出（wrap）的矛盾。** 为了让证明器快，密码学界近年流行 31 位小素域（如 KoalaBear、Mersenne-31）——一个域元素正好塞进一个机器字，不需要多精度运算。但 Transformer 的中间量相对 p≈2³¹ 是巨大的：2¹⁵ 个 8 位整数乘积的点积达到 2²⁹，覆盖 2²⁰ 个 key 的 softmax 分母达到 2³⁰。如果一个关系式在 mod p 下成立但在整数上不成立，作弊的证明器就能"改变计算"仍通过验证。**每一条约束都必须配上界，保证两边都低于 p**——这是本文标题中"wrap-free"的含义。

**障碍三：规模。** 一条 16,384 token 的序列过 Qwen2.5-32B，计算迹约有 6×10¹¹ 个待承诺域元素和 7×10¹¹ 次查表。这个量级塞不进任何 GPU 内存或主机内存；而且查表次数超过了 p，LogUp 多重集论证会失效，必须分区。

### 1.3 初学者需要的密码学概念阶梯

论文默认读者熟悉交互式证明系统。这里用最短路径补齐概念链：

- **有限域 Fp**：所有运算在 mod p 下进行的世界，p=2³¹-2²⁴+1（KoalaBear 素数）。加乘都有逆元，但"大小"失去意义——只有"模 p 相等"。
- **承诺（commitment）**：像把数据锁进信封。Merkle 树把大数据哈希成一个根，之后可以打开任意位置证明其值，但无法篡改。绑定性质使作弊者不能对不同内容给出同一信封。
- **sumcheck 协议（LFKN 1992）**：证明"一个多元多项式在 {0,1}ⁿ 上求和等于 c"。每轮证明器发一个单变量多项式，验证器抽查后给随机挑战，n 轮后归约到单点求值。作弊被抓住的概率每轮最多 d/|F|。这是所有现代 SNARK 的发动机。
- **zerocheck**：证明某多项式表达式在所有 {0,1}ⁿ 点上为零——通过给 sumcheck 加权 eq(τ,x) 实现。
- **GKR 协议**：对深度电路做逐层归约的交互证明，证明器代价与电路规模线性相关。
- **lookup argument 与 LogUp**：Transformer 里到处是非算术操作（exp、SiLU、取整）。Plookup 开创了"查表证明"：证明某值确实在表中。LogUp（Haböck 2022）用"对数导数"把乘积多重集相等转化为分式和相等——证明 Σᵢ 1/(Z-aᵢ) = Σ_v m(v)/(Z-v)，在随机点 Z 处检查即可。它避免了巨型乘积，天然适合并行。
- **可靠性（soundness）**：作弊证明器让验证器接受假命题的概率上界。本文达到 2⁻¹⁰³（含 30 位工作量证明），即千分之一×十亿分之一×十亿分之一的量级。
- **Fiat–Shamir 变换**：把交互式协议变成非交互证明——用随机预言机（哈希函数）的输出代替验证器的随机挑战。证明器把历史消息全部哈希来派生挑战，使挑战无法被预测和操纵。
- **交互式预言机证明（IOP）与 round-by-round soundness**：现代 SNARK 的标准分析框架，逐轮界定"作弊被抓住"的逃逸概率，Fiat–Shamir 安全性在此基础上建立。

### 1.4 研究动机的空白

此前最强的系统 zkLLM（2024）证明 13B 模型一次推理需约 15 分钟，且它工作在大素域（BLS12-381）、对非线性函数做近似、不固定被服务函数的整数语义。距离"证明生产级模型实际执行的推理"还有数量级差距。Sable 的目标就是把这条鸿沟填上。

## 二、论文定位和关联工作

### 2.1 可验证 ML 推理的谱系

**通用 SNARK 编译路线。** zkCNN（2021）最早把 sumcheck/GKR 用于卷积网络；zkGPT（USENIX Security 2025）针对 GPT-2 规模优化约束布局，在 CPU 上约 22 秒证明 GPT-2；zkML 与 ezkl 把模型编译进 Halo2 电路。这条路线通用但扩展到 30B 级模型代价过大。

**zkLLM（CCS 2024）。** 与本文最直接的对比对象。它组合了张量运算的 sumcheck、非算术运算的 tlookup 查表论证、以及专门的注意力协议 zkAttn，在 BLS12-381 标量域上工作，用配对承诺输出 <200kB 的短证明，A100 上约 13 分钟证明 LLaMa-2-13B 的 2048 token 前向。关键区别：zkLLM 是零知识的、证明的是定点近似，且查表（tlookup）未处理"查表次数超过 p"的问题；Sable 非零知识、逐位固定语义、显式处理 wrap 与 chunk。

**FlashProve（Anthropic，2026 年 11 月，同期工作）。** 与 Sable 几乎同时发布的重量级竞争者：证明 Llama 4 Maverick（400.7B 参数 MoE，每 token 激活 16.15B），基于 Goldilocks 64 位域 + IOP + Reed-Solomon + BLAKE2b，单 H100 在 1024 token 窗口上以约 111 token/s 批量（批 24）证明，证明约 18.8 MB，零知识，协议在 Lean 中机器验证。论文对它与 Sable 做了细致的差异分析（见 2.3 节）。

**非密码学路线。** GPU 可信执行环境（硬件信任假设）、裁判式委托（需要诚实方持权重重执行）、TOPLOC（ICML 2025，对浮点激活特征做局部敏感哈希的统计验证）。Sable 的声明是精确的且验证器不需要权重，代价是高得多的证明成本。

### 2.2 底层工具谱系

- **sumcheck/GKR 效率**：Thaler 2013 给出矩阵积的线性时间证明器；Libra（2019）使一般电路 GKR 线性时间并加零知识；Spartan、HyperPlonk 围绕布尔超立方上的 zerocheck 构建 SNARK。小域 sumcheck 证明器算法（Bagad-Domb-Thaler 2024、Dao 等 2026）让大部分工作留在基域。
- **查表论证**：Plookup（2020）→ LogUp（2022，对数导数）→ Papini-Haböck 2023（用 GKR 证明 LogUp 的分式树，消除对查表挑战的依赖承诺）→ Lasso/Jolt（结构化表 + 虚拟机）。
- **哈希多项式承诺**：FRI（2018）与 STARK；BaseFold（CRYPTO 2024）在可折叠码上做折叠式承诺；WHIR 降低验证查询成本；Ligero/Brakedown 的线性码承诺。Sable 用 BaseFold over Reed-Solomon（乘法子群上、码率 1/2），按"混合高度 Merkle 树"组织不同长度列。
- **小域趋势**：STARK 证明器从 64 位域迁到 31 位域（Plonky3 的 KoalaBear、Circle STARK 的 Mersenne-31），Binius 走二进塔。挑战必须来自扩域（这里 Fp⁴/Fp⁸）以保 soundness。
- **整数量化推理**：I-BERT、LLM.int8()、SmoothQuant、QuaRot/SpinQuant。FO 直接借用 QuaRot 的随机正交旋转抑制离群值、动态行指数、每列权重指数。

### 2.3 定位对比表

**定位结论**：Sable 是"开放权重 + 审计者证明"路线的首个生产规模实例——用非零知识换取小域速度与完整语义（整段回复、停止规则、温度采样），把验证器哈希量压到可递归的 4.2M 次 BLAKE3 压缩，明确以"递归 + 零知识外层"为终态。它与 FlashProve 构成了同一问题的两种取舍：Sable 证明更长上下文的完整回复且任何人都可重算其权重承诺；FlashProve 隐藏权重、证明更小、但每证明只查一个 token 且上下文 1024。

## 三、问题定义

### 3.1 从具体场景到抽象问题

**具体问题**：如何让计算方（服务器）以密码学方式说服任意第三方——它输出的整段回复 y，确实由承诺 CW 绑定的 32B 级量化 Transformer 权重 W、从 prompt x、按客户端 nonce 决定的种子 r 逐位计算得出，包括每一个取整、归一化、softmax 和采样决策？

论文的核心洞察是把"验证一段推理"分解为三个独立的抽象子问题，每个都能被已有密码学原语精确表达：

1. **函数固定问题** → 定义整数函数 FO：把 Transformer 的每一步都定义为整数运算与查表，无浮点、无数据依赖循环，对给定输入输出唯一（论文证明了确定性定理 5.1）。
2. **关系证明问题** → 构造 wrap-free 约束系统：FO 的每个操作对应一个 gadget（承诺见证列 + 多项式约束 + 查表），每条约束作为整数恒等式双方绝对值都低于 p，于是"Fp 中成立 ⟺ 整数上成立"（定理 6.1），且每个 gadget 恰有一个满足约束的输出（确定性，定理 6.2）——作弊者无法在不被查出的情况下改变任何中间值。
3. **规模问题** → 流式证明协议：证明器对模型做两遍扫描（承诺遍 + 证明遍），逐层重建见证，任何时刻只驻留一层的见证；查表按 ≤2³⁰ 分 chunk 保持 LogUp 在素域上的可靠性。

**形式化定义**：声明 st = (CW, policy, x, y, nc)。关系 R 包含 (st, W) 当且仅当 CW 承诺 W、y 是 FO(W,·,r) 从 x 的自回归输出、且 y 满足停止规则（前 G-1 个 token 非停止符，第 G 个是停止符或达到最大长度 Gmax）。停止规则纳入关系是精妙的——否则任何有效输出的前缀都合法，服务器可以随意截断回答。种子 r=SHA256(seed‖nc‖CW‖SHA256(x)‖policy) 由客户端 nonce 锁定，服务器无法选择随机性。由于 FO 确定且因果，全部 S=P+G-1 个位置可在一次 teacher-forced 前向中证明。

### 3.2 这个抽象的精妙之处

- "逐位精确"看似苛刻，实则是唯一能被证明的定义：浮点推理连"相同的输入"都不能保证相同的输出。一旦接受这一点，问题就从模糊的"验证推理"变成清晰的"验证整数函数求值"。
- 三层分解让每层都能独立形式化验证（论文附录给出每个 bound 的证明），也独立地被测试（11.10 节的伪造攻击回归测试）。
- "审计者证明"的诚实定位：不假装能直接给每个客户端返回 135 MiB 证明，而是把"验证器足够便宜以至于可以递归压缩"作为设计目标——这是对 IVC（增量可验证计算）路线的务实贯彻。

## 四、问题解法

### 4.1 FO：把 Transformer 铸造成整数函数（第 5 节）

FO 面向 Qwen2 架构（RMSNorm 预归一化、GQA、RoPE、SiLU 门控 MLP），运行示例 Qwen2.5-32B-Instruct（64 层、d=5120、词表 152,064），并扩展到 Qwen3 的 QK-norm 与 MoE。关键数字格式设计：

| 组件 | 格式 | 要点 |
|---|---|---|
| 残差流 | 24 位整数（A=[-2²³,2²³)，10 个小数位） | SatAdd 饱和加法截断到 A |
| 矩阵乘输入/权重 | 8 位 [-127,127] + 2 的幂指数 | **指数放在归约轴之外**：行指数×列指数，累加器是精确整数，缩放一次移位完成 |
| Q/K/V | 静态每头指数，e^Q_h+e^K_g(h)=E^attn 共享一个全局常数 | 一张指数表服务所有头与层 |
| 非线性 | 查表：τ_exp（10 位）、τ_SiLU（16 位）、τ_recip、RoPE 的 cos/sin | 表条目用双精度正确舍入，边界 10⁻⁴ 内用 60 位算术重算，平台无关 |
| 采样 | θ=0 贪心 argmax；θ>0 逆 CDF，u_t=BLAKE3(r‖t) 低 30 位 | 概率 <2⁻¹³ 模式的 token 不可被采样——这是 FO 的一部分 |

每个原语都配有防溢出的界：线性层精确和至多 2¹⁵ 项×127² <2²⁹；PV 积按 2¹² 个 key 分块使部分和 <2²⁹（任意 2²⁰ 上下文成立）；softmax 分母 2^E·δ 的归一化用带符号指数处理 E∈[-5,14]。**从 BF16 检查点到 FO 的映射是确定性程序**：QuaRot 式随机正交旋转抑制离群值、逐层融合 RMSNorm 增益、1,024 token 校准文本确定静态指数、首位置全词表扫描兜底。Qwen2.5-32B 上该程序 4 分钟跑完，两次运行比特一致。

对 Qwen3 的扩展体现了"组合而非重造"：QK-norm 是现有的 ShiftQ8+NormScale 作用于每头行；MoE 路由用阈值选择论证（平局归小索引）+ 动态多重集匹配槽位与专家，k 个槽的权重对齐后合并成单一下行累加器（<2²⁹·⁶）。**行钳制（row clamps）**处理未训练 token 首位置的极端行指数，不改变任何未钳制行的行为。

### 4.2 wrap-free 约束系统（第 6 节）

设计规则一句话：**每条约束作为 Z 上的恒等式，在满足 gadget 查表的值上，双方绝对值 <p（除带偏置的 ShiftQ8S 外均 <2³⁰·⁹）**。于是域关系与整数关系等价。

所有静态查表进一张 2²⁶ 行、7 列的**带标签表 T**：范围检查 u∈[0,2^k) 只花一次查表（行 (k,u)），无论界多宽；舍入 gadget 的移位相关界来自每个移位值一行。这让"每个界一次查表"成为可能。

代表性 gadget 的巧思（以 ShiftRound 为例）：

- 移位 k 不是证明器自由选择的——SR 查表的第一坐标是定义移位的表达式（公开常数±承诺行指数），查表把整个 regime 绑定到诚实移位上；
- k≥1 时两条查表给出 0≤acc+2^{k-1}-2^k·c<2^k（即 c=⌊acc/2^k⌉）并界住 |2^k c|；k≤0（左移）时关系 c=2^{-k}acc 在域上可能 wrap——**SRA 输入界**（每元素 |acc|≤2^{23+k}）堵住缺口。论文坦率承认这个界是开发中被随机搜索攻击逼出来的（Remark 6.3），并有回归测试。

NormScale 的带符号归一化、Requant8 的最小性见证（选中元素 4a_{j*}≥255s 证明 e 是最小指数）、注意力行最大值的 gather 论证（动态查表集，乘数 μ_j 计数每个 key 行被选次数）、MoE 路由的阈值选择，每个 gadget 都遵循"约束+查表+显式整数界"三件套。注意力分数矩阵按 128×128 平铺、只保留下三角（因果掩码进入 softmax 查表的公开门控输入）。

### 4.3 协议：域、chunk 与单一承诺（第 7 节）

**域（domain）**是协议的原子单位：一组列（committed / virtual / public 三种角色）+ 约束 + 查表。其核心优化是**把所有查表的 LogUp 分式树的叶子层与 zerocheck 合并进单个 sumcheck**（定理 7.1）——省掉每域一个 sumcheck，代价是括号度数升高（最大域度数 8-10）。注意力每个保留 tile 是 2¹⁴ 行的块。

**Chunked LogUp**（定理 7.2）：16K 序列约 7×10¹¹ 次查表 >300p，单一多重数列会让 p 份表外值正负抵消（p/(Z-a)≡0）。按 ≤2³⁰ 查表分 chunk、每 chunk 自己的多重数列、一张对 T 的 GKR 同时证明所有 chunk。元组压缩定理 8.1 给出关键教训：用单挑战的幂压缩 k 元组损失 log₂k 位 soundness——Sable 为每个坐标独立抽 β₁,...,β₈，"免费"省下约 2.6 位。

**单一多线性承诺**：所有张量与权重打包进宽度 2⁵–2²³ 的列（列数而非元素数决定证明大小与验证哈希，宁padding也要宽列），每列 RS 码率 1/2 编码；**混合高度 Merkle 树**让一层的所有尺寸类共享一条打开路径；**按层规约**（per-layer reduction）把全局求值证明所需的"每层见证重建"从 5 次压到 3 次。BaseFold 式折叠在 Fp⁸ 上做混合长度批处理，153 次查询前加 30 位工作量证明。

**两遍结构**：承诺遍逐层前进（存层间残差流于主机），证明遍从采样约束倒推回 embedding，声明（claims）逆向流动并在每层结束时打开该层单元。设备端 Fiat–Shamir 转录本使证明遍无主机往返。

### 4.4 单 GPU 证明器（第 9 节）

| 技术 | 作用 | 实测效果 |
|---|---|---|
| 见证流式重建 | 16K 见证数 TB，只存层边界（每层约 42 ms 重建） | 峰值 GPU 内存 37–72 GiB |
| 按约束程序生成 CUDA 核 | 每域的多项式程序编译成专用核 | 首轮在基域表上跑，第二轮折叠进扩域 |
| 设备驻留转录本 | 每个 BLAKE3 压缩一个 warp | 轮转录步 25.9→8.8 µs |
| CUDA graph 重放 | 中间层证明遍形状相同 | 64 层 1×4K 证明 133→106 s |
| Fp₄ 延迟归约 | 每坐标单次模减 | Fp₄ 乘法 255→371 G/s |
| 小 GKR 轮平铺 | 把 (pair,lookup) 工作项铺满网格 | 每层 GPU 时间 1.01→0.90 s |

### 4.5 面向递归的验证器（第 10 节）

递归成本 = 验证器做的事。四步把验证器 BLAKE3 压缩从 17.8M 降到 4.2M（4.2×）：公共列闭式求值；固定表（T、RoPE）承诺一次；最终打开记录而不哈希（查询之后再无挑战，吸收无意义）；更少更宽的列 + 共享 Merkle 路径（列数 84.8K→32.6K）。BLAKE3 电路本身用同一证明系统实现：G 函数每行 80 列、XOR 查 2¹⁶ 行表、LogUp 内存连线（写 -μ、读 +1），每压缩 2.4–2.8 µs，4.2M 压缩约占主证明 6%——递归第一层定价约为主证明 10%。

## 五、评估指标与实验证据

### 5.1 指标体系

- **主指标：证明时间与开销比**。证明时间是被证明推理本身的多少倍（overhead），以及绝对秒数——直接决定"可验证推理"是否实用。
- **跨系统指标：ps/参数/token**。归一化每参数每 token 的证明耗时（皮秒），可跨模型规模比较。
- **成本指标：美元/证明**。按公开 GPU 价格折算。
- **精度指标：PPL 超出比例、Top-1 一致率、MMLU/GSM8K**。精确性 bought 的精度代价——"the price of exactness is accuracy"。
- **验证指标：证明大小（MiB）、单核验证秒数、验证器 BLAKE3 压缩次数**。
- **安全指标：soundness 误差位数**。
- **消融：Q/K split、精度归因、工程 ablation、FO 未定义频率**。

### 5.2 端到端证明（主结果，单卡 RTX PRO 6000 Blackwell 96GB）

| 系统 | 模型 | GPU | 时间 | ps/pt |
|---|---|---|---|---|
| zkLLM | LLaMa-2-13B, 2,048 tok | A100 40GB | 803 s | 30.2 |

### 5.4 精度：精确性的价格

Qwen2.5-32B（WikiText-2 145 窗×2048 token，296,815 预测；MMLU 14,042 题 5-shot；GSM8K 1,319 题 8-shot）：

| 变体 | PPL 超出 | Top-1 一致率 | MMLU | GSM8K |
|---|---|---|---|---|
| BF16 | — | — | 83.2% | 88.6% |
| FP8 (E4M3) | +0.7% | 95.5% | 83.0% | 88.4% |
| SmoothQuant INT8 | +1.6% | 93.9% | 83.2% | 88.2% |
| **FO** | **+8.3%** | **86.3%** | 81.8% | 88.0% |

FO 与 BF16 的 MMLU 差 1.4 点、GSM8K 差 0.6 点（≤1.6/1.7 点的任务级差距在两个 Qwen3 模型上同样成立：MMLU 1.4/1.6 点、GSM8K 1.7/1.4 点）。精度归因实验（每个变体只放宽一个步骤）：**12 位 Q/K 消除 37% 的 PPL 差距**、一致率升至 88.6%；浮点 softmax、多 4 位的 SiLU、16 位 up 投影都在噪声内（<3%）；校准文本换成 WikiText-2 训练集也无变化。差距的约三分之一追溯到 8 位 Q/K——这正是 Q/K split 的出发点。

### 5.5 Q/K split：免费的精度

Qwen3 的 QK-norm 使每个 KV 组的 e^K_g 有自由度（组内 e^Q_h+e^K_g=E^attn）。把全部余量给 K 会让归一化后的 K 只剩约 2 位有效位。校准程序改为按组最小化舍入噪声 Σ(4e^Q‖K‖²+4e^K‖Q‖²)。**只动校准常数，证明大小与成本零变化**，却消除 Qwen3-30B-A3B 的 53%（46–60）、Qwen3-32B 的 23%（19–26）PPL 差距；MMLU 各提升 2.6/3.0 点（McNemar z=8.9/10.3）。这是全文性价比最高的单点发现。

### 5.6 FO 未定义频率与鲁棒性

345 万真实 token（WikiText-2 全测试集、全部 GSM8K、2,000 条 MMLU）+ 160 条 4,096 token 对抗序列（重复注入短语、随机字节、全词表首位置）上 **FO 未定义 0 次**——诚实际明器不会中途 abort。没有行钳制时 Qwen3 有 7+2 个罕见 token 首位置越界，钳制修复且不改变其他行。

### 5.7 验证与正确性测试

每条证明消息逐一损坏必被拒；换权重、采样不符种子、伪造最终打开（25 消息+9 预言机元素）、伪造 no-wrap 界（wrapped 左移位、过大指数、越界 router 移位）全部被拒；设备转录本与主机转录本产出字节相同证明。BLAKE3 电路也通过两类伪造测试。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**优势一：比 zkLLM 快 40–64 倍（ps/pt）。**

因果链：① 31 位小域使基域元素单机器字、无多精度（zkLLM 的 BLS12-381 标量域 255 位，每次乘法需要大数运算）→ ② 但小域引入 wrap 风险 → ③ Sable 用"每约束显式整数界 + 查表强制范围"把风险转为少量额外查表（每元素 1 次承诺 + 2-3 次查表的开销结构）→ ④ 证明器得以用 GPU 上的 32 位乘法 + Barrett 归约跑满吞吐。〔论文实验支持：表 18 逐约束给出界；表 10 的 Fp₄ 优化 255→371 G/s〕扣除硬件 3.5× 后仍有约 11–18× 的协议级差距。〔这是阅读者推算：论文明言"部分来自硬件"，未单独给出协议归因实验。〕

深层差异还有：zkLLM 的配对承诺换来 200kB 短证明但配对运算昂贵；Sable 的哈希承诺放弃短小换取便宜。**这解释了为什么 Sable 的证明大三个数量级而验证慢一个数量级**——两个系统在"证明大小 vs 证明速度"谱系的两端。

**优势二：开销比"仅"41–50×，低于 FlashProve 的 70–95×（对 vLLM）。**

因果链：① 非零知识 → 无需掩码消息与隐藏承诺的随机填充 → ② 开放权重使 CW 是任何人可重算的普通 Merkle 根，一次承诺服务无限次证明（FlashProve 的隐藏承诺限 688,127 批）→ ③ 整数 8 位矩阵乘可跑在整数张量核上，FO 服务引擎 batch-1 解码与 FP8 打平。〔论文实验支持：表 17 服务对比；表 8 归一化对比〕但这一优势有明确适用边界：闭权重场景不成立（约 1.9×10⁴ 证明后权重可被线性代数恢复）。

**优势三：Q/K split 零成本消除 23–53% PPL 差距。**

因果链：① QK-norm 后 Q、K 都是 8 位 + 指数，E^attn 固定 → ② 误差分析：score=Q·K 的舍入噪声 ∝ 4e^Q‖K‖²+4e^K‖Q‖²（量化步长平方×范数）→ ③ 全给 K 使 K 只剩约 2 位有效位、噪声项被 K 主导 → ④ 按组优化分割最小化总噪声。关键在于这只改变静态校准常数（e^K_g 的选择），E^attn、指数表、所有界、证明大小与成本全部不动。〔论文实验支持：表 14 的 with/without split 对照 + 配对区间〕机制上这与量化文献中"离群值通道主导量化误差"的共识同构——把有限比特预算在乘法两端重新分配，等价于 QuaRot/SpinQuant"用旋转打散离群值"思想在指数维度上的版本。

**优势四：验证器哈希 17.8M→4.2M（4.2×）与证明 360→134.8 MiB。**

因果链：① 递归成本∝验证器每一步操作 → ② "公共列闭式求值"把 O(n) 折叠降为 O(log n)——因果掩码、词表指示子都是结构化比较器 → ③ "查询后无挑战则吸收无意义"的观察使最终打开免哈希 → ④ 列数（而非元素数）决定每查询打开成本 → 宽列 + 混合高度树让一次查询覆盖所有尺寸类。〔论文实验支持：表 3 逐项给出每步降幅〕

### 6.3 综合判断与未决问题

**多研究共同支持的机制**：① 整数函数+查表是当前可验证推理的主流技术栈（zkLLM、FlashProve、Sable 三者一致）；② 离群值/比特预算分配主导量化精度损失（量化文献共识 + 本文归因实验）；③ 哈希承诺+小域是证明器速度的正确方向（STARK 生态广泛采用）。

**仍属本文自证的机制**：wrap-free 界的"零漏洞性"依赖论文自己的伪造测试（虽然覆盖面广，但非形式化验证——FlashProve 的 Lean 证明在此维度更强）；成本模型的 1.56–2.45× 残差（latency-bound 小形状、注意力域的加法指令占比）说明对证明器的理解尚不完全。

**优势成立条件**：开放权重、审计者可承受 106–477 MiB 与 19–56 s、上下文 ≤16K、单 GPU 96 GB 内。**可能失效条件**：闭权重（泄露问题）、超长上下文（注意力二次项使 16K 已用 72/96 GiB，32K 直接 OOM）、需要每请求附带证明的 toC 场景（须等递归+ZK 层完成）。

## 七、必要知识反推

假设让一个无背景的人重做这项工作，最少需要什么？

### 7.1 领域知识层（研究对象）

- **Transformer 推理的完整数值路径**：RMSNorm、GQA、RoPE、SiLU-MLP、QK-norm、MoE 路由的每一步在浮点下到底计算什么——否则无法把它们"翻译"成整数原语并预见到首位置 token 的极端激活（行钳制的存在证明作者被这个坑过并系统化了它）。
- **量化推理的误差结构**：离群值、行/列指数、离轴缩放（scale off the reduction axis）——FO 的所有格式设计都围绕"8 位乘积+精确整数累加"这一量化不变量。不懂 QuaRot 就不会想到旋转可以白送。

### 7.2 方法论知识层（研究脉络）

- **sumcheck/GKR/zerocheck 的证明器代价结构**：知道"度数 d 的约束→d 次 fold→每轮 n 个元素"的成本模型，才能做出"合并叶子层进 zerocheck，接受度数 8-10"这类交换。
- **LogUp 在素域上的 N<p 前提**：这是 chunking 的直接动机，也是元组压缩定理（每坐标独立挑战省 log₂k 位）的出发点。
- **承诺方案的证明大小经济学**："列数而非元素数决定打开成本"这一洞察驱动了宽列、混合高度树、按层规约的全部布局决策。
- **Fiat–Shamir 与 IOP 的 round-by-round 分析框架**：soundness 预算表（表 2）逐项可追溯，没有这个框架无法诚实地声称 2⁻¹⁰³。
- **递归证明的成本传递律**："递归层的成本=验证器的操作数"——这决定了为验证器做减法的整个第 10 节。

### 7.3 工程知识层（系统实现）

- **GPU 编程的延迟 vs 带宽判别**：识别证明遍 94–97% 时间 GPU busy（带宽受限，优化折叠吞吐）vs 1×4K 的 3,800 个单块轮（延迟受限，优化 CUDA graph 与设备转录本）。
- **内存层级经营**：pinned host memory、层边界流式重建、见证重建次数从 5 压到 3 的按层规约——每少一次重建就是约 25% 证明时间。
- **字节级确定性工程**：主机/设备转录本产出字节相同证明、CUDA graph 重放的三条规则——没有它无法验证重放的正确性。

### 7.4 知识融合的关键节点

1. **"被证明的必须是函数"×"小域快"的碰撞**：意识到浮点不可证明后，量化知识（离轴缩放）与密码学约束（no-wrap 界）在"8 位输入+24 位累加器+2³¹ 素数"的具体数字上碰合——这是全文最核心的工程洞察，需要同时精通两边的"单位"。
2. **"查表次数>p"×"LogUp 分式恒等"的碰撞**：从代数结构（p 份相同分式求和为零）推出 chunking，而非经验性兜底。
3. **"递归成本=验证器操作"×GPU 工程的碰撞**：为验证器减哈希的每一步（闭式公共列、免哈希最终打开）都是"密码学观察 × 证明大小经济学"的乘积。
4. **精度归因×校准自由度的碰撞**：看到 12 位 Q/K 消 37% 差距后，不是加宽格式（破坏界、增加成本），而是发现 QK-norm 留下的指数自由度可以零成本重分配——Q/K split 是"实验发现→机制理解→零成本工程化"的完整链条。

## 八、论文中可以提取的通用性灵感

**1. 精确性是可验证性的前提：先钉死语义，再谈信任。** 论文证明"浮点推理连自身都不是函数"从而必须定义 FO。推广场景：审计 AI agent 的工具调用轨迹（先定义确定性的轨迹语义）；验证数据库查询执行（先固定查询计划）；供应链溯源（先定义"来源"的精确断言）。凡是"验证 X"的问题，第一步都是把 X 从连续/含糊的东西变成离散/确定的东西。

**2. 约束系统的"wrap-free"设计模式：让域等价于整数。** 在带模运算的抽象层工作却需要整数语义时，为每条关系配显式界、用查表强制范围，使"mod p 成立"恢复整数含义。推广场景：区块链智能合约的整数溢出防护（几乎同构的问题）；机器学习中的数值稳定性证明；任何"有限精度实现正确性"的形式化。

**3. 比特预算的零成本重分配：校准自由度是隐藏的金矿。** Q/K split 不改任何格式、代码与证明成本，仅重选校准常数就消除 23–53% 差距。推广场景：分布式训练中的梯度分桶边界重分配；编译器寄存器分配中的溢出权重；网络量化中的逐通道缩放。通用原理：**在总量固定的资源约束下，分配方案本身常有未被优化的自由度**。

**4. 为下游消费者设计：递归思维前置。** Sable 不是先做一个大证明再想怎么压缩，而是把"验证器操作数"作为一级优化目标（17.8M→4.2M），因为递归层的成本等于验证器的成本。推广场景：API 设计（为重试/幂等优化）；日志系统（为下游解析优化格式）；数据库（为物化视图优化写入路径）。凡是会被二次处理的产物，都该为二次处理而设计。

**5. 流式+重算的内存经济学。** "存层边界、按需重建见证（42 ms/层）"用少量重复计算换取 TB 级内存需求坍缩。推广场景：大模型训练的激活重算（gradient checkpointing，完全同构）；流式计算引擎的算子状态最小化；视频编辑代理帧。

**6. 对称性/同构的工程压榨：CUDA graph 重放。** 发现中间层证明遍形状相同后，捕获一次图、参数化重放。规则化重复工作是通用优化机会：编译器的循环不变量外提、 serving 的 continuous batching、硬件的脉动阵列。

**7. 诚实的边界声明作为设计资产。** 论文明确声明非零知识、审计者规模、闭权重泄露、soundness 分析中哪一步不是直接引用定理——这些声明本身构成威胁模型（第 4 节）并指明路线图。推广到任何系统设计：把"不声称什么"写清楚，比额外功能更能建立信任。
