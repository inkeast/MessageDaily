## 先说结论

这是一期从头到尾由 GenSpark 赞助的实操视频（Wes Roth 在 0–120s 段与片尾两次口播致谢并附推广链接）：他为自己的业余项目《Grid Iron Guild》——一个设定在"龙与地下城"式宇宙、由 AI 担任教练、球员与经理的奇幻橄榄球联赛——制作一支 30 到 90 秒、工作室级观感的动画宣传片。他没有动画技能（自称这辈子没打开过 After Effects）、也没预算雇制作团队，于是全程在 GenSpark Media Studio 里与一个 agent 聊天完成：角色定妆、"故事圣经"管理一致性、3D 白台走位、480p 草稿到 1080p 定稿、AI 作曲、节点式剪辑导出。真正值得看的不是"某个模型多强"，而是整条影视生产线被收进一个聊天框之后制作方法本身的重构：一致性从掷硬币变成工程、试错被搬到廉价的草稿层、提示词由 agent 代写而人只负责意图与验收。边界同样先说清：下述所有功能表现均出自赞助演示语境，成片质量没有第三方验证。

## 一个只有 AI 球员的联赛，和"五个订阅拼不出一支片"

Wes Roth 开场介绍项目：《Grid Iron Guild》是暂定名，"有点像设定在 D&D 宇宙里的橄榄球游戏，但有个小转折——这里 AI 当教练、AI 打比赛、管理球队、在联赛里一路成长"（0–120s 段，他自述）。游戏规则复杂，所以宣传片要兼任"动画解说片"，把玩法讲清楚。传统两条路都走不通：雇制作团队太贵；自己用 AI 做，就得订五六个订阅——图像一个、视频一个、配音一个，为保持一致还要上个 3D 引擎——"然后我得在它们之间拖文件，而且什么都对不上"（0–120s 段）。

他给出的解法是本期赞助商 GenSpark Media Studio：一个工作区聚合视频模型 Seedance、Kling、Veo；图像模型 Nano Banana、Flux、GPT Image、Grok Imagine、Ideogram、Seedream；配音 ElevenLabs；3D 的 Marble 与 Tripo（模型名均为转写校正，见校正表）；音乐模型另有五家（见下文）。他强调"由一个 agent 规划并跑完整个生产流程，不需要技术背景"，交互方式就是聊天，"就像你跟任何聊天机器人聊天一样"。

成片有两支。30 秒版台词只有几句："精灵、兽人、巨龙、开着重型机械的哥布林。每一次阻挡都是一场豪赌，而骰子永远饥饿。……《Gridiron Guild》，绝不留情。"（120–240s 段）长版约两分钟，由两位解说员"维斯珀伯爵（Count Vespero）"与"斯尼基（Snicket）"用一场比赛把规则讲完：两队一颗尖刺球、轮流行动、"一次检定失败，整回合结束"；格挡掷骰、破甲掷伤病；各族风格分明——木精灵投掷美如画、蜥蜴人"跑得像尾巴着了火"、矮人"顽固、铁甲、粗鲁得惊天动地"、鼠人"怎么这么多？为什么这么多？"；他自己的哥布林队"与其说打球，不如说在球场附近作案"，链锯合法、碾压裁判受鼓励；巨魔能把队友扔进端区，掷出 1 点则"巨魔有点饿了——加里（Gary），不要！"（1320–1560s 段）。从规则描述看，其内核与奇幻战棋橄榄球《Blood Bowl》高度同构——这是写作者推断，节目未提及该游戏名。

## 一致性的工程化：定妆、变体与"故事圣经"

流程第一步不是写提示词，而是"把样子尽早钉死"（120–240s 段）：先用低分辨率草稿磨角色造型——比如反复试肩甲要"很大、巨大还是庞然巨物"。与 agent 的交互方式值得注意：只给方向性轻推（"make it bigger and more dangerous"，更大、更危险），不使用任何设计术语；agent 会把定稿参考图"冻结"为风格基准，之后只生成带细微变化的新变体。他对比了过去：想要六个变体就得手写六条提示词，"新变体像不像参考图是掷硬币，前提是那个模型支持上传参考图"（240–360s 段）。锁定后，同一角色能在不同护甲、不同镜头间保持是"同一个人"。

视觉定稿后进入他所谓的"正典（canon）化"——他专门科普 canon（正典：公认的作品与设定集合）与 cannon（加农炮）的区别，还放了张格里多与汉·索罗"谁先开枪"的梗图：星战正典我们说了不算，"但在 GenSpark Media Studio 里我们可以"（240–480s 段）。具体机制叫 story bible（故事圣经）：写入制作简报（风格基调），再上传整文件夹参考资产——解说员、场上角色、整队阵容、"据称"存在的秘密武器——引擎自动把每个独立角色登记为有名字的角色、区分正邪。"这里的内容我一个字没打，只上传了图片，它自己猜、自己推断每张图是什么"，错了也容易改（480–600s 段）。目标一句话："当我说'用木精灵队'，生成引擎知道我指的就是这套。"

演示段还有两个细节。其一，agent 会先反问澄清："你说的奇幻橄榄球，是选秀板那种，还是真木乃伊在古代竞技场里真打？"——他说这"已经在帮你省下大把时间，因为图像模型并不总能分清这两者"（360–480s 段）。其二，他选的编排模型是 Claude Fable 5.1，"截至录制时大概是干这类活最好的模型，但要留给更长更复杂的任务"（360–480s 段）——本站此前记过他评 Fable 5.2 为"凡人可用的最强模型"，两说互为参照（[Fable 5.2 一文](https://inkeast.github.io/MessageDaily/posts/2026-11-15-wes-roth-fable-mythos-5-2-model-three-gimped/)）。

## 白台走位与两段经济：把电影术语变成提示词模板

3D 部分他借用了电影术语 blocking（走位）：开机前先安排演员站位与运动。GenSpark 的提示词模板是两遍式："block out〔舞台上有什么〕on a white stage, then shoot the final〔成片镜头什么样〕"。第一遍，引擎（Marble 1.1 Plus）先在白色舞台上生成角色跑动的粗胚，可播放、无限循环、自由推拉镜头找机位；第二遍再按文字描述——夜、浓雾大雨、低机位追踪——把成片补全（600–840s 段）。他对 3D 引擎的来历专门标注：Marble 来自 World Labs，"如果你知道李飞飞（Fei-Fei Li），她就是背后的人"（600–720s 段；World Labs 由李飞飞联合创立、Marble 为其 3D 世界生成产品，此点与公开资料一致）。

经济结构在多个环节显形：图像端草稿用低清、定稿才出高清；视频端先让 Seedance 出 480p 验证走位与机位，"锁定、看着不错了，再用 1080p 出最终片段"；背景不满意就重roll（720–840s 段）。他看完终稿自嘲："我觉得自己入错行了，我本该去当导演。"定价信息也直接展示：GPT Image 2 每周免费额度"仅限会员，免费账号没有"；Nano Banana 2 Flash 每张 17 积分（120–240s 段）。

做解说类视频的一个可迁移技巧：把"掷骰子"做成实时叠层。他用两段片段拼接——第一段结尾由 agent 现场模拟一次掷骰，第二段按结果播后果；第一次它真掷出了颗二十面骰（d20），他觉得"挺有意思——按说这正是你预期会看到的东西"（960–1080s 段）。

## 音乐靠量、歌词靠磨：LLM 写词的四个毛病

配乐环节他把站内音乐模型排了个队：Mureka（完整人声、可上传参考音轨——"有人甚至哼一段旋律、在桌上敲个节奏当参考"）；ElevenLabs Music；MiniMax Music 3.0；Google Lyria 3.5；Cassette AI（纯器乐）。就这个项目他最喜欢 Lyria 3.5，"ElevenLabs 这次不合我想要的风格，但过去出过很棒的音乐"——同时强调"某一个听着不行不代表模型不行，风格错配而已"（840–960s 段）。

方法论是"量"：别指望一遍出爆款，"到这个阶段我已经写了几千首歌，会反复回来听的只有一小张清单"（960–1080s 段）。更有迁移价值的是他总结的 LLM 写歌词四大毛病（840–960s 段）：滥用"我/你"人称；一味追求语法正确；关键词过度重复（"要一首关于橄榄球的歌，你就会听到满耳朵的'橄榄球'"）；太直白、不够诗意。他的对策：歌词先在别处写好、磨掉这些毛病，再拿进音乐模型试。

## 剪辑不出工作区，以及"agent 快会剪片子了"

最后一段是 Video Composer：不需要外部剪辑软件，双击开节点即可在画板上剪——时间线、拖拽重排、拆分、Trim Left/Right、字幕、变速、加音轨、导出回画布，"全部在同一个工作区完成"（1080–1320s 段）。混音也交给 agent："人声一开口音乐自动压低，反之亦然"（960–1080s 段）。他顺带抛出一个判断："现在有些跑 agent 的模型已经非常擅长视频剪辑——Fable 就是顶尖水准"（1200–1320s 段）。另有社区区"Get Inspired"可看别人的作品，包括 TikTok 舞蹈与"拿一个人的形象去演另一个视频动作"的形象迁移玩法（1080–1200s 段）。

收尾他给这期工作下了方法论总结："一个点子、一个工作区，一条不雇人就根本做不出来的成品宣传片"（1440–1560s 段），随后是第二轮赞助口播与返佣链接。

## 机制 → 影响 → 启发

1. **技能门槛转移链**：模型聚合 + agent 编排（变化）→ 动画、编曲、剪辑等专业技能被代理，用户技能退化为"意图描述 + 验收判断"（机制）→ 个人创作者能独立产出原先必须外包的物料（一阶影响）→ 小型制作外包与"五订阅拼装"工作流同时受压，个人竞争力从技能栈转向品味与参考库（二阶影响）。观察指标：此类套件的模型清单与积分定价迭代速度、社区区作品质量。启发：非专业者交付物的上限 = 参考资产库质量 × 迭代量。
2. **一致性工程化链**：参考图冻结 + 故事圣经（变化）→ 角色一致性从"抽卡概率"变成受控工程（机制）→ 多镜头叙事与系列内容可量产（一阶）→ 资产沉淀进平台 AI Drive，锁定加深（二阶）。观察指标：故事圣经能否导出、跨平台复用。启发：先锁正典再量产；一致性靠资产库，不靠提示词复述。
3. **两段经济与量胜筛选链**：低清/480p 草稿层廉价试错 + 音乐按量产出（变化）→ 生成边际成本可控、失败廉价（机制）→ 制作模式从"谨慎单次"变为"大量生成 + 人工筛选"（一阶）→ 筛选与品味成为新瓶颈，他几千首歌只留一张短清单（二阶）。观察指标：草稿与终稿两档的价差。启发：把验收标准前置成规则（故事圣经、正典），筛选标准比生成技巧更值钱。
4. **提示词下沉链**：agent 代写具体 prompt、人只给 nudge（变化）→ 提示词工程从用户技能下沉为 agent 职责（机制）→ 交互重心移向"说清要什么 + 怎么验收"（一阶）→ 模型选择的默认权（agent 反问你用哪个模型）落到平台手里（二阶）。启发：练"描述效果与验收标准"，比背提示词模板更有长期价值。
