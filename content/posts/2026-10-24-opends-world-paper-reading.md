## 一、论文背景

### 1.1 深度搜索：从问答到自主研究

**深度搜索（Deep Search）** 是指 AI 智能体自主地获取、分析和整合信息，以解决复杂信息寻求任务的能力。可以把它类比为人类研究员的工作方式：接到一个研究问题后，不是从一个固定文档库里翻答案，而是自己决定去哪里找、用什么工具打开、如何把碎片线索拼成结论。

近两年，随着大模型与工具增强智能体（tool-augmented agent）的发展，模型已经具备了多轮搜索、网页浏览、跨源推理等能力，Deep Research 类产品陆续落地。但一个根本问题随之浮现：**如何可靠地评估这些智能体在真实环境中的研究能力？**

### 1.2 真实 Web 与静态检索环境的三大落差

论文开篇指出，现有 Deep Search 评测与真实开放 Web 环境之间存在系统性落差，体现在三个方面：

1. **多模态多样性（Diverse Modalities）**：真实信息以文本、图片、音频、视频多种形式存在。同一个研究任务的不同阶段可能依赖不同模态——比如先从一段视频里认出一个生物，再去查它的化石记录。
2. **异构格式（Heterogeneous Formats）**：信息分散在 HTML、PDF、XML、Parquet、ZIP 等不同结构的资源里。即使同是文本，HTML 网页和 Parquet 数据表的获取与解析方式完全不同。
3. **交互式访问需求（Interactive Access Requirements）**：很多证据无法通过一次检索直接获得，需要网页导航、界面操作、参数更新、文件下载等交互动作才能"解锁"。例如在博物馆虚拟导览里切换视角才能看到某个展柜。

这三者叠加，构成了真实 Web 环境中**复杂的证据获取过程**——而这恰恰是现有基准（大多基于静态语料库或封闭检索路径）没有充分覆盖的。

### 1.3 为什么要造一个新基准

论文的逻辑链条很清晰：

- 现有评测要么是静态检索（给定文档库），要么是封闭 Web 环境（模拟站点），都没有系统性覆盖多模态 + 异构格式 + 交互访问三合一的证据获取挑战；
- 于是无法回答一个关键问题：**当前最强的智能体，在真实开放的 Web 上做端到端研究，到底行不行？**
- 要回答它，需要一个任务定义清晰、证据链可验证、答案唯一、且在真实 Web 上可复现的基准。

这就是 OpenDS-World 的由来。值得强调的是，这个基准还带来一个意外的副产物：**人类在这个基准上只有 21.1% 的准确率，而最好的模型达到 39.0%**——模型首次在"真实世界研究任务"上大幅超过人类，这个发现本身就具有范式意义。

## 二、论文定位和关联工作

### 2.1 开放 Web 深度搜索评测谱系

论文的 Related Work 把这个方向的工作分为三支：

**（1）开放 Web 搜索与持久事实查找**

- **BrowseComp**（Wei et al., 2025, OpenAI）：1266 道需要在开放互联网上持久导航才能解出的短答案题。人类求解率仅 29.2%（两小时限制），Deep Research 51.5%。它是 OpenDS-World 最重要的参照系——同样采用"问题反转"构造（从冷门事实出发加约束直到难以直接检索），但 BrowseComp 以文本搜索为主。
- **GAIA**（Mialon et al., ICLR 2024, Meta/HF/AutoGPT）：466 道对人类简单（92%）对 GPT-4 插件难（15%）的通用助手任务，考察多工具协调。
- **DeepWideSearch / LohoSearch**（2025-2026）：分别评估搜索的宽度与超出人类难度上限的长程搜索。
- **BrowseComp-Plus / MM-BrowseComp**：更公平的评测与多模态版本，其中 MM-BrowseComp 已开始引入视觉证据，但交互访问维度仍有限。

**（2）多模态证据接地**

- **MM-BrowseComp**（Li et al., 2025）：多模态浏览基准，要求连接视觉线索与外部 Web 信息。
- **视频深度研究基准**（Liu et al., 2026；Fang et al., 2026）：把线索分布到视频帧与开放 Web 检索中。
- **MMInA**（Tian et al., 2025）：多跳多模态互联网智能体基准。

**（3）交互式证据获取**

- **WebWalker**（Wu et al., 2025）：网站遍历，检索超越落地页。
- **UIS-Digger**（Liu et al., 2026）：面向未被索引信息的动态界面与嵌入文档。
- **CAP**（Xu et al., 2026）：跨站点浏览器智能体，复杂动作与感知。
- **OSWorld / WebArena** 系：GUI/计算机操作基准，重交互但多用模拟环境。

### 2.2 OpenDS-World 的差异化定位

与上述工作相比，OpenDS-World 的独特之处在于**三合一**：

| 维度 | BrowseComp 系 | GAIA 系 | GUI/WebArena 系 | **OpenDS-World** |
|------|--------------|---------|-----------------|------------------|
| 真实开放 Web | 是 | 是 | 否（模拟站点） | **是** |
| 多模态证据 | 部分（文本为主） | 部分 | 少 | **4 模态，82.5% 任务≥2 模态** |
| 异构文件格式 | 少 | 部分 | 少 | **42 种格式，96% 任务≥2 格式** |
| 交互式访问 | 弱 | 中 | 强（模拟） | **7 类访问，95.5% 任务≥2 类** |
| 人类表现参照 | 29.2% | 92% | — | **21.1%（1000 次独立求解）** |

定位结论：OpenDS-World 是**首个面向真实开放 Web、将多模态/异构格式/交互访问三类证据获取要求系统合并**的深度搜索基准，并且用 1000 次独立人类求解做了难度校准——这是它与同期所有基准最大的区别。

## 三、问题定义

### 3.1 从具体场景到抽象任务

论文面对的具体场景是：评估智能体能否像人类研究员一样，在真实 Web 上完成端到端的多步信息研究。

其核心洞察是：**研究的难度不在"问题本身多绕"，而在"证据获取过程多难"**。一道题如果所有证据都能通过两三次文本搜索拿到，那考察的只是推理；而如果证据分布在视频、PDF、数据集、虚拟导览里，需要导航、下载、解析才能拿到，考察的就是一整套自主研究能力。

### 3.2 OpenDS 任务的形式化定义

**开放 Web 深度搜索（OpenDS）** 定义为一个事实问答任务：

- **给定**：一个事实性问题 q、可用的初始线索（一段真实视频 + 音频 + 问题文本）、以及一个提供搜索/浏览器/视频处理工具的统一工具环境；
- **求**：一个唯一且可验证的事实答案 a；
- **约束**：证据可能分布在任意网站、文档、多媒体资源与在线应用中，其位置与访问方式事先不告知智能体；智能体必须基于当前信息决定后续搜索目标、选择合适的访问与处理方式，并通过跨源推理逐步建立证据之间的联系。

用表格把 OpenDS 与经典 QA 对应起来：

| 经典 QA | OpenDS |
|---------|--------|
| 给定文档库 | 开放、动态的真实 Web |
| 检索一次或几次 | 多步自主探索（搜索→访问→处理→连接，循环） |
| 单一模态文本 | 文本/图片/音频/视频混合 |
| 单一格式（如纯文本） | 42 种格式（HTML/PDF/MP4/Parquet/ZIP…） |
| 直接读取 | 7 类访问操作（观察/导航/参数更新/时间索引/图形操作/声明式查询/工件转移） |
| 答案可从单文档导出 | 证据链多节点相互依赖，单线索不能直接暴露答案 |

### 3.3 这个抽象的精妙之处

这个定义把"研究能力"拆解成了可测量的三重耦合能力：**信息发现**（去哪找）、**证据获取**（怎么拿到）、**跨源推理**（怎么连起来）。它刻意不限制搜索路径与工具使用策略，把难度全部压在"证据获取过程"上，从而能区分出"会推理但不会找信息"与"真正会研究"的智能体。同时"唯一可验证答案 + 标注证据链"的设计让自动评分成为可能。

## 四、问题解法

### 4.1 基准构造三阶段：锚点 → 扩展 → 反转

OpenDS-World 的 200 个任务不是拍脑袋写的，而是通过一条可复现的流水线构造的。类比来说，这像先种一棵"证据树"，再把树倒过来变成问题。

**阶段一：真实世界锚点（Real-World Anchor）**

- 专家标注员从 8 个领域挑选 500 个候选公开视频；
- 联合分析连续视觉帧与音频，识别出一个可验证的初始锚点——锚点对应的实体必须**只能通过视频的视听内容识别出来**（防止退化为页面级文本搜索）；
- 核心实体必须唯一映射到一个有效的 Wikidata 条目，保证语义指称无歧义；
- 视频随基准一起归档分发，确保评测可复现。

**阶段二：开放 Web 证据扩展（Open-Web Evidence Expansion）**

- 在证据链每个节点，标注员构造搜索查询、用 Google 搜索获得候选源集合，逐一检查并选择与当前节点有明确语义关系且证据可验证的源；
- 选择时刻意兼顾模态、格式与访问类型的多样性；
- 从选中源中抽取新实体作为下一节点；**每个节点都必须被多个独立 Web 源佐证**，不依赖单一来源；
- 递归扩展直到到达一个唯一、稳定的终端节点——它就是参考答案。

**阶段三：问题反转（Question Inversion）**

- 把完整证据链反转为**一组相互依赖的约束**：中间节点不显式出现，每个节点被转写成由前序证据累积推导的间接指称描述；
- 关键性质：**任何单条线索都不能直接暴露目标实体**，只有组合起来才能唯一确定答案。这保证了直接检索答案文本无法解题。

### 4.2 人工验证与人类测试

**十人独立验证**：审查证据有效性（事实准确、来源真实可访问、相邻节点转移有证据支持、锚点确需视听识别）与任务有效性（问题清晰、约束一致、答案唯一）。任何事实错误/证据不足/关系矛盾/答案不唯一的候选任务被直接剔除，最终保留 200 题。

**1000 次独立人类求解**：50 名求解者（与出题人完全隔离），分 10 组各答 20 题，每人只答一组以控制疲劳；允许用 Chrome 等常规浏览器，禁止使用任何 LLM 工具；不设时限，自愿终止。这套流程既提供人类基线，也用"每题被解出人数"把任务划成三档难度：

- **Low**（≥2 人解出，54 题）、**Medium**（1 人解出，61 题）、**High**（0 人解出，85 题）。

### 4.3 统一评测 Harness

所有模型在完全相同的工具环境与预算下评测：

**三类 16 个工具**：

| 类别 | 工具 | 功能 |
|------|------|------|
| Search | text_search / image_search / open_page / youtube_search | 文本/图片/视频搜索与网页读取 |
| GUI | browser_navigate / get_markdown / get_clickable_elements / click / form_input_fill / press_key / scroll / screenshot / get_download_list / get_download_content | 真实浏览器会话内的导航、点击、输入、截图、下载与读取工件 |
| Other | youtube_read_video / youtube_read_subtitle | 视频帧采样（默认 10 帧，1-100 帧/次）与字幕提取（可限定时间窗） |

**执行预算**：搜索阶段每样本 3600 秒 + 100 次工具调用，任一到达即终止；之后进入**无工具的收尾阶段**（最多 2 次请求、5000 token 输出预算），仅凭已收集证据作答。

**上下文管理**：最近 4 条工具观察保持完整；更早的搜索结果只保留前 2 条、文本截断至 2000 字符；图像上下文上限 250 张。

**评分**：Qwen3.8-27B 作为 LLM 裁判，基于语义等价判断答案对错（主指标 ACC），同时记录总 token 消耗与耗时作为成本指标。

## 五、评估指标与实验证据

### 5.1 指标体系

- **主指标：ACC**（答案准确率）——直接衡量"端到端研究是否成功"，由 LLM 裁判对照参考答案判定语义等价。它衡量的是发现+获取+连接证据并得出唯一事实答案的**全链路能力**，而非任何单一环节。
- **辅助指标：难度分层准确率**（Low/Medium/High，按人类求解人数校准）——衡量难度单调性。
- **成本指标：总耗时（小时）与总 token 消耗（百万）**——检验"投入是否换来产出"。
- **行为指标：工具调用构成、类别转移矩阵、终止原因、失败恢复决策、预算耗尽率**——用于行为层面诊断。
- **消融/细分指标：按 8 领域、4 模态、8 格式、7 访问类型、视频时长的准确率切片**——定位具体短板。

### 5.2 数据集规模与结构

- 200 任务、8 领域（Science/Society 各 33、Daily Life 30、Culture 27、Nature 22、History 19、Economy 18、Technology 18）；
- 787 条标注证据条目（平均 3.94/题），覆盖 4 模态、42 种格式、7 种访问类型；
- 任务级覆盖：文本 99.5%、图片 44.5%、视频 35.5%、音频 16%；82.5% 任务≥2 模态；HTML 98%、MP4 35%、PDF 31%；96% 任务≥2 格式；95.5% 任务≥2 类访问；
- 锚点视频 34.5% 超过 20 分钟，56% 超过 10 分钟。

### 5.3 主结果：12 个前沿模型 + 人类

| 模型 | 总体 ACC | Low | Medium | High | 总耗时(h) | 总 Token(M) |
|------|---------|-----|--------|------|-----------|-------------|
| **GPT-6 Astra** | **39.0** | 59.26 | 40.98 | 24.71 | 62 | 187 |
| Claude Opus 5.5 | 38.0 | 53.70 | 40.98 | 25.88 | 65 | 339 |
| Gemini 3.8 Flash | 36.5 | 51.85 | 34.43 | **28.24** | 59 | 976 |
| Claude Fable 5.1 | 33.5 | 48.15 | 32.79 | 24.71 | 110 | 481 |
| GPT-5.6 Sol | 28.0 | 46.30 | 31.15 | 14.12 | 30 | 186 |
| Qwen3.8-Max | 25.5 | 40.74 | 26.23 | 15.29 | 85 | 839 |
| GLM-5.3-Flash | 23.5 | 42.59 | 16.39 | 16.47 | 128 | 389 |
| DeepSeek-V4.1-Flash | 20.5 | 33.33 | 13.11 | 17.65 | 120 | 599 |
| Kimi K3 | 17.5 | 27.78 | 14.75 | 12.94 | 110 | 310 |
| GLM-5.3 (纯文本) | 13.5 | 22.22 | 6.56 | 12.94 | 145 | 345 |
| DeepSeek-V4-Pro (纯文本) | 12.5 | 27.78 | 11.48 | 3.53 | 148 | 297 |
| Qwen3.8-Flash | 12.0 | 22.22 | 13.11 | 4.71 | 75 | 752 |
| **人类** | **21.1** | — | — | — | ~646 | — |

关键读数：

1. **最强模型失败率 61%**（GPT-6 Astra 122/200 未解出）；
2. 难度单调下降：12 模型平均 Low 39.66% → Medium 23.50% → High 16.76%；High 档最佳者是 Gemini 3.8 Flash（28.24%）而非总体冠军；
3. **模型超过人类**：39.0% vs 21.1%，且人类 42.5% 的题无人解出、人均耗时 38.8 分钟/题、主观难度均分 3.884/5（65.5% 的尝试打了 4 或 5 分）。

### 5.4 成本与准确率脱钩

这是论文最有信息量的发现之一：

- GPT-6 Astra 与 GPT-5.6 Sol 总 token 几乎相同（187M vs 186M），准确率差 11 个百分点；
- Gemini 3.8 Flash 消耗约 **5.22 倍**于 GPT-6 Astra 的 token（976M），准确率反而更低；
- DeepSeek-V4-Pro 累计 2.39 倍于 GPT-6 Astra 的耗时，准确率只有 12.5%；
- 单任务均值：GPT-6 Astra 51.05 次调用 / 18.66 分钟；Qwen3.8-Flash 89.94 次调用但准确率垫底。

结论：**更多的时间或 token 不保证更好的深度搜索**——瓶颈在源选择、工具协调与停止决策，不在"努力程度"。

### 5.5 工具使用、失败与预算行为

- **工具构成差异大**：GPT-5.6 Sol 最偏搜索（74.5% Search），Claude Opus 5.5 与 Qwen3.8-Flash 有 51.5%/49.4% 的 GUI 操作；但构成相似不等于成绩相似（后两者 38% vs 12%）；
- **类别内粘滞**：Gemini 的 Search→Search 转移占 84.63%，Qwen3.8-Flash 的 GUI→GUI 占 84.97%——模型倾向连续做同类操作；
- **失败代价不成比例**：工具失败只占 2.83–9.42% 的调用次数，却吃掉 **19.27–61.90%** 的执行时间（GPT-6 Astra：6.34% 调用 / 42.57% 时间）；
- **恢复策略**：失败后最常见决策是换工具（Claude Opus 83%、Gemini 81%、GPT-5.6 Sol 79%），Kimi K3 与 GLM 5.3 则更多用改参数重试（38%/37%）；
- **自然终止 ≠ 答对**：GPT-6 Astra 69% 任务自然终止，准确率 39%；Qwen3.8-Flash 仅 6.5% 自然终止、80% 打满调用预算；
- **预算耗尽分化**：触及任一上限的比例从 Claude Opus 的 16.5% 到 Qwen3.8-Flash 的 81.5%；双上限同时耗尽≤1%，说明"时间密集型"与"调用密集型"是两种不同的失败模式。

### 5.6 细分切片：短板在哪里

- **领域**：GPT-6 Astra 在 Society（51.5%）、Nature（50.0%）最强；Claude Opus 在 Nature（50.0%）、Science（45.5%）强；Gemini 在 History 最佳（36.8%）——模型间领域差异显著（Science/Society 跨模型标准差最大：13.2/12.9pp）；
- **模态**：GPT-6 Astra 拿下 Text（38.69%）与 Image（48.31%）；Gemini 3.8 Flash 在 Video（43.66%）与 Audio（50.00%）领先——音视频处理呈"家族优势"；
- **格式**：GPT-6 Astra 在 8 类格式中 6 类第一，PDF 50.0%、CSV 60.0%、ZIP 57.14%；JPG 普遍最差；ZIP 跨模型方差最大（0–57.14%）；
- **访问类型**：GPT-6 Astra 在 6 类第一（工件转移 46.67%、声明式查询 61.54%）；Gemini 在时间索引最佳（46.32%）；声明式查询跨模型方差最大（0–61.54%）；
- **难度与证据构成的关系**：High 组比 Low 组更多音频（22.4% vs 7.4%）、更多 ZIP（12.9% vs 1.9%）、更多长尾格式（48.2% vs 31.5%）、更多超媒体导航（72.9% vs 61.1%）与工件转移（67.1% vs 53.7%），而图片/视频反而更少——**越难的任务越依赖"难获取"的证据形态**。

### 5.7 长程执行证据

- 标注证据链平均只有 3.94 个源，但 3/4/5/≥6 个源的任务中位工具调用数分别是 74/56/72/82.5 次——**紧凑证据链在执行中膨胀成数十倍长的轨迹**；
- 执行长度与证据链规模不单调相关，说明决定研究复杂度的是"不确定线索的消解与候选源的探索"，不是源的数量本身。

## 六、效果优势的根源解释

本部分回答两个问题：（a）为什么这个基准能把最强模型压到 39%？（b）为什么模型与人类的相对表现呈现"模型反超"的罕见格局？

### 6.1 根源机制与证据链

**因果链一：三属性叠加 → 强制协调三类工具 → 暴露协调短板 → 准确率封顶**

1. 任务构造强制 82.5% 的任务跨≥2 模态、96% 跨≥2 格式、95.5% 跨≥2 类访问（论文实验数据支持的机制）；
2. 这意味着单靠 Search 或单靠 GUI 都无法走通证据链，必须搜索→交互→处理循环交替（论文工具转移矩阵显示模型普遍"类别内粘滞"，如 Search→Search 84.63%，阅读者推测：这种粘滞与跨类协调要求错位是失败的行为学表征）；
3. 结果是任何一类能力的短板都会传导到最终准确率（推理：木桶效应；论文证据：Qwen3.8-Flash 调用量最大但准确率最低，DeepSeek 纯文本版在 High 档崩到 3.53%）。

**因果链二：证据获取的不确定性 → 轨迹长度膨胀 → 预算/失败管理成为第二瓶颈**

1. 问题反转设计保证单线索不能直接暴露答案，模型必须探索多个候选源（论文实验：中位 56–82.5 次调用 vs 3.94 个标注源）；
2. 探索过程中工具失败虽只占 2.83–9.42% 的调用，却占 19.27–61.90% 的执行时间（论文数据）——失败管理直接消耗预算；
3. 预算耗尽率从 16.5% 到 81.5% 不等，且 GPT-6 Astra/Claude Opus 较少耗尽预算但准确率仍<40%（论文数据）——说明**即便执行管理过关，源选择与证据整合仍是硬瓶颈**（论文原文明确指出这一点）。

**因果链三：为什么模型（39%）反超人类（21.1%）**

1. 人类求解被禁止使用 LLM 工具，只能用常规浏览器（论文设定）；人均 38.8 分钟、总投入约 646 小时，42.5% 的题无人解出（论文数据）；
2. 模型在证据定位宽度、多语言检索、不知疲倦的迭代上有人类没有的优势（这部分是与 BrowseComp 论文动机一致的推断：机器的记忆广度与不知疲倦特性）；
3. 交叉参照：BrowseComp 上人类 29.2%（2 小时限）而 Deep Research 51.5%——同一"模型反超人类"格局；GAIA 则相反（人类 92% vs GPT-4 插件 15%），因为 GAIA 任务"对人类概念上简单"。OpenDS-World 的任务对人类与模型都难，但模型的相对优势更大（阅读者综合推断，论文未直接对比 GAIA）。

**反事实检验**：论文的难度分组分析提供了一组自然反事实——如果把 High 组的音频/ZIP/长尾格式/工件转移换成 Low 组更多采用的图片/视频证据，难度梯度与证据形态梯度同步变化（6.6 节切片），侧面印证"证据获取属性"而非"题目语义"是难度的主要来源。

围绕上述因果链，本次检索得到如下外部证据：

| 研究（可核验链接） | 相似尝试 | 相关结论 | 与本文的差异与适用边界 | 对根源解释的影响 |
|---|---|---|---|---|

### 6.3 综合判断与未决问题

**多研究共同支持的机制**：

- 问题反转 + 答案难以直接检索，是构造高难度开放 Web 任务的有效手段（BrowseComp 与本文一致）；
- 开放 Web 上人类表现天然有上限（BrowseComp 29.2%、OpenDS 21.1%），模型系统可超越人类求解率（BrowseComp Deep Research 51.5%、OpenDS GPT-6 Astra 39.0%）。

**仍属合理推测的部分**：

- "三属性叠加 → 强制工具协调 → 暴露短板"的具体传导路径是本文数据支撑下的结构化解读，但论文未做逐属性受控消融（无法把 39% 的缺口精确分解给模态/格式/访问各自贡献多少）；
- 模型反超人类的成因中，"人类禁用 LLM 工具"的设定影响多大，论文无法单独量化。

**优势成立条件与可能失效条件**：

- 基准难度依赖真实 Web 的动态性——若目标源改版/失效，题目可解性会漂移（论文用视频归档缓解锚点问题，但证据链仍依赖在线源）；
- 39% 的天花板反映的是 2026 年 10 月的前沿模型；随着多模态 agent 训练进步，天花板会被推高（参照 BrowseComp 从 51.5% 到 2026 年 90%+ 的轨迹）；
- 未决问题：资源消耗与准确率为何系统性不相关？答案质量与搜索轨迹之间的定量关系如何？论文自己指出 OpenDS-World 可作为递归自我改进（RSI）的天然试验场——200 个可验证任务 + 787 条验证源 + 完整执行轨迹，构成了可复用的反馈环境。

## 七、必要知识反推

假设让一个完全没有背景的人从头完成这项工作，最少需要掌握什么？

### 7.1 领域知识层

- **Web 信息生态的实际形态**：知道信息以什么模态、格式、访问方式分布（这是三属性分类法的经验来源——不理解 Our World in Data 这类"一页含 HTML+CSV+API+ZIP"的真实源，就设计不出 Figure 3 那样的属性框架）；
- **Wikidata/Knowledge Graph 基础**：锚点实体唯一映射 Wikidata 是保证无歧义指称的关键技术选择；
- **情报研究（OSINT）式的问题构造法**：从答案倒推约束链，是情报学与解谜题设计的成熟技巧，本文将其流程化。

### 7.2 方法论知识层

- **基准构造方法论**：任务反转、多源独立佐证、标注-验证分离（标注员与验证员、求解者完全隔离）——不掌握这些无法保证"答案唯一且不可直接检索"；
- **人类评测设计**：如何组织 50 人、1000 次独立求解并用求解人数校准难度分档；如何控制疲劳（每人只答一组）与污染（禁 LLM 工具）；
- **LLM-as-judge 评测协议**：语义等价判分的提示设计与局限；
- **行为轨迹分析方法**：工具转移矩阵、终止原因分类、失败恢复决策分布、预算耗尽分解——把 agent 评测从"看分数"升级到"看行为"。

### 7.3 工程知识层

- **统一 agent harness 的实现**：持久浏览器会话、元素索引化交互、下载工件读取、视频帧采样与字幕提取接口；
- **上下文与预算管理**：观察压缩规则（保留最近 4 条、截断旧观察）、图像上限、收尾阶段无工具作答——这些工程细节直接决定评测公平性；
- **可复现性工程**：输入视频本地化（input_video 保留 ID）避免依赖在线视频可用性。

### 7.4 知识融合的关键节点

1. **"研究难度 = 证据获取难度"的洞察节点**：把 IR 评测的关注点从"检索结果排序"移到"获取过程的模态/格式/访问三维属性"——领域知识（Web 生态）与方法论（基准构造）在此融合；
2. **"用人类求解数校准难度"的度量节点**：把主观难度变成客观分档（Low/Medium/High），让后续所有切片分析有了锚点；
3. **"行为诊断套件"的分析节点**：成本、工具构成、终止、恢复、预算五套分析交叉印证，把"模型不行"细化为"哪一环节不行"。

## 八、论文中可以提取的通用性灵感

**灵感 1：评测难度应压在"过程"而非"问题"上**

- 核心思想：一道题难，不是因为题面绕，而是因为获取答案所需证据的过程难。
- 论文证据：三属性（模态/格式/访问）覆盖率与难度分组强相关（High 组音频 22.4% vs Low 7.4%、ZIP 12.9% vs 1.9%）；最强模型也只 39%。
- 推广场景：① 教育考试设计（考信息素养而非记忆）；② 企业招聘测评（模拟真实工作流中的信息获取）；③ RPA/自动化工具测试（覆盖异构系统的访问路径）；④ 科研复现性评估（证据可获取性作为难度维度）。

**灵感 2：资源投入与产出脱钩是能力不成熟的信号**

- 核心思想：当"更努力"（更多调用/更多 token/更长时间）不再换来"更好"，说明系统瓶颈在决策质量而非执行量。
- 论文证据：Gemini 5.22 倍 token 换来更低准确率；Qwen3.8-Flash 89.94 次调用/题却垫底；工具失败仅 2.83–9.42% 调用却占 19.27–61.90% 时间。
- 推广场景：① 人效管理（加班时长与产出的相关性诊断）；② 推荐系统（曝光量与转化脱钩的归因）；③ 云成本治理（识别高消耗低回报的工作负载）；④ 自动驾驶测试（里程数与安全性的关系审视）。

**灵感 3：反转构造——从答案倒推相互依赖的约束**

- 核心思想：要造"无法走捷径"的任务，从已知答案出发反向构造一组缺一不可、单条不暴露目标的约束。
- 论文证据：阶段三问题反转后，任何单线索不能直接暴露答案实体，检索答案文本无法解题。
- 推广场景：① 出题/认证考试防作弊（防止搜题）；② 密码学与隐私（k-匿名约束设计）；③ 游戏谜题设计（线索链解谜）；④ 数据防爬（组合约束使单点抓取无效）。

**灵感 4：用人类求解分布做难度校准**

- 核心思想：难度不是标注员的主观判断，而是独立人类求解者的客观通过率分布。
- 论文证据：50 人 1000 次独立求解，按每题解出人数分 Low/Medium/High，三档模型准确率单调下降（39.66/23.50/16.76）。
- 推广场景：① 标准化考试等值化（锚题设计）；② 产品可用性测试（任务通过率分档）；③ 医疗诊断辅助系统评估（按病例难度分层报告性能）；④ 体育分级（段位系统）。

**灵感 5：失败的成本要用"占用资源占比"而非"发生频率"来度量**

- 核心思想：低频事件可能占用不成比例的资源，评估系统健康度要按资源占用加权。
- 论文证据：工具失败调用占比个位数，时间占比却达 19–62%。
- 推广场景：① SRE 事故管理（按 MTTD/MTTR 与影响时长排序而非事故数）；② 供应链风险（小概率高占用事件优先）；③ 个人时间管理（低频高耗时事务的识别）；④ 编译/CI 优化（按累计耗时找瓶颈而非报错次数）。

**灵感 6：为"递归自我改进"预留结构化反馈接口**

- 核心思想：一个可验证答案 + 标注证据链 + 完整执行轨迹的基准，天然构成 agent 自我改进的训练场。
- 论文证据：附录 E 明确论述 OpenDS-World 是 RSI 的天然试验场：可识别的重复失败模式、可迁移策略、可在新任务上验证的修订。
- 推广场景：① 教育（错题本 + 变式训练循环）；② 工业质检（缺陷模式库驱动的工艺迭代）；③ 自动化运维（故障模式库与预案自学习）；④ 游戏 AI（自对弈的奖励信号设计）。
