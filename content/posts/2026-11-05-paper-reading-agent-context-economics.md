## 〇、为什么把四篇放在一起读

Agent 落地到生产环境后，最先撞上的墙往往不是智力，而是账单。一次多步工具调用里，工具返回的原始观察可以占到第 4 步上下文的 96.7%（Coca-Cola 的实测数据）；一段长程任务的压缩摘要，用大模型逐 token 生成要花 60 秒以上（SpecCompact 用户研究的实测中位数 63.74 秒）；一个持久个人助理的每次查询都要为历史上下文付一遍钱（Route to Remember 测得全上下文方案单次评估烧掉 10.7 亿输入 token、23.4 GPU 时）；而想训练一个专用摘要器来省钱，又发现监督信号要么要人工参考摘要、要么要把下游 agent 拉进训练环（SUMONE 要解的死结）。

这四篇论文各自盯住这条成本链上的一环，合起来正好是一张完整的"上下文经济学"分工图：

| 环节 | 论文 | 核心问题 | 关键数字 |
|------|------|----------|----------|
| 表示：压成什么 | Coca-Cola | 工具输出必须以文本进上下文吗 | token 降 70.01%–89.24%，EM 反升 |
| 过程：压缩本身多快 | SpecCompact | 摘要生成的延迟怎么砍 | 加速 2.04–5.63×，用户实测 8.68× |
| 介质：记忆存在哪里 | Route to Remember | 权重记忆能否竞争力文本记忆 | OPSD 59.9% vs 检索 47.8%，读 token 少 5 倍 |
| 监督：摘要器怎么训 | SUMONE | 不依赖下游任务怎么学压缩 | 成本降约 75%–77%，性能仅掉 0.04 |

更耐人寻味的是四篇共享的一个方法论转向：**压缩目标的"任务对齐"正在被各种方式重新定义**。Coca-Cola 用"动作分布对齐"替代"文本重建"；SpecCompact 用"语义等价验证"替代"逐 token 无损"；Route to Remember 用"答案审计"替代"查询路由"；SUMONE 用"掩码可重建"替代"参考摘要模仿"。四个方向不同的工作，都在拒绝同一件事——把压缩当成与任务无关的通用文本处理。

另一个共同点是对"压缩有害精度"这一直觉的集体反叛。四篇的实验部分都出现了压缩后性能不降反升（或仅微降）的段落：Coca-Cola 在全部八个模型-数据集设置上 EM/F1 双双高于 Vanilla；Route to Remember 的权重学生（一种极端形式的压缩）超过了读全上下文的教师；SUMONE 在任务专属 RL 配置下甚至借助压缩拿到全场最佳的 0.68 resolved 率。去噪、抗干扰、强制抽象，这些压缩的副产品正在被系统性地转化为收益。

## 一、Coca-Cola：工具不必说文本

### 1.1 题目

"Tools Need Not Speak in Text"是一个直接的宣言式标题。当前所有 agent 框架（ReAct 范式及其后继）都默认工具返回值以离散文本 token 追加进上下文，这篇论文挑战的正是这个从未被质疑过的接口约定：工具与 agent 之间传递的"信息"，本质上只需要支撑后续决策，而不必是可读文本。副标题点明手段——Latent Context Compression，用连续潜 token 做上下文压缩。模型代号 Coca-Cola 是 Context Compression via Continuous Latent Tokens 的缩写展开。

标题的分量要在时间线里看。2024 到 2026 年，潜 token 研究已经在三个方向上成熟：潜空间推理（Coconut、CCoT、SoftCoT 让推理脱离自然语言链条）、agent 间潜通信（KVComm 直接交换 KV cache、LatentMAS 让异构多 agent 在潜空间协作）、潜记忆（MemGen 的生成式潜记忆、NextMem 的潜事实记忆）。唯独"工具到 agent"这最后一条信息通道还停留在文本时代——Coca-Cola 补上的是这块拼图。

### 1.2 背景

背景是 ReAct 范式下 agent 上下文的失控增长。论文给出了两个量化观察：

- **规模**：在网页搜索 agent 的真实轨迹中，工具返回占上下文的比重随步数单调上升——第 1 到 4 步的总上下文分别为 1,037 / 2,001 / 2,948 / 3,895 token，其中工具返回占 958 / 1,905 / 2,838 / 3,767，第 4 步时占比 96.7%；单次观察的长度分位数 p50=1352、p90=1776、p95=1861。
- **冗余**：这些 token 里真正对下一步决策有用的往往只有零星几个片段。论文举的例子是查"2016 马拉喀什 ePrix 冠军出生年份"，搜索结果里塞满比赛日期（2016 年 11 月 12 日）、赛道长度（2.971 km）、圈数（33 圈）、观众人数（7,000）、杆位得主（Felix Rosenqvist）、最快圈（Loïc Duval），而 agent 真正需要的只有"冠军是 Sébastien Buemi"这一句，据此发起下一次搜索"Buemi 出生日期"。

两个后果随之而来：计算开销膨胀（更长上下文直接推高 token 用量与延迟），以及任务性能退化（无关内容稀释注意力、干扰关键证据——正是"迷失在中间"与"无关上下文干扰"两条研究线早已证明的效应）。现有解法分两路：token 剪枝（LLMLingua 用语言模型估计信息量、LLMLingua-2 把压缩当 token 分类、LongLLMLingua 面向长上下文提高任务相关信息密度）和文本摘要（RECOMP 生成查询相关摘要、Search-o1 用 Reason-in-Documents 模块提取、ACON 联合压缩观察与历史并按失败 refining 指令），但两者的输出仍然是离散 token 序列，必须保持语义连贯，压缩比存在天花板。

### 1.3 定位

这项工作的定位是一次表示层的越界：把潜 token 的三个成熟分支延伸到"工具到 agent"通道上。与最接近的先行者 ICAE（上下文自编码器，用自编码架构把长文本压成少量连续向量、训练语言模型利用这些向量）相比，差异在训练目标：ICAE 及其同族（Gist Tokens、AutoCompressor、500xCompressor）学的是"保留或重建原始文本信息"，Coca-Cola 学的是"保住下一步动作"。作者在贡献声明里说得明确：这是第一个认识到工具不必以显式 token 传递信息并进行潜压缩的工作。值得注意的是"无搜索特定设计"的声明——压缩器只条件化于任务指令、当前推理轨迹与原始观察，因此可以直接迁移到其他工具而无需改架构。

### 1.4 问题定义

形式化地，ReAct agent 在第 t 步的上下文长度近似为 K_t ≈ |q| + Σᵢ(|rᵢ|+|aᵢ|+|oᵢ|)，其中观察项 oᵢ 是增长主力。压缩问题定义为学一个函数，把 (q, h_t, o_t) 映射为潜 token 序列：

z_t = A_φ(C_θ(q, r_t, o_t)) ∈ R^{m×d}

插入 agent 输入嵌入空间后，agent 以 a_{t+1} ~ p_ψ(·|q, h_t, z_t) 选择下一动作。两个核心子问题是：(1) **跨空间可用性**——小模型编码器的隐状态如何被异构的目标 agent 直接消费；(2) **表示预算下的信息保真**——m 个潜 token 里该留什么、丢什么的判据是什么。

论文还给了理论动机，这个分析值得完整转述：对词表大小 |V| 的模型，每个文本位置只能从 |V| 个符号里选一个，n 个 token 的码本容量至多 C_text(n) = n·log₂|V|；而一个 d 维潜 token 有 d_eff ≤ d 个有效坐标，每个坐标在有限精度下有 B 个可分辨取值，m 个潜表示的容量为 C_latent(m) = m·d_eff·log₂B。当 d_eff·log₂B > log₂|V| 时，同样的输入位置预算（m = n）下连续潜表示容量更大——**容量优势来自多坐标联合编码，而每个文本位置永远受限于固定词表里的一次符号选择**。当然作者也坦承：这只是可行性论证，实际可用信息还取决于压缩器的编码能力与 agent 的解码能力。

### 1.5 解法

架构上是三件套：

1. **上下文感知编码器** C_θ：一个小语言模型联合编码任务指令 q、当前步推理轨迹 r_t 和工具观察 o_t，产出上下文条件化的隐状态 H_t = C_θ(q, r_t, o_t)。条件化是必要的，因为同一观察在不同任务下的决策相关性完全不同——同一份酒店搜索结果，"找评分最高的"和"找最便宜的"需要保留的字段不同。
2. **潜适配器** A_φ：把 H_t 变换为固定数量（m 个）潜 token 并线性映射到目标 agent 的嵌入维度 d。推理时以特殊边界标记 ⟨latent_obs⟩…⟨/latent_obs⟩ 直接插入 agent 的输入嵌入序列 X_t = [E_ψ(q, h_t); E_ψ(⟨latent_obs⟩); z_t; E_ψ(⟨/latent_obs⟩)]，agent 主干完全不动——这保证了方法的模型无关性（只要能拿到嵌入接口）。
3. **动作保持训练**：把完整观察 o_t 与潜压缩 z_t 分别喂给**同一个冻结的目标 agent**，得到下一动作分布 p_full = p_ψ(·|q, h_t, o_t) 与 p_latent = p_ψ(·|q, h_t, z_t)，以联合损失优化：

   L = λ_KL·D_KL(p_full ‖ p_latent) + λ_CE·CE(y_{t+1}, p_latent)

   KL 项对齐动作分布（压缩前后 agent 行为不变），CE 项用轨迹里记录的真实下一动作 y_{t+1} 做锚定监督。由于潜 token 连续可微，梯度 ∇L 可以穿过冻结的 agent 回传到压缩器（链式法则经过 ∂z_t/∂(θ,φ)）；训练只更新编码器的 LoRA 参数（rank 16、scaling 32、dropout 0.05）和适配器参数，优化器为 paged 8-bit AdamW，学习率 1.5×10⁻⁴ 线性衰减到 5×10⁻⁵，λ_KL=0.3（前 20% 步数预热）、λ_CE=1.0。训练数据从 4,188 个任务构造出 4,363 个观察-动作对（3,927 训练 / 436 验证）；推理配置为每次工具调用压成 128 个潜 token、每次任务最多 5 次搜索、每次取 5 条结果；硬件为 4×A100-80G（3 卡放冻结 agent、1 卡放压缩器）。

实验覆盖两组模型对（Qwen3.5-35B-A3B 配 Qwen3.5-4B、GLM-4.7-Flash 配 GLM-Z1-9B——每组内编码器用小模型、agent 用大模型）× 四个 QA 基准（NQ、TriviaQA、2WikiMultiHopQA、HotpotQA，前两个单跳、后两个多跳）。结果分三面：

**效率面**（相对 Vanilla）：

| 指标 | Qwen 系（四基准） | GLM 系（四基准） |
|------|-------------------|------------------|
| 输入 token | -71.3% 到 -87.7% | -75.5% 到 -90.5% |
| 总 token（压缩率） | 70.01%–83.68% | 73.73%–89.24% |
| 端到端时间 | -24.4% 到 -32.8% | -41.6% 到 -56.0% |

代表性数字：NQ+Qwen 输入从 14,362.12 降到 1,766.53（-87.70%）；2Wiki+GLM 从 31,693.47 降到 3,003.38（-90.52%）；2Wiki+GLM 运行时间从 106.37 秒到 46.83 秒（-55.97%）。

**性能面**：八个模型-数据集设置里 EM/F1 全部高于 Vanilla。亮点在多跳：HotpotQA+Qwen 的 EM 从 11.00 涨到 25.70（+133.64%）、F1 从 16.41 到 33.75（+105.67%）；2Wiki+Qwen EM +38.73%。对四个基线（Vanilla、LongLLMLingua、LLMSummary、ICAE），16 个数据集-指标对里拿了 13 个最高，8 个模型-数据集组合里 6 个双指标最佳（含 GLM 全部 4 个）。与 ICAE 的对照最有说服力——两者架构完全相同，仅训练目标不同（文本重建 vs 动作保持），ICAE 在全部八个设置里压缩率都更低（如 2Wiki+GLM：74.12% 对 89.24%）；LLMSummary 在剩余三个设置里压缩率略高但性能全面落后（如 NQ+GLM：EM 16.00% 对 Coca-Cola 23.50%）。

**消融面**：潜 token 数 m ∈ {8,16,32,64,128} 各训一个压缩器，F1 从 26.34% 稳定爬到 31.45%，压缩率在 m≤64 时保持 78.83%–82.56%、m=128 时降到 73.73%（默认取 128 换性能）；条件化信号逐项拆除——去推理状态（q,o）EM 掉 2.05 点、去任务目标（r,o）掉 3.48 点、只留观察（o）掉 5.16 点；而即便 Observation-only 变体（EM 18.34%、压缩率 79.94%）也在两个维度上同时优于全部压缩基线（最佳基线 EM 17.00%、压缩率至多 74.62%）——功劳再次记在动作保持训练上，而非架构或条件化。

### 1.6 知识反推

从结果反推因果链，Coca-Cola 的收益有三个相互咬合的来源。

第一，**容量优势兑现为压缩率**。多坐标联合编码让 70%–89% 的压缩率成为可能，这是文本方法（LongLLMLingua 在八个设置里只有 35.92%–78.90%）够不到的区间。压缩率的天花板差异不是工程优劣，而是表示形式的数学性质。

第二，**目标对齐避免了"重建冗余"**。ICAE 对照是全文最干净的一组实验：同样的架构若以恢复原始观察为目标，会把宝贵的表示预算花在赛道长度、观众人数这类决策无关内容上——ICAE 在 TriviaQA+Qwen 上 EM 反而最高（61.80% 对 59.20%），但其压缩率只有 66.92% 对 83.68%，省不下来的 token 最终抵不过性能持平。动作保持训练让压缩器只留"下一步要用的东西"，这是压缩率与性能能同时赢的根本原因。

第三，也是最有意思的一点：**压缩本身就是去噪**。EM 不降反升（尤其多跳任务翻倍级提升）说明，原始观察里 96.7% 的工具 token 不但在花钱，还在稀释注意力。案例研究（HotpotQA #377，"Jens Risom 引入了哪种以极简和功能性为特征的设计"）给了具体机制：搜索结果同时包含"他是 Mid-Century Modern 的重要塑造者"与"他最早把斯堪的纳维亚设计引入美国"两条信息，Vanilla 在两条之间摇摆、多搜一轮后仍答错（Mid-Century Modern）；Coca-Cola 的潜 token 直接锚定问题相关的证据，少一轮搜索答对（Scandinavian design）。长上下文文献里的"迷失在中间"效应，在这里以反向方式被利用了——删掉干扰，比加长窗口更能提分。

值得记下的还有论文的诚实边界：Coca-Cola 需要为目标 agent 训练专属压缩器（跨 agent 迁移性未讨论）；训练依赖采集好的工具使用轨迹（4K 级别的观察-动作对）；潜 token 不可被人阅读审计，部署后的可解释性、安全性检查（比如工具观察里被注入的恶意指令在潜空间里如何表现）是开放的暗面。

### 1.7 通用灵感

跳出 agent 压缩本身，这篇论文至少给出三个可迁移的想法。

其一，**接口约定的隐含成本值得定期审计**。"工具返回文本"是继承而来的默认值，从未有人证明过它最优；类似的无声约定还有"检索结果必须原样进 prompt""多 agent 通信必须走自然语言""思维链必须是可读文本"——都是潜在的潜空间化对象。审计的方法也简单：问一句"这个格式的消费者究竟需要什么"。

其二，**有损压缩的正确损失函数应由下游定义**。"对齐动作分布而非重建输入"这个思路可以平移到任何中间表示的设计上：检索器该对齐最终答案的支撑性而非查询相似度，记忆系统该对齐未来调用模式而非过去原文，特征抽取器该对齐决策边界而非输入重建。凡是被"重建损失"卡住压缩率的地方，都值得找一次下游对齐。

其三，**"不可读但可用"开辟了新的系统分层**。当信息只需服务机器决策时，可读性这一约束可以整体卸下；码本容量分析提供了一个估算收益上限的干净框架（d_eff·log₂B 对 log₂|V| 的比较可以粗算任何嵌入维度与词表规模组合下的理论增益）。同时要记住硬币的另一面：不可读意味着不可审计，在安全关键场景这是决定性的反向约束。

## 二、SpecCompact：压缩本身也要快

### 2.1 题目

标题的主干是 Accelerating LLM Agent Context Compaction——注意它加速的不是 agent，而是"上下文压缩"这个动作自身。当 Codex、Claude Code、Hermes 这类生产级 agent 都把周期性摘要作为标准件之后，一个此前被忽略的成本浮出水面：用大模型把长历史总结成摘要，本身要读一遍长上下文再逐 token 解码，用户在 agent 干活的中途要为这一次"整理内务"干等几十秒。方法名里的两个关键词 Slot-Parallel（槽并行）与 Semantic Speculative Verification（语义投机验证）分别对应论文的两个加速来源：把摘要拆成可并行的槽、把逐 token 验证放宽为语义级验证。

### 2.2 背景

背景是 compaction 已经成为 agent 框架的标配但代价高昂。OpenClaw 和 Hermes 等框架都采用结构化摘要模板，把总结组织成 Goal、Constraints and Preferences、Progress、Key Decisions、Next Steps、Critical Context 六个字段（Hermes 还多一个 Files 字段）。加速生成的现成工具是投机解码：小模型起草、大模型单次前向验证，保持目标分布无损（Leviathan et al. 2023 的经典框架）。但直接套用有两个不匹配：其一，有效摘要本就允许措辞不同而信息等价，逐 token 无损验证过严，浪费了这种自由度——近期的语义投机工作（SpecReason 用目标模型裁决完整推理步、DREAM-R 用 RL 对齐 drafter 并完全并行化起草与验证）已把验证放松到句子级，证明"有损但快"在推理加速上成立；其二，即便句子级投机，对单一长摘要仍是串行生成——一个摘要写完才能写下一个。异步与并行压缩的先例（Slipstream 让压缩与 agent 继续执行重叠、Parallel Compaction 分块并发总结）提出了更进一步的问题，也正是论文的切入点：**摘要自身的结构能否指导并行生成与目标模型验证？**

### 2.3 定位

定位上，这篇工作站在三条线的交叉口：投机解码/语义投机（提供验证机制）、异步与并行压缩（提供"压缩可以与执行重叠或分块并行"的先例）、结构化摘要模板（提供并行单元）。它的独特一步是把 OpenClaw 的六槽 schema 从一种输出格式，升格为并行度的来源——模板不再只是给下游 agent 看的组织方式，而成了生成调度的骨架。这属于系统与算法的协同设计，而非纯算法创新；论文自己的表述是"结合训练、并行起草与逐行语义验证加局部修复，并优化执行以减少重复上下文处理与模型调用"。

### 2.4 问题定义

前置的实证问题是：槽位不依赖其他槽的输出能否独立生成？作者在 LiveClawBench 的 100 条轨迹（每条六槽、共 600 个槽）上做了对照——单体生成（一次输出全部六槽）平均充分性 4.44 分，独立生成（每槽只看共享历史）4.73 分，得分 ≥4 的槽占比 85% 对 93%（评分由 LLM 裁判按五条二值准则求和给出）；把单体生成的槽顺序、或独立生成的调用顺序反转，均分变化不超过 0.03。这个"顺序无关、独立不劣"的双重验证支撑了核心设计决策：**槽是天然的并行单元，验证与修复应在槽内进行而非全局串行**。优化目标随之清晰——在保持摘要信息保留质量的前提下，最小化压缩的端到端延迟。

### 2.5 解法

方法分三层。

**槽条件化起草**：用目标模型配合生成提示离线产出各槽内容，SFT 微调一个 Qwen3-0.6B 小模型作为 drafter。训练数据约 5 万条，来自 AppWorld、τ³ 与 LiveClawBench 轨迹；每个历史-槽对一个训练样本（T 条历史产出 6T 个样本），损失只在目标槽内容 token 上计算交叉熵。语义投机不要求 drafter 与目标共享词表——这是相对原始投机解码的一个重要解绑（原始框架要求小模型与大模型同词表才能做分布校正）。每个请求包含共享历史与完整 schema，但只要求生成指定槽；槽契约规定内容与格式（如 progress 槽要求 Done/In Progress/Blocked 三段、critical_context 槽要求保留精确文件路径与错误消息）。

**逐行语义验证与局部修复**：drafter 自回归产出一行即提交，目标模型判断"该行内容是否被历史支撑且与已接受前缀一致"，输出 positive/negative 一个判断 token。从 top-k token 概率取两个标签各自的最大概率（同标签的多种 token 形态——大写开头、带前导空格——取最大者；缺失时用剩余概率质量与最小返回概率的较小值代理），归一化得接受分 r = p̂⁺/(p̂⁺+p̂⁻)，r ≥ η（取 0.7）则整行接受；否则目标模型就地生成替换行（拒绝行不进输入），更新后的前缀 A_{s,t} 继续条件化后续起草——drafter 始终从"摘要里已保留的内容（含目标模型的修复）"继续。

**系统优化**是工程亮点，五项合力：

1. 独立槽调度：六流并发，各自维护已接受前缀与串行的提出-验证-修复循环；某槽等验证时其他槽继续起草或提交验证，drafter 与目标的工作得以重叠，服务端可跨槽批处理。
2. 共享前缀缓存：历史 + 全部六槽契约组成公共前缀，验证与修复请求都挂在这个前缀之后，前导 token 跨槽跨步不变，避免每次一行验证都重新 prefill 几万 token 的历史。
3. 草稿缓冲：drafter 一次生成多行缓存，首行送验证；接受则缓冲行免再调用，修复改了前缀则整批丢弃重写（复用要求生成前缀与当前已接受前缀精确一致）。
4. 行感知停止：修复只生成到下一个换行符（把所有以换行结尾的 token 设为停止集、保留其中的文本），不解码用不上的后续行。
5. 检查与终止：重复行或超字符上限直接送修复（省一次语义验证调用）、`#` 开头标题与 `(none)` 空标记免验证直接接受、每槽 12 行 320 token 上限、总摘要预算 2,048 token 超限报错。

部署配置：vLLM 服务（NVIDIA RTX PRO 6000 Blackwell），Gemma4-31B-IT 单卡 BF16、Qwen3.5-122B-A10B 双卡 FP8、drafter 独占一卡；每 8 次 agent 模型调用触发一次压缩（保留系统与 setup 消息及当前输入）；起草与修复每次最多 64 新 token、验证只出 1 token。

结果分四块。**延迟面**（20 条匹配输入）：相对 Hermes 式摘要化，Gemma4 加速 4.28–5.63×（AppWorld Normal 38.89→8.26 秒、Challenge 39.12→9.14 秒、τ³ 36.21→6.43 秒、LongBench-16k 74.13→29.72 秒），Qwen3.5 加速 2.04–2.41×；对 OpenClaw 则 8 个设置里 7 个更快（唯一例外 Qwen3.5+τ³：8.71 对 7.68 秒）。**系统优化独立贡献**：在都已经槽并行的前提下，五项优化再叠 1.19–2.44×（Gemma4 AppWorld Normal 从 20.17 到 8.26 秒、Qwen3.5 从 9.55–11.43 到 7.49–8.71 秒）。**真实部署**：嵌进 Hermes 代码库、Gemma4 四卡、编码/数学/多任务三场景、同一上下文快照盲测，压缩中位延迟从 63.74 秒降到 7.28 秒，中位配对加速 8.68×；摘要质量盲评 28 份回应里 39.3% 偏好 SpecCompact、28.6% 偏好 Hermes、28.6% 认为相当、3.6% 无法判断。**下游性能**是模型依赖的：Qwen3.5 上 SpecCompact 比 Hermes 的 AppWorld Normal/Challenge TGC 分别高 4.76/1.68 点、τ³ 成功率高 0.83 点（Challenge SGC 微降 0.72 点）；Gemma4 上 TGC 低 2.98/4.07 点、τ³ 低 2.50 点。长上下文面（LongBench GovReport/QMSum 的 ROUGE-L 与 RULER 8k/16k）：Qwen3.5 上与 Target-self（目标模型直接生成各槽）差距 ≤0.6 点且两个 RULER 长度上反超（74.23/72.60 对 72.98/72.15）；Gemma4 上差 0.83–4.50 点。

### 2.6 知识反推

加速从哪里来？拆开算有三层来源。

第一层是**结构并行**：独立生成实验证明槽间无信息依赖（反转顺序均分变化 ≤0.03），六槽从共享历史同时起草，把"串行等六份摘要"变成"等最慢的一份"。这一层的前提——"每个槽的信息可以从历史独立恢复"——是摘要模板设计者没有预料到的副产品。

第二层是**语义验证的高接受率**：摘要任务恰好落在语义投机的甜区——目标模型只裁决"行是否被历史支撑且与前缀一致"，这种二元判断比逐 token 匹配宽松得多，drafter 的小模型草稿大量被整行放行，目标模型的调用从"生成全部"退化为"裁决加偶尔修复"。反过来，这正是摘要与推理链的区别：推理步的正确性有唯一性约束，摘要的措辞自由度天然更大。

第三层是**系统消垄**：共享前缀缓存消灭了重复 prefill（否则每次一行验证都要重读几万 token 历史——"哪怕验证只回一个 token 也要一次昂贵 prefill"是论文点名的痛点），行感知停止消灭了修复时的无效解码，草稿缓冲摊薄了逐行调用开销——三项合计再贡献约 2 倍，说明纯算法并行只拿到一半收益。

Qwen3.5 上加速缩水到 2 倍出头的三个原因同样有启发性：基线本身更快（122B 大模型的摘要化在 FP8 双卡上已经不慢）；0.6B drafter 模仿 122B 目标的规模差距导致接受率比特 Gemma4 低 19.6 个百分点；混合注意力（线性注意力层需要从检查点恢复递归状态，文本前缀匹配不再保证缓存可复用）使共享前缀缓存的收益大打折扣——最后一点是新型架构对经典系统优化的侵蚀，值得所有依赖 prefix caching 的推理基础设施团队警惕。

而下游性能的模型依赖性（Qwen3.5 上反而更好、Gemma4 上变差）提示：加速机制会改变摘要内容（哪些行被接受、哪些被修复），这种改变的净效应取决于目标模型对摘要风格的敏感度。论文讨论节的坦白——"不提供相对目标模型摘要化的一致精度优势，更好的 drafter-目标对齐（如 DREAM-R 的 RL 路线）可能改善权衡"——是少见的诚实，也直接指出了后续工作方向。另一个来自讨论的洞察是信息分布的槽间差异：Progress 与 Decisions 的证据散布全文，Goal、Constraints、Next Steps 主要依赖首尾——这为"槽条件化滑动窗口注意力"提供了设计依据。

### 2.7 通用灵感

可迁移的启发有三条。

其一，**输出结构是免费的并行度**。只要输出可以分解为彼此弱依赖的单元（模板字段、章节、要点、检查项），"先验证独立性、再并行生成、单元内验证修复"就是通用加速范式。摘要之外的候选场景：结构化数据抽取的多字段抽取、多维评估报告的并行打分、测试套件的分片执行。关键动作是先做那组"独立生成不劣于单体、顺序反转不敏感"的预实验——它同时验证了可行性并给出了性能下界。

其二，**"无损"约束该在哪儿松手是个设计决策**。投机解码的逐 token 无损在数学上优雅，但多数下游只需要语义等价；把验证粒度从 token 放宽到行、把等价判据从分布相同放宽到"被证据支撑且与前缀一致"，加速空间立刻打开。松手的代价（下游性能模型依赖的漂移）要像论文一样用分离评估（compaction 加速与下游任务分开测）来监控。

其三，**算法收益要靠系统兑现**。同样六槽并行，不做前缀缓存与行级停止只有一半速度。"每槽 12 行 320 token"这类预算约束配上重复检测与终止规则，是防止投机机制被退化输出（重复行、无限生成）劫持的必要护栏——投机系统的鲁棒性设计常被论文省略，这里是完整范本。

## 三、Route to Remember：记忆写进权重，读时再审计

### 3.1 题目

"Route to Remember"一语双关：字面是"记得走的路线"，实指为每条查询在两种记忆之间路由（route）以达成记住（remember）。标题浓缩了论文的双重主张——权重记忆经过正确训练可以成为有竞争力的长期事实存储（Remember 部分），而它无法自我修复的盲区要靠路由机制补上（Route 部分）。这篇来自 George Washington University 与 Amazon 的产学合作，发表在 NeurIPS 2026 的个性化长期记忆 workshop，选题直指生产级持久 agent 的记忆瓶颈。

### 3.2 背景

生产级 agent 的记忆几乎全部以文本形态存在：从超限上下文里抽取要点、写成自然语言句子外部存储、查询时按相关性检索回 prompt（A-MEM 的原子笔记加演化链接、Mem0 的知识图谱、Li 等人的 MemOS 操作系统抽象）。这个设计的每一步都在收费——每次查询都要付出检索延迟与上下文 token，且存储在涨而窗口不涨，检索质量最终成为精度的约束瓶颈；综述们从反方向得出同一结论：巩固、更新、遗忘远比检索不发达，更长的窗口不是记忆系统的替代品。

权重记忆（把知识内化进模型参数）是教科书式的替代：查询零上下文、边际成本与对话长度无关，写入才需一次训练。但这条路布满前车之鉴：模型编辑方法（定位并覆写前馈权重）在数千次编辑后退化；LoRA 作记忆库的实证研究发现容量随 rank 增长但对逐字回忆的迁移有限；早期的权重记忆尝试在剥夺上下文的推理条件下表现糟糕。近期的自进化 agent 工作复兴了在策蒸馏（OPD-Evolver 蒸馏事后诸葛亮教师、KBSD 用信息不对称自蒸馏校准搜索行为），但都聚焦技能内化，且没有把记忆本身从 harness 里隔离出来。此前最接近的诊断研究（Deng 2026 的基底不对称性）对比每用户 LoRA 与检索，结论是互有胜负、参数记忆追不上文本系统——留给本文的问题正是：**参数记忆在情景与语义回忆上到底能被推多远，需要什么配方**。

### 3.3 定位

这篇论文的定位是一项"配方正名"研究加"架构组合"研究。正名：证明权重记忆此前的劣势应归咎于训练目标（SFT）而非存储介质，on-policy 自蒸馏才是内化情景/语义记忆的正确方式。组合：承认权重记忆有两个训练解决不了的先天缺陷（随更新遗忘旧事实、感知不到"从未记录"而虚构），设计 verify-then-regenerate 路由让两种介质各守其长。与蒸馏系自进化工作的差异在蒸馏对象——教师的特权是用户记忆的近期有界窗口（而非事后信息或搜索提示），学生推理时无上下文，目标是特定用户的情景/语义记忆而非技能或搜索策略。评估协议的完备性也是卖点：配对 McNemar 检验、按用户聚类的 bootstrap 置信区间、逐用户差值，"不让任何结论依赖单个用户的行为"。

### 3.4 问题定义

问题设定在一个用户跨会话的时间序列上：历史为会话序列 S₁…S_T，每会话结束写一次记忆、读多次（每个会话后都做问答评估）。两种记忆消费同一中间表示——基模型把每会话对话抽成带时间戳的记忆点叙事句。文本系统直接存检这些句子；权重系统把它们增强成三类 QA 对并转成训练监督：**Paraphrases**（多措辞问同一事实，让模型泛化到表面形式之外而非死记一种问法）、**Counterfactuals**（陈述错误事实要求纠正，教模型应对假前提问句）、**Unknowns**（问从未记录的属性要求显式拒答——后文将证明这是拒答能力的唯一来源）。评估在 HaluMem 基准上逐会话进行，题分六类：基础事实（311）、记忆冲突（304）、动态更新（94）、多跳推理（79）、泛化应用（311）、记忆边界（339，该拒答的 OOD 问题）；主读模型 Qwen3.5-9B，裁判 Claude Sonnet 4.6（correct/hallucinated/omitted 三态、无部分分）。保留研究用补充协议把每题在 20/40/…/100 会话后重问，画出各系统的遗忘曲线。

### 3.5 解法

**OPSD（on-policy self-distillation）**：训练每用户 LoRA 学生（rank 64、α=128，每会话 30 轮、每轮采样 60 个在策问题、adapter 跨会话持久累积）在无上下文条件下复现教师的输出；教师是同一个基模型条件于近期有界记忆窗 M_t——当前会话记忆点永远保留，再尽量塞最近的旧会话（12,000 字符上限、整会话丢弃凑预算）。损失是学生自身采样分布上的逐 token KL：L(θ) = E_q E_{y~πθ(·|q)} Σᵢ KL(π_base(·|q,M_t,y_<i) ‖ πθ(·|q,y_<i))。**在策采样是关键**——离策变体（教师强制教师原文）47% 且遭受曝光偏置与复读循环，在策版 61% 且生成干净。

两个被消融证明生死攸关的设计：教师必须始终用冻结基模型而非累积学生快照（自然的自蒸馏选择会让错误跨会话复利、遗忘曲线晚期崩塌；换冻结教师读封顶记忆约值 +14 点，泛化类 20→50、基础事实 56→78）；问题池保持固定或温和增长（对抗性出题器——用 GRPO 训练最大化学生-教师 KL 的提问者——单会话探测有用、跨会话反噬至 26%：难度追逐的奖励让生成池塌缩到单一题型、饿死多样性；课程扩容到 1000+ 问题同样稀释原生事实。教训：**出题者该拓宽对已记录事实的覆盖，而不是最大化难度**）。检索与 MemOS 基线及 VtR 路由共用 Qwen3-Embedding-0.6B 余弦 top-5。

**VtR（verify-then-regenerate）路由**：权重记忆先作答 ŷ；用 q 与 ŷ 双键各检索一次**合并后的**文本库（superseded 值已整合进相关陈述或整体替换——不合并的话三分之一裁决回来是冲突，合并后压到约 1%）；廉价验证器（三分类头，不是第二个 LLM agent）对照答案锚定证据判 supported/conflicting/unsupported；仅后两者触发再生成——由**不带 adapter 的基模型**基于双证据集重答（每个记忆点带时间戳、指示依证据作答），回退路径纯文本、不继承审计要抓的虚构。两个检索键刻意分开：审计该看"实际声称了什么"，再生成该看"问题使什么可答"，两集合仅部分重叠。

结果分四层。**主对比**（HaluMem 原生题 n=1438）：OPSD 59.9% 超过全部文本基线——提取记忆进上下文 51.9%、原始对话 51.3%、MemOS 检索 47.8%（领先检索 12.1 点，用户聚类 CI [9.4, 14.8]，8/8 用户为正、逐用户差值 7.1 到 18.1 点，配对下 OPSD 独有正确 309 题对检索 136）；oracle 上界 GT 记忆点 64.0%。最有杀伤力的对照是 SFT：同数据、同表示、仅换目标，36.9%，低于全部文本基线。VtR 再加 6.2 点到 66.1%（p=2×10⁻⁶，CI [3.6, 8.6]），六类中五类改善（边界 +17.7 到 99.4%、多跳 +12.7、泛化 +9.3、动态 +5.3、基础 +4.8，唯冲突 -9.9），且在每个年龄上都优于两个单系统。**成本结构**（读写分离）：权重记忆读侧每查询仅 326K 总输入 token / 1.0 GPU 时，对比检索 1.7M / 0.9、提取记忆 1.03B / 22.5、原始对话 1.07B / 23.4——比全上下文低四个数量级、比检索低五倍；写侧则贵：提取（30.2M in/12.0M out，共享）之外再付 QA 增强 + 蒸馏（OPSD 额外 76.5M in/31.4M out）。crossover 测算：对全上下文约 600 次查询回本（每查询省约 2.4×10⁵ 输入 token），对检索要十万次量级（每查询仅省约 310 token）。VtR 读成本介于两者之间（1.3M in，门槛放行 38% 查询）。**遗忘曲线**：上下文方案断崖（原始对话 age 40 崩、提取记忆撑到 60——越压缩的表示断崖来得越晚），权重平滑衰退（59.9→32.4@80），检索几乎水平（47.8→40.1@80，top-5 抓取对事实年龄无感）——权重优势集中在近期，约二十会话后检索反超；合龄集合上 MemOS 总分反超 OPSD（46.1 对 43.7）。**遗忘的非均匀性**：边界类（拒答习惯）跨龄存活（81.7→88.1@100），全部内容类塌向地板（泛化与多跳 age 100 归零）；幻觉率从 33.0% 爬到 50%+ 而省略几乎不动——模型变得自信地错，而非恰当地谨慎。跨规模（4B：57.4 对检索 45.6；27B：62.6 对 47.4——**底座越小 OPSD 优势越大，9B 上 +8.0、4B 上 +9.4、27B 上 +1.2**）与第二基准 LoCoMo（OPSD 46.9 vs MemOS 31.3/SFT 16.9/提取 46.4；VtR 60.4 全场最佳、对抗类 73.1）排序复现。路由设计的负结果同样精彩：查询-记忆相似度对正确性零信号（权重记忆正确/错误答案的 top-1 相似度 0.735 对 0.741、检索 0.737 对 0.737——所有阈值退化成永远选更好的系统）；查询嵌入分类器至多 +0.9 点、原始嵌入反而有害；自洽性在边界类反转（95–99% 一致性桶 0.971、完美一致性桶崩到 0.404——确定性的错误值完美重复而真实的拒答措辞多变）；逐 token 置信度与答案长度相关 0.65（两类别的长度-正确性符号相反，单一全局探针平均掉两个相反效应后 AUC 仅 0.63）；长度固定的拒答串探针检测"可答性"AUC 0.918（在 OPSD adapter 下依旧 0.918，证明读的是参数知识状态）、但检测"答错"仅 0.516（碰运气）——**一切只看问题与模型内部状态的信号都失效，因为它们都看不到实际产出的答案**，这正是 VtR 形态的由来。

### 3.6 知识反推

OPSD 为什么能力压 SFT 23 个点？表层机制是在策采样让学生在自己会犯错的分布上接受教师打分，规避曝光偏置与复读循环。更深一层，学生为何能超过自己的教师（59.9 对 51.9）？论文给的三解释都站得住：(i) 多措辞训练平均掉了单条提取语句的噪声——心理学意义上的巩固；(ii) 免于上下文内搜索——学生从不需要在上百条干扰语句里定位答案，而全上下文方案的幻觉率 33–34% 恰好卡在这种搜索上；(iii) adapter 跨会话持久，保住了早已滑出任何单个教师窗口的事实。第三条尤其微妙：**教师每轮只见近期窗口、学生积累全部历史，蒸馏的是"教师的推理方式 + 超越教师窗口的持久化"**。

权重记忆的两个先天缺陷为何恰好是文本的领地？遗忘是参数更新的数学性质（后面会话的训练集覆写前面的事实，如用户搬家），而检索列表对事实年龄无感；"从未记录"在参数里无物可查——模型会给没记录的属性编造具体的薪水与体重、同一问题跨年龄不一致——而文本系统读一眼空列表就能报告缺失。论文说得很准：**是可检查性而非知识量的差异**。LoCoMo 上全部范式的对抗类都在地板（2.5–10.6）复现了同一结论。

VtR 的有效则源于一个精巧的检索论：用生成的答案而非原始问题做检索键，等于让权重记忆先把问题映射到"记忆点本身所在"的语义区域——陈述句对陈述句的匹配比问句对陈述句好做得 多，直接削减检索噪声。合并存储把假冲突从 36% 压到 1%，说明路由的成败一半系于上游数据治理。门控账本也值得看：放行 22% 为 SUPPORTED（正确率 61.8→65.6）、再生成 77%（38.5→54.1，修复 814 / 破坏 277、净 +537、对已对答案 21% 的损坏率）——再生成不是免费的，但净收益显著为正。

另外两个值得收藏的细节：去除 Unknowns 增强，边界类从 88% 崩到 1%、总体掉 14–16 点、幻觉率升至约 60%——**拒答是学出来的习惯，不是参数存储的副产品**；加倍 unknown/counterfactual 预算反而净负（边界 +5 但泛化 27→18、多跳 33→22）——增强配方有最优点。还有对抗遗忘的失败实验：SFT-replay 重放缓存答案帮到远尾（age-100 27→32%）但击穿动态更新（重放已被取代的值等于重教过期事实）——权重记忆与易变事实的相互作用里有结构性陷阱。 rubric 的诚实审计同样值得学习：动态更新与多跳两类 56% 的全方法失败（含看全文的全上下文）里约一半是金标或评分问题（34% 金标不可从引用证据恢复、11% 逐字说出金标仍判错）——论文主动把 0.24–0.30 的分数放在 0.39–0.48 的可达天花板下解读。

### 3.7 通用灵感

三点超出记忆领域的启发。

其一，**介质换挡的临界点可以精算**。写贵读贱对写贱读贵的成本结构互补，"每份记忆约 600 次查询回本（对全上下文）、十万次量级（对检索）"这类 crossover 公式适用于一切有读写不对称的架构决策——物化视图 vs 即时聚合、预计算索引 vs 全表扫描、模型蒸馏 vs 大模型直呼。论文还点出权重记忆的天然用例："内化成千上万用户各自都会查询的共同事实或技能，而非单个用户的过渡性历史"。

其二，**路由信号要观察后果而非前提**。四种查询侧信号（相似度、查询特征、自洽性、置信度）全部失效而答案审计有效的对照，是对"事前预测不如事后验证"的一次干净实证；且置信度探针的解构（检测可答性 0.918 vs 检测答错 0.516）说明信号失效有具体结构——它知道你知不知道，不知道你对不对。任何 A/B 双系统的仲裁器设计都该优先考虑审计产出物。

其三，**写入策略应该分层，分界线用数据找**。论文自己给出的部署建议是"近期会话蒸馏进权重、长尾留给检索"，遗忘曲线的交点（约二十会话）就是分界线；边界类拒答习惯的跨龄存活进一步暗示：习惯类与内容类的衰减速率不同，可以按速率分别选介质。这种用实测曲线找介质分界线的思路，比空谈"混合架构"实在得多。

## 四、SUMONE：没有参考答案，也能学会摘要

### 4.1 题目

SUMONE 这个名字可以读作"Summarizer as One"——一个单一的摘要器。标题的每个限定词都是对现有方法某一依赖的切断：Simple and Efficient 说的是仅 2B 参数、推理时只留摘要器本身（训练用的重建管线整体退役）；Summarizer 说的是独立模块而非 agent 工作流的一部分；Plug-and-Play Agent Memory 说的是同一检查点插到不同模型、不同 harness 上无需再训练。论文要解决的核心矛盾藏在引言里：学出来的压缩方法往往依赖下游任务结果或求解器行为做监督，这把训练绑死在特定任务和 agent 上——SUMONE 用掩码重建把监督信号彻底解放出来，"自监督直接来自原始轨迹，无需参考摘要或下游任务执行"。

### 4.2 背景

背景是三类既有方案的各自残缺。第一类，提示词或规则压缩（Codex 与 Claude Code 的自动 compaction、丢弃旧交互）：实用但无学习。第二类，把记忆管理织进 agent 训练（HiAgent 在工作流内按子目标摘要、FoldGRPO/Context-Folding 训练 agent 直接适应压缩后的工具响应、AgentFold 的主动折叠、MEM1 的端到端摘要式上下文管理）：能贴合任务，但设计或训练绑定特定工作流或下游求解器。第三类，通用记忆框架（A-MEM 跨上下文与外部存储管理信息）：接口宽泛，但要求 agent 额外学习与记忆系统交互。训练一个专用小模型来压缩其他 agent 的运行上下文，剩下的问题就是训练信号从哪来——给长轨迹和它的压缩版，如何判断"完整"与"紧凑"？参考摘要需要标注或强模型蒸馏，任务奖励需要执行下游（昂贵且引入任务偏置），两者都引入外部依赖。

### 4.3 定位

定位上，SUMONE 属于独立摘要器路线，但把监督从"下游任务结果"（CoMem 用解耦长上下文模型、由下游 agent 行为监督）换成"数据自身派生的重建信号"。方法谱系上它借了两个经典：掩码重建作为自监督目标（去噪自编码器、BERT 的 MLM、BART 的序列去噪、MAE 的掩码自编码器——以及用掩码实体重建训练 agent 自管记忆的 MemTrain；SUMONE 与其的差异在于训练独立的文本摘要器、下游 agent 完全不进训练环），以及 GRPO 式 RL 微调。论文的认知科学类比是海马体（McClelland 等的互补学习系统）：让记忆管理成为专用模块的能力，服务不同的皮层——SUMONE 只解决"学会从原始交互历史写紧凑记忆"这一部分。

### 4.4 问题定义

形式化：给定过期历史 H 与保留上下文 C（系统指令、任务说明、既有记忆、近期交互），摘要器 π_θ 生成 S ~ π_θ(·|C,H)。目标是 S 简洁且保留 H 的信息——不靠参考摘要、不靠任务奖励，直接从原始历史获得训练信号。信息论表述干净利落：把 H 分块后掩掉子集 Ω，好摘要应最大化条件互信息 I(S; H_Ω | H̄_Ω, C) = H(H_Ω|H̄_Ω,C) − H(H_Ω|S,H̄_Ω,C)；第一项与摘要器无关，于是**摘要凡能降低对缺失内容的不确定性者即为保留信息**——重建质量是它的语义代理，SUMONE 不显式估计这个量。

### 4.5 解法

训练管线像一个信息守恒实验，五步闭环：

1. 摘要器（Qwen3.5-2B 初始化）把过期历史压成 S（摘要提示要求按 Goal/User profile/Constraints/Progress/Decisions/Key assets/Risks/Open loops 等模板段组织、追加式并入既有记忆、保留精确实体名与日期数字、不逐字复述被删段）。
2. 把 H 切成约 512 token 的块（优先沿角色切换与工具调用等自然边界），随机掩掉 50% 的块换成缺失标记。
3. 冻结的重建器（Qwen3.5-9B）在 (C, 部分可见历史, S) 条件下按序恢复全部缺失块。
4. LLM 裁判（DeepSeek V4.1 Flash）对每块打 precision（预测中被真值支撑的比例）与 recall（真值被恢复的比例），质量分 Q(S) 为均值之和；最终奖励 R(S) = Q(S) − λ|S|/L_max 显式表达压缩-保真权衡。
5. GRPO 组内归一化（每上下文采 8 个候选摘要、组内 z-score 化为相对优势）优化摘要器；重建器始终冻结。

数据约 5K 条压缩实例（16K 与 32K 上下文长度、搜索与代码约各半），8×H20-141G 上用 veRL 训 600 步（批 6、组 8、恒定学习率 1×10⁻⁶、rollout 温度 1.0、评估温度 0）。部署时重建管线整体退役，只剩 2B 摘要器在 32K 阈值触发时压缩——这就是"即插即用"的含义。

主实验（下游 Qwen3.5-35B-A3B + OpenCode harness、32K 压缩阈值、原生 harness 压缩关闭）：

| 基准 | 方法 | 性能 | 输入 token | 总成本 |
|------|------|------|-----------|--------|
| DeepSearchQA | Full History | 0.52 | 2.83M | $0.170 |
| | Self-Summary | 0.44 | 652K | $0.044 |
| | SUMONE | **0.48** | 591K | $0.038（约省 77%） |
| SWE-bench Verified | Full History | 0.63 | 4.1M | $0.286 |
| | Self-Summary | 0.56 | 1.05M | $0.082 |
| | SUMONE | **0.59** | 1.09M | $0.071（约省 75%） |

对 Self-Summary 的优势同时覆盖性能与成本：摘要成本仅其 0.04×/0.08×、总成本 0.86×；对 Prompt-2B（同底座 Qwen3.5-2B、同摘要提示、不训练）0.48 对 0.29——**这 19 个点是训练目标的直接功劳，证明仅仅换成轻模型不够**；对 CoMem（下游监督的独立记忆模型）DSQA +0.16、SWE +0.02、LongMemEval +0.16。截断基线（Recent Truncation）性能崩塌（0.16/0.46）说明丢信息不可取，压缩必须是语义性的。隔离记忆评测 LongMemEval-S 上 SUMONE 0.47 为压缩方法最高（Prompt-2B 0.43、CoMem 0.31；oracle 0.85、全历史 0.77），且四类能力最均衡——单会话检索 0.48、多会话推理 0.41、时序 0.36、知识更新 0.43（CoMem 更新类 0.61 但多会话推理只有 0.08、Prompt-2B 多会话 0.51 但更新类 0.24——各偏一科，SUMONE 四项皆可）。迁移性是重头戏：同一检查点跨五个下游 LLM（Gemini 3.7 Flash：SWE 0.55 对 Self-Summary 0.52 省 $0.08；GLM-5.3：0.66 对 0.61 省 $0.14；GPT-6 Luna：0.58 对 0.54 省 $0.01；DeepSeek V4.1 Flash：0.74 对 0.66 省 $0.04；DSQA 上甚至多个模型反超全历史）与四个 harness（OpenCode/OpenHands/Codex/DS Harness 全部优于 Self-Summary）免微调。与下游 RL 兼容：任务专属 RL 训练后 SWE-bench 拿到 0.68 全场最佳（Self-Summary 0.65）、DSQA 0.55 紧追 0.57 且成本 0.039 对 0.052。消融三板斧：重建奖励 0.48 对直接 judge 奖励（"评这份摘要好不好"的 RL）0.41 对无训练 0.29（LongMemEval 0.47/0.36/0.43——直接 judge 奖励甚至低于无训练，欠定义的全局判断会带偏模型）；掩码率 25%:0.41 / 50%:0.48 / 75%:0.29（25% 时重建器从可见历史就能猜出缺失、摘要边际价值测不出，75% 时恢复超纲、信号噪）；长度惩罚 λ=0.01:0.47 / 0.1:0.48 / 0.2:0.45 / 0.5:0.37（过弱摘要冗长、过强丢信息）。

### 4.6 知识反推

SUMONE 的效果从哪来？因果链的第一环是**监督信号的接地程度**。直接 judge 奖励问裁判"这份摘要好吗"，裁判面对一个欠定义的全局判断只能给印象分（LongMemEval 上 0.36 甚至低于无训练的 0.43——RL 放大了裁判的偏见）；重建奖励问的是"把摘要给别人，能不能把原文恢复出来"——一个可执行、可证伪的测试，与"摘要该保留未来可能需要的信息"的目标严格对齐。掩码率的消融进一步揭示了信号设计的微妙：掩太少，重建器绕过摘要直接看原文，摘要的边际价值测不出来；掩太多，恢复任务本身超纲，梯度淹没在噪声里。50% 是"逼着重建器用摘要"与"任务仍然可解"的平衡点。

第二环是**任务无关性带来的迁移红利**。因为训练信号只关于信息守恒而不关于任何下游目标，学到的压缩行为不偏科：LongMemEval 四类能力均衡是直接证据；跨五个模型四个 harness 免调迁移是间接证据（摘要的"可读性"是跨模型的公共属性，而任务特异性收益会随模型漂移）；下游 RL 还能继续叠加（0.68 全场最佳）说明压缩与任务学习正交——SUMONE 腾出的上下文空间反而给了 RL 更大的发挥余地。

第三环是**经济分工**。2B 模型做日常整理（$0.02/M token 级），昂贵模型只消费紧凑上下文；摘要成本随下游模型单价线性放大——Gemini 3.7 Flash 的 Self-Summary 要花 $0.47/query 摘要费而 SUMONE 全程只要 $0.39 总成本。**模型越贵，模块化的分红越厚**；这为"专用小模型作通用中间件"的产品形态提供了清晰的经济论证。

诚实的局限论文也写了：训练数据集中在搜索与代码轨迹，对话、具身等其他领域的记忆需求可能不同；重建器与裁判的能力上限会传导进摘要器（学生超不过裁判的品味）；λ 与摘要预算这类超参需要按域调。

### 4.7 通用灵感

三条。其一，**"可恢复性"是信息保留的通用试金石**——凡是需要评价"压缩/摘要/抽象是否丢了东西"的场景（日志归并、状态快照、事件折叠、特征工程），都可以套用"掩掉一部分、看能否借助压缩结果恢复"的自举评测，无需人工标注；配合组内相对比较（GRPO）还能绕开绝对分数的校准问题。其二，**模块的独立性由训练信号的独立性保证**——SUMONE 能即插即用的根因不是工程封装，而是它的损失函数里没有下游任务的影子；想造真正可复用的中间件组件，先检查监督信号是否被某个终端任务污染。其三，**自监督 + RL 的组合拳值得记住**——用无标注数据构造可计算奖励（重建分减长度罚）、再用 RL 优化生成器，是绕开昂贵标注或脆弱裁判的现成模板；掩码率的"太难太噪、太易无效"的倒 U 形曲线提醒：自监督任务的难度校准本身就是超参。

## 五、合读：一张上下文经济学的路线图

把四篇放回一条线上看，它们分别回答了上下文经济的四个正交问题，而且答案互相兼容到几乎可以拼装成一个系统。

**表示层**（Coca-Cola）：信息以什么形态过账？连续潜 token 用容量分析证明了文本形式的压缩天花板可以被打破，动作保持训练保证留下的恰是决策所需——代价是每个 agent 要配一个专属压缩器，且表示不可审计。**延迟层**（SpecCompact）：压缩这个动作本身计时收费吗？槽并行加语义验证加系统消垄，把 60 秒的整理内务压到 7 秒；但下游性能的模型依赖性提醒我们，加速机制改写的摘要内容并非免费。**介质层**（Route to Remember）：记忆存在哪个账户里？权重记忆写贵读贱、近期强远期弱、看不见缺失；文本记忆写贱读贵、全龄平坦、可检查缺失。VtR 用答案审计把两种货币兑换起来，oracle 与现实的差距（69.3% 对 66.1%）标出了路由研究剩余的空间。**监督层**（SUMONE）：压缩能力本身从哪学？掩码重建给出任务无关、标注无关、agent 无关的自举信号，换来了单检查点跨五模型四 harness 的迁移性——正交性是可组合性的前提。

四篇合读还有三个交叉印证值得记录。

一是**"对齐下游"的胜利是全方位的**：Coca-Cola 对齐动作分布胜过 ICAE 的对齐重建（同架构 8/8 设置压缩率全胜），Route to Remember 对齐实际答案胜过对齐查询特征（四种查询侧信号全灭），SUMONE 对齐可恢复性胜过对齐裁判印象（直接 judge 奖励甚至低于不训练），SpecCompact 的语义验证对齐"被历史支撑"胜过逐 token 分布等价——四种"对齐"都击败了各自领域里更表层的目标函数。这几乎可以升格为一条设计准则：**压缩系统的损失函数，应该是下游消费者能通过的测试，而不是压缩结果自身的某种品质**。

二是**诚实边界正在成为高质量论文的标配**：SpecCompact 明说没有一致的精度优势并给出模型依赖的双向数据；Route to Remember 主动给出权重记忆被检索反超的年龄交点、并审计了评分器的 rubric 偏差（边界类约五分之一"幻觉"其实是被误判的有效拒答）；SUMONE 承认训练域偏窄与裁判上限传导；Coca-Cola 的 Observation-only 消融反过来证明了自己的条件化并非全部收益来源。这些边界本身就是后续研究的地图。

三是**训练配方的小细节常是成败手筋**：OPSD 里"教师永远用冻结基模型"值 14 个点、"Unknowns 增强是拒答的唯一来源"（去掉即从 88% 崩到 1%）；SUMONE 里掩码率 50% 与 λ=0.1 的最优点；SpecCompact 里共享前缀缓存对混合注意力架构的失效。宏图之外，这些数字才是可复现的经验。

下一个悬而未决的问题也顺理成章：四条线索能否收敛？用 SUMONE 式自监督训练 SpecCompact 式槽并行摘要器、把近期内容压进 Coca-Cola 式潜表示、远期内容沉淀到 OPSD 权重、读取时 VtR 审计路由——这个每块都已单独验证过的组合，就是上下文经济学的完整账本。谁先把它跑通，谁就拿到了长程 agent 的成本钥匙。
