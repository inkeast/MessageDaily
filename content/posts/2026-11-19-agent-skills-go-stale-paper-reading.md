## 一、论文背景

### 1.1 Agent Skill：把经验变成可复用的资产

LLM Agent 的核心循环是观察—决策—行动。如果每个任务都从零开始推理，同一个 workflows 反复重建，推理与环境交互的开销会不断累积。于是业界发展出**技能**这一层：把成功经验沉淀为可复用的指令、代码与资源（以 Anthropic 的 Agent Skills 为代表，一个 skill 就是一个含 SKILL.md、scripts/、references/ 的文件夹），任务到来时按需加载，让过去学到的决策与流程直接复用。

这条路线的源头可以追溯到 **Voyager**（[arXiv:2305.16291](https://arxiv.org/abs/2305.16291)）：Minecraft agent 把验证成功的可执行代码连同描述一起存入技能库，新任务按语义检索、组合调用，实现不更新权重的终身学习。之后的 Agent Workflow Memory（arXiv:2409.07429）、SkillWeaver（arXiv:2504.07079）等把这一思想推广到网页与通用 agent。2025 年 Anthropic 将其产品化为开放的 Agent Skills 标准（[skill.md](https://skill.md/)、[github.com/anthropics/skills](https://github.com/anthropics/skills)）：技能文件夹经渐进式披露加载——启动时只读 name 与 description，任务匹配才展开正文。官方仓库 star 已达 19 万级，skill-creator 安装量超 43 万，说明技能已成为生产环境的主流机制。

论文引用 Achille 与 Soatto 的提法，把技能的本质概括为**摊销**：今天保留的经验，是为了减少未来任务的推理与环境交互成本。这个视角很关键——技能的价值不在本身内容多精彩，而在它能省下多少未来的计算。

### 1.2 环境演化：资产如何变成负债

摊销成立的前提是**保留的状态仍然有效**。而真实环境从不停滞：

- 软件更新改了 API 端点名或库行为（MCP 协议从带会话演进为无会话，保存的连接配置立即失效——论文图 1 的例子）；
- IRS 税表年度修订，字段重编号、改名、增删（W-9 表 2018 版 Line 1 的字段名是 f1_1[0]，2024 版变成 f1_01[0]）；
- AppWorld 的 API 文档端点改名、ScienceWorld 里的目标物体被挪了位置。

论文定义：当环境从 W0 变为 W1，技能状态中部分**依赖环境的信息**（文件路径、字段标识符、API 假设）不再有效时，该状态就**过期**。关键洞察在于过期是**局部的**——改名一个端点，工作流的其余步骤依然有效。问题从要不要整个丢弃技能，变成如何识别并只修正失效的部分。

这与软件工程里的经典命题同构。Lehman 软件演化定律指出：真实世界中使用的系统必须持续适配，否则满意度持续下降（持续变更律）；演化带来的复杂性若无人偿还就不断累积（复杂度递增律）。Cunningham 1992 年提出**技术债**隐喻：先行快速交付就像负债，不重构偿还就会以利息形式拖慢未来的一切变更。经验估计维护占软件生命周期成本的 60–80%。Agent 技能正是同一种债务的新形态：把解析好的值缓存进 SKILL.md 相当于主动举债——换来了 W0 的执行节省，押上的是 W1 的失效风险。

### 1.3 已有应对方式与共同困境

| 应对方式 | 做法 | 问题 |
|---|---|---|
| 运行时补偿 | Agent 靠当前观察发现不一致，现场修正动作 | 任务可能仍然做对，但每个后续任务都要重复同样的纠错；且状态本身没修，错误持续累积 |
| 整体重建 | 检测到变化就重写整个技能 | 丢弃仍有效的部分；重建成本高（论文实测是局部修复的 1.24–2.28 倍 token） |
| 等失败再修 | 任务失败才触发维护 | 忽略纯成本型退化（成功率不掉但步数猛增）；部署期任务结果常常拿不到 |
| 一有变化就检查 | 对任何环境变更都触发 | 变更绝大多数与技能内容无关（论文 TB-2 对照实验中 62 个等价变更里只有极少数真冲突） |

还有一个被普遍忽视的测量问题：只看任务成功率不足以判断技能是否仍有价值。论文的核心主张是**技能价值必须两维联测**——相对无技能基线的边际任务贡献 ΔU 与执行节省 S。一个过期技能完全可能成功率不变而节省消失，甚至成功率高企的同时把执行成本抬得比不用技能还贵。这个两维视角贯穿全文的全部实验设计。

## 二、论文定位和关联工作

论文把自身置于三条研究线的交点上：技能评测、变化环境下的 agent、技能库生命周期管理。

### 2.1 谱系一：可复用技能的构建与评测

Voyager（arXiv:2305.16291）确立代码技能库范式后，Agent Workflow Memory（arXiv:2409.07429）从交互历史归纳工作流，SkillWeaver（arXiv:2504.07079）让网页 agent 自我发现并打磨技能，Wang 等 2025（arXiv:2504.06821）诱导程序化技能。评测侧，SkillsBench（arXiv:2602.12670，87 任务 ×18 配置，策展技能平均 +16.6pp 但 13 个任务带技能反而变差）、SWE-Skills-Bench（arXiv:2603.15401，发现部分伤害可追溯至版本不匹配的指导）、How Well Do Agentic Skills Work in the Wild（arXiv:2604.04323）等系统度量技能收益。**关键区别**：这些工作评测的是静态环境中的技能收益来源（写法、检索、任务匹配），本文追踪的是**同一个技能状态跨 W0→W1 迁移的价值变化**——技能收益如何被环境变化摧毁、又如何被维护恢复。

### 2.2 谱系二：变化环境下的 Agent

CodeUpdateArena（[arXiv:2407.06249](https://arxiv.org/abs/2407.06249)）评测模型知识对 API 更新的内化（161 个合成 API 变更 ×670 程序合成题，发现微调文档几乎无效、微调使用示例才有效）；StableToolBench（arXiv:2403.07714）解决工具评测稳定性；Learning Evolving Tools（arXiv:2410.06617）、可编程演化的 agent 基准（arXiv:2603.05910）测试 agent 应对演化工具的能力。本方向同期还有 Δτ-Bench（1,588 任务 ×6 个连续工具生态版本，发现旧技能在版本切换后甚至让 agent 比无技能更差，最强模型成功率仅 42.3%）与 MCPEvol-Bench（123 个 MCP 服务器 ×11 种演化算子，GPT-5.4 任务满足度掉 13.7%、Claude Sonnet 4.6 掉 14.4%，错误增长集中在规划与推理层而非语法层）。**关键区别**：这些工作测的是 agent（或模型）在变化环境中的表现，本文测的是**持久化技能状态的价值损益**——把 agent 能力的退化和技能资产的贬值分开度量。

### 2.3 谱系三：技能库生命周期管理

SkillsVote（arXiv:2605.18401，从收集、推荐到演化的治理）、SkillOps（arXiv:2605.13716，自维护软件生态式管理）、动态技能生命周期管理（arXiv:2605.10923）、SkillForge（arXiv:2604.08618，云技术支持的自进化技能）、Ratchet（arXiv:2605.22148，研究何时退休技能、指出无人维护的库可跌到无技能以下）。最接近的是 **SkillGuard**（arXiv:2605.10990，技能漂移即契约违犯：把技能文档中的契约与线上环境比对来定位修复点）。**关键区别**：SkillGuard 的检查来自技能**文档声明**的契约，本文的检查来自**经过验证的成功执行**（执行画像），且本文把维护效果的评估落到任务与执行价值恢复及 token 成本摊销上，而非只看检测准确性。

### 2.4 定位总结

| 维度 | 之前的工作 | 本文的推进 |
|---|---|---|
| 度量对象 | agent 在变化环境中的表现 / 技能在静态环境的收益 | 同一技能状态跨环境版本的价值变化（ΔU 与 S 双轴） |
| 过期归因 | SWE-Skills-Bench 观察到版本不匹配伤害 | 系统分解为操作特异性（缓存型 vs 程序型）与模型补偿能力两个因子 |
| 维护触发 | 文档契约比对（SkillGuard）/ 任务失败 | 从成功执行自动构造检查，零模型调用重放触发，带对照误报评估 |
| 维护动作 | 修复或退休 | 先验证后定点修复、失败重建、验证不过保留原状的完整决策链，并给出 token 摊销账 |

一句话定位：这是第一篇把技能复用当作**跨环境版本的投资决策**来精确记账的论文——收益多少、损失多少、维护花多少、几次回本，全部量化。

## 三、问题定义

### 3.1 从具体场景到抽象问题

具体场景五花八门：Nginx 配置结构变了、税表字段重编号了、API 端点改名了、实验器材换房间了。剥离表面差异，它们共享同一个深层结构：**一个缓存了环境相关决策的状态 σ0，一段保持任务目标不变的环境迁移 W0→W1，以及一个能力固定的 agent π**。要回答的问题是：σ0 在迁移后还值多少钱？能否以低于重建的成本把价值修回来？

### 3.2 形式化定义

论文的符号系统干净利落。设 σ0 为在 W0 中创建并验证过的技能资源集（指令、代码、关联资源），π 为固定基座模型与执行 harness 的 agent，x 为任务，s∈{∅, σ0} 表示是否携带技能。轨迹 τ～Pπt(·|x,s)，环境版本 t∈{0,1}。归一化任务得分 Rt∈[0,1]，执行成本 ct（agent 轮次，ScienceWorld 用环境步数）。由此定义**技能价值两分量**：

- 边际任务贡献：ΔUπt = Uπt(σ0) − Uπt(∅)
- 相对执行节省：Sπt = (Cπt(∅) − Cπt(σ0)) / Cπt(∅)

跨迁移的**价值损失**：LπU = ΔUπ0 − ΔUπ1，LπS = Sπ0 − Sπ1。当 ΔUπ1 < 0，即带技能反而低于无技能基线时，称**负迁移**。

两个精妙之处值得展开。**其一，基线锚定在同一个 W1 的无技能 agent 上**：环境变化也会改变无技能基线本身（表单改版后无技能填表也会变难），所以正的损失并不自动等于过期——必须减去基线自身的漂移。这防止了把环境整体变难错记成技能贬值。**其二，显式承认部署期无法估计这些量**（需要成对的无技能执行），因此维护决策不能依赖它们——这直接引出了后面基于重放而非基于性能对比的触发设计。

论文还引入**操作特异性**这一自变量：技能把多少环境相关选择**提前固化**了。存具体字段名（cache-heavy）特异性高；保留枚举 get_fields() 的推导步骤（procedural）特异性低。两个变体出自同一 W0 素材与同一撰写模型，只差撰写指令，从而构成受控对比。

### 3.3 抽象的类比

| 软件维护概念 | 本文对应 |
|---|---|
| 代码库（积累的结构） | 技能状态 σ0（指令 + 代码 + 资源） |
| 运行环境升级（OS、依赖） | W0→W1 迁移（API 改名、表单改版……） |
| 回归测试（捕获行为变化） | 执行画像检查（捕获观察差异） |
| 定位 bug（哪段代码受影响） | 验证器定位冲突的技能内容 |
| 热修复（改最小范围） | LLM 定点修复 |
| 大重构 / 重写 | 原流程重建 |
| 技术债利息 | 每次任务多付的补偿轮次 |
| 维护预算决策 | token 摊销回本次数 n* |

这个抽象把一个看似 agent 特有的问题接到了四十年软件维护积累的概念工具箱上——但有一个关键的新自由度：传统软件的回归测试要人写，这里检查可以从技能内容与成功执行中**零模型调用地自动构造**。

## 四、问题解法

论文的解法分两半：前半是**诊断**（第 3 节，过期如何摧毁价值），后半是**治理**（第 4 节，选择性维护）。方法全景是一个四阶段闭环（图 2）：画像健康使用 → 重放画像检查 → 验证与定位 → 维护与验证。

### 4.1 构造执行画像：把成功执行变成可重放的检查

类比：软件发布前的回归测试套件——但这里不用人写测试用例。输入是技能状态 σ0 与 W0 中成功执行的记录；输出是执行画像 M0 = {(pj, qj, e(0)j)}，三元组分别是**源引用**（指向技能中依赖该观察的指令/代码位置）、**可执行检查** qj（路径存在性、字段写入落点、API 调用、环境动作）、**参考输出** e(0)j = qj(W0)。

构造完全靠规则：TB-2 上规则抽取识别技能中的命名路径、命令与标识符；IRS 上把填表例程跑在**带互异占位值的合成输入**上，记录每个写入落到哪个字段（排除真实申请人数据）；AppWorld 与 ScienceWorld 直接回放成功执行记录中代码发出的 API 调用与动作。三次 W0 重放输出不稳的检查被丢弃，保证参考输出可比较。整个构造**零模型调用**，跨技能共享观察例程，无需为每个技能手写测试。

### 4.2 复用前重放：零成本的哨兵

技能每次被复用前，维护器在当前环境 Wt 重放全部检查、与 W0 参考输出比对，得到差异集 Dt = {j : qj(Wt) ≠ e(0)j}。为空则技能原样复用。这一步的类比是部署前的冒烟测试：便宜（论文实测中位耗时 0.2–4.3 秒）、无模型调用、每次复用都跑得起。

关键设计：检查同时携带**证据**（变了什么观察）与**地址**（pj 指回依赖该观察的技能内容）。检测到技能相关的变化需要这两者——缺前者无从发现漂移，缺后者无法定位该修哪里。

### 4.3 验证：变化不等于冲突

类比：告警审计。观察变了不代表技能失效——无技能基线变了、或变化落在技能不依赖的属性上，都不需要修。验证器先做简单规则判断（AppWorld/ScienceWorld 上无效调用直接定位到组件），需要语义解释时由 LLM 验证器（Opus 4.7）比对技能内容、原始与当前观察，同一提示独立采样三次、至少两次支持才确认冲突，取置信度最高的一致判断作为定位与解释传给修复。不支持的差异保持技能原样。TB-2 验证提示词明确写着：你的工作是审计告警而非照单全签；纯效率损失也是真漂移，不要因为任务最终能过就归为任务噪声。验证器还接收技能在 W0/W1 的平均轮次等执行统计作为证据，全程不需要外部 changelog。

### 4.4 修复优先、重建兜底、验证把关

- **定点修复**：LLM 维护器只改定位到的受影响内容，保留其余部分与撰写风格，并保持技能跨任务输入可复用。修复提示词强调：不能把过期细节删掉让 agent 自己想办法——那恢复了正确性却丢掉了技能存在的理由（效率）。候选可用验证反馈迭代精修（Self-Refine 机制）。
- **重建**：冲突无法定位、或修复反复过不了验证时，用原撰写流程在 W1 中从零重建（不接触旧技能）。
- **验证准入**：候选在 W1 的验证任务上执行，性能阈值取健康技能与过期技能验证分的较低者，成本目标取健康技能验证成本；主准则不过时回退准则兜底（性能不低于过期分一个标准误、成本不超过过期执行、且至少一项改善）。两者都不满足则**保留原技能**。验证数据与报告评估严格分离（held-out 答案与冲突标签只对评估者可见）。

维护期间**任务执行 agent 保持不变**——只动可复用状态，不动执行器。

### 4.5 方法全景与设计取舍

| 阶段 | 输入 | 动作 | 模型调用 | 失败出口 |
|---|---|---|---|---|
| 画像构造 | σ0 + W0 成功执行 | 规则抽取检查 + 记录参考输出 + 源引用 | 无 | 输出不稳的检查丢弃 |
| 复用前重放 | 画像 + 当前环境 | 执行检查、比对 | 无 | 差异为空则原样复用 |
| 验证 | 差异集 + σ0 + 前后观察 + 执行统计 | 规则直判或 LLM 三采样多数表决 | LLM（仅 TB-2/IRS） | 不确认冲突则不动 |
| 修复 | 冲突报告 + 受影响内容 | LLM 编辑 + 验证反馈精修 | LLM | 反复失败转重建 |
| 重建 | 原撰写流程 + W1 | 从零重做技能 | LLM | 验证不过则保留旧技能 |
| 准入 | 候选在验证任务的表现 | 双阈值 / 回退准则 | 环境 | 都不过则保留旧技能 |

整条链路的取舍得一句话概括：**便宜的先跑（规则、重放），贵的后跑且要带门（LLM 验证、修复、重建都要过验证关），任何一步失败都退回保守状态（保留原技能）**。

## 五、评估指标与实验证据

### 5.1 实验设置：四个基准 × 两个模型 × 两种风格

环境迁移的设计原则是**任务目标、评分标准、技能状态三不变，只变环境中一项技能可能持久化的东西**：

| 基准 | 变更内容 | 任务规模 | 性能指标 | 成本单位 |
|---|---|---|---|---|
| TerminalBench-2 | 包/配置/模式/文件的审计变更 | 38 任务-变更对 | 通过率 | agent 轮次 |
| IRS 历史税表 | 5 组真实年度修订（W-9 2018→2024 等），字段重编号/改名/增删 | 5 表 ×10 申请人 = 50 | 字段准确率 | 轮次 |
| AppWorld | 3 个 API 端点改名，文档同步更新 | 51 任务 | 任务成功率 | 轮次 |
| ScienceWorld | 导电任务目标物体挪到起始房间，任务文本不变 | 41 变体 | 归一化得分 | 环境步数 |

模型为 Claude Opus 4.7 与 Haiku 4.5（同一 harness、工具、指令、评分；TB-2 上经 Harbor2 以 Claude Code agent 运行）。技能由 Opus 4.7 用 Liu 等 2026c 的精修流程创建、以 Anthropic skill-creator 为格式模板，同一 W0 素材产 procedural / cache-heavy 两版。每个变更保证适应所需信息在 W1 中仍可获得（可从当前表单枚举字段、API 文档列出新端点）。

### 5.2 主结果一：过期摧毁价值的多种形态（表 1，cache-heavy）

8 组模型×基准对比中，执行节省全部下降，性能增益 7 组下降。Opus 上呈现三种典型形态：

| 形态 | 案例 | ΔU (W0→W1) | S (W0→W1) |
|---|---|---|---|
| 省钱红利缩水但仍有正贡献 | AppWorld Opus | +9.8pp → +5.9pp | 37.9% → 22.2% |
| 性能转负、成本仍省（负迁移） | IRS Opus | +18.8pp → **−12.5pp** | 84.0% → 24.6% |
| 双输：更差且更贵 | ScienceWorld Opus | +0.0 → **−13.0pp** | 16.2% → **−38.9%**（比无技能多 38.9% 步数） |

第三种形态最能说明为什么必须双轴测量：ScienceWorld Opus 带过期技能比不带技能少拿 13 个百分点还多走近四成步——技能同时毒化了决策与效率。TB-2 Opus 也是负迁移（+4.7→−11.4pp）。Haiku 则全部保持正增益（+11.4～+25.9pp），但增益同样普遍缩水。

### 5.3 主结果二：操作特异性决定脆弱性（表 2、表 8）

cache-heavy 在 W0 省得更多（TB-2 两模型多省 31.5/31.2pp，IRS Opus 多省 19.0pp，配对 bootstrap 95% CI 全部为正），但变更后性能损失也更大（TB-2 Opus 多损 22.9pp [11.0, 36.1]、IRS Opus 多损 18.7pp [10.2, 27.8]、IRS Haiku 多损 16.8pp [6.8, 27.2]）。缓存型把字段名、路径等选择提前固化——W0 省下发现步骤，W1 固化值失效且无重推路径可走。IRS Opus 的对照最清晰：变更后程序型仍保留 +6.2pp 增益，缓存型转负为 −12.5pp。

但这不是普适规律：AppWorld 与 ScienceWorld 的变更恰好打在两种风格都保留的信息上（端点名、任务指定位置），两者损失相近（AppWorld 风格差 L_U 均为 3.9pp）。**缓存的代价只在缓存的内容失效时兑现**。

### 5.4 主结果三：同一过期技能，强模型受伤更重（第 3.3–3.4 节）

IRS 上固定同一 cache-heavy 技能：Opus 绝对准确率 73.1% 远高于 Haiku 的 30.5%，但相对各自无技能基线，Opus 是负贡献（−12.5pp）、Haiku 反而是正贡献（+25.9pp）。且这不是孤例——四个基准上 Haiku 两种风格全部保持正增益，Opus 多次无技能更好。

行为分析（200 条 IRS 轨迹）揭示机制：两组模型都频繁检查当前表单（Opus 73/100、Haiku 80/100），但检查后 Opus 只有 7/73 仍写废弃字段，Haiku 有 36/80。检查关联更高的准确率（Opus 程序型组内差 +24pp、缓存型 +68pp）也关联更多轮次。cache-heavy Opus 的分解最戏剧化：20 条不检查轨迹贡献 −16.7pp 准确率差与 +37.1pp 成本节省——**总体的轮次节省是靠不检查就照做的便宜错误轨迹撑起来的**，而 30 条检查轨迹准确率更高却比基线还多花轮次。看似省钱的聚合数字下藏着质量崩坏。

### 5.5 主结果四：选择性维护恢复价值（表 4、表 13）

对比 No maintenance（原样复用过期技能，允许运行时补偿）与 Selective（repair-first 策略），Haiku 结果：

| 基准 | 技能 | 任务表现（无维护 → 维护后） | 成本（无维护 → 维护后） |
|---|---|---|---|
| TB-2 | Cache | .561 (+11.4pp) → .649 (+20.2pp) | 38.9 (43.5%) → 32.1 (53.4%) |
| IRS | Cache | .305 (+25.9pp) → **.975 (+92.9pp)** | 7.0 (43.1%) → 4.7 (61.5%) |
| AppWorld | Cache | .627 (+15.7pp) → .667 (+19.6pp) | 28.7 (13.9%) → 23.3 (30.3%) |
| ScienceWorld | Cache | 1.000 (+7.3pp) → 1.000 (+7.3pp) | 28.0 (49.0%) → **18.6 (66.1%)** |

- IRS 修复后 +92.9pp，较无维护提升 67pp（摘要的 up to 67pp 出处）；Opus 版 .731→.981。
- ScienceWorld 体现维护的第二重意义：满分保持的同时步数再省 33%（procedural 25.6→16.1，省 37%——摘要 up to 37% 出处）。**分数已满时维护的价值全在效率**。
- 8 组设置平均执行成本全部下降；唯一例外是 procedural AppWorld 任务表现略降（配对差 −5.9pp，CI [−21.6, +9.8] 跨零）。
- 策略消融（表 13）：repair-only 与 rebuild-only 互有胜负（ScienceWorld procedural 修复被拒、重建拿到 1.000/16.1 步），Selective 按验证门自动择优，支持保留重建兜底。

### 5.6 触发器质量：漏报与误报（表 12）

TB-2 上 51 个标注真冲突：重放标出 34、验证确认 28（17 个漏报均为记录属性之外的字节级变更）；62 个等价变更对照：重放误标 7、验证否决 5，仅 2 例导致不必要的修复。IRS 验证接受全部 10 个字段真冲突、拒绝 4 个字段名未变的修订；AppWorld 无变化环境 51 任务零误报。验证层在两个方向上都被证明必要。

### 5.7 成本与摊销（表 5、表 15）

重放中位耗时 IRS 1.2 秒、AppWorld 0.2–0.3 秒、ScienceWorld 3.6–4.3 秒，零模型调用。IRS 维护一次（验证 + 候选生成 + 准入验证）耗 91.1K–151.1K 模型 token；修复（58.6–142.8K）比重建（133.6–197.9K）省 1.24–2.28 倍。相对**退休技能退回无技能**基线，每次使用节省 token 3.57K–6.74K，回本需要 21.2–41.9 次复用；相对继续用过期技能（已经很便宜但输出错误），回本要 39–105 次——论文诚实指出这个更悲观的口径。20 组 IRS 组合中 18 组相对退休省 token、15 组相对过期复用省 token。

### 5.8 实验设计如何支撑主张

- **同技能跨版本配对**：同一 σ0 在 W0/W1 各测有无技能四格，任何价值变化只能归因于环境迁移——这是全部结论的因果支点。
- **同一素材两种风格**：控制撰写模型与 W0 材料，只变撰写指令，风格差异才是干净的。
- **held-out 分离**：验证用的申请人/任务与报告评估严格分开，防止维护器偷看考题。
- **对照实验**：等价变更对照证明触发器不乱报；ScienceWorld 的 matched sham（搬完再搬回）控制搬运本身的干扰。
- **配对 bootstrap CI**：TB-2 抽任务-变更对、IRS 抽表单-申请人对，保持前后与有无技能配对重采样。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**因果链一：过期技能的伤害机制（为什么更强模型受害更深）。**

链路：环境变更使固化选择失效 → agent 面对指令与观察的冲突 → 要么照做（错误：Opus 不检查轨迹写废弃字段、准确率崩）要么现场重推（昂贵：检查轨迹比无技能基线还多花轮次）→ 聚合上表现为负迁移或成本激增。强模型基线本身高，技能增益空间小，而其服从指令的倾向强——同样的过期指令，Haiku 带着走仍胜过自己从零做（基线 .046 太低），Opus 的基线 .856 却被过期技能拖到 .731。**技能的已实现价值 = 状态内容 × agent 的解读与补偿方式**，前者是资产项，后者可以变成负债项。（论文实验已支持：表 1、表 3、附录 C 的贡献分解。）

**因果链二：运行时补偿不等于维护（为什么必须改状态）。**

链路：补偿只修正当前轨迹 → 状态未变 → 每个后续任务重复同样的检测与纠错开销；补偿还依赖模型能力，弱模型补不动（Haiku 36/80 检查后仍写废弃字段）。维护把修正**固化回可复用状态**，一次性付费、次次免单。（论文实验已支持：ScienceWorld 维护后保持满分同时步数 28.0→18.6；IRS 修复后 +67pp 于无维护。）

**因果链三：执行证据锚定 + 定点修复为什么优于文档契约或整体重建。**

链路分三段。**触发段**：检查来自验证过的成功执行而非文档声明——文档可以写错或过时，成功执行是环境行为的一手记录；重放零模型调用使得每次复用前检查在经济上可行（对照：等任务失败再触发会漏掉纯成本退化，且部署期拿不到任务结果）。（论文实验已支持：表 12 对照误报 2/62。）**修复段**：过期是局部的（一个端点名失效、其余流程仍有效），定点修复保留仍有效部分且比重建省 1.24–2.28 倍 token。（论文实验已支持：附录 E.2。）**验证段**：修复也可能改坏，验证门拦下坏候选（ScienceWorld procedural 被拒修复在评估上只有 .561，重建版本 1.000）——没有验证门的修复链不可信。（论文实验已支持：表 13 与 E.1。）

**因果链四：操作特异性的对冲本质（阅读者推测的部分）。**

论文数据表明 cache-heavy 是 W0 收益/W1 风险的杠杆放大器。把 W0 多省的 31.5pp 与 W1 多损的 22.9pp 并置，可解读为一种**技术债的利率结构**：缓存=主动举债换当期速度，环境变更=债务到期。论文只展示两端数字，未在中间设计偿还时机实验（何时从缓存降级为程序型），这一步推广属于阅读者基于其数据的推测。

### 6.3 综合判断与未决问题

**得到多项独立研究共同支持的机制**：(1) 环境变更可致技能负迁移（本文、Δτ-Bench、MCPEvol-Bench、Ratchet 均有证据）；(2) 执行/旅程回放是检测漂移的有效手段（本文重放、MCPEvol-Bench 四层门、CodeUpdateArena 的示例学习从三个不同角度汇聚）；(3) 定点修复优于整体重建有明确成本证据（本文 token 账）。

**仍属推测或单一来源的机制**：执行画像优于文档契约的判断缺乏直接对照实验；操作特异性作为可调节的设计变量（而非事后分类）未获独立验证；单次维护事件的外推（连续多轮维护、profile 自动刷新）论文明确留给未来工作。

**适用边界**：本文的迁移每次只改一项、适应信息保证在 W1 可得——真实部署的多因素同时变更与信息缺失场景未覆盖；每类新环境需要适配器定义检查观察什么；两个模型同属 Claude 家族，补偿行为的模型间差异可能不同。

## 七、必要知识反推

假设让一个零背景的人重做这项工作，最少需要掌握什么？

### 7.1 领域知识层

- **Agent Skills 的实际形态与加载机制**（SKILL.md、渐进式披露、Anthropic skill-creator 流程）：不知道技能长什么样，就无法构造两种撰写风格的受控对比，也无法解释为何路径/标识符这类字面量会成为过期点。
- **四套基准的内部结构**：TB-2 的容器化任务与测试、IRS 表单的 pypdf 字段树、AppWorld 的 API 调用体系、ScienceWorld 的动作-观察循环——检查画像的观察例程必须贴着各环境的可观察属性设计。
- **MCP 协议等真实接口的演化方式**（会话到无会话）：动机例子必须真实可信，读者才会认这个问题重要。

### 7.2 方法论知识层

- **摊销视角的学习理论**（Achille & Soatto）：技能价值=未来推理成本的减少，这是全部度量定义的理论出发点。
- **软件维护与技术债的概念体系**（回归测试、热修复 vs 重写、维护预算）：本文方法几乎逐项对应，没有这套语言很难把维护决策讲成摊销问题。
- **受控实验与因果归因设计**：配对 W0/W1、固定 harness 只变技能、同素材两种风格、验证/评估分离、配对 bootstrap——任何一个环节松动，价值变化就无法归因于过期本身。
- **知识编辑与技能生命周期文献**（CodeUpdateArena、SkillGuard、Ratchet 等）：定位表需要知道前人停在哪里。

### 7.3 工程知识层

- **零模型调用的检查构造技术**：规则抽取、合成占位输入、成功执行回放——可行性全在这些工程细节上，稍有不慎检查就不稳定（三次重放过滤就是为此）。
- **验证/修复提示工程**：审计式验证提示（不得照单全签）、效率保持式修复提示（不得删掉过期细节了事）——提示的措辞直接决定维护质量。
- **token 级成本核算**：把维护拆成验证/生成/准入三段记账，才能算出 21–42 次回本这类部署者真正关心的数字。

### 7.4 知识融合的关键节点

最有创造性的融合点有三个。**其一，软件维护 × agent 技能**：把技能状态当作需要回归测试的代码资产，把成功执行当作自动生成的测试套件——两个领域各出一半（概念框架 + 自动化机会），缺一不可。**其二，两维价值度量 × 触发设计**：正因为认识到部署期测不出 ΔU/S（需要成对无技能执行），才把触发器建立在重放差异而非性能对比上——度量上的不可能性直接塑造了方法形态。**其三，局部性洞察 × 修复优先策略**：观察到过期是局部的（一个字段名失效、其余流程完好），才有修复优先、重建兜底的分层设计及其 token 账。

## 八、论文中可以提取的通用性灵感

**灵感一：缓存是负债，摊销要记折旧。**
核心思想：任何把环境相关决策提前固化的缓存都在 W0 获利、在环境变更时暴露风险；收益应按可折旧资产对待而非永久资产。
论文证据：cache-heavy 在 W0 多省 19–31.5pp 但 W1 多损 16.8–22.9pp（表 2、表 8）。
推广场景：RAG 的索引快照（语料更新后检索漂移）、CI 缓存（依赖升级后缓存键失效或更糟——命中了错的）、编译产物与容器镜像（基础镜像安全补丁后旧层失效）、提示词模板中的硬编码示例、数据管道的 schema 映射表。

**灵感二：成功执行的回放是最便宜的环境哨兵。**
核心思想：把验证过的成功执行转成可重放检查（带参考输出与源引用三元组），可以在零模型调用成本下持续检测环境漂移。
论文证据：重放中位 0.2–4.3 秒、零模型调用；真冲突 34/51 被标出、对照误报被验证层压到 2/62（表 12）。
推广场景：API 集成的契约测试（从真实流量录制生成）、浏览器自动化站点的视觉/结构断言、数据质量监控（回放历史查询检测口径漂移）、爬虫的反爬升级预警、MCP 服务器发布前的金丝雀回放（MCPEvol-Bench 独立收敛到同一做法）。

**灵感三：修复要带验证门，验证不过就保守回退。**
核心思想：自动修复系统必须包含拒绝坏修复的机制，且全部失败路径都退到保守状态（保留原状），因为改错比不改更危险。
论文证据：ScienceWorld procedural 的修复候选被验证拒绝（评估分 .561），重建候选通过拿到 1.000；准入双阈值 + 回退准则。
推广场景：LLM 代码补丁的 CI 门（不过测试不合并）、自动数据库 migration 的回滚点、自动 prompt 优化的离线评估门、自进化 agent harness 的 token 预算门、知识库编辑的事实核查层。

**灵感四：聚合指标会藏住行为分层的真相。**
核心思想：平均值相同的两组轨迹可能由便宜而错误的多数与昂贵而正确的少数构成；诊断必须分解到行为子群。
论文证据：cache-heavy Opus 的轮次节省全部来自不检查的 20 条轨迹（贡献 +37.1pp 成本节省、−16.7pp 准确率），检查轨迹反而比基线多花轮次（附录 C）。
推广场景：A/B 测试的分群分析（整体持平但新用户流失）、模型评测的按难度分层（总分掩盖能力断崖）、运维的平均延迟（长尾请求被均值吃掉）、销售pipeline 的转化漏斗分解、教育测评的按错因归类。

**灵感五：同一资产的价值取决于使用者的纠错能力。**
核心思想：过期指导对弱执行者可能仍是净收益（其基线太低），对强执行者是净损失（其基线高且服从性强）；资产价值从不是内容的固有属性。
论文证据：同一 cache-heavy IRS 技能，Haiku +25.9pp、Opus −12.5pp（各自对无技能基线）。
推广场景：文档分层（新手要 SOP、专家要原理）、风格指南按团队成熟度裁剪、遗留代码对维护型团队 vs 重构型团队的价值差异、教学材料的因材施教、法规指引对不同规模企业的适配。

**灵感六：维护决策是一笔可计算的摊销账。**
核心思想：一次性维护成本对比每次使用的节省，回本次数 = 维护成本 / 每次节省——把是否维护从直觉变成算术。
论文证据：n*retire = Ksel/(G∅−Gsel)，IRS 上 21.2–41.9 次回本；相对继续用过期技能则需 39–105 次（更悲观的基线必须如实并列）。
推广场景：重构 vs 继续打补丁的工程决策、模型再训练 vs 推理端补偿的训练成本摊销、基础设施升级的迁移成本回收期、索引重建的查询节省回收、技能库的退休/修复/重建三分决策。

## 附录：一页速查

- **问题**：环境迁移 W0→W1 后技能状态过期，任务贡献 ΔU 与执行节省 S 双双受损（极端：−13pp 且步数 +38.9%）。
- **诊断因子**：操作特异性（cache-heavy 脆弱但 W0 省得多）× 模型补偿能力（强模型照做出错、检查多花钱；弱模型反而受益）。
- **方法**：执行画像（检查 + 参考输出 + 源引用，零模型调用构造）→ 复用前重放 → LLM 验证（三采样多数表决）→ 定点修复（优先）/ 重建（兜底）→ 双阈值验证准入 → 不过则保留原状。
- **效果**：相对无维护，任务表现最高 +67pp（IRS），步数最高省 37%（ScienceWorld）；8 组成本全降。
- **账本**：重放 0.2–4.3 秒零模型调用；维护 91–151K token；修复比重建省 1.24–2.28 倍；相对退休 21–42 次复用回本，相对用过期技能 39–105 次。
- **边界**：单因素变更、适应信息在 W1 可得、Claude 家族两模型、每类环境需检查适配器；连续多轮维护未评估。
