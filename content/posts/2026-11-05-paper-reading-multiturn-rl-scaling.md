# 多轮 RL 到底提升了什么：训练、推理时扩展与轮级信用三条证据链 —— 三篇论文合并精读

多轮 agentic RL 已经成了训练长程 agent 的默认范式：让模型在环境里反复交互、消费反馈、修正后续动作，轨迹成功率显著上升。
从深度研究、工具增强推理到 web 交互，应用全面开花；
GRPO、GiGPO、PPO 等算法把单轮的结果奖励顺利扩展到了交互场景。
但一个根本问题始终没有被认真回答：**这些提升究竟来自哪里？**

是模型每一步的决策都变好了吗？
如果是，为什么同一个 RL 模型偶尔还是会犯低级错误？
如果不是，那轨迹级成功率的提升由什么构成——而这种构成在真实部署的紧预算、不可逆动作场景下还靠得住吗？
这些问题不只是学术好奇：当 agent 被放进金融、数据库操作这类没有重试机会的环境里，"靠什么能力得分"比"得了多少分"更决定安全边界。

本期精读的三篇论文恰好构成一条完整的证据链，从三个角度回答同一个问题：

- **第一篇（2611.06483，中科院自动化所、国科大、清华）是诊断**：用 Pass@(K,T) 双维评估框架拆解多轮 RL 的收益来源，发现它并不均匀提升单步动作质量——收益集中在误差恢复与长程韧性，而且依赖充足的交互预算；紧预算下优势缩水甚至反转。顺带给出一个极简的缓解方案 BudgetMix RL。
- **第二篇（2611.06868，MBZUAI IFM）是推理时扩展**：既然 RL 训练出来的单步动作未必更好，那能否在推理时用轮级 best-of-N（Turn-BoN）补上这一块——每轮采样 N 个候选动作，让一个现成开源选择器在执行前挑一个，结果 pass@1 提升 5-10%，解题轮数减半。
- **第三篇（2611.06728，TurnWise）是训练时重构**：把 RL 训练信号本身对齐到轮粒度——用静默补全前缀打分构造"剩余回报"的轮级优势，配合 turn-mean 损失聚合，在流式视频理解三基准双骨干上全面领先，重复率下降 61.5%。

诊断、推理时补强、训练时重构，三篇论文的共同结论可以浓缩成一句话：**"轮"（turn）是多轮 RL 的正确基本单元——理解 RL 提升了什么要看到轮级，推理时扩展要做在轮级，训练信号的信用分配与权重也要落在轮级。**
轨迹级指标会同时掩盖问题（第一篇）和错配信用（第三篇），而轮级干预则能在不重训（第二篇）或最小改动（第三篇）的前提下兑现收益。

## 论文一：What Does Multi-Turn Reinforcement Learning Really Improve in LLM Agents?

> **论文链接**：https://arxiv.org/abs/2611.06483
>
> **机构**：中国科学院自动化所（认知与决策智能复杂系统重点实验室）、中国科学院大学人工智能学院、清华大学——纯高校/科研院所合作，无企业参与
>
> **项目页**：https://rethinking-agentic-rl.github.io/

### 一、题目

标题直译是"多轮强化学习究竟提升了 LLM agent 的什么能力？
"。
这个问句本身就是全文的姿态：不提出新方法、不刷新纪录，而是对已经蔚为大观的多轮 agentic RL 做一次解剖。
它的潜台词是——大家都在报告轨迹级成功率的提升，但成功率是一个终点指标，它无法区分"每一步都走得更稳"和"靠后续轮次把前面的错误救回来"这两种截然不同的能力结构。

而这两者的区别，恰恰决定了 agent 在真实部署中是否可靠：如果 RL 提升的是前者，那么收益在任何预算下都应该成立；
如果是后者，那么收益就隐含地依赖"犯错之后还有轮次可用"这个条件——而现实中的硬预算限制、不可逆动作（金融交易、数据库写操作）恰恰会抽走这个条件。
标题用一个问号把整个社区习以为常的叙事打了一个问号。

### 二、背景

这项工作嵌在两条文献脉络的交汇处。

第一条是**单轮 RL 机制分析**。
Yue 等人的 Pass@K 分析发现单轮 RLVR 并不能扩张基模型的能力边界，只是对已有解重加权；
ProRL 报告长时间 RL 可以扩张边界；
Yuan 等人把增益归因于旧技能重组（f(g(x)) 式的组合）；
Wu 等人则称之为潜在基模型行为的放大。
这些发现共同提示：最终成功可能掩盖 RL 增益的真实来源——单轮领域已经学会了不轻信终点指标。

第二条是**多轮 agentic RL**。
GRPO、GiGPO 等方法把结果奖励扩展到交互任务，评估却几乎都停留在轨迹级成功。
最相关的前作（Zhai et al. 2026）提出了 Pass@(K,T) 指标并观察到 agentic RL 能超越基模型能力边界——本文正是借用这一指标，但把问题向前推进两步：超越边界之后，收益依赖什么条件、分布在轨迹的哪些位置、机制是什么。

此外，过程监督方向的工作（GiGPO 的状态分组优势、SPA-RL 的逐步归因、ARPO 的熵引导探索）都在尝试给多轮 RL 更细的信号，但没有人系统回答过"轨迹级 RL 到底把什么能力练强了、把什么能力练弱了"。本文补的就是这块空白。

### 三、定位

这是一篇机制分析论文，附带一个轻量的工程缓解方案（BudgetMix RL）。
定位类似"给 agentic RL 做体检"：体检项目包括轨迹级双维评估（Pass@K 与 Pass@T）、状态匹配的逐步动作质量分析、似然分析（动作 NLL 与轨迹累积对数似然比）、训练动态追踪。
它的贡献不在于任何单项技术，而在于把一组互相咬合的证据摆在一起，逼出一个此前被轨迹成功率掩盖的结论。

作者团队来自中科院自动化所与清华（国科大人工智能学院为联合培养单位），长期做 agent 训练、奖励建模与环境工程，这篇是他们"重新审视自家范式"的反思之作——论文的 AI 使用声明里还专门注明曾评估 LLM judge 作为过程奖励模型，作者核实了全部数值。
这种自我审计式的立场在方法论文里相当少见。

### 四、问题定义

核心问题是：**多轮 agentic RL 的性能增益究竟由什么构成，在什么条件下成立？** 拆成四个子问题：

1. 沿采样宽度 K 扫（Pass@K），RL 是否扩张基模型的经验能力边界？
2. 沿交互深度 T 扫（Pass@T），增益是否稳定存在？
3. 在相同状态下，RL 模型的单步动作是否系统性更好？
4. 如果不是，轨迹级增益从何而来——机制是什么？

实验设定覆盖四个模态各异的交互基准：DeepCoder-MT（多轮代码生成，每轮可提交程序、查看单测反馈、再修改）、BFCL v3（函数调用）、InterCode-SQL（交互式 SQL，基于 Spider 构造）、FrozenLake（具身规划网格世界，训练与测试地图不相交）。
主模型为 Qwen3-4B 与 Qwen3-8B，主算法为 GRPO，辅以 GiGPO 与 PPO 验证结论的算法无关性；
训练基于 VeRL 框架，学习率 1e-6、每任务组采样 G=16 条轨迹、KL 系数 0.001。

评估用 Pass@(K,T)：固定 K 扫 T 得 Pass@T（主文 K=8），从而把"交互深度"从混杂的轨迹成功率里隔离出来。
各任务的满预算分别为 FrozenLake Tmax=70、DeepCoder-MT Tmax=10、BFCL-v3 Tmax=24、InterCode-SQL Tmax=10；
评估在温度 0.6、top-p 0.9 下进行，base 与 RL 用完全相同的任务实例、prompt 模板与轨迹数，Pass@k 采用无偏估计量。
一个容易混淆的伪象被专门排除：紧预算下任务可能结构性无解（FrozenLake 最短路径超过 T 步就到不了终点），作者对每个任务计算了结构性表现上限（FrozenLake 用最短路径、BFCL 用官方标注的参考轨迹、两个代码任务因其每轮即可完整提交故上限恒为 100%），证明在距离上限还有大量余量时 RL 依然没有优势——增益消失不是"任务变无解"造成的。

### 五、解法

论文的"解法"分两层：先是**分析框架**，后是**缓解方案**。

分析框架有三个关键设计：

- **状态匹配的逐步质量评估**：从 base 与 RL 轨迹中均衡采样中间状态构造状态池（排除状态访问分布差异的干扰），在每个状态上分别从两个策略各独立采样 G=16 个动作，用任务自带的可靠步级度量打分——FrozenLake 用有限 horizon 动态规划（折扣 0.95）算每个动作的精确 Q* 值，DeepCoder-MT 用候选程序在官方单测上的通过率。这是全文最硬的一块实验设计：它把"单步谁更好"变成了可以精确测量的问题。
- **误差态构造**：在中间状态注入一个错误动作（FrozenLake 注入增大到终点最短路径距离的动作；DeepCoder-MT 用 Qwen3-1.7B 把代码改坏，若单测通过率下降则采纳），比较两模型在"刚犯错之后"的决策质量与续跑成功率。
- **似然分析**：固定历史，计算 RL 动作在 base 策略下的 NLL（局部合理性），以及完整轨迹在两策略下的累积对数似然比 LLR（整体偏好）——两者分别回答"RL 的单步动作离 base 分布多远"和"RL 策略偏爱自己轨迹多少"。

**诊断结论**环环相扣：

1. **Pass@K 上 RL 全面领先**（K 从 1 扫到 128）：与单轮 RL 不同，多轮 RL 确实能把轨迹级成功推出基模型的经验能力边界（Takeaway 3.1）。
2. **但 Pass@T 上增益依赖充足预算**：固定 K=8 扫 T，预算收紧时优势缩水，某些任务上甚至反转（base ≥ RL）。结构性上限分析排除了"任务无解"伪象（Takeaway 3.2）。
3. **逐步质量并不均匀提升**：状态匹配比较中，RL 动作仅在 46.8%（DeepCoder-MT）和 42.8%（FrozenLake）的状态上更好，平均质量差 Qstep 为 -0.005 与 -0.018——整体还略偏向 base（Takeaway 3.3）。
4. **优势集中在误差态与轨迹后段**：误差态上格局反转，RL 在 67.3%（DeepCoder-MT）和 65.7%（FrozenLake）的误差态上选出更优动作（Qstep +0.112/+0.071）；
从相同误差态继续执行，RL 最终成功率 51.3% vs base 38.6%（FrozenLake）、38.5% vs 22.9%（DeepCoder-MT）。
按归一化轨迹深度 t/Tmax 分组，RL 早期无优势甚至更差，随交互展开逐渐反超。
5. **似然分析给出机制解释**：RL 动作在 base 策略下的平均 NLL 为 12.20，与 base 自身动作的 10.25 大幅重叠——单步动作仍是"局部合理"的；
但成功 RL 轨迹的累积 LLR 达约 228，base 成功轨迹仅约 26：RL 策略给自己的完整轨迹赋予了高得多的概率。
单步条件概率合理不等于整条轨迹能被可靠采出——多轮 RL 学到的是**把局部合理的动作可靠组合成长程轨迹的能力**。
6. **训练动态证实这不是终点巧合**：优化轨迹奖励 Rmulti 的过程中，DeepCoder-MT 上 Rmulti 上升 0.331，步级奖励 Rsingle 却下降 0.097——轨迹增益与步级退化在训练中并行发展，逐步侵蚀是 RL 优化的内生趋势。

**缓解方案 BudgetMix RL** 极其朴素：保持奖励机制不变，只把交互预算从固定 Tmax 改为训练维度——对每个任务按 10% 间隔构造候选预算集合（去重后）并均匀采样一个，总预算与剩余轮数写进系统 prompt（budget-aware 模板在训练与评估中保持一致），超预算未完成记零分。可与 GRPO、GiGPO、PPO 组合；GiGPO 的锚点匹配额外把剩余预算 (st, B−t) 纳入状态。其思想是：**紧预算限制重试机会、要求早期决策更谨慎；充足预算保留长程执行机会；让模型在两种条件下都见过、都练过。**

**结果**：Pass@8 评估下，25%/50%/75% 预算档 BudgetMix 在全部四个任务上全面超过 full-budget RL 与 base（两种模型规模、三种算法平均）：25% 档增益最大（4B +7.9、8B +7.3 个点量级，DeepCoder-MT 8B 上高达 +13.2），50% 档 +5.2/+4.7 左右，75% 档 +3.8~+4.2，100% 档 +1.0~+1.6（四任务总平均 4B +4.2、8B +4.8）——低预算增强不以牺牲长程能力为代价。看几个具体数字更直观：FrozenLake 8B GRPO 的 25% 档从 full-budget 的 31.9 升到 40.8，DeepCoder-MT 8B GRPO 的 25% 档从 31.5 升到 45.5；同时 100% 档上 GRPO BudgetMix 79.6 对 full 的 78.0、PPO BudgetMix 86.7 对 full 的 85.0，满预算不降反微升。训练动态上，BudgetMix 的 Rmulti 升 0.323 的同时 Rsingle +0.006，不再出现步级质量侵蚀。

作者还讨论了过程监督这条路的边界：FrozenLake 上 oracle Q 值过程奖励与 GiGPO 能稳住紧预算表现，但真实任务（BFCL）没有精确步级 oracle，稠密信号方法（GiGPO、PPO）表现与 GRPO 相当，连 GPT-5.6-Sol 做的 LLM judge 过程奖励也无济于事——高质量过程信号在现实中不可得，这正是 BudgetMix 走"更简单的路"的理由。

### 六、知识反推

从这篇论文可以反推出一条关于多轮 RL 的完整因果链：

**轨迹级结果奖励 + 充足预算 → 收益可以通过"犯错-恢复"循环兑现 → 梯度自然偏向增强误差恢复与后段韧性，而非均匀提升单步质量（Rsingle 随训练下降是内生趋势）→ 一旦部署环境预算收紧或动作不可逆，收益的基础就被抽走。**

似然分析补上了中间机制：RL 不需要把每个动作的概率质量推得比 base 更高（NLL 重叠：12.20 vs 10.25），它只需要让"好动作的组合"在自己的策略下变得高概率（LLR 悬殊：228 vs 26）——这是一个**组合层面的概率重新分配**。
这也解释了为什么 RL 能突破 Pass@K 边界：边界之外的成功不是靠某个更聪明的单步，而是靠一条在 base 策略下概率极低的完整轨迹被 RL 策略托举起来。
论文一的图 1 给了一个二轮玩具例子：base 策略在 T=2 时成功率 0.74 高于 RL 的 0.84 反例方向上，等到 T=3 多出一次纠错机会时 RL 反超——预算改变的不是任务，而是两类能力的相对价值。

BudgetMix 的成功则反推另一个教训：**交互预算不是一个中性的评估参数，而是任务本身的一部分条件**。
同样的奖励在不同预算下含义不同（紧预算下"能重试"的价值归零），把它变成训练分布的一个维度，等于让模型学会对预算条件化——这和课程学习、域随机化的精神一脉相承，但随机化的对象是"资源约束"而非任务难度。
值得注意的是 prompt 里明确告知总预算与剩余预算，模型因此获得了规划所需的完整信息；
没有这个条件化通道，随机化本身未必可学。

### 七、通用灵感

1. **终点指标会撒谎，撒谎的方式是"平均掉结构性差异"。** 轨迹成功率把"每步更稳"和"更会救场"混为一谈；
任何长程系统的评估都值得问一句：增益分布在时间轴的哪些位置、分布在哪些状态类型上？
本文的"误差态/正常态分桶 + 轨迹深度分段"是可以平移到任何 agent 评估的模板。
2. **"能力依赖条件"是部署风险的主要来源。** 训练与评估默认的隐性条件（这里是充足预算）在真实环境中往往不成立。审计一个系统时，把所有隐性条件显式化、逐个施压（本文是把 T 从 Tmax 压到 25%），是发现脆弱性的通用手法。
3. **把评估维度变成训练维度，是最廉价的鲁棒性方案。** BudgetMix 没有改算法、没有加 critic、没有新奖励，只是把"T"从评估扫参搬进训练分布——这个思路可以平移到任何"模型在某维度上表现不稳"的场景：上下文长度、工具可用性、噪声水平、并行度。
4. **组合能力与单点能力是两种资产，需要不同的护栏。** 论文证明可以只提升前者而牺牲后者（Rsingle 下降）。团队在做能力评估时应区分"单步决策质量"与"长程组合可靠性"；不可逆动作场景（提交、发送、删除）尤其需要单步质量护栏——因为那里没有误差恢复的舞台。
5. **机制分析要有"反事实对照"。** 本文每个结论都配了对照片：结构性上限排除无解伪象、状态池均衡采样排除访问偏差、LLR 与 NLL 互相印证。做分析型工作时，先设计好"结论的替代解释"，再为每个替代解释准备证据，结论才立得住。

## 论文二：On Turn-Level Best-of-N Sampling for Scaling LLM Agents

> **论文链接**：https://arxiv.org/abs/2611.06868
>
> **机构**：Institute of Foundation Models (IFM), MBZUAI Labs——纯研究机构（阿布扎比），也是生成器之一 K2-Horizon 的发起方
>
> **代码**：原文未提供

### 一、题目

标题直译是"论轮级 Best-of-N 采样用于 LLM agent 的扩展"。
关键词是"turn-level"：既有的 agent 推理时扩展主要在轨迹级做 best-of-N——并行生成 N 条完整轨迹、用裁判打分、挑最好的一条；
本文把选择粒度下沉到每一轮：每轮生成 N 个候选动作，选一个执行。
标题里一个不起眼的"On"透露了论文的姿态：这是一篇系统评估论文，核心贡献不是发明这个想法（作者坦诚与 Kang et al. 2026 为并发独立工作，且已互相知悉），而是把它**在大模型尺度上用开源选择器做扎实的实证，并解释它为什么有效、改变了什么、代价几何**。

### 二、背景

推理时扩展的主流方案各有痛点。

**轨迹级 BoN**（Kwok et al. 2026 用 LLM 裁判对完整轨迹按 rubric 打分）的选择发生在轨迹完成之后——它只能挑选结果，无法改变轨迹中间动作的分布；而且它需要 N 份并行环境执行。这对跑在用户自己机器上的 agent 是硬伤：终端 agent、computer use agent 的沙盒就是用户的机器，"N 个沙盒"根本拿不出来；即便顺序生成 N 条再评分，时间上也不可行。**DFS/MCTS 等搜索方法**需要环境状态的检查点与回滚，在真实交互环境里同样不现实。**训练 critic 做值引导生成**（Zainullina et al. 2025 在数学与 SWE 任务上用 critic 引导搜索）有效，但要专门训练一个状态-动作值函数。

本文的问题是：**能不能不训 critic，直接用现成的开源 LLM 当"生成式裁判"，在每轮执行前从 N 个候选里挑出最好的动作？**
这个想法在 RL 历史上有深厚渊源——大动作空间下"采样候选集+值选择"是 BCQ、EMAQ、Muesli 等工作反复验证过的经典套路（连续动作空间没法枚举 argmax，就采样一批再挑）。
本文相当于把这个经典想法移植到 LLM agent 的推理时，并系统回答它在 agentic 场景下是否成立。

### 三、定位

这是一篇实证评估+轻量理论的论文。定位上有三个鲜明特点：

第一，**规模大且全开源**——生成器用 Qwen3.6-35B（中档）与 K2-Horizon-375B（MoE 大模型），选择器用 Kimi-K3 与 DeepSeek-V4.1-Flash 两个开源旗舰，与并发工作（4B-9B 小生成器 + 闭源 GPT-5.6-Sol 选择器）在规模与开放性上形成互补。
第二，**不求实用求机理**——作者明说这更像一个"思想实验"：每轮 N 个候选加选择器推理的代价（总 token 3.6-8.7 倍）被如实量化，留给后续工作去优化（方向包括只在部分轮启用、蒸馏小选择器）。
第三，**分析深**——不止报 pass@1，还拆解了选择器每轮挑了什么类型的动作、轨迹级行为如何随之改变、失败轨迹是否也变好了、不同强度的生成器获益来自哪里。
MBZUAI IFM 既是 K2-Horizon 的发起方，做生成器规模效应的实验有天然优势。

### 四、问题定义

研究问题：**在复杂长程终端任务上，用现成开源 LLM 做逐轮动作选择，能否提升任务成功率与稳定性？增益的机制是什么、代价多大、对生成器能力如何缩放？**

实验设定：Terminal-Bench v2.1（89 个真实终端任务，涵盖命令行环境中的软件工程与系统管理操作）× 每配置 4 次试验，mini-SWE-agent harness。
生成器基线 pass@1 约 47.5%（Qwen3.6-35B）与 73.3%（K2-Horizon-375B）；
选择器在 Terminus-2 harness 上 pass@1 约 88%（Kimi-K3）与 82%（DeepSeek-V4.1-Flash）——刻意构造"选择器强于生成器"的设置，且两档生成器差距悬殊，便于观察增益随生成器能力如何缩放。
候选数 N∈{4,8}（预实验发现 N=2 与基线几乎相同），生成温度 1.0、top-p 0.95，选择器用 Kimi-K3 max / DeepSeek-V4.1-Flash high 推理档，listwise JSON 输出候选索引。

评估维度刻意做得立体：pass@1 与 pass@k（能力）、consistency@k（4 次试验中至少 k 次成功的任务占比，稳定性——前沿模型在同一任务上的表现时好时坏，一致性本身就是稀缺属性）、解题轮数分布（效率）、28 条坏行为 rubric 的轨迹标注（行为质量，其中 13 条来自 Wang 等人对真实 SWE agent 轨迹的归纳，另 15 条为本文新增的诊断/测试/需求覆盖类检查项）、token 开销（成本，以生成器与选择器的输出 token 计，避免基础设施相关的墙钟时间干扰）。
行为标注只给裁判看任务与完整轨迹、不给正确性信息，且每条轨迹判两次取平均，以避免"结果污染过程评价"。

### 五、解法

**方法本体极简**：每轮，生成器以相同上下文 i.i.d. 采样 N 个候选动作；选择器以 listwise 方式读入完整交互上下文+候选列表，推理后返回最佳候选的索引；被选中的动作进入终端执行，观察追加进上下文，进入下一轮。两个关键工程决策：选择采用 listwise（一次性给全列表让选择器比较）而非 pointwise/pairwise——未校准的逐点打分需要多裁判多次调用，锦标赛式两两比较代价 O(N·k) 在小规模实验中已被发现过于昂贵；**选择发生在执行之前——只有被选中的动作接触环境**，不需要 N 个沙盒，这是与轨迹级 BoN 最关键的工程区别，也是整个方案在真实部署中唯一可能落地的前提。

理论部分把直觉形式化。
经典策略改进定理（Sutton et al.）保证对 Qπ 贪心的策略不劣于 π；
但那需要对所有动作取 argmax 且逐状态成立。
作者证明了一个弱化版（命题 2）：设 πN 为 Turn-BoN 诱导的策略（先从 π 采 N 个候选、再经选择器选择的两段式分布），若在 πN 的折扣稳态状态访问分布 d^πN 下，被选动作的平均优势非负——E_{s~d^πN, a~πN}[A^π(s,a)] ≥ 0——则 J(πN) ≥ J(π)。
注意条件只需在**平均意义下、在 πN 自己访问的状态上**成立，不必逐状态：这解释了为什么一个不输出数值分数、甚至不完美的生成式选择器也能稳定改进——它只需要在多数访问状态上"平均不选错"。

**实验结果**分四层：

1. **通过率与一致性**：Qwen3.6-35B 从 47.5% 升至 52.8%（N=4）、55.2%（N=8）；
K2-Horizon 从 73.3% 升至 77.9%（N=4）、76.7%（N=8）——5-10 个百分点的量级。
pass@k 曲线在小 k 处覆盖更高（轮级选择把生成器"往正确的方向引导"），consistency@4 同步提升。
增益受生成器能力上界约束，但弱生成器（与选择器差距更大）获益更多。
两档生成器上 N=8 均未稳定优于 N=4，暗示宽度收益在 4-8 之间已接近饱和。
2. **效率**：解题轮数 N=4 时约降 40%、N=8 时约降 50%——选择器在每轮滤掉空转动作，轨迹更短。
3. **行为层面**（全文最精彩的部分）：对每轮被选动作按命令模式分类为八类行为（编辑文件、测试最近修改、跑测试/检查、安装包、链式命令、只读检查、命令循环、畸形调用），与"从 N 个候选均匀随机选"的对照相比，选择器显著偏好"做实事"的行为、显著回避"空转"行为——所有行为偏好差距经 10000 次配对 bootstrap 检验 p<0.01（仅 K2 生成器上的命令循环一项不显著）。
被选动作的 shell 命令总字符数也显著更长——选择器偏好把多条命令链式组合的"复合动作"。
轨迹级用 LLM 裁判（DeepSeek-V4.1-Flash-1017）按 28 条坏行为 rubric 标注 36 个难任务共 360 条轨迹：循环行为占比降 14-18 个点（p<0.05），"未诊断就重试"降 11-22 个点。
**更关键的是失败轨迹也变好了**：失败轨迹的平均坏行为数从 3.9 降到 2.7（K2）、8.9 降到 6.8（Qwen3.6，满分 28）——失败变成了"认真做完但能力不够"的失败，而不是"卡死在坏行为模式里"的失败。
K2 的失败基线轨迹有 33% 在重跑失败命令，BoN 下降到 10%；
忽略任务指令的从 28% 降到 15%；
Qwen3.6 未诊断重试从 50% 降到 26%、"写了不可能失败的测试"从 65% 降到 47%。
4. **代价与失败模式重分布**：每条轨迹总 token 为基线的 3.6-8.7 倍（如 K2 基线 72K → N=8 时生成器 334K+选择器 69K）；
选择器为弱生成器推理更多（Qwen3.6 配置下选择器 token 89-125K，K2 仅 67-107K）——候选质量分布越散，选择越费力。
失败构成上，K2 的增益主要来自上下文超限（4.2%→1.1%）与 agent 错误（2.2%→0.7%）的锐减——选择器帮强模型及时收手交卷而不是无休止调查；
Qwen3.6 的增益主要来自错误提交从 44.9% 降到 34.6%——选择器每轮把候选对着任务要求打分，帮弱模型对齐需求。
**同一个干预在强、弱生成器上修的是不同的病。**
附录还验证了增益不来自作弊/hacking 行为。

### 六、知识反推

增益的因果链可以被完整反推出来：

**随机策略在同一任务上成败并存（这正是论文一"组合能力≠每步能力"的另一面）→ 每轮 N 个候选扩大了动作覆盖 → 强选择器在候选间区分"推进任务"（编辑、测试、链式命令）与"空转"（只读、死循环、畸形调用）→ 逐步选择近似满足命题 2 的平均优势条件 → 诱导策略整体改进 → 轨迹更短、更一致，失败轨迹也展现更好的工程行为。**

与论文一对读会得到一个漂亮的互补结论：论文一证明 RL 训练出来的策略"单步不更好、组合更可靠"；
论文二证明反过来也成立——**单步决策质量可以通过推理时的选择器补齐，而且这个选择器不需要训练**。
两者共同指向：agent 的"单步决策质量"与"轨迹组合能力"是两个可分离、可分别干预的自由度。
训练（RL）目前主要改善后者，推理时（Turn-BoN）目前主要补前者。

还有一层反推关于选择器的作用机理：它每轮把候选动作对着"任务要求"评审，等于把需求满足检查内嵌进了生成循环——Qwen3.6 的错误提交大降正是因为此（基线常常"检查自己写了什么"而非"检查任务要什么"，这与它 44.9% 的错误提交率互为因果）。
这与 rubric 式过程奖励的思路殊途同归，但零训练成本。
另一个细节：选择器对弱生成器要花更多推理 token——**裁判的难度与被审对象的质量负相关**，候选质量越散、真假辨别越费力。
这为"蒸馏小选择器"的路线给出了一个预警：小选择器的推理预算可能更吃紧。

### 七、通用灵感

1. **选择粒度决定干预能力。** 轨迹级选择只能"事后挑尸检报告"，轮级选择能"事中做手术"——前者改变结果分布，后者改变过程分布。任何级联/多阶段系统里，把评估与选择下沉到最小决策单元，通常能解锁对过程分布的塑造能力。
2. **"执行前选择"规避了对环境并行的苛刻要求。**
让 N 个候选纸面竞争、只让赢家接触副作用——这个模式可平移到任何副作用昂贵或不可逆的场景（数据库写、对外发送、文件系统变更、生产环境操作）：用廉价的评审替代昂贵的试错。
这与论文一的"不可逆动作需要单步质量"结论形成工程上的呼应。
3. **强模型当裁判的经济学要算清楚。**
用 88% 能力的模型给 47%-73% 能力的模型当逐轮选择器，token 开销 3.6-8.7 倍换来 5-10 个点。
论文诚实指出这不实用，但指明了两个优化方向：只在部分关键轮启用 BoN（哪些轮是关键轮本身是个好研究问题）、蒸馏专用小选择器。
任何"贵但有效"的方案都值得这样拆解其成本结构，而不是笼统地问"要不要用"。
4. **失败轨迹的质量是独立于成功率的资产。**
论文专门分析失败轨迹的行为改善——一个"干净地失败"的 agent 比一个"肮脏地失败"的 agent 更容易调试、更容易从日志里学习、也更可能只是差临门一脚。
评估 agent 时把失败轨迹的行为质量纳入度量，是被普遍忽视的实践。
5. **理论不必精确才有用。** 命题 2 的条件（平均优势非负）无法事前验证，但它把"为什么生成式裁判也有效"从直觉变成定理，并给出了失败模式（选择器系统性偏坏）的判据。工程论文里这类"弱但对"的理论刻画值得更多。

## 论文三：Turns Matter: Advancing Streaming Video RL via Turn-Level Credit（TurnWise）

> **论文链接**：https://arxiv.org/abs/2611.06728
>
> **机构**：复旦大学、上海创新研究院、京东、斯坦福大学、上海人工智能实验室、香港中文大学、北京大学、东京大学、香港科技大学、香港大学——横跨中美日、企业+多高校的产学研大协作（上海流式多模态研究集群）
>
> **代码/模型/数据**：原文标注有 Code/Model/Dataset 链接占位

### 一、题目

标题直译是"轮很重要：经由轮级信用推进流式视频 RL"。
主标题两个词就把论文的立场说完了：流式视频 RL 现有的 GRPO 训练把一条轨迹的优势广播到所有轮上，这个粒度是错的——轮才重要。
副标题里的"Turn-Level Credit"点明手段：不是改奖励设计（那是 MMDuet2、ThinkStream、StreamPro 的路线），而是改**信用的分配与聚合粒度**。
方法名 TurnWise 一语双关：既指"按轮明智地（wise）分配"，也谐音 turn-wise（逐轮地）——命名本身就是论文论点的浓缩。

### 二、背景

流式视频理解要求模型在观测仍在到达时反复决策"现在回应还是继续观察"。
论文开头的例子很直观：看一个烹饪视频，用户问"最终的菜长什么样"——模型在 112 秒看到盛盘时应该第一次回应，116 秒补一句香草碎的细节，此后 120/124/128/130 秒的重复回答则是纯冗余。
一个合格的助手应当在有新证据时回应、有补充信息时跟进、再说只是重复时保持沉默——这个判断同时取决于当前视觉证据与"模型已经说过什么"。

这个设定与论文一的 agent 设定在形式上同构：都是多轮交互、都以轨迹级奖励做 GRPO 训练。
现有方法都在**奖励设计**上做文章：MMDuet2 用 PAUC 奖励+短跨度训练缓解奖励稀疏与时间信用分配；
ThinkStream 用正确性+格式+时机奖励训练增量推理；
StreamPro 组合轮级响应分数与轨迹级连贯奖励。
但它们共享同一个盲区：**GRPO 的优势估计始终是轨迹级的**——一条轨迹一个优势，广播给每个动作 token。
论文点破了一个微妙的区分：turn 级打分与 turn 级策略信用是两回事，你可以给每一轮打分（StreamPro 就做了），但只要优势还是共享的，学习信号就还是轨迹级的。

### 三、定位

这是一篇方法论文，但有清晰的诊断先行。它识别出流式视频 RL 的两个**粒度失配**：

1. 共享轨迹优势会让好轨迹里的坏轮继承正信用（早期回答成功后，冗余重复仍被强化——即使奖励里已有重复惩罚项）、坏轨迹里的好轮背负负信用（早期失败后有价值的跟进被压制）；
2. token-mean 损失聚合让长回应在损失里天然压过短的等待动作——而"等待"恰恰是流式交互里与"回应"同等重要的一等动作，一个 NO REPLY 可能只有一个特殊 token，却在决策意义上与一段完整回答等价。

TurnWise 的两个组件分别对应这两个失配：**信用分配决定每轮学什么方向，损失聚合决定每轮占多大权重**。
机构阵容庞大（复旦/京东/上海AI实验室/Stanford 等十家），基准、奖励与训练管线大量复用 MMDuet2 的设置（PAUC 奖励、gpt-oss-20b 裁判、20 秒片段、G=4），属于站在同领域前作肩上的定向改进——把前作"奖励设计"路线遗留的"信用粒度"问题补齐。

### 四、问题定义

问题：**如何在不引入 critic、不增加 rollout 的前提下，把 GRPO 的学习信号对齐到流式决策轮粒度？**

约束条件很实际：流式视频 RL 的奖励（PAUC 打分）本身要调 LLM 裁判，每条轨迹的评估已经不便宜；任何需要额外 critic 网络（PPO 路线）或额外采样/裁判调用的方案都会让训练成本失控。理想方案应当只重用已有的东西。

形式化设定：流式实例包含视频输入 x、用户问题、初始对话历史 h0 与观测计划（决策时间网格）。
每轮策略生成文本回应或显式等待输出 NO REPLY（∅）；
等待不产生用户可见输出，但作为生成动作与回应一起被优化。
同组 G 条轨迹共享观测（对齐的观测计划与 horizon T）但对话历史可因早期回应不同而分叉——因此一个新回应的价值同时取决于已有证据与已传达信息，这正是"同一个回应在不同上下文里价值不同"的结构性来源。
轨迹奖励沿用 MMDuet2 的 PAUC 组合：Ri = 3Pi − 2Drep_i − 0.5Dout_i − 2Dprefix_i，其中 Pi 度量回复窗口内的质量与及时性（同样质量越早回应贡献越高），三项惩罚分别针对信息重复、窗外回应与共享前缀违规——注意这些项都是**非可加**的（重复率是整条轨迹的比例），这为后文的分解技巧埋下伏笔。

### 五、解法

TurnWise 的两个机制都围绕"决策轮"这一公共单元展开。

**机制一：静默补全前缀打分 → 剩余回报优势。** 核心观察是：等待是显式动作，所以可以把"第 t 轮之后的动作全部替换为沉默"的前缀拿给**同一个**轨迹裁判打分，得到 Ui,t = R(ai,1,…,ai,t,∅,…,∅)——它度量"保留前 t 个决策、此后不再说话"能拿到的奖励。每个前缀都用与完整轨迹相同的初始历史、决策时间戳、回复窗口与评估 horizon 打分；端点上 Ui,0 是全沉默参考（未必为零——初始对话历史里的既有回复也计分），Ui,Ti = Ri。

由此定义第 t 轮的**剩余回报** Fi,t = Ri − Ui,t−1：从该轮开始的采样延续还能挣多少分。
差分 ri,t = Ui,t − Ui,t−1 给出轮级奖励增量，而 **telescoping（裂项）恒等式保证这个分解对非加性奖励项也精确成立**——Ui,t 逐项加总恰好回到 Ri，不管 R 里包含多少比例型、窗口型的非可加项。
这是整个方案数学上最漂亮的一步：不需要假设奖励可加，只需要"沉默"这个可执行的反事实。

然后在 rollout 组内、在对齐的轮 t 上做组相对化：Âi,t = clip[(Fi,t − F̄t)/(σR + ε)]，clip 到 ±amax=5。
第二个等价形式把修正写得更直观：Âi,t = clip[(A_global_i − α(Ci,t−1 − C̄t−1))/(σR + ε)]，其中 Ci,t−1 = Ui,t−1 − Ui,0 是决策前已累积奖励——**轮级优势 = 全局优势减去"决策前已经挣到的分"的组相对量**。
早于平均的成功不再直接给后面的冗余回应抬轿，早于平均的失败也不再压低后面有价值的跟进；
一条 Ri 高于组均值的轨迹，完全可能在后段拿到负轮级优势（若其剩余回报低于组均值）。
修正强度由 α∈[0,1] 插值控制（α=0 退化为标准 GRPO，α=1 完全修正），训练前 10% 的更新里从 0 线性升到 1（信用热身）。
计算上复用已缓存的逐轮评分做确定性扫描——**零额外 rollout、零额外裁判调用、零 critic**。

**机制二：turn-mean 损失聚合。** 标准 GRPO 按总 token 数平均，第 t 轮权重为 Li,t/Σs Li,s——一条 100 token 的长回应压过一条 1 token 的等待。TurnWise 改为先在轮内对 token 损失取平均、再跨轮平均：Li = (1/Ti)·Σt[(1/Li,t)·Σk ℓi,t,k]，每个"回应-或-等待"决策获得相等权重 1/Ti，与输出长度无关。

**训练管线**：Qwen2.5-VL-3B 与 Qwen3-VL-4B 先在 100,874 条指令（EgoExo4D、EgoExoLearn、Live-WhisperX、Tarsier2、LLaVA-Video，1% 留验证）上 SFT 一轮（lr 1e-5、冻结视觉塔），再在 3,983 个流式实例上做 GRPO 式 RL（batch 8、G=4、温度 1.2、top-k 10、AdamW 1e-6、一个策略优化 epoch、无 KL/熵正则、δ=0.2 双重裁剪），遵循 MMDuet2 的 20 秒目标片段与两秒采样至多 90 帧设置。所有 RL 基线（MMDuet2、ThinkStream、StreamPro）在同一流式 GRPO 框架、同一 SFT 初始化、同一奖励裁判下复现，保证对比只反映方法差异；评估用贪心解码，模型只看已观测前缀与自己之前的回应。

**结果**：三基准双骨干全部最佳——ProactiveVQA PAUC 43.56（3B）/42.44（4B）、OVO-Timing 平均 Timing F1 21.59/11.15、StreamingBench 平均 49.43/58.96，分别超过最强非 TurnWise 基线（MMDuet2/ThinkStream/StreamPro）+3.96/+3.87/+0.69（3B）与 +6.26/+1.92/+2.38（4B）。分项上 4B 的 VAD 与 Web 类别较最强对手提升 3.49 与 6.43 个点，StreamingBench 主动准确率从 35.60 升至 38.40。

消融（3B）显示两机制互补：相对"仅信用修正"，完整 TurnWise 重复率从 15.53 降到 5.98（-61.5%）、Timing F1 升 2.96、StreamingBench 升 0.49；
相对"仅 turn-mean"，Timing F1 提升 13.42 个点、重复率再降 38.9%。
α 敏感性上，完整框架内 α=1 在 PAUC、Timing F1、StreamingBench、重复率四项上全面最优。

**最有说服力的是信用重分配的取证**：在 11,116 条真实训练轨迹（84,184 个决策）上，21.20% 的决策相对全局分配**改变了优势符号**，53.15% 的轨迹同时收到正负两种轮级优势——单条轨迹内部的决策获得了不同方向的学习信号；被判重复的 2,972 条回应中，带正全局优势的重复回应有 59.83%（722 中的 432 条）被轮级信用改为负优势；全部重复回应获得负优势的比例从 75.7% 升至 81.6%。训练动态上，turn-mean 让末段 50 次更新的平均奖励从 0.657 升至 0.711、重复惩罚从 0.069 降至 0.036，窗外回应比例从 0.537 降到 0.289，非沉默决策比例从 62.2% 降到 37.0%——**奖励更高、回应更挑剔**，模型学会了沉默。

### 六、知识反推

优势根源的因果链：

**轨迹级共享优势把"决策前已累积的奖励"错误地计入当前决策的信号 → 冗余回应继承早期成功的正信用、有用跟进背负早期失败的负信用 → 静默补全前缀打分把轨迹奖励精确分解为"已累积 + 剩余回报"（telescoping 对非加性奖励也精确）→ 21.20% 的决策符号翻转、59.83% 的正优势重复回应转负 → 冗余被抑制（重复率 -61.5%）；同时 token-mean 下长回应主导损失 → turn-mean 给短等待决策等权 → 响应时机改善（Timing F1 +13.42）。**

这里有一个值得单独反推的方法论巧思：**前缀打分之所以可行，是因为这个环境里存在一个"无操作动作"（沉默）**。
大多数 agent 环境没有真正的 no-op（论文二里的终端 agent 每轮必须做事），但凡是存在幂等/可放弃动作的交互系统——对话、监控、告警、推荐、交易里的"不动作"——都可以用同一招把轨迹奖励反事实地分解到决策点，获得 critic-free 的轮级信用。
这本质上是把 return-to-go 原则用环境的结构免费实现了；
相比之下，GiGPO 需要锚状态重复出现、PPO 需要 critic 网络估计，都是更贵的路。

另外，turn-mean 与 Turn-BoN（论文二）在"权重"问题上构成镜像：论文二的选择器让好动作不被生成分布淹没（推理时），TurnWise 的 turn-mean 让短决策不被损失加权淹没（训练时）——两者都在对抗"长输出天然占据主导"的偏差。
而与论文一对照则更微妙：论文一发现 RL 训练会内生地侵蚀单步质量（Rsingle 下降），TurnWise 的 turn-mean 恰好是一种保护短决策权重的训练结构——或许两类设定共享着"轨迹级信号会淹没单元级质量"的深层病因，而粒度对齐是同一个药方的两种配法。

### 七、通用灵感

1. **打分粒度≠信用粒度。** 给每轮打了分不代表每轮得到独立的学习信号——只要优势还在轨迹层面共享，轮级打分就会被平均掉。任何"评估很细、训练信号很粗"的系统（过程奖励模型、rubric 裁判、多维评分卡）都值得检查这最后一公里的粒度失配。
2. **用环境的结构换算力。**
静默补全前缀打分不引入 critic、不加 rollout，全靠"等待动作存在"这一环境性质。
设计信用分配方案时先问：这个环境里有没有可以免费执行的反事实（no-op、幂等操作、可撤销动作）？
有的话，reward decomposition 可以变成一次纯计算。
3. **信用分配（学什么方向）与损失聚合（占多大权重）是两个正交旋钮。**
TurnWise 的消融证明单独拧任何一个都不够（仅信用时重复率反而高达 15.53、仅 turn-mean 时 Timing F1 只有 8.17），合起来才最优。
多数 RL 系统改进只盯着前者，后者（token-mean vs turn-mean vs trajectory-mean）是被忽视的设计空间——尤其当动作长度高度不对称（长回应 vs 短等待）时。
4. **对训练信号做取证，而不只对指标做对比。**
论文用 84,184 个决策的优势符号翻转率、53.15% 的轨迹内正负共存、432/722 的重复回应转负来直接展示机制在起作用——这种"打开引擎盖拍照"的证据比端到端分数更有说服力，也更能在消融失败时定位原因。
做训练方法创新时，为机制本身留下可观测的日志并事后取证，应成为标配。
5. **热身（warmup）是粒度迁移的润滑剂。** α 从 0 线性升到 1 让策略先在熟悉的共享优势下稳定，再逐步切换到轮级信用——任何把训练信号"变细"的改动都可能初期震荡，渐进迁移是低成本的对冲。

## 三篇合读：轮作为多轮 RL 的一等公民

把三篇论文放回一条线上看，图的完整度令人满意。

**论文一给出诊断**：多轮 RL 的收益=误差恢复+长程韧性，不是单步质量；收益依赖充足预算（错误后要有轮次可重试）。用本文的语言说：**RL 学会的是轨迹级的重新组合，而非轮级的逐点改进**——NLL 重叠（12.20 vs 10.25）说明单步没变好，LLR 悬殊（228 vs 26）说明组合变可靠了。

**论文二在推理时补上缺的那一半**：既然训练没让单步更好，就用一个更强的选择器在每轮做近似单步策略改进，命题 2 的平均优势条件刻画了它为何稳定有效；而它的工程前提——执行前选择、只让赢家接触环境——恰好也是不可逆场景最需要的安全结构。

**论文三在训练时重排信用**：既然轨迹级信号会错配轮级决策，就把优势与损失都下放到轮上，用环境自身的沉默结构免费完成分解，21.20% 的决策符号翻转直接展示出被共享优势掩盖的轮级真相。

三篇合起来还有两点超越单篇的观察。

第一，**"轮"正在成为多轮 RL 的通用坐标**：评估上（Pass@T 把交互深度作为独立轴）、推理时（Turn-BoN 把计算花在轮上）、训练时（轮级信用与轮级权重）、诊断上（误差态、轨迹深度分段、优势符号翻转都以轮为单位计量）。
这与单轮推理领域"token/step 作为基本单元"的成熟路径完全同构——一个领域开始认真讨论它的最小决策单元时，通常是它走向精细科学的标志。
论文一的 BudgetMix 甚至把"轮数"本身变成了条件化变量（prompt 里写明总预算与剩余预算），可见轮不只是分析单位，还是模型可以感知并据以规划的输入。

第二，**三条路线的成本-收益结构差异巨大，且互补**。
Turn-BoN 零训练成本但推理代价 3.6-8.7 倍，适合"不能重训、愿意付推理钱"的场景，作者自己标注它目前更是思想实验；
TurnWise 训练结构改动极小（零 critic、零额外 rollout）但需要重训，收益永久固化在权重里，重复率降 61.5% 这类行为级改善只有训练路线能给；
BudgetMix 连算法都不改、只改训练分布与 prompt，是最便宜的鲁棒性保险，25% 预算档 +7 个点以上的增益全部来自"见过紧预算"。
真实系统的合理姿势很可能是组合：BudgetMix 式的条件多样化训练打底、轮级信用保证信号精度、关键轮上叠加选择式的推理时扩展——三层恰好分别覆盖训练分布、训练信号、推理时计算三个正交维度。

第三，**"轮"也是风险治理的切口**。
论文一指出轨迹成功率掩盖了两类部署风险：紧预算下增益消失、单步质量甚至退化——对不可逆动作场景（金融、数据库）这是安全边界问题；
论文二的选择器恰好在执行前把关、只放行胜出动作，天然是一层单步护栏；
论文三的 turn-mean 则从训练端保护短决策不被长输出淹没。
当监管与工程界开始给 agent 划"动作红线"时，轮级的测量（论文一）、轮级的过滤（论文二）与轮级的记账（论文三）提供的是三件现成的工具。

论文一在结论里写道，agent 系统不应只按最终任务成功来评估，还要看其在执行约束下的鲁棒性与单个决策的可靠性。
三篇论文用不同的手法响应了同一个呼吁：**把多轮交互从"一条会得分的轨迹"还原为"一串需要各自负责的决策"——理解它们、选择它们、为它们分别记账。**
这大概就是"Turns Matter"最完整的注脚。
