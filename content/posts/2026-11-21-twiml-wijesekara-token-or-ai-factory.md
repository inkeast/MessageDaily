## 先说结论

这是 TWIML AI Podcast 第 785 期（2026-11-17 发布，HPE 赞助的「AI 经济学」系列；集号与日期经节目官方页核实）：主持人 Sam Charrington 对话 HPE Private Cloud AI 工程负责人 Sadeepa Wijesekara——他同时是 Tokenomics Foundation 治理委员会成员，而其东家靠卖「本地 AI 基础设施」赚钱，本期立场需要打折听。核心矛盾一句话：模型单价在降、企业账单在涨，因为 agent（能自主拆解任务、连续多次调用模型的程序）把 token（大模型按量计费的最小文本单位）用量放大了 20 到 50 倍（嘉宾称，引所见数字）。嘉宾给出的解法链条是：先建「按 agent、按用例拆账」的可见性——多数组织没有，这是「第零步」；再做「工作负载放置」，在单条 agent 工作流内逐调用决定去前沿模型还是本地开放权重模型（权重公开、可自行下载部署的模型）。嘉宾引用的内部测算称本地推理在 60%-70% GPU 利用率下仍有 ROI、本地最多省 60% token 成本——均为卖方数字。他也承认反方：前沿实验室会永远领先，正确策略是混合而非纯本地。写作者判断：这期价值不在结论而在方法——它把 build vs buy 从一次性平台决策，拆成了 agent 工作流内逐调用的工程问题，并给出了可操作的起步顺序。

## 一、事件背景：Apple 削 token 预算，与「单价降、账单涨」的算术

主持人开场抛出新闻由头：Apple「昨天」宣布削减内部 token 预算，此前 Uber、Meta 在今夏早些时候也有类似报道（主持人称，节目引述，本文未独立核实这些新闻本身）。嘉宾的呼应很直白：客户给开发者打开 AI 闸门后「token 预算完全失控」，HPE 内部也在预测一笔庞大的 token 支出。

为什么定价页上的单价曲线一路向下，企业账单却一路向上？嘉宾给出的机制是一道乘法：agent 完成一项任务要触发多次模型调用——检索一步、研究一步、规划一步——其 token 消耗是聊天机器人的 20 到 50 倍（嘉宾称）；单价降幅小于用量涨幅，总账单必然上涨。这解释了 Apple 们的动作：不是不用 AI，而是开始像当年管采购卡（P-card，公司发给员工的小额采购卡）一样管 token——早期随便刷，之后上流程、上配额。嘉宾还补了一个行为学注脚：终端用户看不到企业成本时只会用最好的模型，就像花 20 美元订了 ChatGPT 的人不会主动挑低配档（嘉宾类比）。

主持人提出更细腻的读法、嘉宾认同：这类新闻表面是「少花钱」，实质是「别给所有工作都用最大模型」。**机制（多调用放大用量）→ 影响（收预算、上管控）→ 启发（成本控制的抓手在「按步骤选模型」，不在「砍项目」）**——这是全文第一根链条。

## 二、第零步是看见账单：按 agent 拆账、行业本体与 SaaS 盲区

主持人问：你接触的大多数组织，能说清谁在花 token 吗？嘉宾一个字：No。于是有了本集传播力最强的概念——「第零步」（step zero）：在谈任何优化之前，先把支出按 agent、按用例、按子调用拆开，给每个 agent 打上「属于哪个业务流程」的标签。HPE 正在做内部兼对外的 Ops 看板；嘉宾同时坦承 HPE 自己也只做到部门级归因，「还没到按 agent、按用例、按轮次」的细度（嘉宾承认）。

主持人随即点出执行难点：不同开发者给同一工作流起不同名字，打标「很快会乱」。嘉宾承认「确实会非常乱」，解法是行业级的本体（ontology，对事物的统一分类命名体系）/分类学标准——多数公司从没建过，这正是 Tokenomics Foundation 想推动的事。还有一个盲区由主持人点出：SaaS 应用内嵌的 AI 用量，有些含在订阅价里、有些按量加购，基本游离在企业自建账本之外。**机制（无遥测、无标准标签、SaaS 盲区）→ 影响（看不到谁在花钱，优化无从下手）→ 启发（第零步是建可见性，且需要行业统一分类标准，而非每家公司自造一套）**——第二根链条。

## 三、逐调用的 build vs buy：路由、开放权重模型与 GPU 放置

有了可见性，才谈得上「工作负载放置」（workload placement）——本集把老问题 build vs buy 翻新成逐调用决策：需要前沿推理的规划步骤值得付溢价；检索、摘要类步骤可下放给更小的开放权重模型。嘉宾强调决策变量不止成本：延迟、合规、数据治理、数据引力（数据因体量、合规或敏感度而「挪不动」，只能就近计算的现象）都会否决「送去云端」——有些数据哪怕任务需要前沿推理也不能出公网。

开放权重模型的进步是这个决策成立的前提。嘉宾转述「开放前沿阵营的人」的说法：开放权重模型距前沿推理只差一到两个月；主持人补充，几个月前这个差距还是六个月（节目口径）。路由落地则由简到繁：先用确定性规则（这类工作去云、这类留本地），可观察、可调优，之后才上按 prompt 内容自动选择的路由——嘉宾观察，客户对「智能路由器」很谨慎，因为路由器本身会变成又一个需要监控的变量。

经济账（卖方数字，注意归属）：嘉宾称其内部 ROI 计算器显示，本地 GPU 在 60%-70% 利用率下相对公有云/前沿模型仍有 ROI，盈亏平衡点「可能低于 60%」；建议按 3-5 年周期对「同模型、同 GPU、云端 vs 本地」做成本测算。配套玩法包括同集群混布不同 GPU（高参数模型用 H200/B300，音视频低时延用 RTX 6000，均为 NVIDIA 产品线，嘉宾称）并由软件栈自动调度；以及按时间填谷：白天工程师编码，夜里跑全库安全漏洞扫描。**机制（差距缩短 + 本地固定成本 + 分档路由）→ 影响（大量非前沿步骤可本地化省钱）→ 启发（先做 3-5 年 ROI 测算再谈立场；把最大模型留给真正需要前沿推理的步骤）**——第三根链条。

## 四、安全与数据引力：明文 prompt、七层防御与三类回撤客户

主持人带来本集最尖锐的反方：前沿实验室规模那么大、模型菜单那么宽，「你怎么可能在推理成本上竞争得过 OpenAI 或 Anthropic」？嘉宾的回应分两层：数字上，「做个成本测算就知道了」；定性上直接让步——「他们会一直是前沿，所以才叫前沿模型」，策略应是混合而非纯本地（嘉宾承认）。他还承认另一个反方事实：开放权重模型在云里也能跑，此时剩下的是数据引力与 IP 风险问题，不再是成本问题。

IP 风险这段是全集信息密度最高的部分。嘉宾的机制推演：prompt 发到 GPU 上是明文，管理员 dump 内存就能看到；协议写「不用你的数据训练」可能是真的，但 prompt 会落日志、会进评测集，评测可能把「正确答案」带出来，还可能「基于你的数据造合成数据再去训练」——「没人给清晰回答，但也没完全说不」（嘉宾称）。主持人则引述近期的「Mathgate」/Navier-Stokes 风波：有研究者具体指控前沿厂商用其数据训练后抢先发论文（节目引述，未独立核实）。

与之配套的是嘉宾口中的「七层」agent 安全（嘉宾称，未逐层列全）：短时效、任务级令牌（凭证不随 agent 常驻）、安全沙箱与网络策略（引用 NVIDIA 开源、2026-11-10 刚捐入 CNCF 的 OpenShell 项目，写作者据 CNCF 官网核实）、机密计算（连管理员也看不到内存中的 prompt，绑定硬件远程证明）、全程审计与行为模式监测，外加 MFA 等传统人侧控制。嘉宾也承认：agent 的合规标准目前不存在——「我没见过，若有请听众告诉我」。

三类真实客户（嘉宾案例，匿名，无法独立核实）：亚洲某知名车企在 AWS 上跑 agent，发现必须传敏感数据后「拔插头」转向本地；欧洲某国国防方向要求 AI 软件栈主权留在本国、与本地公司共建；工业制造客户要把推理放到工厂设备旁并支持断网运行，把 PCAI（Private Cloud AI，HPE 的本地 AI 软硬件一体产品）OEM 进自家产品，发到数十个安装点。**机制（明文可见性 + 合规 + 断连需求）→ 影响（数据引力客户事实上退出公有云推理）→ 启发（把「谁能看到我的 prompt」列为架构第一问；低风险用例先行、高风险后上，是组织落地的现实路径）**——第四根链条。

## 五、利益与边界：HPE 自家的 AI 工厂，与嘉宾承认的例外

HPE 内部是这期的活标本（嘉宾自述）：全球约 6.5-6.7 万员工；内部聊天机器人（转写名 ChatGPE）约两年前上线；成本归因到部门级；编码工具统一指向内部端点，由端点决定去 Anthropic/OpenAI 还是本地 PCAI；内部 PCAI 从最初一两台扩到九台。嘉宾明说未来是混合架构「但偏向本地，因为省成本且安全得多」。写作者提醒：这正是其产品线，整期对话都在此立场下展开，数字与判断请按「卖方口径」打折采用。

边界与例外（反方全部保留）：嘉宾承认 HPE 自身成本归因粒度不足；承认前沿永远领先、纯本地不对；承认行业缺价值度量——只有呼叫中心、采购单这类流程有清晰的单位成本，多数内部流程没有；承认缺 agent 合规标准；并预判未来一年「token 成本」话题会退场，讨论转向「价值与 ROI 证明」，而更大的主题是 agent 安全（「现在也许太担心成本了」，嘉宾称）。**机制（成本杠杆拉完后，账单不再是焦点）→ 影响（竞争转向谁能量化 agent 创造的价值）→ 启发（先给业务流程定义单位成本，再引入 agent 做对照——这是嘉宾给 CIO 的排序，也是 Tokenomics Foundation 想标准化的方向）**——第五根链条。
