# 为 Agent 而设计：Resend 创始人 Zeno Rocha 谈邮件投递的手艺、MCP 反共识与 AEO 生意经

> 信源说明：本文基于 Latent Space 频道 2026-11-10 发布的《Designing for Agents — Zeno Rocha, Resend》（视频 ID `bdIoODXsu8k`，全长 5152 秒≈86 分钟，英文转写 43 段、0s–5152s 已完整读取、无跳读，未见同句循环式幻觉）。嘉宾 Zeno Rocha，依开场介绍与全场对话推断为开发者邮件 API 公司 Resend 的联合创始人/CEO——推断级标注；其创建 Dracula 主题、位列 GitHub 最活跃开发者之列为节目自述。主持人依口播线索推断为 Shawn Wang（swyx，Latent Space 主理人）：节目中自称内容创作者、同时运营 Latent Space 与 AI Engineer（AIE）两个品牌的「CMO agent」、持有 latent.space 与 ai.engineer 域名、FreeCodeCamp 出身——与 swyx 公开身份吻合，推断级。利益相关：主持人自述为 Resend 天使投资人（其 30 余家投资组合之一）。全部数字与判断均为嘉宾或主持人陈述，按「Rocha 称/主持人认为/节目引用」分层归属，本文未独立核实、不替播客背书；数字保留节目口径。转写存在系统性专名误听（公司名 recent→Resend、Sandgrid→SendGrid、Alpo→Apple 等），以文末校正表处理，无法确认处保留原文并标注；完整修正版转写与逐段中文翻译见文末附录（由发布脚本追加）。站内关联：[Jay Parikh 谈 GitHub 规模与 agent PR](https://inkeast.github.io/MessageDaily/posts/2026-11-09-latent-space-jay-parikh-github-scale-agent-prs/)、[Handshake AI 谈前沿实验室数据采购](https://inkeast.github.io/MessageDaily/posts/2026-11-10-latent-space-handshake-ai-frontier-labs-data/) 两文同属本站 Agent 时代访谈系列，可对照阅读。

## 先说结论

这是一场「存量行业 × 新分发渠道」的案例教学。Rocha 口径下，Resend 已服务约 430 万用户（录制当天上午数字）、12 万付费客户，是约 1000 万美元 ARR（年度经常性收入）的公司，SDK 的 NPM 下载量今年早些时候超过 SendGrid、目前已是其两倍多——但他同时承认论邮件发送量 SendGrid 仍大得多（企业客户体量）。他的核心判断是：**开发者的决策入口正从搜索引擎迁移到编码 Agent**——节目引用的追踪数据显示 Claude Code 推荐 Resend 的比例达 60% 以上——所以产品必须「无形态（formless）」、API 优先，官方 MCP（Model Context Protocol，模型上下文协议，Agent 调用外部工具的开放标准）服务器要做到 80 多个工具、逼近后台面板 100% 的能力，这与 Cloudflare「两个工具」的极简路线针锋相对。反面是老牌巨头：在他看来 Twilio 的规模与十年 SEO 资产没有换来产品速度。另一条贯穿全场的暗线是创始人的取舍：他明确说「1000 万 ARR 且女儿愿意亲近」的现实优于「1 亿美元但女儿不想理你」；而主持人——以自己因官方 MCP 有无而弃用 Plausible 改用 PostHog 的采购行为——为渠道迁移提供了活体样本。

## 邮件这门「手艺」：投递率的机制与反滥用的猫鼠游戏

如果以为发邮件就是调一个 API，这期节目前半段会系统性地纠正你。Rocha 反复强调这是他与联合创始人（前端出身、零基础设施经验）进入后才逐步领教的领域：高量级投递与扩容一个应用完全不同，「不能扔 GPU 解决」；Gmail、Outlook、Yahoo Mail 各有各的规则，行业「老派」且高度依赖关系。机制上最反直觉的一条：给 10 万人发信时直接全量投递会被 Gmail 节流（throttle），因为邮箱提供方要先观察互动信号——打开、归档、秒删还是无视——再决定后续批次享受到的待遇。所以要做的是把最活跃的受众排到队列最前、分批错峰、在不同提供商之间分散；再往下是 IP 层的「疯狂的基础设施游戏」：整块购买 IP、核查 IP 历史声誉、划分 IP 池并随时间动态平衡。供方想看到的是持续平滑上升的发送曲线，而「一次性发一大批然后消失、一周后再来一次」恰恰是滥用者的指纹——Rocha 的总结是，**做邮件营销就是做滥用者绝不会做的事**。

滥用者画像由他亲手描出：买两天前注册的新域名、网站连 200 状态码都不返回、用与品牌相似的 look-alike 域名（他特别提醒：为「冷外联」另配一个相似域名是灾难，因为看起来就是在钓鱼）、一次性海量发送后消失。节目里最极端的案例是一个日本团伙（冷开场转写作 game，按上下文应为 gang）一次性带来约 2 万个在不同注册商登记的域名，每个维度都要逐项排查。前车之鉴来自 Mailgun 创始人 Ev（结合上下文推断为 Ev Kontsevo，现做安全产品）：Rocha 称对方告诉他当年 90% 的研发都花在对抗滥用者上、「这是个可怕的生意」——这句话促成的决策是把反滥用做成自动化系统，而不是堆人的-org。

度量体系本身也在崩塌：打开率依赖 1×1 透明 GIF，但 Apple 的隐私改动（预读邮件、生成摘要——转写作 Alpo，已校正）让「打开」信号严重失真；于是只能依赖点击追踪，而点击追踪又要求链接与图片的域名同发送域一致——把图片和链接托管到别处正是滥用者的经典特征。共享追踪域还有「坏邻居」问题：同域的某个客户发了钓鱼，整个域名进黑名单，数天到数周才能除名。Resend 的应对是把最佳实践烤进产品：自动从 HTML 提取生成纯文本版本（垃圾邮件过滤器可以直接读内容，Rocha 称此举「大幅」提升投递率）、发送前的链接检查器、拼写检查器与投递洞察。

## 默认信任、版本化的客服与一个靠关系的行业

面对「免费注册+海量发送必然引来垃圾邮件」的质疑，Rocha 给出的不是技术答案而是一个社会比喻：同行的做法像是「先坐 18 年监狱证明自己是好公民，出狱才能做事」，而他想住在「生来自由、犯错才受罚」的社会——即**默认信任每个新客户，把反欺诈的摩擦从用户侧移到平台侧**；一旦从退信率、投诉率等信号发现异常就快速封禁，然后人工对话。对话的产出是一个关键区分：多数问题是「误用（misuse）」而非「滥用（abuse）」——用他的话说，「纯属技术不行」。顺带一提其早期「社会证明」的来历：AI 之前的某个周六，他在自己数据库里按 .com 域名翻客户，翻到 WBD.com（转写作 WBG，华纳探索）才知道华纳在用 Resend——如今客户名单从华纳兄弟、HBO 到独立开发者并存。

这套哲学要求客服能规模化，Rocha 直接把客服当软件版本讲：V1 病急乱投医地招人；V2 招到领域专家但仍是被动的；V3 定下一条漂亮的政策——**「只能带链接回复工单」**：答案必须先写成文档再回复链接，单张工单因此慢一个半小时，但知识库从此滚雪球；到去年 12 月用户破 100 万、如今约 400 万（Rocha 口径），堆人彻底失效，于是全面重构为 V4 并死守免费层——他自述学生时代靠 Heroku 免费层起家，免费层是原则而非获客话术。另一个反直觉发现是行业的人际性：投递这件事「很多时候得拿起电话」——Resend 招了 Postmark 元老与在 Mailchimp 工作过约 15 年的人，靠他们的关系网打开局面。用户侧最大的工单来源则是 DNS：Lovable、Bolt（转写作 Bulge）、v0（转写作 VZero）带来的一代新用户连 CNAME/A 记录/TXT 都不认识，出了问题不会排障；Resend 因此找到并推动冷门的 Domain Connect 协议——相当于给域名做「一键 OAuth」式的授权——说服 Vercel（转写作 Versel）等加入，其间还吐槽 GoDaddy 为此收费昂贵、协议几乎无人维护、第一家提供商谈了几个月。

## 从 SES 之上「贴到金属」：基础设施的分层经济学

主持人提供了一个外部参照：FreeCodeCamp（Quincy Larson）约 500 万订阅者的 newsletter 走 Amazon SES，月费约 5000 美元（主持人称）——便宜，但「便宜」正是理解这个市场的钥匙。Resend 自己也是从 SES 之上起家的：创新点放在开发者体验（DX）层——全语言 SDK、Serverless/Lambda 场景的接入教程（当时几乎无人做）。但 SES 的隐性成本在周边设施：收事件要配 SNS、看日志要 CloudWatch、事件量大还得 SQS 排队、webhook 要自建，「账单足迹」膨胀得比想象快。对照组是同赛道的 YC 公司 Agent Mail：其创始人明说「建在 SES 之上、不与它竞争」；Rocha 的路线相反——现在「下沉到金属」：自购整块 IP、自管 IP 池、控制对每个邮箱提供商的吞吐、重建供方关系。他说这是当下「旗舰级」的变更、已做了数月即将官宣，换来的除了投递力还有可观测性——邮件到底进了收件箱、垃圾箱还是促销标签页，这个「中间地带」过去只能靠用户投诉倒推。性能也一并动了刀：发送路径已不用 JavaScript、换成 Go，P99 延迟被当作「不该如此」的对象正面挑战；主持人顺势感慨重写经济学——语言选择不再重要，他自己就跑着从没正经学过的 Rust 项目。这条路的起点注脚是 React Email：Rocha 称之为「我们的 Next.js」——用开源做漏斗顶端，文档里甚至亲笔写了 SendGrid、Mailchimp、Mailgun 的接入教程，策略是「先给给给、再索取」。这里有一处值得并列的时间线分歧：主持人以为 React Email 早于公司一年做出，Rocha 的回忆则是「先启动 Resend，在建司过程中从用户调研里长出了 React Email」。他还自嘲花大力气打磨的后台面板如今「没人打开」——因为 API 与 MCP 太顺了。

## 为 Agent 设计产品面：无形态、80 个 MCP 工具与「官方集成」成为采购标准

几个月前「MCP 已死、只有 CLI 才重要」还是流行论调（主持人转述），Resend 的数字是另一回事：MCP 调用量每月至少翻倍，8 月底约 120 万次（Rocha 称，节目展示了逐月曲线）；他的产品观是「我希望产品是无形态的——用户想怎么用就怎么用」，所以从第一天就 API 优先。戏剧性的细节是第一个 MCP 竟由 a16z 投资人 Yoko 写成：本地版意外爆火后应 Rocha 之请转入公司 org；而要做远程 MCP 又倒逼公司回头重建 OAuth 与整套权限模型——「先有阻碍，再造 auth」。主持人则贡献了本期最生动的采购侧证据：Plausible 的 MCP 是 Sentry 代建的、非官方维护，他因此整体弃用 Plausible 改用 PostHog；选 Strava 也是因为它有官方 MCP；X 的 MCP 只能本地跑、桌面端可用手机不行，直接劝退——**「官方 MCP 的有无」已经成了他的 B2B 采购标准**。工具数量之辩是全场最鲜明的反共识：上线约 20 个工具、现在 80 多个且还在加，目标是覆盖后台面板 100% 的能力——「用量计费、团队邀请、账号开通与删除该不该暴露成 API」才是真难题；主持人点出这与 Cloudflare 只做「两个工具」的路线针锋相对，Rocha 不以为意，还补充了一个工程观察：单个工具回传数据过大反而坏事，近期就把一个 contacts 工具改小了。工程侧他点名 Next.js 的「错误」：Server Components 引导你把数据绑进页面、默认不产出公开 API——正确姿势是完全 headless 的后端、前端只是众多客户端之一；Resend 早年把 API 架在 Next 上「账单高得离谱」，迁到传统 Node 服务、如今靠 monorepo 复用，但公开 API 仍需单独维护，「维护两套很痛苦」。

产品面的偏执还延伸到招聘与长尾：careers 页支持 CLI、API、skills 三种申请方式（「让 Claude 帮你申请 Resend 的设计师岗位」）——主持人质疑这是给自己收 slop（低质机器申请），Rocha 反而把 CLI 申请当筛选器：愿意装好 CLI、走完认证的人「多走了一英里」。同理，全部 SDK 都是人工编写的（评估过 Stainless、Fern 等代码生成器，不满意其产出），.NET、Java、Rust 也不例外——「四百万用户里也许只有五百人用某个 SDK，我在乎那几百人」；他把这归因于在巴西长大、用着烂电脑烂网的经历：不为只有旧金山、纽约的最新 MacBook 用户做产品。产品形态上还有实时的 multiplayer 协同编辑器——Resend 的全员工大会就在自家邮件产品里开，20 人同编一封邮件、结尾一起点发送；下一步是把「收件」也 API 化：以程序批量开出几十个收件箱，配读取、标未读、星标、打标签的 API——主持人立刻对上了 Missive、Help Scout、Front 这类共享收件箱产品（Rocha 当场给主持人开了 feature flag）。读件那一侧的生态也聊了：主持人称自己已不亲读大部分邮件，交给 AI 助手 Poke（公开资料显示为可连接邮箱与日历的 AI 助手产品）加两位真人；他看好 Instinct（节目称估值 25 亿美元、尚无营收）；当天早上 Superhuman 的更新则引发「被收编后趋于同质化」的观感（细节转写含混、未核实）。

## AEO 实战：当推荐引擎从搜索框变成模型

先交代口径：主持人是 Resend 的天使投资人，「Claude Code 推荐 60%+」为节目引用的第三方追踪数据。Rocha 的 AEO（Answer Engine Optimization，面向问答引擎/大模型的优化）体系是「传统 SEO 底子+为模型改造」：Resend 2023 年起步时在 SEO 上毫无优势——Twilio、Postmark、Mailgun 已投了十年以上——于是做长尾文档（不止 Python，还有 Django 等框架组合的超短文章）；等模型兴起，再把几乎每个页面改成问答格式、挂上 FAQ（「Resend 过 SOC 2 吗」下面直接给答案）；借文档工具 Mintlify 上线 llms.txt（供大模型读取的站点说明文件标准），再给营销站每一页做 .md 版本（URL 后缀加 .md 与内容协商均可访问）。定价页事故是最好的案例：某个周日他让模型比较「用 Resend 与几家竞品各发 120 万封邮件谁最便宜」，模型不仅算错还吐槽「Resend 定价不透明」；症结是模型读不了 JavaScript 挂件，于是他把该页数据以纯文本写进 .md 版，几天后再问，数字就对了。代价是双源维护——.md 和页面各改一遍，「如果我想要轻松的路，当初就不会做邮件」；而 .md 的抓取量在常规分析工具里看不到，只能去 Datadog 的服务端日志里查。教训项同样值得记录：竞品老老实实做「我们 vs SendGrid」对比页，反而被模型推荐得更多——Resend 曾试图做「不太像对比页」的东西，效果不佳；新做的各竞品采用率对比图因此特意把数据写成文本。模型侧的观察是：至少在 Opus 4.5 上存在明显的时新性偏差（recency bias）——Replit（转写作 Raplit）这类老工具的推荐在减少、新工具在冒头——所以最实在的建议是「让尽量多的人在尽量多的地方谈论你的产品」。渠道观方面两人各自陈述、未构成一致结论：主持人认为 Reddit 对模型推荐不重要，Rocha 称 Hacker News、Twitter 的影响也不如从前。工具生态一地鸡毛中有真金：Resend 同时订着四家 AEO 追踪工具（Profound 一类），共同缺陷是「只报告、不给行动建议」，反倒是 Moz 这类老牌 SEO 工具更有主张；Ahrefs（转写作 AHFs）则被主持人称作新加坡的一门大生意（其口述营收数字单位存疑，见未采用条目）。主持人自己把这件事自动化到了科幻边缘：Latent Space 与 AIE 各有一个「CMO agent」，负责研究选题、记录已试过的实验、派生执行用的 agent，他只在「实验窗口」签字放行；授权的工具包括 Ahrefs、DataForSEO，还自建了 AIO 追踪器，「让数字上涨」。对话里还碰到一个新协议：WorkOS 的 Michael Grinich（转写作 Greenwich）在推 auth.md——让 Agent 替用户注册与认证的开放协议（主持人口径），与 Netlify（转写作 Nelify）式「免账号先用」同源；Rocha 在「要不要做免登录试用、要不要开 provisioning API」上明确表示反复横跳——最顺滑的入口也最容易被滥用。

## 生意、定价与创始人的取舍

定价是行业级痛点：传统按联系人计费的逻辑是「按你从每个联系人身上获得的价值收费」，但 AI 客户增长太快——Mistral 就用 Resend，Rocha 称其用户增速「疯狂」——按联系人计费「有点失灵」，公司正在设法修正。营销邮件与事务邮件在他口中是两种生意：后者是「进队列、出队列」，前者是「批次+间隔+分析+加减速+阻断」的整台引擎；每个域名都有速率上限——主持人设想 10 万封邮件理想情况 10 分钟发完，Rocha 的回答是：Resend 自己给 430 万用户群发要花超过一天，想快就得「付更多钱进另一个队列」，主持人笑称「这就是 token 限速的 reset 按钮」。主持人顺势抱怨自己作为内容创作者付给 Substack 约 1 万美元/年的 newsletter 账单「似乎太贵了」。企业化则刚刚起步：约 50 人全远程（主持人口径），只招了第一名销售（AE）；Rocha 强调企业客户本质上是「另一个产品」——不是把 WorkOS、SSO、SCIM（账号自动开通/回收标准，转写作 scam）、审计日志摆上定价页就完事，还涉及本地部署/VPC 等形态，他宁可分层推进也不一次加 20 个人，以保护远程文化。个人侧的故事更完整：YC W23 批（当届约 250 家），他带着一岁女儿进 YC，周围创始人多未婚无孩——「你连 B 轮都没融就结婚了？」；他从「要做本批第一」的执念里走出来，结论是「YC 没有赢家，那是无限游戏」——同批的人已有散伙、七次转型、离场。Paul Graham 的现场故事被他用来收束设计观：一位合伙人直言「你太在乎设计了，不在乎的话你会走得更远」——刺痛但成立；他想了几天的回答是：宁可做只有 1000 个用户、有身份感的产品，也不做一万个用户、连自己都不用的产品——这个市场里人人产品糟糕，设计就是差异化。同一逻辑落到家庭：「10 年后女儿黏着我、我们是 1000 万 ARR 的公司」，优于「1 亿美元的公司、女儿不想跟我玩」——他自认这个选择可能对也可能错，但优先级已定。主持人坦承同款焦虑：陪家人时刷着手机想「本该去评测新模型」，两头不专注、双输。收尾的品类之辩两人始终没达成一致：Rocha 把 Resend 定位为「下一代 SendGrid / AI 原生 SendGrid」，主持人直评「这不是品类创造，是品类支配」，并以 HubSpot 的 Dharmesh Shah（转写作 Darmesh）创造 inbound marketing（集客营销）品类为标尺——真正的品类创造是「两个词就说完，不需要长宣言」；Svix（webhooks as a service）与一家「反 webhook」公司（不做推送、只帮你发布一份可拉取的 JSON）的旧案被用来注解这件事有多难。

## 机制 → 影响 → 启发

- **分发迁移链条**：开发者决策入口从搜索框/官网 → 编码 Agent 与模型回答（节目引用：Claude Code 推荐 Resend 60%+；Resend 的 MCP 调用月翻倍、8 月约 120 万次）→ 直接原因是工作起点移进了 Claude Code/Codex 这类 Agent 环境 → 得利方：API 优先+官方 MCP+「模型可读页面」的厂商；失意方：十年 SEO 资产的持有者与无公开 API 的 SaaS（主持人弃 Plausible 用 PostHog 即活例）→ 二阶影响：产品定义本身改变（无形态、80+ 工具全覆盖、headless 后端成为架构原则），营销从排名战转向多地点的有机讨论 → 观察指标：官方 MCP 调用量、各家模型中的推荐份额、.md 页面抓取量、SDK 下载量 → 读者启发：把 API 当第一产品；Agent 集成要官方维护；关键页面给模型留一份纯文本的真相源。
- **基础设施分层套利链条**：新玩家在 DX 层创新、租用 SES 底座（Agent Mail 至今停留此层）→ 分发稳固后下沉自建（IP 块与 IP 池、吞吐控制、供方关系、Go 重写）→ 得利方：掌控可观测性（进箱/垃圾/促销标签第一次可见）与性能（P99）；失利方：把规模当护城河的老玩家——Rocha 对 Twilio 的判词是「他们在睡觉」→ 二阶影响：可观测性本身成为卖点；重写成本下降使「语言不重要」→ 观察指标：投递可见性功能上线、自建基础设施比例、发送延迟曲线 → 读者启发：先租后建，下沉时机看分发是否已稳；评估供应商时把「规模」与「产品速度」分开计分。
- **信任成本内化链条**：行业默认「先审后放」（注册问卷+人工审核+高拒绝率）→ Resend 默认信任+信号触发的快速封禁+人工对话区分误用与滥用 → 得利方：真实开发者零摩擦上手；平台以「只许带链接回复工单」的政策把客服反哺成知识库 → 成本：反欺诈必须内部化为系统工程（Ev 的「90% 研发对抗滥用」即前车之鉴）→ 二阶影响：免费层成为原则性资产（巴西经历→为边缘用户做产品→手写全部 SDK）→ 观察指标：误封率与申诉时长、新用户激活速度、免费层存续 → 读者启发：把合规摩擦从用户侧移到平台侧，再用产品把最佳实践「教」出去（自动纯文本、检查器、洞察）。
- **计费与 Agent 增长冲突链条**：按联系人计费的行业惯例 → AI 原生客户的用户数暴涨（Mistral 案例）→ 账单与价值错配、计费模型失灵（Rocha 称正在修正）→ 二阶影响：营销邮件的「批次引擎」属性被显性化——速率、队列与优先级成为可售卖的杠杆（付更多进更好的队列，类比 token 限速）→ 观察指标：新计费模式的发布、企业层（VPC/SCIM/审计）收入占比 → 读者启发：为指数级增长的客户设计计费与队列，别让你的计费表惩罚增长最快的最佳客户。
