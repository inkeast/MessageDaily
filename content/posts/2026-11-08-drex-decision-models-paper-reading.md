> **领域标签**：cs.CL / 判别式决策模型 / 推理效率

## 一、论文背景

### 1.1 生成式推理的产量困境

长思维链（long CoT）自回归推理已成为新 AI 应用的默认选择，因为它在广泛任务上准确率更高。但在**生产环境**里它有三宗罪：**答案不一致**（同一问题多次采样给出不同回答）、**需要解析输出**（自由文本要再抽成结构化决策，解析会失败）、**成本与延迟高**（每个生成 token 都要过一遍大网络的解码循环）。这催生了**判别式推理的复兴**：决策模型（decision model）接收用户给定的状态与选项集合，**不做任何自回归解码**，直接返回选项上的概率分布——一个 Request 一次前向，答案天然结构化、可复现、便宜。

这个接口由 Jev 的 System One API 首创、开源 Kev 栈复刻，本文沿用它并自建训练。论文核心追问：**一个模型能否服务任意选项集、给出校准概率、在一个长上下文上回答大量问题、对选项重排保持稳定，且达到生产级延迟？**

### 1.2 关键洞察：输出形状必须在推理时由用户决定

已有三类读出方案——encoder 分类头、T5 文本到文本、decoder 提示生成——共同缺陷是**输出形状在部署前固定**：分类头的标签训练时焊死，reranker 每候选一个分数，embedding 模型每输入一个向量。而决策模型要的是**选项集合随输入变化**：三个选项的题和 150 个选项的题用同一个模型、同一个头。约束解码能保证合法输出，但逐 token 概率连乘再归一化不等于模型对「选项整串」的分布（前缀共享、长度不均时尤甚）；逐选项打分再归一化则每选项一次前向。Drex 的答案是第四条路：**在推理时对用户供给的选项做分类的新读出机制**。

### 1.3 四个研究问题

- **RQ1 校准**：概率与经验准确率的匹配程度；单一全局温度是否够用。
- **RQ2 选项顺序**：概率与决策对选项排列的敏感度。
- **RQ3 训练**：SFT（含一致性损失）→ RLAF（验证结果 + LLM-as-judge 调整反馈 + KL 正则）→ 视觉 SFT 三段式各贡献多少。
- **RQ4 容量/注意力/模态**：稠密多模态骨干 + 双向注意力 vs 共享状态指针头，各自优劣。

## 二、论文定位和关联工作

### 2.1 读出机制谱系

| 方法 | 机制 | 选项集可变 | 前向次数 | 与 Drex 的关系 |
|---|---|---|---|---|
| Encoder 分类头（BERT 等） | 末层 + 固定标签线性层 | ✗ | 1 | 输出形状焊死 |
| 似然打分 | 各选项 log-likelihood | ✓ | 每选项 1 次 | 有长度/措辞偏置 |
| 多选提示 + 符号打分 | 选项标 A/B/C，对符号 token 打分 | ✓ | 1 | readout 头的训练化版本；需正确绑定符号↔选项 |
| 约束解码 | 生成限制在合法串内 | ✓ | 逐 token | 归一化 ≠ 选项整串分布 |
| 跨编码器（cross-encoder） | (query, 候选) 对分类 | ✓ | 每候选 1 次 | 成本随候选数线性涨 |
| 指针网络 | 对输入位置的分布 | ✓ | 1 | Drex 指针头的直系祖先 |
| **Drex 指针头** | `<decide>` query · 各 `</opt>` key 点积 | ✓（K≤255） | 状态 1 次 + 每问 1 次 | 跨编码器+指针网络合体 |
| **Drex readout 头** | `<ans>` 隐藏态 → 255 码 logit | ✓（K≤255） | 每问 1 次（重编码） | 多选提示符号打分的训练化 |

### 2.2 与 Jev / Kev / pplx-decider 的关系

接口遵循 Jev 的 System One；指针模型建在开源 Kev 代码上（打包编码、块因果掩码、每问题独立因果序列、指针头、CE/平方 Cramér/置换一致性损失均继承 Kev）；Max 的注意力模式与 readout 采纳开源 pplx-decider 设计但**从 Qwen3.8-27B 基座自行训练权重**。论文自认的新颖点：RLAF 训练阶段、Max readout 头训练、图像编码器训练、评测与推理栈。

### 2.3 定位总结

| 维度 | 指针模型（DLM/v1.5/v2.0） | Drex Max |
|---|---|---|
| 骨干 | Efficient-DLM-8B（扩散）/ MiMo-9B（混合）/ Qwen3.6-35B-A3B（MoE） | Qwen3.8-27B 稠密多模态 |
| 输出头 | 256 维指针头（2.1M/1.0M 参数，<0.03% 骨干） | 255 码无偏置线性层（1.3M 参数） |
| 状态编码 | 每请求 1 次，跨问题共享缓存 | 每问题 1 次，不可缓存 |
| 注意力 | 因态/行式因果 | 全注意力层非因果（双向） |
| 模态 | 文本 | 文本+图像 |
| 顺序鲁棒 | 部分架构性（可选选项隔离掩码仅限纯注意力骨干） | 完全学出（代码-位置绑定） |
| 成本 | 长文档多问便宜 | 每问付全状态成本，换精度 |

## 三、问题定义

### 3.1 决策请求

请求 = (S, I, {q_k})：状态 S（文本或 JSON 渲染缩进文本）、可选图像集 I、问题序列。每个问题 q_k = (τ_k, u_k, O_k)：类型 ∈ {choice, noul, score}、指令、有序选项表（K≤255）。模型对每个问题返回分布 p_k。三种类型统一为「有限选项上的分布」：

- **choice**：命名选项 + 每选项概率 + argmax；
- **noul**：二元判断，返回 p(yes)；
- **score**：整数刻度 0..L−1，额外返回期望等级 ŝ = Σ i·p_i。

置信度沿 System One 定义：c_choice = (max_j p_j − 1/K)/(1 − 1/K)。

### 3.2 五个理想性质

1. **闭世界输出**：分布支撑在供给选项上——靠构造保证而非提示或约束解码；
2. **问题独立性**：p_k 不依赖同请求的其他问题（批量/缓存/回放浮点误差内一致）；
3. **顺序鲁棒**：置换选项，概率等变、top 选项不变；
4. **校准**：Pr[top 正确 | 置信度=c] = c——置信阈值可作路由规则；
5. **多模态扎根**：图像证据要进图像本身，而非依赖文字描述。

前两条**所有 Drex 架构构造性保证**（块因果掩码/独立序列），后三条是学出来的——论文实测而非假设。

### 3.3 抽象的问题所在

判别式读出的根本约束：**输出头只能用骨干内的知识给选项排序**。没有解码循环就没有中间推理步骤的搜索空间——这是效率的来源，也是闭卷知识上限的来源。论文把它作为开放问题诚实呈现（Section 10），并用实验划定边界（HLE 21% vs GPT-6 Sol 39%）。

## 四、问题解法

### 4.0 全景

```
请求 (状态 S, 图像 I, 问题 q1..qQ)
  ├─ 指针模型：打包成 [S | b1 | b2 | ...]，块因果掩码
  │    状态编码一次缓存 → 每问一小段前向 → 指针头打分
  └─ Drex Max：每问独立序列 [I; S; u; "A: opt1; ...; <ans>"]
       48 DeltaNet 层因果 + 16 全注意力层非因果
       readout: h(<ans>) → 255 logit → 取前 K 个 softmax

训练（Max）：SFT 全参(+一致性损失) → RLAF(LoRA+KL 锚定+judge 奖励) → 视觉 SFT
```

### 4.1 组件一：指针头——选项由其结束符的隐藏态代表

问题块内每个选项用 `<opt>…</opt>` 包裹，最后跟 `<decide>` token。指针头把 `<decide>` 处隐藏态投影为 query，每个 `</opt>` 处隐藏态投影为 key，缩放点积后 softmax：

z_j = (W_k h_{o_j})ᵀ (W_q h_d) / √d_p，p = softmax(z/T)，d_p=256。

因 `</opt>` 处于选项末尾且因果注意力量纲下已读过状态与指令，其隐藏态**在上下文中概括了整个选项**——这是「选项表示」与「打分」的解耦。选项数可变无碍：3 个与 150 个选项用同一头，训练没见过的选项走同一机制。推理只需状态一次编码 + 每问一次短前向，无解码循环。

### 4.2 组件二：Drex Max 的非因果注意力 + readout 头

骨干 Qwen3.8-27B：64 层，48 层 Gated DeltaNet（线性注意力、循环态、从左到右）+ 16 层全注意力（每四层一层）。Max **只在这 16 层全注意力层去掉因果掩码**：每第四层允许上文 token（状态、选项列表开头）注意序列中所有后续 token（后面的选项、指令）。信息流仍以 3/4 层左行为主，但每四层一次「全局交换」让**所有选项彼此比较、与上下文双向比对后再作答**——因果指针做不到。

每问编码为 [图像 token；S；指令；"A: 选项1"；…；`<ans>`]，readout 头 W_r ∈ R^{255×5120}（无偏置）把 `<ans>` 处末层隐藏态映射到 255 个单 token 选项代码（A,B,…,AA,…）各一 logit，取前 K 个 softmax。代价有二：其一，**符号绑定**——骨干必须学会把代码 γ_j 关联到其后选项文本（多选提示的已知难题），置换选项即改变 255 个 logit 与选项的对应，**顺序鲁棒性完全靠学**；其二，非因果层使状态表示依赖问题内容（Remark 2 证明首个全注意力层起状态表示随问题变化），**状态缓存不可共享**——每问付全状态编码成本。

### 4.3 组件三：三段式训练

**Stage 1 SFT（全参）**。1,150,460 条文本决策记录、11 个域（最大 Language & reading 18.3%、Tools/routing/home 15.7%），多蒸馏自强教师，其余来自开源数据与可验证程序生成（执行结果/游戏引擎），每条标签对金答案/执行/引擎校验。损失 = 交叉熵（对 one-hot 或教师软目标）+ score 型问题的**平方 Cramér 距离**（累积分布差，即预报检验中的 ranked probability score）+ 两个一致性正则：ℓ_π 惩罚选项置换下预测分布的变化（对称 KL），ℓ_s 惩罚状态句子/字段打乱下的变化（stop-gradient 单向）。K≥3 的选项每见过一次就洗一次牌；随机插入 NONE/干扰选项教模型「不强选」。

**Stage 2 RLAF（调整反馈强化学习）**。监督标签是 one-hot，但诚实答案常是不确定的——one-hot 教过置信。RLAF 的奖励（Max 版）：

r(a) = ρ·1[a=y*] + η·log q^J_a，J(θ) = E[Σ_a π_θ(a)·r(a) − β·KL(π_θ‖π_0)] − 一致性项

y* 是验证结果（金标签/执行/引擎），q^J 是 **judge**（Qwen3.8-27B 高推理档——Max 自己基座的生成形态）对同一请求逐 token 生成后的选项分布。妙处：judge 不比 Max 更准，但**能做单次前向做不了的长 CoT**，为无验证结果的记录也提供第二意见。KL 项锚定冻结的 SFT 模型 π_0 防漂移（β=0.1，ρ=0.2，η=0.05）。指针版 RLAF 略不同：teacher 分布经验证结果调整为软目标 q̃，奖励是 proper scoring rule（对数 + 0.5 球形 − Cramér），**直接求导**（REINFORCE 不优于直接微分故弃用）。论文明确标注一个理论缺口：judge 对错误选项给足概率时最优策略可能压过验证答案，且 judge 与验证答案一致时会锐化分布导致过置信——**此机制可能部分解释 Max 的实测过置信，但未实测**。

**Stage 3 视觉 SFT**。只训图像编码器与投影（0.6B 参数，95k 记录），教模型从图像决策；文本精度不受损（66.9→66.8）。

**部署温度**：v1.5/v2.0 用 T=1；Max 用 held-out 上 NLL 最小化的 **T_dep=1.009**（近 1，只微调概率不改 top 选项）。

## 五、评估指标与实验证据

### 5.1 指标与协议

- **Decision Index 0.4.1**：37 公共基准 5 域，官方指标折算为**机会校正技能分**（0=均匀猜测，100=完美），二分类与 150 选项任务可比；评测覆盖全部 **140,620 公共请求**；另有含私有测试（同技能+新域）的满分。
- 统计纪律：Wilson 区间、逐请求 bootstrap（5,000 重采样，Decision Index 按请求重采样、域内按基准重采样）、精确 McNemar 检验；明确声明未做多重比较校正。
- 污染过滤：剔除与基准例状态精确匹配或共享 >2 个 8 词序列的训练记录；承认改写与教师蒸馏污染不可过滤。

### 5.2 结果一：Decision Index 0.4.1——Max 设决策模型新 SOTA

| 模型 | 公共分 | 满分 | 新域子分 |
|---|---|---|---|
| **Drex Max** | **67.52** | **66.60** | **56.45** |
| Drex v2.0 | 61.25 | 52.76 | 39.22 |
| Drex v1.5 | 58.08 | 45.78 | 30.82 |
| Jev 1.14.0 | 60.70 | 60.24 | 48.26 |
| GPT-6 Luna Decisions | 47.78 | — | — |

Max 对 v2.0 的领先 bootstrap 95% CI **[3.3, 7.8]** 分，37 基准中 **28 个**更高。满分掉分幅度是关键信号：Max 公共→满分仅 −0.9，v2.0/v1.5 分别 −8.5/−12.3——**小模型在未见域崩塌，Max 的泛化显著更好**。逐决策级（230k choice 决策）Max 比 v2.0 准 **+1.86pp [1.72, 2.00]**。最大单基准提升：GSM8K **66.8→83.2**、BBH 78.3→93.7、WinoGrande 86.1→94.8、MuSR 59.6→70.3、ACOS F1 23.9→39.8、家电模拟器 54.5→70.5。两个大跌都在 Arts 域长结构序列任务：POP909-CL（下一个和弦预测）**79.5→55.6**、Habermas Machine（偏好聚合）62.4→50.5。

### 5.3 结果二：Decision Bench v4 与外部榜

1071 条真实记录决策（949 文本/62 文图/60 纯图像）：

| 模型 | 总准确率 | 纯图像题 | ECE | 中位耗时 |
|---|---|---|---|---|
| Claude Opus 5.5 | 95.6 | 100.0 | — | 4.33 s |
| GPT-6 Sol | 94.7 | 100.0 | — | 2.05 s |
| **Drex Max（图像）** | **94.0** | **98.3** | 1.40% | **0.66 s** |
| d3-turbo | 93.7 | 98.3 | 1.18% | 0.72 s |
| Jev 1.14 | 92.3 | 66.7 | 1.60% | 0.51 s |
| Drex Max（文字渲染） | 92.1 | 63.3 | 1.51% | 0.66 s |
| Drex v2.0 | 87.9 | 68.3 | 1.73% | 0.38 s |

- Max 与 d3-turbo/GPT-6 Sol **统计打平**，落后 Opus 5.5 仅 **1.6 分**（p=0.046）；图像编码器把纯图像题从 63.3% 拉到 **98.3%**、Design 类 26.7→**96.7%**。
- Artificial Analysis 决策指数（第三方，Max 63.7）：落后三强（d1-ultra 65.3 / SubQ Snap 65.0 / Elephant 9B 64.7）至多 1.6 分、无置信区间不排名；领先 Jev 1.14 **6.6 分**；WildGuardTest F1 **95.5 全场最高**、When2Call 94.0 超所有语言模型；但 HLE-MC **16.0 vs Claude 70.2**——闭卷知识鸿沟在硬知识上原形毕露，语言模型总分更高（79.0）但成本 **44-1100 倍**（$51,295 vs $46 每百万请求）。
- 其他：JevBench-231 91.8%（决策模型前列，硬层 82.9% vs v2.0 73.9%）；DecideBench 最小对准确率 **97.0%**（决策模型最高）、ECE 1.1% 最低；游戏竞技场胜率 64.0% 决策模型最高（GPT-6 Sol 65.0）；OSWorld 判读探针 AUROC **0.780**——唯一显著超过「短转写=成功」启发式（0.709）的模型。

### 5.4 结果三：校准（约 230k 决策）

| 模型 | 准确率 | ECE@部署温度 | T*（域内拟合） | ECE@T* | top-80% 精度 | top-50% 精度 |
|---|---|---|---|---|---|---|
| Drex Max | 87.9% | 3.61% | 1.35 | 1.35% | 96.1% | 99.3% |
| Drex v2.0 | 86.0% | **1.37%** | 0.91 | 0.79% | 94.4% | 98.9% |
| Drex v1.5 | 85.3% | 4.54% | 1.48 | 1.17% | 94.0% | 99.3% |
| GPT-6 Luna Dec. | 76.4% | 4.87% | 1.91 | 6.57%↑ | 85.1% | 91.8% |

- v2.0 微欠置信（T*<1 锐化反而更好）；Max 过置信（均值置信 91.2% > 准确 87.9%）。**Luna 的警示**：T* 按 NLL 拟合，单一温度同向缩放一切，无法同时校正「部分过置信+部分欠置信」，ECE 反升。
- **总体 ECE 掩盖分域失准**：Max 的 Language 域（占 56% 决策）ECE 仅 0.5% 拉低总量，其余四域 **7.2-9.2%**；6-20 选项题 ECE **8.4%**（v2.0 仅 2.0%）。部署建议：任何含阈值路由的应用应在**该类请求的标注决策上单独调温度**。
- 选择性准确是决策模型的实用红利：只用最有把握的 50% 决策，Max 精度 **99.3%**——低置信送人审即可获得可调精度。

### 5.5 结果四：选项顺序鲁棒性（1,591 决策 × 3 种顺序 × 4 模型）

| 模型 | 置换 flip 率 | K=2 | 3≤K≤5 | K≥6 | 不稳定决策准确率 |
|---|---|---|---|---|---|
| Drex Max | **4.3%** [3.3,5.3] | 1.0% | 7.2% | 13.3% | **37.6%** vs 稳定 87.2% |
| Jev 1.14 | **4.3%** | 2.0% | 5.2% | 14.5% | 45.9% vs 81.8% |
| Drex v2.0 | 5.9% | 2.0% | 9.5% | 16.2% | 46.8% vs 84.7% |
| Drex v1.5 | 5.3% | 2.0% | 7.8% | 15.6% | 37.7% vs 82.9% |

- 反直觉发现：**readout 头的 logit 绑定位置，Max 却与 Jev 并列最稳**、比混合骨干指针模型更稳——顺序鲁棒可由训练习得。
- 准确率几乎不受顺序影响（Max 83.6→83.4，翻转涨跌近乎抵消）；flip 高度集中于低置信、多选项决策（K≥6 时 13-16%）。
- 两个实用结论：(1) **顺序不稳定是错误的强信号**——不稳定决策准确率仅 37.6%；但「不稳定即弃答」不比「最低置信弃答」更准（差 ≤0.4pp），额外审视顺序敏感性增益有限；(2) 三序分布平均**改善 log loss**（Max −0.014 nats [0.005,0.024]）**不改善准确率**。

## 六、效果优势的根源解释

> 按「方法差异 → 机制变化 → 指标提升」因果链展开，区分论文已证与推测。

**解释 1：为什么判别式 readout + RLAF 能以 1/55 成本逼近 frontier 生成式？**

因果链：任务接口固定为「状态+选项→分布」→ 单次前向即可读出，**信息路径短**：无解码循环意味着无采样方差（同请求同分布，输出可复现）、无长 CoT 的误差累积、无输出解析失败 → 延迟从秒级降到 **183ms**、$0.06/千次；全注意力层去因果掩码 → 选项间与上下文**双向比较**后才打分，替代了部分「生成中反复比对」的功能 → Knowledge 域技能 +9.2、MuSR（多步软推理）59.6→70.3。
边界条件同样清晰：readout 只能用骨干已有知识排序，无搜索/工具循环 → HLE 21% vs Sol 39%、GPQA 55% vs 90%——**判别式吃「比较与判断」的效率红利，付「闭卷知识」的上限代价**。【论文实验支持：Table 23 硬知识基准对比；Section 10 明确承认未测「先 CoT/工具再 readout」的混合方案。】

**解释 2：RLAF 的 +2.0 分从哪来？**

因果链：SFT 的 one-hot 标签在诚实答案不确定时**教出过置信**（Müller et al. 标签平滑文献同向）→ RLAF 把训练信号换成「验证结果 + judge 分布」的软组合 → 模型学到的是**把概率质量分配给合理选项集**而非全押单点 → 准确率 +1.5pp 的同时 ECE −0.9pp（proper scoring rule 的数学性质保证准确与校准不互换而是同向）；judge 是同基座生成形态可做长 CoT → 覆盖无验证结果的记录，注入单次前向得不到的推理信息 → 这解释了为什么 RLAF 增益在 MuSR/GSM8K 这类推理型基准更大。
【论文实验支持：Table 7 受控消融。】【推测标注：judge 与验证答案一致时锐化分布→过置信的机制链论文自己提出但未实测——Max 实测过置信（ECE 3.61%）与此相容但不构成因果证明。】

**解释 3：为什么一致性损失降 flip 不降准确？**

因果链：ℓ_π 直接把「选项置换下分布不变」写进损失（对称 KL）→ 等价于对选项排列做数据增强式的正则化，压缩模型对排列维度的敏感自由度 → flip 率 6.3→4.2%；但准确率由 CE 主导项决定，排列敏感度与任务正确性近似正交 → 指数分不动。反向佐证：去掉一致性项后 RLAF 阶段 flip 反而高于纯 SFT（6.3 vs 5.3）——**judge 的排序偏好可能被蒸馏进目标模型**（judge 生成时对选项顺序有偏好），一致性项恰好抵消这一通道。【论文实验支持：Table 7；judge 偏好蒸馏机制论文明示为假说且两个模型差异未隔离（训练阶段不同）。】

**解释 4：Max 为何强于指针模型、又为何在 Arts 域反而变弱？**

强：四重差异混杂——骨干容量（27B 稠密 vs 9B/35B-A3B）、非因果注意力、readout 头、训练数据——**论文承认除 RLAF 外未做受控分解**（Section 10 列为 future work：同骨干同数据下指针 vs readout × 有无非因果掩码的 2×2）。可归因线索：Knowledge +9.2 与稠密容量、新域子分 56.45 vs 39.22 与泛化相关。
弱：POP909-CL（−23.9）与 Habermas（−11.9）都是**长结构序列**任务——和弦序列/偏好画像要求逐元素精读，而 readout 头要求把代码绑定到长选项文本，符号绑定在长结构选项上更易失败；指针头让每个选项由自己的 `</opt>` 隐藏态代表（表示随选项走），readout 的表示集中在 `<ans>` 一点（表示要靠代码回忆）。【论文实验支持：分数事实；「代码-长选项绑定困难」是论文给出的假设，未单独检验。】

**解释 5：过置信为何集中在非 Language 域与 6-20 选项题？**

因果链：部署温度 1.009 在训练分布 held-out 上拟合 → Decision Index 上 T*=1.35 说明**部署分布≠评测分布**；Language 域占训练大头（18.3%）且任务同质 → 校准近乎完美（0.5%），其余域置信超准确 5-9pp → 单一全局温度只能同向缩放，无法校正「一域过置信一域欠置信」（v2.0 恰因两向偏差部分抵消而总体 ECE 最低 1.37%）。6-20 选项题：正确率掉到 71.7% 而置信习惯未随选项数收缩 → ECE 8.4%。【论文实验支持：Tables 18/19；机制层（为何置信不随 K 收缩）无直接证据。】

## 七、必要知识反推

### 7.1 领域知识层

- **判别式 vs 生成式接口**：分布「读出」与分布「生成」的全部工程差异——解码循环的有无决定了延迟、一致性、解析成本的量级；理解这一点才理解决策模型为何复兴。
- **多选提示的似然偏置与符号绑定**：长度偏置、前缀共享下逐 token 归一化失真、A/B/C 绑定问题——readout 头是符号打分的训练化，其弱点（绑定）也继承而来。
- **混合注意力架构**：Gated DeltaNet 线性注意力层用循环态、不能施加任意掩码——这解释了选项隔离掩码（架构性置换等变）为何只适用于纯注意力骨干，混合骨干必须**学**顺序鲁棒。
- **proper scoring rule 体系**：对数/球形/Brier/平方 Cramér 距离——为何「proper」（期望最大值在说真话处取到）使其成为「输出是预报而非标签」场景的天然目标函数。

### 7.2 方法论知识层

- **校准测量协议**：15 桶 ECE、分域/分选项数分解、单一温度的能力边界（只能同向缩放）、选择性准确率与覆盖率-精度曲线。
- **置换等变的构造 vs 学习**：哪些不变性可以用架构（选项隔离掩码）白拿，哪些只能用损失（ℓ_π）买——以及混合骨干如何把前者排除。
- **观测性检查点分析 vs 受控消融的区分**：v2.0 七检查点只能读「阶段叠加效应」，Table 7 才是消融；论文对 0.3 分级差异与重复评测波动同量级的告诫是评测素养范本。
- **统计检验工具箱**：配对 bootstrap（按请求重采样以处理请求内相关性）、McNemar 只用不一致对、Wilson 区间——以及「未做多重比较校正」的诚实声明。

### 7.3 工程知识层

- **两段式前向的成本结构**：状态 pass（随状态长度增长）与问题 pass（随问题数增长）分离 → 缓存复用使「百万 token 文档上批量提问」便宜一个量级；非因果注意力破坏可缓存性（Remark 2 的证明思路值得学）。
- **延迟优化三板斧**：共享 prefill（前缀只算一次）、CUDA Graphs（消除小核发射开销，短序列有效）、运行时长度参数化核（免每长度 JIT）；以及「答案改变型优化必须配对验证准确性」的上线纪律。
- **温度部署流程**：训练分布 held-out 拟合 T_dep → 换部署域要重拟合；阈值路由应用必须随模型重新标定（0.80/0.51/0.25 的教训）。

### 7.4 知识融合的关键节点

1. **「把 LLM 的隐藏态当分类器用」的接口设计**：融合了 pointer network（集合可变）与多选提示（单次前向）两条线，用 `<opt>`/`</opt>`/`<decide>` 三个特殊 token 把「选项」变成一等公民——表示在选项处、打分在问号处。
2. **「judge 不是教师是第二意见」的 RLAF 设计**：judge 与被训模型同基座、能力不更强，但**拥有解码循环这一被训模型没有的资源**——奖励里 log q^J 项的真正价值是注入单 pass 拿不到的推理产物。
3. **「性质分构造与学习两层」的系统观**：闭世界/问题独立性免费（架构），顺序/校准/扎根要买（训练+测量）——工程上先守住免费的，再量化要买的。

## 八、论文中可以提取的通用性灵感

### 灵感 1：读出接口优于生成接口，当且仅当输出空间可被用户枚举

- **核心思想**：任务若能表述为「从用户给的有限集合中分配概率」，判别式读出就在一致性、延迟、成本、可审计性上全面占优；生成式的优势（开放输出、搜索、闭卷知识）只在其不可枚举时保留。
- **论文证据**：183ms vs 2.0-3.5s；$0.06 vs $3.33-10.17 每千次；Decision Bench 94.0 与 GPT-6 Sol 打平；HLE 21 vs 39 划出边界。
- **推广场景**：(1) agent 的路由/门控/分类决策全部可决策模型化（论文的文档搜索四类决策是模板）；(2) 评测中 LLM-as-judge 的结构化子任务；(3) 内容审核标签；(4) 推荐召回重排；(5) 任何「阈值触发动作」的生产逻辑——只要能枚举选项就能获得校准概率与可调精度。

### 灵感 2：一致性正则——把不变性写进损失比事后修补便宜

- **核心思想**：系统应满足的不变性（顺序、格式、表述）直接以「变换前后输出分布的 KL」作为训练正则项，比在推理时集成/投票便宜得多且可微。
- **论文证据**：ℓ_π+ℓ_s 使 flip 6.3%→4.2% 而指数分不动；三序 ensemble（推理时补救）只改善 log loss 不改善准确率——正则化买到的东西事后买不到。
- **推广场景**：(1) 任何对输入排列敏感的排序系统（搜索、推荐）；(2) 表单/JSON 字段顺序无关的解析模型；(3) 数据增强的理论化替代——直接惩罚「不变性违反」而非枚举增强；(4) 对抗训练的轻量 cousin；(5) API 的向后兼容测试（语义不变的代码重构）。

### 灵感 3：judge 奖励——用「同能力但不同资源约束」的自身变体扩展训练信号

- **核心思想**：训练一个受约束的快速系统时，用同一基座的**慢速生成形态**做 judge：它不更聪明，但拥有被训系统被剥夺的资源（这里是解码循环），其输出为无验证标签的样本提供信息。
- **论文证据**：judge=Qwen3.8-27B 高推理档（Max 同基座），对每条记录（含无验证结果的）给分布；RLAF 全量 +2.0 分。
- **推广场景**：(1) 蒸馏的新形态：非「大教小」而是「慢教快」「生成教判别」；(2) 程序合成：解释器验证 + 慢模型评分的组合奖励；(3) 组织决策：快决策者训练时参考同资历慢决策者的书面分析；(4) 缓存系统：离线慢路径产出校准在线快路径；(5) 机器人：仿真慢规划器的分布作为快策略的奖励塑形。

### 灵感 4：置信度是免费的可调精度旋钮——前提是校准随域监控

- **论文证据**：top-50% 精度 99.3%、top-80% 96.1%；但分域 ECE 7.2-9.2%、6-20 选项 8.4%，单一温度不可救；阈值须按模型按域重标（0.80/0.51/0.25）。
- **核心思想**：结构化概率输出使「精度-覆盖率」成为运行时可调参数，而非模型固定属性；但校准是**经验性质**，部署域偏移即失效，须持续监控。
- **推广场景**：(1) 人机协作分流的生产化（低置信→人审）；(2) 风控阈值管理；(3) 医疗辅助决策的知情同意（给出可信不确定度）；(4) 多级级联系统的退出条件设计；(5) 数据库查询优化器的成本估计置信路由。

### 灵感 5：构造性保证优先，学习性保证测量——系统性质的分层设计

- **核心思想**：把系统需要的安全/一致性质分成两层：能用架构或类型系统白拿的（闭世界输出、问题独立性）绝不留给学习；只能学的（顺序鲁棒、校准）必须配套测量协议与退化监控。
- **论文证据**：闭世界靠 softmax-on-options 构造保证；顺序鲁棒无架构方案（混合骨干限制）→ 训练一致性项 + 1,591 决策三序实测 + flip-置信关联分析。
- **推广场景**:(1) 分布式系统的不变量 vs 最终一致；(2) 编程语言的静态检查 vs 动态测试；(3) 密码学的构造安全 vs 统计安全；(4) 供应链的签名（谁发的）vs 语义绑定（内容是否如声明）——下一篇精读将展示这个 gap 的安全后果；(5) 法务合规的结构性隔离 vs 实质性审查。

### 灵感 6：压缩比与判别精度的经济学——指针共享缓存 vs readout 重编码

- **核心思想**：两种读出头代表两种成本结构：指针头「状态一次编码、N 问摊销」适合长文档多问；readout 头「每问全量重编码」用计算换双向比较的精度。接口统一让二者可在同一系统按问题类型路由。
- **论文证据**：缓存状态 21.6ms/问 vs Max 183ms/问；Max 精度 +1.86pp（230k 决策）；家族四模型同一 API。
- **推广场景**：(1) 混合精度服务的分级计费；(2) 编译器的解释执行 vs 优化编译；(3) CDN 的边缘缓存 vs 源站重算；(4) 数据库物化视图 vs 即席查询；(5) agent 框架中「热路径判别 + 冷路径生成」的双系统架构。

### B. 术语备忘

- **决策模型 / System One 接口**：输入状态+问题+选项，输出选项分布，无自回归解码。
- **指针头**：`<decide>` 处 query 与各 `</opt>` 处 key 点积打分，状态可跨问题缓存。
- **readout 头**：`<ans>` 隐藏态 → 255 个选项代码 logit 的无偏置线性层；需符号绑定，每问重编码。
- **RLAF**：Reinforcement Learning from Adjusted Feedback——验证结果 + judge 分布构造奖励/软目标，KL 锚定 SFT 模型。
- **noul**：二元问题类型，返回 p(yes)。
- **flip 率**：选项置换后 top 选项改变的比例；**机会校正技能分**：0=随机、100=满分的基准分标准化。
