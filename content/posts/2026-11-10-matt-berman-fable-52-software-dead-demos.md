## 先说结论

Berman 的结论毫不含糊：Fable 5.2 是他用过的最好的模型——依据不只是榜单，还有他自报「大概超过一千亿 token」的实测预算。演示端的口号是「software is dead」：三行提示词做出可通关的《战争机器》级游戏关卡（Berman 称约 85 亿 token、按 API 价折算约 1.5 万美元），约 50 小时造出他称为「找不出一个缺陷」的浏览器版 Excel 克隆，90 亿 token 做出他认为「可以直接拿去卖」的多人游戏。跑分端同样凶悍（演示显示）：计算机操作基准 OSWorld 2.1 上 Fable 5.2 得 89.3，大幅领先他此前心中最佳的 Astra（79.5）与自己常用的 Opus 5.5（87）。但他的选型结论同样明确：Fable 更强「毫无悬念」，可 Opus 5.5 更快、更省，他的大项目至今仍用 Opus——能力与成本的非对称是这代模型的核心矛盾。片尾他把一切接回 METR 那份「Anthropic 通往递归自我改进没有实质瓶颈」的报告：公开发布的模型已是如此，内部压着的该是什么样。

## 三行提示词与 85 亿 token：从《战争机器》到可以上架的《Tumble Beans》

开场演示是一段完全可玩的《战争机器》（Gears of War）克隆：掩体射击、定时装填、AI 队友倒地后复活，难度高到 Berman 玩得忘了自己正在录视频。他强调两点：其一，提示词只有三行——「用虚幻引擎（Unreal Engine）做出尽可能精确的《战争机器：E-Day》克隆，只需做一个关卡，但画面、玩法、角色要和真的同样完整」（E-Day 为 Berman 口中「刚发布」的系列新作）；他偏好这种故意欠规格（underspecifying）的提示写法。其二，成本：切到 ultra code 模式（他口中对「扇出一组子 agent 并行干活」的高耗费模式的叫法）放手让它跑，至今 85 亿 token、仍在继续，按 API 定价折算约 15,000 美元——他由此说「几天之内做出一个 3A 级游戏」。

更强的证据是《Tumble Beans》：一个《糖豆人》（Fall Guys）全套戏仿克隆，提示词同样只有数行（「确保关卡好玩、复杂且各不相同，做十个关卡」），他唯一追加的要求是多人模式。Berman 与团队两位同事 Alex、Brian 现场连线实测对战，过程流畅。账单：超过 90 亿 token、约 71 小时构建、约 13,000 美元。他的判断是这已经是「一个可以卖的游戏」——有游戏想法的人可以把它做出来、去变现。同一批早期权限下，同事的作品还包括：方块画风《使命召唤》类多人游戏；反编译《大乱斗 Melee》移植安卓实机游玩；《传送门》（Portal）克隆（画面「略欠火候」，但一条提示词、手机可玩）；F-Zero 类赛车《Starlane》（旁白都由 AI 生成）；Brian 用上一代模型重做的《Tidekeeper》二代；画面亮眼的《Dragon Rider》。

## 生产力与内容工具：50 小时的「完美」Excel、达芬奇克隆与 25 美元的解说动画

第二组演示对准生产力软件。Excel 克隆：约 50 小时完成，Berman 称「找不出一个缺陷或缺失功能」——单元格里的都是真公式、可点入查看，示例销售跟踪表带着完全可用的透视表（pivot table，数据汇总工具）；浏览器版，他承诺发布公开链接供观众自测。视频剪辑侧是达芬奇 Resolve（DaVinci Resolve）克隆：波形显示、片段剪切、磁吸对齐、完整键盘快捷键、关键帧一应俱全；这个名为 Kestrel 的程序是本地 Windows 应用而非网页。更值得记录的是一句旁证：同事 Alex 独立做过同款，并且「已经一直在用自己 vibe code（凭自然语言让模型写码）出来的剪辑器剪真实视频」——工具从演示走进了生产。Berman 的口号由此从「software is dead」升级为「software is solved」。

内容制作侧，他展示了完全由模型生成的动态图形（motion graphics）：一支 1 分 52 秒讲清「软件反编译」的成片花约 950 万 token、约 45 分钟、约 25 美元；「LLM 工作原理」动画同样被评为「完美」（嵌入、transformer 层、损失曲线、下一 token 预测），他说将直接用于后续视频——以前是团队要以天计的活。他此前那支以反编译与 Photoshop 克隆论证「软件已解决」的视频，本站[已成文](/posts/2026-10-11-matt-berman-decompile-software-solved-verifiable-loops/)。

## 物理世界与纯生成的边界：91 美元的水球仿真、37 美元的承重塔与「第一个坏的」

第三组演示更接近「物理理解」。子弹穿透注水气球的实时光线追踪（ray tracing）仿真：单个 HTML 文件（JavaScript+HTML+CSS+WebGL2），零框架、零外部库——因为提示词明令「不要用 Three.js 或任何外部 web 库，我要测试你的物理理解，请完全从零写」；子弹速度、口径、阳光强度与方向都可用滑杆实时调整、物理即时重算，画面可任意角度冻结。成本仅 4,100 万 token、约 2.5 小时、约 91 美元。3D 打印承重塔（Berman 称灵感来自 RPN，转写疑似、未核实）：限定 Bambu Lab P2S 打印机、0.4 毫米喷嘴、PLA 材质、整塔低于 10 克，模型产出的结构件从约 6 磅的笔记本层层实压——iPad Pro、两台 MacBook Pro、Mac mini、NVIDIA DGX Spark、reMarkable，最后压上一把电钻，「there it goes」——据此推断塔在此时被压垮。整个实验约 1,000 万 token、1 小时出头、37 美元。还有 1,300 万 token、约 30 美元的 Blender 建筑渲染（提示词只有一句「让它像房地产开发商的梦」，成品带泳池、太阳能板与室内版本，唯一败笔是车道正中长了棵树），以及由 AI 驱动每个「市民」行为（对话、遛狗、走进咖啡馆）的 3D 欧洲小镇，彩蛋是「老欧洲街景配未来派汽车」。

同一节里出现了全场唯一明确的失败样本：让他「只看照片和视频」复刻 Roadster 发布会场景，成品被他自己当场撤回好评——「这是我看到的第一个坏的」。另一个庞然大物则成功：用虚幻引擎生成整座东京，67.2 亿 token、约 70 小时、约 11,000 美元，火车站、进站电车、全城车流与建筑上的光线追踪反射——Berman 称「每一栋楼都是模型从零建的」，且这段他自己也是第一次看。另有一张他用量的截图显示 80 亿缓存输入 token 加约 1,500 万输出 token、约折合 11,700 美元（演示显示，未指明对应哪个项目）。

## 跑分与实测：89.3 分的计算机操作、九成正确的自主决策、10 分钟的全库审查

跑分侧（演示显示）：Frontier Code 2.0 上 Fable 5.2 碾压榜单所有模型，包括他此前最爱的 Opus 5.5；Frontier Suite 得 69.9 领跑；Carbon 与 Astra 落后（Carbon 唯一获胜的项目是 Automation Bench：53 对 Fable 5.2 的 51）；Terminal Bench Science 上同日发布的 Mythos 5.2 得 75.3、险胜 Fable 5.2 的 74.6。计算机操作基准 OSWorld 2.1 上 Fable 5.2 得 89.3，碾压他心目中「地球上最佳计算机操作模型」Astra 的 79.5；Opus 5.5 意外拿到 87。Humanity's Last Exam（HLE，综合性高难基准）得 74.2，比 Fable 5.1 高约 10 分、比 Opus 5.5 高略少于 10 分。

实测观察更具体。其一，极其自主：它会替 Berman 做决定，而「十次有九次、也许更多」那些决定正是他会做的。其二，效率跃迁：ultra code 极贵、他不推荐日常使用，但最大思考档加 ultra code 对他全部代码库做完整代码审查时，bug、安全问题、UI 不一致「找出一堆」，且过去要 60–120 分钟的活现在最多约 10 分钟——他强调这不是每秒 token 数（在 Claude Code 里被混淆掉了），而是「它知道完成任务的最短直线路径」。其三，选型现实：Opus 5.5 至今是他所有大项目的主力；Fable 更强「毫无疑问」，但 Opus 更高效、更快、便宜得多。

## 定价与收束：降两成、快 2.5 倍，与「内部还压着什么」

定价（Berman 称）：较 Fable 5.1 下调约 20%，现为每百万输入 token 8 美元、输出 40 美元；快速模式（fast mode）提速 2.5 倍，但价格翻倍至 16/80 美元（他没有快速模式权限）。他还提到一件「Anthropic 不常做的事」：本周按订阅状态与时长向用户发放 Fable 用量重置（resets）。这次显性降价与本站此前引述 Anthropic 上市文件 S-1 时记下的口径——「每代模型完成同样任务的成本下降 25%–40%」（[Jamin Ball 拆解 S-1](/posts/2026-11-08-latent-space-anthropic-s1-myths-jamin-ball/)）——互为印证。片尾一句带过：他说这一切「难怪 METR 刚发布那份『Anthropic 有一条通往递归自我改进的直通路』的报告」——公开的 Fable 5.2 已如此，内部模型与投喂的 token 规模可想而知；该报告本站已按他上一期视频[专门成文](/posts/2026-11-08-matt-berman-metr-anthropic-rsi-12-months/)，此处不重复。

## 机制 → 影响 → 启发

1. **三行提示词＋海量 token＋子 agent 扇出 → 软件生产成本从「团队·月」压缩成「token 账单」**。直接原因是模型的长程任务完成速度（Berman 称 60–120 分钟的任务被压到约 10 分钟）与自主决策可靠度（九成正确）；得的是有想法的个人与小团队——他们获得了此前 3A 工作室和软件公司独占的实现能力，失的是以「实现」为卖点的长尾软件与外包；二阶影响是软件价值加速向分发、数据、运维与责任承担集中。观察指标：Berman 承诺公开的浏览器版 Excel 克隆与可玩游戏链接是否兑现、独立开发者用这代模型上架作品的速度。启发：把「写不出来」从风险清单划掉，风险改押在「值不值得做」与「谁来运营」。
2. **能力-成本非对称 → 选型从「追最强」转向按任务性价比分层**。机制是推理成本随能力档位陡增（Berman 日常仍用 Opus 5.5）；降价 20% 与 2.5 倍速快速模式正是对分层需求的定价响应，也与 S-1 每代成本降幅同向。观察指标：两类模型的实际用量份额、快速模式开放后的第三方评测。启发：评估模型看「完成你的任务要多久×花多少钱」，聚合榜单只当入围门槛。
3. **计算机操作与自主性跳变（OSWorld 89.3、九成决策正确）→ agent 从被指挥的工具变成可委派的对象**。全库代码审查这类原本「不可行」的任务变成例行操作，但每一步自主都是新的风险面；九成正确意味着一成仍需人类兜底。观察指标：Anthropic 是否扩大用量重置、第三方对 Fable 系模型自主任务失败率的评测。启发：开始把「可委派清单」显式化，并为每类委派保留复核点。
4. **失败样本的信号价值（Roadster 复刻是「第一个坏的」）→ 演示叙事天然偏采样自成功任务**。有真实参照物需要对齐的重建任务暴露了非对称弱项，而聚合基准看不见这种弱项。启发：用自己的用例测失败模式，警惕 demo 驱动的能力判断——Berman 主动给出反例，恰是这类频道最值得保留的可信度来源。
