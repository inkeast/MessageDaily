## 先说结论

这是 Latent Space 旗下新桌谈节目「High Stakes Testers」的第一期（节目自称 high taste testers，"高品味测试员"），录制于 OpenAI Dev Day 之后：主持人明言 OpenAI 不在场、可以畅所欲言，四位重度 AI 用户边吃边评。全场的核心判断可以压缩成三条。其一，Dev Day 的发布很热闹，但产品化欠账严重——Dots、Spaces 等新东西藏在 UI 深处，远程执行没有兑现"任务完成、合上笔记本"的承诺。其二，决策模型（TypeSafe 的 Jef 及其克隆，转写如此）被一致视为新一代基础设施积木：能力上并非跃迁，但校准、速度与单价解锁了新的用法，已有嘉宾用自家评测给出"成本降 10-20 倍"的实证。其三，模型侧进入新世代分水岭：Opus 5.5 与 Soul 6.1 被认为重新拉开与第二梯队的差距，Grok 4.7 定位失败，开源与前沿的差距从半年重新拉大到约一年（均为嘉宾观点）。

## Dev Day 观感：发布热闹，产品藏在"三个点"后面

嘉宾们对 Dev Day 的共识是"重发布、不重发布会"：Dots、GPT-6.1 Soul、ultra fast 模式、类 Notion 的协作白板 Spaces，以及还在排队名单上的 decisions API。但好评很快转向批评。多位嘉宾抱怨新功能"深藏"：Spaces 像共享白板，能写 markdown、能画图，但入口隐蔽；ChatGPT 里甚至藏着一个地图克隆，埋在第二侧边栏的三个点菜单后面——有嘉宾发帖之后才被告知"这功能早就在了"。Codex 桌面应用的近期更新被几位嘉宾评为"倒退"：多了一个侧边栏、性能变差、断网时输入框直接冻结；ChatGPT 与 Codex 的合并被形容为"AI 发烧谵梦"，一个下拉框似乎只换模型不换体验；"Fork Chat"被改名成"Copy"的理由（非开发者不懂 fork 一词）也让开发者嘉宾不满——他们恰恰是目标用户。

一位嘉宾把这归因于 AI 写代码本身：Codex 应用复杂到"AI 之前很难做出来"，但"东西随机变、随机坏，像 AI 写的文本，眯着眼看会问：等等，这是什么"。另一位补充了一个更结构性的判断：既要企业又要消费者的中间态产品，最后对谁都不适用；对照 Grokbot（专业个人助理，调校精准）与 Muse（面向大众、运转良好）的专注才是出路。Dots 的定位同样被质疑——"企业 Dots 和消费 Dots 是两个产品"；有嘉宾推测 Dots 最终不是独立 App 而是独立设备，并吐槽 OpenAI 与 Jony Ive 合作的实体设备迟迟未到（Dev Day 上再次被追问"Johnny，我的设备在哪"）——"三到六个月在 AI 时间里已经算长期"。

## 助手范式：没兑现的"合上笔记本"与没解决的信任边界

Dev Day 的叙事是"任务完成，可以合上笔记本了"，但现场没有一个人合上：云执行的设置繁琐，一合上笔记本 agent 就停摆；有嘉宾为了让 agent 继续跑，把笔记本敞着留在办公室。为什么这么难？嘉宾的解释是：Claude Code、Codex 内部本来就是一份大 JSONL 追加日志，"把状态送上云"在技术上并不神秘，难在实验室没有把状态外部化承诺为稳定 API——大家不想押注一个随时会变的私有接口，于是都在自造 harness，也没有 agents.md 这样的状态标准。对照物是 Pi 的持久化执行（节目口述为 PyDurable，作者 Mario 自述一年内重写七次才发布）：状态逐步落盘，本地与云端可以无缝接力。

围绕"该不该把个人邮箱接给助手"，这张桌子给出了一支清晰的信任温度计：几位嘉宾的可信名单是 Apple、Google、OpenAI，"没有第四家"；Meta、Amazon、Facebook 一律不配个人邮箱——理由不是能力而是动机预判（一位嘉宾"感觉 Meta 更可能先干再说、事后承担后果"，另一位当场表示不完全同意）。Dots 是其中一位嘉宾第一个接了个人邮箱的助手；另一位直到 Cognition 收购 Poke 之后才敢接日历。OAuth 连接器是否存在也被反复强调——"绝不把邮箱密码输给 Gmail 以外的任何东西"。

提示注入解决了吗？一位嘉宾认为"基本解决"，依据是新模型（Astra、Opus 5.5 一代）带宪法层级与提示注入基准、外部内容很难穿透；他还举例 Matthew Berman 曾请著名越狱者 Pliny 对某款新 agent 做五次攻击尝试未果。但更多人当场反驳：五次太少；而且"意外"比"恶意"更危险。节目举的例子包括：有用户的助手在主人挂售二手时直接告诉买家"你应该直接上门"；Instinct 在朋友来问时把邮箱里的 Netflix 双因素验证码直接给了出去；一位把邮箱接入 Grokbot 的嘉宾说，五份待发草稿里约有一份含他不想发的细节（比如以"我是此人的 Grokbot"开头），所以一律人工审核后手动发送。桌面最终形成的共识是：读可以，写必须显式授权（"read only, write with explicit permission"）。配套的工程解法也在浮现：有嘉宾的朋友在做 MCP 网关公司（节目称 Executor）——把 Gmail、Drive、Notion 等连接集中在一台家用 Linux 盒子上，任何新助手只接一次 MCP 就继承全部工具、技能与配置；另有嘉宾期待助手能按商户开虚拟信用卡，现场被告知 Stripe 的 Link 已经在做"每笔购买生成一张虚拟卡+人工审批"。

## 决策模型：Jef、TypeSafe 与 Cloudflare 的克隆战争

OpenAI 在 Dev Day 放出 decisions API（目前只是排队名单），被普遍视为对 TypeSafe 旗下 Jef 的跟进——嘉宾援引一期独家访谈称，OpenAI 版现在"就是 Luna 加一层结构化输出包装"，多模态在路上。嘉宾们兴奋的点不是能力跃迁——"GPT-4o mini 早就能做大部分分类"——而是三件事：其一，校准。多数厂商收走了 logprobs，旧模型给 0-1 的置信度只会输出 0、0.5、1 三档，Jef 给的是"接近真实概率"的逐决策概率。其二，速度与单价让 AI 能塞进"以前塞不进的奇怪位置"——例如网站 Command-K 搜索菜单的即时候选排序：用户敲三个字母，模型毫秒级判断该去二十个页面里的哪一个。其三，切换成本极低：把历史人工标注当评测，新模型一致率超过阈值就只人工审分歧项。

实证来自 Raindrop 嘉宾：他们正在内测的"代理式记忆管线"——Jef 做结构化输出与排序重排、Soul 系模型做重理解，回头分析 agent 轨迹并建议往 CLAUDE.md 里加什么——在自家评测上与 Opus 5.5 对齐，成本降 10-20 倍且无需推理链；他同时提醒，前沿模型不开推理链做分类时"惨不忍睹"。嘉宾们对社交网络上的病毒式演示普遍不屑："有了格式保证就兴奋，等于自曝此前的管线有多糟。"

竞争侧，节目称 Cloudflare 的克隆 Cliff 在某基准上"小模型与 Jef 同性能且快得多、大模型性能更好也更快"；而 Cloudflare CEO Diogo 在另一档节目里被剪出连续七次的"别拿基准测我们"。嘉宾认为结构化分类极易过拟合——对超受约束的重复任务，过拟合甚至无所谓，但 Jef 的卖点是跨任务多样性，"忠实评测很难，于是用户也不知道该选谁"。另有传闻称 TypeSafe 正在谈百亿美元级融资（节目明言是 rumor）；多位嘉宾判断这个品类会长出本地/端侧版本（ONNX/WebGPU 版 Jef 已可运行），并引用 OpenAI 早年"幻觉即二分类"的论文提醒："二分类看起来简单，实则是世界上最难的问题之一。"至于 OpenAI 为何现在跟进，嘉宾打探到的口径是：TypeSafe 证明了品类与市场存在，"我们的开发者也想要我们的版本"。量级上，一位嘉宾估其影响"约为推理模型那一次变革的三成"——不到 ChatGPT 时刻，但方向确定。

## 模型桌评：Opus 5.5 重写叙事，Grok 4.7 落入无人区

主菜环节是模型选型。写作与"灵魂"：Ben Davis 的党线是"Claude 系模型有灵魂，GPT 系是天才工程师但零灵魂"——写作相关一律 Opus 5.5，GPT-6 系全回避；他引用 Sam Altman 的公开表态"我们模型的写作不行，在追赶"。反转在于：就在 Opus 5.5 之前，他的立场完全相反（4.8 一团糟、4.6 是最后一个好版本；他做的每日 AI 摘要在 4.6→4.8 切换后被用户投诉"读不下去"）。Anthropic 这次的发布叙事也被全桌认为罕见：官方实质上"把自家历代 Claude 批了一顿"——研究员为 Opus 5 道歉、"慢慢变差"的梗图疯传、"5.5 修好了"——嘉宾称这是 Anthropic 头一回这么做。为什么内部没察觉？共识是 Anthropic 内部日常用的是未发布的 Mythos/Fable 级模型，且无限量、高速，与付费用户的体感完全是两种体验——"Anthropic 没人用 Opus"。

选型结论：Opus 5.5 与 Soul 6.1 是"日常够用、不必动用旗舰"的两款；Astra Ultra 留给硬问题（一位嘉宾在最快档 20 分钟烧穿一周额度，认为值）；Sonnet 5.5 被评为"最好的你不该碰的模型"——当 Opus 的廉价子代理很好，"有点灵魂的小弟"。Muse Spark 被认为是明显的洼地：百万上下文、多模态（能直接"听"视频里的掌声而非依赖转写）、比 Gemini 便宜且略快，是 Jef 出现之前"扔大段文本"的最便宜选择。Grok 4.7 则被评"令人失望"：定价陷阱（超 200k 上下文价格翻倍、开快速模式再翻倍、叠加后接近三倍，嘉宾认为"同价更好的模型"宣传不实）叠加 token 效率糟糕（步骤与推理极多），结果是既不快（Muse 是）、不便宜（Muse/Luna 是）、也不够强（Opus 是）——"按 Opus 的价钱买 Grok"。唯一好的体验在 Grokbot，嘉宾推断这个模型被 RL 牺牲给了自家产品；但 Grok 接入 X 实时数据仍被公认为"最好的研究模型"，Grok build CLI 还能被其他 agent 当免费 X 数据源的子代理调用（X 的 OAuth 连接器发布后，Pi、Hermes 等也能直连；有嘉宾提及随 OpenClaw 发布的 bird CLI 因 cookie 方案遭封号而迁移 OAuth，人名转写存疑）。

开源侧：一位嘉宾在 GLM-5.3-flash 发布时判断 DGX Spark 会涨价、让父亲去俄亥俄的 Micro Center 抢了四台（"靠算力赚钱很蠢，算力不该升值"）；他在 Sparks 上跑 V4.1 flash（转写如此）做可验证的爬山任务没问题，但"OpenAI 前沿与其他一切之间的鸿沟"仍然巨大。全桌估计：开源模型从前阵子的落后半年，被 Opus 5.5 与 6.1 的跳变重新拉大到约一年。节目还引用嘉宾自跑的 Slop Code Bench（威斯康星大学某实验室出品）子集：10 个问题里 Opus 5.5 写了约三万行代码、其中 51% 是测试，而 Sonnet 5 与 Opus 4.8 各约一万行、测试占比仅 10-15%（节目称，样本很小）。世代论收束了这一节：嘉宾认为模型能力呈"天花板—平台"结构，今年夏末各家一起撞上了上一代的天花板（子代理编排、长任务，但缺力量与判断力），现在只有 6.1 Soul、Astra、Opus 5.5、Fable 5.1 进入"新一代"，标志是集群行为（swarming）与"可信度"——最有说服力的例证是：一年前没人会把带发送权限的邮箱接给模型，现在敢了。

## 重度用户的工作流与可迁移的启发

桌谈最后各自交代了个人技术栈，模式惊人地一致：一位的"个人助手"就是一个装满脚本与 markdown 记忆的 Git 仓库，要做事时把 Claude 或 Codex 启动在仓库里；另一位用 Pi——给它专属 Gmail、信用卡、提醒与 cron——自评"比 Dots 好用"，并认为主动式助手真正难的正是"主动性"本身；还有一位维护约 30 个 Grokbot，用 Linear 工单让它们互相协作，把 Grokbot 当参谋长去调 Cursor 云端代理跑 Opus 5.5。可迁移的工程细节包括：主线程只做编排、不执行（"你的上下文应该是我们的对话，不是执行过程"）；给子代理设 48 个会在两小时烧穿 Astra 限额（该嘉宾回调到 15）；压缩（compaction）必然打爆缓存，希望有"只剥掉大图片、不写摘要"的压缩选项；用一个侧线程盯主线程的推理是否跑偏；夜间批处理用"穷人版 Ralph 循环"——排队五到十条改进指令通宵跑，早上九点统一审查，但开场那句警告仍然成立：让模型通宵跑，产出的代码会超出你能可靠消化的量。

被低估名单与硬件展望：Google AI 搜索概览（约 300 毫秒出答案，对比 ChatGPT 默认最高推理档的 10-30 秒）；Devin 当"随便一个想法的沙盒电脑"（跨仓库、不受本机合盖影响，而 Cursor 云端环境配置太费劲且"你让它写段文字它非要发 PR"）；硬件侧有嘉宾兴奋于 Tesla 里的 Grokbot（Ultra 档，语音指挥、车自己开、机器人回话），并预言 Muse 的"电子宠物机"吊坠会即刻售罄、是完美的圣诞礼物；但也有冷水："需要充电的东西已经饱和，手机之外没有第二块屏能幸存——用另一个要充电的东西去充电，不成立。"收尾时一位嘉宾的请求几乎总结了整场：与其反复刷末日论，不如让普通人真实体验一次"它帮我订好了理发店、省了五分钟"的触感——这正是各家实验室都在转向简单用例的原因：普通用户用上助手，才会上瘾那种持续的 token 流量。
