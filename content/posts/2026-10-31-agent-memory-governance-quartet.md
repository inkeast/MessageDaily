## 引言：从「存什么」到「怎么治理」

如果让时间倒回两年，Agent 记忆（agent memory）研究的核心问题还是「存什么」：存原文还是存摘要、存三元组还是存笔记网络、按轮次 CRUD 还是按会话蒸馏。MemGPT 做上下文分页，Mem0 做逐轮增删改查，A-Mem 组织 Zettelkasten 笔记，Zep 维护时序知识图谱——这些系统回答的都是表征问题（representation）。

但 2026 年 10 月底集中出现的这四篇论文，不约而同地把镜头转向了另一个维度：**治理（governance）**。它们各自抓住记忆生命周期中一个此前被表征研究遮蔽的正交问题：

1. **监督从哪来**——优化一个记忆系统需要反馈信号，人工标注的 QA 昂贵且不可扩展，能否从无标注历史自动生成可靠监督？MemSteer 给出肯定回答。
2. **怎么存**——单一记忆表征各有盲区，冗余与冲突随时间累积，如何在保留互补性的同时控制存储膨胀？Microsoft 的 Curation+Consolidation 用情景+关系双记忆加离线巩固回应。
3. **怎么冲突治理**——一条记忆可以「对过去有效、对现在失效」，语义相关不等于当前可用，如何区分保留与使用？CALM 把它形式化为冲突感知的生命周期治理问题。
4. **何时注入**——检索到相关经验不等于应该注入，实现级教训的相关性只有在执行过程中才会显现，谁来做注入决策？MUSE 用三级记忆加门控运行时注入作答。

这四个问题恰好覆盖记忆生命周期的四个环节：**监督生成 → 存储巩固 → 冲突治理 → 运行时准入**。更值得注意的是四篇的机构光谱：北大+MSRA、Microsoft、哈工大+美团、中科大+人大——高校与企业实验室在同一个周末（10 月 28–29 日）从不同切入点收敛到同一命题，这本身就是一个强信号：记忆治理正在成为 Agent 记忆研究的下一主战场。

下面按「监督→存储→治理→注入」的生命周期顺序逐篇精读，每篇按背景、定位、问题定义、解法、实验证据、根源解释、知识反推、通用灵感的框架展开。

## 一、MemSteer：用户历史即监督

> MemSteer: Turning User Histories into Supervision for Agent Memory Optimization，[📄 原文链接](https://arxiv.org/abs/2610.39276)

### 1.1 背景：记忆设计优化缺一个反馈信号

Agent 记忆系统的设计——存储粒度、检索策略、上下文组装方式——本质上是应用相关的工程问题。不同用户的历史数据在内容、模态、组织方式上差异巨大，一套设计打天下注定次优，因此近邻工作 ALMA、MemEvolve、M⋆ 都在探索**记忆设计自动优化**（memory-design optimization）。但这些方法依赖下游任务的成败信号做反馈，而个人记忆场景（邮件、文档、对话记录）天然没有「成功或失败」可言。QA 标注能补上这个信号——问题、参考答案、支撑证据三件套既能评估候选设计，又能诊断失败响应——但为每个新用户手工构造 QA 太贵。论文第一节的动机图把问题画得很清楚：左边是 labor-intensive 的人工标注，右边是 MemSteer 的自动化转化，输入是无标注历史，输出是 QA+证据监督。

### 1.2 定位：不训练模型，只优化设计

MemSteer 的定位非常克制：它**不改模型参数**，只优化记忆系统的设计空间（存储表示、检索策略、上下文构建），监督来自历史本身而非人工。这使它与两条近邻工作拉开距离：MemBuilder/MemMA 用合成 QA 训练记忆构建模型或修复记忆库（改的是模型），MemSteer 用合成 QA 评估与修订记忆设计（改的是架构）。作者在相关工作里专门强调了这一区分：「我们 investigates whether history-derived QA can provide reliable feedback for evaluating and improving memory-system designs」——关键词是 reliable（可靠），合成监督的可靠性正是全文的技术核心。

### 1.3 问题定义

给定无标注用户历史 H，构造 QA-证据监督集合：

D_H = {(q_i, a_i, E_i)}, i = 1..N

其中 q_i 是关于历史的问题，a_i 是参考答案，E_i 是选中的源记录集合（带源文本 span 引用做溯源）。参考答案用于评估候选记忆设计，证据标注用于诊断失败响应。在此之上，MemSteer-Opt 用这套监督迭代修订设计 d = (s, r, c)——存储、检索、上下文三要素——目标是仅凭验证集 QA 准确率 A(d) 接受或拒绝修订。

### 1.4 解法：答案计划先行，双重验证兜底

监督构造分三步：

**图引导素材准备**：把用户历史组织成源记录图（同会话、相邻文档段、显式引用、充分词面重叠的记录连边），从种子做路径扩展采样连通子图，形成上下文预算内的素材包 B，每条记录带 span 引用。

**证据落地的答案计划（evidence-grounded answer plan）**：这是全文最有辨识度的设计。LLM 规划器不直接生成问题，而是先构造一份「答案计划」：声明要问的主题（subject · property · constraints）、支撑事实及其 span 引用（f_1 [r_1:s_1]）、每条证据记录的贡献（r_1: f_1, f_2 · identity）、组合事实所需的操作、参考答案。计划通过程序化检查（结构一致性、溯源覆盖）后才驱动独立的问题生成调用。这个「先计划后提问」的两阶段设计是消融实验里质量提升的最大来源之一。

**源审计 + 盲答恢复双重验证**：语义审计由 LLM 审查者逐条判断答案支撑与问题-计划一致性；盲答恢复只给盲读者问题、答案类型和素材包记录，要求其独立作答并引用来源——候选必须让读者声明可答、答案在类型归一化后与参考精确一致、引用覆盖全部证据记录，三者缺一不可。验证将 QA 质量从 75.4%（无验证）推到 90.9%（双 judge 平均）。

MemSteer-Opt 侧的关键机制是**证据引导的失败分层诊断**：对每个错误响应，检查所需源记录是否完整进入最终上下文——进入了则是「回答失败」；缺失则查记忆系统能否恢复对应记录——任一记录不可恢复是「存储失败」，全部可恢复是「检索失败」。分层后的失败案例按类别采样（每类至多 10 条）喂给设计提案者，避免高频失败类型挤占反馈预算。

### 1.5 实验证据

在 ATM-Bench（约四年个人记录、11,034 条多模态记录、1,013 主问题集 + 31 题 Hard 多跳集）与 RHELM（21,142 条交互记录、10 个 persona、1,305 官方 QA）上：

- **监督有效性**：MemSteer-Opt 把 ATM-Bench Question Score 从 Base-BM25 的 54.9 提到 68.3（+13.4），Hard 从 8.2 提到 29.1（+20.9），证据召回 R@10 从 61.7 提到 84.1（+22.4）；RHELM 无外部数据 +4.1、有外部数据 +6.6 个准确率点。
- **与官方标注打平**：ATM 四项指标全部略超 Official-QA（主集 +1.1、Hard +1.3），RHELM 落后 0.1/0.8 点——考虑到 Official-QA 的训练集包含在评估集内，这个「打平」实际含金量更高。
- **外接优化器也受益**：M⋆ 与 MemEvolve 各自在自己的设计空间内用 MemSteer 监督获得 +6.0 与 +18.6 主集 QS 提升（对比 Official-QA 的 +4.4 与 +18.6），证明监督效用不绑定特定优化器。
- **新用户持续优化**：六用户共享设计迁移到 held-out 用户 Martin Keller 反而降 3.5 点，但用目标用户历史生成的监督继续优化后回升到 44.3%（超 Base-BM25 的 41.2%）——监督可以从目标历史持续再生。
- **关键消融**：两阶段 Plan-Q 的 QA 质量 85.9% 显著超直接生成 67.8% 与联合生成 73.1%（代价是每题 token 从 64k 涨到 105k）；诊断+分层采样的反馈构造拿到最高 QS 68.3，而随机采样加金证据只有 62.7——**失败归因比原始证据更有价值**。

### 1.6 根源解释：为什么合成监督能逼近人工监督

MemSteer 有效的根源可以反推为三层：

第一层，**答案计划把「问什么」从生成问题解耦成组合事实的声明**。直接从素材生成问题时，LLM 倾向提出素材浅层就能支撑的问题，多跳与聚合问题占比低、证据-答案链条模糊。答案计划强制先声明事实组合方式与各记录贡献，再让问题生成器「反推」问题，自然覆盖联合推理型问题——这解释了 Hard 集 +20.9 的巨大增益（多跳问题正是合成监督最缺的类型）。

第二层，**盲答恢复是合成监督可靠性的守门员**。合成 QA 的经典失败模式是「问题不可独立回答」或「答案不可从素材恢复」，盲答恢复用一个不知参考答案的读者模拟了这一检验，配合类型归一化的精确匹配把低质候选挡在训练集外——Naive-QA 验证保留率仅 21.2% 说明无计划的合成候选大多数过不了这关，而 MemSteer 保留 47.9% 且质量 90.9%。

第三层，**证据标注让失败可归因到设计层**。没有证据标注时，错误响应只能整体反馈给提案者；有了证据，错误可以定位到存储/检索/回答某一层，修订建议因此有的放矢——这是消融中「加金证据只有边际改善、加诊断有明显改善」的直接原因：金证据告诉提案者「缺什么」，诊断告诉提案者「为什么缺」。

### 1.7 知识反推：从论文可以提取的可复用知识

- **合成 QA 的质量杠杆在「计划-生成分离」**：需要高质量合成监督时，先让 LLM 声明推理结构（事实、贡献、操作）再做程序化校验，比端到端生成质量高 18 个百分点以上，代价是约 60% 的 token 开销——在监督质量决定下游优化上限的场景这是划算的。
- **盲测式验证是合成数据的通用质检器**：让一个「盲」模型只凭素材独立完成任务并对照参考答案，能把合成数据从「自洽」提升到「可独立复现」——这个模式可迁移到合成代码测试、合成工具调用轨迹等任何合成监督场景。
- **分层失败归因优于整体反馈**：任何迭代优化系统（不只是记忆设计）都可以用「证据在不在上下文」这类可程序化检查做失败分层，分层后的反馈信噪比显著更高。
- **监督预算存在甜蜜点**：100→200 训练问题带来最大增益，之后检索召回平台化——合成监督不必贪多，质量优先于数量。

### 1.8 通用灵感

MemSteer 的深层启示是「**数据本身可以是优化器**」：当一个系统的设计空间难以端到端学习、但存在可程序化评估的输出时，从系统处理的原始数据反向生成评估监督，就能驱动无梯度的设计搜索。这个范式不限于记忆系统——检索管线、数据清洗规则、甚至 prompt 工程都可以套用「历史→监督→评估→归因→修订」的闭环。局限也同样清晰（作者在 Limitations 坦承）：监督由 LLM 生成与验证，三个环节共享的偏差可能联合通过验证；生成问题服从历史分布而非用户真实信息需求。

## 二、Curation+Consolidation：情景与关系的互补双记忆

> Long-Term Agent Memory through Complementary Curation and Consolidation，[📄 原文链接](https://arxiv.org/abs/2610.39790)

### 2.1 背景：长程对话记忆的两大表征路线各有盲区

长时程对话 agent 需要跨会话回忆事实、事件与关系。非参数化记忆（non-parametric memory）是主流路线——不训练模型，外挂存储按需检索——但内部又分两派：情景式（episodic）保留事件叙事与时间线，关系式（relational）抽取实体-关系元组支持结构推理。两派此前多为单打独斗：Nemori 做自适应情景蒸馏，Zep 建时序知识图谱，各自的失败模式恰好互补——情景记忆在多跳实体依赖推理上弱（叙事冗长、实体连接隐式），关系记忆在时序与叙事语境上弱（元组紧凑但丢失「在什么语境下说的」）。同时，任何记忆库都随交互单调增长，存储成本、检索开销与噪声同步上升。

### 2.2 定位：一篇「组合式创新但实证扎实」的系统论文

按提取清单的评审预判，这篇是「组合式创新（双记忆+聚类巩固均有先例），但互补性实证扎实、跨 4 骨干泛化」。它的价值不在发明新表征，而在用干净的消融证明「叙事与结构两种记忆假设的交互作用」——这是对「什么让记忆有用」这一基础问题的实证回答。作者自己的表述很准确：「这两种表征反映了对记忆为何有用的根本不同假设：情景记忆保存叙事语境与序列，结构化关系记忆优先紧凑、可查询的关系结构。」

### 2.3 问题定义

系统分三个阶段：离线记忆策展（memory curation，逐会话处理转写）、离线巩固（consolidation，周期性压缩去噪）、在线检索问答。目标是三元优化：QA 准确率、token 效率、记忆库规模——且不牺牲第一个的前提下压后两个。

### 2.4 解法：双库 + HDBSCAN 聚类巩固

**记忆策展**：每个会话结束后跑一次 LLM 策展（会话级而非轮级，摊薄 LLM 调用成本）。情景记忆每条含标题、一句话摘要、细节段落（保留叙事语境与背景）、会话时间戳。关系记忆抽取五元组 (e, r, o, t, c)：实体、关系、对象、时间戳、**源上下文**——第五个字段 c 是设计亮点，记录三元组被抽出时的原文语境（说话者意图、陈述条件、附加细节），弥补结构化抽取不可避免的细节损失；时间戳 t 则解决「关系事实被存储时没有记录何时为真」这一关系记忆的常见失败模式。

**巩固**：用 UMAP 降维（cosine 距离、10 邻居、5 维目标）+ HDBSCAN 密度聚类（Euclidean、Excess of Mass、min_cluster_size=10），把语义相似的记忆聚成对应「演化中概念」的簇，簇内记忆整体喂给 LLM 决定 MERGE（合并冗余/互补）或 DELETE（删除过时/冲突/被取代）。巩固离线运行，每 10–20 个会话触发一次即可。

**检索**：双库独立 top-k 语义检索（text-embedding-3-small 向量），情景库返回 top-k 情节、关系库返回 top-2k 元组（元组更短，同预算下约可检索两倍条目），k=10 之后性能平台化。固定 top-k 避免了查询时额外 LLM 调用。

### 2.5 实验证据

在 LoCoMo（10 段长对话、1,540 QA、平均 24k token/对话）与 LongMemEval-S（500 题、平均 115k token/题）上：

- **主结果**：gpt-4.1-mini 骨干下 LoCoMo LLM Score 0.902（超 Nemori 0.744、Mem0 0.435、Zep 0.369、FullContext 0.913 仅差 1.1 点但省 87% token）；gpt-4o-mini 下 0.835 反超 FullContext 0.790——长上下文加满反而降性能再次被实证。LongMemEval-S 达 0.855，几乎全类别超 FullContext 0.656 与 Nemori 0.746。
- **互补性消融（关键证据）**：单一情景记忆 0.871、单一关系记忆 0.837（gpt-4.1-mini），混合 0.902。增益集中在设计预期的两类问题上：多跳 +2.5–6.3 点（关系元组的实体依赖推理兑现）、时序 +3.4–6.8 点（情景时间线兑现）——双记忆的互补不是均匀的，而是在各自假设擅长的问题类型上兑现。
- **效率**：每题 2,738 token vs FullContext 21,788；巩固压缩记忆库 16.34% 仅损失约 1% 性能（0.902→0.892）；min_cluster_size 敏感性分析显示 mcs∈[5,20] 内性能稳定在 0.892–0.898，mcs=2 时过度合并掉 2.6 点，mcs=2→20 压缩率从 30.9% 单调降到 9.6%、簇数从 2,208 降到 144（LLM 巩固调用省 15 倍）。
- **骨干泛化**：gpt-5.4 与 gpt-4.1-mini 几乎持平（0.906 vs 0.902），开源 Qwen3-8B 也有 0.762——作者据此主张「主要挑战在记忆系统设计而非模型容量」。

### 2.6 根源解释：互补性从哪来

双记忆增益的根源在于两种表征对「什么让记忆有用」的假设覆盖了不同的问题空间：

情景记忆以时间戳叙事保留「事件发生的顺序与语境」，时序问题（先说了什么后改了什么）天然对齐；关系记忆把「人与人、人与事、人与地」的隐式连接显式化为可检索元组，多跳问题需要沿实体依赖链走两步以上，恰是元组的强项。关键细节是五元组里的源上下文字段 c 与时间戳 t——没有 c 的元组是干巴巴的断言（丢失说话者意图），没有 t 的元组无法参与时序判断（不知道何时为真）。作者对关系记忆两大经典失败模式的针对性修补，让关系库不是情景库的退化压缩版，而是真正正交的第二视图。

巩固有效则是因为记忆库的膨胀主要是冗余驱动：同一概念在多个会话被反复表述，HDBSCAN 把它们聚到一起后 LLM 只需做局部合并/删除决策，不需要全局重写——离线、增粒度、低频触发的工程选择保证了巩固的成本可控。

### 2.7 知识反推

- **多表征记忆的价值在问题类型分布上兑现**：如果你的应用多跳/时序问题占比高，双表征（叙事+结构）是高杠杆设计；如果以单跳事实查询为主，单一精心设计的表征可能已够。
- **结构化抽取必须带上下文与时间戳**：五元组的 (t, c) 两字段是被低估的设计——恢复「何时为真」与「在什么语境下说」能把元组从检索命中工具升级为推理可用证据。
- **巩固是离线批处理而非在线服务**：UMAP+HDBSCAN+LLM 局部决策的管线可以每 10–20 会话跑一次，工程上几乎零侵入；mcs∈[5,10] 是压缩-精度的好折中（16–22% 压缩、可忽略损失）。
- **会话级策展摊薄成本**：对比 Mem0/A-Mem 的逐轮 LLM 调用，会话级单次策展把抽取成本从轮数线性降到会话数线性。

### 2.8 通用灵感

这篇的元启示是「**正交假设的双视图好于单视图的精雕细琢**」：与其把一种表征打磨到极致，不如识别任务内在的多重结构（时序的、关系的）并各给一个专职视图。这个思路明显对标人类认知的双系统（情景记忆 vs 语义记忆），但论文的贡献是证明了工程化版本在 token 预算约束下依然成立——且巩固机制说明双视图的成本可以用离线压缩控制。局限：纯文本对话评测（多模态未验证）、策展质量对骨干 LLM 敏感（gpt-4.1-mini→gpt-4o-mini 掉 6.7 点）。

## 三、CALM：冲突感知的生命周期治理

> CALM: Conflict-Aware Lifecycle Memory Governance for Long-Horizon Language Agents，[📄 原文链接](https://arxiv.org/abs/2610.38573)

### 3.1 背景：相关 ≠ 有效 ≠ 可用

长期交互历史会积累一类尴尬的记录：对今天的推理已经过时、对重建过去却不可或缺。用户从西雅图搬到波士顿，「我住在西雅图」这条记录对「我现在住哪」是干扰，对「我搬家前住哪」是必需证据。现有系统处理这个张力的方式都不完整：纯相关性检索把两条都召回（污染当前态推理）；Mem0 式更新直接删旧（丢失历史证据）；Zep 记录双时序但不做查询时裁决。论文开篇一句话点题：「语义相关性、证据落地的有效性、查询特定的适格性是三件不同的事（semantic relevance, evidence-grounded validity, and query-specific eligibility are distinct）」——相关性度量与查询的关联度，有效性是查询无关的持久属性，适格性由查询的时间指向、适用范围与意图共同决定。

### 3.2 定位：保留与使用解耦的治理层

CALM（Conflict-Aware Lifecycle Memory governance）的自我定位是**记忆后端与工作上下文之间的治理层**：不替换底层存储、不修改检索器、不动回答模型，只在「检索之后、入上下文之前」做生命周期治理与查询条件准入。这与 A-TMA（答案时状态解析）等工作的区别被明确写出：CALM 治理的是既有记忆进入工作上下文的资格，不做证据扩展、不做答案侧解析。适配器式的定位让它理论上可以套在任何记忆系统外——虽然实验里实际用的是基准提供的会话记录后端。

### 3.3 问题定义

形式化地，对每条记忆 m_i 区分三个属性：语义相关性 ζ（与查询的关联度）、查询无关有效性 V（基于累积证据的可靠度）、查询条件适格性 g∈{0,1}（是否应进入本次查询的工作上下文）。工作上下文 C_q = {m_i ∈ R_q | g_{q,i} = 1}。三条属性相互独立：相关的记忆可能已被取代，被取代的记忆对历史查询仍然适格。系统要同时优化当前态与历史态两种查询的准确率，并在错误记忆污染下保持鲁棒。

### 3.4 解法：三阶段状态机 + 双门控

**阶段一：证据落地记忆适配**。把异构后端记录（对话片段、抽取事实、摘要）转化为规范记忆单元 m_i = (c_i, E_i, a_i, ρ_i, s_i)：内容、证据集（每条证据含 id/内容/时间戳/溯源/可靠性权重 ν）、属性组（语义类型、时间锚、来源溯源、关联实体、适用范围）、聚合可靠性权重、生命周期状态。证据对齐用确定规则：归一化后完全相同才合并，同实体同属性不同值的记录保持分离——让治理层而非适配层裁决它们是冲突还是不同时间态。可靠性权重按来源粒度固定赋值（如 LoCoMo 的 observation 0.95 > event summary 0.88 > session summary 0.82）。

**阶段二：生命周期治理状态机**。构建生命周期图 G = (M, E_conf, E_dep)，用确定性规则识别冲突与依赖边：偏好反转 0.95、时序位置变更 0.94、约束变更 0.92、任务状态变化 0.90、槽位值更新 0.88、弱对立信号 0.70——强度 ≥0.75 的非弱冲突触发取代（supersession）：新记忆转 ACTIVE，旧记忆转 SUPERSEDED、存储有效性封顶 0.15、保留指向替代者的指针。依赖边（j→i 表示 m_j 是 m_i 的前提）在源被取代时传播失效风险，级联风险 ≥0.70 标记待验证、强依赖（≥0.80）的源被取代则直接转 STALE。状态机含六态：CANDIDATE → ACTIVE（直接用户证据或置信 ≥0.60）→ STABLE（证据数 ≥2 或置信 ≥0.80），旁路 SUPERSEDED / STALE / ARCHIVED。关键设计：**时间流逝本身不触发任何转换**——时间只用于判断适用区间，不做自动衰减。

**阶段三：查询条件门控**。先过共享的硬适格过滤器（当前态查询排除 CANDIDATE/ARCHIVED/STALE/SUPERSEDED 态记录；显式历史查询可放行时间区间匹配的被取代记录且不改其持久状态），幸存者构造四维特征 x = [ζ, V, ψ, 1−R]（相关性、存储有效性、查询-记忆兼容性 ψ——时间/实体/范围/类型四因子均值、查询条件风险 R——冲突/依赖/时间/生命周期四风险的噪声或聚合）。两种门控共用特征与阈值 0.50：CALM-ZS 是四特征等权均值（免训练），CALM 是一隐层 MLP（仅在开发集上用独立构造的适格性监督训练——正例须同时满足支撑答案、条件兼容、不误导三谓词，相关但过时的记忆作为难负例）。被拒记忆留在持久存储中，可服务未来的兼容查询。

### 3.5 实验证据

在 LongMemEval-S（500 题）与 LoCoMo（1,540 非对抗题）上跨 Qwen3-30B-A3B、GPT-4.1-mini、GPT-4o-mini 三骨干：

- **主结果全胜**：LongMemEval-S 总体 79.60 / 83.00 / 78.20，三个骨干全部第一或并列第一（最强基线 EverMemOS 分别 66.40 / 83.00 / 65.40）；LoCoMo 总体 88.70 / 93.51 / 88.70 同样全第一。可学习门控比零样本稳定多 2–3 点。
- **冲突拦截**：错误记忆拦截（EMB）81.30%、有用记忆保留（UMR）72.06%、冲突泄漏（CL）20.00%（CALM-ZS 为 79.32/67.76/21.68）——对比无门控的 0/100/100。
- **错误注入鲁棒性**：向候选集注入 0–50% 主题相关但过时/矛盾/被取代的记忆，CALM 全程最高且 0→50% 只掉 7.0 点，Relevance-Only 掉 11.6、去阶段三变体掉 16.8；50% 注入时 CALM 领先扩大到 9.0 与 15.6 点——污染越重治理越值钱。
- **历史重构（概念性实验）**：对每条更新链配对当前态与历史态查询，CALM 双向准确率同时最高，超最强基线分别 +3.71 与 +9.26 点——历史态领先更多证明「屏蔽 ≠ 删除」：被取代记录保留在库里、按查询时间指向放行，两不耽误。
- **匹配对照**：同候选集同预算下 Temporal-Filter 74.40、Recency-Rerank 75.60、Validity-Rerank 77.20、CALM-ZS 76.60、硬过滤+学习重排 78.40，全部低于完整 CALM 79.60——增益不等于任何单一启发式，来自「硬过滤+有效性排序+阈值准入」的组合。
- **消融**：去阶段一 69.80、去阶段二 75.60、去阶段三 74.00（vs 79.60），三阶段角色互补；组件级去冲突 73.00、去时序 72.60、去有效性 72.40，各掉 4–7 点。
- **开销**：可学习门控带来 +3.0 点准确率，代价是内存 +3.1%、总延迟 12.00→12.84 秒（回答生成仅 +0.05 秒）——门控是廉价操作。紧预算下优势更大：2048 token 预算时领先 CALM-ZS 达 4.8 点。

### 3.6 根源解释：解耦为什么有效

CALM 的增益根源在于把「保留决策」与「使用决策」分离到两个时间尺度：

保留决策（阶段二）是**查询无关的、离线的、证据驱动的**——冲突检测基于实体-属性槽匹配与时序规则，取代判定有明确阈值（0.75），有效性封顶（0.15）防止被取代记录在任何单一评分里翻身。因为不删除，历史证据零损失。

使用决策（阶段三）是**查询条件的、在线的、四维的**——同一份存储有效性 V=0.15 的被取代记录，在当前态查询被硬过滤器直接排除，在历史态查询因时间区间匹配而减免时序与生命周期惩罚、可能通过门控。两个决策点各自处理各自的信息（离线证据 vs 在线查询意图），互不越权。

这解释了为什么所有「在线单一启发式」对照（时效过滤、新近重排、有效性重排）都追不上：它们都在用单一在线评分同时承担两个本应分离的决策。也解释了错误注入实验的形态——注入的记忆主题相关（骗过 ζ）但处于被取代/冲突态（被 V、R 与硬过滤器抓住），污染越重，四维特征里三个维度都在发力。

### 3.7 知识反推

- **相关性排序之后还有一个准入问题**：任何 RAG/记忆系统的检索 top-k 之后、拼上下文之前，都存在「这条证据对这个查询是否适用」的裁决空间——四维特征 [相关性, 有效性, 兼容性, 风险] 是个可直接套用的最小特征集。
- **状态机的阈值可以工程化冷启动**：冲突强度分级（0.70–0.95）+ 取代阈值 0.75 + 有效性封顶 0.15 全是手设常数，零训练版本（CALM-ZS）就能拿到大部分收益（76.60 vs 79.60），说明生命周期治理的主要价值来自规则本身而非学习。
- **硬过滤与软评分是互补的两层**：硬过滤器用状态类型做确定性排除（当前态查询直接排除四种非活跃态），软评分只在幸存者上做细粒度裁决——先粗后细比单一连续评分更稳。
- **时间不做衰减、只做区间匹配**：这一设计与时序知识图谱的双时序（ asserted vs valid time）思想呼应——「何时记录的」与「何时为真」分离，后者才参与适格性判断。
- **难负例造门控监督**：把「语义相关但过时/冲突/错时段」的记忆作为加权 BCE 的难负例，是在线分类器训练的教科书式好实践。

### 3.8 通用灵感

CALM 的元命题是「**治理对象从内容转向状态**」：记忆系统需要的不仅是每条记录的内容正确，更是一套关于记录的元数据管理——有效性区间、生命周期状态、依赖关系——以及在这些元数据上的确定性状态机。这几乎是把数据库管理系统的成熟思想（事务、版本、失效传播）搬进 agent 记忆。局限也来自这里：确定性规则可能漏掉隐式冲突、门控依赖上游检索质量（多跳推理可能误伤有用证据——Qwen 骨干的多跳分数偏低被作者自己指出是冲突抑制与复杂推理证据保留之间的折中）、学得门需要开发集监督。

## 四、MUSE：三级记忆与门控运行时注入

> MUSE: Multi-Level Memory with Selective Runtime Injection for Scientific Coding Agents，[📄 原文链接](https://arxiv.org/abs/2610.38332)

### 4.1 背景：科学编码的经验有层次，教训在执行中方显现

科学编码 agent（把数学模型与研究目标翻译成可执行软件：数值求解器、GPU 内核优化、科学仓库修复）面对的任务有明确的层次结构：全局层面有跨任务共享的科学检查（如半精度输入上浮），问题层面有匹配该题的求解路径（如离散化格式选择），实现层面有具体到接口与更新顺序的局部选择。现有记忆机制没有显式对齐这个层次：Agent KB 分规划与执行两级但面向通用问题求解，AutoSci 区分可复用知识与项目材料但服务完整研究流程。更棘手的是第二个问题：**实现级教训的相关性从任务描述看不出来**——某个历史问题与当前任务问题描述不相似，但它踩过的坑（FP8 原生 cast 编译失败）恰恰是当前这步操作要避开的。任务级检索天然漏掉这类经验，只有执行到具体操作时其相关性才显现。

### 4.2 定位：三级记忆 + 选择性注入的完整闭环

MUSE（Multi-Level Memory with Selective Runtime Injection）的对比表（论文 Table 1）把定位说得很清楚：十个基线里有的有成功失败经验、有的有多级记忆、有的有运行时注入，MUSE 是唯一三者兼备且注入可选择（可跳过）的。它不训练模型（记忆全部通过上下文供给，权重与工具接口不变），求解、记忆构建、门控统一用 ZCode + GLM-5.3-flash，检索用 Qwen3-Embedding-8B。

### 4.3 问题定义

从 N 个冻结的源尝试 τ_i = (q_i, h_i, s_i, e_i)（问题、可见交互历史、最终提交、反馈）中构建三级记忆，目标是在新问题上通过初始化注入与运行时注入复用经验。L0 全局记忆跨任务共享、完整提供给每个 agent；L1 方法级记忆按问题相似度匹配；L2 实现级记忆按当前交互匹配。三级划分的依据是**判断相关性所需的信息层级**：共享检查带适用条件跨任务复现，方法教训连接问题需求与求解策略，实现教训关联局部选择且「其相关性可能随具体操作与工具交互的展开才变得明显」——一个源可以提供有用的实现检查而不指导整体解法，这正是需要超越初始问题匹配做运行时检索的动机。

### 4.4 解法：L0 巩固 + 四路检索 + LLM 门

**记忆构建**：抽取 agent 读每个源尝试产出 L1 教训（实际路线 + 证据落地的正确方法或路线选择教训）与 L2 教训集合（关键实现决策、理由、与结果的关系；显式区分 observed / derived_from_contract / proposed_unverified 三种证据状态）。L0 全局库由巩固 agent 增量构建（add/replace/retire 操作，保留适用条件、公式、地址映射、短代码片段；预算 80,000 token）加全库审查（对照源实现与结果核查、解决冲突）。抽取 prompt 里有大量防幻觉设计：历史 agent 的声明不是事实、通过测试不等于验证了每个局部选择、未测试的修复建议必须标注 proposed。每条教训保留源材料（提交代码 + 评估指标），成功与失败尝试都入库——成功给可复用路线，失败给待检查的坑。

**初始化注入**：完整 L0 文本 + 按问题相似度 Top-5 的 L1 参考（k=5）。

**运行时注入**：在 Write/Bash 等指定工具返回后触发，以当前交互 Δh_t = (a_t, p_t, o_t)（assistant 消息体、工具参数、工具返回）为查询做**四路检索**：assistant 消息体查 L2、工具参数分别查历史提交库 Js 与 L2、工具返回查历史错误库 Je——四路各取最近邻一条，同源合并、排除已注入与已初始化提供的源，至多四条候选进 gate。**LLM 门**（无工具访问）看任务摘要、此前公开轨迹、当前交互与候选记录，判定候选是否支持具体修订或补充检查：选中的话输出选中源 ID 加一条针对性 review note（指出当前哪个操作/假设/结果需要复核、与选中经验的关系、该验证什么——至多 100 词），没有合适候选就返回空选择跳过注入（|A_t| ≤ 1，一次至多注一条）。被门拒绝的源仍可被后续检索命中，注入过的源从后续候选中排除。

### 4.5 实验证据

四个基准：PDEAgent-Bench（PDE 求解器，451 测试题）、KernelBenchX（KBX，内核正确性+加速，122 题）、KernelGenBench-MS（KGB，140 题）、SWE-bench Science（科学仓库修复，84 题）。每基准随机抽约 30% 题做记忆抽取（共享同一批无记忆 rollout），记忆库冻结后评测。十个基线（Vanilla、RAG、ReasoningBank、ReMe、TRAD、AdaMEM、AutoSci-SciMem、EvoScientist、Agent KB、ACE）同求解 agent 同源数据：

- **六指标全胜**：PDE 通过率 92.2%（Vanilla 44.8%，最强基线 EvoScientist 87.8%）；KBX 正确率 79.5% / 加速率 44.3%（ACE 66.4/36.9）；KGB 66.4/24.3（对比 RAG 正确 57.9、ReMe 加速 20.0）；SWE Science 40.5%（ReMe 35.7、Vanilla 29.8）。
- **层级消融（PDE）**：L0 单独 82.7（已超多数基线但低于最强 EvoScientist 87.8）→ +L1 到 89.4（超最强基线）→ +门控 L2 到 92.2——三级各有贡献且方向互补。
- **门控消融（最重证据）**：去掉 LLM 门、改为直接注入最高相似度候选（保留三级记忆与四路检索），KBX 正确率从 79.5 崩到 66.4（−13.1 点）、加速 44.3→37.7，KGB 66.4→62.1、24.3→20.0，SWE 40.5→32.1，PDE 92.2→90.7——**门控「选择 + review 建议」的增值在四个基准一致成立，KBX 上单门就值 13 个点**。
- **跨基准迁移**：KBX 抽取的记忆库用在 KGB 上：完整 MUSE 62.1 正确 / 25.0 加速（Vanilla 44.3/8.6，迁移基线中 ACE 50.0/22.1）——同域跨基准经验复用接近同源水平（66.4/24.3）。迁移消融显示 L1 主要提加速（15.7→23.6）、门控 L2 主要提正确（54.3→62.1）。
- **案例研究**：KGB logaddexp2 任务 L0 提供「半精度输入需上浮到 FP32/FP64」规则使 Vanilla 的编译错误消失（1.048× 加速）；FP8 转换任务 L1 检索到排名第 1/63 的历史源——其有用教训（整数 E4M3 编码路线）与该源失败提交（原生 cast）不同，MUSE 用编码路线通过全部 32 测试（1.380×）而 Vanilla 0/32；KBX 归一化任务中初始问题相似度排 13 名（Top-5 之外）的历史源，在写码后被四路检索召回、门选中其两遍方差实现，修订后通过且 1.884× 加速。

### 4.6 根源解释：为什么门控值 13 个点

MUSE 的增益根源集中在「检索与注入之间的语义鸿沟」上：

运行时四路检索用的是**表层相似度**——当前操作与历史实现的表面匹配。但「操作相似」不等于「经验适用」：历史源可能操作相似却依赖不同的输入布局、数值假设或接口要求。门控看到的额外信息——目标任务的完整需求与至今的执行历史——恰好是检索查询（只有当前交互三元组）缺失的判断依据。更关键的是门控输出不只是选择，还有 **review note 这个中介表征**：它把历史经验转译成「针对当前这一步该检查什么」的具体建议，把「注入一条经验」变成「注入一次定向复核」。KBX 上 13.1 点的差距说明：错误的注入（相似但不适用的经验）不只是无效，是主动有害——它会把 agent 引向错误的实现路线；门控的跳过选项因此和选择选项同样重要。

三级结构的贡献则是把「经验的适用粒度」显式化：L0 的规则几乎无条件适用（每个任务都收到完整库），L1 的方法需问题匹配（相似度 Top-5），L2 的实现细节需操作匹配（运行时检索）——粒度越细，匹配信号越局部、时机越靠后。层级消融的阶梯（82.7→89.4→92.2）证明三个粒度各自命中了不同层面的需求。

### 4.7 知识反推

- **查询设计要与经验的粒度对齐**：任务级查询配方法级经验、交互级查询（消息体/工具参数/工具返回分路）配实现级经验——四路检索的实质是用操作的不同侧面（意图、实现、结果）分别索引历史。
- **错误库是一等公民**：历史错误单独建索引（Je）、由工具返回触发查询——失败的尝试比成功的更常在运行时被需要（报错时刻正是最相关的时刻）。
- **门控输出的 review note 比经验本身更接近可用知识**：把检索命中转译为「当前具体该复核什么」的行动指令，是上下文注入的增值环节——这个模式可迁移到任何运行时指导系统（lint、code review、测试建议）。
- **证据状态标注防记忆幻觉**：observed / derived / proposed 三级标注写进抽取与巩固 prompt，防止「未测试的修复建议」被当成「已验证的成功路线」复用——记忆库自身的可信度管理。
- **同域经验可跨任务家族迁移**：KBX→KGB 迁移只掉 4.3 点正确率，说明只要领域（GPU 内核优化）一致，三级结构抽出的经验有相当好的泛化性。

### 4.8 通用灵感

MUSE 的元启示是「**注入时机与注入内容同等重要**」：同一个经验库，无差别注入（相似度直注）与门控注入相差 13 个点——上下文不是越多越好，而是越切题越好。加上 CALM 的结论（相关性 ≠ 适格性），两篇从不同方向收敛到同一命题：**记忆系统的最后一步不是检索而是裁决**。局限：全部实验单骨干（GLM-5.3-flash）、冻结记忆库不考察持续更新（作者明确把记忆巩固与冲突消解列为未来工作——恰好是 CALM 与第二篇的主场）、四基准集中在科学计算域。

## 五、四篇合评：记忆生命周期的治理全景

把四篇放回一条时间轴上，一个完整的治理链条浮现出来：

### 5.1 监督从哪来：MemSteer 的答案——从数据反向生成

任何治理都需要评估标准。MemSteer 证明了监督可以不从人工来、不从任务成败信号来，而从系统所治理的原始数据反向构造——前提是用「答案计划 + 程序化校验 + 盲答恢复」把合成监督的质量推到与人工标注打平（ATM 四指标略超、RHELM 差 0.1–0.8 点）。这为整个治理链条提供了燃料：没有可扩展的监督，后续所有环节的优化都只能靠人工评估兜底。它同时证明监督要**带证据**——证据让失败可归因到存储/检索/回答某一层，这是分层治理的前提。

### 5.2 怎么存：Curation+Consolidation 的答案——正交双视图 + 离线压缩

存储环节要同时回答「用什么表征」与「如何不膨胀」。双记忆的消融数据（混合 0.902 vs 单情景 0.871 / 单关系 0.837，增益集中在多跳 +2.5–6.3 与时序 +3.4–6.8）给出了表征层面的定量答案：不同问题类型需要不同的记忆假设，双视图不是冗余而是分工。巩固环节（16.34% 压缩、~1% 损失）则证明膨胀可以用离线批处理控制——UMAP+HDBSCAN 聚类把「哪些记忆在讲同一件事」变成可计算问题，LLM 只做簇内局部的 merge/delete 决策。值得注意它与 MemSteer 的一个呼应：MemSteer 的图引导素材准备同样是「先聚类相关记录再生成监督」——相关性聚类是存储与监督两个环节共享的基础设施。

### 5.3 怎么冲突治理：CALM 的答案——状态与准入分离

巩固解决冗余，但冲突（同一事实的不同时间态、被取代的断言）不能靠合并或删除解决——删了就丢历史，留了就污染现在。CALM 的解法是引入时间上分离的两级决策：离线的生命周期状态机（冲突检测、取代判定、有效性封顶、依赖失效传播）管理记录的持久状态，在线的四维门控按查询意图裁决准入。EMB 81.30% / UMR 72.06% 的组合说明拦截与保留可以兼得；历史重构实验双向领先（当前态 +3.71、历史态 +9.26）则是对「保留 ≠ 使用」最直接的验证。CALM 也暴露了治理的代价：Qwen 骨干多跳分数偏低提示强冲突抑制可能误伤复杂推理需要的证据——治理强度存在 tuning 空间。

### 5.4 何时注入：MUSE 的答案——粒度对齐的门控

治理的最后一环发生在记忆即将进入上下文的时刻。MUSE 的门控消融（去门 KBX −13.1 点）与 CALM 的匹配对照（Validity-Rerank 77.20 vs CALM 79.60）从两个域给出同向证据：**检索排序之后的裁决层有独立且可观的增值**。两者的门控设计也形成有趣的对照——CALM 的门是轻量 MLP 打四维特征（便宜、可批量），MUSE 的门是 LLM 看完整上下文生成选择+review note（贵、带转译）——前者适合每查询要过几百条候选的记忆 QA 场景，后者适合每次注入成本高、注入错误代价大的执行中场景。门控的形态应与注入的粒度匹配。

### 5.5 四个环节的正交性与组合空间

四篇各自聚焦一个环节、互不覆盖，这既是正交性的证据也是组合的机会：

- MemSteer 的合成监督可以驱动 CALM 门控的训练（论文里 CALM 的适格性监督来自开发集标注——正是 MemSteer 想消灭的人工环节）；
- Curation+Consolidation 的双库可以作为 CALM 的记忆后端（CALM 明确说自己 backend-agnostic），其巩固环节的 merge/delete 决策恰好需要 CALM 的冲突判定规则；
- MUSE 的三级记忆在运行中持续积累，其 L0 巩固（add/replace/retire）本质上就是一个简化版生命周期状态机——作者在 Limitations 里明确把「记忆巩固、冲突消解、过时经验退役」列为未来工作，指向的就是 CALM 的主场；
- MemSteer 的失败分层诊断（存储/检索/回答）与 CALM 的证据覆盖诊断（检索/门控/打包三阶段命中率）是同一思想在不同环节的实例化。

换言之，一篇理想的「完整系统」应该是：MemSteer 式监督驱动设计优化 → 双表征存储 + 离线巩固 → 生命周期状态机 + 查询条件门控 → 粒度对齐的运行时注入与转译。四篇论文各自验证了链条上的一段，段与段之间的接口（证据格式、状态元数据、特征定义）已经高度兼容。

### 5.6 共同的方法论信号

跳过细节，四篇在方法论上有三个收敛点：

**证据落地（evidence-grounded）成为通用要求**。MemSteer 的 QA 必须带源 span 引用，CALM 的记忆单元必须带证据集与溯源，MUSE 的教训必须区分 observed/derived/proposed 且保留源材料——三条线索都指向「记忆的可信度来自可追溯性」，无来源的记忆在治理框架里等于二等公民。

**确定性规则优先于学习组件**。MemSteer 的计划程序化校验、CALM 的冲突规则与状态转换阈值（0.75/0.15/0.65）、MUSE 的四路检索路由，核心机制全是确定性规则；学习组件（MemSteer 的设计提案者、CALM 的 MLP 门、MUSE 的 LLM 门）都在规则的骨架上做局部增强。这与其他 agent 领域「先规则后学习」的工程共识一致。

**免训练是共同约束**。四篇都不更新模型权重（MemSteer 明确 without updating model parameters，CALM 只训一个 MLP 门，MUSE 全上下文供给）——治理被视为模型之外的系统层问题，这个定位选择使方法可以即插即用于任意骨干，也决定了治理的上限受骨干能力约束（第二篇的骨干敏感性实验是反例证据）。

## 六、结语

这四篇论文读下来，最深的印象是 Agent 记忆研究的问题结构正在数据库化：监督生成像数据质量管理，双记忆存储像多模态索引，生命周期治理像事务与版本控制，运行时注入像查询优化器的准入控制。表征研究回答「记忆长什么样」，治理研究回答「记忆如何被信任、被维护、被恰当地使用」——前者在 2024–2025 年被充分探索后，后者正在成为新的主战场。

四个环节里，个人判断成熟度排序大概是：存储表征（第二篇，工程最完整、直接可用）> 运行时准入（CALM 与 MUSE，概念清晰且消融扎实）> 冲突治理（CALM 的规则系统有效但阈值工程味重、泛化待验）> 监督生成（MemSteer 闭环惊艳但依赖 LLM 自我验证的偏差共享风险仍在）。而四篇留下的最大空白恰好重合：持续演化环境下的记忆治理——MUSE 冻结库、CALM 依赖基准提供的记录、MemSteer 优化到收敛即停，「记忆系统在交互中边用边治」的在线治理范式还没有一篇完整覆盖。

对工程实践者，四篇各自有可直接搬走的东西：MemSteer 的「计划-生成分离 + 盲答验证」合成监督配方、第二篇的五元组 (e,r,o,t,c) 存储模式与 UMAP+HDBSCAN 巩固管线、CALM 的四维准入特征集与状态机阈值、MUSE 的四路检索路由与 review note 注入模板。对研究者，四篇共同指向的开放问题是在线治理：冲突在流式到达时如何检测、监督在分布漂移下如何再生、门控在新领域如何免开发集适配。记忆治理的故事才刚开场。
