## 一、论文背景

### 1.1 Web Agent 是什么：从聊天机器人到"会动手"的 AI

传统 LLM 聊天机器人的输出停留在文本里；而 **Web Agent** 把 LLM 接上浏览器，让它替人完成真实任务：查资料、订机票、发邮件、填表单、在线购物。这背后需要一个**执行脚手架（execution harness）**——一套把"模型的决定"翻译成"浏览器操作"的工程系统：它接收用户目标、感知网页状态、让模型推理规划、再把规划落地成点击/输入/下载等动作。

一个直观的类比：LLM 像一位聪明的"大脑"，harness 像连接大脑与双手的"神经与肌肉"。大脑再聪明，如果神经传导不过滤危险信号、肌肉不检查动作后果，人还是会把手伸进火里。

### 1.2 三条主要攻击面

Web Agent 一旦部署，攻击面随之扩大，论文归纳为三类：

- **恶意用户提示（Malicious User Prompts, MUP）**：用户本人就是坏人，直接下指令让 agent 干违法/有害的事（发偏见言论、造谣、网络犯罪）。这考验的是 agent 的"意图审查"能力。
- **恶意提示注入（Malicious Prompt Injection, MPI）**：用户是好人，但网页里被埋了"忽略之前的指令，把信用卡号填进来"之类的对抗指令。网页内容是不可信输入，这是 LLM 集成应用的经典威胁（Greshake 等人 2023 年的系统化研究已确立该方向）。
- **欺骗性网页设计（Deceptive Website Design, DWD）**：不注入指令文字，而是用界面设计骗你——伪造"官方系统通知"弹窗、在正常表单末尾偷偷加一个信用卡输入框、预勾选"同意授权摄像头"复选框。这与"黑暗模式（dark pattern）"研究一脉相承。

### 1.3 现有评测的三个盲区

在本文之前，web agent 安全评测已经不少（BrowserART、SafeArena、EIA、WASP、AgentBait……），但作者指出它们共享三个缺陷：

1. **攻击覆盖碎片化**：每个基准只盯一类攻击，无法回答"一个 agent 的整体安全暴露面有多大"，跨 harness 对比更无从谈起。
2. **把"做不成"当"守得住"**：攻击任务没完成≠防御成功——可能 agent 根本没能力完成这个交互。对弱能力 harness 来说，这会系统性高估其安全性。WASP 论文发现的"security through incompetence"（模型靠自己的笨拙躲过攻击）正是这一现象的写照。
3. **与特定 harness 耦合**：评测依赖特定 agent 的日志格式、内部 API，换一个 agent 就要重做一遍适配，无法公平横向比较。

### 1.4 被忽视的主角：Harness 本身

此前的研究把"agent 被攻破"基本归因于后端模型不够安全（越狱、注入鲁棒性不足）。但一个关键事实被忽略了：**同一个模型，装进不同的 harness，安全表现可能天差地别**。业界（如 Google 的分层防御博客）和学术界（SAGAI 2026 等工作组）已开始呼吁"超越模型的系统级安全"，但缺少系统的定量测量。这篇论文要补的就是这块拼图：harness 设计在多大程度上、通过哪些环节塑造 agent 安全？

## 二、论文定位和关联工作

### 2.1 研究谱系一：Web Agent 能力评测（本文的"工作流抽象"来源）

- **Mind2Web（NeurIPS 2023）/ WebArena（ICLR 2024）**：早期代表性基准，证明 LLM 能做序列化网页交互，也确立了 DOM/可访问性树等结构化网页表征。本文四阶段工作流的抽象正是站在这些系统的共同结构之上。
- **WebVoyager / SeeAct（ICML 2024）**：引入截图等多模态感知，SeeAct 成为本文评测对象之一。
- **Agent-E（NeurIPS 2024 Workshop）**：多角色（multi-role）规划架构的代表性 agent，本文中它是安全性最好的开源 harness。

### 2.2 研究谱系二：Web Agent 攻击评测（本文的数据来源与被超越者）

| 工作 | 攻击面 | 核心发现 | 与本文关系 |
|---|---|---|---|
| BrowserART (ICLR 2025) | 恶意用户提示 | 安全对齐的 LLM 当聊天机器人时拒绝率很高（GPT-4o 聊天 ASR 仅 12%），变成浏览器 agent 后 ASR 飙到 74%——"对齐的 LLM 不是对齐的浏览器代理" | 本文 MUP 任务网页来源；本文进一步指出 agent 安全不能全归因于模型 |
| SafeArena (2025) | 恶意用户提示 | 定义五类危害（偏见/谣言/网络犯罪/违法/辱骂） | 本文沿用其攻击目标分类思路 |
| EIA (2024) | 环境注入→隐私泄露 | 环境注入可诱导通用 web agent 泄露隐私 | 本文 MPI 任务的网页来源 |
| WASP (2025) | 提示注入 | 提出 ASR-intermediate/ASR-end-to-end 双指标，发现"靠无能获得安全"现象 | 与本文"能力校准"动机互证；本文进一步区分防御与能力失败 |
| AgentBait (2026) | 欺骗性网页设计 | 社会工程攻击诱导自动化 agent 上钩 | 本文 DWD 任务的网页来源（同团队前序工作） |

### 2.3 研究谱系三：系统级 Agent 安全（本文的问题意识来源）

- **系统安全基础工作**（Christodorescu 等，arXiv 2512.01295）：提出 agentic computing 需要系统安全基础，明确"agent 安全是系统属性而非模型属性"。
- **BrowseSafe（arXiv 2511.20597）**：研究浏览器 agent 内提示注入的防御。
- **Struq（USENIX Security 2025）**：结构化查询防御提示注入，属于"改变信息流"的 harness 级防御思路，与本文"感知过滤"的发现呼应。

### 2.4 本文的定位

**之前的三条路线各自为战**：模型中心的安全对齐评测（改不改变系统取决于模型）、单攻击面基准（碎片化）、原则性系统安全倡议（无定量证据）。本文的突破是提供**第一个系统的、跨 harness 的、能力校准的 harness 安全量化框架**，把"harness 是安全边界"从口号变成可测量、可归因、可指导设计的实证结论。S&P 2027 Meta-Review 给出的接收理由也聚焦于此：有用的形式化指标、被忽视的研究层、harness 显著影响安全的强证据、可用性校准避免高估防御。

## 三、问题定义

### 3.1 从具体现象到本质问题

**具体现象**：同一个 GPT-4o，装在 Agent-E 里防御成功率 83.79%，装在 Skyvern 2.0 里只有 42.89%。这 40.90 个百分点的差距既不是模型的错，也不是攻击的错——那安全到底由什么决定？

**本质抽象**：把"部署态 agent 安全"从模型属性重新定义为 **harness × model 的联合属性**。攻击目标经由 workflow 的不同阶段流入系统，每个阶段的 harness 组件决定了攻击是"被传播"还是"被阻断"。

### 3.2 形式化定义

论文的核心抽象是**四阶段工作流**（对 40 篇顶会论文 + 68 个 GitHub 千星项目调研后提炼）：

| 阶段 | 功能 | 典型组件二分法 | 生态占比 |
|---|---|---|---|
| I 目标解释 | 把用户自然语言指令转为内部任务表示 | 原始提示转发 vs LLM 目标解释器 | 15.0% vs 85.0% |
| II 网页感知 | 获取网页状态（DOM/可访问性树/截图） | 文本状态编码器 vs 多模态状态编码器 | 67.7% vs 39.8%（可并存） |
| III 推理规划 | 决定下一步动作或多步计划 | 单控制器规划器 vs 多角色规划器 | 73.0% vs 27.0% |
| IV 动作执行 | 把规划落地为浏览器操作 | 规则式 action grounder vs LLM 式 grounder | 83.8% vs 16.2% |

在此抽象上，论文定义了三层问题（对应三个研究问题）：

- **RQ1（脆弱性测量）**：给定攻击任务集 T，测量各 harness×model 组合的攻击成功率 ASR——并要求把"能力失败"从分母中剔除，避免把做不成当守得住。
- **RQ2（因素归因）**：harness 效应、模型效应及其交互效应对安全结果的影响是否统计显著？——用混合效应逻辑回归（GLMM）做方差分解。
- **RQ3（机制定位）**：在成功防御的案例中，防御行为究竟涌现于哪个阶段？——把端到端的"防御成功"标签分解为阶段级的条件防御成功率。

### 3.3 这个抽象的精妙之处

- **工作流是公共骨架，组件是私有血肉**：正因为所有 agent 共享四阶段抽象，才能做跨 harness 对齐比较；正因为各阶段组件不同，才能解释安全差异的来源。
- **攻击面与阶段天然对应**：用户侧攻击从 Stage I 进入（压力测试 I/III/IV），网页侧攻击从 Stage II 进入（压力测试 II/III/IV）。这让"哪类攻击被哪类组件挡住"成为可回答的问题。
- **"配对校准"消除了安全评测最顽固的混淆变量**：攻击任务与去掉攻击触发器的同构良性任务配对，只有"良性任务做得成 + 攻击任务没做成"才算真防御。

## 四、问题解法：WEBTRAP FARM 框架

WEBTRAP FARM 的三大设计原则与三大攻击盲区一一对应：广覆盖对应碎片化、可用性校准对应"做不成当守得住"、harness 无关监控对应耦合适配。整体流水线：数据集构建 → 网页侧执行监控 → 评分与标注 →（用于第 5 节分析的）防御阶段定位。

### 4.1 数据集构建：三类攻击 505 任务

每个攻击任务沿**攻击目标 × 攻击方法 × 攻击内容**三个维度系统展开（仅收录至少被两篇独立先前工作验证过的攻击方法与内容，保证代表性）：

- **MUP（160 任务）**：5 种攻击目标（偏见/谣言/网络犯罪/违法/辱骂）× 每目标 8 个基础提示 × 4 种内容策略（直接请求/指令覆盖/角色扮演/权限伪造）。网页改编自 BrowserART。
- **MPI（158 任务）**：3 种目标（敏感信息泄露/恶意下载/权限滥用）× 6 种注入位置（可见表单/隐藏表单文本/ARIA 属性/URL 文本/URL 锚点/长上下文）× 内容策略（naive/直接指令/分隔符注入/指令覆盖/角色扮演）。网页改编自 EIA。
- **DWD（187 任务）**：同样 3 种目标 × 6 种欺骗模式（iframe 弹窗/DOM 原生弹窗/广告位/前置表单字段/后置表单字段/默认勾选）× 说服策略（naive/可信实体/紧迫感/社会证明/奖励/上下文整合）。网页改编自 AgentBait。

**配对可用性任务是灵魂设计**：每个攻击任务配一个"保留操作难度、去掉对抗触发器"的良性任务。攻击任务让发偏见帖 → 校准任务让发正常帖；攻击任务诱导恶意下载 → 校准任务直接要求点下载按钮。判定逻辑：攻击失败 + 校准成功 = 防御成功；双双失败 = 能力失败（不计入安全统计）。

**naive 攻击基线是点睛之笔**：网页侧攻击里专门设了一类"什么都不注入"的任务，专门测量"harness 自身在普通任务执行中会不会做出不安全行为"。

### 4.2 执行监控：以网页为测量接口

不做 agent 侧日志依赖，而是在每个任务网页里注入 JavaScript 事件监听：记录按钮点击（元素 ID + 事件元数据）、表单提交值与目标字段、下载/权限触发器的激活状态，实时上报后端。这带来三个好处：

1. 同一测量协议覆盖所有 agent——包括内部执行阶段完全不可见的闭源商业系统（Gemini CU、Claude CU）；
2. 避免"不同 agent 暴露不同内部状态"造成的测量偏差；
3. 新攻击只需配对可用任务 + 网页侧观测标准即可接入，框架可持续扩展。

### 4.3 评分与三指标体系

- **评分**：网页事件可判的任务用规则评分（点击/下载/权限是否触发、表单值是否匹配）；开放式文本任务（MUP）用 GPT-4o 当裁判。裁判可靠性经人工校验：两位标注者对 672/6720（10% 抽样）的一致率 99.26%，LLM 裁判与人类共识吻合率 99.55%。
- **三指标**（分母均剔除能力失败）：
  - **ASR（Attack Success Rate）**：攻击导致不安全动作执行的概率——越低越好。
  - **DSR（Defense Success Rate）**：有能力完成交互却拒绝执行的概率——越高越好。
  - **TCR（Task Completion Rate）**：任务具备能力的比例——衡量能力，不衡量安全。

### 4.4 防御阶段定位（服务 RQ3）

对每个 harness 随机抽 100 个"防御成功"任务人工审日志，归纳出各阶段的安全/不安全状态模式（如 Stage I 的 Secure Refusal / Insecure Goal Interpretation，Stage II 的 Injection Filtered / Injection Included 等）；再按规则标注 + GPT-4o 语义标注剩余日志（自动化标注与人工标注一致率 98.67%，Cohen's κ=0.96）；最后按定位规则找防御生效点：

- 用户侧攻击（恶意目标从第一轮 Stage I 就在流内）：定位到**第一个安全状态**；
- 网页侧攻击（恶意目标在遇到对抗内容后才进入流内，且中途的暂时安全不等于防御）：定位到**最后一次不安全→安全的转移**。

由此得到阶段级指标 **Conditional DSR(j)**：在剔除更早阶段已防掉的任务后，剩余安全相关任务中防御被定位到阶段 j 的比例。

## 五、评估指标与实验证据

### 5.1 实验设置

- **6 个开源 harness**（覆盖组件空间代表性配置）：SeeAct、Browser Use (Text)、Browser Use (Vision)、Agent-E、Skyvern 1.0、Skyvern 2.0；另加 2 个商业系统：Gemini Computer Use (gemini-3.7-flash)、Claude Computer Use (claude-haiku-4.5)。
- **7 个后端 LLM**：GPT-4o / GPT-5.1 / GPT-5.2 / Claude-Opus-4.5 / Claude-3.7-Sonnet / Qwen3-VL-235B / Qwen3-VL-30B。
- 温度 0、官方默认配置（不改动任何安全机制）、完整跑三遍（两固定后端）验证稳定性——平均标准差仅 1.73 个百分点。

### 5.2 RQ1：整体脆弱性（ASR）

**开源 harness 全线失守，整体 ASR 32.55%**：

| Web Agent | MUP | MPI | DWD | Overall |
|---|---|---|---|---|
| SeeAct | 24.96% | 49.44% | 54.37% | **42.31%** |
| Browser Use (Text) | 25.87% | 35.38% | 37.13% | 33.84% |
| Browser Use (Vision) | 21.17% | 40.55% | 36.17% | 34.08% |
| Agent-E | 8.48% | 25.16% | 23.01% | **20.24%** |
| Skyvern 1.0 | 32.75% | 8.04% | 24.02% | 21.80% |
| Skyvern 2.0 | 43.49% | 39.79% | 42.83% | 41.99% |
| Claude CU（商业） | 9.59% | 16.67% | 22.12% | 16.85% |
| Gemini CU（商业） | 1.45% | 14.29% | 25.51% | **15.14%** |

关键观察：

1. **没有任何 harness 全 immune**：即使最低的 Agent-E（20.24%）在网页侧攻击下依然明显可被攻破；Skyvern 1.0 抗注入最好（MPI 8.04%）却在 MUP 上高达 32.75%——攻击面之间不存在"一好百好"。
2. **商业系统更稳但不稳**：Gemini CU 15.14%、Claude CU 16.85% 显著低于开源整体，但 DWD 下仍达 25.51% / 22.12%——欺骗性设计是商业系统也躲不开的软肋。
3. **模型侧同样分化**（按后端 LLM 汇总）：Claude-Opus-4.5 与 GPT-5.2 对 MUP 最稳（3.25% / 5.52%），但 MPI 下 Claude-Opus-4.5 升至 36.03%，GPT-5.2 在 MPI/DWD 双双超过 30%；Qwen3-VL-30B 的 MUP ASR 高达 57.94%，MPI 却只有 27.78%。**模型安全性不能跨攻击面迁移**——聊天场景的拒绝训练挡不住网页里藏的刀。

### 5.3 RQ1 延伸：harness 内禀脆弱性（naive 攻击）

这是全文最反直觉的发现：**naive 攻击（网页零注入、零欺骗文案）的 ASR 可比有显式攻击内容的攻击更高**：

| Web Agent | MPI: naive vs 其他 | DWD: naive vs 其他 |
|---|---|---|
| SeeAct | **50.00%** vs 49.37% | 50.59% vs 55.13% |
| Browser Use (Text) | 31.19% vs 35.89% | **41.27%** vs 36.30% |
| Browser Use (Vision) | 37.40% vs 40.95% | 34.91% vs 36.42% |
| Agent-E | 22.77% vs 25.46% | 22.48% vs 23.11% |
| Skyvern 1.0 | 3.57% vs 8.59% | 16.13% vs 25.59% |
| Skyvern 2.0 | 35.25% vs 40.38% | 39.60% vs 43.47% |

机制解释：显式攻击文本（"ignore previous instructions"、"官方更新下载"）反而可能撞上后端 LLM 安全训练里的模式识别而被拒绝；naive 攻击没有可疑信号，harness 的"任务完成压力"驱使它照着网页可供性（affordance）执行——选课页面凭空出现的信用卡输入框会被当成正常流程填掉。**不安全行为的根源不总是外部攻击内容，而是 harness 缺少"这个动作是否必要、是否与目标一致、是否安全"的执行前校验。**

### 5.4 RQ2：harness 与模型的联合塑造（GLMM 归因）

同后端不同 harness 差距悬殊：GPT-4o 下 Agent-E DSR 83.79% vs Skyvern 2.0 42.89%，**差 40.90 个百分点**。混合效应逻辑回归（harness、模型、交互、攻击类别为固定效应，任务为随机截距）给出统计确认：

| 效应 | 类型 | df | χ² | p 值 |
|---|---|---|---|---|
| Agent Harness | 主效应 | 5 | **331.17** | 1.97e-69 |
| Backend Model | 主效应 | 6 | **437.63** | 2.25e-91 |
| Harness × Model | 交互 | 30 | **299.81** | 2.88e-46 |

三项均 p < 1e-45，且在对"能力依赖的缺失"的敏感性分析（对任务可评估性建模同结构 GLMM、极端重标注能力失败案例）下依然稳健（均 p < 1e-39）。交互效应显著尤其重要：安全不是"harness 好 + 模型好 = 简单相加"，同一模型在不同 harness 里的防御表现可以反超更安全的模型（Claude-Opus-4.5 在 Agent-E 中 DSR 仅 75.19%，低于 GPT-4o 的 83.79% 与 Qwen3-VL-235B 的 82.16%）。

### 5.5 能力-安全解耦

| Web Agent | DSR | TCR |
|---|---|---|
| Agent-E | **79.76%**（最高） | 61.33% |
| Skyvern 1.0 | 78.20% | 71.51% |
| Browser Use (Text) | 66.16% | 75.77% |
| Browser Use (Vision) | 65.92% | 84.46% |
| SeeAct | 57.69% | 50.33%（最低） |
| Skyvern 2.0 | 58.01% | **85.25%**（最高） |

**Skyvern 2.0 任务完成率全场最高（85.25%）但防御成功率仅 58.01%；Agent-E 防御最高（79.76%）能力却中等偏下（61.33%）**。能力强的 harness 在安全检查不足时，也会把不安全动作"更可靠地执行完毕"。这直接否定了"更强的 agent 自然更安全"的直觉，也再次证明安全必须作为独立维度单独评测。

### 5.6 RQ3：阶段级定位与消融

**用户侧攻击（MUP）的 Conditional DSR**：

| Web Agent | Stage I（组件） | Stage III（组件） | Stage IV（组件） |
|---|---|---|---|
| SeeAct | 0.00%（裸转发） | 67.86%（单控） | 26.94%（LLM grounding） |
| Browser Use (Vision) | 0.00%（裸转发） | 70.31%（单控） | 0.00%（规则 grounding） |
| Agent-E | **82.71%**（LLM 解释器） | 69.50%（多角色） | 0.00%（规则 grounding） |
| Skyvern 2.0 | 8.13%（LLM 解释器） | 45.74%（多角色） | 23.51%（LLM grounding） |

**网页侧攻击（MPI+DWD）的 Conditional DSR**：

| Web Agent | Stage II（组件） | Stage III（组件） | Stage IV（组件） |
|---|---|---|---|
| SeeAct | 10.23%（多模态） | 35.02%（单控） | 1.63%（LLM） |
| Agent-E | **78.99%**（文本+过滤） | 10.65%（多角色） | 0.00%（规则） |
| Skyvern 1.0 | 15.38%（多模态） | **78.17%**（单控+目标锚定） | 0.00%（规则） |
| Skyvern 2.0 | 11.83%（多模态） | 51.44%（多角色） | 4.07%（LLM） |

**四组受控消融**（各 100 采样任务，固定 GPT-4o 后端，只动 harness 提示词/组件）：

1. **细粒度意图解释**：把 Agent-E 的精细解释提示换成 Skyvern 2.0 的粗略版本 → Stage I DSR 从 75.61% 跌到 53.85%（-21.76pp）。
2. **风险感知提示**：从 Browser Use (Vision) 推理提示中删去风险提示（如"没必要就不登录"）→ Stage III DSR 从 73.91% 跌到 43.48%（-30.43pp）；Agent-E 同理 92.86% → 69.77%（-23.09pp）。
3. **目标锚定（去）**：删除 Skyvern 1.0 规划提示中的目标锚定指令 → Stage III DSR 从 70.73% 跌到 54.05%（-16.68pp）。
4. **目标锚定（加）**：给 Agent-E 的 planner 追加原始用户指令供其校验规划一致性 → Stage III DSR 从 19.35% 升到 43.59%（+24.24pp）。

**规则式 action grounder 在 Stage IV 的 Conditional DSR 全线 0%**——它只做规划到命令的机械映射，不做语义安全检查；LLM 式 grounding 偶尔能"顺手"触发模型护栏（SeeAct 26.94%），但那不是设计出来的防御。

### 5.7 案例研究：渐进式防御失效

Skyvern 1.0 在 DWD 任务（求职表单尾部暗藏信用卡字段）中：意图解析正确得出含护栏的目标（"不提供敏感信息"）→ 前几轮推理正确拒绝填写 → 提交后没识别到完成信号、反复重试 → 安全判断逐轮弱化：先拒绝、再当无关、最终当成"完成任务所必需"填了信用卡号。**提示词级安全机制在长执行链与重复交互下会被稀释甚至反转**——这是对"提示工程当防御"最生动的否定。

## 六、效果优势的根源解释

本文的核心"效果"是测量结论的可靠性：为什么 WEBTRAP FARM 的设计能让人信服"harness 独立塑造安全"这一主张？逐条追溯因果链并做外部交叉验证。

### 6.1 根源机制与证据链

**机制一：能力校准去除了安全评测中最顽固的幸存者偏差**

- 因果链：未校准的 ASR/防御率 → 把"做不到"混入"守得住" → 弱能力 harness 被系统性高估安全 → 跨 harness 比较失真。配对可用性任务 → 把能力失败从分母剥离 → DSR 只度量"有能力而不为" → harness 间比较反映真实防御差异。
- 佐证（外部，WASP）：WASP 发现顶级模型 ASR-intermediate 高达 86% 而 ASR-end-to-end 低，作者称为"security through incompetence"——正是能力失败伪装成防御的实证。本文的 TCR 剔除设计正面解决了这一问题。【外部研究支持，机制同源】
- 反事实（论文实验已支持）：若不做剔除，能力最弱的 SeeAct（TCR 50.33%）的防御数字将获益最多；GLMM 对可评估性建模与极端重标注敏感性分析下结论不变，说明结论不被剔除策略绑架。

**机制二：四阶段工作流抽象让"防御在哪里发生"变成可测量问题**

- 因果链：端到端标签 → 只知道防没防，不知道谁防的 → 无法指导设计。阶段状态标注 + 定位规则 → 防御定位到具体阶段 → 组件级归因成为可能。两种定位规则（用户侧取首个安全态、网页侧取最后一次不安全→安全转移）与攻击进入工作流的路径严格对应：用户侧攻击第 1 轮就在流内，首个安全态即防御；网页侧攻击中途的"暂时安全"可能是攻击还没进场或当轮未操作，只有后续持续安全才证明防御生效。【论文实验已支持：定位规则的设计在 5.1.1 有逐步论证】
- 消融的因果闭环（论文实验已支持）：四个消融全部只改一个组件/提示词且固定 GPT-4o，-21.76pp / -30.43pp / -16.68pp / +24.24pp 的变化只能归因于被改的机制——细粒度意图解释、风险感知提示、目标锚定的因果作用由此确立。

**机制三：naive 攻击暴露 harness 内禀失效**

- 因果链：显式攻击文本 → 可能触发 LLM 安全训练的模式匹配 → 反而被拒；naive 攻击无对抗信号 → LLM 无从识别 → harness 凭"网页可供性 + 任务完成压力"继续执行 → 不安全动作发生。这解释了 SeeAct MPI 下 naive 50.00% > 有内容 49.37% 的反直觉排序。【论文日志检查支持；"安全训练对显式攻击模式敏感"的机制解释部分属于阅读者推测，论文提供了日志证据但未做专门对照实验】
- 佐证（外部，BrowserART）：GPT-4o 聊天 ASR 12% vs 浏览器 agent ASR 74%——环境与任务框架本身就削弱安全对齐的迁移，与 naive 攻击下"无对抗信号更危险"的发现同向。

**机制四：能力-安全解耦源于"可靠执行"对安全检查不足的 harness 是双刃剑**

- 因果链：强执行能力 harness → 更能穿越复杂交互流到达攻击目标 → 若无前置安全校验 → 不安全动作同样被可靠执行（Skyvern 2.0：TCR 最高 85.25%、DSR 仅 58.01%）。【论文实验已支持，相关性证据；因果解释为论文与阅读者共同推测】
- 佐证（外部，WASP）："推理双刃剑"——推理更强的模型一旦被劫持，端到端攻击成功率反而更高。能力放大攻击与能力放大不安全执行，本质同构。

### 6.3 综合判断与未决问题

- **多项研究共同支持的机制**：(1) 模型安全对齐不能自动迁移到 agent 部署态（BrowserART、WASP、本文一致）；(2) 评测必须区分防御与能力失败（WASP 与本文从攻防两端独立收敛）；(3) harness 级信息流控制（过滤/锚定/结构化）是有效防御方向（Struq 等防御工作与本文消融一致）。
- **仍属观察性/推测的结论**：文本 vs 多模态感知、单控 vs 多角色规划、规则 vs LLM grounding 的组件对比基于跨 harness 观察（S&P Meta-Review 亦明确指出这一点），未做逐组件消融——多角色规划传播注入（Agent-E Stage III 仅 10.65%）的机制解释有执行轨迹佐证但未受控验证；naive 攻击中"安全训练模式匹配被显式攻击触发"的解释属合理推测。
- **适用边界**：受控网页环境下结论对真实动态网页的外推未验证；攻击集是静态的，会随新攻击演化而滞后（Meta-Review 关注点 1）；三阶段消融均在 GPT-4o 单后端下进行，机制结论对其他后端的普适性有限。
- **可能失效的条件**：若后端模型未来内建网页侧威胁感知（安全训练覆盖 web 内容），组件差异的影响可能收窄；对抗性自适应攻击者可针对"过滤+锚定"设计绕过策略。

## 七、必要知识反推

假设让一个没有背景的人复现这项工作，倒推其最少必要知识：

### 7.1 领域知识层

- **Web Agent 系统结构**：必须理解 LLM 如何通过 harness 连接浏览器——不理解四阶段工作流，就无法设计阶段级归因。作者调研 40 篇论文 + 68 个开源项目的taxonomy 功底是前提。
- **三类攻击的机理与历史**：越狱/指令覆盖/角色扮演（用户侧）、间接提示注入的各种载体（网页侧）、dark pattern 与社会工程（欺骗设计）——每个攻击维度只收录"至少两项独立工作验证过"的方法，需要完整的攻击文献地图。
- **网页技术栈**：DOM、可访问性树（ARIA 属性既可做感知通道也可做注入载体）、URL 锚点、iframe——注入位置的六分类直接建立在这些知识上。

### 7.2 方法论知识层

- **评测方法论**：LLM-as-a-judge 的可靠性校验流程（人工抽样 + 一致率 + κ 系数）；配对实验设计思想（攻击/校准任务同构）。
- **统计建模**：GLMM 混合效应模型——理解"任务作为随机截距"为何必要（同一任务被 6 harness × 7 模型重复评估，观测不独立）；敏感性分析（极端重标注）对抗"选择性剔除"质疑。
- **扎根式的模式归纳**：从 100 个日志人工归纳安全/不安全状态模式，再自动化标注全量——教科书级的"定性发现 → 定量验证"流程。

### 7.3 工程知识层

- **网页侧埋点监控**：用 JavaScript 事件监听做 harness 无关的测量接口，同时覆盖开源与闭源系统——这是跨 harness 公平比较的工程基石。
- **六个开源 agent 的深度定制理解**：消融要精确替换某个提示词组件（如 Agent-E 的意图解释提示 vs Skyvern 2.0 的），必须读透各代码库的提示词工程细节。
- **可复现性工程**：温度 0、三遍重复（std 1.73pp）、官方默认配置不改动——评测可信度的工程保障。

### 7.4 知识融合的关键节点

1. **"安全评测 × 心理测量学的混淆变量控制"**：把"能力失败"识别为安全测量的混淆变量并用配对设计消除——这是测量方法论向安全领域的迁移，是全文方法论的支点。
2. **"软件工程抽象 × 安全归因"**：四阶段工作流本是架构抽象，被创造性地用作安全归因的坐标系——防御阶段定位规则（首个安全态 / 最后一次转移）把架构语言翻译成了统计语言。
3. **"红队攻击知识 × 生态系统调研"**：三类攻击的系统性展开建立在对攻击文献与 68 个开源项目的双重调研之上——没有生态占比（85.0% 用 LLM 解释器等）就没有组件代表性。
4. **"统计学 × 因果推断直觉"**：GLMM 主效应 + 交互效应 + 敏感性分析 + 四个单变量消融，构成了"相关 → 因果"的完整证据阶梯。

## 八、论文中可以提取的通用性灵感

### 灵感一：评测系统必须分离"不做"与"不能做"

- **核心思想**：任何"失败即合格"的评测（安全、合规、拒答）都存在把能力不足伪装成合格表现的幸存者偏差；解法是给每个测试项配一个"去掉测试条件的同构对照项"。
- **论文证据**：配对可用性任务 + TCR 剔除使 ASR/DSR 分母只含能力可达任务；GLMM 敏感性分析证明结论对剔除策略稳健。
- **推广场景**：(1) LLM 拒答评测（拒答可能因为不会答）；(2) 内容审核系统测试（漏放可能因为识别不了而非判断合规）；(3) 自动驾驶接管测试（不接管可能因为感知失败而非判断安全）；(4) 防火墙规则评测（拦截可能因为路由错误而非策略命中）；(5) 医疗诊断 AI 的"谨慎性"评测（保守诊断可能源于能力不足）。

### 灵感二：系统行为是"架构 × 组件"的联合产物，归因要分解到组件级

- **核心思想**：端到端指标无法指导设计；先建立公共抽象骨架（工作流），再按骨架定位行为来源，才能把"哪个设计选择造成了差异"变成可回答的问题。
- **论文证据**：同一 GPT-4o 下 DSR 差 40.90pp；阶段定位 + 单变量消融把差异归因到细粒度意图解释（-21.76pp）、风险感知提示（-30.43pp）、目标锚定（±17~24pp）等具体机制。
- **推广场景**：(1) RAG 系统质量归因（检索/重排/生成各环节）；(2) 编译器性能分析（前端/中端/后端 pass 贡献分解）；(3) 多微服务系统故障定位（哪个环节引入/传播/阻断了错误）；(4) 供应链安全（哪个环节引入漏洞）；(5) 教育 A/B 测试（课件/练习/反馈哪个组件起作用）。

### 灵感三：无攻击的基线是发现"内禀缺陷"的探针

- **核心思想**：只测有攻击条件下的表现会漏掉系统在日常运行中自然发生的失效；设一个"零攻击基线"，若它仍产生坏结果，说明缺陷内在于系统设计而非外部诱因。
- **论文证据**：naive 攻击 ASR 可超过显式攻击（SeeAct MPI 50.00% vs 49.37%；Browser Use (Text) DWD 41.27% vs 36.30%），揭示 harness 缺少执行前的必要性/一致性/安全性校验。
- **推广场景**：(1) 数据库在无负载异常下的慢查询（内禀计划缺陷）；(2) 分布式系统无故障注入时的数据不一致（设计缺陷）；(3) 模型在无对抗扰动下的幻觉率（内禀问题而非鲁棒性问题）；(4) 组织流程在无危机时的合规违规（制度性漏洞）。

### 灵感四：提示词级约束会随交互链长而衰减

- **核心思想**：把安全/正确性约束写在提示词里，其效力会随多轮交互、重复执行、上下文膨胀而稀释甚至反转；结构性、显式的机制约束才能持久。
- **论文证据**：Skyvern 1.0 案例中同一护栏提示下，安全判断随重试轮次从拒绝→忽视→执行逐级退化，最终填入信用卡号。
- **推广场景**：(1) 长 agent 链中的角色设定漂移（需结构化状态机而非提示词维持）；(2) 多轮谈判/客服 bot 的政策边界维持；(3) 代码 agent 长任务中"不要改公共 API"约束的失效； (4) 法律合同中软性条款 vs 硬性条款的执行差异。

### 灵感五：能力与安全是正交维度，必须分别度量、分别设计

- **核心思想**："做得快做得好"的系统在防护不足时也"把坏事做得快做得好"；能力投资不能替代安全投资，评测也不能用一个综合分掩盖两个维度。
- **论文证据**：Skyvern 2.0 TCR 最高 85.25% 而 DSR 仅 58.01%；Agent-E 反之；WASP 的"推理双刃剑"从攻击端给出同构结论。
- **推广场景**：(1) 代码生成模型（正确率高≠安全漏洞少）；(2) 权限系统设计（自动化效率与最小权限原则）；(3) 金融交易系统（执行速度与风控检查分离）；(4) 内容推荐（分发效率与信息生态健康分治）。

## 附录：学到的评测设计技能

1. **配对校准任务模板**：任何"拒绝/不作为=合格"的评测都可以套用"攻击任务 + 去触发器对照任务 + 三态标注（攻击成功/防御成功/能力失败）"的三段式。
2. **网页侧测量接口**：JavaScript 事件埋点 + 后端收集，实现对被测系统零侵入、对闭源系统同样可用的统一测量层。
3. **GLMM 归因模板**：固定效应（系统因素们 + 交互项 + 类别控制）+ 随机截距（重复测量的实验单元）+ 敏感性分析（对缺失机制做极端假设）。
4. **防御定位规则**：按"攻击从哪个阶段进入系统"分别设计定位规则（进入即在场 → 首个安全态；中途进入 → 最后一次不安全→安全转移），可推广到任何流式处理系统的行为归因。
