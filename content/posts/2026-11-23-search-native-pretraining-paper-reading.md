> **论文链接**：[Search From the Start: Search-Native Pretraining for Language Models](https://arxiv.org/abs/2611.26809)
> **发表时间**：2026年11月
> **机构**：EPFL、多伦多大学（Swiss AI Initiative 访问博士奖学金与 armasuisse 资助，纯学术合作；标注教师模型使用 GLM-5.2）
> **领域标签**：cs.CL — 语言模型预训练、检索增强

## 一、论文背景

要理解这篇论文，先要理解一个矛盾：**今天的语言模型部署时几乎都接了搜索工具，但它们的预训练却与搜索毫无关系。**

语言模型的预训练目标是预测静态文本的下一个 token。事实知识必须被"压缩"进模型参数里——这带来三个被反复验证的问题：

1. **参数容量有限**。Morris et al. (2025)、Huang et al. (2026a) 等工作表明，模型参数中可存储的事实知识存在容量上限，无法从一般规律推断的事实必须靠死记（Allen-Zhu & Li, 2024）。小模型受害最深：参数少，能记住的事实更少。
2. **知识会过期**。现实世界的事实持续变化，Vu et al. (2023) 的 FreshQA 专门测这一点；编码进权重的知识会随时间腐烂，更新需要重新训练或事后编辑。
3. **知识难以核查**。参数化知识是黑盒分布式的，事后验证、编辑、删除单条事实都很困难。

业界目前的通行解法是"预训练 + 后训练教搜索"：先训一个只会预测下一个 token 的基座，再在 SFT/RL 阶段教它发起搜索查询、利用检索证据（WebGPT、Search-R1 等）。这已经成了 GPT-5 级别产品的标准路径。

但论文提出了一个根本性质疑：**如果一种能力（搜索）最终必不可少，为什么要等到后训练才教？** 近期一批工作（Zhang et al. 2025、Baek et al. 2026、Minder et al. 2026）已证明"能力相关数据在预训练早期引入"有持续收益，但把这种思路扩展到搜索能力、并规模化到百亿 token 级语料，一直没有可行方案——难点在于：谁来标注"这里该搜、搜什么"？百万级文档逐个让人或大模型标注成本不可接受。

论文的核心研究问题可以一句话概括：**能否在保持原有 next-token prediction 目标不变的前提下，用普通预训练文档规模化地教会模型搜索？** 答案是 Search-Native Pretraining，产出的模型叫 QueryLM。

## 二、论文定位和关联工作

这篇论文处在三条研究脉络的交汇点。

### 脉络一：推理时/后训练接入搜索与工具

- **WebGPT**（Nakano et al., 2022，[arXiv:2112.09332](https://arxiv.org/abs/2112.09332)）：OpenAI 微调 GPT-3 使用文本浏览器，模仿人类"提交搜索、点击链接、引用来源"的研究方式，用人类反馈优化答案。搜索能力完全在后训练注入。
- **Toolformer**（Schick et al., 2023，[arXiv:2302.04761](https://arxiv.org/abs/2302.04761)）：让 LM 自监督地学会在文本中内联插入 API 调用——采样候选插入点、执行调用、按"是否降低后续 token 损失"过滤、再微调。这是与本文最相近的方法论先驱：QueryLM 的插入点采样策略直接参照了它。区别在于 Toolformer 是对一个已预训练好的 6.7B 模型做微调，而本文把同样的内联注入做到了 1 亿 token 级预训练语料、从零训练。
- **Search-R1**（Jin et al., 2025）等 RL 方法：用强化学习教模型推理中利用搜索引擎，同样是后训练。

### 脉络二：预训练阶段外部化知识

- **REALM**（Guu et al., 2020）/ **RETRO**（Borgeaud et al., 2022）：检索增强预训练的早期代表，但需要**修改架构**（联合训练检索器或增加检索编码器与交叉注意力层）。
- **LMLM**（Zhao et al., 2025，[arXiv:2505.15962](https://arxiv.org/abs/2505.15962)）：把事实知识外部化为实体-关系键值存储，预训练时有策略地 mask 掉检索值，教模型做定向查找而非记忆。局限：查询是结构化实体-关系查询，插入点固定在实体值之前，知识库来自 Wikipedia 三元组。
- **Co-LMLM**（Feldman et al., 2026，[arXiv:2607.07707](https://arxiv.org/abs/2607.07707)）：LMLM 后续，用连续向量查询替代文本查询，扩展到 FineWeb-Edu。360M 规模 SimpleQA 表现对标 gpt-4o-mini。
- 本文与 LMLM 系列的差异是明确的：QueryLM 发起的是**灵活的自然语言 web 查询**、检索源是 1.34 亿网页文档的 BM25 索引（可无缝切到 Tavily 真实搜索引擎）、**不改架构、不建实体键值库**，插入位置也更一般化（不限于实体值之前）。

### 脉络三：预训练数据前移（front-loading 能力数据）

- **Instruction Pretraining**（Cheng et al., 2024）、**Safety Pretraining**（Maini et al., 2025）、推理数据前移（Akter et al., 2025）等：证明指令遵循、安全性、推理等能力可以在预训练阶段引入。
- **Early Data Exposure**（arXiv:2605.12705）：把后训练数据混入预训练（early exposure），能让该能力在后续微调中更抗遗忘，且算力匹配实验中最优点在两个极端之间——这为本文"搜索能力放在预训练更稳固"的发现提供了独立佐证。
- **MidTool / SPT**（2026）：在 mid-training 阶段注入工具使用/技能包数据。

### 定位总结

| 维度 | 之前的路线 | 本文的突破 |
|------|-----------|-----------|
| 搜索能力注入时机 | 后训练（WebGPT、Search-R1、Toolformer） | 预训练从零开始 |
| 查询形式 | 结构化（LMLM）或无（REALM/RETRO 被动检索） | 灵活自然语言 web 查询 |
| 架构改动 | 需要交叉注意力/检索器（RETRO、Co-LMLM） | 零改动，标准 decoder-only |
| 数据规模 | Toolformer 约 10 万级样本 | Wikipedia 8.43B + DCLM-Edu 101.5B token |
| 核心论证 | 提升即效 | 后训练 SFT 无法完全追回预训练获得的优势 |

## 三、问题定义

论文面对的具体场景是：模型在生成中遇到"原文之外的未知事实"时，应当学会发起搜索。将其抽象，本质是一个**条件分布重塑问题**。

给定一篇文档被切成前缀 $p_i$ 与后续 $s_i$，一个理想的搜索增强文档应该在 $p_i$ 与 $s_i$ 之间插入查询 $q_i$ 与响应 $r_i$。训练目标的形式化定义（论文式 1）：

$$L(\theta) = -\sum_{t=1}^{\tilde{T}} \mathbb{1}[t \notin I_R] \log p_\theta(\tilde{x}_t | \tilde{x}_{<t})$$

其中 $I_R$ 是所有检索响应 token 的索引集合。也就是说：

| 组件 | 是否计算 loss | 学到什么 |
|------|--------------|----------|
| 原始文档 token | 是 | 正常语言建模 |
| `<WEB-QUERY>` 与查询 token | 是 | **何时搜、搜什么** |
| `<WEB-RESPONSE>` 与响应 token | **否（mask）** | 响应只作为条件上下文，不学习复现它 |
| 原文后续 $s_i$ | 是 | **如何用检索证据续写** |

这个定义的精妙之处在于**损失掩码的不对称性**：模型被训练成"把检索响应当作给定的外部证据来条件化续写"，而不是"背诵检索结果"。这直接对应了能力的两个侧面——发起搜索（生成查询有 loss）与利用搜索（续写有 loss、复现响应无 loss）。掩码还避免了让模型浪费容量去学习复现外部文档的风格，把宝贵的参数预算留给"如何使用证据"。

约束条件同样重要：不改变标准 next-token 目标、不改架构、标注成本必须摊薄到可规模化（一次性标注整个语料库、可跨模型复用）。

## 四、问题解法

方法的完整管线分四步，可以类比为"先请老师傅带徒弟做出一万件示范品，再让徒弟独立标注整个工厂的活儿"。

### 4.1 种子数据：GLM-5.2 教师标注 1 万篇 Wikipedia

教师模型 GLM-5.2 对前 1 万篇英文 Wikipedia 文档（2000-9000 字符）做两遍标注：

1. **选位置**：通读全文，标记"即将出现的具体事实（名字、日期、数量）能从外部检索获益"的位置；
2. **写查询**：只用该位置左侧最多 1600 字符的上下文生成搜索查询。

**两遍分离是关键设计**：选位置可以看全文（避免在无用处插入），写查询只能看左侧（与推理时可用的信息严格一致，防止查询泄露答案——"作弊查询"会让模型学到坏习惯）。

每个查询用 BM25 over FineWeb-Edu 检索，去重、过滤与原文 35% 以上 trigram 重叠的段落，保留前 5 段各约 900 字符，最后由 Gemma 4 E4B 压缩成 1-3 句。最终种子集每篇文档约 20 个查询。

### 4.2 标注器 Mϕ：单次前向并行打分

用种子数据微调 Gemma 4 E4B（LoRA rank 16），得到标注器 Mϕ。它面对整篇文档时**一次因果前向**就能输出每个 token 之后的插入概率：

$$\pi_i(x) = \Pr(<|\text{WEB-QUERY}| \mid x_{1:i})$$

类比：这相当于把 Toolformer"逐位置采样候选再逐一验证"的串行流程，改成了并行打分——预训练规模标注的工程前提。

过滤两道关：τ=0.05 概率阈值 + 最小间隔 40 字符；生成查询后还要通过 ROUGE-1 F1 ≥ 0.1 的"响应-续写重叠"过滤（词面重叠作为相关性代理，确保检索回来的东西真能帮到续写）。

### 4.3 模拟 web 响应：BM25 over Sphere

为 1.34 亿网页文档（Sphere）建 BM25 索引。每个查询取 top-10 段落，选取与查询词干重叠最多的句子，压到约 400（Wikipedia）/800（DCLM-Edu）字符。选 BM25+Sphere 而非 API 或更大索引，是覆盖率与成本的折中（100B FineWeb-Edu 子集已覆盖 1T 子集 90% 的查询，Sphere 相关性更优）。

### 4.4 预训练与推理

在标注后的语料上从零训练 decoder-only Transformer（Wikipedia 用 SmolLM2 配置 360M；DCLM-Edu 用 nanochat 配置 400M/1.4B/3.3B）。推理时在生成开头注入 `<|WEB-QUERY>` 触发搜索，检索结果填回 `<WEB-RESPONSE>` 后继续生成——训练与推理格式完全一致，无迁移缝隙。

**成本账**（论文表 14）：数据准备每语料一次（标注 token + A 次检索），可跨模型复用；训练时 token 从 D 增至 D + Aℓ；推理时每次查询加 ℓ token。消融显示响应压到 50 字符或每文档只留 Top-2 插入，都能把开销减半以上而保留大部分能力（3.3B Top-2 版 QA 37.9% vs 完整版 39.4%，仍高于基线 36.9%）。

## 五、评估指标与实验证据

### 5.1 指标体系

| 类别 | 指标 | 定义 | 衡量的能力 |
|------|------|------|-----------|
| 主指标 | 8 项知识密集 QA 平均准确率 | TriviaQA/NQ/PopQA/WebQs（事实）+ HotpotQA/2Wiki/MuSiQue/Bamboogle（多跳）；base 用 4-shot 答案包含率，SFT 用 0-shot LLM 评判 | 有搜索时的知识任务表现 |
| 关键对照 | 反事实证据跟随率 | 给出与训练事实矛盾的检索证据，看答案是否跟随证据 | 证据接地（grounding）vs 参数记忆 |
| 辅助 | FreshQA/HaluEval/RAGTruth | 时效事实、幻觉环境下的忠实度 | 接地能力多角度验证 |
| 完整性 | 8 项通用基准闭卷 | ARC/HellaSwag/PIQA 等 | 代价检查 |

实验设计的关键是 **FLOP 对齐基线**：同架构、同计算量的标准预训练模型（基线处理的文档 token 更多，以抵消 QueryLM 处理查询+响应 token 的额外开销），检索时基线直接复用 QueryLM 的查询与结果，只差"预训练是否见过搜索示范"。

### 5.2 核心结果

**Base 模型（4-shot，Tavily 检索）：**

| 规模 | QueryLM | FLOP 对齐基线 | 差距 |
|------|---------|--------------|------|
| 400M | 24.8% | 7.5% | **+17.3** |
| 1.4B | 30.3% | 18.6% | +11.7 |
| 3.3B | 32.0% | 23.9% | +8.1 |

规模越小差距越大——恰好说明参数知识越少，搜索预训练补偿越强。更具冲击力的对照：**400M QueryLM（预训练 3.09×10^19 FLOPs）平均 24.8%，超过 SmolLM3-3B 无搜索的 23.6%（2.07×10^23 FLOPs），算力约少 6700 倍**；1.4B QueryLM 在全部知识密集任务上持平或超过 3.3B FLOP 对齐基线。

**SFT 后优势保持（论文最核心的论证）：**

| 设置 | QueryLM | 基线 | 差距 |
|------|---------|------|------|
| Search SFT 3.3B | 39.4% | 36.9% | +2.5 |
| 标准 SFT 3.3B | 33.7% | 27.5% | +6.2 |
| 标准 SFT 400M | 22.2% | 16.5% | +5.7 |

即使给基线喂高比例搜索示范的 Search SFT，也**不能完全追回**预训练阶段获得的优势——这是"搜索应作为原生能力"这一范式主张最直接的实验证据。

**证据接地：**

- 反事实证据下 3.3B SFT 版跟随率 64.3% vs 57.9%；400M 差距最大（51.7% vs 57.9% 的基线在无证据时更高，但反事实下 400M QueryLM 51.7% 反超）；
- 闭卷（无证据）时 QueryLM 反而更差（3.3B base 14.6% vs 16.7%）——它真的把"记忆"重构成了"查证"；
- FreshQA base 版 +15.2~+16.2pp；HaluEval/RAGTruth 相关上下文下 prefer-right 全面更高；
- 查询质量：换成 Qwen3-30B 生成的查询，QueryLM 提升小于基线提升——自产查询更有效。

**代价（论文如实报告）：** 闭卷通用能力 base 略降（-0.9~-2.5pp，SFT 后持平）；闭环 base 3.3B 为 14.6% vs 16.7%；3.3B 规模上固定查询源时 QueryLM 的上下文利用优势反而逆转（推测参数知识与上下文推理增强所致）。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**因果链：预训练语料内联注入查询-响应示范 → 模型从第一个 token 起就以"用证据续写"为目标 → 知识获取路径从参数记忆重构为检索接地 → 参数知识不足的小模型获得不成比例的收益，且该能力经后训练无法被完全复制。**

分步拆解并标注证据等级：

1. **【论文实验支持】训练信号的重构。** 损失掩码使模型在预训练中把检索响应当作条件而非目标。证据：闭卷时 QueryLM 更差（14.6 vs 16.7）而有证据时大幅更好——它确实把本可记忆的事实"外包"给了检索。FreshQA 上 never-changing 事实项 QueryLM 略低（8.8 vs 13.2）而 slow/fast-changing 项大幅更高，与"记忆换检索"的预测一致。
2. **【论文实验支持】规模补偿效应。** 400M 差距 +17.3、3.3B 差距 +8.1，单调递减。参数知识越少，外部化的边际收益越大；这也解释了 400M 超 SmolLM3-3B 的 6700 倍算力效率。
3. **【论文实验支持】预训练能力的不可完全恢复性。** Search SFT 后基线仍落后。这是范式主张的核心证据：搜索能力不只是"行为格式"，而是与语言建模目标深度融合的预测策略。
4. **【阅读者推测】梯度暴露量差异。** Search SFT 只有约 5.3 万条对话、其中 21% 带搜索插入，而 QueryLM 预训练在百亿 token 上见过数千万级插入示范。优势可能部分来自曝光量而非"预训练阶段本身"。（论文未做同等数据量的后训练对照，此为本文局限之一；但 Early Data Exposure 的算力匹配实验——最优点在两极端之间——不支持"全放后训练"的极端。）
5. **【阅读者推测】证据跟随率提升的双刃性。** 反事实跟随 64.3% 意味着对矛盾证据的顺从也更高——若检索源被投毒或出错，QueryLM 可能更易被误导。论文未评估检索对抗鲁棒性。

| LMLM（[arXiv:2505.15962](https://arxiv.org/abs/2505.15962)） | 预训练期外部化事实，mask 检索值损失 | 小模型可对标更大 LLM | 结构化实体查询、Wikipedia 三元组库；PopQA 上 LMLM 强于本文 Wikipedia 版（知识库同源优势） | 支持：预训练期外部化知识对小模型有效；限定：查询灵活性与语料广度不如本文 |
| Co-LMLM（[arXiv:2607.07707](https://arxiv.org/abs/2607.07707)） | 连续向量查询 + 预训练拷贝知识 | 360M 对标 gpt-4o-mini（SimpleQA） | 需诱导知识库与专用检索机制；本文 400M 过训版 Tavily 27.7% vs Co-LMLM 19.1% | 支持且直接对照：灵活 web 查询 + 无架构改动在可比设定下更优 |
| Toolformer（[arXiv:2302.04761](https://arxiv.org/abs/2302.04761)） | 自监督内联工具调用插入 | 少量演示即可教会 6.7B 模型用工具 | 对已预训练模型微调、10 万级样本；插入点采样策略被本文继承 | 方法相似、结论互补：证明内联注入可行；本文证明规模化到预训练收益更大 |
| WebGPT（[arXiv:2112.09332](https://arxiv.org/abs/2112.09332)） | 后训练教 GPT-3 浏览搜索 | 人类反馈可提升事实性 | 完全后训练路径；本文证明该路径并非能力获取的最优时机 | 限定：后训练能教搜索（所以本文方案非唯一解），但本文证明其不完全等价 |
| Early Data Exposure（arXiv:2605.12705） | 把能力数据混入预训练 | 早暴露的能力更抗后续微调遗忘；算力匹配最优点在两极端之间 | 任务为音乐/指令/化学，非搜索 | 结论相近、方法不同：独立佐证"预训练期引入能力更稳固"的根源解释 |
| MidTool / SPT（2026） | mid-training 注入工具/技能数据 | 工具能力前置提升 agentic 表现 | mid-training 而非从零预训练；MidTool 发现通用工具 mid-training 对深度搜索收益边际 | 支持：能力前移的普适性；限定：搜索类能力可能需要专门的搜索示范（与本文一致） |
| REALM/RETRO（2020/2022） | 检索增强预训练 | 检索可降困惑度、减参数 | 被动检索（查询即 prompt）或需改架构 | 支持：预训练+检索融合有效；凸显本文"模型主动发起查询"的增量 |

检索说明：以上均为本次检索（arXiv 原文页与综述）可核验的文献；未发现直接反驳"搜索预训练优于搜索后训练"的相反结论工作，但注意 MidTool 指出通用工具 mid-training 对 web 深度搜索收益边际——与本文"需要专门搜索示范"的发现一致而非矛盾。

### 6.3 综合判断与未决问题

**多项研究共同支持的机制**：(a) 预训练期引入能力数据带来后训练难以复制的收益（本文 + Early Data Exposure + Instruction Pretraining 系）；(b) 知识外部化对参数知识不足的小模型收益最大（本文 + LMLM 系列）；(c) 内联工具示范是教会模型用工具的有效格式（本文 + Toolformer）。

**仍属推测的部分**：优势中"预训练阶段本身"与"搜索数据曝光量"的归因拆分（论文未提供等量后训练对照）；3.3B 规模以上优势是否继续收窄乃至消失。

**适用条件**：收益集中于知识密集、检索可及的任务；小模型（≤3.3B）与算力受限场景收益最大。**可能的失效条件**：检索源质量差或被对抗操纵（跟随率更高的双刃剑）；闭卷/通用任务上小幅代价可接受性取决于应用；参数知识已充足的大规模模型上收益递减。

## 七、必要知识反推

假设一个无背景的人要做这项工作，最少需要掌握什么？

### 领域知识层

- **参数化知识的极限**：必须知道 LM 记忆事实有容量约束、会过期、难编辑（Kandpal et al. 2023 长尾知识、Morris et al. 2025 记忆量化）——否则不会产生"把知识外移到检索"的动机。
- **搜索增强的现有形态**：从 WebGPT 到 Search-R1 的后训练路径及其数据构造方式——否则无法定位"时机前移"这一空白。

### 方法论知识层

- **自监督工具注入范式**：Toolformer 的"采样-执行-按损失过滤"循环是插入点策略的直接前提；不懂它就无法设计 τ 阈值 + 重叠过滤的替代方案。
- **知识外部化预训练**：LMLM 的损失掩码思想（mask 检索值）是本文损失设计的参照系，也是必须超越的对象（结构化查询 → 自由查询）。
- **蒸馏与规模化标注**：教师标注种子 → 小模型标注器 → 全语料扫描的两阶段范式；以及 LoRA 微调的工程细节。

### 工程知识层

- **检索基础设施**：BM25 索引构建、Sphere/FineWeb-Edu 语料特性、检索响应压缩的成本权衡（论文 6.2/6.3/6.4 节全是这类工程判断）。
- **FLOP 对齐的对照设计**：如何公平比较"处理了更多 token 的搜索模型"与"只看文档的基线"——把响应 token 的前向计算也计入基线预算，是结论可信的前提。
- **预训练栈**：SmolLM2/nanochat 配置、Muon 优化器、4K token 打包、bf16 训练。

### 知识融合的关键节点

1. **"位置与查询分离标注"**：融合了教师模型的全局视野与推理时的因果约束——这是防止查询泄露答案的洞察，种子质量的命门。
2. **"单次前向并行打分"**：把 Toolformer 的串行采样重构成并行打分，是标注从 10 万篇到 1 亿 token 的规模化跃迁点。
3. **"不对称损失掩码"**：融合了 LMLM 的掩码思想与标准 LM 目标——不改目标函数形式，只改 mask 集合，使搜索能力与语言能力在同一优化过程中共同生长。

## 八、论文中可以提取的通用性灵感

### 灵感一：能力注入的时机本身就是设计变量

**核心思想**：一种能力的注入时机（预训练 vs mid-training vs 后训练）对最终效果的影响，可能不亚于数据本身的质量。

**论文证据**：FLOP 对齐下，Search SFT 后基线仍落后 QueryLM 2.5pp、标准 SFT 后落后 6.2pp——同样的搜索示范数据，放在预训练收益更大。

**推广场景**：代码能力（把代码执行轨迹混入预训练而非只靠代码 SFT）；多语言能力（低资源语言数据前移）；安全对齐（Safety Pretraining 已在验证）；领域适应（医疗/法律语料前移而非 LoRA 补课）。

### 灵感二：教师标注种子 → 小模型规模化蒸馏的标注范式

**核心思想**：用强模型精标 1 万样本训练专用标注器，再以单次前向的并行方式扫描全语料——把"每篇都要大模型"的 O(N×C) 成本降为 O(N×c) + O(10^4×C)。

**论文证据**：GLM-5.2 标 1 万篇 → Mϕ（Gemma 4 E4B + LoRA）标注 101.5B token 的 DCLM-Edu，且标注一次、跨 400M/1.4B/3.3B 三个模型复用。

**推广场景**：合成数据的规模化质检；私有语料的领域偏好标注；RLHF 奖励数据的预筛；任何"大模型判断好但太贵"的批量标注任务。

### 灵感三：不对称监督——让模型学会"用"而非"抄"

**核心思想**：对工具返回的内容做损失掩码、只监督行为与决策 token，模型会把外部内容当作条件而非模仿目标，避免浪费容量学习复现外部风格。

**论文证据**：响应 token 无 loss，模型学会条件化续写；Oracle 消融（响应换成含金标准答案的摘要）显示更强的上下文依赖并不带来更好的下游泛化——监督"如何用"比提供"更好答案"更重要。

**推广场景**：多模态训练中对参考图像做掩码只监督输出；Agent 轨迹训练中掩码环境返回只监督动作；RAG 系统训练只监督答案与引用而非检索文本。

### 灵感四：小模型 + 原生工具 = 算力杠杆

**核心思想**：当能力可以被外化为工具调用，小模型凭借"会用工具"可以在特定任务族上追平参数量大若干倍、算力多几个数量级的模型。

**论文证据**：400M QueryLM 24.8% vs SmolLM3-3B 无搜索 23.6%，算力少约 6700 倍；1.4B 持平或超过 FLOP 对齐 3.3B。

**推广场景**：端侧/边缘设备模型 + 云端工具 API；低成本垂直 Agent（小模型 + 领域数据库）；算力受限组织的能力建设路径。

### 灵感五：诚实报告代价是范式论文的可信度来源

**核心思想**：主张新范式的论文应完整报告适用边界与代价，让读者自行判断权衡。

**论文证据**：论文如实给出闭卷通用能力 -0.9~-2.5pp、闭环 base 略差、3.3B 固定查询时优势逆转、成本公式与 Top-2 折中方案——这些"不利数据"反而强化了核心主张的可信度。

**推广场景**：任何方法论文写作；内部技术选型报告；benchmark 评审。
