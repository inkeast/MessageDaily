## 一、论文背景

### 1.1 编码 Agent 的上下文是怎么变成账单的

要理解这篇论文，先要理解一个编码 Agent（coding agent）是怎么干活的。给定一个 GitHub 仓库里的真实 issue（比如 Django 的某个 bug），Agent 会循环执行：搜索相关代码、读文件、编辑、跑检查，每一步都通过 bash 命令完成。关键在于：**每一步的命令和输出都会追加进对话历史，而下一轮请求要把整个历史重新发给模型**。也就是说，第 50 轮请求要付前面 49 轮积累的全部 token 的钱。生产环境的统计印证了这一点：Manus 团队把缓存命中率列为决定 Agent 经济性的头号指标，因为 Agent 大约每 100 个输入 token 才产出 1 个输出 token——成本几乎全在重读历史上。

### 1.2 Prefix Caching：让重复前缀变便宜的双刃剑

LLM 推理最贵的环节之一是 prefill：模型要处理 prompt 的每个 token 才能开始生成。Prefix caching（前缀缓存，工程上常称 prompt caching）的思路是：如果两次请求的开头部分完全相同，服务端可以复用上次算好的 KV cache，跳过这部分计算。主流 API 都为此设计了差异化计价：Anthropic 的缓存读价格是原价的 0.1 倍（部分新模型低至 0.05 甚至 0.025 倍），OpenAI 宣称折扣最高 95%，缓存写入则要收 1.25–2.5 倍的溢价。vLLM（Kwon et al., 2023）、SGLang（Zheng et al., 2024）等开源服务系统也内置了这一机制。

问题在于缓存匹配的规则极其苛刻：**前缀必须逐字节一致，从第一个 token 开始匹配，改一个字符，从改动点之后的全部内容都要按全价重算**。这就带来两个反直觉后果：

1. 往 prompt 里加的每个 token，之后每一轮都要为它付费（哪怕是便宜的缓存价）；
2. 删掉 prompt 中间一段旧内容，看似变短了，实则改变了前缀——改动点之后的整个后缀失去缓存命中，要按全价重算一次。

### 1.3 两种上下文管理直觉的碰撞

社区对 Agent 上下文管理有两类流行直觉：

- **加上下文**：RAG 式地把检索到的候选代码、相关定义塞进 prompt，让 Agent 少做搜索（LocAgent、RepoGraph 等工作）；
- **删上下文**：把旧的工具输出掩蔽（masking）、摘要（summarization）或驱逐（eviction），让后续 prompt 变短（The Complexity Trap、AgentDiet、TokenPilot等工作）。

这两类方法在论文里几乎都以 token 数量作为收益指标。但 Weinberger 与 Hozez（2026）研究真实账单时发现：最激进的压缩方案把工具输出 token 砍了 38.4%，账单反而涨了 6.8%，且 token 缩减量与实际费用变化的相关系数只有 0.15——约 87% 的成本来自缓存的创建与读取，用户侧压缩能触及的部分很小。**Token 节省不等于成本节省**，这一信号正是本文的直接动机之一。

### 1.4 为什么这个问题此刻重要

真实生产中 Agent 的输入几乎全是缓存读：TraceLab（Zhu et al., 2026）分析了 8,058 个 Claude Code 与 Codex 会话，发现 95.6% 的输入 token 是缓存读取。这意味着缓存价格参数 c 是成本公式里最敏感的变量——它从 0.025 到 1 变化时，缓存部分占账单的比重从 18–30% 摆到 90–95%。一个上下文管理方法若只在单一价格（或纯 token 计数）下评估，结论可能在整个真实价格区间上都不成立。本文要做的，就是把加法与删法放进同一个**带价格的记账框架**里重审。

## 三、问题定义

### 3.1 从具体场景到抽象问题

具体问题：给编码 Agent 加检索代码、删旧观测，到底能不能降总成本？这个问题难在三点：token 数不等于账单（三流三价）；改 prompt 会断缓存（局部变动的代价是全局的）；Agent 不是被动接受者——它会用更多搜索步骤补偿被删的信息。

论文的核心洞察是：**加上下文与删上下文是同一个记账问题的两次检验**——对 prompt 的局部改动，在计入缓存复用与后续行为之后，是否降低整段运行的总推理成本。这把一系列看似无关的干预（检索包、掩蔽、摘要、反思、微调）统一到同一个被测量对象上。

### 3.2 形式化定义

一次运行的成本：

```
cost(c, p) = U + c·C + p·O
```

其中 U = Σ(Pt − Ht) 为未缓存输入 token 总数，C = ΣHt 为缓存命中 token 总数，O 为输出 token 总数；c 是缓存输入相对未缓存输入的价格，p 是输出价格相对未缓存输入的倍数。基准设定 c ∈ {0.1, 1}、p = 4，对应主流 API 的缓存读价（0.025–0.1）与输出价（5–6 倍）。

删除的盈亏条件（固定后续动作）：

```
R·c·B > (1−c)·S
```

即删除 B 个 token 在剩余 R 次请求中省下的缓存价（左），必须大于改动点之后 S 个 token 失去命中、按 (1−c) 差价重算的一次性代价（右）。加法是镜像：加进的 B 个 token 至少每轮付 cB。

### 3.3 这个抽象的精妙之处

- **价格向量让符号翻转可预测**：不等式对 c 单调，c=1 时任何删除都划算（R>0, B>0），c 很小时只有大块、早删才划算——这直接解释了为什么同一方法在不同价格下结论相反。
- **own-cache 记账隔离了测量污染**：只计运行自己早期请求产生的缓存前缀（Ht = min(Pt, LCPt)，LCPt 为与上一请求的最长公共 token 前缀），使成本成为运行自身的属性。
- **固定动作重放分离两种代价**：把未掩蔽轨迹的动作按掩蔽规则重放一遍，得到的账单差是纯记账效应；与真实掩蔽运行的差是行为效应。这是一个会计恒等式而非因果中介分析——论文对此边界非常诚实。

## 四、问题解法

论文的解法是一个测量框架 + 五组预注册实验，可以类比成把临床双盲试验的方法学搬进 Agent 评测。

### 4.1 组件一：三流记账与 own-cache 审计

类比：会计上把现金流拆成经营/投资/筹资三流分别报告，而不是只看总额。论文对每次运行的每个请求，用服务模型自己的 tokenizer 计算与上一请求的最长公共 token 前缀，只把这部分计为缓存命中。vLLM 按 784-token 块上报命中，会比逐 token 计数少约 9.8% 的命中；Qwen3-Coder 的服务端还会复用上一轮回复（83% 请求），这些口径差异都被显式记录（Section K）。

**并发缓存共享偏差**是本文发现的重要测量陷阱：消融实验的多个条件共享采样种子、在同一服务器并行运行，前缀相同的条件会互相预热缓存。在 Verified 上，剔除兄弟条件贡献的命中后，证据包的成本溢价从 +8% 跳到 +36%（单独跑预注册复核为 +29%）。这相当于对照组沾了实验组的光——任何并行的成本消融都可能被系统性美化。

### 4.2 组件二：盈亏不等式与 break-even masking

类比：库存管理中的经济订货批量——补货省的持有成本要大于一次补货的固定成本才值得下单。删除 B 个 token 省的是后续 R 次请求的缓存价，付的是 S 个后缀 token 的一次性重算。论文把这个不等式直接做成策略：**break-even masking（MAR）**——每当不等式成立，就把最新 10 条之外的旧观测一次性批量掩蔽。剩余请求数 R 用先导实验的剩余步数分布估计（R = min(250−t, max(59−t, 25))）。

### 4.3 组件三：预注册受控实验协议

类比：临床试验的预注册——任务集、条件、主假设、检验方向、多重校正（Holm）在跑实验前写进带日期的内部研究记录，未获支持的假设照报（Table 3 完整列出，包括 12 项 not supported）。单元分析是任务：任务内平均重复运行、任务间配对、2,000 次 bootstrap 置信区间。所有条件共享 prompt、采样设置与按任务固定的种子。

### 4.4 组件四：固定动作重放（replay）

类比：财务上的静态预算 vs 实际发生额对比。对每条未掩蔽轨迹，按掩蔽规则重建每个请求的 prompt 并重新记账（复现率 99.6–100%），得到若动作不变掩蔽本身值多少钱（直接项）；真实掩蔽运行与重放的差值就是 Agent 行为反应的代价（行为项）。

### 4.5 实验平台

- **基准**：SWE-bench Verified、SWE-bench test（80 题）、Loc-Bench（224 题）；确认实验只用从未用过的新任务（219 / 201 个 fresh 任务）。
- **脚手架**：自建最小 bash agent（50 步 / 64K 上下文）、mini-SWE-agent 2.4.6（官方 prompt 与提交协议）、SWE-agent 1.1.0（第三方复核）。
- **模型**：7 个开源模型三大家族（主力 Qwen3.6-27B，加 Qwen3-Coder-30B-A3B、Qwen3.5-4B/9B、Qwen3.8-27B、Gemma-4-26B-A4B、GLM-4.7-Flash），vLLM 本地服务，总计 20,000+ 次运行。
- **质量**：官方 SWE-bench harness 打分为主，可执行沙箱本地分辨率为辅，二者分开报告。

## 五、评估指标与实验证据

### 5.1 指标体系

| 类别 | 指标 | 定义与方向 |
|------|------|-----------|
| 主指标 | 成本变化（按价格向量） | cost(c,p) 相对基线的百分比变化，c ∈ {0.1, 1}、p = 4，另有 c ∈ {0.025–1} × p ∈ {2–8} 网格 |
| 行为指标 | read+search 命令数 | 每次运行的读/搜命令计数，衡量探索量，越少越好 |
| 质量指标 | resolved rate / on-target / Acc@10 | 官方 harness 分辨率（主）、编辑命中 gold 函数比例（廉价代理）、定位任务函数级 Acc@10 |
| 机制指标 | 缓存命中率、步数、re-fetch 次数、重放分解 | 解释成本变化的来源 |

### 5.2 加上下文：证据包实验（Section 4）

证据包 E5：稠密代码检索模型按 issue 文本排序函数，top-3 非测试函数全文展示 + 7 个按位置列出，代码图检索器补充相关代码，总量 ≤1000 行（约 14K token）；在首次编辑或第 8 轮换成位置索引。

| 对比（vs 无证据 E0） | read+search | 成本 c=0.1 | 成本 c=1 | 分辨率 |
|------|------------|-----------|---------|--------|
| Verified, 80 任务 | −32%（−6.64/次） | +36% | +25% | +3.8pp（官方） |
| Verified, 219 fresh（预注册） | −26%（−4.87/次） | +42% | +29% | +0.0pp（±5pp 等价） |
| SWE-bench test | −26% | +42% | +33% | −1.9pp |
| 等长随机代码 E5r | +0.68（无效） | — | — | 对照成立 |
| 保留到结束 E2 | — | — | — | 成本 +80~127% |

三个关键结论：(1) 探索确实减少了——且效果来自相关性而非长度（随机代码无效）；(2) 成本反而上升 33–42%，因为 14K token 的证据每轮都要付缓存价；(3) 分辨率无可测提升——oracle 编辑位置给 +5.8pp 但 p=0.065 未过显著性。机制分析显示：无证据的 Agent 本来就不会展示证据包 80% 的内容，另有 7% 三条命令内就能自己找到，真正省下的只有那 12% 需要挖的行（与节省量相关 ρ=+0.27）。

**互补性发现**：把检索排序免费附加到 Agent 自己的定位答案后面（不进 prompt），184 个 held-out Loc-Bench 任务上函数 Acc@10 从 0.386 升到 0.538（比 Agent 单独高 15.2 点、比检索单独高 12.0 点），三个模型全部复制（+14.1~+20.1）。零 token 成本的互补，胜过 14K token 的堆料。

### 5.3 删上下文：掩蔽实验（Section 5–6）

rolling masking（MM10，Lindenbauer 推荐设置）在 201 个 fresh Verified 任务、两个模型上的预注册结果：

| 设定 | c=0.1 | c=1 | 质量变化 |
|------|-------|-----|---------|
| mini-SWE-agent, Qwen3.6-27B | **+116%** | −19% | −0.5pp |
| mini-SWE-agent, Qwen3-Coder | **+87%** | −25% | +2.0pp |
| SWE-agent, Qwen3.6-27B | **+101%** | −29% | −0.9pp（本地） |
| GLM-4.7-Flash | **+38%** | −36% | +3.5pp（本地） |
| Gemma-4-26B-A4B | **+56%** | −19% | +6.2pp（本地） |

四组主检验全部支持——**符号随价格翻转**，实测交叉点 c≈0.19–0.55。机制：rolling 每轮都在不同位置改写 prompt，缓存命中率从 82% 跌到 38%。

break-even masking（MAR）把溢价压到 +2.8%/+1.8%（c=0.1），c ≥ 0.25 时省 10–26%。在运行很长（平均 171 步）的 GLM-4.7-Flash 上，MAR 通过非劣性检验（比不管理省 12.7%），本地分辨率反而 +7.8pp——因为它避免了 21/115 次的上下文溢出失败（降到 4–6 次）。

六方法重评估（201 任务 × 3 模型 × 6 方法，3,618 次运行）显示：LLM 摘要（MS）也会随价格翻转（Qwen3.6：c=0.1 +22%、c=1 −14%）；AgentDiet 式反思（MD）在 c=0.1 三模型全部更贵（+29~36%）且 c=1 也不省；两价格下成本排名的 Kendall τ 仅 +0.07~+0.47——**从 token 数或单一价格得出的方法排名，在另一价格下对 2/3 模型不成立**。33 种方法×模型×脚手架组合中，无一在当前 API 价格四角（c ∈ {0.025, 0.1}, p ∈ {4, 6}）全域更便宜。

### 5.4 重放分解：钱花在哪了

| 设定 | 规则 | 总溢价 | 直接项（断缓存） | 行为项 | 额外步数 |
|------|------|--------|----------------|--------|---------|
| mini, Qwen3.6-27B | rolling | +116% | +90% | +26% | +5.3 |
| mini, Coder | rolling | +87% | +86% | +1.2% | −0.1 |
| SWE-agent, 115 | rolling | +101% | +52% | +49% | +23.7 |
| SWE-agent, 115 | batched | +24% | −21% | +45% | +23.2 |
| SWE-agent, 115 | break-even | +9.6% | −15% | +25% | +23.4 |

读懂这张表：rolling 的钱大头烧在断缓存上；batched/break-even 若动作不变本可省 3–22%，但 Agent 对信息缺失的行为反应（重新获取被掩蔽的内容：每 run 多 1.5–3.0 次读、1–2 次搜索；SWE-agent 里多跑 23–28 步）把节省全部吃掉。只有 12% 的观测 token 是可证明过期的——删掉那些只省 4.6%（c=1，固定动作）。

### 5.5 测量偏差清单（Section O）

论文最后给出成本实验的六条评测清单：三流分报；own-cache 逐 token 记账；说明缓存块大小与回复复用；避免并发共享前缀（或校正）；报告评测噪声（单次评测均值的相对标准误 3–4%）；按价格区域联合推断。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

本文的优势是测量框架的揭示力，其因果链如下：

1. **token 数 ≠ 成本**：方法差异（三流价格向量 vs 单一 token 计数）→ 机制变化（缓存命中价是全价 1/10 时，省 1 个缓存 token 的收益是 0.1，而断缓存重算 1 个 token 的代价是 0.9——九倍不对称）→ 指标差异（同一 rolling masking 在 c=1 省 19–36%、c=0.1 涨 38–116%）。【论文实验已支持，四组预注册检验】
2. **局部改动的全局代价**：前缀匹配的逐字节严格性意味着改动点之后全部后缀重算。rolling 每轮改动一次 → 命中率 82%→38% → +90% 直接溢价。【论文实验已支持，重放分解】
3. **Agent 的行为补偿**：被删的信息会被再获取——Qwen3.6 上 rolling 每 run 多 2.0 次 re-fetch、多 5.3 步；SWE-agent 里 masked 运行从 92 步涨到 116 步。盈亏不等式假设动作固定，看不见这笔钱。【论文实验已支持，Section Q 配对分析】
4. **并发条件互相预热缓存**：共享前缀的兄弟条件贡献 3.7–6.7% 的 prompt token 命中，系统性美化干预组（+8% vs +36%）。【论文实验已支持，隔离重跑复核】
5. **检索的价值形态判断**（阅读者推测，部分有论文证据）：证据包缩短的是找答案的搜索，而非判断答案对错的能力——分辨率不变、蒸馏实验（Section M）中学生模型学会的也只是早提交少检查（提交率 +20pp、编辑后检查 4.19→1.83 次、分辨率持平），二者互为镜像。

### 6.3 综合判断与未决问题

**多研究共同支持的机制**：(a) 缓存命中是 Agent 成本的主导变量（本文、Weinberger & Hozez、Lumer、TraceLab 四方独立证据）；(b) 破坏前缀连续性的局部压缩会适得其反（本文、Song、TokenPilot）；(c) 删信息诱发行为补偿（本文重放分解与 Liu 的独立发现同构）。

**仍属推测的部分**：检索证据只省搜索不省判断的证据链，主要来自单一检索设计与 Qwen 系模型；Gemma 上探索减少不复现（+0.46），说明模型行为与证据暴露的耦合（Gemma 第 2 步就写脚本触发索引替换）可能改变结论。

**适用条件与失效条件**：盈亏不等式在缓存免费（c→1）或运行极长（R 大，如 GLM 的 171 步）时倾向删除；在缓存极便宜（c=0.025）或运行很短时倾向保留。闭源前沿模型、长思考预算、供应商特有的过期/写费/断点机制均在本文边界之外——作者自己列出了这些限制。一个开放问题：停止策略（何时结束运行）与上下文删除作用于同一条昂贵的尾部，二者的交互尚未被测量。

## 七、必要知识反推

假设让一个零背景的人重做这项研究，最少需要知道什么？

### 7.1 领域知识层

- **编码 Agent 的运行机制**：多轮循环、命令+输出追加进历史、每轮重发全历史——不理解这个就无法理解为什么 token 成本随轮数复利增长。
- **Prefix caching 的工程语义**：逐字节前缀匹配、块粒度（vLLM 784-token 块）、回复复用与否——不理解就无法实现 own-cache 记账，也无法发现并发共享偏差。
- **API 计价结构**：三流三价、缓存写入溢价、输出倍率——这是成本公式的直接来源。

### 7.2 方法论知识层

- **预注册与多重校正**：假设先于数据固定、Holm 校正、非劣性检验（带预设边际）——这保证 20,000 次运行里挖出的结论不是 p-hacking 产物。
- **配对设计与 bootstrap 推断**：任务为分析单元、条件内平均、任务间配对、2,000 次重采样。
- **盈亏分析的一阶建模**：从删除的 token 经济学推出 RcB > (1−c)S 并闭式化交叉点 c*——这是把测量变成可复用规则的关键一步。

### 7.3 工程知识层

- **可复现实验基建**：本地 vLLM 服务、代理记录每个请求并按服务模型 tokenizer 精确重切、无 Docker 的按版本可执行环境（Django 3.0–5.0、SymPy）。
- **轨迹重放技术**：给定规则重建历史 prompt 并复记账单（99.6–100% 复现率）——这是直接/行为分解的实现基础。

### 7.4 知识融合的关键节点

最有创造性的一步是**把服务系统的缓存语义（工程知识）嫁接到评测方法学（方法论知识）上**：多数研究者二者居其一，而 own-cache 记账与并发偏差的发现需要同时理解 vLLM 怎么命中缓存、以及消融实验怎么被污染。第二个节点是**会计恒等式思维**：把总成本差拆成直接项与行为项不是因果推断的标配工具，而是从财务分析借来的视角。第三个节点是不等式的双向使用：既当分析工具（解释符号翻转）又当策略（break-even masking），一个公式两处落地。

## 八、论文中可以提取的通用性灵感

**灵感一：计量单位错了，优化方向就反了**

核心思想：当系统存在差异化定价（缓存/未缓存/输出三流三价）时，用聚合单位（总 token 数）做优化目标可能系统性地指向错误方向。
论文证据：rolling masking 省 19–36% 的 token 预算（c=1）却多花 38–116% 的钱（c=0.1）；AgentDiet 的 token 记账收益在账单口径下消失。
推广场景：(1) 数据库优化里逻辑读 vs 物理读的计价差异；(2) 混合云中出口流量与内部流量的价格差；(3) CDN 回源与边缘命中的成本核算；(4) 端侧推理中内存带宽 vs 计算的能耗定价；(5) 任何有冷热路径分层计费的系统调优。

**灵感二：局部最优不等于全局最优——改写历史有一次性重算代价**

核心思想：对一个增量复用结构的任何中段修改，会使修改点之后的全部内容失去复用资格；省下的重复使用费必须覆盖一次性重建费才划算。
论文证据：RcB > (1−c)S 不等式及其实测交叉点；batched（十轮一删）远优于 rolling（每轮一删）。
推广场景：(1) 增量编译/构建缓存——改头文件触发全量重编；(2) 浏览器资源缓存失效策略；(3) 分布式系统的写放大（LSM-tree 的 compaction 时机）；(4) 版本控制中 rebase vs 追加提交的成本；(5) 知识库更新时全量重嵌入 vs 增量嵌入的选择。

**灵感三：被干预的对象会反击——测量必须包含行为反应**

核心思想：对自适应系统的任何干预，其真实成本 = 记账成本 + 系统行为变化的成本；只看前者会高估收益。
论文证据：固定动作重放显示 batched/break-even 本可省 3–22%，但 Agent 的 re-fetch 与 23–28 步额外运行吃掉全部节省。
推广场景：(1) 经济政策的价格管制诱发黑市与囤积；(2) 推荐系统改动的用户适应（先尝鲜后疲劳）；(2) 代码重构对下游调用方的连锁维护成本；(4) 压缩感知中丢信息后重建的计算代价；(5) 组织流程精简后隐性协调成本上升。

**灵感四：并行实验不是无干扰的——共享资源会系统性美化干预组**

核心思想：并行运行的实验条件若共享可复用的中间产物，后到的条件会搭先到条件的便车，产生向干预组倾斜的偏差。
论文证据：并发条件互相预热缓存，证据包溢价被低估四倍（+8% vs +36%）。
推广场景：(1) A/B 测试中共用连接池/缓存的相互干扰；(2) 竞争同一 GPU 的并行训练任务计时失真；(3) 共享微服务依赖的级联限流效应；(4) 基准测试的页表/分支预测器预热污染；(5) 多租户数据库的缓冲池竞争。

**灵感五：免费附加优于付费堆料——信息注入的位置决定其成本**

核心思想：同样的信息，放在 prompt 里每轮付费，附加在输出端则零边际成本；注入位置本身是一个设计变量。
论文证据：14K token 证据包进 prompt 成本 +33–42% 且分辨率不变；检索排序免费附加到 Agent 定位答案上，Acc@10 +14~20 点、零 token 成本。
推广场景：(1) 搜索系统的 query 改写 vs 结果重排的成本差异；(2) 教育中前置灌输 vs 按需提示的学习成本；(3) API 设计中宽接口 vs 窄接口加组合层；(4) 人机协作中的检查清单前置 vs 检查点后置。

**灵感六：结论要按参数区间陈述，而不是给单点答案**

核心思想：当结论依赖外部价格/环境参数时，应该报告盈亏边界（break-even）而非单一设定下的胜负。
论文证据：论文所有结论都按 c 的区间陈述（如 batched 在 c ≥ 0.25 时更省），并给出闭式交叉点；33 组合在四角价格无一全域占优。
推广场景：(1) 硬件采购按电价/利用率区间给方案而非单点推荐；(2) 云资源选型按负载波动区间给 reserved/on-demand 配比；(3) 药物剂量按人群亚组给有效边界；(4) 算法选型按数据规模给切换点；(5) 投资策略按利率环境给区间配置。
