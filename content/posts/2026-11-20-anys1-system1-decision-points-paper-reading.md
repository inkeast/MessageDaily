## 一、论文背景

### 1.1 LLM Agent 的成本困境：每一步都在"深度思考"

现代 LLM agent（基于 ReAct 等范式）在执行长程任务时，习惯把大模型（System-2）当作万能引擎：每一步——无论是写代码、规划下一步，还是判断"这个搜索结果相关吗"——都要把不断膨胀的轨迹上下文发给大模型推理一遍。这带来两个直接后果：**延迟随轨迹长度累积攀升**，**token 成本随步数线性爆炸**。论文引用 Kapoor et al. (2025) 的批评：学术界 agent 基准的成绩往往是在忽视成本延迟的条件下刷出来的。

关键观察是：agent 工作流里的许多中间步骤并非开放生成，而是**从一小撮已知选项中选一个**——判断 UI 请求属于"设计、构建、评审还是修复"、检查搜索结果是否包含目标品类、确认预算是否超标。这类有界判断用大模型做，就像用卡车送外卖。

### 1.2 双系统理论与"快慢模型"分工

认知科学家卡尼曼在《思考，快与慢》中把人的认知分为两个系统：System 1 快速、自动、直觉，System 2 缓慢、审慎、费力。这一框架已被大量引入 LLM agent 研究：SwiftSage（NeurIPS 2023）用小模型做快速动作提议、GPT-4 做慢速规划；Dualformer 在单一 Transformer 内集成快慢两种推理模式；System-1.x 学习在快慢规划间平衡。这条路线的共同目标是：**让便宜快速的系统处理常规判断，把昂贵的 System-2 留给真正需要深思的环节**。

### 1.3 类型化决策模型：不生成文本、只做判断的"新物种"

2026 年 9 月，TypeSafe AI 公司（前 OpenAI 研究员 Diogo Almeida 创立）发布商业模型 Jev，定位为首个"System One 模型"：不聊天、不生成文本，输入非结构化状态和一组类型化问题（Choice 多选 / Score 打分 / Noul 布尔），一次前向输出带校准概率的决策结果，宣称比大模型快 20–200 倍、便宜 40–400 倍。开源社区随之出现 Kev、AnyJev 等开放权重复现。这类"类型化决策模型"为双系统 agent 提供了理想的 System-1 候选。

### 1.4 现有双系统 agent 的瓶颈：每个工作流都要"手工挂钩子"

已有的快慢结合系统（SearchJev 用于搜索 agent、AgentDecision 用于工具选择、REFLEX with Jev 用于选择性控制等）都依赖**为单一固定工作流人工预设决策点（hook）**：工程师挑选该工作流在哪里需要判断、有哪些选项，再在这些硬编码挂钩处收集训练监督，训出一个专用 System-1。工作流 A 训出 S1A，工作流 B 训出 S1B——换一个场景就要重来一遍工程。当通用 agent 面对没有预声明挂钩的新工作流时，所有判断只能退回 System-2，快模型的优势归零。

### 1.5 机遇：Agent Skills 生态爆发

Anthropic 于 2025 年 10 月推出 Agent Skills：把"怎么做某件事"的程序性知识打包成含 SKILL.md 的文件夹（附脚本、参考文档、模板），agent 按需加载。2025 年 12 月该格式发布为开放标准，OpenAI Codex、Gemini CLI、Cursor、VS Code 等数十个工具跟进。公开仓库已积累超过十万个技能（SkillMD-138K 数据集收录 13.8 万份）。技能天然是"程序性"的：其分支与检查点**隐式定义了在哪里需要判断、在哪些选项间判断**。这构成一个天然、跨领域、无需人工逐工作流工程的决策点矿藏——AnyS1 的出发点正在于此。

## 二、论文定位和关联工作

### 2.1 谱系一：Agent 技能与工作流编译

一条线研究 agent 如何检索、遵循、内化技能（SkillRL、SKILL0、Skill Following 等），或从技能语料合成轨迹微调生成式策略（AgentTuning、SkillGym、SKT 等）；另一线把自然语言程序编译为显式程序：DSPy 编译声明式调用、HEXIS 把技能编译为扩展有限状态机、SkVM/SkillSmith 编译为运行时接口、SCOPE 编译为神经符号谓词程序。

**关键区别**：此前技能学习把整个技能当作单一提示或轨迹级目标喂给一个生成模型；编译型工作流在语义分支处仍依赖 LLM 调用、静态规则或未校准的启发式守卫。AnyS1 把粒度下沉到**技能内部的单个决策**：跨技能挖掘可枚举决策点、采集真实执行状态、训练一个校准的通用 System-1，把编译后的技能执行变成 System-1 与 System-2 协作的工作流。

### 2.2 谱系二：类型化决策模型与校准回退

商业 Jev 之后，开放工作或在开源 LM 上挂 pointer/决策头（Kev 面向通用选择、SearchJev/AgentDecision 面向特定 agent 状态），或用循环置换读出去偏概率（AnyJev 缓解选项顺序敏感）。基于这些模型的双系统 agent 通过选择性回退（selective deferral，理论根基是 Geifman & El-Yaniv 的选择性分类）加速搜索与工具调用。

**关键区别**：这些系统的决策点均来自单一工作流的手工挂钩。AnyS1 将范式泛化为从技能库自动挖掘决策点，配合 label smoothing 校准的单个 System-1，支持无标注开发校准（AnyS1^warm）或零样本阈值迁移（AnyS1^cold）。

### 2.3 定位对比表

| 维度 | 既有双系统 agent | 技能编译系统 | **AnyS1** |
|------|------------------|--------------|-----------|
| 决策点来源 | 人工为单一工作流预设 hook | 编译产物但分支处仍调 LLM | 从 1,072 个公开技能自动挖掘 |
| System-1 数量 | 每工作流一个专用模型 | 无（或未校准启发式） | 单个通用 4B 模型跨所有技能 |
| 训练监督 | 仅在硬编码 hook 处收集 | — | 容器真实执行状态 + 双教师共识 |
| 置信度处理 | 多数未校准或逐任务拟合 | — | label smoothing 内建校准 + 冷/热两档阈值 |
| 跨 System-2 迁移 | 未见验证 | — | 同一 System-1 权重跨 DeepSeek/GPT-6 两族复用 |

**定位结论**：AnyS1 是"决策点供给方式"的范式转换——从"每工作流手工工程"到"从技能生态一次性挖掘共享决策点"，可视为把 JevAgentHarness（下文详述）验证过的校准委托机制嫁接到技能挖掘的通用数据源上，实现零 per-workflow 工程的双系统执行。

## 三、问题定义

### 3.1 从具体场景到抽象结构

具体场景：一个通用 agent 加载任意技能执行任务，希望中间的常规判断不再逐次调用大模型。深层洞察是：**程序性技能的文档结构天然编码了"判断点"的三个要素——在哪判断（分支位置）、判断什么（问题）、在什么选项间判断（候选集）**。把这三要素从非结构化散文中抽出来，判断问题就退化为一个"状态 + 问题 + 选项集 → 选项分布"的打分问题，恰是类型化决策模型的舒适区。

### 3.2 D/E/G 三类节点的形式化

AnyS1 按"任务类型 + 决策复杂度"把工作流步骤分为三类节点：

| 节点类型 | 定义 | 执行者 | 类比 |
|----------|------|--------|------|
| **D（deterministic）** | 由结构化状态完全确定（如固定工具调用、预算检查） | 直接跑代码，零 token | 程序里的 if/for |
| **G（generative）** | 开放式生成（写批评、拟查询） | System-2 | 老司机也会遇到要动脑的路 |
| **E（enumerable）** | 读非结构化内容、从有限候选集选一（技能中固定或可从状态列出），始终附"以上皆非" | System-1（置信度足够时） | 多选题 |

每个 E 节点形式化为决策点模板 (q, O, d)：问题 q、带一句话定义 d(o) 的选项集 O（含"以上皆非"）；在运行状态 s 处触发，构成实例 x = (s, q, O, d)。

### 3.3 目标函数

记单集成本 C 与全 System-2（All-S2）成本 C_S2，可分解为：

C/C_S2 ≈ (1−s_E) + C_E/C_S2 + κ

其中 s_E 是 E 节点在 All-S2 成本中的占比，κ 是 System-1 自身开销。**问题定义**：仅用技能语料挖掘的监督（不用目标工作流任何数据），学一个泛化到未见技能的决策模型 f，配合轻量校准门 g，在保持任务成功率不低于 All-S2 的约束下，尽可能压低 C_E 项——即逼近 s_E − κ 的节省上界。这个定义的精妙之处在于它把"省多少"的 ceiling（E 节点成本占比）和"靠什么省"（委托给多快的模型）解耦，后面 RQ3 的分析直接建立在此分解上。

## 四、问题解法

AnyS1 框架分离线构建（Any-DP 数据集 + System-1 训练）与运行时（编译执行 + 置信度门控）两阶段。离线所有 LLM 步骤用 DeepSeek-V4.1-Flash。

### 4.1 离线第一步：从 SKILL.md 挖掘决策点模板

类比"考古发掘"——技能散文里埋着判断点，需要带着"逐字证据"挖出来：

- **三遍独立抽取**：LLM 分析器独立阅读 SKILL.md 及捆绑文档三次，返回带类型的候选决策点，每个必须附**逐字支持引文**（exact string match 对技能原文验证），防止幻觉；
- **合并与置信**：LLM 合并三遍等价点，记录支持度 σ(p)∈{1,2,3}，逐字段取多数，从技能文本为每个选项写一句话定义以区分同名选项；
- **过滤**：保留 σ(p)≥2、可仅从状态回答、含至少两个候选加"以上皆非"的 E 节点。

### 4.2 离线第二步：容器执行采集真实状态

模板只回答"判断什么"，训练还需要**真实运行时状态 s**。直接让 LLM 捏造状态会得到整洁的散文摘要，与真实轨迹上碎片化的工具输出（截断的终端输出、多文件用户消息）严重失配。AnyS1 的方案是"真跑一遍"：

1. **任务合成**：为每个技能（预先在仓库级切分训练/保留集防泄漏）生成自包含多阶段任务——含输入文件、参考解、隐藏 verifier，外加两个跨类干扰技能，迫使 agent 既选对技能又跨依赖阶段推进；任务只有在网络隔离容器中"verifier 拒绝初始文件、接受参考解"才保留；
2. **轨迹执行**：OpenHands agent 在隔离容器中执行验证过的任务，LLM 定位器将轨迹对齐到技能决策点，**逐字提取**每个决策出现处的前置观测（任务指令、用户消息、原始工具输出，排除 agent 自身推理）；
3. **双教师共识标注**：因执行 agent 自身动作可能次优、单遍 LLM 教师有选项顺序偏差，对每个状态跑两遍独立教师（第二遍反转选项顺序），仅保留 y1=y2 的顺序不变共识样本。

在 SkillMD-138K 的 1,072 个公开技能（16 个类别、仓库级去污、排除所有评测相关技能）上跑完流水线，得到 **Any-DP**：17,865 个类型化决策点（D/E/G 占比 21.3/64.5/14.2%）、2,846 个容器验证任务、25,986 个共识标注样本，教师一致率 89.2%。两个关键统计：E 节点占全部工作流节点的 64.5% 且 **100% 技能至少含一个 E 节点**（有界判断无处不在，节省空间巨大）；64.6% 的 E 节点需要语境语义推断而非字面查找（17.8%）——静态规则无法替代学习出来的 System-1。

### 4.3 离线第三步：校准 System-1 训练

- **架构**：Qwen3.5-4B-Base + rank-16 LoRA（α=32，覆盖 attention/MLP/Gated DeltaNet 投影）。输入按结构化分隔符序列化为 ⟨s⟩状态; ⟨q⟩问题; ⟨opt⟩选项:定义⟨/opt⟩×n; ⟨dec⟩。**选项交互 pointer 头**：取 ⟨dec⟩ 隐状态与 n 个 ⟨/opt⟩ 隐状态过一层位置无关双向自注意力（候选选项互相看见彼此）再用 2× MLP 与 ⟨dec⟩ 匹配，softmax 输出选项分布；残差投影零初始化使初始 logit 与标准 pointer 头一致。
- **校准目标**：运行时回退依赖 p_f 反映真实正确率，而硬标签交叉熵导致过自信（Guo et al. 2017 的经典发现），故直接在训练中内建 label smoothing（ε=0.1，Müller et al. 2019）：L = Σ CE(p_f, (1−ε)e_y + εu_O)。
- **训练配置**：1 epoch、bf16、lr=1e-4。

### 4.4 运行时：置信度门控的双系统执行

编译后的技能工作流按节点类型分流：D 节点跑代码（零 token）；G 节点交 System-2；E 节点由 System-1 单次前向打分，最大概率 c(x) 过阈值 τ 则采纳、否则回退 System-2：g(x) = I[c(x) ≥ τ]。τ 的两种确定方式（都在测试前固定）：

| 模式 | 校准数据 | 机制 | 适用场景 |
|------|----------|------|----------|
| **AnyS1^cold** | 153 个保留开发技能状态 | 拟合单一全局 τ=0.918，逐基准原样使用 | 全新工作流、零目标域执行 |
| **AnyS1^warm** | 50 条无标注开发 episode | System-2 全答 E 节点、旁录 System-1 分数，对齐 System-2 决策拟合 τ（目标 ≥95% 一致） | 已部署工作流、无人工标注 |

换 System-2 骨干（Flash→Sol）时 System-1 权重完全不动，仅 AnyS1^warm 重拟合 τ。

## 五、评估指标与实验证据

### 5.1 评测体系设计

- **基准（均为未见域，与 Any-DP 零技能重叠）**：SOPBench（268 个保留任务，多轮客服对话、程序与数据库硬约束，指标 Pass %）；ALFWorld（134 个未见文字家庭任务，多房间搜索操纵，指标 SR %）；WebShop（500 条用户指令、118 万商品目录、15 步上限，指标 Score 0–100 与二值 SR %）。三个域分别覆盖"策略约束对话、部分可观测具身搜索、噪声网页导航"。
- **效率指标**：相对未编译 System-2 agent（同骨干）的每集成本节省 Sav.%（System-2 按官方 API 牌价、4B System-1 按 L4 自托管吞吐 $0.0045/千次单遍决策计价）；每集关键路径模型调用时间 Time(s)。所有配置与 All-S2 共享精确请求缓存，运行只在 System-1 答处分叉——保证差异可归因。
- **四个研究问题**：RQ1 省钱提速不掉成功率？RQ2 门控/真实状态/校准损失各自贡献？RQ3 节省由什么决定？RQ4 置信度选对了该委托的决策吗？

### 5.2 主结果（RQ1）

DeepSeek-V4.1-Flash 作 System-2：

| 配置 | SOPBench Pass | ALFWorld SR | WebShop Score/SR | 平均节省 | 结论 |
|------|---------------|-------------|-------------------|----------|------|
| 未编译 agent（基线） | 55.2 | 82.8 | 54.9/34.4 | — | 参照系 |
| Compiled All-S2 | 83.2 | 96.3 | 66.9/38.0 | 81% | 编译本身即 +18 点效果 |
| Jev 作 System-1 | 84.0 | 96.3 | 67.1/38.6 | 84% | 商业基线 |
| **AnyS1^warm** | **84.3** | 95.5 | **68.1**/38.8 | **89%** | 超过 Jev 且免远程调用 |
| **AnyS1^cold** | 83.2 | 95.5 | 67.9/38.0 | 87% | 零目标域执行仅让出 0.1 平均点 |

关键路径模型时间：AnyS1^warm 相对未编译 agent 削减 70–92%（All-S2 只做到 51–87%）。换 GPT-6 Sol 复现同一模式：编译省 71%，AnyS1^warm 提到 82%（75–91%）、时间降 63–84%，cold 省 81% 且距 All-S2 仅 0.8 平均点。**同一 System-1 权重跨两个 System-2 模型族无需重训**，说明 Any-DP 捕获的是工作流内在的决策语义而非教师特定先验。

值得注意的细节：WebShop 上 AnyS1^warm 的 Score（68.1）反而高于 All-S2（66.9）——单遍打分抑制了 System-2 在简单二元相关性检查上的过度审慎，"快而果断"偶可反超"慢而啰嗦"。

### 5.3 消融（RQ2）：三个组件缺一不可

| 消融维度 | 对照 | 结果 | 说明 |
|----------|------|------|------|
| 门控 | AnyS1^warm/cold vs **All-S1**（全委托） | ALFWorld SR 从 96.3% 崩至 40.3%；等委托率随机委托使 System-2 分歧多 4 倍以上 | 长程探索中一个错分支会级联失败，必须门控；短程 SOPBench 无门控也幸存 |
| 训练状态源 | Any-DP vs **LLM 捏造状态**（S1-syn，84,481 条、3.3 倍数据量） | 留出容器 Dev 集 83.8 vs 65.0（**+18.8 点**）；ALFWorld E +5.3 点 | 理想化摘要与真实碎片化工具输出的观测鸿沟，多数据也填不平 |
| 校准目标 | label smoothing vs 硬标签 CE / CE+Brier | 原始准确率几乎不变（82.4 vs 82.3/81.9），但 ECE 0.094 vs 0.146/0.148；门控一致率 97.7% vs 92.4–93.7%；硬标签使阈值膨胀到 τ=0.998 | 无平滑的 logit 在陌生状态上也饱和到概率 1.0，置信度失去排序意义 |

### 5.4 节省由什么决定（RQ3）与置信度选择（RQ4）

- **E 节点份额决定天花板**：按成本分解归一化，E 节点占未编译成本的 17–22%（ALFWorld/WebShop）而 SOPBench 仅 4%——AnyS1^warm 在 SOPBench 几乎委托全部 E 节点后逼近该界；
- **单遍打分兑现速度**：本地 System-1 每决策中位 21.8–31.7 ms（H100 实测），比 System-2 的 E 调用（1.51–1.78 s）快 56–81×，也快于商业 Jev 远程往返（0.65–0.67 s）；System-1 运行时间仅占未编译每集时间的 0.2–0.3%；
- **置信度排序而非委托量保正确**：对 All-S2 的测试 E 决策扫 τ 得操作曲线，同等覆盖率下置信度门控与 System-2 的一致率远超随机子集（AURC 低 2–6×）。在线阈值处：ALFWorld 委托 50% 达 92.4% 一致（随机 68.2%）；WebShop 委托 41% 达 84.3%（随机 69.8%）；SOPBench 委托 98%。但一条全局 τ 无法通吃所有域：cold 的 τ 在 SOPBench 偏保守（40% 委托、100% 一致）、在 WebShop 偏激进（55% 委托、80.0% 一致）——工作流各异的操作曲线解释了 warm 校准的价值（20 条开发 episode 即可逼近全量拟合）。

### 5.5 指标如何支撑主张

实验设计与论点的对齐度高：跨三域未见基准 + 跨两 System-2 族 → 支撑"通用 System-1"主张；共享请求缓存协议 → 成本差异严格归因于 System-1 接管；预注册阈值 → 杜绝测试集调参；成本分解（式 1）→ 把"节省上限"变成可计算量而非口号。短板在于 AnyS1^warm 的基线节省中编译贡献（81%）大于委托增量（+8 点），论文对此做了诚实拆分。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**因果链 1：技能挖掘 → 决策点自动泛化 → 零 per-workflow 工程**
机制：SKILL.md 的分支/检查描述天然编码判断位置与候选集（论文实验：E 节点占 64.5%、100% 技能含 E 节点）；verbatim 引文验证 + 三遍共识（σ≥2）保证挖出的模板忠于真实工作流分支而非 LLM 幻觉。
证据等级：论文实验已支持（Any-DP 统计 + 跨三域零重叠基准仍保成功率）。"挖掘模板忠实度"本身未单独消融——属于阅读者推测的潜在薄弱点。

**因果链 2：容器真实状态 → 弥合观测鸿沟 → 跨域准确率**
机制：真实轨迹状态是碎片化、截断、多源的；LLM 捏造状态是理想化散文。System-1 在前者上训练才见过真实输入分布。数据量 3.3 倍的捏造状态仍差 18.8 点——**是分布差异而非数据量差异**在起作用。
证据等级：论文实验已支持（Table 3b 三种子对照）。

**因果链 3：label smoothing → 防域外置信度饱和 → 阈值可迁移**
机制：硬标签 CE 把 logit 推向概率 1.0，即使对陌生状态——置信度丧失区分"会与不会"的排序能力；平滑保留均匀概率质量，使 dev 上拟合的阈值语义可跨域迁移（cold 的 τ=0.918 直接可用）。这与校准文献的经典结论（Guo et al. 2017：现代网络普遍过自信）一致。
证据等级：论文实验已支持（Table 3c：准确率不变、ECE 与门控一致率分化）。

**因果链 4：置信度门控按不确定性排序 → 拦截级联失败状态 → 保住成功率**
机制：长程任务中一个错误 E 分支改变后续全部状态分布，错误会复合（All-S1 在 ALFWorld 崩溃 96.3→40.3 即反证）；门控的价值在**挑对**委托对象（AURC 降 2–6×），而非降低委托量。
证据等级：论文实验已支持（操作曲线 + 随机委托对照）。

### 6.3 综合判断与未决问题

**多研究共同支持的机制**：(1) 校准置信度门控是双系统 agent 保成功率的前提（AnyS1 消融、JevAgentHarness 的 −19 点反例、System Switch 的 AUROC-收益相关）；(2) 训练数据必须来自真实 agent 执行状态（AnyS1 的 +18.8 点、AgentDecision-4B 的犯错后状态训练）。这两条在至少两个独立系统中重现，可信度高。

**仍属推测或单源支持的机制**：label smoothing 相对其他校准手段（温度缩放、Brier）的优越性仅有单源消融；"挖掘模板的 verbatim 忠实度"未独立评估；WebShop 上超过 All-S2 的 1.2 点可能含超参/方差因素，论文未深究。

**适用条件**：节省上限受 E 节点成本份额硬约束（生成密集型工作流获益有限）；编译为显式程序是前提，开放式仓库技能的自动编译仍是未解问题（论文自认）；warm 模式需要约 50 条 System-2 全答的开发 episode，冷启动阈值在部分域会过保守/过激进。**可能的失效条件**：候选集在运行时动态剧烈变化的技能、E 判断正确但依赖跨步骤隐式记忆的场景、System-1 与 System-2 判断相关性极高的域（委托收益趋零）。

## 七、必要知识反推

假设一个零知识的人要复现这项工作，最少需要掌握什么？

### 7.1 领域知识层

- **Agent 执行范式**（ReAct、轨迹、工具调用、状态累积）：不理解"每步都在调用大模型"就看不到成本问题；需要知道 OpenHands 等开源 harness 才能跑容器执行。
- **Agent Skills 生态**（SKILL.md 格式、渐进式披露、公开仓库规模）：不知道技能里藏着分支结构，就想不到"决策点可以挖"。
- **双系统认知理论**（Kahneman）：D/E/G 分类与委托-回退机制的概念骨架。
- **类型化决策模型原理**（pointer/决策头、单遍打分 vs 自回归生成）：System-1 的实现基础。

### 7.2 方法论知识层

- **校准理论**（过自信现象、ECE、label smoothing 的机制）：门控可迁移性的理论根基——不理解"硬标签驱动置信度饱和"就无法解释为何 ε=0.1 是关键超参。
- **选择性分类/级联**（Geifman & El-Yaniv、FrugalGPT 一脉）：委托规则 g 的设计空间与成本分解直觉。
- **LLM 标注偏差**（选项顺序偏差、循环置换去偏）：双教师反序共识标注的动机；Zheng et al. 2024 的"LLM 不是鲁棒的多选选择器"是必引前置。
- **数据集去污方法**（MinHash 去重、仓库级切分、基准排除）：跨域评估的可信度保障。

### 7.3 工程知识层

- **容器化沙箱执行**（网络隔离、verifier 设计"拒绝初始/接受参考解"的双向验证）：合成任务真实性的技术保障。
- **LoRA 微调与自托管推理**（rank-16 适配、L4 吞吐计价、H100 延迟测量）：4B 模型落地为"每千次 $0.0045、22–32 ms"的经济账。
- **评测协议设计**（共享请求缓存、预注册阈值、关键路径时间统计）：保证成本对比可归因、防测试集泄漏的实验纪律。

### 7.4 知识融合的关键节点

1. **洞察融合点**：把"技能 = 程序性分支文档"（领域知识）与"类型化决策模型 = 有限选项打分器"（方法论）对接，得出"决策点可以从技能里挖"——这是全文的创造性核心；
2. **数据融合点**：容器执行（工程）+ 反序双教师共识（方法论）结合，解决"真实状态从哪来、标签怎么可信"两个互相锁死的问题；
3. **部署融合点**：label smoothing（方法论）+ 阈值两档策略（工程）结合，让同一个模型同时服务"零样本新工作流"与"已部署工作流"两种场景——校准不再只是评测指标，而成为可迁移的运行时接口。

## 八、论文中可以提取的通用性灵感

### 灵感 1：把"专家系统"埋在文档里的判断点当作可开采资源

- **核心思想**：人类-written 程序性文档（SOP、runbook、技能文件）中隐式编码了大量结构化决策点，可以带逐字证据地挖掘成训练数据——文档即矿藏。
- **论文证据**：1,072 个技能挖出 17,865 个决策点、E 节点占 64.5%、100% 技能含 E 节点。
- **推广场景**：企业内部 SOP/工单处理手册 → 自动抽取路由规则训练分类器；法律法规文档 → 判定条件抽取；医疗指南 → 分诊决策点挖掘；游戏攻略 → NPC 行为决策树。

### 灵感 2：真实执行状态与生成式摘要之间存在不可忽视的"观测鸿沟"

- **核心思想**：用执行环境真实采集的状态训练小模型，比用 LLM 捏造的理想化状态好得多——数据分布的真实性比数量更重要。
- **论文证据**：3.3 倍数据量的捏造状态训练反而低 18.8 点。
- **推广场景**：机器人演示学习（真机遥操 vs 仿真合成）；推荐系统（真实曝光日志 vs 模拟用户）；对话系统（真实客服记录 vs LLM 角色扮演）；软件工程（真实崩溃堆栈 vs 合成 bug 报告）。

### 灵感 3：校准应内建于训练而非事后修补，且校准值本身是可迁移资产

- **核心思想**：label smoothing 让概率保留排序能力，使一个域上拟合的置信度阈值能零样本迁移到新域——置信度不只是评测指标，而是跨域可复用的运行时接口。
- **论文证据**：硬标签 CE 阈值膨胀至 0.998、门控一致率掉 5 点；平滑训练的全局 τ=0.918 在三个未见基准保住可靠性。
- **推广场景**：医疗 AI 分诊（阈值跨医院迁移）；内容审核（政策更新后阈值沿用）；自动驾驶接管决策（新路况下置信度门控）；任何"小模型先答、大模型兜底"的级联系统。

### 灵感 4：按不确定性排序的委托优于按委托量控制

- **核心思想**：委托/自动化决策的安全性来自"挑对哪些决策交给快系统"（置信度排序），而非"少委托一些"；等量的随机委托会放大错误。
- **论文证据**：同等覆盖率下 AURC 低 2–6×；All-S1（全委托）在长程任务崩溃；随机委托的 System-2 分歧多 4 倍。
- **推广场景**：人机协作审批流（低置信自动、高置信放行）；自动驾驶的干预请求；金融交易的人工复核触发；代码生成的测试优先级排序。

### 灵感 5：编译 + 委托是两个正交的效率杠杆，应分开度量

- **核心思想**：把非结构化流程编译为显式程序（结构性去 LLM 化）与把有界判断委托给快模型（模型层分工）贡献不同、可叠加，成本分解公式让各自上限可计算。
- **论文证据**：编译贡献 81% 平均节省与 +18 点效果；委托在其上再叠加至 89–91%。
- **推广场景**：RPA 流程再造（先固化流程再引入 AI 决策点）；数据管道优化（规则下沉为代码 + 模糊处模型兜底）；任何"确定性骨架 + 概率性判断"混合架构设计。

### 灵感 6：跨模型族复用要求监督信号来自"任务语义"而非"教师个性"

- **核心思想**：想让一个小模型服务多个不同的大模型骨干，训练数据应编码工作流内在的决策语义，而非模仿特定教师的风格偏好。
- **论文证据**：同一 System-1 权重在 DeepSeek-V4.1-Flash 与 GPT-6 Sol 两族下均保成功率（换骨干仅重拟合标量 τ）。
- **推广场景**：多供应商 LLM 应用的统一中间件；模型迁移成本评估（换骨干不动适配层）；跨平台助手的共享策略层。

## 附录：术语速查

- **System-1 / System-2**：借自卡尼曼双过程理论；本文中分别指 4B 类型化决策模型（单遍打分）与大 LLM（自回归生成 + 推理）。
- **E 节点 / 决策点模板 (q, O, d)**：可枚举判断及其"问题—选项—定义"三元组；运行时与状态 s 结合成实例 x。
- **AnyS1^warm / AnyS1^cold**：阈值 τ 分别用 50 条无标注开发 episode 校准 / 从 153 个保留状态拟合单一全局值（0.918）零样本迁移。
- **Any-DP**：1,072 技能 × 容器执行 × 双教师共识产出的数据集（17,865 决策点、25,986 样本）。
- **AURC**：风险-覆盖曲线下面积，衡量"置信度排序挑对委托对象"的能力，越低越好。
