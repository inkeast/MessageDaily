## 一、论文背景

### 1.1 LLM 的知识从哪里来：两条传统路径

大语言模型解决知识密集型任务，历来依赖两条路径。第一条是**参数化知识**：模型在预训练阶段把海量语料"背"进网络权重，好比学生把知识内化进了大脑。第二条是**检索增强生成（RAG）**：推理时挂一个外部检索器，把相关文档找出来塞进上下文，好比开卷考试——问题来了先翻书。

这两条路径对"事实查询"类任务足够：问"XX定理的内容是什么"，翻到那一页抄下来即可。但论文开篇就点出一个更深的场景：**在陌生领域解题**。这要求的不是"查到一条事实"，而是：

1. 理解一个没见过的新原理（它到底在说什么？前提条件是什么？）；
2. 判断它对当前问题是否适用（这个定理的假设我的问题满足吗？）；
3. 把它编织进一个正在演进中的推导过程（我推到一半发现缺一块前提，得回头补）。

这就像人类面对一门新课：不是翻书抄答案，而是**读教材、消化概念、再回来接着推**。论文把这种能力命名为**自学习（self-learning）**——在任务展开的过程中，自主地从参考资料中检索、研读并应用知识。

### 1.2 为什么现有范式做不到

**RAG/固定上下文范式的缺陷**：经典 RAG 是"先检索、后生成"的一次性流水线——检索发生在推理之前，检索什么完全由初始问题决定，与后续推理演化无关。可真实的解题过程是：推到一半才发现缺什么，这时候才需要回头查。检索与推理是**割裂**的。后来的 agentic RAG 与搜索智能体（如 ReAct 风格）允许交错推理与检索，但它们的目标通常是"找到事实碎片拼出答案"，而非"系统研读一份结构化的长篇材料并学会其中的原理"。

**上下文学习（ICL）范式的缺陷**：另一支研究考察模型能否从给定材料中学习（如 CL-bench），但材料是**预先组装好、直接喂到嘴边**的。模型不需要自己决定"学什么、去哪学、学到什么程度"。

**元强化学习/测试时适应的缺陷**：Reflexion 靠多次尝试间的语言反思，MCTR 靠测试时权重更新，SEAL 让模型生成自我编辑再微调自己。它们都需要**重复尝试的反馈**或**测试时的参数修改**。而论文追求的设定更朴素也更严苛：单次解题episode内、静态参考资料、没有重复尝试的纠错信号，模型必须自主决定研读什么。

### 1.3 一个被忽视的训练信号富矿：教科书

人类最好的自学材料是教科书——结构化、体系化、由浅入深。对 LLM 而言，教科书是天然的自监督语料：**书中每道习题都配有讲解（exposition），讲解与习题天然配对**。如果去掉参考答案，"读讲解→做习题"本身就是一个可自动验证的训练任务。这给强化学习提供了近乎无限的免费训练信号，而此前几乎没有工作系统利用这一点。

### 1.4 核心挑战：RL 训练中工具使用的崩溃

用 RL 训练模型使用检索工具，近年已被 Search-R1 等工作证明可行。但社区反复观测到一个顽固的失败模式——**工具使用崩溃（tool-use collapse）**：随着训练推进、模型解题能力增强，它会越来越多地"凭本事硬算"，越来越少地调用工具，最终退回纯内省推理。直觉上很好理解：答对了就有奖励，而不用工具也能答对的路径更短、方差更低，优化器天然偏爱它。但对真正需要学新知识的陌生问题，弃用工具就意味着断粮。这一机制性问题正是本文方法设计的主要靶点（第 4、6 节详述）。

## 二、论文定位和关联工作

### 2.1 谱系一：检索增强推理（RAG → 搜索智能体）

| 工作 | 核心思想 | 与本文的关键区别 |
|---|---|---|
| RAG（Lewis et al., 2020） | 生成前一次性检索注入上下文 | 检索与推理割裂，无法响应推理中涌现的知识缺口 |
| ReAct（Yao et al., 2023） | 交错推理与行动（含信息获取动作） | 提示工程方法，无训练；目标是指令执行而非研读学习 |
| Search-R1 / R1-Searcher（2025） | RL + 结果奖励训练搜索策略，模型学会何时搜、搜什么 | 面向开放域 QA 的事实检索——找"答案碎片"；本文面向教科书原理研读——学"方法本身" |
| MARAG-R1 / PaperSearchQA / KARL | 多检索工具协调 / 科学文献搜索 / 大规模离线 RL 搜索智能体 | 均以信息聚合为目标；本文以知识获取与演化解题的耦合为目标 |

作者对定位的概括很精准：**区别不在"检索 vs 推理"，而在"把知识获取与一个不断演化的推理过程协调起来"**。Search-R1 类工作里，检索是为了补齐缺失的事实；本文里，研读是为了理解并运用不熟悉的原理——搜索结果可能重塑整个解题策略。

### 2.2 谱系二：元学习与测试时适应

| 工作 | 核心思想 | 与本文的关键区别 |
|---|---|---|
| ICL / CL-bench | 从提示范例/给定材料中适应任务 | 材料是预先组装的，模型不决定学什么 |
| Reflexion | 跨尝试的语言反思，权重不变 | 依赖重复尝试的反馈信号 |
| MCTR | 元认知记忆 + 测试时 RL 权重更新 | 需要测试时改参数；本文推理时权重冻结 |
| LaMer | 优化跨 episode 回报，让探索惠及后续尝试 | 跨 episode 目标；本文是单 episode 内完成学习 |
| SEAL（MIT, 2025） | RL 训练模型生成"自我编辑"，微调自身权重 | 适应发生在参数空间；本文适应发生在上下文空间，不动权重 |

本文与元学习的联系在于**学会一种获取策略**，而不是跨 episode 元目标或测试时参数适应——这是它与 SEAL 等自我改造路线的本质分野。

### 2.3 谱系三：细粒度智能体 RL（本文方法的直接技术基底）

| 工作 | 细粒度信号设计 | 与本文的区别 |
|---|---|---|
| StepSearch | 步级信息增益 + 冗余惩罚（TF-IDF 启发式） | 启发式奖励需要金标文档 |
| SLATE | 共享前缀截断采样 + LLM 裁判分解过程奖励 | 需要额外采样分支；本文直接在采样轨迹上打分 |
| IG-Search | 金答案似然的文档反事实增益 | 依赖金答案；本文工具裁判不可见参考答案 |
| OpenClaw-RL | 从后续交互观察中提取评价性监督 | 面向在线策略更新的通用框架 |

本文的组合拳——**正确性门控的退火探索奖励 + 冻结初始模型作裁判的回合级信用重分配**——在设计上独树一帜：探索奖励不奖励调用本身而只奖励"答对且至少调用成功一次"，信用重分配做中心化保持轨迹级优势均值不变。

### 2.4 本文的定位结论

在前两条谱系的交汇处，本文立起一块新界碑：**以教科书为自监督语料、以证明题正确性为可验证奖励，用 RL 训练出一个可跨书、跨学科、跨任务迁移的"研读策略"**。它同时是：搜索智能体范式从"事实检索"到"原理研读"的升级；自学习范式从"给定材料"到"自主选择材料"的升级；细粒度智能体 RL 从"步骤质量"到"知识获取-推理耦合"的升级。此外，作者团队的前置工作构成了完整支撑链：Intern-S1-MO（长程数学推理智能体）、AdvancedMath-Bench（高等数学证明生成与验证基准）、悲观验证方法（证明判定的奖励来源）——本文是这条技术脉络向"自主学习"方向的延伸。

## 三、问题定义

### 3.1 从具体场景到抽象问题

**具体场景**：给模型一道取自某教科书的数学证明题，配一本抠掉了全部习题解答的教科书（保留定义、定理、讲解与一般性结果的证明），让模型自己读书做题。

**深层洞察**：这个场景的本质结构是——**知识获取与推理生成必须持续互相塑造**。一次失败的推导暴露出缺失的前置知识；一个新遇到的定理可能改写整个解题策略。这与"检索一次、生成一次"的 RAG 有本质区别，与"材料喂到嘴边"的 ICL 也不同：模型必须自主决定**学什么（what）、去哪学（where）、学到什么程度（when to stop）**。

**类比**：自学习 ≈ 开卷考试中"边推边翻书"的能力，而 RAG ≈ 考前发给你一张固定的小抄。小抄抄什么不由考试过程决定；而"边推边翻书"的每一次翻页都由当前卡壳的位置驱动。

### 3.2 形式化定义

给定证明问题 $q$ 与结构化教科书 $\mathcal{B}$（教科书被表示为章节序列，每章含标识符 $\iota_k$、标题 $\ell_k$、正文 $x_k$）。策略 $\pi_\theta$ 在每个非终止轮 $t$：先生成推理 $z_t$（基于问题与历史交互），再从教科书访问动作空间 $\mathcal{A}$ 中选择并执行动作 $a_t$，获得观察 $o_t$。终止轮 $T$ 输出最终证明 $\hat{y}$，不再访问教科书。完整轨迹：

$$\tau = (z_1, a_1, o_1, \ldots, z_{T-1}, a_{T-1}, o_{T-1}, z_T, \hat{y})$$

奖励由 LLM 裁判对照**对模型隐藏的**参考解答 $y^\star$ 判定：$r(\tau) \sim J_{sol}(q, y^\star, \hat{y}) \in \{-1, +1\}$。

**目标**：最大化证明正确率——但要害不在单题正确率，而在**学到的策略可迁移**：能迁移到没见过的书、没见过的学科、甚至不是数学的任务，而不是记住训练用书的内容或适应特定参考环境。

### 3.3 这个抽象的精妙之处

三点设计排除了所有"作弊"捷径，使问题真正指向自学习：

- **抽掉参考解答**：题目出处章节里没有答案可查，模型无法把"研读"退化成"找答案"——必须理解原理才能做题；
- **排除指代章节号的习题**：题面自足，不给"翻到第X节"的作弊线索；
- **参考解答对裁判单向可见**：奖励判定用参考答案，但参考答案不在模型可见材料内——形成"可验证但不可抄"的奖励结构。

这套设定把"自主学习"压缩成了一个**可验证奖励的 RL 问题**——这正是它能用 GRPO 类方法训练的前提。

## 四、问题解法

方法全景：一条端到端流水线把原始教科书变成结构化参考材料并抽出证明题（4.1）；一个模仿人类研读流程的三工具接口 BookNavigator（4.2）；一套针对"维持探索"与"抑制无效调用"双目标的 GRPO 改造（4.3）。

### 4.1 问题-教科书数据管线的构建

**类比**：把一座图书馆改造成"习题考场"——书保留在架上，但所有书后答案页被撕掉，且每道题登记了出处（provenance），供后续干预实验使用。

流程：解析 158 本本科/研究生数学教材（分析、代数、数论、几何、图论、微分方程、数值计算、竞赛数学、概率统计）为按章节索引的文本，保留层级结构；习题与解答从讲解内容中分离抽取并链接源书；讲解材料保留定义、定理、解释性段落与一般性结果的证明。最终得到 **5,183 道证明题**，其中训练集 4,557 题（132 本书），三套评估划分：ID-Book（训练书内留出 205 题）、OOD-Book（未见过的 7 本书 155 题）、OOD-Subject（完全留出的概率统计学科 19 本书 266 题）。每本书平均 56 节、20.8 万 token——长篇、跨节依赖，构成真正的研读环境而非"一页小抄"。

### 4.2 BookNavigator：给模型一套"人类研读动作"

三个动作精确对应人类读书的三个基本操作：

| 动作 | 人类类比 | 输入 → 输出 | 作用 |
|---|---|---|---|
| `get_toc` | 先翻目录，了解全书结构 | 无参数 → 完整章节 ID/标题树（含各节 token 数与内容状态） | 全局定向 |
| `search_index` | 翻索引、按关键词定位 | 关键词查询 → 排序的章节 ID + 匹配片段 | 定位疑似相关材料 |
| `read_section` | 翻到某节从头读 | 章节 ID → 该节完整正文（定义/定理/证明/例子） | 在完整上下文中精读 |

`search_index` 是基于关键词的词法检索：查询与正文归一化分词后，按加权词覆盖、词邻近度、精确短语匹配、标题相关度打分。系统提示词中内置了一整套"TOC 优先"的检索控制器：检索前先想清楚是否需要、首次调用必须且只能是 `get_toc`、根据目录状态位（container/heading_only/body/too_long）决定读不读、搜索词用书的语言而非长英文改写、最多一次 TOC + 两次搜索 + 通常一次完整精读、两次搜索无果就停止改写查询……这套协议本身就是"如何研读一本书"的行为规范，为 RL 提供了良好的初始探索分布。

每个动作的观察 $o_t$ 追加进交互历史，模型因此可以在推理与读书之间自由交错，并根据正在成形的解答与已读内容调整下一步动作。上限 8 轮交互、64k token 轨迹总长。

### 4.3 带细粒度奖励的强化学习：改造 GRPO

**先补背景：GRPO 是什么。** GRPO（Group Relative Policy Optimization）是 DeepSeekMath 提出的 RL 算法：对同一道题采样一组（如 8 条）回答，用组内奖励的均值与标准差归一化得到每条回答的优势——高于组均值被强化、低于被抑制，从而省掉 PPO 的价值网络。它与可验证奖励（数学对错可自动判）天然契合，是当前推理模型与智能体 RL 的主力算法。

**GRPO 用在这里的两个失灵**。论文 §2.4 开门见山：

1. **终局奖励对单次检索决策的指导极弱**（信用分配问题）：一条成功的轨迹可能含大量冗余检索，一条失败轨迹里的某次检索其实很有价值——终局 ±1 的信号分辨不出来；
2. **能力增强反而杀死工具使用**：随着训练使解题能力增强，"不用工具也能答对"的路径越来越占优，咨询参考资料的动机持续衰减——即第 1.4 节所述的工具使用崩溃。

两个失灵对应两个组件，一防"弃读"、一防"滥读"：

**组件一：退火探索奖励（防弃读）。** 类比：健身新手的"出勤奖励"——只要练了（至少成功调用一次工具）且完成了训练计划（答案正确），就发额外奖金，奖金数额随时间递减但不清零。形式化：对正确轨迹（$r(\tau)=1$）且至少一次工具调用成功，加探索奖励 $b(\tau)$：

$$R_n(\tau) = r(\tau) + \beta_n \, b(\tau) \, \mathbb{I}[r(\tau)=1]$$

$\beta_n$ 按**余弦调度从 1 退火到 0.25**（50 个 rollout 步内），训练早期强力鼓励碰书，后期保留小额激励防止弃读。注意门控条件设计：**只有答对的轨迹才拿探索奖励**——这避免了"为调用而调用"被强化（滥读不加分）。

**组件二：回合级工具信用（防滥读）。** 类比：带教老师复盘你的每一次翻书——这次翻页是找到了要用的东西（useful）、无所谓好坏（neutral）、还是纯属浪费（harmful）？由一个**冻结的初始模型副本**担任工具裁判 $J_{tool}$，对每个非终止轮评估：

$$c_t = J_{tool}\big(q, (z_u, a_u, o_u)_{u=1}^{t}, z_{t+1}\big)$$

三档标签：**useful**（获得相关新信息/澄清未决条件/纠正误解/给出有意义的导航线索）、**neutral**（合理探索或验证但无已证明的收益）、**harmful**（明显冗余或无关的检索、无理由重复失败的请求、可证明的协议违规）。裁判可以看到**下一轮的推理**作为回溯性证据（刚读的东西有没有被用上），但**看不到参考答案与最终对错**；"没有立即被使用"本身不构成差评。映射为分值：harmful=0.5，useful/neutral=1。

**信用的重分配数学**（GRPO 目标内的改造）：对组内每条轨迹先由 $R_n(\tau)$ 算轨迹级优势 $A$，再按回合分数中心化重分配：

$$\tilde{A}_t = A + \alpha |A| (c_t - \bar{c}), \qquad \bar{c} = \frac{\sum_t m_t c_t}{\sum_t m_t}$$

其中 $m_t$ 是第 $t$ 轮未屏蔽的模型生成 token 数，$\alpha=1$ 控制重分配强度。中心化（减去 token 加权均值 $\bar c$）保证整条轨迹的 token 加权平均优势仍是 $A$——**过程信号只在不改变结局信号总量的前提下重新分配功劳**，harmful 轮被削、useful 轮被增。$\tilde{A}_t$ 赋给第 $t$ 轮所有模型生成 token（推理+工具调用），工具返回的观察文本排除在策略损失之外（沿用 Search-R1 确立的检索 token 屏蔽惯例）。

**裁判为什么用冻结的初始模型？** 一致性：所有训练变体用同一个裁判，评估不随策略漂移；且消融显示这不需要更强的模型——**初始模型本身就提供了有用的工具使用监督**（这一点很反直觉，见 §5.4）。

## 五、评估指标与实验证据

### 5.1 指标体系

- **主指标：证明准确率**（proof accuracy）——每题独立采样 4 个证明、由 8 次悲观验证的 GLM-5.2 判定，取平均。它衡量的不是"格式正确的答案"而是"经得起最严格复查的完整推导"，这是证明任务的黄金标准。方向：越高越好。
- **辅助指标（迁移）**：三划分准确率（ID-Book / OOD-Book / OOD-Subject）+ 外部基准 BrowseComp-Plus（迭代式信息检索）与 CL-bench（从给定上下文学习，四类子任务）。检验的是"学到的是通用研读策略还是领域记忆"。
- **辅助指标（行为）**：Tool Traj.（含至少一次工具调用的轨迹占比）与 Calls/Traj.（平均每轨迹调用次数）——直接观测工具使用是否崩溃。
- **消融指标**：正确性-only RL、+工具信用、+探索奖励、完整方法的精度与工具使用行为对比。

### 5.2 主实验：RL 解锁自学习（表 1 精简）

| 协议 | 总体 Base | 总体 +RL | Δ |
|---|---|---|---|
| No-Book（不给书） | 55.7 | 68.5 | +12.9 |
| Top-k Sections（检索 k 节拼上下文） | 62.2 | 73.1 | +10.9 |
| Long-Context（按书序塞满 64k） | 56.7 | 72.2 | +15.5 |
| Oracle Section（直接给出处那节） | 60.9 | 71.0 | +10.0 |
| **Self-Learning（本文）** | **51.5** | **79.5** | **+28.0** |

三个关键读数：

1. **训练前自学习是最差的（51.5%，低于不给书的 55.7%）**——初始模型不会读书：交互协议不熟、读书浪费预算、甚至被无关内容带偏。这个"反转起点"很重要：它说明自学习不是现成能力，而是 RL 激发出来的潜能；
2. **训练后反超所有固定检索基线 6.4pp 以上**（79.5% vs Top-k 的 73.1%）——而且固定检索基线各自做了 RL 仍追不上。这证明优势不来自"看到了什么材料"，而来自**让读什么、何时读服从推理的演化**；
3. **跨书 85.2%、跨学科 86.7%，均为全部协议最高**——对未见过的书和完全留出的概率统计学科，增益不缩水反而最大（+20.0 / +29.9pp），直接支撑"域无关研读策略"主张。

### 5.3 归因实验：增益来自哪里（表 2）

五条件对照（配对书 / 无书 / 同学科换书 / 删源节 / 删非源节）：

| 条件 | Base | +RL |
|---|---|---|
| 配对教科书 | 51.5 | 79.5 |
| 无书 | 55.7 | 71.7 |
| 同学科换一本 | 49.6 | 75.2 |
| 删源节（含前后共 9 节） | 49.0 | 74.6 |
| 删 9 个无关节（对照） | 53.0 | 79.8 |

解读：(a) 无书条件也从 55.7 涨到 71.7——训练顺带增强了裸推理，但有书仍比无书高 7.8pp，**知识获取与应用的贡献独立存在**；(b) 换书 75.2%、删源节 74.6% 都高于无书——模型没有依赖特定书或背过的源节，能从别的书、别的节学到东西；(c) 删源节掉 5.2pp 而删无关节几乎不掉（79.8 vs 79.5）——掉分取决于删的是不是真知识，不是删节本身。归因结论：增益 ≈ 更强的裸推理 + 更强的知识获取应用能力 + 通用研读策略，而非记忆。

### 5.4 消融：两个组件各管什么（表 4 精简，全文最关键的证据）

| 设置 | 总体精度 | Tool Traj. | Calls/Traj. |
|---|---|---|---|
| Base | 51.5 | 36.9% | 1.5 |
| 正确性-only RL | 74.9 | **6.7%** | 0.3 |
| RL + 工具信用 | 76.2 | 7.0% | 0.3 |
| RL + 探索奖励 | 77.0 | 79.9% | 5.9 |
| **完整方法** | **79.5** | 58.4% | 3.0 |

四条结论，每条都对应主张的一环：

1. **正确性-only RL 精度大涨（+23.4pp）但工具轨迹从 36.9% 崩到 6.7%**——工具使用崩溃在该设定下被定量复现：变强后模型确实抛弃了教科书；
2. **工具信用 +3.3pp（ID-Book 60.7→64.0），主要提升在域内**；但救不了工具使用（7.0%）——过程反馈能改善学习效率，不能提供读书动机；
3. **探索奖励把工具轨迹拉回 79.9%，OOD 增益显著**（OOD-Book +2.0、OOD-Subject +2.9）——动机问题必须靠显式激励解决；
4. **完整方法全划分最强且工具轨迹 58.4%、调用 3.0 次/轨迹**——不是调得越多越好（单独探索奖励 79.9% 工具轨迹反而精度更低），而是"有动机 + 有甄别"的组合以适中的工具频率拿到最高泛化。

### 5.5 跨任务迁移：不是数学专属（表 3 精简）

在两个外部基准上用其原生推理协议（不用 BookNavigator）：

| RL 协议 | BrowseComp-Plus | CL-bench 总体 |
|---|---|---|
| Base | 50.2 | 14.8 |
| No-Book RL | 48.6（↓1.6） | 16.2（↑1.4） |
| Top-k RL | 49.9（↓0.3） | 15.5（↑0.7） |
| **Self-Learning RL** | **51.9（↑1.7）** | **17.1（↑2.3）** |

Self-Learning 是唯一在 BrowseComp-Plus 上超过 Base 的策略，CL-bench 上四类子任务中 DKR +4.5、RSA +1.2 涨幅最大；所有 RL 策略在 PTE（程序性任务执行）上都掉分——迁移是**有选择的**：迭代检索与知识习得类任务受益，忠实执行既定流程类任务不受益（证明导向训练与流程导向执行的错配）。作者的诚实报告反而是论文可信度的加分项。

### 5.6 指标如何支撑主张

主张"RL 能培养域无关的自学习策略"需要三个环节的证据链，实验设计恰好一一对应：**策略存在**（主实验：全划分最高、反转起点证明是学出来的）→ **策略通用**（OOD-Book/OOD-Subject 不缩水 + 归因实验排除记忆解释 + 跨任务基准迁移）→ **策略与工具使用因果相关**（消融：只有维持住工具使用的变体才拿到最强泛化增益，正确性-only 精度不低但泛化差）。每个数字都有明确的证词角色，不是数字堆砌。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**对比对象**：固定检索基线（Top-k Sections 最强）与正确性-only RL。它们为何曾经有效？固定检索在静态问题上有效，因为大多数习题所需知识与题面相关性高，一次检索就能覆盖；正确性-only RL 在训练分布内有效，因为终局奖励足以驱动推理能力增长。

**baseline 的根本局限**（机制层面）：

- 固定检索的瓶颈是**信息流单向**：检索内容在推理开始前注入、此后冻结，推理过程中涌现的知识缺口无法回流到检索决策——材料的相关性由初始问题单方面决定。无论怎么训（Top-k +RL 只有 73.1），这个结构性天花板不可逾越；
- 正确性-only RL 的瓶颈是**优化目标与工具使用的激励不相容**：奖励只看终局对错，而"不读书也答对"的路径更短、方差更低，优化器必然逐步压缩工具调用——不是"没做激励工具的事"，而是"激励结构主动淘汰工具使用"。这解释了 36.9%→6.7% 的崩溃不是偶然而是必然后果。

**本文方法的根本性改变**（因果链，标注证据等级）：

1. **知识获取与推理耦合** → 信息流从单向变双向：推理中发现的缺口驱动下一次检索，新读到的定理重塑解题策略（论文动机阐述；轨迹示例定性支持——拟阵一题中模型先发现记号矛盾、搜编号、读定义、修正理解后完成证明）；
2. **退火探索奖励改变优化景观** → "答对且读过书"的轨迹在组内比较中系统性占优于"答对但没读书"的轨迹，工具使用被持续强化而非淘汰 → 工具轨迹维持 58.4% 而非崩溃到 6.7%（**论文消融直接支持**）；
3. **余弦退火（而非固定或线性归零）平衡两阶段** → 早期高 β 建立读书习惯，后期 0.25 地板维持动机又不让调用本身喧宾夺主（**论文实验支持**：单独探索奖励 β 恒定时工具轨迹 79.9% 但精度 77.0 < 79.5，说明过度激励同样有害，退火与工具信用的组合才最优——该对比由消融表可推出）；
4. **回合级信用改变梯度结构** → harmful 轮优势被削、useful 轮被增，且中心化不扰动轨迹级信号 → 同样的工具频率下每次调用质量更高（**论文消融支持**：ID +3.3pp；**阅读者推测**：它还起到防止探索奖励被"垃圾调用"套利的作用——门控条件只要求"至少一次成功调用"，若无信用甄别，模型可能学会开局刷一次无意义调用来骗奖金；论文未直接验证此反事实，但完整方法 3.0 次/轨迹 vs 单独探索奖励 5.9 次/轨迹且精度更高，与此解释一致）;
5. **教科书自监督的规模效应** → 5,183 题全部由教材管线自动构造、奖励由悲观验证自动判定，无需人工标注轨迹（**论文事实**；**阅读者推测**：这种近乎零成本的监督来源可能是该方法相对 SFT 蒸馏路线的根本经济性优势）。

**反事实推理**：去掉探索奖励 → 工具崩溃、泛化增益缩水（消融直接给出）；去掉工具信用 → 精度掉 3-5pp 且工具使用仍崩溃；去掉悲观验证（放宽为单次判定）→ 奖励噪声增大（论文未做此消融，但同团队 AdvancedMath-Bench/悲观验证工作确立单次 LLM 判证明的误判率不可忽略，属**推断而非本文直接证据**）。

### 6.3 综合判断与未决问题

**多项研究共同支持的机制**：(1) 终局-only 奖励在多步工具任务中信用分配不足且诱发工具弃用——Search-R1 谱系、ASTER、Diversity over Frequency 与本文消融四方一致；(2) 过程级/细粒度信号系统性优于终局-only——StepSearch、SLATE、R1-Searcher 与本文工具信用消融一致；(3) 激励结构（而非能力）决定工具使用行为——R1-Searcher、AutoTool 与本文探索奖励消融一致。

**仍属推测的机制**：工具信用防止探索奖励被垃圾调用套利（有间接证据、无直接实验）；悲观验证的严格性对最终迁移的定量贡献（未消融）；"知识获取-推理耦合"目前主要靠动机阐述与轨迹定性支持，缺乏对耦合度的定量测量。

**优势成立的条件**：任务存在结构化、可解析的长篇参考资料且参考答案可抠除；奖励判定足够可靠（悲观验证成本不低：每证明 8 次 65k-token 审查）；学科知识分布足够广以支持策略泛化。

**可能失效的条件**：参考资料非结构化（如混乱网页）时三工具接口优势可能消失；判定器系统性偏差会被 RL 放大；PTE 类程序性任务已显示负迁移；GRPO 固有的训练稳定性风险（LLDS）在更长训练下是否显现未验证。

## 七、必要知识反推

假设让一个完全没有相关信息的人重做这项工作，最少必须掌握什么？

### 7.1 领域知识层

- **LLM 知识获取的两种形态与各自失效模式**：参数化知识会过时、RAG 是静态单向注入——不理解这点就无法定义"自学习"要填补的空白；
- **数学证明任务的结构**：证明需要多步严格推导、可对照参考答案判定、习题与讲解天然配对——这是构造自监督任务的领域前提；
- **教科书作为语料的特性**：层级结构（章-节-正文）、习题/讲解可分离、解答可抠除——不知道这些就设计不出数据管线。

### 7.2 方法论知识层

- **RLVR（可验证奖励强化学习）范式**：DeepSeek-R1/DeepSeekMath 一系确立了"规则可验证的奖励 + 策略优化"路线——不知道它就不会想到把证明正确性当奖励；
- **GRPO 机制**：组相对优势、token 级重要性加权、截断目标——改造它必须先精通它，尤其是优势在 token 间如何传播（重分配数学才有了力）；
- **信用分配理论与过程奖励谱系**：StepSearch/SLATE 等步级监督工作——本文的工具信用是这条线的延续，不知道前作就意识不到"终局奖励对单步指导弱"；
- **LLM-as-judge 与悲观验证**：判定证明需要裁判；单次判定误判率不可忽略、多次独立审查 + 全票通过可压噪——这是同团队前置工作，直接决定奖励质量；
- **工具使用崩溃现象**：必须知道"RL 变强→弃用工具"的倾向存在，否则不会设计探索奖励——这是方法设计的靶心知识。

### 7.3 工程知识层

- **教科书解析管线工程**：PDF/原始文本→章节索引结构、习题/解答分离、provenance 元数据登记——5,183 题数据集的可行性基础；
- **词法检索系统设计**：加权词覆盖/词邻近度/短语匹配/标题相关度打分——`search_index` 的实现知识（有趣的是没用稠密检索，规避了嵌入模型依赖）;
- **多轮智能体训练基础设施**：64k 轨迹、8 轮交互、128 题 × 8 轨迹/批的 rollout、工具观察屏蔽、冻结裁判并行服务——没有这套 infra 一切无从谈起；
- **评估协议设计**：三划分构造逻辑（换书/换学科分离变量）、五条件归因实验的对照设计（源节删除 vs 非源节删除的数量匹配对照）、外部基准的原生协议适配。

### 7.4 知识融合的关键节点

三个化学反应节点，缺一不可：

1. **"教科书=免费自监督"的洞察**：把领域知识（习题-讲解配对）与 RLVR 方法论熔接——习题的参考答案被抠掉后仍然存在，天然构成"可验证但不可抄"的奖励结构。这是整篇论文的种子；
2. **"崩溃机理→双组件对偶设计"的转化**：把工具使用崩溃的两个成因（动机衰减+无甄别）分别映射为两个奖励组件（探索奖励治动机、工具信用治甄别），并用中心化数学保证二者不互相干扰（均值守恒）。这是方法的核心创造力；
3. **"冻结裁判"的反直觉选择**：不是更强的模型、恰恰是初始模型自己当裁判——把"一致性"与"零额外成本"置于"裁判能力"之上，且消融证明可行。这打破了"过程监督需要更强监督者"的思维定式。

## 八、论文中可以提取的通用性灵感

### 灵感一：激励结构决定行为存亡——"能力增长会杀死协作行为，除非激励随时间退火"

**核心思想**：任何"用更笨但更可靠的手段（工具/流程/协作）能做好"的能力，一旦主体内功变强，纯内省路径就会因更短更低方差而被优化器偏爱，把前者淘汰。解法不是禁止内省，而是给"既做对又用了可靠手段"的路径发随时间退火（高→地板值而非零）的额外奖励。

**论文证据**：工具轨迹 36.9%→6.7%（崩溃）vs 探索奖励维持 79.9%、完整方法 58.4% 且精度最高；余弦退火到 0.25 而非 0。

**推广场景**：① AI 助手训练中防止模型放弃调用计算器/搜索直接口算；② 人机协作系统中防止资深员工不再写文档/不再带新人复核；③ 代码智能体防止"看起来能跑"就跳过测试执行；④ 教育场景中防止学生掌握套路后跳过推导步骤；⑤ 多智能体系统中防止强 agent 吞掉弱 agent 的参与度。

### 灵感二：过程信号要"中心化重分配"，而非叠加——均值守恒的功劳再分配

**核心思想**：给终局奖励补充过程评价时，不要做加法（过程分直接加进总奖励，会扰动结局语义、诱发刷分），而要做减法后的重分配：以 token/时间加权均值为锚，高于锚的步骤借优势、低于锚的还优势，总量守恒。过程信号只改变功劳的分布，不改变功劳的总量。

**论文证据**：$\tilde{A}_t = A + \alpha|A|(c_t - \bar{c})$ 的中心化设计；ID-Book +3.3pp 且不牺牲终局信号；完整方法以 3.0 次/轨迹的适中频率击败 5.9 次/轨迹的高频变体。

**推广场景**：① 团队绩效评估中项目奖金按贡献中心化再分配而非人人加分；② 多步工作流自动化中每步质量分的相对化使用；③ 强化学习任何需要"过程奖励不污染结果语义"的场景；④ 在线教育的过程性评价设计；⑤ 检索系统的探索奖励（避免为查而查）。

### 灵感三：冻结的初始自我可以当合格的裁判——监督者不必更强

**核心思想**：评估"某个交互是否有益"不需要超过被评估者的能力——初始模型副本在温度 0、有完整上下文回放的条件下，足以对工具调用质量给出有用的三档判定。一致性（不随训练漂移）与零成本比裁判能力更重要。

**论文证据**：工具裁判即冻结 Intern-S2-Preview-35B 副本，ID +3.3pp；作者明言"这不需要更强的模型"。

**推广场景**：① RLHF 中用冻结策略副本做过程标注以省奖励模型成本；② 大规模数据清洗中用小模型做初筛裁判；③ 自我改进系统中用历史版本做一致性评估锚点；④ 组织中用制度化的"入职时自己"做决策复盘基准；⑤ 多智能体系统中轻量级互相评估架构。

### 灵感四：自监督语料的"抠答案"改造——把存量教材变成无限训练信号

**核心思想**：任何"题目+解答"配对的存量语料（教材、题库、文档、案例库），只要把解答从模型可见材料中抠掉、但保留在判定端，就自动变成"可验证但不可抄"的强化学习任务源。监督信号不是没有，而是藏在存量材料的结构里。

**论文证据**：158 本书管线化产出 5,183 题，全程零人工轨迹标注；参考解答对策略单向隐藏构成奖励不对称。

**推广场景**：① 法条-案例库训练法律推理智能体；② 药典-适应症文献训练医学研读智能体；③ 开源 issue-PR 历史训练代码修复智能体；④ 论文-复现报告训练科研方法学习；⑤ 企业 SOP-故障手册训练运维智能体。

### 灵感五：工具是训练期脚手架还是终身技能，取决于任务是否持续需要新知识

**核心思想**：外部能力（检索/工具/参考资料）在训练中有两种命运：若任务知识可完全内化，工具是脚手架、用完可弃（视觉任务）；若任务需要持续获取新知识（陌生领域），工具使用本身是必须保住的可迁移策略。设计训练前先想清楚你处在哪种情形——两种情形的 correct 策略相反。

**论文证据**：本文 OOD 泛化增益与工具使用维持强关联（消融表）；对照视觉工具崩溃文献中"工具率衰减但性能保持"的相反结论；PTE 子任务的负迁移显示策略迁移有边界。

**推广场景**：① 教育设计：考试型学科（可弃参考书）vs 研究型学科（须保文献能力）；② 企业培训：操作性技能 vs 需要持续学习新法规/新工具的岗位；③ AI 系统设计：闭卷 benchmark 优化 vs 开卷持续学习系统；④ 个人学习策略：内化基础知识 vs 保持"知道去哪找"的元知识；⑤ 智能体产品定位：快答型（压工具成本）vs 研究型（保工具深度）。

## 附录：一条真实研读轨迹的样子

论文附录 B.4 给了一个四轮完成拟阵（matroid）证明题的交互实例，可一窥学到的策略形态：

1. **Turn 1（发现矛盾→定向）**：模型读题后发现等式两侧基集不一致的"矛盾"，反复思考无果后调用 `get_toc` 定位到第 8.2 节《Matroids》（25,031 token，很大）；
2. **Turn 2（精确锚点搜索）**：意识到整节太大，改用 `search_index` 搜题号"8.2.41"——搜到的却是同编号的 Proposition（对偶恒等式），不是习题解答（解答已被抠掉，无从抄袭）；
3. **Turn 3（读定义）**：调用 `read_section` 读整节，拿到 Definition 8.2.40（限制/收缩的定义）与 Theorem 8.2.43（秩函数公式）——正文只陈述可交换结果、把证明留给习题；
4. **Turn 4（修正理解→完成证明）**：由秩函数公式修正了对记号的误读，验证两侧秩相等，完成两个恒等式的证明。

这条轨迹浓缩了自学习的全部要素：由推理困境驱动的定向、对检索结果的甄别（区分 Proposition 与习题解答）、精读后的理解修正、以及知识向推导的最终整合——恰恰是任何固定检索基线无法执行的动态过程。
