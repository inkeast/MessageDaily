## 一、论文背景

### 1.1 一个没人检验过的行业默认假设

模型厂商发布新编码模型时的标准动作，是展示 SWE-Bench Pro 这类编码基准的分数提升。行业把这些分数当作模型编码能力的直接证据：分数更高，意味着模型能帮开发者完成更多工作。用户照此选模型，监管者照此判断模型强弱（欧盟《通用目的 AI 行为准则》即以基准分数为参考），买家照此做采购决策。但这条从基准分数到真实生产力的推理链条，此前从未被因果检验过。

基准和真实工作的差距是结构性的。SWE-bench 系列的任务来自公开仓库中已经解决过的问题，判定标准是能否通过既有的测试用例。而真实工作中：任务描述往往含糊不清；代码必须符合项目风格；最关键的是，得有人愿意接受你的改动。GitHub 上维护者合并 PR 的标准并不是基准测试。METR 在 2026 年 3 月的研究笔记中发现，SWE-bench Verified 的自动评分比真实维护者的接受率平均高出 24.2 个百分点——大约一半通过基准测试的 PR 会被人类代码评审拒绝。

### 1.2 为什么此前没人能回答这个问题

测量特定模型对真实生产力的因果影响，困难在于混淆因素太多：

- **人的差异**：先尝试新模型的人可能本来就更熟练，跨开发者对比分不清是模型强还是人强。
- **任务的差异**：即便观察同一个人，他可能把最难的任务留给最强的模型——最强模型在任何指标下都会显得低效。
- **样本构成的差异**：已有研究中每个 agent 的 PR 往往集中在少数仓库，这些仓库自身的合并习惯主导了统计结果。

既有研究要么横截面比较不同 agent（混合了模型、工具、人三个变量），要么在实验室里给受试者派发任务（无法反映开发者自己选择的工作），要么比较项目层面而非开发者层面的变化。没有一项研究能消除这些偏差。

### 1.3 一个天赐的自然实验

2026 年 6 月 12 日下午 5:21（美东时间），Anthropic 收到美国出口管制指令，被迫对所有客户停用 Claude Fable 5，持续 19 天，至 7 月 1 日恢复。停服期间用户只能转向低档模型，多数人选择了 Opus 4.8——这个模型在 SWE-Bench Pro 上比 Fable 5 低 10.8 分（69.2% 对 80.0%）。

这构成一个近乎理想的双向自然实验：干预来自外部，与用户意愿无关；人和项目不变，只有模型变。同一批人可以被观察到停服前（用 Fable 5）、停服中（被迫用 Opus 4.8）、恢复后（重新可用 Fable 5）的完整轨迹。

## 二、论文定位和关联工作

本文处在三条研究脉络的交汇点。

### 2.1 谱系一：编码 agent 的 PR 挖掘研究

AIDev 数据集（Li et al.）率先系统性收集了 coding agent 在 GitHub 上开启的 PR，后续工作研究了如何挖掘这类数据（Robbes et al., MSR 2026）、agent PR 为何被合并或拒绝（Peralta et al., MSR 2026）、不同 agent 和任务类型下的合并率比较（Pinna et al.），以及 agent PR 常在几乎没有评审的情况下被自动合并（Branco et al., LGTM!）。这条线的局限：都是横截面比较，不控制用户与模型的对应关系，发现的 agent 间差异混合了模型、工具和人。

### 2.2 谱系二：AI 生产力的因果经济学

- **Italy ChatGPT 禁令研究**（Kreitmeir & Raschky, arXiv:2403.01964）：利用 2023 年意大利突然禁用 ChatGPT，对 36,000 余名欧洲 GitHub 用户做 DID。发现禁令对经验开发者的产出没有系统性影响（早期版本报告的最初两日约 50% 产出下降很快恢复）。这是与本文方法论最接近的前驱——政府干预作为自然实验——但它比较的是有没有 AI，不是模型之间的强弱。
- **Copilot 上线自然实验**（Yeverechyahu et al., arXiv:2409.08379）：利用 Copilot 2021 年 10 月只支持 Python/Rust 不支持 R 的选择性发布，比较语言间贡献变化；2022 年 6 月模型升级后，Python 包的维护型贡献显著上升。本文结果与它方向相反，但作者指出该研究比较的是项目不是开发者，未跟踪同一批人自选的工作。
- **随机田野实验**（Cui et al., Management Science 2026；Becker et al. / METR, arXiv:2507.09089）：METR 的 RCT 让 16 名经验丰富的开源维护者对自己的 246 个真实任务做 AI 可用/禁用随机分配，发现用 AI 反而慢 19%。但这类实验也有内生问题：一项大型田野实验中被分配 AI 工具的开发者前 29 周只有 44% 真正采用了它；且受试者知道自己被观察、任务可能由研究指定。
- **实验室任务研究**（Merali, arXiv:2512.21316）：固定任务下发现模型每年进展约节省 8% 任务时间——但任务是指派的，不反映开发者日常真正交给 agent 的工作。

### 2.3 谱系三：基准有效性批判

Raji et al. 的 AI and the Everything Benchmark、Wallach et al. 的 ICML 2025 立场论文（生成式 AI 评估是社会科学测量问题）、BetterBench（NeurIPS 2024）、Hardy et al. 的基准信息价值研究、Bean et al. 的构念效度研究，共同构成对基准分数能否代表真实能力的质疑。OpenAI 在 2026 年 2 月公开宣布停止报告 SWE-bench Verified，理由是其测试中 o3 失败的题目里 59.4% 存在测试设计或题目描述缺陷。本文为这条理论批判脉络补上了来自真实工作场域的因果证据。

### 2.4 本文定位

| 维度 | 之前的研究 | 本文 |
|---|---|---|
| 比较对象 | 有 AI vs 没有 AI / 不同 agent / 不同项目 | 同一开发者、不同模型（11 分基准差距） |
| 干预来源 | 自愿采用（自选择）或随机分配（反应性） | 外部政府指令，与用户意愿无关 |
| 工作来源 | 研究指派任务或项目级汇总 | 开发者自己选择的真实工作 |
| 模型识别 | 无法区分具体模型 | PR 描述中的 co-author 行（96–99% 准确） |
| 结论 | 增益存在或混合 | 基准增益未转化为产出（双向自然实验+五次升级验证） |

## 三、问题定义

### 3.1 从具体场景到抽象问题

具体场景：Fable 5 比 Opus 4.8 在 SWE-Bench Pro 上高 10.8 分，用 Fable 5 的开发者是否真的完成了更多工作？

深层抽象：基准分数是一种代理测量（proxy measurement）。本文问的是这个代理对目标构念（真实生产力）的**因果效度**——即基准分数的变化，在控制了人和任务之后，能否映射为产出的变化。这本质上是测量学里的构念效度问题被移植到了因果推断框架中。

### 3.2 形式化定义

- **给定**：开发者集合及其在 GitHub 上的全部 PR 记录；每个 PR 是否在 t 天内被合并；每个 PR 使用的模型（由 co-author 行识别）；外生干预（Fable 5 停服/恢复）；若干次模型升级事件。
- **求解**：拥有高分模型（Fable 5）相对于被迫使用低分模型（Opus 4.8），对开发者产出的因果效应。
- **产出定义**：两个主结局——7 天合并率（PR 创建后 7 天内被合并的份额）与周合并 PR 数（开发者一周内开启且 7 天内被合并的 PR 数量）。合并意味着一段代码完工并被项目接纳，是既有田野研究的标准生产力度量。

### 3.3 平衡性检验：两组人到底像不像

因果识别的可信度建立在处理组与对照组的可比性上。P0 期间（Fable 5 发布前），处理组 244 名开发者与对照组 315 名（抽样）在所有观测特征上高度相似：中位 PR 数 34 对 35（标准化差 −0.06）、7 天合并率 92.7% 对 91.5%（+0.05）、1 小时合并 73.9% 对 71.5%、在自己仓库开 PR 的比例 65.9% 对 67.3%、外部作者占比 18.8% 对 16.8%——全部标准化差异落在 −0.18 到 +0.15 之间，远小于常用的 0.25 阈值。唯一的边缘项是 feat 开头的标题占比（23.5% 对 31.5%，−0.18），说明处理组做的新功能略少一点，但方向上只会让结论更保守。升级分析中换模者与未换模者差异更大（外部作者 23.5% 对 11.7%），这也是作者把升级分析定位为观测性关联的原因之一。

### 3.4 这个抽象的精妙之处

作者没有问哪个模型更好，而是问基准分差这个被全行业默认有效的信号，在真实产出上能兑现多少。停服分析的主估计是翻转对比 (β1+β3)/2——两个有 Fable 5 的阶段（P1、P3）相对停服阶段（P2）的平均差异。这个设计让开发者自身成为自己的对照，日历日固定效应吸走所有人共享的冲击，安慰剂（P0 对 P2，两个都没有 Fable 5 的阶段）则检验两组人在无事发生时是否同步移动。

## 四、问题解法

### 4.1 数据管道：从 co-author 行到模型标记

Claude Code 默认在提交中加入 Co-Authored-By 行标记所用模型。当开发者让 PR 描述复用提交信息时，这个行就暴露了每个 PR 用的模型。作者用 GitHub Search API 按 2025-11-20 到 2026-10-05 的窗口收集这类 PR，主采集在 2026-11-02 完成，保证每个 PR 至少有 7 天被合并的时间。保留规则：(1) 描述恰好命名一个 Claude 模型；(2) 作者是人类账号；(3) 创建于研究窗口内。准确性验证：随机抽检 200 个 PR 的提交记录，模型名与 PR 描述在 96%–99% 的情况下一致。

一个关键透明点：这样的模型命名 PR 仅占已合并 Claude Code PR 的约 1%（1,219 个抽样中 1.0%，95% CI 0.6%–1.7%），但它们的合并率与只有默认署名行的 PR 接近（周度差异 −4.0 到 +6.1 个百分点），且在所有阶段占比稳定（0%–1.8%），没有证据表明这是群异常样本。

### 4.2 停服分析（自然实验）

按 PR 创建时间（UTC）划分四个阶段：P0 发布前（5/26–6/9）、P1 可用（6/9–6/12，仅 3 天）、P2 停服（6/15–6/30，参照组）、P3 恢复（7/2–7/15）。停服开始后的周末和恢复当日被排除，因为切换后立刻开的 PR 可能包含切换前写的代码。

- **处理组**：297 名在 P1 至少开过一个 Fable 5 PR 的开发者。
- **对照组**：8,908 名在 5/26–7/15 期间一直用 Opus 4.8、从未用过 Fable 5 的开发者。
- **模型**：PR 级线性概率模型 Yit = αi + γt + β0·P0it + β1·P1it + β3·P3it + εit，其中 αi 是开发者固定效应（吸收开发者间一切稳定差异），γt 是日历日固定效应（吸收所有人同日共享的冲击，包括停服期间 Opus 4.8 可能因涌入变慢之类的共同影响），标准误按开发者聚类。
- **主估计**：翻转对比 (β1+β3)/2；β0 为安慰剂。

这个设计对反事实假设的要求非常具体：要打破它，一个混淆因素必须恰好只影响 Fable 5 用户、恰好始于 6 月 12 日、恰好止于 7 月 1 日。停服期间大量 Fable 5 用户涌入 Opus 4.8 可能使后者变慢或限制变化——但这影响的是两组人共用的 Opus 4.8，被日历日固定效应吸收；只有当这种拥挤对来自 Fable 5 的用户与其他 Opus 4.8 用户产生不同影响时才会污染估计。同时要强调，停服带走的不只是基准分差，还有模型的全部属性（速度、额度、行为习惯），所以估计的是失去又夺回 Fable 5 的整体效应——而这恰恰是用户按基准分数选模型时实际买到的东西。

选择线性概率模型而非 logistic 的三个理由：系数直接就是百分点差（与排行榜同单位）；带开发者固定效应的 logistic 会丢弃全部 PR 都被合并（或都没被合并）的开发者——而这占多数；翻转对比是多个系数的均值，线性模型下计算直接。

### 4.3 升级分析（观测性关联）

2026 年 2 月至 9 月 Claude Code 有 8 次 Opus/Sonnet 系模型升级。对每次升级，比较换模开发者升级前一周（旧模型）与后一周（新模型）的 PR。入选主池的规则预先设定：至少 10 名换模开发者在两周内都有外部作者 PR（交互分析需要）。5 次升级入主池（Opus 4.6→4.7、4.7→4.8、4.8→5、5→5.5、Sonnet 5→5.5），涉及 1,208 名开发者、15,442 个 PR；另有 944 名两周边续用同一模型未换模的开发者（8,569 PR）作日历对照。合并采用逆方差加权。由于开发者自己选择是否换模，这一分析明确标注为观测性关联——但它与停服分析互为补充：停服是外生强制但窗口短，升级是自选择但样本大、区间窄。

### 4.4 合并语义探查

对 2,019 个抽样 PR（处理组全部 1,019 个外部作者 PR + 1,000 个随机内部作者 PR），通过 GitHub PR 端点读取合并者账号、评审记录与改动规模，回答第三个问题：一个合并到底意味着什么。

## 五、评估指标与实验证据

### 5.1 主结果一：停服分析——模型使用剧烈摆动，合并率纹丝不动

处理组的模型使用率在 P1 高达 82.3%，停服期间跌至 0.9%（74.6% 转向 Opus 4.8），恢复后仅回升到 26.9%。同期这些开发者的 7 天合并率始终在 90.5%–94.6% 的窄带内。翻转对比估计：拥有 Fable 5 使合并率提高 **+1.4 个百分点（95% CI [−1.4, +4.3]）**，不显著——即使按最有利于 Fable 5 的读法，上限也只有 4.3 个百分点。安慰剂（P0 对 P2）为 −2.6 [−6.2, +1.1]，接近零，说明两组人在无干预时基本同步移动。

按实际使用强度换算（工具变量式缩放）：P1/P3 相对 P2 的使用率差为 54 个百分点，用翻转对比除以 0.54，得每个实际使用 Fable 5 的 PR 效应约 +2.7 [−2.6, +8.0]；直接比较同一开发者命名 Fable 5 的 PR 与其他 PR（as-used 比较）同样为 +2.7 [−0.7, +6.1]，均不显著。

### 5.2 主结果二：升级分析——5 到 18 分的基准增益，合并率不升反微降

六个有 SWE-Bench Pro 分数的升级中，新模型比旧模型高 5 到 18 分。但五次升级合并估计为 **−0.9 个百分点 [−1.9, +0.2]**——五次点估计全部为负，所有 95% 区间都包含 0。逐次看：Opus 4.6→4.7 为 −4.1，Opus 4.7→4.8 为 −0.1，Opus 4.8→5 为 −0.8，Opus 5→5.5 为 −1.7，Sonnet 5→5.5 为 −3.5；唯一不入池的 Sonnet 4.6→5 为 +1.8 [−0.6, +4.3]，但其升级后窗口恰与 Fable 5 回归重叠。

周合并 PR 数：换模者相对未换模者 +2.4% [−4.9%, +10.2%]，不显著；打开的 PR 数 +2.7% [−6.7%, +13.0%]。停服期间产出也未掉：处理组开发者日均开 PR 数在停服前/中/后分别为 4.8/5.0/5.2。

### 5.3 八次升级事件的逐项明细

| 事件 | 升级（日期） | 基准增益 | 换模开发者 | PR 数 | 合并率变化（百分点） |
|---|---|---|---|---|---|
| 1 | Opus 4.5→4.6（2/5） | 无分数 | 54 | 443 | +1.7 (−5.2, +8.5) |
| 2 | Sonnet 4.5→4.6（2/17） | 无分数 | 9 | 104 | +5.1 (−51.3, +61.4) |
| 3 | Opus 4.6→4.7（4/16） | +10.9 | 115 | 1,516 | −4.1 (−9.7, +1.6) |
| 4 | Opus 4.7→4.8（5/28） | +5.1* | 113 | 3,482 | −0.1 (−1.9, +1.6) |
| 5 | Sonnet 4.6→5（6/30） | +5.1 | 193 | 1,440 | +1.8 (−0.6, +4.3) |
| 6 | Opus 4.8→5（7/24） | +10.0 | 404 | 5,477 | −0.8 (−2.3, +0.7) |
| 7 | Opus 5→5.5（9/22） | +10.7 | 458 | 4,000 | −1.7 (−5.9, +2.6) |
| 8 | Sonnet 5→5.5（9/28） | +18.1 | 118 | 967 | −3.5 (−7.8, +0.9) |

注：* Opus 4.7 为 64.3、Opus 4.8 为 69.2；事件 1、2 因 Anthropic 未公布 Opus 4.5/Sonnet 4.5 的分数而无基准增益列；事件 2 因换模人数过少不入任何合并池；事件 5 因外部作者 PR 不足 10 人也不入主池。增益最大的 +18.1（事件 8）对应的恰是第三负的 −3.5。

日历对照进一步支持稳健性：六个可比较升级中，未换模开发者自身在发布后也多数出现合并率微降（事件 3 为 −8.5、事件 8 为 −1.1），扣除这一共同趋势后没有任何升级显示明确上升，全部区间含 0。这说明换模者合并率的微负部分是时期共同效应，而非换模本身有害。

### 5.4 次要结局与机制探查

| 结局 | 停服分析 | 升级分析 |
|---|---|---|
| 7 天内合并（百分点） | +1.4 (−1.4, +4.3) | −0.9 (−1.9, +0.2) |
| 周合并 PR 数（%） | 未估计（无可靠对照） | +2.4 (−4.9, +10.2) |
| 1 小时内合并（百分点） | 0.0 (−5.8, +5.8) | +0.8 (−2.1, +3.8) |
| 未合并即关闭（百分点） | −0.5 (−3.0, +2.1) | +0.5 (−1.3, +2.3) |
| 30 天内被 revert（百分点） | 0.0 (−0.4, +0.4) | 样本过小（16 前 / 2 后） |
| 自动检查失败（百分点） | — | +0.3 (−1.4, +2.0) |
| 合并耗时（%） | +8.4 (−9.0, +29.2) | +2.4 (−2.1, +7.2) |

机制探查揭示了为什么没有变化的空间：2,019 个抽样 PR 中 **95% 由作者本人合并、90% 没有任何他人批准**（内部作者 97%、外部作者 94% 都是自并）；每个阶段的中位开合间隔都不足半小时；六次升级前换模开发者已把 94.5% 的 PR 在 7 天内合并、77.1% 在 1 小时内合并、83.8% 的人所有 PR 全部被合并——天花板效应使新模型几乎无处提升合并率。即便只看升级前有未合并 PR 的开发者子群，换模者的变化也是 −1.3 [−6.9, +4.3]。

### 5.5 稳健性与可排除的效应上限

十余种设定下停服估计落在 −0.1 到 +3.7 个百分点之间：加入处理组周线性趋势 +1.6；开发者×仓库固定效应 +1.4；对全部 PR（无论是否命名模型）重拟合 +0.5；熵平衡加权对照 +0.4；开发者等权 +3.7（区间 [−5.5, +12.9]，精度大降）；唯一显著的是全 PR 样本下开发者等权的 +3.6 [+0.1, +7.1]。升级侧：六次合并 −0.8、八次 −0.4、单一堆叠模型 −1.4、扣除日历对照 −1.1、开发者×仓库固定效应 −1.2（[−2.3, −0.02]，显著为负）。作者遵循 Rothman（1990）不做多重比较校正，转而考察所有设定下估计的规模与方向。

由于零结果本身就是发现，关键问题是数据能排除多大的效应：最宽松的读法下，停服设计排除超过约 4 个百分点的合并率增益，平均升级排除超过 0.2 个百分点，实际使用 Fable 5 的单 PR 上限 +8.0。作为对照，10.8 分基准差距若按行业直觉应兑现的生产力差异远大于此。

### 5.6 对照方式本身决定结论——附 E 的四层比较

作者在 7–8 月间另收集了 10,232 个同时段命名 Fable 5 或 Opus 4.8 的 PR，演示比较单位的影响力：像排行榜那样直接混合所有 PR，Opus 4.8 的合并率反而高 2.6 个百分点 [−4.6, −0.5]（显著）；加日历固定效应后 −2.3；限定同一批开发者内 −2.1；再限定同开发者同仓库 −0.9（不显著）；而停服 DID 设计给出 +1.4。开发者层面组内相关系数高达 0.42——混合比较主要在比较选择不同模型的开发者，而非模型本身。这一段是对所有 agent 排行榜方法论的正面打击。

## 六、效果优势的根源解释

本文的优势不是模型效果，而是识别策略与机制解释的强度。要解释的核心结果：为什么 10.8 分的基准差距没有兑现为产出差异？

### 6.1 根源机制与证据链

**机制 A：任务派发分布落在旧模型能力圈内。** 开发者交给 agent 的任务本来就不是 SWE-Bench Pro 上那些难题。论文实验支持的证据：升级后 PR 描述长度、提及文件数、feat 类新功能占比都没变化（附 F），说明开发者没有借新模型之力去啃更硬的骨头；94.5% 的 PR 在升级前就已合并，天花板封死了提升空间。外部佐证：Anthropic 对内部 132 名工程师的调查发现过半受访者只能把 0–20% 的工作完全交给 Claude；对专业开发者的访谈研究（Huang et al.）显示有经验者只派清晰、易验证、出错代价小的任务。因果链：任务派发分布 ≪ 模型能力边界 → 基准增益作用在真实派发分布之外的题目上 → 真实产出不受影响 → 合并率与周产出持平。这一链条中任务分布部分是论文直接测量（描述长度、feat 占比不变），能力圈判断由天花板证据间接支持。

**机制 B：基准构念本身偏离真实工作。** SWE-Bench Pro 以是否通过原始修复的测试判定成功，这些测试质量存疑（OpenAI 审计发现 Verified 中 59.4% 失败题存在缺陷）且只覆盖工程师工作的一小部分——不测需求澄清、风格适配、评审后的返工。厂商发布基准分数不附置信区间，分数差是否大于偶然波动无从判断（731 任务下 10.8 分差距的 95% CI 约 [6.4, 15.2]，虽为正但比宣传的裸分差宽得多）。Terminal-Bench 2.1 上 Fable 5 只领先 1.6 分——但作者指出这并非因为 Terminal-Bench 更贴近日常，而是五分之一的 Fable 5 运行因安全拒绝回退到了 Opus 4.8。

**机制 C：合并即自并，产出度量被自我把关主导。** 95% 自并、90% 无他人批准、中位半小时合入——合并率主要反映开发者自己认为代码够好了，而非通过了社会化的质量关卡。若模型间差异只在他人评审时才显现（写出让维护者更愿意接受的代码），本文估计会偏小。这既是对结果的限定，也呼应了 LGTM! 线关于 agent PR 免评审自并的发现。

**机制 D（对唯一显著负值的解释）**：Opus 4.6→4.7 升级后的 −4.1 与开发者×仓库设定下显著为负的 −1.2，可能部分源于 2026 年 4 月 16–20 日 Claude Code 的质量事故，该事故同时影响了升级窗口前后的两个模型。

### 6.3 综合判断与未决问题

**多研究共同支持的机制**：基准判定标准与人类工作标准脱节（B）——METR 的评审研究、OpenAI 的审计与本文的机制 D 三路独立证据互相咬合；任务派发分布限制模型代差兑现（A）——得到 Anthropic 内部调查、开发者访谈研究以及本文任务特征不变的直接证据支持。

**仍属推测的部分**：模型间差异是否会在社会化评审场景（外部维护者严格评审的仓库）显现，本文因自并占绝对主导而无法回答；merge 是否只是作者认为代码够好而非真的够好，需要更长的质量随访。

**适用边界**：结论限定于 Claude Code 用户、模型命名可见的 PR 子样本（约 1%）、以及合并类产出度量；它不否定 AI 编码工具整体相对无 AI 的价值（Cui et al. 的增益），只否定基准分差在真实派发工作上的兑现率。若未来开发者的任务派发分布随信任度上移（下放比例超过 20%），机制 A 的天花板可能松动，结论或需重估。

## 七、必要知识反推

假设让一个没有相关知识的人从零完成这项研究，最少需要哪些知识？

### 7.1 领域知识层

- **GitHub PR 生命周期**：open→review→merge/closed 的状态机，合并是代码被项目接纳的公共信号，revert 是事后撤销信号——没有这个概念就无法定义产出变量。
- **Claude Code 的署名机制**：Co-Authored-By 行默认写入提交，PR 描述可复用提交信息——这是能把 PR 映射到具体模型的唯一公开通道，不知道它整个数据管道无从谈起。
- **模型发布与基准格局**：Anthropic 各代模型的发布节奏、SWE-Bench Pro/Verified/Terminal-Bench 各测什么、分数怎么读——否则无法构造有意义的模型间对照。

### 7.2 方法论知识层

- **因果推断与 DID 设计**：平行趋势假设的内涵（需要什么混淆因素才能打破它：恰好只影响 Fable 5 用户、恰好始于 6 月 12 日、恰好止于 7 月 1 日）；固定效应吸收什么、不吸收什么；安慰剂检验与翻转对比的逻辑；聚类标准误；线性概率模型相对 logistic 的固定效应性质。
- **测量效度理论**：构念效度、代理测量——把基准分数到生产力的映射当作测量学问题来攻击，这是选题的智力支点。
- **工具变量式的强度缩放**：把按可用性的效应（翻转对比）除以实际使用率差（0.54），换算成按实际使用的效应——需要理解其假设（可用性只通过实际使用的 PR 影响结果）。
- **稳健性框架**：不做多重比较校正的理由（Rothman）、以估计的规模与方向跨设定考察替代显著性检验。

### 7.3 工程知识层

- **GitHub Search/REST API 的大规模采集工程**：分窗规避搜索截断、速率限制、正则精确匹配剔除松散命中、bot 账号排除。
- **事件研究的时间窗设计**：排除切换后紧邻日（代码可能是切换前写的）、P1 与 P3 不对称的处理、事件交互入选规则的事先设定以防 p-hacking。
- **外部效度检验设计**：抽样验证模型名与提交的一致性（200 PR）、估计命名 PR 的代表性（占比 1% 但合并率与未命名 PR 接近）。

### 7.4 知识融合的关键节点

真正的创造性融合发生在三处：其一，把一次出口管制事故识别为双重差分的天然干预（政策事件 × 计量方法）；其二，把默认署名行的工程细节转化为模型级识别通道（产品机制 × 数据管道）；其三，把产业界的基准营销问题转译为测量学的构念效度问题，再用经济学工具求解（测量理论 × 因果推断）。三个节点分别解决了识别来源、识别手段、识别对象三个层次的问题。

## 八、论文中可以提取的通用性灵感

**灵感一：代理指标的因果效度必须独立检验，不能由其构造过程自证。**

- 论文证据：SWE-Bench Pro 10.8 分差距在真实产出上最多兑现 4.3 个百分点的合并率增益（且不显著），行业默认的推理链条失效。
- 推广场景：(1) 医疗 AI 用诊断准确率营销，需检验真实临床结局；(2) 教育 AI 用考试提分宣传，需追踪长期学习产出；(3) 招聘中算法笔试分与入职后绩效的效度；(4) 推荐系统的离线 AUC 与线上留存的效度。

**灵感二：分析单位的选择可以彻底翻转结论。**

- 论文证据：附 E 中同一批 PR，混合比较时 Opus 4.8 反而高 2.6 个百分点（显著），逐层收紧到同开发者同仓库后缩为 −0.9（不显著），DID 设计给出 +1.4；组内相关 0.42 说明混合比较主要在比较人。
- 推广场景：(1) A/B 测试中混合新用户与老用户会掩盖分群效应；(2) 医院比较手术成功率须控制病人构成；(3) agent 排行榜混仓库比较会度量仓库习惯而非模型。

**灵感三：天花板效应下，改进只会出现在有失败空间的地方——先找天花板再找增益。**

- 论文证据：94.5% 的 PR 在升级前已 7 天合并、83.8% 的开发者所有 PR 全被合并，新模型无处分发力气；改看 1 小时合并率、有未合并 PR 子群、周产出量等有空间的指标，依然无增益。
- 推广场景：(1) 系统优化前先测基线是否已到物理上限；(2) 药物试验须选有症状空间的患者；(3) 自动化工具投资应投向瓶颈工位而非已饱和工位。

**灵感四：用户实际使用的任务分布决定技术上限的兑现率——能力供给与使用分布是两个变量。**

- 论文证据：开发者任务特征（描述长度、文件数、feat 占比）在升级前后无变化，Anthropic 调查显示过半工程师下放比例仅 0–20%。
- 推广场景：(1) 更强的数据库引擎遇不上复杂查询负载则无收益；(2) 高档 GPU 跑轻量推理是资源错配；(3) 组织引入高端工具后不改变任务分配结构，ROI 研究会低估技术本身。

**灵感五：被中断的自愿使用是稀缺的识别资源，值得快速动员研究。**

- 论文证据：停服窗口仅 19 天，作者在 11 月即完成全量采集、验证与多重稳健性，并同步公开加盐哈希的数据与复现代码。
- 推广场景：(1) 平台故障/政策突变对用户行为的冲击研究；(2) 断网/断电事件的准实验设计；(3) 企业灰度回滚作为天然对照。

**灵感六：零结果的价值由可排除的效应上界定义。**

- 论文证据：作者明确不与 11 分直接对比（单位不同），而是给出数据能排除的增益上限——停服设计排除约 4 个百分点、平均升级排除 0.2 个百分点。
- 推广场景：(1) A/B 测试不显著时报告置信区间上界而非仅 p 值；(2) 桥接安全性论证中给出可排除风险量级；(3) 无效药物试验中界定无危害边界。

### 8.7 附加灵感：发布方不报置信区间时，外部研究者可以自己算

- 论文证据：作者用 731 个公开任务给 10.8 分的基准差距补算了 95% 置信区间（约 [6.4, 15.2]），并指出厂商发布分数从不附区间，分数差是否大于偶然波动无从判断——这本身就是基准生态的一个公开缺陷。
- 推广场景：(1) 自动驾驶接管率统计的区间披露；(2) 医疗 AI 多读一致性的置信报告；(3) 任何以裸分差做营销的 leaderboard 均可被第三方用任务量反推噪声上限。

## 附录：读文时值得注意的细节

- **P3 的一个特殊混淆**：恢复阶段 PR 中 33.7% 带 Claude 行但不带模型名，其中 82% 来自单一开发者的自定义 footer——论文在敏感性分析中用封顶加权限制了该开发者的影响，这类单点依赖的透明处理值得同类研究借鉴。
- **恢复期的现实约束**：订阅用户在 7 月 7 日前每周只能把一半额度用于 Fable 5，叠加 Sonnet 5 于 6 月 30 日发布、美国 7 月 4 日假期——P3 的 26.9% 回用率不能简单读为需求疲软。
- **统计功效的诚实披露**：单一升级要检测 3 个百分点的变化（80% 功效）需约 650–1,500 名换模开发者，单事件永远达不到；只有合并五次升级才把区间收窄到约 ±1 个百分点。
- **数据可得性**：论文明确不点名任何开发者；GitHub 登录名、仓库名与 PR 链接均以加盐哈希替换后随复现代码公开——在隐私与可复现之间给出了可操作的范式。
- **与 8.7 灵感的呼应**：第三方给厂商分数补算置信区间这种做法，本身可以被社区制度化——若 leaderboard 普遍强制附带任务量与区间，裸分差营销的空间会大幅收窄。
