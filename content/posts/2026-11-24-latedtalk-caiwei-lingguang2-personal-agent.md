## 先说结论

灵光 2.0 的核心变化不是功能堆叠，而是产品内核的更换：从「对话」换成「事项」（内部叫 thread），对外心智从「帮你办事」改成「帮你管事」——蔡伟把这归结为「责任的转移」，并以此作为区分 Personal Agent 与 chatbot、任务型 agent 的本质标准。他明确否认「什么热做什么」：1.0 的 coding agent、2 月的世界模型、10 月的 PA 在他看来是一条线——「站在模型能力边缘做产品创新」；但产品形态一年三换这件事本身说明，to C 产品形态目前是模型能力边缘的函数，而不是产品规划的函数。六个多月的开发里，真正决定发布时点的不是智能而是安全：效果「大差不差的版本」早一两个月就有，但安全不到 60 分不发，红蓝演练后有些漏洞要两三四个月才补得上。上线一周多的反馈里最有信息量的不是留存「跟 Muse 差不多的水位」，而是人群变化——安卓/鸿蒙占比上升、iOS 下降，三端留存拉平，而 1.0 上 iOS 曾高出另外两端十个点以上；一周数据不足以定论，但这是「PA 可能比信息获取类产品更普惠」的第一个信号。商业模式他给了两条路——按生产力价值收费、按决策与连接价值收费——并判断绝对体量上后者（商家付费，类似抽佣与广告）可能更大；更远的终局是双边网络里 agent 与 agent 之间交易、平台作为中间枢纽提供决策与履约，这是本期最大胆也最不确定的判断。

## 一、三次转向，一条线：从 coding agent、世界模型到「帮你管」

主持人开场把外界质疑直接摆上桌：灵光 1.0 去年 11 月定位 coding agent，今年 2 月提「生成你的世界」讲世界模型，10 月 27 日 2.0 又定位 Personal Agent——「什么热做什么」。蔡伟的回应分两层。

第一层是产品史。他说灵光 1.0「一开始并没有完全定位成 coding agent」，团队的理念一直是「站在模型能力边缘做产品创新」，第一个切入点是基于信息的个人助理：当时的 chatbot 都以 markdown 输出，灵光用 coding 的方式写代码做结构化呈现，他称更结构化的内容大幅提升了信息获取效率——这是第一阶段。第二阶段是闪应用：模型能输出的不只是文字，还有语音、图片和可交互应用，微积分、几何这类教育 query 天然适合互动内容；海外 Lovable、Replit 服务的是中小 B，国内当时没做好，灵光把「做应用」的能力开放给普通用户。这里有一个被移动端硬约束改写的决策：绝大部分应用为桌面端设计，桌面用户能等三五分钟，移动端三十秒到一分钟以上就走掉；同步与异步因此成了两种产品形态，「闪应用」的「闪」就是这个约束的产物。第三阶段是今年 4 月的灵光圈：团队原以为闪应用适合做工具（瑜伽、体重管理），自己做的自己用，后来发现「女友生日惊喜」这类带内容属性的东西介于工具与内容之间，于是做了 UGC 社区。

第二层是为什么走到 PA。蔡伟给了两个「启发」：Claude Code 和 OpenClaw。他让 Claude Code 盯股票、波动超过阈值推微信，发现它靠调 GitHub 上的三方工具「居然搞成了」——长程任务能力到了实用阶段；OpenClaw（小龙虾）则证明了模型能力可以突破「对话」本身：去年之前绝大多数 AI 原生应用以对话框为主框架，但对话只是交互方式，不代表 AI 产品的本质，小龙虾出现在 Slack、Discord 等 IM 里就是证据。主持人的反方意见是：不用 Claude Code，我也会用移动端 app 盯股价；蔡伟的回答是「它更智能」——真助理是「合适的时候告诉你合适的事」，有些直接做、有些先提醒或请示，你告诉它盯什么不盯什么。这是「盯」与「管」的区别雏形。

真正的分叉在于独立形态。蔡伟说春节到 4 月一直在想两个问题：PA 值不值得一个全新的独立产品形态——而不是 chatbot 主产品的附庸，豆包、ChatGPT、Kimi 已有大量用户；以及模型能力到不到这一步。OpenClaw 的门槛给了第二个问题部分答案：他自己装了两三个小时，装好还要「养」，直接推给国内 C 端用不起来（后来被验证）。4 月之后团队全力走这条路，当时内部叫「灵光 2.0/下一代灵光」，没有考虑做新 app——PA 与灵光的主张一脉相承，是 app 的下一改版；只有 kill time 类产品才需要新 app（转写此处为「骚扰的东西」，疑为 kill time）。

写作者推断：这段叙述最有价值的不是「三次转向」本身，而是它暴露的 to C 产品规律——在模型能力快速移动的时期，产品形态由模型能力的边缘决定；团队自认为的「一条线」，在外界看来就是三次转向，差别只在于叙事是否跟得上。这与张小珺商业访谈录里蔡伟讲的「三代产品史」互为印证（见[本站 11 月 18 日文章](https://inkeast.github.io/MessageDaily/posts/2026-11-18-caiwei-personal-agent-history/)），本场新增的是 OpenClaw 安装失败这种一手细节，以及「为什么不做新 app」的明确回答。

## 二、六个多月做了什么：一条架构弯路、一组「眼力劲儿」、一条安全底线

蔡伟说持续管理跟进的 PA，底层架构与 chatbot、任务引擎不同：harness 内层更复杂，核心是 agent runtime——什么时候调什么工具、按时/按事件/按状态触发。最大的弯路是最早基于 OpenClaw 那一版（插件生态丰富），但 OpenClaw 的逻辑是操纵一个超级工具=电脑（「龙虾时代买 Mac mini」），适合桌面；搬到移动端做原生 PA，扩展性与可控性都差，试了一两个月放弃，改自研基建。生产系统与 demo 的差别在 cost、吞吐、延时、并发、稳定性。为什么用蚂蚁百灵基模而不是开源模型加后训练，他给了三点：生产期模型效果可控，有的问题要到预训练或 mid-training 才能解决；性能与成本的平衡点不一定在三方模型的大/flash/小三档里；三方不开 base 模型、不知数据配比——「海外做得好的 AI 原生产品，ChatGPT、Claude Code，都是模型与应用强耦合」。代价是「很多东西不 work」，灵光是向百灵提需求最多的团队。

第二件事是调效果。好助理的标准是「最合适的时候讲最合适的信息、办最合适的事」，要了解你、有上下文、「有眼力劲儿」。他的例子是发消息的频率：股票大涨大跌时发，还是特定股票有新闻时发；发多了烦、发少了失职。主持人后来追问「你们花了很多时间调效果？」蔡伟说是的，「今天发三条消息，内容是不是你最关心的，很不容易」——看上去是细节，对 C 端体验天差地别。

第三件事是边界。付钱场景目前不允许灵光默默付掉，一定提示并授权（他说未来不一定）；连接了钉钉、邮箱不等于可以在私人信息里为所欲为，「隐私没做好是巨大的灾难」。蚂蚁接入了 APASS 帮用户管控数据权限、给模型边界感；蔡伟强调边界感与效果是两件独立的事。主持人的反方意见是：支付要授权，自动化程度就低、人要时不时看——这正是本期没有展开的张力：责任转移的幅度，受限于授权的粒度。

这三件事被他收进「三要素」：智能、供给、安全可信，三块都要到水位，任何一块是短板都难满足需求。主持人转述用户吐槽「灵光只能调支付宝和阿里服务」；蔡伟的回应分两层：短期解释（Muse 相对无缝地链接服务，一部分靠 BD、大部分直接 MCP；灵光在蚂蚁接支付宝服务 ROI 高，即使只接开放生态也有地图、钉钉、机票、酒旅、股票信息）；长期判断（封闭还是开放取决于商业利益与用户利益，中国虽封闭仍有支付宝、微信几大生态，封闭/开放不直接与体验挂钩；去年同期的很多公司没开放接口，今年越来越多以 MCP 开放）。

安全是发布节拍器。蔡伟说，单从智能与效果，更早一两个月就有大差不差的版本，但安全是底线不是锦上添花，至少要到 60 分；主持人问 8 月底以来 Instinct 火爆、9 月初 Meta 发 Muse，着不着急；他说想过更早发，但对用户负责。第一版出来后请安全团队做红蓝演练攻防 agent runtime 与沙箱（用户间理论完全隔离），找漏洞与权限问题，有些补得很快、有些要两三个月甚至四个月，排优先级，最基础的安全体验必须堵的漏洞不可妥协。

算力账是本期最技术的一段。chatbot/任务类产品要快又要好：「豆包 10 秒、灵光 30 秒，哪怕好 10% 用户也不买账」；PA 的很多 query 在后台执行（早上总结 24 小时新闻，早十几分钟晚十几分钟差别不大），可以 20–30 秒——延迟容忍度高意味着可以用更小模型、更便宜的卡、削峰填谷提升 GPU 利用率；成本不是线性的，「chatbot 10 个 query vs PA 100 个不是 10 倍」。主持人引用巴克莱的测算：美国常驻型 agent 每月每 DAU 云托管推理成本 4 美元，比 ChatGPT 免费用户高十倍；蔡伟说具体数字不能透露但「能做到更低」，不知道巴克莱的口径（「是不是 Muse」），并给了一个大判断：算力成本 1–2–3–5 年会大幅下降，优先用户体验、先占领市场，不能用今天的算力成本看未来三五年。主持人追问「每人独立虚拟云主机还是池子」，蔡伟说成本上走池子的概念，「很多公司强调云主机是让用户觉得安全，本质是虚拟隔离」；主持人举了两台机子靠 CPU 温度信号传递信息的例子，蔡伟承认理论上完全隔离也不能保证数据不互通，有没有好机制满足安全隐私合规才最重要。这一段与硅谷101对话灵光 CTO 林怿时讲的「独立云主机」叙事互为印证（见[本站 11 月 12 日文章](https://inkeast.github.io/MessageDaily/posts/2026-11-12-antgroup-lingguang2-superapp-ecosystem/)），但蔡伟本场把「独立云主机」说成成本上走池子、技术上无区别——对公众叙事是一次不小的收缩。

## 三、上线一周：留存、人群下沉与「打不通部门墙」

蔡伟对一周多反馈的总评是「留存超出预期」，量级「大概跟 Muse 差不多的水位」；他特意说过去内测数据好、对外往往下降（内测多是公司内部同学），这次「出街」一周粘性反馈超出预料，而预期本来不高——因为很多供给没完全接进去。使用场景「五花八门」：理财、个人健康、娱乐生活，连智能硬件（车、机器人）这种极客场景也有；连接服务里用户用得好的前三：理财相关（支付宝类）、带个人 context 的邮箱与网盘、第三是钉钉——钉钉是「意外中的意外」，团队没怎么优化办公场景，但工作用钉钉约等于生活用微信，本质还是 context 多。邮箱也让他惊讶，「以为国内没多少人用邮箱，turns out 体量不小」。

人群变化是本场最值得跟踪的数据。1.0 用户集中在一二线白领高知人群，「比例超过一半以上，远超自然人口大盘」；1.0 的 query 曲线是早上上班涨、九点跌、午休涨、下午小跌「逐渐摸鱼」、四五点一路涨、峰值晚上十点多，「完美匹配一线打工牛马」。2.0 这几天发现安卓/鸿蒙占比提升、iOS 下降，两种可能：iOS 版做太烂，或 PA 形态更普惠。他的解释是：1.0 的信息获取/chatbot 形式市面上已有很多好产品（豆包、千问跑得很前），对下沉市场用户没提供足够增量价值；PA 现在没有已被广泛使用的应用，「不管一二线还是三四线，满足需求就会用」；留存数据上 2.0 三端差不多，1.0 上 iOS 留存明显高于另外两端十个点以上。

吐槽也集中在供给：「为什么这件事干不了」，本质是后面的服务没接进去。蔡伟承认大部分是供给问题、智能也有很多问题，但强调灵光形态在市面上「非常有特点」，用户对全新产品接纳度高，对「说能托管却托管不了」非常沮丧。印象最深的一条是「灵光能连接很多东西但打不通公司部门墙」；他的解释是不完全是部门墙——有些是支付宝里的服务但也是三方服务，需要三方授权，「不能默认一个公司就把所有东西拿过来用」，大趋势越来越开放，需要灵光、蚂蚁、生态合作方共同推。至于能快速改的，他举了 push 点进去详情页「非常粗糙」的例子，已经可以互动让它按你的风格改，但「很多用户说不出、不知道能干这个」；他给所有 AI 用户的建议是：任何不满意的地方先试着直接跟它说，很多时候有惊喜感。

关于形态，他判断对绝大部分用户「高频刚需」对 PA 成立，但产品形态不一定是今天灵光这样。Instinct 给的最大启发是「不一定只是独立 app，可以有很多出口」；团队讨论过不做 app、出现在 IM 或信息流里，判断至少国内先沿 app 形态效率更高，但短信、电话、智能硬件都在考虑，「PA 无处不在只是路径问题」；硬件优先选 context 多的场景，只提醒吃药所有 app 都能干，知道你每天说什么话、身体状况才能给建设性意见。Muse 的启发则是「克制、对细节的把控与调优」，他自己感受 Muse 的效果调得比其他竞品好。关于「PA 会不会是新入口」，他说有可能但也许不是唯一入口，也不认为 PA 会单一一统江湖把所有 app 挂后台——「如果是那样是悲哀的事情」，世界会失去前台多样性，后台更多是最后一公里履约；「单一前台+所有后台」是极端的完全效率驱动型假设，有人订餐厅选酒店喜欢自己干，PA 不指望解决每一类人的每个需求，切入点是某类人的效率类需求。这一段与[本站 10 月 25 日「AI 助理争夺战」](https://inkeast.github.io/MessageDaily/posts/2026-10-25-guigu101-ai-assistant-wars/)里对 Instinct iMessage 路径、Muse Goals 的梳理互为印证，本场新增的是一家中国大厂对「多入口」的明确表态。

## 四、怎么收钱、终局是什么：两种用户价值与双边网络里的 agent

蔡伟说团队最近在思考商业模式，起点是「商业模式是用户价值的外溢」。第一种是生产力价值：请人盯股票、天气、日历，成本一个月 100 块、创造价值 150 块，收中间价差，可按事项也可包月——主持人说跟 Claude Code 有点像，他说「有点像，本质帮你办事、办多少给多少」。第二种是连接与决策价值：灵光帮你挑商品很专业，等于让渡部分决策权，灵光是嫁接在你和商家之间的通道，国内语境大部分商家付费，「本质跟抽佣、广告费一样」。他判断绝对体量上中国商业生态里后者可能更大；前者的意义是帮灵光识别、筛选、分层用户（重度依赖事项的用户 vs 浅层信息需求），不一定赚那么多钱；「大头可能来自后者」，更期待两者之外出现其他模式，近期会沿这两个方面尝试。

第二种价值涉及远期终局：PA 发达后现有双边网络平台怎么演变。他的设想是有些双边网络自己进化、拥抱 agent 生态成下一代网络——很多交易决策由 agent 发生、agent 相互交易，部分商品与人群现在模型能力已经可达。主持人问：已有 agent 的商家和 agent 的我，还需要淘宝吗？蔡伟说淘宝不会是现在的形态但仍需中间大枢纽在两边的 agent 之间——需求要通过非常分散的商家满足，个人很难直接建立与所有分散商家的连接，需枢纽帮决策与履约（物流、仓储的规模效益好理解；信息连接层的平台价值就是决策）。他以女友生日选礼物为例：有人享受选、有人不享受但知道重要，有助理帮你决策时你关心的是好礼物、女朋友开心，不享受过程——「这就是中间决策的价值」。主持人追问「我不干涉过程只要结果，我的 agent 直连各种 agent」，他说那种形态也可能，但不会一蹴而就，现有网络提供的价值依然会在价值链里，「不是每个环节现在都能被 AI 取代」。小商家把服务做成 MCP 接灵光现在还不行，他在考虑对三方开放平台，「非常符合商家利益，商家应积极拥抱」。

壁垒问题他的回答有三点：持续跟踪你的事情有排他性——助理足够好就不需要那么多助理，市场最后「会有若干个，但少于十个甚至少于五个」主流 PA；迁移难度（context）；与商业生态有关，供给生态越好能力越强，是双边。窗口期他引用「客观规律」：绝大多数线上 C 端产品的特定形态窗口通常一年最多两年，但形态遇大变化后又有新形态（优爱腾之后仍有抖音快手）；核心看变化，不取决于最先跑出来的产品用户量级，「通常 3~6 个月持续领先」就算领先。指标上他最看托管事项数，辅助用户数、粘性、留存，不把灵光与主要看对话数的产品直接比较。主持人转述「昨天刚公布」的数字是托管超 160 万个事件、执行超 300 万次；公开报道 11 月 5 日口径是上线一周托管超 116 万项、执行超 360 万次、用户规模突破 2000 万，11 月 11 日口径是两周托管超 300 万项、执行超 1100 万次——节目口径与公开口径对不上，本文并列记录、不强行调和。

后来者多快能做出？他说壳容易做，难的是效果、性能、稳定性、安全，有样本后「至少是半年的工作量」且要投入足够资源，大部分公司不会这么做（追到半年后别人又演进，大概率选差异化）；大公司有积累可能从 20 分开始，从零半年、从 20 分四个月。主持人问投放为何克制、何时更激进，他说会非常快，产品角度希望阶梯式：发现问题→提升体验与智能→获得新用户；至于春节各家会不会「发红包搞个 PA」，他猜不会那么意外，但「单纯发红包意义没那么大」。

对字节豆包手机这类进驻 OS 的路径，他的评价是「非常好的尝试、不同的技术链路」：豆包手机本质是解决供给——直连供给、手机后台有很多服务可绕过；但实操层面会遇到困难，合作方觉得安全性没保障就「阶段性封禁」——这与[本站 10 月 8 日晚点聊 Q3 季报](https://inkeast.github.io/MessageDaily/posts/2026-10-08-ai-q3-review-personal-assistant/)记录的豆包手机操作其他 App 一周内被小红书、滴滴、微信封锁互为印证；灵光会看这样的技术方式但没选择走这条链路，「是判断和主张的问题」。硬件则「不完全是技术路线选择，是不同场景的 BD」：有耳机或 Pad 类设备挂在身上能收集当天声音与所有行为动作，context 更多、逻辑也通，但硬件得卖出去，是电子消费品逻辑，渠道、品牌感知、生产周期注定不可能那么快。为什么蚂蚁是大公司里第一个推出 PA 的？他说很难回答，也许别家之前战略中心没往这个方向；主持人的推测是今年上半年 OpenClaw 偏开发者、随后热点转到 Claude Code 偏办公/知识工作者，大公司重心随之迁移，C 端在 PA 起来之前是往下走的；蔡伟补充蚂蚁一直做 C 端投入，投放不激进但这条线一直在，有自己的 coding agent 但内部用、对外做得不多，蚂蚁特别之处是「科技普惠基因」——关键是信不信这个方向、知不知道怎么达到、当时能否拿到足够资源。

下一里程碑：托管事项再上一个数量级超过千万；他强调这比用户数更能反映用户价值——用户数只是每天来问个问题，做增长、做个打卡 DAU 也会加一个；千万放在中国网民里不是特别大的数，哪怕灵光完全不变，触达到对的人也完全可达。产品表达、测评体系都是产品价值主张的外延：先定义核心特色与差异化，再围绕内核定功能、评测、安全，「抛开内核谈评测、功能总能说出道理」，大小公司很多扯皮是维度不对。

## 五、「盯」与「管」：责任的转移，以及一个做了十五年 AI to C 的人怎么看阈值

主持人文案「能帮你管事」何时明确？蔡伟说 4 月就有想法，但那时没有「管」这个词，一开始很多场景用「盯」——帮你盯着，高频刚需契合产品；盯是管的子集，只是帮你看、有事告诉你；管有时可以直接执行掉，范围更广。核心区别是「帮你管事」与「帮你办事」不一样，灵光与 chatbot 类、完成任务类的本质区别是「责任的转移」：办事、问答责任都在我，我叫你做啥你做啥；真正好的 PA「我可以放心把责任交给你，你负责帮我搞定，你应该比我更关心我关心的事」。他举的例子是重要人物的私人医生团比本人更关心他的健康，建议何时体检、吃什么你就照做；做到责任转移后合作方式发生非常大变化——托付给他，真正从人的维度帮你解决问题。

未来一年的目标，他说是希望看到多种类型用户（不同职业、城市、年龄）在各种场景因为用了灵光「省掉很多生活带宽」、提升生活质量与效率，比如宝妈以前给宝宝做辅食、带宝宝用纸笔记，现在不需要了。他自己用灵光最多的是理财。惊喜时刻是发现能直接用它连接硬件——最开始不是设计场景，完全没讨论，模型层面也没专门加训；第一版产品后在灵光上发指令扫地机器人真动起来时「wow」。

蔡伟的经历是这套方法论的底色，完整脉络已在张小珺访谈中展开（见[本站 11 月 18 日文章](https://inkeast.github.io/MessageDaily/posts/2026-11-18-caiwei-personal-agent-history/)），这里只记本期新增的几处。2011 年创业做视觉搜索时技术还是 handcraft feature 加 part-based model，开 CVPR 聊的是 feature 多少维（4000 维、6000 维）、benchmark 提高百分之一，一年 CVPR 两百多篇，能把 CVPR/ICCV/ECCV 所有文章读完；to C 走了没多久就发现非常困难——团队年轻，「回头看很多东西不 ready」，转型给电商网站输出能力，2013 年把公司卖给 Pinterest。在 Google 他最早在 Image Search，那时 DeepMind 刚被收购一两年，后成立偏 research 部门，再后来整个团队并入 Gemini；Google Photos 从零做几年内涨到几亿用户，Lens 之前 Google 最早做过 Google Goggles，「看到一朵花想知道品种」的需求今天依然非常大。他说最大的 learning 是怎么做高度不确定性的技术产品——当时技术最多知道是花、不知品种，需要对模型能力有更好判断。离开 Google 后去 Stanford 读 MBA（脱产两年），2019 年回国创业、做 VC 投资；第二次创业在 ChatGPT 之前，用 GAN 做短视频 AIGC，设想 100% AI 解决实际只有 30%、六七十% 靠人补，招了人工剪辑、编剧——主持人总结为「人工为主智能为辅」。22 年底看到 ChatGPT 非常兴奋，「真放出来能用了，泛化性如此好」，当时已在做基金，国内一大批做大模型与应用的公司都有接触。选择蚂蚁而非第三次创业的理由：做大模型应用的资源门槛比移动互联网创业高得多——后者小团队融小几百万甚至小几十万美金做 demo 一步步做上去——他想做高影响场景，所以看资源更充裕的大厂，蚂蚁里也有之前在 Google 的老朋友；他至今认为大模型领域创业公司（PA、世界模型等）仍有机会，「创业与大公司用不同打法」。to C 方法论：把握技术趋势、匹配未被满足的需求；to C 难在需求要洞察（用户不会告诉你、问也没用），简单在「不管什么方式做出产品形态，用户真认可就认可，不管团队背景」。

技术阈值与用户阈值是他反复讲的框架：技术持续进行，起点 30 分每年涨 2 分，5 年到 40 分，突然一年涨 10 分到 50 分再到 60 分；用户侧感知不连续，技术演进积累到阈值，体验提升是代际性的；另一种可能是市场大变化（移动互联网，大家能手机）解锁新场景。局外看某年 GPT 爆发、深度学习爆发，从业者其实持续跟踪；启示是对技术发展保持乐观通常带来好回报，但要在一线判断「突破是把 50 分推到 55 还是 60，用户阈值是 55 还是 60」，正好卡到阈值就能看到产品爆发。他心中的执念是做一款国民级应用，把技术普惠到每个人——这是主持人在片头就点出的线索，也是本场所有判断的前提。

## 行业地图：机制 → 影响 → 启发

**链条一：产品内核从「对话」换成「事项」。** 变化：灵光 2.0 把基本单位定为 thread（事项），第二个 tab 叫「帮你管」，很多 PA 竞品选的是长对话。直接原因：模型已能持续消费大量上下文并跟进，蔡伟认为这是 PA 最大特色，功能只是内核的上层包装。谁得谁失：得的是能把「管」做深、有安全与供给禀赋的大厂；失的是以对话数为核心指标的 chatbot 产品，它们的增长方式（打卡、拉新）在他看来「不能反映价值」。二阶影响：评测体系跟着内核走——托管事项数可能成为 PA 的通用指标，但只有各家把「管事」当内核时才成立。观察指标：托管事项数/用户数的比值、跨领域留存、三端留存是否持续拉平。读者启发：做 AI 产品先定内核再定功能，「抛开内核谈功能就是比口才」。

**链条二：安全与供给成为发布节拍器。** 变化：灵光 2.0 晚了一两个月发，原因是安全不到 60 分；上线后用户吐槽集中在「干不了」而非「答不好」。直接原因：三要素里智能可以靠基模与 harness 追，安全要红蓝演练、供给要三方授权，都不完全在团队手里。谁得谁失：得的是有金融级安全积累与自有生态（支付宝、钉钉）的公司；失的是只能做「壳」的后来者——蔡伟估计有样本后也要半年，从 20 分起跳也要四个月。二阶影响：中国 app 生态的封闭会放大供给差距，「部门墙」与三方授权会持续成为 PA 体验瓶颈。观察指标：连接器数量（公开报道：截至 11 月 3 日接入支付宝、钉钉、夸克、飞书等 40 余项）、红蓝演练后的漏洞修复周期、用户「干不了」类反馈占比。读者启发：PA 的竞争不是模型竞赛，是安全、供给与模型三者短板的竞赛。

**链条三：商业模式从「按次」走向「决策权」。** 变化：蔡伟给出两种用户价值——生产力价值（办多少给多少）与连接/决策价值（商家付费，类似抽佣与广告）。直接原因：PA 介入了消费决策链路，让渡决策权意味着可以按决策结果收费。谁得谁失：得的是有商家生态的平台型公司（灵光在蚂蚁接支付宝 ROI 高）；失的是只靠订阅的独立 PA 产品和依赖前台曝光的商家。二阶影响：双边网络可能演进为 agent 与 agent 交易、平台作为中间枢纽提供决策与履约——这是本期最远也最不确定的判断，蔡伟自己说「不会一蹴而就」。观察指标：灵光是否上线商家侧收费、Muse/Instinct 的付费用户与交易佣金的实际结构、小商家 MCP 接入何时开放。读者启发：先问用户价值在哪，再问收费形式；「商业模式是用户价值的外溢」这句话对 to C 创业者是个好用的检验。

## 对照：与张小珺访谈、硅谷101对话林怿的口径异同

一致处（互为印证，一句带过）：三要素「智能/供给/安全可信」、春节后启动与 4 月定型、半年调效果与 OpenClaw 安装两三个小时、算力削峰填谷、Instinct 多出口与国内短信电话痛点小、Muse 的边界感、极客连扫地机器人、托管事项数指标——张小珺商业访谈录（[本站 11 月 18 日文章](https://inkeast.github.io/MessageDaily/posts/2026-11-18-caiwei-personal-agent-history/)）与本场的叙述一致。本场独有、本文展开的：从 coding agent/世界模型到 PA 的定位变化过程、「盯」与「管」、责任的转移、六个多月的架构弯路、上线一周的人群与留存反馈、商业模式两种价值与双边网络终局、豆包手机路径的评价、连硬件的惊喜时刻与未来一年目标。

## 尾声

蔡伟在结尾被问到「自己用灵光最多的是什么」，答案是理财；被问到惊喜时刻，答案是扫地机器人真的动起来。这两个答案放在一起很像本期节目的缩影：一边是精心设计的三要素、责任转移与双边网络终局，一边是产品上线一周后用户与团队自己都还没搞清楚的所有可能性。蔡伟的判断是需求「非常普世」、千万托管「完全可达」，主持人则反复把部门墙、供给、授权这些摩擦摆回桌面——两种视角之间，就是 Personal Agent 接下来一年要验证的东西。
