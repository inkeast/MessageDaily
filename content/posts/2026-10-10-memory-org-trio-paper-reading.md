# 用进废退、认识论分离与步级复用：Agent 记忆的组织、表示与使用 三论文精读

如果把 LLM Agent 比作一个新入职的员工，那么「记忆系统」就是他的笔记本：今天解决了什么问题、用户喜欢什么、上次踩了什么坑，都得记下来，下次遇到类似情况翻出来用。过去两年这个「笔记本」研究方向的重心，一直放在**怎么存和怎么检索**上——向量库存文本块、相似度排序取 top-K，这套范式被称为 RAG（检索增强生成）。

但 2026 年 10 月 8 日同日提交的三篇论文，恰好从三个不同角度质疑了同一个前提：**记忆的价值不由记录本身决定，而由它与当前任务的关系决定**。

- **Hippocam**（中科院信工所）说：一条经验该保留多少细节，取决于它服务于哪个意图、最近有没有被用过——被复用的知识应该被强化，久不用的应该自然褪色（用进废退）；
- **CogMem**（清华深圳研究生院）说：「Jon 被解雇了」和「Gina 认为 Jon 被解雇是个错误」在向量空间里几乎是同一个点（余弦相似度 0.8231），但它们的**认识论地位**完全不同——一个是事实记录，一个是某人的观点。这个区别必须写进记忆的**表示结构**里，不能指望检索时靠模型自觉；
- **DeltaReplay**（清华）说：检索到一条旧轨迹只是开始，**每一步**都该单独判断——这步能照抄吗？还是换个参数就能用？还是干脆别用？把记忆整条使用或整条丢弃，三种情况下各有一种会亏。

三篇论文分别处理记忆的**组织**（Hippocam：上下文即记忆）、**表示**（CogMem：认识论图模式）与**使用**（DeltaReplay：步级三路由），拼在一起恰好是 Agent 记忆系统的完整生命周期。本精读将逐一拆解。

## 一、论文背景：为什么「存起来再检索」不够了

先补齐几个基础概念。

**Agent 记忆系统是什么**：LLM 本身是无状态的——每次推理只看当前上下文窗口里装的东西。当 Agent 需要跨会话、跨任务持续工作（个人助手服务用户几个月、GUI Agent 反复执行手机任务），就需要外部机制把历史经验留存下来，需要时再注入上下文。这套「写入→管理→读取」的循环就是 Agent 记忆系统。

**主流范式是「被动检索」**：标准 RAG（Lewis et al., 2020）把文本切块、向量化、建扁平索引；查询时按嵌入相似度取回 top-K 拼进 prompt。围绕这套范式演化出大量变体：MemGPT/Letta 用操作系统式分页管理上下文，Mem0 做 CRUD 式事实更新，A-Mem 用卡片盒笔记法自组织，HippoRAG 用图结构加个性化 PageRank。

理解这套范式为什么长期有效，才能理解它为什么开始失效。被动检索的隐含假设是：**记忆的价值在写入时就已经确定**——相似度高的记录对相似的问题有用，所以「存好块、排好序」就足够了。上下文窗口的扩大（百万 token 级）一度还提供了另一条出路：干脆不建记忆，把全部历史塞进窗口。但两条路线都撞上了同一堵墙：模型面对的每一个决策，真正需要的不是「与查询最相似的记录」，而是「在当前处境下正确、且细节恰到好处的信息」。窗口再大，装满无关细节的窗口本身就是干扰；检索再准，取回的记录也还要回答「现在怎么用」。

**三篇论文各自咬住这套范式的一处裂缝**：

1. **上下文与记忆割裂**（Hippocam 的切入点）。上下文管理派（如 HiAgent 做子目标摘要、Context-Folding 折叠子任务）和记忆库派（mem0、A-Mem）是两套独立机制：前者管当前窗口装什么，后者管外部库存什么。结果要么是记忆库检索回来的内容与当前工作上下文脱节，要么是摘要蒸馏（如 ACE 的 playbook）丢掉了后续召回所需的具体信息——Hippocam 的实验里，ACE 在 LoCoMo 对话记忆基准上只有 22.5%，ReasoningBank 只有 18.3%，远低于记忆库方法。

2. **扁平表示抹掉认识论区别**（CogMem 的切入点）。「谁说的」这件事，在扁平向量库里无处安放。作者做了一个直接量化：构造 150 对「事实记录 + 高词汇重叠的归属观点」，BGE-M3 嵌入下平均余弦相似度 0.8231；当查询问「Jon 发生了什么」时，扁平 RAG 有 64/150（42.7%）的概率把「Gina 的观点」当成事实记录返回。作者称之为**语义坍缩（Semantic Collapse）**。这直接损害心智理论（Theory of Mind，即理解「他人信念可能与事实不同」的能力）类推理。

3. **整存整用的三种失败**（DeltaReplay 的切入点）。存下来的成功轨迹，与新任务的关系有三种：完全匹配（可照抄）、部分匹配（参数不同/只共享前几步）、不相关。现有方法要么把检索结果一律塞进 prompt（prompt 注入型），要么整条判定执行或丢弃（执行型），各支持一种用法。作者归纳出三种失败模式：**慢复用**（能照抄的步还要模型重新推理，GUI-explorer 用 GPT-4o 每步 66 秒）；**过度丢弃**（只差一个参数的记录被整条扔掉）；**误用**（不相关记忆塞进 prompt 反而误导——论文引用的 Darwinian Memory 消融中，只用任务目标检索弱相关记忆，AndroidWorld 成功率从 41.0% 掉到 29.7%，比不用记忆还低 11.3 个点）。

三篇论文共享一个大背景：**Agent 记忆研究正从「读」与「写」的单点优化，转向「记忆与当前任务的关系」这一相对性视角**。这个转向的外部证据在第六部分展开。

顺带一提三篇的机构画像：Hippocam 出自中科院信息工程研究所（共同一作制、通讯作者制，纯科研编制）；CogMem 出自清华深圳国际研究生院（NSFC 与深圳科技项目资助）；DeltaReplay 出自清华大学（Preprint、Under review 状态）。三篇均无企业合著，属于纯学术工作——这在这个沾着大量产业记忆系统（Mem0、Letta、Zep）的领域里不算多数派，研究动机更多来自科学问题（认知理论的形式化）而非产品需求。

## 二、论文定位和关联工作

### 谱系一：上下文管理 → Hippocam

Hippocam 站在三条线的交叉点上。**上下文压缩**谱系：LongLLMLingua 按查询相关性压缩、SUPO 学习压缩工具使用历史、Context-Folding 隔离子任务、HiAgent 摘要已完成子目标、AgentFold 训练模型折叠历史后缀——这些方法都只处理后缀（最近的工作），且用「推断的未来需要」指导保留。**记忆库**谱系：Generative Agents 给记忆打重要性分、MemoryBank 用遗忘曲线、Mem0/A-Mem/MemTree 做各种组织演化——都维护独立于对话的库。**经验学习**谱系：Reflexion、Agent Workflow Memory、ReasoningBank、ACE 从任务反馈中提炼策略。

Hippocam 的差异点：不建独立记忆库，**上下文本身就是记忆**；用显式意图边界（而非推断的未来需要）指导保留内容与粒度；把更早的前缀（而非只有后缀）纳入整合范围；记忆、知识、学习由同一个用进废退循环统一，而不是三套机制。

### 谱系二：图结构记忆与认知架构 → CogMem

CogMem 的灵感来源是**互补学习系统理论**（CLS，McClelland et al., 1995；Kumaran et al., 2016）——海马体快速编码情景、新皮层缓慢固化语义。图检索谱系里，LightRAG 用实体-关系图、HippoRAG 1&2 用个性化 PageRank，但它们的图模式是任务无关的，不区分归属信念与事件记录。更早的命题语义网络 SNePS（1986）建模过认知主体的信念结构。同场竞技的记忆系统包括 Mem0（层级偏好存储）、A-Mem（自我改进记忆库）、LightMem（剪枝降延迟）、GAM（把召回当深度研究过程）。

CogMem 的差异点：新颖性主要在**架构与表示层**——用 Claim 中间节点的两跳结构（Person→Claim→About→Person/Concept）显式承载「谁持有什么观点」，用意图驱动的确定性图算子替代静态检索管线。论文明确声明与另一个同名 CogMem（Zhang et al., 2025，三层架构做多轮推理）是不同系统。

### 谱系三：GUI Agent 经验记忆 → DeltaReplay

GUI Agent 记忆已有大量前序工作：探索记忆（AutoDroid、MobileGPT）、工作流（Agent Workflow Memory）、页面图（PG-Agent）、状态机与知识图（ActionEngine、EAM）、提示与捷径（Mobile-Agent-E）……论文的总结是：这些工作聚焦**存什么、怎么组织、怎么检索**，而检索到的记忆通常**作为整体**进入上下文或被执行。最接近的是 MAGNET（分离稳定功能与可变外观、抽象出带占位符的工作流），但它的分离在建记忆时就固定了，检索结果只作 prompt 参考。

方法论上，DeltaReplay 把 CRAG（纠错式检索增强生成，对检索结果做细化/丢弃/补充）的思想搬进 GUI 轨迹记忆，并把「记忆怎么用」本身作为研究对象。

## 三、问题定义

三篇论文把各自的具体场景抽象成了三个本质问题。

**Hippocam：如何在不建独立记忆库、不更新参数的前提下，让 Agent 从自己的交互历史中持续学习？** 具体拆解：给定不断增长的交互上下文 C 与嵌套的意图结构，求一套整合（consolidation）机制，使得（1）活跃上下文始终聚焦当前意图；（2）久远的经验逐步抽象但原始记录可恢复；（3）被复用的知识随新经验被强化、补充、更新。约束是：不维护独立记忆库、不设重要性评分、不设基于时间的遗忘规则——遗忘必须从「不被使用」中自然涌现。这个抽象的精妙之处在于把「记忆管理」转化为「上下文维护」：不是决定库里的东西去留，而是决定眼前这份不断生长的文本该怎么层层折叠。

**CogMem：如何让记忆系统区分「事实」与「谁认为什么」，并按查询意图动态重构答案？** 形式化地：给定嵌入函数 Φ 会把认识论地位不同的陈述压到相近向量空间区域（语义坍缩问题），求一种记忆表示 G=(V,E) 与检索机制，使得（1）归属信念与无归属记录在结构上可分离；（2）易变情景痕迹能固化为稳定语义知识且保留溯源；（3）同源冲突观点能按时间调和而不抹平分歧。关键洞察是把「认识论状态」从文本语义中剥离出来，变成图的**拓扑位置**——观点必须走两跳，事实只要一跳。论文还据此提出有效记忆系统的三性质：认识论完备性（区分信念与记录）、主动可塑性（从模糊意图动态构造检索路径）、动态稳定性（情景痕迹渐变为语义知识）——分别由 Claim 节点、搜索代理、巩固机制承接。

**DeltaReplay：给定一条检索到的历史轨迹，当前这一步到底该怎么用它？** 论文给出了最形式化的定义。每个记录步骤 e 有两个不可直接观测的性质：**可执行性** µ_t(e)（当前屏幕上能否按原样执行）与**适用性** ρ_t(e)（该步的操作是否推进当前任务）。由此每步落入三个区制之一：DIRECT（存在适用且可照抄执行的步骤）、PARTIAL（适用但需换参数或重接地）、INAPPLICABLE（无适用步骤）。正确用法分别为：照抄执行、在记录指导下选新动作、无视记忆。类比：CBR（案例推理）经典的 retrieve-reuse-revise-retain 循环里，前人把功夫花在 retrieve，DeltaReplay 把 **reuse 这一步拆到步级粒度**。

三个定义共享同一个思想内核：**质量是关系量，不是属性量**。一条记忆没有「好/坏」的固有属性，只有「与当前意图/查询/任务的关系」。三个抽象各自排除了什么干扰也值得注意：Hippocam 排除了「库」这个外部实体（否则就要回答库与上下文的一致性问题），CogMem 排除了「检索排序」这个单点（否则意图只能被压成查询向量），DeltaReplay 排除了「整条记录」这个单元（否则关系判断只能是布尔值）。抽象单元越小、越贴近使用现场，关系的分辨率就越高——这是三篇论文共同的解题哲学。

## 四、问题解法

### Hippocam：一个主 Agent + 三个辅助组件

架构像一家小公司：主 Agent 负责干活（推理、用工具、与环境交互），三个辅助 LLM 组件在旁边各司其职。

**JANUS（意图栈维护，双面神）**：把进行中的工作组织为嵌套意图栈——每个意图 i=⟨目的 p, 退出条件 χ, 起始消息位置 b⟩，意图可以嵌套（大目的套小目的）。JANUS 在主 Agent 每次推理前检查栈：该关的关（Continue/Close/Shift），该开的开（Deepen），并向主 Agent 注入第一人称引导。类比：一个只看方向不看动作的项目经理——「读文件」「跑命令」是手段不算新意图，「从调研转向写交付物」才是意图变化。

**PRECIP（意图整合，海马体）**：意图关闭时，把该意图管辖的工作消息压缩成一条自包含的第一人称消息，替换原文。保留什么有严格规则：已确立的状态变化、Agent 明确说过的结论及其证据（必须带出处、逐字保留）、外层意图还需要的未处理材料、有信息量的失败（失败且知道为什么行不通）；丢弃发现过程（怎么发现的不重要，发现的事实才重要）。类比：项目结项报告——结论、遗留状态、踩过的坑留下，会议过程丢弃。

**PALIM（递归前缀整合，涟漪）**：随着新意图开启，更早的消息变成「前缀」，PALIM 递归地把它们整合得越来越抽象。每次整合把消息拆成两部分：**叙事**（我做了什么、结果如何，每折一次粒度变粗一档）与**知识**（被证实的独立事实与教训，直接关于其主体陈述、带 good/bad/neutral 方向标记，跨折叠存活、可合并可更新）。何时整合由预算控制：保护至少 K=2 个交互轮、B=4096 tokens 的工作尾部（上限为上下文容量 W=128,000 的 20%），前缀积累满 16,384 tokens 且含 2 条意图整合后才常规折叠；预测占用超 0.80W 时压力清扫。

**消息树与渐进召回**：所有被替换的原始消息保留为替换消息的子节点，形成树。主 Agent 有一个 recall 工具，需要更细的证据时逐层下钻，每 recall 一次重新评估「够不够用」，够就停。类比：档案馆的摘要目录——先看摘要，不够再调卷宗，卷宗里还有更细的原始记录。论文的两个 MemoryAgentBench 案例展示了深度自适应：一个问题一轮 recall 就凑齐了三条事实记录、嵌套引用保持关闭；另一个问题第一轮只暴露一条作者记录、竞争性的作者/语言记录还藏在嵌套引用后面，第二轮再下钻一层才凑齐——召回深度由问题的证据需求决定，而不是把整棵树展开。

**用进废退闭环**：被召回复用的知识参与新工作，其成败反馈连同新观察一起进入下一轮整合（被强化/补充/修正）；没被用到的知识在递归整合中细节持续褪色。没有评分、没有定时遗忘——prominence 完全由使用驱动。论文用一个 ALFWorld 例子展示了知识演化的全生命周期：「把目标物体拿到台灯下再用灯」最初是具体操作，随后在碗、钟、铅笔、雕像、书、马克杯上反复成功，知识吸收了跨物体类别与任务措辞的证据，最终以不逐一列举类别的一般形式存在；同时一个寻常的遥控器放置情节，先保留目的地细节，再缩为完成任务清单里的一项，最后情节细节从叙事中完全消失——知识在生长，情节在褪色，两者同步发生。

论文附录 B 给出了三个组件的完整 prompt，其中的约束设计值得玩味。JANUS 的规则包括「绝不为主观臆测的未来开意图」「绝不在部分进展时关闭意图——必须有完成证据」「绝不基于声称的意图关闭——只有交付的结果才算数」；PRECIP 的规则包括「绝不总结具体内容——摘录原文（摘要会逼你重读源文件）」「绝不替 Agent 推断——不从 Agent 未分析的内容得出结论」「绝不投射未来——不写下一步计划」；主 Agent 的记忆规则则强调「记忆读起来是散文，是因为它被整合过，不是因为它比工具结果更不可信」「bad 标记的条目不是别人留给你的警告，是你已经试过的事情」。这些第一人称设计（记忆以「我」的口吻写就）让主 Agent 把整合消息当作自己先前的工作而非外部转述——这是「上下文即记忆」在心理层面成立的关键细节。

### CogMem：PEC2F 图 + 认知搜索代理

**写入（Memorize）**：每轮对话增量转成图记录。五类节点：Person（人）、Concept（概念，向量聚类得到）、Event（时间地点绑定的具体事件）、Fact（观察到的稳定属性/习惯，注意这是操作记录类型不保证真理）、Claim（归属观点）。Claim 是核心创新：「Jon 认为 Gina 很懒」不是 Person 节点的属性边，而是一条两跳路径 (p_jon, CLAIMS, n_claim) ∧ (n_claim, ABOUT, p_gina)——观点节点自带内容与情感倾向。每个节点保留源轮次标识与时间戳，Evidence Grounding 算子随时能找回原话。

**离线巩固（Consolidate）**：模仿 CLS 的情景→语义转化。同一人-概念对在 30 天窗口内聚成至少 3 个事件，触发 LLM 抽象函数合成高层 Fact 节点（如三次「去徒步」→「有徒步习惯」），并用 SUPPORTED_BY 边连回源事件（Evidence Mounting 策略：不删原始情节，抽象层提供语义捷径、需要细节时可下钻——与 Hippocam 的消息树异曲同工）。同源 Claim（同 source/target/predicate）按时序调和为 CURRENT/SUPERSEDED/CONFLICTING 视图，**不同说话者的观点永不合并**。

**读取（Reason）**：一个基于 ReAct 的认知搜索代理，规则控制器先做 LLM 意图解析，再触发四个**确定性**图算子：锚定 O_anchor（混合词法+语义打分取前 15 个入口节点）、时空遍历 O_traverse（按边类型与时间窗过滤邻居，最深 2 跳）、交集 O_intersect（多实体邻域求语义重叠，找共同点）、证据接地 O_ground（回溯原文验证）。控制器最多 5 步，证据足够即停。类比：不是把图书馆整个搬来看，而是先查索引卡（锚定）、按目录翻（遍历）、交叉比对两本书（交集）、必要时调原件（接地）。意图与算子的映射是规则化的：查询含「比较/共同点」触发交集，问「A 怎么看 B」触发带 Claim 边类型的遍历，含时间表达则触发带时间门控的遍历，要求验证时触发接地——LLM 只负责解析意图与判断证据是否充分，走哪条路是确定性代码，这让检索路径可复现、可审计。

一个完整例子走一遍：问「Caroline 和 Melanie 都喜欢什么活动？」——锚定找到两个人物节点；意图解析识别出「都」→ 交集算子在两人邻域求 Concept 交集，得到{露营、艺术}；遍历验证两人到这两个概念都有 LIKES 边；证据接地抽回原文确认。问「Caroline 是什么时候从瑞典搬来的？」——锚定后带时间过滤遍历事件时间线，找到 2019 年的搬家事件，再接地到原话「当我 2019 年从瑞典搬来时」。两条查询走的是完全不同的算子组合，这就是「主动重构」与「统一相似度排序」的区别。

### DeltaReplay：转移图 + 步级三路由

**记忆形态**：每条成功轨迹是转移图中的一条路径——节点存页面（截图+UI 树），边存动作（类型、元素、输入文本）。每条边的关键拆分：**任务无关操作**（打开哪页、点哪个按钮，只要屏幕匹配就可复用）与**任务特定参数**（输入的名字/金额/日期、何时结束，必须替换）。按任务标识（同任务/同模板/同族/同 app）检索。

**每步决策流程**：

1. **结构匹配**：当前屏幕与跟踪位置的记录节点比对 UI 树余弦相似度（宽松阈值 ≥0.60）与结构重叠（≥0.70），或模糊文本匹配 ≥80。匹配则做 **VerifyMap**——按结构上下文（而非元素索引）在当前屏幕找记录目标元素的对应物，所以索引从 23 变 26 也能找到。
2. **语义匹配**：屏幕对不上时，取屏幕严格匹配（≥0.65/≥0.80）的至多 8 个候选步，LLM selector（看到目标、历史、当前 HTML）选正确的下一步，**可以显式全拒**。
3. **三路由**：Route A（照抄）——结构校验通过且该步不带旧任务参数，直接执行映射后的当前动作，**零模型调用**；Route B（换参重接地）——该步适用但带旧参数，四条规则（无模型调用）判定是否带参，然后**把新旧任务描述逐词对齐、配对出旧/新参数、替换后在新屏幕上找元素**执行，对不齐或多个元素同名则弃权；Route C（丢弃）——其余一切情况（映射失败/selector 全拒/Adapt 弃权），基座 Agent 用与无记忆时完全相同的 prompt 兜底，若其动作与下一记录步等价则路径位置仍前进。

**安全性设计**：照抄/换参的步可能在不变屏幕上静默失败，所以不在同一屏幕重复执行同一步。附录 J 给出理论：转移一致性条件下重接地可正确迁移（命题 1）；当正确匹配无害时，丢弃路由把每步损失下界钳制在误接受率 δ（命题 2）——这是「敢丢弃」的数学兜底。

用一个论文图 1 的例子串起全流程。记忆里存着旧任务「关闭 WiFi，然后打开蓝牙」的轨迹；新任务是「打开 WiFi，然后打开相机 app」。两条任务描述逐词对齐：WiFi 对 WiFi（同一个实体），off 对 on（参数不同），bluetooth 对 camera（后面的步骤完全不同）。于是第一步走 Route B——操作是「切换 WiFi 开关」（任务无关、可复用），参数从 off 换成 on（任务特定、必须替换）；到蓝牙那步，屏幕与记录分叉、语义匹配也找不到适用步，Route C 接管，基座 Agent 自己打开相机。整个过程只有 selector 处可能花一次模型调用，能照抄的步全部零调用通过。

selector 的 prompt 还按记录来源分了四种头部话术，每种都注入不同的先验警示：同任务记录直接恢复执行；同模板记录明确警告「记录中的名字、文本、数字、日期属于那条运行而非当前目标——在当前目标自己的值被输入之前绝不选依赖它的步骤」；同族的更易任务记录警告「其目标只是当前目标的前缀，绝不选会结束任务的候选」；同 app 的其他任务记录只允许借用「穿过 app 的路径」（开应用、到某屏、打开表单或列表），「它输入的值、它的选择和它的结束属于那个任务」。这些头部话术是三种失败模式的 prompt 级防线，与路由的算法级防线互为表里。

## 五、评估指标与实验证据

### Hippocam：8 项指标的能力矩阵

骨干统一为 DeepSeek-V4.1-Flash（1M 上下文），对比 Plain（无记忆基线）/HiAgent/mem0/A-Mem/Letta/ReasoningBank/ACE。四个研究问题分别是：能否从累积经验中学习（RQ1）、学到的东西能否跨域泛化（RQ2）、记忆在长交互中是否可靠（RQ3）、这套统一机制有多通用（RQ4）——整个评估矩阵就是按这四问设计的，每个基准对应一到两种能力而非泛泛打分。

| 基准（能力） | Hippocam | 最强 baseline | 差距 |
|---|---|---|---|
| ALFWorld 成功率（具身任务学习） | 97.8 | ACE 97.8 | 并列第一 |
| ScienceWorld 进度（科学实验） | 81.9 | ACE 91.9 | 次优 |
| StreamBench 准确率（流式任务学习） | 81.7 | Letta 81.3 | +0.4 |
| 跨域 Frozen SciWorld（知识迁移） | 78.9 | ACE 62.7 | +16.2 |
| FEVER（QA→事实验证迁移） | 61.8 | HiAgent 61.8 | 并列 |
| GoodAI interleaved（交叉任务抗干扰） | 88.7 | Letta 51.7 | +37.0（mem0 仅 3.3） |
| LoCoMo 整体（对话记忆，judge 准确率） | 77.6 | A-Mem 67.5 | +10.1（时间类 86.6 vs 67.6） |
| MemoryAgentBench multi-hop（冲突消解） | 71.7 | Letta 44.3 | +27.4（64k 输入 41.0%，无 baseline 超 37.0%） |

8 项中 7 项领先或并列第一。注意评估设计的巧妙之处：单看任何一项都可能「偏科」，这套矩阵专门检验**同一个机制能否同时支撑学习（StreamBench）、迁移（跨域 ∆：SciWorld +19.2pp、FEVER +6.0pp，为仅有的两个双正增益方法之一，另一个是 ACE 的 +14.0/+2.0）与长期可靠性（LoCoMo/MAB）**——支撑了「统一机制」的核心主张。跨域实验还有个容易被忽略的对照设计：Frozen（每个目标任务独立评估、同一源域快照）测纯泛化，Sequential（带源域记忆跑完整目标序列 vs 空记忆起跑）测知识整合，∆stream 差值衡量源域知识是帮还是拖累后续学习——mem0 在 SciWorld 上 ∆stream 为 −28.1pp，说明其记忆不但没帮上新领域还在拖后腿，这种「负迁移」只有这种配对设计才能暴露。

值得单独一提的还有 RQ4 的能力画像分析（论文图 1 的解读）：各 baseline 呈现明显的偏科——A-Mem 强在 ScienceWorld（87.2%）但 multi-hop 仅 24.3%；ACE 强在 ScienceWorld（91.9%）但 LoCoMo 只有 22.5%；ReasoningBank 同样弱于对话记忆（18.3%）。论文由此提出一个诊断性观察：经验蒸馏出的「指导性知识」不必然保留后续召回所需的「具体信息」——HiAgent 靠子目标式上下文组织取得更均衡的画像，暗示组织工作上下文本身就能支撑较广的需求面。Hippocam 则在均衡之上叠加了整体领先。

消融三连（各击一个组件）：去意图条件化，GoodAI interleaved 从 88.7% 掉到 65.6%（孤立模式 85.1→77.8），无关填充内容保留率从 14% 升到 63%——意图边界决定「留什么、留多细」；去前缀整合，ToolBench 从 78.7% 掉到 65.7%，ALFWorld 步数 9.62→11.74、起始上下文 19.7k→50.7k tokens——递归抽象支撑后续工作效率；去 recall，MAB-64k 从 41.0% 掉到 27.0%——摘要不能替代原文。另一个反事实：把前缀整合换成 ACE 的 playbook 生成，ALFWorld 成功率同为 100% 但步数 9.00 vs 8.12——直接使用保留的事实与教训并不输于先蒸馏成策略手册。

两个延伸观察值得单独记录。其一，StreamBench 从 150 任务延伸到 300 任务后累计准确率：DDXPlus 93.0%（A-Mem 91.3%、Letta 91.7%）、ToolBench 78.7%（A-Mem 74.3%）——领先随经验积累扩大而非收窄，说明学习没有在早期饱和。其二，MAB 按输入长度拆开：6k 时 97.0（与 HiAgent 并列）、32k 时 77.0（最强 baseline Letta 仅 37.0）、64k 时 41.0（无 baseline 超 19.0）——历史越长，整合+召回的相对优势越大；论文还附带了 DetectiveQA（十部长篇小说上 71 个问题）的 85.9%，作为超长叙事推理的旁证。

成本分析（StreamBench 后 150 任务）：准确率升高的同时每任务成本降约 10%（DDXPlus 87.3→98.7%、0.0095→0.0085 USD/任务）——稳定前缀带来缓存复用，ToolBench 每正确答案成本 0.0173 vs A-Mem 0.0271 美元。但作者诚实指出：整合本身有价（前缀整合占 ToolBench 成本 34.0%），成本优势依赖缓存折扣（缓存价低于缺失价约 15% 时优势才保持），不构成跨供应商的一般性结论。

### CogMem：语义坍缩探针 + 双基准

探针实验直接验证核心问题：150 对事实-声明，扁平 RAG 误归因 42.7%（64/150），PEC2F 类型约束检索降到 6.0%（9/150）。评估还做了三项控制以增强可比性：所有方法统一 BGE-M3 嵌入（消除表示质量差异）、统一答案生成 prompt（隔离检索质量的贡献）、统一答案模型上下文上限（各方法自己的检索上限按官方推荐配置）—— architectural 差异无法完全对齐，论文如实声明。

LoCoMo（F1，Qwen2.5-14B 骨干）：Single-hop 60.40 / Multi-hop 48.42 / Temporal 56.20 / Open Domain 55.80，四类全第一；最强记忆 baseline GAM 的 Multi-hop 为 42.96、学习式遍历 RoG 为 41.80。GPT-4o-mini 骨干同样全类别第一（59.20-63.80）。LongMemEval 总体准确率：GPT-4o-mini 68.40 / Qwen 66.50，均第一（次优 LightMem 64.29）。50 例盲评人偏好：胜 68%/平 20%/负 12%（作者自评样本小，仅作辅助证据）。

消融对应三组件：去 ReAct 代理（换固定三步管线），Multi-hop F1 从 48.42 崩到 22.81（−25.61，最大降幅）——自适应导航是第一大贡献；去 Claim 节点（拍平为属性边），知识更新准确率 73.08→56.67（−16.41）——认识论分离直接支撑更新类任务；去巩固，Multi-hop 48.42→43.56（−4.86），且平均推理步数从 3.42 降到 2.67——语义捷径既提准又提效。

成本核算：LoCoMo 全量构建记忆耗 1,578.2k backbone tokens / 1,216 次 LLM 调用，低于 A-Mem（1,626.8k）、Mem0（1,799.4k）、MemoryOS（2,991.8k）。代价是图增长：巩固后节点 +14.8%、边 +47.4%（新增 497 个 Fact 节点、540 节点/4,708 边）——用存储换检索效率。100 例错误归因：向量语义漂移占 23%（开放域 32%）、时间归一化失败占时间类错误 44%、模式粒度损失占 11%——结构化改善关系/时间证据的获取，但嵌入漂移等失败模式仍在。

消融之外，两组敏感性分析给出了算子设计的「甜点区」：锚定候选数 K 呈倒 U 型（K=3 时「锚定盲视」掉 4.6 点，K=15-18 饱和，K>18 噪声反噬）；遍历深度 D=2 最优（D=1 不够多跳、D=3/4 只添噪声）；交集算子 K=10 峰值。这些曲线说明「主动检索」的收益依赖超参与图规模的匹配，不是免费的。

### DeltaReplay：按记忆覆盖分组的对照设计

这个实验设计特别值得学习：**按「记忆中与当前任务最接近的记录」分组**（same task/same template/same app/none），因为记忆只含成功运行，覆盖组与任务难度相关，跨组成功率不可比，必须分组报告。两骨干（Qwen3-VL-30B、Qwen3.8-Flash），LLM 裁判判成功。

| 覆盖组 | 基座（Flash） | DeltaReplay（Flash） | 记忆可用性 |
|---|---|---|---|
| AndroidWorld 同任务（n=20） | 80.0（21.7s/步） | 90.0（9.3s/步） | 大量可照抄步 |
| AndroidWorld 同模板（n=22） | 63.6（19.5s/步） | 86.4（12.6s/步） | 参数不同 |
| AndroidWorld 同 app（n=48） | 39.6 | 41.7 | 仅可借导航步 |
| AndroidWorld 无记录（n=26） | 30.8 | 34.6 | 无 |
| SPA-Bench 同族（n=15） | 0.0 | 46.7 | 共享前缀步 |

总体：AndroidWorld-116 上 +10.3/+7.8pp（两种骨干），SPA-Bench-60 上 +25.0/+16.6pp。同任务时延从 21.7 降到 9.3 秒/步（−57%，模型调用 2.11→1.00 次/步）。42 个有模板记录的任务上配对 McNemar 检验 p=0.039。SPA-Bench 同族组是「部分匹配」的极端检验：15 个任务两个基座全部失败（0.0%），DeltaReplay 靠复用更易任务共享的前缀步拿到 33.3%/46.7%——从零到有的跃迁只能来自记忆，这是覆盖分组设计才能呈现的证据。

对照两组负结果记忆基线：RAG-prompting 41.4%（低于无记忆基座 49.1%，且最慢 34.8s/步）、GUI-explorer 47.4%——**塞进 prompt 的记忆在覆盖低时是毒药**（same-app 组 RAG-prompting 掉到 25.0%，none 组 11.5%），而 DeltaReplay 在这些组不降反升。GUI 专训模型 GUI-Owl-1.5（50.9%）也被两个通用骨干+DeltaReplay 超过。

消融直击主张：朴素照抄（不校验直接回放记录）在 same-template 只有 9.1%——记录对它自己的实例正确、对新实例错误；去 Route C（不丢弃、总执行最佳记忆候选）45.5%，低于基座；去语义匹配（same-app）20.0%——适用性判断必须先于重接地。路由盲标（Claude Fable 5.1 标 150 步，对路由不知情）：A 路由精度 83.7%、B 78.0%（其中参数替换步 19/20 正确，跨任务借步 20/30）、C 75.5%，差异在约 ±10-12 点的采样误差内。路由占比随覆盖变化：same-task 时 A 占 56.1%，same-app 时 C 占 89.9%——路由机制确实在按记忆可用性分配用法。

另外两个实验细节体现了评估的克制。运行间方差被显式标定：无记忆可用的 26 个 AndroidWorld 任务上，DeltaReplay 与基座成功率差一个任务、时延差 2.1-4.1 秒/步，作者据此把「约一个任务/组、约 2-4 秒/步」划为噪声带，避免把随机波动解读为提升。成功判定统一用 SPA-Bench 单 app 评测器（LLM 裁判读全部步骤截图），在 AndroidWorld 自带规则检查器可用的 75 个任务上与裁判标签一致率 91.5%（248/271）——两个基准、所有方法共用同一把尺子。

## 六、效果优势的根源解释

### 根源机制与证据链

**Hippocam 因果链**：

1. baseline 的根本局限有两处。记忆库方法（mem0/A-Mem）检索回来的内容脱离当前工作语境：GoodAI 交叉任务下 mem0 只有 3.3%，因为库里的条目没有「服务于哪个意图」的维度，交叉干扰无差别命中；经验蒸馏方法（ACE/ReasoningBank）把经历提炼成通用策略，但策略是**去情景化的**，丢掉了后续召回所需的具体信息——LoCoMo 上 22.5%/18.3%，说明「知道怎么做」救不回「记得说过什么」（论文实验已支持）。
2. Hippocam 的本质改变：意图边界把「保留什么、保留多细」变成条件化决策（消融：去意图条件化后无关填充保留率 14%→63%、interleaved 掉 23.1pp——论文实验已支持）；整合保留原文成树，使「抽象上下文」与「可恢复细节」不再是二选一（去 recall 掉 14pp——论文实验已支持）。
3. 机制传导：意图条件化 → 上下文高信噪比 → 交叉任务抗干扰（88.7%）；原文成树+渐进召回 → 学习指导与证据召回兼得 → LoCoMo 77.6% 与 MAB 71.7%；用进废退 → 知识随使用演化 → 跨域整合增益 +19.2pp。
4. 用进废退的微观证据（论文附录 A.6，属观察性关联而非因果证明）：ToolBench 3,086 次知识项转移中，被使用项 28.4% 被补充、无使用项仅 0.9%；ALFWorld 里被文本复用的项保持不变的比例更低（41.6% vs 63.2%，即更多被改写更新）——使用与知识演变相关联。

**CogMem 因果链**：

1. 局限根源：嵌入空间的几何由词汇语义主导，「解雇」与「认为解雇是错的」共享大部分显著内容，认识论区别在这个空间里**没有对应的维度**（探针：余弦 0.8231、误归因 42.7%——论文实验已支持）。
2. 本质改变：Claim 两跳结构把认识论状态从语义空间**搬到拓扑结构**——查询要的是记录就排除 Claim 节点，要的是观点就走 CLAIMS 边。误归因 6.0%（论文实验已支持）。调和视图（CURRENT/SUPERSEDED）让「事实变了」有结构化的时间线可查，而不依赖模型从一堆相似文本里猜先后（知识更新 73.08 vs 去 Claim 56.67——论文实验已支持）。
3. 检索侧：固定管线无法按意图调整搜索路径 → 意图解析触发算子组合（比较→交集、时间→门控遍历）→ Multi-hop/Temporal 提升最大、去代理崩 25.61pp（论文实验已支持）。巩固提供语义捷径 → 检索步数 3.42→2.67、Multi-hop +4.86（论文实验已支持）。
4. 阅读者推测：语义坍缩探针是合成数据（按 LoCoMo 模式构造），真实对话中的坍缩率可能不同；错误分析显示向量漂移仍占 23% 错误——结构化缓解但未消除表示层面的瓶颈。

**DeltaReplay 因果链**：

1. 局限根源：整存整用把「记录与任务的关系」这个逐步变化的量当成整体常量。prompt 注入型对无关记忆也无条件条件化 → 误导（same-app 39.6→25.0）；执行型整条判定 → 参数不同即全弃（朴素照抄 9.1%）；两者的损失 Mechanism 不同但同源（论文实验已支持）。
2. 本质改变：把复用性拆成两个可判定因子——页面一致性（结构匹配可验）与动作通用性（操作/参数拆分）——于是三种区制各有对应用法。结构匹配是零模型调用的确定性校验 → 可照抄的步不再推理（时延 −57%、调用 2.11→1.00）；参数替换救回「只差参数」的记录（63.6→86.4）；显式丢弃+命题 2 的界 → 无关记忆不受伤（same-app/none 组不降反升）（论文实验已支持）。
3. 反事实推理：去掉任何一路都会复现对应的失败模式（去 Route C 45.5%<基座、朴素照抄 9.1%）——三路由缺一不可，这正是「区制覆盖完整性」主张的直接验证。

### 综合判断与未决问题

**多研究共同支持的机制**：（1）分离+巩固的双层结构（CLS 理论、Harvard adapter 工作、两篇论文互证）；（2）粒度对齐——记忆单元切到使用粒度（技能粒度研究与 DeltaReplay 跨域互证）；（3）无关记忆有害、选择性使用必要（DeltaReplay 的 same-app 对照、IBM 剂量研究、context rot 综述三方一致）。

**仍属推测的机制**：用进废退是否真能替代显式遗忘规则——Hippocam 的知识演变证据是观察性关联（API 连接的代理指标），作者也承认相邻整合统计不能确立未用知识的一般性褪色；CogMem 的语义坍缩在真实（非合成）对话中的发生率未知。

**优势的适用条件**：Hippocam 依赖骨干模型的长上下文与缓存计价，且单次运行评估、部分消融未过显著性线；CogMem 的构建成本（1,578k tokens）与图增长（边 +47.4%）在超长史上可能放大，其错误分析自认时间归一化（时间类错误 44%）与嵌入漂移仍是短板；DeltaReplay 的检索按基准任务标识进行（作者自列为局限），记录按 app 版本冻结、不处理 app 更新导致的元素消失，参数依赖任务描述显式给出（「明天」这类隐含值交回基座）。

**可能的失效条件**（阅读者推测，论文未直接检验）：意图结构在意图频繁切换、深度嵌套的工作流中维护成本可能激增（JANUS 在主 Agent 每次推理前都要运行一次）；Claim 分离在「谁说的」本身不重要的领域（单用户、无社交对立面的助手场景）收益会缩水，退化为一套普通图 RAG；步级路由的屏幕匹配阈值（余弦 0.60/结构 0.70）跨 app 生态（桌面、Web）迁移时未必保持，结构相似度对重排版 UI 的鲁棒性未验证。

## 七、必要知识反推

假设一个完全没有背景的人要做这三件工作，他最少需要知道什么？

**领域知识层**：

- LLM Agent 的运行机制（上下文窗口、工具调用、多轮交互）——不知道这些就无法理解「上下文即记忆」的可行性边界；
- 人类记忆科学的核心结论：Tulving 的情景/语义记忆二分、Ericsson & Kintsch 的长时工作记忆、Miller & Cohen 的前额叶目标导向注意、CLS 双系统理论——Hippocam 的组件分工与 CogMem 的巩固机制全部由此映射而来，不知道理论就只能做出工程上零散的摘要器；
- 心智理论（ToM）与归属信念的语义——CogMem 问题定义的前提；
- GUI 自动化与移动 app 的现实：UI 树结构、元素索引的不稳定性、app 频繁更新——DeltaReplay 的操作/参数拆分直接来自这个领域知识。

**方法论知识层**：

- RAG 与向量检索的数学（嵌入、余弦相似度、ANN 索引）及其失效模式——三篇论文的 baseline 全在这上面；
- 案例推理（CBR）四步循环——DeltaReplay 的概念骨架；
- 图论基础与图遍历/personalized PageRank——CogMem 的算子设计；
- 消融实验与配对检验设计（McNemar、符号检验）——三篇的评估严谨性来源；
- 检索后处理的既有范式（CRAG 的细化/丢弃/补充）——DeltaReplay 明言的方法论出处，知道它才能看清「把检索后处理搬到步级」增量在哪里；
- 简单的决策理论工具（效用界、条件期望分解）——DeltaReplay 附录 J 的两个命题用的不过是 undergraduate 级别的不等式，但正是这一点让「敢丢弃」有了数学表述：关键不是数学深，而是想到给「不用」建模。

**工程知识层**：

- 提示工程：三个辅助组件（JANUS/PRECIP/PALIM）的行为完全由结构化 prompt 约定（附录 B 全文给出），包括大量 NEVER 规则——知道「用约束清单塑造 LLM 组件行为」是必备技能；
- 基准构建与评测协议：LoCoMo 的 judge 协议、覆盖分组设计、缓存感知的成本核算——评估「记忆是否真的有用」比做记忆本身更难；
- 移动设备/模拟器操作与 LLM API 计价；
- 复现级的环境工程细节：DeltaReplay 在真机（Redmi Note8）与模拟器（Pixel 6 AVD）上跑、排除有真实副作用与登录墙的 app、为 LLM 裁判设计截图分批摘要协议——这类「脏活」知识决定了实验能否成立，却很少出现在方法论教材里。

**知识融合的关键节点**：

1. **意图 = 记忆组织的坐标系**（Hippocam）：把认知科学的「目标导向注意」映射为 LLM 上下文的消息分段结构，这一步让「保留粒度」变成可条件化的决策——领域知识（前额叶理论）× 工程知识（上下文管理）的化学反应；
2. **拓扑承载认识论**（CogMem）：意识到嵌入空间没有「谁说的」这个维度后，把命题语义网络（SNePS）的思想翻译成现代图 RAG 的节点类型设计——理论移植而非新 primitives；
3. **区制 → 路由**（DeltaReplay）：把「记录与新任务的关系」形式化为两个可判定属性（µ/ρ），再让每个区制对齐一种用法——这个抽象让「记忆怎么用」第一次成为可以列表格、可以证明界的独立研究对象。

## 八、论文中可以提取的通用性灵感

**灵感一：质量是关系量，不是属性量**（三篇共享）。核心思想：一个信息单元的价值（保留多少细节、要不要分离表示、怎么用）没有固有答案，只相对于当前意图/查询/任务成立。论文证据：Hippocam 的意图条件化消融（interleaved −23.1pp）、CogMem 的类型约束检索（误归因 42.7%→6.0%）、DeltaReplay 的覆盖分组（same-template 63.6→86.4）。推广场景：知识库建设（条目粒度按使用场景分层而非统一模板）；教育（同一知识点对不同目标学生保留不同深度）；缓存系统（淘汰策略按访问模式而非固定 TTL）；推荐系统（物品价值按用户态相对化）。

**灵感二：有损压缩 + 无损归档 + 按需下钻的三层结构**（Hippocam 消息树与 CogMem Evidence Mounting 不约而同）。核心思想：抽象层负责日常效率，原文层负责极端情况的可追溯，中间用溯源指针连接——不要在「摘要 vs 全文」间二选一。论文证据：Hippocam 去 recall 掉 14pp、CogMem 巩固省 0.75 步/查询且细节可经 SUPPORTED_BY 找回。推广场景：日志系统（摘要索引+原始日志冷存）；代码文档（API 摘要+可跳转实现）；法务合规（决策摘要+完整证据链）；个人知识管理（卡片笔记+原文锚点）。

**灵感三：把判断从语义空间搬到结构空间**（CogMem）。核心思想：当两种语义高度重叠但地位不同的信息在现有表示中不可分时，不要改进表示，而是给它们不同的结构位置——让「类型」先于「相似度」发挥作用。论文证据：余弦 0.8231 的陈述对靠两跳拓扑分离后误归因 6.0%。推广场景：数据库设计（软删除与状态机替代覆盖更新）；风控（传闻与审计证据分表存储）；协作系统（个人观点与团队决议分频道）；新闻核查（原始报道与转述评论结构分离）。

**灵感四：复用前先做零成本的确定性校验**（DeltaReplay）。核心思想：能用结构校验（屏幕匹配、元素映射）解决的问题不要花模型调用，把昂贵的不确定性推理留给真正需要判断的地方。论文证据：Route A 零模型调用、整体调用 2.11→1.00 次/步、时延 −57%。推广场景：编译器（语法检查在类型推断前）；CI 流水线（lint 先于测试先于人工评审）；检索系统（布尔过滤先于语义排序）；API 网关（限流规则先于业务逻辑）。

**灵感五：显式拒绝路径是安全下界**（DeltaReplay Route C + 命题 2）。核心思想：任何辅助决策系统（记忆、建议、自动化）都必须有一条定义良好的回退路径回到无辅助基线，且这个「敢不用」的选项让系统在辅助质量差时不劣于不用——数学上把损失钳制在误接受率。论文证据：same-app/none 组不降反升 vs RAG-prompting 掉到 25.0%/11.5%；去 Route C 后 45.5% 低于基座。推广场景：医疗 AI 辅诊（不确定时回退标准流程）；自动驾驶（置信度低交回驾驶员）；代码助手（建议无效时保持手写路径）；投资顾问（信号不足时默认指数基金）。

**灵感六：遗忘可以从动态中涌现，不必显式编程**（Hippocam 用进废退）。核心思想：与其给每条记忆维护重要性分数和遗忘曲线，不如让「被使用」本身成为强化信号、让「不被使用」通过递归抽象自然褪色——规则更少、偏差更少。论文证据：无评分无遗忘规则的系统在 8 项指标中 7 项领先；知识项被使用后 28.4% 被补充 vs 未使用 0.9%。推广场景：组织知识管理（常用文档自动浮出、久置文档自动归档）；个人笔记（按 revisit 频率重组层级）；产品功能排序（使用驱动的默认配置）；语言学习（间隔重复的另一种实现思路）。

**灵感七：评估要按「关系的存在性」分组，而不是只看总体平均**（DeltaReplay 的覆盖分组设计）。核心思想：当方法的效果依赖某个外部条件（记忆里有没有相关记录）时，把该条件显式定义为分组变量、分组内比较，比总体平均更能揭示机制——总体平均会把「记忆有用组的收益」与「记忆无用组的噪声」搅在一起，既高估方法也掩盖失败模式。论文证据：DeltaReplay 总体 +10.3pp 的背后，是 same-template 组 +22.8pp（63.6→86.4）与 none 组 +3.8pp（噪声带内）的异质组合；RAG-prompting 总体 41.4% 的背后，是 same-task 组 80.0% 与 none 组 11.5% 的剧烈分裂——不看分组就会得出「记忆注入还行」的错误结论。推广场景：A/B 测试（按用户与新功能的接触度分层分析）；药物临床试验（按生物标志物分组做亚组分析）；营销归因（按触点暴露分组衡量创意效果）；教育评估（按先修知识水平分组检验教学法）。

## 结语

三篇论文放在同一天读有一种奇特的一致性：它们都没在「更大的记忆库、更强的检索器」上继续内卷，而是各自把「记忆与当前任务的关系」变成了可操作、可度量、可证明的研究对象——Hippocam 用意图结构组织它，CogMem 用认识论拓扑表示它，DeltaReplay 用步级路由消费它。对做 Agent 系统的工程师，最直接的行动项是：检查你的记忆系统有没有「敢不用」的路径（灵感五）、你的摘要层下面有没有可下钻的原文层（灵感二）、你判断记忆相关性的坐标系是不是任务相对的（灵感一）。对研究者，三篇论文留下的共同空白也同样清晰：Hippocam 的单次运行与未显著的消融、CogMem 的合成探针外推性、DeltaReplay 的任务标识检索，都是下一轮工作的入口。
