## 先说结论

当基础模型一个版本一个版本地变强，AI 应用公司还能守住什么？这是主持人 Koji（转写通篇误作"科技"）在本期《十字路口》开场的定调，也是嘉宾 Jason 与石天鑫九个月里三次转型反复回答的同一个问题。他们的答案对同类团队颇有参考价值：其一，未来六到十二个月"零人公司"不是可行场景，值得做的是人与 Agent 大量协作的场景；其二，所有工种的工具正在统一成 Claude Code 和 Codex，这是一次类似"Facebook 之于 Zynga、eBay 之于 PayPal"的平台跃迁，围绕它做产品是当下少数确定的机会带。他们据此收敛出的产品是 Treg（官网 treg.to，转写多误作"Trig/Track"）——"面向数据和工具的 OpenRouter"：一个 Key 聚合大量专业数据与工具端点、纯按量付费，上线约三周收入已是上一个产品 Super Design 的好几倍（Jason 称具体数字不便分享）。对不创业的读者，这期节目同样给出三条可检验的机制链条：分发渠道向 Agent 平台迁移、模型订阅红利重塑单位经济、Agent 成为工具的"真正用户"进而重构工具市场——下文逐一展开。

## 九个月三次转型：一场"模型变强之后，应用还剩什么"的生存实验

先复原时间线。Jason（93 年生，重庆大学热能与动力工程本科，后赴澳洲读交互设计）此前在澳洲创业公司 Relevance AI 带产品与 AI 团队，三年多前就在做全自动销售、SDR；石天鑫（94 年生，电子科技大学嵌入式系统专业）在苹果中国做过半年多测试工程师实习，之后在阿里、字节待了十年。两人去年年底开始创业，九个多月里完成了三四次转型（0:00–4:00）。

第一个产品 Super Design 是设计 Agent。它的起点是 Jason 自己的 YouTube 频道：UI 设计相关视频流量巨大，说明需求存在，于是先做了 Cursor 插件——"跟它说我要设计这个东西，直接给你出来三四版不同的版本"——随后开源，几个月拿到六千多 GitHub Star，且完全是自然增长（2:00–6:00）。Jason 由此得出的经验是：开源在 AI 产品赛道是重要的营销工具。但正式创业后他们反而没有继续走开源：一是没看到 IDE 插件形态好的商业化路径；二是插件意味着用户必须先用 Cursor、Claude Code 或 Codex，他们想让更多人用，于是转向网页版——"但没想到后面一年的变化是大家全都涌入了 Codex 跟 Claude Code"（4:00–6:00）。

真正逼停 Super Design 的是两个机制（4:00–6:00）：一是模型前端能力代际跃升——从 Gemini 3 开始所有大厂都卷前端能力，OpenAI 和 Anthropic 被倒逼补足，Jason 直言"这又是一个模型吞噬应用的故事"；二是 Claude Code、Codex 作为通用 Agent 基础能力越来越强、Skill 生态发展得很好，用户拿 Claude Code 加上比较火的前端设计 Skill 也能出不错的效果。单点应用被模型和平台两头挤压，是团队今年早期焦虑的直接来源。

第二个产品 Crewlet（转写中同一名字出现 Coolate、Colet、酷睿等多种误写）诞生于今年二月到六月 Jason 称为"魔幻时间"的窗口：一款 OpenAI 产品（转写为"Open Cloud"，具体名无法确认）让大量创业者相信 AI employee 的未来已来，纷纷转型涌入这个赛道。Jason 的直接契机是二月份看到 Posia（转写疑似）——一个"AI 帮你运营整个公司"的产品，当时年经常性收入约十几万美金，体验让他"大为震撼"，上一次这种感觉还是第一次用 Cursor。主持人 Koji 也是用户：Posia 仅凭他的邮箱就推断出身份、推荐了"给播客主用的 AI 后台"，他充了几百美元开了"God Mode"，结论是"没有帮我赚到钱，只帮我花钱"；Jason 的体验类似但更进一步——Posia 帮他做好网站、写开发信（cold email）找客户，"那个 email 竟然还有人回了"——但产品形态"看上去非常 dodgy"，很难把真实业务的内部系统接进去（6:00–10:00）。

Jason 复盘出的机制是：Posia 最聪明的地方是把"从零到一"做到丝滑极致——注册即生成创业想法、搭好落地页，这也是它几个月做到十几万美金 ARR 的原因；但真正进入业务线后要交付结果，这部分它做不到（8:00–10:00）。Crewlet 想补的正是后者：进入已有业务的公司，做全自动的"零人增长团队"，覆盖 SEO、社媒、广告预算自动调整、找客户。产品上线后有用户愿意预付费（pre-order），但"真要递交结果，我们发现太难了"（10:00–12:00）。难在两点：数据不一定拿得准，工具市场本身很分散；营销没有银弹，有效渠道是动态变化的——"当每个人都在做这件事情的时候，这个渠道好像又没有那么有效了"，其中很需要人的品味（taste）。他举的例子很具体：让 Agent 做 SEO 选词，工作流是找流量好、竞争低的词去下注，但大部分关键词早被抢光，真正的机会是那些当前流量不高、而你判断一到三个月后会火起来的词——这种判断很难完全交给 Agent（12:00–14:00）。

于是团队做了事后看最有价值的决定：暂停产品开发，回到仍有自然流量的 Super Design 上，花两个月"用 AI 运营这家公司"，把它当作零人公司的对照实验（14:00–16:00 附近）。结果落点清晰：客服支持可以全自动、bug 修复可以自动化，但增长相关的工作非常难自动化，需要人介入的判断太多。由此得到两条确定性判断——未来六到十二个月零人公司不是可行场景，要解决的是人机大量协作的场景；以及一定要围绕 Claude Code 和 Codex 生态做产品（14:00–16:00）。用 Jason 的话说，这两个月的价值是"帮我梳理了一下对未来一些判断的确信"，否则团队很可能还在迭代 Crewlet，纠结是不是 Skill 没做好、Prompt 没调好（34:00–36:00）。

把这一节抽成机制链条：模型能力代际提升（前端能力、通用 Agent 加 Skill 生态）→ 挤压单点应用的差异化空间 → 应用团队被迫从"做全栈 Agent"退到模型和平台够不到的层（数据、工具、工作流）→ 二阶影响是"交付结果"类产品大量证伪、"从零到一"类产品体验内卷 → 对读者的启发：判断一个 AI 应用值不值得做，可以先问它挡住了模型的哪条进步路径。

## 一个没做宣发的插件，改变了增长曲线

"围绕 Claude Code 和 Codex 生态做产品"这个结论不是推演出来的，是一次意外实验的结果。Jason 说，做 Crewlet 期间他们试了很多增长实验都没什么用，真正改变增长曲线的，是石天鑫某天把 Super Design 原有的 CLI 加 Skill 发布到 Codex 刚开放的 Work 和插件市场——没有任何宣发，海量用户涌入（14:00–16:00）。石天鑫还原了细节：早期市场里没多少有意思的插件，ChatGPT 和 Codex 本身已有巨大用户群，插件只要有吸引力就能被看见、被转化；他们还观察到当时插件市场按字母顺序排序，于是把名字从 Super Design 改成"01 Super Design"，短暂排到了第一位，几天后平台改了排序规则，但这个起步带来了最初的一批量（16:00 附近）。更关键的后验指标是：来自这个渠道的用户流失率（churn）更低（16:00–18:00）。

主持人在此补充了行业判断：Codex 和 Claude Code 有海量用户但体验没有做好，围绕它们做增益"有点像当初 Facebook 出来之后 Zynga 在上面做游戏，PayPal 在 eBay 上做支付"（16:00–18:00）。Jason 还提到他与一位创始人（转写为"U wear"，公司名无法确认）聊到的观察：今年之前设计师用 Figma、做营销的用邮件序列工具，各工种工具不同；今年以后大家的工具统一成了 Claude Code 和 Codex——"一个比较大的平台跃迁"（26:00–28:00）。

与之对照的是自建全栈的教训。Jason 坦言之前做 Agent 时想涵盖的东西太多：Harness 自己做、推理自己做、有人甚至自己做沙盒和记忆层——"你做的每一层，都有一个对应的公司在不断的优化和迭代"，小团队在全栈上跟整个行业赛跑必输；最近的迭代方向是把某一部分做得很好，嵌进 Claude Code 和 Codex 生态（24:00–26:00）。

这条链条可以写成：平台开放插件市场，叠加巨大存量用户 → 早期分发红利（哪怕排序规则都很原始）→ 插件形态嵌入用户既有工作流，流失率更低 → 二阶影响是创业公司的冷启动逻辑从"买量、内容"变成"占平台身位" → 启发：平台早期的规则粗糙本身就是红利。石天鑫的总结是"早期的这些工具和市场都值得去尝试一下，因为你不知道某一个尝试就获得了流量"。

## Treg：给 Agent 的 Costco、按量付费与数据飞轮

复盘 Crewlet 时，团队发现各家的 Harness 差别不大，真正可迁移的资产是工具和数据那一层——Agent 要做真实的 go-to-market 或专业工作，需要大量专业数据和工具，而他们内部本来就为 Crewlet 做过一层中转服务。把它单独拿出来，就是 Treg（16:00–18:00）。商业模式极简：用户调用 API 和数据，按用量付费，没有任何月费。上线约三周，收入已是 Super Design 的好几倍（18:00 附近）。

付费最集中的场景是 go-to-market：越来越多人在 Codex 和 Claude Code 里做原来要用 SaaS 做的获客工作。以海外找 B2B 客户为例，过去要分别购买 Apollo、RocketReach（转写误作"Rocket Search"）等供应商，每家只覆盖一部分数据、又都按月收费，用户往往只能选一家；聚合之后可以按场景和行业挑最合适的端点。此外还有 SEO、AEO 排名与 AI 可见度数据源，以及社媒 UGC 场景下生图、生视频的端点——他们接入了上百种 AIGC 相关模型。石天鑫特别提到视频模型（如 MiniMax 的视频模型，转写为"H3"，疑指海螺 Hailuo 系列）质量高、价格好，但普通人为一次性需求办包月并不划算，这正是按次付费聚合的用武之地（18:00–24:00）。

主持人问了两个尖锐的反方问题。第一：Claude Code、Codex 不接 Treg 也能干这些事，会不会慢慢不需要这一层？Jason 的回答划出了两层边界：业务工作需要的是实时数据，不是模型开箱即知；浏览器抓取能拿到一部分，但找人、社媒等很多数据抓不到——不少平台基本把爬虫关掉了。主持人在此补充了身边案例：他有朋友选 Kimi 的原因就是 Kimi 接入了万德（Wind）的股票交易数据——数据本身的独占性已经开始反向选择 Agent Harness；而 Treg 代表中立市场的另一面：各家 Harness 享用同样的工具，用户从 Claude Code 切到 Codex 时，积累的工具调用和数据都留在原地（20:00–22:00）。第二：为什么这层价值最终属于 Treg，而不是最强的数据供应商直接对接模型公司——你们是不是阶段性的中间层？Jason 的回答是定位式的："我们站在一个中立的点上……更像一个 Costco"；现实是每个场景都有几十个供应商、各有所长，"这个行业就有一个头部提供商可以解决最好的方案"的假设（转写此处出现的"Codegen"一词无法确认所指）并不成立。他以 Clay 为例：它背后的数据大部分来自一批按 API 用量收费的数据提供商，Clay 整合后转卖，而这些供应商本来就没有很好的终端触达方式（20:00–22:00）。

最有想象力的部分是数据飞轮。石天鑫提出："我们现在的很多产品的真正用户其实并不是一个人了，而是这个人的 Agent。"Treg 的机制包括：随机挑选用户让 Agent 给产品反馈，简单 bug 直接修掉、有趣的功能请求收进来；更系统的是类似大众点评的端点评分——让 Agent 对每次 API 调用做脱敏评价（返回数据有没有用、哪个字段起了作用），沉淀出每个端点在"有用度"和"性价比"上的得分，展示给后续用户，让他们的 Agent 按需选择：要精确性就挑最贵最好的端点，要广度和便宜就挑高性价比端点（22:00–26:00）。Jason 把它总结为应用团队的通用策略："既然我们没有办法训练我们自己的模型，我们总要让一些数据去反哺我们自己的产品。"

这条链条：Agent 成为工具的实际调用者 → 工具选择从"人的品牌认知"变成"机器可读的效果与价格数据" → 聚合平台用 Agent 反馈形成数据飞轮、反向定义端点排名 → 二阶影响是数据供应商的终端分发权让渡给中立聚合层 → 启发：凡是"用户是 Agent"的产品，都应设计机器可消费的评价体系与计费颗粒度（按次、按结果）——这正是 Treg 与传统 API 市场的本质差别。

## 生态红利与其他玩家：两百美元套餐与五五开的终端用户

这期节目事实上是一份"Claude Code / Codex 生态机会清单"。成本结构上，Jason 点出一个常被忽略的红利：直接向模型公司买 token 再转卖给用户，对创业公司压力很高；而 Codex 和 Claude Code 的用户花 200 美元编程套餐，获得的是当下价值约六千到七千美元的 API token 使用量——"这个红利，作为用户和我们这些比较小型的创业公司，都要想好怎么利用"（28:00–30:00）。这解释了为什么围绕编程套餐用户做生意、而不是自建订阅制 Agent，在单位经济上顺得多。

生态里的其他样本（28:00–34:00）：Apify（API 市场、长尾爬虫端点）和 DataForSEO（SEO 数据供应商）都是存在多年的公司，今年"莫名其妙"获得大量增长（Jason 语）；Exa（转写误作"Axel"）专注为 Agent 做搜索，石天鑫称应已到 C 轮；Composio、Firecrawl（转写误作"FireCrew"）做工具编排、OAuth 授权与网页抓取，增长明显。石天鑫的观察是：这些传统上算基础设施的公司，用户结构正从几乎全部开发者变成接近五五开——一半是终端用户，是不编程的白领，"他只知道我接了 Firecrawl 以后，我的 Claude Code 可以抓网页抓得更高效一些"。工具的采纳决策者从人变成了人的 Agent，这是对"基础设施公司该怎么做 PLG"的重新回答。

主持人也贡献了两个案例（26:00–28:00）：ChatCut（转写疑似）的 Codex 插件让 Agent 剪视频时先产出带编辑器的"中间状态"——三个音轨、十个片段，可以拖拽微调——而不是直接吐出一个无法增量修改的成片。这个设计直指生成式工具的痛点：视频每改一次要重新渲染十到二十分钟、烧大量 token，中间状态的本质是把"生成"变成"可操作"；而 Jason 作为宣发视频工具 Hyperframe 的重度用户补充说，中间状态他自己也不改，而是把反馈打包让 Agent 去操作。另一个是 Eagle（转写名存疑），一个主打"用 Codex、Claude Code 操作，computer use 效率极高"的浏览器。石天鑫还举了两个更轻的例子（32:00–34:00）：Vibe Island 把 MacBook 灵动岛做成多任务完成通知器——像素小人加声音，AI Hacker House 黑客松冠军作品，在 X 上发布后付费销量很好，两位嘉宾都买了；以及朋友"晶晶"做的 Orca——"Agent 的 IDE"，同时管理 Claude Code 和 Codex 的多个会话，核心卖点之一是"Codex 配额用完，把做到一半的任务平滑转移到 Claude Code"，两边薅羊毛；已有八万 GitHub Star，有的用户同时跑五十到一百个会话。

## 留在牌桌上的人：Loop、模型组合与技能贬值

方法论层面，主持人问起 Posia、Crewlet 时期流行过一阵的"Loop Engineering"（36:00–38:00）。Jason 的切分是：创业分创新和运营，创新显然没法靠 Loop——"你帮我造一个创业公司，此时是达不到的"；运营里 Loop 有很多踏踏实实的事可做。石天鑫引用《系统之美》，给出相当具体的工程原则：Loop 不要一开始建得太复杂，建短小精炼的——一个 Loop 只监控数据库找安全风险，一个只做代码整理，"小到它不太容易出错"；十几个小 Loop 之间的配合（某个 Loop 修的 bug 引发问题，线上监控的 Loop 会兜底发现并提示）自然形成系统的健壮性。他举的真实痛点是：产品一旦有邀请奖励、赠送 credits 这类激励机制，就会持续招来黑客攻击，四个人团队每天折腾这些非常痛苦——长期运行的监控 Loop 能把这类损耗接住（36:00–38:00）。团队也真实经历过至暗时刻：某天醒来发现被盗刷了约四千美元的 credits，"你觉得天都塌了"（48:00–50:00）。

工作方式的变化（38:00–44:00）：Jason 说最大的区别是同时跑的会话（session）比以前多得多——尤其 Fable 这类模型（转写一处作"Fibre 5.1"，疑似）发布后，自动完成质量已很高，他会同时开五到十个会话；其次是从纯本地转向云加本地混合，尤其 Grokbot（写法存疑）把云端沙盒体验做得"极致丝滑"，他们把 Treg 和 Super Design 的所有 Loop 都搬了上去。Jason 还提到 Grokbot 买了 Cursor（嘉宾陈述），他由此理解了这件事的合理性：Cursor 最好的部分是沙盒——每个编码任务有对应沙盒；本地开五六个隔离环境很难，云端点开即测，PR 里带链接随时进沙盒验证。石天鑫的对应做法是"大副模式"：受 YouTube 上一位工程师（转写名"昆"）的 First Mate 工具启发——船长只跟大副布置任务，大副去调度其他会话——他用 Herder（存疑）这类新一代终端管理工具让 Agent 之间互相沟通。模型选择上，Jason 几个月前还是 Claude Code 重度用户，Astra 发布后换到 Codex，最震撼的体验是把一段视频一次性一比一复刻，模型甚至自己从原视频截图、裁剪、再嵌进新视频；石天鑫则两个都用：没有绝对领先，Fable 某天强一点、Astra 立刻反超，"这个时代需要长期用世界上最好的模型，去感受他们的差异"。国产模型的分工也很具体：Kimi 曾作为 Super Design 的主模型（设计能力强）、MiniMax 的视频模型质量价格俱佳、石天鑫个人喜欢 DeepSeek 4.1 Flash 的效率，但生产环境大量情况下 Claude 更稳，最终没敢切换；另有一个转写作"JAB/GPT"的模型（疑指此前鸭哥一期讨论过的 Jev，无法确认），Jason 认为它的生态位是"速度足够快加场景简单"，适合做端点调度的路由器和大规模数据过滤的召回引擎——"一个快速的 System One 直觉的模型，可以做一个很好的路由"（44:00–46:00）。

节目最后回到人（44:00–50:00）。主持人提到 DeepSeek 一位研究员的文章《我不得不把我的才华埋葬在昨天》（节目引用）。石天鑫的回应是这期节目最诚实的一段：他前十年是前端工程师，擅长写 React，"从去年开始你就可以很清晰地知道，这一个技能对于你来说意义不是那么大了"——除非做到世界前几百名；想清楚接下来几年做什么之后，他"义无反顾"地加入了 Jason 的团队（转写此处团队名作"Satori"，无法确认）。他的判断是"对于程序员来说，你再也写不过 AI 了"，但跨领域的能力反而会被释放——Jason 自己就是例证：设计师出身、不爱调像素、习惯用产品经理视角看问题、还写前端代码，"反倒这样的人会比较容易被释放出来"。心态层面，两人都经历过想放弃的时刻：Jason 说做 Crewlet 那段时间最挣扎，他的原则是"这个方向上还能想到什么真正改变处境的事，想不到就换方向"；石天鑫的版本是快速失败（fail fast，转写误作"feel fast"）——知道要失败就让它快速失败，换新东西尝试。被问到"是否相信 AGI 由模型进化带来、但仍在创业"，Jason 回答：模型是必要条件，但路径太多；团队所有人都是 AI 重度用户，"保证自己沉浸在最新的 frontier 在哪里"，对六到十二个月的最大机会保持直觉。石天鑫补上最后一个护城河判断：即使万能模型存在，它也需要工具和数据——如果它花一千美元 token 才能拿到的数据，Treg 能让它一百美元拿到，"它可能会直接选择我"（50:00–51:00）。

对行业，这期节目把"AI 应用哀鸿遍野"的叙事换成了一张具体的机会地图：分发在向 Agent 平台迁移（插件市场），成本在被补贴（编程套餐），用户在换人（Agent 替人选择工具），资产在换层（从模型和全栈退到数据与工具）。对个人和团队，可带走的观察指标至少有四个：插件市场的排序与分发规则何时收紧，那是红利窗口的刻度；200 美元套餐对应的 token 价值何时缩水，那是单位经济的刻度；端点评分这类"机器口碑"基础设施何时成型，那是工具市场重构的刻度；以及五十到一百个并发会话下人与 Agent 交互的新形态，那是平台团队还没有集中处理的空白区——两位嘉宾的判断是，空白区正是下一批创业机会长出来的地方。
