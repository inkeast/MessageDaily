# VisSearch-Bench: Evaluating Long Horizon Visual Search in Multimodal Agents —— 精读

> **论文链接**：[VisSearch-Bench: Evaluating Long Horizon Visual Search in Multimodal Agents](https://arxiv.org/abs/2611.04894)
> **发表时间**：2026 年 11 月
> **机构**：清华大学、蚂蚁集团、中国人民大学
> **领域标签**：cs.CV / 多模态 Agent 评测 / 开放网页搜索 / Benchmark 方法论

---

## 一、论文背景

### 1.1 从「看图答题」到「带眼睛上网找答案」

多模态大模型（MLLM）正在从一次性视觉问答进化成能规划、用工具、与开放网页多轮交互的 Agent。它们可以发起文本搜索、图片搜索、以图搜图、读网页、放大看图的局部——证据不再局限于 prompt 里的内容，而是搜索过程中动态收集的。这比「只靠参数记忆答 VQA」更接近真实的信息 seeking。

但现有评测有个共同盲区：很多任务里**图片只是入口**——Agent 从图里认出一个人物/物体/地点的名字之后，剩下的全是文本检索。这类任务无法考察 Agent 如何处理多张图片、如何跨搜索步骤连接视觉信息。另一些更新的基准虽然增加了图片搜索与工具调用的次数，但**次数多不等于视觉上下文复杂**——关键在于这些视觉操作之间有没有连接、能不能支撑后续搜索和最终答案。

### 1.2 核心概念：视觉上下文管理

论文提出的评测视角叫**视觉上下文管理（visual context management）**：Agent 在搜索过程中**组织并使用视觉信息、并将其与其他发现建立连接**的能力。真实网页搜索不是一串互不相干的图像识别任务：

- 早期证据形成初始假设，后期证据用来比较候选、排除一些、发现新的；
- 新信息甚至可能**改变对早先图片的理解**；
- 例如「找目录里所有满足某视觉条件的作品」——得先确定全集，再逐个看图，最后汇总。

由此引出基准要回答的基本问题：**Agent 能否在开放网页搜索中，随着证据积累可靠地组织和使用视觉证据？** 这要求任务必须涉及多图、多对象、有依赖的搜索步骤。

### 1.3 现有基准缺什么

与 BrowseComp（纯文本）、MMSearch（重查询改写与重排）、BrowseComp-VL（视觉识别+多跳检索）、MM-BrowseComp（推理清单）、MMSearch-Plus（细粒度视觉线索溯源）、VisBrowse-Bench（视觉原生搜索）等相比，论文的对比表指出：此前的基准在「集合型答案」「证据链接」「部分得分」三个维度上最多只覆盖其一（如 MM-BrowseComp 有部分得分但无集合答案、VisBrowse-Bench 有多图但无证据链接），**没有一个同时覆盖全部**。VisSearch-Bench 是首个三者兼备的。

## 二、论文定位和关联工作

### 2.1 能力矩阵定位

| 基准 | 开放网页 | 图片搜索 | 多图 | 多跳 | 集合答案 | 证据链接 | 部分得分 |
|---|---|---|---|---|---|---|---|
| BrowseComp | ✓ | — | — | ✓ | — | — | — |
| MMSearch | ✓ | 部分 | 部分 | 部分 | — | ✓ | 部分 |
| BrowseComp-VL | ✓ | ✓ | — | ✓ | — | — | — |
| MM-BrowseComp | ✓ | ✓ | ✓ | ✓ | — | ✓ | ✓ |
| MMSearch-Plus | ✓ | ✓ | ✓ | ✓ | — | 部分 | — |
| VisBrowse-Bench | ✓ | ✓ | ✓ | ✓ | — | — | — |
| BrowseComp-V3 | ✓ | ✓ | ✓ | ✓ | — | ✓ | ✓ |
| InterLV-Search (L3) | ✓ | ✓ | ✓ | ✓ | — | — | — |
| VDR-Bench | ✓ | ✓ | — | ✓ | — | — | — |
| **VisSearch-Bench（本文）** | ✓ | ✓ | ✓ | ✓ | **✓** | **✓** | **✓** |

### 2.2 与三个最近亲的差异

- **MMSearch-Plus / VisBrowse-Bench**：考察视觉证据「是否被用到」，本文考察「如何被组织与连接」——任务设计从搜索结构（五类）出发而非内容主题；
- **MM-BrowseComp**：用推理清单评关键步骤完成度，但答案以单点为主；本文的任务大量要求**集合完整性**（全部列出才算对），并把过程分定义为「关键状态恢复率」而非步骤勾选；
- **VDR-Bench**：致力于消除文本捷径与全图匹配捷径，本文的防捷径机制（见 4.2）与之互补——自动化检查 + 人工审查绕过视觉要求的意外短路径。

### 2.3 模型侧背景

评测覆盖的 16 个模型横跨开源（Qwen3.5/3.6/3.8 系、GLM-5.3-Flash、GLM-4.6V、Kimi-K3、DeepSeek-V4.1-Flash、MiniMax-M3、Qwen3-VL 系）与闭源（GPT-5.5、Gemini 3.5 Flash、Claude Opus 4.8）。论文特意指出：**更长的上下文窗口并不保证有效的视觉状态管理**——这正是用长程任务而非长 prompt 来测的理由。

## 三、问题定义

### 3.1 形式化

每个任务提供自然语言问题 q、可选初始图片集 I₀（文本发起任务为空）、目标输出格式 σ。多模态 Agent 通过工具与网页交互：文本搜索、图片搜索、以图搜图、网页访问、图片检视。第 t 步时，Agent 基于交互历史

h_t = (q, I₀, (a₁,o₁), …, (a_t,o_t))

选择下一个动作；交互结束后按格式 σ 产出答案 ŷ。**视觉上下文**= 任务涉及的视觉信息及其与对象身份、外部事实、搜索目标的连接；**视觉上下文管理**= 组织、连接、使用这些信息来检查对象、比较候选、过滤结果、跨步骤汇总。

### 3.2 双指标定义

- **Accuracy（全对才算对）**：a_i = I[E_σᵢ(ŷ_i, y_i)=1]，其中 E 是任务特定的比对规则（实体别名归一；无序集合去重忽略顺序；有序序列保序）。答案必须包含且仅包含所需内容。
- **Process Score（PS）**：每任务标注 m_i 个**关键状态**（所有系统在最终答案前都会报告的中间实体/子问题答案），PS = 恢复的状态比例 |R_i|/m_i 的任务均值。不同搜索路径只要恢复同样的关键状态得分相同——**评状态不评路径**。

为什么需要 PS：最终答案错了，可能因为搜错了范围、漏了视觉候选、或汇总出错——单一 Accuracy 无法区分，PS 能定位「部分对」与「全对」之间的鸿沟。

## 四、问题解法

### 4.0 全景：五阶段构建管线

```
阶段1 源发现与筛选        公开来源 → 有界实体集 / 实体-图片链接 / 可核实事实
阶段2 证据结构化          实体+图片+事实+候选集 → 可溯源证据图（人工审查）
阶段3 任务设计            五类搜索结构之一实例化 → 撰写问题（隐藏中间节点与答案）
阶段4 编译任务与锁定金标  锁定参考答案 + 显式答案类型 + 可接受别名 + 金标轨迹
阶段5 完整性门 + LLM后滤  源可达性/字段完整/集合覆盖/答案可重算 → 工具捷径检查 → 人工复审
```

### 4.1 组件一：五类搜索结构（基准的骨架）

| 类别 | 题量 | 参考解步数(均/最) | 考什么 | 典型例子 |
|---|---|---|---|---|
| 集合式视觉搜索 | 68 (33.3%) | 23.9 / 51 | 对一组对象逐一收集并核验视觉信息，再过滤/比较/汇总；难点是全覆盖+逐项判断与总结一致 | 大都会博物馆 1977 期 PDF 中哪些乐器可见人或动物装饰，逐件列馆藏号 |
| 顺序视觉搜索 | 34 (16.7%) | 14.4 / 19 | 前一步的视觉线索/事实引导后一步搜索 | 从历史建筑照片到无台阶入口、设计师、原用途 |
| 宽深混合搜索 | 34 (16.7%) | 23.8 / 61 | 顺序+集合两阶段；一阶段结果决定另一阶段的搜索范围或目标 | 先认出电影海报→演员→筛选其主系列电影海报是否含游乐园背景 |
| 竞争性视觉消歧 | 34 (16.7%) | 3.9 / 5 | 用局部形状/纹理/标记等细节区分相似候选并核验身份 | 相似的实验室仪器、相机配件型号辨别 |
| 视觉结构引导搜索 | 34 (16.7%) | 15.8 / 19 | 用图中对象的顺序/位置/连接决定搜什么、按什么顺序、在哪停 | 按图内座位卡顺时针报参议员；按 Advisory 列逐条核查直到风速≥80mph |

全集 **204 题、3593 个参考解步骤（中位 17.0/题、最高 61 步）**、覆盖 7 大领域（文化 23.5%、生命科学 17.6%、物理科学 17.6%、社会 11.8%、地理 11.8%、技术 11.8%、商业 5.9%）25 子域；**91.7% 的任务带初始图片**。

### 4.2 组件二：三条构建原则与防捷径

- **视觉不可或缺**：关键视觉证据不能被题面文字、网页标题、caption、OCR 或模型知识替代；
- **视觉证据整合**：任务必须要求把视觉观察与对象身份、外部信息连接起来；
- **公开可解与可审计**：证据公开可检索、关键状态可验证、参考答案明确。

标注流程：**先固定来源再写题**——参考答案不依赖模型搜索结果或主观判断。自动化检查源可达性、字段完整性、集合覆盖、答案可重算，并检查「只用文本搜索」的捷径；**绕过关键视觉证据或存在更短意外路径的任务直接丢弃**。最后人工逐题复审。发布包（Parquet，图片内嵌）含 9 个字段：题目、参考答案、金标轨迹（含来源链接）、两个评分 prompt 等。

### 4.3 组件三：评测协议

- **Pass@1、温度 0**，每任务全新上下文跑一次，取首个完整回复；
- 五类证据工具：网页搜索、网页阅读（截断 12000 字符）、文本图片搜索、以图搜图、图片裁剪（可放大至 4×）；每次搜索最多 5 条结果；**每任务图片预算 20 张**（初始+检索+裁剪共享）、**30 轮 ReAct、60 次证据工具调用**、每轮最多 4 次；
- 评分用语义裁判（LLM judge），但规则极其严格：列表不允许多/漏/错项、单位与精度按题目要求、给多个未排除的候选直接 0 分；过程分按任务类型定制（如表格题用行匹配 F1）；
- 搜索后端统一：Serper（网页/图片）+ SerpApi（以图搜图），保证公平。

## 五、评估指标与实验证据

### 5.1 主结果：16 模型 + 两框架

| 设定 | 最佳系统 | Accuracy | Process Score |
|---|---|---|---|
| Direct Answer（无工具，13 模型） | Gemini 3.5 Flash / GPT-5.5 | **6.37%** | 22.28% / 22.61% |
| ReAct（7 个 backbone） | **Kimi-K3（26.47%）** | GPT-5.5 25.49% | **GPT-5.5 49.52%**（最高） |
| DeerFlow（3 个 backbone） | GPT-5.5 | 20.10% | 38.30% |

关键读数：

1. **最强系统也只完整解出约 1/4 的任务**——长程视觉搜索远未解决；
2. **双指标冠军不同**：Accuracy 最高是 ReAct+Kimi-K3，PS 最高是 ReAct+GPT-5.5——完整成功率与单点正确率并不同轨；
3. **搜索带来巨幅提升**：如 Qwen3.5-397B 直接答 1.96% → ReAct 15.69%（PS 12.72%→32.43%）；
4. **框架收益因模型而异**：GPT-5.5 与 Qwen3.5 上 ReAct 胜 DeerFlow，Qwen3.6-35B 上 DeerFlow 反超（10.78% vs 7.35%）——没有普适最优框架；
5. 开源 Direct 几乎团灭（多数 <2.5%），闭源 Direct 也只有 4.90–6.37%。

### 5.2 分类结果：不同模型不同强项

- **集合式最难**：最高准确率仅 11.76%（Kimi-K3）；GPT-5.5 在该类 PS 44.10% 但 Accuracy 只 8.82%——**「拿到部分正确结果」与「完成整个集合任务」之间有巨大鸿沟**，这正是 PS 存在的意义；
- **竞争性消歧是搜索依赖型**：所有 Direct 模型 0.00%，ReAct 的 DeepSeek-V4.1-Flash 与 Qwen3.8-27B 都达到 **44.12%**——以图搜图等工具是刚需；
- Kimi-K3 领跑顺序搜索（32.35%/56.34%）；GPT-5.5 领跑混合宽深（23.53%/48.36%）与结构引导（50.00%/70.61%）。

### 5.3 消融：视觉通道的价值拆解

四个设定（同一 backbone、同一初始图）：Direct（无工具）/ Text（网页搜索+阅读）/ Caption（图片搜索+以图搜图，但检索图只给同模型生成的文字描述）/ Full（直接看图+裁剪）：

| 模型 | Direct | Text | Caption | Full | Full−Text |
|---|---|---|---|---|---|
| Qwen3.6-35B-A3B | 0.98 | 5.88 | 6.37 | 7.35 | +1.47 |
| Qwen3.5-397B-A17B | 1.96 | 8.33 | 14.71 | 15.69 | +7.35 |
| DeepSeek-V4.1-Flash | 1.96 | 12.25 | 19.12 | **22.55** | **+10.29** |

- Full 全面最高：**直接看图不可替代**——文字 caption 丢掉了跨图比较所需的细节；
- Caption 有趣的双向性：它比 Full 多解出 6/8/13 题（描述步骤减轻了组织图片信息的负担），但丢掉 8/10/20 题——**净效应为负**（如 Qwen3.5 从 15.69% 掉到 14.71%）；
- Text 设定下降最狠（DeepSeek 掉 10.29 分），证明相当一部分任务的视觉信息文字渠道拿不到。

### 5.4 行为分析：工具用量与分布

- 各模型每任务证据工具调用 18.8–42.9 次、主循环 15.8–25.4 轮、运行 1.98–4.68 分钟；
- **更多调用 ≠ 更高准确率**（散点无明显正相关）；
- **视觉工具调用集中在前 20% 进度**（占全过程的 41.5%–69.2%），但后期也持续使用——视觉信息贯穿搜索全程，不是一次性的入口。

### 5.5 案例研究：失败模式图鉴

附录给出 17 条完整轨迹（7 成功 10 失败），失败模式极具教学价值：

- **集合覆盖不全**：找到 30 张测绘图纸的索引却只显式分类了 2 张，坦承其余无法核验；
- **文本近似匹配带偏**：历史地图题中把文本重叠当成图像匹配，一路错到底；
- **正确候选得而复失**：先正确找到 makerspace，被搜索噪声（别家图书馆的同名设施）覆盖，改口报错；
- **证据权重错配**：以图搜图已返回**完全相同的原图**并标注正确型号，模型却更信相似商品列表的标题，给出错误答案、还自评「高置信」；
- **初始解读压过证据**：把梨形瓶先入为主当分液漏斗，反向搜索命中博物馆藏品「光合测定计」原图仍被视为「相似配置」；
- **结构引导走错节点**：跳过一个火山/一个巴士站、或把错误记录绑定到起始 ID，整条链路随之跑偏。

## 六、效果优势的根源解释

基准的「效果」= 证明力：能否分离失败路径、能否防作弊、结论是否站得住。逐条检验：

**主张 1：基准测的是「视觉上下文管理」而非单点识别或纯文本检索。**
因果链：任务按五类搜索结构而非内容主题设计 → 每类结构对应一种上下文管理需求（集合汇总/链式依赖/两阶段耦合/细粒度区分/结构引导）→ 三条构建原则（尤其视觉不可或缺+捷径丢弃）堵住文本替代路径 → 分数差异只能来自连接与组织能力。证据：Direct（纯参数知识+单次看图）最高 6.37% vs ReAct 26.47%，说明任务超出单步识别；Text 消融掉 10.29 分（DeepSeek），说明文本渠道补不齐视觉信息；消歧类 Direct 全零，说明必须以图搜图。防作弊设计：来源先固定后写题（答案不依赖模型行为）、绕视觉捷径的任务丢弃、搜索后端统一、温度 0 单次采样、金标答案与轨迹对被评模型保密。

**主张 2：PS 与 Accuracy 的落差本身就是核心发现。**
因果链：集合型任务要求「全覆盖+一致汇总」→ 单项判断对 80% 也可能整体 0 分 → GPT-5.5 集合类 PS 44.10% vs Acc 8.82% 的五倍落差量化了「部分正确」与「任务完成」的鸿沟 → 失败案例（只分类 2/30 张图纸）显示瓶颈在覆盖与组织而非识别。这一分离失败路径的能力正是双指标设计的证明力。

**主张 3：Full > Caption 证明「原始像素进上下文」的必要性。**
因果链：Caption 用同模型把检索图转成通用描述 → 描述天然丢失局部细节与跨图可比特征 → 细粒度区分与跨图比较任务受损 → 净失分（丢 8–20 题、得 6–13 题）。同时 Caption 偶尔胜 Full 提示「图像信息过载」是真实存在的第二瓶颈——组织负担 vs 信息保真的权衡。

**主张 4：结论的稳健性边界。**
单次采样（Pass@1、温度 0）无方差报告；16 模型中参加 ReAct 的仅 7 个、DeerFlow 仅 3 个，框架对比非全因子；LLM 裁判虽规则严格但仍是模型裁判；开放网页随时间漂移（论文以来源链接+锁定金标缓解）。这些不推翻主结论（6%→26% 的提升远超噪声），但相邻名次的细微差距应谨慎解读。

## 七、必要知识反推

### 7.1 领域知识层

- **多模态搜索工具栈**：网页搜索、图片搜索、以图搜图（reverse image search）、网页清洗阅读、图片裁剪各自的信息获取边界——不理解工具就理解不了 Text/Caption/Full 消融的设计；
- **信息检索的「宽与深」**：多跳（深）与集合收集（宽）是两个正交维度，混合任务=两阶段耦合——这是任务分类学的理论骨架；
- **实体消歧与溯源**：别名归一、版本/ID/日期精确匹配、以图为锚的身份核验——评分规则严格性的来源。

### 7.2 方法论知识层

- **基准任务的结构化设计法**：先定义能力维度（五类搜索结构）再产题，而非堆内容主题——与按领域分类的传统做法相反；
- **防捷径工程**：文本泄漏审查、意外短路径检测、来源先行锁定、金标对被评者保密——开放网页基准的效度护栏；
- **双指标分离设计**：全对才算对（终局效度）+ 关键状态恢复率（过程效度）——「评状态不评路径」避免了强制唯一搜索顺序的伪约束；
- **对照消融的通道拆解**：Direct/Text/Caption/Full 四级递进，每级只增一类信息通道——归因清晰。

### 7.3 工程知识层

- **Agent 评测基础设施**：预算控制（图片 20 张、工具 60 次、轮次 30、每轮 4 次、网页 12000 字符、单图 1536px、裁剪 4×）——公平比较的资源护栏；
- **评分 prompt 工程**：严格裁判的六条规则（完整性/语义匹配/列表/数字条件/格式/冲突处理）+ F1 型过程分模板 + 格式恢复消息；
- **数据发布工程**：Parquet 内嵌图片、评分 prompt 随数据分发、本地 JSONL 与发布包的字段分离。

### 7.4 知识融合的关键节点

1. **「视觉上下文管理」的概念化**：把散落的观察（图只是入口、调用次数≠复杂度）提炼为一个可测构念——这是从「现象吐槽」到「基准设计」的关键一跃；
2. **结构分类学 × 内容分类学的正交**：五类搜索结构 × 7×25 领域，保证能力维度与内容覆盖互不混淆；
3. **过程分的状态对齐思想**：允许不同路径恢复相同状态——把「过程评价」从轨迹模仿中解放出来。

## 八、论文中可以提取的通用性灵感

### 灵感 1：评「连接」而非「出现」——考察信息之间的组织结构

- **核心思想**：判断一个系统是否真正使用了某类信息，不要看该信息是否出现过（入口式使用），而要看它是否被组织进后续决策与最终答案（结构式使用）。任务应按信息连接结构分类，而非按内容主题分类。
- **论文证据**：五类搜索结构各对应一种连接需求；Direct 与 Text 设定的惨淡成绩证明「入口式使用」远远不够。
- **推广场景**：(1) 员工培训评估：不是「听过课」而是能否把知识串进工作流；(2) RAG 系统评测：检索片段是否被真正整合而非堆砌引用；(3) 阅读理解测试：跨段落推理题 vs 单句查找题；(4) 供应链风控：单点合规 vs 全链路追溯；(5) 科研文献综述的能力考核。

### 灵感 2：双指标分离「部分正确」与「全部完成」

- **核心思想**：对要求完整性的任务（集合、清单、多步流程），同时报告「全对率」和「关键分量恢复率」；两者的落差本身就是最重要的诊断信号——它定位了瓶颈在覆盖/组织而非单点能力。
- **论文证据**：GPT-5.5 集合类 PS 44.10% vs Acc 8.82%；全榜最优系统也只 26.47%。
- **推广场景**：(1) 软件测试通过率 vs 分支覆盖率；(2) 医疗诊断的鉴别完整度评分；(3) 客服工单的一次性解决率 vs 步骤完成率；(4) 法务尽调的清单完整性审计；(5) 学生解题的步骤分与结果分并报。

### 灵感 3：原文进上下文——中间表征会丢信息

- **核心思想**：让系统经由中间描述（caption、摘要、转述）接触信息，会系统性丢失细粒度与跨源可比的特征；在需要精确比较的场景应让原始证据直接进入决策上下文，即使组织成本更高。
- **论文证据**：Caption 比 Full 净丢正确答案（8–20 题损失 vs 6–13 题增益）；但 Caption 偶尔胜 Full 提示过载是另一瓶颈。
- **推广场景**：(1) 会议纪要 vs 原始录音的留存策略；(2) 代码评审看 diff 而非只看摘要；(3) 数据分析看原始分布而非只看均值报表；(4) 翻译审校对照原文而非只读译文；(5) 二手研究的原始数据可及性规范。

### 灵感 4：防捷径是开放环境基准的生命线

- **核心思想**：凡是开放环境中可验证的任务，都要假设存在「绕过目标能力的短路径」（文本泄漏、全图匹配、参数记忆）；基准构建必须把捷径检测（自动化+人工）作为一等公民，必要时直接丢弃任务而非修补答案。
- **论文证据**：三原则中的视觉不可或缺；捷径审查作为独立阶段；绕过视觉的任务被丢弃。
- **推广场景**：(1) 招聘笔试的题库防泄漏机制；(2) 竞赛出题的对拍与防搜题设计；(3) 安全演练的红队剧本保密；(4) 广告反作弊的自然流量验证；(5) 考证类 AI 产品的「闭卷模式」设计。

### 灵感 5：给能力定义「结构分类学」——五个正交结构胜过一百个主题

- **核心思想**：为待测能力先建立结构分类（每种结构对应一种可区分的认知操作），再在每格填充内容；这使 benchmark 的每个格子有明确归因，也使「模型强在哪类结构」成为可回答的问题。
- **论文证据**：五类结构 × 模型的交叉表揭示 Kimi-K3 强在链式、GPT-5.5 强在混合与结构引导、DeepSeek/Qwen3.8 强在消歧——不同模型的优势结构截然不同。
- **推广场景**:(1) 产品团队的能力矩阵评估（结构×场景）；(2) 病历库按病理机制而非部位分类；(3) 教育测评的二维评分量规；(4) 投资组合按风险结构而非行业标签配置；(5) 缺陷库按失效模式分类归档。

### 灵感 6：证据权重判断——「检索到正确答案」≠「采信正确答案」

- **核心思想**：决策系统常犯的错误不是找不到证据，而是给相似但错误的候选更高权重（标题党、先入为主）；评测应包含「正确证据与强干扰并存」的场景，并惩罚未排除歧义的多候选输出。
- **论文证据**：失败案例 S11（原图已标注正确型号却信了商品列表）、S12（藏品原图命中仍坚持初始解读）；评分规则「多个不兼容候选不给分」。
- **推广场景**：(1) 情报分析的多源信源可靠性评级；(2) 医疗第二意见的优先级规则；(3) 反诈系统的可信来源白名单；(4) 竞品调研的原始文档优先原则；(5) AI 搜索产品对「直接证据 vs 二手转述」的置信度展示。

### B. 术语备忘

- **视觉上下文管理**：组织、连接、使用视觉信息及其与对象身份/外部事实/搜索目标关系的能力。
- **五类搜索结构**：Set-wise（集合式）/ Sequential（顺序）/ Hybrid Wide–Deep（宽深混合）/ Competitive Disambiguation（竞争性消歧）/ Visual-Structure-Guided（视觉结构引导）。
- **关键状态（critical states）**：所有系统最终答案前都会报告的带标注中间实体/子答案，Process Score 的计分单位。
- **捷径（shortcut）**：绕过目标视觉要求的更短路径（文本泄漏、全图匹配等），构建期检测并丢弃任务。
- **Caption 设定**：检索图片只返回同模型生成的文字描述，保留视觉信息抽取但增加一次转述——隔离「原始像素」贡献的对照组。
