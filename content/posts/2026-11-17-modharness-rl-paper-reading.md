## 一、论文背景

要读懂这篇论文，需要先弄清三个层层递进的概念：什么是 Agentic RL、什么是 harness、以及为什么『把 harness 变成可学习的程序』是一件值得做的事。

### 1.1 从 LLM 到 Agentic RL：会自己做事的模型

传统的大语言模型（LLM）像一位『一问一答』的顾问：你给一段文字，它回一段文字。而 **LLM Agent** 把模型变成了『自己动手做事』的执行者——它接到一个任务（比如修一个 bug），然后连续多轮地思考、调用工具（搜索代码、执行 shell 命令、查数据库）、观察结果、再决定下一步，直到任务完成。ReAct 这类经典工作确立了『推理与行动交错』的基本范式，AgentBench 则展示了这种交互在各类环境中的广泛适用性。

**Agentic 强化学习（Agentic RL）** 就是训练这类 agent 的方法：让环境给出一个可自动验证的奖励（比如 bug 修没修对、SQL 查询结果对不对），用强化学习（RL）直接优化模型参数，使其学会更好地完成多轮交互任务。近年的综述（如 [The Landscape of Agentic Reinforcement Learning for LLMs: A Survey](https://arxiv.org/abs/2509.02547)）把它视为从『被动文本生成器』到『嵌入动态环境的自主决策者』的范式转变。本文训练用的 GRPO 算法（Group Relative Policy Optimization）出自 DeepSeekMath：对每个任务采样一组轨迹，用组内奖励的归一化优势来更新策略，是目前开源社区最常用的 agent RL 算法之一。

### 1.2 Harness：模型外面那层『脚手架』

一个 agent 的表现，并不只取决于模型权重。**Harness（脚手架/驾驭层）** 指的是包裹在模型外面的工程层，它决定两件事：

1. **模型看到什么**——多轮交互的完整记录（历史）如何装进有限的上下文窗口；
2. **模型被如何引导**——什么时候给它附加提示、检查清单、行为规范。

这个概念在软件工程 agent 领域最为成熟。SWE-agent 的经典发现是：**agent-计算机接口（ACI）的设计会主导 agent 的表现**——同样的模型，接上不同的工具界面和历史组织方式，成绩可以差出一大截。直观地说，harness 就像飞机的驾驶舱仪表系统：引擎（模型）再强，如果仪表盘（harness）把关键信息埋在一堆噪音里，飞行员也会迷路。

harness 里有两大类组件与本文直接相关：

- **上下文管理**：交互越攒越多，冗长的工具输出会淹没那一点点真正关键的信息。『Lost in the Middle』和 Chroma 的 Context Rot 研究都表明，名义上下文容量 ≠ 可用证据量——塞得越满，模型对中间内容的利用率越差。于是有了 MemGPT（把上下文当操作系统式的分级内存管理）、ReSum（周期性摘要搜索轨迹）这类压缩/记忆方案。
- **行为引导**：模型会犯一些反复出现的错误（比如无意义地重复同一个工具调用），于是有了附加指令、接口约束、护栏等引导手段。

### 1.3 现状的核心缺陷：harness 是『手工写死』的

问题来了：现有 Agentic RL 工作里，harness 几乎总是**人工预先写好、训练全程固定不变**。这带来两个挑战（论文原话归纳）：

1. **不可扩展**：一个有效的 harness 取决于任务领域、训练数据、模型本身和上下文预算四重因素。换个模型、换个预算，最优 harness 就变了——为每种组合手工调一套，是『手工作坊』式的劳动，无法规模化。所以它应该**从数据中自动得出**。
2. **会过时**：RL 训练中模型行为在不断变化。旧失败模式可能自己消失（RL 自己就能修掉一些错误），新失败模式又会冒出来。训练开始时写的 harness，到训练中后期可能已经不对症。所以 harness 应该**随模型一起演化**——并且只针对那些模型自己学不会的顽固失败做干预。

这就引出论文的核心问题：**如何让 harness 变成可从数据优化的对象，并让它与模型训练同步优化？**

近期已有一批工作尝试在训练中调整 harness（按预设日程衰减脚手架、交替改写 scaffold 与权重更新、从故障中编辑 harness 模块等），但它们的更新空间要么事先固定、要么绑定在任务特定的 scaffold 上——本质仍是在人工设计的空间里做选择或修补。没有任何工作提供一条通用路径：**从类型化的交互状态中推导出 harness 操作，并与模型一同优化**。这正是 ModHarness-RL 的位置。

## 二、论文定位和关联工作

ModHarness-RL 处在两条研究脉络的交汇点上：『训练期间更新 harness/上下文』与『训练期间共演化记忆/技能/提示』。下面按谱系梳理（链接均可核验）。

### 2.1 谱系一：harness 与上下文的训练期优化

这一谱系直接把 harness（或上下文管理）与模型权重放在一起更新，是本文最近的竞品带。

| 工作 | 核心思想 | 与本文的关键区别 |
|---|---|---|
| **HarnessForge**（[arxiv:2606.01779](https://arxiv.org/abs/2606.01779)，本文最强 harness 类基线） | LLM 从观测故障中归因，编辑 planning/action/memory 模块，生成可执行 harness，再对齐策略 | 更新空间绑定在三类固定模块上；本文则是定义在类型化 STATE 上的任意程序，且逐触发器重放验证 |
| **Co-Harness**（[arxiv:2607.22688](https://arxiv.org/abs/2607.22688)） | harness 与模型权重共同演化 | 依赖模型在线改写 harness；本文 harness 是确定性程序，无需模型调用即可运行 |
| **SIA / WHALE / VACE**（论文引用：arxiv:2605.27276 / 2609.00196 / 2609.37105） | 交替 scaffold 重写与权重更新 / 简单的联合 harness-权重优化配方 / 验证门控的交替共演化 | 更新空间事先工程化定义；本文从轨迹数据中推导程序并按失败持续性选择安装 |
| **PATS / Rubric-scaffold RL**（arxiv:2607.21419 / Zhou et al., ICML 2026） | 训练脚手架按日程衰减、外部评分标准辅助探索后撤退 | 衰减日程预设；本文由 REPLAY 重放证据 + 判官决定每个失败是否需要持续干预 |
| **Context LM / Context-1 / MemGPT / ReSum**（arxiv:2609.37725 / Chroma Context-1 / arxiv:2310.08560 / arxiv:2509.13313） | 把上下文当被管理的资源：训练策略自管上下文、自编辑搜索行为、OS 式内存、周期摘要 | 靠模型改写上下文或训练权重来管上下文；本文用离线学得的确定性程序改写，保留 KV 缓存 |

### 2.2 谱系二：记忆/技能/提示与策略共演化

这一谱系演化的是 agent 读到的东西（记忆、技能库、指令），与本文 STEERING 的功能面重叠。

- **EvolveR**（Wu et al., ICML 2026，本文基线）：把过去轨迹蒸馏成经验原则库，按任务检索后追加进上下文。
- **SkillRL**（[arxiv:2602.08234](https://arxiv.org/abs/2602.08234)，本文最强第三方基线）：从经验中归纳层级化技能库 SkillBank，随 RL 训练递归演化，在 ALFWorld/WebShop/搜索增强任务上超基线 15.3%。
- **INSPO**（[arxiv:2512.01945](https://arxiv.org/abs/2512.01945)，本文基线）：指令-策略共演化，训练中按重要性权重采样指令种群、弱者淘汰。
- **EDGE**（arxiv:2608.21946，论文引用）：经验蒸馏引导探索，且随策略进步**撤回**指导。

论文对这些工作的共同批评是：它们只往提示里**追加**内容，指导的触发靠语义相似度检索、任务类型匹配或模型选择——指导的投放是『模糊匹配』的。而 ModHarness-RL 的指导条件定义在**类型化的交互块**上，每个触发器可以精确重放、定向于一个具体失败模式，是确定性、可审计的控制。

### 2.3 谱系三：程序化 harness 的灵感来源

- **SWE-agent 的 ACI 发现**（NeurIPS 2024，论文引用）：接口设计主导表现——本文把『接口设计』本身变成学习目标。
- **AlphaEvolve**（[arxiv:2506.13131](https://arxiv.org/abs/2506.13131)）：用 LLM 写代码、以评分为适应度做进化搜索，证明『LLM 提议程序 + 执行验证 + 保留最优』的搜索范式有效。ModHarness-RL 把这套范式搬进了 RL 训练循环：候选程序在存储轨迹上重放评估，通过 held-out 门控择优安装。
- **Code as Agent Harness**（[arxiv:2605.18747](https://arxiv.org/html/2605.18747v1)）：以代码作为模型与 harness 之间的执行接口——与本文『harness 即程序』的表征选择相互印证。

### 2.4 定位总结

| 维度 | 之前的路线 | 本论文的突破 |
|---|---|---|
| harness 表征 | 人工写的 scaffold 代码 / 固定模块组合 | 类型化 STATE 上的**程序**：可由 LLM 从轨迹直接写出 |
| 更新时机 | 训练前写死，或按预设日程衰减 | 与策略更新**交替共演化**，每轮基于最新在线数据 |
| 更新空间 | 事先工程化定义（模块编辑/指令种群/记忆库） | 从数据的失败假设中**推导**，理论上是程序空间的开放搜索 |
| 投放指导 | 语义检索/类型匹配/模型选择（模糊） | 类型化触发器（确定性、可重放、可定向单点失败） |
| 运行成本 | 常需模型在线改写（贵、慢、破坏缓存） | 确定性程序执行，**零模型调用**，前缀缓存大部分保留 |
| 该不该管的判断 | 一般不区分失败是否会自行消失 | **REPLAY 重放**判断失败趋势，只管『RL 学不会』的顽固失败 |

一句话定位：**这是第一个把 agent harness 的两个核心组件（上下文组装 + 行为指导）统一表示为类型化状态上的可学习程序、并与 RL 策略交替共演化的通用框架**。

## 三、问题定义

### 3.1 从具体场景到抽象问题

**具体场景**：训练一个代码定位 agent。它每轮读上下文、发一条 shell 命令、看输出，最多 10 轮。手工 harness 该怎么写？历史满了砍哪些内容？模型老是重复 grep 同一个词，要不要提醒它？——这些问题没有通用答案：取决于仓库长什么样、模型几 B、上下文给 1K 还是 8K token，还取决于训练进行到第几步。

**论文的核心洞察**：harness 的两个核心职能（组装上下文、纠正行为）**本质上都是『交互记录的函数』**——输入是『到目前为止发生了什么』，输出是『模型下一轮看到什么 + 被提示什么』。既然是函数，就可以写成**程序**；既然是程序，就可以（a）由 LLM 从数据中直接写出，（b）在存储的轨迹上执行验证与评估，（c）用搜索/门控的流程择优安装。于是『调 harness』从人工试错变成了一个**可优化的搜索问题**。

### 3.2 形式化定义

- **多轮 agent**：策略 π_θ 解任务 q，第 t 轮读上下文 c_t、采样动作 a_t（一轮的完整回复，以一个工具调用结尾）、得观察 o_t = T(a_t)，直到终止轮。**harness 负责构建 c_t**。
- **Agentic RL 目标**：max_θ E[r(τ)]，τ = (q, a_0, o_0, …, a_T) 为轨迹，r(τ) 是环境奖励。本文用 GRPO 优化。
- **STATE（结构化状态）**：s_t = (q, u_0, …, u_{t-1})，u_i = (a_i, o_i)。存成带类型的记录（类似一个 Python 类实例）：每轮有 `.thought`（模型的推理）、`.name/.args`（工具调用）、`.exec_output`（工具结果及类型化元数据）等属性。
- **基础 harness**：追加式扁平化 c_t^flat = flatten(s_t) = q ⊕ u_0 ⊕ … ⊕ u_{t-1}（⊕ 为拼接）。
- **待学习的 harness**：H = (compress, steer) 两个程序，新的上下文为 c_t = flatten(compress(s_t) ⊕ steer(s_t))。

**给定**：任务分布 D、环境与奖励、基础策略 π_0、上下文预算、一个能写程序的 LLM creator（GPT-5-mini）。
**求**：程序对 (compress, steer)，使得在 held-out 任务上训练出的策略 π_K 的期望得分最大（或在得分与 token 成本间取得 Pareto 优势）。
**约束**：程序在受限沙箱下执行、不调用任何模型（零 token 成本）、每轮每条轨迹都要跑（必须毫秒级）；steer 的安装须严格优于现任（held-out 门控）。

### 3.3 这个抽象的精妙之处

把 harness 表征为『类型化块上的程序』同时解锁了三个性质——它们正是『可学习、可演化』的全部前提：

1. **可学习（learnable）**：LLM 读训练轨迹 + 奖励就能直接写出程序，不需要人工设计搜索空间；
2. **计算便宜（cheap）**：程序执行不调模型，才能在每轮每条轨迹上全量运行——上下文优化必须跑在 RL 的海量 rollout 上才有意义；
3. **可测试（testable）**：程序可以在存储轨迹上**重放**评估，先验证再安装——这把『改 harness 像开盲盒』变成了『先回放考试再上岗』。

反过来说：如果 harness 组件是『让一个强模型在线改写』（如在线 compaction），那么它既贵（每轮每轨迹都要花 teacher token）、又不可重放（改写结果随内容漂移）、还破坏前缀缓存（论文实测这种方案一个训练 run 要 12,365~247,347 次 teacher 调用、最多 1,789M token）。**表示方法的选择本身就是论文的第一个贡献**。

## 四、问题解法

ModHarness-RL 的完整流程分两个阶段：先离线学一次 COMPRESSION，再让 STEERING 与策略训练交替共演化 K 轮。下面按组件拆解。

### 4.1 COMPRESSION：把历史『归档』而不是『摘要』

**类比**：与其雇一个速记员（teacher 模型）每次会议都重写纪要，不如写一套**自动归档规则**——超过 1000 字的旧文件只留目录、导入语句、函数头和首尾几行，正文折叠；搜索结果和新文件原样保留。规则写一次，之后每次归档零成本。

**本论文做法**：compress 读 s_t 的全部类型块，返回 STATE 的一个新视图——重渲染较早的轮次，卸载（offload）不再需要的内容，保留关键信息并装进预算。两个程序每轮都读**完整记录** s_t，所以某轮被卸载的信息在构建后续上下文时依然可用（不是丢了，而是不展示）。

论文附录给了一个真实学得的程序（CodeSearch）：

```python
def compress(state):
    for turn in state, except the newest turn:
        for call in turn.calls:
            if call is not a file read: skip      # 搜索结果不动
            if len(call.output) < 1000: skip      # 短内容不动
            digest = summarize(call.output)       # 长文件读→留 imports/defs/首尾行
            if digest saves >= 200 chars:
                call.output = digest
    return state
```

在一个 cantools 仓库的 episode 里，它把模型第 5 轮之前读到的工具输出从 5,626 字符压到 2,809 字符，文件结构仍然完整可见。

**怎么学出来的**（训练前一次性完成，之后冻结）：

1. **ROLLOUT**：基础策略在训练任务上 rollout，按任务分组存入水库 R_0（带奖励）；
2. **PROPOSE_COMPRESS**：GPT-5-mini creator 读 rollout 与上下文填充情况，写若干候选程序；每个候选进入修复-审查循环：编译修到能跑 → 在存储 episode 上执行 → 用两个测量检查——是否 **unfaithful**（删掉了任务相关信息）或 **inert**（几乎没压缩）——不合格就修订；
3. **GATE**：每个程序在 held-out 训练任务上、冻结的基础策略下、与训练完全相同的 agent 循环和上下文限制下试一轮，**得分最高者胜出**成为 H_0，训练期间保持固定。

**为什么固定不随训练更新？** 作者试过每 10 步重拟合 compress（evolving COMPRESSION），四个设置全部低于固定版（如 8B limited 从 0.412 掉到 0.279）——**策略训练需要稳定的上下文分布**，压缩规则反复变会让策略一直在追一个移动靶。

### 4.2 STEERING：只做模型『学不会』那部分的教练

**类比**：好教练不会每分钟都喊话（那是噪音），只在你反复犯同一个错误时才叫暂停画战术板；而且他会先翻训练录像，确认这错误是偶发失误（多练练自己就好了）还是顽疾（必须现在纠正）。

**本论文做法**：steer 是一组**触发器**，每个触发器 = 一个 s_t 上的小程序（检测一种可执行规则命中的失败模式）+ 一段简短指导文本。触发器命中时，指导作为块附加在该轮上下文末尾；不命中就完全静默。

一个真实学得的触发器（CodeSearch）：检查最新一轮是否用 cat 打开了某个 .py 文件且输出里只有一个 def/class 定义——是则提示『如果你刚打开的视图只有一个函数或类，先打开定义它的模块、扫一遍邻近定义再提交』。在 pypika 仓库的 episode 里，agent 第 4 轮触发该提示后扩大了视野，最终提交 Term.rlike 拿到 3/3 满分。

**每轮怎么进化**（每 10 个训练步一轮，共 K=20 轮，与训练并行跑，trainer 不用等）：

| 步骤 | 输入 | 做什么 | 输出 |
|---|---|---|---|
| UPDATEPOLICY | π_{k-1}, H_{k-1}, 训练任务 | GRPO 更新策略 | π_k + 新 rollout 入水库 |
| PROPOSESTEER | 最新 rollout R_k | creator 读**混合结局组**（同任务有成功有失败的组），提出失败假设：触发器 + 指导洞见 | 候选集 P |
| REPLAY | P + 全部历史水库 R_{0:k} | 每个候选触发器在**所有**存储 rollout 上执行，画出『失败率随训练步变化』曲线——下降/持平/上升 | 重放证据 E |
| ADMIT | E + 已安装集 | 判官（同为 GPT-5-mini）三选一：**intervene**（失败持平或上升→送门控）/ **monitor**（像真的但未定型→下轮再看）/ **continue**（持续下降→交给训练） | 准入子集 |
| GATE | 准入子集 | 因指导之间会相互作用，打包在 held-out 任务、π_k 下整体试，**严格高于**现任 H_{k-1} 才安装 | H_k |

关键设计是 REPLAY：『最新 rollout 告诉你现在什么在失败，但不能告诉你这失败会不会自己消失』。因为触发器是程序，可以零成本地在历史轨迹上回溯执行——这一步不需要任何模型调用。论文做了一个漂亮的验证实验（Case 1/Case 2）：判官决定安装的失败，安装指导后果然被压下去；判官决定不装的失败（已经稀少且在降），后续训练中确实继续下降——**判官知道什么时候不需要它**。

### 4.3 两个组件为何恰好互补

- COMPRESSION 解决『看到什么』：预算紧时提分（有限预算下 Qwen3-8B CodeSearch +8%、Qwen2.5-7B ALFWorld +21%），预算松时省 token（prefill token 最多 −35%，ALFWorld 充分预算下服务上下文 −74%）；
- STEERING 解决『怎么做』：CodeSearch 上平均 +15%，是两个程序中在结构化代码任务上更强劲的一个；
- 确定性程序执行（0.3~1.4 ms/轮）让两者都能在**每轮每轨迹**上全量运行——这是任何需要模型调用的方案（在线 compaction 749~4127 ms/轮）做不到的。

### 4.4 全景流程（Algorithm 1）

```
输入: 基础策略 π0; 轮数 K=20; 训练任务 Dtrain; held-out 训练任务 Dhold

# 阶段一：压缩优化（一次）
R0 ← ROLLOUT(π0, Dtrain)
P  ← PROPOSE_COMPRESS(R0)         # creator 写+修+查 unfaithful/inert
H0 ← GATE(π0, ∅, P, Dhold)        # held-out 择优，冻结

# 阶段二：策略与引导交替共演化
for k = 1..K:
    (πk, Rk) ← UPDATE_POLICY(π_{k-1}, H_{k-1}, Dtrain)   # GRPO
    P  ← PROPOSE_STEER(Rk)          # 从混合结局组提失败假设
    E  ← REPLAY(P, H_{k-1}, R_{0:k})# 全水库回放画失败曲线
    P  ← ADMIT(P, H_{k-1}, E)       # intervene/monitor/continue
    Hk ← GATE(πk, H_{k-1}, P, Dhold)# 打包严格占优才装
return (πK, HK)
```

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**对比对象**：固定手工 harness（以及各『学一样东西』的基线）。它为什么曾经有效？因为 ACI/接口设计确实主导 agent 表现，一套精心手写的 scaffold（如 DeepAgents）在任何模型上都稳定加分（+2~+10%）。它的根本局限不在『写得不好』，而在**结构性错配**：

- **表征层局限**：手工 scaffold 是静态文本/代码，无法表达『取决于模型当前行为』的条件逻辑——它对训练第 1 步和第 200 步的策略一视同仁，而 RL 恰恰让这两者判若两模。
- **信息层局限**：语义检索式的指导投放（EvolveR/SkillRL）把『何时指导』交给向量相似度，无法区分『模型正在犯的错』和『模型已经会做的对』——指导变成了双向噪音。
- **成本层局限**：模型在线改写式方案（在线 compaction、HarnessForge 的编辑执行）的 teacher 成本与轮数×轨迹数线性相乘，撑不起 RL 训练规模。

**本文方法的根本性改变与因果链**（每步标注证据等级）：

1. **程序化表征 → 零成本全量执行 → 优化空间打开**：harness 组件写成确定性程序后，每轮每轨迹运行成本从『一次 teacher 调用』（百 ms 级、千 token 级）降到毫秒级零 token（Table 2 实测 0.3~1.4 ms/轮）。【论文实验已支持】
2. **程序化表征 → 可重放 → 安装前可验证**：候选触发器能在全水库历史轨迹上回放，把『要不要管这个失败』从猜测变成趋势判读；held-out 门控进一步保证只装严格占优者。【论文实验已支持：消融 w/o judging 全降；Case 1/2 证明判官判断正确】
3. **REPLAY 失败趋势判读 → 只干预 RL 学不会的失败 → 指导信噪比结构性提升**：这是对『指导该不该给』的信息论式回答——对会自行消失的失败给指导是纯噪音（挤占上下文、干扰 credit assignment），REPLAY 用零成本回放把这部分噪音滤掉了。【论文实验已支持：判官实验 + w/o generation 消融；『指导噪音干扰 credit assignment』的具体机制为阅读者推测，论文未直接测量】
4. **确定性渲染 → 前缀缓存保留 → 真实成本下降**：追加式 harness 缓存命中率 64~95%，COMPRESSION 保持 58~72%，配合总 token 减少，prefill 在 3/4 格更低。【论文实验已支持】
5. **交替共演化 → 两个非平稳对象互为目标 → 收敛到相互适配的 (π, H)**：策略在变（失败集合在漂移），harness 逐轮针对最新失败更新、又通过门控避免拖累当前策略；顺序执行的两种次序都更差（Table 3），说明收益确实来自『交替』而非『先后做了两件事』。【论文实验已支持】

**反事实推理**：去掉 REPLAY 判读（w/o judging）→ 四设置全降；去掉共演化（顺序执行）→ 全降；去掉上下文稳定性（evolving COMPRESSION）→ 8B-limited 从 0.412 跌到 0.279（−32%，比 base 还低）。三个关键设计各有一个『去掉就塌』的消融支撑，反证其必要性。

### 6.3 综合判断与未决问题

**得到多项研究共同支持的机制**：
- 共演化/交替优化优于静态或顺序方案（本文 Table 3 + SkillRL/INSPO/Co-Harness/SIA 谱系）；
- 前缀缓存对真实成本的重要性（本文 C.4 + LMCache 等系统研究）；
- 上下文压缩是真实且被广泛承认的瓶颈（MemGPT/ReSum/Context-1 + 本轮检索的多项 2026 工作）。

**仍属合理推测或单一来源的机制**：
- 『类型化触发器的指导信噪比优于语义检索』——本文只有端到端分数支撑，未做指导投放的逐点对照分析（标注：论文实验已支持整体结论，机制细节含推测成分）；
- 『REPLAY 趋势判读 ≈ 区分 RL 可自学/不可自学失败』——Case 1/2 仅两个案例，样本极小。

**优势的适用条件**（论文自身 limitation + 检索综合）：
- 交互必须**结构化、可类型化**——工具调用带类型结果时触发器才能写；开放式对话等语义信号为主的场景不适用；
- 门控样本有限（128~256 held-out 题），偶尔会放行略差的程序；
- creator 是专有模型（GPT-5-mini），策略只见程序输出、程序文本从不进 loss（这点设计上已隔离蒸馏嫌疑），但 creator 质量对候选程序上限的影响未消融；
- **可能的失效条件**：任务分布漂移剧烈（失败模式持续翻新，20 轮更新频率跟不上）；奖励稀疏到混合结局组无法形成（PROPOSESTEER 的输入断了）；需要语义级压缩的领域（确定性规则删不准）。

## 七、必要知识反推

假设让一个完全没有背景的人重做这项工作，倒推他必须掌握的知识：

### 7.1 领域知识层

- **多轮 agent 的运行机制**：上下文-动作-观察循环、工具调用协议——不知道这些就无从定义 STATE 的类型块；
- **harness/ACI 的经验性地位**：必须知道 SWE-agent 等工作已证明『模型外的那层』主导表现，才会有『把它变成学习对象』的问题意识——这是选题合法性的来源；
- **上下文窗口的病理学**：Lost in the Middle / Context Rot / 冗长工具输出淹没关键证据——不知道『塞满上下文有害』就没有 COMPRESSION 的动机；
- **RL 训练的行为漂移**：必须理解训练中失败模式会生灭，才会有『harness 要跟着变 + 只管学不会的』这一核心约束。

### 7.2 方法论知识层

- **GRPO 及组相对优势**：训练目标与 advantage 归一化的实现细节（组内均值/方差），论文训练管线的地基；
- **LLM-as-creator 的程序合成范式**：写-编译-修复-审查循环、JSON 结构化输出——AlphaEvolve 等工作验证过的『提议-验证』搜索思想；
- **进化搜索/门控选择**：候选生成 → 执行适应度评估 → 择优安装的循环；held-out 验证以防过拟合到训练任务；
- **脚手架理论（scaffolding）**：Wood/Bruner/Vygotsky 的经典教育心理学——支持应随能力增长而撤退，论文把这一原则工程化为 REPLAY 判读。

### 7.3 工程知识层

- **RL 训练基础设施**：verl（HybridFlow）+ vLLM 服务 + FSDP 的组合，8×H100 单节点跑 200 步的配置调通；
- **KV 缓存/前缀缓存机制**：PagedAttention 的缓存语义、为什么改写历史会破坏前缀复用、prefill token 的正确测量方法（提示 token × 未命中比例）——不懂这个就会用错误的效率指标得出错误结论；
- **沙箱执行与受限程序**：LLM 生成的程序须编译通过、受限导入、限时执行、失败跳过（agent 看未压缩历史）——安全与鲁棒性的兜底；
- **评估隔离设计**：D_hold 与训练/评估集按任务身份严格三分、统一 creator、统一超参——否则任何比较都不可信。

### 7.4 知识融合的关键节点

1. **『harness = 交互的函数』+『函数可写成程序』**：把工程直觉（ACI 重要）与程序合成范式（LLM 能写程序）焊在一起，得到『harness 即可学习程序』的表征——全文的支点；
2. **『程序可重放』+『RL 失败会漂移』**：两个独立事实相乘得到 REPLAY——用回放曲线回答『该不该管』，这是全文最漂亮的化学反应；
3. **『确定性渲染』+『前缀缓存语义』**：系统层知识与学习层设计融合出『程序化压缩天然省成本』——让 COMPRESSION 在与 teacher 在线改写的对比中拿到 100~1000× 效率优势；
4. **『上下文稳定性』+『RL 非平稳性』**：解释了为何 COMPRESSION 冻结、STEERING 逐轮更新这一不对称节奏——两个组件面对的是不同时间尺度的非平稳性。

## 八、论文中可以提取的通用性灵感

**灵感 1：把工程层重构为『可学习程序』，是介于手工设计与端到端训练之间的第三条路**
核心思想：任何『包裹模型的工程层』（提示、路由、压缩、监控规则）都可以改写为定义在结构化状态上的程序，从而进入『LLM 提议-执行验证-门控安装』的自动优化循环。
论文证据：COMPRESSION/STEERING 程序从轨迹自动学得，8/8 设置超越固定 harness，最高 +24%。
推广场景：RAG 系统的检索后处理规则；推荐系统的重排启发式；数据库查询优化器的 hint 规则；客服工单的自动分派逻辑；DevOps 告警聚合与降噪规则。

**灵感 2：干预前先判断『问题会不会自己好』——用重放把干预决策建立在趋势上**
核心思想：对正在自愈的系统施加帮助是纯成本（噪音 + 依赖）；可回放的执行日志让『这个问题是否持续』变成可测量的曲线问题。
论文证据：REPLAY 在全水库轨迹上回放候选触发器，判官只对持平/上升的失败安装指导；Case 1/2 验证判官两种判断都正确。
推广场景：线上服务的自动回滚决策（错误率在降就别回滚）；学生的自适应辅导（先看错误趋势再介入）；医疗方案的调整时机；代码评审——区分新手偶发失误与系统性误解。

**灵感 3：把昂贵的在线智能『编译』成廉价的离线程序**
核心思想：teacher 模型的知识用一次（离线写程序），之后每步执行都是零边际智能成本——相当于把解释性知识 JIT 编译为确定性代码。
论文证据：同一个 GPT-5-mini，在线 compaction 每 run 花最多 1,789.5M token、4127 ms/轮；编译成程序后 0.198M token、1.42 ms/轮，分数 4 局中 2 局还更高。
推广场景：把 LLM 审码意见编译成 lint 规则；把专家诊断逻辑编译成规则引擎；把昂贵的 A/B 分析结论编译成缓存策略；编译器优化 pass 的自动生成。

**灵感 4：共优化的两个对象若时间尺度不同，应对齐各自的更新节奏**
核心思想：策略权重（慢变化、需稳定上下文）与失败模式集合（快变化、需持续跟踪）是非平稳性时间尺度不同的两个对象——一个冻结、一个逐轮更新，好于统一处理。
论文证据：evolving COMPRESSION 四设置全降（最惨 −32%），而 STEERING 20 轮更新持续加分；顺序执行任一先后都差于交替。
推广场景：课程学习中学习率与课程内容的节奏配比；组织中制度修订与人员培训的节奏；数据库中索引重建与查询优化的频率；双时间尺度的元学习。

**灵感 5：指导的条件化投放优于全局投放**
核心思想：同样的指导内容，『什么时候出现』决定它是信号还是噪音——条件应定义在可观测、可执行检查的状态特征上，而非语义相似度。
论文证据：类型化触发器版 STEERING 在 CodeSearch +15~20%，而全局指令共演化的 INSPO 在 limited 下低于 base（−1~−6%）。
推广场景：IDE 提示（检测到模式再弹，而非常驻侧栏）；新员工 onboarding（按当前任务形态给检查清单）；健康提醒的情境触发；文档系统按错误上下文注入陷阱提示。

**灵感 6：评估『会改东西的方法』必须控住评估面**
核心思想：任何带进化/自适应组件的方法，其收益声明必须隔离统一 creator、统一预算、held-out 门控、缓存友好测量，否则改进与混淆无法区分。
论文证据：所有基线统一 GPT-5-mini creator、统一训练配置；效率测量用 prefill token 而非提示 token（防『改写历史反而显得省』的假象）；外部检索亦发现 harness 进化评估的混淆是领域公认痛点（arxiv:2607.12227）。
推广场景：任何 autoML/自调优系统的 benchmark 设计；A/B 测试中实验者效应的控制；教育测评中自适应测验的公平性设计。
