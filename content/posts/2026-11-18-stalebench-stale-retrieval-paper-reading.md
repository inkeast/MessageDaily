## 一、论文背景

### 1.1 Agent 记忆是什么，为什么会存出"多个版本"

一个长期运行的 LLM Agent 迟早需要记忆：跨会话记住用户的偏好、项目状态、组织里的人事变动。业界已经形成了一条完整的"记忆层"产品线——Mem0、Zep/Graphiti、LangMem、Letta（MemGPT 后继）——它们的基本范式是：把对话或事件流抽取成事实条目，写入向量库或知识图谱，查询时按相似度检索 top-k 塞进上下文。

问题出在**事实会变**。Agent 先后存下『Peter Sagan 效力于 Bora-Hansgrohe』和『Peter Sagan 效力于 TotalEnergies』，然后被问『Sagan 现在效力于哪支球队？』——这是一个**值无关查询**（value-agnostic query）：它只点名实体，不点名答案。两个版本都完美匹配查询命名的实体，任何相似度函数都无法在两者之间做出区分，检索器返回哪个纯看相似度噪声的脸色。论文在真实数据上测得：**53% 的时候返回的是过期版本**——这没有任何对抗性构造，只是事实变了、查询点名的是实体而非答案。

### 1.2 这个失败为什么一直没被隔离测量

论文指出四条相邻研究线都绕开了这个问题：

- **模型/世界新鲜度基准**（FreshQA、RealTime QA、StreamingQA、DyKnow、GrowOVER）：测模型参数或语料是否跟得上世界，不建模 Agent 自有存储的保留决策；
- **知识冲突研究**：测读者拿到冲突上下文后表现如何，但不问*哪个版本被送进了上下文*；
- **长期记忆基准**（LoCoMo、LongMemEval）：测宽泛回忆能力，但多会话金标准把 staleness 稀释掉了——有分析指出 LoCoMo 94% 的问题只需回看不超过两个会话，且大多数基准对每个事实的更新/删除次数接近零；
- **生产记忆系统**：普遍自带新鲜度机制（Mem0 的 ADD/UPDATE/DELETE 裁决、Zep 的双时间轴失效标记、ERASE 的到达即改写），但**没有公共测量仪说明这些机制何时是必要的、其最难的组件值多少分**。

### 1.3 廉价修复的隐性代价

实践者的第一反应是给检索加时间戳重排（time-rerank）：检索 top-k 后按时间戳取最新的。这确实把 current@1 从 0.464 拉到 0.925。但重排不改变候选集——过期版本只是被降位而非删除，上下文里依然同时躺着新旧两个版本（论文称为**污染**，contamination）。而知识冲突文献早已知道：读者拿到自相矛盾的上下文时表现不可靠。**检索侧的修复是否真的传导到读者侧**，正是这篇论文用实验回答的问题——答案是否定的，甚至在一位读者上符号翻转（详见第五节）。

## 二、论文定位和关联工作

### 2.1 研究谱系

**谱系一：时间感知语言模型与时间 QA。** TempLAMA（Dhingra et al., 2022）从 Wikidata 限定符构造带年度有效期的 (主体, 关系, 客体) 三元组，探测参数化 LM 在特定时刻"相信"什么。StaleBench 直接复用 TempLAMA 的时间三元组，但下移一层提问：**当 Agent 已经把新旧两个值都存进了自己的存储，检索能否浮出当前值？** TimeQA、SituatedQA、TemporalWiki、MQuAKE 同样测时间范围化/演化/编辑后的事实，但都不建模"Agent 自有存储在两个值都已写入后决定保留什么"。

**谱系二：知识冲突与读者行为。** Chen et al. (2022)、Jin et al. (2024)、Wu et al. (2024, ClashEval) 确立了读者解决冲突证据的不可靠性。StaleBench 取互补侧——*哪些版本到达了上下文*——然后在读者轨道上闭环，发现两条文献线在闭环处交互：一个孤立看很强的检索修复（time-rerank）在读者消费其输出后可能有害。

**谱系三：Agent 记忆系统机制。** MemGPT 的自编辑、Mem0 的 LLM 裁决 ADD/UPDATE/DELETE、Zep 的双时间轴边失效、Memory-R1 的 RL 学习记忆操作、ERASE（Li et al., 2025, NAACL Findings）的到达即改写、Generative Agents 的重要性×新近度评分、HippoRAG 的图索引。这些论文**发布了机制但没有发布测量仪**——StaleBench 的策略阶梯把这些机制的原则放在同一挽具下评测，并直接运行了 Mem0、Graphiti、LangMem 三个部署系统和对 ERASE 的忠实复现。

**谱系四：实体分辨率。** 同事实检测本质是实体分辨率问题：记录链接可追溯到 Fellegi & Sunter (1969)，神经实体匹配（Li et al., 2020）、实体链接（Wu et al., 2020）、共指（Joshi et al., 2019）、以及最接近本文锚点自由轴的 TempEL（Zaporojets et al., 2022，Wikipedia 快照上的时序实体链接）。这条线**内禀地**测量匹配质量；缺失的是匹配错误在下游保留决策中的**价格**——给定质量的同事实检测值多少分新鲜度、随锚点撤除如何移动。这就是 StaleBench 键控阶梯作为"针对 oracle 的成本曲线"的定位。

**谱系五（同期收敛）：记忆更新评测集群。** 2026 年出现了一批把"更新/遗忘"推到中心的研究：Memora 与 FAMA 指标（Genies + ASU，Findings of ACL 2026）惩罚依赖已失效事实的回答，发现记忆系统跑得越久罚分越重（周尺度 18.2 点涨到季尺度 29.5 点）；StateMemBench（arXiv:2608.19652）把"后值覆盖前值"的 supersession 作为被测现象、把过期答案列为独立计分结局并配备反更新探针。StaleBench 与它们共享"把 staleness 从背景噪声提升为被测对象"的判断，差异化在于：源定义标签 + 键控难度旋钮 + 读者轨道 + 对部署系统的版本审计。本文与 HEAMS（2611.20144）、AdMem（2611.20605）、LEDGER（2611.20927）、Jetriever（2611.21478）构成同日的 Agent 记忆评测集群（见附录）。

### 2.2 定位对比表

| 路线 | 问的问题 | 看不见的东西 |
|---|---|---|
| TempLAMA / FreshQA / RealTime QA / StreamingQA / DyKnow / GrowOVER | 模型/语料跟得上世界吗 | Agent 自有存储、保留决策、预算 |
| 知识编辑（ROME/MEMIT、MQuAKE） | 能改写权重吗 | 存储本身 |
| 知识冲突（Chen 2022 / Jin 2024 / ClashEval） | 读者拿到冲突上下文怎么办 | 哪个版本进入上下文、以多少内存代价 |
| 实体链接 / 记录链接 / TempEL | 两个提及是同一实体吗 | 判错在下游保留决策中的价格 |
| LoCoMo / LongMemEval | 宽泛长期记忆能力 | 孤立的 staleness（多会话金标准稀释它） |
| 记忆系统（MemGPT/Mem0/Zep/ERASE…） | 发布新鲜度机制 | 隔离测量仪、oracle 定价的键控 |
| **StaleBench** | **存储能否浮出自己的最新知识、每个修复值多少、读者付出什么代价** | 自然对话引用（代词/昵称/语篇共指）、多值事实仅作集合召回 |

**定位结论**：StaleBench 是第一个*隔离* stale retrieval 的公共基准——标签来自源（Wikidata 有效年份）而非任何被测系统的检索分数；同时它是一把*定价尺*：把同事实检测的难度做成受控旋钮，量出每一档修复离 oracle 差多少分；再接一个读者轨道，量出检索指标看不见的读者代价。

## 三、问题定义

### 3.1 从具体场景到抽象结构

具体场景：Agent 记忆系统存了同一事实的多个版本，被问当前值。抽象洞察：这是一个**结构性不可判定问题**——查询嵌入的是实体，每个候选版本都嵌入"实体 + 某个值"，查询-版本相似度被共享的实体分量主导，版本次序由噪声决定。论文的机制解释甚至给出了定量预测：store-all cosine 的 current@1（0.464）接近平均版本数的倒数，且按每事实版本数分层后逐层吻合（2 版本 0.482，≥3 版本 0.289）。

用数据库语言说：**记忆系统缺少主键**。检索相似度是"按内容找"，而版本选择需要"按身份找"——同一事实的判定（keying）就是给记忆建主键，本质是实体分辨率。类比表：

| 数据库概念 | Agent 记忆对应物 |
|---|---|
| 主键 / 候选键 | 事实键（keyer 的输出） |
| upsert（插入或更新） | 保留策略的 overwrite 机制 |
| 软删除 / 墓碑标记 | invalidate 机制（temporal-KG 失效） |
| 实体分辨率 / 记录链接 | 同事实检测（same-fact detection） |
| 索引查询 vs 全表扫描 | 键检索 vs 嵌入相似度检索 |

### 3.2 形式化定义

- **给定**：按时间顺序到达的语句流（每句是可嵌入的自然语言断言 + 元数据时间戳）；每事实一个值无关查询；**源定义**的"当前值"金标准（Wikidata 在最终年的有效值；A→B→A 型回返按值计分而非按发射序号）。
- **策略空间**：store-all 检索（可选时间感知）、或保留策略 = keyer（这是否是已存储事实？）× mechanism（overwrite 槽 / invalidate 保留）× path（写路径 / 读路径 / 对称），可选槽预算 B。
- **求**：top-k 排序，被三族指标计分。
- **约束/护栏**：货币性标签永不来自检索分数；所有策略超参只在 val 分割上调；读者轨道超参继承检索调参、绝不针对读者准确率调优；始终报告保留修复失败之处。

### 3.3 两个关键抽象的精妙之处

**锚点旋钮（anchor knob a）**。模板化语句每次重复主体的表面形式，于是"匹配那个字符串"几乎是完美的同事实检测器——这是所有带重复主体的基准的隐含礼物。真实日志则先介绍实体、后用短形式指代。StaleBench 把锚点做成概率旋钮：非引入性语句以概率 a 用机械导出的别名（Ebrard / M. Ebrard / Los Angeles）替代全名。锚点在场时各键控档位不可区分，撤除后按真实差距散开——**同事实检测的难度从基准的隐含属性变成了受控变量**。

**受控对（controlled pair）**。跨策略比较总被"两个策略同时差异太多"的质疑打断。论文构造读路径键控（retain-everything）与对称键控（read+write）这一对：两者在读路径是同一策略，**在全部 468 个查询上返回完全相同的 rank-1 语句**（逐查询验证 + 回归测试钉死），唯一差异是第 2–5 位填什么——contamination@5 为 0.998 对 0.000。于是读者准确率的任何差异只能归因于 ranks 2–5。这是把相关性观察升级为因果归因的实验设计核心。

## 四、问题解法

### 4.1 基准构建（图 1 的 build 部分）

**数据**：TempLAMA 的 5,839 个事实键中，保留每年单值（保证 top-1 计分清晰）且 2010–2020 窗口内至少变更一次的 892 个事实，覆盖 9 个关系（球队、职位、雇主、党派、教练、主席、政府首脑、所有者、学校），平均 2.1 个不同值（最多 6）。连续同年同值坍缩成一段，用关系专属模板言语化；以概率 p 换用改写模板（paraphrase 旋钮）；年份只进元数据。查询用值无关问句（『S 现在效力于哪支球队？』）。按键哈希切分 val 424 / test 468。三个更大配置框住主配置：含从不被查询的干扰事实的 full_corpus（7,078 语句）、2,995 主体库存、以及 2,904 事实的规模轨道。

**指标**：top-1 三分——current@1（对的事实+当前值）/ stale（对的事实+过期值，即被隔离的失败）/ miss（错的事实）；top-k 上报 current@k 与 **contamination@k**（top-k 同时含某事实的当前与过期版本）以及流结束后的 slots（足迹）。contamination@k 对上下文质量**非单调**——删掉答案也能改善它——所以论文规定它永不脱离 current@k 单独出现（附录 B）。

### 4.2 策略阶梯（policies 部分）

类比：这是一张**针对 oracle 的成本曲线**，每一档回答"这一质量的同事实检测值多少分新鲜度"。

| 组件 | 档位 | 说明 |
|---|---|---|
| store-all 受害者 | BM25 / Cosine | 存一切、按相似度排 |
| 廉价修复 | time-rerank(k)、recency-weight | 候选集不变，只动排序/加权 |
| keyer 阶梯 | threshold（余弦阈值 τ，向量库记忆的默认做法）→ gazetteer（地名录精确匹配）→ fuzzy linker（字符三元组 Jaccard，无别名表、无学习）→ entity linker（+全部可导出别名）→ LLM（glm-4.6 一次性判断）→ oracle（真事实键） | 写路径判定 |
| mechanism | overwrite（破坏性替换）/ temporal-KG invalidate（标记失效并保留，Zep/Graphiti 设计） | 判定后做什么 |
| path 变体 | 读路径键控（查询过同一解析器、按新近度排序该键的槽、全部保留）、对称键控（读+写） | 论文的新增档位 |

关键设计：oracle 是**写路径 oracle**——同事实检测完美但仍按余弦检索，所以读路径档位可以超过它（Table 3 的亏空列为负）。

### 4.3 读者轨道与部署系统三重计分（score 部分）

**读者轨道**：每个策略的 top-5 作为读者上下文（qwen2.5:14b 与 glm-4.6），答案按对当前值的归一化包含计分为 correct/stale/hedged。两个控制：闭卷条件（无上下文 0.088 / 0.244，排除预训练回忆）；每个条件跑两遍——上下文含/不含存储年份（『为什么不给模型看日期』这一最廉价质疑的读者级形式）。

**部署系统**：Mem0（两个版本线）、Graphiti、LangMem 与复现的 ERASE 进入策略位置，在相同流、相同编码器、相同挽具下被**三重计分**：(1) by id——把返回的记忆归因到源语句（榜单惯例）；(2) by text——记忆文本说的是当前值还是过期值；(3) reader——读者从系统自己的 top-5 作答。每个 (release, vector store) 组合先过手工探针门（6 组中 4 组通过，失败组会产生看似合理、实则测量后端的数字）。

## 五、评估指标与实验证据

### 5.1 指标体系与主表（Table 2，锚定配置，468 测试事实）

| 策略 | current@1↑ | stale@1↓ | cont@5↓ | slots↓ |
|---|---|---|---|---|
| BM25（store-all） | 0.400 | 0.592 | 0.991 | 995 |
| BM25 + time-rerank | 0.936 | 0.051 | 0.991 | 995 |
| Cosine（store-all） | 0.464 | 0.530 | 0.974 | 995 |
| Cosine + time-rerank | 0.925 | 0.049 | 0.974 | 995 |
| Cosine + recency-weight | 0.784 | 0.203 | 0.936 | 995 |
| Reconsolidation（threshold τ） | 0.859 | 0.073 | 0.137 | 513 |
| Lexical key（gazetteer） | 0.972 | 0.004 | 0.000 | 467 |
| Keep-latest oracle | 0.979 | 0.000 | 0.000 | 468 |

读表要点：(1) store-all 失败正如值无关分析预测（stale 0.530/0.592）；(2) 廉价修复把 current@1 拉到 0.9+ 但 **contamination@5 纹丝不动（0.936–0.991）**——重排只是降位不删除；(3) 保留策略在源头消灭矛盾（cont 0.000、槽减半）。但此表有一处必须随表声明的性质：**锚定配置在 current@1 上已饱和**——一条从问题模板恢复主体、逐字保留、答最新的盲规则可得 0.996 同时 maximally 污染（cont@5 = 1.0、995 槽），恰是读者轨道测出的最差安排。饱和是检索指标的性质而非任务的性质（读者准确率跨策略 0.327–0.985）。四个预登记配对比较全部 p<10⁻³，其中两个**逆着论文自己的策略**（time-rerank > cosine；最佳 store-all 修复 > threshold 键控）——诚实的显著性报告。

### 5.2 中心测量：锚点撤除的价格（Table 3）

锚定时 gazetteer 与 oracle 无法区分（raw p=1.00/0.26）；撤除（a=1）后各档位散开（p<10⁻³）且差距悬殊：

| 键控档位 | a=0 | a=1 | 键控亏空（对写路径 oracle 0.827） |
|---|---|---|---|
| Overwrite: threshold τ | 0.859 | 0.513 | 31.4 |
| Overwrite: gazetteer（精确） | 0.972 | **0.169** | **65.8** |
| Overwrite: fuzzy linker（无别名表） | 0.968 | 0.714 | 11.3 |
| Overwrite: linker + 别名表 | 0.972 | 0.776 | 5.1 |
| Read-path key（不覆盖） | 0.989 | 0.831 | −0.4 |
| Symmetric key（读+写） | 0.989 | 0.831 | −0.4 |
| Symmetric + 别名表 | 0.994 | **0.912** | −8.5 |
| Overwrite: true-key oracle | 0.979 | 0.827 | — |

三个结论：(1) **部署系统用的两档（threshold、gazetteer）各付几十点**——gazetteer 崩溃因为短形式无法匹配（无检索审计显示 89.3% 事实散落多槽），threshold 靠的表面相似度恰是被别名移除的东西；(2) 锚点自由的同事实检测**并非不可解**——它是实体分辨率问题，用记忆文献尚未采用的普通机制（三元组链接器）可解到距 oracle 几分；(3) **对称解析是免费的**——同一解析器跑在查询上不需要写路径缺乏的任何资源，读路径修 miss（0.167→0.045）、写路径修污染与足迹（467 vs 995 槽），只有对称档两者兼得（0.831 + cont@5 0.034）。机械短形式下对称解析甚至击败写路径完整别名表（0.831 vs 0.776，p=0.03；规模轨道 6.3 vs 11.4 亏空）；自然短形式（附录 I，VR46→Valentino Rossi 类）下该强结论消失（0.780 vs 0.812，不显著），但**无论用什么解析器，解析查询都有益**（各 p<10⁻³）在两种配置下成立。库存完备性是被定价的轴：库存 468→2,995 时 fuzzy 亏空 11.3→28.6，现实语料上翻倍至 23.7。

**检索收益不传导**：time-rerank 检索侧 +46.2 点，读者侧对 qwen 是 **−22.9 点**（符号翻转）、对 glm 仅 +6.6。保留策略则 +42.1/+36.3。**受控对**（read-path vs symmetric，rank-1 全 468 查询逐条相同）：current@1 判平（0.989=0.989）、current@5 偏爱污染方（保留一切永不缺当前值）、读者却是 0.983 vs 0.327（**65.6 点**，p<10⁻³）与 0.979 vs 0.684（29.5 点）。污染方还是全轨道 current@1 最高者（超 oracle），却挂着双读者最差成绩。**分离二者的是 contamination@5——本文新增的指标，这对实验是它最干净的论证。**

**机制是位置性的且探针是因果的**（构造上下文，Table 24）：仅当前语句 0.991；前置一条过期版本代价 14.1 点；同一对语句换序（当前在前）再损 53.6 点——单条过期邻居的代价随位置在 **14.1–67.7 点**间摆动，读者大体回答上下文末尾的内容，而这恰是 time-rerank 制造的排列。glm-4.6 位置效应不可检出（p=0.076）却仍为污染付 29.5 点——**污染的代价跨读者泛化，位置敏感性是读者的属性**。把相同 top-k 反序呈现：rerank 的读者分从 −22.9 变 +13.9（219 个答案改变不抵消），保留策略**零个**答案改变（每事实一条语句，无可重排）——修复的符号由它不控制的提示组装惯例设定。全文普查（附录 L）：42 对策略比较中 current@1 倒挂 13 对、contamination@5 仅 2 对；限定可部署策略后 24 对中 current@1 仍倒挂 3 对、contamination@5 零倒挂。

**展示年份几乎免费地闭合差距**：上下文带存储年份时受控对闭合（0.983=0.983；glm 1.5 点）、最差排列 0.314→0.925。主张不受影响——它关于 current@k 看不见什么——但保留应读作解决矛盾的两种方式之一（存储里或提示里），后者几乎免费；前者在时钟不可信（附录 E：每族修复只读一个时间信号，时钟乱序击垮 time-aware 族、到达乱序击垮 retention 族，双坏无可恢复）、系统不返回有效期时间戳（Mem0 不返回；Graphiti 返回但默认读路径丢弃）、槽预算受限（995 vs 464 槽）时是应选的那种。

|---|---|---|---|---|
| Mem0 2.0.11 | 0.180 | 0.480 | 0.947 | 0.627 |
| Mem0 0.1.118 | 0.913 | 0.573 | 0.593 | 0.720 |

**Mem0：机制离开了安装路径。** 2.0.11 的 add() 走分阶段抽取，系统提示声明唯一操作是 ADD——UPDATE 裁决提示在 mem0/memory/ 下无任何调用点（事件直方图、双语句探针、库源码三重独立证实；857 个 ADD、0 个 UPDATE）。两条语句的探针即见分晓：0.1.118 返回 ADD 1 + UPDATE 1、rank-1 是当前值；2.0.11 返回 ADD 2、过期版本排第一。更深的发现是**归因惯例会撒谎**：by id 高估 0.1.118 达 34.0 点（qwen 的 UPDATE 只重贴标签不改写文本，当前 id 坐在过期文本上）、在 2.0.11 上彻底失效（62% 记忆的 id 指向与文本不同的实体；id 级 miss 0.533 vs 文本级 0.000）。两版本差距按 id 是 73 点、按文本 9.3 点、读者端 0.720 vs 0.627 且无锚时反序——榜单会报的那个数最不可靠。换 glm-4.6 裁决则 UPDATE 改写文本、两种计分一致（0.793/0.793）——分歧本身就是模型依赖的。**保留最旧的写路径定价法**（同解析、每实体留最旧而非最新）给出最干净的正面测量：0.1.118 得 0.353、store-all 与 2.0.11 塌到 0.007——裁决回路真正值的是这个差距，远小于 id 级指标标榜的。**本文的读路径修复后置其上**（无再摄取、无模型调用）：0.1.118 读者 0.720→0.900（+18.0）/0.500→0.853（+35.3）；2.0.11 达 0.993。

**Graphiti：镜像失败。** 写路径失效标记照常开火（157/179 次 supersession），但**默认 search() 不过滤失效边**、按插入序破平局——按安装计分 0.347 低于 store-all，尊重自己的失效标记（有效边优先，同样零模型调用）后 0.833、读者 0.593→0.893；加上查询解析+同实体合并达 0.967。库暴露了有效性过滤器，文档化的默认调用拿不到。

**LangMem：同机制第三种坏法。** qwen 版重写相似记忆但保持 store-all 足迹（327 插入 + 375 更新，327 槽）+ 自行添加无人写过的记忆；无锚时 0.553 的查询直接 miss（短形式写的记忆不是全名查询检索到的）。glm 版把库整合成编年史——332 字符传记、平均含 1.72 个值、25.3% 的 top 记忆写入了流里从未提及的窗口后年份（模型把自己知道的写进了库）——对世界正确、对基准问题 hedged（text 0.147）、读者 0.613，错误不是 stale 而是『两者皆非』。

**ERASE（复现）：编辑库而非到达。** glm 裁决下 0.953/读者 0.980——四机制最佳、距写路径 oracle 3.3 点、无别名表无标识符。代价是 qwen 版误删：147 删除 vs 1395 保留中，0.133 事实的所有版本无存——**能移除过期的机制就是能移除事实的机制**。无锚时跌至 0.713：短形式到达检索不到它取代的全名版本，编辑够不到过期条目——§5.2 的锚点依赖在写路径重现。

四系统共享模式而失败从不重样：Mem0 版本间丢裁决、Graphiti 留裁决读时丢、LangMem 应用裁决但按模型或全留或写成编年史、ERASE 应用到库也（qwen 下）应用到没提的事实。**没有单一计分惯例能描述全部四个。**

### 5.5 边界实验（数字怎么塌）

- **版本数分层（附录 D）**：423 个双版本事实上 time-rerank 0.967；45 个 ≥3 版本事实跌到 **0.533**，被 threshold 键控（0.778）反超——重排的 k 必须盖住全部版本，而最优 k 跟踪的正是同键问题本身。标题 0.925 是被容易的 90% 主导的混合物。
- **两个时间信号（附录 E）**：时钟乱序：time-rerank 0.925→0.484、保留族不动；到达乱序：gazetteer/oracle→0.472、time-aware 族不动；双坏无恢复。迟到的过期报告（剂量 q）：overwrite 按比例失守（q=0.5 时 0.486）而 cont@5 恒 0.000——递给读者的不是矛盾而是一条自信的过期记忆。**哪个档位最好取决于部署能信哪个信号。**
- **规模与多值金标准（附录 M，v1.1）**：2,904 事实上键控阶梯完好，threshold 反超 time-rerank（0.777 vs 0.721，区间不重叠）；set recall@5 上 oracle 0.890 < recency-weighted store-all 0.940——**每事实一槽对新鲜度是正确足迹、对覆盖是错误足迹**，基准分开定价。
- **LLM 键控（附录 J）**：glm-4.6 一次性裁决：锚定 0.846 劣于全部机械档、无锚 0.459 落在阶梯中段；失败模式是不肯合并（散落 52.4% 事实）而候选其实在 top-4 里（86.1%）——是判断不是召回；994 次模型调用对机械档的零次。**在此证据下，收拢无锚缺口的是实体分辨率机制，不是模型规模。**

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**对比对象（baseline）**：store-all 相似度检索 + 时间感知廉价修复——它们有效的条件与失效的根源：

1. **相似度版本选择的结构性不可判定**（论文实验已支持）：值无关查询的嵌入被实体分量主导 → 版本次序由噪声决定 → current@1 ≈ 版本数倒数且逐层吻合。这不是实现缺陷，是该范式在此查询类上的数学性质。
2. **廉价修复只动排序不动候选集**（论文实验已支持）：time-rerank 的 top-5 与 cosine 的 top-5 在 100% 查询上相同 → 污染保留 → 而读者对污染的代价巨大且位置敏感（构造上下文因果证明 14.1–67.7 点）→ time-rerank 把当前版本提到最前，恰好制造读者处理最差的排列（当前在前、过期贴近问题）→ **+46.2 的检索分在读者端变成 −22.9**。
3. **保留策略在源头删除矛盾**（论文实验已支持）：键控正确时 contamination=0.000、槽减半、读者端 +42.1/+36.3；且对呈现顺序**零答案改变**——顺序不变性是存储的属性不是读者的属性。
4. **同事实检测 = 实体分辨率**（论文实验已支持）：锚点撤除后部署系统键控的崩溃模式（gazetteer 89.3% 散落 = 分裂错误；threshold 的假合并 7.3% 不可逆销毁证据 = 合并错误）正是实体分辨率的经典 split/merge 权衡；用普通链接器（无学习）即可解到距 oracle 几分，说明缺口是**机制采用**问题而非研究前沿问题。
5. **对称性免费**（论文实验已支持）：写路径解析器跑在查询上不需要新资源 → 读路径修 miss（嵌入从不认识短形式查询的问题）、写路径修污染与足迹 → 对称档两者兼得；后置到 Mem0 上 +18.0/+35.3 点、后置到 Graphiti 读路径 0.593→0.893/0.967——**免费且可移植**。
6. **读者差异的机制**（论文自认不知）：qwen 位置惩罚 53.6 点 vs glm 不可检出（4.5 点）——为何两读者不同，论文明确声明不解释（规模与预训练知识量 0.088 vs 0.244 不同）。此为**开放问题**，非已证机制。

### 6.3 综合判断与未决问题

**多项研究共同支持的机制**：(a) 相似度检索不能承担版本选择——StaleBench 的结构分析、Memora 的罚分、StateMemBench 的 supersession 计分、Jetriever 的『相似度≠效用』从不同侧面一致；(b) 结构化/确定性机制优于让 LLM 在上下文里裁决新鲜度——Don't-Ask 的确定性选择器、StaleBench 的机械链接器优于 LLM 一次性键控、保留策略的顺序不变性，三者同向。

**仍属推测/开放的部分**：两读者位置敏感性的差异机制（论文明示不知）；LLM 键控的下界测量（一次提示、4 候选、1 模型——库存化的 LLM 键控是显然但未跑的实验）；自然短形式下对称优势让位于别名表（点估计支持、不显著）。

**优势成立条件**：时间戳与到达序至少一个可信任（各修复族各读一个信号）；库存覆盖被查主体（读路径是最容易的方向——查询总用全名；椭圆查询会两边都付费）；槽预算受限或系统不返回时间戳时保留优于提示侧日期。

**可能失效条件**：需要历史本身作为记录的场景（审计/合规）中破坏性覆盖是错误机制、假合并不可恢复——论文因此同时评测 invalidation（约 2× 足迹、零精度代价、墓碑可恢复）；事实静默失效（无新版本到达）超出仪器测量范围。

## 七、必要知识反推

假设让一个没有背景的人重做这项工作，最少需要知道什么？

### 7.1 领域知识层

- **Agent 记忆系统的实际形态**（Mem0 的 ADD/UPDATE 裁决、Zep/Graphiti 的双时间轴边失效、LangMem 的结构化输出补丁、MemGPT 系谱）——不理解这些机制就无法构造它们的原则化抽象（keyer × mechanism × path），§5.4 的三重计分也无从设计。
- **信息检索**：BM25 与稠密检索的排序机制、time-rerank/recency 加权的确切含义——否则写不出『候选集不变所以 cont@j≤k 按构造相同』这类推理。
- **时间知识图谱的双时间轴概念**（valid time vs system time）——temporal-KG 档位与 Zep 设计的对应关系由此而来。

### 7.2 方法论知识层

- **实体分辨率谱系**（记录链接→神经实体匹配→实体链接→共指→TempEL）——这是识别出『同事实检测本质是实体分辨率』的前提，也是能判断『记忆文献尚未采用它』的知识基础。
- **知识冲突读者研究的结论**——知道读者对冲突上下文不可靠，才会设计读者轨道去验证污染的代价而非假设它。
- **基准设计的因果纪律**：源定义标签、val/test 隔离调参、预登记比较族、符号翻转置换检验 + Holm 校正、把失败与自身逆势结果一并报告——没有这些，Table 2 里『两个比较逆着自己策略』的诚实与受控对的逐查询回归测试钉死都无从谈起。
- **问卷/心理语言学式的构造上下文方法**——把污染从观察变量变成操纵变量，才能把 14.1 与 53.6 点拆开归因。

### 7.3 工程知识层

- **部署系统的版本考古能力**：读 mem0 两个版本线的分发路径与调用点、发现 UPDATE 提示无 call site、用事件直方图+两语句探针+源码三重独立证实——以及『每个 (release, backend) 先过手工探针门，4/6 通过』的工程纪律（失败组会产生看似合理的假数字）。
- **可复现工程**：结果文件注入稿件（零手抄）、宏断言进构建（受控对前提破坏即 fail the build）、LLM 调用缓存随发布、单笔记本 CPU 一小时内复现全部非 LLM 数字。
- **成本核算**：给每个部署系统记推理时长（4.2h/7.5h/3.1h/0.5h）与模型调用数（LLM 键控 994 次 vs 机械档 0 次）——修复的价格不只是精度差。

### 7.4 知识融合的关键节点

1. **节点一：把『记忆的新鲜度问题』重写成『给记忆建主键』**——领域知识（记忆系统机制）× 数据库/实体分辨率知识的化学反应，产生了 keyer 阶梯与成本曲线的整个框架。
2. **节点二：把『读者不可靠』从文献假设变成可归因测量**——受控对设计（工程上的回归测试思想）× 读者研究（方法论）的融合，产出 65.6 点这一全文最锋利的数字。
3. **节点三：把『引用机制』与『机制在跑』区分开**——版本考古（工程）× 三重计分（方法论）融合，让基准第一次能对部署系统说『你榜单上的数字是错的』。

## 八、论文中可以提取的通用性灵感

**灵感一：评测指标必须闭环到最终消费者，否则可能把修复排反。**
核心思想：中间指标（检索 current@1）与终端指标（读者准确率）可以对同一组策略给出相反排序。
论文证据：time-rerank 检索 +46.2 / 读者 −22.9；受控对 rank-1 全同而读者差 65.6 点；42 对比较倒挂 13 对。
推广场景：RAG 系统只报检索召回不报答案质量；推荐系统只报 CTR 不报满意度；代码补全只报候选命中率不报采纳率；GUI Agent 只报元素定位不报任务完成；多轮对话只报轮次检索不报会话目标达成。

**灵感二：把『隐含难度』做成受控旋钮，量出能力成本曲线。**
核心思想：很多系统的表观能力来自基准的隐含礼物（重复主体→字符串匹配即可）；把礼物变成概率旋钮，各方法按真实差距散开。
论文证据：锚点 a 从 0 到 1，gazetteer 0.972→0.169、fuzzy 0.968→0.714；锚定时各档 p=1.00 不可区分。
推广场景：代码生成中把『测试用例恰好覆盖分支』做成覆盖旋钮；翻译中把『术语表先行』做成可用性旋钮；Agent 评测把『任务描述完整度』做成旋钮；安全评测把『攻击面暴露度』做成旋钮。

**灵感三：因子化策略空间 = keyer × mechanism × path。**
核心思想：把复合系统分解为正交决策维度的乘积，才能归因『差在哪一维』并发现被忽略的维度（读路径）。
论文证据：同 keyer 下 overwrite vs invalidate 零精度差、2× 足迹；同解析器写路径 vs 对称路径差 9–12.6 点且免费。
推广场景：把 RAG 分解为 chunker × retriever × reranker × assembler；把微调分解为数据 × 目标函数 × 调度；把 Agent 框架分解为规划器 × 工具接口 × 记忆策略；把数据库分解为存储引擎 × 索引 × 查询优化器分别定价。

**灵感四：写路径已有的组件，免费跑在读路径上——检查你的系统里的不对称。**
核心思想：系统常在写入侧做昂贵判断、在读取侧退回通用机制；把写侧解析器复用到查询上是零成本的对称化。
论文证据：symmetric keying 0.831 vs 写路径单独 0.714；后置到 Mem0 0.1.118 +18.0/+35.3 点、2.0.11 达 0.993、Graphiti 0.593→0.893——全都不加模型调用。
推广场景：编译器前端的类型信息用于 IDE 查询；ETL 的实体规范化用于查询改写；日志系统的写入端 schema 用于读取端过滤；API 网关的写入端校验复用为读取端路由。

**灵感五：每族修复只读一个信号——把鲁棒性假设显式化并分别腐蚀。**
核心思想：看似冗余的两种修复（时钟 vs 到达序）实际各依赖一个正交假设；分别腐蚀信号才能看清互补域。
论文证据：时钟乱序击垮 time-aware 族（0.925→0.484）、到达乱序击垮 retention 族（0.972→0.472）、双坏无恢复；迟到的过期报告让 overwrite 递出自信的过期记忆而非矛盾。
推广场景：缓存同时依赖 TTL 与写入序；分布式系统的心跳 vs 向量时钟；数据管线的晚到数据处理；人机系统的双通道确认。

**灵感六：评测部署系统要 pin 版本 + 多重计分，归因惯例本身是测量对象。**
核心思想：被测系统的行为可在次版本间离开文档化路径；id 级归因、文本级事实、终端读者三个视角可以给出 73 点 vs 9.3 点的相反叙事。
论文证据：Mem0 2.0.11 裁决离开 add()；by id 高估 0.1.118 达 34 点、在 2.0.11 上 62% id 张冠李戴；glm 裁决下 UPDATE 改写文本、分歧消失——惯例的偏差还是模型依赖的。
推广场景：评测依赖的库版本锁定与行为探针；LLM 榜单按日志归因 vs 按输出内容计分的分野；Agent 工具评测区分『调用了工具』与『工具产生了影响』；任何 wrapper 测量都要先证明 wrapper 量的是系统而不是后端。

## 附录：同日 Agent 记忆评测集群（2026-11-15/16）

这篇论文与另外四篇同日工作构成一个值得整体阅读的集群：

- **[HEAMS](https://arxiv.org/abs/2611.20144)**（Mila + Mozilla）：对记忆系统的整体评测——性能之外并列隐私、用户主权、安全三维；治理层是隐私/安全改善的唯一来源且各维皆有代价。与 StaleBench 互补：一个横向扩维度，一个纵向钻单一失败。
- **[AdMem](https://arxiv.org/abs/2611.20605)**（Princeton + Amazon + Arm，NeurIPS 2026 Workshop）：期望接地的程序性记忆——朴素积累跨任务经验会让 Agent 比无记忆更差；补的是逐动作归因与条目显式生命周期（效用驱动的驱逐与合并）。其『条目需要生命周期』与 StaleBench 的 supersession 生命周期是同一问题在程序性/陈述性记忆上的投影。
- **[LEDGER](https://arxiv.org/abs/2611.20927)**：可审计的变更下 Agent 记忆——LM 提议事实、显式规则裁决哪个值当前/信哪个源/删什么，每条事实保留来源与有效期。它把 StaleBench 定价的『裁决』做成了带出处的一等公民。
- **[Jetriever](https://arxiv.org/abs/2611.21478)**：把记忆检索从相似度转向效用——按决策效用分对全池打分，间接查询任务上 gold-first 84.8% vs BM25 1.6%。与 StaleBench 的值无关失败同声相应：相似度在记忆检索里是错误的排序信号。

集群的合读价值：五篇论文从评测维度（HEAMS）、条目生命周期（AdMem）、裁决可审计性（LEDGER）、排序信号（Jetriever）、失败隔离与定价（StaleBench）五个方向同时收敛到同一个判断——**Agent 记忆的研究重心正从『存得下、找得到』转向『知道什么还成立』**。
