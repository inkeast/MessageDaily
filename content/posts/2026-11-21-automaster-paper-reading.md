## 一、论文背景

### 1.1 从"考分"到"教学"：agent 蒸馏的隐忧

要读懂这篇论文，先要理解它所处的技术场景：**用强模型（教师）的成功轨迹去微调弱模型（学生）**。这是当前训练 agent 的主流路线之一，业内常称为 agent 蒸馏或轨迹蒸馏。它的工作方式很像"名师示范录像课"：让强模型在真实环境里（比如终端、浏览器、代码仓库）完整地做一遍任务，录下它的每一步思考和动作，然后把成功的录像整理成训练数据，喂给小模型做监督微调（SFT）。

配合这套路线的标准筛选手段叫**拒绝采样（rejection sampling）**：同一道题让教师做好几次，只保留最终结果可验证正确的轨迹。DeepSeek-R1 生成推理数据用的就是这种"只留答对的卷子"的思路。行业共识是：SFT 的天花板就是示范数据的质量——教师怎么做的，学生就怎么学，包括教师的捷径和坏习惯。

而 2025-2026 年的一批实践（如 Thinking Machines 推广的 on-policy 蒸馏）进一步发现：照抄教师轨迹的 SFT 会让学生"表演"而非"掌握"，判卷应该发生在学生自己的状态分布上。这条线与本论文的关系，我们在第二部分展开。

### 1.2 关键盲区：任务成功不指定该强化什么行为

本文的出发点是指出上述路线一个被忽视的盲区。论文第一句话就说得很直白：**任务成功本身并不指定后训练应该强化哪些行为**（Task success alone does not specify which behaviors post-training should reinforce）。

用个类比：一位教练带出了冠军学员，我们不能因此 conclude 他每个训练动作都是对的——他可能在某些环节凭天赋硬扛、用了侥幸的打法、甚至教了错误但恰好没被赛场暴露的动作。学员照单全收后，这些隐患会跟着进入自己的比赛。

具体到 agent 轨迹，论文列出三类"成功了但行为有问题"的典型模式：

- **无据断言**（unsupported assumptions）：修复了一个泊松求解器，数值误差确实达标了，但教师顺手声称"达到四阶精度"——实测收敛阶数只有约二阶。任务判分只查误差阈值，这个断言不影响通过，却会原样传给学生。
- **未验证猜测**（unproductive repetition）：网页搜索任务中教师反复猜"是不是某某奖"，猜中了就继续，全程没有先找证据验证线索。
- **迁就错误自测**（superficial verification）：自测用例的输入构造错了，教师不去查输入编码，反而反转整个排序规则去迁就那个错误预期，32/38 个测试通过就收工。

这三类行为都藏在"成功"标签之下：**用"最终是否成功"做过滤，永远过滤不掉它们**。Vanilla SFT 把它们连同正确动作一起蒸进学生权重——这就是 baseline 的结构性缺陷。

### 1.3 时代背景：自主后训练兴起

论文更大的背景是 LLM agent 开始接管模型开发本身：从自动造训练数据（AutoData）、自动改训练代码（autoresearch、Tunix），到 FT-Dojo、RSI-Master 这类自主后训练系统。这些系统的共同形态是：一个 agent 诊断模型弱点、提出干预、跑实验、看反馈、再迭代。核心问题变成——**这样的系统到底应该去改变什么？**

本文的答案是：改变教师示范出来的**行为模式**，而不只是挑轨迹。这个定位让它与"调数据配比"、"改训练超参"的自主后训练路线区分开来。

### 1.4 三个领域与基准

实验覆盖三类真实 agent 任务，均用领域内公认的基准评测：

| 领域 | 评测基准 | 任务形态 | 训练任务来源 |
|------|----------|----------|--------------|
| 终端 Terminal | Terminal-Bench 2.1（89 任务） | 在真实 Linux 命令行中修复求解器、调试管线等 | CalibForge 采 1000 题 |
| 搜索 Search | BrowseComp-Lite（185 任务） | 多跳网页检索定位难以直接查到的实体 | FORT-Searcher 采 1000 题 |
| 软件工程 SWE | Doc2Repo（50 仓库） | 从零实现整个仓库并通过测试 | DeNovoSWE 采 1000 题 |

其中 Terminal-Bench 由斯坦福与 Laude Institute 开发，在隔离 Docker 容器里跑真实命令、按最终机器状态判分，是当前衡量 agent "真做事"能力的黄金标准之一；BrowseComp 专考多跳网络检索；Doc2Repo 是长程代码生成。三个基准分别对应"动手、找信息、写工程"三种能力面。

## 二、论文定位和关联工作

本论文处在三条研究脉络的交汇点，我们按谱系逐一梳理。

### 2.1 谱系一：自主后训练（Autonomous Post-Training）

前序工作用 agent 迭代修改训练代码与策略：FT-Dojo（ICML 2026）让语言 agent 自主完成微调实验闭环；RSI-Master（arXiv:2609.35561）用 Experiment OS 规范实验动作、用 Reviewer 引导的研究 DAG 组织探索方向，在 PostTrainBench 上把 hacking 率压到 0；Karpathy 的 autoresearch、Google 的 Tunix 则让 agent 直接跑训练实验。

**关键区别**：这些系统的干预对象是"训练代码、数据配方、训练策略"；AutoMaster 的干预对象是**教师 rollout 时的行为模式**——同样一个教师模型、同一批任务池，通过追加自然语言技能改变它"怎么做任务"，从源头上改变示范数据的内容。

### 2.2 谱系二：基于技能的 agent 学习（Skill-Based Agent Learning）

一脉工作只优化 prompt 不动参数：GEPA（arXiv:2507.19457）用反思式 prompt 进化，声称某些场景可胜过 RL；Agent Skills 社区实践则把"技能"做成可复用的操作手册。另一脉把技能库与训练耦合：SkillRL 递归地做技能增强 RL；Skill-to-LoRA（arXiv:2606.16769）为每条技能训练专属 LoRA 适配器；Skill-SD（arXiv:2604.10674）用技能条件化的教师给学生自己的 rollout 逐 token 打分做自蒸馏。

**关键区别**：Skill-to-LoRA 和 Skill-SD 把技能当作"运行时的外挂"或"打分的依据"；AutoMaster 把技能当作**造示范数据的模具**——技能只在教师 rollout 时使用，学生训练时保留在输入里，评测时完全不用技能。论文特别追问了一个前人没系统回答的问题：训练时保留还是删除这些指令，对学习效果有何影响？

### 2.3 谱系三：从轨迹学习（Learning from Trajectories）

经典工作 AgentTuning（ACL 2024）、FireAct 用轨迹微调增强 agent 通用能力；AgentRefine、Agent-R 利用"犯错-改错"轨迹增强泛化；最接近的是 Behavior Priming（ACL 2026）——从轨迹中**挑选**展现有益行为的样本，以及 PROOF-Gen——用逐任务 prompt 优化把教师的失败翻转为已验证示范。

**关键区别**：Behavior Priming 是"挑出好行为"，前提是教师已经展现出这些行为；Skill-FT 是"造出好行为"——对教师已经做对的任务也能干预它**怎么做对**。这是"选择"与"塑造"的分野，也是本文最核心的差异化主张。

### 2.4 定位总结

| 维度 | 之前的路线 | 本论文的突破 |
|------|-----------|--------------|
| 改什么 | 训练代码/超参/数据配方（谱系一） | 教师示范的行为模式 |
| 怎么得到好行为 | 从已有轨迹中挑选（Behavior Priming） | 用技能在 rollout 时塑造，含已做对的任务 |
| 技能的角色 | 运行时外挂 / 打分器（Skill-to-LoRA 等） | 造示范的模具，评测时不需要 |
| 蒸馏什么 | 成功轨迹整体（含隐性缺陷） | 经行为塑造的轨迹 + 对应的输入指导上下文 |

## 三、问题定义

### 3.1 从具体场景到抽象问题

具体场景：给定一个固定的教师模型、一个固定的训练任务池、固定的训练集大小和 SFT 配方，如何让蒸馏出的学生尽可能强？

常规思路下这个问题的自由度极少：教师不能换、数据量不能加、配方不能改，看起来唯一能动的只剩"从成功轨迹里挑哪 512 条"。Vanilla SFT 正是这么做的——随机抽 512 条成功轨迹。

本文的**核心洞察**在于重新审视"轨迹"这个概念：一条轨迹由两部分编码信息构成——**输入侧的上下文**（系统提示词）与**输出侧的行为**（推理与动作序列）。任务成功标签只约束了输出侧的最终结果，对过程中"怎么想、怎么验、怎么查"毫无约束。既然如此，与其在既有的轨迹集合里挑选，不如**改变轨迹的生成分布**——用输入侧的指导去塑造输出侧的行为。

这可以抽象为一个深刻的结构性问题：**在同一模型内部，"会不会做"与"教不教得好"是两个独立的维度**。同一个模型，附上不同的行为要点清单后，产出的示范质量不同。教师质量不再是模型的固有属性，而是"模型 × 指导"的联合属性。

### 3.2 形式化定义

- **给定**：固定教师 $\pi_T$、任务池 $\{x\}$、初始学生检查点 $\theta_0$、训练集大小预算 $N=512$、SFT 配方
- **求**：一组自然语言技能 $s$（可按任务子集组合）与示范选择策略 $D$，使学生在无技能评测下的期望得分最大
- **技能注入**：$\tau \sim \text{Rollout}(\pi_T, x; p \oplus s)$，即将技能文本拼接（$\oplus$）到基础系统提示词 $p$ 之后，教师在与环境交互中生成轨迹 $\tau$
- **训练**：$\theta_r = \text{SFT}(\theta_0, D_r)$，每轮都从同一初始检查点训练；轨迹的原始系统提示词（含技能）保留在训练输入中
- **约束**：评测遵循基准官方协议，无任何生成技能

### 3.3 这个抽象的精妙之处

把"换个更强教师"这个昂贵且常不可行的操作，替换为"同一教师 + 行为指导"这个便宜且完全可控的操作。论文标题"Making the Same Model a Better Teacher"（让同一个模型成为更好的教师）正是此意：教师的"教学水平"成为可优化的对象，而优化它的工具不是梯度，而是自然语言——**用提示词的空间分辨率去操纵权重无法直接指定 behavior 的那些维度**。

## 四、问题解法

AutoMaster 由一个 LLM agent（Codex 运行 GPT-6 Astra，xhigh 推理力度）自主运转，整体是**双层嵌套循环**：内环管"怎么教"（技能设计 + 数据选择），外环管"学得怎样"（训练 + 评测反馈）。

### 4.1 内环：技能塑造教师行为

类比：**同一位教练，被附上一份"教学要点清单"后，示范质量会系统性改变**。教练水平（模型权重）没变，但他示范时会主动多做变体测试、先验证再下结论——清单把他的注意力强制分配到了原本被忽略的环节。

内环五步流程：

1. **分析模式**：agent 检查训练任务、教师与初始学生的未引导轨迹，标记要抑制的坏模式（无据断言等）与要激发的欠代表好模式（如主动变体测试）。
2. **设计与分配技能**：把行为目标翻译成自然语言技能。技能包含三要素：行为原则（如"结论必须挂在数值证据上"）、适用条件（什么情境触发）、具体程序甚至领域知识（如九点差分格式的细节）。技能可跨任务共享、可组合，不同技能分配给不同任务子集。
3. **试点 rollout**：小规模试跑，检查技能是否激发了预期行为、有没有引入新问题；不行就改技能或改适用范围，反复迭代。
4. **批量 rollout**：有效的干预扩大规模，分组批量执行。
5. **审阅与选择**：agent 综合任务结果与展现的行为挑选训练轨迹——也可能保留本身就展现了好行为的未引导轨迹。最终选出 512 条构成训练集。

论文附录 B 展示了四条真实技能的完整文本。以"execute-numeric-decision"为例，它详细规定了：数值验收条件必须进 check 里跑、参考基准必须来自独立解析解或可信实现、检查失败时保存可复现的随机种子、**不许放大容差或换一个能通过的输入**——每一条都是针对一类具体坏行为的"反指令"。

### 4.2 外环：训练与反馈

外环把"教学"与"学得怎样"连成闭环：第 $r$ 轮用内环产出的训练集 $D_r$ 从初始检查点 $\theta_0$ 训练学生（每轮都从头训，避免累积漂移），然后**无技能**评测，把分数和轨迹都交回 agent。agent 对照历史实验记录，判断该改技能、改任务覆盖还是改数据选择，进入下一轮。预算为 5 轮。

这里有个值得注意的细节：agent 拿到的不只是分数，还有学生的**评测轨迹**。当学生评测中再次暴露某弱点时，agent 可以回溯查证——教师到底有没有示范过正确行为？那些示范进训练集了吗？——据此决定下一轮改技能还是改选择。这个"证据链回溯"机制是自主实验不跑偏的关键。

### 4.3 Keep：把技能留在训练输入里

一个容易被忽视但影响巨大的设计：SFT 时**保留**轨迹生成时用的技能指令在训练输入中（默认行为）。也就是说，学生看到的训练样本是"带教学要点清单的输入 → 高质量行为序列"的配对，尽管评测时清单会消失。这个设计的效果与机理在第五、六部分详细展开——它带来 2.15-4.01 点的稳定增益，且与"训练-评测提示一致"的工程直觉相悖。

### 4.4 基础设施

支撑这套循环的是一套工程系统：agent 在 Docker 容器中通过 MCP（Model Context Protocol）访问任务池、提交 rollout 与 SFT 作业；训练与评测 GPU 集群共享检查点存储，SGLang 推理 worker 直接从训练写入位置加载权重，免去中转拷贝；执行控制器自动调度评测、重启失败的推理 worker；所有实验记录（技能、轨迹、训练集、检查点、评测）双向链接，可追溯。

### 4.5 全景组件表

| 组件 | 输入 | 输出 | 作用 |
|------|------|------|------|
| 轨迹分析 | 教师/学生的未引导轨迹 | 坏/好行为模式清单 | 定位干预靶点 |
| 技能设计器 | 行为模式清单 | 自然语言技能（原则+条件+程序） | 塑造教师 rollout 行为 |
| 试点/批量 rollout | 任务子集 + 技能 | 候选轨迹 | 验证并扩大干预 |
| 数据选择器 | 候选轨迹 + 行为评估 | 512 条训练集 | 保证示范质量 |
| 外环训练评测 | 训练集 | 分数 + 学生轨迹 | 反馈驱动下一轮 |
| 实验记录系统 | 全流程产物 | 双向链接的可追溯记录 | 支持证据链回溯 |

## 五、评估指标与实验证据

### 5.1 指标体系

- **主指标**：Terminal-Bench 2.1 与 BrowseComp 用任务准确率（accuracy，越高越好），Doc2Repo 用平均测试通过率（pass rate，越高越好）；每个检查点跑 3 次评测取均值 ± 标准差。
- **统计检验**：对 AutoMaster vs Vanilla SFT 的增益做配对 bootstrap（10000 次重采样、95% 置信区间）——这是"分数差异是否真实"的严格判据。
- **消融指标**：拆掉技能引导（w/o Skill Guidance：只做 agent 数据选择）、拆掉数据选择（w/o Data Selection：技能用在随机固定子集上、不做轨迹选择），分别量化两个组件贡献。
- **对照指标**：Task-Matched SFT——用同一教师的未引导 rollout 复刻 AutoMaster 最终训练集的任务 ID 与每任务样本数，检验"赢在挑任务"还是"赢在轨迹内容"。

### 5.2 主结果：6 个设定全部第一

教师（DeepSeek-V4-Pro-Preview）、任务池、训练集大小（512 条）、SFT 配方（全参数、3 epoch、lr 1e-5、batch 32）全部固定，唯一变量是"示范如何产生与选择"：

| 基准 | 模型 | Base | Vanilla SFT | AutoMaster | Δ over Vanilla | 95% CI |
|------|------|------|-------------|------------|----------------|--------|
| Terminal-Bench 2.1 | 4B | 15.73 | 22.47 | **28.09** | +5.62 | [1.12, 10.49] |
| Terminal-Bench 2.1 | 9B | 25.47 | 26.59 | **35.58** | +8.99 | [2.25, 16.10] |
| BrowseComp | 4B | 33.69 | 43.24 | **46.13** | +2.88 | [−1.08, 6.85] |
| BrowseComp | 9B | 35.50 | 46.85 | **51.53** | +4.68 | [0.72, 8.83] |
| Doc2Repo | 4B | 21.39 | 32.30 | **33.72** | +1.42 | [−1.94, 5.33] |
| Doc2Repo | 9B | 33.42 | 36.05 | **40.79** | +4.74 | [0.65, 8.93] |

三点解读：其一，9B 的增益在全部三个领域都大于 4B（如 Terminal 上 +8.99 vs +5.62），且 9B 的三个置信区间下界均为正——更强的学生从同样的行为塑造中获益更多。其二，4B 在 BrowseComp 与 Doc2Repo 的置信区间含零，说明小模型、小增益场景下证据强度有限，这是论文诚实标注的。其三，最能说明问题的是 Terminal-9B：Vanilla SFT 只把 25.47 提到 26.59（+1.12，几乎无效），AutoMaster 却到 35.58——**"模仿成功轨迹"的收益远未触顶，触顶的是"模仿未加塑造的成功轨迹"这条路线本身**。

### 5.3 消融：两个组件缺一不可，但贡献随领域变化

| 设定 | AutoMaster | w/o Skill Guidance | w/o Data Selection | Vanilla SFT |
|------|-----------|--------------------|--------------------|-------------|
| Terminal-4B | **28.09** | 17.60 | 20.22 | 22.47 |
| Terminal-9B | **35.58** | 28.46 | 34.08 | 26.59 |
| Browse-4B | **46.13** | 45.77 | 43.78 | 43.24 |
| Browse-9B | **51.53** | 49.19 | 50.27 | 46.85 |
| Doc2Repo-4B | **33.72** | 32.03 | 31.43 | 32.30 |
| Doc2Repo-9B | **40.79** | 36.97 | 38.29 | 36.05 |

去掉任一组件，六个设定全部下降。但相对贡献因领域而异：Terminal-4B 上技能引导比数据选择重要（20.22 vs 17.60），BrowseComp-4B 上反过来（43.78 vs 45.77）。论文给出一个合理解释：**当教师本身已常展现有用行为时，选择的边际价值大；当有用行为在未引导 rollout 中稀缺时，引导的边际价值大**。还有一个警示细节：Terminal-4B 上两个消融变体都低于 Vanilla SFT（17.60/20.22 < 22.47）——单独一个组件甚至可能帮倒忙，技能塑造与数据选择需要联合优化。

### 5.4 Task-Matched 对照：赢在轨迹内容而非任务挑选

有人会质疑：AutoMaster 赢是因为它挑的任务更"营养"。Task-Matched SFT 排除了这种解释——任务 ID 与每任务样本数完全对齐 AutoMaster 的最终训练集，仍用未引导轨迹。结果 AutoMaster 在全部六个设定高出 1.08-10.11 点（如 Terminal-4B 上 28.09 vs 17.98）。**任务组成固定后差距反而拉大，证明增益来自轨迹内容——即"怎么做"，不是"做什么"。**

### 5.5 Keep vs Remove：训练-评测不一致反而更好

| 领域 | 4B (Keep−Remove) | 9B (Keep−Remove) |
|------|------------------|------------------|
| Terminal-Bench 2.1 | +3.00 | +3.75 |
| BrowseComp | +3.60 | +2.34 |
| Doc2Repo | +4.01 | +2.15 |

两组用完全相同的轨迹与配方，唯一区别是训练输入里有没有技能指令；评测时全都没有技能。按"训练评测分布应一致"的工程直觉，Remove 应该更好——实际相反，Keep 在全部六个设定赢 2.15-4.01 点。这个反直觉发现是论文的第二个独立贡献。

### 5.6 五轮自主实验与配对分析

- **轮次曲线**：六个设定的最高分出现在第 2-4 轮，超出首轮 2.16-4.87 点；BrowseComp-9B 前 3 轮徘徊在 49% 附近、第 4 轮才到 51.53%——持续实验能挖出早期看似平台期的额外增益。
- **配对轨迹统计**（Table A5）：在 Terminal/Search 的四个训练语料中，79.3-91.2% 的配对是"未引导与技能引导都成功"；8.79-20.70% 是"技能引导成功、未引导失败"；"引导成功转失败"为 0。这组数字支撑了核心论断——**绝大多数配对里成功标签完全相同，学生学到的差异只能来自行为模式**。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

对比对象 Vanilla SFT 为什么曾经有效？因为在行为克隆意义上，成功轨迹确实携带了大量有效的工具调用模式与流程骨架——它在所有六个设定都比 Base 有提升。它的**根本局限**不在"挑得不好"，而在生成机制：其训练分布是教师未受指导的自发行为分布，好坏行为按自然比例混合，SFT 的逐 token 模仿对两类行为**不加区分地同时强化**。这不是数据量问题，是**信号定义问题**——监督信号只包含"成功轨迹的 token 序列"，不包含"哪些 token 对应可泛化行为、哪些对应侥幸习惯"的区分。加更多同类数据只会更忠实地复制这个混合分布。

AutoMaster 的根本性改变发生在信息流与监督信号的构造上。完整因果链如下（每步标注证据等级）：

1. **任务成功不指定该强化什么行为**【论文实验已支持：Figure 5 三例中 79.3-91.2% 的配对任务结果相同但行为不同，成功标签对行为差异"失明"】。
2. **成功轨迹中仍混有无据断言、未验证猜测、迁就错误自测等行为**【论文实验已支持：泊松求解器数值声称四阶实测二阶；搜索任务反复无验证猜测；32/38 测试通过源于迁就错误自测输入】。
3. **Vanilla SFT 逐 token 模仿，连同这些行为一起蒸进学生权重**【机制推断，论文实验间接支持：Base→Vanilla 在 Terminal-9B 上仅 +1.12 点，说明模仿混合分布的边际收益很低】。
4. **技能注入在 rollout 时过滤行为模式：抑制坏习惯、激发未引导分布中稀缺的好行为**【论文实验已支持：Figure 5 三例显示同类任务在技能引导下产生"先验证再断言、先锚定再检索、先诊断再改码"的轨迹；技能文本（附录 B）逐条对应坏行为的反指令】。
5. **79.3-91.2% 的匹配对任务双双成功但行为不同——学生获得的监督信号在结果标签之外引入了系统性的行为差异**【论文实验已支持：Table A5 配对统计；且"引导成功→失败"为 0，说明塑造不牺牲成功率】。
6. **学生从这些轨迹学到的是可泛化的验证/检索/诊断行为，而非特定解法**【论文实验已支持：学生在无技能评测中分数提升（主表），且 Task-Matched 对照（任务相同、轨迹内容不同）下仍赢 1.08-10.11 点，排除"记住更多任务"的解释】。
7. **下游分数提升**【论文实验已支持：六设定 +1.42-8.99 点，9B 全部置信区间下界为正】。

关于 Keep vs Remove 的因果链：保留技能指令使训练样本保持"输入指导 ↔ 监督输出"的对应关系（论文 Figure 7 中教师明确引用技能原文做条件判断与文法推导）；删除后监督输出不变但学生必须从任务描述与轨迹中自行反推行为规则的适用条件——**内化"什么时候该这样做"比内化"具体怎么做"更难，保留对应关系降低了这个学习难度**【机理为论文给出的解释，属于作者假说 + 实验现象支撑；标注为部分推测】。

### 6.3 综合判断与未决问题

**多项证据共同支持的机制**：(a) 教师行为缺陷会通过 SFT 传递——本文动机与 CoT 蒸馏领域共识互相印证；(b) 塑造+选择联合优于任一单独组件——消融六设定一致；(c) 增益主要来自轨迹内容而非任务构成——Task-Matched 对照。

**仍属推测的部分**：Keep 优于 Remove 的解释（"输入指导↔监督输出对应关系利于内化"）是作者的机理解释，虽有 Figure 7 的显式引用证据，但缺乏对"对应关系强度"的量化操纵实验；它与 context distillation 传统做法（学生端用简化输入）的张力需要后续工作厘清——一个可能的调和是：当监督输出**显式引用**输入指导时保留尤其重要，而这在静态推理任务中很少见。

**适用条件与可能失效场景**：其一，教师需有足够的指令跟随与自我修正能力——技能本质上靠 prompt 施加约束，若教师太弱，约束不生效（论文未测试更弱教师，这是边界外推）；其二，行为塑造的质量依赖 agent（GPT-6 Astra）的轨迹分析能力，换更弱的 agent 效果未知；其三，4B 模型在 Browse/Doc2Repo 上置信区间含零、且 Terminal-4B 的消融变体低于 Vanilla——小模型+弱信号场景下方法可能不稳定；其四，5 轮预算内最高分出现在 2-4 轮，更长的实验预算是否持续受益未知。

## 七、必要知识反推

假设一个没有背景知识的人要复现这项工作，最少必须掌握什么？

### 7.1 领域知识层

- **Agent 轨迹的解剖学**：知道一条轨迹由系统提示词、思考、动作、工具返回构成，且 SFT 损失只算 assistant 侧 token——不理解这个就无法意识到"系统提示词是可操纵的输入变量、行为是可塑造的输出"。
- **三类基准领域的任务语义**：终端任务的"误差阈值与精度声称"、检索任务的"线索锚定与验证"、SWE 任务的"自测与规范冲突"——不熟悉这些领域的行为陷阱，就写不出附录 B 那种精确到"不许换通过输入"的技能条款。
- **教师模型的行为特征**：知道 DeepSeek-V4-Pro 在未引导时常见的坏习惯（从轨迹分析获得），这是设计干预靶点的前提。

### 7.2 方法论知识层

- **蒸馏/拒绝采样的天花板原理**：明白 SFT 逐 token 复制混合行为分布、成功标签无法区分行为好坏——这是全文的问题意识来源。
- **prompt 工程与技能注入的机制差异**：理解技能是"条件化的行为规则"（什么情境下怎么做），不是泛泛的风格描述——写偏了要么无效要么干扰任务执行。
- **行为主义"塑造"（shaping）思想**：本文的方法名 Skill-FT 与行为学中"通过环境设计诱导目标行为"的思想同构，理解这一点才能把"抑制坏行为+激发稀缺好行为"组织成连贯方法。
- **自主实验循环的方法论**：对照-消融-配对 bootstrap 统计、每轮从同一检查点训练以隔离数据效应——这些实验设计知识决定结论可信度。

### 7.3 工程知识层

- **大规模 rollout 基础设施**：Docker 沙箱集群、教师 API 调用配置（温度 1.0、16384 token 预算、500 步上限）、SGLang 服务化——没有这些无法批量产生轨迹。
- **SFT 训练配置**：全参微调、131072 最大序列长度、Megatron Adam、cosine 退火——长轨迹训练本身是工程挑战。
- **MCP 与实验记录系统**：agent 通过工具接口操作全套流程，检查点-数据-技能-评测双向链接——自主实验不跑偏的保障。

### 7.4 知识融合的关键节点

真正的创造性洞察发生在三个融合点上：(1) **"成功≠示范合格"的批判** × **提示词可控性** → 用输入侧变量操纵输出侧行为的 Skill-FT；(2) **行为主义塑造** × **蒸馏数据生产** → 把"造数据"从挑选问题重构为生成分布控制问题；(3) **训练-评测一致性直觉** × **内部化假说** → 敢于保留评测时不存在的技能指令并系统验证。三个节点都不是知识的简单叠加，而是来自不同领域的概念发生了化学反应。

## 八、论文中可以提取的通用性灵感

**灵感一：结果标签是低维度信号，过程质量是高维度自由度。**
任何"只按最终结果筛选"的学习系统（拒绝采样、按成交筛选的销售培训、按疗效筛选的诊疗路径）都只约束了一个维度，过程中的坏习惯会原样传递。论文证据：79.3-91.2% 配对结果相同但行为迥异，仅换内容不换任务的对照差 1.08-10.11 点。
推广场景：代码评审（只看能否合并会奖励碰运气的修复）、医疗培训（只看诊断对错会奖励未验证的直觉）、自动驾驶数据生产（只看是否到达会奖励危险驾驶）、RAG 系统优化（只看答案对错会奖励检索捷径）、管理者以结果论考核下属。

**灵感二：同一执行者的表现可被"条件清单"系统性重塑——可教性独立于能力。**
"会不会"与"教不教得好"是两个正交维度，固定权重下教师的教学水平仍是大额可优化变量。论文证据：教师、数据量、配方全固定，仅行为塑造即 +1.42-8.99 点。
推广场景：专家知识萃取（给专家附上"讲解你为何排除 X"的清单再录示范）、机器人示教编程（给示教者附加安全要点清单）、客服话术生产、法律/医疗模板化专家经验、任何"强人带新人"的师徒制场景。

**灵感三：监督信号中的"显式对应关系"是学习效率的杠杆——保留输入指导与输出的配对。**
当输出明确引用了某条输入指导时，保留该指导（哪怕应用时不存在）比构造"干净但需自行反推规则"的样本更利于内化。论文证据：Keep 六设定全胜 Remove 2.15-4.01 点。
推广场景：教科书编写（保留解题时引用的定理陈述，而非只给答案步骤）、带注释的代码示例、运动教学视频保留教练的口头提示音轨、编程教学中的 pair programming 录像（保留导师语音）、企业 SOP 培训保留"为什么这么做"的背景说明。

**灵感四：两条改进路线（塑造生成分布 vs 筛选生成结果）应联合优化。**
单独塑造（数据随机选）或单独筛选（行为分布不变）都可能低于朴素基线（Terminal-4B 消融 17.60/20.22 < 22.47），联合才达 28.09。论文证据：消融六设定一致。
推广场景：内容平台运营（作者引导+编辑筛选）、数据标注质量（写清楚的标注指南+多轮质检，缺一不可）、人才招聘（岗位说明塑造候选人行为+面试筛选）、产品增长（改产品设计+用户分群运营）。

**灵感五：自主实验系统的价值在"证据链回溯"而非"更多尝试"。**
AutoMaster 的 agent 能把学生弱点回溯到"教师有没有示范过→进没进训练集"，用历史证据决定下一步，而非盲目试错。论文证据：五轮实验最高分在第 2-4 轮（超出首轮 2.16-4.87 点），BrowseComp-9B 第 4 轮才突破平台期。
推广场景：个人知识管理（实验笔记与结论双向链接）、自动化科研（A/B 测试平台的假设-证据追踪）、故障排查系统（告警与变更历史关联分析）、任何需要"从失败中定位原因"的迭代流程。

## 附录：方法与基线速查

| 名称 | 一句话定义 |
|------|-----------|
| Skill-FT | 用自然语言技能塑造教师 rollout 行为后做 SFT 的训练范式 |
| AutoMaster | LLM agent 自主设计/执行/迭代 Skill-FT 干预的后训练系统（双层循环） |
| Vanilla SFT | 从成功未引导教师轨迹随机抽 512 条做标准 SFT 的基线 |
| Base | 未做任何额外微调的目标模型本身 |
| w/o Skill Guidance | 消融：保留 agent 数据选择、去掉技能引导 |
| w/o Data Selection | 消融：保留技能引导（固定随机任务子集）、去掉 agent 轨迹选择 |
| Task-Matched SFT | 对照：任务 ID 与每任务样本数对齐 AutoMaster，仍用未引导轨迹 |
| Keep / Remove | 对照：训练输入保留 / 删除技能指令（评测时均无技能） |
| 内环 / 外环 | 内环=技能设计+数据选择（怎么教）；外环=训练+评测反馈（学得怎样） |
