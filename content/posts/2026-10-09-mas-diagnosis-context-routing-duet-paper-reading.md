# 结构即信号：拓扑条件诊断与证据路由计算

## 一、论文背景

### 1.1 多智能体系统的"疑难杂症"：症状相似，根因不同

过去两年，多智能体 LLM 系统（LLM-MAS）从论文原型走进了生产环境：AutoGen、MetaGPT、CrewAI、LangGraph 等框架让多个 agent 分工协作完成单模型难以胜任的任务。但系统越复杂，出错的方式就越花样繁多——而且一旦出错，排查极其困难。

多智能体系统的执行会留下 trace（每个 agent 的输入输出与消息往来记录）。诊断的困难在于一个核心现象：**相似的症状可能对应完全不同的根因**。论文一开篇举的例子是：同样表现为"最终答案引用了错误信息"，可能是因为上游 agent 在传递时丢了信息，可能是中间 agent 用了过期版本的数据，也可能是负责验证的 agent 没有核对。症状层的信息不足以区分根因，这是所有基于 trace 的诊断方法的共同瓶颈。

现有工作（MAST、Who&When、AgenTracer 等）主要靠两个思路：要么人工整理失败模式分类法再让 LLM judge 标注，要么训练监督模型从 trace 特征预测失败类别。前者依赖强模型（贵），后者依赖标注数据（且换了框架就失灵——这是后文的关键伏笔）。

论文一的切入点是一个被忽视的结构变量：**通信拓扑（communication topology）**——谁和谁说话、信息如何流动。直觉上，不同的连接方式天然孕育不同的失败方式：流水线式（Layered）系统容易在交接处丢信息，中心化（Centralized）系统容易验证失配，去中心化（Decentralized）系统容易互相等待，共享消息池（Shared Message Pool）系统容易语义漂移。如果"形状"真的与"病灶"相关，那么把形状告诉诊断模型，就应该能显著提升诊断精度——这正是标题"Know the Shape, Find the Fault"的含义。

### 1.2 RAG 的天花板：答案不在任何一条记录里

论文二瞄准的是另一个基础问题：**上下文构造（context construction）**。

LLM 处理长文档、表格、数据库等外部信息源时，主流方案是 RAG（检索增强生成）：把问题变成查询，检索相关内容，塞进上下文，让模型作答。近年的 agentic RAG（如 Self-RAG、IRCoT、Interact-RAG）让这一过程更灵活——模型可以改写查询、多轮检索、决定何时停止。

但所有这些方法共享一个隐含假设：**所需的证据已经存在于源数据中，只需要"找到"它**。论文二指出这在很多真实任务中不成立：问"哪三个月的营业利润率增幅最大"，答案不在任何一条记录里——你需要先检索收入和成本，再跨行计算比例，再比较排序。证据必须被**派生（derived）**出来，而不是被检索出来。

一边是只会检索的 RAG，另一边是 Direct Code（直接写一个程序处理全部数据）——后者面对异构源（dataframe + 报表 + 分层表格 + 维基段落）和多轮评估需求又力不从心。论文二的答案是：把检索和计算统一成一个可学习的序贯决策问题，让模型自己学会"何时检索、何时计算、何时停"。

### 1.3 为什么合读

两篇论文表面相距甚远（可观测性 vs 上下文工程），内核却是同一个洞察的两种应用：**上下文中的结构信息比原始信息量更值钱**。MAScope 证明把"系统长什么形状"这一结构先验注入提示，弱模型即可完成原本需要强模型的结构重建工作；RECAST 证明把"证据该以什么操作构造"这一结构决策交给学习的路由器，小模型即可掌握原本只有大模型才有的领域判断力。一者注入结构信号、一者学习结构决策，恰好是"给模型什么样的上下文"这一问题的两条互补路线。

## 二、论文定位和关联工作

### 2.1 论文一（MAScope）的研究谱系

**谱系一：多智能体失败分类与归因**。MAST（Cemri et al.）用专家分析整理出 14 类失败模式（MAST-14）并用 LLM judge 做可扩展标注，是本文失败分类的直接基础；Who&When 形式化了"哪个 agent 在哪一步出错"的归因任务；A2P 用反事实推理做归因；AgenTracer 训练 8B 模型做轨迹归因；LumiMAS 结合异常检测与根因分析。**关键区别**：这些方法全部只依赖 trace 文本，没有把通信拓扑作为显式的诊断输入。MAScope 的五条对照 baseline（MAST-Judge、Flat-GBM、Neural-Trace 等）均出自这一谱系。

**谱系二：通信拓扑的设计与优化**。Guo et al. 区分了四类典型通信结构（分层/中心化/去中心化/共享池），是本文拓扑标签的直接来源；GPTSwarm 在节点/边层面优化 agent 图，DyLAN 按 query 自适应选择参与者，AgentPrune 剪枝冗余通信链路以省 token，MaAS/AFlow 自动搜索架构与工作流。**关键区别**：这些工作把拓扑当**优化对象**（为了任务性能改拓扑），MAScope 把拓扑当**诊断条件**（利用拓扑与失败的统计关联做判别）——拓扑第一次从"被设计的变量"变成了"提供信号的观测量"。

**谱系三：软件工程中的结构化故障定位**。谱分析（spectrum-based fault localization）等经典 SE 技术也被用于 LLM-MAS 归因。MAScope 的"结构化上下文 + 规则校验"设计与之精神相通，但面对的是自然语言 trace 而非程序执行覆盖矩阵。

**定位结论**：MAScope 是第一个把通信拓扑显式条件化进 LLM-MAS 失败诊断的框架，其贡献与其说是判别器本身（TC-Judge 只是零样本提示工程），不如说是**打通了"异构 trace → 拓扑恢复 → 条件化诊断"的完整管线并实证了拓扑-失败关联**（χ²=409.9，p=1.2×10⁻⁷⁰）。

### 2.2 论文二（RECAST）的研究谱系

**谱系一：RAG 与自适应检索**。从原始 RAG（Lewis et al. 2020）到迭代/分层检索（IRCoT、RAPTOR），再到自适应决策（Self-RAG 的检索开关、Interact-RAG 的 planner-reasoner-executor 工作流）。**关键区别**：这些方法再自适应，证据构造仍以"选取/精化已有信息"为主；RECAST 把证据构造扩展到"关系计算与程序化转换"——证据是派生的。

**谱系二：工具增强与程序化推理**。表格专用模型与符号程序（TaPas、Binder 等）、通用工具调用框架（Toolformer、ToolLLM）、程序辅助生成（PAL、Program-of-Thoughts）、工具合成（CPT 等）。**关键区别**：这些方法要么直接生成"产出答案"的程序，要么依赖为特定源类型设计的操作；RECAST 学的是"构造任务相关证据"的迭代选择-任务化-评估循环，且明确分离路由（学）与编译/作答（冻结）。

**谱系三：RL 训练路由/策略**。Interact-RAG 等用大模型做零样本路由；ToolRL 等工作探索工具选择的 RL 优化。RECAST 的差异化在于奖励设计（正确性 + 部分 token-F1 + 结构合规的三项加权）与 mixed-outcome 组过滤策略，并用消融逐项验证了这些设计。

**定位结论**：RECAST 的定位是"检索与计算的统一可学习路由层"——不改检索器、不改编译器、不改作答模型，只训练一个 9B 路由器，就在异构任务族上超过大模型路由的 agentic RAG 系统。

### 2.3 两篇论文的定位对照

| 维度 | MAScope（论文一） | RECAST（论文二） |
|---|---|---|
| 问题域 | LLM-MAS 可观测性/失败诊断 | 异构源上下文构造 |
| 核心抽象 | 拓扑作为诊断的条件变量 | 证据构造作为异构操作上的序贯决策 |
| 获取结构信号的方式 | 规则+LLM 抽取（TSE，一次提取复用） | SFT+GRPO 训练（RouterLM） |
| 下游使用结构的方式 | 注入零样本提示（TC-Judge，不训练） | 策略自身即结构（路由决策） |

| 机构背景 | 北航，纯高校 | MIT+Google，一作为 Google 实习生 |
| 成本主张 | 成本降至强模型 6% | 9B 模型超大模型基线 15.9pp |

## 三、问题定义

### 3.1 论文一：把"失败诊断"抽象为"结构条件下的证据判别"

**具体问题**：给定一段多智能体系统的执行 trace，判断它发生了 MAST-14 中的哪些失败模式（14 位二进制向量）。

**核心洞察**：失败模式与通信拓扑不是独立的——不同拓扑有不同的失败倾向分布（实证：χ²=409.9）。因此同一段 trace，在"已知系统是流水线"与"已知系统是共享池"两个条件下，最可能的失败解释不同。诊断的困难部分来自医生不知道系统的形状；把形状作为先验条件注入，等价于把"从 trace 反推结构"这一最难的认知步骤外包给了显式的提取器。

**形式化**：设 trace 为 t，其通信拓扑为 τ(t) ∈ {Layered, Centralized, Decentralized, SharedMessagePool}，失败向量为 y ∈ {0,1}^14。诊断即估计 P(y|t)——但 MAScope 将其条件化为 P(y|t, τ, π_τ, s_τ)，其中 π_τ(c)=N_{τ,c}/N_τ 是从 400 条独立标注 trace 估计后冻结的先验（每类拓扑下各失败模式的频率），s_τ 是拓扑特有失败模式的文字描述。三个额外条件全部来自结构，不依赖测试时的人工输入。

**精妙之处**：这个抽象把"结构重建"与"证据判别"解耦成两个子问题，各自用最合适的工具解决——结构重建用规则+LLM 抽取（一次性、可复用、可校验），证据判别用零样本提示（无需训练、无框架过拟合风险）。它把一个看似需要端到端学习的难题，拆成了两个各自已有成熟解法的子问题。

### 3.2 论文二：把"上下文构造"抽象为"异构操作上的序贯决策"

**具体问题**：给定自然语言任务 q 与异构源集合 X（表格、报表、段落、画像），构造使答案正确的上下文证据 E。

**核心洞察**：许多任务的证据不在任何单条源记录中，必须经"过滤、聚合、计算"派生。这提示把证据构造从"检索空间的选择问题"升级为"操作空间上的决策问题"——类似把监督学习中的"特征工程"替换为"特征学习"：与其在每个任务上手挑检索策略，不如学一个策略自动选择与组合操作。

**形式化**：E = G_θ(q, X)，y = F_ans(q, E)。RECAST 把 G_θ 实现为马尔可夫决策过程：每轮状态为已积累证据+执行反馈，动作为三元选择 {CALL_PRIMITIVE, SYNTHESIZE, ACCEPT_CONTEXT}，其中 CALL_PRIMITIVE 在 {Lexical(BM25), Semantic(BGE-M3), Relational(只读SQL)} 中选择并任务化（formulate）参数，SYNTHESIZE 由冻结 CompilerLM 翻译为可执行 Python。策略只训练 G_θ（RouterLM），F_ans 与编译器均冻结。

**类比对应关系**：

| 决策/RL 概念 | RECAST 对应物 |
|---|---|
| 状态 s_t | 已接受证据 + 各操作执行反馈（状态/命中数/错误） |
| 动作空间 | 3 类原语调用 / 程序合成 / 接受终止 |
| 策略 π_θ | RouterLM（Qwen3.5-9B + LoRA） |
| 奖励 | λC·正确性(0.90) + λF·token-F1(0.08) + λV·结构合规(0.02) |
| 冻结环境 | CompilerLM 与 AnswerLM 均不更新 |

**精妙之处**：任务化（formulate）动作的参数是自然语言描述的"证据目标"，而非直接的操作调用——这使路由器学到的是**领域特定的证据构造意图**（何时需要算、算什么），而非绑定特定工具的调用模板。这正是 held-out 基准与换编译器实验中迁移性的来源。

## 四、问题解法

### 4.1 论文一：MAScope 的两阶段管线

**阶段一 TSE（Trace Structural Extractor）：从异构 trace 恢复拓扑**。

| 步骤 | 输入 | 输出 | 机制 |
|---|---|---|---|
| 1. 压缩 | 原始 trace（异构框架格式） | ≈4k token 匿名化视图 | 打分保留重要 span，匿名化为稳定证据 ID（P01、E1 等） |
| 2. 抽取 | 压缩视图 | ≤24 条关系 | LLM 抽取五类关系（control/use/feedback/pool_read/independent），每条须引用证据 ID |
| 3. 校验 | 关系集 | 修复后关系集 | 规则校验 + 最多 1 次修复；正则恢复隐式共享池读取 |
| 4. 分派 | 关系集 | 拓扑标签 | 分类器 + 正例门控输出 Guo 四类拓扑之一 |

类比：这像给病历做"影像学检查"——不管病人（框架）口述症状的格式如何，先标准化成同一套解剖结构图（交互图），再从结构图读出体型（拓扑标签）。证据 ID 引用机制保证每条关系可回溯到原文，规则校验兜住 LLM 抽取的幻觉，"≤1 次修复"控制成本。

**阶段二 TC-Judge（Topology-Conditioned Judge）：条件化诊断**。将四样东西注入零样本提示：(1) 压缩 trace；(2) TSE 预测的拓扑标签；(3) 先验 π_τ（由 400 条独立 trace 的探索切片一次性估计后冻结，测试集无泄漏）；(4) 拓扑特有失败签名（文字描述，如 Layered 系统的逐跳交接风险）。低成本模型（gpt-mini 级）单次 JSON 调用输出 14 位失败向量。

**成本摊销设计**：固定编排（orchestration）下，拓扑不随执行实例变化——TSE 一次提取、跨执行复用。1,000 条 trace 共享一次拓扑提取，边际成本只剩 judge 调用。这是"6% 成本"数字的来源，也是工程上最重要的一条性质。

### 4.2 论文二：RECAST 的路由-编译-作答三件套

**组件一：RouterLM（唯一被训练的组件）**。Qwen3.5-9B + LoRA，thinking 模式关闭。每轮观察当前证据与反馈，从动作空间选择并任务化。训练分两阶段：

- **SFT（3,368 条专家轨迹）**：对每个至少有一条"正确、可执行、结构合规"轨迹的问题，选一条最优轨迹（偏好更准确高效的），对欠表示的基准族与难度做上限过采样。作用：建立有效的操作选择与任务化模式。
- **GRPO（608 实例）**：奖励 R = 0.90·C + 0.08·F + 0.02·V（C 为冻结裁判判定的答案正确性，F 为 token 级 F1，V 为结构合规）；采用 mixed-outcome 组过滤——只保留既有成功又有失败轨迹的组，使组内相对比较提供更强的学习信号，同时天然提升样本效率。

**组件二：CompilerLM（冻结）**。默认 Gemini 3.5 Flash。收到 SYNTHESIZE 的自然语言操作说明，一次调用翻译为可执行 Python（对 dataframe/表格做过滤、聚合、连接、算术）。

**组件三：AnswerLM（冻结）**。同为 Gemini 3.5 Flash，所有方法共享同一裁判与同一评分提示，保证对比公平。

**运行时协议**：温度 0；多轮方法上限 6 轮；保留证据上限 4,000 字符；域内实验重复 3 次取均值。证据+执行反馈（命中数、错误信息、状态）驱动多轮精化，RouterLM 判断充分后交 AnswerLM 作答。

**类比**：RECAST 像一位"实验室主管"（RouterLM）指挥两名助手——一位资料员（原语检索，翻卡片查档案）、一位程序员（CompilerLM，按需写脚本算数）。主管不必自己会写代码，只需判断"这个问题该查还是该算、查什么、算什么、够不够"。SFT 教会主管基本流程，GRPO 用最终答案的对错打磨主管的判断力。

## 五、评估指标与实验证据

### 5.1 论文一：MAScope-Bench 与三层验证

**基准**：自建 MAScope-Bench（2,220 条 trace = MAST-clean 851 + Inject-Mix 961 + LG-Ctrl 408）。三子集各司其职：MAST-clean 继承 MAST 原始 14 类标注（另独立重标 200 条分层子集核对），Inject-Mix 用受控故障注入覆盖新框架与拓扑组合，LG-Ctrl 固定框架身份只变拓扑（隔离"框架指纹"与"拓扑"两个变量）。

**主指标：Macro-F1（MAST-14 多标签）**。14 类失败模式长尾分布，宏平均给尾部模式权重，防止判别器只押注高频类。取值越高越好，衡量的是"对全部失败类型的均衡判别力"而非表面准确率。

**核心结果**（MAST-clean）：

| 配置 | gpt-mini | gpt-5.4 |
|---|---|---|
| M0（同 trace/提示/模型，无拓扑） | 0.173 | 0.372 |
| M4（真实拓扑条件化） | **0.350（+102%）** | 0.399（+7.3%） |
| 完整管线（TSE 预测拓扑） | 0.346 | — |

三个关键读数：(1) 弱模型获益翻倍、强模型获益温和——说明拓扑条件主要补的是弱模型缺失的结构推理能力，强模型已能从 trace 隐式推断；(2) 预测拓扑 0.346 与真实拓扑 0.350 仅差 0.004（oracle gap 可忽略），管线无泄漏；(3) 0.346 达到 trace-only gpt-5.4（0.372）的 94%——弱模型+结构先验≈强模型。

**跨框架 LOFO 与对照组**：以 ChatDev/Magentic/MetaGPT 三族做 leave-one-framework-out，监督式 Flat-GBM 从 0.490 跌到 0.226（仅保留 46%）、Neural-Trace 从 0.296 跌到 0.127（保留 43%），而零样本 TC-Judge 保留 82%（0.350→0.286）。Inject-Mix 上拓扑条件同样有效（gpt-mini 0.304→0.321；gpt-5.4 0.320→0.356）。

**成本**：851 条 trace 判定，gpt-5.4 裸跑 $8.73 vs gpt-mini+拓扑 $0.52（6%）；1,000 条共享一次 TSE（$0.0099 setup），$0.63 vs $10.26（16.4 倍）。

**实验设计为何能证明论点**：M0 是严格配对对照（同 trace、同模型、同提示模板，仅差拓扑三要素），排除了"换了更强提示词"的混淆；LG-Ctrl 固定框架只变拓扑，隔离了框架指纹；TSE 恢复率（MAST-clean 93.8%、LG-Ctrl 76.5%）单独汇报，说明管线瓶颈不在结构恢复。

### 5.2 论文二：六基准 + 三 held-out 的双层验证

**基准**：域内六个异构族（DataBench、FinQA、HiTab、HotpotQA、LaMP、MultiHiertt，各 100 题），覆盖 dataframe、财务报表、分层表、维基段落、用户画像五类源表示；held-out 三个（2WikiMultiHopQA、TAT-QA、WikiTableQuestions）测零样本迁移。

**主指标：任务成功率**（冻结 Gemini 3.5 Flash 裁判、统一提示、温度 0），越高越好。3 次重复取均值控制随机性。

**Baseline 设置**：五条对照覆盖谱系两端——No Context（无检索直答）、Fixed Retrieval（单次 BGE-M3 稠密检索取 top-3）、Direct Code（单程序直出答案）、IRCoT（推理-检索交替，同 Qwen3.5-9B 口径）、Interact-RAG(Gemini)（planner-reasoner-executor 工作流，最强基线）。所有方法共享同一 AnswerLM 与裁判，比较的纯粹是"上下文构造策略"这一个变量。

**核心结果**：

| 对比 | 数字 |
|---|---|
| 域内六基准平均 | RECAST **75.6%** vs Interact-RAG 59.7%（+15.9pp） |
| held-out 三基准平均 | **79.3%** vs 最强基线 64.3%（+15.0pp；2Wiki 83.0 / TAT-QA 81.0 / WTQ 74.0） |
| 同 Qwen 口径 | IRCoT 57.0% → 训练-free RECAST 64.1%（+7.1pp） |
| 训练的价值 | 训练后 9B 路由器 75.6% vs 训练-free Gemini 路由器 70.6%（+5.0pp） |

**实验设计为何能证明论点**：held-out 基准证明的是"路由策略学到的是可迁移的判断力而非基准特异技巧"——三个新基准横跨多跳文本 QA、文本+表格混合数值推理、半结构化表格 QA，全部正迁移；换 CompilerLM 实验（Flash Lite 73.2%、Qwen3.5-9B 67.2%）证明策略不绑定特定编译器——路由学到的是"要算什么"（意图层），而非"怎么写代码"（实现层）。

## 六、效果优势的根源解释

### 6.1 论文一：为什么 4k token 的结构先验能顶替强模型

**因果链一：结构条件化替代结构重建**。

1. baseline（M0/gpt-mini）必须先从原始 trace 隐式反推"谁在和谁协作、信息怎么流"，再对失败证据做判别——两步挤在一次前向里，弱模型的容量顾此失彼【论文实验支持：M0 0.173，几乎不可用】；
2. TC-Judge 把结构重建外包给 TSE（规则+LLM 抽取，93.8% 准确率），judge 只需按给定拓扑对证据做**定向核查**——Layered 查逐跳交接、Centralized 查 hub 聚合与验证、Shared Pool 查语义漂移【机制解释，论文设计明示】；
3. 定向核查把无限证据空间收窄为拓扑相关的少数检查项，等价于给判别器一个高信噪比的特征子空间【机制推理】；
4. 因此弱模型 Macro-F1 翻倍（0.173→0.350），且强模型获益小（+7.3%）——结构重建恰是弱模型与强模型差距的主要构成【论文实验支持：两模型增益差异 102% vs 7.3%】。

**因果链二：零样本先验规避框架捷径**。

1. 监督式 baseline 在固定框架分布上训练，学到的是"框架指纹→失败类别"的映射（如 ChatDev 的输出格式特征），而非"结构→失败"的规律【论文证据：Flat-GBM 的混淆矩阵显示 held-out 框架上的预测集中在训练折叠的高频失败模式】；
2. LOFO 换框架时该映射失效——Flat-GBM 保留 46%、Neural-Trace 保留 43%【论文实验支持】；
3. TC-Judge 的条件（拓扑标签+先验+签名）是跨框架不变量：同一拓扑标签在不同框架下共享失败倾向【论文实验支持：保留 82%，且 Inject-Mix 新框架组合上同样有效】；
4. 结论：拓扑条件化不仅提升精度，还把"框架特异性捷径"替换为"结构不变性规律"，这是泛化的根源【论文实验支持】。

**反事实验证**：去掉真实拓扑用预测拓扑，F1 仅降 0.004——说明瓶颈不在结构恢复精度；去掉拓扑三要素（M0），F1 腰斩——说明增益确实来自结构条件而非提示工程的其他细节（模板与模型均未变）。

### 6.2 论文二：为什么学出来的路由胜过大模型路由

**因果链：操作空间扩展 × 下游奖励对齐**。

1. Interact-RAG 等自适应检索系统的动作空间限于"检索什么、何时停"——面对需要计算的任务（如 FinQA 的跨行财务计算），它只能检索出原料然后指望 AnswerLM 自己算，证据层不提供派生信息【机制分析】；
2. RECAST 扩展动作空间至 {原语检索, 程序合成}，且 SYNTHESIZE 的参数是自然语言"证据目标"而非代码——路由器学的是"这个任务需要什么样的证据"（意图），实现细节留给冻结编译器【论文设计】；
3. GRPO 用最终答案对错（而非中间检索指标）优化路由策略，使"何时检索、何时算、何时停"的领域判断被显式蒸馏进 9B 模型【论文设计：奖励 λC=0.90 主导】；
4. 因此 9B 路由器超过 Gemini 路由器 5.0pp——大模型的通用推理替代不了针对任务分布训练出的领域策略【论文实验支持】。

**消融建立的三个互补性证据**（每个数字都经过原文核对）：

| 消融 | 数字 | 证明的机制 |
|---|---|---|
| primitive-only / synthesis-only / 双通道 | 56.8% / 59.9% / 64.1%（训练-free） | 两类操作各自不占优、不同任务族依赖不同操作——**双通道互补**是架构必要性的直接证据 |
| SFT-only / GRPO-only / 两阶段 | 67.3% / 72.6% / 75.6% | SFT 建立有效模式（+3.2pp），GRPO 用下游信号优化（+8.5pp），组合超任一——**模仿与强化互补** |
| 只留正确性奖励 / 去 mixed-outcome 过滤 | 68.9%（−6.7）/ 73.0%（−2.6） | 部分 token-F1 与结构合规提供轨迹间区分度；混合结局组提供更强相对信号且样本效率更高 |

**反事实验证**：训练-free RECAST 已达 64.1%（超同口径 IRCoT 7.1pp）——说明操作空间扩展本身有价值；训练再拉到 75.6%——说明学习锁定增量。两个增益来源可分离、可叠加。

### 6.3 外部相关工作检索与对照

围绕两条根源解释，检索外部关联证据（基于论文 Related Work 与已核验的文献信息）：

| 研究 | 与本文的相似尝试 | 相关结论 | 差异与适用边界 | 对根源解释的影响 |
|---|---|---|---|---|
| [MAST / Cemri et al.](https://arxiv.org/abs/2503.07514)（多智能体失败分类法） | 同用 LLM judge 标注 MAST-14 | 证明 LLM judge 可扩展标注失败，但未用结构条件 | 无拓扑输入；MAScope 直接复用其分类学与标注 | 支持"判别器可行"，凸显"结构条件"是 MAScope 的增量 |
| [Who&When / A2P / AgenTracer](https://arxiv.org/abs/2411.18159)（失败归因） | 从 trace 定位责任 agent/步骤 | AgenTracer 靠反事实重放+故障注入获得监督信号 | 任务是"归因"（谁错）而非"分类"（错哪类）；AgenTracer 训练 8B 模型，跨框架迁移未如 MAScope 验证 | 补充：同域不同任务设定，其监督数据构造思路与 TSE 的证据引用机制互补 |
| [Guo et al. 2024 拓扑分类](https://arxiv.org/abs/2407.09564)（四类通信结构） | 定义 Layered/Centralized/Decentralized/SharedPool | 实证拓扑影响任务性能 | 只关心性能、不关心失败诊断 | 支持"拓扑是有效结构变量"的前提，MAScope 将其从性能预测反转为失败预测 |
| [GPTSwarm / AgentPrune / AFlow 等](https://arxiv.org/abs/2402.16823)（拓扑优化） | 把拓扑当优化对象 | 优化拓扑可提升性能/降成本 | 优化需要已知拓扑；MAScope 反向解决"从 trace 恢复拓扑" | 互补关系：优化工作反衬"拓扑恢复"本身是未被解决的子问题 |
| [Self-RAG / IRCoT / Interact-RAG](https://arxiv.org/abs/2310.11511)（自适应检索） | 学习/规划检索动作 | 自适应优于固定检索 | 动作空间限于检索；RECAST 加计算通道 | 支持"自适应决策有效"，同时是其超越对象（+15.9pp 的直接对照组） |
| [PAL / Program-of-Thoughts 等程序化推理](https://arxiv.org/abs/2211.10435) | 用程序做数值推理 | 程序提升计算准确性 | 单程序直出答案，不迭代、不混合检索 | 支持"计算派生证据"路线有效；RECAST 证明纯计算不如混合（59.9% vs 75.6%） |
| [ToolRL 等工具选择 RL](https://arxiv.org/abs/2504.13958) | RL 优化工具/动作选择 | 下游奖励优于模仿学习 | 工具集为预定义 API；RECAST 含程序合成通道且验证 formulate 层迁移 | 支持"GRPO 优化路由"机制的普适性 |

**综合判断与未决问题**：

- **多研究共同支持的机制**：(1) 结构/拓扑是多智能体系统的有效结构变量（Guo 的性能研究 + MAScope 的失败研究从两端收敛）；(2) 自适应决策优于固定策略（Self-RAG 到 Interact-RAG 的谱系 + RECAST）；(3) 下游奖励训练的策略迁移性优于监督式特征映射（ToolRL + MAScope 的 LOFO 对比从不同任务设定得出同向结论）。
- **仍属推测的机制**：拓扑先验注入对更强模型（gpt-5.4 以上）的增益可能持续衰减（论文只测到 +7.3%）；RECAST 的 formulate 意图层迁移性（换编译器只测了两个替代品）在更弱编译器下是否保持，尚无充分证据。
- **适用条件**：MAScope 的成本优势依赖"固定编排下拓扑可复用"——编排频繁变更的场景，TSE 提取成本需重新摊销；RECAST 的六轮/4,000 字符上限适合中等复杂度证据构造，超长程任务（需数十轮派生）未验证。
- **可能的失效条件**：动态拓扑（运行中重组的 agent 图）会使冻结先验 π_τ 失配；RECAST 面对纯知识记忆型任务（证据确实只靠检索）时双通道可能退化为单通道，与强检索基线的差距应缩小（推测，论文未单独报告此类任务的分解）。

## 七、必要知识反推

若让一个没有背景的人复现这两篇论文，最少必须掌握什么？

### 7.1 领域知识层

- **多智能体系统与通信拓扑**（两篇共同的地基）：必须理解 agent 间信息交换的组织方式（谁发消息给谁、经不经过中介、有无共享存储），否则无法理解"拓扑→失败倾向"的关联从何而来。Guo et al. 的四分类是必备起点。
- **MAST-14 失败分类学**：不掌握这 14 类失败模式的定义，连标注目标都无从谈起。
- **RAG 的问题设定与局限**：必须知道 RAG 的"检索-生成"基本循环，才能识别"证据必须派生"这一动机为何指向计算通道。
- **异构数据源的表示**：dataframe、分层表格、财务报表、文本段落的差异决定了原语设计（为什么需要 SQL 型 Relational 操作）。

### 7.2 方法论知识层

- **提示工程与零样本判别**：TC-Judge 的实现本体是零样本提示——先验注入、证据引用、JSON 结构化输出的设计经验直接决定判别质量。
- **信息抽取的可校验性设计**：TSE 的"证据 ID 引用 + 规则校验 + 有限修复"三件套是控制 LLM 抽取幻觉的标准手法，需要从 NLP 信息抽取文献中继承。
- **统计假设检验**：χ² 独立性检验与 p 值解释——"拓扑与失败相关"这一全文前提的合法性依赖于此。
- **SFT+GRPO 两阶段训练**：LoRA 微调、组相对策略优化、奖励塑形（三项加权）、组过滤策略——RECAST 的训练栈是当前后训练的标准配置，缺一不可。
- **实验设计方法论**：配对对照（M0）、leave-one-domain-out（LOFO）、held-out 泛化、故障注入——知道"如何证明增益来自声称的机制"比实现方法本身更关键。

### 7.3 工程知识层

- **trace 解析与匿名化**：各框架 trace 格式差异巨大，压缩至 4k token 且保持证据 ID 稳定是工程密集型工作。
- **成本核算**：token 级计费模型、摊销分析（一次提取 × N 次复用）——"6%"这一卖点需要正确的会计口径。
- **冻结组件的评估隔离**：共享 AnswerLM 与裁判、温度 0、统一评分提示——保证对比公平性的协议设计。

### 7.4 知识融合的关键节点

两篇论文各自的关键融合节点惊人地相似：**把"结构"从领域知识转化为可计算的输入**。MAScope 融合了"拓扑影响失败"的领域直觉 + "零样本判别器可行"的方法认知 + "固定编排下拓扑不变"的工程观察，三者在"拓扑条件化"这一设计上会合——任何一个知识点单独存在都推不出这个设计。RECAST 融合了"证据需派生"的任务认知 + "序贯决策可学习"的方法认知 + "意图层（formulate）与实现层（编译）分离"的架构判断，三者在"路由器学意图不学实现"上会合——这也是其迁移性的根源。

## 八、论文中可以提取的通用性灵感

**灵感一：结构先验是最便宜的能力放大器**。

核心思想：当一个弱能力者（小模型/新人）面对复杂任务时，把任务的隐式结构显式化并作为条件提供，可以替代大部分能力差距。

论文证据：MAScope 中 4k token 的拓扑三要素让 gpt-mini 的 F1 翻倍、达到 gpt-5.4 的 94%，成本降至 6%。

推广场景：(1) 代码评审——给初级评审者"变更影响的调用图谱"作为条件，而非让其从 diff 反推；(2) 医疗分诊——按"就诊路径拓扑"（首诊-检查-会诊的不同组合）条件化分诊规则；(3) 客服路由——把工单在组织内的流转结构显式注入路由模型；(4) 教育辅导——按解题步骤的结构类型（线性/分叉/循环）给学习者不同提示。

**灵感二：监督学习学到捷径，零样本+结构不变量学到规律**。

核心思想：在单一分布上拟合的监督模型容易学到分布特异的特征（框架指纹），而非任务的本质规律；用跨分布不变的量做条件，可以把"捷径"逼成"规律"。

论文证据：LOFO 下监督式 baseline 只保留 43-46%，零样本拓扑条件保留 82%；Flat-GBM 的混淆矩阵显示其预测集中于训练折叠的高频失败类。

推广场景：(1) 风控——反欺诈模型按"交易网络结构"而非商户 ID 特征条件化，防换平台失效；(2) 医学影像——按成像协议结构而非医院指纹条件化，提升跨医院泛化；(3) 教育——按题型结构而非题库指纹训练诊断模型；(4) 工业质检——按产线拓扑而非工位指纹归因缺陷。

**灵感三：把"选择做什么"与"怎么实现"分层，是迁移性的来源**。

核心思想：策略层只学意图（要什么），实现层交给冻结的执行者（怎么做），意图比实现更可迁移。

论文证据：RECAST 的 RouterLM 只输出自然语言"证据目标"，编译留给 Gemini Flash；换 Flash Lite 或 Qwen3.5-9B 编译器，性能只降 2.4pp/8.4pp；held-out 基准零样本 +15.0pp。

推广场景：(1) 机器人——规划层输出子目标，底层控制器跨硬件复用；(2) 管理——主管定"验收标准"而非实现步骤，团队成员可替换；(3) API 编排——意图层路由 + 执行层适配器，后端供应商可切换；(4) 科研指导——导师提"什么证据能支持假设"，实验手段由学生自选。

**灵感四：互补通道 + 下游奖励 = 小模型学到领域判断力**。

核心思想：让小模型掌握专家判断力的公式是"给它互补的工具箱 + 用最终结果的好坏打磨选择策略"，而非单纯扩大模型。

论文证据：检索/计算双通道互补（单通道 56.8%/59.9%，双通道 64.1%）；SFT+GRPO 组合 75.6% 超任一单独阶段（67.3%/72.6%）；9B 路由器超训练-free Gemini 路由器 5.0pp。

推广场景：(1) 个人助理——"查资料/跑计算"双通道 + 用户反馈强化，蒸馏用户工作习惯；(2) 投研——检索公告与计算财务比率的混合路由，用回测结果优化；(3) 编程助手——读代码/跑测试双通道，用 CI 通过率优化路由；(4) 临床决策支持——查指南与算风险评分互补，用预后对齐。

**灵感五：固定开销的摊销设计决定部署可行性**。

核心思想：当系统存在"运行间不变的结构"（编排、配置、领域知识），把不变部分的一次性提取成本摊销到大量执行上，可以把昂贵流程变成廉价流程。

论文证据：TSE 拓扑提取一次 $0.0099，1,000 条 trace 复用后总成本 $0.63 vs 强模型逐条 $10.26（16.4 倍）。

推广场景：(1) 数据管道——schema 演化图一次构建、查询编译复用；(2) 法务——合同模板结构一次抽取、批量审查复用；(3) DevOps——架构依赖图定期重建、故障诊断按图索骥；(4) 内容平台——知识图谱一次构建、个性化检索多次路由。

**两篇论文的共同元灵感**：上下文工程正在从"找到什么内容"进化为"提供什么结构"——无论是诊断（把系统形状告诉模型）还是构造（让模型决定操作形状），竞争的焦点都在结构信息的生产与利用上。这可能是后 scaling 时代最稳定的增益来源之一。
