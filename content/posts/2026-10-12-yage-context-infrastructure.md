## 先说结论

这期公路播客（乌镇开往上海，理想 i8 大部分路段自动驾驶）录于 Jev 发布七十二小时后，但真正的主角不是任何一个新品，而是鸭哥两年来一以贯之的方法论——**Context Infrastructure（上下文基础设施）**。他的核心判断可以压成三句话：第一，Jev 的大火是「基模成熟 × Agentic 成本敏感 × System One 叙事包装」的乘积，技术上并无太多新成分，但火本身值得学习；第二，今年真实的产品主线是「给 AI 一台永不关机的云端电脑」，Manus、Grok Bot、Muse 先后跟进，持久化正在取代「码农式」的 PR 和 Repo 成为 AI 记忆的载体；第三，个人使用 AI 的方法两年没有本质变化——像管理人一样管理 AI，而「强得可怕」的感觉，来自你给它积累的 context 有多厚。外部核验中两处与播客叙述存在出入（开源复现与 Jev 的实际差距、App Store 下滑的真实归因），文中已并陈。

## Jev 为什么火：技术、需求与包装的三重合力

鸭哥给 Jev 的定性很直接：它不是语言模型，不能输出自由文本，只做分类——给几个选项，返回最可能的选择和经校准的概率，而且置信度与概率是分开的两个东西。第一眼看是「GPT 加 Reason Mode」，调研后确认技术上确实接近。类似的 classification API 过去十年至少有四五波公司做过（他点名 Google、OpenAI、Mistral 都发过），全部被弃用。为什么这次火了？他给出三个原因：**基模能力到位**——他引用 Artificial Intelligence Index 称 GPT-4o 约八分，而上一代的通义千问 3.5（4B 参数）已有二十多分，微型模型碾压当年可直接商用的 GPT-4o；**需求起来了**——Agentic 应用让 token 消费急剧增加，大家对成本和延迟更敏感，需要低成本完成高频分类；**包装高明**——「System One Classifier」对上诺贝尔经济学奖得主的系统一/系统二理论，加上创始人确为 InstructGPT 等开创性文章的共同作者，「你得去看看他说的是什么」。他甚至以「比较恶意的揣测」补了一刀：所谓隐身两年，可能主要是等基模成熟——他找过专利、论文、白皮书、代码，什么都没找到。这个揣测与 Jev 创始人 Diogo Almeida 在 TWIML 访谈中的自述（项目实际做了四个月，承认「RLCD 一年做不完」）各有各的说法，姑且并陈。

两个他觉得最有意思的应用都指向同一件事：**高频小决策的成本革命**。一是 Browser/Computer Use——以前让 LLM 看截图理解界面再操作，改成给 DOM tree 问「下一步点哪」，配合级联分类，体感提速十倍且省钱；但他也主动浇冷水：这个方案同时改了输入模态（图像→文本）和输出形式（生成→分类），哪个因素最关键没有做 ablation 之前不知道。二是 Harness Classifier——Codex、Claude Code 这类工具每次 AI 调用工具时都在跑一个「危险与否」的私有分类，这本来就是 quasi-general classifier，以前只有大厂 harness 做得起，现在可以低成本移植到开源实现里。独立评测（arXiv 2609.37647，37 个数据集、34.6 万次请求总花费不到 10 美元）证实了 Jev 的校准确实扎实：选择概率校准良好、支持选择性预测，37 个数据集中 27 个胜过 Qwen3.8-27B。至于播客中「开源只读复现 85% 对 Jev 88%、三个点工程上难体现」的说法，与外部证据有出入：jev-on-a-laptop 复现项目自己的结论是本地免费 Qwen2.5-7B 在 Jev 官方公开题集上落后约 13 个点（73.8% 对 86.6%）——本地方案的优势是成本、隐私与离线，不是准确率持平。两处口径不同，读者自行取信。

价格侧他补了一个导游项目的实例：全中国几十个旅游城市做成的导游 Agent，一天烧掉约四百亿 token（嘉宾自述，未核验），用 Sonnet 算过约 1.2 万美元，换 DeepSeek V4.1 Flash 只花了 300 美元——「以前不敢想的场景突然就现实了」。

## 给 AI 一台电脑：从「码农的记忆」到「生活的记忆」

第二条主线是云端持久电脑。他的梳理：Cursor 很早的 Cloud Agent 就在云端跑，但一切从头开始、无持久化；2026 年 4 月 Manus 先出 Cloud Computer（VM 不销毁、凭据和记忆都留着），8 月 xAI 的 Grok Bot 跟进（自家此前文章记录其 8 月 20-22 日全面开放，每账户一台持久化远程电脑），9 月 Meta 的 Muse 跟上（9 月 8 日上线，三周 340 万下载）。为什么这个思路对？他的解释是「老思路太码农了」——用 GitHub PR 和 Repo 保证记忆连续，脱离代码场景就失效；而一台不关机的电脑记得住你上次的身份信息、大众点评登录过一次就行，真正能完成「跟代码没有关系的生活化的东西」。这与他看到的生活痛点有关：路上常见端着 MacBook 不敢关机的人——「一看就是 Claude Code 和 Codex 用户」。

能力侧让他「impressive 到不行」的是基模的 3D 进展。他用 GPT-6（播客口误作 Ultra；其本人博客确证为 GPT-6 Astra）几句话做出了可达鸭的三维形象、绑骨、动捕联动——摄像头拍他，可达鸭跟着动，一个 VTuber 原型就完成了。他的博客（yage.ai）记录了完整实验：博丽神社建模、爆炸视图、浏览器第一人称漫游、瓷器烧制科普视频，整个流程连同经验教训做成了开源 Skill。他的判断是「基模能力干倒一个工业」——VTuber 皮套原本需要美工、绑骨、动捕的完整分工链条，现在交付成本降了一两个数量级（当然人物精修仍有差距）。

但方法论层面他坚持：**个人使用 AI 的方法没有本质变化，只是水位在涨**。两年前十字路口有期节目叫「大模型还是小学生，不要着急让他去打工」，他的版本是「以前带大专生，现在带本科生——你仍然要管理他：清晰交代任务、验收结果」。这个「像人一样」不是修辞，他给出的对照是：AI 会犯错需要检查、需要明确成功标准——这些跟管理真人完全一样；不一样的是不需要画饼（它天生 helpful）、不用顾忌自尊心，但需要你把要求、context 全部**外化**成文件和 prompt——「人讲究内化，AI 讲究外化」。

## 强得可怕的三段故事：context 才是个人杠杆

标题那句话的注脚是三段亲身经历。**第一段：带娃就医**。幼儿园老师牵着娃时娃挣扎，造成「牵拉肘」（nursemaid's elbow，关节移位）。家长毫无经验，AI 判断症状吻合、建议不必去急诊但该去 urgent care、推荐了西雅图儿童医院并说明「不会自愈，别白扛疼」；到了医院医生一个复位动作解决。他不期待 AI 代替医生，但 AI 在整个决策链里补足了信息、又把「哪家有位置、哪家评价好」这些体力活干完——当时娃在哭、大人要喂饭，完全没精力。**第二段：保险索赔**。AI 接入了他的邮箱，知道全部病情、医院、保险细节，于是整理材料、找收件人、发邮件、跟进账单，全程留档；唯一需要人做的是打电话——「这帮人你不打电话他就不会真的给你寄支票」。**第三段：分享复制**。别的家长孩子被咬也要索赔，他让 AI 把上次流程总结成两份文档——一份给人看、一份给对方的 agent 直接执行，对方拿去就能用。

他的总结是两条启发：**context 真的非常重要**——没有 context 的 AI 只能给你「建议去医院」这类正确的废话；**把 AI 当秘书用、像经理一样管理**——经理的最高境界是「他不在场时 team 还能正常运转」，对 AI 也一样：别手把手教，让它积累 context、沉淀 SOP。「强得可怕」的本质是「我不是一个人在战斗，周围有一个医生、律师、文秘天团，24×7，还能无限复制——一百件事交给一百个秘书」。但他补了一句扎心的观察：觉得 AI 好用的多是老板们，因为他们本来就会用秘书。

## 一切都是文件：Context Infrastructure 的技术路线

去年他给 AI 装眼睛和耳朵的实验，如今一半失败一半进化。失败的一半：每天自动拍照，拍了三四个月停了——「一直没找到它能带来什么额外 context」。进化的一半：录音（尤其会议）继续，且补上了两件配套——一个开源的 intake skill 把录音转写入库，然后走两条索引路线：「雅虎式」人工/LLM 分话题建索引，大课题看索引就知道去哪找文件；「Google 式」embedding 语义检索，AI 可自主发起本地文件的语义搜索。技术选型上他的态度很鲜明：**一切都是文件**，没必要搞 embedding 数据库或 Memory Layer 那样的高层抽象——Manus 那篇 Context Engineering 博客（2025 年 7 月，manus.im）他评价「值一百万美元」，核心思想正是 file system as context：AI 对文件系统本来就是 well-trained 的。他反对单纯为了用 MCP 而 MCP、为了 Memory 而 Memory，用文件加 CLI 就够了。这也是他没用 Grok Bot / Manus 云端电脑的原因：context 难完全迁移，而且密钥等敏感信息会明文出现在聊天记录里——他的很多 AI 是 zero data retention 协议下才敢乱贴东西的。主持人分享了同一方向的实践：微信聊天记录备份到本地、Codex 随时读取，参加活动前让 AI 扫名单找二度好友，「经常有意外惊喜」。

## 零人公司：能自我改进，但商业闭环仍是人的事

鸭哥把 yage.ai 网站的 AI 内容频道当成「零人公司」实验。起点是学员老问「从哪得到靠谱的 AI 信息」，让 AI 自动采集、写作、发布。这件事「稍微一想很简单，仔细想其实很难」：pretraining 学的是共识，共识没有阿尔法；alignment 倾向保守中庸——「乔布斯在 alignment 里肯定会被干掉」。所以 off-the-shelf 的 AI 输出注定平庸，必须注入他自己的思维方法——比如他调研任何东西都反问「横向调研（竞品、alternative）做了吗？纵向调研（这家公司的历史、为什么改变）做了吗？」。结果是读者反馈「不像 AI 写的，有思想」。数据（嘉宾自述，未独立核验）：newsletter 半年从零到 1600+ 订阅，X 账号 5700+ 粉丝，他没有写过任何一篇 post。更有意思的是闭环细节：X 运营本身是 AI 提议的（「你有 newsletter 为什么不运营 X」），连「搞不清楚流量来自哪个渠道」都是 AI 自己发现并解决的——它搭了基于 URL 参数的 UTM 分类体系，分析出「newsletter 用户质量高、X 来的看看就走」，再反过来调整写作和引流策略。鸭哥自己干的事只有两件：**给它装眼睛**（Google Analytics、Search Console、X 高级账户分析）和**装双手**（能自主发推），然后偶尔骂它「写得又像三大顶会了，不像我」。

商业上他答得很诚实：又赚钱又不赚钱。赚钱是因为 Superlinear Academy 的 AI 培训把这个零人公司当教学案例，有真实收入；不赚钱是因为它没有自己跑通新的商业场景。「AI 是放大器」——真正发现需求、找到客户、完成交付还是得靠人。他由此推演出一个反直觉的判断：纯程序员在 AI 时代反而可能处于劣势——「我就缺个程序员」的人如鱼得水，而程序员产生了「我用 AI 肯定比别人好」的虚拟幻觉，商业短板并没有被补上。AI 奖励的两种人：本来就有 domain expertise 的，和会**管理** AI 的——注意他的用词是管理不是使用。零人公司方法论叫「老鸭汤」：开源在 GitHub 上，但「老鸭汤要熬，小龙虾要养」——拿去用不是开箱即用，「开箱即用出来是我，不是用户」，你得在自己的场景跑一遍、把反馈变成文件喂回去，它才变成你的汤。

## 什么在贬值，什么在升值

值钱能力的问题他答得很果断：写代码快、刷力扣不值钱了，设计也在贬值（他称 Figma 时代的设计工具产出已达 Senior 水平——播客原话提到的模型名转写存疑，保留判断）；升值的是**经理能力**——给 AI 搭 Context、搭 Evaluation、让它自我闭环自我改进。但紧接着他泼了冷水，方向却出人意料：他不是担心 AI 取代人，而是「对人类乐观、对用 AI 悲观」——用好 AI 的前提是能清晰表达「我要什么」，而日常生活中能把需求讲清楚的人本来就极少。这个能力可以练：跟 AI 对练，让它指出你哪里没讲清；而且对 AI 的沟通比对人类简单得多——不用顾忌言外之意和自尊心，「我经常爆粗口骂 AI」。

两个补充观察也值得记下。一是他在生活数据上跑出的「多变量回归」实验：Apple Watch、CGM 血糖仪、智能体重秤的数据通过一个 AI 写的 iOS app 加服务器自动同步（开源），AI 用几十天数据训练分类器预测每晚睡眠时长，倒推最相关因素——**咖啡与睡眠无关（证伪省掉了他一周的戒咖啡实验）、酒精前半夜助眠后半夜破坏、最相关的变量是当晚最后一次用 AI 的时间**；戒掉晚间用 AI 后，次月平均睡眠涨了一个多小时（个人数据实验，机制解释来自 AI，供参考）。二是主持人提到的 App Store 数据：「最近一个季度软件付费数量增长率首次下跌」，并归因于 vibe coding 让人自己写工具。这个现象为真——2026 年 Q2 美国 App Store 消费支出同比下降约 6%，十年首次（Sensor Tower 估算，FT 图表）；但外部分析普遍把主因归于 Epic 案后法院强制开放外部支付链接、监管压力与游戏消费疲软，而非 AI 自建软件（FourWeekMBA 的分析标题就叫「Regulation, Not AI, Is the Cause」）。归因之争本身比数据更有信息量：vibe coding 冲击传统软件购买这件事目前更多是叙事而非已被计量的现实。

## 赛博许愿：让 context infrastructure 进组织

被问到一年后的心愿，他说是把这套东西从个人推向组织。他的论据有两个。**执行侧**：亚马逊 Leadership Principle 靠开会、层层 role model 都未必灌输得进去（Bias for Action 说了半天还是一堆人不 bias），但如果执行者是 AI，「贯彻 Leadership Principle 就是个加 prompt 的问题」——AI 在确定性和指令遵循性上有着「无与伦比的优势」（这还没算 24×7）。**协作侧**：他与课代表（合伙人）现在的合作很多已是「两个 agent 在讨论」——对方的 agent 发草案邮件过来，他的 agent 接邮箱审阅、回信提问题，两个 agent 吵几轮事情就定了，人只给高层指导。他的想象是：如果这套东西 scalable，未来会出现协作、沉淀、执行、考评都完全不同的「真正 AI native 的企业形式」。节目最后他也划了目前的边界：具身的东西（机械臂化妆）不放心、产生后果且不经审阅的自动发布不 comfortable——但这个边界在移动，「半年前我觉得不行的事，你看我现在也在做零人公司实验了」。

## 机制链条与可迁移启发

1. **分类决策的商品化 → 大厂私有功能开源化 → 接口与智能分开计价**。小模型能力到位 + Agentic 成本敏感，让「校准的分类判断」成为新原语（独立评测证实校准质量；Ramp 数据显示其一个月抢下约一个百分点企业份额）；此前只有大厂 harness 做得起的安全检测等能力被拉平到开源可用。启发：评估这类产品时把「接口创新」与「智能提升」分开看——开源复现的差距（本地 73.8% 对 86.6%）说明智能本身仍有溢价。观察指标：开源复现的追平速度、OpenAI 决策模型的动作。
2. **Context 文件化 → 个人杠杆非线性放大 → 表达能力成为瓶颈**。录音、微信、健康数据全部落文件、建索引，AI 就能从「正确的废话」变成「医生+律师+秘书天团」；而放大倍数取决于两件事——你积累的 context 厚度，和你把需求说清楚的能力。启发：AI 输出质量是输入 context 质量的函数；个人知识管理的最优解可能朴素得出奇——文件加命令行。
3. **零人公司的真实边界 → 放大器定律 → 自查你的短板**。内容生产、渠道分析、自我改进的闭环已可自动化（1600 订阅、5700 粉为证），但发现需求、打通闭环、完成交付仍是人的活。启发：AI 放大的是你原有的 domain expertise 与管理能力；「缺个程序员」型选手受益最大，纯执行型程序员反而要补商业课。
4. **管理学视角替代技术视角 → 外化+验收+SOP → 组织的新稀缺品**。对 AI 不画饼但要外化要求、验收结果、沉淀 SOP；执行层的确定性和指令遵循性让「企业文化」从洗脑工程变成 prompt 工程。启发：个人练「清晰表达需求」（可与 AI 对练），组织练「把隐性知识变成 AI 可消费的文件」。
