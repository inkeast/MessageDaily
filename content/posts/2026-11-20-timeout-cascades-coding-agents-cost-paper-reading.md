## 一、论文背景

### 1.1 AI 编码 agent 为什么贵

AI 编码 agent（coding agent）已经成了大模型最成功的落地场景之一：给它一个 GitHub issue，它能自己翻仓库、改代码、跑测试、反复迭代直到产出可用的补丁。SWE-agent、OpenHands、Claude Code 这类系统的基准成绩一路走高，但这条 agentic 工作流也让推理变得异常昂贵——**一个任务可能包含几十到几百次模型调用**，每一步都要重放不断增长的对话历史（输入 token 与输出 token 之比可达数百比一），还要跑测试、解析日志、修复报错。业界测算普遍指出：编码任务的"每任务完成成本"（cost per completed task）而非"每 token 价格"才是部署时真正要优化的指标。

更麻烦的是当前的主流做法：**为了最大化解决率，所有任务默认跑最大的模型**。这就像公司里每个工单——包括"改一行配置"——都交给最贵的架构师处理。很多软件任务其实相当常规，小模型完全能搞定，大模型只在少数难题上才有必要。当编码 agent 从演示走向生产，"能不能解"之外的问题浮出水面：**解这个任务到底烧了多少推理算力**。

### 1.2 小模型正在快速追赶

论文 Figure 1 展示了一个关键趋势：2024 年中，sub-40B（400 亿参数以下）开源模型在 SWE-bench Verified 上的解决率几乎为零；到 2026 年初，最强的 sub-40B 模型 Qwen3.5-35B-A3B 在同一 agent 脚手架下已能解决 61.2% 的真实软件工程任务。小模型不再是"便宜但基本不能用"，而是成了可信的候选。

但差距并没有消失——只是**搬家了**。论文 Figure 2 按难度分层对比 GLM-4.7-Flash（30B）与 GLM-4.7（355B）：

| 难度档 | 任务数 | GLM-4.7-Flash | GLM-4.7 | 小模型相对水平 |
|---|---|---|---|---|
| Easy（<15 分钟） | 194 | 62% | 77% | 81% |
| Medium（15–60 分钟） | 261 | 36% | 68% | 53% |
| Hard（>1 小时） | 45 | 2% | 36% | 6% |

小大模型的差距集中在 hard 档，而 easy+medium 占了基准的 91%。这个"差距的梯度结构"正是本文全部故事的起点：**如果差距是均匀的，混合推理无利可图；差距集中在尾部难题上，小模型优先的级联就有了套利空间**。

### 1.3 两条降本路线的对照

学界已有一大类"级联与路由"工作（详见第二部分）：要么按成本从低到高依次试模型（级联），要么训练一个分类器预测任务难度再分发（路由）。但这些工作几乎都在**单轮文本任务**上做的。编码 agent 是多轮、工具调用、仓库级的长程任务——失败信号是什么？升级时机怎么定？难度标签从哪来？这些都没人在完整 agentic 场景下系统回答过。本文就是要补上这块空白，并回答一个颇具工程哲学意味的问题：**复杂的难度路由器到底值不值**。

## 二、论文定位和关联工作

### 2.1 研究谱系一：LLM 级联（Cascade）

**FrugalGPT**（Chen et al., 斯坦福, 2023, [arXiv:2305.05176](https://arxiv.org/abs/2305.05176)）是这条线的开山之作：把多个 LLM API 按成本排成链，先用便宜模型生成，再用一个轻量"打分器"（DistilBERT 或统计信号）判断质量是否达标，不达标就升级到下一个更贵的模型。报告的降本幅度高达 59–98%。FrugalGPT 的核心贡献不是"先便宜后昂贵"的直觉，而是**把升级判据工程化**——级联的心脏是校验器（verifier）。

本文与 FrugalGPT 的关键区别：FrugalGPT 的升级信号是**答案质量的评分**，适用于有明确答案的 QA 任务；而编码 agent 的补丁好坏在执行时无法廉价判断（最终要靠隐藏单元测试验收），本文改用**超时/失败信号**作为升级触发——这相当于把"校验器"退化成执行时间本身，工程复杂度近乎归零。

### 2.2 研究谱系二：学习式路由（Learned Router）

**RouteLLM**（Ong et al., LMSYS/UC Berkeley, ICLR 2025, [arXiv:2406.18665](https://arxiv.org/abs/2406.18665)）用 Chatbot Arena 的人类偏好数据训练轻量路由器（矩阵分解/BERT 分类器），预测"这个 query 是否需要 GPT-4 级模型"，报告在保持 95% 质量下把成本降 85% 以上，且路由器可泛化到未见的模型对。同路线还有 Hybrid LLM（Ding et al., 2024）与 Best-Route（2025）。

这条线的共同前提：**难度信号可以从输入特征在执行前预测出来**，且预测器需要标注数据、训练与阈值校准。本文的对照实验直接挑战了这个前提的必要性——一个零训练的超时规则就能拿到 oracle 路由器 92% 的收益（16.4% vs 17.9%）。

### 2.3 研究谱系三：小模型能力崛起

- 70 个开源 SLM 的综述（Lu et al., [arXiv:2409.15790](https://arxiv.org/abs/2409.15790)）指出小模型在推理、数学、编码上快速逼近大模型。
- Belcak et al.（[arXiv:2506.02153](https://arxiv.org/abs/2506.02153)）论证 agent 调用大多是重复性、范围明确、非对话式的，适合专用 SLM，服务 7B 模型比 70–175B 便宜 10–30 倍（延迟、能耗、FLOPs）。

本文把这条线从"单步能力对比"延伸到"完整 agentic 工作流中的难度分层利用"。

### 2.4 研究谱系四：agent 经济学

OpenAI 对百万级 Claude 对话的经济任务分析（Handa et al., 2025）显示软件开发已是最高频 AI 工作负载之一；Anthropic 经济指数报告进一步指出使用正从聊天界面转向 API 与 Claude Code 式工作流。多步循环使"每完成任务成本"成为关键部署指标——这为本文的 GPU 小时度量提供了现实依据。

### 2.5 本文定位

| 维度 | 之前的路线 | 本文的突破 |
|---|---|---|
| 任务形态 | 级联/路由均在单轮任务上验证 | 完整 agentic coding（多轮工具调用、仓库级） |
| 升级信号 | 评分器（FrugalGPT）/ 预训练分类器（RouteLLM） | 超时 + 失败信号，零训练零校准 |
| 对比实验 | 级联与路由各自为战 | 首次在同基准上头对头对比超时级联 vs 难度路由 |
| 核心结论 | 更复杂的路由 → 更大的节省 | 简单级联逼近 oracle 路由（差 1.5pp），复杂路由基础设施可能是过度设计 |

一句话定位：**这是第一个在完整 agentic coding 场景下系统对比超时级联与难度感知路由的工作，核心贡献是一个反直觉的经验发现——超时本身就是足够好的路由信号**。

## 三、问题定义

### 3.1 从具体场景到抽象问题

具体场景：一个生产级编码 agent 服务面对 500 个真实 GitHub issue，手里有一个便宜的小模型（单卡可部署）和一个贵的大模型（多卡部署），每个任务有 2 小时墙钟上限。怎么组合两个模型，使 GPU 小时总成本最小，同时整体解决率不低于"全用大模型"的基线？

抽象问题：**任务难度信息藏在哪里、以多高的成本获取，决定了混合推理系统的最优形态**。论文把设计空间端到端地铺开：

- **级联**（执行后决策）：先跑便宜的，用执行过程暴露的信号（超时/失败）决定是否升级；
- **路由**（执行前决策）：从任务文本预测难度，直接决定谁先跑。

其他混合形态（并行竞速、集成投票、投机生成、预算调度器）要么需要额外的接受判据，要么需要并行执行或模型内集成，论文将其留作未来工作，专注级联与路由这对最直接、最可部署的机制。

### 3.2 形式化

- 给定：任务集 T（SWE-bench Verified 500 题）、小模型 M_s（GLM-4.7-Flash）、大模型 M_l（GLM-4.7）、每任务成本 C_gpu = t_wall × n_gpu（墙钟时间 × 占用 GPU 数）；
- 求：调度策略 π: T → {先 M_s（可升级）/ 直送 M_l}；
- 约束：整体 resolve rate ≥ 纯 M_l 基线（71.2%）；目标 min Σ C_gpu。

级联策略下总成本 = 所有被调用尝试的 GPU 小时之和（升级任务要付两次的钱，且冷重启不继承小模型的任何中间状态——一个刻意保守的假设）。

### 3.3 这个抽象的精妙之处

论文最深的洞察是把**执行时间重新定义为任务难度的免费代理变量**：小模型能解的任务倾向于在有限窗口内收敛完成，解不了的则耗尽预算自然暴露。传统视角里"超时"是失败条件，本文视角里超时是**路由信号**——且获取成本为零。路由器做的是"执行前预测难度"，级联做的是"执行中免费观测难度"，两者信息的重叠度有多高，就是 RQ4 要回答的问题。

## 四、问题解法

### 4.1 总体设计：两阶段实验 + trace 驱动模拟

类比：先给每个棋手单独下一盘完整的棋并录像，再在录像上推演各种"换人策略"——不用重新下棋。论文先让 36 个模型各自在 SWE-bench Verified 上完整跑一遍（记录轨迹、token 数、GPU 小时、墙钟时间），再用这些单模型 trace 模拟两种混合架构，**固定 agent 脚手架与任务结局，只变调度策略**。

### 4.2 评测底座

**模型池**：36 个 2024 年中至 2026 年 Q1 的开源权重模型，覆盖 Qwen2/2.5/3/3.5、QwQ、Llama 3、GPT-OSS、GLM-4.7、Kimi-K2.5、MiniMax-M2.5 等家族。以 40B 为实用部署分界：40B 以下可塞进单张高端卡（候选第一级），以上需要多卡分布式（扮演昂贵回退）。DeepSeek 系列因试点中每任务墙钟时间过长而在主实验中排除（预算不可行，论文在局限中说明）。

**服务与硬件**：vLLM 0.16.0 on ROCm 7.0.0（Qwen3.5 系列用 vLLM 0.17.0 on ROCm 7.2.1），全部跑在 AMD Instinct MI300X（192GB HBM3、5.3TB/s 带宽）上，按模型可靠部署的最小 GPU 数分配，多卡用张量并行。选择 MI300X 使单卡即可容纳 30B 级模型并留足长上下文 KV cache。

**Agent 脚手架**：统一用 mini-swe-agent——Princeton/Stanford SWE-bench 团队出品、核心仅约 100 行 Python 的极简 agent，只有 bash 一个工具、线性历史、subprocess 独立执行动作，官方报告 SWE-bench Verified 74%+，Meta/NVIDIA/IBM 等广泛采用。选它正因为**脚手架工程量极小，性能差异主要反映模型本身**。超参：每任务最多 250 步 / 2 小时墙钟，超出即终止计为未解决；每对模型-任务只跑一次（多模型多种子的全量评测成本不可行，作者坦承这点并在讨论中反复校准结论的置信度）。

**难度分层**：直接用 SWE-bench Verified 官方人工标注（OpenAI 组织 93 名资深 Python 开发者对每题估计"熟悉代码库的工程师需要多久修好"）：Easy <15 分钟（194 题 38.8%）、Medium 15–60 分钟（261 题 52.2%）、Hard >1 小时（45 题 9.0%）。

### 4.3 超时级联架构

流程：每个任务先交给 GLM-4.7-Flash，配一个可配置的时间预算 T。四种结局触发升级：超时 / 空补丁 / 语法错误 / 测试失败。升级 = **冷重启**：GLM-4.7 从原始任务状态重跑，不继承小模型的编辑、工具输出或中间推理。总成本 = 两次尝试的 GPU 小时之和。

为什么选 GLM-4.7-Flash 而不是解决率最高的 Qwen3.5-35B-A3B（61.2%）？因为**级联省钱取决于 GPU 小时成本而非解决率**——Qwen 系列需要显著更多的 agent 轮次才终止，单任务墙钟更长；GLM-4.7-Flash 终止更快、单任务更省，且与 GLM-4.7 同家族使对比更干净。这个选择本身就体现了论文的核心度量观：步数×模型规模才是成本，解决率只是分子。

超时参数 T 从 0 扫到 120 分钟（与整体 2 小时上限对齐），描绘成本-精度权衡曲线。

### 4.4 难度感知路由架构

不训练分类器，而是**用官方难度标签模拟 0–100% 各种分类准确率**：100%（oracle）时 easy/medium 直送小模型、hard 直送大模型；小模型失败仍按冷重启升级；中间准确率随机扰动派发。这给出难度路由可期的**经验上界**。混合策略模拟只用两模型轨迹都完整的 466 题（190 easy / 238 medium / 38 hard）。

两种架构的直观对照：级联是"先干再说，干不动再换人"；路由是"先看任务书再派人"。前者把决策推迟到执行中，用真实执行信号换掉了预测器。

## 五、评估指标与实验证据

### 5.1 指标体系

- **主指标：resolve rate**（最终补丁通过该任务全部 SWE-bench 验证测试的比例——FAIL_TO_PASS 与 PASS_TO_PASS 都要过）与 **GPU-hour**（C_gpu = t_wall × n_gpu，按任务独占 GPU 计费的不摊销口径，使跨模型可比）；
- **辅助指标**：平均串行墙钟时长（衡量级联的延迟代价）、超时-成本 Pareto 曲线；
- **消融指标**：路由准确率扫描（0%→100%）、超时扫描（0→120 分钟）。

### 5.2 五个研究问题的答案

**RQ1 小模型能否当第一级？** 能。sub-40B 模型从 2024 年中的近零解决率升至 Qwen3.5-35B-A3B 的 61.2%（同脚手架同服务栈），GLM-4.7/Kimi-K2.5/MiniMax-M2.5 作为大模型参照。小模型已是可信的第一级候选，但尚不能整体替代大模型。

**RQ2 差距藏在哪里？** 集中在 hard 档。easy 62% vs 77%（相对 81%）、medium 36% vs 68%（相对 53%）、hard 2% vs 36%（相对 6%）。easy+medium 占 91% → 混合推理的空间巨大。

**RQ3 级联省钱不掉精度吗？** 是。超时扫描显示：超短超时（如 5 分钟）会掐死本可完成的小模型导致无谓升级；超时越大省越多，120 分钟档最优——

| 配置 | resolve rate | GPU 小时 | 相对基线 |
|---|---|---|---|
| GLM-4.7-only（基线） | 71.2% | 2585 | — |
| 级联 120 分钟（全部任务） | 73.4% | 2160 | **-16.4%** |
| 级联 120 分钟（easy 任务） | — | 821→546 | **-33.5%** |

解决率不降反微升 2.2pp：少数 GLM-4.7 失败的任务反被 Flash 解掉。人工检查发现一个疑似**互补性模式**——大模型有时过度工程化修复（改太多引入新失败），小模型给出更直接的补丁反而通过。作者对此非常克制：单次评测下部分效应可能是跑间方差，把主结论严格限定在"降本不掉精度"，互补性留待多种子验证。

**RQ4 需要难度路由器吗？** 几乎不需要。路由准确率扫描：0% 准确率反而比基线更贵（2623 > 2585 GPU 小时，错路由纯亏）；100% oracle 达 17.9% 节省（2122 GPU 小时）。级联 16.4% vs oracle 路由 17.9%，**只差 1.5pp**——而真实难度分类器（对未见代码问题的难度预测，本身是开放难题）的训练、校准、部署成本全免了。

| 架构 | resolve rate | GPU 小时节省 | 复杂度 |
|---|---|---|---|
| 大模型 only | 71.2% | — | — |
| 超时级联（最优超时） | 73.4% | 16.4% | 低 |
| 任务路由（oracle） | 73.4% | 17.9% | 高 |

**RQ5 级联的延迟代价？** 大模型 only 平均每任务 41.6 分钟；级联在 30 分钟超时档平均 65.5 分钟、120 分钟档 84.5 分钟——翻倍左右。工具执行占不到 5% 总时间，开销几乎全在模型推理。结论：级联把 GPU 小时换成串行墙钟，**最适合异步工作流**（Google Jules、Open SWE 这类委派后后台执行、事后审阅的场景），不适合用户等待每一轮响应的交互式结对编程。

### 5.3 实验设计如何支撑论点

五个 RQ 构成完整证明链：RQ1/RQ2 先立前提（小模型够格、差距有结构）→ RQ3 证明级联有效（省钱不掉精度）→ RQ4 证明不必上复杂系统（逼近 oracle 上界）→ RQ5 诚实标出代价边界（延迟翻倍）。尤其 RQ4 的 oracle 设计精明——它不是打稻草虫，而是给出路由的**理论上界**，然后证明简单方法已贴住上界，从而"复杂路由的比例收益假设"被正面证伪。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**对比对象**：大模型-only 基线。它有效的原因很简单——每题都用最强火力；它的根本局限是**为 91% 的 easy/medium 任务支付了不必要的多卡推理成本**，这是结构性的浪费而非工程优化可消除的。

**因果链**（逐步标注证据等级）：

1. **方法差异：执行时间作为隐式难度信号**（论文实验已支持）——小模型能解的任务倾向在有限窗口内完成（120 分钟超时下 easy 档 33.5% 的节省就是直接证据：能解的 easy 任务大多在窗口内收敛，无需升级）；
2. **机制变化：升级判据从"预测的难度"变成"实测的执行行为"**（论文实验已支持）——路由器在执行前做点估计，级联在执行中做序贯观测；前者要为预测误差买单（0% 准确率时 2623 > 2585 GPU 小时，纯亏），后者的"误判成本"只是小模型的一次尝试（30B 级单卡成本）；
3. **工作量结构放大收益**（论文实验已支持）——easy+medium 占 91%，小模型在 easy 档已达大模型 81% 相对水平，意味着大量任务"白送"节省空间；hard 档仅占 9%，即使全错判升级也只多付 9% 任务的两次尝试；
4. **指标提升：16.4% 总节省 + resolve rate 微升 2.2pp**（论文实验已支持，但微升部分作者主动降级为"可能含方差"）。

**反事实推理**：若去掉"超时"这个关键设计，退化为"小模型失败必升级"（超时=无穷大且无 2 小时上限），小模型会在解不了的 hard 任务上耗尽 250 步才升级，小模型尝试成本大幅膨胀；若超时过短（5 分钟），又掐死本可解的任务。120 分钟档的收益依赖"能解的在窗口内完成、不能解的尽早暴露"这个执行时间分布的分离性——**这正是论文成立的核心经验前提**。

**补充一个本文未展开但值得指出的背景**（阅读者推测）：GLM-4.7-Flash 是 MoE 架构（30B 总参/3B 激活），每 token 推理成本远低于 355B/32B 激活的 GLM-4.7，且论文特别指出 Flash"终止步数更少"——步数少意味着重放上下文的输入 token 累积更少，这在"输入 token 主导 agent 成本"的普遍规律下是双重省。这解释了为何解决率略低的 Flash 比解决率更高的 Qwen3.5-35B-A3B 更适合当第一级。

### 6.3 综合判断与未决问题

**多研究共同支持的机制**：(1) 任务难度分布长尾偏斜是级联收益之源——FrugalGPT 的"easy query 假设"与本文 91% easy+medium 互证；(2) 小模型在常规任务上已具备实用能力——Belcak 与本文 RQ1 独立得出一致结论。

**仍属合理推测的部分**：(1) 大小模型"过度工程化 vs 直接补丁"的互补性——仅单次评测+少量人工轨迹检查，作者自己标注为未验证的 bonus；(2) 执行时间与可解性的分离性是否在其它模型对/其它基准上同样成立——论文只测了一对模型（GLM-4.7 家族）与一个基准。

**优势成立的前提条件**（论文 VI-D 节明确）：easy/medium 占工作负载大头（若 hard 主导，级联退化为"大模型+白付小模型尝试费"）；小模型在服务成本上显著便宜且能稳定解常规任务。**可能失效的场景**：交互式低延迟产品（墙钟翻倍不可接受）、任务分布整体偏难的领域（如大型重构）、小模型失败成本高昂（每次失败都烧满 2 小时预算）。

## 七、必要知识反推

假设让一个完全没有背景的人重做这项研究，他至少需要以下知识：

### 7.1 领域知识层

- **SWE-bench Verified 的结构与验收协议**（FAIL_TO_PASS/PASS_TO_PASS 测试、人工难度标注的存在）——不知道难度标签可用，RQ2 的分层分析与路由模拟无从谈起；
- **agent 成本的构成**（多轮调用 × 上下文重放 × 模型规模 → GPU 小时）——不理解"步数即成本"，就无法解释为何选终止更快的 Flash 而非解决率更高的 Qwen；
- **MoE 架构的激活参数概念**——30B/3B 激活 vs 355B/32B 激活的成本差是级联经济性的物理基础。

### 7.2 方法论知识层

- **级联与路由的经典文献**（FrugalGPT 的校验器、RouteLLM 的偏好训练）——不知道前人升级信号的设计，就不会意识到"超时"是一个未被 agentic 场景检验过的替代信号；
- **trace 驱动模拟方法论**——先采单模型轨迹再离线推演策略，是整个实验能在 36 模型 × 500 任务规模下可行的前提；
- **oracle 上界实验设计**——用模拟分类准确率扫出路由收益上界，才能做出"级联逼近理论最优"的强结论。

### 7.3 工程知识层

- **vLLM/ROCm 服务栈部署与张量并行**——36 个模型在 MI300X 上的最小可靠 GPU 配置、KV cache 预留，直接决定成本测量的口径；
- **mini-swe-agent 的选择理由**——100 行、bash-only、脚手架偏差最小化，这需要对 agent 框架生态的熟稔判断；
- **基准评测的统计纪律**——单次评测的局限、方差来源的诚实标注，是把"解决率微升"正确降级为"不降"而非过度宣传的关键。

### 7.4 知识融合的关键节点

最有价值的化学反应发生在**系统度量观 × 机器学习直觉**的交叉点：把"agent 的执行时间"从运维指标重述为"任务难度的免费后验观测"，再用信息论式的对照实验（vs 预执行预测的上界）证明这个免费信号已捕获绝大部分可路由信息。这个融合节点不需要发明新模型，而需要同时理解 GPU 计费、agent 轨迹行为与级联文献三块知识的接口。

## 八、论文中可以提取的通用性灵感

### 8.1 失败信号可以同时是路由信号（信号利用类）

**核心思想**：系统运行中自然产生的副产品信号（超时、崩溃、重试）往往承载了决策所需的关键信息，把"失败处理逻辑"重构为"信息采集机制"可以免费获得智能调度能力。
**论文证据**：超时在传统部署中是纯失败条件，本文将其用作难度代理，捕获 oracle 路由器 92% 的收益。
**推广场景**：① 数据管道中把扫描超时的表自动路由到更强的人工审核；② 客服系统把用户改写/重问的对话升级到高级模型；③ 编译器把 OOM 的优化 pass 降级为保守模式；④ 推荐系统中把冷启动期点击稀疏的用户自动切到探索策略。

### 8.2 简单基线应先于复杂学习系统（方法论类）

**核心思想**：在投入训练分类器/路由器之前，先用零学习成本的规则方法建立强基线；复杂系统的增量收益必须超过这个基线才值得部署。
**论文证据**：oracle 路由（任何真实分类器的上界）只比零训练的超时级联多省 1.5pp，学习式路由的工程成本很难被这个增量覆盖。
**推广场景**：① 搜索排序先调 BM25 再上学习排序；② 异常检测先做阈值规则再训孤立森林；③ 需求预测先跑季节性平均再上深度模型；④ 任何 MLOps 团队的模型选型流程设计。

### 8.3 差距的分布结构决定混合系统的形态（机制类）

**核心思想**：两个能力档次的系统（模型/人/算法）之间，性能差距若集中在特定难度区间，则"先低档后按需升级高档"的混合架构可套利；差距若均匀分布则无利可图。
**论文证据**：小大模型差距集中在 hard 档（2% vs 36%）而 easy 档接近（62% vs 77%），91% 的 easy+medium 任务构成套利空间。
**推广场景**：① 医疗分诊：全科医生处理常见病+专科医生兜底（转诊信号=首诊检查异常）；② 法务：模板合同自动生成+复杂条款转律师；③ 云计算：spot 实例优先+on-demand 回退；④ 教育刷题：学生先自学、卡壳超时再请求辅导。

### 8.4 成本度量应绑定"每完成任务"而非"每次调用"（度量类）

**核心思想**：多步系统的经济性度量必须落在任务粒度（含失败重试的累计成本），单步价格会系统性误导架构决策。
**论文证据**：Qwen3.5-35B-A3B 解决率更高但步数更多、GPU 小时更贵，被终止更快的 GLM-4.7-Flash 击败第一级资格；级联升级任务的"两次付费"也只在任务粒度下可见。
**推广场景**：① API 网关按 job 而非 call 计费对账；② 人工客服按解决率而非接单量考核；③ CI 系统按合入 PR 而非构建次数算成本；④ 自动驾驶按安全到达而非传感器帧数评估算力预算。

### 8.5 异步场景是延迟换成本策略的天然栖息地（部署类）

**核心思想**：用串行时间换资源成本的做法，其可行性取决于产品交互模式而非算法本身——异步工作流天然免疫延迟惩罚。
**论文证据**：级联把平均墙钟从 41.6 分钟拉到 84.5 分钟，但 GPU 小时省 16.4%；作者明确定位到 Google Jules/Open SWE 类异步编码产品。
**推广场景**：① 夜间批处理报表用更便宜更慢的流水线；② 邮件异步起草 vs 即时聊天回复用不同档模型；③ 离线渲染 vs 实时预览用不同分辨率；④ 后台索引构建 vs 前台搜索服务。
