## 一、论文背景

### 1.1 软件控制流需要的不是文本，而是判断

当大语言模型（LLM）从聊天工具变成软件组件，一个矛盾暴露出来：**程序的控制流需要的是判断，而 LLM 输出的是文本**。路由一个请求、给一个动作设置信门槛、按评分标准给证据打分、判断某个条件是否成立——这些都是软件里每天发生数十亿次的『快判断』。用生成式 LLM 做这些事，你要把结构化问题翻译成自然语言提示，等模型逐字生成一段文本，再解析、校验、处理格式错误和幻觉——输出端的工程成本经常超过推理本身。

论文开篇就点明了这个设定：可复用的判断模型应该『解释一个运行时提供的任务，并返回应用允许结果上的概率』。注意两个关键词：**运行时定义**（任务不是训练时固定的）和**概率**（不只是答案，还有置信分布，程序才能设阈值分流）。

### 1.2 System One 决策模型：Jev 引爆的新品类

2026 年 9 月，前 OpenAI 研究员、RLHF 的共同发明者之一 Diogo Almeida 创办的 TypeSafe AI 发布了 Jev，引爆了『决策模型（Decision Model）』这个新品类。它的命名与设计借用了卡尼曼《思考，快与慢》的双系统框架：

- **System 2（慢思考）**：GPT、Claude 这类生成式 LLM，逐 token 推演、组织语言，能力强但慢、贵、输出不可控；
- **System 1（快判断）**：Jev 这类决策模型，不生成任何文本，输入一段状态（文档、工单、对话记录）加一组预定义类型的问题，一次并行返回所有答案，每个答案带概率分布。

Jev 支持三种强类型原语——**Choice**（从选项中选一个，返回全选项概率分布）、**Score**（在有序等级上打分，返回分布与期望值）、**Noul**（布尔判断，返回 p(true)）。由于输出空间被候选集封闭，模型在结构上不可能编造选项之外的值。TypeSafe 官方宣称在合适的任务上比前沿 LLM 快近 200 倍、成本最低降至约四百分之一（端到端 70–500ms，输入 $0.042/百万 token、输出免费）。

Jev 迅速形成了一个生态：APUS 发布了全球最早一批开源复现；ConvAI 的 Laya、Mapika 的 Decider、Jared Palmer 的 Kev 等开权重跟随者出现；学界也开始把它当作研究对象——例如把 Jev 直接换入 24 篇 ACL 论文的分类器（TDM-Gauntlet）、用决策模型做临床工具调用与记忆检索。

### 1.3 问题：闭源天花板上的开放研究需求

但 Jev 本身是闭源 API。论文指出，要把『类型化概率决策』发展成一个开放的研究方向，研究者必须拿到权重：才能考察表征与训练如何影响决策质量、才能把模型适配到新领域、才能检验概率在任务变化后是否仍然可靠。这些恰恰是 API 黑箱做不到的。同时，闭源领跑者也暴露了这个方向的未解难题——多问题组合推理、跨任务迁移、概率校准——这些难题的机理研究更需要可拆解的开放模型。

Decision 1.0 就是在这个背景下诞生的：**六个开权重模型、双向编码器与因果解码器两种架构、统一 Choice/Noul/Score 接口、含一个工作流专家模型、附完整评测文档**，目标是给『可编程决策』建立一个开放地基。

## 二、论文定位和关联工作

### 2.1 谱系一：System One 决策模型家族

- **Jev 1.13.0**（TypeSafe AI, 2026.9）：本领域的事实标杆与本文最强 baseline。开创 Choice/Score/Noul 类型化接口与『校准决策』训练理念（RLCD）。**闭源、仅 API**——这正是本文存在的直接理由。本文评测中 Jev 以 Overall 81.05% 居首。
- **Laya**（ConvAI Innovations）：开权重候选标记式决策模型（421M ModernBERT + 决策头），本文 Kai 的直接对照与 Lex 工作流专测的对手；其 [MASK] 候选标记设计被 Kai 的打分器继承。
- **Decider**（Mapika）、**Kev**（Jared Palmer，三个尺寸）：System One 风格的开权重跟随者，Kev 的外部套件还被本文用作 Transfer 面板。
- **APUS fast-browser-use**（2026.9）：最早的开源复现之一，验证了『跳过自回归解码、隐状态直接打分』的核心逻辑在浏览器自动化场景可行。

### 2.2 谱系二：候选条件化分类的技术源头

候选条件化打分（把标签当描述喂进模型而非固定输出索引）直接连接到**基于蕴含的零样本文本分类**（Yin et al., EMNLP 2019, [arXiv:1909.00161](https://arxiv.org/abs/1909.00161)）——把每个类别描述成自然语言假设、用蕴含模型判定。区别在于：零样本蕴含只做推理，而决策模型是**在决策任务上显式训练并输出校准分布**的专用模型。

### 2.3 谱系三：骨干架构来源

- **编码器分支**：ModernBERT（Warner et al., 2024, [arXiv:2412.13663](https://arxiv.org/abs/2412.13663)）→ mmBERT（Marone et al., 2025, [arXiv:2509.06888](https://arxiv.org/abs/2509.06888)）→ Vela Encoder → Kai/Lex 的初始化链。
- **解码器分支**：Qwen3.5 系列（0.8B/2B/4B/9B），其 **Gated DeltaNet（GDN）+ 全注意力 3:1 混合**骨干来自 Yang et al.（ICLR 2025, [arXiv:2412.06464](https://arxiv.org/abs/2412.06464)）：线性注意力的 delta 规则（写入前先擦除旧关联）+ 数据依赖门控（快速遗忘），训练线性时间、推理常数状态，已被 Qwen3-Next、Kimi Linear 等采用。

### 2.4 谱系四：校准方法

温度缩放（Guo et al., ICML 2017）是分类器事后校准的经典方法；本文用它单独拟合分布锐度（保 argmax 不变），并在概率质量面板单独评测——把『选得对』与『概率可信』拆成两个维度。

### 2.5 生态位：决策模型作为研究对象的后续工作

本文所属生态同期出现了多篇把决策模型当研究材料的工作，它们反过来印证了开放权重的价值：TDM-Gauntlet（[arXiv:2611.20191](https://arxiv.org/abs/2611.20191)）把 Jev 换入 24 篇 ACL 论文，发现 zero-shot 可直接替换 12/46 个测试集、标签加持后 gap closed 达 72%；System 1 agents（[arXiv:2611.21053](https://arxiv.org/abs/2611.21053)）用决策模型做临床 MCP 工具调用，10,888 次调用零幻觉值；Jetriever（[arXiv:2611.21478](https://arxiv.org/abs/2611.21478)）用 Jev 全池效用打分做记忆检索，R@1 从相似度检索的近 0 提到 84.8%。

### 2.6 定位总结

| 维度 | 之前的路线 | Decision 1.0 的突破 |
|---|---|---|
| 权重开放 | Jev 闭源；Laya/Decider/Kev 开源但单架构、评测零散 | **六模型全开权重（Apache 2.0）**，含推理代码、配置、评测文档 |
| 架构 | 各家单一架构 | **双向编码器 + 因果解码器双路线**同接口并存，外加工作流专家 |
| 接口 | Jev 定义了 Choice/Score/Noul | **复用并开源了同一接口**，跨架构统一（2–255 候选、2–10 等级） |
| 评测 | 各自为战 | **公共基准**（3,766 决策、5 面板、15 系统同题同序对比）+ 概率质量 + 工作流专测三线并评 |
| 诚实度 | — | 明确披露基准开发期反复观察、Overall 权重事后选定、配方不可归因 |

一句话定位：Decision 1.0 = Jev 定义的类型化决策接口 + Laya 的候选标记打分 + ModernBERT/Qwen3.5 双骨干 + 程序化监督与自然语言标注混合训练，**把闭源领跑的品类第一次做成了完整开源的研究基础设施**。

## 三、问题定义

### 3.1 形式化

**给定**：一个请求包含文本状态 x 与问题集 {q₁,…,q_Q}。每个问题由四元组定义：类型 t ∈ {Choice, Noul, Score}、指令 u、候选描述 C = (c₁,…,c_K)。全部内容在**推理时**由应用提供。

**求**：每个候选的条件概率

p_θ(i | x, u, C, t) = exp(z_i/T) / Σ_k exp(z_k/T)

其中 z_i 是候选得分，T > 0 是推理温度，填充候选不参与归一化。

### 3.2 三个类型化接口

| 接口 | 语义 | 返回 |
|---|---|---|
| **Choice** | 从 K 个候选中选一个 | 完整概率分布 + 最大值对应的候选标识符 |
| **Noul** | 布尔判断（接口名即 Boolean judgment） | p(true)（在 false/true 两个备选上） |
| **Score** | 有序评分等级（如 1–5 星） | 等级分布 + 期望指标 Σᵢ (i−1)·pᵢ；编码器原生接口还支持对给定数值求期望 |

工程约束：编码器接口 1,024 token 上限、因果模型 16,384；Choice 支持 2–255 个候选、Score 支持 2–10 级；问题之间独立计算、可批量。应用可以显式提供『弃权/未知』候选，让模型在证据不足时表达不确定。

### 3.3 这个抽象的精妙之处

这个定义做对了两件事：

1. **任务绑定从权重移到输入**。传统分类器的标签集固化在输出层维度里，换任务就要换头重训；这里候选描述本身就是输入的一部分，同一个模型、同一次前向，可以服务任意应用定义的任意结果空间。这相当于把『函数签名』交还给调用方——决策模型成了一个类型化的通用判定算子。
2. **输出空间封闭**。概率只在应用提供的候选上归一化，模型不可能输出候选之外的值——一类幻觉（编造格式、编造选项）被构造性消除；剩余的风险被压缩为『选错』与『概率不准』，两者都可度量、可设阈值管理。

类比：如果说生成式 LLM 是一个会写作文的顾问（你要读它写的文章再提炼结论），决策模型更像编程语言里的**类型安全函数调用**——`decide(state, question) -> TypedDistribution`，签名由你在运行时给定，返回值直接进 `if` 语句。

## 四、问题解法

Decision 1.0 的核心工程问题是：**如何把一个文本任务定义绑定到它允许的结果上，同时保留底座模型的语言理解能力**。两条架构路线回答同一个接口。

### 4.1 模型家族总览

| 模型 | 初始化 | 参数量 | 上下文 | 架构/定位 |
|---|---|---|---|---|
| Kai-0.6B | Vela / mmBERT | 0.57B | 1K | 双向编码器；通用 |
| Lex-0.6B | 早期 Kai | 0.57B | 1K | 双向编码器；**工作流专家** |
| Eos-0.8B | Qwen3.5-0.8B | 0.75B | 16K | 因果解码器；通用 |
| Sol-2B | Qwen3.5-2B | 1.88B | 16K | 因果解码器；通用 |
| Nox-4B | Qwen3.5-4B | 4.21B | 16K | 因果解码器；通用 |
| Lux-9B | Qwen3.5-9B | 7.94B | 16K | 因果解码器；通用 |

参数量含部署的决策读出头；每个 checkpoint 权重独立。

### 4.2 编码器分支（Kai/Lex）：三路独立类型路径

**类比**：像一家公司里三个职能科室（选择科、判断科、评分科）共用一个前台（共享嵌入层），各科室有自己的办公流程但读同一份档案。

输入打包顺序：类型化问题在最前，随后每个候选描述前加一个 `[MASK]` 标记，状态放最后。外部候选 ID 只是簿记信息，不进入 token 序列——双向注意力让每个标记能同时看到自己的候选描述、证据和竞争选项。

计算路径：

1. 共享嵌入层 + LayerNorm 后，喂入 **三条独立路径**（Choice/Noul/Score 各一条），类型信息来自共享的三项类型嵌入表；
2. 每条路径是 22 层 ModernBERT 骨干：宽度 768、pre-LayerNorm 残差、GEGLU 前馈宽度 1,152；全局注意力出现在第 0、3、…、21 层，其余层用 ±64 token 的双向局部窗口；Q/K 上加 RoPE；第一层注意力归一化为 Identity（因为嵌入已归一化）；
3. 路径专属最终 LayerNorm 后，把选中的类型嵌入加到每个 token 上，再过**两层交互层**（全局自注意力 + ReLU 前馈 768→3072→768）；
4. **候选打分**（继承 Laya 的候选标记设计）：收集每个候选的上下文化标记向量 hᵢ，经类型专属打分器 zᵢ = w_t^⊤ GELU(W_t·LN_t(hᵢ) + b_t) + a_t（W_t ∈ R^{768×768}）得到标量分，掩码 softmax 出分布。打分器在同类型内跨候选共享。

原生混合类型批处理时，每条激活的骨干路径处理完整的填充批次，按类型选行后才进交互层。Lex 与 Kai 拓扑相同、权重独立适配。

### 4.3 解码器分支（Eos/Sol/Nox/Lux）：混合骨干 + 共享读出头

**类比**：把一个生成式 LLM 的『嘴』（词表生成头）摘掉，换上一个『评委』——评委先通读全部材料（状态、问题、所有候选块、结尾的后缀），再给每个候选亮分。

骨干继承 Qwen3.5 文本拓扑：Eos/Sol 24 层，Nox/Lux 32 层；**每四层一组 = 3 个 Gated DeltaNet 混合器 + 1 层全因果注意力**（Lux 为 24 GDN + 8 full）；两类层都是 pre-RMSNorm 双子层（token 混合 + SwiGLU 前馈），层栈后接独立 RMSNorm。视觉塔和词表生成头在决策推理中不存在。骨干 BF16、决策打分 FP32。

| 模型 | 层数 | 宽度 | FFN | Q/KV 头 | GDN K/V 头 | 混合排布 |
|---|---|---|---|---|---|---|
| Eos-0.8B | 24 | 1,024 | 3,584 | 8/2 | 16/16 | 18 GDN + 6 全注意力 |
| Sol-2B | 24 | 2,048 | 6,144 | 8/2 | 16/16 | 18 GDN + 6 全注意力 |
| Nox-4B | 32 | 2,560 | 9,216 | 16/4 | 16/32 | 24 GDN + 8 全注意力 |
| Lux-9B | 32 | 4,096 | 12,288 | 16/4 | 16/32 | 24 GDN + 8 全注意力 |

输入顺序：状态 → 类型化问题 → 候选块（各含键与描述）→ 末尾的决策后缀。问题类型编码在 token 序列里。

**候选条件化读出**是这一分支的关键设计。设 H 为最终归一化后的序列，eᵢ 是候选块 i 的最后一个 token，L 是未填充序列长度。读出头收集 hᵢ = H[eᵢ] 和 h_q = H[L−1]（**后缀末位状态**），分别 LayerNorm 得 cᵢ 和 q，再用共享 FP32 头打分：

zᵢ = (W_k cᵢ)^⊤(W_q q)/√256 + w^⊤ GELU(A_c cᵢ + A_q q + b)

四个投影独立参数化，只有候选侧非线性投影带偏置；这个头在同一 checkpoint 内**跨所有候选、所有三种决策类型共享**。填充候选在温度缩放和 softmax 前被掩码。

这个设计的巧处在于处理**候选间信息不对称**：靠前的候选端点看不到后面的候选（因果掩码），但后缀末位查询 q 看过完整输入——每个候选的分数都被『全局视野』条件化。这支持任意数量的输出候选，但**不强制排列不变性**（论文后面会诚实报告候选顺序敏感性）。

### 4.4 训练：程序化监督 + 自然语言标注 + 回放

- **分布监督**（Lex/Sol/Nox/Lux）：目标 y ∈ Δ^{K−1} 上的交叉熵 L_CE = −Σᵢ yᵢ log p_θ(i|·)，训练时 T=1。硬标签即 one-hot；软标签保留源分布；**人类序数均值通过相邻等级插值表示**（保住标注均值）。候选重排必须同步重排目标；有序等级不能乱序打乱。
- **Kai**：继承多语言监督（SNLI、MASSIVE、BoolQ、TyDi QA、HelpSteer2、OpenAssistant 等），转换成候选决策；在约 21,000 条完整输入上适配 Choice/Score 路径，共享嵌入冻结，发布版保留早期 Noul 路径。
- **Lex**：在 typed-decisions 数据集生成的 6,000 条训练决策上专化早期 Kai（客服、发票、安全事件、agent 轨迹），教师软标签与硬标签各半，三路径全适配、嵌入冻结，固定重训日程后在 2,000 决策测试集上评测。
- **Sol/Nox**：英/中程序化决策课程 + 意图与推理标注，回放保留旧任务；自然语言适配用 24,000 条混合（保留决策 + Cosmos QA + SQuAD 2.0 可答性 + SNLI）。Sol 用候选交叉熵；**Nox 额外通过冻结的词表答案字母行做监督保留**（部署时移除该辅助读出）——一个防止适配把基座读能力磨掉的巧招。
- **Lux**：在 24,000 条混合（保留决策 + 人工标注判断）上适配 Qwen3.5-9B，最终阶段用硬标签交叉熵，并把不透明的选项键替换成语义描述（证据、候选描述、顺序、标签保持不变）。
- **Eos**：先只热身读出头、再全模型适配，24,000 行。
- **数据卫生**：同源父组/近重复组整体划入同一 split；已知评测匹配从自定义训练中排除。
- **选择与校准**：checkpoint 选择以决策准确率为主、概率质量破平；正温度单独以最小化 NLL 拟合（保 argmax）；Lex 用固定日程、不做测试期温度拟合。

作者明确声明：各模型初始化与配方不同，这个家族是**已发布系统的对比，不是受控的规模或注意力方向研究**——这句自我限定在评测解读时很重要。

## 五、评估指标与实验证据

### 5.1 基准与协议

公共基准含 **3,766 个评分决策、54 个任务切片**，五个面板：**Decisions**（显式分类/布尔规则/等级判断）、**Composition**（交互约束与状态更新）、**Reading**（证据理解）、**Inference**（可答性/蕴含/常识）、**Transfer**（外部 Kev 套件复用）。覆盖英文与中文。

面板构成与聚合：Decisions 与 Composition 各 880 例、宏平均 10 个任务族；Reading 480 例（BoolQ 一半权重 + 英/中 Belebele 各四分之一）；Inference 等权平均四个 120 例来源（Cosmos QA、SQuAD 可答性、SNLI、QASC）；Transfer 用 Kev 套件 1,046 道可答题的微准确率。Overall = 30% Decisions + 25% Composition + 15%×3 其余——**权重是看到结果后选定的**，只提供描述性排名。所有系统经各自原生接口获得相同样例与候选顺序。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**对比对象**：未调 LLM（Qwen3.5 原始词表 + 固定答案字母 logits）。它为什么曾经有效？因为基座预训练注入了语言与世界知识，生成式接口万能；但在结构化决策上它要为『输出格式』付出代价——逐 token 生成、解析、候选空间未被显式建模。

**因果链一：任务绑定迁移 → 显式决策面板大涨（论文实验已支持）**
候选条件化把『任务→结果空间』的绑定从权重搬进输入 → 同一次前向可服务任意应用定义的候选集（2–255 个）→ 决策适配不必为每个任务重训，只需在『读候选描述并竞争打分』这一通用能力上训练 → Decisions +10~17 点、Inference +11.67 点（Lux/Sol/Nox vs 各自参照）。读出头把基座『下一个词分布』改造成『整个候选集的一次性归一化分布』，避免了枚举生成与解析——System 1 agents 的 10,888 次调用零幻觉从外部佐证了封闭输出空间的结构安全。

**因果链二：后缀查询条件化 → 长候选列表的一致评分（论文设计已支持，效果为推测）**
解码器读出用 suffix-final 查询条件化所有候选分数 → 靠前的候选端点虽看不到后面的候选，但其分数经过看过全部输入的 q 校准 → 支持可变候选基数。论文未单独消融该设计，此环节属于阅读者推测。

**因果链三：独立计算 → Composition 天花板（论文实验已支持）**
问题之间独立计算、无状态激活复用、无跨问题约束传播 → 每个判断都是无状态的快照 → 交互约束与状态更新（Composition）恰恰要求把前一个判断的结果喂给下一个 → Composition 成为全家族最弱面板（Lux 52.75 vs Jev 66.38）。这不是数据量问题而是**接口的计算图缺失**——论文未来工作第一条（前缀状态复用 + 分支）正对此症。

**因果链四：温度只调锐度 → 校准不随精度改进（论文实验已支持）**
温度缩放只做单调锐度调整、保 argmax → 排序错误不会被修复 → Lux 精度逼近 Jev 但 ECE 5.56% vs 3.35% → 『选得对』与『概率可信』必须分开训练/评测。TDM-Gauntlet 的发现（概率粒度取整会让 conformal 预测集失效）从外部印证：**概率质量是决策模型的独立产品属性**。

**因果链五：适配的能力交换（论文实验已支持）**
Nox 的 Reading 比未调参照掉 8.91 点、Sol/Eos 的 Transfer 低于更小对手 → 决策适配把分布从通用语言理解拉向判别任务时，部分阅读/迁移能力被交换掉 → Nox 的冻结词表行辅助读出、回放混合等设计是针对此症的缓解，但未完全消除。

### 6.3 综合判断与未决问题

**多项独立研究共同支持的机制**：运行时候选条件化 + 封闭输出空间的非生成式打分，在显式决策任务上带来一致且可观的收益（本文 Lux/Sol/Nox vs 参照、TDM-Gauntlet 12/46、System 1 agents 零幻觉、APUS 复现）。

**仍属推测或未决的部分**：(1) 与 Jev 的差距应归因于训练数据与配方——论文自认无法归因，只能由后续受控研究验证；(2) suffix-final 查询、双线性+非线性双分支读出等具体设计缺少消融证据；(3) Composition/Transfer/校准三个短板中，前两者需要接口级创新（状态复用、组合计算图），后者需要超越温度缩放的校准训练——都是开放问题。

**优势成立的条件**：任务能表达为封闭候选集上的判断、候选描述可自然语言化、证据在输入预算内。**可能失效的条件**：候选集巨大且不透明（TDM-Gauntlet 发现 >300 标签时 0/5 替换成功）、需要跨问题状态传递的组合推理、需要候选顺序鲁棒的高风险场景。

## 七、必要知识反推

假设让一个有通用深度学习能力但对该领域一无所知的人复现这项工作，他最少需要知道什么？

### 7.1 领域知识层

- **System One 决策接口**：必须理解 Choice/Noul/Score 的语义、弃权候选的用途、置信分布在软件控制流里的用法（设阈值分流、级联）。不理解这些，就无法设计正确的输出契约。
- **语义路由与 agent 控制的真实需求**：路由、门控、评分是软件里高频判断的三种形态——这是任务分布设计的来源，也是评测面板的来源。

### 7.2 方法论知识层

- **候选条件化分类脉络**：从蕴含式零样本分类（Yin 2019）到 Laya 的候选标记——知道这条线才能把『读候选描述』做成通用能力而非逐任务微调。
- **现代骨干架构**：ModernBERT 的交替全局/局部注意力与 GEGLU；Gated DeltaNet 的 delta 规则 + 门控遗忘；3:1 线性/全注意力混合的取舍（长程压缩 vs 精确检索）。不知道这些就无法解释为什么编码器适合 1K 短上下文、混合解码器扛 16K 证据。
- **分布监督与序数结构**：软/硬标签交叉熵、人类序数均值的相邻等级插值、候选重排的目标同步——有序 Score 的语义不能用无序分类的损失蛮干。
- **校准理论**：温度缩放的机理与边界（保 argmax、只调锐度），ECE/Brier/NLL 各自度量什么。

### 7.3 工程知识层

- **权重适配手术**：摘掉词表头换读出头、冻结嵌入、head-only 热身再全模型适配、辅助词表行保留基座能力（Nox）并在部署时移除。
- **数据卫生**：近重复组同划 split、评测匹配剔除、回放混合防遗忘——否则评测数字会被泄漏污染。
- **评测方法学**：面板化基准设计、宏/微平均的选择、组 bootstrap 置信区间、『基准被开发期观察』对结论效力的限制。

### 7.4 知识融合的关键节点

1. **接口与骨干的对接**：意识到 Jev 的类型化接口可以架在两种截然不同的骨干上（双向编码的三路类型路径 vs 因果解码的共享读出头）——这是『开放基础模型家族』而非『单模型』的来源。
2. **生成头的拆除与重建**：把『下一个词分布』重造为『候选集一次性归一化分布』，同时用 suffix-final 查询补偿因果掩码造成的信息不对称——两个领域知识（LM 读出与判别学习）的化学反应。
3. **适配-保留平衡**：把灾难遗忘文献的回放/辅助任务手法移植到决策适配上（Nox 的冻结词表行、Lux 的保留决策混合）——方法论知识层的直接迁移。

## 八、论文中可以提取的通用性灵感

### 灵感一：把任务定义从权重移到运行时输入

- **核心思想**：当一个模型的输出空间由输入描述而非权重维度决定时，它就从『专用分类器』变成『通用判定算子』，软件可以在不重训的情况下复用它。
- **论文证据**：同一组模型在 54 个任务切片、2–255 个候选的跨度上工作；Lux 相对参照 Decisions +10.26 点而无任何任务专属微调。
- **推广场景**：内容审核规则频繁变更的平台；A/B 实验中动态调整的分层策略；多租户 SaaS 里每个租户自定义工单分类体系；机器人任务中随环境重定义的动作集；法务/合规中按辖区更新的裁量标准。

### 灵感二：封闭输出空间是一类安全的构造性保证

- **核心思想**：与其事后过滤幻觉，不如把输出空间在架构层面封闭——不可能生成的东西不需要检测。
- **论文证据**：概率只在应用提供的候选上归一化；外部佐证 System 1 agents 10,888 次调用零编造值。
- **推广场景**：数据库查询接口只允许白名单表/列；API 网关只允许注册过的路由；医疗处方系统只允许药典内药品；代码生成先限定可调用的函数集合。

### 灵感三：概率分布是可组合的工程资产，不只是答案的附属品

- **核心思想**：返回全候选分布（而非只返回 top-1）让下游能做置信门控、级联、期望值计算——分布本身成为系统设计的材料。
- **论文证据**：Score 接口返回期望指标 Σ(i−1)pᵢ；System One Auto 用概率驱动 Kai→Vega 级联（65.80%→82.25%）；反过来 ECE 5.56% 的校准短板会直接限制这类用法。
- **推广场景**：风控系统按概率分桶自动放行/人审；搜索排序融合多个打分器的分布；主动学习选低置信样本标注；多 agent 投票按校准概率加权。

### 灵感四：『选得对』与『概率可信』是两个独立维度，必须分开训练与验收

- **核心思想**：精度的提升不会自动带来校准；温度缩放只调锐度不修排序。
- **论文证据**：Lux 的 Brier/NLL 追平 Kev-9B 但 ECE 更高；Jev 三项概率指标全胜且同时 Overall 第一——说明校准可以被当作训练目标（如 RLCD 理念）而非事后补丁。
- **推广场景**：任何要按置信度行动的 ML 系统（医疗、自动驾驶、金融）；LLM agent 的工具调用门控；预测性维护的告警分级。

### 灵感五：适配专用能力时用辅助锚点保住基座能力

- **核心思想**：向新任务适配时，保留一条通向旧能力的梯度通路（回放、冻结的辅助读出），能缓解能力交换。
- **论文证据**：Nox 用冻结词表答案字母行做监督保留（部署时移除）；即便如此其 Reading 仍掉 8.91 点——说明该手法必要但不充分，反向强调了它的重要性。
- **推广场景**：推荐系统的兴趣漂移适配；机器人从仿真到实机的域适配；代码模型适配新语言时保留旧语言能力；客服模型季节性更新。

### 灵感六：开放权重是归因研究的先决条件

- **核心思想**：闭源 API 只能测端到端行为；只有拿到权重才能把系统差异归因到架构、数据、配方，并研究迁移与校准的机理。
- **论文证据**：本文以『已发布系统的对比、非受控研究』的诚实声明，恰恰暴露了配方归因在当前生态里做不到——而这是它开源的直接动机之一；同期 TDM-Gauntlet、System 1 agents 等研究都建立在可获取的决策模型（开源家族或 API）之上。
- **推广场景**：开源模型评测生态建设；企业采购前的第三方基准；复现性研究；安全审计（如本文生态中的决策模型提示注入鲁棒性研究）。
