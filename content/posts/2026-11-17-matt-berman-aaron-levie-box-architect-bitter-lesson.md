## 先说结论

这场访谈最值得记的不是 BoxWorks 发布了什么，而是一家做了二十年企业内容管理的 SaaS 公司，把自己在 Agent 时代的生存法则讲得异常直白。Levie 的核心假设是：模型会无限变好，所以只建「就算存在超级智能也仍然需要的基底」——数据治理、安全、高吞吐基础设施、给 agent 用的易交互 schema；其余一切，包括没来得及发布就已过时的功能，「随时扔掉」。当天发布 Box Architect 是这套哲学的产品化：用前沿模型自动设计业务流程与应用，起因是内部 demo 里 agent 用 30 秒做完了客户要花两天白板规划的工作。往前推是他的千倍 token 论：三年内每条信息将被一到十个 agent 处理，「往哪里投算力」会成为一种核心竞争力，而他以开放权重作为对冲 AI 实验室守门人权力的「逃生阀」。对读者，这是观察老牌 SaaS 公司如何自我改造的一份坦率样本，也是理解「软件价值坍塌、基底价值上升」的一个企业侧证词。

## 两层软件世界：agent 之上，系统记录变成系统智能

背景先摆清楚：访谈发生在 BoxWorks 发布当天，Berman 开场道贺 Box 股价历史新高，Levie 的回应是把股价归因于投资者终于接受了他讲了多年的叙事——非结构化数据在 AI 世界里的位置「正在拼到一起」（节目口径）。Berman 评价这是他听过的厂商里把 context、context management 与 security 讲得最清楚的一家，随后抛出引子：两年前微软 CEO Satya Nadella 预测软件将收敛成两层——agent 与 ground truth context（真相上下文），这一预测兑现了吗？

Levie 的回答把 Jensen Huang 的说法接了过来：未来大概会有比人多数十倍到百倍的 agent，也就是全球在组织里游荡着数百亿量级的 agent（转写此处数字含糊，按 30~500 亿理解并存疑）在处理信息。这时必须有东西守住 ground truth 和 guardrails：哪个 agent 能访问哪些 CRM、ERP、lakehouse 数据，能访问哪些来自文件的非结构化数据。他特别反驳了一种想当然：「有人觉得把这些扔进一个数据库就行了」——真正重要的是访问控制、数据治理和关于上下文的元数据，agent 得靠这些才知道把查询路由到哪、怎么找到对的东西；不能把所有信息丢进一个巨型 blob，而要用正确的治理、沙箱和隔离来策展。于是世界的大模样是：一层是海量 agent，另一层是被现代化的「系统记录」（system of record）变成的「系统智能」（system of intelligence），控制访问层与治理、存储信息，并且仍然保留终端界面——因为用户终究要往系统里灌数据、要和它交互。

## Box Architect：不是把 agent 塞进流程，而是让模型设计流程

当天的旗舰发布 Box Architect，官方口径是一个自主系统，用来构建、设计、运行并最终优化建在 Box 上的 agent、工作流和应用。Levie 给的用例是：企业进来一句「我要一个合同管理方案／供应链文档审查方案／发票处理方案」，不再需要自己写整套软件、也不必拼装三五个工具，而是让前沿智能（他举例今天的 Astra、Opus、Fable）直接把完整方案设计出来，Box 内部的积木全给它用。

这个产品的起源故事比定义更有信息量。Levie 说，六到九个月前有工程师做了个内部示例，让当时的最新模型在 Box 环境里设计一个完整应用，「我们当时就惊了——agent 用 30 秒做完了我们的客户要花两天去想、在白板上画、再把整个架构搭出来的事」。转折点是今年夏天：模型在工具使用、计算机使用上「疯了」，对业务流程的理解大幅变好，GDPval 这类企业工作流基准上的表现让他判断，与其把 agent 塞进现有自动化的某个节点，不如让 AI 从头设计整套自动化——甚至反过来告诉企业「这个流程本身也许有更好的做法」。Berman 追问这是不是先做内部自动化再外卖，Levie 纠正：从一开始就是按客户用途去建的，但「如果我们不觉得模型已经 ready，就不会发布」。

他把这个形态放进行业坐标：Decagon、Sierra，以及转写疑作 Finn 的那家（疑指 Intercom 的 Fin，未核实），都在做「帮客服运营人员设计客服 agent 的 agent」；Box Architect 把同一模式扩展到任何业务流程——客户入职、贷款处理、客户接待——而且接下来数月内还会基于 ground truth 自动优化流程、看失败案例自我改进。值得注意的是 Box 对边界的表态：你可以用 Architect 一站到底，也可以用 headless 的 Box 配别家技术，两者 Box 都欢迎——因为「信息需要流向工作发生的地方」：合同要出现在 Salesforce，供应链文档要出现在 SAP 或 Oracle，营销方案要出现在 ChatGPT 或 Claude 里。Levie 自称 Box 是「宗教般以伙伴为中心」的公司，开放与互操作是教义。

## 「苦涩教训」经营学：随时扔掉，并在没有界面的世界里创造价值

Berman 的问题切中了每家 SaaS 公司都在纠结的划线问题：模型、harness、context，哪些自己建？Levie 的回答是「尽可能骑在智能曲线上」：凡是会被更好的前沿模型淘汰的东西都不建，除非只是模型暂时做不到的临时 scaffolding。他给自己的定位是「苦涩教训皈依度的上限」（bitter lesson pilled，网络语，指彻底接受 Sutton 的《苦涩教训》）——要建的就该是那种「就算模型比今天强一千倍也仍然需要的结构性的东西」。

这个哲学的日常形态是扔东西。「多久扔一次？」——「一直在扔。」Levie 说 Box 有过压根没发布就过时的能力：还没来得及上线，新模型一出来整个功能就作废了；你花三个月建一层东西，模型工具使用能力一强，整层直接报废。「你相当一部分时间是盖在流沙上，或者跑步机上」，必须非常不留恋。Berman 问公司内部有没有成文的原则清单，Levie 笑答「我们没那么聪明，也许该写个 memo」——并当场表示这次访谈激发了他，会去写一篇「苦涩教训备忘录」择期发布。他预告的内容会是：假设我们拥有超级智能、它在每个话题上都比我们每个人都聪明，那么要在一个组织里安全部署它，需要什么基底？答案是数据治理、极强的安全、高吞吐的基础设施组件，以及一整套易交互的 schema，让智能体要在你系统里建对象时能直接调用底层工具。他给的历史类比是十五年前写一份「全面 API-first」的内部备忘录——就像 Amazon 的 Bezos 要求自用的东西全部对外开放——而今天每个软件公司都要再走一遍这个旅程，并接受一个推论：会有很长一串场景里，没人会看到你的界面，所以你要确保自己在无界面世界里也能产出可观的价值。

## 千倍 token 论：算力投向成为竞争力，开放权重是逃生阀

Berman 抛出 Levie 此前公开讲过的「千倍 token 用量」预测，问机制。Levie 说「你现在就能看到」：设想三年后，世界上产生的每条信息都会被一个、三个、五个、十个 agent 看到、审查、处理。他给的四个企业侧样本是：销售——每个客户都有一个 agent 持续构建、随时更新的画像；网络安全——企业里每个有意义的信号事件（陌生 IP 登录、没见过的设备）都会拉起 agent 去审查，每次代码 push 不仅有人审还跑风险仿真、向外扇出；工程——agents on agents，既并行构建也审查、测试、模拟；制造与供应链——每份进来的 CAD 设计、供应商合同、发票都被 agent 抽取关键数据回灌 ERP。他的量化判断是「我们现在大概只走到了百分之一：我电脑上干的很多事没有任何 agent 看到——三年后不会是这样」。

Berman 顺着问：竞争力是不是就等于谁能更快发现用例、往上面扔 token，最终谁拿到的 token 最多谁赢？Levie 的回答在这两极之间摇摆，而且摆得很诚实：一方面他「深度确信 token 的正确投放比数量更重要」，无限 token 可能把人带偏方向、浪费能量，他不是「token 拉满」派；另一方面他又承认，投向「值得的问题」的算力量，可能成为未来决定性竞争优势之一。他随即自己指出这件事的暗面：如果资本过度成为竞争优势的依赖，就会得到权力集中和创新变少——这「令人兴奋，也可能反乌托邦」。他给出的不对称性在于人与 agent 的供给曲线：人是有限的，多数公司招聘工程师到一定规模就到顶了，工程师还要换工作、培养速度也跟不上；agent 没有上限，唯一的限制是数据中心的规模。药企的例子：把算力撒向药物试验与创新，就能比对手更快跑实验、更快验证想法。

Berman 把矛头推向结构：如果 AI 实验室是这些 token 的守门人，他们会不会对未来经济体里谁赢谁输有过多决策权？Levie 的回答只有一句但立场明确：「这就是为什么我坚定地支持开放权重」——市场需要多个可选项，开放权重是逃生阀。

## 谁付账：席位加消费的混合定价，token 变成预算行项

很多企业领导听到 token 分配的讨论会紧张：钱最终谁出？Box 主要按席位收费，这种模式会消失吗？Levie 的答案是一个混合结构：只要还有人参与数据和 agent 的工作，席位组件就应该保留——企业需要这个维度的可预测性，不想一切都透过「 volatile 的消费定价、我这个月欠多少」的镜头去看；但 agent 的行为方式不可提前预测，所以新的消费组件必然出现。他判断三到五年后，token 预算会变成正常的预算规划——就像「你想往营销项目投多少钱、往免费午餐投多少钱、往 token 投多少钱」，一个可以按战略需要增减的行项；眼下那些「某公司大幅收紧 token 开支」的头条，只是新奇期的现象。

至于 CFO 的恐惧——Berman 的原话是「我说这句话时能听见一千名 CFO 的颤抖」：你没法提前预测解决某个具体问题要花多少 token。Levie 承认帮不了太多，Box 能做的核心是「用最低成本帮客户从数据里榨出最多价值」，而这就是当天另一项发布的位置：与 NVIDIA 合作的上下文检索引擎（context retrieval engine），用 NVIDIA 的 embedding 模型做预索引与排序，让 agent 在海量非结构化数据上只抓自己需要的片段——花在无用数据上的 token 更少、找东西更快。这项能力会在未来数月随企业高级版推出，客户可以无感受益，也可以通过 API 直接取回文档内的相关片段。转写称所用模型为 Nemotron Retrieve（原转写 Neutron，疑为 NVIDIA Nemotron 系列检索模型的同音误识，未独立核实）。

## 开放与闭源共生：Oracle 类比，与 Muse Spark Open 的里程碑时刻

Berman 搬出投资人 Gavin Baker 那张被广泛引用的图：总 token 用量明确向开源倾斜；但 OpenAI 和 Anthropic 又是史上最好的两家生意——这怎么同时成立？Levie 的回答是「100% 都成立」，并主动用了一个他自称不喜欢的类比：2005、2006 年之后硅谷创业公司基本都跑在开源数据库上，而同一时期 Oracle 照样长成三千亿美元公司——总有人 roll your own 并自己扛运维，也总有人要平台替你干这件事。开放与封闭是悖论式同步增长的，而且是自我强化的：开放权重把整体 AI 成本打下来之后，他反而「付得起」把前沿闭源模型用作编排器或规划层，把开放权重用于海量执行层——扫每一份文档、对每一笔交易做反欺诈。光靠前沿模型的定价，这个量他永远付不起。「开放权重 somehow 意味着你在闭源上花得更多」——这对没部署 AI 的人来说完全反直觉，但这就是他在很多客户环境里实际看到的。

那么开放权重自己的商业模式呢？Berman 点出难题：训练 capex 巨大、模型免费送、neo cloud 拿去就能 serving 赚钱。Levie 的判断很冷静：现实中你必须同时是推理提供商才能把训练货币化；他点名 NVIDIA「讽刺的是它就是一家推理提供商，只是低一层、你没在打它的 IP 而已」。有资格这么玩的：Meta、Google、NVIDIA。Meta 与 Google 现在都不再发布前沿级的开放权重——但 Levie 紧接着给了这期访谈里最生动的一段：如果开放权重只是落后闭源前沿一代，而这一代只落后四个月呢？他让 Berman 想象回到今年 3 月：那时已经过了所谓 Claude Code 时刻，「如果 Meta 在 3 月宣布一个达到 3 月前沿水平的开放权重模型，我们的脑子会炸掉」。而这正是 Muse Spark Open（Levie 口中「Muse Spark、Open 什么的」，与 Berman 确认）刚刚做到的事——本站此前已按 AI Daily Brief 成文，可对照。他的推论是：3 月的前沿大概已经「喂饱」了大量用例——他以 IT 工单类任务为例，称（并明说数字是现编的）约八成已被 3 月水平的前沿完全解决，也就意味着开放权重现在就能支撑这八成；只要保持三到六个月的落差轨道，开放权重会持续吞掉前沿在半年前解锁的全部用例，那是巨量的 token 工作。

访谈最后回到 Box 自己会不会训模型。Levie 说某些用例做后训练「几乎不可避免」，但现在还在收割模型原生增益的阶段（他再次把这归为苦涩教训）。他对冒出来的后训练生态如数家珍：Trajectory、Prime Intellect、Applied Compute、Fireworks、Baseten、Ngram（专名按转写保留、未经核实）——企业知识后训练换效率与准确率、高频重复的工作流单独训一个小模型。他甚至设想未来企业直接用自家数据训一个模型、跑在 Box 平台里：「让大家更容易做到这件事」。

## 机制—影响—启发：三条链

其一，模型能力突变（今夏工具使用、计算机使用、GDPval 级企业工作流能力）→ agent 能在几十秒内设计出此前要人天级规划的业务方案（证据：Box 内部 30 秒 vs 两天的 demo，Levie 称）→ 应用层的「预制软件」价值被抽走，Box 把价值押到基底（治理、安全、检索、互操作）→ 二阶影响：企业软件采购从「买应用」转向「买让模型长出应用的地基」→ 观察指标：Architect 类产品的采用率、企业自建与采购比例 → 启发：当自建软件成本坍塌（与 Berman 自己的论断互为印证，见 11-04 旧文），卖地基比卖楼稳，但地基必须是无界面也有价值的 API-first 地基。

其二，token 单价下降（开放权重竞争＋检索引擎省 token）→ 前沿模型用量反而上升（编排用贵的、执行用便宜的，Levie 称在客户环境普遍可见）→ 印证千倍 token 论，也解释了 Anthropic 净收入留存 900% 一类数字（本站 10-30 旧文）→ 二阶影响：token 进入企业预算表、SaaS 定价从纯席位走向混合 → 观察指标：企业预算里 token 行项的出现、Box 类公司收入结构中消费组件占比 → 启发：评估 AI 基础设施生意，看「总 token 消耗 × 每 token 毛利」，不要被单点价格战带偏。

其三，agent 数量爆炸（每条信息 1–10 个 agent 处理，Levie 预测）→ token 分配权集中在 AI 实验室等守门人手中 → 权力集中与创新减少的结构性风险（Levie 自认的暗面）→ 对冲机制：开放权重逃生阀＋企业侧多模型自适应路由（Box 的理想形态）→ 二阶影响：模型可替换性成为企业谈判筹码，n-1 开放权重与闭源的落差月数成为行业关键变量 → 观察指标：开放权重落后闭源的月数（Levie 口径现为约四个月）、企业路由层渗透率 → 启发：无论企业还是个人，别把工作流焊死在单一闭源入口上；与同日 Wes Roth 的「Claude 就是操作系统」终局论（另一篇）对读，正好是这一判断的正反两面。
