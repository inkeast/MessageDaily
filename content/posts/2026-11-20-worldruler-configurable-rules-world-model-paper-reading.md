## 一、论文背景

### 1.1 什么是交互式世界模型

想象你在玩一个由 AI 实时『画』出来的游戏：你按下手柄，模型不是播放预制动画，而是逐帧生成你对世界施加动作之后的画面。这就是**交互式世界模型（interactive world model）**——它从初始图像和动作序列出发，生成可探索、可交互的视频世界。Google DeepMind 的 Genie 3 是这一方向的标志性产品：720p、20-24 FPS 实时生成、分钟级场景一致性，被定位为通往 AGI 的关键台阶。国内也出现了 Matrix-Game、Yume、AlayaWorld 等一系列实时交互世界模型。

这类系统的底层是**动作条件视频生成**：给模型一段视觉历史 `H` 和动作 `u`，它预测下一窗口的视频。游戏引擎（如 Unity）用显式状态机 + 渲染管线做到这件事；世界模型则试图用神经网络从数据里『学』出环境动力学，换取无需手工建模资产的泛化能力。

### 1.2 现有世界模型缺什么：规则与存档

论文的出发点来自一个游戏设计的观察：**规则决定玩家动作的后果**，不同规则在相似场景和动作空间中创造出截然不同的玩法体验。两个经典例子：

- 《Cat Mario》颠覆传统平台跳跃规则——看似安全的平台会塌陷、看似道具的蘑菇会杀死玩家；
- 《It Takes Two》设计了独特交互规则——用钉子在不可逾越的沟壑上造桥。

而现有视频世界模型是从真实世界视频中学出来的，它们内化了『真实世界的常见物理』，却没有机制去遵循**用户自定义的、超越真实世界行为的规则**（比如『打倒怪物会掉钥匙』）。更棘手的是两个具体能力缺口：

1. **存档/读档（save/load）**：游戏的基本功能。但视频模型没有显式的存档语义——你无法『保存』一段生成世界的状态，下次从那里继续。生成是采样性的，重开一次，世界就变了。
2. **看不见的状态**：如果开关打开了视野外的门，玩家转过头去，门应该已经是开的。纯视频模型只维护『看到的画面』，视野外的世界状态对它而言不存在。

### 1.3 两个核心挑战

论文把『可定制玩法的世界模型』拆成两个挑战，这是全文的问题主线：

- **Rule-State Persistence（规则-状态持久化）**：保存/加载时联合保留规则定义、规则依赖和世界状态。例如规则链『剑击打倒怪物 → 怪物掉钥匙 → 钥匙开锁门』：玩家在捡钥匙之前存档，读档后必须仍然存在『已死的怪物、地上的钥匙、关着的门、以及剩余的规则』——包括当前画面里根本看不到的信息。
- **Rule-to-Visual Realization（规则到视觉的实现）**：把规则引发的改变准确落实在**指定的对象和属性**上，尤其是受影响对象尚未入画时。开关开的门在视野外，门第一次入画的瞬间就必须是开着的——存储的状态要能约束这次『首次出现』，并在后续交互中持续有效。

前者要求世界有可序列化的显式状态，后者要求生成过程接受状态条件的局部控制。纯端到端视频模型在这两点上都有结构性缺陷，这就是 WorldRuler 要填的坑。

## 二、论文定位和关联工作

### 2.1 谱系一：视频世界模型（长时程一致性路线）

前序工作主要攻克实时性与长时程一致性：Yume 1.5（上下文压缩 + 注意力蒸馏做实时生成）、WorldPlay（重构上下文记忆改善几何一致性）、Matrix-Game 3.0（相机感知记忆检索 + 自纠正训练）、AlayaWorld（流式 3D 点缓存）、AlayaVista（全景潜状态 + 视口渲染）、Alaya-EVOKE（外部空间记忆 + 长时程监督）。这些工作解决『画面随时间不崩』，但**都不维护用户定义的规则状态**。WorldRuler 与它们的关系是互补：规则状态作为额外条件源约束后续视频生成。

### 2.2 谱系二：可控视频生成（局部编辑路线）

从相机轨迹（CameraCtrl、MotionCtrl、DragNUWA）到语言指令控制角色与相机（H3-World），再到显式表示支撑的对象级操控：WorldCraft（3D 表示 + 世界坐标约束做对象操控）、CustomX（3D 资产定制角色/动作/场景）、SolarRenderer（结构化场景表示适配视频生成器）、GraphVid（交互图控制多实体）、Park et al.（图对齐的去噪监督，用成对『视频-图』修改做训练）。这条线解决『改对地方、别动无关内容』，但**不跨交互维护规则依赖的状态**。WorldRuler 借用其局部控制思想，把『编辑指令』升级为『规则执行产生的持久状态』。

### 2.3 谱系三：世界模型中的状态与规则（最直接的谱系）

这是本文的直系前驱，三个近期工作构成了它的直接语境：

- **Code World Model（CWM）**：用编码智能体维护世界状态并编译为代理视频（proxy video）再渲染；
- **Programmable World Model（PWM）**（值得注意：这是 Alaya Lab 自家前作，arXiv 2609.10540）：自然语言 → 可执行程序维护显式全局状态，状态增强 3D 有向包围盒确定性编译为像素对齐条件，在自建 CombatStateBench 上达 94% 计数 / 98% 状态准确率；
- **State World Models（SWM）**（arXiv 2610.26811，本文最强基线）：Stateful Harness 把世界演化与视频渲染解耦——可执行规则裁决动作结果，冻结视频模型渲染结果，VLM 从生成片段更新状态；其 WorldState-Bench（50 组反事实孪生对）显示：纯规则提示下最好的视频后端只有 32% 的对完成率，完整 harness 达 92%。

### 2.4 定位对比与结论

| 维度 | 纯视频世界模型（Genie 3 类） | 图控制编辑（GraphVid 类） | CWM / PWM | SWM | **WorldRuler** |
|------|------|------|------|------|------|
| 显式规则执行 | 无 | 无 | 有 | 有 | 有 |
| 规则+状态联合存档/读档 | 无 | 无 | 部分 | 无 | **有（联合 checkpoint）** |
| 离屏对象首次出现控制 | 无 | 无 | 部分（离屏状态） | 无 | **有（动态绑定 + 预置状态）** |
| 属性级局部落实 + 无关内容保持 | — | 有（无持久状态） | 部分 | 弱（Effect 仅 ~21%） | **有（去噪内属性替换）** |
| 规则开关配对训练数据 | 无 | 部分 | 无 | 无 | **RuleVerse（3200 对）** |

**定位结论**：WorldRuler 站在『显式状态执行』谱系（CWM→PWM→SWM）的延长线上，把该谱系此前没解决的两件事做成闭环——(1) 规则/状态/绑定的**联合序列化**（真正的存档语义）；(2) 规则后果在**指定视觉实例**上的精确落实（SWM 的 Effect/Timing/Hold 只有 15~21%，说明『裁决对了但画不出来』是其瓶颈）。这正好是对 SWM 结论（解耦有效）的下一步：解耦之后，渲染端如何被状态精确控制。

## 三、问题定义

### 3.1 从具体场景到抽象问题

具体场景：玩家在 AI 生成的游戏世界里自定义规则、存档、读档、继续玩。表面上看这是『视频生成质量』问题，但论文的洞察是：这本质上是**『权威状态』与『观测生成』两个系统的绑定问题**。

深层结构相似性：规则系统（游戏引擎的状态机）知道**什么该发生**，视频模型知道**画面长什么样**，缺的是两者的接口——『哪次改变、落在哪个实例、哪个属性、什么时刻』。这类似经典 MVC 架构中模型与视图的分离，只是这里的『视图』是一个不可解释的概率采样器，接口必须做到**潜空间与去噪过程内部**。

### 3.2 形式化定义

给定：初始视觉观测 `I0`、用户定义规则集 `R`、动作序列。求：遵循规则的交互视频。

维护三类表示：

- 可执行 3D 规则图 `Gt`（规则定义 + 依赖 + 对象身份/属性 + 空间信息）
- 执行状态 `Xt = (St, qt)`（对象属性 `St`；事件历史/规则激活记录/转移进度/待处理效果 `qt`）
- 绑定 `Bt`（规则实体 ↔ 3D 对象 ↔ 视觉实例的对应）

生成按窗口进行，第 `n` 窗口：

```
Vn ~ p(Vn | I0, Hn, Un, Cn),   Cn = Condition(Gn, Bn, Sn)
```

其中条件 `Cn` 由规则图、绑定、状态序列构成。两个约束目标即两大挑战：`Save/Load(G,X,B)` 可逆（持久化），`Cn` 能在指定实例的指定属性上生效（视觉实现）。

### 3.3 这个抽象的精妙之处

关键在于**把『裁决权』和『渲染权』分开，又把两者的接口做成可学习的**。规则执行是离散、确定、可序列化的（适合存档）；视频生成是连续、采样、不可解释的（适合画质）。此前工作要么只分开（SWM 用文本指令连接两端，损耗在接口上），要么只连接（端到端模型无法存档）。WorldRuler 的抽象是：接口本身（对象绑定 + 属性替换）成为显式建模的对象——这是它能在 SWM 之上把 Effect 从 20.74% 拉到 58.47% 的结构原因。

## 四、问题解法

WorldRuler = 可执行 3D 规则图（裁决+存档） + 动态对象绑定（接口定位） + 属性状态替换（接口执行） + 反事实训练（接口学习） + RuleVerse（数据）。按生成闭环的顺序拆解：

### 4.1 组件一：可执行 3D 规则图——世界的『存档格式』

类比：这就是游戏引擎的实体-组件系统 + 规则脚本，被改造成可与视觉生成器共存的轻量图结构。

- **对象节点**：持久身份、语义描述、3D 支撑、属性状态；**规则节点**：触发器、状态前置条件、效果赋值；**类型化边**：区分动作主体/动作目标/前置条件对象/效果目标——因此**后果可以发生在远离触发器的位置**（拉杆开门，门在另一个房间）。
- 执行语义的细节见功力：动作请求 ≠ 动作完成（需确认的完成事件才满足规则）；未知属性保持显式未知，**不能通过否定式钻空子**；带时长的变化记录当前值/目标/转移进度（半开的门不满足『门已开』谓词）；对不可见对象的效果在状态里持续存在；效果目标无法解析时保留描述、规则来源和事件时刻直到可绑定。
- **Checkpoint 联合序列化** `Ct = Save(Gt, Xt, Bt)`，`Load` 完整恢复三者。读档后，相同的后续动作与事件证据应产生一致的规则决策。

### 4.2 组件二：动态对象绑定——『规则说的门是哪扇门』

绑定回答两个问题：规则寻址的是场景中哪个实例？该实例在当前视野的哪个区域可控？

- 语义/外观/空间一致性匹配候选实例与规则实体，绑定存入 `Bt`；同类对象保持不同身份，视角变化、遮挡、重现不破坏已建立的绑定。
- 已定位对象：相机投影 + 实例分割（SAM2）给出时空掩码 `Mi`。
- **首次出现控制（First-appearance control）**：这是本文最漂亮的机制之一。规则可以在对象**不可见时**更新其状态；一旦 3D 绑定已建立，存储状态在生成『该对象首次入画窗口』**之前**就被赋给投影区域——视野外被打开的门，第一次被看到就是开的，无需重演开门动作。完全未定位的实体效果保持 pending，直到可靠对应出现。

### 4.3 组件三：感知反馈——不泄漏答案的闭环

独立感知模块从生成帧估计身份、可见性、视觉属性、动作完成度，**不接收期望的规则结果作为提示**（防止把答案当线索）。通过身份/置信度/时间有效性检验的证据更新绑定、局部几何与普通可观测状态，并为需要视觉确认的规则提供事件。规则规定状态与观测结果**分开记录**：门被要求开但看起来关着——规定状态保留，观测差异引导下一窗口纠正。反馈只影响其被接受之后的窗口，不回写已交付视频，不把未确认结果当成功。

### 4.4 组件四：对象属性状态替换——去噪过程内的『属性编辑器』

这是方法的技术核心，解决『状态条件如何在采样过程中精确生效』。类比：像是给扩散采样器装了一个『属性仪表盘 + 校正器』——每一步去噪都先读表、再校正、再写回。

**读（Reader）**：流匹配参数化下，去噪步的干净估计为 `ẑ0 = zσ + σ·vθ(zσ, σ, Cn)`。对对象掩码做 pooling 得局部特征 `ai`；冻结的仿射读出器 `ŝi = Ai·ai + bi` 从视觉特征估计当前属性（在标注真实视频上独立拟合，**不接触规则目标**，保证读数不被目标污染）。

**校正 + 相容调整**：规则执行给出当前有效目标 `s*i`，差异 `δi = s*i − ŝi`。当受控属性可独立辨识（`Ai` 行满秩）时：

```
Bi = Aiᵀ(AiAiᵀ)⁻¹        # 右逆：把属性差异映射回特征空间
Qi = I − BiAi             # 零空间投影：与读出正交的自由度
a′i = ai + Biδi + γ(δi)·Qi·fϕ(ai, hi, ŝi, s*i, σ)
```

两项分工：`Biδi` **直接校正属性坐标**（保证读出满足 `Ai·a′i + bi = s*i`，且 `δ=0` 时自动消失、不扰动已达标特征）；`γQfϕ` 是可训练 writer，**在被约束于 reader 零空间的子空间里学习相容的外观/运动变化**——只改属性读数可能画出『数值对了但画面不对』的结果，零空间分支负责让变化看起来自然。多属性联合求解避免顺序写入冲突。

**写回（Write back）**：校正散射回干净估计并更新采样速度 `v′θ = vθ + (ẑ′0 − ẑ0)/σ`，规则修正进入后续去噪轨迹。写入排除固定历史边界、不可见区域、未授权属性；支撑外的潜变量不被直接修正——**局部性就是无关内容保持的来源**。

### 4.5 组件五：反事实重建与双向属性交换——接口如何学习

配对数据 `(V0, V1)`：同场景、同动作上下文、规则事件对齐，仅在指定规则属性状态上不同（规则开/关两支各用自己的真实状态与视觉结局）。先在真实局部特征上拟合正则化仿射 reader 并检验属性可辨识性，然后**冻结 reader、视频生成器、视觉编码器，只训练 writer ϕ**。三项损失：

- `Lrec`：从共享去噪轨迹的局部估计出发，两个分支分别重建各自目标特征——学每个状态的视觉实现；
- `Ldiff`：监督两分支输出之差等于真实特征之差——共享输入迫使输出差异只能来自状态条件；
- `Lswap`：双向交换，从一支的真实特征写入另一支的属性、重建对应目标——干净输入、零噪声级、只改受监督属性，配对中无关内容的对齐让该目标同时监督『属性改变』与『局部内容保持』。

### 4.6 RuleVerse 数据集：自动化采集 + 配对标注

用 GTA-V（开放游戏环境）+ Habitat（室内交互）构建自动化流水线：勘察场景原生对象/部件/空间关系/交互能力 → LLM 生成规则手册（自然语言描述 + 可执行条件 + 状态赋值）与交互脚本 → 代码检查绑定/语法/初始条件/可行性（Habitat 还做规则质量筛查）→ 编译为导航/交互/相机控制 → **同一计划在规则开/关两个分支各执行一遍**（关规则支保留原生动作与游戏原生反应）→ 记录视频、对象身份、动作事件、状态轨迹、触发条件、效果时刻 → 独立解释器重算条件与效果、成对控制/视频完整性/标注对应检查、解码视频去重。

规模与构成：**3,200 对 / 6,400 视频，2,900 训练 / 300 测试**；五类触发器（动作/空间/关系/状态/序列）× 多类效果（属性/几何/存在性/拓扑(Habitat)/行为(GTA-V)）；跨对象绑定规则占 Habitat 60.2%、GTA-V 40.2%；**75.4%（Habitat）/61.1%（GTA-V）的规则首次激活在视频后半段**，约 19% 依赖动作历史——即数据刻意覆盖了『状态需要长期保持』和『激活依赖前置动作』的难例。公开输入为初始图像+规则+请求动作，参考视频与状态标注留在答案侧（防评测泄漏）。

### 4.7 实现配置

视频生成：MiniMax-H3 Ref2VA Turbo，1344×768、24 fps、每窗口 124 帧；感知栈：Qwen3.8-Max（视觉理解）、SAM2（实例分割）、DA3（几何估计）。

## 五、评估指标与实验证据

### 5.1 指标体系

**RSR（Rule Success Rate，规则成功率）**——主指标，五个分量评估规则启用视频上的标注规则事件：

| 分量 | 衡量什么 |
|------|----------|
| Identity | 触发对象与效果目标是否与参考身份匹配（找对对象） |
| Trigger | 指定触发条件是否可见地成立（时机对） |
| Effect | 规定改变是否在目标上实现（核心：画出来了没） |
| Timing | 效果是否在触发后开始、在规定窗口内建立（时刻对） |
| Hold | 结果状态是否在要求的观测区间内保持（持续对） |

**FCR（Full Completion Rate，完整完成率）**——任务级指标：Stages（全部规则事件都成功，而非单阶段平均）、Order（阶段按规定时序发生）、Goal（最终目标可见达成）。

消融专用指标：**First-appearance**（离屏受影响目标首次入画时身份与规定属性是否正确）、**Preservation**（无关对象/属性是否保持原样）。判定用冻结 VLM 评估器、固定选择题、3 fps 采样；不确定判定留在分母且不得分——评估协议对全部方法一致。

### 5.2 主结果一：RuleVerse（Habitat 子集）

| 方法 | Identity | Trigger | Effect | Timing | Hold | RSR 均值 | Stages | Order | Goal | FCR 均值 |
|------|------|------|------|------|------|------|------|------|------|------|
| MiniMax-H3（裸生成） | 78.85 | 53.37 | 17.79 | 9.13 | 9.62 | 33.75 | 11.21 | 13.64 | 5.26 | 10.03 |

| SWM | 98.16 | 68.66 | 20.74 | 15.67 | 17.05 | 44.06 | 15.55 | 17.58 | 20.82 | 17.98 |

开放游戏环境下优势保持（RSR +23.23 vs SWM），且 SWM 的 FCR 归零而 WorldRuler 达 66.66——多阶段任务里 SWM 无法把规则后果视觉化，任务链条断在第一环。

### 5.5 消融一：组件贡献（Habitat 子集）

| 变体 | RSR | FCR | First-appearance | Preservation |
|------|------|------|------|------|

| 去属性状态替换 | 46.43 | 38.50 | 12.90 | 17.16 |
| 去 Lswap 交换损失 | 51.24 | 45.75 | **6.45** | 20.63 |
| **完整方法** | **64.99** | **48.04** | **29.69** | **28.71** |

三个组件各司其职：动态绑定没了 RSR 掉 16.9（对应不上实例）；属性替换没了 RSR/FCR 掉 18.56/9.54（状态落不进画面）；**去掉交换损失 First-appearance 从 29.69 崩到 6.45**——比去掉属性替换本身还低，说明替换模块的有效性完全依赖其训练目标（属性变了但无关内容/外观相容性没学好，首次出现照样错）。

### 5.6 消融二：存档到底要存什么

| 恢复设置 | Consistency | Post-load RSR | Post-load FCR |
|------|------|------|------|
| 仅最后图像 + 规则文本 | 94.25 | 49.23 | 40.11 |
| 规则 + 属性，无执行进度 | 95.13 | 51.26 | 45.53 |
| **规则 + 执行状态 + 绑定联合** | **98.17** | **54.36** | **47.89** |

这组实验直接验证『联合持久化』主张：只存画面和规则文本（多数现有系统的做法）读档一致性 94.25%；把执行进度（事件历史、激活记录、转移进度）一起存，一致性升到 98.17%，读档后续规则实现与任务完成也最高。存档内容的完备性是可度量的设计变量。

### 5.7 证据链总结

- 核心主张『显式规则执行 + 状态条件生成优于纯视频/纯 harness』：由 5.2/5.3 支撑（RSR/FCR 全面大幅领先）；
- 主张『属性替换在去噪内生效且保持无关内容』：由消融 5.5 的 Preservation 差距支撑；
- 主张『联合存档必要』：由 5.6 的三档对比支撑；
- 外部效度：由 5.4（他人基准持平略优）支撑。指标设计与主张一一对应，RSR 五分量恰好把『接口失败』拆解为可定位的环节，这是评估设计的亮点。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**因果链一：显式可执行状态 → 视野外/跨窗口信息不再依赖视觉记忆 → Hold/Effect/存档一致性提升。**
纯视频模型中，『怪物已死』这一事实只存在于历史帧的像素里；转场、遮挡、重采样都会侵蚀它。SWM 已证明解耦有效（32%→92%），但其接口是文本指令——裁决结果要经过自然语言『转述』给渲染器，转述有损，所以 SWM 的 Effect 只有 ~21%。WorldRuler 的改变不是『也做了规则执行』，而是把接口从文本升级为**结构化绑定 + 属性级条件**：规则执行输出的不再是『门开了』的描述，而是 `gate.open=1` + 门实例的时空支撑 + 去噪内强制执行。Effect 20.74→58.47 的提升对应接口信息带宽的本质变化。（论文实验已支持：5.2 表；SWM 32→92 来自 SWM 原文。）

**因果链二：右逆 + 零空间的分解 → 『可保证的校正』与『可学习的自由』分离 → 属性精确性与画面相容性兼得。**
`Biδi` 保证读出恒等于目标（数学恒等式，非学习目标），`γQfϕ` 的更新被投影进 reader 零空间——writer 无论怎么学都**不可能破坏属性读数**，只能在『读数不变』的自由度里改善外观与运动。这把『控制正确性』从优化问题降格为代数恒等，把『相容性』留给学习。外部旁证：ICLR 2026 FlowGuide 同样利用扩散 bottleneck 潜空间的局部线性/子空间方向做精确属性编辑与身份保持；TokenDial 用『方向 + 强度 + 掩码』分解做连续属性控制且报告身份/背景保持最佳——『在潜空间中沿可控方向做有界修改』这一机制族在多个独立工作中收敛。（标注：右逆保证是论文推导的数学事实；『零空间约束是 Preservation 提升的主因』为论文实验支持的机制解释，幅度归因含推测成分。）

**因果链三：动态绑定 + 预置状态 → 控制在首次出现之前建立 → First-appearance 29.69 vs 6.45。**
首次出现控制的必要条件是**空间 grounding 先于生成**：必须知道门在 3D 里的位置，才能在它入画的第一个窗口就把开的状态投影进去。消融中去掉 Lswap 使 First-appearance 崩溃（6.45）揭示了另一层：grounding 解决『在哪』，反事实配对训练解决『变了状态的物体长什么样』——两者缺一不可。（论文实验已支持。）

**因果链四：感知反馈与规则状态分离记录 → 防止『观测改写事实』与答案泄漏。**
反馈不接收期望结果，未确认结果不计成功——这是对『生成-评估闭环』常见的自我欺骗（把希望当观测）的结构性防御。SWM 也有类似设计（渲染矛盾不能推翻规则状态），两文独立收敛于同一原则。（两文实验均支持该设计必要性，但均未做『反馈带答案』的对照消融——此条为机制推测 + 跨文互证。）

### 6.3 综合判断与未决问题

- **多项研究共同支持的机制**：(1) 规则/状态的显式执行优于隐式像素记忆（SWM、PWM、LiveWorld、WorldRuler 四线独立收敛）；(2) 配对±单干预监督对『改该改的、保不该改的』有效（WorldRuler 的 Lswap 消融 + DualityForge 的去配对消融）。
- **仍属推测的机制**：零空间分解相对于『直接微调全部参数』的净贡献未被单独消融（论文只消融了『有无替换』与『有无 Lswap』，未对比『替换但不加零空间约束』的变体）；感知反馈的防泄漏设计无对照实验。
- **优势成立条件**：属性需可被线性 reader 可辨识（Ai 行满秩是硬前提，复杂语义属性可能不满足）；依赖可靠实例分割与 3D 几何（长尾对象/极端视角下绑定会退化）；RuleVerse 规模 3,200 对，writer 的泛化上限未在更大规模开放域验证。
- **可能失效条件**：规则涉及全局风格/氛围类属性（无明确对象支撑，局部 scatter 无处落笔）；读出器属性集之外的新颖属性（需重拟合 reader）；对画面保真要求超过规则要求时，替换算子可能引入局部突兀。

## 八、论文中可以提取的通用性灵感

### 灵感一：裁决权与渲染权分离，接口显式建模

**核心思想**：把『决定发生什么』的确定性逻辑与『呈现发生什么』的概率生成分开，并把两者之间的接口本身当作一等公民来设计（对象绑定 + 属性条件），而不是用自然语言一句带过。
**论文证据**：SWM 用文本接口 Effect 仅 20.74%，WorldRuler 结构化接口提升至 58.47%；WorldState-Bench 上纯提示 32% vs harness 92%（SWM 原文）。
**推广场景**：LLM Agent 工具调用（规划器与执行器的接口结构化）；机器人 stack（任务规划与底层控制的接口）；数据库应用（事务逻辑与视图渲染分离）；UI 生成（逻辑状态与视觉呈现的绑定）。

### 灵感二：可保证部分用代数，可学习部分约束在零空间

**核心思想**：当一个系统有一部分目标是可精确度量的，用数学恒等式直接保证它（`Biδi`），让学习模块只能在『不影响保证』的自由度（零空间 `Q`）里发挥——把『正确性』与『优雅性』解耦。
**论文证据**：`Ai·a′i + bi = s*i` 是恒等式而非损失项；δ=0 时校正自动消失，不扰动已达标内容；Preservation 28.71 vs 去替换 17.16。
**推广场景**：代码生成（类型约束由编译器保证、风格由模型学习）；控制工程（PID 保底 + 学习残差补偿）；安全强化学习（硬约束层 + 软优化层）；数据库查询优化（语义保持的等价变换 + 启发式重写）。

### 灵感三：控制必须先于事件建立（First-appearance 原则）

**核心思想**：要让某对象以指定状态出现，控制信号必须在它出现之前就绑定到其空间位置——事后修正远不如事前条件化。
**论文证据**：动态绑定使 First-appearance 29.69 vs 固定绑定 20.58；存储状态在首次入画窗口生成前赋给投影区域。
**推广场景**：流式系统预取（内容到达前建立路由）；自动驾驶预测（行人出现前预测遮挡区）；缓存系统（访问前预热）；教育（先建立图式再呈现材料）。

### 灵感四：配对±单干预数据是『改变与保持』的最优监督

**核心思想**：共享一切上下文、只翻转一个干预变量的配对数据，能同时教会模型『该改变什么』与『不该动什么』——这是受控实验思想的数据化。
**论文证据**：去掉 Lswap 使 First-appearance 从 29.69 崩至 6.45；DualityForge 独立报告去配对大幅退化。
**推广场景**：A/B 测试文化（单变量原则）；模型对齐（成对偏好数据的严格构造）；医学（配对临床试验）；调试（最小重现用例构造）。

### 灵感五：存档 = 状态 + 进度 + 绑定的联合序列化

**核心思想**：交互系统的可恢复性要求把『规则/逻辑』『执行进度』『外部对应关系』三者一起保存——只存快照或只存规则都不够。
**论文证据**：联合 checkpoint 一致性 98.17% vs 仅图像+文本 94.25% vs 缺进度 95.13%；读档后 RSR/FCR 同样最高。
**推广场景**：长程 Agent 会话（检查点需含工具状态与任务进度）；工作流引擎（断点续跑需持久化绑定与已完成节点）；游戏网络同步（状态同步 vs 帧同步的取舍）；分布式系统（事务与消息偏移的联合持久化）。

### 灵感六：闭环反馈要防『答案泄漏』与『观测改写事实』

**核心思想**：用生成结果更新系统状态时，反馈通道不得接触期望结果，且事实记录与观测记录必须分离——否则闭环会自我强化幻觉。
**论文证据**：感知模块不接收规则结果作为提示；规则规定状态与观测结果分开记录，未确认不计成功；观测差异只引导后续窗口纠正。
**推广场景**：RLHF 奖励模型防 hack；自动评测系统的盲评协议；RAG 系统中检索证据与生成主张分离；科学计量中的预注册（防止观测改写假设）。
