## 【论文精读】OPD 的失配预算：训练-推理不一致到什么程度，在策略蒸馏才会"翻车"？

> **论文标题**：How Much Training-Inference Mismatch Can On-Policy Distillation Tolerate?
> **作者机构**：Aalto University（芬兰）、Nanyang Technological University（新加坡）、Independent、Beijing Institute of Technology（北京理工大学）、University of Cambridge（剑桥）、Shenzhen University of Advanced Technology（深圳理工大学）——Cong Yu 等，纯学术合作
> **发布时间**：2026 年 11 月 8 日
> **arXiv**：2611.11450（cs.LG）
> **开源代码**：https://github.com/benyucong/train-inference-mismatch-opd/

---

### 一、 论文背景

**先讲清楚 on-policy distillation（OPD，在策略蒸馏）是什么。** 大模型后训练里有一条越来越主流的路线：让一个学生模型自己写答案，再让一个固定的教师模型给每个 token 打分，学生朝着教师靠拢。形式化地说（式 1）：学生对每个 token 的 advantage 是 A_t = log p_T(y_t|y_<t) − log p_θ(y_t|y_<t)——教师觉得这个 token 比学生以为的更可能出现，advantage 为正，更新就推高它；反之压低它。教师是"标准答案的连续版本"，逐 token 给出细粒度反馈，不像 RL 只在整条回答结束时给一个 0/1 奖励。2026 年以来不少模型发布的后训练阶段都在跑 OPD（论文点名了 Xiaomi LLM-Core、NVIDIA 等流水线），阿里 ROLL 框架也把它做成了标准 pipeline（`token_level_rewards = -reverse_kl`，纯 KL 信号无外部奖励）。

**OPD 的成本瓶颈在 rollout。** 学生要学的回答必须先由学生自己生成（rollout），再由教师逐 token 打分——在 7B 学生上，这两步吃掉了每个训练步 76% 的时间。所以"更便宜的 rollout"直接等于"更便宜的 OPD"。工业界有两个标准加速手段：

1. **量化推理**：把 rollout 引擎的权重和 KV cache 存成 8-bit FP8 甚至 4-bit，同样显存能装更多并发回答；
2. **异步 rollout**：让生成跑在训练前面，trainer 不必等它——代价是 rollout 用的是几个版本之前的旧权重（stale weights）。

用一个类比来理解这对矛盾：OPD 训练像**学生做练习册、老师在旁边逐题批改**（rollout = 做题，教师打分 = 批改）。量化引擎相当于让学生用一支"略有磨损的笔"做题（字迹有点走样），异步相当于"老师手里拿的是学生三分钟前的作业"（不是最新进度）。两个都会让"学习的材料"和"当前的真实状态"之间出现偏差——偏差小无伤大雅，偏差大到什么程度会让学生越学越歪？这就是本文要量化的东西。

**但两个手段都引入同一个问题：训练-推理失配（training-inference mismatch）。** rollout 引擎跑的不再是"正在被训练的那个模型"——它是一个有些走样的副本。学生学习的回答，严格说不再是"它自己会生成的回答"。

**这个失配对 RL 是已知致命伤。** REINFORCE/GRPO 这类 on-policy RL 的更新只在对模型自身采样无偏时才成立，引擎的样本会带来系统性偏置；每次权重同步又把漂移复制回引擎，形成累积循环——已有研究（Zhong et al. 2026）表明连标准 vLLM 引擎的微小失配都能让 RL 崩溃。因此 RL 社区发展了两类对策：**精确匹配**（trainer 与引擎共享内核、逐位一致）和 **per-token 校正**（截断重要性采样、token 掩码、score centering）。生产级 OPD 流水线出于惯性把这些 RL 补救也照搬了过来。

**可是有三个线索暗示 OPD 对失配远没有 RL 那么敏感**：Semi-OPD 和 Lightning OPD 干脆用未训练学生的旧 rollout 蒸馏全程，效果居然不差；AsyncOPD 让生成领先很多个批次仍能达到同步训练的精度。这些是孤立的 anecdotes，没人量化过"OPD 到底能忍多少失配"。

**这就是本文的问题**：给 OPD 的失配容忍度做一个严格的测量学研究——能忍多少（预算）、伤害从哪来（机制）、怎么用这个容忍度省钱（工程）。一篇非常典型的"先问对问题，再给可操作的答案"的系统实证论文。

### 二、 论文定位和关联工作

这篇论文落在 **LLM 后训练系统 × 量化/异步推理基础设施 × 蒸馏理论** 的交叉点上，属于测量/实证研究（measurement study）而非新算法。先解释几个必要概念：

- **rollout 引擎（rollout engine）**：负责生成训练样本的推理引擎（如 vLLM），与 trainer（如 verl）是两套独立实现，各有各的 kernel 和数值细节——即使权重完全同步，两者的 next-token 概率也有微小差异。
- **held-out KL**：在留出问题集上，学生与教师的 per-token KL——衡量"学生学得像不像教师"，是本文的主指标。
- **失配预算（mismatch budget）**：OPD 能在不明显伤害训练质量的前提下吸收的最大失配——一个学生模型一个刻度。

相关工作的版图与本文的位置：

| 相关方向 | 代表工作 | 与本文关系 |
|---|---|---|
| RL 失配灾难与对策 | Zhong et al. 2026（RL 崩溃）；截断 IS、score centering、token 掩码 | RL 侧结论已知；本文证明这些补丁对 OPD 不仅无益反而略有害 |
| 精确匹配路线 | Thinking Machines、vLLM train-inference consistency、RadixArk | 从根上消灭失配，但需按模型/GPU 重建，无法覆盖量化与异步 | 
| 陈旧/固定 rollout 蒸馏 | Semi-OPD、Lightning OPD（一次性 rollout）、AsyncOPD、f-OPD、Near-Policy | 各自研究单一失配源的某个区间；本文提供统一刻度与预算框架，并反向解释了 Semi-OPD 为何有效（其等效失配 0.082 < 预算下界 0.184） |
| 量化 rollout | FP8-RL、NVIDIA NeMo RL FP8、SkyRL FP8 | RL 侧的量化栈，靠重要性采样续命；本文测的是 OPD 侧根本不需要这些续命手段 |
| 低比特 OPD | Low-bit OPD（量化学生） | 学生量化 vs 本文引擎量化，问题正交 |

**一句话定位**：第一篇为 OPD 建立"统一刻度的失配度量 + 经验失配预算 + 分钟级准入检查"三件套的工作，并配套机制级证明（不动点 + 前缀漂移分解）解释 OPD 与 RL 容忍度差异的根源。

从顶会评审视角预判（个人分析，非官方意见）：**新颖性高**——"失配预算"概念的统一刻度化（把 bit 宽、versions 数、权重噪声折算成同一个 nats/token 读数）加上预注册式的实验规则（判定阈值 τ=20%、bootstrap 检验在跑实验前定死），方法论在同领域实证研究中属于少见的高水准；但它不是新算法，且预算区间依赖具体学生与质量阈值、跨模型外推需要重新校准（1.5B 学生的反例论文自己就展示了），普适性受限。适合 ML 系统（MLSys/NeurIPS 系统 track）或实证科学风格（reproducibility/measurement）的 venue。

### 三、 问题定义

论文要回答三个层层递进的问题：

1. **容忍度有多大（预算）**：跨 rollout 引擎配置（量化 bit 宽、陈旧版本数、权重噪声水平）与学生模型（1.5B/3B/7B），OPD 能容忍多大的训练-推理失配而不损失训练质量？失配的来源不同，伤害是否可比？
2. **能否在训练前判断引擎安全（准入）**：检验一个候选引擎是否安全，目前需要一次 5.5-6 小时 × 8 GPU 的完整训练——能否压缩到分钟级的离线估计？
3. **失配如何伤害 OPD（机制）**：伤害发生在哪里？从 RL 继承的 per-token 校正（截断重要性采样、score centering）能否扩大 OPD 的预算？

其中"失配"本身需要一个操作化定义——这是第一个子问题：**量化用 bit 宽表示、异步用版本数表示、噪声用 σ 表示，三种来源没有天然可比性**，必须先统一到一个刻度上才能谈"预算"。

论文的做法（第 3.1 节）：把失配定义为 rollout 引擎 next-token 分布 q 与训练器学生分布 p_θ 之间的期望 per-token KL（式 2），在引擎实际访问的前缀上测量，单位 nats/token。D(c) 为配置 c 整个训练过程的失配水平（各步 d_n 的平均）。零失配 = 两个分布在所到前缀上完全一致。标准 BF16 vLLM 引擎（无量化、无陈旧）的基线失配仅 **0.0008 nats/token**——纯粹来自 kernel 与数值实现的差异。

**一个重要澄清**（论文反复强调）：trainer 会用学生自己的 log 概率重算 advantage（式 1），所以引擎失配改变的只是"哪些 token、哪些前缀被用于训练"，而不是"给定 token 在给定前缀处的 advantage 数值"——这个区分是第六部分机制分析的基石。

### 四、 问题解法

论文的方法论由三件套构成：统一度量、预算测定、准入检查；加上一套严谨的实验协议。

#### 4.1 统一失配度量与经验预算

**度量**：D(c) = 训练各步 d_n 的平均（式 2 的平均）。同一把尺子量量化（bit）、陈旧（versions）、噪声（σ）——论文发现 8 个版本陈旧仅 0.0028 nats/token，而全层 FP8 可达 0.56-0.68，**bit 宽和版本数单独都不预测伤害，统一刻度才行**。

三种失配源在同一刻度下的直观对比（7B 学生实测）：

| 失配源 | 配置 | D(c)（nats/token） | 相对标准引擎倍数 | 预算判定 |
|---|---|---|---|---|
| 基线（kernel 差异） | 标准 BF16 vLLM | 0.0008 | 1× | 通过 |
| 陈旧权重 | k=8 版本旧 | 0.0028 | 3.5× | 通过 |
| 量化（保首层） | vLLM FP8 cache + 首层 BF16 | 0.0037 | 4.6× | 通过 |
| 量化（全层） | Model Optimizer FP8 全层 | 0.56-0.68 | 700-850× | 失败 |
| 噪声（对照源） | σ=0.325 | 0.39 | 490× | 失败 |

这张表已经能读出论文的核心洞见：**"几 bit""几版旧"这类工程参数与安全与否没有直接映射——必须量失配本身**。同为"FP8"，保不保首层 KV cache 差了两个数量级；同为"走样的引擎"，噪声 0.39 失败而陈旧 0.0028 几乎无感。

**预算的判定协议**（预注册式，判定规则在跑实验前固定，附录 B）：

- 主指标：held-out KL 的相对变化 Δ(c) = K(c)/K(0) − 1（530 道留出数学题：AIME24 + MATH-500）；
- 失败判据：Δ(c) ≥ τ = 20% **且** 95% 问题配对 bootstrap 置信区间不含 0（重复运行间最终 KL 差异至多 1.5%，20% 阈值远高于噪声；标准训练把 7B 学生 KL 从 0.0965 降到 0.0481，20% 的回升约抹掉五分之一训练收益）；
- 次指标（不参与预算判定）：AIME24/25+AMC23 非重叠 28 题 × 16 采样的准确率掉 ≥5 点；
- **经验预算区间**（式 4）：B_emp(τ) = [所有通过配置的最大 D(c)，所有失败配置的最小 D(c)]——一个括号而非精确阈值，诚实标注"不保证上界以下的一切配置都安全"。

#### 4.2 准入检查（Admission Check）

预算测定本身需要多次完整训练，不可能为每个新引擎配置都来一遍。准入检查的流程（式 5、6）：

1. 候选引擎对 16 道数学题各生成 2 条回答（32 条响应，几分钟、单 GPU）；
2. 标准 BF16 引擎对同一批 token 重新打分，离线估计失配 D̂(c)（引擎 vs 标准引擎的 per-token 差异——注意不需要教师、不需要 trainer）；
3. 准入规则：α·D̂(c) < L 则放行（初设 α=1.5 安全边际、L=0.41 准入线，均来自先导实验：100 步先导发现训练中失配至多达到离线估计的 1.47 倍）；
4. 放行 ≠ 安全证明——训练中仍持续监控 d_n。

用类比说：**这像银行发信用卡前的风控评分**——不看完整还款历史（完整训练），用小额试探（32 条响应）估计信用（失配水平），加上安全边际后与授信额度（准入线）比较，放卡后仍然持续监控账单（训练中失配监控）。

#### 4.3 实验配置矩阵

- **学生-教师对**（3 对，2 个模型家族）：DeepSeek-R1-Distill-Qwen-7B → Skywork-OR1-Math-7B；DeepSeek-R1-Distill-Qwen-1.5B → JustRL-DeepSeek-1.5B；Llama-3.2-3B-Instruct → GT-Llama-3.2-3B-MATH。7B 上 17 个 rollout 配置（6 个量化 + 5 个异步 + 4 个噪声 + 2 个组合），1.5B/3B 补充 FP8 实验。
- **量化配方**：NVIDIA Model Optimizer FP8（权重+激活+KV cache）、NVFP4（4-bit 权重激活 + FP8 cache，Blackwell 上模拟仅测质量）、vLLM FP8 KV cache（权重激活保持 BF16）——各配方在全层与"首层 KV cache 保留 BF16"两种变体下测试。
- **权重噪声**：每次权重同步后给引擎加固定高斯偏移（σ ∈ {0.0665, 0.15, 0.234, 0.325} × 各投影矩阵标准差）——提供"可控旋钮"式的失配来源。
- **训练配方**：DAPO-Math-17k，每步 8 题 × 8 回答，温度 1，最长 16,384 token/回答，AdamW lr=1e-6，200 步/运行；vLLM 引擎 + verl 训练器；默认不开重要性校正与 score centering（第 6 节单独评估它们）。
- **硬件**：两节点 8 张 NVIDIA GH200。

### 五、 评估指标与实验证据

#### 5.1 主结果：7B 学生的失配预算 = [0.184, 0.39] nats/token

| 失配水平 D(c) | 结果 |
|---|---|
| ≤ 0.184（全部 12 个配置：量化首层 BF16 变体、陈旧 k≤8、噪声 σ≤0.15、FP8+异步组合） | 全部通过，Δ(c) 介于 −5.0% 到 +6.4%；最高的两个通过配置最终 KL 与标准运行差 <0.5% |
| ≈ 0.39（两个噪声配置 σ=0.325） | 失败，Δ(c) ≈ +23% |
| 0.56-0.68（全层量化含首层 KV cache FP8） | 失败，Δ(c) = +54%~+60%，准确率掉 3-5 点；全层 FP8 下 rollout 从一开始就几乎全错（图 1） |

**预算区间的读法**：0.184 是标准引擎失配 0.0008 的 **230 倍**（"超过 200 倍仍可容忍"）；0.39 约为其 2 倍处崩溃。阈值改为 τ=25% 时区间移动到 [0.39, 0.56]——预算依赖质量规则，不是模型固有常数。

#### 5.2 失配与伤害都依赖模型（不能外推）

- **1.5B 学生的反例**：同样的全层 FP8 失配 D=0.36-0.39（与 7B 失败水平相当），1.5B 的 Δ(c) 高达 **+420%~+479%**、准确率掉约 11 点——远比 7B 的 +23% 惨烈；但保留首层 KV cache BF16 后 Δ=−4.3% 通过。
- **3B 学生的正例**：Llama-3.2-3B 全层 Model Optimizer FP8 失配仅 D≈0.01、Δ=+5.6% 通过——Llama 无 key 投影偏置，结构上更不敏感。
- **敏感源定位**（很精彩的归因）：7B 上 FP8 KV cache 主导一切失配，其中**第一层 cache 占 93-99%**；DeepSeek 学生有 key 投影偏置且缺 QK 归一化，首层 keys 异常大——keys-only 模拟把该层 82% 的效应归因于首层 key 的舍入。修复方案自然浮现：**只把首层 KV cache 留在 BF16**，vLLM FP8-cache 的失配估计从 0.52 降到 0.0037 nats/token（约 140 倍改善）。

这个"首层异常"的架构解释值得展开：DeepSeek-R1-Distill-Qwen 系列保留了 key 投影偏置（Llama 与 Qwen3 原生则没有或做了 QK 归一化），偏置使首层 key 的幅值分布远离原点、对 FP8 舍入最敏感——一层 cache 的舍入误差经注意力传播被放大为整个引擎的分布漂移。它给"量化感知的模型设计"提了一个具体方向：**让关键归一化（QK-Norm）成为默认配置，低精度 rollout 的兼容性会大幅提升**；反过来，蒸馏自 DeepSeek 的模型在 FP8 rollout 场景下天然处于劣势，需要针对性配方。

#### 5.3 准入检查：8 发 8 中，成本 24 分钟 vs 44+ GPU 时

- 8 个训练前固定的决策（5 个来自离线检查）**全部命中**实测结果；通过组估计值 ≤0.030、失败组 ≥0.408，边界 L/α≈0.27 恰在两组之间。
- 成本：6 个配置的检查 24 分钟单 GPU；对比一次完整训练 5.5-6 小时 × 8 GPU。
- **诚实的局限记录**：训练中实际失配达到离线估计的 1.56-1.68 倍，超过了先导设定的 α=1.5；σ=0.325（D=0.39）的失败点低于先导准入线 L=0.41——即先验参数偏乐观，回溯设定 L=0.184 可保守化但仍非通用保证。

#### 5.4 预算内的效率收益（7B）

| 维度 | 结果 |
|---|---|
| 异步吞吐（updates/hour vs 同步 BF16） | k=1/2/4/8 → 1.24×/1.54×/1.62×/1.59×（k≥4 后 trainer 成瓶颈，饱和）；FP8+k=4 → 1.63×；k=8+FP8 → 1.55× |
| KV cache 容量 | FP8 ≥ **1.93×** BF16 的 token 容量；1,536 序列/步的大批量下 BF16 被迫逐出重算，vLLM FP8 cache → 1.11×、Model Optimizer FP8 → 1.16× 吞吐 |
| 时间到质量 | FP8+k=8 达到同步 BF16 的 step-200 held-out KL 快 **1.62×**（3.69h vs 5.98h，最终 KL 0.047602 vs 0.047643，准确率 60.5% vs 61.5%）；90% 改善目标下 FP8+k=4 快 1.69× |

#### 5.5 OPD vs RL：同一引擎，生死之别

在 OPD 通过的 3 个配置上跑 REINFORCE/GRPO（同一 7B 学生、0/1 奖励、无教师）：

- **REINFORCE 三连崩**：噪声 σ=0.15（D=0.097）奖励归零、准确率掉 21 点；NVFP4+首层 BF16 长度爆炸掉 59 点；FP8 首尾层 BF16 掉 63 点。
- **GRPO 崩 2/3**：噪声与 NVFP4 崩（熵塌缩/长度爆炸），FP8 首尾层 BF16 通过。
- 换算成倍数：**OPD 容忍 >200× 标准引擎失配；REINFORCE 约 12×、GRPO 约 60× 即失效**。
- 排除混淆：RL 起始失配与 OPD 相当（0.88-1.02×），前 100 步权重移动幅度更小（0.43-0.90×）——不是"RL 动得多所以坏得快"。
- **score centering 能救 RL**（REINFORCE +61 点、GRPO +16.5 点），但对 OPD 无益。

三种方法在同一组引擎下的生死对照表（7B 学生，200 步）：

| 引擎配置（D, nats/token） | OPD | GRPO | REINFORCE |
|---|---|---|---|
| 噪声 σ=0.15（0.097） | 通过 | 崩（准确率掉点，回答顶到长度上限） | 崩（奖励归零，掉 21 点） |
| NVFP4 + 首层 KV cache BF16（~0.02） | 通过 | 崩（熵塌缩，掉 15 点） | 崩（长度爆炸，掉 59 点） |
| FP8 + 首尾层 BF16（~0.013） | 通过 | 通过 | 崩（奖励近零，掉 63 点） |
| 全层 FP8（0.56-0.68） | 崩 | 崩 | 崩 |

这张表读出一个实用的推论：**"引擎安全阈值"是训练方法的属性而非引擎的属性**——同一个引擎配置，REINFORCE 全灭、GRPO 活一个、OPD 全活。反过来，任何关于"量化 rollout 是否安全"的讨论若不指明训练算法，都是不完整的。

### 六、 效果优势的根源解释

本文的核心贡献是把"OPD 比 RL 耐失配"从直觉提升为定量规律，并解释到机制层。因果链如下。

**主因果链：方法差异 → 机制变化 → 指标差异**

- **方法差异**：OPD 的 advantage 是教师-学生对数比 A = log p_T − log p_θ（逐 token、随训练收缩到 0）；RL 的 advantage 基于常数奖励 R（整条回答一个分，不随模型变好而消失）。
- **机制变化**（式 7 + 附录 D.2）：失配 δ = q − p_θ 引入的梯度偏置满足 ‖g_bias‖ ≤ 2‖δ‖₁‖A‖_∞——**当学生逼近教师时 A→0，偏置无论引擎多差都自动消失**；固定点分析证明"匹配教师"是任意引擎下的驻点（期望梯度恰为 ½E[(log p_θ − log p_T)²] 的梯度，Hessian 半正定）。RL 的误差是 R·δ，R 不收缩，且每次权重同步把漂移累积回引擎形成正反馈。
- **指标差异**：OPD 在 200× 失配下 held-out KL 不变，REINFORCE/GRPO 在 12×/60× 崩溃——上面的机制差异直接预测了这个数量级差距。

一个补充实验排除了替代解释：**漂移的方向性不是保护来源**。OPD 的负漂移系数使学生"远离引擎"（越练离走样副本越远），有人可能猜是这种"逃离"方向在保护训练。论文做了反事实：给 advantage 加常数 b=+0.15/+0.5 把漂移系数翻成正（学生向引擎靠拢，模拟 REINFORCE 的情形），held-out KL 反而比标准运行还低 6.5%/6.9%——说明**保护来自"误差随目标达成而消失"的结构，而非漂移符号**。

**为什么预算仍有上限（失配怎么伤害 OPD）**：分解失配误差为两部分——**per-token 误差 T**（引擎在所到前缀上概率不同）与**前缀漂移 S**（引擎到达了不同的前缀）。从通过水平（σ=0.15）到失败水平（σ=0.325），S 增长 5.3× 而 T 仅 2.1×——**伤害主要由 S 驱动，而 S 是 per-token 校正够不着的**（它们只作用于被采样 token 上的 T）。论文甚至估算了覆盖 S 需要的重加权代价：约 10²⁷ 条回答/有效样本——宇宙级不可行，所以"把失配控制在预算内"是唯一现实解。这解释了第二个发现：**截断 IS（step 100/200 使 KL +2.9%/+7.0%）和 score centering（KL +2.3%~+3.7%）对 OPD 都略有妨害**——它们修的问题（T）不是主要矛盾，却引入了估计噪声。

T 与 S 的区分可以用一个比方：你在按导航开车去目的地（训练到教师）。

- **T（per-token 误差）**：每个路口你转向的角度略有偏差——重要性采样这类 per-token 校正相当于"每转一次方向盘就修正一次角度"，理论上能压住。
- **S（前缀漂移）**：某次走错了一个路口，之后的整条路线都变了——你在完全不同的街道上做后续修正，逐路口的修正逻辑根本"看"不到这层偏差。

从通过到失败，路线偏差（S）的增长（5.3×）远快于转向偏差（T）的增长（2.1×），而手里的工具只能修转向。

**为什么晚期训练更脆弱**：训练到 step 200 时误差本身缩到初期的 0.11-0.13，但更新信号缩得更快（误差/更新比从 0.93 升到 1.88）——**失配的相对影响随训练推进而放大**，预算是全程约束而非仅起点约束。

**工程因果链**：统一 KL 刻度 + 准入检查把"哪个引擎安全"的判断从 6 小时训练压缩到分钟级离线估计 → 可以放心叠加 FP8（≥1.93× KV 容量）与异步（消除等待）→ 时间到质量 1.62×。反向应用同样成立：Semi-OPD/Lightning OPD 的等效失配 0.082 落在预算内，其成功被理论解释而非反常。

把两条链合并成一张总表：

| 问题 | 方法答案 | 机制解释 | 数值锚点 |
|---|---|---|---|
| 能忍多少？ | 统一刻度 + 预算区间 | 教师锚定不动点 | 7B：[0.184, 0.39]，200× 通过 / 490× 失败 |
| 为何 RL 不行？ | 同引擎对照实验 | R 不随训练收缩 + 同步累积漂移 | RL 在 12×/60× 崩溃 |
| 伤害从哪来？ | T/S 误差分解 | 前缀漂移 S 主导且校正不可达 | S 增 5.3× vs T 增 2.1× |
| 怎么省钱？ | 准入检查 + 敏感层定位 | 首层 KV cache 占失配 93-99% | 首层保 BF16：0.52→0.0037 |
| 省了多少？ | 预算内最优组合 | FP8 供容量 + 异步供吞吐 | KV 容量 1.93×；时间到质量 1.62× |

#### 6.1 外部检索交叉验证

**（1）OPD 的失配敏感性确实低于 RL——多个独立来源一致。** RL 侧：FP8-RL（https://www.chatpaper.ai/zh/dashboard/paper/fa8d8032-100b-42b1-bea8-35362165c492）报告 RL 中 FP8 rollout 的失配"可能引发训练-推理失配与不稳定"，需要重要性采样校正（TIS/MIS）兜底；NVIDIA NeMo RL 的 FP8 实践（https://developer.nvidia.cn/blog/run-high-throughput-reinforcement-learning-with-end-to-end-fp8-precision/）同样靠端到端 FP8 + 重要性采样才把准确率差距抹平——**RL 侧的共识是"量化 rollout 必须配校正"，本文的 OPD 侧结论是"校正反而略有害"，两者互补而非矛盾**。SkyRL 的 FP8 方案（https://www.plushcap.com/content/anyscale/blog/anyscale-fp8-reinforcement-learning-in-skyrl-preserving-policy-consistency-across-training-and-rollout）走"精确匹配"路线（同步后逐位一致的 FP8 权重载荷），在 400 步 DAPO 上匹配 BF16 曲线——这正是本文说的"从根上消灭失配"方案，代价是无法享受异步收益、且需按模型重建。

**（2）"per-token 监督有覆盖不到的盲区"被长程 agent 蒸馏工作独立印证。** AACL 2026 的 CHOP 论文（https://aclanthology.org/2026.aacl-long.167）发现长程 agent 的 OPD 在教师仍有序列级区分力（AUROC≈0.75）时，token 级梯度对齐度从 0.71 衰减到 0.09、标准 OPD 只能收回 1.3% 的师生差距——与本文"前缀漂移 S 是 per-token 手段够不着的误差源"在精神上高度一致：**误差发生在"走到哪些状态"层面，而 per-token 手段只修"状态处的概率"层面**。差别在场景：CHOP 针对工具调用导致的状态分布外漂移，本文针对引擎失配导致的前缀漂移，两者是同一枚硬币的两面。

**（3）OPD 的工程价值被工业界采用进度佐证。** 阿里 ROLL 框架已将 OPD 做成官方 pipeline（纯 OPD 与混合 OPD 两种模式，https://alibaba.github.io/ROLL/zh-Hans/docs/User%20Guides/Pipeline/on_policy_distill_pipeline_start），支持 RLVR 与 Agentic 两种配置——说明"rollout 成本主导 OPD 训练时间"是普遍痛点，本文的失配预算直接可用于这类系统的量化/异步决策。ActionOPD（HF papers 2610.19820）等后续工作则在动作粒度上重新定义 OPD 的监督单位，与本文的"统一刻度"思路互补。

**（4）相反/边界证据：预算不可跨模型移植，论文自己就提供了最强反例。** 1.5B 学生在 D=0.36-0.39（7B 的邻界区）出现 +420% 的灾难，而 3B Llama 全层 FP8 几乎无感（D≈0.01）——失配的产生量与伤害的敏感度都是模型属性（QK 归一化、key 偏置的存在与否）。这意味着"FP8 rollout 安全"没有模型无关的答案；第三方摘要（Paperium 对本文的评述，https://paperium.net/article/shop/26970/how-much-training-inference-mismatch-can-on-policy-distillation-tolerate）也强调了同样的边界："校准的阈值依赖模型、配方与层，准入检查是筛选工具而非形式化保证"。此外，本次检索范围内未发现对"教师锚定不动点"论证本身的质疑性工作；检索到的相关工作均与之相容。

### 七、 必要知识反推

要真正读懂并复现这篇论文，需要倒推补齐以下知识：

**数学侧**：

1. **策略梯度与 advantage**：∇J = Σ_t A_t ∇log p_θ(y_t|y_<t) 的含义；REINFORCE 的响应级奖励 vs OPD 的 token 级教师对数比（式 1）——两者共享更新形式、只差 advantage 来源，这是全文对比实验的公理基础。
2. **KL 散度的 nats 单位与期望形式**：为什么用 per-token 期望 KL 而不是总 KL；为什么在"引擎访问的前缀"上测（分布差异要在采样分布下才有梯度意义）。
3. **不动点/驻点与 Hessian 半正定**：附录 D.2 的证明骨架——期望 OPD 梯度等于某势函数梯度、教师匹配点是驻点、且该性质与引擎无关。
4. **重要性采样与截断**：RL 处理 off-policy 的标准工具；为什么它能修 per-token 偏差（T）但概念上无法触及前缀分布变化（S）；方差爆炸使其在高维长序列上不可行。
5. **bootstrap 置信区间与配对检验**：预注册判定规则（Δ≥20% 且 95% CI 不含 0）的统计含义；为什么重复运行间 1.5% 的波动决定了 20% 是个"远离噪声"的阈值。

**系统侧**：

6. **训练-推理双引擎架构**：vLLM（rollout）与 verl（trainer）为何数值不一致（kernel 融合顺序、归约顺序、精度差异）；权重同步（weight sync）在异步训练中的时序。
7. **FP8/NVFP4 量化**：权重/激活/KV cache 各自的量化粒度（per-tensor vs blockwise）；KV cache 量化为什么对首层异常敏感（QK 归一化缺失 + key 投影偏置 → 首 layer key 幅值大 → 舍入误差占比 82%）。
8. **异步 RL/OPD 的 staleness**：k versions old 的含义；为什么 k≥4 后 trainer 成为吞吐瓶颈（rollout 已不在关键路径上）。

**领域侧**：

9. **蒸馏谱系**：offline SFT → offline distillation（教师数据）→ online/on-policy distillation（学生自采+教师打分）→ semi/lightning OPD（一次性 rollout 复用）的演化逻辑与各自失配特征。
10. **评测集**：AIME24/25、MATH-500、AMC23、DAPO-Math-17k 的角色（训练集 vs held-out）。

### 八、 通用性灵感

这篇论文的价值远超 OPD 训练本身，几条可迁移的思想：

1. **"先统一刻度，再谈权衡"**。量化用 bit、异步用版本数、噪声用 σ——不可比的干预维度一旦折算到同一把尺（nats/token），"预算"这个概念才能成立。任何系统优化问题（延迟 vs 一致性、压缩 vs 精度、缓存 vs 新鲜度）都可以问：**我的统一刻度是什么？我的预算是多少？** 没有统一刻度的"A 比 B 好"都是修辞。

2. **预算是区间不是阈值，是模型属性不是普适常数**。B_emp = [0.184, 0.39] 明确标注了"通过与失败之间未经测试"；1.5B/3B 的反例证明外推需重新校准。工程上对应一个成熟习惯：**安全边界标注其标定条件**，而不是给出一个看起来普适的数字。

3. **预注册判定规则是实证研究的金标准**。τ=20%、bootstrap CI、失败判据全部在跑实验前写死（附录 B）——这避免了"看完结果再挑显著性好讲"的科研最常见偏误。做任何 A/B 实验前先固定成功标准，这个习惯的价值怎么强调都不过分。

4. **"机制诊断先行"的省钱路径**。首层 KV cache 占 93-99% 失配 → 只把首层留在 BF16 → 140 倍失配改善，几乎零成本。**全局换 BF16 是工程直觉，单层定位是测量科学的红利**：先找到敏感瓶颈，再精准修复，避免"要么全量要么不干"的二极管决策。

5. **从相邻领域继承的补丁要重新论证**。RL 的截断 IS/score centering 被 OPD 流水线"惯性采用"，本文证明它们对 OPD 有害无益——因为两者的误差结构不同（T vs S 主导）。**移植方法论时，先问"它修的问题在我这里是主要矛盾吗"**，这个思维检查点在跨领域借鉴中几乎处处适用。

6. **不动点思维评估训练系统的鲁棒性**。判断一个扰动是否致命，问两个问题：扰动引入的误差会不会随目标达成而自动消失（A→0 则偏置→0）？扰动会不会经反馈回路累积（RL 的权重同步循环）？**"误差消失的目标 + 无累积的路径"= 鲁棒**——这个框架适用于任何带反馈的学习系统。

7. **区分"哪些 token 被看到"与"token 上的分数对不对"**。trainer 重算 advantage 意味着引擎失配只改变训练数据的分布（前缀），不改变逐点标签——这个清晰的概念分离是全文机制分析的支点。一般化地：**当一个系统的输入分布与标签来源可以解耦时，扰动的影响分析要分别讨论两者**。

8. **分钟级代理检查 + 训练中持续监控，代替昂贵全量验证**。准入检查的架构（离线估计 + 安全边际 + 准入线 + 在线监控）是一个可以直接复用的模式：任何"完整验证太贵、不验证风险太大"的场景（模型上线前评估、基础设施变更、数据管道切换）都适用——**用廉价代理缩小实验空间，用监控兜住代理的盲区**。

9. **读论文时留意"反直觉的负结果"**。本文最容易被忽略却最有信息量的发现之一是：从 RL 继承的校正手段对 OPD 略有害（+2.3%~+7.0% KL）。负结果往往比正结果更精确地划定了机制的边界——"什么没用"与"为什么没用"合起来才是完整的科学故事。

---

**给实践者的操作摘要**（从论文流程提炼）：换新学生模型时——

1. 跑 2-3 个代表性训练运行（含一个全层量化、一个标准引擎），按预注册规则定出该学生的预算括号与准入线；
2. 对每个候选引擎配置做离线准入检查（16 题 × 2 响应，分钟级、单 GPU，无需教师与 trainer）；
3. 放行 α·D̂(c) < L 的配置，敏感层（如首层 KV cache）优先保留 BF16；
4. 训练全程监控 d_n——训练中失配可能涨到离线估计的 1.5-1.7 倍，越界即回退；
5. 晚期训练最脆弱（误差/更新比随训练上升），不要因前 100 步平稳就放松监控。

**总结**：这篇论文把"OPD 能容忍多少训练-推理失配"从一个模糊的工程直觉变成了一套可测量的制度：统一刻度（nats/token）、经验预算（7B 上 [0.184, 0.39]，约为标准引擎的 200-500 倍）、分钟级准入检查（8 决策全中、成本仅为完整训练的 1/400）、机制解释（教师锚定不动点 + 前缀漂移主导的伤害）、以及立即可用的工程红利（FP8 首层 KV cache 保 BF16 + 异步 k=4-8 → 1.62× 时间到质量）。它同时诚实标注了所有边界：预算不可跨模型外推、准入不是保证、晚期训练更脆弱。对任何在做 LLM 后训练基础设施的团队，这是一篇"读完就能改流水线配置"的论文。
