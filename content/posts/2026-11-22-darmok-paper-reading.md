## 一、论文背景

**英式密码填字（cryptic crossword）是什么？** 美式填字的线索是一个直接的语义或百科问题，比如「秘鲁的首都」直接对应 LIMA。而英式密码线索是**一段同时支持两套语法的双重规格**：按标准英语读，它是一句通顺但故意误导人的话（surface reading，表面读法）；按「填字英语」的组合规则读，同一段文字会在一个未标记的边界处切开成两部分——一个**定义**（几乎总在线索首或尾）和一个可执行的**字谜运算表达式**（回文、字谜重组、容器嵌套、删字母、同音、Spoonerism 等约十几种字符串操作算子的嵌套 AST），两者必须求值出同一个答案串。论文给出一个入门例子：

> 「Note invested in aluminium raised capital (4)」→ LIMA

表面读法是一句财经句子；字谜解析则是：Note→唱名 MI（音阶缩写）、aluminium→化学符号 AL、invested in→容器插入得 A[MI]L、raised→Down 方向反转，得 LIMA；定义 capital 指秘鲁首都。系统名 Darmok 取自《星际迷航：下一代》同名剧集——一个用寓言式表面语法掩盖组合式指称的外星种族，正是密码线索的绝妙隐喻。

**为什么难？** 两个结构性原因：

1. **双重语法对抗语义检索**。表面读法主动误导直接检索；无交叉字母时让 LLM 输出 top-K 候选，正确答案几乎全落在 rank 1–2（论文 324 次试验中 96/99 的正确命中在 rank≤2，rank 3–10 合计只贡献 3 个）。
2. **网格拓扑稀疏**。美式网格每个白格都被横竖两个词同时检查（100% checking）；英式 15×15 blocked 网格中每个词 40%–50% 的字母位置完全不被交叉约束（占全部白格 61.3%–65.0%）。交叉几何救不了解析不了字谜的求解器——一个错字母落在未检查格上，垂直方向毫无纠错能力。

**锦标赛规则把难度推向极端**。时报填字锦标赛（1970 年起办，伦敦）采用字典序评分：**先看零错误，再看速度**——一个错格或空格会让穿过它的所有线索判错，有任何一错的网格排在所有全对网格之后，无论多快。按独立线索精度粗算：每线索 97% 准确率的求解器，一次产出 30 线索全对网格的概率只有 0.97^30 = 40.1%。2026 年第 55 届锦标赛的真实数据说明了这条帕累托边界多么无情：资格赛第四快的选手因 89/90 掉到第 61 名；决赛中最快的完赛者 Chloe Hutton（8m09s）因一错只列 29/30，冠军属于最快全对者 Liam Hughes（10m05s）。

**LLM 求解现状**。单线索基准（Cryptonite、Decrypting）早已确立这是严峻的推理挑战，但此前没有任何自动系统在真实锦标赛时钟下接近冠军级全网格求解。与此同时，前沿模型的单线索能力持续上升，但云 API 会停滞、超时、触发安全拒绝、陷入推理循环。这就构成了论文的背景张力：**能力不是瓶颈，可靠性才是**。

## 二、论文定位和关联工作

### 2.1 美式填字求解谱系（对照系）

- **Proverb（1999）/ WebCrow（2005）/ Dr.Fill（2011）**：加权约束满足 + 概率推理。核心依赖美式网格的两个性质——100% 检查、直接线索的高召回冷候选检索（top-10³ 召回 95%–99%）。
- **Berkeley Crossword Solver（2022）**：神经检索 + 概率置信传播，在美式锦标赛达超人类。

英式密码填字**同时违反这两个性质**（稀疏网格 + 组合字谜导致候选快速衰减），因此这条谱系的技术无法直接迁移——这是英式密码二十多年保持「AI 保留地」的原因。

### 2.2 英式密码单线索谱系（前作）

- **Lacross（1977–79）/ Crossword Maestro**：规则文法分解单步字谜。
- **Cryptonite（EMNLP 2021）/ Decrypting（NeurIPS 2021）**：大规模单线索基准，证明 seq2seq 难以泛化到未见过的字谜组合。
- **LLM 单线索评估（Sadallah et al. 2024/2025；Saha et al. 2025）**：测试各类提示策略。
- **符号验证路线（Andrews & Witteveen 2024/2025）**：让 LLM 合成 Python `proof()` 函数验证字谜推导——论文第 4.4 节对其做了审计复现（详见第五部分），是其放弃的路线。
- **统计物理视角（Hartmann, PRE 2024）**：证明交叉约束会在单词解题概率上升时诱发解出簇的渗流相变——为「交叉字母放大机制」提供了理论侧写。

### 2.3 本文自身谱系与复合 AI 系统

- **2025 V1（作者前作，参加 2025 年锦标赛）**：单模型贪心增量准入，测试集 82.1%。论文对其做了「病理学解剖」（见第四部分）。
- **分布式容错经典**：N-version programming（Avižienis 1985）、RAID（Patterson et al. 1988）、The Tail at Scale（Dean & Barroso 2013）、active-active 复制（Schneider 1990）、纠错内存（Hamming 1950）——论文明确把 Darmok 定位为这些思想在 LLM 编排上的投影。

### 2.4 定位总结

| 维度 | 之前的状态 | Darmok 的突破 |
|---|---|---|
| 求解范围 | 单线索基准 / 美式全网格 | 英式密码**全网格** + 真实锦标赛时钟 |
| 可靠性目标 | 平均精度 | 字典序目标：零错误优先、速度其次 |
| 系统形态 | 串行启发式链 / 单次调用 | 并行多席位 + 同步屏障 + 非驱逐后备 |
| 核心论点 | 「能力靠模型」 | 「能力普及后，瓶颈转移到最坏情形韧性」 |

**定位结论**：这是第一个在英式密码填字上达到冠军级人类水平（且快于所有人类选手）的自动系统；更重要的是，它把「复合 AI 系统何时需要冗余」从一个工程直觉提升为有对照实验支撑的科学论断。

## 三、问题定义

**从具体场景出发**：在锦标赛现场，吃进官方 PDF、在时钟内交出锁定网格。目标函数是字典序的：P(全网格零错误) 优先，E[完成时间] 其次。

**核心洞察——论文发现的深层结构相似性**：英式密码填字的网格求解 ≈ 在**不可靠但能力足够的分布式组件**上做约束传播。三个对应：

| 填字世界 | 分布式系统世界 |
|---|---|
| 线索 i 的求解（30 路并行请求） | 并行 RPC 到重尾延迟端点 |
| 交叉字母一致性（a_i[p_ij] = a_j[p_ji]） | 共享状态上的写冲突 / 一致性约束 |
| 提供商降速、超时、安全拒绝、token 循环 | 组件部分失效（partial failure） |
| 冗余席位 + 后备层 | N-version 编程 / RAID / active-active 故障转移 |
| pass barrier 处整网格重建 | 同步屏障 + 无冲突快照（Jacobi 式迭代） |

**形式化问题定义**：给定线索集 I、每个线索在给定上下文（交叉字母模式）下的条件解题率 p_i(·|pattern)、以及各席位 API 的可用性/延迟/失败模式分布（重尾、相关或无关），设计一个编排策略，最大化 P(所有线索正确且无空格)，约束在时间预算 T 内完成；且该策略必须在不接触 ground truth 的运行时工作。

**为什么这个抽象精妙**：

1. **复合概率把问题推到尾部**。0.97^30 = 40.1% 说明：平均精度再高，网格级目标也会被尾部错误主导。优化对象天然是「最坏情形」而非「平均情形」。
2. **它分离了两类失败**：认知失败（答案错，模型间相关——两个模型常错向同一个诱饵）与运营失败（超时/拒绝/网络，模型间不相关——Gemini 降速时 Claude 正常）。前者靠交叉验证与准入门槛，后者靠冗余故障转移。混同两者就会误配机制。
3. **为什么必要**：如果把问题定义成「提高单线索精度」，就会走向提示工程或更大模型——而论文第 4 节用 9,260 次对照调用证明这条路在此任务上已饱和；把问题定义成「尾部韧性」才会导出后面的架构。

## 四、问题解法

Darmok 的总架构一句话：**把全网格求解组织成迭代同步的约束收紧循环，类比经典弧一致性传播，但跑在异步、重尾的推理 API 上**。下面按组件拆解，每个组件讲清输入/输出与类比。

### 4.1 三席位并行求解（per-clue seats）

三个异构前沿模型席位并行求解所有未解线索：

| 席位 | 模型 | 置信地板 τ | 超时上限 | 输出 token 预算 |
|---|---|---|---|---|
| Anchor | gemini-3.1-pro-preview | 50 | 90s（硬） | 11,378 |
| Peer | claude-fable-5 | 85 | 150s | 20,000 |
| Third | gpt-5.6-sol | 50 | 150s | 13,652 |

每个席位的每次响应 (m, a, c) 要成为**合格提案**需满足：状态 ok、答案长度匹配线索 enumeration、自报置信 ≥ τ_m。

**为什么参数异构（第 3.4 节校准实验）**：Gemini 的自报置信是二值的（99.8% 落在 [90,100]），τ=50 实际不筛人；但它的 90–180s 长尾只有 38.2% 准确率且中位置信仍是 99——「卡得越久越胡说」，所以硬砍 90s。Claude 相反：置信曲线平滑且在 85 处有陡坎（[80,89] 桶 84.7% vs [90,100] 桶 99.5%），且 90–150s 深推理尾巴有 91.7% 准确率——所以置信地板 85 + 宽松超时 150s。**类比**：给不同员工配不同的「复查门槛 + 最大思考时间」，依据是其各自的「自信-准确」校准画像，而非一刀切。

### 4.2 同步 pass-barrier 准入递推（Algorithm 1，rebuild-from-kept）

这是论文的算法核心，用来替代 V1 的贪心增量准入。

**V1 的两大病根**（先看它治什么）：

1. **到达顺序随机性 + 级联错误**：API 返回快慢不一，谁先回来谁先写入网格；一个快速返回的自信冷错误把假字母注入垂直线索，后续重试全部条件在假约束上。
2. **部分覆写**：冲突消解在单格粒度而非整词粒度。真实案例（Times #29570）：两个模型冷猜出诱饵 anagram REPOSITED（真值 REDEPOSIT），后续高优先级 Down 答案逐格覆写共享交叉位，把 21A 的格子改成了非词 REDOPISET，而 21A 内部状态仍标记为「已解」。

**Algorithm 1 的做法**：每轮 dispatch 结束后设一道**屏障**（barrier），在屏障处一次性完成准入评分：

1. **提案池化**：本轮新提案 S(t) 与上一轮保留集 K(t−1) 合并为断言集 A(t)。
2. **基础分**：b=2（Anchor 提出或 ≥2 席一致——「冷共识」直接够格）；b=1（孤立的 Peer/Third 提案——空网格上压住不放）。
3. **Jacobi 式交叉支持分**：s = clip[0,6]( b + Σ_j ±w(σ_j^(t−1)) )，对每个活跃交叉 j：字母一致则加、冲突则减，权重取 j **上一轮**的资历 w（out/tentative/supported/locked = 0/1/2/3）。
   - **类比**：Jacobi 迭代 vs Gauss–Seidel——用邻居的**上一步**状态而非本步状态打分，使整个评分严格顺序无关、不需要内层循环，且同轮内两个未经审查的猜测无法互相「抬轿子」通过准入（两个 b=1 的同轮猜测互评时对方权重是 0，1+0=1<2 进不来）。
   - **正面例**：Pass 0 已保留 1A TAPE-RECORD（w=1），Pass 1 Claude 单独提出 2D PAUPERIZE（b=1），在交叉位 P 上与 1A 一致，s = 1+1 = 2 ≥ θ 准入——「孤立好答案被已验证的邻居捞起来」。
4. **严格占优保留规则（θ=2）**：s≥2 且严格高于每个冲突交叉对手才准入。平分则双双落回待解集——**整词级干净驱逐**：被驱逐的词完整消失、带更新后的交叉模式重新求解，杜绝部分覆写。
5. **整网格从零重建**：清空网格，只写 K(t)——因为平分不可能同时通过严格不等式，K(t) 构造性无冲突（Invariant 3.1），重建顺序无关、无部分词污染。

**输入/输出**：输入 = 本轮所有 API 响应 + 上轮 (K, σ)；输出 = 新保留集 K(t)、无冲突网格 G(t)、更新后的交叉字母模式（如 P?U?E?I?E）供下轮重试。**离线回放 135 天日志的收益**：+34 线索（3,804→3,838）、错误网格 10→4、REDOPISET 类污染清零；40 个难题的在线配对测试 +18 线索、空格 33→15、API 成本 −41%、时间 −27%。

### 4.3 迭代约束收紧管线

围绕 Algorithm 1 的轮次编排：

| 阶段 | 内容 | 关键细节 |
|---|---|---|
| Pass 0 冷启动 | 全 30 线索全通配符（??????）发 Anchor+Peer | 33 并发/席 + 150ms 错峰，防 socket/DNS 突发 |
| Pass 1–3 交叉重试 | 带交叉模式 + 词典候选提示（1–100 命中才附）发全部三席 | Retry-Once 门：模式没变就不重发；含本席上轮尝试做自我纠错 |
| Pass 4 历史答案 | 匹配 1–100 条**严格日期过滤**的历史时报答案作非绑定提示 | 防泄漏：只用目标谜题发布日之前的答案 |
| 尾轮重派发 | 模式再变化时至多 2 轮裸模式重试 | 收敛即停 |

**类比**：像数独玩家的「排除法循环」——每锁一个词就给邻居多几个已知字母，难题在 2–3 轮内被「挤」出来。实证（第 4.1 节）：≥3 个已知交叉字母时单席解题率跳升 +33~50 个百分点（Gemini 74.8%→93.6%，三席 oracle 并集 98.1%；≥4 时 100%）——**交叉字母是第一推理放大器**。

### 4.4 非驱逐后备层（容错尾部）

两道**只填空、永不覆写**已准入答案的防线：

1. **异步全网格 boundary feed（gpt-6-astra）**：解题开始即异步启动，单提示喂整个谜题；只在屏障处轮询其输出文件。填空条件：长度匹配、置信 ≥80、与所有已填交叉位一致。
2. **本地终端链**（零 API 调用的确定性收尾）：corroborated singleton（模型提过且词典模式唯一）→ cross-pass persistence（跨轮复现）→ anchor fallback（≥50 的 Anchor 历史提案且仍与交叉一致）→ dictionary sweep（词典/历史/合并词表填充剩余空位）。

**为什么 sweep 是弱占优策略**：锦标赛规则下空格与错格同罚，一个尊重全部交叉字母的未验证猜测不损害任何已保留词、只要词表命中精度 >0 就严格提升期望得分（E2 期间 3 空转对 1 错）。

### 4.5 三副本 active-active 竞速

决赛配置启动 D=3 个并行副本，**先完成者提交**（竞速而非多数投票），副本间用 SHA-256 种子置换派发顺序（不同副本让不同线索占据最早的派发槽）。**类比**：hedged RPC 的思想——对冲重尾延迟。

### 4.6 全景小结

| 组件 | 对应经典机制 | 输入→输出 | 作用 |
|---|---|---|---|
| 三席位 + 合格提案 | N-version 多样性 | 线索 → 候选 (a, c) | 失败模式不相关的冗余源 |
| Algorithm 1 屏障准入 | Jacobi 迭代 + 乐观并发控制 | 提案池 → 无冲突保留集 | 消除顺序随机性与级联错误 |
| 交叉重试 Pass 1–3 | 弧一致性传播 | 收紧模式 → 更高解题率 | 候选空间坍缩的主要引擎 |
| boundary feed + 终端链 | RAID 热备盘 / 分级降级 | 残余空位 → 填充 | 只填不覆写的尾部兜底 |
| 三副本竞速 | hedged request | 三副本 → 最快者 | 压尾延迟 |

## 五、评估指标与实验证据

### 5.1 指标体系

- **主指标**：线索准确率（全网格逐线索对错）与 **perfect grid 率**（字典序目标的第一优先级），加**中位解题时间**（第二优先级；用中位数因为屏障超时让延迟右偏）。
- **辅助指标**：席位归因（first-to-correct / unique solve）、Pass 0 静默率（超时+错误+解析失败占比）、非 Anchor 提交占比。
- **统计纪律**：预注册消融噪声阈值、McNemar 配对检验、Clopper–Pearson 置信上界（诚实处理 7/7 的小样本：7 谜题上界 ≤34.8%，所以主要可靠性证据压在 43 天 E2 日常记录上）。

### 5.2 数据集与语料（为什么有区分力）

| 语料 | 规模 | 设计意图 |

### 5.4 单发基线：平均平价 + 双峰尾部风险

7 谜题×3 抽样的单发整谜题基线（每模型 21 次）：gpt-6-astra **21/21 全对**（中位 4m32s）；claude-fable-5 19/21（2 次安全拒绝直接 0/30，中位 14m54s 慢于人类）；gpt-5.6-sol 16/21（3 超时 + 1 次 HTTP 520）；gemini-4-argon 15/21（6/21 陷入 32k token 循环得 0/30，65k 上限的 9 次难题抽样 7/9）；gemini-3.1-pro 7/21。

**关键读法**：每个单发模型各有自己「全对很快但偶发 0/30」的尾部失败模式，且模式互不相同——这为第六部分的因果链埋下伏笔。

### 5.5 消融：平均情形 vs 尾部情形的背离

**留一消融（16 谜题测试集，安静条件）**：去掉交叉重试 −13 线索（唯一超噪声项）；去掉次席/历史 pass/全网格 feed 各 −1~0；甚至把三席换成 Anchor 单席 + feed，仍 461/463 平价（只是慢 ≈1 分钟）。**表面结论：整个系统像个过度工程的 Rube Goldberg 机器。**

**2×2 因子消融（41 天 E2 回放，1,204 线索）**：corroboration 准入与本地终端链是互为备份：全开 1,204/1,204；单独关终端链 −4；单独关 corroboration −5；**同时关两个 −99**（交互项 −90）——单因素消融掩盖了 91% 的互备贡献。

**尾部现场证据 A——132 天生产尾部**：按 Anchor Pass 0 静默率排序，最差十分位 13 天（静默率 42.9%–100%，含 9 天客户端 DNS 突发、3 天提供商 brownout）整体准确率仍 98.68%（373/378），非 Anchor 席位承担 32.1% 的答案（两日峰值 89.8%，单日峰值 90.0%）；3 个 brownout 日在同步准入架构下 86/86 = 100% 全对。

**尾部现场证据 B——决赛解剖**：开赛数秒后主 Anchor 端点遭遇服务端延迟 brownout，中位请求延迟 16s→50–190s，有效 token 交付从 117 崩至 33 tok/s（−72%），Pass 0 的 23/30 线索撞上 90s 超时，17/23 重试再失败。Darmok 仍以 6m52s 交出 30/30：次席供 13 答案、异步 feed 供 4（17/30 = 56.7% 无 Anchor 路径），且席位独立交叉验证了 26/30 条目与 feed 答案 17 个受检位中的 13 个。反事实回放：仅 Anchor 只能解 13–15/30；去掉 feed 则 26/30。

### 5.6 实验设计如何证明「尾部韧性」论点

论证结构是三段式：① 用单发电池证明平均情形已平价（能力不是瓶颈）；② 用安静条件下的留一消融证明冗余在平均情形下贡献 ≈0（静态评估会误判）；③ 用 132 天自然故障 + 决赛人为不可控故障两处现场证明同一批冗余在最差情形承担 18.6%–89.8% 的负载而精度不塌（≥98.68%）。②与③合起来才构成论点——只看②会得出「拆掉冗余」的错误结论，正如论文的 RAID 类比：在健康的 10 分钟基准里拔掉镜像盘观察到零数据丢失，就断言镜像盘多余——**坏的是评估方法学，不是磁盘阵列**。

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

对比对象：单发前沿模型（平均平价但各有 0/30 尾部模式）与 V1 贪心链（串行、顺序依赖）。Darmok 的优势不来自「更多能力」而来自三条约束与信息流的本质改变：

**因果链 1：同步准入消除覆写级联（论文实验已支持）**
方法差异（屏障同步 vs 增量写入）→ 机制变化（顺序无关评分 + 整词驱逐 + 从零重建，Invariant 3.1 构造性杜绝部分覆写）→ 可验证中间量（135 回放错误网格 10→4、+34 线索；REDOPISET 污染清零）→ 指标（E0→E1：97.97%→99.53%，perfect 59%→88%，时间 9m40s→6m03s）。**要点**：这不是「加了个好功能」，而是把「错误状态能自我繁殖」的病根换成了「错误状态构造性不可存在」。

**因果链 2：交叉字母坍缩候选空间（论文实验已支持）**
方法差异（把网格状态反馈回提示）→ 机制变化（≥3 已知字母时假定义/假 anagram 在思维链内被剪枝）→ 可验证中间量（单席 +33~50pp；oracle 98.1%@3、100%@≥4；71 条冷失败线索重派解出 63）→ 指标（消融 −13 为唯一超噪声项；E2 中 24.3% 线索由重试轮提交）。外部理论侧证：Hartmann 的渗流相变（论文引用）。

**因果链 3：异构席位的运营失败模式不相关（论文实验已支持；外推部分为阅读者推测）**
方法差异（并行 N-version + 非驱逐后备 vs 串行链/单发）→ 机制变化（Gemini 超时 brownout、Claude 安全拒绝、GPT-5 HTTP 520、gemini token 循环是**基础设施层**失败，跨提供商不相关）→ 可验证中间量（最差十分位 98.68%；brownout 日 100%；决赛 17/30 非 Anchor 仍 30/30）→ 指标（99.17%→99.84%）。**重要限定（阅读者推测，有外部证据）**：不相关的是**运营**失败而非**认知**失败——论文自己的残余错误（TOMB for TAME、RABBETS for RABBITY：两席收敛到同一诱饵）与外部研究（见下）都表明模型**答案级**错误高度相关，b=2 的双席共识机制在极端诱饵上仍会被相关错误攻破。

**因果链 4：静态消融系统性低估冗余（论文实验已支持）**
方法差异（2×2 因子 vs 留一）→ 机制变化（上游共识预先接管了下游恢复层的职责，单关任一者时另一者兜住）→ 指标（−4/−5 vs −99，交互项 −90）。

### 6.3 综合判断与未决问题

- **多源共同支持的机制**：重尾组件需要请求级对冲与同步屏障（Tail at Scale + 业界实践 + 本文）；冗余在不完美独立下仍有价值（Knight-Leveson 的反面 + arXiv:2606.20158 + 本文尾部数据）；答案级错误相关是真实的（Kim et al. + 本文残余错误分析）。
- **仍属合理猜测/单源的机制**：运营失败跨提供商不相关的程度（论文遥测支持三家，样本仅此）；消融交互项结论的普适性（单源）。
- **优势成立条件**：目标函数对零错误/完美率敏感（字典序或高可靠性场景）、组件失败重尾且异构、存在可验证的中间约束（交叉字母）供收紧。若目标是平均精度、组件同质或无外部校验信号，冗余的边际价值会向本文静态消融结果靠拢。
- **可能失效条件**：极端诱饵上的相关认知收敛（TOMB/RABBETS 类，需答案级多样性机制而非仅运营级冗余）；提供商同时故障（三副本共享主机与项目配额，论文自承非独立）；unchecked 格上的正字法变体（PAUPERISE/PAUPERIZE 类，交叉字母原理性无约束）。

## 七、必要知识反推

假设让一个完全没有相关知识的人重做这项工作，反推其必须掌握的最少知识：

### 7.1 领域知识层

- **密码填字的双重语法与字谜算子库**（charade/anagram/container/reversal/hidden/homophone/Spoonerism/&lit…及各自的指示词表）：不理解就无法设计提示、无法评估答案、无法理解为什么交叉字母是「外部约束」而提示工程不是。
- **网格拓扑与检查率规则**（blocked vs barred、unchecked 上限）：不理解「未检查格原理性无交叉约束」就无法预判残余错误的分布（正字法变体集中在 unchecked 格）。
- **锦标赛字典序规则**：不理解「一错格全线索判错」就无从推导 0.97^30 的复合惩罚，也就不会把问题定义成尾部韧性。

### 7.2 方法论知识层

- **分布式容错谱系**（N-version、RAID、active-active、hedged RPC、纠错内存）：V2 架构几乎每个组件都是这些思想的投影；尤其要知道 RAID 类比才能识别「静态消融误价冗余」这一评估学问题。
- **约束满足/弧一致性传播 + Jacobi vs Gauss–Seidel 迭代**：准入递推的顺序无关性直接来自这个选择。
- **LLM 评估方法学**：配对 McNemar、预注册噪声阈值、复制噪声基线（P0' 同提示重复）、Clopper–Pearson 小样本界——没有这些，第 4 节的「无效结论」就不可信。
- **渗流/相变直觉**（可选）：帮助理解为什么「每词解题率过阈 → 全网格解出簇雪崩式连通」。

### 7.3 工程知识层

- **LLM API 的真实故障模式谱**：超时、安全分类器拒绝、MAX_TOKENS 截断、HTTP 5xx、客户端 DNS/socket 突发、提供商 brownout 的遥测特征（服务端 vs 客户端延迟、僵尸请求）。
- **置信校准与延迟-准确权衡的实测方法**：分置信桶统计准确率、按延迟窗截尾分析——τ 与超时上限的全部数值都来自这类测量而非拍脑袋。
- **防污染的语料工程**：post-cutoff 语料、严格日期过滤的历史答案、canonical grading 判据预注册。

### 7.4 知识融合的关键节点

1. **「填字网格 ≈ 分布式系统」的类比跃迁**：把锦标赛规则翻译成字典序优化目标、把提供商降速翻译成部分失效——这是全部架构设计的种子节点。
2. **「运营失败 ≠ 认知失败」的分离**：来自同时掌握 LLM 故障模式谱与容错理论的人——只有前者会做朴素多数投票（被 Kim 类相关性击穿），只有后者不会想到用 τ=85 过滤 FIRST NAMES(78) 这类诱饵。
3. **「用系统自己的日志做反事实回放」**：评估学（因子设计）+ 工程遥测（调用级 JSONL）+ 统计纪律（预注册）三者的融合点，产出了 −90 交互项这个全文最反直觉的数字。

## 八、论文中可以提取的通用性灵感

**灵感 1：尾部韧性设计范式——当模型掌握平均情形，竞争转移到最坏情形。**
论文证据：单发模型平均平价（gpt-6-astra 21/21）但各自持有 0/30 的尾部模式；Darmok 的增益集中在最差十分位（98.68%）与决赛 brownout（56.7% 非 Anchor 仍 30/30）。
推广场景：生产级 Agent 服务（SLA 由最差请求定义）、自动驾驶规划栈、医疗/法律 QA 高风险决策、金融交易系统、任何「一次失败不可接受」的 LLM 编排。

**灵感 2：消融交互项警示——单因素消融会系统性误价互备冗余。**
论文证据：corroboration 与终端链单独去掉各 −4/−5，同去 −99，交互项 −90；静态基准会判整个后备层「无用」。
推广场景：安全关键系统的冗余评估（SRE 演练应用因子化故障注入而非单组件下线）、多模型管线的组件取舍、组织流程评估（两个看似重复的岗位实为互备）、模型融合研究中的组合消融设计。

**灵感 3：rebuild-from-kept——用「从零重建无冲突快照」替代「增量覆写共享状态」。**
论文证据：Invariant 3.1 构造性杜绝部分覆写；回放错误网格 10→4。
推广场景：多 Agent 协作编辑共享文档/代码库（整提交 vs 逐行覆写）、数据库乐观并发控制的快照重建、Agent 长程任务的检查点管理、任何多写者共享状态的系统。

**灵感 4：非驱逐后备层——下游只许填空、不许覆写。**
论文证据：feed 与终端链永不覆盖已准入答案，使冗余层的加入不可能破坏上游正确性（加层零风险）。
推广场景：Agent 流水线中追加「廉价兜底步骤」（规则/检索/词典）的设计契约、缓存层次的写策略、人机协作系统中自动化建议的非破坏性插入原则。

**灵感 5：异构组件必须异构校准——没有放之四海的统一阈值。**
论文证据：Gemini 需要硬 90s 截断（长尾 38.2% 准确率且高自信）而 Claude 需要 τ=85 + 150s 宽窗（长尾 91.7%）；GPT-5 的 150s 上限保留全部 76/76 独有解。
推广场景：多模型路由的每模型阈值、混合云多供应商配置、异构硬件集群的差异化超时、团队管理中按成员校准「复核门槛」与「思考时限」。

**灵感 6：强制解释是未验证猜测的刹车。**
论文证据：去掉字谜解释字段（P5）让超时率 25.1%→15.3%、token 194→34，但联合完成子集精度 −2.86pp、地板处高自信错误近翻倍（1.5%→2.9%）——没找到自洽解析的模型会继续搜索到超时（干净弃权）而不是快速吐一个低精度猜测。
推广场景：高风险场景强制 LLM 输出依据（医疗/法律/财务）、代码生成强制先写测试逻辑再写答案、Agent 行动前的 plan-out-loud 约束。

**灵感 7：分解隔离单点故障——把 30 条线索拆开，安全拒绝只能废一条而不是整张网格。**
论文证据：claude-fable-5 单发把 30 线索拼一个提示时 2/21 触发序列级安全分类器直接 0/30；逐线索派发把误杀隔离到单线索。
推广场景：长上下文批处理任务的分片执行、内容审核管线的粒度设计、多步骤 Agent 中把「一次拒绝毁全程」的链路改为分段可恢复。

**一句话总结**：Darmok 表明，当基础模型跨过能力阈值，AI 编排的学科形态随之改变——从「哄弱模型出能力」的艺术，变成「用强而动荡的模型构建高可靠系统」的工程；而评估这种系统的第一戒律是：**别在晴天检修时判断雨伞的价值**。
