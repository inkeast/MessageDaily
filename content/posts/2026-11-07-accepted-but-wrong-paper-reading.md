## 一、论文背景

### 1.1 迁移修复的"静默失败"问题

当业务过程依赖的运行时或 API 升级（如 Python 3.9→3.12），必须修复代码使其继续履行同样的义务。破坏有两类：

- **响亮的**：被删函数抛异常，立刻暴露
- **安静的**：每次调用都成功，但结果变了。论文给了三个例子：
  - 枚举渲染成 `3` 而不是 `Priority.HIGH`
  - `sum()` 返回更精确的浮点数，不再匹配账本存量
  - `Buffer.poolSize` 增大八倍，悄悄改变每次上传的分块方式

关键困难在于：**有效调用仍可产生无效效果**；Agent 察觉"貌似合理的错误值"的能力远弱于察觉显式错误（论文引 Kraishan 的工具故障研究）。这与程序修复领域的经典 **patch overfitting 问题**（弱测试放过错误补丁）在迁移场景下叠加放大。

### 1.2 前序研究与四条审稿质疑

本文是同一项目第四层工作的延续。直接前驱（55 任务、3 模型族、3 覆盖级别）发现：全断言门在典型输入下放出 0.377 错误程序，作者边界输入降到 0.065。审稿人提出四条质疑：

1. 边界输入是作者写的，与隐藏输入"同源"
2. 修复空间是有限"菜单"
3. 合同从未有人工签署
4. 测试分区只有 34 簇

本文用预注册新实验回应：盲写者回应质疑 1，大菜单+硬干扰项回应质疑 2，AI 审计部分回应质疑 3，新增 15 簇回应质疑 4。

### 1.3 为什么这个问题现在重要

LLM 编码 Agent 越来越多地被用于依赖升级、API 迁移的自动修复（BBCFixer、DepRepair、Byam 等系统）。这些系统的接受标准通常是"编译通过"或"自身测试通过"——而这正是论文证明会大量放行错误修复的门。发布检查（release gate）的充分性成为 Agent 修复能否安全上线的核心问题。

## 二、论文定位和关联工作

### 2.1 依赖演化后的客户端修复

| 工作 | 核心思想 | 与本论文的关系 |
|---|---|---|
| Fruntke & Krinke (FSE'25) | 自动修复依赖破坏性变更 | 接受标准为编译/测试 |
| Byam (EMSE'26) | 编译错误+错误定位+API 差异 + LLM 修 Java 依赖升级 | 信号对应本文 runtime/schema 门 |
| DepRepair (arXiv'26) | 决定性证据常在上游（release note、API diff） | 启发本文"从变更注记写输入" |
| BBCFixer (arXiv'26) | 行为性依赖破坏：新旧版本执行差分定位根因 API | **最近邻**。但差分仅作修复证据、非发布标准 |
| Gilesi (arXiv'25) | API 交互快照跨版本比较 | 差分测试在 API 边界的应用 |
| BBCBench | 100 个 Python/JS 行为性依赖破坏基准 | 论文未在其上评测的三个理由：需装依赖（违反离线协议）、oracle 是项目自身失败测试（无法与修复独立变化）、自由形式代码空间不可枚举 |

**本文相对 BBCFixer/Gilesi/Byam 的四点增量**：固定修复者信息只变发布门；在**完整修复空间**与模型修复上测门的假接受/假拒绝率；把"不存在安全替换"注册为合法结局；比较门的输入来源（作者/盲写者/修复模型自身）。

### 2.2 版本感知生成与 Agent 工具演化

CodeUpdateArena、LibEvolutionEval、GitChameleon 等评估版本相关生成，但都以测试为 oracle，不问"更弱的 oracle 会放过多少"。ToolEVO、ToolDriftBench、DynamicMCPBench 等研究 Agent 面对工具漂移；Kaliyev & Maryanskyy 发现会话内验证与最终符合性有差距。本文设置不同：**上游演化 + 固定义务，发布 oracle 是被操纵的变量**。

### 2.3 Oracle、合同与补丁过拟合

- Overfitting 经典：Smith et al. (ESEC/FSE'15)、Xiong et al. (ICSE'18)；LLM 时代 "solved issues 未真正解决"：UTBoost (ACL'25)、Wang et al. (ICSE'26)
- 可执行性质/合同：QuickCheck 性质测试、蜕变测试、消费者驱动合同测试、API 版本差分回归测试
- LLM 写测试：CodeT（同模型生成测试并对采样程序按一致性排序）、Self-debugging；BreakGuard 用 LLM 测试检测行为性破坏变更
- LLM 裁判偏差研究（MT-Bench）→ 本文只用 LLM 审计合同、双盲复刻+冻结裁决规则

### 2.4 定位结论

**之前的路线**：修复系统（能否修好，以项目测试为准）或生成基准（版本知识）
**本论文的突破**：**门的充分性科学**——在可枚举的完整修复空间上，量化"给定发布会放行多少错、挡住多少对"，并系统比较门的输入来源。模型无关测量是"对可能修复空间计算的变异分数的补集"。

## 三、问题定义

### 3.1 形式化框架

任务五元组：(消费者需求 R, 旧过程 p₀（在旧运行时 A₀ 满足 R）, 有限修复域 D, 可见输入集 Xᵥ, 隐藏输入集 Xₕ)。

**定义 1（隐藏正确性）**：过程 p ∈ D 在新运行时 A₁ 上正确 ⟺ 对每个 x ∈ Xₕ：
- 输出满足从 R 导出的接受断言 + 在 R 约束的输出上与 A₀ 的 p₀ 相等
- 留下的文件与 p₀ 相同（保持性）

隐藏合同永不展示给修复者。

**定义 2（发布门与四结局）**：门把候选在 Xᵥ 上的观察映射为放行/拦截：
- 正确完成（放行且正确）
- **假接受**（放行且不正确）——本文核心指标
- 假拒绝（拦截但正确）
- 安全不放行（拦截/弃权且不正确）

**无安全修复任务**：D 中无正确程序（穷举确认），正确处置是不放行。

### 3.2 核心洞察：门的充分性由输入决定

论文的深层洞察可以表述为一个类比：

> **发布门 ≈ 考试卷；修复空间 ≈ 全部可能答案；假接受率 ≈ 错误答案的得分率。**

换更难的题型（更强断言族）不如换覆盖考点更准的题（命中变更行为的输入）。错误修复要骗过门，只需要在门的输入上"看起来对"；如果门的输入恰好行使了文档化变更，静默错误就无处藏身。

### 3.3 可见输入集的层级（自变量设计）

| 层级 | 构成 | 说明 |
|---|---|---|
| T | 典型输入 | 现状基线 |
| E | T + 1 条作者边界输入 | 从 release note 写出，QA 规则强制使旧过程可见失败 |
| Wₖ | T + 盲写者前 k≤3 条有效输入 | 隔离 LLM 只看 release note+可见合同 |
| Gₖ | T + 写者标记 legacy-binding 的输入 | **预注册守卫** |
| S | T + 修复模型自己写的测试 | 修复前写，标记 binding |
| ES | E + S | 组合 |

所有新增输入的期望输出来自旧运行时上的 p₀——**无任何模型编写代码或期望值被执行或信任**。

### 3.4 抽象的精妙之处

把"发布检查可靠吗"分解为可在**完整有限空间**上穷举测量的量（假接受率/假拒绝率），使结论不依赖特定模型的采样运气；同时用四个模型族把模型无关结论与模型行为连接。给定与求解的边界清晰：给定 R、p₀、D、Xₕ，求各可见集对 FA/FR 的因果影响。

## 四、问题解法

### 4.1 基质：三个真实运行时、73 任务、60 变更簇

- **运行时**：CPython 3.9.6→3.12.15、Node.js 20.20.2→24.21.0、SQLite CLI 3.51.0→3.54.0（离线安装、冻结不变；SQLite 3.54.0 发布于 2026-10-09，在模型训练截止之后——天然污染对照）
- **任务**：55 个前驱任务原样导入 + 18 个新任务（锚定逐字引用的官方页面：Python What's New 3.10–3.12、Node.js 弃用注册表与 Buffer 参考、SQLite 3.53/3.54 发布日志）
- **计数**：66 受影响任务 ∈ 60 簇（CPython 45、Node.js 13、SQLite 8）；7 个不变对照。按类别：**25 静默、34 显式、7 无安全修复**
- **制定规则**：逐字引用、确定性、隐藏输入上旧过程失败、每任务至少一个正确片段选择（无安全修复任务除外）、静态安全；每任务一条作者边界输入且必须使旧过程可见失败（边界输入 QA 规则）；两个候选任务在干构建中未过门被弃；**不加同构变体**
- **切分**：新簇按哈希 20%/谱系进开发集；测试分区 52 受影响任务 ∈ 49 簇，其中 15 簇全新

### 4.2 预注册与双冻结（方法论核心）

设计被 SHA-256 哈希集冻结两次：
- **F0**：任何模型调用之前（03:10 写入，351 文件）
- **F-test**：任何修复/自测/探针调用之前（03:48，794 文件）

每次冻结存储设计文本逐字副本并哈希冻结脚本本身——这是前驱研究"设计文本需事后重建"教训的直接产物。时间线（2026-10-17 UTC）：03:10 F0 → 03:15 盲写者完成（73 调用）→ 03:24 AI 审计完成（146 调用）→ 03:43 模型无关族 M4 计算 → 03:48 F-test → 04:38 GPT-5.6-luna 跑完。

### 4.3 盲写者：信息隔离的测试作者

- **调用**：每任务 1 次隔离 GPT-5.6-luna 调用（经加固 Codex 客户端：MCP 服务器/插件/应用/网页搜索全禁；只读临时沙箱、空工作目录；输出 schema 强制；动用自身工具即作废）
- **所见**：需求、锚定摘录、输入键、典型输入及其旧输出、输出检查。**从未见过**模板、片段、旧程序、隐藏输入、任何结果
- **输出**：至多 3 条输入，各带 legacy-binding 标记
- **验证（fail-closed，仅数据）**：输入必须键型精确匹配；必须在旧运行时旧过程上干净确定地运行（由此得到期望输出）
- **产出**：176 条输入保留于 69 任务，35 条被标 non-binding；27 条丢弃（13 旧运行时报错、12 重复、2 非确定）；3 条恰等于某隐藏输入（按预注册保留并披露）

### 4.4 修复协议与四个模型族

- **等信息**：所有臂见需求/摘录/模板/字段域/旧过程/本臂可见输入 + "EDIT BUDGET: unlimited" + 弃权许可
- **四臂八格**：T、S、E、ES ×（patch/full 表示 × diff 视图开/关 × 片段正/逆序）
- **门失败时**：恰好一次修订，带 pass/FAIL 反馈、无期望值
- **模型**：GPT-5.6-luna（Codex CLI，high effort）、Qwen3-8B（4-bit MLX，greedy）、gpt-oss-20b、qwen3.6-35b-a3b（LM Studio，temperature 0）；gemma-4-12b-qat 未通过准入（0/12 精确输出，泄漏思维链文本，decode 20.7 tok/s——服务配置问题，不作模型结论）
- **准入检查**（12 调用资格赛）：12/12 精确输出、p5 prefill ≥500 tok/s、p5 decode ≥32 tok/s、开销 ≤0.5s——Qwen3-8B（38.9）、gpt-oss-20b（61.4）、qwen3.6-35b-a3b（104.0）首次通过
- **调用量**：GPT-5.6-luna 2626、Qwen3-8B 3266、gpt-oss-20b 2965、qwen3.6-35b-a3b 2885，无一作废
- **统计**：以簇为单位（簇内任务平均）；sign-flip 置换 p 值（≤16 簇精确，否则 20 万次 Monte Carlo）；整簇 bootstrap 95% CI；族内 Holm 校正。功效仿真（r=0.3 反事实效应）：Qwen3-8B 0.99、gpt-oss-20b 0.91–0.94 为确认性族；GPT-5.6-luna 0.03–0.06（近天花板）为描述性

### 4.5 第二、三阶段：回应"有限菜单"质疑

**大菜单阶段**（F0 2c95616bd805，2026-10-18）：
- 菜单从 405 片段扩至 **1491**，每新增片段由旧片段经 1-2 个作者算子生成（模块属性的文档化兄弟、文档化内建/字符串方法/算符/SQLite 函数/CLI 模式互换、整数字面量编辑），逐一对照 63 个新锚定官方页校验
- 可见过滤：片段须在典型输入上于任一运行时干净运行；step-1 prompt 保持 2048 token 输入上限内
- 25 任务仍少于 15 选项（无适用算子）；**1986 个程序全部穷举评估**
- 跑 T/E 两臂八格：GPT-5.6-luna 1242 调用、Qwen3-8B 1599、gpt-oss-20b 1403、qwen3.6-35b-a3b 1387

**硬干扰项阶段**（F0 bf681a0b7291，2026-10-19）：
- **硬干扰项定义**：在大菜单片段上用同样算子生成候选，仅当在典型输入上新程序输出 == 旧程序旧输出时保留（纯可见信息构造——它们通过可见差分检查）
- 233 硬片段加入 26 任务 → 1689 片段、2310 程序全部穷举；359 个硬源程序中 329（论文摘要作 0.919 比例的来源是 0.990 门通过率）——正文报告 323/359 为 hidden-wrong
- **写者 v2**：qwen3.6-35b-a3b 与 Qwen3-8B 用无 binding 标记的新 prompt（要求行使变更及边界值）各写至多 3 输入

### 4.6 AI 合同审计

- 两盲 GPT-5.6-luna 调用/任务（146 调用），所见：需求、摘录、模板、片段、旧程序、声称类别、典型输入上的合同实例；不见隐藏输入/输出/结果
- 五条 rubric：R1 材料记录了变更 / R2 类别正确 / R3 legacy 等式是合理读法 / R4 无断言严于需求 / R5 合同完整
- 冻结裁决规则：一项计"否"仅当两次复刻皆否；审计后合同永不修改

## 五、评估指标与实验证据

### 5.1 指标体系

- **主指标（假接受率 FA）**：完整修复空间上 hidden-wrong 程序被放行的比例（任务均值）——直接量化"门放行错误修复"
- **对称指标（假拒绝率 FR）**：hidden-correct 被拦比例——门的误伤
- **模型指标**：每尝试错误发布率（8 格平均）、正确完成率（要求 H1 对比中 CC 降幅 ≤0.05，证明门不伤正确修复）
- **stale 计数**：旧程序在可见检查下失败的任务数——输入"看到"变更的间接证据
- **menu-independent 计数**（post hoc）：可见输入无法与正确程序区分的错误程序数——脱离菜单构成的绝对量

### 5.2 主结果一：模型无关穷举（52 受影响测试任务）

| 可见输入 | 平均新增输入 | FA | FR | stale |
|---|---|---|---|---|
| 仅典型 | 0.00 | **0.410** | 0.010 | 34/52 |
| +盲写者 k=1 | 0.96 | 0.130 | 0.010 | 49/52 |
| +盲写者 k=2 | 1.85 | 0.075 | 0.010 | 50/52 |
| +盲写者 k=3 | 2.46 | 0.070 | 0.010 | 50/52 |
| +守卫写者 k=3 | 1.85 | 0.157 | 0.010 | 42/52 |
| **+作者边界输入** | 1.00 | **0.065** | 0.010 | 52/52 |

**关键数字链**：
- 0.410→0.065：一条边界输入砍掉 84% 的假接受；簇级差异 −0.342、36 个不一致簇
- **新鲜复现（M4c）**：15 个新簇上 0.471→0.061（差异 −0.410，95% CI [−0.589, −0.238]，严格 Holm p 0.002）——这些簇在效应首次观测时不存在，排除"见效后才检验"
- FR 全程 0.010：门几乎不误伤

**守卫的失败（M4a 不阳性）**：G₃ 只保留写者标记 legacy-binding 的输入，FA 仅到 0.157，超过预注册 0.10 上限。机制：写者把 176 条中 35 条标为 non-binding，**这些恰好偏向揭示变更的输入**（G₃ 下 stale 42 任务 vs W₃ 下 50）。"旧输出在此不再必需"的判断正是 release note 最相关之处，也正是写者出错之处。M4b 零不一致簇：无守卫输入本来就不造成假拒绝，守卫无事可防。

**鲁棒性（post hoc）**：按类别拆分——静默类 S（23 任务）0.571→0.080（E）/0.091（W3），显式类 E（25 任务）0.297→0.053/0.055，效应在两类都成立；leave-one-lineage-out 全部显著。即静默类基线更危险（0.571），但边界输入同样治它。

**盲写者重叠诚实披露**：3 条写者输入等于隐藏输入；剔除后 W₁–W₃ 为 0.149/0.094/0.090——仍低于 0.10 上限但高于作者输入。保留输入与隐藏输入的最高字符串相似度均值 0.70（中位 0.72，20 条 ≥0.9），与作者边界输入的 0.71 相当。

### 5.3 主结果二：四个模型族的修复

每臂 456 次尝试（正确完成/假接受/假拒绝）：

| 模型 | T | S | E | ES | 无门 |
|---|---|---|---|---|---|
| GPT-5.6-luna | 398/22/0 | 403/9/0 | 408/7/0 | 409/0/0 | 45 |
| Qwen3-8B | 268/98/0 | 271/80/0 | 270/24/0 | 268/20/0 | 182 |
| gpt-oss-20b | 320/71/0 | 327/47/1 | 353/8/0 | 351/8/0 | 111 |
| qwen3.6-35b-a3b | 354/49/0 | 363/30/0 | 368/7/0 | 379/8/0 | 97 |

**H1（边界输入）按族**（簇均值差，Holm p）：
- Qwen3-8B：0.233→0.057（CI [−0.267, −0.094]，p<0.001）✅ 确认性
- gpt-oss-20b：0.181→0.020（p<0.001）✅ 确认性
- qwen3.6-35b-a3b：0.120→0.018（p 0.004）✅（描述性族）
- GPT-5.6-luna：0.056→0.018（p 0.499，描述性——本身近天花板）
- **跨族复现标准满足**（3 个开权重族全阳性 + 全部确认性族阳性）；正确完成零下降

**H2/H3（自测）**：每族都降（22→9、98→80、71→47、49→30）但**无一通过 Holm 校正**（最小 p=0.132 严格/0.088 代码）；ES 相对 E 几乎无差（20/8/8 vs 24/8/7）。自测复现标准不满足。

**为什么自测弱**（三重证据）：
1. **量**：GPT-5.6-luna 为 71/73 任务写出有效测试，Qwen3-8B 仅 30/73
2. **质**：Qwen3-8B 无守卫自测门在完整空间放出 0.240（盲写者 0.070）
3. **恰好弱在最需要处**（表 6，离线作用于各自 T 臂错误候选）：盲写者 W₃ 放出 Qwen3-8B 错误候选的 0.170、gpt-oss-20b 的 0.083；它们自己的无守卫测试放出 0.330、0.339——**误读 release note 的模型会写出认同其误读的测试**

**写者×修复者矩阵（post hoc 假设生成）**：每族自测步骤恰用盲写者 prompt，故各族测试可零成本互相配对。21 个全体写者都有测试的任务上：GPT-5.6-luna 写者对每个修复者都是最佳或并列最佳门；**同模型格 0.161 vs 跨模型格 0.187**——与"自测对自身错误特盲"假说不符，更支持**写者能力比独立性更重要**（与 CodeT 在强模型下有效一致）。作者明确标注这是假设而非结论。

**模型规模**：绝对边界效应随能力缩小（Spearman ρ=−1.00，精确 p 0.083，n=4）；相对效应不减（ρ=−0.40）。强模型只是产生的错误发布少，不是不需要门——GPT-5.6-luna 典型输入下仍发布 22 个错误修复，双输入源下 0。

| 可见输入 | FA | FR |
|---|---|---|

## 六、效果优势的根源解释

### 6.1 根源机制与证据链

**问题**：为什么一条边界输入就能把假接受率从 0.410 砍到 0.065，而更强的断言族无此威力（前驱研究：runtime/schema 门放 0.80、全断言 0.36）？

**因果链 1：错误修复的"生存空间"= 与正确程序在门输入上不可区分（论文实验已支持）**

```
静默变更的本质：新旧行为只在行使变更的输入上分歧
→ 典型输入通常不行使变更（stale 仅 34/52 可见失败）
→ 错误程序（多数保留旧行为或引入第三种行为）在典型输入上与正确程序同输出
→ 门无论用什么断言族，比较的都是同一对输出 → 无法区分（FA 0.410）
→ 加入 1 条行使变更的输入 → 新旧行为分歧暴露 → stale 52/52 → FA 0.065
```

menu-independent 计数是这条链的直接量化：不可区分错误程序从 113 降到 14（早期菜单）。这不是断言写得好，而是**观测点选得准**——信息论意义上的"区分性输入"。

**因果链 2：为什么"从 release note 写输入"有效（论文实验已支持）**

```
每个任务锚定 pinned release note 逐字文本
→ 变更的语义（何时新旧行为分歧）在 note 中被显式记录
→ 读 note 的写者（作者或盲 LLM）能构造命中分歧点的输入
→ 盲写者与隐藏输入同源相似度 0.70 vs 作者 0.71——效果相当（0.070 vs 0.065）
```

这说明效果的来源是**输入与变更文档的语义对齐**，而非作者对程序的私有知识——回应了"作者既写边界又写隐藏输入"的质疑。

**因果链 3：守卫为何失败——判断即盲区（论文实验已支持）**

```
守卫丢弃写者标为 non-binding 的输入（35/176）
→ 这些输入偏向"行使变更"（stale 42 vs 50 任务）
→ "旧输出在此不再必需"需要正确理解变更语义
→ 而正确理解变更语义正是整个任务最难处 → 写者在此系统性出错
→ 守卫恰好删除最有区分力的输入（0.157 vs 0.070）
```

这是一个自我指涉的陷阱：**用模型判断去过滤模型生成，过滤标准恰好踩在模型最弱的判断上**。

**因果链 4：自测为何弱——误读写出认同误读的测试（论文实验已支持）**

```
自测 = 修复模型读同一份 release note 写输入
→ 若模型误读 note → 其测试编码同一误读的期望
→ 测试与修复共享同一错误世界观 → 一致通过（Qwen3-8B 自测放自家错误 0.330 vs 盲写者 0.170）
→ 弱模型连有效测试都难产出（30/73 任务）
```

但同/跨模型格 0.161 vs 0.187 提示这不是"独立性问题"而是"能力问题"（阅读者推测部分：矩阵是 post hoc、单 prompt、每格错误修复少）。

**因果链 5：硬干扰为何部分穿透（论文实验已支持）**

```
硬干扰构造条件：典型输入上新输出==旧输出（可见差分通过）
→ 它们与正确程序在典型轴上不可区分（0.990 通过）
→ 边界输入能杀掉多数（0.168 残留）但硬干扰是"在边界轴附近也精心匹配"的程序
→ 残留不可区分程序随菜单 14→46→77 增长
→ 结论：单输入门有理论上限，需要更多正交输入
```

### 6.3 综合判断与未决问题

**多项证据共同支持的机制**：
1. 门的充分性由输入对变更的行使决定（穷举 FA + stale 计数 + menu-independent 计数三重一致）
2. 输入可从变更文档可靠导出（作者输入三菜单复现 + 盲写者两阶段过预注册测试 + 15 新簇前瞻复现）
3. 写者能力是测试质量的主导因素（矩阵 + 两个本地写者失败 + 自测三重弱点）

**仍属推测/开放**：
- "独立性无益"仅由 post hoc 矩阵支持（4 族、1 prompt、格内样本少）
- 守卫失败的机理（写者判断恰好最弱）是对 35/176 标记模式的解读，未做受控分解
- 硬干扰的 0.168 残留是否可由第 2-3 条边界输入收窄——未测试

**适用边界**：修复限于文档化片段菜单（自由形式臂因沙箱权限未跑、无一字模型代码被执行）；三谱系无 web API；合同无人工签署（AI 审计部分通过）；隐藏输入仍为作者所写；写者结果特定于前沿模型。

## 七、必要知识反推

### 7.1 领域知识层

- **三谱系的发布语义**：CPython What's New / Node.js 弃用注册表 / SQLite release log 的文本惯例——不知道就无法锚定 60 个变更
- **静默 vs 显式破坏的行为差异**：枚举 str 化、浮点精度、poolSize 翻倍等具体机制——任务设计的素材
- **运行时安装与版本管理**：多版本 Python/Node/SQLite 并存、Homebrew/系统二进制、二进制哈希记录

### 7.2 方法论知识层

- **预注册科学的完整流程**：假设冻结、决策规则先定、Holm 校正、confirmatory vs descriptive 的功效预演——本文的骨架；不理解就无法读懂"哪条结论是证实性的"
- **置换检验与簇级统计**：sign-flip permutation、整簇 bootstrap——小样本多重比较的正确工具
- **穷举评估 vs 采样评估**：有限域 D 上每个程序都能评判——模型无关测量的前提；"变异分数的补集"这一视角
- **门/测试充分性理论**：FA/FR 权衡、区分性输入概念
- **污染控制的实验设计**：训练截止后发布物（SQLite 3.54）、无文档探针
- **LLM 隔离调用工程**：禁 MCP/插件/搜索、只读沙箱、schema 强制、工具即作废——"盲"的可信度保障

### 7.3 工程知识层

- **片段生成算子**：文档化兄弟属性、内建互换、字面量编辑——把"菜单扩大"变成可审计操作
- **fail-closed 验证**：旧运行时确定性执行产生期望输出——不信任任何模型写的期望值
- **本地模型服务**：MLX 4-bit、LM Studio temperature 0、吞吐准入阈值（prefill/decode/开销）——本地族可比性
- **可复现性基础设施**：create-only 运行目录、独立检查器双实现断言语义、渲染清单哈希每个数字

### 7.4 知识融合的关键节点

1. **"穷举空间" × "预注册"**：只有有限菜单才能穷举，只有穷举才能把门的 FA 做成确定量——而预注册让模型无关结果在模型调用前就可锁定（M4c 在 F0 已知）。
2. **"release note 作为公共信息" × "测试输入生成"**：把上游文档从"修复线索"（DepRepair 的用法）重构为"区分性输入的规格说明"——这是全文最核心的视角转换。
3. **"写者×修复者对称性" × "能力假说"**：注意到每族自测恰用盲写者 prompt，零额外调用构造出配对矩阵——把"独立性问题"转成可检验的数据结构。
4. **"诚实报告文化" × "实验设计"**：LM3 反向、守卫失败、强证据标准未达成、gemma 不准入、3 条重叠输入——每条负面结果都被保留并分析，这种披露本身是方法论的一部分。

## 八、论文中可以提取的通用性灵感

### 灵感 1：观测点决定区分力，不是观测精度（机制类）

**核心思想**：当你无法区分"对的"与"看起来对的"，问题往往不在测量仪器的精度（断言族），而在测量位置（输入）是否命中使二者分歧的维度。
**论文证据**：同一全断言门，典型输入 FA=0.410，换 1 条行使变更的输入 FA=0.065；前驱研究中 runtime/schema(0.80)→全断言(0.36) 的断言族升级远不如输入升级。
**推广场景**：
- A/B 测试：选错细分维度再精确也测不出差异
- 医疗诊断：筛查指标再灵敏，不在病理活跃期采血也无效
- 安全审计：审计脚本再严格，不覆盖攻击面关键路径就是形式主义
- 模型评测：benchmark 题目不区分能力差异时，评分协议再精细也无用

### 灵感 2：判断式过滤会踩中判断最弱点（机制类）

**核心思想**：让生成者先做一层"这个该不该用"的元判断再过滤其输出，过滤标准若恰好是其系统性弱项，会精准删除最有价值的部分。
**论文证据**：legacy-binding 守卫让写者标记"旧输出不再绑定"的输入——恰是模型最常误判处——FA 从 0.070 恶化到 0.157，而它要防的假拒绝本来就不存在（M4b 零不一致簇）。
**推广场景**：
- RAG：让 LLM 先判断文档相关性再检索，相关性判断弱时会漏掉关键证据
- 代码评审：让作者自标"关键改动"请求重点评审，会系统性转移视线
- 风控：让申请人自报风险类别再适用规则
- 数据清洗：用模型置信度过滤训练数据，会删掉难例

### 灵感 3：生成者与其验证器共享世界观（信号利用类）

**核心思想**：同一个体（或同能力层个体）既生产又验证时，错误会在两者间自洽，形成"内部一致、外部错误"的闭环。
**论文证据**：Qwen3-8B 自测放行自家错误候选 0.330，盲写者（更强模型）只放 0.170；但同/跨模型格 0.161 vs 0.187 表明主因是能力而非身份——强模型的自我验证仍可工作。
**推广场景**：
- 组织管理：下属汇报+自我检查不能替代独立审计，但强团队自检质量确实更高
- 编译器：自举（用编译器编译自己）验证的是自洽性，需外部测试补充分歧覆盖
- AI 安全：Constitutional 类自评的风险与可行边界
- 科研复现：作者提供的验证代码 vs 独立重实现

### 灵感 4：把"文档"重构为"测试规格"（范式迁移类）

**核心思想**：变更文档（release note、设计文档、迁移指南）不仅供人读，它显式编码了"何时新旧行为分歧"——因此是区分性测试输入的生成规格。
**论文证据**：盲写者仅见 release note 与可见合同、不见程序，3 条输入把 FA 降到 0.070；效果随菜单扩大与硬干扰加入持续复现（0.053、0.058）。
**推广场景**：
- API 弃用流程：弃用通知自动生成回归测试输入
- 合同工程：OpenAPI spec 变更 diff 驱动消费者契约测试
- 硬件规格：datasheet 修订项生成验证向量
- 法规合规：新规条文生成合规检查点

### 灵感 5：穷举小空间胜过采样大空间（方法论类）

**核心思想**：回答"X 会放行多少错误"这类充分性问题时，构造一个可穷举的受限空间得到精确答案，比在不可穷举空间采样更有证明力。
**论文证据**：有限片段菜单（405→1491→1689）使 1986/2310 个程序全部评判，FA 成为确定量而非估计量；LM3 进一步揭示 FA 数值本身是菜单构成的函数——提醒报告绝对量时要同时报"不可区分程序数"。
**推广场景**：
- 安全研究：小协议状态空间穷举找全部漏洞模式
- 形式化方法：受限 DSL 中穷举反例
- 算法测试：小输入全枚举找边界 bug
- 产品 A/B：受限用户群全量实验

### 灵感 6：预注册+时间戳是 LLM 时代实证的可信度基建（方法论类）

**核心思想**：当实验对象（LLM）快照漂移、数据集可能被污染时，"何时知道什么"的证明（冻结哈希+逐字设计副本+公开时间线）成为结论可信度的核心。
**论文证据**：双冻结（F0/F-test 各存 351/794 文件哈希）、M4c 在 F0 已知并披露、15 新簇前瞻复现、SQLite 3.54（训练截止后）作污染对照、负偏差逐条记录（功效记录晚于 F-test 被记为 deviation）。
**推广场景**：
- AI 评测报告：模型版本+数据截止披露的标准做法
- 数据科学：分析计划预注册防 p-hacking
- 竞赛评测：题库冻结与提交时间戳
- 供应链：制品溯源（SLSA 类）思想
