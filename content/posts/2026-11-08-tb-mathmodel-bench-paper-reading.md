## 一、论文背景

### 1.1 数学建模考的是「从烂摊子到可辩护的答案」

数学建模竞赛（中国的 CUMCM、国际的 MCM/ICM）给参赛队的题目是**刻意欠定义的真实世界问题**：题目只给一段情境描述加一堆附件（Excel/CSV/PDF），参赛队要在几天内交付一条完整链路——**假设 → 模型 → 求解 → 敏感性分析 → 可辩护的建议**。这跟「解一道有唯一答案的数学题」完全不同：难点从「 deduction（演绎）」变成了「 modeling（建模）」——同一道题可以建成时间序列、优化、动力系统、图论或多准则模型，只要假设显式、计算可信，任何一种建法都成立。

论文认为这恰好是长程 Agent 评测的理想靶子，两个性质使然：

1. **定量化**：最后一问通常落在可以核对的数字上；
2. **多模态**：题面引用图（几何信息只在图里）、附件是电子表格——纯文本管道做不了。

一个合格的建模 Agent 要在上下文里同时握住题面与附件、选定一个建模方向、写并运行代码、处理文件与单位、最后给出自洽的答案——这正是当前 Agent 的短板合集。

### 1.2 现有评测的空洞：分数要么片面、要么没人核对

论文开篇就点名现有基准的两类通病：

- **代码/终端/助手基准**（SWE-bench、Terminal-Bench、GAIA、τ-bench）：考仓库编辑、命令行能力、工具调用，但从不考「建模制品」，也没有可行性约束；
- **数学/运筹基准**（MATH、GSM8K、FrontierMath、NL4Opt、OptiBench）：考演绎或把应用题解析成求解器可吃的形式，但「假设、敏感性分析、可辩护建议」这些建模核心环节全部缺席；
- **最接近的建模基准分两派**：Mamo（1209 题）让 solver 检查单一形式化制品——精确但片面；ModelingBench（68 题）与 MM-Bench（111 题）用 **LLM 裁判给报告打分**——生态丰富但裁判校准依赖强、不可复现，最致命的是：**报告里的数字从头到尾没人核对过**。一篇组织漂亮、答案违反物理约束的报告照样拿高分。

### 1.3 三个设计难题

把完整竞赛题变成可验证基准，必须解决三个此前无人同时处理的问题：

1. **没有唯一真值**：不同队做不同假设，答案天然发散——把某一篇论文捧成「标准答案」等于把某队的选择变成真理；
2. **锚定带来不对称失败**：朴素地算「与参考答案的距离」，会奖励抄答案、惩罚超越——一个做得比论文更好的模型反而得分更低；
3. **貌似合理的错误答案太容易产生**：数字看着合理却违反题面物理约束（比如定日镜额定功率低于 60 MW、板凳龙把手速度超过 2 m/s 上限），锚点比对根本抓不住。

这三个问题分别催生了本文的三大支柱设计：多参考面板评分、方向感知单侧计分、两层可行性验证。

## 二、论文定位和关联工作

### 2.1 四象限定位：Agentic × Verifiable × Terminal × Multimodal

| 基准 | 题数 | 图 | 评测信号 | Agentic | 物理可行性 | Lean | 多模态 |
|---|---|---|---|---|---|---|---|
| Mamo (2025) | 1209 | – | Solver 检查 | ✗ | ✗ | ✗ | ✗ |
| ModelingBench (2025) | 68 | – | LLM 裁判 | ✗ | ✗ | ✗ | ✗ |
| MM-Bench (2025) | 111 | – | LLM 裁判 | ✗ | ✗ | ✗ | ✗ |
| **TB-MathModel（本文）** | **18** | **21** | **可执行验证器** | ✓ | ✓ | ✓ | ✓ |

TB-MathModel 是第一个同时满足「完整竞赛题 + Agent 终端运行 + 可执行验证器 + 物理可行性检查 + 机器可查证明 + 多模态」的基准。只有 18 题看似少，但每题都是完整竞赛题（含多个子问题，只对最后一问的数值核心计分），且每题配 2–6 个评分指标（共 **60 个**）。

### 2.2 各谱系继承与差异

- **终端 Agent 基谱系**（Terminal-Bench）：本文直接复用其容器化终端 harness——但把「仓库级任务」换成「完整建模题」，把「leaderboard 分数/rubric」换成「建模制品 + 可行性契约」；
- **运筹求解谱系**（OptiMUS、ORLM、ORQA）：提供了「执行有效性」的先例（solver 证明解可行/最优），但它们只对给定形式化制品负责，不要求假设与建议；
- **形式化验证谱系**（Lean 4 + Mathlib、miniF2F、DeepSeek-Prover）：以往用定理证明器**找答案**，本文反其道用证明器**审计基准自己的可行性判定**——据作者所知这是首创；
- **锚定计分谱系**：对标已发表论文数值是数值基准的标准做法，本文首次系统披露其三个被低估的隐患（方向不对称、退化计分带、未钉死单位）并各给出可审计规则。

## 三、问题定义

### 3.1 评测对象的定义

被测对象是「模型 + harness」组合（如 GPT-6 Astra + codex CLI）。每个任务中，Agent 被丢进一个网络隔离的 Docker 终端容器，拿到：题面原文 + 官方附件 + 21 张从官方 PDF 裁剪的图 + 一个输出 schema（只给字段名与类型）。Agent 必须在 4 小时内产出**一个 JSON 制品**（多出的 CSV/XLSX/PNG 不计分）。制品之后的一切——计分与可行性——全部机器可执行。

### 3.2 形式化：单侧计分与多参考面板

设某任务 t 的指标集 M(t)，其人类优秀论文面板 P(t)，论文 p 实际报告的字段子集 S_p。提交 m 在面板上的得分为：

**O-EVAL(m, t) = (1/|P≠(t)|) Σ_p R(m, S_p)**

其中 R 是把权重在 S_p 上重归一后的加权指标分。每篇论文投一票——「模型在这个人报告的字段上离这个人的答案有多近」。因为 R(p, S_p)=1，每篇论文与自己完全一致，复现稿复现整个面板。

单侧性由方向语义保证：每个指标声明 higher_is_better / lower_is_better / target_value / exact_value，**方向性指标采用不对称单侧奖励：达到或超过锚点从不低于 1.0 分**——比论文做得好永不挨罚。两条契约测试锁死这两个性质：oracle 自洽（每个复现稿恰好 1.0 分）、单侧性（到锚点或以上绝不算失败）。

### 3.3 可行性的三层分类学

论文对「可行」做了一个诚实的分层，这是理解其验证设计的关键：

| 层级 | 内容 | 谁来验证 |
|---|---|---|
| A — 单位/取值范围 | 概率 ∈[0,1]、厚度>0、计数非负 | 程序门 + Lean |
| B — 内部一致性 | 面积=格数×宽×高、分区求和、精确恒等式 | 程序门 + Lean |
| C — 物理真值 | 这片场真的产 60 MW 吗？ | 都不能——需独立重放或物理模型 |

两层验证**只声明能决定 A 与 B**；证据缺失的义务被报告为「有见证的缺口」而非默默通过——审计从不高估自己证明了什么。

## 四、问题解法

### 4.0 全景

```
[任务包] 题面原文 + 附件 + 21 图 → [Agent 容器]（断网终端, 2CPU/8GB/4h）
                                          │ 产出单个 JSON 制品
                                          ▼
                              [独立验证器容器]（无网, 180s）
                                          │
              ┌───────────────────────────┼────────────────────────┐
              ▼                           ▼                        ▼
     复现国奖论文(oracle)         程序化可行性硬门              Lean 4 证书层
     方向感知单侧计分             六种可判定不变式              624 条内核检查义务
     对多参考面板取均值           18/18 任务覆盖                无 Mathlib、整数精确
              └────────── 单侧 O-EVAL ──────────┴─── 门失败 → 任务记 0 分 ───┘
```

### 4.1 组件一：任务构建管线

18 题 = CUMCM 与 MCM 各 2023–2025 三年 × 每年 A/B/C 三题。只取近三年是刻意的：更老的题目在前 LLM 时代校准、任务组合与评审标准都不同，近年更难、更有区分度。两个赛事互补（CUMCM 偏工程/优化、中文；MCM 偏建模、英文），每年全取三题避免主题樱桃采摘（A=物理/工程、B=数据/优化、C=数据科学）。**21 张图分布在 6 个任务上是承重的**：题面引用它们表达文字未重述的几何（如板凳龙掉头曲线决定龙头终速），没有图像通道的 harness 物理上无法恢复——这就是多模态评测的意义。基准是纯评测集，无训练/验证/测试划分。

### 4.2 组件二：方向感知单侧计分 + 可审计边界规则

三条命名的边界规则处理反复出现的失败模式：

1. **退化计分带**：宽度小于数值量级 2% 的带无法区分好坏，扩到 5%（实际改动一格：stair-wear 72.67→73.52）；
2. **不可比单位**：锚点是任意原始指数、schema 未钉死单位（如七鳃鳗宿主鱼指数 **1080**）时，模型归一化到 [0,1] 报同一量不算错——此类指标按「仅配置」规则对包括 oracle 在内的所有人剔除；
3. **基数不匹配**：多余条目排除而非计为缺失。域外值（相关系数出 [−1,1]、负计数）记零分并记录原因。

两个报告指标：**O-EVAL = clamp(R/O, 0, 1)**（对 oracle 归一的绝对分）；**MULTI-BO = 1 + clip((O_t−f_t)/(1−f_t), −1, +1)**（对 DeepSeek-Flash 基线的多参考增益指数，1.0=持平 Flash，1.08=吃掉剩余差距的 8%；余量 <0.10 时退回原始差；缺失制品记 −1）。它是比值不是百分比，不可与 O-EVAL 直接比。

### 4.3 组件三：多参考面板——「问询每一位人类专家」

建模无唯一正解，于是对每个任务抽取**全部可得的**优秀论文最终问数值：**99 篇面板论文、94 篇产出可计分数量**，覆盖 18/18 任务，每题 1–18 篇（中位数 4）。等权保证一人一票；只报告单一字段的论文充当单字段检查而非被丢弃——对不完整报告的诚实处理。论文绝不静默丢弃：给不出数量的 5 篇携带机器可读的排除理由（number_only_in_figure、figure_only、no_numeric_estimate 等五类）；数值从不向现有锚点插值或调整。

面板还让人类分歧显形：mcm-2024-c-tennis（网球动量）上 **11 篇优秀论文中 10 篇**认为动量假设成立，而复现锚点（本身也是国奖论文）认为不成立——答主流得 0.909、答锚点得 0.091，分数反映的是选了哪种有效统计检验而非建模质量。此类「文献分裂」任务被显式标记并**排除出任何头部排名**但保留在面板中。

### 4.4 组件四：两层可行性验证

**第一层：程序化硬门。** 每任务注册一个可行性检查（覆盖 18/18），所有硬错误分支落入六种可判定不变式：domain/range（概率∈[0,1]、厚度>0）、integer/binary（决策位∈{0,1}）、ordering（q95≥均值、峰值≥平均）、exact identity（面积=格数×宽×高、龙头速度×放大比≤2 m/s）、finite domain（决策位数∈{16,17}）、partition/sum（地类计数求和）。三条契约保持门的诚实：覆盖性（任务不能裸奔）、oracle 自洽（国奖复现必须通过自己的检查）、区分性（合成与真实违规必须被拒）。门失败 → O-EVAL 记 0、MULTI-BO 记 −1。

**第二层：Lean 4 证书。** 为了让「门自己」也可审计，同一批不变式被重新证明为 Lean 4 定理——**624 条义务跨全部 18 任务**，由 decide 或 omega 消解。不用 Mathlib（命题在精确整数上可判定，数值放大成整数、无浮点容差——唯一例外是复合指数，容差本身是被审计假设的一部分）。信任审计（#print axioms）只出现 propext/Quot.sound 或无公理，grep 确认无 sorryAx、无 native_decide。**区分性测试套件**每次突变一个数值叶并要求构建失败且引用该字段——六种形式的十种突变全部被拒。两个软警告被升级成证明：旅游接受度指数被单位约定驳倒、可持续性得分在任何合理容差下两个约定都不符。

## 五、评估指标与实验证据

### 5.1 主结果：七个多模态参赛项

每项三种子 × 18 任务，Docker（python:3.12-slim + 固定科学栈）、断网（模型流量走本地重试代理，无法搜答案或装包）、2 CPU / 8GB / 无 GPU / 4 小时：

| 模型 + harness | O-EVAL(%) | MULTI-BO | 成本(USD) |
|---|---|---|---|
| GPT-6 Astra + codex | **64.58 ± 2.93** | 1.132 ± 0.02 | 246.41 |
| Fable 5.1 + claude-code | 63.11 ± 1.33 | 1.081 ± 0.05 | 272.80 |
| DeepSeek-Flash + opencode | 59.81 ± 1.25 | 1.000 | **2.54** |
| GPT-5.5 xhigh + codex | 59.75 ± 1.55 | 0.998 ± 0.01 | 99.37 |
| Kimi K3 + opencode | 58.23 ± 1.12 | 0.953 ± 0.04 | 23.26 |
| GLM-5.3 + opencode | 57.78 ± 1.30 | 0.941 ± 0.05 | 28.15 |
| Qwen3.8 Flash + opencode | 52.66 ± 1.17 | 0.803 ± 0.04 | 8.30 |

五条发现：

1. **最新旗舰领跑**：GPT-6 与 Fable 分别领先第三名 4.8 与 3.4 分；
2. **钱买到的是有界差距**：领跑者 $246–273 一轮，而 $2.54 的 DeepSeek-Flash 只落后 4.8 分——**约 1/100 成本**拿到 92.6% 的分数；
3. **低价开源扎堆**：只有两个旗舰超过基线指数，其余全在 1.0 以下；
4. **小分差≠确定排名**：种子间标准差最大 2.93 pp，两领跑者间 1.5 pp 的差距在一个标准差以内——报告次序但不宣称显著；
5. **推理算力非单调**：DeepSeek-Flash 开最大推理档反而跌到 **48.11%**（MULTI-BO 0.864），比默认档低 11.7 分且更贵。

### 5.2 Harness 敏感性：测的是模型不是壳

固定 DeepSeek-Flash 换四种 harness：O-EVAL 只在 **59.81–59.88 之间移动（0.07 pp）**，远小于种子偏差——排行榜量的是模型本身。

### 5.3 结构性发现

- **CUMCM–MCM 巨差**：弱参赛项 CUMCM 接近 100% 而 MCM 在 0–60%；最强者也只略微收窄（GPT-6：CUMCM 82.9 vs MCM 46.2；GPT-5.5：79.7 vs 39.8）。工程题有确定终值、MCM 更开放且锚点更可争——**基准的区分力来自开放性 MCM 题**；
- **两个全有全无任务**：mcm-2024-b-submersible 所有人 100%，mcm-2024-c-tennis 连旗舰都低于 40%——这类任务区分的是模型 regime 而非同 regime 内的模型；
- **许多低分是参考尺度问题而非建模错误**：模型/面板比值超 5× 的指标（1080 的原始指数 vs [0,1] 归一、1.007 的可持续性分 vs 0–100 效用、6×6 网格 vs 数百格离散化）。

### 5.4 基准自审：发现并修复的计分陷阱

这是全文最珍贵的部分——作者审计自己的计分规则并公开改动：

- 两个门误报（带符号弹性被当负计数、缺失字段被当硬矛盾）修正，零分数变动；
- 退化带扩宽动一格 +0.35 pp；
- 剔除两个不可比单位指标使**每个参赛项整体抬升 0.05–2.62 pp**——系统性计分错误的典型指纹（对所有提交同等生效）；
- **最重的一笔：龙舞锚点自身物理不可行**。论文的 1.406276 m/s 会让把手达 1.406276×1.604793=**2.2568 m/s**，超过 2 m/s 上限——因为它在整数秒上采样、跨过了 t=14.48s 处的真实连续峰值。锚点修正为 **1.246266 m/s** 后：**12 个模型本来就报对了却一直坐着 49.82% 的分，2 个抄了错误论文值的反而拿着 100%**。基准错了、模型对了——这是对「独立可检验的可行性层」最锋利的论证。

### 5.5 可行性层抓住了什么

门硬性作废了 **7 个格子**：4 个 heliostat 违规（额定功率低于 60 MW 或镜面低于 2 m 下限）、smoke-screen / Juneau / Olympic 各一个。Lean 层把两个软警告变成证明，并通过「谓词拒绝已报告制品却接受修正制品」证明非空泛性。唯一数值良构的任务（龙舞）四次重跑一致到机器精度（std=4.6×10⁻¹⁶）。

### 5.6 三个案例研究

| 案例 | 教训 |
|---|---|
| 龙舞 | 模型对、锚点错；恒等式 head_speed×ratio=2 m/s 是暴露论文值不可行的机制 |
| 种植（crop） | 论文全约束集在官方附件上联合不可行、报告值来自未公开启发式 → 锚定在论文需求上限下可复现的精确 MILP 最优解并显式标记 |
| Juneau | 可持续性分各单位尺度不一（锚点 1.007 vs 某代理自报的 0–100 效用）→ 修复应放在任务 schema 钉死字段范围，而非评分器里重缩放 |

## 六、效果优势的根源解释

基准论文的「效果」= 基准设计的证明力。逐条检验：每个实验设计为什么能支撑作者的主张？

**主张 1：分数量的是建模能力而非文采或抄写。**
因果链：LLM 裁判 → 只评组织与行文 → 数字从不被核对 → 流畅但违规的报告得高分（Figure 1a 的反例：h=1.2 m 违反 h∈[2,6] m 照样拿 8.5/10）。TB-MathModel 改为 schema 约束的 JSON 制品 + 可执行验证器 → 评的只能是数值核心；单侧计分消除了「抄锚点最优」的激励（抄与超越同分 1.0，但超越其他指标空间仍可赢）；断网容器消除搜题作弊。证明力证据：**harness 换四个只动 0.07 pp**（排除壳贡献）、**门精准移除恰好违反约束的 7 格而排名其余稳定**（不是一刀切惩罚）、龙舞案例 12 个正确模型被旧锚点错压至 49.82% 被修正——说明分数确实跟着数值正确性走，且错误可被机制性发现与修复。

**主张 2：多参考面板比单锚点更公正。**
因果链：单锚点 → 某一队的假设成为真理 → 模型答「另一种有效检验」被判错。面板 → 一人一票 → 分数=「与多个人类接受答案的接近度」。证明力证据：网球动量任务上 10/11 论文与锚点对立，面板使「答主流」得 0.909；而此类任务被显式排除出头部排名——设计不仅纠偏，还**标记了自己纠不了偏的地方**。

**主张 3：可行性验证可靠且不越权。**
因果链：只靠锚点距离 → 看似合理的违规值漏网 → 加独立于计分的验证层。六种不变式全部可判定（无需人类裁判）、Lean 层把门的正确性本身内核检查（624 义务、无 Mathlib、整数精确、无 sorryAx/native_decide、十突变全拒）→ 验证器的正确性也变成机器可查事实。证明力证据：龙舞不可行锚点正是被「精确恒等式」抓住的；三层分类学（A/B 可判、C 需物理重放）显式声明了验证边界——**不过度声明**本身就是证明力的一部分。

**主张 4：基准能指导模型开发。**
因果链：可行性门 + oracle 归一分 = 可执行可复现的 RL 奖励 → 拒绝采样（保留并按 O-EVAL 排序过门轨迹）今天就能做；GRPO 以门为硬乘子教模型「先满足物理再追参考」。发现 (a) MCM 开放题区分质量 → 训练假设/建模/敏感性而非闭式求解；发现 (c) 大量失分是单位/尺度错配 → 出数前先声明并核验单位、范围、schema。龙舞案例表明 12 个模型会算但不会自检——验证器进奖励恰好补这一课。

**成立边界**：18 题的小面板使种子噪声（±2.9 pp）接近头部差距，作者如实声明相邻行不可显著区分；面板规模随各题国奖论文数波动（1–18 篇）；C 层物理真值超出结构化制品可判范围——只有题目允许独立重放时才检查。

## 七、必要知识反推

要独立做出这个工作，需要哪些知识？

### 7.1 领域知识层

- **数学建模的工作流本体**：假设→模型→求解→敏感性→建议的链条，以及「同一情境多种合理建法」的本质——没有这个认知就不会理解为什么必须多参考、为什么 single anchor 是认识论错误；
- **CUMCM/MCM 赛事生态**：赛制、国奖（Outstanding）论文的可得性、A/B/C 题的题型分布、2023–2025 的题目内容——选材与复现的全部基础；
- **不变式思维**：把「物理可行」翻译成六种可判定形式（范围/序/恒等式/有限域/划分）——这是把模糊的「合理性」变成可执行检查的抽象能力。

### 7.2 方法论知识层

- **测量论视角的基准设计**：效度（测的是建模不是文采）、信度（种子方差 vs 排名差距的诚实报告）、区分度（全有全无任务的诊断）、偏差源分析（harness、单位、锚点错误各自的指纹）；
- **LLM 裁判的失效模式**：校准依赖、不可复现、数字不核——以及「可执行验证器」替代路线的适用条件（答案可结构化、约束可判定）；
- **单侧计分与不对称奖励**：方向语义（higher/lower/target/exact）为何必须来自建模语义而非数值符号；
- **契约测试（contract test）**：把设计性质（oracle 自洽、单侧性、门覆盖/自洽/区分）变成 CI 式断言——基准自身的回归测试。

### 7.3 工程知识层

- **容器化 Agent 评测设施**：任务/Agent/验证器三容器分离、网络隔离与模型代理、资源限额、CLI harness 预装、成本按固定价格快照核算；
- **Lean 4 可判定性工程**：decide/omega 消解、整数缩放去浮点、#print axioms 信任审计、变异测试验证非空泛——不用 Mathlib 的极简证明栈；
- **MILP 复现**：当论文约束联合不可行时退到可复现精确最优解并标记（crop 案例）；
- **数据溯源（provenance）工程**：每锚点记录论文 id、PDF/OCR 源、复现范围——龙舞纠错之所以可能，正因为锚点可重推导。

### 7.4 知识融合的关键节点

1. **「用证明器审计基准」的角色反转**：形式化验证社区用 Lean 找答案，本文用它证明基准自己的判定——两个领域的嫁接点在「断言变机器可查事实」；
2. **「问询每位专家」的面板化**：把无唯一真值从借口变成设计——投票式归一化 + 排除理由机器可读；
3. **「审计自己并公开改动量」的基准伦理**：0.05–2.62 pp 的系统性抬升、龙舞反转全部如实披露——可信度的来源不是宣称而是自审记录。

## 八、论文中可以提取的通用性灵感

### 灵感 1：单侧计分——对齐参考时永不惩罚超越

- **核心思想**：凡是「以参考答案为锚」的评价（基准、KPI、模仿学习奖励），距离型指标会系统性奖励复制、惩罚改进；给指标声明语义方向并对方向性指标用单侧奖励（达到或超越锚点即满分），可消除这一扭曲。
- **论文证据**：单侧性被契约测试锁死；龙舞案例中抄错误论文值的两个模型曾在朴素计分下拿 100%。
- **推广场景**：(1) 企业对标最佳实践时的 KPI 设计（超过标杆不该扣分）；(2) 模仿学习奖励塑形；(3) 代码评审中对「优于参考实现」的方案；(4) 自动阅卷系统的开放题评分；(5) 体育/竞赛打分规则中「距离世界纪录」类指标。

### 灵感 2：用形式化工具审计评测器本身——「谁来验证验证器」

- **核心思想**：评测系统的可信度瓶颈常在其判定逻辑自身；把判定规则编译成定理证明器的义务，让「检查器的正确性」也变成机器可查的事实，并用变异测试证明检查非空泛。
- **论文证据**：624 条 Lean 义务 + 信任审计（无 sorryAx/native_decide）+ 十突变区分套件；龙舞不可行锚点被恒等式义务暴露。
- **推广场景**:(1) 风控规则的合规性形式化审计；(2) 数据质量断言生成 SMT 义务；(3) CI 中对测试套件本身的变异测试；(4) 法规即代码（rules as code）的可判定子集；(5) 医疗决策支持系统的约束检查器认证。

### 灵感 3：多参考面板——无唯一真值时的「问询所有专家」

- **核心思想**：开放性任务的「真值」是一组人类可接受答案的分布而非一个点；对全部可得专家答案等权投票、每人只在其报告的字段上投票、分歧大的样本显式标记并隔离出排名。
- **论文证据**：99 篇面板论文、94 篇产出可计分数量、中位 4 篇/题；网球任务 10/11 对锚点的分歧被显式标记。
- **推广场景**：(1) 医学诊断的第二意见聚合；(2) 开放式生成内容的人工评估协议；(3) 众包标注的标注者分歧建模（不静默取多数）；(4) 需求评审中多方干系人加权；(5) 政策情景分析的多模型集成。

### 灵感 4：验证器即奖励——评测基建直接变成训练信号

- **核心思想**：一个可执行、可复现、带可行性门的评分器天然就是 RL 奖励：拒绝采样立即可用，GRPO 把门作为硬乘子让模型「先合规再优化」；评测集同时是轨迹收集器。
- **论文证据**：Section 4.4 的三个杠杆（verified reward for RL、针对失败模式的训练目标、可检验的 witness 字段）；龙舞案例「模型会算但不会自检」的诊断直指验证器进奖励的价值。
- **推广场景**：(1) 任何带规则检查器的自动评分任务（代码合规、报表勾稽）转化为 RL 环境；(2) 合规前置的产品流程设计；(3) 用「要求提交证据字段」训练模型自检；(4) 教育中「过程性评分量规」直接驱动练习系统。

### 灵感 5：成本–精度前沿上的「足够好」经济学

- **核心思想**：排行榜应同时报告能力与成本；1/100 成本拿到 92% 分数的开源选项在很多现实部署中是理性选择，而「更多推理算力」并不单调换分（DeepSeek 最大档反而 −11.7 分）。
- **论文证据**：$2.54 的 DeepSeek-Flash 59.81% vs $246 的 GPT-6 64.58%；最大推理档跌至 48.11%；成本主要由 token 单价而非用量决定（GPT-5.5 费率约为 Flash 的 33×/50×）。
- **推广场景**:(1) 企业模型选型的性价比决策矩阵；(2) 自动化任务的「何时停」策略（过度思考有害）；(3) 云资源分级定价的用量设计；(4) 竞赛/考试中时间预算分配。

### 灵感 6：基准自审与「系统性误差指纹」

- **核心思想**：当一项修正使**所有**被评对象同向移动时，它是评测系统的系统误差而非被评者的差异；基准应维护「发现–修复–量化影响」的公开账本，并敢于公布「曾经是基准错了」的案例。
- **论文证据**：剔单位不可比指标使所有参赛项 +0.05–2.62 pp（系统误差指纹）；龙舞 12 个模型 49.82%→修正；两个门误报零分变的记录。
- **推广场景**:(1) 考试机构的质量审计与等值化；(2) A/B 实验平台的指标口径变更管理；(3) 竞赛排行榜的作弊与误差复盘公告；(4) 度量体系 SLO 的「度量自身的 SLO」；(5) 科学仪器的校准履历。

### B. 术语备忘

- **O-EVAL**：多参考面板分（对 oracle 归一并 clamp 到 [0,1] 后的任务均值）。
- **MULTI-BO**：对 DeepSeek-Flash 基线的多参考增益指数（1.0=持平；比值非百分比）。
- **单侧计分（one-sided scoring）**：方向性指标达到或超越锚点不低于 1.0 分，永不惩罚改进。
- **六种可判定不变式**：domain/range、integer/binary、ordering、exact identity、finite domain、partition/sum。
- **硬门（hard gate）**：可行性验证失败 → 该任务 O-EVAL=0、MULTI-BO=−1。
- **文献分裂（literature-split）**：人类面板内部多数与锚点对立的任务，标记并排除出头部排名。
- **三层可行性**：A 单位/范围、B 内部一致性（两层验证器可判）、C 物理真值（需独立重放）。
- **承重图（load-bearing figures）**：题面依赖图承载几何信息的 21 张图，缺失则答案不可恢复。
