# 一、论文背景

## 1.1 大模型做算术：准确但不保证

语言模型（LLM）如今能答对大多数长算术题——但这句陈述里藏着一个关键限定词："大多数"。当我们说 GPT-6.1 加法准确率 98.6% 时，这个数字来自**采样估计**：抽一批题测一测，统计正确比例。它对**下一道没见过的题**没有任何承诺。论文开篇给出了一个极具冲击力的对照：GPT-6.1 Sol 在 220 道预注册题目中答对 217 道，它的 3 个错误全部发生在 300 位和 1000 位加法上——**错误答案是完整给出的、远在 token 预算之内、格式与正确答案完全一致**。也就是说，错误是"静默"的：用户没有任何办法从输出形式上察觉它错了。

这就是采样准确率与保证（guarantee）的区别：

- **采样准确率**："测过的题里 98.6% 是对的"——对未测输入没有约束力；
- **保证**："对所有输入（包括无限长的）都可证明正确"——数学命题，不是统计陈述。

## 1.2 现有两条路线及其缺口

**路线一：让模型自己更强**。链式思维（Chain-of-Thought，逐步写出推理过程）、改进位置编码、改数据格式，这些手段确实把模型能正确加减乘的长度往外推了。但每一项工作中，"对未见输入正确"始终只是一个估计，残留的错误是静默的。

**路线二：工具调用**。让模型调用计算器/代码解释器（Toolformer、PAL、ToRA、ReTool 等）。计算是精确了，但**计算过程被移出了网络**——模型只是"报了个算式让外部程序跑"。这带来一个哲学层面的损失：如果我们要理解"神经网络本身能否可靠地执行算法"，工具调用等于交了白卷。同时它也带来工程依赖：需要外部解释器、需要决定何时调用、调用环节本身不受网络层面的任何保证约束。

## 1.3 问题的数学本质：无限 vs 有限

要让一个网络在**无限多**的输入上都正确，行为必须被**有限多条事实**固定住。这在什么条件下可能？论文给出了一个可以追溯到 1956 年的经典观察（见第六部分详述）：**如果计算的每一步只读外部工作内存的一个有界视图，且步与步之间没有其他状态传递，那么所有步骤的输入只来自一个有限集合**——枚举检查这个集合，就等于检查了任意长度的所有运行。

这个条件与链式思维恰好相反：链式思维的每一步都能读到之前所有步骤的输出，上下文无限增长，因此**任何有限测试都不足以认证**（论文定理 2 严格证明了这一点）。

于是背景问题清晰了：能否**用构造的方式**让一个预训练模型满足"每步只读有界视图"，然后对它做有限枚举认证，把"大概率对"升级成"必然对"——同时计算仍留在网络内部？这就是 Sketchpad。

# 二、论文定位和关联工作

## 2.1 研究谱系

**谱系一：神经网络做算法/算术**。Neural GPU（2016）从零训练出能超出训练长度的二进制加减乘；Goat 等微调工作在有界长度上达到高准确率；可微转录机、神经细胞自动机从零训练即能远超训练长度。它们的共同点：**准确率靠采样估计**，且多数回避了除法、gcd 等难题。也有证明性工作——理想化训练假设下的精确性、小型 RNN 加法的 MDL 目标证明、专用参数化 transformer 求值任意深度布尔电路——但都是"理想化/小型/专用"网络，不是预训练大模型。

**谱系二：程序化执行与上下文纪律**。Neural Programmer-Interpreter（NPI，2016）让网络通过指针读便笺本执行小学加法——Sketchpad 的"指针读纸"在架构上正是它的直系后代，而 Cai 等人 2017 年对 NPI 泛化性的递归验证也是本文定理 1 的前驱。CAEF（2024）微调 Llama-3.1-8B 在文本带上逐步执行算术。理论侧，inductive scratchpad（Abbe 等，2024）与 **PENCIL（Yang 等，ICML 2025，[arXiv:2503.14337](https://arxiv.org/abs/2503.14337)）**都发现"限制每步读取的内容"是长度泛化的关键——PENCIL 的标题"Long Thoughts with Short Memory"几乎就是 Sketchpad 思想的另一个表述。

**谱系三：语言模型解码的计算普遍性与认证**。Schuurmans 等证明自回归 LLM 解码计算上万能；**Lewandowski 等（2026，[arXiv:2601.08061](https://arxiv.org/abs/2601.08061)）**迈出认证一步：把每步解码限制在固定提示+局部符号对上，枚举检查某通用系统全部 1,857 条规则（温度 0 精确匹配）。Sketchpad 与它共享"pinned 政策"这个极限形式，但有两点本质推进：① Lewandowski 检查的是预训练模型"碰巧"通过所有规则（零训练），Sketchpad **训练**一个模型去满足条件；② Lewandowski 用精确匹配，Sketchpad 认证 **margin**，经定理 3 落到 fp16 真实硬件路径上仍然稳健。

**谱系四：神经网络验证**。主流验证（Reluplex 等 SMT 方法、zonotope 传播）在**连续输入区域**上界定输出，计算代价高且难上大模型。Gross 等（NeurIPS 2024）对固定输入规模的小 transformer 给出紧凑性能证明。Sketchpad 的差异在于：**输入集是有限的（2,446 个视图），却覆盖了任意长度的输入**——有限枚举即可，无需解约束求解器。

**谱系五：视觉输入与持续学习**。像素语言模型（PixelBERT 类）读渲染文本；2016 年就有小网络从数字图片学加减法但学不会乘法。持续学习侧（LwF、EWC、progressive networks、Activated LoRA、模态门控 adapter）为本文的"乘性门"提供了语境：灾难性遗忘是微调的顽疾，本文的门在 g=0 时**逐位**恢复基座模型，是渐进网络的"硬开关"变体。

## 2.2 定位总结

| 维度 | 之前的路线 | 本论文 |
|---|---|---|
| 正确性依据 | 采样估计（CoT、长度泛化、微调） | 有限枚举 + Lean 证明的等价性（构造性保证） |
| 计算位置 | 网络外（工具调用） | **网络内**（每次前向就是一步计算） |
| 认证对象 | 理想化/小型/专用网络，或精确算术假设 | 预训练 0.8B VLM + LoRA，**部署路径 fp16 实测 margin** |
| 覆盖运算 | 多为加减乘 | 加减乘除、平方根、gcd，再组合出多项式代数 |
| 每步读取 | 无界上下文（CoT 类） | 三格视图（32×96 像素），步间零状态 |
| 与基座关系 | 微调损伤基座（灾难性遗忘） | 乘性门 g=0 逐位还原基座 |

定位结论：Sketchpad 站在"NPI 的指针读纸 + Moore 的有限实验理论 + Lewandowski 的 pinned 解码认证"三条线的交点上，第一次把三者同时推到"预训练多模态大模型 + 形式化证明 + 真实部署硬件"的完整闭环。

# 三、问题定义

## 3.1 从具体到抽象

具体场景是"让小模型做任意位数精确算术"。剥掉场景外壳，论文面对的**抽象问题**是：

> **一个函数（神经网络）在无限输入域上的正确性，何时可以被有限多的检查所固定？**

注意这不是"训练一个更准的模型"的问题——那是优化问题；这是"正确性如何变得可查"的问题——是**性质归约**问题：把"无限输入上的全称量词"归约为"有限集合上的全称量词"。

## 3.2 归约成立的结构条件

论文的核心洞察可以写成一条对应关系：

| 自动机/程序世界 | Sketchpad 世界 |
|---|---|
| 有限状态机，每次读一个输入符号 | 模型每次读一个三格视图 |
| 状态转移函数 δ(s, e) | 网络输出 f(视图) |
| 状态寄存在机器内部（有限） | 状态全部寄存在纸面（sheet）上，由 runtime 落笔 |
| 输入字母表有限 | 视图集合 V 有限（2,446 个） |
| 检查全部转移 = 理解机器 | 检查全部视图 = 认证网络 |

**形式化定义**（定理 1 的语言）：设配置集合 C（纸面内容+视图位置+控制状态），视图映射 view: C → V∪{⊥}，落笔映射 paint: C×A → C。模型运行是从 c₀ 开始反复 c_{t+1} = paint(c_t, f(view(c_t)))；参考运行用真值表 T 代替 f。那么：

**模型从每个初始配置的运行 ≡ 参考运行 ⟺ f(v) = T(v) 对参考运行可达的所有视图 v 成立。**

特别地，若可达视图都在表内（R_T(I) ⊆ V）且每个视图 margin > 0，则**任意长度的每次运行都精确**。

## 3.3 这个抽象精妙在哪

第一，它把正确性**责任切成了两半**：网络要负责的（f = T on V）是有限的、可枚举的；运行时要负责的（布局只会呈现表内视图 + 参考程序本身正确）是常规代码问题。两类责任可以用完全不同的手段审计。

第二，它有一个**必要的反面**（定理 2）：如果允许每步读历史（链式思维），任何有限测试集都不充分——论文构造了一个"查表正确 + 一个 attention 头"的解码器族，对任何有限测试集都存在一个成员全过测试、却在更长的运行上出错。这说明 pinned-sheet 政策不是工程取巧，而是**逻辑必要**。

第三，它把浮点硬件现实纳入了定义（定理 3）：认证的不是"精确算术下的模型"而是"真实执行路径上的模型"，只要 margin 超过扰动上限的两倍，argmax 就不变。

# 四、问题解法

Sketchpad 系统由三个部分构成：**一张纸（sheet）、一个模型（Qwen3.5-0.8B + LoRA）、一个运行时（runtime）**。设计只服务于一个要求：每步输入必须来自可预先列出的有限集合。

## 4.1 纸面机器：视图、提示与表

**纸**是 32 像素格子的网格，每格空白或一个数字（固定字形集 sprite，因此每个视图是一幅**精确的图像**）。**视图**是连续三格，渲染成 32×96 像素的条带，视觉编码器读为恰好 3 个图像 token。

一步的提示（prompt）只有：一个操作 token + 视图图像 + "=" + 两个占位 token。模型在一次前向中在这三个位置输出：**一位数字、进位/借位、下一操作**。提示里没有任何其他东西——作者称之为 **pinned-sheet 政策**：模型的输出是视图的函数 f(视图)，仅此而已。步与步之间模型不留任何状态；纸是它唯一的记忆。

**表（tables）**穷举每种操作能遇到的每个视图及正确输出：

| 操作 | 含义 | 视图构成 | 行数 |
|---|---|---|---|
| SUM | 列加 | 进位(空/1) + 上下两数字(空/0-9)，输出 0-19 单 token | 242 |
| MUL | 单列乘 | 被乘数位 × 乘数位 + 进位(空/0-8) | 1,100 |
| ADD/ADZ/FLS/NXT | 部分积累加/收尾/冲刷/下一位 | 乘法流程的其余四表 | 453 |
| SUB | 列减（带借位） | 借位 + 上下两数字 | 242 |
| EST | 商的估计 | 余数前两位 + 除数首位(5-9) | 400 |
| DEC | 估计降 1 | 猜测数 1-9 | 9 |
| **合计** | | | **2,446** |

为什么这 2,446 就够？加法每列最多"两个数字+一个进位"，排列组合有限；除法用了 **Knuth Algorithm D** 的规范化：先把两数同乘 f=⌊10/(d₀+1)⌋ 使除数首位 ≥5，此后商位估计 q̂=min(9, ⌊(10r₁+r₂)/d⌋) 与真值之差至多 2，靠"最高列借位暴露估计过大 → DEC 降 1 → 至多补两次"收敛，于是商位决策也只依赖三个格子的局部信息。平方根用逐位法（对 c²a 取 c∈{1,2,4,5} 保证首位根 25-49），复用同一张 EST 表。gcd 就是循环的欧几里得除法。运行时每步都断言当前视图在表内，并用 1,000 题随机参考运行/程序复核。

## 4.2 模型与训练：把表"教"进 LoRA

底座 **Qwen3.5-0.8B**：24 层（隐藏 1024），6 层全注意力 + 18 层 Gated DeltaNet 的混合架构，自带视觉编码器。唯一可训练部件是 **rank-16 LoRA**（scale 2），覆盖 150 个投影矩阵（注意力 QKV/O、DeltaNet 三投影、全部 FFN 三投影），共 **10.2M 参数（1.2%）**。

训练目标是三项之和：表行交叉熵 + **logit margin 的 hinge 损失**（hinge 目标 h=4）+ 对基座模型在 128 token 纯文本上的 KL 蒸馏惩罚（λ=1，防遗忘）。每 100 步算一次全量证书，margin < 2 的行进入重放；**全部行 margin ≥ 3 才停**。实际 1,200 步全过、1,600 步停止——**单张 H100 上 19.8 分钟**。注意这些表是"教"会的而不是底座自带的：基座 Qwen3.5-0.8B 零样本只能通过 12/2,446 个视图（还全是"照抄单个数字"的 SUM 视图），加 8 个示例做 few-shot 也只过 158/2,380。

## 4.3 认证：三个定理与一张证书

**定理 1（视图上精确 ⟺ 任意长度运行精确）**。充分方向：归纳法——只要 f=T 在可达视图上成立，每步落笔结果与参考运行一致，于是下一步视图仍在可达集内，归纳完成。必要方向需 paint 关于输出单射。**这条定理在 Lean 4（Mathlib 4.35.0）中形式化，无 sorry、无附加公理**。

**定理 2（pinned 政策的必要性）**。构造 4-token 词表、两状态表的解码器族：一个查表（margin R）+ 一个对 sink token 打分 e^c 的 attention 头，把 4R·k/(e^c+n) 写进错误状态的 logit（n=上下文长度、k=事件数）。取 e^c=3M+5（M 为最长测试上下文），该头在所有 ≤M 的测试上下文上无害、margin 全正，却在长度 2M+4 的运行上翻盘。这就是 Moore 1956"有限实验无法识别无限状态机"在 transformer 上的复活——**链式思维下没有有限测试集能认证模型**。

**定理 3（扰动鲁棒）**。若执行路径上每个视图的 logit 与证书记录值之差 ∥·∥∞ ≤ τ，且所有 margin > 2τ，则 argmax 不变，运行仍精确。这把证书从"精确算术的世界"接到"fp16 浮点的世界"。

**证书落地到部署设备**。部署路径是浏览器：ONNX Runtime Web + WebGPU + 16 位精度（Apple M4 笔记本 GPU）。实测全部 2,446 视图通过，最小 margin **3.02 logits**（出现在"5+6 无进位"这个加法视图），乘法 6.52、计算器表 4.61——按定理 3 容忍任何 <1.51 的 logit 扰动。与 32 位 PyTorch 服务端（最小 3.96）每表差异 <1 logit，而 4-bit 量化的早期 adapter 偏差可达 3 logits 且能把 margin 从 +9.4 打到 -8.9——对照之下 16 位路径的稳定性并非理所当然。批处理会改变 fp16 logit，实测随机批（2/4/32）最大 logit 移动 1.09、margin 移动 0.64，仍满足 τ=1.09 < 1.51。完整检查在 M4 上 3.5 分钟；证书是 JSON 文件，绑定字形集与模型文件的 **hash**、设备、库版本、每行 margin（精确到 10⁻³）；新 GPU 上客户端按需重算，默认重查每表最低 margin 的十分之一。

## 4.4 组合成代数与"门"

**代数运行时（定理 4）**：多项式求解/展开/因式分解的每一步推导都是对已认证过程的调用序列，其出错概率被分解为"表错（被证书排除）+ 转录错 + 组合程序错"三部分，后两者由常规代码的**答案检查**守护（有理根代回、无理根对用 Vieta 关系整数验证、展开式在 x=1 点检验）。教科书路线（移项、求根公式、Pascal 规则、有理根定理+综合除法）在 11 题基准上 10 题快于"多点求值+插值"的计算机代数路线。

**乘性门（gating）**：微调算术会伤及别的能力——一个初步算术 adapter 虽只把纯文本困惑度改变 0.65%，却让指令遵循 IFEval 掉 16.4 分（灾难性遗忘的教科书案例）。解法是给每个 LoRA 分支乘一个标量图输入 g：y = xW + g·s·(xAᵀ)Bᵀ。**g=0 时逐位等于基座**（在 2,500 次 chat 前向 + 2,688 个表视图上对 logit/隐状态/缓存状态逐 bit 验证）；g=1 时在 M4 上复现全部 2,446 个 margin。在此基础上训练**对话 adapter**：模型自己决定何时输出一段"纸面程序"，生成暂停、runtime 执行、结果回填。训练管线 = 监督数据 + 自蒸馏 + 在策略蒸馏（off 基座）+ GRPO（KL 锚定监督检查点），且**每个阶段都保留表目标**、以 2,446 行全过为硬门槛。

## 5.1 指标体系：论文的"证明力"设计

这篇论文的指标设计非常讲究层次——每一层都直接对应一个主张：

| 层 | 指标 | 证明的主张 |
|---|---|---|
| 认证层 | 2,446 视图 margin > 0（fp16 部署路径实测） | "有限枚举 = 任意长度正确"的条件成立（定理1+3） |
| 对照层 | 基座模型同 2,446 视图的通过数（12/2,446；8-shot 158/2,380） | 能力是 adapter 教出来的，非底座自带 |

## 5.3 核心结果二：浏览器 200 题与成本模型

Apple M4 / Chrome / WebGPU / fp16，一次一题：除法（10 位小数）中位 7.0s、平方根（6 位）9.8s、gcd 7.0s、带符号加减 2.0s，**200/200 全部精确**。实测时间贴合线性成本模型 t ≈ 0.065s×前向数 + 0.037s×视图数（中位比率 1.01）——独立过程共享批量前向（4 个任务 32 次前向 vs 串行 73 次）。

## 5.4 核心结果三：margin 的含义与扰动容忍

fp16 部署路径全部 2,446 视图通过，最小 margin 3.02 logits。这个数字的意义由定理 3 赋予：**只要真实路径上 logit 偏离证书记录不超过 1.51，结论不变**。批处理实测扰动 ≤1.09，安全余量成立；4-bit 路径的 ±3 偏差则会击穿证书——这解释了为何部署选 16 位且证书必须绑定具体执行路径的文件 hash。

## 5.5 核心结果四：能力保留（诚实的部分失败）

对话 adapter 在 held-out 表述上调用纸面的精度/召回 0.994/0.989（基座 4-shot 仅 0.971/0.809）；词题/方程/嵌入散文的正确书写率 92.8%/96.7%/98.3%。开发集上 IFEval -1.5±2.0、GSM8K -1.6±3.4、MMLU -1.4±1.6，均在预注册判据内。但作者发现它是第五个在相同题目上打分的候选，于是**主动在未用过的题上重测**：MMLU 守住（-2.0±1.1），**GSM8K 没守住：-5.8±1.7**（0.491 vs 0.549）。论文如实报告"多步应用题上的保留判据未被确认"，并把损失定位在多步推理而非纸面调用环节。这种把失败写进正文与图表（Extended Data Table 4 末行）的做法，本身就是论文可信度的一部分。

## 5.6 机制证据：决定发生在哪一层

logit lens 显示正确输出成为稳定 top token 的中位深度：加法 19、乘法 20（第 5 个全注意力层结束时）；深度 ≤15 时任何表最多 13% 视图就位。类均值干预（class-mean intervention）：深度 20 之后施加，加法 79/80、乘法 80/80 的输出被改到目标；深度 ≤15 施加则零改变；乘法在 19→20 层间突变。结论：**数字决策集中在第五个全注意力层**——认证证书虽然不回答"网络哪里在算"，但机制分析补上了这一问。

# 六、效果优势的根源解释

## 6.1 根源机制与证据链

对比对象是"前沿模型 + 链式思维"。为什么 0.8B 能在 1000 位加法上全对、而 GPT-6.1 错 2 题？因果链如下（每步标注证据来源）：

1. **方法差异**：链式思维每步读整个历史（上下文随长度增长）；Sketchpad 每步只读三格视图、步间零状态。【论文设计，可直接验证】
2. **机制变化 A——错误面从无限变有限**：无界上下文中，"对未见输入正确"需要无穷多条事实来固定；有界视图下，正确性 = 2,446 行查表。【定理 1，Lean 形式化】
3. **机制变化 B——认证可执行**：margin>0 在 fp16 真实路径上逐行实测通过，且 3.02 的最小 margin 给出 1.51 的扰动容忍。【论文实验，浏览器证书】
4. **机制变化 C——错误传播被结构性切断**：链式思维中一步错则后续全错（上下文携带错误）；pinned 政策下每步输入只由"纸面真值"决定——若模型在某视图上正确，该步就正确，与之前发生过什么无关。【定理 1 归纳结构；定理 2 反面证明无界上下文不可认证】
5. **指标体现**：220/220 vs 217/220，且差距集中在最长的 1000 位（20/20 vs 19/20）；浏览器 200/200。【预注册实验】

关键在于：第 4 步不是"大概率对"的统计陈述，而是**结构上必然对**——这是"指标好看"与"指标证明了主张"的分界。220 题对比只是演示；真正的证明力在证书 + 定理，220 题是"证书确实落到地面"的一致性检查。

**反事实验证**：论文内置了两个反事实。① 去掉 pinned 政策（读历史）→ 定理 2 证明任何有限测试都不充分；② 去掉 adapter（基座裸跑）→ 12/2,446 视图、23/220 题。二者共同说明：保证来自"结构 × 训练"的乘积，缺一不可。

**诚实边界**：保证是**相对 runtime 的**——布局、外循环、参考程序是常规代码且未在 Lean 中形式化（靠每步断言+随机参考运行检查）；证书绑定具体执行路径与文件 hash；对话/转录环节（词题 → 纸面程序）不在证书覆盖内（约 7% 词题 mistranslate；GSM8K -5.8）。论文对此没有回避。

## 6.3 综合判断与未决问题

**多研究共同支持**的机制：有限状态系统的可枚举性（Moore 1956 → Cai 2017 → Lewandowski 2026 → 本文）与上下文有界性对泛化/认证的价值（PENCIL、inductive scratchpad）。

**仍属论文单方证据**的部分：margin 证书在 fp16 浏览器路径的稳定性（批内实测 τ=1.09 < 1.51）；"视觉网格纸"优于"文本带"的隐含判断。

**适用条件**：任务必须能分解为"有限视图 + 常规代码 runtime"的形式（本文：笔算程序 + 低次一元多项式 + ≤3 元线性系）；换 GPU/库版本需重算证书（默认重查最弱十分之一）；每步约 0.1s 的代价使其不适合高速场景。

**可能失效条件**：更低精度量化、批组成远超已采样范围、字形集渲染差异、runtime 布局 bug（表外视图）——前三条被定理 3 与 hash 绑定部分对冲，最后一条靠运行时断言，属常规代码信任。

# 七、必要知识反推

假设一个毫无背景的人要复现这项工作，最少必须掌握什么？

## 7.1 领域知识层

- **笔算算法与数论基础**：小学竖式加减乘、Knuth Algorithm D（含规范化与 q̂≤q+2 定理）、逐位开方（c²a 缩放保证首位根 25-49）、欧几里得 gcd。不理解这些就无法把"任意长度运算"切成"局部三格决策"。
- **自动机理论**：Moore 1956 的有限实验思想——不理解"为什么有界视图是充分的而链式思维不是"，整个系统的设计动机就不可理解（定理 1/2 正是它的形式化）。
- **transformer 与 VLM 架构**：Qwen3.5 的混合注意力布局（全注意力层的位置直接决定了机制分析里"第五层做决策"的结论）、LoRA 的低秩结构、图像 token 化。

## 7.2 方法论知识层

- **形式化验证**：Lean 4 + Mathlib 的工作流——把"纸面机器"抽象成配置/视图/落笔映射，把归纳证明写成 `regeneration` 引理。没有这层，定理 1 只是直觉。
- **神经网络验证传统**：margin 思想（正确 token 对次优 token 的领先量）与扰动界（τ < m/2）的配对是 Reluplex 一脉 robustness 论证在有限集上的简化版。
- **训练配方**：交叉熵 + hinge（margin 目标）+ KL 蒸馏的多目标组合；低 margin 行重放；以证书全过为停止判据——把"验证"嵌入"训练循环"是本工作的独门方法论。
- **持续学习**：灾难性遗忘文献（LwF/EWC/progressive nets/on-policy 蒸馏），否则无法理解门的必要性与对话 adapter 的配方。

## 7.3 工程知识层

- **浏览器端推理栈**：ONNX 导出、transformers.js、ONNX Runtime Web、WebGPU fp16、批处理对 logit 的扰动测量、缓存前缀的因果性（Lemma 4：缓存实现与全 prompt 逐位一致）。
- **证书工程**：文件 hash 绑定、JSON 证书格式、新设备重查策略、预注册实验的种子管理与评分规则。
- **成本建模**：t ≈ α·前向数 + β·视图数的线性模型与 lockstep 批量（4 任务 32 前向 vs 73）。

## 7.4 知识融合的关键节点

三个"化学反应"节点值得注意：

1. **古典自动机 × 现代 VLM**：把 1956 年的 Moore 实验观察翻译成 2026 年的"每次前向读三格"——跨越 70 年的等价性。
2. **定理 3 × 浏览器工程**：抽象的扰动鲁棒性定理，具体到"fp16 + WebGPU + 随机批"的实测 τ=1.09——形式定理与部署工程的缝合点。
3. **证书 × 训练循环**：不是"训完再验证"，而是把全量证书计算（每 100 步一次）作为训练控制器（低 margin 重放）与停止判据——验证内化为优化信号。

# 八、论文中可以提取的通用性灵感

## 8.1 灵感一：用"结构约束"换"可证明性"——把无限问题折叠成有限问题

**核心思想**：当一个系统在无限输入域上的正确性无法直接验证时，通过约束其信息流结构（每步只读有界输入、步间无隐藏状态），可以把全称命题折叠成有限枚举。

**论文证据**：定理 1（视图精确 ⟺ 任意长度精确）与定理 2（去掉约束则任何有限测试不充分）的一正一反；2,446 行枚举 + margin 证书即完成"无限长度"的覆盖。

**推广场景**：① 代码生成——若让模型逐 token 决策且每步只读有界规格片段，或可枚举认证某类程序合成；② Agent 工作流——把长程任务强制分解为有限状态机式的步骤（外部状态存储替代上下文记忆），错误传播与审计都变局部；③ 数据管道/ETL——每条记录的变换只依赖固定 schema 视图，可穷举测试；④ 安全审计——协议状态机的实现若满足"每步有界读"，其正确性检查从无限轨迹降为有限转移表。

## 8.2 灵感二：证书要落在真实执行路径上，而非理想化模型上

**核心思想**：形式保证若要在现实世界有效，认证对象必须是实际部署的数值路径（特定硬件、精度、库版本、批处理形态），并量化其对扰动的容忍度。

**论文证据**：32 位 PyTorch 最小 margin 3.96 ≠ 部署路径 3.02；4-bit 路径 margin 可从 +9.4 翻到 -8.9；批处理改变 fp16 logit 至 1.09——证书因此绑定文件 hash、实测于 WebGPU、按需重算于新设备。

**推广场景**：① 任何"离线验证 + 在线部署"的 ML 系统（风控、医疗）都应记录验证时的执行环境并做路径绑定；② 量化/蒸馏发布前，重跑与部署精度一致的鲁棒性证书；③ 模型供应链安全——hash 锚定的证书可作为制品完整性的一部分；④ 嵌入式/边缘 AI——不同 SoC 上的重认证流程设计。

## 8.3 灵感三：验证驱动的训练——把"证书全过"当作优化目标与停止判据

**核心思想**：不要"训练完再验证"，把可验证条件（margin 下界、枚举通过）直接写进损失（hinge）、数据调度（低 margin 重放）和停止规则（全部 ≥3）。

**论文证据**：训练损失含 hinge 于 margin（h=4）；每 100 步全量证书；19.8 分钟收敛到全表 margin ≥3；对话 adapter 每个训练阶段都保留表目标并以 2,446 行全过为硬门槛。

**推广场景**：① RLHF/对齐训练——把可形式检查的约束（如拒绝类输出）做成 hinge 项 + 枚举审计；② 编译器/内核优化——以测试套件全覆盖为损失调度信号；③ 机器人技能学习——以安全集枚举通过为课程推进条件；④ 数据清洗——低置信样本自动重放同构。

## 8.4 灵感四：能力的"硬开关"——用乘性门而非正则化来防遗忘

**核心思想**：微调新增能力时，给新分支乘一个可切换的标量门，g=0 时新分支贡献精确为零，基座能力逐位保留；能力切换权交给系统层。

**论文证据**：y = xW + g·s·(xAᵀ)Bᵀ；g=0 在 2,500 chat 前向 + 2,688 视图上逐 bit 等于基座；对照实验：无门的初步 adapter 使 IFEval 掉 16.4 分。

**推广场景**：① 多技能产品——同一基座挂多个门控 adapter，按会话/任务路由；② 隐私与合规——可在推理时"关掉"特定能力（如某领域知识）以满足监管；③ A/B 实验——g 连续插值做能力消融的因果研究；④ 安全回滚——新能力出问题时秒级回退基座。

## 8.5 灵感五：诚实报告负面结果并预注册判据，是可信度的组成部分

**核心思想**：预注册（题目、评分、判据、访问日期）+ 主动在未用过的数据上复检 + 如实公布失败判据，能把"过拟合评测"的嫌疑转化为可审计记录。

**论文证据**：GSM8K -5.8±1.7 超出预注册带宽，论文如实写明"保留判据未确认"并定位损失来源；第五个候选的身份披露后主动换新题重测。

**推广场景**：① 学术评审——要求预注册成为 ML 论文惯例；② 企业模型评测——内部 benchmark 固定种子与判据后再跑竞品对比；③ 竞赛/招标——先公开测试协议再提交系统；④ 任何"第 N 次调参后终于过线"的场景都适用复检纪律。

---

**一句话总结**：Sketchpad 的贡献不是"小模型算得准"，而是展示了第三条路——在"采样大概对"的端到端模型与"精确但出网"的工具调用之间，存在"**结构上必然对且计算留在网内**"的构造：把每步输入压进有限视图集，正确性就变成 2,446 行可查的表格，Lean 与 fp16 浏览器共同为它背书。1956 年 Moore 的思想在 2026 年的视觉-语言模型上完成了一次漂亮的还魂。
